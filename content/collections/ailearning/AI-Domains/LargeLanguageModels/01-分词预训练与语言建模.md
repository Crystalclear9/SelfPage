## 1. 先定义我们到底在学习什么

语言模型的直接输出是离散符号上的条件概率分布。输入一段前缀，模型并不是从数据库里找到唯一正确答案，而是为词表中的每个可生成符号分配概率。这些符号称为 token，它们可能对应一个汉字、一个英文词的一部分、一段空白、若干字节或特殊控制标记。概率分布随后经过采样或搜索才成为文本。把分布、解码与最终任务结果分开，是理解大语言模型的第一道门槛。

设词表为有限集合 $`\mathcal V`$，模型参数为 $`\theta`$，编码后的序列为 $`x_{1:T}`$。自回归模型按链式法则定义

```math
p_\theta(x_{1:T})=\prod_{t=1}^{T}p_\theta(x_t\mid x_{\lt t}).
```

这不是假设各位置独立。恰好相反，每个因子允许依赖完整可见前缀。真正的限制来自模型表达能力、上下文窗口、位置处理和训练数据。若使用固定窗口 $`L`$，实现实际上可能只让条件依赖最近 $`L`$ 个符号；这时它仍是一种合法的条件建模方式，却不等于对任意长历史进行精确推断。

序列终止也属于概率模型。若没有终止符，给定长度下各序列概率可以归一化，但无限变长文本的整体概率解释还需要停止机制。实用模型通常通过结束标记和外部生成长度上限共同控制输出。外部上限截断一段回答，不应被当成模型主动给出了完整答案。评估时要分别记录正常结束、长度截断以及协议错误。

<a id="llm-1-detail-2"></a>

### 1.1 概率正确、文字自然、任务正确是三种要求

模型对常见表述赋予高概率，可以改善文本预测；同一模型却可能把罕见事实写错。事实正确的答案还可能因为表达少见而概率较低。比如数据库中某设备的真实序列号是一个随机字符串，模型几乎无法仅凭语言规律恢复它，但可以流畅地写出格式正确的另一串字符。格式能力、事实来源和任务验收因此不能合并成一个指标。

另一种误区是把一个答案的序列概率当作该答案语义为真的概率。序列概率衡量模型对这段文字的偏好，其归一化空间包括词表里的大量其他文字；语义真假事件则需要定义事实世界、证据与判定规则。没有这样的事件模型，输出字符串的概率并不能直接变成事实置信度。若要做选择题，可以在给定候选和评分协议下比较条件概率，但仍需检查长度、候选模板和答案标签的偏置。

<a id="sec-1-1"></a>

<a id="llm-1-detail-3"></a>

### 1.2 一个序列概率的完整手算

假设真实答案有四个 token，每步真实 token 的条件概率都是二分之一。联合概率为十六分之一，负对数似然为 $`4\log 2`$，每 token 平均负对数似然为 $`\log 2`$，困惑度为二。若另一答案有八个 token，即使每步概率相同，其联合概率也只有二百五十六分之一。联合概率偏好短序列并不说明长答案内容更差，而是乘积概率天然受长度影响。

再考虑两个两步答案。答案甲的两步概率为零点九和零点一，答案乙为零点三和零点三，两者联合概率都为零点零九。甲在第一个位置很确定，但在第二个位置犯了严重错误；乙每步都不太确定。总似然相同会掩盖错误位置的差异。研究训练问题时应同时保留分位置损失、特殊符号损失和任务分项，而不能只观察一条平滑的平均曲线。

<a id="deep-dive-1"></a>

<a id="llm-1-detail-4"></a>

### 1.3 为什么预测任务可能孕育复杂能力

要预测技术文档里的下一个词，模型有时必须利用变量关系、篇章结构和背景知识。训练目标虽然局部，解决它的内部表示可能包含较复杂的信息。这个论证说明复杂表示具有工具价值，却不证明模型必然学会人类希望的推理算法。模型也可能利用格式、题目来源、重复片段等捷径减少损失。能力解释必须依靠新的输入、反事实改变和错误分析，而不能由目标名称直接推出。

所谓上下文学习，是在当前输入中提供任务描述或示例，改变接下来输出的条件分布。通常推理阶段不会因此更新模型权重。它可以表现出任务适应性，但对示例顺序、标签映射、提示格式和分布距离可能敏感。把上下文中的暂时适应称为永久学会某知识，会混淆状态层次；本次请求结束后，该上下文未必仍然可见。

## 2. 分词器是一套可执行的数据协议

<a id="llm-1-detail-6"></a>

### 2.1 编码、解码和可逆性

把原始文本记作 $`s`$，分词器编码为 $`E(s)`$，解码为 $`D(x)`$。理想的原样往返要求 $`D(E(s))=s`$。但如果编码前进行了不可逆的大小写折叠、空白归一化、Unicode 规范化或控制字符过滤，往返能恢复的只是规范化文本。因此先问清楚输入是原始字节、Unicode 字符串还是标准化字符串，再讨论是否无损。

中文里的一个可见字符不总等于一个 Unicode 码点，一个码点也不总等于一个字节。英文重音字母可能有组合形式，表情可能由多个码点组成。若评估用字符数，必须说明数的是哪一种单位。字节级方案便于覆盖任意有效编码的文本，但罕见字符可能被拆成多个 token；词片方案可以压缩常见片段，却需要未见字符串的回退机制。这些选择会影响长度、速度和不同语言的资源公平性。

<a id="llm-1-detail-7"></a>

### 2.2 用一个极小例子理解合并式分词

设起始符号是单字符，训练语料里“学习学习”出现多次。合并式算法可以先统计相邻符号对，再把频率最高的一对替换成新符号。如果先把“学”“习”合成“学习”，原来四个位置就变成两个位置。合并规则及其顺序必须保存；仅保存最后词表，通常不足以唯一恢复编码过程。相同词表配不同优先级，可能对有重叠的字符串产生不同切分。

频率最高并不等于语义最重要。大量模板、代码缩进或网址前缀可能获得优先合并；少数语言、专业缩写和随机标识符则可能仍被细分。分词器训练集因此是一种资源分配机制。检验分词器应覆盖不同语言、代码、数字、空格和特殊字符，而不能只展示一条常见英文句子的压缩率。压缩较高也不自动意味着最终任务更好，因为粒度改变了统计难度和表达共享方式。

<a id="llm-1-detail-8"></a>

### 2.3 特殊符号与模板为什么属于模型定义

开始、结束、填充、角色分隔和工具调用标记都有协议含义。相同可见文字若被放在不同角色模板里，模型接收的 token 序列就不同。用户正文中出现看似结束标记的字符串，是否被编码成普通文字还是控制符号，也必须由协议决定。任意把输入文本解释成特权控制符号，会改变本来应由调用端维护的边界。

训练和推理模板不一致，是一种常见却隐蔽的分布变化。例如训练样本总在助手回复后带结束符，推理却把助手前缀拼错，模型可能继续生成角色标题。排查时先保存实际 token ID 和边界位置，再判断模型是否“理解不了指令”。只看界面上渲染后的字符串，会漏掉重复起始符、缺失分隔符和错误的结束规则。

## 3. 从最大似然到可计算的训练损失

<a id="llm-1-detail-10"></a>

### 3.1 经验风险与目标分布

给定训练样本 $`x^{(i)}`$，负对数似然目标是各个有效预测位置的 $`-\log p_\theta`$ 之和。若按所有 token 平均，长文档贡献更多；若先对每篇文档取平均再对文档平均，每篇文档权重相同。这两者并非只是日志显示不同，而可能对应不同训练目标。数据混合、掩码和归一化分母一起定义了经验分布。

设真实条件分布为 $`p`$，模型为 $`q`$，交叉熵满足 $`H(p,q)=H(p)+D_{KL}(p\Vert q)`$。在数据分布固定、模型可表达并找到全局最优的理想条件下，最小化期望负对数似然等价于减小条件分布的 KL 散度。有限数据、模型错设和优化误差都会使这个理想不完整。这个分解解释了目标，却不提供某个实际模型已经逼近真实语言分布的证明。

<a id="llm-1-detail-11"></a>

### 3.2 平移标签与因果可见性

输入 $`[BOS,a,b,c]`$ 应预测 $`[a,b,c,EOS]`$。在位置对应上，模型读到的前缀必须严格早于当前标签；若把同一位置的目标 token 直接暴露给模型，训练会变成复制。Transformer 的因果掩码控制可见信息，输入与目标错开一个位置确定监督对象，两者共同维护条件概率的含义。只做其中一个并不能自动保证数据管道正确。

还要区分数据里的对齐关系与框架接口。本章显式构造 `x=s[:-1]`、`y=s[1:]`，`F.cross_entropy` 直接比较对应行，并不会再移动标签。有些因果语言模型接口则接收与输入相同的 `labels`，在模型内部完成错位；官方困惑度示例采用的就是这种约定。不能既手工移动又让模型内部再移动一次，否则会跳过本来要预测的下一位置。先核对实际接口，再验证一个三符号小例的输入、logits 行与目标，比仅凭“左移”“右移”的说法可靠。

填充符在损失中通常忽略，但注意力是否还能读取填充位置是另一件事。文档拼接也有类似问题：如果前一篇文章的尾部可以影响下一篇文章的开头，模型学到的是拼接流上的条件分布。若想让文档独立，必须采用正确的边界或块掩码，而不是只在文本里插入一个视觉分隔线。边界政策要与未来推理用途一致。

<a id="llm-1-detail-12"></a>

### 3.3 Softmax 的梯度与数值实现

给定 logits $`z_j`$，真实类别为 $`k`$，单步损失为 $`-z_k+\log\sum_j e^{z_j}`$。对 $`z_j`$ 求导得到 $`p_j-\mathbf 1[j=k]`$。在直接优化这组 logits 的局部解释中，梯度下降沿真实类别的负梯度提高该分数，并降低其他类别分数；共享网络参数的更新还会耦合多个样本，不能据此保证每条样本的真实类别概率都同步上升。梯度方向也不是语义真实性判别。错误标注或污染数据仍会被同一公式认真拟合。数学上没有一个额外开关能识别“这个 token 来自错误事实”。

计算时应使用稳定的交叉熵或 log-softmax，避免先计算非常小的概率再取对数。把所有 logits 同加常数不改变概率；用最大值平移可以防止指数溢出。低精度训练还涉及累加误差和损失缩放，但不应为了防止数值问题随意截断目标概率，否则会改变梯度。先在双精度小例子上核对公式，再扩大模型和精度范围。

<a id="sec-2-1"></a>

<a id="llm-1-detail-13"></a>

### 3.4 梯度累积时分母不能随意改变

两个微批次分别有三个和七个有效 token。若对各自平均损失求梯度后等权平均，前三个 token 总共占一半权重，后七个也占一半；真正的全局 token 平均应按三比七加权。变长序列、回复掩码和分布式训练经常使有效数量不等，因此所谓“累积等价于大批量”需要分母和随机操作也满足条件。

一种清楚的实现是先累计各批次损失总和，并按整个累积窗口的有效 token 数归一化；另一种是事先知道各批次有效数量后对平均损失加相应权重。若窗口内没有任何有效标签，应明确跳过或报错，不能用一个随意的常数分母把空批次伪装成正常训练。日志也要记录有效监督量，而不是只记录样本条数。

## 4. 三个独立的最小实验

<a id="llm-1-detail-15"></a>

### 4.1 实验一：字符、字节与无损合并

下面的合并器只是教学协议：在字符串上按给定优先级做替换，不声称复现某个产品 tokenizer。实验检验两个不变量：每次合并不改变可还原内容，编码粒度可以改变 token 数而不改变原始 UTF-8 字节数。它还提醒读者，不能把本实验的字符计数直接推广为所有 Unicode 字素的计数。

```python
text = '学习学习 AI'
tokens = list(text)
for pair in [('学', '习')]:
    result, i = [], 0
    while i < len(tokens):
        if i + 1 < len(tokens) and tuple(tokens[i:i+2]) == pair:
            result.append(''.join(pair)); i += 2
        else:
            result.append(tokens[i]); i += 1
    tokens = result
assert ''.join(tokens) == text
assert len(tokens) < len(text)
raw = text.encode('utf-8')
assert raw.decode('utf-8') == text
assert len(raw) > len(text)
print({'characters': len(text), 'merged_tokens': len(tokens), 'bytes': len(raw)})
```

这里减少的是离散预测步数，不能由此推导训练速度同比提升。更大的词表会增加输出投影的参数与计算成本；不同切分还改变预测难度。若要比较真实方案，应固定文本、模型和预算协议，同时报告 token 长度分布、字节吞吐和下游质量。只用平均长度比较，会隐藏极端长样本和罕见字符的尾部风险。

```math
4\times3+1+1+1=15.
```

### 4.2 实验二：掩码损失与正确的累积

本实验用一组固定 logits 排除模型训练的随机因素。前后两个微批次有效长度不同，验证按有效 token 数加权才等价于直接拼接。忽略值只决定损失是否计入，不负责修复错误的因果注意力。这种把数据、模型和聚合分开的测试方式，比一上来观察训练是否下降更容易定位管道错误。

```python
import torch
import torch.nn.functional as F
torch.set_num_threads(1)
z = torch.tensor([[2., 0.], [0., 1.], [2., -1.],
                  [1., 0.], [-1., 2.]], dtype=torch.float64)
y = torch.tensor([0, 1, 1, 0, 1])
loss = F.cross_entropy(z, y, reduction='none')
a, b = loss[:2].mean(), loss[2:].mean()
whole = loss.mean()
correct = (2 * a + 3 * b) / 5
wrong = (a + b) / 2
assert torch.allclose(whole, correct)
assert not torch.allclose(whole, wrong)
masked = y.clone(); masked[-1] = -100
value = F.cross_entropy(z, masked, ignore_index=-100)
assert torch.allclose(value, loss[:4].mean())
shifted = F.cross_entropy(z + 1000., y)
assert torch.allclose(shifted, whole)
print(float(whole), float(correct), float(wrong))
```

这个数值实验确认的是损失聚合恒等式。在真实网络中，即使聚合正确，批归一化、dropout 的随机掩码、优化器每步更新次数也可能使小批次累积与单次大批量不完全一致。检验等价性时，先关闭这些额外因素，再逐项恢复，能够把数学定义问题和随机执行问题区别开。

### 4.3 实验三：从零训练一个完整的条件语言模型

下面实现一个五符号的二元语言模型。每个前一个符号对应一行可训练 logits，训练语料只包含两种句型：开始、甲、乙、结束，以及开始、甲、丙、结束。模型足以学习“开始后总是甲”“乙和丙后结束”及“甲后两种分支均可”，却没有长距离记忆能力。这个模型小到可以逐项解释，适合检查似然、优化与采样的连接。

```python
import torch
import torch.nn.functional as F
torch.set_num_threads(1)
torch.manual_seed(17)
# 0=BOS, 1=甲, 2=乙, 3=丙, 4=EOS
sentences = [[0, 1, 2, 4], [0, 1, 3, 4]] * 20
x = torch.tensor([a for s in sentences for a in s[:-1]])
y = torch.tensor([b for s in sentences for b in s[1:]])
weight = torch.nn.Parameter(torch.zeros(5, 5, dtype=torch.float64))
opt = torch.optim.Adam([weight], lr=0.08)
initial = F.cross_entropy(weight[x], y).item()
for _ in range(450):
    opt.zero_grad()
    loss = F.cross_entropy(weight[x], y)
    loss.backward(); opt.step()
final = F.cross_entropy(weight[x], y).item()
prob = weight.detach().softmax(dim=-1)
assert final < 0.25 and final < initial
assert prob[0, 1] > 0.99
assert abs(prob[1, 2].item() - 0.5) < 0.01
assert abs(prob[1, 3].item() - 0.5) < 0.01
assert prob[2, 4] > 0.99 and prob[3, 4] > 0.99
# 贪心同分时按张量顺序选择，采样则保留两个分支。
g = torch.Generator().manual_seed(31)
branches = torch.multinomial(prob[1], 1000, replacement=True, generator=g)
assert (branches == 2).sum() > 350
assert (branches == 3).sum() > 350
print({'initial_nll': initial, 'final_nll': final,
       'branch_probabilities': prob[1].tolist()})
```

最优平均损失接近 $`\frac{\log 2}{3}`$，因为每个三步句子只有“甲后选乙还是丙”包含一比特不确定性。模型把其余确定转移的概率推近一，但有限 logits 不会达到精确的一。这个残余损失是数据分支本身的条件熵，不能简单认定为优化失败。反过来，训练损失低也没有证明模型学会了未出现过的句法或知识；它只拟合了一个极小的条件转移表。

### 图解：语言模型预测的是 token 条件分布

![出现次数相同的两个输入有不同的条件熵，等频分支贡献平均损失下界](images/01-img-state-conditional-entropy.webp)

[打开原图放大](images/01-img-state-conditional-entropy.webp)

先把“见过多少次”与“见到后还有多少不确定性”拆开。图中对照实验三中出现次数相同的两个输入。BOS 与甲都出现四十次，但 BOS 后面确定是甲，只有甲之后存在乙、丙两种等频结果。对当前只按输入符号查一行 logits 的模型，经验最优条件分布因此有平均负对数似然下确界 $`\frac{40}{120}\log2=\frac{\log2}{3}`$。这是当前数据与模型状态约定下的条件熵，不是通用语言不可约的熵率；有额外可预测上下文时，目标可以不同。有限 logits 不能把其他质量精确压成零，实际只逐渐接近该边界。

下面再逐对核对这份条件分布从哪里来：

![四种输入的后继计数分别按行归一，结束符从未作为输入](images/01-img-transition-normalization.webp)

[打开原图放大](images/01-img-transition-normalization.webp)

图中逐项对应实验三的 `x` 和 `y`。两种四符号句子各重复二十次；每句从前三个符号预测后三个符号，贡献三对监督，合计一百二十对。程序是在每句内部取 `s[:-1]` 与 `s[1:]`，再汇总这些预测对，没有额外加入跨句子的 `EOS → BOS`。如果直接把整批句子连成一条流再错位取标签，就会产生另一套计数与目标。

表中每行固定一个输入，列出各后继的计数与归一化概率。四行合计一百二十个监督位置。BOS 一共出现四十次，后继全部是甲；甲出现四十次，其中乙、丙各二十；乙、丙各出现二十次，后继都是 EOS。把每个非空行除以自己的总次数，就得到右侧的经验条件分布。**按行归一化是在估计“给定当前输入，下一符号怎样分布”；除以一百二十得到的则是输入与后继的经验联合频率。** 两者不应混用。

为什么 EOS 行没有圆点，也没有列出经验概率？训练输入没有 EOS，因此该行的经验条件概率没有分母；不能据零计数断言“EOS 后所有词概率都是零”。这个程序的五行 logits 初始化都为零，而 EOS 行从不被 `weight[x]` 选中。它的梯度始终为零，在当前未启用权重衰减的 Adam 配置下维持原值，softmax 后仍是每个符号 $`\frac15`$。这只是未训练参数的初始化状态，不是数据教会模型“结束以后要均匀说话”。实际生成应在首次 EOS 时停止，不能把该行当作有效学到的语法。

右侧未画出的目标质量为零，画满整条的目标质量为一；这些是经验分布上的理想边界值。有限 logits 的 softmax 每项严格为正，只能逐渐接近这些边界；这解释了程序为何断言“概率大于零点九九”，而不要求等于一。对于参数行，只要把同一行所有 logits 加上一个常数，概率也不变，所以即便条件分布已确定，logits 本身也没有唯一数值表示。

图中 BOS 与甲各占四十次输入，但前者只有一种结果，后者有两种等频结果；乙与丙各占二十次，却也是确定后继。计数、经验不确定性和对未来分布的估计误差，是三个不同问题。可对照 Jurafsky 与 Martin《Speech and Language Processing》第 3.1.2 节的二元计数与行归一化；表中只列出现过的后继，每个非空行中其余词表目标的计数和概率均为零。

### 图解：从训练损失到完整句子概率

![五符号模型的初始和训练后负对数似然与理论下界](images/01-img-training-nll-and-bound.webp)

[打开原图放大](images/01-img-training-nll-and-bound.webp)

前一张图给出经验目标。本图对照程序实际达到的损失与理论下界。实验使用 float64、CPU 和学习率零点零八的 Adam。初始损失为 $`\log5\approx1.609438`$，四百五十次更新后约为 $`0.232802`$，距下界仍有约 $`0.001753`$。设备与框架版本可能改变末位数值，概率恒等式与理论下界不受这些末位变化影响。

先把整体损失按输入状态拆开。记模型转移概率为 $`q(v\mid u)`$，有效位置等权的目标恰好是

```math
\begin{aligned}
&L={}-\frac13\log q(\text{甲}\mid\mathrm{BOS})\\
&-\frac16\log q(\text{乙}\mid\text{甲})
-\frac16\log q(\text{丙}\mid\text{甲})\\
&-\frac16\log q(\mathrm{EOS}\mid\text{乙})
-\frac16\log q(\mathrm{EOS}\mid\text{丙}).
\end{aligned}
```

系数来自真实计数除以一百二十：BOS 行占三分之一，甲行合计占三分之一，乙、丙行各占六分之一。它不是“四个输入状态等权”，也不是“五个词表类别等权”。理论上除甲行外都可趋近确定预测，甲行的两个后继各占一半，所以目标下确界是

```math
L_{\inf}=\frac13\log2\approx0.231049.
```

把各行经验频率记作 $`\widehat p(\cdot\mid u)`$、输入频率记作 $`\widehat\pi(u)`$，还可以精确写成

```math
\begin{aligned}
&L-L_{\inf}
=\sum_{u:\,n(u)>0}
\widehat\pi(u)\\
&D_{\mathrm{KL}}\!\left(
\widehat p(\cdot\mid u)\,\Vert\,q(\cdot\mid u)
\right)
\geq0.
\end{aligned}
```

因而图中约零点零零一七五三的差值是已见状态上的剩余拟合差距；约零点二三一零四九则来自等频分支本身的不确定性。继续降低损失主要是在把有限 softmax 推近理想条件频率，不能让不可判定的两个等频分支同时变成唯一正确答案。零计数的 EOS 输入行不出现在这个和中，其参数完全不受该经验目标辨识。

再沿树读一条完整句子。固定起始 BOS，生成“甲、乙、EOS”的概率是三条实际条件边的乘积，约为

```math
\begin{aligned}
&0.998002629\times0.499370091\\
&\times0.998002628
\approx0.497377228.
\end{aligned}
```

经过丙的另一条路径具有相同概率。两条训练语法中的完整句子总质量约为零点九九四七五四，剩余约零点零零五二四六仍分配给其他终止路径，例如过早结束、出现其他符号或产生更长序列。这里按首次 EOS 停止；模型没有被硬性限制为只会生成训练语法。低 NLL 不等于输出空间中所有非法路径都已消失。

同样，程序从“甲后”分布独立抽一千次，当前运行得到乙五百一十次、丙四百八十九次、甲一次。第三种结果不是程序错误：另外三个类别各保留约零点零零零四二的概率，有限 softmax 允许罕见越界。不同随机种子会改变计数；这些抽样频数也不能替代条件概率的解析值。贪心在两个分支并列时固定选择一个，只描述该解码规则，并没有证明数据里另一个分支不合理。

PyTorch 交叉熵文档可用于核对未归约损失与平均分母；固定窗口困惑度说明解释了真实语言模型评价为何还需明确上下文窗口和计分位置。本实验没有注意力窗口，只使用前一个符号，结果衡量的是该二元条件模型在这组转移上的拟合。

### 4.4 如何给这个小模型做真正的泛化测试

随机把重复句子拆成训练与测试，会让两边都出现同样的转移，测到的主要是相同分布下的拟合。若留出一种从未见过的转移，二元模型没有理由自动给它高概率。若构造必须记住两个位置之前信息的任务，模型会因结构限制失败。这种失败具有解释价值：它区分了模型容量不足、训练数据覆盖不足和评价协议太容易三类原因。

可以构造“开始、颜色、无关符号、颜色对应答案”的数据。两个样本最后一个可见符号相同，却要求不同答案，任何只读最后一个符号的模型都必须在它们之间折中。增加训练步数不能解决输入表示中信息被丢弃的问题。先证明存在这种不可区分样本，再考虑改用更长上下文或注意力网络，方法选择就有了明确依据。

<a id="llm-1-state-aliasing"></a>

### 图解：把两种历史压成同一状态，会留下怎样的损失

![只看占位符会把两个历史合并，保留颜色后才能分别预测停和走](images/01-img-context-state-collision.webp)

[打开原图放大](images/01-img-context-state-collision.webp)

把上面提到的长依赖测试具体化：两种历史等频，完整历史“红、占位”后必须预测“停”，“蓝、占位”后必须预测“走”。本图只评价最后一个待预测符号，不把前面颜色与占位符的预测混入分母。二元模型在两个样本上都只读“占位”，因此必须输出同一分布；完整历史中的区别在进入模型之前已经丢掉。

设模型给“停”的概率为 $`q`$，并先考虑概率质量全部分配给停与走，则最后一步平均损失为

```math
\begin{aligned}
&L(q)=-\frac12\log q-\frac12\log(1-q)\\
&\quad =-\frac12\log\!\bigl(q(1-q)\bigr).
\end{aligned}
```

因为 $`q(1-q)=\frac14-(q-\frac12)^2\leq\frac14`$，最低点在 $`q=\frac12`$，损失为 $`\log2`$。若词表还有其他符号，分给它们的质量会使停与走的概率总和小于一，仍不能把下界降低。当 q 靠近零或一时，式中的一项趋向无穷，对应于同一状态下另一类样本的概率被压到接近零。仅凭当前状态做确定性分类，最好也只能对一半；随机化不会创造缺失的颜色信息。

若改用读取最近两个符号的模型，两种输入状态不再相同，可以分别趋近概率一的正确后继，对最后一步的理想损失下确界变成零。这里的零是概率单纯形上的理想值，有限 softmax 仍是趋近边界。于是这个人工分布上有

```math
\begin{aligned}
&H(Y\mid Z)=\log2,\qquad
H(Y\mid H)=0,\\
&\quad I(Y;H\mid Z)=\log2,
\end{aligned}
```

其中 $`H`$ 是完整历史，$`Z`$ 是只保留“占位”的状态。上式把压缩历史造成的最优对数损失差写成条件互信息。与主训练例中“甲之后数据本来就有两个合理后继”不同，此处完整历史下答案完全确定，损失来自状态压缩。两种现象都会出现一半、一半的最优预测，却对应不同改进：前者需要承认真实不确定性，后者需要保留相关历史。

这也给下一项实验划定边界。增加相同重复句、训练更多步或更换学习率，都不会使同一“占位”输入同时输出两种确定答案；读取更多上下文才改变可辨识性。反过来，实际神经网络读到两步历史后能否逼近零，还需要单独训练与测试；本图证明的是表示造成的理想下界，并未伪造一个已经执行的长上下文网络实验。关于有限历史条件建模与分布式表示的经典背景，可继续读 Bengio 等人的原论文。

## 5. 困惑度、单位和可比较的评价

<a id="llm-1-detail-20"></a>

### 5.1 从熵到困惑度

设有效 token 总数为 $`N`$，平均负对数似然为 $`\ell`$，困惑度定义为 $`\exp(\ell)`$，其中对数底为自然底。若使用二为底的交叉熵，则用二的幂恢复。困惑度可理解为一个与交叉熵对应的有效分支规模，而不是“每一步有多少个候选真正可能”。实际分布可能极不均匀，相同熵对应的概率形状也不唯一。

不要对各批次困惑度直接求算术平均。应该先累计损失总和与有效数量，计算全局平均损失后再取指数。指数是非线性函数，各批次的 token 数也可能不同。类似地，一篇短文和一篇长文的文档平均困惑度，不等于整个语料的 token 加权困惑度。报告时写出分母，往往比保留更多小数位更重要。

![每步条件概率均为 p 时，三步和五步的路径概率分别是 p 的三次方和五次方](images/01-img-conditional-path-product.webp)

[打开原图放大](images/01-img-conditional-path-product.webp)

**完整路径与逐步条件概率。** 本图假定一条给定路径的每步条件概率都固定为 p，则整条路径概率为 pᴸ。若每步概率严格在零和一之间，路径加长会降低该路径的概率，不能直接用不同长度的原始概率比较语言模型优劣。转入负对数后，总量线性增长，再按同一分词单位平均才能比较；若分词器不同，还应考虑每字节等统一口径。箭头上的概率各自以已生成前缀为条件，整条路径按链式法则相乘。进一步阅读可对照《Speech and Language Processing》第 3 章。

```math
\begin{aligned}
&P(w_{1:L})=\prod_{t=1}^{L}P(w_t\mid w_{\lt t})\\
&\quad =p^L\quad\text{（本例每个条件概率均为 }p\text{）}.
\end{aligned}
```

<a id="llm-1-detail-21"></a>

### 5.2 为什么不同分词器的困惑度不能直接排名

同一段文字若切成两个大 token 或十个小 token，每步平均信息量的单位已经改变。假设该文本整体负对数似然恰好相同，十个 token 的平均损失仍会更小。因此更低的 token 困惑度可能只反映粒度变化。可以在严格定义下报告每字节的编码长度，但需要保证比较的是同一原始文本，处理方式一致，并把特殊符号和结束概率如何计入说明清楚。

每字节位数可以写成总负对数似然除以原始字节数再除以 $`\log 2`$。如果模型只给出一个确定性分词路径的概率，而多种 token 序列能够解码成同一文本，那么它未必等于文本全部编码路径概率的精确和。因此字节归一化是一种常用可审计评分协议，却不应不加条件地称作任意 tokenizer 下唯一的真实文本熵。

<a id="llm-1-detail-22"></a>

### 5.3 训练集、开发集和污染边界

应在训练前建立来源和时间边界，开发集用于选择，最终测试集用于一次冻结后的检验。仅按文本行随机划分，会让同一网页的不同段落、同一问题的改写或同一本书的相邻片段穿越边界。对于语言模型，污染还可能来自公开题目的答案解释、教学博客和二次转载。逐字去重只能发现最明显的一部分。

若要研究推理而非记忆，可以改变数字、实体、关系方向和表述，加入结构相同但答案变化的反事实样本。不过新题也可能引入更难的词汇或格式，从而混淆变量。合理的做法是成对设计，只改变需要检验的因素，并保留原题、变化规则和判定逻辑。单次改写失败不能立即证明模型只会背诵，成体系的变化更有解释力。

<a id="visual-example-largelanguagemodels-01"></a>

### 对照表：困惑度需要共同的概率计量单位

| 评分分解 | 总负对数似然 | 有效 token 数 | 每 token 均值 |
| --- | --- | --- | --- |
| 分词方案 A | 12 | 6 | 2 |
| 分词方案 B | 12 | 3 | 4 |

**说明。** 同一总负对数似然十二，按六个 token 归约得到二，按三个 token 归约得到四，指数化后困惑度便相差很大。这个独立算例刻意固定总量，只展示分母改变的效果。跨分词器比较应寻找共同的字符或字节单位，并说明边界、结束符和文本规范化约定。

**适用条件。** 真实不同模型的总似然也会变化；本表不宣称同一文本的不同 token 分解通常具有相同总量，只用于说明计量单位问题。

## 6. 数据混合决定模型优先学什么

<a id="llm-1-detail-24"></a>

### 6.1 文档采样、token 采样和温度权重

有两个来源，甲有九百万 token，乙有一百万 token。按原始 token 比例采样，乙占十分之一；若按来源等权，乙占一半，相当于对乙重复暴露更多。若使用 $`w_i\propto n_i^\alpha`$，当指数为一时接近规模比例，指数为零时来源等权。中间值调节大来源和小来源的竞争，但没有对所有目标任务普遍最优的指数。

混合权重既是技术选择，也是目标选择。若某来源格式整齐且预测简单，它可能显著降低总体损失，却未增加罕见任务能力；若专业来源很难，增加它的权重可能提高总体损失同时改善专业测评。因此需要按来源报告有效 token、损失、重复率和任务结果。总体损失的升降不足以替代数据配方的实际价值判断。

<a id="llm-1-detail-25"></a>

### 6.2 去重改变权重而不是创造真理

本节从语言建模目标解释去重如何改变经验分布。需要从原始记录实现筛选、近似去重、污染隔离和配比时，可接着读第 6 章的[预训练语料工程](06-预训练语料工程.md)。

假设一条错误说法被复制一千次，一条纠正只出现一次，最大似然会把重复样本当作更多证据，除非处理流程主动改变其权重。去重能减弱机械复制带来的频率放大，但保留下来的唯一文本仍可能是错的。质量筛选、来源可信度和事实校验解决的是不同问题，不能让一个去重哈希承担全部数据治理工作。

精确去重、近似去重和语义去重也有不同误差。过于激进的规则可能删掉合法的模板实例，例如相同格式但关键数字不同的实验记录；过于宽松则保留大量改写副本。评估去重策略时，应人工检查保留和删除两边的代表样本，并观察不同语言及文体的删除比例。只展示压缩掉多少字节，很难判断是否损害覆盖。

<a id="sec-5"></a>

<a id="llm-1-detail-26"></a>

### 6.3 数据数量与有效信息量的区别

把相同一百条数据重复一千遍，优化器确实进行了更多参数更新，但经验分布的支持集没有扩大。重复训练可能帮助尚未收敛的模型拟合，也可能增加记忆。新增来源若与现有来源高度相关，其信息增量同样可能有限。数据规模统计应同时给出原始数量、去重后数量、训练暴露次数和覆盖维度，避免把它们都叫作“训练了多少数据”。

长文截断还会产生选择效应。如果总保留开头，结尾的结论、参考文献和异常说明更少进入训练；如果固定长度滑窗，边缘位置的监督覆盖可能不均匀。可以随机裁剪或调整打包策略，但必须知道这些策略改变了模型看到的条件上下文。任何吞吐优化都应在有效监督量和目标分布上重新核验。

<a id="llm-1-detail-27"></a>

## 7. 训练预算与推理资源的数量级

<a id="llm-1-detail-28"></a>

### 7.1 参数、激活和优化器状态

参数内存只是总内存的一部分。训练还需要梯度、优化器动量或方差状态、可能存在的主权重，以及前向保存的激活。激活大小受批量、序列长度、层数和具体实现影响。某种低精度参数格式节省了权重内存，不代表全部训练显存按相同比例下降。报告应说明哪些张量采用何种精度，而不是只给一个模型位宽。

粗略的参数量乘 token 数估算适合比较同一架构家族的数量级，但不同注意力实现、词表规模、序列长度和硬件利用率都会改变实际成本。训练时间还取决于通信、数据读取、编译和检查点。理论浮点运算更少的方案可能因为小矩阵和调度开销更慢，所以需要把理论预算和实测耗时分别记录。

<a id="llm-1-detail-29"></a>

### 7.2 预填充与逐 token 解码

预填充阶段一次处理输入上下文，解码阶段逐步产生新 token。使用 KV 缓存时，每层保存历史位置的键和值，避免重新计算整个前缀的投影。缓存大小大致与批量、总缓存长度、层数、键值头数、每头维度、元素字节数以及键值两份成正比。采用分组查询注意力会改变键值头数，但具体内存仍取决于实现和分配策略。

缓存并没有让注意力变成与历史长度无关的运算。新查询仍需与可见历史键进行匹配；输出越长，累计读取历史的工作越多。批量服务还涉及不同请求的长度、排队和缓存碎片。平均每秒 token 数可能很好看，但用户感受到的首 token 延迟和长尾延迟并不由同一个数字决定。教学实验没有 GPU 服务负载，不能据此声称某生产吞吐水平。

<a id="llm-1-detail-30"></a>

### 7.3 一个可复算的缓存例子

假设仅为估算而设批量为二、层数为十二、缓存长度为一千、键值头数为四、每头维度为六十四、每元素两字节，则键和值的理论存储量为两份乘以上述各项，等于二千四百五十七万六千字节，约二十三点四 MiB。这里没有计算权重、临时注意力张量、框架分配开销和输出 logits。若头数或长度翻倍，缓存主体也随之翻倍。

这个例子的用途是建立维度检查习惯。先写每个因子的单位，再做乘法，最后明确使用十进制 MB 还是二进制 MiB。若把查询头数误当成键值头数，在分组查询结构中就可能高估；若忽略批量和键值两份则可能低估。资源估算应能被别人从配置重新算出，而不是只给一个无法追溯的数字。

<a id="llm-1-detail-31"></a>

## 8. 从条件分布到解码算法

<a id="llm-1-detail-32"></a>

### 8.1 贪心并不保证整段概率最大

第一步甲概率零点六，乙概率零点四；甲后最佳下一步概率零点五，乙后最佳下一步概率零点九九。贪心先选甲，最终路径概率零点三；以乙开头的最佳路径概率零点三九六，反而更高。局部最优与全局最优的差异来自未来条件分布。这也说明“每一步选最可能 token”不是整段最大似然搜索的充分条件。

束搜索保留多个前缀，可以缓解局部决策，但有限束宽仍可能剪掉最终最优路径。长度归一化、结束惩罚和覆盖项会进一步改变搜索目标。任务评价如果重视简洁或完整性，就要明确这些偏好怎样进入算法，不能把加过长度奖励的结果仍称为未经修改的最大概率序列。

<a id="llm-1-detail-33"></a>

### 8.2 温度、截断与采样分布

温度采样把 logits 除以正数温度再做 softmax。温度低会使分布集中，温度高会使分布平缓；任何有限正温度都不是自动的事实校验器。若错误答案本来概率最高，降低温度可能更稳定地给出错误。探索性任务可以利用多样性，精确任务则还需要验证器、证据或约束解码。

顶部候选截断和累计概率截断会删除部分支持并重新归一化。原模型的概率评分与截断后实际采样概率因此不同。若用生成轨迹估计某个统计量，应记录实际采样规则，而不是事后用未截断概率代替。结束符被过滤掉也可能导致反常长输出；所有后处理都需要与停止协议共同测试。

<a id="llm-1-speculative"></a>
### 8.3 精确投机解码：接受与拒绝怎样共同恢复目标分布

小模型先提出候选，大模型再验证，为什么不一定改变输出分布？关键在拒绝后的补偿采样。固定一个实际前缀，令大模型的目标分布为 $`p`$，提议分布为 $`q`$，均定义在同一有限词表上。先抽 $`Y\sim q`$，再以

```math
a(Y)=\min\{1,\frac{p(Y)}{q(Y)}\}
```

接受它。只在 $`q(Y)>0`$ 的实际提议上计算比值；对 $`q(x)=0`$ 的项约定 $`a(x)=0`$，其接受质量始终为零，因此无需除以零。记总接受率 $`A=\sum_x\min\{p(x),q(x)\}`$。若拒绝且 $`A\lt 1`$，从残差分布

```math
r(x)=\frac{[p(x)-q(x)]_+}{1-A}
```

重新抽取最终符号。它确实归一化：因为两个分布总质量均为一，正差质量等于负差质量，均为 $`1-A`$。于是最终输出 $`x`$ 的概率为

```math
\begin{aligned}
&q(x)a(x)+(1-A)r(x)\\
&\quad =\min\{p(x),q(x)\}\\
&\quad +[p(x)-q(x)]_+=p(x).
\end{aligned}
```

这给出一步的精确证明；$`A=1`$ 时 $`p=q`$，不会进入残差分支。由 $`\min(u,v)=\frac{(u+v-\vert u-v\vert )}{2}`$，还有 $`A=1-\tfrac12\lVert p-q\rVert_1`$。因此接近目标的草稿分布可以提高接受率，但接受率本身没有说明草稿成本或硬件吞吐。原始算法论文给出了这种校正采样与自回归批量验证的组合。

手算三词例子：$`p=(0.5,0.3,0.2)`$，$`q=(0.2,0.5,0.3)`$。三个接受概率是 $`1,0.6,\frac{2}{3}`$，被接受的无条件质量为 $`(0.2,0.3,0.2)`$，总和 $`A=0.7`$。正残差为 $`(0.3,0,0)`$，所以拒绝后必须输出第一词。最终质量为 $`(0.5,0.3,0.2)`$。若错误地在拒绝后直接从 $`p`$ 重抽，结果会是 $`(0.35,0.39,0.26)`$；即使重抽使用大模型，也无法自动修复已经发生的选择偏差。

![投机采样每个词元的接受质量加上拒绝补偿，恢复目标分布](images/01-img-speculative-mass-balance.webp)

[打开原图放大](images/01-img-speculative-mass-balance.webp)

表中各列以无条件质量计数，补偿项的总和为 $`0.3`$，不是归一化后的残差分布。接受与补偿是两个互斥事件，必须先乘各自事件概率再相加。还可把草稿改为 $`q=(0,0.6,0.4)`$：接受质量为 $`(0,0.3,0.2)`$，拒绝概率为 $`0.5`$，全部补给第一词，仍能得到同一目标。这说明“草稿从不提出某词”和“最终永远不会输出该词”是两回事；校正步骤能够补回缺失支持。

多词草稿按自身前缀逐步提出，大模型利用因果计算一次得到各草稿前缀的目标条件概率。验证须从左到右，在首个拒绝处用当前前缀的残差校正，并丢弃后续草稿；它们依赖了被拒绝的历史。全部接受时还可从最后一个草稿前缀对应的目标分布多抽一词。对真实前缀逐步应用上述恒等式，再用链式法则，才得到整段分布保持不变的结论。

边界同样重要：这里 $`p`$ 指实际希望采样的分布，包含温度、截断等已确定的处理，不能用原始 softmax 概率验证另一种采样协议。$`q`$ 有零值而 $`p`$ 为正并不破坏证明，残差可以补足该支持；实现仍需取得相应目标概率。缓存应截断到已接受的前缀，结束符应遵循同一停止规则。分布等价不承诺相同随机种子生成同一字符串，也不承诺必然提速；低接受率、较贵草稿或验证开销都可能抵消收益。

<a id="visual-mechanism-largelanguagemodels-01"></a>

### 图解：top-k 截断会删除支持并重新归一化

![保留两词的原质量为零点八，重新归一后其余候选概率归零](images/01-img-top-k-support.webp)

[打开原图放大](images/01-img-top-k-support.webp)

**从重归一化继续追到支持集变化。** top-2 保留原概率质量 $`0.8`$，所以在两个保留词上有 $`q_i=\frac{p_i}{0.8}`$；因此 $`D_{\mathrm{KL}}(q\|p)=\sum_iq_i\log\frac{q_i}{p_i}=-\log0.8\approx0.2231`$。反方向却包含原分布仍有正概率、而 q 概率为零的词，故 $`D_{\mathrm{KL}}(p\|q)=+\infty`$。该例的总变差距离为被删质量 $`0.2`$。

如果验证文本出现第三或第四个词，用这个截断采样分布计算其负对数概率会得到无穷，而原模型概率并不为零。因此采样配置与语言模型似然评价必须区分。有限温度缩放通常保留有限 logit 的正概率支持，top-k 则直接删除候选；参数定义可核对 Transformers 生成配置。

**图中的机制。** 完整分布为 0.5、0.3、0.15、0.05。只保留前两个候选后，剩余质量为 0.8，重新归一化得到 0.625 与 0.375，另外两个候选概率为零。图把支持删除与温度平滑区分开：它不是只把原概率保持不变再随便抽样。

**条件与边界。** 本例分数无并列。其他截断策略、保底候选与结束符处理会影响实际生成，采样分布也不等同训练概率模型。

## 9. 能力、记忆和可靠性之间的间隔

<a id="llm-1-detail-35"></a>

### 9.1 参数知识与上下文证据

参数中的知识是通过训练分布和优化过程形成的分布式表示，通常不带可以直接追溯的来源记录。上下文中的证据则有明确文本位置，但模型能否正确使用，还取决于检索、位置、冲突处理和生成过程。有证据进入窗口不意味着答案必然忠实；生成引用也不意味着引用真的支持结论。这些问题在检索增强章节会分阶段拆解。

较长窗口增加可放入的信息，却可能引入无关内容、冲突和干扰。可以通过移动同一证据的位置、加入相关但错误的近邻、交换事实主体等方式检验使用能力。测试时应保持问题和真值不变，只改变证据排列，从而把窗口容量和证据利用分开。单个大窗口数字只描述输入上限，不能描述所有位置上的可靠读取性能。

<a id="sec-6-1"></a>

<a id="llm-1-detail-36"></a>

### 9.2 训练目标与任务评价必须并列

一个模型在常见文本上 NLL 更低，可能只是更好地预测了套话；另一个模型的整体 NLL 稍高，却在罕见计算任务上更准确。两者并不矛盾，因为损失按 token 分布加权，任务指标按问题或用户需求加权。任何模型选择都应先说明部署分布和错误代价，再决定怎样组合指标。

对推理题，可以同时评价最终答案、过程中的可检查步骤、扰动稳健性和计算预算。过程看起来合理却答案错误，与答案碰巧正确但过程无效，是不同错误类型。不能仅凭长篇解释就证明模型执行了正确算法；也不能因为解释不完整就断定内部没有有用计算。研究结论应限定在可观察证据支持的范围。

<a id="llm-1-detail-37"></a>

### 9.3 置信、拒答和校准

概率校准讨论的是定义良好的事件：例如在模型给出某一置信区间的题目中，正确率是否接近宣称值。自然语言里的“我很确定”不是自动校准的数值输出。若把某个答案 token 的概率当置信度，必须验证这个代理与完整任务正确性的关系。候选空间改变、模板改变或答案长度变化，都可能影响这一关系。

拒答也需要评价。过于保守会拒绝可回答问题，过于冒进会在证据不足时编造。应按可回答与不可回答子集报告正确回答率、错误回答率和拒答率，并结合具体成本。把所有拒答计为安全成功，会掩盖可用性问题；把所有回答计为有用，也会奖励无根据的输出。明确事件定义才能讨论校准和取舍。

<a id="llm-1-detail-38"></a>

## 10. 进一步研究该怎样设计

<a id="llm-1-detail-39"></a>

### 10.1 先写假设，再选择可证伪的变化

假设是“模型通过关系结构解题”，可以把实体名替换为无意义符号，保持关系图不变；再改变一条边，让答案随之改变。如果模型仅依赖熟悉实体的共现，替换后可能失效。若假设是“长上下文提升证据使用”，就应固定证据数量、答案分布和解码规则，只改变必要上下文长度，而非同时更换更简单的题目。

每个实验应说明干预变量、保持不变的因素、测量指标和可能的替代解释。对于小样本结果，给出题目级成对差异比只报两位小数的总体分数更有价值。随机种子控制运行复现，但不能消除题目选择偏差。应保留失败例子和预先定义的排除规则，避免在看到结果后悄悄修改评价集合。

<a id="llm-1-detail-40"></a>

### 10.2 小实验和大模型结论之间的距离

本章二元模型证明了可以用交叉熵学习条件转移，并验证了数据中的不可约分支熵。它没有验证大模型的缩放规律、复杂推理、跨领域迁移或服务性能。将小实验提升为大模型结论，需要相应规模、架构、数据和评价证据。教学上可以讨论机制类比，但必须把“演示恒等式”和“实证支持某能力”区分开。

逐步扩大研究时，先从可完全检查的任务开始，再增加词表、历史长度、数据异质性和模型容量。每一步记录新引入的自由度及失败模式。若直接跳到一个不可解释的巨大系统，很多现象虽然有趣，却很难知道由分词、数据、优化还是解码造成。可控实验的价值正在于让好奇心转化为可验证的问题。
