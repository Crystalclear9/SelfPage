## 1. 后训练首先是目标定义问题

预训练模型学习文本条件分布，指令微调希望它在给定任务、对话历史和输出约束时产生合适回复，偏好学习则利用候选回复间的比较来调整行为。参数高效微调回答的是哪些参数能够更新，和前两者回答的目标问题处于不同层次。一个实验完全可以同时使用指令数据、偏好损失和低秩参数化，不能把这些名称排成互斥的模型类别。

先把任务写成输入 $`x`$ 和完整回复 $`y`$。输入包含的系统文本、角色模板、历史轮次和工具结果都是条件的一部分；回复可能包括内容和结束标记。若训练与评估使用不同模板，即使原始问题相同，条件分布也已经变化。数据管道应保存结构化消息，再通过固定模板构造 token 序列，而不是在不同脚本里临时拼接字符串。

<a id="llm-2-detail-2"></a>

### 1.1 三种问题：示范、排序和执行反馈

示范数据告诉模型“在这个输入上，希望生成这份回答”。比较数据告诉模型“在这两个候选中，标注者更偏好哪一个”。环境反馈则告诉系统“执行后产生了什么结果或奖励”。示范不一定唯一，排序不一定反映绝对质量，执行成功也不一定满足所有行为要求。研究前必须明确监督信号提供了什么信息，缺少什么信息。

例如两个回答都算错，但一个措辞更流畅，比较标注可能仍选择它。单纯学习该比较不会自动恢复正确计算。又如示范总是非常详细，模型可能把长度当成质量信号；如果部署需求是精确简答，这种行为并非训练失败，而是目标与需求不匹配。方法选择要回到希望改变的错误类型，而不应只按算法名称的新旧排序。

## 2. 监督微调的损失到底覆盖哪些位置

<a id="llm-2-detail-4"></a>

### 2.1 回复掩码与条件似然

典型的回复监督目标为

$$
L_{SFT}=-\frac{1}{N}\sum_{i,t}m_{it}\log\pi_\theta(y_{it}\mid x_i,y_{i,<t}),
$$

其中 $`m_{it}`$ 标记受监督的位置，$`N=\sum m_{it}`$。提示部分可能不计损失，但仍参与前向并影响回复预测。把提示标签设为忽略值，不等于模型看不到提示。若要训练多轮助手行为，可以监督多个助手片段，但要说明用户消息、工具返回和特殊控制符号是否进入分母。

一个直观错误是把用户问题本身也作为主要预测目标，导致长问题占据多数损失，而真正回复只贡献少量梯度。这不一定数学上非法，却可能偏离指令跟随目标。另一个错误是把填充位置当真实结束符，模型会从大量填充中学习提前结束。最小测试应打印每个 token、角色、标签和掩码，逐项核对边界。

<a id="sec-1-1"></a>

<a id="llm-2-detail-5"></a>

### 2.2 手算：token 等权与样本等权

一条回复有两个 token，每个损失为一；另一条有八个 token，每个损失为三。全局 token 平均为二点六，先按回复平均再按样本平均则为二。前者长回复占更多权重，后者每条回复占相同权重。两者都是可定义目标，但会对长解释、短答案和不同任务比例产生不同影响。论文或项目若只写“平均交叉熵”，还不足以完全复现。

如果采样器已经对任务类别做了重平衡，再在损失中重复加相同权重，可能无意中把重平衡效果平方。应把抽样概率、样本权重和 token 分母写成同一个期望公式，再检查目标分布。对于混合任务，可以分别记录任务占比、有效回复 token 和梯度贡献代理，避免某类长文本仅凭长度统治训练。

<a id="sec-2-1"></a>

<a id="llm-2-detail-6"></a>

### 2.3 一个可直接运行的掩码实验

这个实验不训练真实语言模型，而用固定 logits 验证回复位置的监督语义。它既测试忽略位置不产生直接 logits 梯度，也测试目标位置仍能得到梯度。真实网络里提示表示可能经由回复损失获得梯度，那是条件信息通过网络传播的结果，并不与提示标签被忽略矛盾。

```python
import torch
import torch.nn.functional as F
torch.set_num_threads(1)
z = torch.tensor([[1., 0., -1.], [0., 2., 1.],
                  [1., 0., 2.], [2., 1., 0.]],
                 dtype=torch.float64, requires_grad=True)
labels = torch.tensor([-100, -100, 2, 0])
loss = F.cross_entropy(z, labels, ignore_index=-100)
manual = -torch.log_softmax(z, -1)[2:, :][torch.arange(2), labels[2:]].mean()
assert torch.allclose(loss, manual)
loss.backward()
assert torch.equal(z.grad[:2], torch.zeros_like(z.grad[:2]))
assert z.grad[2:].abs().sum() > 0
empty = labels.clone(); empty[:] = -100
assert (empty != -100).sum() == 0
print('sft_mask_loss', float(loss.detach()))
```

空回复不能直接沿用普通平均，因为分母为零。上面只检测该状态，真实训练器应选择报错、跳过并记录，或根据明确的数据规则修复。若默默把空样本当作零损失，训练曲线会被压低，监督量也被高估。数据质量检查因此要在模型优化前完成，而不是等到梯度异常时再猜测。

## 3. 偏好数据是有条件的比较观测

<a id="llm-2-detail-8"></a>

### 3.1 Bradley–Terry 模型与可识别性

对同一提示 $`x`$ 的候选 $`y_a,y_b`$，设潜在奖励为 $`r(x,y)`$，常见比较模型为

$$
P(y_a\succ y_b\mid x)=\sigma(r(x,y_a)-r(x,y_b)).
$$

比较只依赖差值，所以给同一提示的所有奖励加相同常数，不改变任何比较概率。奖励的绝对零点不可识别。若还有独立温度参数，奖励尺度与温度之间也存在混淆，需要固定约定。不能把奖励分数直接解释成跨任务可比的绝对正确概率。

该模型假设偏好可以由标量差通过逻辑函数描述。真实标注可能存在平局、循环偏好、标注者群体差异和上下文依赖。甲偏好简洁，乙偏好完整，把他们混在一起可能得到并不代表任何单个人的折中。数据应记录规则、候选来源、标注一致性和无法判断的情况，不应为了适应二元损失把所有平局强制变成确定胜负。

<a id="llm-2-detail-9"></a>

### 3.2 比较对图与未覆盖区域

如果某组候选只在组内比较，与另一组没有连接边，则两组相对奖励位置无法由数据确定。即使优化器输出了数值，也可能是初始化或正则化作出的选择。更普遍地，训练对只覆盖特定提示和候选分布，模型在其他输出上的奖励外推未必可靠。在线优化一旦主动寻找高奖励区域，就可能暴露这种外推缺陷。

候选生成策略也决定数据难度。若一个候选明显胡言乱语，排序很容易，却可能教不会模型区分两个都合理但细节不同的回答。若全部候选来自同一个模型版本，偏好模型可能缺少对未来新风格的覆盖。设计比较数据时，应将明显错误、细粒度差异、长度匹配和不同任务类型适度组合，并保留评价集中的独立候选来源。

## 4. 从正则化奖励优化推导最优策略

<a id="llm-2-detail-11"></a>

### 4.1 有限输出空间上的完整推导

固定一个输入 $`x`$，设参考策略 $`q(y)>0`$，目标策略为 $`p(y)`$，奖励有限，正则强度 $`\beta>0`$。考虑

$$
J(p)=\sum_y p(y)r(y)-\beta\sum_y p(y)\log\frac{p(y)}{q(y)}.
$$

在约束 $`\sum_y p(y)=1`$ 下，对每个 $`p(y)`$ 求驻点，得到 $`r(y)-\beta(\log(\frac{p(y)}{q(y)})+1)+\lambda=0`$。整理并归一化可得

$$
\begin{aligned}
p^*(y) &=\frac{q(y)\exp(\frac{r(y)}{\beta})}{Z},\\[6pt]
Z &=\sum_y q(y)\exp(\frac{r(y)}{\beta}).
\end{aligned}
$$

目标对策略分布是凹的，严格正参考支持下熵项给出合适的严格凹性，因此这个归一化解是最优解。也可写 $`J(p)=\beta\log Z-\beta KL(p\Vert p^*)`$，从 KL 非负性直接得到结论。有限空间推导避免了无穷序列中可积性与停止机制的技术问题；推广时必须确保分区函数有限。

<a id="llm-2-detail-12"></a>

### 4.2 参考支持与正则方向

若 $`q(y)=0`$ 而 $`p(y)>0`$，前向相对参考的 KL 项发散，因此有限目标下不能把概率质量放到参考零支持处。真实 softmax 在有限 logits 下通常给每个有限 token 序列正概率，但截断采样、硬约束和外部过滤会改变有效支持。推导里的参考策略和收集候选时的采样器不是同一个对象，必须分别记录。

这里使用的是 $`KL(p\Vert q)`$。把方向换成 $`KL(q\Vert p)`$，导数和最优解都会改变，不能继续照搬指数倾斜公式。正则强度也有具体含义：较大值更限制偏离参考，较小值使奖励差异更强烈地影响策略。在神经网络参数化和有限优化中，观测到的 KL 未必随一个超参数严格单调，仍需实际监测。

<a id="llm-2-detail-13"></a>

### 4.3 第二个实验：验证解析解而非宣称完成 RLHF

下面对三个离散回答直接计算最优分布，并验证目标与 KL 分解。实验没有奖励模型训练、在线环境、PPO 或真实语言生成，因此它检验的是策略空间上的解析公式。把验证范围说清楚，有助于在后续复杂实现中定位究竟哪一层引入了误差。

```python
import numpy as np
q = np.array([0.5, 0.3, 0.2], dtype=float)
r = np.array([0.0, 0.7, -0.2])
beta = 0.6
u = np.log(q) + r / beta
logz = np.max(u) + np.log(np.exp(u - np.max(u)).sum())
pstar = np.exp(u - logz)
def kl(p, ref):
    return np.sum(p * np.log(p / ref))
def objective(p):
    return p @ r - beta * kl(p, q)
assert np.isclose(pstar.sum(), 1)
assert np.isclose(objective(pstar), beta * logz)
for p in [q, np.array([0.2, 0.5, 0.3]), np.array([0.7, 0.1, 0.2])]:
    assert np.isclose(objective(p), beta * logz - beta * kl(p, pstar))
    assert objective(p) <= objective(pstar) + 1e-12
print('optimal_policy', pstar, 'objective', objective(pstar))
```

这个分解还给出一个有用诊断：若实际策略远离解析最优，差距可以由到最优策略的 KL 衡量。但对巨大语言输出空间，通常无法枚举全部回答或精确计算分区函数。奖励模型误差、采样误差和参数化约束也同时存在，不能把小空间里的精确恒等式当作真实训练已经达到最优的证明。

## 5. DPO 的推导与实现边界

<a id="llm-2-detail-15"></a>

### 5.1 从奖励重参数化到比较损失

由上式有 $`r(x,y)=\beta\log[\frac{p^*(y\mid x)}{q(y\mid x)}]+\beta\log Z(x)`$。同一输入下两个回答相减，分区函数项消失。将这个奖励差代入逻辑比较模型，并用可训练策略代替理想策略，得到

$$
L_{DPO}=-\log\sigma\left(\beta\left[\log\frac{\pi_\theta(y_w\mid x)}{q(y_w\mid x)}-\log\frac{\pi_\theta(y_l\mid x)}{q(y_l\mid x)}\right]\right).
$$

其中胜者和败者必须针对相同提示及相同条件协议。原始 DPO 的序列 log 概率是回复 token 条件 log 概率之和，包括哪些特殊标记应预先定义。随意改成按长度平均，会改变目标；它可能是研究变体，但不能声称与上述完整序列推导完全相同。

<a id="llm-2-detail-16"></a>

### 5.2 梯度在做什么

设括号内策略相对参考的差为 $`\Delta`$，则损失对 $`\Delta`$ 的导数为 $`-\beta\sigma(-\beta\Delta)`$。当策略尚未充分偏向胜者，梯度较大；已明显区分后，梯度变小。这是在调整胜败相对优势，不保证胜者绝对概率每一步都增加。softmax 归一化、多样本共享参数和其他损失项会使绝对概率变化更复杂。

偏好数据可分且没有额外约束时，逻辑损失可能持续推动比较间隔扩大，没有有限参数最优点。训练损失接近零不意味着模型的真实质量已经饱和，也可能只是把训练比较对记住。应监测独立偏好、任务正确性、与参考的分布偏移和输出行为，必要时使用早停或其他明确正则，而不是单纯追求更小训练损失。

<a id="llm-2-detail-17"></a>

### 5.3 第三个实验：两候选 DPO 与手算方向

该实验用两个候选的可训练 logits，参考概率不相等。它验证稳定的逻辑损失、相对参考的优势方向以及胜者概率上升。最后一个现象在这个极小、单比较对的设置中成立，不应推广为任意复杂 DPO 训练的定理。参考分布被固定，不参与梯度更新。

```python
import torch
import torch.nn.functional as F
torch.set_num_threads(1)
logits = torch.nn.Parameter(torch.zeros(2, dtype=torch.float64))
ref = torch.tensor([0.8, 0.2], dtype=torch.float64).log()
beta = 0.4
opt = torch.optim.SGD([logits], lr=0.3)
def terms():
    lp = torch.log_softmax(logits, dim=0)
    delta = (lp[0] - ref[0]) - (lp[1] - ref[1])
    return delta, F.softplus(-beta * delta)
d0, l0 = terms(); before = l0.item()
l0.backward()
assert logits.grad[0] < 0 and logits.grad[1] > 0
opt.zero_grad()
for _ in range(160):
    opt.zero_grad(); delta, loss = terms()
    loss.backward(); opt.step()
d1, l1 = terms()
assert d1.item() > d0.item() and l1.item() < before
assert logits.softmax(0)[0].item() > 0.9
assert not ref.requires_grad
print('dpo_losses', before, l1.item(), 'winner_p', logits.softmax(0)[0].item())
```

若把胜败顺序反过来，梯度方向也应反过来；若交换两个回答时没有交换掩码或参考概率，损失可能仍下降，却在优化错误目标。最小单元测试应覆盖对称交换、同分输入、极端间隔和参考恒定性。复杂训练中还应核验每个回复的 log 概率是否只覆盖助手答案，避免把不同提示长度误计入偏好差。

## 6. RLHF 训练链路中的估计与偏差

<a id="llm-2-detail-19"></a>

### 6.1 奖励模型、策略优化与评价器

一个常见链路先用示范得到初始策略，再用比较数据训练奖励模型，最后在带正则的目标下优化策略。奖励模型是偏好监督的估计器，策略优化器会主动寻找它给高分的输出；最终评价器则用于判断实际质量。若三者使用完全重叠的数据和特征，系统很容易只对内部评分器变得擅长。

优化奖励并不等于优化真实偏好，因为奖励只是有限数据上训练的代理。输出一旦进入训练候选之外的区域，奖励误差可能变得很大。更高的代理分数和更差的人工体验可以同时发生。应保留独立人评或可验证任务指标，监测随着优化强度增加而出现的分歧，而不能用奖励曲线上升作为唯一成功依据。

<a id="llm-2-detail-20"></a>

### 6.2 重要性比率与在线数据

策略更新中若使用旧策略采样的轨迹，新的策略概率与旧策略概率之比可以用于某些期望的修正。但需要旧策略在新策略关心的区域有支持，还需要控制方差。序列概率比是各 token 比率的乘积，长回复可能带来极大方差。剪裁或其他稳定化会改变估计偏差与方差，不能把实现中的所有近似都称为无偏。

本章不实现完整 PPO，因此不把离散解析实验包装成在线强化学习。理解 PPO 至少还需要状态、动作、优势估计、旧策略固定窗口、价值函数和截断目标等定义。若项目只是离线比较数据上的 DPO，应如实记录，而不是因为训练目标包含“偏好”就宣称已搭建完整的人类反馈强化学习系统。

<a id="llm-2-detail-21"></a>

### 6.3 长度、风格与标注者捷径

更长回答常有更多解释机会，也更容易显得认真，但长度本身不是质量。若胜者系统性更长，偏好训练可能学到冗长。可以构建长度匹配的比较对、单独标注信息完整度与冗余、按任务长度分层报告，并检查模型是否为了高分重复结论。简单除以长度并非普遍解法，因为它也可能惩罚必要推导。

风格偏差同样重要。固定开场、礼貌用语和分段格式可能与胜者标签高度相关，模型因而优先复制表面特征。反事实测试可以保持内容不变只交换格式，或者保持格式不变交换正确与错误细节。如果评价器仍追随格式，说明它没有充分衡量目标内容。训练数据的标注准则应把这些维度拆开，而不是让一个笼统“更好”标签承担全部含义。

## 7. LoRA：限制可训练更新的秩

<a id="llm-2-detail-23"></a>

### 7.1 参数化与参数数量

设原线性层权重 $`W_0\in\mathbb R^{d_o\times d_i}`$，低秩更新写成

$$
\begin{aligned}
W &=W_0+sBA,\\[6pt]
A &\in\mathbb R^{r\times d_i},\quad B\in\mathbb R^{d_o\times r}.
\end{aligned}
$$

原始权重冻结，训练参数为 $`r(d_i+d_o)`$，缩放 $`s`$ 常按一个预先固定的规则设定。只有当秩远小于输入输出维度时，参数量才明显下降。低秩更新的秩不超过 $`r`$，但经过多层非线性组合后，整个网络函数的变化不等于一个简单的全局低秩映射。

LoRA 不要求原始权重本身低秩，而是假设某些任务所需的适应可以用受限更新较好表示。若任务需要的变化不在可表达集合内，增加训练时间也不能弥补全部偏差。不同层、不同投影位置和不同秩的选择会改变容量与成本；把所有模块都设同一个秩只是一个配置，不能自动称作理论最优。

<a id="llm-2-detail-24"></a>

### 7.2 完整梯度与初始化陷阱

设损失对有效权重的梯度为 $`G`$，则 $`\nabla_B L=sGA^T`$，$`\nabla_A L=sB^TG`$。常见初始化让 $`A`$ 随机、$`B`$ 为零，这样初始更新为零，模型函数与基座一致；第一次反向中 $`A`$ 的梯度为零，而 $`B`$ 通常非零。更新 $`B`$ 之后，$`A`$ 才能获得非零梯度。不能因为首步某个因子梯度为零就认定训练坏了。

若两个因子都初始化为零，两个梯度也同时为零，普通一阶优化无法启动。若两个都随机，初始函数就可能偏离基座。缩放还会影响有效梯度大小，秩变化时不应只比较参数量而忽略初始化方差、学习率和缩放规则。公平实验应记录这些配置，并测量有效更新范数而不仅仅看因子范数。

<a id="llm-2-detail-25"></a>

### 7.3 第四个实验：零初始化、冻结与合并

本实验用二维线性回归验证梯度公式和训练后权重合并。目标更新本来就是秩一，因此秩一参数化具有足够表达能力；这是一项受控机制演示，不能据此推出真实大模型所有任务都只需秩一。基座张量不参与优化，实验同时断言其值没有改变。

```python
import torch
torch.set_num_threads(1)
torch.manual_seed(23)
dtype = torch.float64
x = torch.randn(128, 2, dtype=dtype)
w0 = torch.tensor([[1., 0.], [0., 1.]], dtype=dtype)
base_copy = w0.clone()
target_delta = torch.tensor([[0.4, -0.2], [0.8, -0.4]], dtype=dtype)
y = x @ (w0 + target_delta).T
A = torch.nn.Parameter(torch.randn(1, 2, dtype=dtype) * 0.1)
B = torch.nn.Parameter(torch.zeros(2, 1, dtype=dtype))
s = 1.0
opt = torch.optim.Adam([A, B], lr=0.05)
loss = ((x @ (w0 + s * B @ A).T - y) ** 2).mean()
loss.backward()
assert torch.equal(A.grad, torch.zeros_like(A.grad))
assert B.grad.abs().sum() > 0
opt.zero_grad()
for _ in range(700):
    opt.zero_grad()
    loss = ((x @ (w0 + s * B @ A).T - y) ** 2).mean()
    loss.backward(); opt.step()
merged = w0 + s * B.detach() @ A.detach()
separate = x @ w0.T + s * (x @ A.detach().T) @ B.detach().T
assert torch.allclose(separate, x @ merged.T, atol=1e-12)
assert torch.equal(w0, base_copy) and not w0.requires_grad
assert loss.item() < 1e-8
# 两个因子都为零会卡住。
a = torch.zeros(1, 2, dtype=dtype, requires_grad=True)
b = torch.zeros(2, 1, dtype=dtype, requires_grad=True)
((x @ (w0 + b @ a).T - y) ** 2).mean().backward()
assert torch.equal(a.grad, torch.zeros_like(a))
assert torch.equal(b.grad, torch.zeros_like(b))
print('lora_final_mse', loss.item())
```

合并等价要求没有仍在生效的随机适配分支，基座、缩放和矩阵方向一致，并考虑数值舍入。若训练时使用适配分支 dropout，推理关闭随机性后才讨论确定性合并。量化基座与合并后重新量化还会引入额外误差，所以“可合并”不是保证任意精度转换都逐位相同。应在固定参考输入上比较输出和任务结果。

<a id="lora-first-update-geometry"></a>

### 7.4 LoRA 首步怎样选择有效权重方向

初始 $`B_0=0`$、$`A_0`$ 随机时，“先更新 B”还能给出更具体的有效权重变化。设使用同一学习率 $`\eta`$ 的普通 SGD，无动量、无衰减，并以 $`G_0`$ 表示损失对有效权重的梯度。首步有 $`B_1=-\eta sG_0A_0^T`$、$`A_1=A_0`$，因而

$$
\Delta W_1=sB_1A_1=-\eta s^2G_0A_0^TA_0.
$$

这不是任意全参数 SGD 步 $`-\eta G_0`$，而是由初始 $`A_0`$ 的行空间筛选、缩放过的方向。若 $`A_0`$ 的行正交归一，$`A_0^TA_0`$ 是输入空间投影；若行不正交，它只是半正定矩阵，不能不加条件地叫正交投影。初始随机子空间因而参与了优化几何，后续 $`A`$ 获得梯度后该子空间也可改变，并非永远固定。

取 $`G_0=\begin{pmatrix}1&2\\3&4\end{pmatrix}`$、$`A_0=(1,0)`$、$`s=1`$、$`\eta=0.1`$，首步得到 $`\Delta W_1=\begin{pmatrix}-0.1&0\\-0.3&0\end{pmatrix}`$。第二输入坐标暂时完全没变，即使它的全参数梯度并不为零。若把 $`A_0`$ 放大十倍而保持 $`B_0=0`$，初始网络仍完全相同，但这个首步有效更新放大一百倍。因此“起始输出相同”不足以保证两种初始化具有可比较的训练尺度。

Adam、不同因子学习率或因子衰减会改变上式，不能把它当所有 LoRA 优化器的精确迭代公式。它的用途是解释为什么比较秩、缩放和初始化时应记录有效更新范数与层输出变化，不能只对齐可训练参数数目。对连续几步同时更新两个因子，还会出现因子变化的乘积项；想核对实际轨迹，应每步重新计算合并更新，而非把两个因子的范数相乘当作函数变化的精确度量。

## 8. 参数高效不等于所有资源都按比例下降

<a id="llm-2-detail-27"></a>

### 8.1 冻结参数仍参与前向与反向路径

冻结基座可以减少其梯度和优化器状态，但网络仍需执行基座前向运算。为使较早的适配层获得梯度，还可能需要通过冻结层传播输入梯度，保留相应激活。可训练参数减少很多，并不意味着总训练时间和内存按同样比例减少。瓶颈可能转移到激活、序列长度或数据吞吐。

如果只在最后一层训练小头，早期冻结网络的表示可以缓存，但前提是输入预处理和基座都固定，且没有需要重新采样的数据增强或上下文变化。对于在多层加入 LoRA 的模型，缓存最后表示通常不再有效，因为适配层已经改变中间计算。资源优化必须与实际计算图对应，而不能仅凭“冻结”二字推断可以省去全部反向。

<a id="deep-dive-5"></a>

<a id="llm-2-detail-28"></a>

### 8.2 与全量微调、提示调整和检索的比较

全量微调有更大的参数更新空间，可能适应更深变化，也需要更多存储和更强约束来防止遗忘。LoRA 限制更新空间，便于保存多个任务差量，但秩和注入位置会限制能力。软提示主要改变条件输入中的可训练向量，不能直接改动全部内部权重。检索则提供外部证据，解决知识更新和来源可追溯的问题，与改变模型参数具有互补性。

如果模型缺少某个实时事实，优先考虑给它可核验的上下文，未必需要微调；如果它知道事实却总不按指定结构输出，指令数据可能更直接；如果目标是改变偏好取舍，可以研究比较学习。把所有问题都交给一次微调，会掩盖错误的来源。先建立失败分类，再选择干预层次，通常比先挑方法再找应用更有效。

<a id="llm-2-detail-29"></a>

### 8.3 秩、缩放和学习率的公平对照

比较不同秩时，若缩放保持固定，因子初始化方差和有效更新幅度可能随秩改变；若缩放按秩变化，又引入另一个影响梯度的因素。因此实验应明确比较的是某个完整配置族，而不是声称纯粹测量了秩的因果效果。可以同时记录初始输出差、首步更新范数、训练曲线和最终独立评价，以解释结果。

相同训练步数不保证相同计算预算，相同学习率不保证相同优化难度。公平比较可以分别给出固定 token 预算和固定实测时间预算，但二者回答不同问题。若每个方法允许的调参次数不同，最终最好分数还会包含选择优势。应报告搜索范围、选择集和最终测试边界，让方法比较具有可复查的依据。

## 9. 训练验收要看完整行为而不是单一损失

<a id="llm-2-detail-31"></a>

### 9.1 四层评价矩阵

首先评价数据和管道：模板、角色、掩码、重复、长度和划分是否正确。其次评价优化：梯度是否有限、预期参数是否更新、基座是否冻结、损失是否符合手算。再评价独立任务：正确率、格式约束、证据使用和拒答取舍。最后评价部署行为：同一权重配不同模板、精度和适配版本是否仍满足接口契约。

每层都有独立失败模式。训练 loss 降低可能伴随格式正确率下降；偏好胜率提高可能伴随事实错误增多；低秩参数更新正常也可能是加载了错误基座。验收报告应保留模型、分词器、模板、适配器和解码配置的组合标识。仅保存一个权重文件名，不足以描述可执行模型的完整身份。

<a id="llm-2-detail-32"></a>

### 9.2 遗忘与回归测试

任务适应可能损害原有能力，因此需要冻结一组基础回归任务。回归集应覆盖希望保留的语言、格式和功能，而不是只挑适配任务附近的样本。若训练数据中故意提高某种回答风格权重，其他风格变差可能是目标冲突，而非随机故障。报告应指出哪些能力是硬约束，哪些允许交换，以及选择依据。

不要在每次看到回归失败后直接把对应题加入训练，再继续用同一题声称通过独立测试。可以将发现的失败纳入开发回归集，同时保留另一个未参与修复的测试边界。长期项目需要分版本管理这些集合，避免“所有失败最终都被训练过”造成虚假的稳定进步。

<a id="llm-2-detail-33"></a>

### 9.3 解释失败时的优先顺序

先检查数据与标签，再检查前向协议和损失，随后检查优化器参数组、梯度和学习率，最后才讨论模型容量不足。若连一小批人工样本都无法拟合，扩大数据往往只会放大问题。反过来，小批完全拟合也不证明泛化，需要独立样本。将这些检验分层，可以避免用昂贵训练替代简单的实现核对。

对于偏好学习，再检查胜败顺序、同一提示约束、参考模型固定、回复概率掩码和长度分布。对于 LoRA，检查注入模块是否真正被调用、因子是否进入优化器、合并是否重复执行以及适配器是否与基座匹配。一个适配器被重复相加两次，输出仍可能流畅，因此要用固定参考向量而非肉眼判断加载成功。

<a id="llm-2-detail-34"></a>

## 10. 进阶练习与详细解答

<a id="llm-2-detail-35"></a>

### 10.1 题一：示范与偏好是否等价

题目：只有“甲优于乙”的标签，能否把甲直接当作唯一正确示范？

解答：可以把它构造成一种额外训练方案，但信息含义已经变化。比较只说明相对偏好，甲可能仍有事实错误，也可能只是比乙少错一点。唯一示范的交叉熵会强化甲的全部 token，未必只强化造成偏好差的部分。应结合绝对质量筛选或额外标注，再说明从比较转示范的假设。否则容易把比较数据中的残留错误当成标准答案。

<a id="llm-2-detail-36"></a>

### 10.2 题二：提示忽略后的梯度

题目：提示标签全部设为忽略值，提示嵌入是否一定没有梯度？

解答：不是。提示位置没有直接预测损失，但回复的表示可能通过注意力依赖提示，因此回复损失可以沿计算图回传到提示嵌入。实验一只断言独立 logits 上忽略位置梯度为零，不能直接推广到共享网络参数。应区分“该位置没有直接监督”和“该位置不影响任何受监督输出”两种陈述。

<a id="llm-2-detail-37"></a>

### 10.3 题三：奖励平移不可识别

题目：给某输入下每个候选奖励都加七，比较概率和正则最优策略是否改变？

解答：比较差值不变，逻辑偏好概率不变。指数倾斜中分子都乘相同常数，分区函数同乘该常数，归一化策略也不变。目标值整体加七，但最优策略不变。这说明奖励零点不能由同输入比较识别。不同输入若各自允许任意平移，绝对奖励均值也需要额外约定才可解释。

<a id="llm-2-detail-38"></a>

### 10.4 题四：KL 方向的影响

题目：为什么不能把正则中的两个分布交换后继续使用同一个解析解？

解答：对 $`KL(p\Vert q)`$ 求导包含 $`\log(\frac{p}{q})+1`$，从而得到指数倾斜。对 $`KL(q\Vert p)`$ 求导则含 $`-\frac{q}{p}`$，驻点方程形式不同。两种正则还对支持缺失和概率质量的分配施加不同惩罚。若改变方向，应从新目标重新推导，而不是只替换公式中的符号名称。

<a id="llm-2-detail-39"></a>

### 10.5 题五：DPO 的参考项能否删除

题目：如果胜败参考概率不相等，删除参考 log 概率差会有什么后果？

解答：目标将不再优化相对参考的优势，而变成直接扩大策略胜败序列概率差。参考原本对两个回答的偏好会影响需要纠正的幅度。实验三参考更偏向胜者，初始均匀策略相对于参考反而不够偏向胜者；删除参考项会改变初始比较间隔和梯度。只有在特定参考差为零等条件下两者才局部一致。

<a id="llm-2-detail-40"></a>

### 10.6 题六：序列和与长度平均

题目：把每条回复 log 概率除以长度，是否只是数值缩放？

解答：当不同回复长度不同，这不是统一常数缩放，而是对每个候选施加不同变换，可能改变胜败间隔和排序。原始推导使用完整序列概率，因此长度平均属于新目标。它可以用于研究长度偏差，但需要重新说明理论含义、比较基线与评价，不应假称保持所有原结论。

<a id="llm-2-detail-41"></a>

### 10.7 题七：DPO 损失下降意味着什么

题目：训练偏好损失接近零，能否证明模型的绝对回答质量很高？

解答：不能。它主要说明训练比较对的相对间隔被拉大。若胜者本身错误，或训练对存在风格捷径，损失仍可下降。还可能出现未见输出上的分布变化。应使用独立事实任务、长度分层偏好和行为回归，检查目标是否真正迁移到希望的质量维度。

<a id="llm-2-detail-42"></a>

### 10.8 题八：LoRA 参数量

题目：输入输出维度都是一千，秩为八，低秩因子有多少参数？与完整矩阵相比约占多少？

解答：参数量为八乘两千，即一万六千；完整矩阵有一百万，占比百分之一点六。这里未计偏置、其他可训练模块和优化器状态，也没有计算冻结权重本身的存储。因而只能说该矩阵的新增可训练参数减少，不能直接推出总训练内存同样减少到百分之一点六。

<a id="llm-2-detail-43"></a>

### 10.9 题九：双零初始化

题目：两个低秩因子都为零时，为什么普通梯度下降无法启动？

解答：对任一因子的梯度都乘另一个因子。两者都为零时，两边梯度同时为零，下一步仍为零，形成停滞。让一个因子随机而另一个为零，可以保持初始有效更新为零，同时允许零因子首先获得梯度。这个设计体现了函数保持与可学习性之间的配合，而不是随意的初始化习惯。

<a id="llm-2-detail-44"></a>

### 10.10 题十：因子范数与有效更新

题目：把 $`A`$ 乘十、$`B`$ 除以十，有效权重是否改变？优化过程是否完全一样？

解答：乘积 $`BA`$ 不变，所以当缩放和其他因素固定时，当前确定性函数不变。但各因子的梯度尺度、权重衰减和优化器状态会改变，后续路径不一定相同。这是一种参数化不唯一性。监测时应关注有效更新范数和输出变化，不能仅凭某个因子变大就断言模型函数发生同等放大。

<a id="llm-2-detail-45"></a>

### 10.11 题十一：低秩和任务容量

题目：目标权重差的秩为二，而只允许秩一更新，在线性全覆盖数据上能否精确表示？

解答：一般不能，因为任何秩一乘积的矩阵秩至多为一。若输入只位于某个子空间，两种矩阵在该子空间上的作用仍可能相同，所以“数据上不能精确拟合”还需要覆盖条件。应区分矩阵全空间表示能力和有限数据上的可观测函数差异。这也解释了有限训练误差低并不保证所有输入都适配正确。

<a id="llm-2-detail-46"></a>

### 10.12 题十二：冻结与反向计算

题目：基座权重冻结，是否可以把整个基座前向放在无梯度上下文里？

解答：若需要梯度穿过这些运算到达更早的可训练适配层，就不能随意切断计算图。冻结权重只是不求该参数的梯度，不等于不求输入梯度。只有当其输出确实作为固定特征且上游无待训练参数时，才可安全按相应边界停止梯度。应根据计算图判断，而不是依据模块名称。

<a id="llm-2-detail-47"></a>

### 10.13 题十三：偏好长度捷径

题目：胜者平均长度是败者两倍，怎样检验模型是否主要学了冗长？

解答：构造长度匹配对照，并对同一内容制作简洁与冗余版本；同时保留需要详细解释的任务，避免把短答案直接定义为好。按长度区间报告独立偏好与事实正确率，观察冗余增加是否仍获高分。若评价器只追随长度，就需要修改标注或评价维度，而不只是给生成长度设硬上限。

<a id="llm-2-detail-48"></a>

### 10.14 题十四：适配器加载验收

题目：加载未报错且输出流畅，是否足以证明适配器正确？

解答：不够。可能加载到错误基座、错误模块、错误缩放，或根本未进入前向。应核对配置与参数名，比较固定输入下基座、分支和合并输出，验证适配参数改变能影响目标输出，并检查是否重复合并。对于精度转换，设置合理的数值容差，再跑任务回归，不能只凭一条自然语言样本判断。

<a id="sec-7-1"></a>

<a id="llm-2-detail-49"></a>

### 10.15 题十五：独立评价的边界

题目：每次发现测试失败就加到训练，再在原测试集上报告提高，有什么问题？

解答：原测试集已参与模型选择和修复，变成开发资料。进步可以作为回归修复记录，但不再是独立泛化证据。应另保留未参与修改的集合，或按冻结时间创建新测试。记录题目何时进入训练或开发能够保留证据链，避免长期迭代后忘记数据边界。

<a id="llm-2-detail-50"></a>

### 10.16 题十六：设计一个可解释的方法比较

题目：比较全量微调与 LoRA，怎样避免把调参预算差当成方法优势？

解答：固定训练与选择数据，预先定义各方法搜索空间和允许试验次数，同时报告参数、token 预算和实测耗时。按独立开发指标选配置，最后一次评估冻结测试，并给出逐题差异与回归能力。若某方法用了更多搜索资源，应明确报告。可以分别比较固定计算预算和各自充分调参的结果，但不要把两种问题混为一个结论。

<a id="llm-2-detail-51"></a>

## 11. 综合研究：从目标到可交付配置

先构造有限候选任务，把每个输入的所有回答概率完整列出，用解析奖励倾斜求参考最优，再用 DPO 学习比较。研究偏好对覆盖不足、错误标签和参考支持变化时的结果。由于候选空间可枚举，可以直接计算真实奖励、训练偏好损失和 KL，而不是只靠一个代理指标猜测。这个阶段应优先获得清楚结论，而非增加网络规模。

再把策略参数化为一个小型共享网络，逐步引入参数耦合，观察某个输入的更新如何影响其他输入。最后比较全量参数与低秩更新，保留相同数据和评价边界。每一步都应写出新增近似：从分布空间到参数空间、从完整比较到稀疏比较、从精确期望到采样估计。这样才能解释理论目标与实际训练之间的差距。

<a id="sec-8-1"></a>

<a id="llm-2-detail-52"></a>

### 11.1 研究报告的最小证据集

报告应包括任务定义、数据来源与划分、模板与监督掩码、参考模型身份、候选采样策略、损失公式、参数更新集合和选择协议。结果部分同时给出优化诊断、独立任务指标、长度与风格分层、保留能力回归以及失败例子。对本章四个 CPU 实验，应明确它们分别验证掩码、解析策略、DPO 方向和低秩机制，没有训练真实大模型。

最终交付要能从配置还原完整函数：基座、分词器、模板、适配器、精度和解码共同决定行为。保存可执行参考输入和期望输出，检查合并前后及重新加载后的差异。训练日志与中间模型应根据诊断和恢复需求归档。本章代码在内存中构造小型对象，不依赖下载模型或外部服务；扩展到真实基座时，仍需逐项核对这些依赖。

<a id="llm-2-detail-53"></a>

## 12. 进一步推导：序列目标与估计误差

<a id="llm-2-detail-54"></a>

### 12.1 回复似然的分解与掩码一致性

完整回复的 log 概率是每个位置条件 log 概率的和。比较两个回答时，提示本身相同，所以若错误地把提示似然也加进去，在理想一致实现中它可能抵消；但不同长度拼接、填充、截断或模板处理会使这种抵消不再可靠。因此正确做法仍然是明确回复掩码，而不是依赖偶然抵消。参考模型与策略必须对相同 token ID、相同前缀和相同有效位置评分。

尤其注意结束标记。两个答案内容相同但一个未正常结束，如果评分不包含结束相关位置，可能无法反映停止行为。反过来，若在截断样本末尾人工添加正常结束标签，就会把预算限制伪装成自然停止。数据构造应保留原始停止原因，并在偏好对中检查截断是否与胜负标签相关，否则模型可能学习一种由采集流程引入的长度偏差。

对于多轮对话，回复概率是条件于此前历史的概率；如果前文包含模型自己生成的错误，训练时是否保留这些历史会改变任务分布。只在完美示范历史上训练，部署却面对自身失误累积，可能出现明显差距。可以设计带纠错历史的任务，但应避免把未来纠正答案提前放入模型可见前缀。任何修复型样本都要逐位置核对因果边界。

<a id="llm-2-detail-55"></a>

### 12.2 DPO 在二候选空间中的精确解释

如果某个输入只有两个回答，其策略可由一个 logit 差表示，参考也有一个固定差。比较标签中胜者比例为 $`\rho`$ 且介于零和一之间，逻辑交叉熵的最优比较 logit 为 $`\log[\frac{\rho}{(1-\rho)}]`$。因此最优策略相对参考的 log 概率差应等于这个值除以正则系数。这个结论在单输入、完全自由策略和稳定标签分布下成立，提供了一个可手算的校验对象。

当所有比较都把同一回答判为胜者，比例为一，逻辑最优间隔趋于无穷。有限优化会停在某个很大的间隔，而不是存在一个自然有限的最佳参数。若加入标签平滑、正则或早停，才得到不同的有限约束。不能把这些不同处理产生的数值差异全部归因于优化器不够好；首先应检查目标本身是否有有限极小值。

真实语言模型中多个输入共享参数、回答空间巨大，独立二候选的最优条件可能无法同时满足。某个比较对的更新会通过共享表示影响其他对，可能产生互相帮助，也可能冲突。可以用梯度内积作为局部冲突诊断，但它只反映当前参数附近的一阶关系，不等于长期训练结果。研究应结合逐任务曲线与最终回归，而不把单步角度当作完整解释。

<a id="llm-2-detail-56"></a>

### 12.3 偏好噪声、平局与软标签

若标注者对某一对回答选择甲的比例为零点六，使用软标签可以保留这种不确定性，而不是把多数票变成完全确定胜利。二元交叉熵在正确事件定义和足够数据下会鼓励预测该选择比例。但如果标注者来自不同人群，零点六可能表示群体分歧，而非同一个人的随机噪声。这两种解释在部署时有不同含义，应尽可能保留群体或任务条件。

平局还可能表示两者都好、两者都差或无法比较。把这三类全写成五五概率会丢失绝对质量与可比性信息。更完整的数据设计可以设置额外标签，或先判断最低质量门槛，再进行相对比较。复杂标注体系会增加成本，因此需要根据目标错误选择必要维度，而非无限增加标签。关键是承认二元比较不是对全部质量结构的无损压缩。

对明显矛盾的比较循环，应先调查是否存在上下文遗漏或标准不一致。例如甲更简洁、乙更完整、丙更谨慎，不同任务上偏好次序可能改变。若把任务条件压缩掉，任何标量奖励都只能折中。把条件补全有时比更换优化算法更有效。模型不能凭空修复监督协议没有表达的价值标准。

<a id="llm-2-detail-57"></a>

### 12.4 奖励误差怎样被策略优化放大

设真实奖励为 $`r`$，估计奖励为 $`\hat r=r+\epsilon`$。两个指数倾斜策略的比值包含误差项的指数以及归一化修正。即使训练候选上的平均误差不大，某些罕见输出上的正误差也可能被优化器主动利用。因为策略不是被动接受固定数据分布，而是在寻找高估区域，所以离线均方误差小不足以保证优化后质量。

在有限输出且误差绝对值一致受界的理想条件下，可以推导对最优策略和值函数的稳定性界；但真实输出空间通常缺少这种全局误差界。实践中应把优化强度逐级增加，观察代理奖励与独立评价是否开始分离，并检查新出现的高奖励输出。若发现分离，应调查奖励支持与标注标准，而不是继续把更大代理分数当进步。

一个简单可证伪的实验是人为给某个无用格式添加奖励偏差，看策略是否逐渐集中于该格式。然后用完全独立的真实任务评价验证实际效用没有同步提高。这能演示代理优化风险，但不能据此断言所有奖励学习都会失败。研究结论应限定于误差结构与优化压力，而不是对整个方法族作无条件评价。

<a id="llm-2-detail-58"></a>

## 13. 低秩适配的几何与优化细节

<a id="llm-2-detail-59"></a>

### 13.1 秩约束和最佳近似的关系

若我们直接希望用秩不超过 $`r`$ 的矩阵逼近某个目标更新，并以整个矩阵的 Frobenius 误差衡量，截断奇异值分解给出最佳低秩近似，剩余误差由被舍弃奇异值的平方和描述。但真实神经网络训练损失不是对权重差的均匀矩阵误差。输入分布、下游非线性和参数耦合都会改变重要方向，因此不能直接用权重奇异值尾部作为任务性能的完整预测。

在线性回归里，预测误差涉及输入协方差。某个权重方向数值很大，但输入几乎从不沿该方向变化，它对数据上的预测影响可能很小；反之，一个小权重差若作用于高方差输入，可能很重要。这说明低秩容量应结合数据分布分析。实验四选择全秩随机输入与秩一目标，使机制尽量清楚，但真实任务的有效维度需要另外检验。

<a id="llm-2-detail-60"></a>

### 13.2 因子化的不唯一性与正则化

对任意可逆的秩维变换 $`R`$，把两个因子改为 $`RA`$ 与 $`BR^{-1}`$，乘积保持不变。这种参数化自由度使因子范数和条件数可能变化，而函数暂时不变。对两个因子分别施加权重衰减，等价于在参数化空间中施加约束，并不等同于直接对有效更新施加普通平方范数惩罚。不同正则会偏向不同分解与优化路径。

因此保存检查点时，因子的形状、缩放和精度都属于必要元数据。只保存乘积可以复现某个合并后的确定性权重，却无法无损恢复原优化器状态和后续训练路径。若项目需要继续训练，应保存相应状态；若只需推理，可以选择合并形式，但要重新验证数值与接口。这是训练可恢复性和推理可复现性两个不同要求。

<a id="llm-2-detail-61"></a>

### 13.3 模块选择与计算图覆盖

在注意力中只适配查询和值投影，与适配全部投影或前馈层，改变的是允许更新的函数路径。模型可能通过多层组合补偿某些限制，但这种补偿是否容易学到取决于任务和数据。不能仅凭最终可训练参数相同，就认定两种注入位置具有同等表达能力。合理比较应记录具体模块名和每层秩，并检查实际挂接数量。

自动匹配模块名时尤其容易出现静默错误。一个名称过滤器可能在新模型版本里少匹配一层，或匹配到不希望改变的输出头。应列出匹配结果，断言数量与形状，再做一个局部扰动测试：改变某个适配因子应影响预期路径的输出。若训练损失仍能下降，也不能证明所有预定模块都参与；其他可训练部分可能掩盖缺失。

<a id="llm-2-detail-62"></a>

### 13.4 合并、反合并与精度边界

在精确算术和固定配置下，把低秩乘积加进基座与保留分支计算等价。在浮点算术中，先做两次矩阵乘与先合并再乘可能具有不同舍入顺序，逐位一致通常不是合理要求。应设置与输出尺度匹配的绝对和相对容差，并特别检查阈值附近的分类或结构化行为，避免小数差异跨过离散决策边界。

重复执行合并会把更新加两次；先合并又忘记禁用分支也会造成同样问题。反合并在有限精度下也可能不能完全恢复原值，因此频繁来回操作会积累误差。更可靠的流程是保留不可变基座与单独适配器，根据明确状态创建推理权重，并用参考样本断言合并仅发生一次。状态管理问题不应交给自然语言输出是否流畅来发现。

<a id="llm-2-detail-63"></a>

## 14. 数据设计中的高级对照

<a id="llm-2-detail-64"></a>

### 14.1 任务泄漏与模板泄漏

即使训练和测试文本没有逐字重复，同一问题生成器、答案模板和来源风格也可能泄漏捷径。若所有正确回答都含某个结尾，模型可通过表面形式学习比较。应该把模板与标签交叉组合，检查在去掉风格线索后是否仍能区分内容。对于代码和数学任务，可以用执行或精确规则评价，但执行环境与边界样例也必须固定。

将题目族作为划分单位，比按回答行随机切分更有说服力。同一提示的多个候选应处于同一个分区，否则模型可能在训练中见过测试问题的其他答案。若研究跨来源泛化，还应保留完整来源外推集。划分越严格，任务通常越难，但这正是识别数据记忆和方法迁移的重要信息，不能在分数下降后随意放松边界。

<a id="llm-2-detail-65"></a>

### 14.2 负例难度与课程安排

容易负例能帮助早期学习基本格式，却可能在后期提供很少信息。困难负例更能区分细节，但若标注可靠性不足，可能引入大量噪声。课程安排可以先覆盖基本规范再增加细粒度比较，不过这也是一种数据分布随时间改变的训练方案，应记录各阶段和选择依据。不能只展示最后阶段的数据比例，却把整个过程当成固定分布训练。

困难负例还应区分“模型难判断”与“人也难判断”。前者可能有明确证据，适合训练；后者可能存在价值冲突或信息不足，应允许不确定标签。把所有含糊题都强制标成确定胜负，会让模型学到虚假的自信。质量控制包括复核分歧、保存理由和检查标注者是否具备必要知识，而非单纯追求更多比较条数。

<a id="llm-2-detail-66"></a>

### 14.3 偏好优化与可验证任务的配合

当任务有明确答案或可执行测试时，偏好评价可以补充可读性和完整性，但不应替代正确性验收。一个回答文字优美却程序测试失败，应保留这个事实维度。反过来，程序通过有限测试也不证明覆盖所有输入，仍需边界案例和需求检查。不同监督信号应根据其可观察范围分工，而不是让某一个评分器决定所有质量。

可以先设硬约束筛除无效候选，再在有效候选中做软偏好排序；也可以用多指标报告而不压成单一分数。若必须聚合，权重和最低门槛需要由任务需求定义。任何聚合都会隐藏某些交换，因此报告分项结果和典型冲突样本，有助于读者理解“更好”究竟意味着哪一种改善。

<a id="llm-2-detail-67"></a>

### 14.4 让小实验具备研究价值

小实验的优势是可以穷举、手算和排除替代解释。比如二候选 DPO 可以准确观察参考偏置如何改变最优间隔；线性 LoRA 可以知道目标秩是否足够。只要问题定义清楚，这些结果就有价值。缺点是无法代表真实语言分布中的所有复杂性，因此应在结论中明确保留这种边界，而不是用“大模型机制已证实”夸大范围。

完整研究可以先用小实验建立预期，再在更复杂的模型上验证相同诊断量是否仍有解释力。若规律不再成立，应检查新增因素：共享参数、数据异质性、近似梯度、候选分布变化和评价噪声。把差异本身作为研究对象，通常比只挑符合预期的曲线更能推进理解。严密的学习资料也应保留这些未解决问题，让读者知道下一步可以如何追问。

<a id="llm-2-detail-68"></a>

### 14.5 检查点选择也属于学习算法

训练过程中保存多个检查点，再按开发集选择最佳一步，是整个学习算法的一部分。两个方法若各自展示最好的训练时刻，却使用不同频率检查或不同数量候选，其选择机会并不相同。应该记录评价频率、早停标准和允许的回退次数。对于噪声较大的偏好评价，可以使用预先规定的平滑或重复标注，但这些规则不能在看到结果后只对某个方法有利地调整。

最终报告还应区分同一训练运行内的波动与不同随机种子间的波动。前者来自检查点、采样和评价噪声，后者还包含初始化与数据顺序。重复运行能够揭示不稳定性，却不能修复有偏的数据划分。若计算预算只能完成一次运行，应如实呈现这一限制，并尽量利用成对题目分析和确定性机制实验提供补充证据，而不是给单次分数附上没有根据的精确置信结论。

在学习笔记中保留这些选择规则，也能避免日后只记得一个最好数字而忘记其获得成本。方法的实际价值同时包含效果、稳定性、资源和可维护性，任何一个维度都需要具体可复算的证据支持。

实际复现实验时，还应记录软件版本、随机种子、线程数和数值精度。确定性机制测试可以使用严格断言，随机任务效果则应给出合理范围与失败解释。不要为了让断言通过而在看到结果后不断调整阈值；应从数学预期或独立开发实验确定条件，再保留原始观察。
