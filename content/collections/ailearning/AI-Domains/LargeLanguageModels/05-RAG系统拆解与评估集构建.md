## 1. 文档不是无版本的字符串集合

知识库中的一条内容应有来源身份、版本、生效与到达时间、权限、章节位置和删除状态。文档可能已过时但仍被索引，也可能新版本已上传却尚未生效；这两个时间与查询时点的关系要定义。只给每块一个随机编号，无法解释它来自哪份规则，更难在更新、引用和缓存中保持一致。RAG 的正确性从知识对象开始，不是生成末端才处理的引用格式。

<a id="rag-5-detail-2"></a>

### 1.1 原始位置与展示上下文分开保存

块可以附加标题路径或邻近定义帮助检索，但新增展示文本不一定是原文连续片段。应分别保存原始区间、引用片段与渲染后的模型上下文，避免把自动拼接内容伪装成原文逐字引文。表格还需保留表头与行列关系，单独抽一个数可能丢掉对象、单位或前提。来源定位要能回到具体版本，不能只链接一个会不断变化的首页。

字符偏移、字节偏移与 token 偏移又不相同。中文和组合字符使它们更容易分离，规范化、去空白与重排后原始位置也可能失效。处理链若改写文本，应保留可解释映射或冻结用于引用的标准版本。一个看起来相近的句子不等于相同证据，特别是否定、时间和条件被截断时。引用应绑定实际被读取的内容，而不是最后随机附上同主题链接。

<a id="rag-5-detail-3"></a>

### 1.2 切块尺度是任务与预算问题

块太小可能把定义与条件分开，块太大可能引入大量无关内容和重复，占据预算。重叠可以保留边界，却增加近重复候选。最合适尺度取决于问题需要单句事实、表格行还是多段联合，不能凭固定字数宣称普遍最优。比较时既看证据在库中是否完整，也看候选与最终上下文是否保留足够信息。

相同候选数不意味着相同上下文成本。两个大块可能比十个短块更长，包含的重复和必要条件也不同。应同时报告块长分布、重叠、检索候选数与最终字符或实际 token 预算。若实验采用字符预算就明确命名，不把它误称真实模型 token；分词器不同会改变编码长度，部署前需要用实际编码器重新核对。

<a id="rag-5-detail-4"></a>

### 1.3 实验一：标题路径与原文区间同时保真

本段将简单文档按行形成块，并为内容附标题路径。每块的原始区间仍精确对应原文本，不把附加标题纳入伪造连续引文。最后用中文编码说明字符位置与字节数不同。示例不是完整 PDF 或表格解析器，它只验证来源映射应遵守的必要不变量，真实文档还需处理版式、页码与复杂表格。

```python
text = '# 存储规范\n## 方案蓝\n正式项目的日志保存14日。\n临时项目只保存2日。\n'
blocks, path, cursor = [], [], 0
for line in text.splitlines(keepends=True):
    content = line.rstrip('\n')
    start, end = cursor, cursor+len(content)
    cursor += len(line)
    if content.startswith('## '):
        path = path[:1]+[content[3:]]
    elif content.startswith('# '):
        path = [content[2:]]
    elif content:
        blocks.append({'id': f'c{len(blocks)+1}', 'version': 'v1',
                       'start': start, 'end': end, 'text': content,
                       'heading_path': tuple(path)})
assert cursor == len(text) and len(blocks) == 2
for block in blocks:
    assert text[block['start']:block['end']] == block['text']
    assert block['heading_path'] == ('存储规范', '方案蓝')
rendered = ' / '.join(blocks[0]['heading_path'])+'\n'+blocks[0]['text']
assert rendered != text[blocks[0]['start']:blocks[0]['end']]
assert len('方案蓝'.encode('utf-8')) != len('方案蓝')
print('source slices verified:', [(b['start'], b['end'], b['text']) for b in blocks])
```

## 2. 召回、重排与上下文选择各有不可越过的上限

召回器从允许的库产生候选，重排器在候选里调整次序，上下文选择在预算内组织内容。若证据根本未索引，不能靠调重排找回；若已召回却被预算或重复挤掉，扩大库也未必有帮助。应保存每阶段输入输出与排除原因，让定位沿真实链条进行，不把所有失败统一叫生成幻觉再盲目换提示。

<a id="sec-2-1"></a>
<a id="rag-5-detail-6"></a>

### 2.1 权限与时点先于相关性排名

一个内容再相关，若查询身份无权读取，就不属于允许证据。权限过滤必须贯穿检索、重排、上下文和缓存，不能只在答案展示时删引用，模型可能早已读到内容。时间也要一致：当前回答、历史时点回答与已知到达时间的回放是不同任务。规则生效与系统知道规则可能不同，按目标保存和过滤，避免无声利用未来信息。

对不同权限的问题评价可回答性时，分母是其允许库，不是管理员看到的全集。一个答案存在于私有文档，不代表普通用户的问题应被计为检索失败；也不能把无权限事实当金标准奖励模型猜出。评价器本身可以拥有额外审计信息，但这些信息只能用于判定，不能流入被测检索与回答路径。角色隔离比最后一个拒绝字符串更根本。

<a id="rag-5-detail-7"></a>

### 2.2 重排强不能补候选缺失

交互式重排可以利用更丰富查询与段落关系，但只看已经给出的集合。先测候选充分性，再测重排后与最终上下文充分性，才能判断阶段是否有改进空间。若单一候选已包含全部必要事实，排序问题相对简单；若答案需联合多段，单块相关分数高不代表组合充分。保留高分重复块尤其可能挤掉得分较低却不可缺的条件。

关键词、稀疏向量、密集向量与混合各有适用输入，精确编号和数字不应无条件交给语义近似。比较方案需共同允许库、查询和预算，记录索引与模型版本。若重排器使用人工标注支持集合直接排序，那是诊断上界，不是可部署检索器；报告中必须把它与真实模型分开，不能让金标准证据偷偷解决本来要评估的问题。

## 3. 评价集应标注充分证据，而不只是相关片段

单段相关、某事实支持与足以回答整个问题是三个层次。问题可能有多个替代充分集合，每个集合又需要多个块联合。可以用一族集合表达：命中其中任一集合的全部必要成员，才算证据充分。普通逐块 recall 描述另一对象，命中一半事实不等于完整答案可生成。标注应允许真实替代来源，否则检索到同样充分的另一段也会被误罚。

<a id="sec-1-1"></a>
<a id="rag-5-detail-9"></a>

### 3.1 库覆盖与条件召回的分母

先判断允许库在指定时点能否支持答案，再在可回答问题中评价检索充分性；最终系统还需要处理不可回答问题。若一百题中二十题根本没有允许证据，将全部失败归为召回器，会混淆内容覆盖与排序。分开报告可回答比例、条件充分召回、上下文保留与不可答行为，才能看见真正上限，而不是不断增加 k 掩盖知识缺口。

证据标注不完整会低估检索能力，问题本身含糊也可能没有唯一答案。应记录答案规则、来源版本、必要条件与不可答原因，安排代表性复核。生成相似问题很方便，却可能只覆盖标题词匹配；真实用户问题、表格、多跳、否定、时间更新和冲突需要分别审计。按文档家族、事件与模板分组开发测试，避免评价只测同源改写记忆。

### 3.2 一个封闭读取器的完整检索实验

虚构平台里，项目与方案关系是一条证据，方案保留天数是另一条，必须联合。旧版本在时点五失效，新版本生效；私有项目只有组乙可读。读取器只解析固定符号规则并在上下文中连接，不使用金标准答案生成结果。金标准充分集合只在评价时出现。稀疏索引用合法库文本构建，这是本任务预先允许的知识访问，不是用测试答案拟合检索器。

程序保留候选、最终上下文、充分性、输出与引用，便于区分哪阶段丢证据。字符预算八十，不宣称真实语言模型 token 成本；没有神经重排与自然语言生成。这个最小管线足以验证权限、版本、重复和联合证据边界，却不能据此断言真实 RAG 的语义理解质量。失败与成功都由代码实际打印，不以每题必须正确作为验收。

```python
from dataclasses import dataclass
import re
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer

@dataclass(frozen=True)
class Doc:
    id: str
    text: str
    start: int
    end: int | None
    acl: frozenset

corpus = [
    Doc('member', 'project Orion uses plan blue', 0, None, frozenset({'A','B'})),
    Doc('member-copy', 'project Orion uses plan blue', 0, None, frozenset({'A','B'})),
    Doc('blue-old', 'plan blue retention_days 7', 0, 5, frozenset({'A','B'})),
    Doc('blue-new', 'plan blue retention_days 14', 5, None, frozenset({'A','B'})),
    Doc('green', 'plan green retention_days 2', 0, None, frozenset({'A','B'})),
    Doc('secret-member', 'project Nebula uses plan red', 0, None, frozenset({'B'})),
    Doc('secret-rule', 'plan red retention_days 60', 0, None, frozenset({'B'}))]
questions = [
    {'id':'q1', 'project':'Orion', 'time':6, 'group':'A', 'answer':14,
     'sufficient':[{'member','blue-new'}, {'member-copy','blue-new'}]},
    {'id':'q2', 'project':'Nebula', 'time':6, 'group':'A', 'answer':None, 'sufficient':[]},
    {'id':'q3', 'project':'Orion', 'time':3, 'group':'A', 'answer':7,
     'sufficient':[{'member','blue-old'}, {'member-copy','blue-old'}]},
    {'id':'q4', 'project':'Nebula', 'time':6, 'group':'B', 'answer':60,
     'sufficient':[{'secret-member','secret-rule'}]}]

def visible(question):
    return [d for d in corpus if question['group'] in d.acl and d.start <= question['time']
            and (d.end is None or question['time'] < d.end)]
def sufficient(ids, alternatives):
    return any(bundle <= set(ids) for bundle in alternatives)
def pack(candidates, budget=80):
    used, kept, seen = 0, [], set()
    for doc in candidates:
        if doc.text in seen: continue
        cost = len(doc.id)+len(doc.text)+3
        if used+cost <= budget:
            kept.append(doc); seen.add(doc.text); used += cost
    return kept, used

def read(project, context):
    mappings, rules = [], []
    for d in context:
        m = re.fullmatch(r'project (\w+) uses plan (\w+)', d.text)
        if m and m[1] == project: mappings.append((m[2], d.id))
        r = re.fullmatch(r'plan (\w+) retention_days (\d+)', d.text)
        if r: rules.append((r[1], int(r[2]), d.id))
    joined = [(days, [m_id, r_id]) for plan, m_id in mappings
              for other, days, r_id in rules if plan == other]
    values = {days for days, _ in joined}
    if len(values) != 1:
        return {'status':'unknown', 'answer':None, 'citations':[]}
    answer, citations = joined[0]
    return {'status':'supported', 'answer':answer, 'citations':citations}

for q in questions:
    library = visible(q)
    vectorizer = TfidfVectorizer(token_pattern=r'(?u)\b\w+\b')
    matrix = vectorizer.fit_transform([d.text for d in library])
    query = vectorizer.transform([f"project {q['project']} retention_days"])
    scores = (matrix@query.T).toarray().ravel()
    order = sorted(range(len(library)), key=lambda i: (-scores[i], library[i].id))
    candidates = [library[i] for i in order[:4]]
    context, cost = pack(candidates)
    output = read(q['project'], context)
    ids = [d.id for d in context]
    assert set(output['citations']) <= set(ids)
    assert all(q['group'] in d.acl and d.start <= q['time'] and
               (d.end is None or q['time'] < d.end) for d in context)
    assert cost <= 80
    if q['group'] == 'A': assert not any(d.id.startswith('secret') for d in context)
    print(q['id'], 'library/candidate/context sufficient:',
          sufficient([d.id for d in library], q['sufficient']),
          sufficient([d.id for d in candidates], q['sufficient']),
          sufficient(ids, q['sufficient']))
    print('candidate ids:', [d.id for d in candidates])
    print('context/cost/output/correct:', ids, cost, output, output['answer'] == q['answer'])
# 金标准只用于诊断读取能力和最低证据成本，不参与被测排名。
q = questions[-1]
required = q['sufficient'][0]
oracle_context = [d for d in visible(q) if d.id in required]
oracle_output = read(q['project'], oracle_context)
minimum_cost = sum(len(d.id)+len(d.text)+3 for d in oracle_context)
assert oracle_output['answer'] == 60
assert minimum_cost > 80
print('diagnostic oracle / minimum bundle cost:', oracle_output, minimum_cost)
```

<a id="rag-5-detail-11"></a>

## 4. 联合证据与预算：为什么独立高分不够

若问题需要甲关系和乙规则，两者共同出现才有用，单块相关得分不能表示组合价值。重复甲即使各自相关，也不能替代乙。相似性重排优化的是候选的某种局部信号，最终上下文却有长度、去重、顺序和条件完整性约束。应将独立排序与组合选择区分，记录必要证据如何因预算而丢失，不默认把前几名拼接就形成充分答案。

<a id="rag-5-detail-12"></a>

### 4.1 一个具有互补性的集合目标

定义教学效用为仅当集合同时含事实甲和乙时为一，否则零。将乙加入空集合没有收益，加入已有甲的集合却有收益，违反通常“边际收益递减”的次模条件。由此可见，多证据充分性不一定是简单覆盖或次模目标，不能直接套用所有贪心近似保证。这是某类任务的反例，不表示所有实际选块都必须做昂贵组合搜索。

实际系统可以用关系展开、去重、查询分解、邻块补充或学到的组合评分来研究，但每项都需独立验证和成本。若使用金标准必要集合直接选择，那是诊断上界，不是可部署方案。评价集的充分证据标注帮助衡量差距，不应进入被测算法作为隐藏答案。教材中的枚举仅在小型已知问题上解释结构，不能被误称为真实 RAG 已解决的通用优化。

<a id="rag-5-detail-13"></a>

### 4.2 实验三：相关高分、重复与互补

人工四候选中，最高单块分数来自无关但高相关表面信号，两个甲副本分数也很高。预算只能容纳两个短块或一个长块。代码对照按分数贪心与金标准充分性枚举，展示有无乙的差异。枚举知道必要事实，明确属于诊断，不用于前面实际检索排名；成本单位也是人工设定，不是实际 tokenizer。

```python
import itertools

items = [
    {'id':'a1', 'cost':6, 'score':10, 'fact':'a'},
    {'id':'a2', 'cost':6, 'score':9, 'fact':'a'},
    {'id':'b', 'cost':6, 'score':8, 'fact':'b'},
    {'id':'c', 'cost':10, 'score':11, 'fact':'c'}]
budget = 12
def complete(rows):
    return {'a', 'b'} <= {r['fact'] for r in rows}
greedy, used = [], 0
for row in sorted(items, key=lambda r: (-r['score'], r['id'])):
    if used+row['cost'] <= budget:
        greedy.append(row); used += row['cost']
choices = []
for n in range(len(items)+1):
    for subset in itertools.combinations(items, n):
        if sum(r['cost'] for r in subset) <= budget:
            choices.append(subset)
oracle = max(choices, key=lambda rows: (complete(rows), sum(r['score'] for r in rows)))
assert not complete(greedy) and complete(oracle)
assert {r['id'] for r in oracle} == {'a1','b'}
assert sum(r['score'] for r in items[:2]) > items[0]['score']+items[2]['score']
print('greedy ids / complete:', [r['id'] for r in greedy], complete(greedy))
print('diagnostic sufficient ids:', [r['id'] for r in oracle])
```

<a id="rag-5-detail-14"></a>

### 4.3 位置顺序和上下文完整性

即使证据都在上下文中，标题、表头、单位与否定若被重排错位，也可能形成另一命题。预算规划应按最终渲染文本计算，包含分隔、来源标签和必要说明，而不是只加原文字符。若对块截断，重新检查事实和条件是否仍完整；截去不方便的尾部不是无损压缩。引用位置也要绑定最终实际读取片段，不能在答案之后凭主题补链接。

多个来源冲突时，应按预设时点和规则处理，不通过排序悄悄决定真值。旧版本可以作为历史问题的合法证据，但当前问题若使用它，需明确是否过时。来源权威层级、例外与适用对象属于任务语义，不是一般相似度能自动恢复的事实。没有足够信息唯一裁决时，允许未知、冲突说明或澄清，避免模型被迫编造单一答案。

<a id="rag-5-detail-15"></a>

## 5. 缓存、版本与权限共同决定可复用性

查询文字相同不意味着合法结果相同。知识快照、查询时点、允许证据范围、检索配置、上下文预算、读取或生成模型、提示模板和后处理都可能影响输出。缓存若只按问题字符串，可能返回旧答案或跨权限内容。复用条件应从完整函数推导，记录足以重建本次结果的身份，而不是把一次命中当成无条件正确。

<a id="rag-5-detail-16"></a>

### 5.1 物理槽位与语义身份

缓存数据保存在哪里，是存储管理；它代表什么条件下的结果，是语义身份。索引更新后仍可保留旧快照用于历史任务，但当前任务不应误取旧版本。权限变化同样要使相关身份失效，不能仅在外层删引用，因为回答正文可能已包含内容。真实系统的用户、组与文档权限可能更细，本章小例中的作用域字段只在其确实完整表达允许关系时足够。

过期或删除文档后，索引、上下文缓存和答案缓存的策略要一致。逻辑不再命中与物理彻底删除是不同要求，不能因为新键避免读取就宣称全部副本已销毁。教学代码只验证结果身份与防误复用，不实现分布式失效或完整数据删除系统。把功能范围说清，才知道真实部署还需补哪一层证据。

<a id="rag-5-detail-17"></a>

### 5.2 实验四：同问题不同快照与作用域

下面在内存中构造缓存键，包含当前例子所有影响条件。先展示仅问题字符串无法区分权限，再确认快照、作用域、时点和配置变化都会产生不同键；字典字段顺序不影响规范序列化。这里的摘要用于稳定身份，不证明来源真实性，程序也没有访问真实私有文档。真实系统要按实际权限和配置扩展，而不是只复制字段名。

```python
import hashlib
import json

def key(query, snapshot, scope, as_of, reader='symbol-reader-v1', packing='k4-char80'):
    identity = {'query':query, 'snapshot':snapshot, 'scope':scope, 'as_of':as_of,
                'reader':reader, 'packing':packing}
    encoded = json.dumps(identity, sort_keys=True, ensure_ascii=False,
                         separators=(',', ':')).encode('utf-8')
    return hashlib.sha256(encoded).hexdigest()

query = 'project Nebula retention_days'
unsafe = {query: 'a synthetic group-B result'}
assert query in unsafe  # 该键无法区分查询者权限。
a = key(query, 'snapshot-1', 'group-A-policy1', 6)
b = key(query, 'snapshot-1', 'group-B-policy1', 6)
c = key(query, 'snapshot-2', 'group-B-policy1', 6)
d = key(query, 'snapshot-1', 'group-B-policy1', 3)
e = key(query, 'snapshot-1', 'group-B-policy1', 6, packing='k8-char120')
assert len({a,b,c,d,e}) == 5
cache = {b: {'status':'supported', 'answer':60}}
assert a not in cache and c not in cache and d not in cache and e not in cache
assert key(query, 'snapshot-1', 'group-B-policy1', 6) in cache
print('snapshot, scope, time and packing changes cannot hit the same cache entry')
```

<a id="rag-5-detail-18"></a>

### 5.3 超时、失败和空结果不可混成“没有答案”

检索没有相关结果、权限内没有证据、索引不可用和工具超时是不同状态。前两者可能属于可回答性，后两者是执行失败。若统一返回一个自然语言“不知道”，评价和监测会把服务故障误当合理拒答。需要结构化状态与阶段记录，最终对用户怎样表述再由接口定义。成功调用也不等于用户问题已解决，字段合法和任务正确仍分开核验。

重试影响成本，具有副作用的工具还需要对应的幂等和确认语义；本章不实际调用这类工具，机制可回到第 3 章学习。缓存失败状态也要有明确时效，暂时性错误不应永久污染问题结果。成本报告计入失败、重试和等待，不只统计一次理想成功路径。可靠性描述需要覆盖真实执行，而不是只测最容易成功的流程。

<a id="rag-5-detail-19"></a>

## 6. 分阶段指标：条件分母与端到端结果

对可回答问题，可分别记录允许库充分、候选充分、最终上下文充分和读取正确。若这些事件按任务定义嵌套，联合成功率可以用逐级条件概率乘积表达，这是链式法则而非独立性假设。分母每级不同，必须写清，不能将几个对不同总体计算的平均数随意相乘。若允许答案来自参数记忆，正确答案又未必拥有证据，此时应另记支持性，不能强行把正确事件塞进证据嵌套链。

<a id="sec-6-1"></a>
<a id="rag-5-detail-20"></a>

### 6.1 可回答、正确、支持与引用是不同事件

答案内容正确可能来自猜测或记忆，不保证使用当前合法证据；引用来自正确主题却不支持具体命题，也不能算事实依据。反之，引用的某个事实成立，完整答案仍可能漏关键条件或组合错误。评价应分别看回答规则、证据支持、必要事实覆盖与引用精确性。最终采用哪些约束作为成功，来自具体任务需求，而非一个统一自动分数。

不可回答问题是另一评价层，不能在召回指标中简单当失败后删除。按权限或时点无证据时，合理未知可能是成功；库外已知答案不能越权变成模型应猜出的目标。答案不存在、冲突未裁决、证据已过期、用户信息不足和执行故障应分别记录。它们需要不同改进，混成一个“拒答类”会让系统只学会表面措辞而失去诊断能力。

<a id="rag-5-detail-21"></a>

### 6.2 本章完整管线的实际结果

四题中，前一题当前公开项目联合两块得到十四，第三题历史时点联合旧规则得到七；第二题普通组查询私有项目，允许库不可回答，返回未知符合协议。第四题组乙有权，完整库也有证据，但前四候选漏了私有规则，最终上下文只有成员关系，返回未知。这是三题正确、一题失败，其中可答三题成功两题，不可答一题正确保留未知，不能把两个分母混成“检索全对”。

诊断直接提供第四题的完整合法证据，封闭读取器能得到六十，说明它具备当前规则连接能力。但该证据最小渲染成本八十四，超过原八十字符预算；即使修候选，还需解决预算或组织方式。这个对照改变了上下文来源和成本，只用于定位，不应作为被测系统原预算下成功。实际失败可以有多个瓶颈，发现第一个不代表后面都已解决。

<a id="rag-5-detail-22"></a>

### 6.3 理想证据对照的正确用途

金标准证据帮助测试读取器在理想输入下是否工作，不能替代真实检索结果。若理想证据也失败，研究解析、问题理解或生成；若真实候选缺失，先研究相应前段。还可固定同一生成器比较上下文组织，或固定证据比较不同读取器，分别控制对象。每个对照标明信息和成本变化，避免把诊断上界包装成完整系统提升。

真实自然语言模型可能从不完整证据推断甚至碰巧猜对，因此还需有无证据、冲突、替换数字和不可答对照。正确且来源支持比仅正确更强，引用形式合法又比实际支持更弱。评价程序应允许发现这些组合，而不是把任何答案正确都归功检索。只有把对象分清，才能知道改动究竟提高了证据覆盖、读取还是无据猜测。

<a id="rag-5-detail-23"></a>

## 7. 失败台账应能定位首个分叉

每题保留查询身份、知识快照、时点、允许范围、金标准答案规则、可替代充分集合、候选、重排、上下文、回答和引用。台账不只写一个“幻觉”标签，而应描述可复算的阶段状态：证据未入库、权限内不可答、切块破坏、召回遗漏、预算丢失、冲突未处理、读取失败或评价不明确。多个问题可能同时存在，优先定位最早失败不表示其他阶段天然正确。

<a id="rag-5-detail-24"></a>

### 7.1 用最小干预排除竞争解释

第四题可以先固定库与读取器，扩大候选看必要规则是否进入；再固定完整候选，改变预算检查是否能容纳；最后提供同样合法的金标准证据，测试读取。每次仅改变明确条件，记录额外信息和成本。直接同时换模型、提示、索引和预算，若结果提升，只能说明完整方案变化，无法定位原因。机制诊断需要对照而不是更多组件名称。

也要防止诊断偷看答案后成为隐含算法。按金标准选择证据、按正确答案决定截断或挑生成结果，都会改变被测权限。可以作为上界和排查，但必须另列。最终部署候选只能使用查询和允许信息，选择后在独立问题上确认。失败样例反复修复仍有回归价值，却已是开发信息，不能无限当最终测试。

<a id="rag-5-detail-25"></a>

### 7.2 k 增大不保证最终上下文单调更充分

候选集合随 k 扩大，在固定排序下候选覆盖通常不会下降；但去重、重排、全局组合、渲染和预算会让最终上下文改变。新增高分长块可能挤掉原本有用短块，更多证据也可能引入冲突和干扰。应分别记录候选与最终上下文，不将某一级的单调性无条件传播到端点。若最终策略有保持既有证据的性质，可以专门证明和测试，而不是默认存在。

本例第四题的必要渲染成本超过预算，单靠把 k 变大无解。可以研究更紧凑且保真来源表示、关系预处理或明确增加预算，但这些都改变流程条件。压缩后保留可验证推导和引用，不能把合成摘要伪装成原文连续引文。若目标问题确实需要更多信息，应承认资源约束而非把失败归因某个向量模型不够大。

<a id="rag-5-detail-26"></a>

### 7.3 将台账转成下一轮可证伪假设

错误集中在表格，可假设缺失表头或行关系，先审查最终块；集中在版本更新，可检查生效与缓存；集中在多证据，可检查联合充分与组合预算。每个假设应给预期会改变的阶段指标和不应改变的对照。若结果不符就修订解释，不只挑支持故事的样例。台账的价值在于将现象转成有信息量的实验，而不是积累无法比较的截屏。

对于评价歧义，先修订标注规范并对全部比较候选一致处理。答案同义、多个充分来源、冲突问题可否合理拒答，都可能改变评分。不能只给新方法开放替代答案，旧方法仍用严格字符串匹配。评价器版本与数据版本一起冻结，发现问题可以修，但修后结论和数据角色需要重新说明，避免把评价政策变化算作模型改进。

<a id="rag-5-detail-27"></a>

## 8. 评价集的分组、负例与支持数

一个问题集至少包含单事实、联合关系、表格、数字比较、否定、历史时点、冲突、无证据和无权限等情形。每类都要有明确答案规则和证据要求，不靠一个总分代表全部能力。样本频率可以按真实请求，也可以为诊断主动增加困难类；二者评价总体不同，应分别报告。人工小题集易于审查，却不代表真实用户分布，只能作为机制与初步回归。

<a id="rag-5-detail-28"></a>

### 8.1 允许检索的库与监督训练数据不是同一对象

检索任务常预先允许访问完整索引库，包括测试问题所需文档；没有这些内容本来就无法检索。用允许库建立词项统计可以是固定任务的合法条件，关键是事先声明。训练监督检索器、选择切块或阈值若使用测试答案和支持标注，则是另一种信息流，不应混淆。是否泄漏要沿任务权限判断，不能机械地说“测试文档出现任何地方都错”或“索引里都有所以标签也可用”。

若研究新文档泛化，可以让检索或表示模型在某些来源训练，测试时再建立包含新来源的合法索引；该设置检验其处理新内容能力。若研究固定库中未见问题，库可共同给定，问题家族与答案反馈保持隔离。两种协议回答不同问题，都需写明训练、索引、开发和测试各自可见什么。正确的分组来自目标，而不是一个不加解释的随机划分函数。

<a id="rag-5-detail-29"></a>

### 8.2 负例不能只选完全无关文本

完全无关段落容易被关键词区分，不能代表真实干扰。可以加入相同实体但错误版本、相近方案、条件不符、否定相反、单位不同和同主题但不支持答案的段落。负例标注应判断是否真不充分，而不因它不是唯一已标正例就直接判负。多个来源可能等价支持，未审核候选不能自动视作错误，这一点对检索训练与评价都重要。

不可答问题也不能全由明显异常字符串组成，否则模型学会表面风格即可拒绝。应与可答问题在语言形式上尽量匹配，区别来自允许证据的实际缺失或冲突。对权限任务，普通用户和管理员问题文字可以完全相同，答案性却不同；缓存和评价要尊重这一条件。这样的对照比给不可答题加一个固定提示词更能检验真实机制。

<a id="rag-5-detail-30"></a>

### 8.3 分组重复与选择不确定性

同一文档或模板生成多个问题，错误和检索难度可能相关。成对比较两个系统时保留问题身份，重采样按真实独立来源或问题家族，而不是将每个改写当独立观察。若多个训练种子又共享同一库和测试，还需区分训练波动与题目抽样。小组数时区间也粗，应给支持数和全部预设运行，不用更多生成改写伪造独立证据。

切块尺度、k、重排器、预算和提示都可能被反复选择，整个搜索过程适应开发集。最终配置冻结后再评价独立问题，报告搜索与失败成本。测试反馈参与修复时，保留旧集作回归，同时另设确认。一个自动评分器重复给相同答案高分，不会把那道题变成多份独立验证；样本来源和信息使用决定证据，不是调用次数。

<a id="rag-5-detail-31"></a>

## 9. 从概率模型到实现边界的进阶联系

抽象地可以将证据集合看作潜变量，回答分布对集合条件分布按检索分布加权求和。实际系统常用确定性 top-k、一次上下文与单次解码，因此不是自动精确计算这个边缘分布。相似度分数也不天然是证据正确概率，做 softmax 只得到一种归一化数值。若要解释概率和校准，需要额外模型、训练与评价，而不能将排序器输出直接当事实可信度。

<a id="rag-5-detail-32"></a>

### 9.1 截断候选与条件分布

若一个理论分布在全部证据集合上有概率质量，只保留部分后重新归一化，相当于条件于该集合范围，忽略被删质量。若不归一又直接相加，得到的总质量可能不足一。两者都有具体数学含义，不应在实现说明中混用。当前教学程序并没有概率检索模型，它只是确定性稀疏排序和闭式规则读取，因此不声称自己实现某论文完整边缘化架构。

多证据问题的潜变量还是一个组合，而不一定单个段落。独立段落概率相乘需要假设，事实上重复、依赖与冲突很常见。可以研究图结构、查询分解和联合模型，但它们增加计算与设计条件。先用充分集合明确评价对象，再选择合适近似，能避免公式看起来完整却和实际任务不一致。理论联系帮助提问，不应代替具体数据与实验。

<a id="rag-5-detail-33"></a>

### 9.2 相关、支持与蕴含方向

一个段落提到同一实体，不等于支持当前答案；支持某个较弱事实，也不等于支持更强结论。多个条件之间的逻辑方向尤其重要：必要条件不能直接当充分条件，例外不能被普通规则覆盖，历史有效不能当当前有效。评价应检查答案命题与来源之间的关系，而不只看关键词重叠或向量相似度。引用评价因此需要超出“引用 ID 存在”的层次。

封闭规则读取器能精确处理它定义的语法和连接，但无法自动理解任意自然语言反讽、省略或复杂逻辑。真实生成模型扩大表达能力的同时也带来新的失败，应在独立支持标注和实际任务上验证。把符号程序看成可审查参考有价值，不能把它的确定性正确推广成自然语言系统已经解决事实问题。每个模型的表达空间与证据范围都应清楚。

<a id="rag-5-detail-34"></a>

### 9.3 成本与质量共同形成研究对象

端到端成本包括文档处理、索引、检索、重排、上下文、生成及失败重试，离线更新与在线查询又有不同摊销。仅比单次检索毫秒或生成 token，可能忽略更昂贵阶段。应固定知识快照、问题、权限和输出要求，分别报告阶段耗时与端点延迟，并说明冷缓存、热缓存和命中比例。没有目标硬件实测就不填假定加速数字。

如果优化删除了上下文、改变解码或拒绝更多问题，质量和覆盖也改变，不能当纯等价加速。可以定义固定质量下成本或固定预算下质量，再按预设规则比较。某方案更快但对联合证据失败，可能不满足应用约束；另一个更准确却超内存，也未必可用。报告保留多维取舍和未测项，比一个无定义“更高效”更有判断价值。



<a id="rag-5-mixture-bound"></a>

### 9.4 有限潜证据模型的截断误差界

为把概率联系变成可证明命题，设查询已固定，潜证据索引为有限集合中的 $`z`$。给定一个真正归一化的检索分布 $`r(z)`$ 和条件回答分布 $`g(y\mid z)`$，边缘分布为

$$
p(y)=\sum_z r(z)g(y\mid z).
$$

保留集合 $`S`$，令删去质量 $`\epsilon=\sum_{z\notin S}r(z)`$。当 $`0\leq\epsilon<1`$ 时，归一化截断分布为

$$
p_S(y)=\frac{\sum_{z\in S}r(z)g(y\mid z)}{1-\epsilon}.
$$

若 $`\epsilon>0`$，再定义被删部分的回答混合分布 $`p_R`$，原分布恰好为 $`p=(1-\epsilon)p_S+\epsilon p_R`$。对离散回答空间，总变差距离满足

$$
\operatorname{TV}(p,p_S)
=\frac12\sum_y\vert p(y)-p_S(y)\vert
=\epsilon\operatorname{TV}(p_R,p_S)
\leq\epsilon.
$$

这里没有假设各证据相互独立，关键是混合权重确实是概率、条件分布正确归一化，并且比较时条件模型没有随截断改变。若保留部分总回答为甲、删除部分总回答为乙且两者不同，总变差恰为删去质量，说明一般情况下不能把该界进一步缩成更小常数。若删去部分和保留部分具有完全相同回答分布，误差又恰为零；删掉多少检索概率并不唯一决定回答变化。

这个界不直接控制解码答案是否变化。原分布的两个最大回答若概率极近，很小的分布扰动也可能交换第一名。它也不直接给某个极低概率答案的对数损失差上界，因为取对数对接近零的概率敏感。要推出这类结论，需要额外的间隔或概率下界。若保留质量为零，归一化截断本身未定义，不能用公式除零后继续解释。边界条件既是证明要求，也是实现需要检测的输入情况。

更重要的是，该命题不是对本章 TF-IDF 管线的直接数值保证。TF-IDF 分数没有被证明等于 $`r`$，实际读者一次看整个拼接上下文，并非逐个证据条件分布的固定混合。若增大候选数改变了渲染和读取模型输入，条件模型也变了，以上共同分布前提不再满足。这个推导提供一种研究工具：先明确概率对象，再分析近似误差，最后检查实现是否保留了前提。不能只因系统同样叫检索生成，就把别的模型中的界拿来证明它的性能。

<a id="rag-5-chain-proof"></a>

### 9.5 支持成功链的精确分解

令 $`A`$ 表示允许库包含充分证据，$`B`$ 表示候选包含充分证据，$`C`$ 表示最终上下文包含充分证据，$`D`$ 表示答案正确且命题由该上下文支持。在候选与上下文只来自允许库、充分性定义一致的条件下，有 $`D\subseteq C\subseteq B\subseteq A`$。若相关条件概率分母非零，链式法则给出

$$
P(D)=P(A)P(B\mid A)P(C\mid B)P(D\mid C).
$$

证明从 $`P(D)=P(D\cap C)`$ 开始，依次用条件概率定义展开；因为 $`C`$ 蕴含 $`B`$、$`B`$ 蕴含 $`A`$，无需重复写已隐含条件。这不是独立性乘积。样本上的对应计数也能望远镜消去分母，最终得到支持成功数除以总请求数。任一中间计数为零时，该条件项没有可估分母，但最终成功数仍可明确为零，报告应保留“不可估”而非伪造条件比例。

若把 $`D`$ 改成“字符串答案碰巧正确”，它可能在 $`C`$ 不成立时由参数知识或猜测实现，嵌套关系随之失效。因此这项分解解释的是限定意义的支持成功。不可答题的正确拒答也不属于这条链，应另计并汇入整体任务效用。一个严格的公式不需要覆盖所有任务事件；明确适用范围比为了统一展示而抹去重要差异更有用。

## 10. 二十四道进阶练习与逐步解析

<a id="rag-5-detail-36"></a>

### 10.1 字节位置为什么不能直接作为字符切片

**题目：** 原文含“保存 14 日”和换行。索引程序记录 UTF-8 字节偏移，展示程序用 Python 字符串切片。两个位置都是整数，是否可以直接通用？

**解析：** 不可以。UTF-8 下一个汉字通常占多个字节，Python 字符串位置按 Unicode 码点计数，二者不是相同坐标。先明确来源以哪一串精确原文为基准，再声明区间单位与半开约定。若保留字节区间，应在原始字节上切片后按正确编码解码，且边界必须位于字符边界；若转换为字符位置，需要建立可验证映射。

归一化换行、删除空白或替换字符又会改变坐标，因而转换应绑定文本版本。实验中的断言证明当前字符串区间可回取，不证明任意前处理后偏移仍正确。引用审查需要验证内容与坐标的对应，不能只检查区间数值在范围内。

<a id="rag-5-detail-37"></a>

### 10.2 添加标题后为什么不能声称逐字原文

**题目：** 检索块来自正文第三段，程序在它前面添加文档名和两级标题。这提高可读性，为什么仍需区分来源文本和展示文本？

**解析：** 因为新字符串可能由原文中不连续的位置拼接而成，甚至包含系统生成的说明。一个连续来源区间不能同时证明这些字符的出处。正确做法是为正文保留原始区间，为标题保留独立位置或元数据身份，展示层记录组合规则。

引用时可指向真实正文与真实标题，不能把拼接字符串伪装成原文某一连续段。如果文档名由外部索引赋予，还需明确它是元数据。可读性与可追溯性可以同时实现，但需要两层表示。审查重点是答案所依赖的命题是否被原文支持，而不是展示块看起来像不像完整段落。

<a id="rag-5-detail-38"></a>

### 10.3 同样大小的块为什么可能有不同有效预算

**题目：** 两种切块方案都平均每块三百字，加入六块后有效证据量是否相等？

**解析：** 不能由平均块长推出。重叠、重复页眉、标题与序列化分隔符都会占据上下文，实际模型又按具体分词器计 token，而不是按汉字等比例计费。六块可能是同一事实的六次复述，也可能包含互补的六个条件。

应在真实渲染结果上计算预算，并判断是否包含至少一组充分证据。若比较切块策略，还需固定问题集合和总预算，不仅固定块数。实验使用字符预算是为了让代码短且边界精确，不能把八十字符直接换算成线上模型八十 token。预算单位及其包含项目是协议的一部分。

<a id="rag-5-detail-39"></a>

### 10.4 增大候选数量一定改善最终答案吗

**题目：** 在相同语料上将候选数量由四增加到八。假设前四保持不变，候选充分性会降低吗，最终答案准确率会降低吗？

**解析：** 在候选严格嵌套且充分性标注固定时，集合包含某组证据这一事件具有单调性，候选充分性不会降低。但最终上下文经过重排、去重与预算打包，未必保持嵌套。新增高分干扰可能挤掉互补证据；即使上下文只增不减，读取模型也可能受冲突与位置影响。

因此不能把集合层面的单调定理推广成端到端质量定理。先检查候选是否真的嵌套，再记录上下文变化及条件读取性能。若排序算法本身随候选数改变，连第一项假设也需重新验证。这个例子说明“更多资料”只有在正确的系统边界内才有确定含义。

<a id="rag-5-detail-40"></a>

### 10.5 权限怎样改变问题的答案性

**题目：** 同一句问题向普通用户和管理员提出，管理员可查看内部映射表，普通用户不可查看。是否应给两个请求使用同一个可答标签？

**解析：** 不应。任务标签至少条件于查询、知识快照、时间和允许访问范围。管理员拥有充分证据，不代表普通用户也拥有。对普通用户正确的行为可能是返回未知，并说明当前允许证据不足；不能借助全库答案判它答错，更不能让缓存泄露管理员结果。

评价构建时可以保留真实事实作为隔离审计信息，但部署路径不得读取超出范围的证据。当前实验第二题就是这种情况：合法上下文缺乏目标项目映射，未知属于正确结果。另一方面，权限检查通过也不能证明回答事实正确，这两个判据需要分别记录。

<a id="rag-5-detail-41"></a>

### 10.6 有效时间与可用时间为什么要区分

**题目：** 一项规则在三月一日生效，但三月五日才进入系统。评价三月三日当时系统能回答什么，直接按生效时间取规则是否合理？

**解析：** 不一定。有效时间描述事实适用的时期，可用时间描述系统实际何时获知它。若研究事后回溯三月三日适用哪条规则，可以按事后完整记录查询有效时间；若研究三月三日在线系统当时的能力，则不能使用五日才到达的信息。

协议需要声明是回溯真值还是当时可知信息，必要时同时保存两类时间。本文简化实验只有规则有效区间，所有条目被视为在评价前已入库，因此不能用它验证迟到数据处理。实现更复杂的时间索引之前，先把问题问清楚，能避免把未来信息带入历史实验而不自知。

<a id="rag-5-detail-42"></a>

### 10.7 多个正确来源怎样计算覆盖

**题目：** 项目映射可由原始通知或等价副本支持，保留规则另在第三份文档。怎样避免将合法替代来源误判成漏检？

**解析：** 用充分证据集合族表示可接受组合，例如同时允许集合{通知,规则}与{副本,规则}。一个候选集合包含任意一组，即满足完整支持。不能要求所有标注来源同时出现，因为那会把冗余文档当必要条件；也不能只命中任意单个来源就算充分，因为跨文档连接仍缺一半。

标注族可能不完备，未命中已知组合只能说明当前标准下未检出，面对新的可信来源需复核。实验中的等价副本展示了这种“组内且、组间或”的结构。评估既记录完整支持，也保留各原子事实的覆盖，帮助判断是哪条连接丢失。

<a id="sec-8-2"></a>

<a id="rag-5-detail-43"></a>

### 10.8 两个相关段落为什么不等于联合证据

**题目：** 问项目的保存期限，两个段落都多次提到项目名，却没有说明项目采用哪个方案。它们相似度都很高，能算充分检索吗？

**解析：** 不能。若答案规则依赖“项目采用方案蓝”和“方案蓝保存十四日”两条事实，只有项目名重复并不建立连接。相关性是排序代理，充分性是关于答案命题的逻辑条件。可以把两个事实分别写成关系，再检查是否有合法连接路径。

缺少中间关系时，答案可能有多种相容取值，因而不能从当前资料唯一确定。对自然语言复杂任务，这种形式化可能只是近似，但仍应要求标注者解释缺失条件。把检索命中率定义为命中任何关键词段落，会系统性高估多跳任务。较好的诊断同时列出相关命中和完整证据命中，避免混成一个数字。

<a id="rag-5-detail-44"></a>

### 10.9 为什么按段落独立收益贪心可能失败

**题目：** 两条证据分别没有答题价值，同时出现才使问题可答。证明“加入证据的边际收益逐步递减”这一假设可能不成立。

**解析：** 设效用为当且仅当同时包含事实 a 与 b 时取一，其余取零。空集合加入 b 的收益为零，已有 a 再加入 b 的收益为一。后一个收益反而更大，违反次模性要求的递减收益。于是不能无条件套用依赖次模性的贪心近似保证。

章节人工例子还显示重复 a 的高分可能挤掉 b，最高独立相似度不等于最优组合。可以研究查询分解、显式覆盖约束和集合重排，但也需评价额外误差与成本。这里的反例证明某个通用保证不适用，并没有证明所有贪心在真实数据上都差；经验优劣仍需固定协议检验。

<a id="rag-5-detail-45"></a>

### 10.10 知道金标准的打包为什么只能作诊断

**题目：** 枚举所有候选子集，用标准答案所需事实选择最佳组合，再报告系统已解决上下文选择，问题在哪里？

**解析：** 选择过程使用部署时不可见的监督信号。它可以回答“如果知道所需证据，当前候选与预算是否足够”，却不能证明系统能够自动找到该组合。应将其标作 oracle 干预，并明确它看见哪些额外信息。实际算法只能用合法输入，例如查询、候选文本和预先训练的评分器。

两者差距有诊断价值，能帮助区分候选缺失与打包错误，但不应混在正式准确率中。若依据 oracle 反复开发算法，新的策略选择也已经适应这些题目，应保留独立确认集。研究中的理想上界必须先写清楚给它提供了什么便利。

<a id="rag-5-detail-46"></a>

### 10.11 第一处失败是否解释所有障碍

**题目：** 第四题的允许库包含充分证据，候选未取齐证据。是否因此认定只修复召回就一定使原系统答对？

**解析：** 不能。第一处失败给出了流程上的最早不满足条件，并非排除了后续独立瓶颈。实验完整证据按同样格式渲染需要八十四字符，原预算只有八十，即使召回修复，原打包约束仍可能阻止两条证据同时进入。

读取器在额外提供两条证据并扩大预算后成功，证明该读取器对这一完整输入可解，却没有证明原约束下的全部流程可解。诊断报告应列出最早失败和后续可检测障碍，避免将局部归因改写成保证成功的修复建议。实际修复之后应重新跑全链路，因为瓶颈可能迁移。

<a id="rag-5-detail-47"></a>

### 10.12 改变预算的oracle怎样写才诚实

**题目：** 原系统预算八十字符，强制加入完整证据后占八十四字符，答案正确。怎样报告这个实验而不夸大改进？

**解析：** 明确记录干预同时改变了证据内容和成本约束，不能仅写“加入正确证据后准确率提升”。应给原始候选、原始上下文、干预上下文及各自渲染成本，再写此结果检验的是读取能力，不是原预算可达性。

若要研究八十字符内是否可答，需要合法压缩、不同切块或不同表示，并检验压缩是否保留来源支持。这些是新的方法与实验，不能由四字符之差推断已经可行。小数值例子同样需要严格对照，因为机制判断取决于约束是否保持，而不取决于超预算幅度看起来大不大。

<a id="rag-5-detail-48"></a>

### 10.13 为什么未知可以是成功也可以是失败

**题目：** 第二题和第四题都返回未知，为什么评价一个正确、另一个错误？

**解析：** 第二题在请求者的允许库中缺少充分证据，未知遵守了证据范围；第四题在允许库中有完整证据，系统因候选和预算问题未能利用，所以未知暴露了覆盖失败。输出字符串相同不代表任务状态相同。

应分别统计允许库可答与不可答上的表现，并说明可答标准、冲突处理和合理拒答政策。如果应用允许在低置信度时拒答，也应将覆盖率与保留答案的风险共同报告，而不能把所有拒答算作事实正确。这个区分将“没有胡编”与“完成了本来能完成的任务”分开，二者都重要但不可互相替代。

<a id="rag-5-detail-49"></a>

### 10.14 为什么缓存身份需要绑定范围而非用户名

**题目：** 缓存键包含用户名和问题，同一用户角色变更后仍命中旧答案。为什么用户名并没有解决权限隔离？

**解析：** 用户身份不等于当前授权状态。角色、资源级规则、组织关系和策略版本可能变化，而相同用户名保持不变。缓存需要绑定实际访问范围或可验证的授权版本，取出后还应按产品要求重新确认有效性。

反过来，不同用户若确实共享相同允许范围和其他全部条件，也未必需要机械地完全分离，关键是语义身份是否等价。本文用简化 scope 字段演示依赖关系，没有实现现实授权系统。规范序列化与哈希只保证输入差异反映到键，不能补救遗漏的权限字段。应先确定依赖，再选择编码方式。

<a id="rag-5-detail-50"></a>

### 10.15 缓存未命中为什么不等于旧资料已删除

**题目：** 更新快照编号让旧键不再被正常请求访问，是否已经完成旧资料删除？

**解析：** 没有。逻辑失效只改变寻址和使用规则，旧值可能仍在磁盘、复制节点、备份或日志。若任务要求实际删除，应单独定义删除范围、保留政策和验证流程；不能从新键命中率推断存储状态。章节实验只验证不同依赖生成不同键，既没有写持久缓存，也没有测删除。

类似地区分有助于做准确工程验收：缓存正确性关注返回值是否依赖当前条件，生命周期管理关注数据是否仍被保存。两者可能共享版本信息，但需要不同证据。不要将一个局部断言扩大成整个系统的治理结论。

<a id="rag-5-detail-51"></a>

### 10.16 超时为什么不能标成知识不可答

**题目：** 索引服务超时，系统返回未知。可以据此给该问题标注“知识库没有答案”吗？

**解析：** 不可以。知识不可答是允许库与证据关系，超时是执行状态。把两者合并会让可答性标签随机器负载改变，还可能掩盖服务故障。结果应保留独立状态，例如正常答复、证据不足、检索失败和超时，并定义重试是否属于同一请求及其成本。

计算端到端成功率时，超时通常计入未完成，但分析知识覆盖时不能据此判库缺失。若只在成功请求上算答案准确率，还要同时报告完成率，防止系统通过大量失败筛出容易样本。正确的失败类型让改进方向从补资料、改检索到修基础设施各有依据。

<a id="rag-5-detail-52"></a>

### 10.17 端到端链式概率是否要求阶段独立

**题目：** 将成功分解为库充分、候选充分、上下文充分和读取成功的条件概率乘积，需要假设检索与读取独立吗？

**解析：** 不需要。一般链式法则使用逐步条件概率，正是为了保留依赖。若阶段事件满足后者蕴含前者，可按嵌套事件简化；若参数记忆让答案无证据也能正确，必须先把“证据支持的成功”与“答案碰巧正确”区分，不能强加嵌套。

真正不合理的是拿各阶段在不同样本条件下的边际比例直接相乘，却当作整体成功。应在相同请求与明确定义的条件子集上估计，并给分母。样本少时条件分母可能很小甚至为零，这时相应项不可估，不应填零或一制造完整公式。

<a id="rag-5-detail-53"></a>

### 10.18 答案正确为什么不证明RAG起作用

**题目：** 模型在无关上下文中仍回答正确。是否说明检索足以支持答案？

**解析：** 不能。正确可能来自参数记忆、常识、偶然猜测或评价泄漏。证据支持需要检查答案中的命题是否能由当前合法来源推出。可以增加无检索、错误证据、证据替换和理想证据干预，但这些是机制研究，需保持其他条件并注意模型可能忽略指令。

若更换证据中的关键数值，模型仍固定回答旧值，便提示它没有按当前证据更新；但单个例子不能证明所有题均如此。应分别记录答案正确、引用有效和命题支持。RAG 的价值是可利用外部知识的具体能力，不能只由总准确率中一部分熟悉题的成功推断。

<a id="rag-5-detail-54"></a>

### 10.19 建索引看见测试文档是否都是泄漏

**题目：** 测试问题来自固定文档库，评价前为全库计算 TF-IDF。这样的无监督索引是否必然违规？

**解析：** 要看研究任务。如果部署假设本来给定完整知识库，索引看见其中原文属于合法输入，不能仅因某文档对应测试题就叫标签泄漏。但测试答案、充分证据标注和错误反馈若参与训练或选择，则有不同的信息使用。若目标是检验对完全新文档的泛化，又需要明确新文档何时可见以及是否允许重建索引。

不同协议可以合理，关键是声明各阶段可见信息并与结论一致。本文允许评价时查询合法库，排序器不读取标准答案；这支持闭库任务机制演示，不证明跨库迁移能力。先定义部署信息条件，再判断泄漏，比套用固定口号更准确。

<a id="rag-5-detail-55"></a>

### 10.20 “不是已标正例”为什么不一定是负例

**题目：** 标注员只找到一份支持文档，训练时将其他所有候选视为负例，会造成什么问题？

**解析：** 可能把等价来源、不同措辞的证明或另一组充分组合误标为负。训练会惩罚有效证据，评价也会将真实改进记成错误。应区分已确认不支持与尚未审核，针对高分候选补充判定，并允许多正例或集合层面的标签。

困难负例尤其需要检查条件、时间和实体关系，不能仅因看起来相近就认定不支持。标注不完备无法完全消除，但可以报告审核范围与争议处理。负例越难，越需清楚解释它为何不能支持当前答案；否则所谓提升可能只是更好地迎合一个漏标的唯一来源，而不是提高知识利用能力。

<a id="rag-5-detail-56"></a>

### 10.21 同一模板的十个改写是十份独立证据吗

**题目：** 一个文档生成十个几乎等价问题，系统全部答对。将它们作为十个独立样本计算窄置信区间合理吗？

**解析：** 通常不合理。共享来源、答案和检索路径会造成相关错误，独立性并未由改写数量获得。应按真实抽样单位，例如文档、事件或问题家族分组，成对比较时一起重采样该组。若只有很少组，区间本身也不稳定，需要报告组数和设计限制。

训练随机种子与问题抽样是不同不确定性来源，也不该混成一批独立回答。可以保留改写来检验表达鲁棒性，但其结论是同一事实下的语言变化表现。统计单位与想推广的总体必须对应，否则精确的小数会掩盖实际上很少的信息。

<a id="rag-5-detail-57"></a>

### 10.22 评价器版本为什么也要冻结

**题目：** 新系统提交时使用了更宽松的支持判定，旧系统保留原评分。准确率提高能归因于模型吗？

**解析：** 不能。评分规则本身就是测量过程的一部分。应在同一问题、来源、标注和评价器版本下重算两者，或明确拆分规则变化带来的影响。自动评分器的提示、模型版本、采样和失败处理都需记录；人工评分也要有规则、盲评与分歧处理。

引用 ID 合法、答案等价和来源蕴含是不同判据，不能在版本升级中悄悄互换。若修正原标签错误，可以发布新版本并保留修订说明，而不是装作数值直接可比。实验的可追踪性不仅关乎训练代码，同样关乎“什么被算成正确”的定义。

<a id="rag-5-detail-58"></a>

### 10.23 为什么修复后还要重新记录失败账本

**题目：** 提升召回后，第一类失败减少，读取失败却增加，是否说明读取器退化了？

**解析：** 未必。更多困难题进入拥有完整上下文的子集，条件分母发生改变，即使读取器本身完全相同，读取失败数量和比例也可能变化。应同时报告同一固定问题上的端到端结果、阶段覆盖和按题配对的状态迁移。若想比较纯读取能力，可在预先固定的共同充分上下文上评价。

失败账本的作用是记录系统状态与因果干预线索，不是把每类计数当互相独立的性能指标。修复也可能改变上下文噪声并真实影响读取，需要进一步控制实验。先检查样本组成，再讨论模型机制，能避免从聚合比例作出过强结论。

<a id="rag-5-detail-59"></a>

### 10.24 下一项研究怎样提出可证伪假设

**题目：** 你想研究联合证据重排，怎样把“效果应该更好”改写成可以被实验否定的假设？

**解析：** 预先限定问题族、允许库、候选来源、预算与对照，例如在同一候选集合和八十字符预算下，新方法提高两事实连接题的上下文充分比例，同时不增加权限或时间违规。规定独立确认集、主指标、可接受成本和失败报告，再比较端到端支持正确率。

若候选本就缺失证据，重排不应被期待解决，这类题单独分层但仍进入总体结果。可以报告负结果：组合充分性提高而答案未改善，说明后续瓶颈仍在。研究假设的价值不在保证成功，而在失败时仍能解释哪条预期没有得到支持。

## 11. 综合研究项目与验收

<a id="sec-8-1"></a>

<a id="rag-5-detail-61"></a>

### 11.1 从局部反例扩展成可复核的系统研究

选择一个范围明确的版本化规则库，先用少量文档手工写出关系与时间条件，不急于接入大模型。为每道题保存允许范围、有效时间、标准命题、至少一组充分证据和不可答原因。构造等价来源、冲突版本、缺失连接、相近实体和权限差异。训练、开发与最终确认的问题按来源家族组织，明确固定库索引可以看见什么，监督训练可以看见什么。这样得到的是可审查协议，而不是先有回答再找解释。

第一阶段实现一个易审查基线，保留原文坐标、过滤结果、排序分数、候选 ID、打包成本、最终上下文与输出。输入字段、空库、重复来源和服务异常要有明确行为。用手工可解的小题验证来源映射及边界，再扩大规模。关闭一条关键证据时系统应出现预期变化，改变权限和时间时不应复用不适用的缓存。若最简单的关系连接尚无法解释，复杂模型只会增加归因困难。

第二阶段只选择一种改进，例如补充联合证据重排。固定候选库、预算、读取器和评价规则，记录新方法是否真正找到可部署的组合。用理想候选与理想上下文作诊断时，单独标注额外信息和超出预算，不混入正式系统结果。若改进同时改变检索与读取，报告整体收益可以成立，但不能把它归因于某一个组件。模块替换的对照与系统级竞争回答不同问题，报告应清楚说明重点。

第三阶段扩展评价到来源与问题家族，记录支持正确率、可答覆盖、不可答处理、权限时间约束、引用有效性和成本。样本量来自预期差异、组间变化和资源，而不是为了得到好看的比例。保留全部预设配置和失败，开发选择后在冻结确认集上运行。没有真实模型调用与硬件实测的项目，不应填推测的语言模型表现、延迟或显存。人工构造库能证明机制与实现边界，真实文档的阅读歧义则需要新证据。

<a id="rag-5-detail-62"></a>

### 11.2 交付如何满足“可以复核”

交付说明应让另一位读者能够从一个问题追到来源原文，再追到过滤、候选、打包和最终判分。对失败给出最早不满足条件及至少一次明确干预，记录该干预是否改变成本或信息条件。若无干预证据，只写待检验解释。图表或汇总表必须标清分母、单位、版本和是否包含超时。可复核不等于所有细节都放正文，可以通过结构化记录与清楚的协议减少重复，但不能省略影响结论的条件。

验收通过不表示系统永远可靠，而表示它在声明范围内满足了预设可检查条件。仍未覆盖的复杂自然语言、多层权限、迟到文档、多语言分词或长上下文行为应作为后续研究范围，而不是用一句“可扩展”当作已实现。真正有价值的进阶学习，是能把一个漂亮的总分拆成可验证的命题，知道哪些证据支持结论、哪些变化会让结论失效，再据此设计下一轮实验。
