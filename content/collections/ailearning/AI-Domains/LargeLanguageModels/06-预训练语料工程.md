# 第 6 章 预训练语料工程：筛选、去重、配比与污染控制

[主题目录](README.md) · [分类目录](../README.md) · [总目录](../../README.md) · [上一章](05-RAG系统拆解与评估集构建.md) · [先修：分词与语言建模](01-分词预训练与语言建模.md)

两套训练文件来自同一批网页，字节数和训练步数都差不多。第一套把转载、导航和题库解析一起交给模型，第二套把来源、版本、重复簇和评测边界分开记录。即使模型结构相同，两次训练看到的内容、重复次数和评测风险也会不同。本章要完成的任务是把一批有版本的原始文本变成一份可重建、可比较的训练语料，并解释每项规则到底改变了什么。

先修是第 1 章的分词、自回归目标和困惑度，以及[交叉验证与泄漏](../../MachineLearning/ModelEvaluation/02-交叉验证泄漏与公平比较.md)中的划分原则。第一遍阅读可顺着原始记录、去重、污染和配比走完第 1–5 节，再运行第 6 节。MinHash 推导、配比对照和语料重建说明补充了实现边界。正文使用同一批虚构来源讲清流程，实验只使用 Python 标准库。

## 1. 从原始记录到可重建的训练输入

<a id="corpus-identity"></a>

### 1.1 分清来源、记录、文本和训练位置

设有三类来源。档案馆公布维修记录，课程网站提供教学文章，镜像站会转载档案。一次抓取保存了一份网页，其中包含正文、导航、同页推荐和更新时间。第二次抓取可能只改变推荐内容，也可能修正正文中的数字。把 URL、抓取记录和正文统称为“文档”，很容易把这两种变化看成一回事。一个 URL 可以有多个抓取记录，一份正文可以出现在多个 URL，一份长正文又可能产生多个训练序列。

| 层次 | 示例标识 | 能回答的问题 |
| --- | --- | --- |
| 来源 | 网站、出版系列或上游数据集编号 | 语料主要来自哪里，哪些来源贡献了被训练的位置 |
| 抓取记录 | 快照、对象键、记录键和原始内容摘要 | 能否定位当时采集的字节 |
| 提取文本 | 记录键、提取器版本、正文摘要 | 哪项规则把同一网页变成了这一版正文 |
| 训练样本 | 语料版本、文档键、token 区间、分词器版本 | 某段输入在训练中是否出现、出现几次 |

![两个训练区间通过正文追溯到同一抓取记录](images/06-img-corpus-lineage.webp)

[打开原图放大](images/06-img-corpus-lineage.webp)

图中同一篇正文切成了两个训练区间。只保留打包后的张量，就很难判断哪段来自撤回的上游文档，也无法把指标变化定位到提取器或分词器。保留父级关系后，可以从某个训练区间回到正文、从正文回到抓取记录。若文本在清理中发生 Unicode 归一化、段落重排或替换，清理后的字符偏移便属于新坐标系。需要引用原始位置时，要保存映射，或明确记录只能定位到原始记录级。

快照时间与文本声称的发布时间也各自有用。前者回答“采集时看到了什么”，后者用于拟合某个时间范围的研究定义。页面显示一个旧发布日期，并不证明其正文在那个日期已经存在。时间实验至少要固定采集边界，并单列来源时间未知、事后修订和从后期存档恢复的内容。对时间不确定的记录，标明未知并定义处理规则，能够让别人用相同规则重建结果。

内容摘要适合核对是否为同一份字节，来源标识适合解释为什么会出现这些字节。若镜像与原站产生相同摘要，合并正文的同时仍应保留别名。尤其当原站和镜像的日期、许可元数据或可信程度不同，训练中采用哪一份代表记录要有可解释的优先级。只保留最先入库者，会把线程调度顺序变成代表规则。

<a id="corpus-filter"></a>

### 1.2 以可解释的规则提取和筛选

原始网页首先要提取正文。提取器可能把论坛回复误作导航，也可能丢掉代码块、题目的上下标、表格列或正文里的换行。抽样检验时要同时展示输入和输出。对于纯文本任务，可先看保留长度、重复行和异常字符。对于代码和数学，还需要逐类检查缩进、公式边界与列对应。仅报告“清理后变短”无法区分去掉菜单和删掉正文。

把筛选规则分成三类更容易调试。第一类来自使用条件，如来源在允许清单上、元数据完整，状态未知时送入复核。第二类来自可观测质量，如模板重复、正文缺失、错码。第三类来自任务偏好，如提高教材、代码或特定语言在预训练中的比重。三类可以使用相似的分数和阈值，但修改阈值后的解释不同。一个文体在任务偏好下被降权，不能据此判定该文体事实质量差。

例如，最少二十个词的规则会过滤一行菜单，也会删掉不少短术语条目。高符号占比会命中乱码，也会命中有效公式。将训练候选按语言、来源和长度分桶后，从保留与删除两侧分别采样，可看出失误是否集中在某种文本。若只抽常见语言，汇总通过率会掩盖小语种或低频文体遭到更高比例的删除。分组样本很小时，给出检查条数和发现的反例，比报出貌似精确的百分比更诚实。

给每条记录分配稳定的去向及理由。常见状态包括进入下一阶段、仅复核、已知不符合范围和重复别名。一条记录同时命中多个规则时，可以记录全部理由，并另外标出主要处置理由。此时“第一条命中规则删除了多少”和“存在某类问题的记录有多少”会是两个不同统计量。更换规则顺序可能只改变原因分布，也可能因先做了文本变换而改变保留集合，必须区分。

处理敏感内容时，限制谁能看原始材料以及记录保存多久。普通哈希用于完整性检查和候选匹配，对于可枚举的短标识，哈希值可被猜测比对。用于分享的报告以聚合计数和合成例子展示问题；原始内容与处置日志需要依照各自访问要求管理。为训练保留一份正文，同时让处置过程可追溯，需要分别设计这两个接口。

## 2. 先定义什么算重复，再选择算法

<a id="corpus-exact"></a>

### 2.1 精确、近似与片段级去重

精确去重的关键是指定比较表示。按原始字节比较时，换行编码不同就会得到两个对象。按正文规范化后的字节比较时，去掉连续空白或归一化 Unicode 可能让它们成为同一个对象。对普通叙述，这种合并有时合理。对程序代码，缩进可能改变语义。先定义文本类型和规范化版本，再计算 SHA-256 等摘要，便于快速查候选。需要严格判定时，可在摘要相同后核对字节。短摘要和跨任务过强的规范化都会增加错合并风险，前者来自表示碰撞，后者来自主动丢失信息。

片段级检测处理另一类问题。一篇长文章只引用了一道题，全文差异很大，却可能完整暴露这道题的答案。可以查找共享长片段，或者把长文切窗后比较。窗口越小，越容易匹配样板语言，且位置报告的数量会上升。阈值越长，越容易漏掉短题和改写。代码、诗歌和问答的典型长度不同，检验区间应与风险单位匹配。把所有任务都折成文档相似度，会使短内容在长文中被稀释。

近似文档去重常把相邻 $`k`$ 个符号作为一个片段，称为 shingle，再比较片段集合。符号单位可以是空白分词、字符、字节或某个训练分词器的 token。改变单位会改变相似度的解释。对没有空格的文本，直接按空格切分几乎失效。对于 HTML 主体，先去掉公共导航可以降低共享模板的影响。若关心重复次数，集合只保留是否出现，使用频次向量或另外计算重复率更合适。

设两份短记录分别为 `a b c d` 和 `a b c e`。二元片段集合分别为 $`S=\{ab,bc,cd\}`$ 和 $`T=\{ab,bc,ce\}`$，共享两项，并集四项，Jaccard 相似度为 $`\frac{1}{2}`$。把比较单位改为单词集合，共享三项，并集五项，相似度变为 $`\frac{3}{5}`$。同一对记录使用两种单位可能落在不同阈值两侧，阈值必须与特征表示一起报告。长度不足以生成一个片段时，要明确采用短文本规则或只走精确比较；把两个空特征集合定义为相似会制造大量误报。

<a id="corpus-minhash"></a>

### 2.2 Jaccard、MinHash 与分带候选

对于非空有限集合 $`S,T`$，令 $`J(S,T)=\frac{|S\cap T|}{|S\cup T|}`$。取一个对并集元素的均匀随机排列，分别记录两个集合中排在最前的元素。两个最小值相等，当且仅当整个并集中最前的元素属于交集。因为这个元素均匀落在并集上，单次签名相等的概率正好是 $`J`$。这是理想随机排列下的结论。工程实现用多个近似独立的哈希次序代替排列，要另行检查哈希碰撞和相关性。

若采用 $`m`$ 个独立排列，记第 $`i`$ 位是否相等为 $`I_i`$。各 $`I_i`$ 是参数为 $`J`$ 的伯努利变量，于是

```math
\widehat J=\frac{1}{m}\sum_{i=1}^{m} I_i.
```

期望由每个指示变量的均值给出。独立性使方差可以直接相加，得到

```math
E[\widehat J]=J,\qquad
\mathrm{Var}(\widehat J)=\frac{J(1-J)}{m}.
```

以 $`m=100`$、$`J=\frac{1}{2}`$ 为例，标准差为 $`0.05`$。如果直接用签名估计和阈值比较，靠近阈值的记录在换种子后可能改变去向。常见做法是先用签名产生候选，再用精确相似度或更针对业务的规则复核。复核能去掉误报，找不回候选阶段漏掉的真实邻居。可以在小型金标准上枚举全对，以直接估计候选召回和复核精确率。

分带把签名切成 $`b`$ 个互不重叠的带，每带有 $`r`$ 行。在独立理想化下，一带完全相同的概率为 $`J^r`$。任一带相同就进入候选，因此入选概率为

```math
P(\text{进入候选}\mid J)=1-(1-J^r)^b.
```

令 $`b=10,r=4`$。当 $`J=0.8`$ 时，候选概率约为 $`0.995`$。当 $`J=0.5`$ 时，仍约有 $`0.476`$ 的概率进入候选。候选列表有低相似度样本，符合设计预期。增大带数会提高高相似度的召回，也会增加更多候选对。固定签名长度 $`br`$ 时，增大带长通常同时减少带数，两者都使候选更难命中。实际还要看桶大小分布；模板页面进入大桶时，桶内两两比较成本可能抵消索引收益。

对一个包含三百条记录的标注子集，可以先算出四万四千八百五十个文档对的精确相似度，将阈值以上的对作为这一表示下的参照。然后固定签名配置，统计参照对中有多少进入候选，以及同一对在几个带中重复命中。前者回答召回，后者决定候选列表是否应先去重。再从阈值上下和最大几个桶里抽样人工复核，判断片段相似度本身是否契合要保护的文档关系。精确阈值是索引的参照，人工标签才用于评估阈值是否有用。

扩大到多个分片时，可以用带编号与签名片段作为分区键，使跨分片的同带记录在同一处比较。输出文档对时用排序后的稳定记录键，汇总时先合并重复命中，再复算相似度。若系统为了控制成本而截断大桶，要把截断策略当成候选规则的一部分。此时未进入候选可能是签名不相等，也可能是系统丢弃了桶内后半段。记录截断的桶和按来源分组的漏检率，才能判断节约的算力是否以某类文档的召回为代价。

### 2.3 相似关系不传递，簇策略会改变数据

设相似阈值为 $`\frac{2}{3}`$。三份文档的特征集合分别为 $`A=\{1,2,3,4\}`$、$`B=\{1,2,3,4,5,6\}`$、$`C=\{3,4,5,6\}`$。则 $`J(A,B)=J(B,C)=\frac{2}{3}`$，而 $`J(A,C)=\frac{1}{3}`$。边表示“该对达到阈值”。若按连通分量只保留一个代表，A 和 C 也会被并到一起。中间记录 B 可能是把两个主题拼接起来的页面，删除 C 会丢掉 A 未覆盖的内容。

![A 与 B、B 与 C 的相似度均为三分之二，A 与 C 仅为三分之一](images/06-img-similarity-linkage.webp)

[打开原图放大](images/06-img-similarity-linkage.webp)

同一个图有两种合理用途。用于防止跨集合泄漏时，如果定义每条可信依赖边的端点必须同侧，那么沿连通分量分组是最细的合法划分。用于决定正文只留一份时，要求“代表能代替成员”需要额外证据。可以逐个检查与代表的相似度，或记录簇的最弱关系并人工审阅大簇。两步目的不同，哪怕使用同一份候选图，也可以得到不同的保留结果。

具体选择还会影响来源构成。若先遇到的一份来自转载站，首次保留策略可能把原始发布的来源归属洗掉。稳定做法是先排除不合格候选，再按可追溯来源、正文完整度和固定键决定代表，保留别名映射。含版本演化的语料也可以保留一对有明确变更关系的记录，再分别报告静态快照与版本学习的统计。记录代表的选择规则，才能在删除来源或刷新抓取后解释为什么代表发生变化。

## 3. 划分边界与污染证据

<a id="corpus-split"></a>

### 3.1 先建立依赖分组，再分配训练与评估角色

设课程站的一道题进入评估集，镜像站转载了原题，讲解博客另写了答案。只按域名划分，镜像和讲解仍可能在训练侧。按完全相同的文本划分，也会漏掉改写和裁剪。应先根据已知的文档系列、题目族、原文链接及可信近重复边建立依赖组，再按用途分配训练、开发、最终评估或隔离。本文将这一分组称作防护组。分组规则应解释它保护的结论，例如“该题目族第一次出现时的表现”，并给出没有覆盖的依赖类型。

![题目、镜像和解析归入同一留出组，独立文档留在训练侧](images/06-img-family-holdout-boundary.webp)

[打开原图放大](images/06-img-family-holdout-boundary.webp)

当某组已经被指定为评估用途时，训练侧的同族候选要隔离。评估项目固定的单位仍是预先冻结的题目；隔离组中的镜像和解析无需加入评估题集。若大量文本被一条很弱的相似边连成大簇，先区分高可信依赖与待复核候选。对影响很大的边，保留证据和人工判断。将所有相似边自动作为分组约束，可能把评估的来源范围缩到很窄，并改变被测任务。宁可记录这一决策，也不要将结果写成单个含义模糊的“已去重”。

有时间限制时，先定义评估对象和它在何时真正可用，再处理同组记录。不能为了让同组完整就把未来的版本整体搬进训练侧。可以把跨界的训练候选排除并报告损失，也可以把整个组固定为留出，只在合法时间范围内抽取评估项目。对按来源泛化的任务，可以留出整站，但仍要检查站间转载。若原始文档按这些规则入库，分词器和需拟合的数据规则也应遵守目标实验的角色边界。使用预先存在的固定分词器时，要区分分词器版本已固定与分词器的训练语料已知。

一次划分要能重放。稳定哈希可用来给普通组分配角色，输入应明确包含组键、盐和版本，不能使用随进程变化的语言内置哈希。将哈希映射到区间后按区间分配只能得到预期比例，重量差别很大的组会让实际 token 比例偏离设计值。冻结时记录组数、文档数、token 数以及来源构成。若要针对目标构成进行分层或平衡，先固定该算法和可用元数据，再生成最终角色表，避免看过模型分数以后反复挑选边界。

<a id="corpus-overlap"></a>

### 3.2 评测重合的证据强度与处置

污染指评估所需信息通过训练等路径被提前暴露，导致相应的泛化解释受到影响。判定首先依赖评估声称测什么。常识问答的事实出现在教材中可能符合任务设定。评估题的具体措辞、答案对和独特评分模板大范围出现在训练中，则会削弱“面对未见题目”的解释。同一段文本出现在检索知识库中的含义也取决于任务。开放书本测试可以要求模型读到知识来源，但把待回答的题和标准答案一起放入索引，会改变实际被评估的能力。

| 证据 | 适合发现 | 主要盲点 |
| --- | --- | --- |
| 精确文档或规范化字段匹配 | 原样复刻、只改外层包装 | 裁剪、翻译和改写 |
| 长子串或局部片段匹配 | 长文中嵌入题目、答案或代码 | 短题和常见表述难区分 |
| 近似检索加人工审阅 | 改写、相关材料、含上下文的转载 | 需要审阅标准，容易受文体影响 |
| 输出侧探针 | 无法查看训练语料时的异常迹象 | 低损失和高准确率可以来自熟悉领域，不能当作通用证明 |

审阅时保存命中单位、规范化方法、两侧位置、字段类型和判断原因。把“同题同解”“题干相同但选项变化”“共享术语”和“无法判断”分开。若只核对题干，可能遗漏训练语料里的答案解释。若将答案作为普通短字符串搜索，会把常用值误认为泄漏。可优先使用题干上下文与答案组合来定位，再对短题和多语言题做人工或针对性的检索。

阈值不能靠一个可疑命中的截图确定。可从相似度各区间采样，让审阅者判定证据。还需抽查未命中样本，例如手工构造的译写和截断对，以估计明显漏检。规则的检出率取决于对照样本如何选，无法用对一份合成集的高召回证明对真实网络资料也高召回。若只拿得到已经公开的语料子集，可以报告“在这个版本和这些规则下未检出”，并单独标出未覆盖的来源。

冻结最终评估后，最好同时报告原始题集与事先定义的隔离子集，说明样本量和题型变化。在看到结果后删除“表现太好”的题，再把剩余分数当主要结果，会引入选择偏差。匹配样本的分数高也可能因为题目本身容易。要估计暴露影响，可以在同一训练配方下对一组文档做添加或替换，或比较设计匹配的未见变体，分别报告难度与表面形式改变的影响。

## 4. 把数据量换成实际训练暴露

<a id="corpus-weights"></a>

### 4.1 文档采样率和 token 份额的换算

设每次独立选择一个来源 $`s`$，概率为 $`q_s`$。从该来源抽一份文档，它实际贡献的有效监督位置平均为 $`\mu_s`$。在各次抽样独立同分布、均值有限且总均值为正的简化设置中，抽取足够多文档后，来源在有效位置中的份额趋于

```math
w_s=\frac{q_s\mu_s}{\sum_j q_j\mu_j}.
```

这个式子由分子和分母的样本均值分别收敛得到。它说的是长程份额，有限批次的份额仍会波动。若系统采到的是定长片段，或在打包中按位置设固定配额，就应按真实采样单位计算，不必套用文档抽样公式。

例如课程短文平均贡献 $`100`$ 个有效位置，档案长文平均贡献 $`400`$ 个位置。各抽一半文档时，课程只占有效位置的 $`\frac{1}{5}`$，档案占 $`\frac{4}{5}`$。若希望各占一半，令 A 代表课程、B 代表档案，文档抽样概率可设成 $`q_A=\frac{4}{5}`$、$`q_B=\frac{1}{5}`$。一般情况下，在各 $`\mu_s>0`$ 时，目标位置份额 $`w_s`$ 可换算为 $`q_s\propto\frac{w_s}{\mu_s}`$。若一个来源的监督位置均值为零，就无法仅靠调文档采样率给它分配正的监督份额。

![两类文档等量抽取时，短文只贡献五分之一有效位置](images/06-img-document-and-token-mixture.webp)

[打开原图放大](images/06-img-document-and-token-mixture.webp)

图中以每格一百个有效位置表示长短差异。实践中先确定份额是按输入 token、有效预测目标、字节、文档还是更新步数定义。序列首位、补齐 token、被掩码的边界和上下文都可能改变有效位置数量。一段文本经不同词表分词后产生不同数量的位置。若比较数据规则，固定分词器有助于把分布变化与计量尺变化分开。若刻意同时比较不同分词器，应补报字节、字符或原始文档等可共同解释的分母。

抽样概率也不是训练梯度的精确贡献。某来源虽然占一半位置，损失水平、梯度大小和批次归约仍可与另一来源不同。如果先对文档内损失取平均，再对文档取平均，短文中的单个位置得到更大权重。逐位置平均得到另一目标。应把数据配比、实际数据暴露和损失归约分别记录，避免把数值相同的文档比误作相同的优化目标。

<a id="corpus-packing"></a>

### 4.2 唯一内容、重采样与打包

设可用语料某来源含一百万个唯一位置，实际训练抽到三百万个位置。这三百万是暴露计数，可能反复取自同一文档或局部。衡量覆盖应额外记录被选中的不同文档和不同位置。无放回采样耗尽后，系统需要明确停止、换来源或重新洗牌进入下一轮。放回采样支持稳定的目标份额，却可能让小来源重复率很高。

在每次均匀独立抽取一个文档的简化模型中，来源有 $`M`$ 份文档，抽 $`n`$ 次。固定文档至少被选一次的概率为 $`1-(1-\frac{1}{M})^n`$。把各文档的被选指示变量相加，得到不同文档数的期望

```math
E[U]=M\left[1-\left(1-\frac{1}{M}\right)^n\right].
```

该推导只用期望的线性性，无需文档间的出现事件独立。取 $`M=100`$、$`n=100`$ 时，期望只覆盖约 $`63.4`$ 份。无放回取同样一百次则覆盖全部。语言模型训练中，如果一条文档只被截取部分位置，文档覆盖还会高估 token 覆盖。相反，给同一记录的不同增强版本分配新键，会让唯一记录数看起来增长，却未必增加独立来源。

将短文拼成定长训练序列时，要定义分隔符、预测边界和注意力边界。若允许后文读前文，模型看到的是连续流。若训练语义要求每份文档独立，仅插入一个分隔符未必够，还要控制跨文档注意力和跨边界的预测目标。截断窗口重叠时，同一原文位置可能多次参与损失。可给打包样本保存文档键和区间表，并检查相邻两文档之间的目标是否符合协议。训练配置中的最大长度无法回答一个真实位置到底被看到多少次。

并行处理时，分片、种子、迭代器状态和去重作用域决定能否重建语料。同源数据分散到多个工人时，单工人去重只能保证分片内部，无法消除跨分片重复。顺序改变导致首次命中的代表不同，也会改变最终构成。可以先按稳定键重分区或形成全局索引，随后用固定优先级确定代表。训练恢复时，再分别验证数据遍历游标和有效位置计数，以免已经训练过的块被额外重复而报告仍显示相同预算。

## 5. 设计能够解释结果的对照实验

<a id="corpus-control"></a>

### 5.1 固定预算，同时报告来源构成

比较两种清理策略之前，先写出问题。若问题是“固定训练预算下，加入新筛选规则对模型有何影响”，则各臂应使用相同的模型结构、初始化方案、分词器、训练目标、优化日程和评估题集。训练 token 数、序列长度与有效位置计数也要对齐或分别报告。若同时删掉半数数据又减少训练步数，难以把差异归因于筛选策略。若用重复抽取填补删掉的文本，重复率本身就是干预的一部分，需要记录。

想拆开两种机制，可以构造两个问题。第一组允许筛选自然改变配比，估计规则作为整体的影响。第二组在来源内替换并约束各来源份额，尽量隔离文本质量或重复率变化。两组可能得到不同结果。前者更贴近默认部署的语料配方，后者帮助解释分数来自来源重分配还是同来源的内容变化。若无法在某个来源内找到足够替代文本，应报告不可比较的范围，不能把随机复制当成无害补足。

| 实验条件 | 尽量保持一致 | 同时记录的变化 |
| --- | --- | --- |
| 同预算比较筛选策略 | 模型、分词器、有效位置预算、评估协议 | 来源份额、每来源唯一覆盖、替换与重复 |
| 同来源比较去重范围 | 来源目标份额、训练预算、分组边界 | 每个来源的跨快照重复和损失类型 |
| 比较候选生成方法 | 片段表示、复核判定、金标准抽样 | 候选规模、漏检、误报与尾部大桶 |
| 比较混合配方 | 数据池、分词器、日程与评估方式 | 位置份额、暴露次数和分组损失 |

评价既需要开发阶段的可重复观测，也需要未用于选配方的最终任务。可同时保留整体与分组困惑度、几个异质下游任务、训练成本和数据处理成本。避免只给一个平均分，让关键领域的损失被常见任务平均掉。随机性较大的实验可使用多种子，配对比较相同种子下的差异，并注明种子数量。单次实验中若某个下游任务跃升，还要检查污染、采样方差和误差条的计算单位。

实验前也可以写清哪些变化无需跑模型就能确认。例如，跨训练评估组的数量、有效位置预算、簇大小和来源份额可从清单直接复算。小型训练实验只能展示一种机制是否存在及方向是否与预期一致。若用小模型挑选几个有希望的候选，最后仍要在目标规模下确认排序，因为模型容量、训练预算与重复率的相互作用可能改变结论。

<a id="corpus-papers"></a>

### 5.2 怎么读语料论文里的正结果和负结果

FineWeb把正文提取、过滤及去重范围拆开比较。值得复查的是其去重实验中的反例：在论文比较的配置中，更广范围地删除重复并未稳定带来更好的模型评估结果，作者最终采用按抓取快照去重的方案。阅读时可把去重范围、实际训练数据量和评测聚合分开记录。这个观察提供了设计对照的理由，无法直接替代另一个数据池或任务上的实验。

DataComp-LM提供标准化数据池、训练配方和下游评估，使过滤、去重及混合策略可以在指定预算内比较。复现其中一个对照时，先确定论文版本与对应代码和数据快照，再核对模型规模、训练 token 数、训练前处理及评估变体。论文中某种模型打分过滤器效果好，仍需要检查它偏向什么文本，在其他语言和文体上是否保留了想学的内容。

DoReMi展示了利用小代理模型调整训练域权重的办法。它给了比“按库存比例抽取”更明确的优化问题，但应用时仍要定义域、参考模型与评估目标。给重要领域更多位置，可能改善该领域，也可能消耗其他领域的覆盖。代理规模与目标规模之间的迁移是需要验证的经验问题。若小来源只能反复提供有限文档，质量与多样性也可能在高权重下出现新的瓶颈。

## 6. 实验一：从记录清单得到训练与隔离清单

<a id="corpus-lab-one-code"></a>

### 6.1 运行流水线并复算规则效果

这组材料完全虚构。用空白切分保留易于复核的词序，正式语料需按文本类型决定规范化方式。清单中已经冻结一条评估题 `e1`，其他条目都是候选。镜像 `t2` 与原始记录 `t1` 只差空白。后续维修记录 `t3` 和它们很像，但最后一个部件不同。长文章 `t5` 包含整道评估题，改写 `t6` 则靠显式题目族标识接到评估边界。另有一篇来源状态未明、一个模板页，以及与题目无关的短指南。以下代码可复制到独立文件运行。

```python
from dataclasses import dataclass, replace
from fractions import Fraction
from hashlib import sha256
from itertools import combinations

@dataclass(frozen=True)
class Record:
    key: str
    source: str
    family: str
    text: str
    decision: str = "allowed"
    role: str = "candidate"

records = [
    Record("e1", "exam", "valve-quiz", "what color marks valve amber",
           role="evaluation"),
    Record("t1", "archive", "maintenance", "pump filter clog check gauge"),
    Record("t2", "mirror", "maintenance", "pump  filter clog check gauge"),
    Record("t3", "archive", "maintenance", "pump filter clog check valve"),
    Record("t4", "guide", "storage", "dry tools before winter storage"),
    Record("t5", "mirror", "mirror-notes",
           "notes what color marks valve amber archived"),
    Record("t6", "guide", "valve-quiz", "amber identifies that control"),
    Record("t7", "guide", "unknown-source", "record wheel damage before use",
           decision="review"),
    Record("t8", "mirror", "navigation", "menu menu menu menu menu"),
]
priority = {"archive": 0, "guide": 1, "mirror": 2}

def words(text):
    return tuple(text.lower().split())

def shingles(tokens, size):
    return {tokens[i:i + size] for i in range(len(tokens) - size + 1)}

def contains(haystack, needle):
    return bool(needle) and any(
        haystack[i:i + len(needle)] == needle
        for i in range(len(haystack) - len(needle) + 1)
    )

def build(rows):
    normalized = {r.key: words(r.text) for r in rows}
    if len(normalized) != len(rows):
        raise ValueError("record keys must be unique")
    evaluation = sorted(
        (r for r in rows if r.role == "evaluation"), key=lambda r: r.key
    )
    candidates = sorted(
        (r for r in rows if r.role == "candidate"),
        key=lambda r: (priority[r.source], r.key),
    )
    manifests, reasons, representatives = {}, {}, {}
    for r in evaluation:
        manifests[r.key] = "evaluation"
        reasons[r.key] = "frozen evaluation item"

    for r in candidates:
        tokens = normalized[r.key]
        hits = [e.key for e in evaluation if
                r.family == e.family or contains(tokens, normalized[e.key])]
        if hits:
            manifests[r.key] = "quarantine"
            reasons[r.key] = "evaluation:" + ",".join(hits)
        elif r.decision != "allowed":
            manifests[r.key] = "review"
            reasons[r.key] = "source decision pending"
        elif len(set(tokens)) < 3:
            manifests[r.key] = "reject"
            reasons[r.key] = "too few distinct words"
        elif tokens in representatives:
            manifests[r.key] = "alias"
            reasons[r.key] = representatives[tokens]
        else:
            manifests[r.key] = "train"
            reasons[r.key] = "eligible representative"
            representatives[tokens] = r.key

    train = sorted(key for key, role in manifests.items() if role == "train")
    candidates_for_review = {}
    for a, b in combinations(train, 2):
        sa = shingles(normalized[a], 2)
        sb = shingles(normalized[b], 2)
        if sa and sb:
            score = Fraction(len(sa & sb), len(sa | sb))
            if score >= Fraction(3, 5):
                candidates_for_review[a, b] = score

    digests = {
        key: sha256(" ".join(tokens).encode("utf-8")).hexdigest()
        for key, tokens in normalized.items()
    }
    return manifests, reasons, candidates_for_review, digests

result = build(records)
roles, reasons, near, digests = result
assert result == build(list(reversed(records)))
assert {k for k, v in roles.items() if v == "train"} == {"t1", "t3", "t4"}
assert {k for k, v in roles.items() if v == "quarantine"} == {"t5", "t6"}
assert roles["t7"] == "review" and roles["t8"] == "reject"
assert roles["t2"] == "alias" and reasons["t2"] == "t1"
assert digests["t1"] == digests["t2"]
assert near == {("t1", "t3"): Fraction(3, 5)}

changed = [
    replace(r, family="undetected-rewrite") if r.key == "t6" else r
    for r in records
]
assert build(changed)[0]["t6"] == "train"

for key in sorted(roles):
    print(key, roles[key], reasons[key])
print("near pairs for review:", near)
```

手算近重复对时，`t1` 的相邻词对有四个，`t3` 也是四个。前三个相同，最后一个不同，所以并集大小为五，相似度为五分之三。这里近重复命中仅生成审阅候选。维修部件不同，读者可以决定两个事实都保留；若把命中一律当作自动删除，会失去一条真实的维修变化。精确去重以词序列为键，因此无需依赖摘要无碰撞的假设。摘要另行生成，便于模拟后续的清单引用。

冻结评估行和隔离行的职责不同。`e1` 作为题目留在评估集合，`t5` 和 `t6` 不能进训练，也不需要变成评估项目。`t5` 由完整片段触发，`t6` 由已知题目族触发。改动 `t6` 的题目族后，文本规则不再识别它，断言应看到它落入训练。这是有意构造的漏检。工程中要通过来源谱系、改写对照或另一种检索补救，同时报告哪些信号缺失。

<a id="corpus-lab-one-check"></a>

### 6.2 用重放和破坏性变体验证协议

逆序重放应得到相同结果。若改成按输入顺序保留第一份，倒序时可能选中镜像，语料文本虽然相同，来源归属已经变化。可以把实验再分成两片，在片内各自去重，观察两片合并后为何有重复。修复可在合并时统一对候选定代表，或按精确键先重分片。近似去重的跨片处理更复杂，因为同一记录可落入多个桶，重复候选还需要稳定合并。

再人为加入一条共享标题却不含答案的文章，检查整题检测是否会误伤它。随后用插入一个词或重排一个短语的方式改动 `t5`，比较整题连续子串与窗口近似检测的结果。每次增加规则都应有一个阳性和一个阴性对照；阳性检验能否命中想发现的现象，阴性检验是否破坏正常样本。规则覆盖率和真实污染风险是不同量，实验只允许从前者推断已覆盖的情形。

这段程序按每个候选与冻结题目比较，并在训练子集上枚举近似对，适合小样本核对。没有实现大规模分带索引，也没有沿任意相似边构造全图。文档族归并可用并查集维护，并与小样本全对比较结果核对。规模化时需记录被拒、审阅与隔离对象的用途，尤其要防止复核队列的后续导出回流到正式训练列表。

## 7. 实验二：同预算下看配比和污染的作用

<a id="corpus-lab-two-code"></a>

### 7.1 用可手算的计数语言模型作对照

把每个例子视为一次“前缀后预测一个词”的监督。模型对给定前缀分别统计两个候选答案 `dry` 和 `wet`，采用加一平滑。来源 A 的短指南每份贡献一个监督位置，来源 B 的长档案每份贡献四个。所有真实训练和评估单位在这个实验里都显式写出，便于单独控制暴露。

第一组比较都使用二十个监督位置。各取四份短、四份长时，指南贡献四个位置；各取十二份短、两份长时，指南贡献十二个位置。两臂保留相同的文档内构造，改变来源份额。第二组固定二十个位置、固定四个指南位置，把两条指南记录替换为对同一测试前缀的原样暴露。另给一个改写测试前缀，它在任何训练臂里都没出现。两组分别检验配比和具体暴露，不能把第一组的来源效应当作第二组的污染效应。

![固定有效位置预算后，改变来源配比与替换为原样前缀是独立干预](images/06-img-controlled-corpus-exposure.webp)

[打开原图放大](images/06-img-controlled-corpus-exposure.webp)

```python
from collections import Counter
from fractions import Fraction
from math import log

def short_guide(n):
    return [("guide", "storage", "dry")] * n

def long_archive(n):
    return [("archive", "storage", "wet")] * (4 * n)

def probability(rows, prefix, answer):
    counts = Counter(y for _, x, y in rows if x == prefix)
    if answer not in ("dry", "wet"):
        raise ValueError("the model has a two-word answer vocabulary")
    return Fraction(counts[answer] + 1, sum(counts.values()) + 2)

baseline = short_guide(4) + long_archive(4)
new_mix = short_guide(12) + long_archive(2)
exposed = (
    short_guide(2)
    + [("guide", "quiz:tool-cabinet", "dry")] * 2
    + long_archive(4)
)

def source_counts(rows):
    return Counter(source for source, _, _ in rows)

assert all(len(rows) == 20 for rows in (baseline, new_mix, exposed))
assert source_counts(baseline) == source_counts(exposed)
assert source_counts(new_mix) == {"guide": 12, "archive": 8}

assert probability(baseline, "storage", "dry") == Fraction(5, 22)
assert probability(new_mix, "storage", "dry") == Fraction(13, 22)
assert probability(baseline, "quiz:tool-cabinet", "dry") == Fraction(1, 2)
assert probability(exposed, "storage", "dry") == Fraction(3, 20)
assert probability(exposed, "quiz:tool-cabinet", "dry") == Fraction(3, 4)
assert probability(exposed, "quiz:cabinet-paraphrase", "dry") == Fraction(1, 2)

for label, rows in [("baseline", baseline), ("new mix", new_mix),
                    ("exposed", exposed)]:
    print(label, dict(source_counts(rows)))
    for prefix in ("storage", "quiz:tool-cabinet", "quiz:cabinet-paraphrase"):
        p = probability(rows, prefix, "dry")
        print(" ", prefix, str(p), "loss", round(-log(p), 4))
```

对 `storage`，基准臂观察到四次 `dry` 和十六次 `wet`，所以平滑后分子为五，分母为二十二。修改配比后分子变为十三，分母仍为二十二。这展示了数据配比如何直接改变经验目标，即便训练过程和预算完全相同。若目标用户的正确选项在两个环境中不同，应分别按环境评估。没有环境标签时，把混合概率提高理解成整体能力改善，会掩盖两个环境的冲突。

对原样测试前缀，基准臂无观察，概率回到均匀。暴露臂观察了两次正确答案，分子为三，分母为四。改写测试的概率保持二分之一，因为这个计数模型不会跨前缀共享参数。与此同时，暴露臂少了两个 `storage` 指南位置，因此它在通用前缀上的 `dry` 概率为 $`\frac{3}{20}`$。固定预算的替换总会改变被替代位置的暴露，本例恰好能把这项代价单独算出来。

### 7.2 对照如何推广，结论在哪里结束

换成有共享参数的语言模型后，改写前缀也可能受暴露影响。要分别控制题目、解答、改写、重复次数与语言，再测未暴露同难度题、不同措辞版本和原样版本。多次采样、不同模型规模及文档顺序都会影响估计。可用每个题目族内的成对差异来汇总，并以题目族而非逐次解码为独立单位估计波动。对于人工改写，先用标准答案核对题义是否等价；语法相似不足以保证难度相同。

要模拟配比的代价，可固定评估来源分布，再把第三个小来源加入训练。若该来源只有一条文档，可把它的训练暴露逐步从零提高到十次，并报告唯一来源数没有同步增加。记录总预算、每个来源被选中的唯一位置、重复位置和组损失。如果做完只看整体困惑度，就无法看出整体变好是否以小来源受损为代价。比较不同配方时，尽量先在清单层核实干预确实发生，再用训练结果解释剩余差异。

这个实验刻意避免大型模型和外部语料。它能检查分母、份额、局部记忆和预算替换的方向。扩大规模时可以保留同一结构，把手写计数替换为小模型，把玩具前缀替换为事先冻结的题目族。可重复实验的重点是能精确说明更换了什么，以及如果模型分数上升，有哪些机制仍然无法由这次对照区分。
