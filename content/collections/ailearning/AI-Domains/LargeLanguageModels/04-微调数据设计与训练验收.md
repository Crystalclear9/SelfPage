## 1. 先从行为变化倒推数据

微调问题应写成“在什么输入条件下，希望输出怎样变化”，而非“有多少条问答就训练多少条”。稳定格式、领域术语、证据引用、拒绝无据断言和工具参数结构是不同目标，对应不同监督与验收。若知识每天更新，检索和版本化来源可能比反复写入参数更容易维护；若主要改变稳定行为，微调可以研究，也可以与检索组合。方法选择由目标和证据决定，不由一个流行名称决定。

数据中目标回答若只在礼貌程度或长度上变化，模型可能主要学习风格；若重复模板数量很大，训练损失可能很低，却没有覆盖新表达和边界。应列出任务族、输入长度、来源、语义难度、可回答性、格式与失败类型，再规划训练和评价。样本数量是一个计数，覆盖是关于任务空间的陈述，二者不能相互替代。

<a id="llm-4-detail-2"></a>

### 1.1 一条样本包含哪些语义对象

一条监督样本至少包含来源与时间、角色化输入、允许读取的证据、目标回答、有效性和损失位置。答案来自专家、模型生成、规则或后续事实时，各有质量条件，不能因为都写成文本就当成等价真值。还要保留答案在原证据中的支持关系，尤其数字、单位、日期、否定和冲突处理；一个语言流畅的错误答案仍会被似然目标认真拟合。

角色是执行协议的一部分，检索到的文档内容不应因出现某个角色分隔字符串就自动变成系统指令。模板序列化要保证控制标记来自可信结构，而普通文本按内容编码。否则训练样本看起来格式统一，实际不同来源可能改变角色边界。微调不会自动修复序列化混淆；数据处理和模型目标需要共同保证它学到的是预期条件分布。

<a id="llm-4-detail-3"></a>

### 1.2 来源与任务族分别隔离

本节的隔离单位是任务适配中的来源和任务族。若要检查底座预训练的文本暴露，先读[预训练语料中的划分边界与污染证据](06-预训练语料工程.md#corpus-boundary)，再分别记录底座与微调数据可核验的范围。

同一文档、事件或模板派生的多条问答往往相关。按问题字符串随机拆分，可能把同一事实的改写分到训练和验证，测试主要测记忆来源。若目标是新来源，应按来源隔离；若目标是新指令表达，还需独立表达或模板族；若是未来知识，明确版本与可得时间。多个轴不一定能同时严格覆盖，要分别设计问题并说明限制。

先分角色再生成训练改写，能减少派生样本跨界。近重复检测帮助发现候选，但语义相似不等于同一来源，字节不同也不等于独立。保留谱系与人工核对依据，而不是靠一个相似度阈值宣称所有泄漏已消除。评价集也不能只包含方便生成的标题问句；应覆盖歧义、证据不足、冲突、非法格式和目标场景中的真实频率。

<a id="sec-1-1"></a>
<a id="llm-4-detail-4"></a>

### 1.3 条数、有效词元与独立信息

一百条各十个有效回答位置，与十条各一千位置，监督数量不同。若按词元平均，长回答贡献更多总权重；若每样本先平均再等权，短回答单位置相对权重更高。复制同一模板增加曝光，不增加同等独立信息；只统计条数无法判断哪个任务族实际主导梯度。应同时记录来源数、独立问题数、有效回答位置与重复程度。

某任务有很多长低质量回答时，它可能以词元数量占据大部分优化，即便样本条数不多。任务混合权重可以改变这个比例，但应从目标风险推导，而不机械追求各类条数一致。训练抽样、损失权重和评价总体也要分别说明。均衡训练可能有助小类，却不自动产生部署分布校准；最终评价仍需与实际用途一致。

## 2. 右移、损失掩码与截断共同定义目标

对完整序列 $`z_0,\ldots,z_T`$，因果语言模型输入前缀，位置 $`t`$ 的 logits 预测 $`z_{t+1}`$。监督区域由目标符号在原序列中的身份决定，再映射到右移标签位置。若先随便标一张同形 mask，再对输入和标签各自切片，容易错一位。提示、回答、结束和填充应逐项手算，不能只因最终损失是标量就认定目标正确。

<a id="llm-4-detail-6"></a>

### 2.1 回答起点怎样映射到标签轴

若原序列中回答首符号索引为 $`a`$，其监督位于右移标签索引 $`a-1`$，该位置的输入是回答前最后一个符号。结束符通常是有效监督，用来学习何时停止；填充不参与有效分母。多轮数据可以只监督最后回答，也可监督所有合法助手段，两者是不同目标。角色标记是否监督也需明确，不应由某个默认模板无声决定。

对只监督回答的任务，提示虽不直接计损失，仍通过前向和反向影响回答预测，模型可以学习如何读取它。把提示目标设为忽略不等于删除提示，也不等于阻止提示表示获得间接梯度。若把提示也纳入损失，则加入重建用户内容等额外任务，可能改变有效权重与学习偏好。两者可研究，但比较时不能称作同一经验风险的不同实现。

![输入与下一目标逐列对应，只有预测 A、B、E 的位置计入损失](images/04-img-next-token-mask.webp)

[打开原图放大](images/04-img-next-token-mask.webp)

输入轨上 `P` 表示提示，`S` 是回答边界，`A`、`B` 是两个回答词元，`E` 是结束符。每列的目标是其右邻词元：第一列虽然读入 `P`，预测边界 `S` 时不计分；第二列读到 `S` 时预测首个回答词元 `A`，此处开始计分。第四列从 `B` 预测 `E` 也计分；序列最后一列没有下一个目标，因此以短横线标记，不是一个有效的零标签。

读到 `S` 后预测 `A` 时，模型仍可利用前缀 `P,S`。损失掩码只关闭指定位置的直接损失，不删除输入、不阻断前缀对后续预测的影响，也不能把未来词元泄露给当前预测。此例恰有三个计分目标 `A,B,E`；若截断移除 `E`，可监督停止的位置随之消失。使用框架时应检查由谁做右移，避免数据整理和模型内部各移一次；可对照 TRL 的标签右移与掩码说明。

### 2.2 截断会改变可回答性与监督覆盖

长度限制可能删除关键条件、答案正文或结束符。若证据被截掉而确定答案保留，就教会在信息不足时断言；若回答全被截掉，样本没有有效监督；若只丢结束，模型少了停止信号。应记录最终可见输入、有效位置、截断类型和语义有效性，而不只记原始字符数。分词后长度才对应实际窗口，中文字符数与 token 数不能机械互换。

处理政策可选择拒绝超长样本、按语义重构、保留必要上下文或另设长任务，但每种政策都改变训练分布。不能根据模型当前容易程度静默丢掉困难长样本，再声称覆盖不变。即使允许截断，也应在截断后核对标签仍由输入支持。解析、来源核验和任务规则有各自作用，单靠数组长度检查无法发现语义条件被删。

### 2.3 实验一：从原序列构造真实监督区域

本段用固定编号说明构造，不调用外部分词器。提示允许四、五，回答允许六、七，起始一、回答边界三、结束八；填充零。构造函数拒绝超长和非法编号，不自行截断。两条回答长度不同，核对结束和掩码、忽略位置零梯度，以及词元平均与序列等权的差异。它是目标接口实验，不训练完整模型。

```python
import math
import torch
import torch.nn.functional as F

PAD, BOS, SEP, EOS, V, IGNORE = 0, 1, 3, 8, 11, -100
def encode(prompt, answer, limit=12):
    if not prompt or not answer:
        raise ValueError('empty prompt or answer')
    if any(type(t) is not int or t not in (4, 5) for t in prompt):
        raise ValueError('invalid prompt symbol')
    if any(type(t) is not int or t not in (6, 7) for t in answer):
        raise ValueError('invalid answer symbol')
    prefix = [BOS] + prompt + [SEP]
    full = prefix + answer + [EOS]
    if len(full) > limit:
        raise ValueError('overlength sample needs an explicit policy')
    x = torch.tensor(full[:-1])
    label = torch.full((len(x),), IGNORE, dtype=torch.long)
    label[len(prefix)-1:] = torch.tensor(answer+[EOS])
    return x, label
rows = [encode([4, 5], [6, 7]), encode([5], [7])]
length = max(len(x) for x, _ in rows)
x = torch.zeros(2, length, dtype=torch.long)
label = torch.full_like(x, IGNORE)
for i, (a, b) in enumerate(rows):
    x[i, :len(a)] = a; label[i, :len(b)] = b
valid = label.ne(IGNORE)
assert valid.sum(1).tolist() == [3, 2]
assert label[0, 3:].tolist() == [6, 7, EOS]
z = torch.zeros(2, length, V, dtype=torch.float64, requires_grad=True)
per = F.cross_entropy(z.transpose(1, 2), label, ignore_index=IGNORE, reduction='none')
loss = per.sum()/valid.sum()
assert abs(loss.item()-math.log(V)) < 1e-12
loss.backward()
assert torch.all(z.grad[~valid] == 0)
weighted = per.detach().clone(); weighted[0] *= 2
by_token = weighted.sum()/valid.sum()
by_sample = (weighted.sum(1)/valid.sum(1)).mean()
assert not torch.allclose(by_token, by_sample)
try:
    encode([4]*10, [6], limit=8)
except ValueError:
    pass
else:
    raise AssertionError('silent truncation accepted')
print('valid targets per sequence:', valid.sum(1).tolist(), 'uniform CE:', loss.item())
```

### 2.4 从损失标量追到每个有效位置

实验中两条有效数三和二，全局均值单位置权重都为五分之一；序列等权时分别为六分之一和四分之一。差异来自统计单位，不能只靠一个全局学习率让所有梯度相同。实际实现若还采用类别或任务权重，分母再按明确公式定义。日志应累计可加分子与相应分母，避免最后小批或空批被当成等权观察。

空有效批次的均值没有定义，可以按协议跳过整个更新并记录；若只返回可求导零，优化器的历史矩或衰减仍可能移动参数。多进程默认梯度平均又会与各进程有效数相互作用，需要按全局目标推导。本文只验证单进程目标，未把这段代码当作分布式训练保证。新增执行层时继续检查等价，而不是默认所有常见技巧天然相容。

### 图解：微调数据中的监督位置

![两条样本分别有三个和两个有效的下一词元目标](images/04-img-valid-target-count.webp)

[打开原图放大](images/04-img-valid-target-count.webp)

**逐列核对输入和标签。** 第一行样本的完整序列是 `BOS, 4, 5, SEP, 6, 7, EOS`；取去掉最后一项的序列作输入，标签只保留回答与结束符。于是 `SEP` 这一输入位置预测 `6`，输入 `6` 预测 `7`，输入 `7` 预测 `EOS`，共有三个监督位置。第二个样本是 `BOS, 5, SEP, 7, EOS`，补齐后只有 `SEP→7` 与 `7→EOS` 两个有效目标。图中数字四到七均为词表 ID，并非损失数值。

**归约按五个目标计算。** 程序的词表大小为十一且 logits 全零，每个有效位置损失均为 $`\log11`$，总损失为 $`5\log11`$，除以五后仍为 $`\log11\approx2.397895`$；忽略位置的 logits 梯度为零。后面的加权检验人为把第一条序列的逐位置损失乘二，词元归约变为 $`\frac85\log11`$，而样本等权归约为 $`\frac32\log11`$。差异来自目标权重，不能用“batch 平均”含糊带过。

进一步展开第一个有效位置的十一维 logits 梯度。全零 logits 给每类 $`\frac1{11}`$ 概率；目标 ID 为六，整个批次有五个有效目标，所以该行梯度为 $`\frac15(p-e_6)`$：目标坐标为 $`-\frac2{11}`$，其他十个坐标各为 $`\frac1{55}`$，总和为零。非目标坐标的梯度较小，但仍为正。忽略位置的独立 logits 梯度为零，提示表示仍可经回答的读取路径收到间接梯度。

**只错位一次。** 本章手工对齐输入与标签，再直接计算交叉熵。某些封装的因果语言模型会在内部移动标签，因此不能将这里已移动过的标签直接交给它再移动一次。Transformers 官方因果语言建模教程采用的标签复制与内部移位约定，应与本章的显式交叉熵路径分开理解。

## 3. 选择可训练范围，就是选择可改变的函数族

全量、冻结部分层、低秩更新和输出头适配有不同可训练空间。某个有限任务只需改变类别映射，输出头可能足够；复杂指令读取或新证据整合则未必能靠最后一层解决。可训练参数比例不是能力保证，也不是总内存比例。应先建立可复算基线，再按相同开发规则比较目标任务、旧能力、格式、拒答和资源，而不是直接追求最小参数数。

<a id="sec-2-1"></a>
<a id="llm-4-detail-11"></a>

### 3.1 冻结权重不等于切断所有反向

若只训练输出头，冻结骨干可以在不建反向图的条件下产出固定特征。本章完整实验属于这种特殊情形。若在多层内部放适配器，后续冻结矩阵仍在链式法则中传递到早期可训练模块的梯度，不能把整个骨干都放入无梯度区域。参数不更新和中间导数不需要是不同命题，混淆会得到前向正常、训练路径错误的实现。

还要区分模式与可训练标志。冻结参数并不自动关闭 Dropout 或停止运行统计变化；推理适配又需要明确评估模式。优化器应只持有预期参数，检查参数身份、梯度和实际更新差值。若替换模块后还沿用旧优化器，即使新参数有梯度也可能不更新。逐项核对这条链，比只打印可训练参数百分比更能发现真实问题。

<a id="llm-4-detail-12"></a>

### 3.2 低秩参数化的有限表达与优化条件

对某线性权重，更新写成缩放乘两个小矩阵。秩限制约束当前有效权重差的空间，目标模块决定在哪些计算路径可变；增大秩拓宽空间，却不保证固定预算下优化更好或泛化更强。学习率、缩放、初始化和正则共同决定轨迹，不能只根据一个秩值比较。具体梯度与初始化已在第 2 章推导，本章关注这些选择如何成为完整可验收配置。

底座量化还改变数值与可用内核，即使适配参数仍为浮点，也不表示目标与未量化底座完全相同。若声称某种合并等价，明确是否对同一浮点底座执行，是否重新量化、舍入或改变模块形式。产物应保存目标层、秩、缩放、词表、模板与底座身份，不能让使用者仅凭一个小权重文件猜测如何恢复。训练便宜和交付完整是两个需要同时验证的问题。

<a id="llm-4-detail-13"></a>

## 4. 完整小实验：底座、适配、选择与自由生成

为隔离流程，任务使用两种内容符号组成长度二到四的序列，共二十八种来源。底座原任务读取最后一个内容符号并原样回答，新任务在另一任务标记下用“是”或“否”符号表示最后是否为甲。控制编号、词表和生成规则完全公开，因此可以检查每个标签。模型是一层因果自注意力加前馈的有限符号网络，不是真实预训练语言模型；其性能只针对这个小生成空间。

<a id="llm-4-detail-14"></a>

### 4.1 固定来源角色与适配问题

预先排列二十八种内容来源，训练十八、验证五、测试五。同一内容的原任务和新任务共享来源角色，不把改写分到不同侧。底座只用训练来源的原任务训练，适配只用训练来源的新任务，验证仅选择适配检查点，测试在选定后一次评价。这样未见来源没有参与底座拟合或适配，但所有来源仍处在同一极小符号与长度范围，不能外推到自然语言或更长序列。

所有目标都含一个回答符号和一个结束符，所以当前任务的词元平均与样本等权恰好一致。前面的变长机制实验已经说明一般情况不等价，不应从这个特例推断真实对话也一样。底座和适配都只监督回答区域，提示仍经计算路径影响输出。我们既报告教师强制交叉熵，也按自己生成的历史检查完整两符号回答，避免一个局部指标替代完整行为。

<a id="llm-4-detail-15"></a>

### 4.2 可独立运行的微型适配流程

适配器只放在输出投影，秩二，缩放为一。冻结骨干后其隐藏特征不随适配改变，因而可以在无梯度区域计算；内部多层适配不适用这个简化。保存清单包含底座内容摘要、词表和适配参数，再用同一结构重建并核对输出；临时目录自动清理。程序不要求某个测试准确率，训练下降和恢复一致只是实现验收，任务结果如实打印。

```python
import copy
import hashlib
import itertools
import tempfile
from pathlib import Path
import torch
from torch import nn
import torch.nn.functional as F

PAD, BOS, SEP, A, B, YES, NO, EOS, RAW, LABEL, V = 0, 1, 3, 4, 5, 6, 7, 8, 9, 10, 11
vocabulary = ['PAD', 'BOS', 'unused', 'SEP', 'A', 'B', 'YES', 'NO', 'EOS', 'RAW', 'LABEL']
old_threads = torch.get_num_threads()
torch.set_num_threads(1)
try:
    torch.manual_seed(71)
    sources = [tuple(t) for n in (2, 3, 4) for t in itertools.product((A, B), repeat=n)]
    order = torch.randperm(len(sources), generator=torch.Generator().manual_seed(72)).tolist()
    train = [sources[i] for i in order[:18]]
    val = [sources[i] for i in order[18:23]]
    test = [sources[i] for i in order[23:]]
    assert len(set(train) | set(val) | set(test)) == 28
    assert not (set(train)&set(val) or set(train)&set(test) or set(val)&set(test))
    def batch(rows, mode):
        xs, ys = [], []
        for row in rows:
            target = row[-1] if mode == RAW else (YES if row[-1] == A else NO)
            prefix = [BOS, mode]+list(row)+[SEP]
            full = prefix+[target, EOS]
            x = torch.tensor(full[:-1])
            y = torch.full_like(x, -100)
            y[len(prefix)-1:] = torch.tensor([target, EOS])
            xs.append(x); ys.append(y)
        size = max(map(len, xs))
        xx = torch.zeros(len(rows), size, dtype=torch.long)
        yy = torch.full_like(xx, -100)
        for i, (x, y) in enumerate(zip(xs, ys)):
            xx[i, :len(x)] = x; yy[i, :len(y)] = y
        return xx, yy
    class Tiny(nn.Module):
        def __init__(self):
            super().__init__()
            self.embed = nn.Embedding(V, 24, padding_idx=PAD)
            self.position = nn.Embedding(16, 24)
            self.norm1 = nn.LayerNorm(24); self.norm2 = nn.LayerNorm(24)
            self.attention = nn.MultiheadAttention(24, 3, dropout=0., batch_first=True)
            self.ff = nn.Sequential(nn.Linear(24, 48), nn.GELU(), nn.Linear(48, 24))
            self.head = nn.Linear(24, V, bias=False)
        def hidden(self, ids):
            x = self.embed(ids)+self.position(torch.arange(ids.shape[1]))
            h = self.norm1(x)
            mask = torch.ones(ids.shape[1], ids.shape[1], dtype=torch.bool).triu(1)
            x = x+self.attention(h, h, h, attn_mask=mask,
                                key_padding_mask=ids.eq(PAD), need_weights=False)[0]
            return x+self.ff(self.norm2(x))
        def forward(self, ids):
            return self.head(self.hidden(ids))
    def loss_on(model, data):
        x, y = data
        return F.cross_entropy(model(x).reshape(-1, V), y.reshape(-1), ignore_index=-100)
    base = Tiny()
    original_train = batch(train, RAW)
    optimizer = torch.optim.Adam(base.parameters(), lr=.01)
    for _ in range(160):
        optimizer.zero_grad(set_to_none=True)
        loss = loss_on(base, original_train)
        assert torch.isfinite(loss)
        loss.backward(); optimizer.step()
    base.eval()
    base_state = copy.deepcopy(base.state_dict())
    def identity(model):
        digest = hashlib.sha256()
        for name, tensor in sorted(model.state_dict().items()):
            digest.update(name.encode()); digest.update(str(tensor.dtype).encode())
            digest.update(str(tuple(tensor.shape)).encode())
            digest.update(tensor.detach().cpu().contiguous().numpy().tobytes())
        return digest.hexdigest()
    base_id = identity(base)
    class HeadAdapter(nn.Module):
        def __init__(self, frozen):
            super().__init__(); self.base = frozen
            for p in self.base.parameters(): p.requires_grad_(False)
            self.down = nn.Linear(24, 2, bias=False)
            self.up = nn.Linear(2, V, bias=False)
            nn.init.normal_(self.down.weight, std=.05)
            nn.init.zeros_(self.up.weight)
        def forward(self, ids):
            with torch.no_grad(): h = self.base.hidden(ids)
            return self.base.head(h)+self.up(self.down(h))
        def adapter_state(self):
            return {'down': self.down.weight.detach().clone(),
                    'up': self.up.weight.detach().clone()}
        def load_adapter(self, state):
            with torch.no_grad():
                self.down.weight.copy_(state['down']); self.up.weight.copy_(state['up'])
    adapted = HeadAdapter(base)
    optimizer = torch.optim.Adam([*adapted.down.parameters(), *adapted.up.parameters()], lr=.025)
    tr, va, te = batch(train, LABEL), batch(val, LABEL), batch(test, LABEL)
    with torch.no_grad(): initial = loss_on(adapted, tr).item()
    best, best_step, state = float('inf'), None, None
    for step in range(1, 301):
        optimizer.zero_grad(set_to_none=True)
        loss = loss_on(adapted, tr)
        assert torch.isfinite(loss)
        loss.backward(); optimizer.step()
        if step % 20 == 0:
            with torch.no_grad(): score = loss_on(adapted, va).item()
            if score < best:
                best, best_step, state = score, step, adapted.adapter_state()
    adapted.load_adapter(state)
    assert identity(base) == base_id
    with torch.no_grad():
        train_ce = loss_on(adapted, tr).item(); test_ce = loss_on(adapted, te).item()
    assert train_ce < initial
    @torch.no_grad()
    def exact(model, rows, mode):
        correct = 0
        for row in rows:
            prefix = torch.tensor([[BOS, mode]+list(row)+[SEP]])
            generated = []
            for _ in range(2):
                token = model(prefix)[:, -1].argmax(-1).item()
                generated.append(token)
                prefix = torch.cat((prefix, torch.tensor([[token]])), dim=1)
                if token == EOS: break
            target = row[-1] if mode == RAW else (YES if row[-1] == A else NO)
            correct += generated == [target, EOS]
        return correct/len(rows)
    print('split sizes:', len(train), len(val), len(test))
    print('initial / selected train / validation / test CE:', initial, train_ce, best, test_ce)
    print('selected step:', best_step)
    print('new task exact base / adapted:', exact(base, test, LABEL), exact(adapted, test, LABEL))
    print('old task exact base / adapted:', exact(base, test, RAW), exact(adapted, test, RAW))
    with tempfile.TemporaryDirectory() as temp:
        path = Path(temp)/'adapter.pt'
        torch.save({'format': 1, 'base_id': base_id, 'vocabulary': vocabulary, 'state': state}, path)
        saved = torch.load(path, weights_only=True, map_location='cpu')
        rebuilt_base = Tiny(); rebuilt_base.load_state_dict(base_state); rebuilt_base.eval()
        assert saved['base_id'] == identity(rebuilt_base) and saved['vocabulary'] == vocabulary
        restored = HeadAdapter(rebuilt_base); restored.load_adapter(saved['state'])
        with torch.no_grad():
            assert torch.allclose(adapted(te[0]), restored(te[0]), atol=1e-6, rtol=1e-5)
        merged = Tiny(); merged.load_state_dict(base_state); merged.eval()
        with torch.no_grad():
            merged.head.weight.add_(state['up']@state['down'])
            assert torch.allclose(merged(te[0]), adapted(te[0]), atol=1e-5, rtol=1e-5)
            rebuilt_base.embed.weight[A, 0] += .01
        assert identity(rebuilt_base) != saved['base_id']
    print('frozen base identity, adapter reload, merge and wrong-base detection: passed')
finally:
    torch.set_num_threads(old_threads)
```

### 4.3 这个实验验证了哪些能力与哪些实现

训练与恢复检验分别说明目标可优化、冻结范围确实不变、选择状态可重建和低秩输出头可合并。它没有比较所有适配层，也没有验证真实量化、GPU 内存或大型预训练底座。测试只有五个未见内容组合，质量数字必须连同支持数和生成机制报告。旧任务回归同样只是这个小规则，不代表通用语言能力保留。

新旧任务使用不同标记，但共享底座与输出投影；只适配输出头可能同时改变两个任务。若新任务改善而原任务退化，应保留结果并研究是否需要更适当目标层、任务混合或约束，而不是只汇报新任务。反过来，若都成功，也不证明全部原能力不变。验收集合覆盖的功能总是有限，应将保留主张限定到实际独立任务和数据。

<a id="llm-4-detail-17"></a>

## 5. 验收应分成任务、格式、证据与保留能力

训练损失是优化诊断，不是全部行为验收。目标任务看正确性和支持数，格式看解析与字段约束，事实看可用证据与引用，拒答看应该回答与不应断言两侧，旧能力看独立回归集合。几项可能相互冲突，例如格式更整齐但事实错更多，拒答更多但服务覆盖下降；不能用一个综合平均把重要退化隐藏。

<a id="llm-4-detail-18"></a>

### 5.1 固定解析器不能替代事实判断

合法 JSON 或合法字段，只证明结构符合规则。字段里的数字、对象与引用仍可能错误；相反，事实正确但格式不合法也可能无法被系统使用，应分别记失败。解析规则需要处理重复字段、未知键、类型、数值范围与引用身份，而不只是捕获语法异常。若选择规则改变，应版本化评价器并对比较候选一致重评，不能只修某模型容易触发的分支。

证据不足的样本要定义允许的行为，例如明确不确定或说明缺失信息。训练中过度肯定的参考答案会与该目标冲突，偏好数据若奖励更长更自信的措辞，也可能放大问题。来源和判定规则比表面语言风格更关键。评价应使用盲化、配对和必要事实对照，不把礼貌或篇幅当真实性代理。

<a id="llm-4-detail-19"></a>

### 5.2 实验三：格式合法不等于事实有据

下面用封闭证据表和结构化回答隔离三件事：JSON 语法与重复键、字段及可见引用、答案是否被证据支持。合法回答与事实相反的回答都能通过结构校验，但只有前者通过封闭事实核对。这里不调用真实语言模型，也不声称规则表能够验证开放世界任意自然语言；它使验收对象清楚可见，避免用格式分数代替事实质量。

```python
import json
import math

evidence = {'d1': '甲', 'd2': '乙'}
def unique_pairs(pairs):
    result = {}
    for key, value in pairs:
        if key in result: raise ValueError('duplicate key')
        result[key] = value
    return result

def parse(text, visible):
    row = json.loads(text, object_pairs_hook=unique_pairs)
    if not isinstance(row, dict) or set(row) != {'answer', 'status', 'evidence', 'confidence'}:
        raise ValueError('schema mismatch')
    if type(row['answer']) is not str or row['status'] not in ('supported', 'unknown'):
        raise ValueError('invalid answer or status')
    ids = row['evidence']
    if type(ids) is not list or any(type(x) is not str or x not in visible for x in ids):
        raise ValueError('invisible reference')
    value = row['confidence']
    if type(value) not in (int, float) or not math.isfinite(value) or not 0 <= value <= 1:
        raise ValueError('invalid confidence')
    if row['status'] == 'unknown' and (row['answer'] or ids):
        raise ValueError('unknown must not claim a supported answer')
    if row['status'] == 'supported' and (not row['answer'] or not ids):
        raise ValueError('missing support')
    return row

def supported(row):
    return row['status'] == 'supported' and all(evidence[i] == row['answer'] for i in row['evidence'])
good = parse('{"answer":"甲","status":"supported","evidence":["d1"],"confidence":0.8}', {'d1'})
wrong = parse('{"answer":"乙","status":"supported","evidence":["d1"],"confidence":0.9}', {'d1'})
assert supported(good) and not supported(wrong)
for bad in (
    '{"answer":"甲","answer":"乙","status":"supported","evidence":["d1"],"confidence":0.8}',
    '{"answer":"甲","status":"supported","evidence":["d2"],"confidence":0.8}',
    '{"answer":"甲","status":"supported","evidence":["d1"],"confidence":true}'):
    try: parse(bad, {'d1'})
    except ValueError: pass
    else: raise AssertionError('invalid output accepted')
print('schema and visible references checked; factual support remains separate')
```

<a id="llm-4-detail-20"></a>

### 5.3 拒答需要同时包含应该回答的样本

只收集证据不足时的拒答示例，可能让模型学会对一切保守；只奖励明确作答，又可能教会无据断言。验收应同时覆盖可答、不可答、冲突与需澄清情形，报告覆盖、保留样本风险和不必要拒答。零覆盖时条件风险没有普通意义，不能记成零错误作为成功。风格更谨慎与事实更可靠是不同主张，都要有对应数据。

校准或拒答阈值应在合法开发区域选择，再在冻结测试上评价。微调后概率尺度可能改变，沿用底座阈值并不自动合理；某个总体上的校准也不保证新任务或新来源。若系统引入检索，证据可见性与拒答原因又多一层。把不确定性目标写进样本时，应确保标签来源与允许信息一致，而不是让参考答案使用模型推理时根本看不到的证据。

<a id="llm-4-detail-21"></a>

## 6. 梯度与参数审计：让“冻结正确”成为可检验命题

可训练标志、梯度存在、优化器成员和实际参数变化是四个不同检查。参数可能有梯度但没有进入优化器，也可能因为零梯度、历史矩或衰减产生意外更新。应记录参数身份集合与更新差值，确认只有预期模块变化。对适配器还要检查缩放和目标层实际生效，防止文件名写着低秩而前向走的仍是原模块。

<a id="llm-4-detail-22"></a>

### 6.1 实验四：冻结矩阵仍可能必须传递梯度

构造早期可训练投影、冻结中间矩阵和末端可训练读出。错误路径在冻结矩阵处使用无梯度区，前向与正确路径相同，末端仍有梯度、损失也能反向，但早期投影梯度丢失。它专门模拟内部适配被意外截断的故障，不训练任务，也不依赖前一段完整实验。验收应检查所有预期参数，不能看到任意一个梯度非零就宣布正常。

```python
import torch

torch.manual_seed(26)
x = torch.randn(5, 2, dtype=torch.float64)
fixed = torch.randn(3, 3, dtype=torch.float64)
a = torch.randn(3, 2, dtype=torch.float64, requires_grad=True)
b = torch.randn(1, 3, dtype=torch.float64, requires_grad=True)
good = (x@a.T@fixed.T)@b.T
reference = torch.autograd.grad(good.square().mean(), (a, b))
a2 = a.detach().clone().requires_grad_()
b2 = b.detach().clone().requires_grad_()
with torch.no_grad(): hidden = x@a2.T@fixed.T
bad = hidden@b2.T
bad_grad = torch.autograd.grad(bad.square().mean(), (a2, b2), allow_unused=True)
assert torch.allclose(good, bad)
assert reference[0].abs().sum() > 0 and bad_grad[0] is None
assert torch.allclose(reference[1], bad_grad[1])
assert not fixed.requires_grad
print('same forward; frozen intermediate must still transmit early-parameter gradients')
```

<a id="llm-4-detail-23"></a>

### 6.2 先过拟合极小集合，再评价泛化

极小集拟合帮助排除标签错位、冻结错误、优化器身份和基本表达不足，但不能证明独立性能。若连极小集都不能拟合，先核对逐位置目标、输入可见性、梯度和更新，再考虑可训练空间是否不够。若训练拟合而新表达失败，转向数据覆盖、来源、选择与分布，而不是无目的增加步数。两个现象对应不同优先假设。

检查点应固定选择指标、比较频率、平局政策与状态身份。只保留最后一步可能错过更好验证状态，事后在多个指标中挑选又会扩大选择机会。完整实验保存的是适配器独立张量副本，不让后续更新改变所谓最佳。推理恢复只证明当前函数，若要续训还需优化器、调度、随机流和采样状态，相关机制可返回深度学习实践检查点章继续演练。

<a id="llm-4-detail-24"></a>

### 6.3 训练资源的比较范围

可训练参数少通常减少部分梯度和优化状态，但底座仍需加载，隐藏状态和计算也可能存在。输出头适配与内部多层适配有不同激活需求，不能用本章无梯度骨干的小例子推断任意低秩训练内存。量化、梯度重算、批量与序列打包改变不同对象，应分别列出实际精度、形状、模式和测量范围。

同有效词元、同更新与同时间是不同公平问题。若比较达到质量阈值的成本，记录候选搜索和失败；若比较固定预算下质量，冻结预算与评价。CPU 教学循环不代表生产设备吞吐，参数字节不代表实际峰值。资源结论也要有对应实验，不能把一个结构性节省当成无条件硬件加速保证。

<a id="llm-4-detail-25"></a>

## 7. 数据混合、长回答与旧能力约束

设任务族风险为 $`R_k`$，训练混合目标为 $`\sum_k\lambda_k R_k`$。权重既来自抽样，也可能来自逐样本或逐词元归约，二者共同决定实际优化。若任务族平均回答更长，词元均值会给其更多质量；若改为样本等权，偏好又不同。比较配方前应把有效任务权重写成公式并用记录复算，不只列原始条数百分比。

<a id="llm-4-detail-26"></a>

### 7.1 目标任务与回归任务如何共同出现

加入旧任务样本可以研究保留，但额外数据、监督和计算也改变了机会。应在同样预设预算下比较，并同时报告目标与旧任务，而不只让一个加权平均看起来好看。某些任务可能不可同时满足，或者当前适配空间无法分离，需承认可行边界。任意选择一个混合权重不保证最坏群体或每项旧能力都不退化。

也可以把旧任务质量设为约束，寻找满足限制的适配方案；此时验证集用于选择可行候选，最终独立测试评价约束是否仍成立。观察到的回归集只是有限能力集合，不应称为“原能力全部保留”。如果底座版本或模板改变，回归比较还需重新固定对象，不能把两个不同初始系统的差值混成适配效果。

<a id="llm-4-detail-27"></a>

### 7.2 长度偏好与答案质量需要拆开

训练参考和偏好标注可能系统性偏爱更长、更肯定或格式更复杂的回答。若实际需求是准确简短，这些偏好会偏离任务。应构造长度受控的内容对照、事实相同但措辞不同的样本，以及关键事实错误但很流畅的反例。盲化位置与来源能减少部分判断偏差，却不能自动消除所有价值与标注分歧。

评价器需要自己的校验集合与版本，查看其在数字、否定、引用和不可答条件下是否可靠。若评分器根据模型输出不断调整，它也参与了开发；最终结果须冻结评价过程或另作确认。训练优化的是给定数据和评分信号，信号偏离真实目标时，更好优化甚至可能更忠实地学习错误偏好。不能让一个自动分数替代任务定义与人工证据。

### 图解：参数冻结不等于输入通路不需要导数

![中间参数冻结，反向梯度仍经该参数传到前面的输入通路](images/04-img-frozen-weight-gradient-path.webp)

[打开原图放大](images/04-img-frozen-weight-gradient-path.webp)

**冻结参数还需要处理已经存在的优化器输入。** 除了新一轮反向传播，还要检查参数在冻结前留下的状态。参数 w 当前为三，但其 $`\mathrm{grad}`$ 已由此前训练留下数值一。此时只执行 $`w.\mathrm{requires\_grad\_}(\mathrm{False})`$，不会自动清掉旧梯度；对仍包含它的普通 SGD 优化器直接执行一次学习率 $`0.1`$ 的 step，w 仍会变为 $`2.9`$。

因此在阶段切换时，应把“不再生成新参数梯度”和“不再被优化器更新”同时落实：清除历史 grad，并恰当地重建或筛选优化器参数集合。把梯度设为零也不等同于所有优化器下都跳过更新，因为动量、权重衰减等状态仍可能起作用；本图的数值只使用无动量、无权重衰减 SGD。梯度跟踪与冻结的区别参阅 PyTorch autograd 说明。

图用独立标量链解释正文的矩阵实验。设$`h=ax,v=wh,y=bv,L=\frac12y^2`$，取 $`x=2,a=\frac12,w=3,b=4`$，并固定 $`w`$。前向依次为一、三、十二，损失七十二。反向有 $`\frac{\partial L}{\partial y}=12`$、$`\frac{\partial L}{\partial v}=48`$、$`\frac{\partial L}{\partial h}=144`$、$`\frac{\partial L}{\partial a}=288`$，而 $`\frac{\partial L}{\partial b}=yv=36`$。固定系数三没有消除它对输入的导数。

也可从同一个函数分别求两个方向的导数。固定 $`b=4`$ 时 $`L(a)=288a^2`$；固定 $`a=\frac12`$ 时 $`L(b)=4.5b^2`$。分别在当前参数上求导，可以复算上面的梯度 $`288`$ 与 $`36`$。

在 $`v`$ 处停止记录上游计算，前向不变，末端 $`b`$ 仍有梯度三十六，$`a`$ 的梯度路径却消失。重新改变 a 后再做前向，损失仍沿左侧抛物线变化，因此数值函数的有限差分仍为二百八十八；消失的是此次计算图登记的上游导数路径。不能把 detach 后得到的梯度缺失，误画成原函数本来是水平线。“损失正常、某个参数有梯度”不足以确认全部预期模块可学习。本图采用 $`\frac12y^2`$，正文实验四采用矩阵输出平方均值，数值不能混用。PyTorch autograd 说明区分参数是否需要梯度与运算是否被记录。

**适用条件。** 并非每个冻结模块都必须保留导数；若它只负责产生固定输入特征，可提前计算。关键是上游是否还有需要学习的参数。

## 8. 实际结果与有限样本的解释

本地 CPU 运行中，底座输出头适配前新任务训练交叉熵约十六点五八五，按验证选第八十次更新后，训练约零点零一九三、验证约一点二二五八、测试约零点零零零一零一。新任务五条测试精确生成从零提升到五条全对，原任务则从五条全对降到全错。冻结底座摘要不变、适配重载一致、合并投影一致与错误底座身份检测均通过。这些结果支持当前有限流程中的取舍，不证明真实语言能力。

<a id="llm-4-detail-29"></a>

### 8.1 为什么测试损失远低于验证也要如实报告

验证与测试都只有五条，长度和标签组成不同，任务难度不必相等。训练内容末符号甲乙为十与八，验证为三与二，测试为一与四；这说明它们虽然同一生成空间，却不是细节完全相同的经验集合。不能看到测试较好就换分割，也不能仅凭差异直接断定泄漏。应先核对来源集合确实不交、底座训练只用训练角色，再诚实承认小支持限制。

小测试满分不意味着精确掌握任意组合或长度。重复符号、位置、边界与任务标记都可能影响隐藏特征，输出头适配只能在其可分离空间内改变规则。若要进一步解释验证失败，应在开发区分析具体来源与逐位置预测，不利用最终测试继续调秩或选择。新的确认应另行设计，而不是把同五条成功重复运行多次当作更多独立证据。

<a id="llm-4-detail-30"></a>

### 8.2 底座冻结不代表原功能冻结

本例只改变低秩输出头，底座所有参数字节保持，却把原任务五条全改错。完整函数包含新增适配路径，因此“底座未动”不能推出行为未变。两任务用了不同标记，也不保证当前隐藏表示和共享读出能将它们完全分离。这个反例提示验收必须直接测需要保留的功能，而不是从参数冻结比例推断。

原任务是人工复制规则，不是通用知识；它的退化也不能被量化成真实大模型遗忘程度。改目标层、训练混合或加入约束是研究候选，都需要新的预算与比较。结论可以很具体：当前仅输出头、秩二和固定数据政策改善新任务，却未通过旧任务回归。一个清楚可反驳的有限结论，比一个忽略代价的“适配成功”更有学习价值。

<a id="llm-4-detail-31"></a>

## 9. 交付身份：适配文件不是完整模型

底座、分词器、词表、模板、特殊符号、目标模块、秩与缩放共同定义适配函数。相同小矩阵接到另一份底座，即使形状能加载也可能产生不同输出。正文用参数内容摘要隔离身份，只说明读取的是约定字节，不把摘要当来源真实性证明。实际模型还需完整配置与加载规范，不能只保存一个名字相似的模型标签。

<a id="llm-4-detail-32"></a>

### 9.1 合并、精度与模式的条件

对同一浮点线性投影，低秩更新可以代数合并到基权重；本章只在这种简单输出头上核对。若重新量化、改变舍入或模块结构，合并前后可能不再数值等价，应另做行为回归。某些适配器还包含非线性或动态机制，也不能照搬矩阵相加。先写函数形式，再判断等价条件，避免把一种实现便利推广为所有参数高效方法的属性。

推理入口不应启动训练，固定位置、模式、预处理与解码即可预测。加载后比较固定样例的中间输入和 logits，检查类别或符号顺序，再核对实际生成与停止。只看文件成功打开或一个回答看起来合理，不足以验证同函数恢复。若有续训目标，另存完整训练状态并演练，不将推理与轨迹等价合成一个含糊通过标记。

<a id="llm-4-detail-33"></a>

### 9.2 版本更新与清理

改变底座、词表或模板时使用新版本身份，回归原任务、目标任务和已知边界，并在未用于修改的证据上确认。旧失败集可以防止重犯，却已参与开发，不能永远当独立测试。报告列出修改所用信息、选定状态和评价器版本，让结果可以追溯。参数很小的适配器同样可能过拟合，文件体积不提供统计免疫。

本章的模型与清单通过临时目录完成保存和重载验证，退出后自动清理。真实项目需要按依赖关系保留底座标识、词表、模板、适配参数、精度与有效配置；删除其中一项可能改变恢复后的预测函数。一个可交付的适配模型，应让使用者知道它从何而来、如何加载、已验证哪些行为，以及哪些任务和运行环境仍需重新测试。

<a id="llm-4-detail-34"></a>

### 9.3 用线性子空间分析“保留与改变”的兼容性

对冻结隐藏表示，设输出变化为 $`\Delta z=\Delta W h`$。若要求所有旧样例的 logits 完全不变，就要求更新矩阵消去这些隐藏向量张成的空间。如果一个新样例隐藏向量已经在旧空间中，那么它也是旧向量的线性组合，同一更新对它必为零；因此在这个限定参数化中，不能既保持这些旧 logits 全不变又改变该新 logits。这个结论不依赖优化器，只来自线性约束。

低秩进一步限制可用更新，但即使全秩输出头，也不能绕过上述完全相同子空间约束。改动中间表示、放松保留标准或使用任务条件化路径可能改变可行性，都是不同研究设计。这里没有计算本实验全部隐藏空间，所以不能把观测退化唯一归因于该定理；它提供一个可以检验的竞争解释。可以在开发集检查隐藏特征的跨度、近似关系与更新敏感性，再设计适当目标层对照。

实际保留要求通常不必是所有 logits 完全相同，而可能是旧任务正确率或损失不超过容忍界，这会允许更大空间。反之，有限旧回归集通过，也不保证其未覆盖方向不改变。把功能约束转成可观察指标，并明确容忍范围，能帮助选择参数化和预算。不能因为训练参数少就默认更新“只改所需知识”；函数变化的定位取决于表示、共享路径和数据证据。

**近似重合比精确重合更常见。** 把一个输出坐标单独取出，令旧隐藏向量为 $`h_o=(1,0)^\top`$，新向量为 $`h_n=(\cos\theta,\sin\theta)^\top`$。要求 $`\Delta w h_o=0`$，强制行更新为 $`\Delta w=(0,c)`$；再要求新输出增加一，就得到 $`c\sin\theta=1`$。因此最小更新范数为

```math
\|\Delta w\|_2=\frac{1}{|\sin\theta|}.
```

![新旧方向越接近，在保持旧输出时达到同一新输出所需的最小更新范数越大](images/04-img-retention-angle-cost.webp)

[打开原图放大](images/04-img-retention-angle-cost.webp)

角度三十度时需范数二，十度时约为 $`5.7588`$，二度时约为 $`28.6537`$；角度零时无解。可行性并非只有“能或不能”两个层次，接近冲突也会放大权重和对其他隐藏方向的影响。

一般地，令 $`P_o`$ 是旧隐藏子空间的正交投影，$`h_\perp=(I-P_o)h_n`$。在保留旧输出、使新输出改变 $`\delta`$ 的所有行更新中，柯西不等式给出范数下界 $`\frac{|\delta|}{\|h_\perp\|_2}`$；当 $`h_\perp\ne0`$ 时，取

```math
\Delta w=\frac{\delta\,h_\perp^\top}{\|h_\perp\|_2^2}
```

恰好达到下界。这里研究的是冻结表示与精确保留一个输出坐标的线性问题。允许旧 logits 小幅变化、只保留分类结果或改变中间表示，都会改变可行集合；不能用这个二维例子直接解释前面实验中的全部遗忘。

![旧输出容差给出竖直带，新输出目标给出斜线，最近可行点在右边界](images/04-img-retention-feasible-update.webp)

[打开原图放大](images/04-img-retention-feasible-update.webp)

**放松旧能力约束的代价。** 本图不再要求旧输出严格不变，而允许绝对改变量不超过 ε，同时要求新单位方向输出增加一。令旧方向 u=(1,0)、新方向 v=(根号三除以二,二分之一)。无约束最小更新是 v，范数一，但会使旧输出增加根号三除以二。在 ε 低于这个值时，约束处于边界，更新为 (ε,2−根号三乘 ε)；范数从严格保持时的二连续降到一。这是单输出线性局部模型，展示保留约束的代价与放松边界，不等同于真实微调的质量保证。

**在更新平面中找最近的可行点。** 将行更新写为 $`\delta w=(a,b)`$。新输出增加一给出直线 $`\frac{\sqrt3}{2}a+\frac12b=1`$；保留旧输出到容差 ε 则给出竖直带 $`|a|\le\epsilon`$。图以 ε=0.4 为例，两条竖边之间的阴影表示保留约束，斜线在阴影内的部分才同时满足两项约束。黑点位于右边界与斜线的交点，图只示意相交关系，实际范数用下面的坐标计算。

不加保留约束时，原点到该直线的正交投影就是单位向量 $`v=(\frac{\sqrt3}{2},\frac12)`$；它的旧输出变化约 0.8660，超出 ε=0.4。因此最近可行点移到右边界，成为 $`(0.4,2-0.4\sqrt3)`$，范数约 1.3670。可以逐个放宽竖带并重复求解最近点，直到 ε 达到 $`\frac{\sqrt3}{2}`$，正交投影终于可行，范数保持一。旧输出容差决定竖带宽度，最近可行点的距离就是实现新输出所需的最小更新范数。

```math
\begin{aligned}
&\delta w^*(\epsilon)\\
&\quad =\left(\epsilon,\frac{1-\epsilon\cos\theta}{\sin\theta}\right)\quad(0\leq\epsilon\lt \cos\theta),\\
&\quad \theta=\frac{\pi}{6}.
\end{aligned}
```
