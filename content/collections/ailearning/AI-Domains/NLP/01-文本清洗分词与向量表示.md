## 1. 文本表示是一组可检验的建模选择

<a id="nlp-1-detail-2"></a>
### 1.1 先区分原始对象、编码对象与任务对象

一个客服系统收到“这次退款不是很慢！”时，磁盘保存的是字节，解码以后得到字符序列，分词器输出的是离散符号编号，模型接收的是向量，业务最终需要的却可能是用户是否满意。这几个对象之间并不存在天然的一一对应。一个可见字符可能由多个码点组成，一个词可能切成多个子词，一组完全相同的词又可能因顺序不同而表达相反关系。讨论表示质量之前，必须先说明保留什么信息，以及下游的正确答案取决于什么。

设原始文本为随机变量 $`X`$，目标为 $`Y`$，确定性预处理为 $`T`$，最终表示为 $`Z=T(X)`$。一旦两个原始输入经过处理变成相同的表示，任何只读这个表示的后续模型都不能重新分辨它们。假如“可以退款”与“不可以退款”被删词规则映成同一个序列，后面增加层数、注意力头或训练轮数，都不能凭空恢复已经删除的否定。表示不是模型前面的一段无害杂务，而是对可利用信息施加限制的操作。

理想的压缩有时可以用条件独立 $`Y\perp X\mid Z`$ 描述：给定表示以后，原文对目标不再提供额外信息。实际任务几乎无法证明这一点，因此应使用有针对性的最小对照样本检验。保持主题相同，只改变否定；保持词汇相同，只交换主客体；保持数字外形近似，只改变小数点。这些试验不能证明充分性，却可以迅速否定明显不适用的清洗和表示方案。

<a id="nlp-1-detail-3"></a>
### 1.2 不变性与敏感性必须由任务定义

在英文主题分类中，将普通单词统一小写可能减少稀疏性；在程序代码中，大小写可能决定变量身份。在搜索中统一全角数字可以改善匹配；在数学转写中把上标字符直接变成普通数字可能改变结构。在情绪识别中重复感叹号可能提供强度信号；在某些主题任务中它主要反映来源格式。没有一种“越干净越科学”的通用排序，只有对某种任务和分布是否有帮助的选择。

不变性是要求 $`f(x)=f(g(x))`$，其中 $`g`$ 是被认为不应改变标签的变换。敏感性则要求某种改变能够反映到输出。例如把“支持退款”改为“不支持退款”，应允许分类发生变化。设计预处理时，先写出期望保持不变的操作和必须保留差异的操作，再检查实现。若业务人员不能确认某个变换是否保义，就应保留原文并将变换作为待比较条件，而不是直接把差异清除。

最小对照集还需要覆盖多种语言和输入渠道。中文空格并不是可靠词边界，拉丁字母混写、表情符号、网址、产品型号和语音转写标点都有自己的规律。一个只在几条标准书面语上通过的规则，很可能在真实输入中系统性删除重要证据。应按来源、长度、字符类型和业务类别检查覆盖，并记录规则影响了哪些样本，避免只观察全体平均指标。

<a id="nlp-1-detail-4"></a>
### 1.3 一个变换为什么会降低理论上限

假设两个原文 $`x_a,x_b`$ 的最优标签分别为零和一，且在某个处理单元内出现概率相同。如果 $`T(x_a)=T(x_b)`$，确定性分类器在这两个样本中至少错一个；随机化也只能把错误分配给两者，不能消除总错误。推广到一个表示值 $`z`$，零一损失下最小条件风险为 $`1-\max_yP(Y=y\mid Z=z)`$。处理后的最小风险是这个量对表示分布的平均。

这解释了为什么检查“冲突桶”很有价值：按规范化结果或特征向量聚合样本，观察相同表示是否包含互相矛盾的可靠标签。但不能把所有冲突都归因于预处理。原文本身可能缺失背景、标注者可能分歧、任务可能本来就多解。正确做法是回看原文、任务规范和样本来源，区分表示造成的不可分辨与目标定义造成的不确定，而不是盲目提高特征维数。

## 2. Unicode、规范化与可追踪清洗

<a id="nlp-1-detail-6"></a>
### 2.1 字节、码点、字素簇和显示长度

UTF-8 是把 Unicode 码点编码成字节序列的方案，字节数量不等于字符数量。Python 字符串长度通常统计码点数量，也不等于用户看到的字素簇数量。带重音字母可以表示为一个预组合码点，也可以表示为基础字母加组合附加符号；某些表情由多个码点和连接符共同构成。因而“截取前十个字符”“按字符标注”都需要明确究竟使用哪个坐标系。

标注系统如果保存字节偏移，而训练程序按码点切片，遇到中文或组合符号就可能截错实体边界。前端常用的字符串索引还可能按另一种编码单元计算。可靠的数据接口应在字段规范中写明偏移单位、左闭右开约定、是否基于原文，以及换行是否在导入时改变。把这套约定连同原始文本一起保存，比只保存最终 token 编号更便于复核和迁移。

<a id="nlp-1-detail-7"></a>
### 2.2 四种规范形式与语义代价

NFD 进行规范分解，NFC 在规范分解后尽可能规范组合；NFKD 和 NFKC 还会应用兼容分解。前两者主要解决同一抽象字符的不同编码形式，后两者可以进一步折叠全角、连字、圈号和某些上标差异。规范化不是简单删除非 ASCII 字符，也不是按外观寻找近似字。外形接近的拉丁字母、希腊字母和西里尔字母未必具有规范等价关系。

这里的关键是兼容等价不保证任务语义相同。例如“①”可能是编号，“1”可能是正文数值；“x²”可能表达平方，“x2”可能是变量名。如果任务只检索普通商品编号，统一这些形态可能有益；如果任务需要精确转写数学结构，同样的操作就可能损坏答案。应在文档中说明选择的规范形式及其理由，并保存原文以支持回显、审计和与标注坐标的对齐。

幂等性 $`T(T(x))=T(x)`$ 是很多规范化流程应满足的性质，但它不等于语义正确。一个把所有文本都替换为空串的操作同样幂等。反过来，若整个清洗管线不幂等，则反复导入或不同服务组合可能产生漂移。例如先替换缩写再删除标点，与先删除标点再替换缩写，结果可能不同。应分别检查每步的性质，并把步骤顺序当成模型版本的一部分。

<a id="nlp-1-detail-8"></a>
### 2.3 大小写、空白、数字和标点的选择

大小写归一可以用小写转换或更强的大小写折叠，它们不是完全等价的操作。大小写折叠用于无大小写匹配时可能把一个字符映成多个字符，因此原文位置不能简单沿用。空白处理也应区分普通空格、制表符、换行和不间断空格。把一切空白压成一个空格，会丢失诗歌、代码和表格结构；把所有空白删除，又会把本来不同的英文单词粘在一起。

数字应根据问题保留精度和角色。价格“9.9”和“99”、时间“08:30”和“18:30”、版本“1.10”和“1.1”不能随意互换。将所有数字替换成统一占位符可以减少词表，却会让数值比较和金额抽取不再可解。较稳妥的方法是保留原始数字并增加结构特征，例如数字类型、单位和数量级；是否这样做仍要在训练边界内验证，不能根据测试错误逐条设计替换规则。

标点有时是句法边界，有时是表情的一部分，也可能是结构化字段的分隔符。“好？”与“好！”的交际功能不同，“不，好”与“不好”也不是同义句。清洗网址或邮箱时同样需要考虑任务：主题分类可能只需域名类型，安全检测可能依赖完整字符模式。更换为占位符之前，应确认目标是否依赖被替换内容，并考虑隐私要求与复核需求。

<a id="nlp-1-detail-9"></a>
### 2.4 实验一：规范化性质和不可逆变化

下面只用 Python 标准库，不下载任何语料。测试分别验证规范等价、兼容折叠、组合顺序和字节长度，最后构造否定被删除后无法区分的冲突。实验使用的字符都受到当前运行环境 Unicode 数据库支持；复现时应同时记录数据库版本，而不能把某个解释器内置的数据版本误称为网上最新标准。

```python
import unicodedata as ud

composed = "é"
decomposed = "e\u0301"
assert composed != decomposed
assert ud.normalize("NFC", composed) == ud.normalize("NFC", decomposed)
assert len(composed) == 1 and len(decomposed) == 2
assert len("中".encode("utf-8")) == 3
assert ud.normalize("NFKC", "Ａ①x²") == "A1x2"
assert ud.normalize("NFC", "Ａ①x²") == "Ａ①x²"
for form in ("NFC", "NFD", "NFKC", "NFKD"):
    value = ud.normalize(form, "Ａ①e\u0301")
    assert ud.normalize(form, value) == value

def bad_clean(text):
    return text.replace("不", "").replace("！", "")

assert bad_clean("可以退款！") == bad_clean("不可以退款！")
print("Unicode 数据版本:", ud.unidata_version)
print("规范化断言通过；否定删除产生标签冲突")
```

不要把最后一条断言理解成建议实施坏清洗。它是一个故障注入试验，故意显示某种规则违反任务敏感性。实际工程中可以保存这类短小反例作为回归样本：一旦规则升级，先检查是否破坏了已知必要区分，再运行完整的验证集评价。小例子证明的是具体机制，不提供任何真实业务提升百分比。

## 3. 分词方案与词表学习

<a id="nlp-1-detail-11"></a>
### 3.1 词、字、子词与字节的取舍

按词切分通常使序列较短，却要求处理词形变化、未登录词和语言边界；按字切分减少中文词表依赖，却把多字词语义交给后续模型；按子词切分在常见单位与组合能力之间折中；按字节表示能覆盖编码允许的文本，却可能显著增加非 ASCII 内容的序列长度。这里的覆盖率、长度和语义单位必须分开讨论，不能只用“没有未知词”概括表示质量。

比较两种分词器时，至少报告训练语料、词表规模、平均与高分位长度、未知或回退比例、特殊符号策略以及目标任务指标。词表较大往往使输入更短，却增加嵌入矩阵和输出分类器参数；词表较小可能减少参数，却提高注意力序列成本。若一个句子由一百个 token 变成两百个，密集自注意力的二次部分可能放大到约四倍，而整个模型总耗时还受线性层、硬件和批处理影响。

中文词边界本身可能存在多种合理分析。“研究生命起源”可以用不同粒度切分，但下游实体、句法或检索任务未必偏好同一粒度。不能把某个分词标准的最高一致率直接等同于所有任务最优。更有信息量的评价是：分词改变以后，哪些实体被切碎、哪些罕见领域词被保留、训练和部署的长度分布是否出现明显差异。

<a id="nlp-1-detail-12"></a>
### 3.2 BPE 的训练单位和确定性规则

这里使用一个教学版词内 BPE：先将每个训练词拆成字符，再添加词尾符号；统计当前序列中相邻符号对的加权出现次数，每轮选择频次最高的一对并把非重叠出现合并。训练得到有序合并表，推理时按这些合并的优先级应用。真实工具还会加入预分词、字节映射、特殊 token 和其他实现细节，不能用这个小程序声称复现了任何现成模型的完整 tokenizer。

必须固定平局处理规则，否则相同词频可能训练出不同合并表。也要声明重复相邻模式如何处理，例如三个相同符号包含两个相邻对，但从左向右非重叠合并后通常只合并一次。训练过程统计的是当前分段，而不是原始字符串中所有可能子串的频次。每轮合并都会改变后续相邻关系，因此不能一次性统计所有原始字符对后把排名当成完整训练结果。

<a id="nlp-1-detail-13"></a>
### 3.3 带频次的手算例

考虑词频为“low”五次、“lower”两次、“newest”六次、“widest”三次的训练词表。在初始字符序列中，字母对“e,s”和“s,t”分别从后两个词贡献九次；“l,o”和“o,w”各有七次。假设平局按符号对的字典序处理，先选“e,s”。下一轮“es,t”仍有九次，于是形成“est”；再下一轮“est,词尾”有九次，形成带词尾的复合符号。

这个例子说明高频子词来自词频加权的邻接模式，而不是语言学词根分析。“est”在这份人为语料中经常一起出现，所以被合并；若换一个词频分布或平局规则，合并顺序可能变化。词尾标记使同一字符片段在词中和词末的统计可区分，也防止在这个教学定义下跨词边界合并。去掉边界标记会改变候选对集合，属于另一种明确需要重新定义的算法。

词表学习不能读取被保留用于最终评价的任务文本，除非实验明确采用允许观察未标注目标域的传导式设置，并公平地给所有方法同样权限。即使不读取标签，词频和词形覆盖也可以包含目标域信息。固定公开预训练分词器与在本任务全部文本上重新训练分词器属于不同设置；文档应写清 tokenizer 的来源与是否在本次任务中适配，而不是一概称为“无监督所以没有泄漏”。

<a id="nlp-1-detail-14"></a>
### 3.4 实验二：从词频训练三个合并步骤

```python
from collections import Counter

frequencies = {"low": 5, "lower": 2, "newest": 6, "widest": 3}
words = {tuple(word) + ("</w>",): count for word, count in frequencies.items()}
merges = []
for _ in range(3):
    pairs = Counter()
    for symbols, count in words.items():
        for pair in zip(symbols, symbols[1:]):
            pairs[pair] += count
    best = min(pairs, key=lambda pair: (-pairs[pair], pair))
    merges.append((best, pairs[best]))
    updated = Counter()
    for symbols, count in words.items():
        out, i = [], 0
        while i < len(symbols):
            if i + 1 < len(symbols) and symbols[i:i + 2] == best:
                out.append("".join(best))
                i += 2
            else:
                out.append(symbols[i])
                i += 1
        updated[tuple(out)] += count
    words = dict(updated)

assert merges == [(("e", "s"), 9), (("es", "t"), 9), (("est", "</w>"), 9)]
assert sum(words.values()) == sum(frequencies.values())
assert ("n", "e", "w", "est</w>") in words
assert ("w", "i", "d", "est</w>") in words
print(merges)
```

这段实验的断言固定了算法、边界、加权方式和前三步结果。它没有声称能够直接处理任意未知 Unicode 字符；若推理遇到训练时完全没有的字符，就需要未知符号或另行设计字节回退。词表里存在某个完整字符串也不代表推理总会把它当成一个 token，因为有序合并规则同样属于 tokenizer 的定义。仅保存最终词表而丢失合并顺序，可能无法重现原来的分段。

## 4. 词袋与 TF-IDF 的精确计算

<a id="nlp-1-detail-16"></a>
### 4.1 计数矩阵与顺序损失

给定训练词表 $`V=\{v_1,\ldots,v_d\}`$，计数矩阵中 $`C_{ij}`$ 表示第 $`i`$ 篇文档里词项 $`v_j`$ 的出现次数。它保留频率，不保留具体位置。同一组词任意交换顺序后计数保持不变，因此“甲喜欢乙”与“乙喜欢甲”在按相同词切分时会得到相同的 unigram 计数。加入相邻二元组可以区分这两个例子，却仍不等于完整记录任意长距离结构。

词袋模型的价值不是宣称语义都由词频决定，而是提供一种透明、成本可控且适合检查数据问题的基线。若类别与少量主题词高度相关，线性模型就可能很好地完成任务；若区别依赖否定范围、指代或复杂关系，词袋可能碰到表示上限。应通过错误样本确认限制，不能因为神经模型更复杂就跳过基线，也不能因为一个小数据集基线很强就推断语言理解已经解决。

<a id="nlp-1-detail-17"></a>
### 4.2 文档频次与平滑 IDF

本章采用与指定实验配置一致的平滑定义：训练文档数为 $`N`$，包含词项 $`j`$ 的文档数为 $`df_j`$，则 $`idf_j=\log[\frac{(1+N)}{(1+df_j)}]+1`$。出现次数是一篇文档内部的计数，文档频次是一篇文档最多贡献一次的计数。某个词在一篇文本中重复一千次，并不会让它的文档频次增加一千；它仍然只给这一篇贡献一次。

先计算未归一化权重 $`w_{ij}=tf_{ij}idf_j`$，再可选择按每篇文档的二范数归一化。默认计数式词频、二值词频和对数词频是不同配置。对数词频常写为正计数位置的 $`1+\log C_{ij}`$；零计数仍为零，不能直接对零取对数。不同论文和工具还可能使用不同对数底、平滑和加一规则，因此比较数字之前必须写出完整公式。

取三篇已经按空格分词的文档：“猫 猫 鱼”“狗 鱼”“狗”。猫的文档频次为一，狗和鱼为二；猫的 IDF 为 $`1+\log2`$，狗和鱼为 $`1+\log(\frac{4}{3})`$。第一篇的未归一化向量按“狗、猫、鱼”排列是 $`(0,2(1+\log2),1+\log(\frac{4}{3}))`$。归一化会同时缩放所有非零维度，不会改变这一篇内部猫与鱼的权重比。

<a id="nlp-1-detail-18"></a>
### 4.3 归一化怎样改变相似度

余弦相似度为 $`\frac{x^Ty}{(\Vert x\Vert\;\cdot\;\Vert y\Vert )}`$，对于非零向量，与对每行做二范数归一化后的内积等价。它弱化整体长度对相似度的直接影响，却不保证长度完全无关：较长文档可能覆盖更多主题和词项，也可能改变词项权重分布。相反，未经归一化的内积通常偏向含有更多共享词或较大权重的文档，具体是否合适取决于任务。

全零向量是必须处理的边界。如果一段新文本全部由训练词表之外的词构成，它在固定词表词袋里可能变成零向量；不能对它直接套用数学上的余弦除法。工具可能约定返回零相似度，但业务含义仍是“没有可用词项证据”，并不等于文本与所有内容都语义无关。应统计这种输入的比例，并为检索或分类设计明确回退和拒答策略。

<a id="nlp-1-detail-19"></a>
### 4.4 实验三：手算、工具实现和训练边界一致

```python
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer

train = ["猫 猫 鱼", "狗 鱼", "狗"]
v = TfidfVectorizer(tokenizer=str.split, token_pattern=None,
                    lowercase=False, norm="l2", smooth_idf=True)
x = v.fit_transform(train)
names = list(v.get_feature_names_out())
expected_idf = np.array([1 + np.log(4 / 3) if word != "猫" else 1 + np.log(2)
                         for word in names])
np.testing.assert_allclose(v.idf_, expected_idf)
row = np.array([{"猫": 2, "鱼": 1}.get(word, 0) for word in names]) * expected_idf
row = row / np.linalg.norm(row)
np.testing.assert_allclose(x.toarray()[0], row)
old_vocabulary, old_idf = dict(v.vocabulary_), v.idf_.copy()
z = v.transform(["新词 新词", "猫"])
assert z[0].nnz == 0
assert v.vocabulary_ == old_vocabulary
np.testing.assert_array_equal(v.idf_, old_idf)
assert np.isclose(z[1].multiply(z[1]).sum(), 1)
print(names, np.round(x.toarray(), 6).tolist())
```

这里为了查看三列小矩阵使用了稠密转换，不应把这一步照搬到百万文档的完整词表。实验确认了固定训练词表和 IDF 的变换行为，但没有训练分类器，更没有真实文本成绩。若要比较分词方案，应将词表拟合置于每个训练折内部，再使用独立验证文本选择方案；在全部文档上先拟合表示再划分数据，会让测试文本参与词项和权重的确定。

## 5. 从稀疏特征到嵌入几何

<a id="nlp-1-detail-21"></a>
### 5.1 线性文本分类器实际上学习什么

对于词袋特征 $`x`$，二分类器可以使用 $`s(x)=b+\sum_jw_jx_j`$。每个词项的贡献可以直接检查，但贡献的解释依赖全部预处理规则和特征间相关性。高正系数表示在拟合模型的条件结构下该特征推动正类分数，不等于这个词在所有语境中都表达积极情感。来源标记、模板或格式也可能获得大系数，模型会利用训练分布提供的相关性，而不会自动遵守研究者希望它使用的语义线索。

加入 n-gram 是让模型拥有更丰富的可加特征，而不是让它自动具备组合推理。二元组“不是 很好”可以获得一个负系数，但没有见过的变体“并非特别好”仍可能无法泛化。字符 n-gram 对拼写变体、词边界不确定和少量噪声有一定适应能力，同时也可能把产品编号、作者签名或排版模式作为捷径。应同时做语义扰动与来源迁移检查。

<a id="nlp-1-detail-22"></a>
### 5.2 嵌入矩阵、独热向量和参数共享

词项编号 $`i`$ 的独热向量为 $`e_i`$，嵌入矩阵为 $`E\in\mathbb R^{\vert V\vert \times d}`$，查表结果可以写为 $`E^Te_i`$。查表没有神秘运算，本质是选择矩阵的一行；学习的核心在于后续目标如何调整这些行，以及相似上下文是否使不同词项共享统计结构。低维向量可以节约下游计算，但它不保证保留原始词表中的所有可分辨方向。

静态嵌入为每个词项提供固定向量，因此同一个编号在不同句子中的初始表示相同；上下文编码器进一步把整个序列作为输入，输出依赖位置和上下文的表示。多义词可以因此得到不同向量，但这种能力来自模型训练和上下文交互，并非“使用向量”本身就必然实现。子词模型还需要考虑如何把多个片段的表示组合成词、实体或句子的表示。

<a id="nlp-1-detail-23"></a>
### 5.3 内积、余弦、范数与各向异性

向量内积同时受方向和范数影响，余弦只比较方向。若训练目标用未归一化内积排序，直接在部署时改成余弦可能改变排序。设 $`q=(1,0)`$，候选 $`a=(10,1)`$、$`b=(1,0)`$，内积更偏向 $`a`$，余弦则使 $`b`$ 更接近查询方向。哪个结果更好必须由训练目标与业务相关性定义，而不能因为余弦更常见就自动替换。

所有向量集中在一个窄锥体内时，随机文本之间也可能有较高余弦；这类几何分布会影响近邻检索和阈值解释。对向量去均值、白化或归一化可能改变这些现象，但这些操作本身也需要拟合数据和验证。不能把测试库整体的均值用于一个声称只允许训练信息的归纳实验，除非已经明确设定为可观察固定目标库的检索场景。

<a id="nlp-1-detail-24"></a>
### 5.4 池化为什么不是无损摘要

均值池化 $`h=\frac{\sum_tm_th_t}{\sum_tm_t}`$ 必须以有效位置掩码 $`m_t`$ 为分母，不能把填充位置混入平均。即使掩码正确，不同词序也可能有相同均值；如果前面的表示不包含位置信息和上下文，后面的均值就不会凭空保留顺序。最大池化突出某些维度的强激活，却丢失激活出现次数和位置；首 token 池化能否有效也取决于模型训练方式。

将一段长文本分块再平均，通常不等于完整编码整段文本。块间关系可能丢失，长块和短块的权重可能不合理，重复内容可能被反复计入。比较池化方案应说明按 token、按句子还是按块等权，是否去掉重叠部分，以及最后是否归一化。许多“换一个句向量就提升”的结论，实际上混合了分块、长度和权重策略的变化。

<a id="nlp-1-detail-25"></a>
### 5.5 实验四：池化掩码和几何不是同一个问题

```python
import numpy as np

q = np.array([1.0, 0.0])
a = np.array([10.0, 1.0])
b = np.array([1.0, 0.0])
cos = lambda x, y: float(x @ y / (np.linalg.norm(x) * np.linalg.norm(y)))
assert q @ a > q @ b
assert cos(q, b) > cos(q, a)
h = np.array([[[1., 2.], [3., 4.], [99., 99.]],
              [[5., 6.], [99., 99.], [99., 99.]]])
mask = np.array([[1, 1, 0], [1, 0, 0]], dtype=bool)
pooled = (h * mask[..., None]).sum(axis=1) / mask.sum(axis=1)[:, None]
np.testing.assert_allclose(pooled, [[2, 3], [5, 6]])
assert not np.allclose(h.mean(axis=1), pooled)
rotation = np.array([[0., -1.], [1., 0.]])
assert np.isclose(cos(q @ rotation, a @ rotation), cos(q, a))
print("掩码均值:", pooled.tolist(), "内积与余弦排序不同")
```

旋转断言揭示另一种解释边界：对所有向量施加相同正交变换，余弦不变，但每个坐标的数值和含义可以变化。因此不能仅凭某个嵌入维度的正负就宣称它天然代表一种固定语义。对嵌入的解释应依赖可复核的任务、探测或干预，同时注意探测器自身可能学到新信息映射，而不是简单读出唯一语义维度。

## 6. 静态、上下文与任务适配表示的比较

<a id="nlp-1-detail-27"></a>
### 6.1 分布式学习目标决定相似性的含义

在分布式表示中，“相似”通常由训练目标中的共现、预测或对比关系定义。经常出现在相似上下文中的反义词，可能在向量空间相近；这对于主题检索有时合理，对于判断态度方向可能不够。相似词、相关词、可互换词和同义词是不同概念。一个类比例子漂亮，不足以说明向量在法律事实、数字关系或所有语言上都可靠。

上下文表示让同一个词项随句子变化，但仍受训练语料和目标限制。句子编码器若主要学习语义匹配，可能弱化词序或小数差异；分类适配后的表示可能只保留当前分类所需信息。研究时应先提出能区分假设的对照任务，例如实体交换、数字替换、时间前后改变，再检查表示距离和下游输出，而不是只绘制二维图后凭视觉决定模型理解了什么。

<a id="nlp-1-detail-28"></a>
### 6.2 预训练与本地训练的公平比较

固定预训练表示已经利用了外部数据、计算和先验；本地 TF-IDF 只从当前训练文档学习统计。两者可以在业务效果上比较，但结论应该是两套完整方案在给定条件下的表现，而不是“某种几何结构单独导致提升”。同时应报告资源、许可、语言覆盖、输入限制和推理成本。若实验关注方法本身，应控制外部数据权限，或明确把它作为额外因素。

微调时要区分更新编码器、只训练线性头以及对固定向量做后处理。它们的过拟合方式、资源需求和可复现边界不同。固定编码器可以缓存训练表示，但如果编码器在每个交叉验证折中不同，缓存必须随折重新生成。先用全部标签微调一个编码器，再把其输出拿去交叉验证分类头，不是在评价完整微调流程的泛化。

## 7. 词表、版本和数据边界是模型的一部分

<a id="nlp-1-detail-30"></a>
### 7.1 需要保存的远不止词项列表

可复现的文本系统需要保存字符规范化、预分词规则、词表编号、合并顺序、特殊符号编号、未知符号策略、截断和填充规则，以及向量权重和后续分类器。词表元素相同但编号变化，会把嵌入行解释错；分词代码相同但规范化形式变化，也可能让同一句话得到不同输入。只保存神经网络权重，不能保证恢复原来的文本到输出函数。

模型接口还要说明输入是否已经预分词、是否允许空文本、列表元素是否按文档还是句子解释。把一整篇文档的句子误当成多个独立样本，会改变样本量和评价单位；把字符列表误当成词列表，则可能让 tokenizer 再次拆分。用几条固定参考输入及其 token、掩码和输出形状做版本检查，可以迅速发现这类接口漂移，但不能替代完整的质量评价。

<a id="nlp-1-detail-31"></a>
### 7.2 拟合、变换和选择的权限矩阵

训练折可以拟合词表、文档频率、嵌入适配参数和分类器；验证折可以用于预先允许的模型选择；最终测试折用于冻结流程后的评价。若需要在新时间或新来源上部署，应让划分单位反映这个目标。随机把同一模板、同一作者或同一事件的近重复文本分到训练与测试两边，会使表示学习获得过于便利的线索，无法回答跨来源或跨事件的问题。

词表裁剪参数如最小文档频率、最大文档频率、词表上限和 n-gram 范围都属于选择过程。即使每次拟合没有直接读测试标签，只要研究者根据最终测试结果反复调这些参数，测试也已经进入选择回路。应保留探索集、冻结规则和独立确认集，或者使用嵌套验证评价整个选择流程。无法重新获得独立测试时，报告就需要明确其探索性质。

## 8. 长度、截断与标签对齐

<a id="nlp-1-detail-33"></a>
### 8.1 子词标签映射是目标定义的一部分

在实体识别中，原始标注可能以词或字符跨度给出，而模型输入以子词给出。常见做法是只在每个原词的第一个子词计算损失，或将标签映射到全部子词。两者改变了训练权重：长词若拆成更多子词，在逐子词平均损失下可能获得更大权重。是否把后续子词标成延续标签，还需要与所用 BIO 规范和最终合并算法一致。

特殊符号、填充符号和未参与监督的位置通常应设置忽略掩码。掩码不仅影响损失，还影响指标和池化。假设十个有效 token 只有两个属于实体，却有九十个填充位置；若把填充都当成正确的背景标签，准确率会被严重抬高。应先将预测还原到约定的原词或原文跨度，再按目标单位评价，而不是在模型张量的所有位置上直接求均值。

<a id="nlp-1-detail-34"></a>
### 8.2 截断会造成选择偏差和不可达答案

固定最大长度会丢弃尾部信息。如果标签证据更常出现在后半段，短截断相当于为某些样本制造缺失信息；如果某类文本系统性更长，截断影响又会与类别相关。应报告截断率、按类别和来源的长度分布，以及金标准实体或答案被截断的比例。只报告平均长度无法揭示少数极长文档的失败模式。

滑动窗口可以扩大覆盖，但窗口重叠会带来重复预测和监督权重变化。对于跨窗口实体，如何合并跨度、处理边缘置信度和避免重复计数，都需要明确。对文档分类，把所有窗口都赋予整篇标签可能引入弱监督噪声，因为某个窗口里未必包含标签证据。选择窗口策略时，应从任务的证据结构出发，而不是把它当作简单的显存技巧。


<a id="visual-mechanism-nlp-01"></a>

### 图解：截断可能切开一个完整实体跨度

![截断可能切开一个完整实体跨度](images/01-mechanism.svg)

**图中的机制。** 原文实体覆盖连续四个 token，但长度限制只保留其中三个，图把被切断的边界和实体原跨度同时画出。训练时不能把剩余片段默认当作完整实体标签；可选择移动窗口、丢弃受损实体监督或采用明确的部分标注规则。

**条件与边界。** 具体策略需与 BIO 标注和评价单位一致。字符数、token 数与编码长度不同，截断前后必须保留坐标映射。

## 9. 进阶：概率单位、可辨识性与表示研究

<a id="sec-6-1"></a>
<a id="nlp-1-detail-36"></a>
### 9.1 不同分词器的困惑度不能直接排名

语言模型首先给 token 序列分配概率。确定性且能还原文本的编码器，为一个字符串选择唯一的规范 tokenization，因此可以直接计算该规范 token 序列的对数概率；这还不自动等于解码后字符串的总概率。只有同一字符串的其他非规范路径概率总和为零时，规范路径概率才等于该字符串的总概率；仅规定编码器输出唯一，并不能排除这些路径。每 token 平均负对数似然又除以不同的长度，因此直接比较困惑度会混入单位变化。字、子词和字节的一个 token 所承载的信息不同，不能因为数值更低就断言语言建模一定更好。

例如，词表含 `a`、`b`、`ab` 三个普通 token，解码把 token 文本直接拼接。编码器即使总把字符串 `ab` 编成单个 `ab`，模型仍可能分别给完整序列 `[ab, EOS]` 和 `[a, b, EOS]` 分配概率 $`0.2`$ 与 $`0.3`$。若没有其他路径解码为该字符串，则文本的总概率是 $`0.5`$，而规范路径评分只使用 $`0.2`$；两者的负对数分别是 $`-\log0.5`$ 与 $`-\log0.2`$。这里的序列概率均包含结束符，避免把前缀概率与完整文本概率混淆。规范路径评分与字符串边缘概率的区别，可进一步核对[分词边缘化原论文](https://aclanthology.org/2023.acl-short.1/)。

若要跨分词器比较，应选择一致的原文单位，例如每字节或每字符的编码长度，并明确对空白、规范化和起止符的处理。即使统一了单位，还要考虑字符串是否存在多种 token 表示、模型是否把概率质量分配给非规范序列，以及文本编码是否可逆。本章不把这些复杂因素省略成“除以字数就完全公平”；可比性来自完整定义和相同数据权限。

<a id="nlp-1-detail-37"></a>
### 9.2 可逆性、规范化与评估对象

若分词可以完全恢复规范化文本，但规范化本身丢失了原始差异，那么整个链路仍然不能恢复原文。例如把全角折成半角后，即使子词编码可逆，也只能还原折叠后的版本。讨论无损编码时必须指定相对于原始字节、Unicode 字符串还是规范化字符串而言。检索常允许某些等价变换，档案保存和法律转录则可能要求原始形式完全保留。

表示研究还应区分信息存在与信息可用。一个高维向量理论上可能编码某个属性，但有限数据和受限下游模型未必能有效读出；一个强探测器得到高准确率，也不代表原模型在实际任务中使用了该属性。更可信的研究会控制探测器容量、比较随机表示与简单表面特征，并通过反事实输入检查目标输出如何随证据变化。

<a id="nlp-1-detail-38"></a>
### 9.3 从错误类型提出下一步实验

如果错误集中在生僻词，可以比较字符回退和子词词表；如果错误集中在否定与角色交换，应优先检查顺序信息和上下文；如果错误集中在新来源，应排查模板捷径与域漂移；如果错误集中在长文本，应分析截断和聚合。每一种改进都对应一个可被否定的机制假设，而不是统一换更大模型。改进以后，还应检查成本、旧能力和受影响群体，避免只追逐一个总体指标。

真正的进阶不在于背诵更多模型名称，而在于把数据表示、目标函数和评价协议连接起来。对一个新方案，能够解释它改变了哪些可区分关系、引入了哪些训练信息、付出了哪些资源、用什么实验可以证明其局限，才是可迁移的理解。下面的练习要求同时给出机制和边界，而不是只给术语定义。

<a id="nlp-1-detail-39"></a>
### 9.4 特征哈希的碰撞、权限与可解释性

特征哈希把任意词项通过固定哈希函数映射到有限维坐标，可额外用一个符号函数决定加减。它不需要先学习显式词表，适合流式输入和内存受限场景，但这并不意味着完全没有状态需要管理。哈希函数、维数、符号规则、规范化和分词仍需要固定；若后面接 IDF 或分类器，这些部分仍然要遵守训练边界。哈希只是替换词项到坐标的映射，不会自动消除选择泄漏。

两个不同词项可能映到相同坐标，称为碰撞。在不带符号的计数中，碰撞会把它们的出现次数累加，导致某个词的证据被另一个词干扰；带符号映射可以在特定随机假设下改善内积估计性质，却不会让每个具体样本都无误。维数越大通常越少碰撞，但内存和计算也可能增加。应把碰撞视为表示压缩的明确代价，而不是把哈希函数的确定性误当成无损。

词表模型能列出某一维对应的词，哈希模型的一维可能混合许多词，因此解释分类系数时需要回到原始输入定位实际激活项。若一条样本同时出现正负符号相反的碰撞词，它们甚至可能抵消。研究者看到某维为零时，不能判断相关词完全没有出现。对于需要逐条说明证据的应用，应在节省内存与可追踪性之间做明确取舍，并保存可复核的分析器定义。

<a id="nlp-1-detail-40"></a>
### 9.5 共现矩阵、低秩分解与负采样目标

另一条表示路径先构造词与上下文的共现矩阵。每个窗口贡献哪些上下文、是否跨句边界、左右位置是否区分、常见词是否降采样，都会改变矩阵。对共现概率构造点互信息时，可写为 $`PMI(w,c)=\log[\frac{P(w,c)}{(P(w)P(c))}]`$。它衡量相对于独立分布的共现强度，而不是简单的共现次数：两个都极常见的词即使共现很多，也可能没有很高的互信息。

低频词的一两次共现可能得到很大的估计互信息，因此需要平滑、频次门槛或其他稳定化措施。对矩阵做截断奇异值分解，可以用低秩向量近似原始关系，但最小化的是所定义矩阵上的重构误差，不是直接最小化某个下游任务的错误。若重要类别差异落在被截断的方向，压缩可能损失任务信息。矩阵分解提供的是一个清楚的统计目标，不能凭低秩三个字保证语义质量。

负采样把某些训练问题改写为区分观察到的词上下文对与从噪声分布抽取的配对。改变噪声分布、负样本数量和采样权重，会改变优化偏好。即使某些理想条件下可以联系到矩阵分解，也不能忽略有限维、随机优化、共享参数和语料分布的条件，直接宣称两套实际系统完全等价。进阶阅读应特别关注推导假设与最终工程配置是否相符，而不是只记住一个看似统一的口号。

<a id="nlp-1-detail-41"></a>
### 9.6 对比学习中的负样本与假负例

句向量对比学习通常给查询一个正配对和若干负配对，鼓励正配对的分数相对于候选集合更高。一个常见形式是对温度缩放后的相似度做交叉熵。温度越低，分数差异被放大，梯度更集中于难区分候选；但这不等于越低越好，过低会放大噪声与错误负例的影响。分数函数、归一化、温度和采样分布共同决定学习到的几何。

如果另一个样本其实也是合理答案，却被当成负例，模型可能被迫拉开语义等价文本。批内负例在计算上方便，但同主题、同实体或重复样本容易制造这类假负例。只增加批大小可能同时增加有效对照和错误排斥，不能单凭负例数量预测最终质量。应检查重复、配对来源和多正例定义，并根据任务评估是否需要将多个答案共同纳入正集合。

难负例也需要防止评价信息回流。用冻结的训练侧检索器从训练库挖掘负例，与根据测试问题反复挑选最难候选，是不同的信息权限。若任务允许固定检索库在部署前完全可见，可以使用库的无标签内容，但仍不能读取保留相关性标注来调整模型。应将语料可见、查询可见、相关性可见和最终指标可见分别写清，避免用一个笼统的公开数据标签掩盖不同的实验条件。

最后，表示评价不能仅检查正例更近。需要同时观察语义相近却标签相反的样本、同一事实不同措辞、不同事实相似模板，以及数字与否定的微小变化。如果模型把“已经付款”和“尚未付款”都拉到同一邻域，主题检索可能仍然得分不错，事实检索却可能失败。对比目标提供了一种学习方式，其成功范围最终仍由正负样本的定义和评价对象决定。

<a id="nlp-1-detail-42"></a>
### 9.7 估计不确定性与表征实验的重复单位

比较两种表示时，一次随机划分的差异可能来自样本构成，而非稳定的方法优势。若目标是新文档，可以按文档配对比较两个模型的错误；若目标是新作者或新事件，就应以作者或事件作为重采样单位。把同一事件下高度相关的几百条短句当成几百次独立证据，会低估不确定性。重复训练种子描述优化随机性，重新抽取来源描述样本不确定性，二者回答的问题也不同。

表示学习通常含有许多选择：分词粒度、维数、窗口、归一化、池化、分类头和训练轮数。尝试次数越多，最好的验证结果越可能部分受偶然性帮助。应记录候选集合和选择规则，并在冻结后用未参与选择的数据确认。若没有条件做独立确认，就应保留探索性措辞，报告全部重要候选，而不是只展示最成功的一个数字和一张最漂亮的可视化。

统计显著也不自动意味着值得部署。一个很小但稳定的提升，可能伴随明显的延迟、缓存成本和维护复杂度；一个总体平均提升，也可能掩盖某个关键来源的严重退化。报告应将任务收益、资源代价和错误结构放在同一评价框架中。对于零向量、超长输入和规范化冲突，应保留绝对数量与比例，因为平均指标有时会把这些需要明确回退策略的失败隐藏起来。

## 10. 练习与详细参考答案

<a id="nlp-1-detail-44"></a>
### 10.1 删除否定以后能否靠分类器恢复

题目：清洗把“能退”和“不能退”都变成“能退”，增加模型容量能否解决？答案：若模型只接收清洗结果，两者在输入上完全相同，确定性输出必须相同。若它们标签不同，至少有一部分条件风险无法消除。增加容量只能利用其他仍被保留且合法的特征，不能恢复已经丢失的区分。修复首先是保留否定，并检查是否还删除了程度词、条件词或转折结构。

<a id="nlp-1-detail-45"></a>
### 10.2 NFC 相同是否意味着业务上可互换

题目：两个字符串规范化后相同，是否可以删除其中一个原始记录？答案：规范化相同说明相对于所选 Unicode 等价关系形式一致，不说明它们属于同一个事件、用户或业务样本。两条独立评价可能内容相同却代表不同请求；一条重复抓取记录可能确实应该去重。去重依据需要结合来源、时间、任务单位和隐私要求，原始记录身份与文本等价不能混为一谈。

<a id="nlp-1-detail-46"></a>
### 10.3 为什么不能按码点数判断界面长度

题目：一个重音字母有时长度一、有时长度二，界面怎样截断？答案：码点计数与用户感知的字素簇不同，应按所需显示单位使用适当的分段实现，并明确数据坐标约定。模型预算若按 token 计数，又属于另一种限制。界面截断、存储字节上限和模型 token 上限应分别校验，避免用一个数字假装覆盖三种不同资源。

<a id="nlp-1-detail-47"></a>
### 10.4 文档频次会随词内重复增长吗

题目：某词只出现在一篇文章里，但重复一百次，文档频次是多少？答案：在这一篇之外都不出现时，文档频次为一；词频是一百。若共有三篇训练文档，本章平滑 IDF 为一加二的自然对数。重复可能提高该文档未归一化的词项权重，但不改变其他文档是否含有该词的事实。先区分统计单位，再代入公式，能够避免把词频误写成文档频次。

<a id="nlp-1-detail-48"></a>
### 10.5 同词表为什么仍可能无法恢复分词

题目：保留了所有 BPE 词项，为何还需合并表？答案：词表只说明可用符号集合，没有完整说明遇到重叠候选时优先组合哪一个。不同合并顺序可能产生不同分段；预分词和边界规则也决定哪些位置允许合并。恢复系统需要词表编号、合并优先级、特殊符号和规范化配置，不能只把字符串列表重新排序后就当成相同 tokenizer。

<a id="nlp-1-detail-49"></a>
### 10.6 字节方案是否解决所有未知输入问题

题目：字节覆盖完整，是否就无需研究分词？答案：字节编码可以避免某类字符词表之外的输入，但非 ASCII 文本可能需要更多 token，长度和计算预算随之改变。覆盖不等于训练中见过组合、不等于模型理解语义，也不等于截断不会发生。应同时衡量长度分布、目标质量和成本，再判断这种覆盖能力是否满足实际约束。

<a id="nlp-1-detail-50"></a>
### 10.7 为什么加入二元组不能解决全部顺序关系

题目：有了相邻二元组，词袋是否已经等同序列模型？答案：相邻二元组仅保留局部顺序统计，较长序列仍可能共享同一组局部片段计数而具有不同全局结构。指代、嵌套和远距离依赖也未必能从有限阶统计唯一恢复。它是有用的特征扩展，可用来验证局部短语是否足够，但不能据此宣称完整保留了原句结构。

<a id="nlp-1-detail-51"></a>
### 10.8 新文本是全零向量该如何解释

题目：测试文本变成全零 TF-IDF，能否说它语义无关？答案：只能说在当前训练词表和分析规则下没有留下非零证据。可能是新领域词、分词错误、过强过滤或空输入导致。应检查原文和分析器输出，统计发生比例，并提供明确回退。随意用测试文本扩充词表会改变评价协议，修复需要通过新的训练和验证流程完成。

<a id="nlp-1-detail-52"></a>
### 10.9 对所有嵌入同时旋转会发生什么

题目：共同正交旋转是否改变余弦近邻？答案：正交矩阵保持内积和范数，所以非零向量的余弦与排序不变。坐标值却会改变，因此某个维度的直接语义解释并不唯一。如果还存在一个未同步旋转的分类头，整个系统输出可能变化；保持任务函数需要相应变换分类头。几何等价与完整模型参数等价应分别讨论。

<a id="nlp-1-detail-53"></a>
### 10.10 均值池化能否忽略填充

题目：填充向量恰好为零，直接除以最大长度是否正确？答案：这会让短样本的向量幅度被额外压缩，即使填充值为零也仍然有偏差。应以有效位置数量为分母，并对完全空序列另行定义。若后面只计算余弦，某些整体缩放可能被消除，但分类器、阈值和数值稳定性仍可能受影响，不能据此省略正确掩码。

<a id="nlp-1-detail-54"></a>
### 10.11 为什么预训练比较需要披露外部资源

题目：固定预训练编码器超过本地词袋，能否证明稠密表示天生更强？答案：结果混合了表示结构、外部语料、训练目标和大量计算。可以诚实地说完整方案在这个协议下更好，但不能把提升全部归因于其中一个因素。要研究结构贡献，应控制或分层分析资源条件，同时报告不确定性和推理成本，避免以系统比较替代单因素因果结论。

<a id="nlp-1-detail-55"></a>
### 10.12 两个分词器困惑度怎样比较

题目：一个词级模型困惑度二十，字级模型困惑度五，谁更好？答案：无法仅凭这两个数判断，因为每个预测单位的信息量不同。需要在相同原始文本与相同编码约定下转换到一致长度单位，并考虑规范化和可逆性。还要检查数据权限、起止符计数和非规范序列概率。单位不一致时直接排名，本质上类似把不同单位的长度数值直接比较。

<a id="nlp-1-detail-56"></a>
### 10.13 未读标签的词表拟合为什么仍有边界

题目：只使用测试文本训练 BPE，不看标签，是否总是公平？答案：这已经让系统观察到目标词形和频率分布。某些传导式任务允许这种权限，但需要明确声明并给比较方法一致机会；严格归纳任务则不允许。泄漏的判断取决于问题定义，不能用无监督三个字替代权限说明。固定外部 tokenizer 又是另一种先验来源，应独立记录。

<a id="nlp-1-detail-57"></a>
### 10.14 如何检查字段和版本没有悄悄改变

题目：新版本 tokenizer 词表大小没变，是否可以直接替换？答案：词项编号、合并优先级、规范化、特殊 token 和截断策略都可能变化。应使用固定参考文本比较 token、偏移、掩码和逆解码结果，必要时检查下游输出和长度分布。词表大小只是一个汇总数字，不能证明函数一致；也不能只用权重文件名相同判断版本等价。

<a id="nlp-1-detail-58"></a>
### 10.15 长文档表现差应该先增加最大长度吗

题目：长文本错误更多，是否应直接把长度翻倍？答案：先检查标签证据的位置、截断率、来源差异和聚合权重。如果主要证据确实被截断，增加长度或窗口可能有帮助；如果问题是窗口重复、来源漂移或标签噪声，增加预算未必有效。还应评估延迟和资源，并在固定验证协议中比较，不要根据测试错误反复挑选窗口参数。

<a id="sec-7-1"></a>
<a id="nlp-1-detail-59"></a>
### 10.16 更强清洗是否总改善泛化

题目：清洗后词表缩小一半、训练更快，是否可以直接接受？答案：资源改善是事实，但质量需要独立验证。应检查必要语义对照、冲突桶、各来源和长度切片，以及最终任务指标。若清洗只删除来源水印，可能减少捷径；若删除否定和数值，则可能降低可达上限。接受标准应同时写明质量与资源条件，而不是让词表缩小本身成为唯一目标。

<a id="nlp-1-detail-60"></a>
## 11. 综合研究任务：把表示选择变成可复核证据

设计一个完全可在本地运行的小实验，分别保留原文、采用规范等价规范化、采用兼容折叠，并比较 unigram、字符片段和一个固定的简单序列表示。先用人工最小对照检查是否保留否定、角色与数字，再使用按模板或来源分组的划分。所有词表、频率和选择都只在相应训练部分拟合，最终测试保持冻结。人工数据用于验证机制，不得将其成绩包装为真实行业表现。

报告中应包含每一步变换的权限、输入输出例子、不可逆信息、词表规模、长度分位数、零向量和截断比例，以及模型需要的资源。对每个失败案例提出一个具体机制假设，并设计只改变相关因素的对照实验。若无法区分是表示、数据还是训练目标造成的错误，应把这种不确定性写出来，而不是用一段泛泛的模型能力描述填补证据缺口。
