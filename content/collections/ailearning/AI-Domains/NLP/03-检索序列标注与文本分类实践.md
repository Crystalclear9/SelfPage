## 1. 实践目标与证据边界

<a id="nlp-3-detail-2"></a>
### 1.1 本章构造三条可检查的完整路径

本章依次建立文本检索、文档分类和结构化标注三个小系统。所有输入均为人工构造，不下载语料、不调用外部模型，也不把小例子的分数包装成真实应用能力。它们的价值在于把前两章的数学定义连接成从文本、特征、训练、预测到评价的闭环，并通过断言检查训练边界、排序约定和结构合法性。

检索任务给定查询和固定文档库，输出有序文档；分类任务为新来源文档预测类别；标注任务为字符序列输出 BIO 标签，再恢复实体跨度。三者可以共享规范化和分析器，但不能共享一个未经说明的评价单位。文档、查询、来源和实体分别是不同统计对象，训练数据权限也各不相同。

代码使用本地 Python、NumPy、scikit-learn 和 CPU PyTorch，单线程设置只是为了让小实验更容易复现，不代表实际吞吐优化。每个代码块自包含，可以单独运行。需要推广到真实数据时，首先替换来源和划分协议，再重新拟合全部状态；不能只把人工例子的字符串换成真实文本，却继续沿用不合适的分组和标签假设。

<a id="nlp-3-detail-3"></a>
### 1.2 先写数据协议再写模型

一个最小协议应回答：输入是什么，输出是什么，部署面对什么新变化，哪些数据可见，如何选择超参数，最终用什么样本确认。检索常允许索引完整的固定文档库，这不等于允许读取保留查询的相关性标签；分类的词表必须在训练折内拟合；标注的标签集合和非法转移应在规范中定义，而不是看到测试错误以后临时修补。

还需要保存身份字段。每篇文档、每个查询和每条标注序列都应有稳定标识，评价时按标识关联预测与金标准，而不是仅依赖列表顺序。来源组用于划分和不确定性分析，可以不进入模型特征。把标识用于追踪与把标识输入模型是两件事，后者可能引入捷径，需要有明确业务理由。

<a id="nlp-3-detail-4"></a>
### 1.3 机制断言与质量结论分开

断言训练与测试来源不重叠，是协议检查；断言矩阵有限，是数值检查；断言模型超过某个真实业务标准，则需要代表性数据和合理的不确定性分析。本章主要建立前两类证据，同时诚实展示人工数据上的预测。即使人工样本准确率为一，也不能推断模型处理真实否定、歧义和领域迁移没有问题。

模型效果不理想同样可以是有价值的结果。未见实体上的失败暴露了词形记忆，词面检索的漏召回暴露了同义表达缺口，分类的来源退化暴露了分布改变。实践报告应该保留这些信息并提出后续实验，而不是为了让示例看起来成功，反复调整测试内容直到全部预测正确。

## 2. 检索表示、BM25 与排序协议

<a id="nlp-3-detail-6"></a>
### 2.1 固定库索引和查询处理

检索库的统计量通常包括文档数、每个词出现的文档数、文档长度和平均长度。若业务允许在部署前索引完整库，这些统计量可以来自全部库文档，因为库本身是系统输入的一部分。保留查询和相关性标注则承担评价角色，不能拿它们反复调参数后还声称独立确认。库更新以后，文档频率和平均长度也可能变化，索引版本应同步记录。

查询和文档应使用约定一致的分析器。例如文档把“退款流程”切成一个词，查询却切成“退款”和“流程”，在纯词项匹配系统中可能完全不相交。统一分析器不意味着查询与文档一定使用完全相同权重，但至少要明确规范化、分词、大小写和停用词策略，并测试空查询与全未知词查询的处理。

<a id="nlp-3-detail-7"></a>
### 2.2 BM25 的饱和与长度归一化

本章使用一个明确的正 IDF 变体：$`idf(t)=\log[1+\frac{(N-df(t)+0.5)}{(df(t)+0.5)}]`$。对查询中每个不同词项，将文档贡献写为 $`\frac{idf(t)f(t,d)(k_1+1)}{[f(t,d)+k_1(1-b+\frac{b\vert d\vert }{avgdl})]}`$，再求和。查询词频在这个教学版本里不额外加权，其他实现可能增加相关因子，不能在公式不同的情况下直接比较分数。

当文档中某词频率增加时，分数趋于饱和，不会像原始词频那样无上限增长。参数 $`k_1`$ 控制这种饱和速度，参数 $`b`$ 控制文档长度归一化强度；$`b=0`$ 不做长度修正，$`b=1`$ 使用完整长度比例项。这里的长度是分析后的词项数，不是字节数或原始字符数。修改停用词和分词也会改变平均长度，因而会同时影响多个因子。

<a id="nlp-3-detail-8"></a>
### 2.3 手算与退化边界

设三篇文档中某词出现于一篇，则本章 IDF 为 $`\log[1+\frac{2.5}{1.5}]`$。如果目标文档长度恰等于平均长度、词频为一，则分式中的长度项退化为 $`k_1`$，整个词频因子为一，贡献就是 IDF。词频增加到二时，因子变成 $`\frac{2(k_1+1)}{(2+k_1)}`$，大于一却小于二，清楚体现了边际收益递减。

平均长度为零意味着库文档分析后全部为空，此时不能直接套用除法，应拒绝建立该配置或定义明确回退。查询全部未知时，所有分数可能相同；排序必须固定平局规则，例如稳定文档标识顺序。这样的返回不应被解释为模型有证据认为排在前面的文档更相关，只是系统为了满足接口给出了确定顺序。

![固定文档长度下BM25词频因子的递减增益与原始词频对比](images/03-bm25-saturation.svg)

为把饱和与长度变化分开，另构造长度均为十二的文档，只改变其中查询词出现次数，其余位置用非查询词填满；平均长度也固定十二。取 $`k_1=1.2`$，将共同 IDF 提出后，贡献因子为

$$
g(f)=\frac{2.2f}{f+1.2},\qquad
g'(f)=\frac{2.64}{(f+1.2)^2}>0,\qquad
g''(f)=-\frac{5.28}{(f+1.2)^3}<0.
$$

于是频次一、二、十二时的因子分别为一、一点三七五、二；第二次出现仍有收益，却没有获得第二份完整信用。图只画物理上允许的 $`1\le f\le12`$，不在固定十二词的文档里安排无限次出现。若复制查询词同时增长文档长度，长度项也会改变，必须将新长度代回原式，不能照搬固定长度的曲线。

这是独立机制对照，六篇检索库中每词频次都为一，不能用本图的饱和解释后面两检索器的实际第二名差异。还应注意 [Speech and Language Processing 第 11 章](https://web.stanford.edu/~jurafsky/slp3/11.pdf)采用的 BM25 变体与本章 IDF、分子常数并不完全相同；公式参数相同的名称，不保证不同实现分数可以直接比较。

<a id="sec-1-1"></a>
<a id="nlp-3-detail-9"></a>
### 2.4 TF-IDF 和 BM25 不是同一个尺度

TF-IDF 余弦按文档向量范数归一化，BM25 用词频饱和和长度项调整贡献。前者的相似度和后者的得分没有可直接比较的绝对尺度，因此不能用同一个数值阈值判断相关。两者都依赖词面匹配，通常都不能自动把完全没有共同词项的同义表达召回。可以通过人工同义改写对照检查这个限制，而不是从名称猜测语义能力。

若将两个检索器融合，应使用验证查询选择可部署策略，或者采用明确的排名融合。分数线性相加之前要处理尺度和分布，不应随意给两个原始分数相同权重。倒数排名融合可以避免部分尺度问题，但它仍引入候选深度、平滑常数和系统权重，仍需报告完整规则与候选预算。

<a id="nlp-3-detail-10"></a>
### 2.5 检索指标需要完整候选与相关性定义

Recall@k 的分母是该查询在评价库中的相关文档数，MRR 关注第一篇相关文档的位置，nDCG 可以使用分级相关性并对靠前结果给予更大折扣。没有相关文档的查询如何处理、未标注文档是否当成不相关、相关性是否穷尽，都会影响含义。特别是采用不完整标注池时，未标注不等于确认无关，应在报告中明确评估限制。

在人工小库里可以完整列出相关集合，从而验证指标实现。真实库通常无法穷尽，因此需要设计标注池和抽样审查。若新系统找到了旧池之外的真正相关文档，它可能被不完整评价低估。相反，只在某个模型召回池里标注，也可能偏向那个模型；比较应使用尽量覆盖各方法的候选与统一裁决。

<a id="nlp-3-detail-11"></a>
### 2.6 实验一：两个检索器与指标完整闭环

```python
import math
from collections import Counter
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer

corpus = ["退款 申请 订单", "物流 查询 包裹", "退款 流程 说明",
          "账户 密码 重置", "包裹 延迟 物流", "订单 发票 申请"]
queries = ["退款 申请", "物流 包裹", "密码 重置"]
relevant = [{0, 2}, {1, 4}, {3}]
tokens = [text.split() for text in corpus]
counts = [Counter(row) for row in tokens]
lengths = np.array([len(row) for row in tokens], dtype=float)
df = Counter(word for row in tokens for word in set(row))
avgdl, n = lengths.mean(), len(corpus)

def bm25(query, k1=1.2, b=0.75):
    result = []
    for tf, length in zip(counts, lengths):
        score = 0.0
        for word in set(query.split()):
            frequency = tf[word]
            if frequency:
                idf = math.log(1 + (n-df[word]+0.5)/(df[word]+0.5))
                score += idf * frequency*(k1+1)/(frequency+k1*(1-b+b*length/avgdl))
        result.append(score)
    return np.array(result)

def ranking(scores):
    return sorted(range(len(scores)), key=lambda i: (-scores[i], i))

def evaluate(order, gold, k=2):
    hits = sum(i in gold for i in order[:k])
    rr = next((1/rank for rank, i in enumerate(order, 1) if i in gold), 0.0)
    dcg = sum((i in gold)/math.log2(rank+1) for rank, i in enumerate(order[:k], 1))
    ideal = sum(1/math.log2(rank+1) for rank in range(1, min(k, len(gold))+1))
    return {"recall": hits/len(gold), "mrr": rr, "ndcg": dcg/ideal}

vectorizer = TfidfVectorizer(tokenizer=str.split, token_pattern=None, lowercase=False)
doc_matrix = vectorizer.fit_transform(corpus)
query_matrix = vectorizer.transform(queries)
cosines = (query_matrix @ doc_matrix.T).toarray()
for i, (query, gold) in enumerate(zip(queries, relevant)):
    for name, score in [("tfidf", cosines[i]), ("bm25", bm25(query))]:
        order = ranking(score)
        metrics = evaluate(order, gold)
        assert set(order) == set(range(n)) and len(order) == n
        assert all(0 <= value <= 1 for value in metrics.values())
        assert order[0] in gold
        print(i, name, order[:2], metrics)
assert ranking(bm25("未出现词")) == list(range(n))
assert np.isclose(math.log(1+(3-1+0.5)/(1+0.5)), math.log(8/3))
assert evaluate([2, 1, 0], {0}, k=2)["recall"] == 0
assert evaluate([2, 1, 0], {0}, k=2)["mrr"] == 1/3
```

这里索引完整人工库是任务允许的行为，而没有用查询相关性训练权重。查询和相关集合是人为选择的可解释样本，因此任何高分都不应外推。实验专门保留未知词平局和第三名首次相关的边界断言，防止把排序显示与指标公式写错。若要进行参数选择，需要另设验证查询，再冻结参数评价独立查询。

### 图解：同一查询的两套得分与第二名竞争

![原六文档查询退款申请的TFIDF余弦BM25得分及前二候选](images/03-retrieval-scores.svg)

图中查询是实验一的“退款 申请”，文档按原编号零到五排列，相关集合在评价前固定为 $`\{0,2\}`$。两个面板各自标出完整六篇文档的分数，零分文档也保留在排序范围中。横轴分别是余弦相似度与 BM25 得分，因此应比较各面板内部的顺序，不能把右侧较大的数值直接解释成更强相关证据。

**先解释右图的同分。** 六篇文档分析后长度都是三，等于平均长度；查询词在匹配文档中的词频都为一，所以 BM25 的词频长度因子恰好为一。“退款”和“申请”的文档频率也都为二，因此每个匹配词贡献

$$
\log\left(1+\frac{6-2+0.5}{2+0.5}\right)=\log2.8.
$$

文档零匹配两词，得分为 $`2\log2.8\approx2.059239`$；文档二只匹配“退款”，文档五只匹配“申请”，两者均为 $`\log2.8\approx1.029619`$。程序固定按文档编号打破平局，二小于五，因此第二名是二。这个排序没有证明 BM25 知道“流程说明”比“发票申请”更符合人工相关性规范。

**再解释左图的严格大小。** 默认平滑 IDF 为 $`1+\log\frac{N+1}{df+1}`$。记出现于两篇文档的词权为 $`a=1+\log\frac73`$，只出现一次的词权为 $`b=1+\log\frac72`$，其中 $`b>a`$。查询的两个坐标都为 $`a`$。文档二含一项 $`a`$ 和两项 $`b`$，文档五含两项 $`a`$ 和一项 $`b`$，所以各自归一化后的余弦为

$$
s_2=\frac{a}{\sqrt2\sqrt{a^2+2b^2}}\approx0.354694,
\qquad
s_5=\frac{a}{\sqrt2\sqrt{2a^2+b^2}}\approx0.378660.
$$

虽然两篇文档都只匹配一个查询词，文档全向量的范数不同，因而文档五严格排在二之前。平滑与归一化定义见 [scikit-learn 1.8 TfidfTransformer 官方说明](https://scikit-learn.org/1.8/modules/generated/sklearn.feature_extraction.text.TfidfTransformer.html)。

图下前二候选使 Recall@2 分别为二分之一与一，而两者第一名都相关，倒数排名同为一。这不是任何方法的普遍优劣结论；它把公式、平局规则、相关集合与候选深度逐项连起来。若改变文档标识，右侧同分的次序可能变化；若改动文档中的其他词项，左侧范数也可能变化。解释差异时，应先检查这些实际原因。

## 3. 文本分类：从来源划分到无泄漏选择

<a id="nlp-3-detail-13"></a>
### 3.1 人工生成过程和目标总体

分类例子使用十二个人工来源组，每组包含积极与消极词汇，并以固定空格分词。来源标记在每组内部不决定类别，因此模型不应靠来源编号完成分类。目标是检验一个完整词袋分类管线能否在未参与训练的来源组上运行，而不是证明它能够处理真实语言中的讽刺、复合否定或跨行业迁移。

预先保留三个来源作为最终测试，其余九个来源用于分组交叉验证选择词项范围和正则强度。每个来源的所有样本始终在同一侧，避免同来源信息跨折传播。这里来源只是人工分组单位，不代表真实数据一定需要来源划分；如果真实目标是新用户、新模板或未来时间，应把相应身份和顺序纳入设计。

<a id="nlp-3-detail-14"></a>
### 3.2 Pipeline 为什么必须包住词表

TF-IDF 词表和 IDF 依赖拟合文档。如果先在全部开发文档上拟合表示，再对变换矩阵交叉验证分类器，验证折已经参与特征统计。正确方式是将向量器与分类器共同放入管线，让每个训练折独立拟合全部状态。参数搜索调用这个完整估计器，验证折只经过 transform 和 predict，不参与 fit。

分组交叉验证还需要把组身份传到切分器，而不是误当成普通模型特征。组数必须足以支持所选折数，每折还应检查标签覆盖。某些真实来源只含单一类别时，简单分组可能造成某折无法训练；这不是让组拆开的充分理由，而是需要更合适的分组策略、数据收集或明确任务局限。

<a id="nlp-3-detail-15"></a>
### 3.3 正则化、特征范围和选择预算

线性逻辑回归的正则参数控制拟合数据与参数规模之间的折中，加入二元组则改变特征空间。两者应联合选择，因为更大的词表可能需要不同强度的正则化。候选集合应预先声明，搜索预算也属于比较条件。尝试几十种词表只展示最好的一种，与只试一种简单基线并不是相同的选择机会。

选择结束后，在全部开发来源上重拟合最优管线，再一次性预测保留来源。最终测试结果不用于修改参数、补词或挑选阈值。如果模型失败，应记录并提出新的研究版本；若继续根据这批测试调整，就应把它降格为探索数据，另找独立确认，而不是在报告里假装它始终未被触碰。

<a id="nlp-3-detail-16"></a>
### 3.4 实验二：分组搜索和词表边界断言

```python
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.model_selection import GridSearchCV, GroupKFold
from sklearn.metrics import accuracy_score, f1_score, confusion_matrix
from threadpoolctl import threadpool_limits

texts, labels, groups = [], [], []
positive = ["满意", "方便", "支持", "可靠"]
negative = ["失望", "困难", "拒绝", "故障"]
for group in range(12):
    for label, words in [(1, positive), (0, negative)]:
        for word in words:
            texts.append(f"来源{group} 服务 {word} 说明")
            labels.append(label)
            groups.append(group)
texts, labels, groups = np.array(texts), np.array(labels), np.array(groups)
train, test = groups < 9, groups >= 9
assert not set(groups[train]) & set(groups[test])
splitter = GroupKFold(n_splits=3)
for a, b in splitter.split(texts[train], labels[train], groups[train]):
    assert not set(groups[train][a]) & set(groups[train][b])
    assert len(set(labels[train][a])) == 2
pipe = Pipeline([("tfidf", TfidfVectorizer(tokenizer=str.split, token_pattern=None,
                                         lowercase=False)),
                 ("clf", LogisticRegression(solver="liblinear", random_state=0))])
search = GridSearchCV(pipe, {"tfidf__ngram_range": [(1, 1), (1, 2)],
                           "clf__C": [0.1, 1.0]},
                      scoring="f1_macro", cv=splitter, n_jobs=1, refit=True)
with threadpool_limits(limits=1):
    search.fit(texts[train], labels[train], groups=groups[train])
    prediction = search.predict(texts[test])
model = search.best_estimator_
vocabulary = model.named_steps["tfidf"].vocabulary_
assert "来源9" not in vocabulary and "来源11" not in vocabulary
assert "来源0" in vocabulary
old_idf = model.named_steps["tfidf"].idf_.copy()
model.predict(["来源999 服务 满意 说明"])
np.testing.assert_array_equal(model.named_steps["tfidf"].idf_, old_idf)
assert prediction.shape == labels[test].shape
assert set(prediction) <= {0, 1}
print("开发选择", search.best_params_, "开发分组CV", search.best_score_)
print("人工保留来源", "accuracy", accuracy_score(labels[test], prediction),
      "macro_f1", f1_score(labels[test], prediction, average="macro"))
print("混淆矩阵", confusion_matrix(labels[test], prediction, labels=[0, 1]).tolist())
```

实验没有断言测试必须高分，而是把协议和输出合法性作为必要条件。由于正负词汇在各来源共享，这个任务故意很简单，模型可能轻易达到满分。这样的结果只说明保留来源的人工词项关联可用，不能验证未见情绪表达、复杂组合或真实来源漂移。应将实际打印结果与数据生成规则一起阅读。

### 图解：从每折拟合边界到最终来源隔离

![实际十二来源的三折分组交叉验证及最终重拟合和保留预测](images/03-grouped-fit-boundary.svg)

图中每一列是一个完整来源，每列四个圆点和四个方点对应代码的四篇积极、四篇消极文档。蓝色表示该行参与整条管线的 fit，橙色只经过已拟合管线的 transform 与 predict，浅灰叉号表示暂不参与。颜色表达操作角色，形状表达样本标签，因此两种信息没有混在同一编码里。

前三行是当前程序环境实际得到的三折：验证来源分别为 $`\{2,5,8\}`$、$`\{1,4,7\}`$、$`\{0,3,6\}`$。每折训练六个来源、四十八篇，验证三个来源、二十四篇；一个来源的八篇文档没有被拆开。右侧九到十一在整个搜索期间都隔离。具体组号的分配次序不是应永久依赖的接口保证；应以 [GroupKFold 的组不重叠规则](https://scikit-learn.org/1.8/modules/generated/sklearn.model_selection.GroupKFold.html)和程序实际输出为准。

**词表在什么地方产生？** 以第一折为例，向量器只接触来源零、一、三、四、六、七，所以“来源2”“来源5”“来源8”这些人工哨兵词不应进入该折词表。验证时，即使输入包含它们，也不会重新估计 IDF。这里的 `groups` 数组用于切分；文本中另有人工“来源编号”字符串，方便检查词表边界，它们在每组内不决定正负标签。两种用途不能因为编号相同就混为一谈。

第四行是完成选择后的新拟合，而不是继续使用某一折的分类器。`refit=True` 用全部九个开发来源重建最优管线的词表、IDF 和分类参数，再对保留三个来源预测。四个超参数候选各经过三折，共十二次候选拟合，随后还包含一次全开发集重拟合；这些成本没有因为图中只画划分而消失。

如果先在全部开发文档上拟合一次 TF-IDF，再沿前三行只交叉验证分类器，第一折的表示状态就已经见到橙色来源，破坏了图中承诺的边界。最终在九组上重拟合则是明确允许的第四行操作，二者所处的评价阶段不同。保留测试结果仍只用于确认冻结后的完整程序，不用于在图中再挑一次词表或参数。

## 4. 序列标注：特征、CRF 训练与跨度评价

<a id="nlp-3-detail-18"></a>
### 4.1 从字符样本构造局部特征

为了让每个步骤透明，本节不下载预训练编码器，而是为每个字符构造当前字符、左右邻居以及序列边界特征。特征字典只在训练序列上建立，测试中的未知特征被忽略。线性映射产生每个位置的标签发射分数，再与可学习转移组成严格约束的链式 CRF。这个系统可以完整训练和解码，却显然不能拥有外部语料提供的语言知识。

标签集合为 O、B-PER、I-PER、B-LOC、I-LOC。开始位置不允许 I，I 只能跟在相同类型的 B 或 I 后。约束只表达编码合法性，不保证实体是真实人物或地点；模型仍可能合法地把普通词标成人名。训练和解码使用相同约束空间，避免只在输出时修复非法路径造成目标不一致。

<a id="visual-local-nlp-03"></a>

### 图解：实体跨度与 token 标签对齐

![原CRF程序的发射分数、Viterbi路径与半开实体跨度](images/03-concept.svg)

本章 CRF 的一个 token 就是一个字符。图中沿用原程序的测试文本“赵六在南京工作”，标签集合也沿用 PER、LOC，没有额外引入组织类型。八条边界线把七个字符分开，所以人名为 $`(0,2,\mathrm{PER})`$，地点为 $`(3,5,\mathrm{LOC})`$，偏移采用左闭右开的字符位置。这里的偏移是本例 Python 字符串的字符索引，不是 UTF-8 字节数，也不是另一个子词分词器的 token 编号。

矩阵逐格显示第 4.3 节原程序训练一百步后、测试句对应的 $`XW`$ 发射分数；每列一个字符，每行一个标签，蓝色实线连出 Viterbi 最终路径。这些是可正可负的局部分数，不是归一化概率。最左列独立最高分为 I-PER 的 1.106，但 BIO 起始约束将其排除；在剩余标签中 B-LOC 的约 0.055 还略高于 B-PER 的约 0.052，图中四舍五入为两位时看起来相同。最终选 B-PER 仍不能只靠这一列解释：其后接 I-PER 的转移分约 1.084，加上“六”的 I-PER 发射分约 2.073，再与整条后续路径共同竞争。Viterbi 的目标是整序列总分最大，不是逐列最大后再修复非法标签。

“赵”的 current=赵 与 right=六 都没有训练词表列，实际仅保留 bias、left=<BOS> 两项特征；这解释了模型没有见过该字仍可获得非零分数。未知词项被忽略不会使整个输入位置消失，也不等于模型已经学会所有未见人名。分数与路径可按本章原程序直接重算；它们只说明这个极小人工训练集的行为。线性链 CRF 怎样由局部特征组成全局分数、为何仍能用动态规划求最优路径，可对照 [Jurafsky 与 Martin 第 18 章第 18.5 节](https://web.stanford.edu/~jurafsky/slp3/18.pdf)。

蓝线与原标注一致；图底部保留有意构造的边界对照，只把“京”的 I-LOC 改为 O，其余六处不变。这个路径仍符合 BIO 约束，却把地点缩成“南”，于是预测跨度为 $`(3,4,\mathrm{LOC})`$。标注是否合法与实体是否完整正确，由此可以分开检查。

字符正确率为 $`\tfrac67`$，但严格实体只匹配完整人名，得到 TP 一、FP 一、FN 一：

$$
F_1=\frac{2TP}{2TP+FP+FN}
=\frac{2}{2+1+1}=\frac12.
$$

“南”不是半个正确实体：在本章精确跨度评价里，它是一个多出的错误预测，而完整“南京”仍然漏检。若改用部分重叠给分，需要另写匹配协议，不能把字符准确率直接当实体分数。跨多句汇总时还必须保留程序中的样本编号，否则两句话恰好拥有相同起止位置与类型，会被集合操作错误合并。

<a id="nlp-3-detail-19"></a>
### 4.2 损失、更新和解码的闭环

每条训练序列的损失是配分函数减去金标准路径分数，取序列平均以后反向传播。模型参数包括特征到标签的权重和标签转移矩阵，优化器必须同时接收二者。训练后使用 Viterbi 解码，在已校验合法的标签路径上恢复实体集合，比较每条序列中起点、终点和类型。跨序列的同一跨度不能混淆，因此实体集合加入序列编号。

本节使用短小的多个训练句和两个新组合句，目的是验证参数更新、结构和评价接口。测试包含未见字符，词项记忆很可能失效，这是应该展示的局限。不能为了让代码输出满分而在测试后把新名字加入训练词表。若希望研究未见实体泛化，应专门建立实体不重叠或上下文不重叠的划分，并增加合理的字形、上下文或预训练信息。

<a id="nlp-3-detail-20"></a>
### 4.3 实验三：完整的 CPU 线性链 CRF

```python
import numpy as np
import torch
from sklearn.feature_extraction import DictVectorizer

torch.set_num_threads(1)
torch.manual_seed(7)
train = [("张三在北京工作", [1, 2, 0, 3, 4, 0, 0]),
         ("李四在上海工作", [1, 2, 0, 3, 4, 0, 0]),
         ("王五去北京学习", [1, 2, 0, 3, 4, 0, 0]),
         ("北京欢迎张三", [3, 4, 0, 0, 1, 2]),
         ("上海欢迎李四", [3, 4, 0, 0, 1, 2])]
test = [("赵六在南京工作", [1, 2, 0, 3, 4, 0, 0]),
        ("北京欢迎王五", [3, 4, 0, 0, 1, 2])]

def features(text):
    return [{"bias": 1.0, "current="+c: 1.0,
             "left="+(text[i-1] if i else "<BOS>"): 1.0,
             "right="+(text[i+1] if i+1 < len(text) else "<EOS>"): 1.0}
            for i, c in enumerate(text)]

vectorizer = DictVectorizer(sparse=False)
vectorizer.fit([f for text, _ in train for f in features(text)])
assert "current=赵" not in vectorizer.vocabulary_
encode = lambda text: torch.tensor(vectorizer.transform(features(text)), dtype=torch.float64)
encoded = [(encode(text), torch.tensor(tags)) for text, tags in train]
w = torch.nn.Parameter(torch.zeros(len(vectorizer.vocabulary_), 5, dtype=torch.float64))
a = torch.nn.Parameter(torch.zeros(5, 5, dtype=torch.float64))
legal = torch.ones(5, 5, dtype=torch.bool)
legal[:, 2] = False
legal[1, 2] = legal[2, 2] = True
legal[:, 4] = False
legal[3, 4] = legal[4, 4] = True
start = torch.tensor([0., 0., -torch.inf, 0., -torch.inf], dtype=torch.float64)

def nll(x, y):
    emission, transition = x @ w, a.masked_fill(~legal, -torch.inf)
    alpha = start + emission[0]
    gold = start[y[0]] + emission[0, y[0]]
    for t in range(1, len(y)):
        alpha = emission[t] + torch.logsumexp(alpha[:, None]+transition, dim=0)
        gold = gold + transition[y[t-1], y[t]] + emission[t, y[t]]
    return torch.logsumexp(alpha, 0) - gold

optimizer = torch.optim.Adam([w, a], lr=0.07)
initial = float(torch.stack([nll(x, y) for x, y in encoded]).mean().detach())
for _ in range(100):
    optimizer.zero_grad()
    loss = torch.stack([nll(x, y) for x, y in encoded]).mean()
    loss.backward()
    assert torch.isfinite(w.grad).all() and torch.isfinite(a.grad).all()
    optimizer.step()
final = float(torch.stack([nll(x, y) for x, y in encoded]).mean().detach())
assert final < initial and np.isfinite(final)

@torch.no_grad()
def decode(text):
    emission, transition = encode(text) @ w, a.masked_fill(~legal, -torch.inf)
    delta, pointers = start+emission[0], []
    for t in range(1, len(text)):
        best, pointer = (delta[:, None]+transition).max(0)
        pointers.append(pointer)
        delta = best+emission[t]
    result = [int(delta.argmax())]
    for pointer in reversed(pointers):
        result.append(int(pointer[result[-1]]))
    result.reverse()
    assert result[0] not in (2, 4)
    assert all(legal[i, j] for i, j in zip(result, result[1:]))
    return result

def spans(tags):
    result, begin, typ = set(), None, None
    for i, k in enumerate(list(tags)+[0]):
        continuation = (k == 2 and typ == "PER") or (k == 4 and typ == "LOC")
        if begin is not None and not continuation:
            result.add((begin, i, typ))
            begin, typ = None, None
        if k in (1, 3):
            begin, typ = i, "PER" if k == 1 else "LOC"
    return result

gold, predicted = set(), set()
for sample_id, (text, target) in enumerate(test):
    output = decode(text)
    gold |= {(sample_id,)+item for item in spans(target)}
    predicted |= {(sample_id,)+item for item in spans(output)}
    print(text, output)
tp = len(gold & predicted)
f1 = 2*tp/(len(gold)+len(predicted)) if gold or predicted else 0.0
assert 0 <= f1 <= 1
assert spans([1, 1]) == {(0, 1, "PER"), (1, 2, "PER")}
print("人工CRF训练NLL", initial, "->", final, "严格实体F1", f1,
      "TP/预测/金标准", tp, len(predicted), len(gold))
```

`spans` 负责从既定 BIO 路径提取跨度，函数自身没有拒绝所有非法 I 标签；本例由 `decode` 中的起点与转移断言保证预测路径合法，金标准也按规范预先给定。若从外部读取任意标签序列，应先显式验证合法性，再执行这一步，不能把提取函数当作通用严格校验器。

模型没有结束转移参数，相当于所有结束分数固定为零，这是显式的简化定义。所有序列非空且无填充，因此程序不演示批量掩码；移植到批量实现时必须补充长度与结束位置处理。上章已经用枚举核对核心动态规划，本章则检查完整参数学习与实体评价，两个实验层次相互补充而不互相替代。

<a id="nlp-3-detail-21"></a>
### 4.4 如何解释训练下降与未见字符结果

训练负对数似然下降说明模型更偏好训练标注路径，不保证测试实体正确。未见字符的当前字特征无法激活，但邻居、边界和转移仍可能提供部分证据；因此它既不必完全失败，也不应被认为天然泛化。应逐条看输出，判断模型是在识别上下文角色、记忆名字位置，还是只学到句子模板。

人工例子的结构比较固定，位置模式本身可能是很强的线索。要进一步研究，应生成不同长度名字、多种句法位置、无实体句、相邻实体和同字不同角色，并按实体字符串或模板分组。每增加一种条件，都需要明确它是在训练中覆盖还是只在最终测试中挑战，避免用不断补测试的方式把确认集变成开发集。

<a id="nlp-3-detail-22"></a>
## 5. 从流程正确到公平的方法比较

<a id="nlp-3-detail-23"></a>
### 5.1 比较单位和资源表

检索比较的单位是查询，分类比较的单位可以是文档或来源，实体比较的主要单位是跨度但不确定性常以文档或来源抽样。应为每个系统列出外部数据、特征拟合、训练轮数、候选数量、最大长度、参数搜索次数和推理成本。系统结构可以不同，但必须明确比较的是完整方案还是某个受控因素。

例如将 BM25 与一个外部预训练向量检索器比较，可以回答给定资源下哪套方案更适合，却不能仅凭结果推断稠密表示结构单独造成提升。将独立 softmax 与 CRF 比较时，如果同时更换编码器和标签规范，同样无法识别结构层的贡献。严谨比较不要求刻意削弱某个模型，而是要求结论与控制条件一致。

<a id="nlp-3-detail-24"></a>
### 5.2 固定基线与逐步消融

检索可以先用原始词项匹配，再加 IDF、长度归一化和词频饱和；分类可以先用 unigram，再加二元组、字符片段和正则选择；标注可以先独立分类，再加合法性约束和可学习转移。每一步都应保留相同数据和评价，观察改善发生在哪类错误。多个因素同时改变时，应诚实报告组合效果，不要强行给每个技巧分配功劳。

消融还应包括合理的重新训练。删掉某类特征后不重训，观察的是固定模型依赖；删掉后重新拟合，观察的是学习流程在缺少该信息时能否用其他特征补偿。两者都重要，但问题不同。在文本里，重复词、相关短语和来源标记常可互相替代，因此某个特征置换后影响小，并不能证明那类信息完全无用。

<a id="nlp-3-detail-25"></a>
### 5.3 配对统计、种子和选择偏差

同一批查询或文档上比较两个系统，应该保存逐样本输出并进行配对分析。检索宏平均指标可以在查询级重采样；微平均实体 F1 则需要每次重新汇总实体计数。来源相关时以来源组抽样，优化随机性则通过重复训练观察。一个固定模型的测试重采样区间，不包含重新调参和重新训练的全部不确定性。

当搜索很多参数以后，最好的验证成绩会有选择乐观性。最终确认集的作用是评价冻结后的完整选择结果，而不是再选一次赢家。若多个模型都用同一测试反复展示和修改，测试逐渐承担了开发角色。应在记录中区分探索和确认，保留失败方案与预算，而不是把研究过程压成一个似乎从未试错的成功故事。

<a id="nlp-3-detail-26"></a>
### 5.4 本章实际结果应如何解读

在本章六篇人工文档上，查询“退款 申请”的 TF-IDF 前两名是文档零和五，BM25 前两名是零和二；相关集合预先设为零和二。因此 TF-IDF 的前二召回为二分之一，BM25 为一。不能据此宣布 BM25 普遍胜出，甚至不能把这个差异完全归给长度归一化：所有文档长度相同，而文档二与五的 BM25 词项贡献在此恰好相等，固定标识平局规则使二排在五前。

TF-IDF 的差异来自向量归一化涉及文档全部词项。文档二含有两个只出现一次的词，文档五含有一个只出现一次的词和一个还出现在其他文档中的词，所以共享查询词的相同局部权重被不同范数缩放。这个手工数据能够清晰展示两套公式的几何差异，但不能代表真实查询分布。若改变文档标识或替换一个无关词，局部比较可能改变，应把这种敏感性当作诊断事实。

分类的实际开发分组交叉验证为一，所选配置为单词级 unigram 与较强正则候选，保留来源二十四篇文档的混淆矩阵对角各为十二。它表明共有的积极消极词足以完成这个人工任务。四个参数候选如果在验证上都满分，选择第一个只是搜索的确定性约定，并没有提供证据说明该参数在真实文本里优于其他值。不要把平局选择写成严肃的最优超参数发现。

CRF 在五条人工训练序列上的平均负对数似然从约八点四五下降到约零点零零一六，两个测试句子的四个实体均严格匹配。未见名字仍被识别，主要可能依赖固定的“在”和“欢迎”等上下文及句子位置模式。测试只有两条序列，不足以估计开放实体能力；应使用不同长度、不同位置、无实体和歧义字符重新挑战。这个结果既值得保留，也必须连同其极窄条件报告。

<a id="nlp-3-detail-27"></a>
### 5.5 基于排序的学习目标和采样分布

若后续训练一个重排器，可以将查询与文档配对输入，使用点式相关性预测、正负文档对的排序损失，或整个候选列表上的目标。点式目标关心单个相关标签，成对目标关心相对顺序，列表目标直接利用候选集合结构。它们的训练分布由候选生成和负例采样共同决定，不能只写用了某种交叉熵就认为概率含义固定。

随机负例通常容易，与真实检索前列的混淆文档差异很大；难负例更接近排序挑战，却可能包含未标注的真相关文档。若正标签不完整，把所有难负例都当成错误，模型可能被迫压低合理答案。需要检查标注覆盖、使用多正例或人工裁决，并说明负例是否来自训练查询和允许的库。测试相关性不能进入挖掘和模型选择循环。

一个重排器只能重排候选中已有的文档。若候选召回率很低，即使重排在固定候选上表现理想，端到端上界仍受限制。因此应同时报告候选生成深度和成本，在相同候选或相同总预算下比较，并区分候选内质量与完整库效果。用金标准文档强行加入每个测试候选可以诊断重排能力，但必须明确这是额外证据条件，不能当成实际召回系统的结果。

<a id="visual-mechanism-nlp-03"></a>

### 图解：检索—判别串联后的总误差包含两阶段失败

![一百问题的证据召回遗漏候选内判断及总体正确流量分解](images/03-mechanism.svg)

这是一组用于解释分母的构造计数，不是前面六文档实验的实测成绩。设一百个问题都需要检索到指定证据，系统才有资格算作正确。八十个问题的必要证据进入候选，其中六十个判断正确、二十个判断错误；另外二十个在检索时已遗漏，归入另一条互斥失败支路。所有色带使用同一高度比例，最后三项仍回到全部一百个问题。

定义 $`R`$ 为必要证据到位，$`C`$ 为端到端正确。在这份明确要求检索证据的协议中 $`C\subseteq R`$，因此

$$
P(C)=P(R)P(C\mid R)=0.8\times0.75=0.6,
$$

而总体失败为

$$
P(C^c)=P(R^c)+P(R)P(C^c\mid R)
=0.2+0.8\times0.25=0.4.
$$

这不需要假设阶段独立，因为第二个比例本来就条件于证据已召回的八十个问题。不能把百分之二十与百分之二十五直接相加：后者不是以全体一百为分母。如果第二阶段的百分之七十五来自另一个更容易的独立候选集，也不能直接代入这里，必须在当前召回子集重新评价。

图中的“证据到位比例”是问题级事件，不等于把每个查询的文档 Recall@k 做平均。一个问题需要多段证据时，找到其中一半相关文档，未必已经具备正确判断条件。若系统允许无证据猜测、备用检索或人工回退，应该重新定义事件和成功协议，不能沿用此图的包含关系。阶段指标只有和真实控制结构、共同样本及正确分母连接起来，才能指出该优先补召回还是补候选内判断。

<a id="nlp-3-detail-28"></a>
### 5.6 稀疏索引、稠密检索和近似搜索误差

小库可直接计算查询与全部文档的分数，大库则需要倒排索引或向量索引。倒排索引利用非零词项快速定位候选，向量索引可能使用近似近邻减少遍历成本。这里应区分表示本身是否把相关文档排得靠前，以及索引是否找到了该表示下真正的近邻。近似搜索的漏召回是另一层误差，不应全部归因于编码器语义。

可以在一小部分库上用精确搜索作为参照，比较近似索引返回的邻居覆盖、任务相关性和延迟。索引参数需要在允许的验证查询上选择；查询批量、缓存、硬件和并发也会影响耗时。不能拿一个系统预热后的单查询最短延迟，与另一个包含加载和建库的总耗时比较。资源表应说明测量边界，必要时分别报告建库、冷启动和稳定推理。

库更新还会影响向量版本兼容性。若更换编码器却只重算新文档，旧文档向量与新查询可能不在可直接比较的空间。即使向量维数相同，也不保证坐标语义和范数分布一致。需要统一重建或明确的兼容方案，并用固定参考查询验证排序变化。索引文件能加载只是格式证据，不是检索函数保持一致的证明。

<a id="nlp-3-detail-29"></a>
### 5.7 联合调参与多任务结果的取舍

一个系统可能同时优化分类、抽取和检索，某个表示更新会改善其中一项却损害另一项。不能在每个任务上分别挑最有利的检查点，再把它们写成同一模型的同时能力，除非实际交付确实保存多个组件。应预先定义主要目标、约束和选择规则，必要时展示帕累托关系，让读者看到取舍而非虚构全面最优。

多任务训练的损失系数还会改变各样本和输出单位的权重。按 token 求和的标注目标可能比按文档平均的分类目标大得多，长度分布变化也会改变平衡。可比较每项损失的归约、梯度规模和有效样本数，但不应只让数字尺度相近就宣称权重合理。最终权衡应由任务收益和约束验证，而不是由训练曲线的视觉平滑决定。

<a id="nlp-3-detail-30"></a>
### 5.8 反事实扰动与分布外输入的诊断边界

把一句话中的人名换掉、把否定加入或把数字改变，是检查模型敏感性的有用办法，但扰动必须保持其他条件合理。随机打乱全部字符会制造极不自然文本，模型失效不一定说明真实任务存在同样问题；过度简单的替换又可能保留模板捷径。应分别构造自然最小对照和明显异常输入，前者检验任务语义，后者检验接口与回退。

对照的标签也需要重新判断。将“北京欢迎张三”换成“欢迎北京张三”不只是交换词序，可能使句子语法和实体解释都变得不清楚。不能自动沿用旧标签再把模型变化视为错误。严谨做法是先由任务规范确认变换的预期输出，再冻结对照集，避免为某个模型量身设计有利或不利的扰动。

<a id="nlp-3-detail-31"></a>
## 6. 错误分析与下一步研究

<a id="nlp-3-detail-32"></a>
### 6.1 检索：词面缺口、排序与标注覆盖

当相关文档没有进入候选，应先检查分析器是否把查询和文档映到不同单位，再看词汇不匹配、过滤、库缺失和标注遗漏。若候选存在但排得太低，才主要是排序问题。把召回和重排混在一个数字里，会难以定位瓶颈。可以分别报告候选召回、重排质量和最终结果，并对固定候选上的上界做诊断。

查询扩展、同义词和稠密表示可能缓解词面缺口，但也会引入歧义和错误召回。例如“苹果”可能是水果或公司，扩展越多并不越好。应按意图、稀有词、实体和长度切片，观察改善是否来自真正语义匹配。对标注池之外的候选还应抽样复核，避免把未标注文档全部当成错误结果。

<a id="nlp-3-detail-33"></a>
### 6.2 分类：否定、来源和不确定输出

人工词表例子的每个情绪词与标签直接对应，真实文本中同一词可能出现在引用、否定和反讽中。应构造只改变否定范围、主客体或事实条件的最小对照，检查模型是否真正利用组合关系。来源标记即使在训练内不决定标签，也可能与某些子群体相关，需要在更丰富的数据中检查捷径和漂移。

若某类输入全未知或明显超出训练范围，可以设计拒答与人工复核，但需要同时报告自动覆盖率和被接受样本的错误。只保留最容易的少数样本自然可能得到很高准确率，不能拿这个数与全覆盖系统直接比较。阈值、拒答和校准都要在允许的选择数据上完成，最终测试只确认冻结策略。

<a id="nlp-3-detail-34"></a>
### 6.3 标注：边界、类型和复杂结构

实体错误可以拆成漏检、误报、边界偏移、类型错误和重复输出，分别对应不同修复方向。某些问题来自原始标注规范而非模型：机构简称与全称是否同类、嵌套机构是否都标注、地点作组织代称如何处理，都需要一致规则。若规范本身不稳定，增加模型容量只会更复杂地拟合分歧。

普通 BIO 线性链不能表达所有重叠和不连续实体。真实任务若需要这些结构，应改用合适输出空间，而不是在评价前丢掉难表示的金标准。新的输出方案又需要重新定义候选范围、约束、损失和匹配规则。实践的合理终点不是把一段代码跑通，而是让任务、表示和评价真正兼容。

<a id="nlp-3-detail-35"></a>
### 6.4 数据学习曲线与覆盖诊断

当模型表现停滞时，可以固定确认协议，在开发数据内部绘制按训练文档、来源或实体覆盖增长的学习曲线。每个规模应重复合理抽样，并保证同一来源不被拆散。若只随机减少 token，剩下的样本可能仍包含全部模板和实体，曲线看起来很快饱和，却没有真正减少独立信息。学习曲线的横轴必须对应研究关心的监督量。

训练误差低而验证误差高，可能提示过拟合或分布差异；两者都高，可能提示表示不足、优化失败或标签噪声。这个经典诊断不是自动因果结论，还需要检查损失实现、数据权限和任务可达性。比如截断导致答案根本不可见时，增加训练数据未必解决；标签规范矛盾时，单纯延长训练也可能只会记住噪声。

对实体识别，还可以按训练中是否见过实体字符串、是否见过其字符、上下文模板是否相同做交叉切片。三种新颖性并不等价：未见完整名字可能由熟悉字符组成，未见字符又可能出现在熟悉句型里。报告应保留这种结构，而不是把所有情况压成一个未知实体准确率。检索也可按查询词是否出现在库、相关文档是否含同义改写等条件切片。

<a id="nlp-3-detail-36"></a>
### 6.5 主动标注与错误采样的选择效应

根据当前模型不确定性挑选样本进行标注，可能提高有限标注预算的利用率，但这些样本不再是部署分布的简单随机样本。用它们训练是合理的主动学习设计，用它们直接估计总体准确率则可能产生偏差。应保留独立代表性评价样本，并记录主动选择策略、批次和人工成本，避免把困难样本上的变化误读为整个流量的变化。

模型最不确定的样本也未必最有价值。它们可能是噪声、超出规范或重复边界，继续标注不能提高任务可解性。可以结合多样性、来源覆盖和规范复核选择样本，比较每单位人工成本的实际收益。若人工知道模型预测，可能受锚定影响，因此用于评估的数据尽量采用盲标或独立复核，不能把人机协作改标签的结果当成完全独立金标准。

<a id="nlp-3-detail-37"></a>
### 6.6 时间与反馈回路中的标签延迟

真实系统的标签可能在请求发生后很久才确定，例如退款最终是否完成、实体是否被人工确认。按请求时间划分时，需要同时检查标签在训练时是否已经可得。把未来才确认的状态回填到早期训练特征，会制造时间泄漏；把尚未确认的样本当成负类，又会引入延迟偏差。应记录事件时间、可用时间和标签成熟条件。

部署后模型还可能影响数据：自动回复改变用户后续表达，推荐文档改变点击，人工只复核某些高分样本。反馈不是原始总体的无偏标签。点击可以受位置和界面影响，未点击不等于无关；未复核也不等于正确。研究更新方案时，应先画清数据产生过程，再决定如何抽样审查、如何使用反馈，避免把系统自己的选择结果不断强化成事实。

## 7. 从实验记录到可交付结果

<a id="nlp-3-detail-39"></a>
### 7.1 保存完整函数和数据身份

交付应包含规范化、分词、词表、IDF、分类器参数、标签映射、CRF 转移约束和评价约定。检索还要记录库文档版本、标识和索引统计；标注要保存偏移单位和跨度格式。只有权重文件而缺少这些状态，无法保证恢复同一个输入输出函数。版本名相同也不能替代内容和配置校验。

本章只在内存中构造系统，不留下模型和脚本。如果扩展为真实交付，应在受控位置保存必要的最终状态与说明，并使用临时目录检查独立进程加载，结束后自动清除测试产物。不要为了保持目录整洁删除唯一的最终模型，也不要把可重建的缓存误当成用户必须保存的学习资料；清理应该基于依赖和用途，而不是文件扩展名。

<a id="nlp-3-detail-40"></a>
### 7.2 可读报告和可复核结果

一份报告至少展示数据来源、生成或采样规则、划分计数、特征与目标、搜索预算、冻结参数、评价定义、实际结果及局限。人工实验要醒目标明人工，不能使用含糊措辞暗示真实客户或行业数据。失败案例应解释为什么失败，以及哪个后续实验能区分替代机制，而不只是列出一串模型升级建议。

本章三个代码块的输出是读者可以在本机重新获得的机制证据。不同库版本和优化器细节可能使小数末位不同，因此必要断言围绕协议、合法性、有限数值和明确公式，而不强求一个无业务意义的末位数值。若需要严格复现，应记录环境、种子和全部参数，同时承认随机优化和平台差异的边界。

<a id="nlp-3-detail-41"></a>
## 8. 进阶：联合系统、检索增强与任务迁移

<a id="sec-6-1"></a>
<a id="nlp-3-detail-42"></a>
### 8.1 检索结果不是生成事实的自动保证

将检索接到生成前，可以给模型提供外部证据，但模型仍可能忽略、误解或混合证据。应分别评价相关材料是否被召回、所需事实是否出现在上下文、生成主张是否受证据支持，以及最终答案是否覆盖问题。相关文档命中率高不意味着所有主张都有来源，引用格式正确也不意味着引用段落真的支持结论。

检索库可能含有冲突、过时和重复信息。排序仅依据词面或向量相似度，不会自动确认来源真实性和时效性。任务需要时间一致性时，应把文档时间、版本和有效范围纳入证据解释，并为无法确定的情况保留拒答。评价时也要区分模型事实错误与库中根本缺少答案，否则无法判断改进应该发生在哪一层。

<a id="nlp-3-detail-43"></a>
### 8.2 任务迁移需要重新审查标签与权限

从分类迁移到检索，类别相同并不必然表示文档互相相关；从检索迁移到生成，能找到主题资料也不代表能回答精确问题。共享编码器可以节约资源，但目标函数和评价单位仍需要重新定义。一个在主题分类上很强的表示，可能把事实相反却主题一致的文本放得很近，导致事实检索失败。

迁移到新语言或新领域时，词表长度、未知比例、实体类型和标注规范都可能改变。应先检查输入可达性和任务兼容性，再决定微调或重新训练。直接沿用旧阈值和类别先验可能失效，使用新领域未标注数据又属于额外权限，需要在协议中说明。迁移不是把路径换成新目录就完成的操作。

<a id="nlp-3-detail-44"></a>
### 8.3 从完整函数到接口不变量

把文本系统视为从结构化请求到结构化响应的函数，可以写出比单纯高分更稳定的接口约束。批量预测的第一个结果应与单独预测同一请求一致，除非明确采用跨请求交互；改变请求顺序再还原标识，结果不应跟着错位；增加无关的日志字段，不应改变模型输入。对词袋分类，字典列名和词项编号必须稳定；对实体输出，跨度应始终落在所声明的原文坐标范围内。

某些直觉上的不变量却不成立，必须根据模型定义判断。复制文档会改变原始词频，归一化后的方向是否保持取决于分析器和 n-gram；加入空白可能改变中文分词；在序列前添加一句话可能改变上下文表示和后续位置。测试不应强迫模型满足未经任务认可的性质，而应区分协议保证、模型性质和业务期待。发现差异时，先定位是哪一层产生，再判断是否错误。

检索还需要测试标识重排：只改变存储顺序，不改变文档标识与内容时，非平局的排名应保持相同。平局则必须按预先规定的稳定规则处理。本章用数组索引作为人工标识，若实际数据库重新编号，平局结果可能随之变化。交付时最好采用稳定业务标识，并记录库更新和删除策略，避免把无语义的顺序变化误报为相关性改进。

<a id="nlp-3-detail-45"></a>
### 8.4 对结果差异做分解而不是编造解释

若新方案比基线高出若干分，应回到同一批预测，统计双方都对、都错、新方案独对和基线独对的样本。只看净差会隐藏大量相互抵消的变化。再按预先定义的来源、长度、词汇新颖性和实体类型分层，观察改善是否集中在与方法假设一致的区域。切片数量很多时，也要警惕偶然显著，探索发现需要独立确认。

错误解释必须有证据。看到 CRF 在未见名字上正确，并不能直接声称它学到了人物概念；可能只需要识别句首两个字。可以把人名移动到不同位置、替换人物与地点的上下文、加入无实体句，比较预测如何变化。看到 BM25 高于 TF-IDF，也不能直接归因于词频饱和；本章实际差异包含平局规则，已经显示这种草率解释为何不可靠。

一个可接受的研究结论可以很有限：在固定人工条件下实现和公式一致，某个对照排除了一个错误假设，但仍无法区分两个替代机制。这样的结论比没有证据的全面语义理解更有价值。报告应将已观察事实、合理推断和待验证猜想用清楚语言分开，让下一位读者知道哪些内容可以直接复核，哪些需要新数据。

<a id="nlp-3-detail-46"></a>
### 8.5 将研究扩展到真实资料的最小步骤

首先确认真实文本的使用权限、来源和任务范围，再建立标注规范及独立划分，保留必要元数据而限制敏感字段进入特征。随后把人工数据替换为代表性训练样本，重新拟合词表、统计量和模型，并保持全部确认数据冻结。不能沿用人工例子的标签映射、阈值和长度设定而不检查它们是否仍然合理。

接着建立简单但有竞争力的基线，记录资源与选择预算，逐步增加假设驱动的改进。真实文本规模大时，先验证数据接口、空样本、对齐和评价器，再投入更多计算。若基础错误尚未排除，训练更大模型只会让排查更昂贵。最后在真正未参与选择的数据上确认，并同时报告整体指标、关键错误、资源与适用范围，让结果能够支持具体使用决策。

还应保留版本之间的变化记录，说明新增数据是否改变来源覆盖和标签规范，旧测试是否已经参与开发，以及哪些结果需要重新确认。学习资料中的小程序可以成为排查接口的起点，但真实验收必须回到实际目标总体，不能让一个容易复现的人工满分替代独立证据。

## 9. 练习与详细参考答案

<a id="nlp-3-detail-48"></a>
### 9.1 索引完整文档库为什么未必是泄漏

题目：检索器读取了全部库文档，是否一定违反测试独立性？答案：若部署任务允许预先建立固定库索引，库内容就是合法系统输入；保留查询及相关性标签仍应独立。若任务要求未来新文档适应，则需要另设时间或新增库协议。关键是问题定义和信息权限，而不是看见全部两个字就一概判定；报告必须把库、查询和标注的可见范围分开说明。

<a id="nlp-3-detail-49"></a>
### 9.2 BM25 的重复词是否无限加分

题目：文档把查询词重复一万遍，得分会线性增长吗？答案：本章词频因子随频次增加趋于有限上界，长度归一化又可能增加分母，因此不会按原始次数无限线性增长。但这不保证系统完全抗重复或垃圾文档，还需要其他质量与来源措施。应写出实际公式和参数，再分析极限，而不是把 BM25 简化成一个神秘质量分数。

<a id="nlp-3-detail-50"></a>
### 9.3 未知查询所有分数为零该如何排名

题目：没有任何词项匹配，第一名是否最相关？答案：排序只是按固定平局规则返回，缺少相对相关证据。可以提示没有可靠匹配、使用回退或返回空结果，但策略要预先定义并评价。若仍返回若干文档，报告应保留零分和平局比例，避免把机械顺序解释成模型置信度；也不能用最终测试答案临时设计同义扩展。

<a id="nlp-3-detail-51"></a>
### 9.4 Recall@2 与 MRR 会给出同一结论吗

题目：唯一相关文档排第三，Recall@2 和 MRR 各是多少？答案：前者为零，后者为三分之一。它们分别关注给定深度内覆盖和首次相关位置，不能互相替代。若下游只读取前两篇，MRR 的非零值并不表示任务可用；若用户会继续浏览，位置折扣又有实际意义。指标选择要对应使用流程，而不是选择对当前模型最有利的一项。

<a id="nlp-3-detail-52"></a>
### 9.5 为什么词表必须位于交叉验证管线内部

题目：只在开发数据上拟合全词表，再交叉验证分类器，有什么问题？答案：每个验证折已经参与词项和 IDF 的确定，评价不再是完整流程对未见数据的表现。将向量器与分类器放入同一 Pipeline，让每个训练折独立拟合，才能保持边界。最终在全部开发集重拟合是允许步骤，但其结果应交给独立保留测试，而非再次宣称开发交叉验证完全独立。

<a id="nlp-3-detail-53"></a>
### 9.6 来源组没有进入特征为何仍要保存

题目：来源字段不输入模型，保存它有什么用？答案：它用于划分、追踪和组级不确定性，防止同来源依赖被误当成独立样本。标识的管理用途与预测用途不同。若将来源直接输入模型，需要额外说明部署是否可见、未来是否有新来源以及是否会形成捷径。删除元数据不一定降低泄漏，反而可能让研究者无法发现原本存在的相关性。

<a id="nlp-3-detail-54"></a>
### 9.7 人工分类满分能证明什么

题目：保留来源的准确率为一，是否说明泛化问题解决？答案：只说明这个人工生成分布中共享词项关联足以完成任务。它不包含复杂否定、讽刺、歧义和真实来源变化。应结合生成规则解释结果，增加针对性对照而非外推行业表现。机制实验的成功是管线自洽的证据，真实质量仍需要代表性数据与合理确认协议。

<a id="nlp-3-detail-55"></a>
### 9.8 CRF 合法路径是否必然是正确实体

题目：输出完全符合 BIO，是否就可交付？答案：合法性只保证编码结构满足约束，不能保证边界和类型符合事实。模型可以合法地把背景标成人名，也可以漏掉全部实体。应使用严格实体评价和错误分析，同时检查规范与坐标。结构约束是必要工具之一，不是语言理解或事实正确的替代证明。

<a id="nlp-3-detail-56"></a>
### 9.9 未见字特征消失后还剩什么信息

题目：测试名字的字都未见过，模型一定无法预测吗？答案：当前字特征可能消失，但邻居、边界和转移仍提供证据，因此不一定全错。若句子模板固定，模型还可能靠位置模式得到表面高分。需要通过实体、上下文和模板分别不重叠的划分区分这些机制，不能只看一个新名字例子就宣称模型获得开放实体泛化。

<a id="nlp-3-detail-57"></a>
### 9.10 为什么训练损失下降不能代替跨度评价

题目：CRF 的 NLL 大幅下降，是否可以省略实体指标？答案：似然优化训练路径概率，实体评价要求完整边界和类型匹配，二者不完全一致。过拟合和合法但错误的输出都可能存在。应同时核对损失有限、参数实际更新、解码合法和独立实体指标；其中任何一项都不能完全替代其余项，尤其不能只用训练数据判断真实泛化。

<a id="nlp-3-detail-58"></a>
### 9.11 置换词项和删除重训有什么区别

题目：某词置换后影响小，能否认为它无用？答案：固定模型可能通过相关词补偿，置换也可能制造不自然组合；删除后重新训练又回答整个学习流程是否能适应缺失信息。两者问题不同，都不能单独推出因果无关。应结合语义对照、相关特征组和重新训练比较，并明确输入扰动是否仍符合真实分布。

<a id="nlp-3-detail-59"></a>
### 9.12 不完整标注池如何影响新检索器

题目：新系统召回了未标注文档，为何可能被低估？答案：若评价把未标注直接当作不相关，它找到的真实相关文档也会被判错。应扩展多方法候选池并进行统一盲评，或明确报告标注覆盖限制。不能只为新系统单独补有利标签而不给基线同等复核，也不能把所有未标注都自动当成相关；需要一致且可复核的裁决。

<a id="nlp-3-detail-60"></a>
### 9.13 同一个随机种子是否保证公平

题目：所有模型都用种子零，比较是否已经充分公平？答案：种子只控制部分随机过程，不控制外部数据、搜索预算、参数规模和候选次数，也不保证不同结构得到相同随机条件。应记录完整资源并适当重复，区分优化与样本不确定性。公平来自问题和权限一致，而不是一个看似统一的数字。

<a id="nlp-3-detail-61"></a>
### 9.14 检索增强为何还需要事实核验

题目：正确文档已经在上下文里，生成会自动正确吗？答案：模型仍可能遗漏、误读、混合冲突或添加无证据主张。应检查每条重要主张是否得到实际证据支持，并分别报告检索覆盖与生成忠实性。引用文档标题不代表内容支持该句，事实核验需要回到具体证据段落、时间和条件，不能用命中率替代。

<a id="nlp-3-detail-62"></a>
### 9.15 结果文件应该保留哪些内容

题目：只保存权重，为什么无法恢复系统？答案：词表编号、IDF、规范化、标签映射、约束和索引版本都参与输入输出函数。缺少任何关键状态可能使相同文本得到不同特征或解释。最终交付应保存必要状态与说明，临时实验产物则按依赖清理。文件名和参数数量相同不是函数一致的充分证据。

<a id="sec-7-1"></a>
<a id="nlp-3-detail-63"></a>
### 9.16 怎样判断下一步应该改数据还是模型

题目：三个系统都存在错误，应统一换更大模型吗？答案：先按不可达证据、分析器错配、来源漂移、标签分歧和表示限制分类。库缺答案应补数据或改任务，词表失配应查分析器，规范冲突应修标注，组合关系不足才考虑更合适结构。每个改动需要对应可检验假设和独立确认，不能用模型规模掩盖所有问题。

<a id="nlp-3-detail-64"></a>
## 10. 综合任务：将三条路径连接成可验证研究

设计一个人工问答服务：先检索流程文档，再分类请求类型，抽取人名地点等槽位，最后生成受证据约束的短回复。为每个阶段保留身份与中间结构，在同一批冻结样本上评价组件和端到端结果。增加词面相同但事实相反、同义却不共词、未见实体、空查询和无答案等条件，观察失败最早发生在哪一层。

先修正一个阶段再重新评估，可以估计瓶颈上界，但人工修正结果不能当作实际系统成绩。报告应解释每条改进链路使用了什么额外信息，哪些参数经过选择，最终确认是否独立。最后保留至少一个未解决问题及其替代解释，提出真正能区分它们的后续实验，让实践成为持续可检验的研究，而不只是一次演示。
