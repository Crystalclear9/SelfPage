## 1. 把完整训练拆成信息路径与梯度路径

前两章分别说明共享空间和融合接口，本章将它们连成实际训练过程。首先区分两张图：信息路径描述哪些输入能够影响输出，梯度路径描述哪些参数能够根据损失更新。冻结某个参数不会删除其前向作用，也不必然允许切断经过它的导数。理解这两张图，是分析阶段训练、桥接器和参数高效适配的基础。

我们使用人工低维观测，完整实现对齐预训练、冻结、跨注意力桥接、开发选择和最终测试。人工任务没有真实图像、语言分词或预训练大模型，因此能够精确知道标签来自哪里。它验证数学和执行机制，不代替自然语言能力评价。每个阶段都要说明看见的数据、优化的对象和最终保存的状态。

<a id="deep-dive-1"></a>

<a id="mm-3-detail-2"></a>

### 1.1 三种损失的监督粒度

对比损失约束样本或语义原型之间的相对关系，匹配损失判断给定两侧是否相容，生成损失约束每个输出位置。它们可以共享编码器，但不等价。一个总体向量足够找配对，却未必保留每个区域的属性；一个匹配分类器可以学到细粒度交互，却未必产生适合缓存检索的共享向量；生成模型还要学习输出顺序和结束。

阶段训练可以先建立可比较表示，再学习读取与任务接口，最后进行更广泛适应。它减少某些优化困难，也可能让后阶段受冻结表示瓶颈限制。单阶段联合训练允许相互调整，却增加梯度冲突和状态管理。不能仅凭阶段数量判断方法先进与否，应根据可观察失败和预算比较。

<a id="mm-3-detail-3"></a>

### 1.2 张量轴与角色的一致性

本章用批次、来源位置、通道三个轴表示来源，查询可有一个或多个位置。对比矩阵的候选轴与跨注意力的来源轴不是同一对象：前者通常跨样本竞争，后者通常在单样本内部读取。把二者混淆可能让一个问题读取其他样本来源，训练 loss 仍会下降，却改变了任务信息条件。

任何打包、重排和缓存都要维护样本身份。图文对比允许按协议把其他样本作为负例，条件问答则通常不允许把其他样本答案当上下文。先写清每个张量行列代表什么，再选择广播与矩阵乘法，能够避免大量形状正确而语义错误的实现。

<a id="mm-3-detail-4"></a>

## 2. 对比梯度如何连接到编码器

<a id="mm-3-detail-5"></a>

### 2.1 从候选目标到共享参数

设图像向量矩阵为 $U$，文本原型矩阵为 $V$，分数为缩放点积。前章给出 logits 梯度，本章强调它怎样累加到共享参数。一个原型可能服务多个图像正例，它既应吸引所有对应观测，也与其他语义竞争。若反向目标仍只选某一个视图为唯一正例，就会把同类其他视图错误排斥。

当一侧有多个视图、另一侧每类一个原型，矩阵不必是方阵。正例关系应由身份矩阵构造，行目标和列目标各自按自己的查询数平均。只为方便使用对角标签而复制原型，会改变候选重复和分母。正确的多正例目标可以直接在长方形矩阵上实现，不需要假装每个配对唯一。

<a id="sec-2"></a>

<a id="mm-3-detail-6"></a>

### 2.2 多视图与原型的双向目标

设有 $N$ 个观测、$C$ 个原型，观测标签为 $c_i$。观测到原型方向使用分类交叉熵；反方向对每个原型，将其所有对应观测作为正例，可以采用平均正例 log 概率。后者的最小参考含正例数量的对数，不能期待两方向训练 loss 都趋近零。正例数量变化会影响数值基线，但不直接表示语义质量变差。

本章完整实验每类具有相同数量视图，因此按原型平均不会额外偏向多视图类。若数量不平衡，应先确定希望随机抽观测还是随机抽语义类，再选择权重。数据采样和损失归约共同定义任务分布，不能只把类别权重加上而忘记采样器已经重平衡。

<a id="mm-3-detail-7"></a>

### 2.3 冻结、缓存与编码身份

对齐后冻结编码器，后阶段可以预计算固定特征，前提是预处理、随机增强和模式也固定。缓存只节省重复编码，不增加新信息。若后阶段仍在编码器内部训练适配参数，旧缓存通常不再对应当前函数。应把编码器状态、投影和归一化版本绑定到缓存身份，而不是只看特征维度。

冻结表示能够复用已有语义结构，却可能保留对比目标忽略的细节不足。若后阶段需要的信息已经被映射合并，桥接器再强也无法恢复。可以先用理想特征检验桥接，再用冻结表示比较，最后考虑局部解冻。这个顺序让每次增加可训练范围都有清楚理由，而不是盲目扩大模型。

## 3. 跨注意力的完整反向传播

<a id="mm-3-detail-9"></a>

### 3.1 固定投影后的矩阵求导

令 $Z=QK^T/\sqrt d$、$P=\operatorname{softmax}_{row}(Z)$、$O=PV$，上游梯度为 $H=\partial L/\partial O$。矩阵乘法给出 $\partial L/\partial V=P^TH$ 和 $\partial L/\partial P=HV^T$。对每个查询行，softmax 的梯度为概率乘上该分量上游梯度减去概率加权平均。

记 $D=HV^T$，则

$$
E_{ij}=\frac{\partial L}{\partial Z_{ij}}
=P_{ij}\left(D_{ij}-\sum_kP_{ik}D_{ik}\right).
$$

随后有 $\partial L/\partial Q=EK/\sqrt d$、$\partial L/\partial K=E^TQ/\sqrt d$。如果使用掩码，非法位置概率为零，在普通有限有效行中相应分数梯度也为零。全掩码行不满足正常 softmax 条件，应在前向前处理，不能依靠反向公式修复。

<a id="sec-2-1"></a>

<a id="mm-3-detail-10"></a>

### 3.2 回到投影矩阵与输入

若 $Q=XW_Q$、$K=YW_K$、$V=YW_V$，则投影参数梯度分别为输入转置乘对应上游梯度。来源 $Y$ 同时出现在键和值两条路径，因此其总梯度为键路径与值路径之和。只计算值路径会忽略路由怎样改变，单独看注意力权重也无法反映完整输入贡献。

查询输入还可能通过残差直接进入输出，必须再加残差路径梯度。多头注意力把每头输出拼接后投影，各头与最终投影都有相应链式法则。复杂实现依然可以由这些局部矩阵规则组成；最有效的核验是先在小维度验证完整梯度，再增加头数、批量和掩码。

<a id="mm-3-detail-11"></a>

### 3.3 实验一：三条输入梯度与方向差分

这个实验固定两个查询、三个来源和二维通道，用平方误差检查全部解析梯度。一个掩码位置被排除，验证其分数梯度为零。最后对查询做方向有限差分。它不训练任务，专门检验缩放、转置和 softmax 轴，方便在后面完整训练失败时排除基本求导错误。

```python
import math
import torch
torch.set_num_threads(1)
dtype = torch.float64
q = torch.tensor([[.4,-.2],[.8,.3]],dtype=dtype,requires_grad=True)
k = torch.tensor([[.2,.5],[-.7,.1],[.6,-.4]],dtype=dtype,requires_grad=True)
v = torch.tensor([[1.,-.3],[.2,.8],[-.4,.6]],dtype=dtype,requires_grad=True)
mask = torch.tensor([[True,True,False],[True,True,True]])
target = torch.tensor([[.1,.2],[-.2,.4]],dtype=dtype)
score = q@k.T/math.sqrt(2)
p = score.masked_fill(~mask,-torch.inf).softmax(1)
out = p@v
loss = .5*(out-target).square().sum()
loss.backward()
h = out.detach()-target
d = h@v.detach().T
e = p.detach()*(d-(p.detach()*d).sum(1,keepdim=True))
assert torch.equal(e[~mask],torch.zeros_like(e[~mask]))
assert torch.allclose(q.grad,e@k.detach()/math.sqrt(2),atol=1e-12)
assert torch.allclose(k.grad,e.T@q.detach()/math.sqrt(2),atol=1e-12)
assert torch.allclose(v.grad,p.detach().T@h,atol=1e-12)
direction = torch.tensor([[.2,.1],[-.3,.4]],dtype=dtype)
def objective(query):
    a = (query@k.detach().T/math.sqrt(2)).masked_fill(~mask,-torch.inf).softmax(1)
    return .5*(a@v.detach()-target).square().sum()
eps = 1e-6
fd = (objective(q.detach()+eps*direction)-objective(q.detach()-eps*direction))/(2*eps)
assert torch.allclose(fd,(q.grad*direction).sum(),atol=1e-9)
print('attention_loss',loss.item(),'directional_derivative',fd.item())
```

本次梯度实验的平方误差约为零点二六零九九二，查询方向导数约为零点零六二三五八，解析结果、自动微分和中心差分全部一致。它检验固定小张量上的求导，不提供模型训练收敛证明；冻结链实验也只验证所声明的计算路径错误，没有把一个反例扩展成所有冻结策略都无效。

分数梯度每行和为零，对应统一平移不改变概率的性质。这个不变量可以额外帮助诊断：若正常有效行的梯度和明显非零，可能是归一化轴或公式错误。数值上比较应有合理容差，不能要求跨不同精度和设备逐位相同。

## 4. 冻结参数与保留导数的区别

<a id="mm-3-detail-13"></a>

### 4.1 一个被冻结的中间层

设可训练桥接把输入映到固定网络所需空间，固定网络再产生任务输出。虽然固定权重不更新，损失仍需要通过它对桥接输出求导。如果把整个固定网络放进无梯度区域，会切断桥接的更新。前向输出完全相同，末端某些参数仍可能有梯度，因此只看能否反向或 loss 下降不够。

只有在固定网络上游没有待训练参数、其输出作为固定特征时，才可以安全缓存或停止梯度。本章阶段二的视觉编码器位于所有可训练桥接之前，可以缓存；桥接之后的固定矩阵和读出仍必须保留输入梯度。两者都叫冻结，合法处理却不同，判断依据是计算图而非模块名称。

<a id="mm-3-detail-14"></a>

### 4.2 实验二：相同前向却丢失早期梯度

构造早期桥接矩阵、固定中间矩阵和末端可训练读出。正确路径保留全部运算，错误路径在中间停止梯度。比较前向一致、末端梯度一致、早期梯度却缺失，直观展示为什么必须按参数逐项审计。实验不依赖外部模型。

```python
import torch
torch.set_num_threads(1)
torch.manual_seed(79)
dtype = torch.float64
x = torch.randn(5,3,dtype=dtype)
fixed = torch.randn(4,4,dtype=dtype)
a = torch.randn(3,4,dtype=dtype,requires_grad=True)
b = torch.randn(4,2,dtype=dtype,requires_grad=True)
good = x@a@fixed@b
ref = torch.autograd.grad(good.square().mean(),(a,b))
a2 = a.detach().clone().requires_grad_()
b2 = b.detach().clone().requires_grad_()
with torch.no_grad(): hidden = x@a2@fixed
bad = hidden@b2
grad = torch.autograd.grad(bad.square().mean(),(a2,b2),allow_unused=True)
assert torch.allclose(good,bad)
assert ref[0].abs().sum()>0 and grad[0] is None
assert torch.allclose(ref[1],grad[1])
assert not fixed.requires_grad
print('forward_equal_but_early_gradient_missing',grad[0] is None)
```

这类故障可以在训练初期用极小样本发现。检查所有预期参数的梯度是否存在且有限，再比较一步更新前后的值；有梯度但没进入优化器的参数仍不会更新。替换模块后保留旧优化器也是常见问题，参数身份必须与当前计算图一致。

## 5. 完整实验的人工世界与阶段边界

<a id="mm-3-detail-16"></a>

### 5.1 已知语义与独立观测

人工语义由三个槽位身份和三个属性类别组合成九种状态，每个状态用两个三维独热向量拼成六维。图像侧只是把语义经固定线性投影映到十维，再加小噪声；文本侧经另一投影映到八维。名称用于类比两个模态，数据本质是人工数值观测，不包含真实视觉或自然语言。

阶段一为每个状态生成十二个训练视图、四个开发视图，共享相同九种语义但噪声独立。双编码器输出六维并归一化，观测到原型使用分类目标，原型到观测使用平均多正例目标。开发数据只用于选择编码器状态。这个协议测试已知语义的新观测，不测试新概念或未见语义组合。

<a id="mm-3-detail-17"></a>

### 5.2 场景、查询与任务标签

阶段二每个场景包含三个来源区域，每个槽位都有一个随机属性。来源顺序独立打乱，查询告诉系统要读取哪个槽位，标签是该槽位的属性。只看查询不知道随机属性，只看区域集合而不看查询也不知道选择哪个位置，因此任务确实要求把问题与来源关系结合。所有输入仍处于已知槽位和属性范围。

训练、开发和测试场景分别有三百六十、九十和一百八十条，使用独立随机流。它们可能共享某些有限符号配置，因为任务空间很小；不应把它描述成全新结构组合外推。噪声和随机场景是新抽样，阶段二最终测试不参与开发选点。标签在生成数据时定义，模型输入不直接含被询问的答案字段。

<a id="sec-4"></a>

<a id="mm-3-detail-18"></a>

### 5.3 桥接器与固定读出

冻结图像和文本编码器，把来源预先编码。桥接器训练查询、键和值投影，得到来源内注意力，再经过固定正交中间矩阵和固定读出矩阵产生三类 logits。固定读出不是语言模型，只用于明确演示桥接梯度必须穿过冻结计算。阶段二只有三个投影模块可训练，固定矩阵作为缓冲区保存。

开发集每十步评价一次，保存最小交叉熵对应的完整桥接状态副本，训练结束恢复，再测试一次。编码器冻结身份逐张量核验，来源同步置换应保持最终输出。所有数据和状态在内存中，不依赖外部权重、索引或下载模型。代码中的准确率断言只检验这个受控任务预期成功，不构成真实大模型质量保证。

<a id="mm-3-detail-19"></a>

## 6. 实验三：两阶段完整训练

下面代码独立运行，包含造数、阶段一、冻结、阶段二、选择与最终评价。它没有调用前两段实验变量，也不读取外部文件。为可复算起见，采用双精度、单线程与固定随机流。若读者改变生成器、噪声或容量，应把新结果当作新的实验设置，不能只保留最好的一次运行。

```python
import copy
import math
import torch
from torch import nn
import torch.nn.functional as F

torch.set_num_threads(1)
torch.manual_seed(83)
dtype = torch.float64
eye = torch.eye(3,dtype=dtype)
semantic = torch.cat([eye.repeat_interleave(3,0),eye.repeat(3,1)],1)
Ax = torch.linalg.qr(torch.randn(10,6,dtype=dtype))[0]
Ay = torch.linalg.qr(torch.randn(8,6,dtype=dtype))[0]
text_input = semantic @ Ay.T
def views(repeats,seed):
    g = torch.Generator().manual_seed(seed)
    labels = torch.arange(9).repeat_interleave(repeats)
    raw = semantic[labels] @ Ax.T + .025*torch.randn(len(labels),10,generator=g,dtype=dtype)
    return raw,labels
train_x,train_label = views(12,84)
dev_x,dev_label = views(4,85)
class Align(nn.Module):
    def __init__(self):
        super().__init__()
        self.image = nn.Linear(10,6,bias=False,dtype=dtype)
        self.text = nn.Linear(8,6,bias=False,dtype=dtype)
    def logits(self,x):
        return 10*F.normalize(self.image(x),dim=-1) @ F.normalize(self.text(text_input),dim=-1).T
align = Align()
opt = torch.optim.Adam(align.parameters(),lr=.03)
best,best_state = float('inf'),None
reverse_target = (torch.arange(9)[:,None]==train_label[None,:]).to(dtype)/12
initial = F.cross_entropy(align.logits(dev_x),dev_label).item()
for step in range(400):
    opt.zero_grad()
    logits = align.logits(train_x)
    forward = F.cross_entropy(logits,train_label)
    reverse = -(reverse_target*logits.T.log_softmax(1)).sum(1).mean()
    loss = (forward+reverse)/2
    loss.backward();opt.step()
    if (step+1)%20==0:
        with torch.no_grad():
            value = F.cross_entropy(align.logits(dev_x),dev_label).item()
        if value<best:
            best,best_state = value,copy.deepcopy(align.state_dict())
align.load_state_dict(best_state);align.eval()
for p in align.parameters():p.requires_grad_(False)
frozen = copy.deepcopy(align.state_dict())
def scenes(n,seed):
    g = torch.Generator().manual_seed(seed)
    values = torch.randint(3,(n,3),generator=g)
    latent = torch.cat([eye[None,:,:].expand(n,-1,-1),eye[values]],2)
    raw = latent @ Ax.T + .025*torch.randn(n,3,10,generator=g,dtype=dtype)
    # 每个样本单独打乱来源顺序，但保留槽位身份在latent中。
    order = torch.rand(n,3,generator=g).argsort(1)
    raw = raw.gather(1,order[:,:,None].expand(-1,-1,10))
    query_id = torch.randint(3,(n,),generator=g)
    labels = values[torch.arange(n),query_id]
    with torch.no_grad():
        encoded = F.normalize(align.image(raw),dim=-1)
    return encoded,eye[query_id],labels
tr,va,te = scenes(360,86),scenes(90,87),scenes(180,88)
class Bridge(nn.Module):
    def __init__(self):
        super().__init__()
        self.q = nn.Linear(3,6,bias=False,dtype=dtype)
        self.k = nn.Linear(6,6,bias=False,dtype=dtype)
        self.v = nn.Linear(6,6,bias=False,dtype=dtype)
        self.register_buffer('fixed_middle',torch.linalg.qr(torch.randn(6,6,dtype=dtype))[0])
        self.register_buffer('fixed_readout',torch.linalg.qr(torch.randn(6,3,dtype=dtype))[0])
    def forward(self,source,question):
        q = self.q(question)[:,None,:]
        k = self.k(source)
        weight = (q*k).sum(-1).div(math.sqrt(6)).softmax(1)
        pooled = (weight[:,:,None]*self.v(source)).sum(1)
        # 冻结矩阵仍传递桥接参数所需的输入梯度，不能整体no_grad。
        return pooled @ self.fixed_middle @ self.fixed_readout
bridge = Bridge()
opt = torch.optim.Adam(bridge.parameters(),lr=.04)
best,best_step,best_state = float('inf'),None,None
before = F.cross_entropy(bridge(*tr[:2]),tr[2]).item()
for step in range(500):
    opt.zero_grad()
    loss = F.cross_entropy(bridge(*tr[:2]),tr[2])
    loss.backward()
    assert all(p.grad is not None and torch.isfinite(p.grad).all() for p in bridge.parameters())
    opt.step()
    if (step+1)%10==0:
        with torch.no_grad():value = F.cross_entropy(bridge(*va[:2]),va[2]).item()
        if value<best:
            best,best_step,best_state = value,step+1,copy.deepcopy(bridge.state_dict())
bridge.load_state_dict(best_state);bridge.eval()
with torch.no_grad():
    output = bridge(*te[:2])
    test_loss = F.cross_entropy(output,te[2]).item()
    accuracy = (output.argmax(1)==te[2]).double().mean().item()
    train_loss = F.cross_entropy(bridge(*tr[:2]),tr[2]).item()
    permutation = torch.tensor([2,0,1])
    assert torch.allclose(bridge(te[0][:,permutation],te[1]),output,atol=1e-10)
    assert train_loss<before and accuracy>.8
    assert all(torch.equal(align.state_dict()[k],v) for k,v in frozen.items())
    assert all(not p.requires_grad for p in align.parameters())
print({'alignment_dev_ce_before':initial,'alignment_dev_ce_selected':F.cross_entropy(align.logits(dev_x),dev_label).item(),
       'bridge_train_before':before,'bridge_train_selected':train_loss,
       'bridge_dev_selected':best,'selected_step':best_step,
       'test_ce':test_loss,'test_accuracy':accuracy})

```

### 6.1 本次运行的实际结果

对齐阶段开发交叉熵由约六点一八一七降到零点零零二七零九。桥接训练交叉熵由约一点零八五八降到零点零零二二零九，开发选定第五百次更新，开发损失约零点零零二二零一。最终一百八十条独立场景的测试损失约零点零零二二四四，准确率为一。冻结字节与来源置换断言全部通过。

这些数字说明当前低维机制足够容易学到，不说明跨自然语言、遮挡、多对象或未见概念的迁移。九种语义全部出现在阶段一，阶段二的槽位和属性范围也相同。测试支持数、已知符号空间和噪声机制都应与分数一起报告。后续研究应在开发角色设计更难变化，再使用新的冻结确认集。

<a id="mm-3-detail-21"></a>

### 6.2 不能只看满分的原因

一个有限任务达到满分可以证明链路在声明范围内工作，却不能证明每个模块都按预期内部解题。注意力可能利用与槽位相关的表示方向，而不形成可读对象槽。应进一步做查询替换、属性交换、来源干扰和冻结表示消融，观察输出按事实变化。若要对机制作更强解释，需要相应干预证据。

固定读出具有足够秩，桥接值投影可以学到将属性映到输出空间。若读出丢掉必要方向，或冻结编码器把不同属性合并，再长训练也可能失败。实验成功来自特定可表达组合，不是任意冻结模型都能靠一个小桥接器适应任何任务。把这些条件写清，才有依据选择下一步扩展。

## 7. 训练阶段的设计与失效模式

<a id="mm-3-detail-23"></a>

### 7.1 阶段顺序改变优化问题

先对齐再桥接，可以让后阶段建立在较稳定表示上；同时训练可能让表示为下游任务重组，也可能损害检索。若后阶段完全冻结，第一阶段丢掉的信息成为硬限制。可以比较冻结、局部解冻和联合训练，但应固定数据角色与选择预算，并保留第一阶段能力回归，而不只追最终分类。

阶段切换还涉及优化器与模式。新的可训练模块应进入新的参数组，冻结参数不应继续被旧优化器意外更新；归一化统计与随机层需要明确模式。学习率重置、动量清空和权重衰减变化都影响路径，应记录，不能把它们藏在“开始第二阶段”这个描述里。

<a id="sec-5-1"></a>

<a id="mm-3-detail-24"></a>

### 7.2 任务损失与辅助目标

如果同时保持对齐损失和任务损失，它们作用于不同查询、候选和输出单位。一个数值较小的目标仍可能贡献较大梯度，平均方式相同也不保证尺度相同。可以按明确任务需求选择权重，并观察检索保留、任务正确和更新范数。梯度冲突诊断有帮助，但不能替代独立评价。

辅助目标也可能提供捷径。例如让模型重建所有输入，会强调与任务无关的细节；让匹配分类器读取来源标识，可能绕开语义。每个新增目标都应说明要修复的失败和预期影响，建立对应对照。更多损失项不是更完整理解的自动保证。

<a id="mm-3-detail-25"></a>

### 7.3 分布式与缓存时的梯度身份

跨设备收集向量时，是否保留其他设备表示的梯度，会影响完整目标。只把它们当常量候选可能是近似实现，需要明确；索引偏移和重复身份也必须正确。梯度累积不能自动重现大批次全部竞争关系。复杂系统应先用小规模精确版本核验，再引入近似并测量其影响。

缓存特征在后阶段固定时合法，但缓存身份应包括编码器、预处理和归一化。若开发选择编码器状态后仍使用旧缓存，训练的桥接与报告的编码器不再对应。保存和恢复时也要绑定阶段身份，不能只保留最后一份名称相同的张量。可复现的是完整函数与信息条件，而不是单个权重文件名。

## 8. 进阶练习与详细解答

<a id="mm-3-detail-27"></a>

### 8.1 题一：对比矩阵必须方阵吗

题目：一百个观测对应十个语义原型，能否构造对比目标？

解答：可以，矩阵是一百乘十，行目标按每个观测的原型标签分类，反方向对每个原型标注多个正观测。两方向分母不同，应分别定义后再组合。不需要为了使用对角标签把原型复制成一百个候选，因为复制会改变竞争。正例身份比矩阵是否方阵更根本。

<a id="mm-3-detail-28"></a>

### 8.2 题二：多正例反向损失的下限

题目：某原型有十二个同等正观测，平均正例 log 概率损失能否趋近零？

解答：若全部概率均匀落在这十二个正例上，最小参考为十二的自然对数，而不是零。它鼓励覆盖每个正例，和任一命中集合目标不同。训练日志应说明基线，不要因损失仍大于二就认定失败。共同任务指标才适合比较不同正例数量下的效果。

<a id="mm-3-detail-29"></a>

### 8.3 题三：来源梯度的两条路径

题目：来源同时产生键和值，为什么只反传值投影不完整？

解答：来源改变既影响被读取内容，也影响注意力路由。总梯度应加键路径与值路径；若有其他残差再继续累加。漏掉键路径可能保持前向正常，却改变优化目标。实验一用独立键和值核验，再回到共享来源相加，是清楚的排错顺序。

<a id="mm-3-detail-30"></a>

### 8.4 题四：分数梯度每行和为零

题目：为什么正常 softmax 行的 logits 梯度和为零？

解答：统一平移所有 logits 不改变概率，损失沿该方向导数为零。解析公式里，概率乘上游值之和减去同一加权均值乘概率和，也恰好抵消。它是局部不变量，可用于检测轴与归约错误。全掩码行没有正常概率，不应套用该结论掩盖无效输入。

<a id="mm-3-detail-31"></a>

### 8.5 题五：冻结层何时能无梯度

题目：固定视觉编码器之后才放所有可训练模块，能否缓存其输出？

解答：在预处理和模式固定、编码器上游没有需训练参数时可以。若可训练桥接在固定网络之前，损失仍要穿过固定网络求输入导数，不能整体停止梯度。判断依据是完整路径。本章两个位置分别演示合法缓存与必须保留导数的冻结运算。

<a id="mm-3-detail-32"></a>

### 8.6 题六：前向一致为何仍有错误

题目：错误实现与正确实现输出完全相同，是否足够验收训练？

解答：不够，停止梯度可以保持数值前向却改变反向。还需检查所有预期参数的梯度、有限性和实际更新，以及优化器是否持有当前参数。实验二就是同前向、同末端梯度却丢失早期梯度的反例。训练实现验收必须覆盖两张图。

<a id="mm-3-detail-33"></a>

### 8.7 题七：为什么本章不是新概念泛化

题目：阶段二测试场景独立生成，能否说模型识别了从未见过的语义？

解答：不能，所有槽位和属性组合都已在阶段一出现，阶段二也使用相同符号范围。它测试新噪声和场景抽样，不是新概念。若要研究组合外推，应预先留出相应语义或结构，并重新设计划分。独立随机流与完全新概念是不同条件。

<a id="mm-3-detail-34"></a>

### 8.8 题八：来源顺序与身份

题目：场景来源被随机打乱，模型怎样仍知道查询哪个槽位？

解答：槽位身份包含在区域语义中，来源打乱只改变存储顺序，身份和内容一起移动。注意力根据查询与来源表示匹配，不依赖固定行号。若身份没有提供，且所有区域在其他方面不可区分，任务可能不可识别。置换测试必须维护同一语义输入。

<a id="mm-3-detail-35"></a>

### 8.9 题九：固定读出的表达条件

题目：固定读出把所有桥接输出映成相同类别分数，训练桥接能否解决？

解答：若读出确实消除了所有类别差异方向，无法仅靠上游恢复。需要检查固定映射的秩与可达输出空间。当前实验固定读出具有足够列秩，值投影可以学习相应方向，因此成功具有条件。冻结模型不是任意黑箱都能适配的保证。

<a id="mm-3-detail-36"></a>

### 8.10 题十：开发最佳状态为什么要复制

题目：把当前 state_dict 直接赋给 best，是否一定冻结了最佳张量？

解答：不一定，状态可能引用仍被后续训练修改的存储。应使用独立张量副本或适当深拷贝，并在结束后恢复该状态。本章两个阶段都复制选择状态，测试在恢复后进行。只记录最佳损失数字而实际测试最后参数，会让报告与模型不对应。

<a id="mm-3-detail-37"></a>

### 8.11 题十一：冻结字节与行为保留

题目：编码器字节完全不变，是否证明完整系统旧行为不变？

解答：不证明，新增桥接和读出会改变完整函数。字节核验只说明冻结范围按约定保持，行为保留需要直接回归。若后阶段训练检索之外的任务，应重新测检索与旧功能。参数状态与任务行为是不同验收对象。

<a id="mm-3-detail-38"></a>

### 8.12 题十二：满分该怎样报告

题目：一百八十条人工测试全对，怎样写结论准确？

解答：连同生成机制、已知语义范围、噪声、支持数和选择协议报告，称为当前受控任务通过。不能外推到自然语言、遮挡或新概念。若根据测试继续改模型，原集合转为开发或回归，再建立新的确认。满分有价值，但其范围必须清楚。

<a id="mm-3-detail-39"></a>

### 8.13 题十三：缓存与解冻

题目：解冻视觉编码器后，继续使用原缓存会怎样？

解答：桥接看到旧特征，编码器更新无法通过缓存影响任务，可能使实际训练与声明不同。应重新在线编码或按明确近似更新缓存，并记录陈旧程度。若缓存本来就是停止梯度设计，必须准确描述目标，而不能声称完全端到端训练。

<a id="mm-3-detail-40"></a>

### 8.14 题十四：共同候选与跨样本泄漏

题目：对比学习允许其他样本为候选，为何条件问答不能直接读取其他样本答案？

解答：两者任务信息条件不同。对比候选游戏预先定义了跨样本竞争，问答若未授权其他答案作为上下文，读取它们就改变目标甚至泄漏。矩阵轴相似不表示信息规则相同。应按样本身份构造掩码与监督，而非按代码方便复用所有张量。

<a id="mm-3-detail-41"></a>

### 8.15 题十五：阶段目标冲突

题目：任务分类提高但检索下降，是否证明第一阶段无用？

解答：不一定，后阶段可能改变表示或投影使其更适合任务，损害原几何。应比较冻结、联合和保留辅助目标的配置，保持开发预算与数据边界。当前现象只说明目标存在取舍，不能唯一归因。每种重要能力都需直接测量。

<a id="sec-6-1"></a>

<a id="mm-3-detail-42"></a>

### 8.16 题十六：一个可验证的下一步

题目：怎样研究桥接失败来自冻结表示还是注意力训练？

解答：先提供理想六维语义给同一桥接，固定数据和预算；再换回冻结编码特征；最后比较局部解冻。若理想特征成功而冻结特征失败，表示瓶颈值得调查；若两者都失败，先查目标、优化与容量。干预改变的信息条件要明确，并用新确认验证选择后的方案。

<a id="mm-3-detail-43"></a>

## 9. 综合研究任务

在当前任务上依次加入不可见来源、重复槽位、属性冲突和新符号，预先定义哪些问题可回答。比较缓存冻结、局部解冻和联合训练，记录每阶段的有效监督、检索保留与任务正确。不要同时改变所有因素后强行解释单项贡献。每个失败都应关联到可见信息、表达或优化中的具体假设。

本章实验在内存中构造人工通道与桥接状态，适合逐步追踪梯度和信息流。若扩展到真实模型，需要另行验证词表、模板、分词、空间与时间编码、生成停止和资源，而不能把当前线性人工通道直接当作真实图像语言系统。清楚界定机制演示，才能把它作为可靠的进阶起点。

## 10. 长方形对比目标的进一步推导

<a id="mm-3-detail-45"></a>

### 10.1 两个方向各有自己的目标矩阵

设 logits 为 $N\times C$，观测方向标签矩阵为 $Y_{ic}=\mathbf1[c=c_i]$。原型方向的目标可以写为 $T_{ci}=\mathbf1[c_i=c]/n_c$，其中 $n_c$ 为该类正观测数。只在每个原型至少有一个正观测时，这个平均目标才有定义。若某批缺少一个类，应跳过该类查询或按明确策略补候选，不能用零分母继续训练。

行方向损失为 $-N^{-1}\sum_{ic}Y_{ic}\log R_{ic}$，反方向为 $-C^{-1}\sum_{ci}T_{ci}\log P_{ci}$，其中 $P$ 是转置 logits 的行 softmax。组合目标的 logits 梯度分别是行概率残差除以观测数，以及转置后的原型概率残差除以原型数。两个分母相同只在特殊方阵协议中成立，直接套前章方阵公式会遗漏权重差异。

本章每个类十二个训练视图，反向目标每个正观测权重为十二分之一。理论上若把全部概率均匀放在正确类的十二个视图，反向损失基线为 $\log12$。代码开发选择只看观测到原型的分类交叉熵，并没有把该值当作完整双向训练损失。报告数值时应保持这一名称，避免误以为双向目标已经降到千分之几。

<a id="mm-3-detail-46"></a>

### 10.2 类别平衡与实例平衡的区别

若一类有一百个视图，另一类只有一个，观测平均目标让前者占多数，而原型平均反向让两类各占一半。这是一个混合权重目标，未必错误，但应明确。可以改抽样器或损失权重以服务某种总体，不能在没有定义未来请求分布时宣称某种平均天然公平。训练频率和评价权重一起决定被优化的能力。

增加某类视图既可能提供真实噪声变化，也可能只是机械复制。反向平均正例损失会因正例数改变基线，但复制没有增加同等独立信息。评价应在独立视图和来源上检查，而不是只看训练目标的绝对数值。若类内差异是任务关键，原型单向压缩还可能弱化这些差异，需要另加对应监督或保留更丰富表示。

<a id="mm-3-detail-47"></a>

### 10.3 从 logits 梯度到归一化投影

设原始编码输出为 $A$ 与 $B$，逐行归一化后得到 $U,V$。若 $G$ 表示 logits 梯度，先用矩阵乘法求 $GV$ 与 $G^TU$，并乘上打分所用的尺度：当 $S=UV^T/\tau$ 时，两项都还需除以 $\tau$。随后再逐行通过单位球雅可比，才能得到真实编码输出梯度。来源同时参与多个候选关系，投影头参数梯度是所有样本贡献之和。若仅对正例点积反向，或者对候选全部停止梯度，都会改变完整目标。

有些实现有意使用停止梯度的一侧作为稳定教师，这可以成为新的训练方案，但不等于当前双编码器同时更新。应说明教师如何更新、候选是否陈旧以及两方向目标是否仍相同。名字都叫对比学习，并不意味着梯度图相同。小批精确版本是复杂近似的参照，应保留用于验证。

<a id="mm-3-detail-48"></a>

### 10.4 表示空间的等价变化

对两侧共享向量同时做同一正交变换，点积保持不变；对未归一化双线性因子还可能存在更一般的参数化自由度。训练状态不同却产生相同对比矩阵，并不奇怪。这种不唯一性说明坐标解释需要谨慎，也说明恢复时不能只比较某个中间维度的数值就认定语义变化。

完整函数身份仍然重要。若只更新一侧编码器或缓存，原先的等价变换不再配套，相似度会改变。共享空间的兼容性由两侧及预处理共同决定，不能因为每侧单独检索正常就认为混合版本可用。部署索引更新和分阶段训练都应维护同一组合身份。

<a id="mm-3-detail-49"></a>

## 11. 跨注意力的可识别性与瓶颈

<a id="mm-3-detail-50"></a>

### 11.1 路由与内容可以相互补偿

注意力权重描述当前值集合上的路由，但不同键、查询和值参数可能产生相同最终输出。若值向量之间线性相关，多个不同概率分配甚至在同一输入上就能给相同加权和。因此输出正确不证明权重唯一正确，更不能从一个注意力矩阵直接识别内部因果算法。研究时应把功能证据与参数解释分开。

例如两个来源值完全相同，无论权重怎样分配，输出都相同，分数梯度也可能为零。键再有区分性也无法让当前任务从路由获得收益。反过来，值差异明显而键无法根据查询变化，模型可能只能输出固定混合。分析失败应检查查询可分、键可分和内容可读三类条件，而不是统一归因于注意力头数不足。

<a id="mm-3-detail-51"></a>

### 11.2 查询与键的双线性自由度

对可逆矩阵 $R$，将查询乘 $R$，键乘 $R^{-T}$，未改变点积矩阵。这表明每个查询坐标不必有唯一语义。实际归一化、正则和投影限制会减少这种自由度，但基本现象提醒我们，不应把某一维权重直接当作固定概念。更可靠的解释来自输入干预与输出功能。

值表示和后续固定或可训练读出也可以形成补偿关系。某个桥接向量在一个读出下有效，换另一个同形状读出未必保持行为。固定读出身份因此不是附属细节，而是完整任务函数的一部分。保存桥接时必须绑定目标网络、维度和处理规则，不能只交付三份矩阵而省略依赖。

<a id="mm-3-detail-52"></a>

### 11.3 多个查询不要求一一分配来源

普通跨注意力对每个查询独立归一化，不限制一个来源被多少查询读取。两个问题都询问同一个对象时，这是合理的；若任务要求每个对象恰好匹配一个槽位，则需要额外结构或损失。不能把行和为一误读成整个矩阵是双随机匹配，更不能从多个查询数推断已经完成对象分解。

加入匹配约束会改变模型与目标，可能帮助去重，也可能不适合需要重复引用的语言任务。应先定义是否真的要求一一对应，再设计方法。一个通用注意力层提供内容选择，不自动解决所有结构化分配问题。把功能边界说清，能够避免用错误指标要求模型完成未被定义的任务。

<a id="mm-3-detail-53"></a>

### 11.4 输出瓶颈与查询问题的关系

固定一个查询得到一个向量，理论上可以编码不少信息，但有限维度、精度和训练会限制可稳定读取的细节。若问题只问单个属性，聚合向量可能足够；若要求同时输出所有区域的精确结构，一个查询可能过度压缩。多查询、分层读取或保留来源残差可以扩充接口，但也增加成本和优化自由度。

本章任务每次只问一个槽位，所以单查询设计符合目标。不能据此说三来源都已经被无损压缩。若未来问题变为列出全部属性，应重新检查输出长度、查询数量和生成协议，并做独立评价。任务变化可能把原先足够的统计量变成信息瓶颈，这正是架构需要与目标共同分析的原因。

<a id="mm-3-detail-54"></a>

## 12. 阶段训练的优化与状态管理

<a id="mm-3-detail-55"></a>

### 12.1 逐阶段目标不是同一个静态目标的必然近似

先优化对齐再冻结桥接，得到的过程通常不能简单写成一次固定权重的联合损失最小化。第一阶段决定可用表示，第二阶段在受限空间中适应，路径与联合训练不同。阶段化可以利用预训练结构，但没有自动达到联合全局最优的保证。比较应把完整训练程序当作方法，而不是只看最后一层形式。

局部解冻也有多个选择：只解冻投影、最后若干层或所有编码器，各自改变可达函数集合和遗忘风险。应先诊断冻结表示缺了什么，再提出最小合理改动。若一个只需重新映射类别的任务失败，可能先调整桥接或读出；若属性本身不可读，才更有理由改编码器。阶段边界应有实验证据，而不是凭惯例固定。

<a id="mm-3-detail-56"></a>

### 12.2 学习率、动量和冻结切换

同一参数从冻结变为可训练时，优化器是否已有旧动量，会影响第一批更新。替换模块后优化器可能仍引用旧参数，导致新参数虽有梯度却不更新。应逐项核对参数身份、梯度与更新差值。对于固定缓冲区，虽然没有梯度，也可能被模式或手工赋值改变，因此冻结身份应覆盖必要状态。

本章固定中间矩阵与读出存为缓冲区，桥接状态副本包含它们，恢复时保持同一函数。编码器状态另外逐张量比较，证明阶段二没有改变约定冻结范围。这些断言不等于完整续训恢复，因为没有保存所有优化器与随机流状态；当前目标只是内存中的阶段选择和最终推理一致。不同恢复要求应分别验收。

<a id="mm-3-detail-57"></a>

### 12.3 模式、随机层与缓存合法性

参数不更新不代表输出固定。Dropout 在训练模式产生随机掩码，某些归一化还更新运行统计。若缓存来自一个随机模式，后续在线评估使用另一个模式，特征可能不同。缓存应明确预处理、模式和随机性政策，必要时保存多视图而非一份偶然结果。当前人工编码器只有线性层，特意避免这些额外因素。

如果后阶段希望继续随机数据增强，缓存固定特征会减少增强覆盖。可以事先缓存多种视图，但那仍是有限集合，不能与无限在线增强完全等同。比较资源时需同时说明质量条件是否改变。真正的效率提升应在明确相同或可接受变化的目标下评估，而不是用更容易任务换取更短训练再宣称无损加速。

<a id="mm-3-detail-58"></a>

### 12.4 数据状态与检查点身份

同一权重配不同词表、模态预处理或原型顺序，输出含义可能完全不同。当前人工实验将这些配置写在同一独立代码中，避免隐藏依赖；真实工程应保存对应清单。检查点名称不能替代内容身份，内容摘要也只证明字节一致，不证明数据来源或授权。每种证据有自己的作用范围。

阶段选择还依赖开发指标、评价频率和平局规则。本章严格更小才更新最佳状态，固定检查频率，最终测试在恢复后一次执行。若看到测试结果再延长训练或改变阈值，原测试就参与选择，应建立新的确认边界。记录整个选择程序，比只报告最好数字更能支持复现。

<a id="mm-3-detail-59"></a>

## 13. 让人工实验具有更强解释力

<a id="mm-3-detail-60"></a>

### 13.1 建立理想特征和随机特征参照

理想六维语义输入可以检验桥接结构是否足够，随机冻结编码可以估计第一阶段是否真正提供有用可读表示。两者与学到编码器比较时，应保持桥接预算、场景数据和选择规则。若随机特征也容易成功，说明人工观测本身足够线性可逆，不能把全部收益归功于对比预训练。

当前代码没有运行这一消融，因此正文只把它作为下一步研究，不预先宣称对比阶段必不可少。完整流程能够通过，不等于每个组件都有独立增量。要证明增量，需要对应基线和固定协议。区分链路验收与方法贡献，是阅读研究论文和设计学习实验的重要习惯。

<a id="mm-3-detail-61"></a>

### 13.2 组合外推与来源外推分别设计

若要测试未见槽位属性组合，可以在阶段一留出部分语义对，并检查阶段二是否也遵守对应边界；否则模型可能在后阶段补见。若要测试新来源，可以改变观测投影或噪声结构，并明确是否允许重新校准。新实例、新组合、新概念和新观测机制是不同外推，不能用一个“测试集”标签同时代表。

任何留出都要考虑任务是否仍可识别。若新概念没有任何语义或观测连接，模型可能没有足够信息推断其类别；若只有独立名称，零样本要求可能本身不合理。应该先写出可利用结构，再设置问题。公平的困难实验既要排除记忆捷径，也要保留理论上可学习的信号。

<a id="mm-3-detail-62"></a>

### 13.3 噪声、干扰与缺失的分解

提高连续噪声改变观测质量，添加无关来源改变注意力竞争，删除必要来源改变可回答性，加入矛盾来源则需要冲突规则。这四种干预不应混为一种鲁棒性测试。分别测量能让失败解释更清楚，也能避免把无答案样本上的拒绝误判为模型弱。

可以保持同一场景和查询，逐级改变一个因素，记录准确率、置信与注意力分布。不要只平均不同难度场景，因为混合比例改变即可制造分数变化。若需要聚合，预先固定权重并保留分层。对噪声强度的外推也不保证单调，实际模型可能出现阈值式失效，应如实记录。

<a id="mm-3-detail-63"></a>

### 13.4 反事实查询与来源交换

在同一来源集合里更换查询，若对应槽位属性不同，正确答案也应改变。这能检查模型是否利用问题，而不只是输出场景最常见属性。反过来固定查询，替换被问槽位属性，应改变答案；只替换无关槽位，则理想行为可以不变。三种成对测试分别针对查询使用、证据使用和选择性忽略。

如果源表示本来带噪，输出变化也可能来自偶然分数波动，因此应对一组预先定义场景统计，而不靠一条例子下结论。测试集若用于发现失败，可以作为开发诊断，再用新场景确认修复。机制研究需要干预，但干预结果仍有数据角色，不能无边界重复利用。

<a id="mm-3-detail-64"></a>

## 14. 从分类桥接走向条件生成

<a id="mm-3-detail-65"></a>

### 14.1 固定读出不是语言模型

当前输出只有三类，固定矩阵不包含词表、因果上下文、语言知识或结束行为。真实语言模型桥接还要匹配嵌入尺度、位置、特殊标记和注意力接口。即使桥接输出维度相同，也不说明它位于语言模型训练分布的有效区域。实际适应需要对应数据与评价，不能把分类成功直接当作生成能力。

若将人工任务扩展为两符号回答，可以明确第一符号为属性、第二符号为结束，检查右移标签和自由生成。再加入同义输出、多轮历史与不可答状态，逐步引入复杂性。每增加一种自由度，就增加一组可检查条件。这样的扩展路线比直接接入不可解释的巨大模型，更容易知道新失败来自哪里。

<a id="mm-3-detail-66"></a>

### 14.2 生成损失的单位和条件可见性

生成训练通常按有效回复 token 平均，对比训练按查询或配对平均，两者长度权重不同。混合时应记录分子与分母，明确提示、来源标记和结束是否监督。来源编码器也应只读取部署允许的信息，尤其视频未来帧不能因为文本端因果掩码存在就合法。整个条件图必须共同遵守时间边界。

教师强制下低损失不保证自身生成历史下完整正确，因此还要检查自由生成、停止、结构和来源支持。对于开放回答，单个参考不能覆盖全部合理表述；对数字、主体和关系则需要严格核验。生成评价器应有独立反例，不应只看文字流畅或与问题主题相关。

<a id="mm-3-detail-67"></a>

### 14.3 保留能力与适配范围

桥接训练可能改变模型使用来源的方式，即使底座冻结，完整系统行为仍可变化。真实系统需要回归语言、格式、拒答、检索和关键任务，选择满足约束的适配状态。不能从可训练参数少推断遗忘风险小，也不能从底座字节未动推出所有功能不变。

若解冻底座，问题更复杂，需要追踪哪些能力变化、哪些数据参与修复。旧失败集有回归价值，但一旦用于选择就不是独立确认。长期迭代应版本化任务和评价器，保留新的确认边界。进阶训练的价值不只在一次分数，而在于能清楚维护这些依赖和取舍。

<a id="mm-3-detail-68"></a>

### 14.4 计算预算与可执行模型身份

真实多模态系统的成本包括各模态编码、桥接、语言解码、缓存、重试和输入长度。减少可训练参数主要节省部分梯度与优化器状态，不自动减少全部前向和激活。冻结网络后仍传递输入导数时，反向计算也未消失。资源结论需要测量对应设备和工作负载，本章 CPU 机制实验没有提供生产吞吐证据。

最终模型身份包含编码器、桥接、读出或语言模型、预处理、模板、精度与解码。任何一个组件变化都可能改变输出。可执行参考样例、版本清单和必要数值容差帮助验证恢复，但它们只覆盖声明范围。保存完整结果资料与删除临时生成物可以兼容，前提是没有把唯一必要依赖当成无用文件清除。

<a id="mm-3-detail-69"></a>

## 15. 进一步练习与研究判断

<a id="mm-3-detail-70"></a>

### 15.1 题十七：为何需要理想特征参照

题目：完整桥接分类通过，能否证明对比预训练提供了不可替代的增量？

解答：不能。人工投影本身可能足够容易逆，随机特征或直接原始输入也可能完成。应增加预算匹配的理想、随机和学到特征对照。当前完整流程验证链路可用，没有运行这些消融，所以不声称组件必要性。方法贡献需要独立证据，不能从流程成功直接推出。

<a id="mm-3-detail-71"></a>

### 15.2 题十八：注意力概率是否双随机

题目：每个查询权重和为一，是否意味着每个来源被读取的总权重也为一？

解答：不是，普通行 softmax没有列约束，多个查询可以都关注同一来源。若任务需要一一分配，要增加相应结构；如果多个问题合理读取同一对象，列约束反而可能不适合。应根据任务定义选择，不把归一化形式误读成匹配保证。

<a id="mm-3-detail-72"></a>

### 15.3 题十九：表示相同的不可区分反例

题目：冻结编码器把两种目标属性映为完全相同来源表示，同一查询下后续确定性桥接能否区分？

解答：不能，后续接收的全部输入相同，输出也必须相同。增加桥接训练时间和参数不能恢复已丢信息。需要改编码器、补充输入或改变任务。这个反例说明诊断应先检查可识别性，再归因于优化。近似相同则还涉及数值稳定与样本问题，需要另外分析。

<a id="mm-3-detail-73"></a>

### 15.4 题二十：正向分数一致与反向训练一致

题目：将候选向量分离计算图，前向损失不变，能否认为与双侧训练等价？

解答：不能，被分离一侧失去来自当前目标的梯度，参数路径不同。它可以是教师或队列近似的一部分，但应明确更新规则与近似。验证不仅比较 loss 数值，还要比较所有目标参数的梯度和更新。相同前向函数不保证相同学习算法。

<a id="mm-3-detail-74"></a>

### 15.5 题二十一：测试断言与模型选择

题目：教学代码要求测试准确率超过某阈值，为什么仍不能称作严格盲测基准？

解答：作者知道生成机制并选择了容易解释的配置，阈值主要确认演示按预期工作。若反复修改直到该固定测试通过，它会参与开发。正式方法比较应预先冻结协议、报告全部运行，再在未参与选择的集合确认。教学可复算有价值，但结论范围不同于未知真实分布上的独立验证。

<a id="mm-3-detail-75"></a>

### 15.6 题二十二：缓存状态与最佳状态

题目：阶段一恢复开发最佳编码器后，阶段二却用末次编码器的缓存，哪里不一致？

解答：缓存不再对应报告的编码器身份，桥接训练和最终组合可能是混合状态。应在恢复后重建缓存，或明确缓存来源并按相同组合评价。本章先恢复选定编码器，再造阶段二特征，所以边界一致。阶段化系统需要把数据缓存也当作有版本依赖的产物。

<a id="mm-3-detail-76"></a>

### 15.7 题二十三：值完全相同时的路由梯度

题目：一个查询的所有来源值向量都相同，损失只通过当前注意力输出传播，查询与键是否一定有非零梯度？

解答：不一定，事实上在这个孤立结构中输出就是共同值，与概率分配无关。对每个分数的导数为权重乘该值减加权平均，两者相同，所以分数梯度为零，查询和键路径也为零。值路径仍可以有梯度，后续更新可能打破相同状态，因此不能直接推断整个训练永远停滞。这个例子说明需要同时检查路由和内容，不能看到查询梯度零就立即认定自动微分错误。

<a id="mm-3-detail-77"></a>

### 15.8 题二十四：查询替换何时应该改变答案

题目：同一场景更换查询后答案没有变，能否证明模型忽略查询？

解答：不能直接证明，因为两个被问槽位可能恰好具有相同属性。应只在预先确认标准答案不同的成对场景上检验变化，或者按答案关系分层。反过来，标准答案相同时强迫输出变化也不合理。干预评价需要先定义应保持与应改变的事件，不能只以输出是否不同作粗糙判断。

对来源替换同样如此：替换无关背景可能不该改变答案，替换关键属性则应改变，删除必要来源可能应转为未知。三种反应各自检验不同机制。把这些规则写在评价前，能够避免观察结果后任意解释成功，也让失败清楚指向问题读取、证据使用或可回答性处理。

<a id="mm-3-detail-78"></a>

## 16. 结论的证据范围与下一步

本章三段独立 CPU 实验分别验证跨注意力梯度、冻结链反例和完整两阶段训练。第三段没有文件读写或外部下载，两个阶段的数据、选择和状态都在独立代码中明确。解析实验提供数学正确性证据，人工训练提供有限机制可学习的证据，二者都没有测试真实视觉、语言和大规模服务。

后续学习可以从一个具体边界展开：新语义组合、复杂来源位置、缺失与冲突、有限查询压缩、生成停止或底座适配。每次先写清问题和可识别条件，再设计单一干预与共同评价。这样内容会随着问题逐步深入，而不是简单叠加术语、参数与没有因果依据的漂亮分数。
