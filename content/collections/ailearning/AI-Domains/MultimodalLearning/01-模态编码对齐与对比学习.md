## 1. 多模态学习从共同对象开始

模态是观察同一世界的不同信息通道，例如图像记录空间外观，声音记录随时间变化的波形，文本记录经过语言选择的描述，传感器记录带单位的测量。不同模态既可能共享信息，也可能各自包含另一方无法恢复的内容。多模态学习的目标不是强行让所有信息相同，而是根据任务决定哪些关系要对齐，哪些差异要保留，哪些条件需要融合。

设一条记录包含图像 $`x`$、文本 $`y`$ 和来源身份 $`g`$。它们被采集到同一行，不保证文本逐项描述图像，也不保证时间和主体一致。网页标题可能只谈背景，字幕可能落后于画面，传感器可能存在时钟偏移。模型优化的是数据提供的配对关系，因此在讨论网络前，应先明确配对是同一实例、同一事件、同一语义类别还是仅有弱相关。

<a id="mm-1-detail-2"></a>

### 1.1 对齐、融合与条件生成分别回答什么

对齐希望不同通道的表示具有可比较关系，典型任务是给图像找描述或给文本找图像。融合希望联合利用信息做判断，允许一个通道补充另一通道缺失的事实。条件生成希望根据一个或多个模态产生新的序列或信号。这些目标可以组合，但共享向量相似并不自动产生细粒度问答能力，能够生成描述也不保证双向检索排名良好。

例如一张图中有两个物体，整体向量可以很好表达“街道场景”，却未保留哪个物体在左边。若任务只找主题相符图片，这可能足够；若任务问“红球是否在蓝盒里”，需要关系和定位。评价应围绕目标粒度，而不是把某个总体检索指标改善称为所有跨模态理解都提高。

<a id="mm-1-detail-3"></a>

### 1.2 共享因素与私有因素

可以用潜在因素解释两个通道：共享语义影响两者，拍摄光照只影响图像，措辞风格只影响文本，来源设备可能同时影响两者。对比训练可能抓住任何可预测配对的共享因素，其中包括不希望利用的水印、模板和来源身份。共享并不天然等于语义正确；如果每个网站有固定图像边框和固定标题格式，模型可以通过网站特征完成配对。

研究时可以设计反事实：保留对象语义但换背景，保留描述事实但换风格，移除水印，或在相同来源内构造候选。如果性能只在跨来源容易区分时很好，却在同来源细粒度候选中下降，说明表示可能依赖捷径。应使用这些结果形成竞争假设，而不是只凭一个注意力图推断模型“看懂”了对象。

## 2. 双编码器与共享空间的可执行定义

<a id="mm-1-detail-5"></a>

### 2.1 从原始输入到归一化向量

令图像编码器为 $`f_\theta`$，文本编码器为 $`g_\phi`$，投影头把两者映到同一维度。原始表示记为 $`a_i,b_j`$，归一化后为 $`u_i=\frac{a_i}{\Vert a_i\Vert _2}`$、$`v_j=\frac{b_j}{\Vert b_j\Vert _2}`$。相似度通常采用余弦点积，再除以正温度 $`\tau`$ 得 logits $`S_{ij}=\frac{u_i^Tv_j}{\tau}`$。维度相同只解决接口，实际几何关系仍需学习。

归一化去掉向量长度作为直接打分来源，使模型不能只增大范数来提高正例分数。然而它也丢掉长度可能携带的信息，投影之前的表示仍可能保留这些内容。检索使用哪个层、是否归一化、温度是否只用于训练，都应明确。只说使用某模型嵌入，尚不足以重建完整评分函数。

<a id="mm-1-detail-6"></a>

### 2.2 零向量和数值下界

归一化公式在零范数处未定义。实现常用一个很小的下界避免除零，但在下界附近的导数与普通单位球切空间公式不同。零向量也没有明确余弦方向，不应把数值上返回零向量当作正常语义表示。训练诊断应记录原始范数分布、接近下界的比例和是否出现非有限值。

低精度矩阵乘法可能使非常接近的候选排名改变，尤其在大候选池和并列附近。理论余弦范围是负一到一，但数值误差可能出现极小越界。用于角度计算时需要合理处理边界，直接检索排序则通常不必随意裁剪所有分数。任何裁剪或量化都会改变执行函数，应在固定参考输入上核验。

<a id="mm-1-detail-7"></a>

### 2.3 配对矩阵的行列含义

一批有 $`B`$ 对样本，相似度矩阵为 $`B\times B`$。第 $`i`$ 行是图像 $`i`$ 对所有文本候选，第 $`j`$ 列是文本 $`j`$ 对所有图像候选。若只有对角线被标为正例，标签为零到批量减一。这种标签隐含“一行里只有指定配对被视为正确”的训练假设，而不保证其他文本语义上都错误。

打乱图像和文本时必须同步更新配对标签。只打乱一边却仍使用对角标签，会让模型认真学习错误关系，损失也可能下降。分布式收集向量时还要记录全局索引偏移，防止每个设备都把本地第一个样本当全局第一个。最小检查应从可读身份构造预期配对，而不是仅看矩阵形状。

## 3. 双向对比目标的完整手算

<a id="mm-1-detail-9"></a>

### 3.1 两个方向的分类损失

图像到文本方向定义 $`R_{ij}=\frac{\exp S_{ij}}{\sum_k\exp S_{ik}}`$，文本到图像方向定义 $`C_{ij}=\frac{\exp S_{ij}}{\sum_k\exp S_{kj}}`$。常见双向损失为

$$
L=-\frac{1}{2B}\sum_i\left(\log R_{ii}+\log C_{ii}\right).
$$

两方向使用相同矩阵但不同归一化轴。行 softmax 的每行和为一，列 softmax 的每列和为一；它们一般不是同一个概率矩阵。用同一行损失算两遍，不会变成真正双向训练。候选数、正例定义和归约分母共同决定该目标，必须完整记录。

<a id="mm-1-detail-10"></a>

### 3.2 二乘二算例与解释

取对角 logits 为二、非对角为零。每个正例概率为 $`\frac{e^2}{(e^2+1)}`$，单方向平均损失为 $`\log(1+e^{-2})`$，双向平均仍是相同数值。它表达在当前两个候选中找对配对的难度，不是全世界所有文本中唯一正确描述的概率。新增相似候选会改变分母，即使原有分数完全不变，损失也可能升高。

若矩阵不是对称的，两方向损失可以差很多。例如某图像与许多描述都相似，而某描述只与一张图相似，行分类与列分类面对的竞争结构不同。分别报告两方向检索，有助于发现候选多样性、描述通用性和表示拥挤。把平均分数合成一个数字，可能掩盖某一方向严重退化。

<a id="sec-2-1"></a>

<a id="mm-1-detail-11"></a>

### 3.3 logits 的解析梯度

对任一元素求导，得到

$$
G_{ij}=\frac{\partial L}{\partial S_{ij}}
=\frac{R_{ij}+C_{ij}-2\mathbf1[i=j]}{2B}.
$$

正例项通常得到负梯度，促使相似度增加；非对角项通常得到正梯度，促使相似度降低。但这些梯度通过共享编码器传播，多个样本的需求可能冲突，因此不能保证一次参数更新后每个正例分数都单调提高。局部 logits 梯度与实际参数空间路径是不同层次。

若暂把归一化向量当独立变量，矩阵形式为 $`\nabla_U L=\frac{GV}{\tau}`$、$`\nabla_V L=\frac{G^TU}{\tau}`$。一个图像既作为自己行的查询，也作为其他列的候选，因此双向梯度包含整个矩阵的贡献。只对对角相似度求导会遗漏负例竞争，不能代表对比学习的训练机制。

<a id="mm-1-detail-12"></a>

### 3.4 实验一：双向损失与所有矩阵梯度

这个实验先核对二乘二手算，再在非对称矩阵上验证解析梯度，并检查两个编码向量集合的梯度。它使用独立小张量，不训练真实图像或文本模型，目的是让每一个求导对象都可核验。双精度与单线程有助于稳定有限数值比较。

```python
import math
import torch
import torch.nn.functional as F
torch.set_num_threads(1)
dtype = torch.float64
s = torch.tensor([[2., 0.], [0., 2.]], dtype=dtype, requires_grad=True)
target = torch.arange(2)
loss = (F.cross_entropy(s, target)+F.cross_entropy(s.T, target))/2
assert abs(loss.item()-math.log1p(math.exp(-2))) < 1e-12
loss.backward()
manual = (s.detach().softmax(1)+s.detach().softmax(0)-2*torch.eye(2,dtype=dtype))/4
assert torch.allclose(s.grad, manual)
u = torch.tensor([[1., .2], [-.3, .8], [.4, -.6]], dtype=dtype, requires_grad=True)
v = torch.tensor([[.7, -.1], [.2, .9], [-.5, -.4]], dtype=dtype, requires_grad=True)
tau = 0.4
logits = u @ v.T/tau
y = torch.arange(3)
value = (F.cross_entropy(logits,y)+F.cross_entropy(logits.T,y))/2
value.backward()
g = (logits.detach().softmax(1)+logits.detach().softmax(0)-2*torch.eye(3,dtype=dtype))/6
assert torch.allclose(u.grad,g @ v.detach()/tau,atol=1e-12)
assert torch.allclose(v.grad,g.T @ u.detach()/tau,atol=1e-12)
print('symmetric_loss',loss.item(),'asymmetric_loss',value.item())
```

这里的非对称例子故意没有做单位范数归一化，只检验点积打分之后的梯度。实际编码器还要经过归一化的雅可比，下一节将单独核对。这种分层实验能在错误发生时指出是 softmax、矩阵方向还是归一化路径有问题，而不是把整个编码器视作不可检查的黑箱。

## 4. 单位球上的几何与温度

<a id="mm-1-detail-14"></a>

### 4.1 归一化的雅可比

当 $`r=\Vert a\Vert _2>0`$、$`u=\frac{a}{r}`$，有 $`\frac{\partial u}{\partial a}=\frac{(I-uu^T)}{r}`$。因此给定上游梯度 $`g`$，原始向量梯度为 $`\frac{(g-u(u^Tg))}{r}`$。它去掉沿单位方向的径向分量，只留下改变方向的切向分量。归一化不是没有梯度，而是约束了梯度如何影响表示。

原始范数越小，局部方向对扰动越敏感，梯度可能更大；范数很大则相反。因此即使最终向量长度固定，原始表示尺度仍影响优化。权重衰减、学习率和归一化下界可能共同影响训练。把单位球相似度当作完全没有尺度问题，会漏掉这一层参数化效应。

<a id="mm-1-detail-15"></a>

### 4.2 温度与可学习 log 尺度

较小温度放大 logits 差异，使竞争更尖锐；较大温度使分布接近均匀。梯度中既有显式的温度倒数，也有 softmax 概率变化，所以不能只说温度减半就让所有参数梯度翻倍。若模型已经把正例分得很开，概率项可能接近饱和，某些梯度反而很小。

若设尺度为 $`e^\gamma=\frac{1}{\tau}`$，则 $`\frac{\partial L}{\partial\gamma}=\sum_{ij}G_{ij}S_{ij}`$。可学习尺度可能通过持续放大已有间隔降低训练损失，却不改善检索排序。应同时观察尺度、独立候选排名与校准，必要时采用明确范围约束。排序不变不意味着概率不变，因此训练损失下降也可能主要来自尺度。

<a id="mm-1-detail-16"></a>

### 4.3 实验二：归一化梯度和尺度导数

下面把两个原始向量归一化，直接比较自动微分与切空间公式，并通过中心差分核对一个方向。随后验证可学习 log 尺度的导数。有限差分在非零向量和普通尺度处进行，不用它证明下界截断点上的光滑性。

```python
import torch
import torch.nn.functional as F
torch.set_num_threads(1)
a = torch.tensor([1.2,-.7,.3],dtype=torch.float64,requires_grad=True)
g = torch.tensor([.4,.8,-.2],dtype=torch.float64)
u = F.normalize(a,dim=0)
value = (u*g).sum();value.backward()
r = a.detach().norm();ud = u.detach()
manual = (g-ud*(ud@g))/r
assert torch.allclose(a.grad,manual,atol=1e-12)
assert abs(float(a.grad@a.detach())) < 1e-12
direction = torch.tensor([.2,-.1,.5],dtype=torch.float64)
h = 1e-6
fd = ((F.normalize(a.detach()+h*direction,dim=0)*g).sum()
      -(F.normalize(a.detach()-h*direction,dim=0)*g).sum())/(2*h)
assert torch.allclose(fd,manual@direction,atol=1e-9)
base = torch.tensor([[.8,.2],[-.4,.5]],dtype=torch.float64)
gamma = torch.tensor(.7,dtype=torch.float64,requires_grad=True)
s = gamma.exp()*base
y = torch.arange(2)
loss = (F.cross_entropy(s,y)+F.cross_entropy(s.T,y))/2
loss.backward()
G = (s.detach().softmax(1)+s.detach().softmax(0)-2*torch.eye(2,dtype=torch.float64))/4
assert torch.allclose(gamma.grad,(G*s.detach()).sum(),atol=1e-12)
print('normalization_gradient',manual.tolist(),'log_scale_gradient',gamma.grad.item())
```

这两个结果提供了具体排错线索：若归一化梯度包含显著径向分量，先检查公式或实现；若尺度导数不符，检查温度与 log 尺度的定义方向。真实模型中权重共享和其他损失会加入额外梯度，因此应先在隔离的小图上验证，再解释完整训练中的观测。

## 5. InfoNCE 为什么可以看作候选分类

<a id="mm-1-detail-18"></a>

### 5.1 从候选来源推导密度比

设给定查询 $`x`$，一个候选来自条件分布 $`p(y\mid x)`$，其余候选独立来自边缘分布 $`p(y)`$，正例位置均匀随机。根据贝叶斯公式，哪个位置为正例的后验与 $`\frac{p(y_j\mid x)}{p(y_j)}`$ 成比例。因此理想打分可以表示这个密度比的对数，再加不影响同一查询排序的常数。这解释了为什么对比目标能学习跨通道依赖。

该结论依赖候选采样机制。若负例来自另一个分布 $`q(y)`$，理想密度比的分母会改变；若候选相关、按难度筛选或包含多份正例，简单分类推导要重新审视。相似度不是天然语义概率，它对应的是特定候选游戏中的相对证据。理解采样器，才能理解模型被鼓励区分什么。

<a id="mm-1-detail-19"></a>

### 5.2 互信息下界与其使用条件

在标准联合正例、独立边缘负例及相关可积条件下，InfoNCE 期望损失与 $`\log B`$ 的差可构成共享信息的一个下界。它的上限受候选数对数限制，有限评分函数还会使界不紧。这个理论联系不能被改写为“训练损失下降就证明模型学会全部语义”，更不能用一次有限批次的数值当作真实总体互信息的精确测量。

共享信息本身也不等于任务价值。来源水印可以高度可预测，却不帮助对象关系推理；两个通道共同包含的身份标识也可能比语义更容易学。互信息观点说明目标寻找依赖，任务设计与数据干预负责判断这些依赖是否有用。应避免用一个信息论名称替代实际错误分析。

<a id="mm-1-detail-20"></a>

### 5.3 批量增加改变什么

增加批量提供更多竞争候选，可以减少某些容易配对的捷径，但也增加假负例概率、计算和跨设备通信。相似度矩阵的元素数随批量平方增长，编码器前向则通常近似随样本数增长。微批次梯度累积不会自动产生跨微批次的负例交互，因此一般不等价于同样总样本数的一次大批次对比损失。

特征队列可以扩大候选池，但旧向量可能来自较早参数，形成表示不一致。动量编码器能缓和变化，却引入另一套状态与更新规则。使用队列时应记录候选年龄、梯度是否回传和身份去重。把队列当作免费的大批次，会掩盖其近似与计算代价。

## 6. 多正例、假负例与语义粒度

<a id="mm-1-detail-22"></a>

### 6.1 单对标签何时过于严格

一张图可以有多条正确描述，两张不同图片也可以都符合“红色汽车”。若批中只把原始对角配对视作正例，其他正确候选会被当负例推开。这个目标可能有助于实例识别，却与语义检索评价冲突。需要明确任务是找唯一原始配对、找所有语义匹配还是找任一充分描述，不同目标需要不同标签集合。

假负例不只来自重复文本，也来自同一主体的不同视角、同一事件的不同片段和等价描述。精确去重能处理机械副本，无法识别所有语义等价。人工或规则提供多正例标签时，也可能漏标，因此“未标正例”不必然等于已确认负例。训练与评价应保留这种不确定性，而不是把所有批内其他样本都称为真实错误。

<a id="mm-1-detail-23"></a>

### 6.2 两种多正例目标并不相同

设某查询正例集合为 $`P`$，候选概率为 $`p_j`$。集合质量目标是 $`-\log\sum_{j\in P}p_j`$，只要求总概率落在任一正例上；平均正例对数目标是 $`-\vert P\vert ^{-1}\sum_{j\in P}\log p_j`$，鼓励每个正例都获得概率。前者允许集中于一个容易正例，后者更强调覆盖，但也受正例质量和数量影响。

前者对 logits 的梯度为 $`p_j-\frac{\mathbf1[j\in P]\,p_j}{\sum_{k\in P}p_k}`$，后者为 $`p_j-\frac{\mathbf1[j\in P]}{\vert P\vert }`$。这两个公式能直接说明训练激励差异。不能只把二者都命名为“多正例损失”而不写公式。若目标只需找到任一正确候选，集合质量可能合适；若需要均衡覆盖不同描述，平均目标更贴近，但仍要检查描述本身是否同等有效。

<a id="mm-1-detail-24"></a>

### 6.3 实验三：重复正例与两种目标

下面用一个查询的三个候选，前两个都是正例。单正例损失会惩罚第二个正确候选，多正例集合损失则允许概率在两者之间分配。再把一个正例变得极易，检验集合目标与平均目标的差异及解析梯度。这个例子不训练网络，直接揭示标签和目标选择造成的行为变化。

```python
import torch
import torch.nn.functional as F
torch.set_num_threads(1)
s = torch.tensor([4.,4.,-2.],dtype=torch.float64)
lp = s.log_softmax(0)
single = -lp[0]
set_loss = -torch.logsumexp(lp[:2],dim=0)
average = -lp[:2].mean()
assert single > 0.69 and set_loss < 0.002
assert torch.allclose(single,average)
z = torch.tensor([12.,0.,-2.],dtype=torch.float64,requires_grad=True)
p = z.softmax(0)
ls = -torch.logsumexp(z[:2],0)+torch.logsumexp(z,0)
la = -z.log_softmax(0)[:2].mean()
gs, = torch.autograd.grad(ls,z,retain_graph=True)
ga, = torch.autograd.grad(la,z)
target_set = torch.zeros_like(p);target_set[:2] = p[:2]/p[:2].sum()
target_avg = torch.tensor([.5,.5,0.],dtype=torch.float64)
assert torch.allclose(gs,p.detach()-target_set.detach(),atol=1e-12)
assert torch.allclose(ga,p.detach()-target_avg,atol=1e-12)
assert ls.item() < 1e-5 and la.item() > 5.9
print('single/set/average',single.item(),set_loss.item(),average.item())
print('easy-positive set/average',ls.item(),la.item())
```

当所有概率均匀分配在数量为若干的正例之间时，平均正例对数目标的最小值是正例数的自然对数，而集合目标可以趋近零。因此两种目标的绝对数值不能直接排名，正例数量变化还会改变平均目标的基线。应比较共同任务指标，或者明确报告与对应最优参考的差距。

集合损失很小不代表两个正例都被覆盖，平均损失较大也不一定表示语义完全错误。应把指标与目标对齐，分别测任一命中、所有必要类型覆盖或逐正例召回。真实多正例集合大小不同，还会影响样本权重，应先按查询定义归约，再决定是否给不同查询等权。


<a id="visual-example-multimodallearning-01"></a>

### 图解：多正例下对角线并非唯一合法匹配

![多正例下对角线并非唯一合法匹配](images/01-example.svg)

**读图与计算。** 一张图可能同时对应多个合理文本。若只把原始配对的对角项当正例，其余所有项都当负例，就可能强迫模型推开语义相同的描述。图将多个正例标在同一查询行，说明标注粒度与批内负例构造必须共同分析。

## 7. 评价协议决定检索分数的含义

<a id="mm-1-detail-26"></a>

### 7.1 候选池、并列和召回

检索指标至少需要说明查询集合、候选集合、正确集合、排名规则和并列处理。只在一个小批次里寻找原始配对，比在完整库里寻找等价语义简单得多；候选越相似，任务越难。Recall@K 常表示前若干名是否包含任一正例，但有的任务采用相关项覆盖比例，应明确事件定义，不能只给指标缩写。

双向检索还受查询和候选数量不同影响。一张图有五条描述时，图像查询与文本查询的样本单位不一样。若把每条描述都当独立图像查询，会重复加权同一图像。可以按图像、主体或事件分组汇总，并同时保留描述层结果。评价分母应对应未来用户请求，而不是仅由数据文件行数决定。

<a id="mm-1-detail-27"></a>

### 7.2 数据划分与来源依赖

同一视频的相邻帧、同一商品的多视角和同一文档的多个描述应根据目标统一划分。否则测试可能只是找到训练中见过主体的另一张近似图。若目标是新主体泛化，必须隔离主体；若目标是已知主体的新视角，则可以设计另一协议，分别报告。哪种划分合理取决于希望推断的部署情形。

分词器、图像预处理和编码器若在测试来源上训练，也应公开这一信息。固定预训练编码器可以是任务允许的背景资源，但测试标签不能用于选择投影和阈值。零样本通常表示未使用特定任务标签训练，并不意味着模型从未在预训练数据中见过相关图像或概念。应描述具体信息边界，而不是依赖一个宽泛名称。

<a id="mm-1-detail-28"></a>

### 7.3 提示分类与概率校准

可把类别名称放进文本模板，编码后与图像比较，得到一种无需训练新分类头的分类接口。类别描述、模板和候选类别集合都会影响分数。加入一个相似类别可能改变归一化概率，即使所有原始相似度不变。因此 softmax 输出不是无需验证的真实类别后验，尤其在开放世界和未知类别场景中。

模板集成应说明如何聚合：先平均文本向量再归一化，与先算相似度再平均，在有些条件下相关但不总相同。若在测试集上反复挑模板，会引入选择偏差。可以在开发任务上冻结模板集合，再报告独立类和来源表现。分类与检索虽然共享空间，也需要各自的评价与错误分析。

## 8. 对齐表示的局限与研究方向

<a id="mm-1-detail-30"></a>

### 8.1 全局向量的瓶颈

把所有图像细节压到一个向量，便于快速检索，却可能丢掉对象数量、位置和关系。文本整体向量也可能对词序和否定不够敏感。可以构造“人追狗”和“狗追人”、数字数量变化、属性绑定交换等成对测试，保持词项或场景相近，只改变关系。若模型分不开，问题可能在表示粒度而非相似度阈值。

局部区域与词片对齐、跨注意力和结构化监督可以补充细粒度交互，但它们增加计算和标注需求。双编码器能够预先缓存候选向量，跨编码器则往往需要对每个查询候选联合计算。实际系统可以先粗检索再精排，将高效全局表示与细粒度交互组合。下一章会进一步讨论融合和条件生成。

<a id="mm-1-detail-31"></a>

### 8.2 对齐与保留私有信息之间的取舍

如果强迫所有投影信息都只服务跨模态匹配，图像中未被文本描述的细节可能受到较少监督。对齐目标可以与重构、分类或局部任务结合，但不同损失的单位、权重和数据覆盖必须说明。增加辅助目标并不自动改善全部功能，也可能让共享参数梯度冲突。应根据想保留的信息提出具体评价。

一个实用设计是区分用于检索的共享投影和用于下游任务的较丰富表示，再检验两者的作用。不能因为投影向量适合检索，就认定编码器每层都只保留共享内容；也不能因为编码器含有某信息，就认定简单线性读出一定能提取。表示存在性与可访问性之间仍有模型和样本限制。

<a id="mm-1-detail-32"></a>

### 8.3 对比目标的不可识别性

若同时对两侧单位向量施加同一个正交旋转，全部点积保持不变，对比损失与检索排序都不变。因此共享空间坐标没有天然唯一语义。某一维与颜色相关的观察可能随等价旋转消失，不能仅凭坐标相关性宣称识别了因果因素。更可靠的是定义可观测功能、干预输入并检验关系是否稳定。

模态间还可能存在多对一关系。相同文本“一个人”对应许多不同图像，模型无法从这段文本唯一恢复衣服颜色。条件生成应保留这种不确定性，评价也不应把一个参考图像当作唯一答案。对齐学习提供共享线索，而不是消除世界中本来存在的歧义。

## 9. 进阶练习与详细解答

<a id="mm-1-detail-34"></a>

### 9.1 题一：配对不等于语义完全一致

题目：网页图像与标题同在一条记录，能否把标题每个主张都当作图像可见事实？

解答：不能。标题可能谈不可见背景、时间或推测，也可能与图像弱相关。应明确监督是网页配对还是细粒度事实支持。若任务要求视觉依据，需要额外标注或验证。对比损失会利用可预测配对的因素，并不自动区分哪些文字可由像素证明。把记录共现误当逻辑蕴含，会让训练与评价目标错位。

<a id="mm-1-detail-35"></a>

### 9.2 题二：行列 softmax

题目：为什么把行方向损失重复两次不等于双向损失？

解答：两个方向的候选归一化轴不同，非对称矩阵中行概率和列概率一般不同。图像作为查询与作为文本候选面对的竞争不同。只有特殊对称结构才可能恰好得到相同数值。实现时应显式转置矩阵或改变归一化轴，并用非对称例子核对，而不只用对角较大的对称矩阵测试。

<a id="mm-1-detail-36"></a>

### 9.3 题三：批量一的损失

题目：只有一个配对、没有其他候选时，单正例对比损失是多少，能否学习区分？

解答：softmax 唯一候选概率为一，交叉熵为零，logits 梯度也为零。它没有竞争信息，不能单独通过这个目标学习配对区分。可以引入额外候选、队列或其他监督，但这些是改变训练信息。零损失在这里恰好表示任务过于退化，不能被当成模型已经学好。

<a id="mm-1-detail-37"></a>

### 9.4 题四：新增候选改变概率

题目：原来只有一个正确候选，加入九个低分候选，正例概率是否保持一？

解答：不是，只要低分候选有有限 logits，它们都进入分母，正例概率会下降。排名第一可以保持，但交叉熵改变。候选概率是条件于当前集合的相对分配，不是固定语义真实性。比较不同批量或候选池的损失，应说明集合变化，不能把数值升高直接归因于表示退化。

<a id="mm-1-detail-38"></a>

### 9.5 题五：归一化的径向梯度

题目：为何纯余弦目标对原始向量的局部梯度与该向量正交？

解答：非零范数处雅可比为 $`\frac{(I-uu^T)}{r}`$，投影矩阵消除沿单位向量的分量，因此内积为零。它反映局部一阶变化主要改变方向。优化器动量、权重衰减和有限步更新可能改变范数，所以不能推断训练中范数严格不变。归一化下界附近也需要使用实际实现的导数。

<a id="mm-1-detail-39"></a>

### 9.6 题六：温度与排名

题目：对所有相似度统一乘正数，会改变候选排序吗？会改变损失吗？

解答：排序不变，但 softmax 概率与交叉熵通常改变。若正例已领先，增大尺度可降低损失；若错误候选领先，可能放大错误。可学习尺度需要独立监测，训练 loss 下降并不必然说明检索排序改善。尺度还影响梯度，因此它是优化的一部分，不只是显示概率的旋钮。

<a id="mm-1-detail-40"></a>

### 9.7 题七：双向梯度的分母

题目：批量大小为四，两方向各平均后再取平均，logits 梯度的总体分母是什么？

解答：每方向梯度带四分之一，再乘二分之一，合并后为八分之一乘两方向概率残差之和。若直接把两个方向损失求和，则整体多一倍。单独训练时可通过学习率部分补偿整体尺度，但有其他损失或梯度裁剪时行为未必等价。应与目标公式保持一致，而非依赖默认归约。

<a id="mm-1-detail-41"></a>

### 9.8 题八：假负例的后果

题目：两条文本都正确描述同一图，却只有一条被标正例，另一条获得什么梯度？

解答：在单正例行损失中，另一条获得正的 logits 梯度，被鼓励降低相似度。它可能有利于找唯一实例，却损害语义多正例检索。解决需明确正例关系，可以去重、合并标签或使用多正例目标，但这些方法依赖标签质量。不能在没有审核的情况下把所有相似文本都当正例。

<a id="mm-1-detail-42"></a>

### 9.9 题九：集合目标是否覆盖全部正例

题目：集合概率损失接近零，能否推出每条正描述都能被检索到？

解答：不能，总概率可以集中在一个容易正例上。平均正例对数目标更鼓励每条正例有概率，但也可能对噪声正例过度用力。应按实际目标评价任一命中与多样覆盖，并考虑不同描述的重要性。两个目标没有无需条件的普遍优劣，关键在于任务事件与标注结构。

<a id="mm-1-detail-43"></a>

### 9.10 题十：互信息是不是语义保证

题目：两个通道共享唯一水印，对比损失很低，是否证明它学会对象语义？

解答：没有。水印提供强依赖，也能帮助识别原始配对，但不一定迁移到对象关系。互信息联系描述共享可预测性，不自动选择人类希望的语义。可以在移除水印、同来源候选和关系反事实题上评价，检查表示是否仍有效。数据结构和干预证据比理论名称更能支持具体能力结论。

<a id="mm-1-detail-44"></a>

### 9.11 题十一：梯度累积与大批次

题目：四次小批次对比梯度累积，是否等价于一次四倍批量训练？

解答：通常不等价。大批次的每个查询会看到其他微批次的候选，小批次独立损失没有这些交叉分母项。即使总样本数和优化器步数一致，目标也不同。若使用缓存或跨批特征，需要说明是否保留梯度与表示是否新鲜，不能仅因候选数量相同就认定完全等价。

<a id="mm-1-detail-45"></a>

### 9.12 题十二：来源划分

题目：同一商品五个视角随机分到训练和测试，分数能否代表新商品检索？

解答：不能直接代表，主体特征已经出现。它更接近已知商品新视角任务。新商品泛化应按主体分组，必要时还隔离来源和时间。两种协议都可以有价值，但结论不同。样本文件不重复不等于信息独立，尤其多模态数据常由同一事件派生大量记录。

<a id="mm-1-detail-46"></a>

### 9.13 题十三：零样本的具体含义

题目：没有使用下游分类标签训练，就能声称模型从未见过测试概念吗？

解答：不能。预训练数据可能包含相关概念、图像或描述。应准确说明未使用哪些特定监督，公开已知数据边界，并避免过度声称完全未知知识迁移。零样本是任务协议信息，不是数据历史绝对清白的证明。若要研究新概念，需要专门设计来源和时间隔离。

<a id="mm-1-detail-47"></a>

### 9.14 题十四：坐标语义

题目：某嵌入维度与颜色相关，能否认为该维度唯一代表颜色？

解答：不能，因为共同正交旋转保持所有相似度，却改变每个坐标的相关性。它可能是当前参数化下的有用观测，但不具唯一识别保证。研究语义最好定义跨样本功能或方向，并用干预验证，同时承认表示等价类。相关性本身还不能证明因果控制。

<a id="mm-1-detail-48"></a>

### 9.15 题十五：全局检索与关系推理

题目：模型能检索“人和狗”，为何可能分不开“人追狗”和“狗追人”？

解答：全局向量可能主要保留对象共现而弱化关系与词序。两个输入共享大量词项和视觉成分，粗粒度对比数据未必迫使模型区分角色。应使用关系交换、数量与属性绑定测试，并考虑局部对齐或跨交互。提高总体召回不一定修复这种细粒度能力，需要对应证据。

<a id="sec-6-1"></a>

<a id="mm-1-detail-49"></a>

### 9.16 题十六：一个完整的可证伪假设

题目：怎样验证检索提升主要来自语义而非来源模板？

解答：固定主体与语义标签，构造跨来源风格、去水印和同来源困难候选；训练选择只用开发角色，最终按未见来源确认。分别报告原始配对与语义多正例指标，观察改进是否在控制来源后仍存在。若只在模板差异大时提升，应保留捷径解释。假设应预先写明预期变化与替代解释，不能在结果出来后只挑支持样本。

<a id="sec-7"></a>

<a id="mm-1-detail-50"></a>

### 9.17 题十七：双向损失的平移不变性

题目：给整个相似度矩阵加同一个常数，双向损失是否改变？如果只给每一行加各自不同的常数呢？

解答：统一常数不改变任何行或列 softmax，因此两方向损失都不变。逐行加不同常数仍不改变行方向概率，但在同一列里，不同行被加了不同量，列方向概率一般改变。因此单方向允许的平移自由度，不一定是双向共同允许的自由度。这个例子适合测试实现是否真的使用了列目标：若逐行不同平移后两方向都完全不变，应检查是否误把行损失重复计算。

更深一层，打分函数的等价变换应根据完整目标判断。行分类只关心每个查询内部的相对差，双向目标还让候选跨查询竞争。参数正则、归一化和额外任务又会进一步减少等价集合。理解这些自由度有助于解释不同参数产生相同检索，却不应据此认为所有训练状态与后续路径都相同。

<a id="mm-1-detail-51"></a>

### 9.18 题十八：来源比例改变最优密度比

题目：训练负例来自偏向某类描述的分布，而部署候选近似均匀，能否直接把训练分数当部署概率？

解答：不能。候选分类的最优分母与负例采样分布有关，训练可能学到相对于该分布的密度比。若想恢复另一目标，需要明确采样概率、支持覆盖与相应校正，或在合法部署候选上重新评价与校准。未知采样偏差不能靠一个统一温度自动消除，特别当采样依赖内容而非只有类别先验变化时。

排序在某些特殊条件下可以保持，但这也需要证明分母变化不改变候选相对顺序。实际困难负例采样往往恰好依赖内容，不能假设只是常数。报告应同时保存训练候选机制和最终检索池，让读者知道模型在哪一种竞争环境里获得监督，再判断迁移结论是否充分。

<a id="mm-1-detail-52"></a>

### 9.19 题十九：缓存候选与参数版本

题目：编码器已经更新，索引中的候选向量仍来自旧版本，只重新编码查询是否合理？

解答：这是一种混合版本函数，未必与新模型的共享空间一致。若两个版本之间存在非平凡旋转或尺度变化，原来可比较的点积可能失效。应把编码器、投影、归一化和预处理版本绑定到索引身份，更新后按明确策略重建或兼容。小规模固定候选测试可以检验，但不能仅因向量维度相同就视为兼容。

若系统有意使用动量或异步更新，需要将陈旧程度作为方法的一部分，报告候选年龄和效果。在线服务的缓存一致性与训练队列近似属于相关但不同问题：前者影响部署函数身份，后者影响优化目标。把两者分清，能避免一条训练曲线很好却上线检索突降时找不到具体变化。

<a id="mm-1-detail-53"></a>

## 10. 综合研究任务

构造两个通道观测同一低维潜变量的人工数据，加入彼此独立的私有噪声和共同来源标识。先只检验相似度矩阵、双向梯度与归一化，再训练小编码器。分别在新实例、同来源困难候选与来源变化条件下评价，观察模型究竟保留了什么。完整训练将在第 3 章连接跨注意力和阶段选择，本章先把对齐目标的数学与标签含义固定清楚。

同时建立多正例关系，让同一语义有多份观测，比较单正例、集合概率和平均正例目标。按查询定义分母，保留假负例和未审核候选的处理规则。报告训练损失、温度、原始范数、双向检索、逐来源结果以及失败对。每条结论都应指向一个明确变化，避免把多个结构修改合成无法解释的提升。

<a id="sec-7-1"></a>

<a id="mm-1-detail-54"></a>

### 10.1 本章实验的实际范围

三段实验分别核验双向交叉熵梯度、归一化与尺度导数、多正例目标差异，没有使用真实图像、文本编码器或外部服务。它们提供可复算的机制证据，不提供大模型迁移、硬件吞吐或自然语言理解结论。运行仅依赖 CPU 与内存，无需持久化模型权重或索引，读者可先复算梯度，再改变配对关系或温度，检查结论的适用范围。

## 11. 更深入的推导：候选分类与信息量

<a id="mm-1-detail-56"></a>

### 11.1 InfoNCE 下界的一条完整解释路径

令正例位置 $`J`$ 在批量个候选中均匀选取，查询从边缘分布抽样，该位置的候选从查询条件分布抽取，其余候选彼此独立地从边缘分布抽取。记所有候选为 $`Y_{1:B}`$。任何评分分类器的期望交叉熵都不小于最优后验的条件熵 $`H(J\mid X,Y_{1:B})`$，因此 $`\log B-L`$ 不超过候选位置与全部可见输入之间的互信息。

在这个特定生成过程中，单独看候选向量，它们的联合边缘不依赖正例位置，所以 $`J`$ 与 $`Y_{1:B}`$ 独立。另一方面，给定 $`J`$ 后，只有正例候选与查询相关，其余候选独立。因此可以用互信息链式法则把 $`I(X;Y_{1:B},J)`$ 一方面写成原始配对互信息 $`I(X;Y)`$，另一方面写成 $`I(X;Y_{1:B})+I(X;J\mid Y_{1:B})`$。后一项等于位置识别的信息量，前一项非负，便得到标准下界关系。

这条解释清楚指出哪些假设不可随意省略：负例必须来自规定边缘、候选构造必须满足独立关系、正例位置的先验要一致，相关熵和期望需要定义良好。困难负例筛选、队列相关性、多正例和来源分组会改变这套随机过程。仍然可以使用相应损失作为工程目标，但不能不加条件继续把同一个数值当作原始互信息下界。

<a id="mm-1-detail-57"></a>

### 11.2 理论最优打分与有限向量模型

最优候选后验由条件与边缘密度比决定，但实际模型只允许单位向量点积除温度，表达集合受到维度、范数和共享编码器限制。任意复杂的密度比矩阵不一定能由一个低维双编码器准确表示。训练未达到理想分类风险，可能来自表达限制、优化不足、样本有限或标签错误，不能只把所有差距都称作数据量不够。

在固定有限样本上，未归一化打分矩阵写成两个表示矩阵的乘积，秩不超过嵌入维度。归一化进一步限制行向量长度，温度只统一缩放。某些任务需要许多独立关系方向，低维瓶颈可能造成候选拥挤。增大维度可以扩充容量，也会增加存储、索引和统计估计成本。维度选择应在质量与预算之间评价，而不是越大越合理。

<a id="mm-1-detail-58"></a>

### 11.3 数据处理不等式的启发与边界

若两个编码器分别只读取自己的模态，在相关信息量有定义的条件下，编码后表示之间的互信息不能超过原始模态之间的信息。这说明编码器无法从不存在于输入中的事实创造可靠共享证据。它可以借助训练先验作推断，但这种推断有不确定性。文本没有说明颜色，图像没有显示背面，任务就不应假设每个答案都能唯一恢复。

这个原则也不能被误用为“所有压缩都不好”。任务只需要原始信息的一小部分，去掉无关细节可能改善泛化和检索。关键在于对目标充分，而不是逐字或逐像素保留全部。共享投影可以为配对任务压缩，私有分支可以服务其他任务。对信息量和语义充分性的讨论都应明确随机变量与目标，而不是只凭向量维度判断。

<a id="mm-1-infonce-binary"></a>

### 11.4 一个能完整算出下界缺口的二元例子

令 $`X`$ 是等概率的零或一，正例满足 $`Y=X`$，所以真正的配对互信息为 $`I(X;Y)=\log2`$。候选数取二，正例位置 $`J`$ 均匀随机，另一个负例独立服从同一二元边缘。负例有一半概率恰好等于查询。这种重复符合标准边缘负采样，并非采样程序出错，也不能为了让指标好看而偷偷删掉。

当两个候选不同，看到查询就能确定哪个位置来自联合配对，最优后验给正例位置概率一，损失为零。当两个候选相同，二者都与查询相同，观测没有保留哪一个是最初抽到的正例位置的信息；最优后验只能各给二分之一，损失为 $`\log2`$。两种情况概率各一半，故

$$
\begin{aligned}
L^* &=\tfrac12\log2,\\[6pt]
\log2-L^* &=\tfrac12\log2\approx0.3466
<I(X;Y)\approx0.6931.
\end{aligned}
$$

即使评分器无限充分、期望损失完全优化，下界仍少了一半真实互信息。这是有限候选游戏本身的缺口，不能仅靠训练更久消除。与第 11.1 节的链式法则核对，忽略查询而只看候选：候选相同时可以确定 $`X`$，候选不同时对 $`X`$ 仍然一无所知。因此 $`H(X\mid Y_1,Y_2)=\tfrac12\log2`$，相应 $`I(X;Y_1,Y_2)=\tfrac12\log2`$，恰好就是下界未捕获的部分。

有限 logits 还会再增加函数近似缺口。设匹配查询的候选分数为 $`a`$，不匹配者为零。在不同候选情形，正确概率是 $`\sigma(a)`$；重复情形仍为二分之一。因此 $`L(a)=\tfrac12\log2+\tfrac12\log(1+e^{-a})`$。取 $`a=2`$，期望损失约 $`0.4100`$，下界仅约 $`0.2831`$；只有 $`a\to\infty`$ 才趋近前面的最优值。这里的零概率后验通过分数极限实现，不要求有限神经网络真的输出负无穷。例子同时区分了真实依赖强度、候选数限制和有限评分器三个层次。

<a id="mm-1-detail-59"></a>

## 12. 对比学习的几何与优化细节

<a id="mm-1-detail-60"></a>

### 12.1 坍塌表示为什么不是有用的低损失解

如果所有图像和文本都映到同一个单位向量，所有 logits 相同，每个候选概率为批量倒数，损失为批量的自然对数。它无法识别任何配对。在某些完全对称参数点，来自不同候选的向量梯度可能相互抵消，所以不能只凭梯度暂时为零就宣布达到好解。应同时检查表示方差、正负相似度分布和实际检索。

负例竞争倾向于避免所有实例完全重合，但具体训练仍可能受初始化、容量和数据结构影响。多正例目标又会改变哪些样本应该靠近，因此不能把实例分散简单等同于语义更好。一个表示可以高度分散却按水印而非对象组织，也可以在同一语义内合理聚集。几何统计是诊断，不是任务意义的替代。

<a id="mm-1-detail-61"></a>

### 12.2 Softmax 曲率与困难候选

对单方向一个查询，logits 的损失梯度为预测概率减目标，Hessian 为 $`\operatorname{diag}(p)-pp^T`$，是半正定矩阵。统一平移 logits 的方向属于零曲率方向，因为概率只依赖差值。这个结构解释了为何极端尺度改变条件数与局部优化，也说明单纯限制所有 logits 的绝对值不是唯一的稳定办法。

高分负例会得到较大概率与排斥梯度，低分容易负例的直接贡献很小。因此许多负例虽然数量大，却未必提供同等有效监督。困难挖掘可以集中计算，但必须区分真正错误与语义假负例。若专门选择最相似的未审核样本，可能恰好选中漏标正例，反而强化不希望的分离。损失难度与标签可靠性要一起管理。

<a id="mm-1-detail-62"></a>

### 12.3 梯度相互作用与样本冲突

一个图像向量同时服务多个文本查询，共享参数又服务所有图像。某条关系希望它靠近一个方向，另一条关系可能要求远离相似方向。局部 logits 梯度公式明确，却不能保证参数化后每条边的变化都符合其单独愿望。可以在开发小集上检查梯度内积或逐对相似度变化，形成冲突诊断，但这些一阶量不决定全部长期训练动态。

对多任务系统，额外生成或分类损失还会加入不同尺度的梯度。即使各损失都是平均，它们的分母和单位不同，数值相同也不表示贡献相同。应明确每个目标的统计单位，观察共享层和投影层的更新，再选择权重。把所有损失直接相加可以作为基线，但不是无需解释的普遍最优方案。

<a id="mm-1-detail-63"></a>

### 12.4 模态差距与非对称信息

两侧向量可能在共享空间中保留不同均值或分布形状，同时仍实现有用检索。几何上完全重叠不是唯一成功标准。图像提供外观细节，文本只提供选择性描述，它们的信息量与噪声不同；强求逐实例完全相等可能牺牲私有信息。应根据跨模态排名、局部关系和下游目标评价，而不是只看两团散点是否混合。

降维可视化还会改变距离关系。二维图上的聚类和间隔不一定代表原空间的实际近邻，不能单凭漂亮散点证明对齐。应保留原维度相似度统计、检索结果与明确反例。可视化适合发现假设，确认假设仍需要可复算的指标和控制实验。

<a id="mm-1-detail-64"></a>

## 13. 数据关系与监督设计的高级问题

<a id="mm-1-detail-65"></a>

### 13.1 实例匹配和语义匹配存在真实冲突

两张不同照片都对应“白色杯子”，实例目标要求把各自原始标题配回唯一来源，语义目标则可能允许两者互换。若描述本身没有足够细节，唯一实例配对在信息上就不可识别。模型可能只好利用背景、文件来源或拍摄风格。把这种任务当作纯语义学习，会误解它为何寻找捷径。

解决方法首先是定义任务关系：增加更具体描述，允许等价正例，或分别评价实例与语义。不能要求模型同时做到文字完全相同却识别唯一图片，又禁止它使用任何图片私有线索。输入提供的信息决定可达到的识别上限，评价应承认歧义。对于生成任务，同样应允许多个合理输出，而不是把参考文件身份当成唯一真值。

<a id="mm-1-detail-66"></a>

### 13.2 多正例数量与查询权重

若某个主体有十条描述，另一个只有一条，把所有正配对逐条平均会让前者获得更高总权重。若先在主体内平均再按主体平均，则两者权重相同。集合概率目标还受正例集合大小影响：更多正确候选提供更大可接受概率质量。比较数据配方时，需要说明这种数量变化是否是希望的目标变化。

描述质量也不一定一致。一条精确关系描述与一条模糊主题描述可能都合法，却承担不同任务。可以按粒度分层、设定明确权重或使用多任务指标，而不是让一个漏标关系掩盖全部。权重应来自任务需求和开发选择，不应在看到测试结果后只给失败描述降低权重。

<a id="mm-1-detail-67"></a>

### 13.3 增广不变性必须符合语义

图像裁剪可能删除文本提到的对象，水平翻转可能改变左右关系，音频变速可能改变事件持续时间含义。文本改写也可能改变否定、数量或主体绑定。如果仍把所有增广都视为同一正例，训练会鼓励忽略本来重要的信息。增广规则应逐任务核验，而不是因为常用于分类就直接迁移到跨模态配对。

可以将增广分为语义保持、只保持粗粒度主题和语义改变三类。对不同层目标使用不同关系，例如全局主题允许某些裁剪，细粒度关系任务不允许。实际采样后检查关键条件是否仍可见，避免在数据管道中制造无答案样本。增广丰富性有价值，但它必须与监督事件一致。

<a id="mm-1-detail-68"></a>

### 13.4 来源、权限和隐私相关的边界

多模态记录可能包含人脸、位置、声音身份或文档标识。某些共享因素能极大帮助配对，却不一定属于目标允许使用的信息。任务设计应明确可见范围与来源身份的角色，在分组评价中检查依赖。这个问题不能仅通过隐藏文件名解决，因为水印、背景和声音特征仍可能编码来源。

若最终检索库按用户权限变化，候选过滤与缓存应遵守相同范围。对比预训练表示本身并不执行访问控制，向量相似度高也不代表调用者有权获取原始记录。教材的人工实验不读取真实敏感资料，但完整系统设计仍需把表示学习和服务授权分开，以免把算法能力误当作数据访问许可。

<a id="mm-1-detail-69"></a>

## 14. 从理论到可复现比较

<a id="mm-1-detail-70"></a>

### 14.1 查询级配对评价与相关样本

比较两个检索模型时，应在同一查询和候选池上记录逐查询差异。来自同一视频或主体的查询通常相关，重采样时可以按来源组保留其全部查询。若部署目标是随机新主体，来源等权比文件行等权更贴近；若目标是随机请求，则频率权重可能更合理。应在看到模型排名前确定总体和分母。

候选池本身若随机抽样，也会带来额外波动。可以固定池作主要比较，再用多组合法候选评估敏感性。若只为每个模型挑一组最容易候选，排名没有公平含义。大库近似索引还会引入搜索误差，必要时与精确点积搜索做子集对照，把表示质量与索引近似分开。

<a id="mm-1-detail-71"></a>

### 14.2 冻结编码器与端到端训练的比较

冻结预训练编码器只训练投影头，能够降低更新成本，但适应能力受固定特征限制。端到端训练可能改变更细表示，也可能遗忘已有能力。比较时需要记录预训练资源、可训练模块、输入变换、有效样本与搜索预算。使用更强预训练底座的提升，不能全部归于一个新投影损失。

冻结并不自动关闭随机增强或编码器内部随机层。若缓存特征，必须确保缓存对应固定预处理和模式；否则缓存方案与在线方案看到的分布不同。分阶段训练还要保存阶段身份和选择规则。第三章会具体检查冻结内部链与桥接梯度，本章先建立公平比较所需的完整对象定义。

<a id="mm-1-detail-72"></a>

### 14.3 本次三段机制实验的实际结果

双向梯度实验的二乘二损失约为零点一二六九二八，非对称小例子约为零点五四七八二七，全部矩阵梯度断言通过。归一化实验的径向梯度内积接近数值零，log 尺度导数约为负零点二三五九三六。它们验证当前公式与自动微分一致，没有评价任何真实图文数据。

多正例实验中，两个同样高分正例让单正例损失约为零点六九四三八六，集合损失约零点零零一二三九；当只有一个正例极高分，集合损失小于百万分之一，而平均正例损失约为六。这些数值直观展示两种目标的激励差异。它们没有说明哪种目标在所有任务上更优，选择仍取决于希望覆盖的正确集合。

<a id="mm-1-detail-73"></a>

### 14.4 把失败转成下一步研究

若失败集中在否定和关系交换，研究局部交互或细粒度监督；若只在同来源候选失败，研究来源捷径；若训练配对很好而新主体差，研究划分与表示泛化；若概率变尖而排名不变，研究尺度与校准。每种现象都有不同可检验干预，不应统一通过增加批量或延长训练处理。

最后为每个结论保留假设、变量、数据边界、评价与替代解释。强结果可以精确限定，负结果也能积累知识。一个真正详实的章节，不只是提供更多名词，而是让读者知道遇到一个具体失败时，该从哪条公式、哪种标签或哪层执行条件继续追问。这种可延伸的理解，才使后续融合与生成研究有可靠基础。
