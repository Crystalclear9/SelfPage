## 1. 从节点状态到整图预测

<a id="graph-4-detail-2"></a>

### 1.1 输出粒度改变监督接口

图分类输入一组可变大小图，每张图只有一个或若干目标；图回归输出连续性质。节点编码器先产生 $H_G\in\mathbb R^{n_G\times d}$，读出函数将其映射为固定维数 $r_G$，预测头再输出结果。训练损失的独立条目通常是图，而不是图中节点。若把图标签复制到每个节点再平均节点损失，优化目标与先读出再预测一般不同，还可能给大图更大权重。

分子例子有助于区分总量与强度。某些性质近似随原子数累积，某些性质则更像局部平均或特定结构响应。求和、均值和最大值分别对应不同统计偏好，但都不能单靠名字保证适合目标。读出应该保留目标所需信息，抑制无关规模捷径，并在图大小变化时保持合理外推。一个图级任务的设计从目标机制开始，而不是先选择某个池化层。

<a id="sec-1-1"></a>

<a id="graph-4-detail-3"></a>

### 1.2 求和、均值和最大值的手算

设节点标量状态为 $(1,2,5)$。求和读出为八，均值为八除以三，最大值为五。若将每个节点状态复制一次，求和变成十六，均值和最大值不变。若任务是总资源消耗，复制应改变输出，求和偏好可能合适；若任务是平均负载，均值更自然；若任务是是否存在极端危险点，最大值或平滑近似可能合适。

但复制节点状态并不等于复制真实图结构。新增节点和边后，编码器本身可能产生不同状态，因此读出性质应在固定节点表示层面与完整图层面分别分析。比如复制整个不相连分量时，局部编码器会重复相同状态，求和才严格翻倍。若把两个副本额外连接，消息已经改变，不能继续沿用简单复制结论。

<a id="deep-dive-1"></a>

<a id="graph-4-detail-4"></a>

### 1.3 图级不变性并不保证表达充分

只要节点编码器等变，读出对节点排列不变，整图预测就对重编号不变。但不同图也可能产生相同多重集合状态，任何只读这些状态的池化都无法区分。上一章六环与双三角形的例子说明，局部表达限制会传递到图级。换一个更复杂分类头不能恢复读出之前已经丢掉的信息，必要时需要改变编码器或增加合法结构输入。

不变性是正确处理编号的要求，充分表达是识别目标差异的要求，两者不能互相替代。一个永远输出常数的模型完全不变，却毫无预测能力；一个依赖原始编号的模型可能训练分数很高，却缺乏应有语义。检查图模型应同时验证这两类性质，并通过具体任务判断哪些结构信息真正重要。

## 2. 可学习读出与规模效应

<a id="graph-4-detail-6"></a>

### 2.1 注意力读出仍是集合函数

可令分数 $s_i=g(h_i)$，权重 $\beta_i=\exp(s_i)/\sum_j\exp(s_j)$，读出 $r=\sum_i\beta_ih_i$。共享打分与集合内归一化使它对节点排列不变。它允许模型强调特定节点，但归一化仍可能弱化总计数：若整个状态多重集合复制相同比例，输出不变。需要计数时可以拼接节点数或求和统计，而不是假定注意力自动保留全部信息。

注意力读出的权重也不能直接当作因果贡献。某节点权重大可能因为其他节点更弱，输出还取决于状态内容和后续预测头。删除节点会同时改变图消息和读出归一化，不能只看原权重推断完整变化。可以做局部敏感性或节点遮蔽实验，但要明确遮蔽是否保留边和度数，它们回答的是不同扰动问题。

<a id="graph-4-detail-7"></a>

### 2.2 多尺度读出与子图层次

可以在多个消息层分别读出，再拼接不同尺度状态，让预测头选择局部与更广范围的信息。层级池化则尝试把节点合成更粗的超节点，再继续传播。后者需要决定簇分配是否可学习、不同图如何保持隔离、是否保留边权和节点数量。复杂池化增加了结构自由度，也引入额外优化和对称性要求，应以明确目标收益为依据。

若目标只依赖简单局部计数，一层消息加求和可能已足够。若目标需要跨分量交互，简单局部表示读出可能不足，但全连接交互又增加计算。选择应从目标距离和结构出发。读出越复杂，并不自动意味着更好的图泛化，尤其当训练图很少而每图节点很多时，自由度仍主要受图级样本数限制。

## 3. 异质图与关系专属消息

<a id="graph-4-detail-9"></a>

### 3.1 节点类型、边类型和属性语义

异质图包含不同实体类型与关系，例如用户、商品、商店，以及浏览、购买、供货等边。不同类型的原始属性维数可能不同，需要类型专属输入映射到共同隐藏空间，或保留不同隐藏空间并为关系定义相应变换。把类型编号当作连续数值直接相加，会引入没有语义的大小顺序。类别应使用明确编码或专属参数。

关系方向同样重要。用户购买商品，与商品被用户购买，可以作为两个方向不同的关系通道；它们可以共享部分参数，也可以独立学习，但应在公式中明确。反向边的出现不表示业务上存在逆交易，而是为允许的信息流提供计算路径。若时间预测不允许某条事件在当前可见，正向与反向计算边都不应出现。

<a id="sec-2-1"></a>

<a id="graph-4-detail-10"></a>

### 3.2 关系卷积的一种形式

设关系类型为 $r$，$\mathcal N_r(i)$ 为通过该关系向 $i$ 发送消息的邻居，一种关系消息层为

$$
h_i'=\sigma\left(W_0h_i+\sum_r\sum_{j\in\mathcal N_r(i)}\frac1{c_{i,r}}W_rh_j\right).
$$

其中 $c_{i,r}$ 可选关系内邻居数量，也可使用其他明确归一化。先按关系内均值再跨关系求和，会让每种存在的关系拥有相近的总尺度；把所有边统一均值则让边数较多的关系更有权重。二者不是同一个算子。不存在某种默认归一化能适合所有多关系业务，需要结合关系频率和目标机制选择。

如果关系很多，每个关系一个完整矩阵可能参数过多。可使用基分解 $W_r=\sum_ba_{r,b}V_b$，共享少量基矩阵并学习关系系数。这限制了关系变换的自由度，可能改善稀有关系估计，也可能造成欠拟合。相关方法背景见[关系图卷积原论文](https://arxiv.org/abs/1703.06103)。本章手算与实验只验证明确写出的简单关系层，不复现实证榜单。

<a id="graph-4-detail-11"></a>

### 3.3 边属性不等于关系类型

边类型是离散语义，例如购买与浏览；边属性是该次关系的具体数值，例如金额、时间差和距离。可以让消息为 $\phi(h_i,h_j,z_{ij},r)$，既选择关系变换，也用连续属性调节内容或强度。若金额单位从元变为分，处理流程应相应转换，不能期待模型自动识别。边属性标准化也需要遵守训练与预测的信息边界。

同一节点对可能有多次事件。把它们聚成一条边时，要说明保留次数、总额、最近时间还是整个序列；不同聚合对应不同充分统计假设。未来预测中只应聚合截止前可见事件，不能用完整历史总额再遮住未来标签。若保留事件序列，模型要同时处理时间顺序和邻居无序性，这两种结构不能混为一谈。

<a id="graph-4-detail-12"></a>

### 3.4 元路径提供组合语义也增加风险

作者—论文—作者可表示合作关系，用户—商品—用户可表示共同兴趣。一条元路径相当于指定关系序列，再把多步连接转成某种组合特征。它能提供领域先验，但路径数量可能迅速增长，热门中间节点可能支配结果。若路径包含预测后的事件，预计算会引入未来信息；若把标签关系本身用于路径，也可能直接编码答案。

比较元路径方法时，应报告路径语义、权重、去重和时间过滤规则。不能只说使用二跳结构，因为不同关系顺序含义不同。路径特征也可能使单层模型具有更广的原始图感受野，因此与普通两层模型比较时要把预处理成本和输入信息算进去，避免只按神经层数比较计算深度。

## 4. 多图批处理必须严格隔离

<a id="graph-4-detail-14"></a>

### 4.1 块对角邻接与节点偏移

把多张图拼成一个批次时，节点特征沿行连接，邻接矩阵形成块对角结构。边表实现需要给后续图的节点编号加累计偏移。另有图归属向量 $g_i$ 指明每个节点属于哪张图，读出按这个向量分组累加。任何跨图边都应被视为构造错误，除非任务本来就定义图间关系。批次只是并行计算容器，不应创造新的业务连接。

块对角传播对每个块独立执行，所以无跨图统计的局部编码器输出应等于逐图单独计算。这个性质可以直接测试：将两张图打包计算，再拆开与单图结果比较。若不一致，优先检查边偏移、度数计算、图读出归属和批内归一化，而不是先怀疑模型表达能力。隔离测试能发现许多训练仍会下降的隐蔽错误。

<a id="graph-4-detail-15"></a>

### 4.2 批内统计可能形成跨图耦合

即使没有跨图边，某些归一化若用整批所有节点计算均值方差，也会让一张图的输出依赖同批其他图。训练时这种耦合可能是有意设计，但评估时应使用正确模式和固定统计。若服务单图推理，训练中的图大小分布和批组成可能影响结果。图级归一化与节点通道归一化具有不同归纳偏置，不能仅凭名称判断相同。

一个实用测试是保持图甲不变，换掉批次中的图乙，观察甲的评估输出是否变化。若模型设计要求单图独立，这应保持一致；若设计显式利用批次统计，则应说明其部署接口。尤其不能让测试批的标签或结果参与归一化或图构造，否则批处理可能成为绕过掩码的信息路径。

<a id="graph-4-detail-16"></a>

### 4.3 空图、孤立点与填充掩码

某些任务允许没有边的图，但通常仍有节点；真正零节点图的读出需要单独定义。均值在零节点情况下未定义，不能静默除零。若采用填充张量，把不同图补到相同节点数，填充节点必须在消息、度数和读出中都被正确屏蔽。只在最后输出时掩码，前面传播已可能混入虚假节点。

不同框架可能默认自动加自环，或默认边表不含重复。自定义批处理时需统一这些约定。节点数与边数应作为输入元数据保留，不能仅从最大索引推断，否则末尾孤立节点容易消失。一个完整数据契约要覆盖节点总数、边方向、图归属、关系类型和属性单位，图模型不能代替这些检查。

## 5. 数据划分围绕真正独立单位

<a id="graph-4-detail-18"></a>

### 5.1 同来源图并不独立

多个图可能来自同一个患者、同一设备、同一分子骨架或同一个原始程序。若随机拆图，训练测试可能共享强烈来源特征。此时分数更接近对已知来源新片段的预测，不一定反映新来源泛化。应该根据目标把同来源放在同一划分，或者分别报告已知来源和未知来源表现。图数量很多不保证独立信息很多。

标准化、词表和特征选择应在训练来源拟合。开发来源用于调参和早停，测试来源最后一次报告。若先用完整数据挑图特征，再按来源切分，测试已影响输入选择。构图超参数如距离阈值、邻居数和边筛选也属于模型选择流程，应纳入同样边界，而不是被排除在神经网络训练之外。

<a id="graph-4-detail-19"></a>

### 5.2 时间划分与重新训练策略

若图随时间生成，可以先训练早期来源、开发中期、测试后期，同时保证重复实体的处理符合目标。严格新实体预测与已知实体未来预测是不同任务。前者可能要求实体不重叠，后者允许历史实体但仅用过去数据。报告应写清是哪一种，不能把按时间划分当作自动解决全部泄漏的保证。

部署中模型可能定期重新训练，也可能只更新图状态。离线评估应重现这个节奏。若测试期每周重训，训练窗口、开发策略和可见标签延迟都需定义；若冻结参数，不能在测试后根据全部表现挑最佳检查点。一个完整预测系统包括更新时间与数据可用性，这些规则和层公式同样重要。

## 6. 消融、成本与图级解释

<a id="graph-4-detail-21"></a>

### 6.1 无边、无属性与关系打乱

无边基线保留节点属性并独立编码，再图级读出，衡量结构是否提供增量。无属性基线只使用固定初始值或简单类型，衡量结构统计本身的作用。关系打乱可以检查类型语义，但需要保留哪些边数和度数应明确。完全随机图会同时改变很多性质，因此结果只能说明这种整体扰动的影响，不能单独归因于某一种结构机制。

边属性消融也要注意尺度。例如把金额全部设为零，若零在标准化后表示均值，和原始零金额不是同一含义。类型消融若删除一种关系，还会改变度数和归一化，因此它同时改变消息内容与其他边系数。可以分别做固定系数屏蔽和重新归一化删除，说明二者对应不同问题，而不强迫一个实验承担全部解释。

<a id="graph-4-detail-22"></a>

### 6.2 质量随预算而非单个最好分数

报告参数量、实际消息边数、训练时间、峰值内存和推理延迟，有助于判断模型收益是否值得成本。多个小图的批次可能由最大图支配显存，平均节点数不够说明资源需求。大图也可能使高阶池化不可运行。应该记录图大小分位数、失败情况和截断规则，否则性能比较可能只在成功样本上成立。

图级模型还可能利用规模捷径。若训练时某来源的大图更容易为正，求和读出可能学到节点数；测试来源规模关系反转后性能下降。可以增加仅规模基线，并按图大小分组评估。规模并非天然非法，某些目标确实依赖它；关键是区分真实机制和偶然来源关联，避免一概删除或一概信任。

<a id="graph-4-detail-23"></a>

## 7. 图级风险、权重与不确定性

<a id="graph-4-detail-24"></a>

### 7.1 平均每图与平均每节点不同

若每张图损失为 $\ell_g$，平均图风险是 $G^{-1}\sum_g\ell_g$。若按节点数加权，则是 $\sum_gn_g\ell_g/\sum_gn_g$，大图影响更大。两者对应随机抽一张图与随机抽一个节点所属图的不同目标。图标签任务通常先考虑每图风险，但业务请求可能具有不同频率，应按实际目标事先规定权重。

多个图来自同一个来源时，平均每图又可能让产图频率高的来源占更大权重。可以先来源内平均，再来源间平均，得到每来源风险；也可以报告请求加权风险。不要只选分数更好的聚合方式。学习材料应帮助读者明确比较对象，而不是把所有指标压成一个没有抽样含义的小数。

<a id="sec-6-1"></a>

<a id="graph-4-detail-25"></a>

### 7.2 自助区间的单位

若测试来源可近似独立，重采样来源并保留其全部图，通常比独立重采样节点更符合新来源泛化目标。比较两模型时使用相同重采样来源，计算配对差异，减少无关波动。区间仍依赖测试来源是否代表目标分布，不能修复系统性域偏移。只有少数来源时，区间本身也可能不稳定，应结合每来源结果查看。

重复训练多个种子主要反映算法随机性，不等于数据抽样不确定性。可以先对每来源平均多个种子的预测或损失，再报告来源间差异，也可以分别展示两类波动。若最终部署只选一个模型，种子集成又是额外预算，应与单模型结果区分。统计汇总必须忠实反映实际使用方案。

## 8. 链接预测的候选与负样本

<a id="graph-4-detail-27"></a>

### 8.1 先定义预测事件

链接预测可能表示补全当前知识图谱中的缺失事实，也可能预测未来一段时间内的新交互。前者通常在静态不完整图上推断，后者需要严格时间快照。未观察边不一定是真负例，因为记录可能缺失、曝光不足或时间尚未到。损失中使用负标签，是一种关于观测和目标的假设，必须写清时间窗与候选范围。

无向边应统一节点对表示，避免同一关系以正反顺序落入不同划分。若编码器输入保留了待预测测试边，便可能直接读取答案；训练、开发和测试边的删除及反向边处理必须一致。结构特征如度数也应从合法消息图重算，而不是先在完整图计算再删目标边。图输入本身是标签泄漏的重要路径。

<a id="graph-4-detail-28"></a>

### 8.2 负采样分布定义训练问题

随机从全部未连边对取负样本通常容易，真实候选可能局限同地域、同类型或已曝光对象。训练若主要学会区分不合法候选，实际排序可能很差。可以使用类型约束或困难负例，但困难采样也可能增大未标记正例比例。需要记录采样分布、每正例负样本数、是否有放回、是否每轮重采样，以及是否使用预测时不可能获得的信息筛选。

在病例对照式采样中，训练正负比例一般不同于真实候选概率，因此 sigmoid 输出不自动是部署概率。若已知抽样与类别先验，并满足相应假设，可以调整截距或重新校准；不能仅因为使用二元交叉熵就把分数称为真实发生概率。排序任务可以先关注相对次序，但决策阈值与资源分配仍需合法开发数据校准。

<a id="graph-4-detail-29"></a>

### 8.3 排序指标依赖候选集合

对每个查询，倒数排名为正确目标排名的倒数，平均后得到 MRR；Hits@K 检查是否进入前 $K$。候选数量越多或越困难，指标通常越低，因此不同候选规则下分数不可直接比较。并列分数如何处理也需要明示：乐观、悲观和平均排名会给出不同值。负样本随机种子应固定或多次报告，不能为模型挑最容易的一批候选。

知识图谱评估有时使用过滤规则，排除其他已知为真的目标，避免把合法替代答案当作负例。过滤集合是否允许包含测试事实，取决于固定基准协议；它属于评估定义，并不表示训练编码器可以读取测试边。训练可见图和评估过滤信息必须严格分开。用于未来预测时，使用未来事实过滤还可能改变实际候选难度，应另行说明。

## 9. 四个独立可运行 CPU 实验

<a id="graph-4-detail-31"></a>

### 9.1 实验一：图批隔离与读出

先把两张不同大小的小图构成块对角矩阵，验证批量传播等于逐图传播，再按图归属向量聚合。修改第二张图属性时，第一张图输出应保持不变。这是有明确失败判据的性质测试，能发现边偏移与错误跨图统计。实验采用密集小图方便阅读，数学性质同样适用于正确的逐边稀疏实现。

```python
import torch

torch.set_num_threads(1)
torch.set_default_dtype(torch.float64)
b1 = torch.tensor([[1., 1.], [1., 1.]])
b2 = torch.tensor([[1., 1., 0.], [1., 1., 1.], [0., 1., 1.]])
x1 = torch.tensor([[1., 0.], [2., 1.]])
x2 = torch.tensor([[3., -1.], [0., 2.], [-2., 1.]])
def norm(b):
    d = b.sum(1)
    return d.rsqrt()[:, None]*b*d.rsqrt()[None, :]
b = torch.block_diag(b1, b2)
x = torch.cat([x1, x2])
h = norm(b) @ x
assert torch.allclose(h, torch.cat([norm(b1) @ x1, norm(b2) @ x2]))
group = torch.tensor([0, 0, 1, 1, 1])
pooled = torch.zeros(2, 2)
pooled.index_add_(0, group, h)
assert torch.allclose(pooled[0], h[:2].sum(0))
assert torch.allclose(pooled[1], h[2:].sum(0))
x_changed = x.clone()
x_changed[2:] += 100
assert torch.allclose((norm(b) @ x_changed)[:2], h[:2])
perm = torch.tensor([1, 0, 4, 2, 3])
hp = norm(b[perm][:, perm]) @ x[perm]
pp = torch.zeros_like(pooled)
pp.index_add_(0, group[perm], hp)
assert torch.allclose(pp, pooled)
assert torch.all(group[torch.nonzero(b, as_tuple=True)[0]] ==
                 group[torch.nonzero(b, as_tuple=True)[1]])
print('batch isolation/group readout/permutation assertions passed')
```

单图输出相同并不涵盖所有训练模式，尤其没有覆盖使用批内统计的归一化层。若加入这些操作，应重新定义并检查预期性质。这里的节点归属不是可学习属性，也不输入分类头，它只负责把批次容器重新拆成原始图，避免模型利用批次顺序记忆标签。

<a id="graph-4-detail-32"></a>

### 9.2 实验二：关系内均值与边属性

构造四个节点、两种有向关系，消息先按关系矩阵变换，再乘边的标量强度。每种关系按接收者邻居数求均值，最后加入中心通道。代码同时用逐边索引累加和显式循环手算验证，不把类型编号当作连续权重。它展示了关系方向、参数选择和分母来源三个独立约定。

```python
import torch

torch.set_default_dtype(torch.float64)
x = torch.tensor([[1., 0.], [0., 2.], [3., 1.], [-1., 2.]])
src = torch.tensor([0, 2, 1, 3])
dst = torch.tensor([1, 1, 2, 2])
rel = torch.tensor([0, 0, 1, 1])
strength = torch.tensor([1., .5, 2., 1.])
weights = torch.tensor([[[1., 0.], [0., 1.]],
                        [[0., 1.], [-1., 0.]]], requires_grad=True)
w0 = torch.eye(2)*.2
out = x @ w0
for r in range(2):
    chosen = rel == r
    count = torch.bincount(dst[chosen], minlength=4).clamp_min(1)
    message = (x[src[chosen]] @ weights[r]) * strength[chosen, None]
    aggregate = torch.zeros_like(x)
    aggregate.index_add_(0, dst[chosen], message)
    out = out+aggregate/count[:, None]
manual = x @ w0
for i in range(4):
    for r in range(2):
        ids = [e for e in range(len(src)) if int(dst[e]) == i and int(rel[e]) == r]
        if ids:
            manual[i] = manual[i]+sum((x[src[e]] @ weights[r])*strength[e] for e in ids)/len(ids)
assert torch.allclose(out, manual)
# Relation zero messages into node one: ([1,0]+.5*[3,1])/2.
assert torch.allclose(out[1], x[1] @ w0+torch.tensor([1.25, .25]))
assert torch.allclose(out[0], x[0] @ w0)
out.square().sum().backward()
assert weights.grad is not None and torch.isfinite(weights.grad).all()
print('relation-specific/edge-strength/manual gradient assertions passed')
```

分母是关系内边数量，不是边强度之和。若希望强度加权均值，需要改变分母，并重新检查强度为零和负数时的定义。这个例子不会自动证明某种归一化更好，而是帮助你把每个算子的实际含义写清。边属性与归一化共同决定消息尺度，不能只记录某层使用了关系矩阵。

### 9.3 实验三：完整人工图分类与开发集选点

下面生成独立人工图实例，节点数为八或十二，边均为环。类别零的正负属性交替，类别一的正负属性各自连成一段，两类都恰好一半正一半负，添加很小的独立噪声再随机重编号。目标依赖属性在关系中的排列，而不是图大小或类别频率。该生成器直接使用标签安排结构信号，属于合法的受控机制实验，不是从现实无标签数据自动发现关系。

训练、开发与测试分别使用独立随机流。模型为一层 GCN、ReLU、图内均值读出和线性分类头。每轮只对训练图反向传播，按开发交叉熵保存最佳状态，最后恢复后测试一次。所有状态只保存在内存，不生成权重文件。小图采用块对角密集矩阵，目的为演示完整边界，不作为大图高效训练实现。

```python
import copy
import numpy as np
import torch
from torch import nn

torch.set_num_threads(1)
torch.set_default_dtype(torch.float64)
torch.manual_seed(19)
def make_graphs(count, seed):
    rng = np.random.default_rng(seed)
    graphs = []
    for i in range(count):
        label = i % 2
        n = int(rng.choice([8, 12]))
        b = np.eye(n)
        for j in range(n):
            b[j, (j+1)%n] = b[(j+1)%n, j] = 1
        values = np.tile([1., -1.], n//2) if label == 0 else np.r_[np.ones(n//2), -np.ones(n//2)]
        values = values+.03*rng.normal(size=n)
        perm = rng.permutation(n)
        graphs.append((torch.tensor(b[perm][:, perm]),
                       torch.tensor(values[perm, None]), label))
    return graphs

def pack(graphs):
    b = torch.block_diag(*[g[0] for g in graphs])
    d = b.sum(1)
    s = d.rsqrt()[:, None]*b*d.rsqrt()[None, :]
    x = torch.cat([g[1] for g in graphs])
    sizes = torch.tensor([len(g[1]) for g in graphs])
    group = torch.repeat_interleave(torch.arange(len(graphs)), sizes)
    y = torch.tensor([g[2] for g in graphs])
    rows, cols = torch.nonzero(b, as_tuple=True)
    assert torch.all(group[rows] == group[cols])
    return s, x, group, sizes, y

class GraphClassifier(nn.Module):
    def __init__(self):
        super().__init__()
        self.project = nn.Linear(1, 8)
        self.head = nn.Linear(8, 2)
    def forward(self, batch):
        s, x, group, sizes, _ = batch
        h = torch.relu(self.project(s @ x))
        pooled = torch.zeros(len(sizes), h.shape[1])
        pooled.index_add_(0, group, h)
        return self.head(pooled/sizes[:, None])

train = pack(make_graphs(60, 101))
dev = pack(make_graphs(20, 102))
test_graphs = make_graphs(40, 103)
model = GraphClassifier()
optimizer = torch.optim.Adam(model.parameters(), lr=.03)
criterion = nn.CrossEntropyLoss()
with torch.no_grad():
    initial = float(criterion(model(train), train[-1]))
best_loss, best_epoch, best_state = float('inf'), None, None
for epoch in range(220):
    model.train()
    optimizer.zero_grad(set_to_none=True)
    loss = criterion(model(train), train[-1])
    loss.backward()
    assert all(p.grad is not None and torch.isfinite(p.grad).all() for p in model.parameters())
    optimizer.step()
    model.eval()
    with torch.no_grad():
        dev_loss = float(criterion(model(dev), dev[-1]))
    if dev_loss < best_loss:
        best_loss, best_epoch = dev_loss, epoch
        best_state = copy.deepcopy(model.state_dict())
assert best_state is not None
model.load_state_dict(best_state)
model.eval()
with torch.no_grad():
    final_train = float(criterion(model(train), train[-1]))
    test = pack(test_graphs)
    logits = model(test)
    accuracy = float((logits.argmax(1) == test[-1]).double().mean())
    first_alone = model(pack(test_graphs[:1]))
    assert torch.allclose(first_alone[0], logits[0], atol=1e-10)
    assert torch.isfinite(logits).all() and final_train < initial
    assert accuracy >= .9
print({'initial_train_loss': initial, 'final_train_loss': final_train,
       'best_epoch': best_epoch, 'dev_loss': best_loss, 'test_accuracy': accuracy})
```

高准确率只说明这个人工任务的结构信号容易被当前模型利用，不能外推到分子、推荐或大图生产环境。测试集参与的断言仅用于确认预期演示机制成功，并未用于选择轮数或架构；若在真实研究中反复改生成器与模型直到测试通过，应再生成独立最终测试。当前代码的目标是可复核教学，而不是声称完成一个无条件泛化基准。

### 9.4 实验四：候选难度、并列排名与负边合法性

链接预测实验不训练模型，固定一个正例分数，分别与容易和困难候选比较，再检查平均并列排名。负样本只从给定的可见节点集合及允许类型中产生，排除自环和当前已知正边。代码明确不窥视未来事实；未来未发生关系会如何标注，必须由另行定义的时间窗决定。

```python
import itertools
import numpy as np

def average_rank(positive_score, negative_scores):
    negative_scores = np.asarray(negative_scores)
    greater = np.count_nonzero(negative_scores > positive_score)
    equal = np.count_nonzero(negative_scores == positive_score)
    return 1+greater+.5*equal

assert average_rank(.6, [.1, .2, .3]) == 1
assert average_rank(.6, [.7, .8, .9]) == 4
assert average_rank(.6, [.6, .2, .8]) == 2.5
known = {(0, 1), (1, 2)}
visible_nodes = set(range(4))
candidates = [(i, j) for i, j in itertools.combinations(sorted(visible_nodes), 2)
              if (i, j) not in known]
assert set(candidates) == {(0, 2), (0, 3), (1, 3), (2, 3)}
rng = np.random.default_rng(7)
chosen = [candidates[k] for k in rng.choice(len(candidates), size=3, replace=False)]
assert len(set(chosen)) == 3
assert all(i < j and (i, j) not in known for i, j in chosen)
# Users 0,1 and items 2,3: only cross-type pairs are legal.
allowed = {(u, item) for u in [0, 1] for item in [2, 3]}
observed = {(0, 2)}
negative_pool = allowed-observed
assert (0, 1) not in negative_pool and (2, 3) not in negative_pool
assert (0, 2) not in negative_pool
print('candidate difficulty/tie convention/negative-pool assertions passed')
```

相同正例在两种候选集上的倒数排名分别为一和四分之一，模型本身完全没变。这个例子直接说明指标数字不能脱离候选定义比较。并列规则采用正例与所有同分负例的平均位置；若使用其他基准约定，应替换函数并在报告说明，而不应把不同规则算出的数字混在一起。

## 10. 十六道进阶练习与详细解答

<a id="graph-4-detail-36"></a>

### 10.1 复制节点时哪种读出改变

题目：固定节点状态，把每个状态复制两次，求和、均值与注意力读出如何变化？解答：求和翻倍，均值保持不变，使用共享逐节点打分的归一化注意力也不变，因为每种消息与其指数质量同时复制。这个结论只针对状态集合；若复制后新增边导致编码器改变，必须重新计算。目标若依赖总量，应确认读出仍能读取计数，而不是仅靠训练规模的偶然关联。

<a id="graph-4-detail-37"></a>

### 10.2 图标签复制到节点是否等价

题目：把每图标签复制给所有节点，并平均节点交叉熵，是否等于读出后算图级交叉熵？解答：一般不等价。非线性损失不能与平均任意交换，节点监督还要求每个局部状态都预测整图标签。它可能产生一种辅助学习目标，但不是原图级任务的无条件改写。若按所有节点统一平均，大图还获得更高权重。必须明确监督粒度和图权重，再解释目标变化。

<a id="graph-4-detail-38"></a>

### 10.3 关系内均值与统一均值差在哪里

题目：节点有十条浏览边和一条购买边，先关系内平均再求和，与所有十一条边统一平均有什么区别？解答：前者使两种存在关系各贡献一个均值，后者让浏览数量占更大总尺度。若还使用不同关系矩阵，内容变换也不同。选择取决于边数量是否代表重要性。可以同时输入关系计数，让模型区分均值质量与数量，但应检查稀有关系的统计稳定性。

<a id="graph-4-detail-39"></a>

### 10.4 边强度为零时如何理解分母

题目：按边数归一化时，一条强度零的边是否等于删除？解答：不一定。它消息为零，但仍计入边数分母，从而缩小其他消息。若删除，分母也减少；若采用强度总和归一化，又是另一种算子。需要根据零强度表示无关系、无贡献还是观测到零量来选择。数据清洗与数学归一化之间必须保持一致，不能只看到零消息就认为没有任何影响。

<a id="graph-4-detail-40"></a>

### 10.5 基分解节省哪些参数

题目：有 $R$ 种关系，每个变换为 $d\times q$，使用 $B$ 个基矩阵后参数量如何变化？解答：完整关系矩阵约为 $Rdq$，基分解约为 $Bdq+RB$，另有中心变换和偏置按实际实现计入。当 $B$ 远小于关系数时可能节省很多，但限制关系矩阵位于共享线性张成空间。它可能改善稀有关系估计，也可能无法表达某些独特关系，不能只按参数减少判断优劣。

<a id="graph-4-detail-41"></a>

### 10.6 没有跨图边是否保证独立

题目：块对角邻接已经正确，单图预测仍随同批其他图改变，可能原因是什么？解答：批内归一化、全批注意力、错误读出分组或其他共享统计都可能形成耦合。先用无统计耦合的简单层验证块对角性质，再逐个加入模块。若耦合是设计选择，需要说明部署批组成；若要求单图独立，则应该在评估模式做替换同伴图测试，确认输出不受其他图影响。

<a id="graph-4-detail-42"></a>

### 10.7 填充节点为什么要多处屏蔽

题目：只在最终读出排除填充节点，是否足够？解答：不一定。若填充节点已参与消息、度数或归一化，真实节点状态在读出前就受到影响。应在构图、传播和统计计算中正确处理掩码，必要时完全不为填充创建消息边。对于空图还需明确输出默认值或拒绝规则。模型能产生一个数并不表示其数学定义完整。

<a id="graph-4-detail-43"></a>

### 10.8 图很多但来源很少说明什么

题目：一百位患者各产生一百张图，随机拆一万张图能否代表新患者泛化？解答：通常不能，训练测试可能共享患者特征和测量条件。应按患者划分，必要时同时报告已知患者新片段与新患者结果。独立样本量更接近来源数，而不是图总数。图内节点或片段再多，也不能替代新的环境来源，这会影响置信区间和模型选择的可信度。

<a id="graph-4-detail-44"></a>

### 10.9 每图和每来源风险如何不同

题目：来源甲有九十张图，乙有十张图，直接平均图误差与先来源内平均有什么区别？解答：前者让甲占九成权重，后者让两来源各占一半。若目标是随机请求，前者可能合理；若目标是随机新来源，后者更贴近。两者都应按任务预先选择，不能在看到结果后挑有利指标。报告来源规模与分组误差有助于读者理解权重的实际影响。

<a id="graph-4-detail-45"></a>

### 10.10 留出正边后还要删除反向边吗

题目：无向边以两个方向存储，测试只删除一个方向是否足够？解答：不足，另一个方向仍暴露关系存在，并可能影响度数和多层路径。应把业务边统一为规范无向对，再按这个单位划分，构建消息图时只为合法边生成两方向。结构特征也要从合法图重新计算，不能在完整图上预先计算后继续使用。

<a id="graph-4-detail-46"></a>

### 10.11 随机未连边是否一定是真负例

题目：一个用户未购买某商品，能否标为不喜欢？解答：不能直接这样解释。可能未曝光、暂时未购买、记录缺失或未来才发生。训练可以定义在某时间窗内未观察到购买为负，但目标应按这个定义表述。若希望推断真实偏好，需要额外观测和假设。负采样是监督构造的一部分，不是无意义的数据平衡操作。

<a id="sec-8-2"></a>

<a id="graph-4-detail-47"></a>

### 10.12 容易负例为什么抬高排名

题目：模型面对随机全库负例很好，面对同类型曝光候选很差，是否矛盾？解答：不矛盾，候选任务不同。全库可能包含大量明显不合法或无关对象，模型只需学到粗粒度筛选；曝光候选已通过前级规则，更需要细粒度区分。应报告候选生成与阶段位置，必要时评价完整召回加排序系统。单个 MRR 数字没有脱离候选集合的绝对意义。

<a id="graph-4-detail-48"></a>

### 10.13 负采样后概率为什么可能失真

题目：训练时正负各半，真实候选正例只占千分之一，输出零点八能否解释为百分之八十发生？解答：通常不能直接解释。训练分布先验不同，且负采样可能依赖特征。只有在明确抽样假设和已知先验下，才可能通过截距调整或独立校准得到部署概率。排序可以仍有用，但阈值决策需要在合法开发候选上重新验证。

<a id="graph-4-detail-49"></a>

### 10.14 过滤评估信息能否进入训练

题目：某静态基准允许用已知真事实过滤其他答案，是否表示编码器可以读取测试三元组？解答：不表示。过滤规则用于定义排名评价的候选，不等于训练输入许可。应分别维护训练消息图、开发测试查询和评估过滤集合。对未来预测，还要考虑未来事实过滤是否符合实际信息条件，不能无差别照搬静态知识补全协议。

<a id="sec-8"></a>

<a id="graph-4-detail-50"></a>

### 10.15 人工实验满分说明了什么

题目：本章图分类测试准确率为一，能否证明模型适合真实分子任务？解答：不能。人工生成机制特意制造了局部可学习信号，噪声小、任务简单，结果主要验证训练管道与结构归纳偏置能够按预期工作。它没有覆盖化学属性、三维几何、标签噪声或跨实验室分布变化。教学实验应保留这种边界，真实应用需独立数据和协议验证。

<a id="sec-8-1"></a>

<a id="graph-4-detail-51"></a>

### 10.16 怎样验收完整图任务

题目：训练损失下降之外，还要确认哪些结果？解答：至少包括图批隔离、节点重编号不变、关系方向与分母手算一致、输入无未来信息、来源划分不重叠、开发集独立选点、测试候选合法、指标并列规则明确，以及失败样本和资源边界。每项都对应独立错误来源。只有把模型、数据和评估一起验收，才能判断最终结果究竟回答了哪个学习问题。

<a id="graph-4-detail-52"></a>

## 11. 对人工图分类实验作完整复核

<a id="graph-4-detail-53"></a>

### 11.1 为什么一层传播就有信号

环图含单位自环后每个节点度为三，传播等于自身与左右邻居的平均。交替正负属性中，一个正节点两邻居为负，传播后得到负三分之一；一个负节点得到正三分之一。经过正负方向的投影与 ReLU，可以把幅度统计编码到图级均值。分段类别的内部节点则保留接近正一或负一的值，仅边界附近被削弱，平均绝对响应较大。

因此这个任务的关键不是识别图是否为环，两类图拓扑相同，而是识别属性与结构的对应。只看无噪声属性多重集合，两类都是一半正一半负；只看图大小，类别也不能区分。传播把局部相邻模式转换成可被读出的幅度差异。这个分析说明模型成功有明确机制，而非靠随机种子偶然碰巧得到满分。

带噪后，图级简单属性统计可能产生微小随机差异，但这些差异与类别没有稳定生成关联。若要严格验证无边模型无法从有限样本噪声中偶然受益，可以配对生成相同噪声多重集合，再在两类中以不同结构排列，或在无噪声极限测试。当前实验没有训练完整无边基线，因此不能用它单独证明任何任意复杂无图模型的性能上限，只能说明受控结构信号可学。

<a id="graph-4-detail-54"></a>

### 11.2 训练选点与测试断言的边界

实际运行中，初始训练交叉熵约为零点六八九三，恢复开发最优状态后训练损失约为零点零零二九六，开发损失约为零点零零二五二，四十张测试图准确率为一。最佳轮数是第二百二十轮对应的零起始索引二百一十九。代码每轮查看开发集，测试只在冻结状态后使用，符合当前演示的选点边界。

需要承认，教学作者知道生成机制，也选择了容易解释的模型。测试断言确保演示达到预期，但不能赋予它真实盲测基准的含义。若读者根据这个测试结果继续修改模型和生成器，应另设最终测试流；若只是核对同一固定示例运行正常，则无需把每次执行误说成新的科学发现。教学可复核和研究独立检验是相关但不同的目标。

数值结果也不要求在所有软件版本和硬件上逐位一致。这里使用 CPU、双精度和单线程降低不必要波动，数学断言仍保留合理容差。若换成大规模稀疏或加速设备，应重新核对数值稳定、速度和内存，不应把此处几秒级小图实验外推为生产吞吐。资源结论必须来自对应规模与设备的实际测量。

<a id="graph-4-detail-55"></a>

### 11.3 如何扩展成真正的结构泛化研究

第一步可以在训练中只出现八节点环，开发和测试使用更大环，研究图大小外推。此时类别分段结构的边界比例随大小改变，原有读出统计也会变化，需要分析模型是否依靠固定幅度阈值。第二步改变图拓扑，从环扩展到带捷径图或随机正则图，研究局部排列机制是否仍然成立。第三步增加属性噪声和缺失，观察结构收益何时消失。

这些扩展应预先定义各自目标，不能在测试失败后临时修改标签规则。可以固定训练模型，分别报告大小、拓扑和噪声轴上的质量曲线，再分析哪种变化导致失效。若同时改变三项因素，只看到性能下降，难以判断原因。控制实验使结论可解释，但也需要承认它们覆盖的分布比真实世界窄。

还可加入来源潜变量，例如不同来源具有不同属性偏移或边测量误差，再按来源划分。若标准化用全体数据拟合，会让测试来源影响训练，正好可以用来演示预处理泄漏。合法方案应只用训练来源估计共享变换，或者事先规定每图独立无监督变换，并在部署保持同样规则。生成器越复杂，记录信息可见性越重要。

<a id="graph-4-detail-56"></a>

## 12. 负采样、概率与排序的更深联系

<a id="graph-4-detail-57"></a>

### 12.1 类别抽样如何改变对数几率

假设真实候选中正例先验为 $\pi$，训练采样后先验为 $\pi_s$，且给定类别后的特征分布不变。记真实后验为 $p(y=1\mid x)$，采样后为 $p_s(y=1\mid x)$。由贝叶斯公式，两者对数几率满足

$$
\operatorname{logit}p(y=1\mid x)=\operatorname{logit}p_s(y=1\mid x)
+\log\frac{\pi}{1-\pi}-\log\frac{\pi_s}{1-\pi_s}.
$$

这说明简单病例对照抽样在相应假设下主要改变截距，而不必改变最优排序。假设很关键：若负样本采样依赖特征、难度或节点类型，类别条件分布也改变，单一常数调整通常不够。实际图负采样往往正是特征相关，因此不能机械套用先验公式。应优先在真实候选开发集做校准与阈值评估。

例如训练正负各半，模型输出二分之一，只意味着在采样分布下证据与先验平衡。真实候选正例稀少时，同样特征对应的发生概率可能很低。排序目标与概率目标虽然共享分数，却需要不同验收。一个排序良好的模型也可能概率失准；一个总体校准的模型又可能对稀有来源排序不佳，应按决策用途分别评价。

<a id="graph-4-detail-58"></a>

### 12.2 AUC、MRR 与真实检索成本

二元 AUC 可以解释为随机正例分数高于随机负例的概率，包含特定并列约定。它依赖负例分布，因此容易负样本会抬高结果。MRR 则更关注每个查询正确目标的排名，但也依赖候选数量和难度。两者都不直接给出完整服务的检索成本、曝光反馈或用户收益。若前级召回漏掉真目标，后级排名再好也无法恢复。

完整检索系统应分别报告候选召回率、候选内排序和最终端到端指标。把只在包含真目标的小候选集上评估的 MRR 当作全库检索表现，会高估实际效果。图编码器的近邻索引、缓存时效和新实体冷启动也影响服务。研究可以选择只评估某一环节，但标题和结论应限定到该环节，避免让读者误以为整个系统都已验证。

对于超大候选集合，评估可能只能采样负例。采样估计与完整排名之间通常不是简单线性换算，尤其 MRR 对排名非线性。应使用基准固定协议，或明确报告采样指标，不能把采样名次直接当作全库名次。若采用统计修正，需要给出抽样假设和误差，而不是只补一个比例系数。

<a id="graph-4-detail-59"></a>

### 12.3 训练边与监督边的双重角色

图自编码或链接预测里，一条训练正边可能既作为编码器消息边，又作为监督目标。这样模型可能利用边自身的存在轻易预测它，训练损失与真正补全缺失边的目标不完全一致。某些方案会在每批预测时删除目标边或部分边，再编码上下文；另一些方案明确把输入重构当作训练目标。两者都需要清楚说明，以便理解训练与测试条件是否匹配。

对于多关系图，若一条目标关系的反向类型或近乎等价关系仍保留，也可能形成快捷答案路径。例如预测作者写作关系，另一条数据库冗余字段直接表示同一事实。不能只删除同名边就认为无泄漏，需要追踪关系语义。结构消融和数据来源审计常常比更复杂的解码器更能提高结论可信度。

若用边级小批训练，应明确本批删除目标边后如何计算度数和缓存。沿用完整训练图缓存可能重新引入被删除边的度信息；即使不直接读取其消息，训练目标仍与无边上下文不同。可以有意使用固定原度近似，但需要把近似列入定义和消融，而不应宣称与严格删除完全等价。

<a id="graph-4-detail-60"></a>

## 13. 异质关系与任务契约的扩展

<a id="graph-4-detail-61"></a>

### 13.1 不同类型的重编号应分别保持一致

用户和商品有各自编号空间，重编号时可以对用户做一个置换、对商品做另一个置换，关系矩阵相应按两端变换。类型专属输入映射不破坏这种等变，因为同类型实体仍共享规则。若把不同类型混进一个编号空间，必须防止类型索引与全局偏移冲突，尤其是同一整数在两个类型中代表不同实体时。

类型边界还限制负样本。用户购买商品只允许用户到商品，不应抽用户到用户作为大量容易负例。关系方向也应保持一致，不能让同一业务事实在不同类型通道里泄漏到测试。设计异质图时可以为每种关系建立输入类型、输出类型、时间规则和属性单位的契约，再让构图代码验证每条边符合规则。

<a id="graph-4-detail-62"></a>

### 13.2 关系缺失与观测机制

不同关系记录频率可能不同。购买往往准确记录，浏览可能因隐私设置或设备故障缺失，缺失不代表没有行为。关系卷积把观测图作为输入，并不会自动校正观测偏差。如果某群体记录更完整，模型可能从关系密度推断群体身份，再形成不公平或不稳定的预测。按来源、测量渠道和缺失程度分组评估，有助于发现这种问题。

可以在人工研究中独立控制真实关系和观测关系，测试模型对随机缺失与群体相关缺失的敏感性。前者可能只是方差增加，后者会引入系统偏差。简单随机删边的数据增广不一定覆盖后者，因此不能把对随机丢边稳健解释为对所有数据缺失稳健。观测机制是任务假设的一部分，需要与架构鲁棒性分开研究。

<a id="graph-4-detail-63"></a>

### 13.3 从结果文件回溯完整计算

最终学习资料只需要 Markdown，但其中应足以复核任务定义、公式、输入边界、实验代码、实际输出和限制。复核不要求留下大量生成脚本、缓存或模型文件；本章实验全部内存运行，也没有自动下载。若以后扩展真实项目，保留必要数据版本与模型身份记录属于正式交付的一部分，临时生成物则应清理，两者要根据用途区分。

一个可读模型说明可以按问题连贯叙述：预测对象是谁，预测时能看见什么，图是如何生成的，训练与选择用哪些来源，输出分数如何使用，在哪些条件下尚未验证。这样的说明比堆积库版本和层名称更能帮助使用者判断适用性。技术细节仍可完整保留在代码与推导中，但不应掩盖最基本的任务语义。

<a id="graph-4-detail-64"></a>

### 13.4 下一步研究应从失败样本出发

如果图级模型在大图上失败，先区分规模外推、批处理内存、读出权重与结构复杂度；如果链接预测只对随机负例有效，先检查候选与曝光机制；如果异质关系中某类误差很高，先检查类型频率、属性质量和共享约束。每类失败都对应不同改进方向，不能统一靠加深网络解决。

最终应能把四章知识连成一条完整链：关系语义决定图输入，消息层决定可见局部统计，深度和采样决定传播范围与近似，读出决定整图保留什么，划分和候选决定评估回答哪个问题。任何一环不明确，最后的准确率都可能被误解。掌握这条链以后，你可以更有把握地继续研究高阶图网络、动态图和几何学习，同时保持对证据边界的清醒认识。

<a id="graph-4-detail-65"></a>

### 13.5 关系实验的逐项数值解释

第二个实验中，关系零用单位矩阵，节点一接收节点零的 $(1,0)$ 和节点二经强度二分之一缩放后的 $(1.5,0.5)$，关系内均值为 $(1.25,0.25)$。再加节点一自身的二成状态 $(0,0.4)$，得到 $(1.25,0.65)$。节点零没有接收关系消息，只保留中心状态 $(0.2,0)$。因此“节点在边表出现”不意味着它一定接收消息，还要看发送与接收位置。

关系一采用行向量右乘矩阵的约定，把 $(a,b)$ 变成 $(-b,a)$。节点一作为发送者贡献 $(0,2)$ 经变换后为 $(-2,0)$，再乘强度二得到 $(-4,0)$；节点三的 $(-1,2)$ 变换为 $(-2,-1)$。二者均值为 $(-3,-0.5)$，加节点二中心状态 $(0.6,0.2)$ 后得到 $(-2.4,-0.3)$。显式写出这些值，能防止把书面列向量公式与代码行向量约定之间的转置问题忽略。

索引三对应的节点同样没有入消息，输出就是中心分支。若误按发送者聚合，结果仍可能数值有限、形状完全一致，却不再符合这组手算。这样的对照比只检查参数有梯度更有判定力：梯度存在只能说明计算图连通，不能说明消息走向正确。学习复杂异质图时，可以先对每种关系选一个接收节点完整列账，再扩大到批处理。

<a id="graph-4-detail-66"></a>

### 13.6 正式结果应保留哪些最少信息

一份精简而完整的实验记录至少需要一个输入定义、一套冻结协议、一组可复核结果和一段适用边界。输入定义包括实体、关系、属性与时间；冻结协议包括划分、开发选择、候选和预算；结果包括总体与关键分组指标；边界说明包含没有测过的规模、来源或部署条件。它们可以用连贯 Markdown 表达，不必堆积临时产物。

对本章来说，最重要的结果是三个性质实验与一个端到端人工训练实验确实运行通过，而不是宣称得到现实业务最优模型。没有使用图学习扩展库、没有下载外部数据、没有保存权重或缓存，所以读者可从正文代码直接复现。若将来把代码迁移到真实任务，应重新建立数据契约和评估候选，保留单元性质测试作为底座，再增加与目标风险相匹配的验证。这样既保持最终文件清爽，也不牺牲论证和复核所需的实质内容。

如果需要把结果交给另一位学习者，可以让对方先独立回答三个问题：当前图批次中是否存在意外跨图影响，当前链接预测候选是否对应真实选择范围，当前测试来源是否曾影响图构建或参数选择。对方无需重读全部训练日志，也应能从文档找到明确答案。若答案依赖口头补充，说明任务说明仍不完整，应补在正式章节中。

在进一步探索时，也建议保留一个简单模型作为稳定参照。每增加一种关系、读出或采样策略，都先运行已有小图性质检查，再比较任务质量和预算变化。这样可以知道改动究竟改变了输入信息、函数表达、优化难度还是资源成本。复杂模型的价值应由这些具体变化支持，而不是由模块数量或术语新颖程度支持。完成这种复核以后，再把经验推广到更大的实验，通常更节省精力，也更容易积累可信结论。
