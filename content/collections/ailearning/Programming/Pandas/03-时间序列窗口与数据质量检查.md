## 1. 时间戳先统一语义

<a id="pd3-clocks"></a>

### 1.1 三个时钟决定一条记录能否用于预测

事件时间是业务行为发生的时间，可用时间是相关字段实际进入预测系统、可以查询的时间，决策时间是模型必须给出答案的时间。三者可能相等，也可能相差数小时乃至数月。支付发生在周一、对账表周三到账、模型周二评分，这笔支付属于周二之前发生的事实，却不属于周二已经获知的信息。只有事件时间而没有可用时间的档案，通常不足以准确重放历史上线条件。

设第 $`i`$ 条记录有事件时间 $`e_i`$、可用时间 $`a_i`$，预测锚点为实体 $`u`$ 与决策时间 $`t`$。本章采用严格可用边界，七日历史集合定义为

$$
H(u,t)=\{i:u_i=u,\ t-7\mathrm d\le e_i<t,\ a_i<t\}.
$$

事件窗控制行为距离预测有多远，可用边界控制当时是否知道。两个条件是交集：先发生但晚到达的记录不能进入，提前预告的未来活动即使已经可知，也不属于这里定义的已发生消费。预告活动可以另建特征，不能悄悄放进历史消费口径。若业务允许恰好在决策时刻发布的信息，应把可用条件改为不大于，并说明系统如何保证发布先于读取。

还有第四个常见时间：处理时间，即离线任务实际运行的墙钟时间。十月重跑一月样本时，处理时间变了，决策时间没有变。使用“今天减七天”构造一月历史，会把运行环境误当业务参数。可复现函数应显式接收决策时间、数据快照与规则版本，不能在内部无说明地读取当前日期。

当字段有独立延迟时，整行一个可用时间也不够。订单编号立即可见，拒付结果一个月后才可见，不能因为它们最终在同一行就给两个字段相同的历史资格。可按字段来源拆表，或将字段可用时间作为单独元数据。描述得越接近真实生成机制，后续代码越容易检查；只有一个笼统的更新时间，往往无法区分业务更正与真正新增的信息。

<a id="sec-1-1"></a>

### 1.2 基础算例：为一条预测记录画出时间窗口

在一月十日零点评分，窗口为一月三日零点至一月十日零点，左闭右开。有四笔同一用户的交易：三日零点金额十，九日金额二十，十日零点金额三十，八日金额四十但十一日才到账。前两笔进入，第三笔命中右边界而排除，第四笔因尚不可用而排除，因此总金额三十、事件数二、平均金额十五。只按日期筛选会错误得到七十，包含当前时刻又会得到一百。

这份手算应保留每笔纳入或排除的理由。只保存最后的三十，无法判断代码是否用一笔错误交易抵消了另一笔遗漏。审查时对照的是成员集合与版本，再比较统计值。两个实现恰巧返回同一个均值，不代表它们用了相同的历史；在金额重复或者正负退款相抵时，数值一致尤其容易掩盖逻辑错误。

窗口还必须说明目标对象。如果预测“这笔订单是否欺诈”，当前订单金额可能在提交时已知，是合法特征；如果预测“用户明天消费多少”，明天实际消费额显然不可用。排除当前记录不是普适戒律，真正的标准是预测接口在决策时刻拥有的信息。本章故意采用严格过去条件，是为了使教学实验具备明确、可逐条验证的边界。

<a id="pd3-timezone"></a>

### 1.3 时区、本地日历与夏令时

无时区时间戳只是一组本地钟面数字。上海的九点与纽约的九点一般不是同一个时刻。已经带有时区的时间可以转换到 UTC 比较；没有时区的本地记录必须先依据来源地区赋予时区，再转换。直接对本地字符串使用`utc=True`，相当于宣称原始钟面就是 UTC，不会自动猜出地区。应从来源契约确定含义，不能靠金额模式或日期排序反推时区。

夏令时带来两类问题：春季向前拨钟产生不存在的钟面时间，秋季回拨使某段钟面重复。对于歧义时间，Pandas 提供显式歧义处理；不存在时间也需选择报错、隔离或具有业务依据的调整。本章优先报错或者记录为隔离对象，而不把无法确定的时刻静默移动。具体本地化选项见[Pandas 时间序列文档](https://pandas.pydata.org/pandas-docs/version/2.3.3/user_guide/timeseries.html#time-zone-handling)。

“最近二十四小时”与“前一个本地自然日”不是同一窗口。夏令时切换日可能只有二十三或二十五个实际小时。固定时长可在 UTC 时间轴比较，营业日统计则先按当地日历确定边界，再转换为 UTC。日历特征如星期几也应说明地区：同一 UTC 时刻在不同地区可能属于不同日期。统一存储时区与统一业务日历是两个独立决定。

时间精度同样会改变并列关系。源系统毫秒时间被截断到秒后，本来先后的两笔交易变成并列。不能再用新表的行号假装恢复顺序。若下游需要毫秒内因果次序，应保留原始精度、序列号或可靠日志位置；没有这些信息时，采用整批同时不可见的保守边界，或明确承认只能模拟较粗粒度的决策场景。

**图解。** 横轴是事件发生时间，纵轴是记录实际可用时间。预测时刻为 9 时，两项时间条件必须同时满足；点 (8,10) 位于可用区域上方，即使事件已经发生也不能用于当时的预测。

## 2. 排除当前记录的历史特征

<a id="pd3-row-window"></a>

### 2.1 最近几行与最近几天定义不同总体

整数滚动窗口按观测位置取固定数量候选，时间窗口按时间跨度选取数量不固定的候选。一个用户三笔交易相隔一分钟，另一个用户三笔交易相隔半年；最近两笔都含两个观测，却代表完全不同的行为跨度。为前者估计短期强度、为后者估计长期习惯时，同一个行窗口可能产生不可比较的特征。特征名最好同时携带计量单位与窗口口径。

均值窗口还包含另一个分母：有效非缺失金额数。窗口有三条订单，其中一条金额未知，订单数三、有效金额数二；金额均值如果跳过缺失，估计的是已知金额订单的平均。不能把它标为全部订单平均而不报告覆盖。可同时输出事件数、有效金额数、金额和、覆盖比例，让模型与审查者看见统计值背后的证据数量。

Pandas 对整数窗口与时间偏移窗口的默认最小观测要求不同，因此示例显式写`min_periods`。本章涉及的接口规则可查[rolling 参数文档](https://pandas.pydata.org/pandas-docs/version/2.3.3/reference/api/pandas.DataFrame.rolling.html)；其余窗口选择和信息边界均需要业务自行定义。最小观测要求只是有效值数量门槛，不代表数据覆盖了足够长的历史，也不代表采集系统一直正常。

以一日金额十、二日金额二十、十日金额三十为例，十日之前最近两笔均值十五；过去三日没有交易，因此时间窗为空。若把两者都叫`recent_mean`，模型解释时很难判断究竟是短期无活动还是长期消费偏低。可命名为`previous_2_events_mean`与`amount_mean_3d`，同时给出`events_3d`和`has_history_3d`。

<a id="sec-2-1"></a>

### 2.2 机制展开：先 shift 再 rolling 也要限定实体

在严格按事件顺序评分、每条前序记录立即可见且没有并列时刻的条件下，组内先移动一位再取最近两行，确实可以排除当前记录。分组是必要条件：把全部用户连在一起移动，会使第二位用户首条记录继承第一位用户末条金额。先排序不会改变这个事实，因为排序只排列记录，不会建立隔离屏障。

还要警惕分组滚动输出的索引。某些组合产生实体键与原索引组成的多级索引，直接转成数组赋给原表可能打乱身份。可靠做法是保留唯一行键，通过明确索引或关系连接回填，并核对每个行键恰有一个结果。`transform`适用于输出必须与组内输入等长且按原标签对齐的场合；它不会使内部错误的时间边界自动变正确。

以下实验用累计历史均值说明组内隔离。代码先建立稳定行键，再排序，输出仍通过行键核对；第一条没有历史应为缺失。这里没有延迟、修订及相同时间，因此它只是有条件成立的快速模式，不应直接替换后面的通用历史查询。

```python
import numpy as np
import pandas as pd
pd.options.mode.copy_on_write = True
x = pd.DataFrame({
    'rid': ['a', 'b', 'c', 'd', 'e'],
    'user': ['u1', 'u1', 'u1', 'u2', 'u2'],
    'time': pd.to_datetime(['2026-01-01', '2026-01-02',
                            '2026-01-10', '2026-01-01',
                            '2026-01-02'], utc=True),
    'amount': [10., 20., 30., 5., 7.]})
x = x.sort_values(['user', 'time', 'rid'], kind='stable')
x['prior_mean'] = x.groupby('user', sort=False)['amount'].transform(
    lambda z: z.shift(1).expanding(min_periods=1).mean())
r = x.set_index('rid')['prior_mean']
assert np.isnan(r['a']) and np.isnan(r['d'])
assert r['b'] == 10 and r['c'] == 15 and r['e'] == 5
print(r.to_dict())
```

<a id="deep-dive-2"></a>

### 2.3 深入讲解：滚动窗口的端点排序和信息可用时间

对于时长 $`h`$，左闭右开窗是 $`[t-h,t)`$；默认偏右的时间窗通常对应另一个端点约定。使用`closed='left'`时应把它解释成集合条件，而不是仅仅记住“排除当前行”这个口号。右端排除的是当前时间边界，左端保留恰好早 $`h`$ 的事件。整数窗口的端点还受到位置边界定义影响，不宜把时间窗直觉不加验证地搬过去。

若数据在同一时间有多行，逐行滚动的实现顺序可能与“整批同刻共同排除”的任务不同。最透明的策略是先在同一实体、同一时间下聚合成一个时间点，再按唯一时间点构造严格历史；或者直接以不等式查询。没有延迟的情况下，同刻聚合适合求和、计数；涉及均值要保存和与有效数，涉及方差要保存充分统计量，不能平均各批均值。

`shift(1)`移动的是行值，`shift(freq=...)`移动的是时间标签而保留原值对应关系，二者不能互换。时间窗口上先把金额移到下一行，会把旧交易金额挂在较新时间，窗口成员因而改变。例如一日十元、十日三十元，十日之前三日窗口本应为空；把一日十元移动到十日所在行再滚动，可能错误地将十元算进最近三日。

双时间条件通常不能通过一次简单滚动表达。按事件时间滚动只限制 $`e_i`$，按可用时间滚动只限制 $`a_i`$；我们需要二者同时满足。若每条事件到达时完整且不修订，可以按到达顺序更新状态并按事件时间淘汰过期项。离线参考实现则逐锚点筛选两个条件，虽然较慢，却适合验证优化版有没有改变集合。

<a id="pd3-window-code"></a>

### 2.4 窗口对照实验与手算

下面用唯一时间索引核对行窗口和三日窗口，不把并列时间问题混入基础实验。十日的行窗口包含一日、二日两笔；三日历史则为空。时间窗`min_periods=1`使空集合返回缺失，而不是把“没有观测”直接编成真实零均值。需要零计数时，应另建计数特征，不应由金额均值猜测。

```python
import numpy as np
import pandas as pd
s = pd.Series([10., 20., 30.], index=pd.to_datetime(
    ['2026-01-01', '2026-01-02', '2026-01-10'], utc=True))
row = s.shift(1).rolling(2, min_periods=1).mean()
time = s.rolling('3D', closed='left', min_periods=1).mean()
assert row.iloc[-1] == 15
assert np.isnan(time.iloc[-1])
assert time.iloc[1] == 10
print('最近两笔:', row.tolist(), '最近三日:', time.tolist())
```

## 3. 建立质量规则

<a id="pd3-contract"></a>

### 3.1 硬约束、诊断提示与隔离记录

硬约束表达当前表承诺的结构，例如事件版本键唯一、实体非空、预测锚点唯一、时间可解析、货币单位明确。诊断提示表达值得调查的变化，例如延迟九十五分位突然增大、某来源缺失率上升、退款比例异常。两者需要不同动作：结构不成立时继续聚合会失去可解释性，通常应中断或隔离；分布变化可能是真实业务变化，不应自动删除以让图表好看。

错误隔离表至少保留原始身份、来源、失败字段、原因码和规则版本。若一行同时违反多个规则，可以保留多个原因，但统计删除数时必须按身份去重，不能把原因次数当删除行数。输入总数应等于接受身份数加隔离身份数；接受与隔离集合应不相交。解析失败不能在`errors='coerce'`后从统计中消失，否则缺失会混合原始未知与处理失败。

时间规则也要区分约束与经验。事件时间晚于入库时间，可能是预告事件，也可能是时钟错误；是否拒绝取决于表是否承诺只记录已发生交易。可用时间早于创建时间在某些系统明显不合理，在迁移数据中又可能因为字段语义改变。应记录时钟来源和允许偏差，不能把一个看似自然的不等式推广为所有表的真理。

金额检查要先确定退款模型。如果退款是独立负向事件，负金额可合法；若每行表示已完成订单净额且合同规定非负，负数才违反值域。同一订单既有原始金额又有退款事件时，需要防止重复扣减。窗口金额和的正确性不仅取决于时间边界，也取决于事实粒度是否统一、每次业务变动究竟在哪一行表达。

<a id="pd3-reconcile"></a>

### 3.2 时间质量不能只看全局均值

全局时间单调并不是多实体表的必需条件，组内单调也只是某些算法的输入要求；两者都不证明记录真实先后。应核对原始时钟、排序键、重复时间比例与每个实体的跨度。排序前后的身份集合和金额总和应保持，排序后再验证算法要求的单调性。把时间解析失败行排到末尾再忽略，无法替代正式隔离。

延迟分布最好按来源和时间分层。总体平均延迟稳定，可能掩盖某地区从分钟延迟变成两日延迟；流量大的低延迟来源会稀释问题。可同时报告可用减事件的中位数、高分位、超阈值比例与样本量，并单独列负延迟。负延迟不宜直接取绝对值，因为符号本身能帮助定位时区或字段口径问题。

窗口输出需要四类检查。身份检查保证每个锚点保留；成员检查保证纳入事件与时间条件一致；统计检查保证和、计数、均值满足关系；覆盖检查保证空窗和缺失机制可解释。例如有效数为零时均值应缺失，有效数正时均值乘有效数应近似等于金额和。浮点比较要有尺度相关容差，整数分币金额则尽量精确对账。

数据质量不是一次全表“合格率”。某条规则覆盖了哪些风险、漏掉了哪些情形，应在说明中明确。事件全部被重复两次时，全局均值不变，金额总和翻倍；金额统一乘一百时，排序、空窗比例和计数都不变。不同不变式提供互补证据，没有单个摘要能证明所有业务语义正确。

<a id="sec-4"></a>

## 4. 历史窗口的三个边界问题

<a id="pd3-empty"></a>

### 4.1 空历史、真实零与采集缺口

没有历史交易可以确定计数为零，但均值没有定义；两笔金额十与负十可以确定和为零、均值为零，但并非没有行为；采集接口中断时看不到交易，则连真实计数是否为零也不确定。这三种状态应由事件计数、金额有效数、覆盖状态或采集心跳区分。仅仅输出一个填零金额列，会迫使模型把不同生成机制当成同一种情况。

窗口覆盖还与实体创建时间有关。刚注册两小时的用户过去七日无记录，是短历史；已运营一年但最近七日无活动，是长历史下的沉默。可以增加可观测历史长度、注册至决策的时长、最近采集成功时间，但这些元数据也必须当时可用。用事后补齐的覆盖状态标注历史，仍可能形成信息泄漏。

`min_periods`不会解决覆盖问题。窗口有一条金额就达到门槛，并不意味着七日都被观察；相反，完整观察七日却没有交易，也可能达不到门槛。若需要每日日志完整，必须由日历网格与来源覆盖记录检验；若业务事件天然稀疏，则不宜把无交易日补成未知金额订单。补网格是在定义一个新的统计单位，需要重新解释分母。

<a id="pd3-ties"></a>

### 4.2 同一时刻的稳定顺序不是信息顺序

稳定排序保证相同键的相对顺序可重复，并不证明第一条已经在第二条评分前到达。若同一秒内两笔金额十、二十，系统整秒批量评分，它们应共同看不到当前秒；若系统有可靠毫秒序列与逐条提交记录，第二笔可能看到第一笔。应先写清服务的决策触发机制，再选择整批排除或顺序读取。

事件编号可以打破排序并列，但只有编号具有真实业务先后意义时，它才有资格决定可见性。随机 UUID 的字典序只是确定性规则，不能变成因果关系。若训练时按 UUID 排序、线上按到达顺序读取，模型会在某些样本上拥有不同的历史。这个误差不会因为两边都“稳定排序”而消失。

同时间版本也需要独立规则。同一订单的两个修订在同一可用时间出现，若没有版本号或权威优先级，无法唯一决定有效金额。随意`drop_duplicates(keep='last')`会把文件顺序当成事实。正确处理是取得业务版本规则，或者把冲突隔离并报告；同刻不同事件则应全部保留，不能为了简化窗口把真实交易删掉。

<a id="pd3-grid"></a>

### 4.3 不规则采样、重采样与信息传播方向

重采样把事件放进日、小时等日历箱，能够统一统计粒度，但每个箱的标签、左右闭合与发布时刻都需要定义。将一天交易汇总后标为当天零点，再在当天早晨作为特征，等于把全天结果提前发布。可以标为日末，或者保留箱末与实际可用时间两个字段；标签位置本身不赋予信息可用性。

前向填充适用于某种状态在下一次更新前持续有效的假设，例如最近已发布会员级别。它不适合把未知消费额编成上一笔消费，也不能越过实体边界。反向填充通常把未来观测带到过去，做历史预测特征时必须格外审查；插值同样可能使用右侧未来端点。即使插值曲线平滑，平滑性也不构成预测时可获得的证据。

累计量与流量要分开。累计里程缺测后前向填充意味着暂时沿用上次状态；每日交易额缺测后前向填充意味着假定今天与昨天发生完全相同的流量。若累计量需要差分，计数器重置、退款或设备更换又可能产生负差。时间处理没有与所有字段都兼容的通用填充顺序，必须从每列的生成机制推导。

## 5. 综合算例与实现核对

<a id="pd3-full-contract"></a>

### 5.1 可重放历史实验的输入与预期

我们使用事件版本表和预测锚点表，金额统一采用整数分。每个业务事件可以有多个修订，`available`是该版本进入特征系统的时刻，`version`在同一事件内递增，修订后的金额替代旧金额。事件身份、实体与发生时间在本实验中保持不变。对于每个锚点，先保留严格早于决策时刻可见的版本，再为每个事件选最新版本，最后按事件时间窗口筛选。这里“最新”始终相对于这个决策时刻。

用户甲有五个事件：一月三日十分，九日二十分，十日零点三十分，八日四十分但十一日才可用，另有九日五分。第二个事件在十二日收到金额二十五分的修订。十日零点评分只纳入十、二十、五，总额三十五；十一日零点评分纳入二十、三十、五，总额五十五；十二日零点评分再纳入已到达的四十，总额九十五。修订恰好十二日可用，严格边界使十二日零点仍使用二十而非二十五。

十三日零点评分的窗口起点是一月六日，第一笔十分已经过期；第二笔此时应使用修订后的二十五，加三十、四十、五得到一百。用户乙只有九日七分，十日评分得到七；用户丙没有历史，计数为零、金额和为零、均值缺失。这个小表同时覆盖左端、右端、延迟、并列事件、版本更正与空窗，适合做后续优化的规范答案。

<a id="pd3-full-code"></a>

### 5.2 自足参考实现与逐项断言

```python
import numpy as np
import pandas as pd
pd.options.mode.copy_on_write = True

def utc(s):
    return pd.Timestamp(s, tz='UTC')

raw = [
    ('e1', 'A', '2026-01-03', '2026-01-03', 1, 10),
    ('e2', 'A', '2026-01-09', '2026-01-09', 1, 20),
    ('e2', 'A', '2026-01-09', '2026-01-12', 2, 25),
    ('e3', 'A', '2026-01-10', '2026-01-10', 1, 30),
    ('e4', 'A', '2026-01-08', '2026-01-11', 1, 40),
    ('e5', 'A', '2026-01-09', '2026-01-09', 1, 5),
    ('e6', 'B', '2026-01-09', '2026-01-09', 1, 7)]
events = pd.DataFrame(raw, columns=[
    'event', 'user', 'event_time', 'available', 'version', 'cents'])
for c in ['event_time', 'available']:
    events[c] = pd.to_datetime(events[c], utc=True)
anchors = pd.DataFrame([
    ('a1', 'A', '2026-01-10'), ('a2', 'A', '2026-01-11'),
    ('a3', 'A', '2026-01-12'), ('a4', 'A', '2026-01-13'),
    ('b1', 'B', '2026-01-10'), ('c1', 'C', '2026-01-10')],
    columns=['sample', 'user', 'decision'])
anchors['decision'] = pd.to_datetime(anchors['decision'], utc=True)
assert not events.duplicated(['event', 'version']).any()
assert not anchors['sample'].duplicated().any()
assert not events[['event', 'user', 'event_time', 'available']].isna().any().any()
assert (events['available'] >= events['event_time']).all()
for _, g in events.groupby('event', sort=False):
    assert g['user'].nunique() == 1 and g['event_time'].nunique() == 1
    assert g.sort_values('version')['available'].is_monotonic_increasing

def replay(source, queries):
    rows = []
    for q in queries.itertuples(index=False):
        visible = source.loc[(source['user'] == q.user) &
                             (source['available'] < q.decision)].copy()
        latest = (visible.sort_values(['event', 'available', 'version'])
                  .drop_duplicates('event', keep='last'))
        hist = latest.loc[(latest['event_time'] >= q.decision - pd.Timedelta('7D')) &
                          (latest['event_time'] < q.decision)]
        assert (hist['available'] < q.decision).all()
        assert hist['event'].is_unique
        n = len(hist)
        rows.append({'sample': q.sample, 'n_7d': n,
                     'sum_cents_7d': int(hist['cents'].sum()),
                     'mean_cents_7d': hist['cents'].mean(),
                     'events_used': tuple(sorted(hist['event']))})
    return pd.DataFrame(rows).set_index('sample')

out = replay(events, anchors)
assert out['n_7d'].tolist() == [3, 3, 4, 4, 1, 0]
assert out['sum_cents_7d'].tolist() == [35, 55, 95, 100, 7, 0]
assert out.loc['a1', 'events_used'] == ('e1', 'e2', 'e5')
assert out.loc['a1', 'mean_cents_7d'] == 35 / 3
assert np.isnan(out.loc['c1', 'mean_cents_7d'])
assert out.index.is_unique and set(out.index) == set(anchors['sample'])
# 打乱物理行顺序不应改变答案。
again = replay(events.sample(frac=1, random_state=19), anchors)
pd.testing.assert_frame_equal(out, again)
# 未来修订不能改变过去样本；十倍放大尚不可见版本也应无影响。
future = events.copy()
future.loc[future['available'] >= utc('2026-01-12'), 'cents'] *= 10
pd.testing.assert_frame_equal(out.loc[['a1', 'a2', 'a3']],
                              replay(future, anchors).loc[['a1', 'a2', 'a3']])
print(out[['n_7d', 'sum_cents_7d', 'events_used']].to_string())
```

### 5.3 为什么这个顺序具有历史正确性

对一个固定锚点，第一步按实体和可用时间限制可见集合，因此任何后续操作都不会引入尚未发布版本。第二步在每个事件的可见版本中选最大可用时间与版本号，由输入契约保证这就是当时最新状态。第三步按事件时间限制窗口，最后聚合只作用于合法成员。这是一个依赖明确前提的小证明：如果源表把实际可用时间记错，或者版本号不具有权威顺序，证明的前提就不成立。

本实验假设修订不改变事件身份、实体与事件时间，所以先筛事件窗再在可见版本中选最新，也能保持同一答案；实际系统若允许修订事件时间，这种交换不一定成立。旧版本可能在窗内，新版本已经更正到窗外，先按旧时间筛选会留下本应消失的事实。先恢复当时每个事件的完整状态，再应用业务窗口，是更易解释的规范顺序。

随机打乱测试验证结果不依赖文件物理行序；未来污染测试验证历史查询不依赖不可见版本；成员断言验证身份集合；金额断言验证聚合。它们分别捕捉不同错误，因此都保留。输出并非每个时点都必须单调增长：滑动窗会淘汰旧事件，退款与修订也会降低总和。对所有历史金额强加单调性，会把正确行为误判为数据损坏。

参考实现对每个锚点扫描源表，规模大时成本较高，但它是审查优化的基准。不能因为慢就删除规范版，只保留复杂向量化实现；应在小表和随机小规模上比较两者，再在真实分布上测性能。正确性样本应包含稀疏实体、高并列率、超长延迟、多次修订与窗口刚好过期，而不仅是均匀时间序列。

<a id="sec-6"></a>

## 6. 进阶：事件时间可用时间与窗口泄漏

<a id="sec-6-1"></a>

### 6.1 滚动窗口中的闭区间决定是否看到当前标签

若预测目标本身是未来七日是否购买，则标签窗口可能写成 $`[t,t+7\mathrm d)`$，特征窗口写成 $`[t-30\mathrm d,t)`$，二者在边界处没有交集。但没有交集并非完整的无泄漏证明：一个名为“过去订单状态”的字段可能在未来退款后被回写，时间标签仍在过去，值却包含未来知识。集合边界与版本可见性必须一起成立。

标签与特征也可以来自同一个事件源，只要读取条件不同。例如过去交易次数用于特征，未来交易次数用于标签；二者共享源表不是问题。问题在于是否把未来状态的修订带入过去统计，或在构建全局清洗规则时利用了未来标签。应区分事实来源共享、观测区间共享与决策信息共享，不能仅凭表名判断风险。

训练与测试划分后，测试时点之前已经到达的交易可以成为测试特征，即使这些交易的发生时间落在训练日期范围之外。反过来，训练文件中的一条事后补录记录也可能不合法。数据分区是存储与评估安排，信息可见性是逐样本的时间条件。把每个分区历史清空会制造部署中不存在的冷启动，把所有分区无条件累计又会读取未来。

<a id="pd3-late"></a>

### 6.2 延迟、回补与两种不同的重算目标

延迟事件到达后，至少有两种合理产物。历史决策重放保持当时可见信息不变，过去十日的特征仍是三十五分；事后完整事实统计可以修正十日事件口径下的总额，以支持财务或业务分析。二者回答不同问题，都可以存在，但必须标明时间口径。将事后事实视图用于训练历史在线模型，通常会高估系统当时的信息质量。

如果采用增量状态，晚到事件需要检查事件时间是否仍在当前窗口内。在窗内则加入，在窗外则不影响当前七日指标；修订金额需要先撤销旧贡献再加入新贡献，不能把二十五分的修订当成一笔新增二十五分。若修订把订单取消，则要撤回对应计数与金额，且保留撤销版本。删除原行会失去历史重放能力，因为无法再知道过去曾发布过什么。

所谓“水位线”可理解为系统愿意等待迟到数据的进度约定，而不是自然界保证此后再无晚到事件。超过等待阈值的数据如何处理，需要明确：隔离、进入补算队列、更新事后报表，还是修正未来状态。离线 Pandas 本身不会替我们选择这套策略。教学实现保留全部版本并按锚点查询，避免把工程等待约定误当真实可见边界。

评价延迟策略时，应报告准确性与可用性的权衡。等待更久能获得更完整数据，却可能错过决策时限；严格即时预测信息较少，但更符合服务要求。可以在相同锚点上比较不同容许延迟的合法特征，研究性能随等待时间变化，而不能在离线试验中等待结果到齐后仍声称是实时预测。

<a id="pd3-asof"></a>

### 6.3 merge_asof：最近已知状态不是任意最近记录

`merge_asof`适合为锚点寻找某个有序时间键上的最近候选。做历史已知状态匹配时通常使用向后方向，配合实体键和最大容忍间隔；是否允许恰好同刻匹配必须显式指定。两张表需要按连接时间键整体升序；仅按实体再按时间排序，不一定满足跨实体的整体时间顺序。接口细节见[merge_asof 官方文档](https://pandas.pydata.org/pandas-docs/version/2.3.3/reference/api/pandas.merge_asof.html)。

匹配键应该选表达可用性的时间。把未来才发布的旧事件按发生时间连接，仍然可能泄漏。对于状态表，还可能需要同时满足业务有效时间和系统可用时间；单个最近键连接通常只解决其中一个维度。遇到双时间版本时应先按锚点限制可见版本再确定有效状态，或者使用经证明等价的专门算法，不能因为 API 名称含有 asof 就假定它天然实现完整历史正确性。

`tolerance`表达最近状态最多允许多旧。例如会员状态超过三十日未更新就视为未知，这是一种特征有效期规则，不是对所有字段都合理的默认。价格报价可能只允许几分钟，永久注册日期则无需短容忍区间。未匹配应保留原因：从未发布、发布太晚、状态过期、实体未知。把这些全填成一个字符串，会丢掉可诊断信息。

右表同一实体、同一连接时间出现多行时，应先根据权威版本规则唯一化，或报错。选择哪一行可能影响答案，不能依赖文件排序的偶然性。时间最近也不代表业务优先级最高：人工纠错版本、撤销消息和普通更新之间可能有额外优先关系。应把优先级转换成明确且经过检查的唯一版本，再做最近匹配。

### 6.4 最近状态连接的完整边界实验

实验有十日、十二日两次状态发布，严格排除同刻。十日零点评分不允许使用十日才发布的状态；十一日能用十日状态；十四日能用十二日状态；十六日时十二日状态已超过三日容忍间隔。实体乙没有状态，应保留样本并给出缺失。输出保留样本编号与匹配时间，便于审查陈旧程度。

```python
import pandas as pd
states = pd.DataFrame({
    'user': ['A', 'A'],
    'published': pd.to_datetime(['2026-01-10', '2026-01-12'], utc=True),
    'tier': ['basic', 'gold']})
queries = pd.DataFrame({
    'sample': ['q0', 'q1', 'q2', 'q3', 'q4'],
    'user': ['A', 'A', 'A', 'A', 'B'],
    'decision': pd.to_datetime(['2026-01-10', '2026-01-11',
                                '2026-01-14', '2026-01-16',
                                '2026-01-11'], utc=True)})
assert not states.duplicated(['user', 'published']).any()
r = pd.merge_asof(
    queries.sort_values('decision', kind='stable'),
    states.sort_values('published', kind='stable'),
    left_on='decision', right_on='published', by='user',
    direction='backward', allow_exact_matches=False,
    tolerance=pd.Timedelta('3D')).set_index('sample')
assert len(r) == len(queries) and r.index.is_unique
assert pd.isna(r.loc['q0', 'tier'])
assert r.loc['q1', 'tier'] == 'basic' and r.loc['q2', 'tier'] == 'gold'
assert pd.isna(r.loc['q3', 'tier']) and pd.isna(r.loc['q4', 'tier'])
matched = r['published'].notna()
assert (r.loc[matched, 'published'] < r.loc[matched, 'decision']).all()
print(r[['user', 'tier']].sort_index().to_dict('index'))
```

### 6.5 从规范查询到高效算法

在无修订、可用时间等于事件时间、同刻整批处理的特殊情形，排序后可用前缀和计算区间和。对每个实体保存有序时间与金额前缀，二分查找左闭起点和右开终点，金额和是两个前缀值之差。计数类似，均值由和除以有效数。这个加速成立的原因是成员集合只由单一有序时间维度决定，而不是因为 NumPy 天然比 Pandas 更正确。

存在延迟时，可以按决策时间推进可用事件状态，同时按事件时间维护窗口。若只支持追加且窗口向前移动，堆、队列或平衡索引可能有效；允许任意修订和乱序后，需要能撤回旧贡献并更新对应事件。方差、分位数等统计的维护复杂度也不同：和与计数可加，分位数不能只保存当前一个数值后随意减去过期值。

分区计算还需要携带边界状态。按日期切文件后，每个文件独立滚动会漏掉前一分区历史；带入足够长的过去事件可以修正固定窗口，但延迟版本可能来自更早事件的最新更新，因此“多读七天文件”不一定足够。应按事件时间、可用时间与版本存储组织读取范围，并对跨文件边界的锚点专门测试。

性能评估应固定输入规模、实体分布、修订率、延迟分布与输出契约。只比较总秒数，可能奖励漏做版本筛选的错误实现。先比较成员和统计完全一致，再测峰值内存、排序成本与重复运行成本。对中小数据，清晰的逐锚点规范版有时已经足够；当性能真正成为瓶颈，再承担复杂状态维护的额外验证责任。

<a id="pd3-statistical"></a>

### 6.6 窗口长度改变估计对象与统计误差

扩大窗口通常增加观测数量，却不只是降低同一估计量的方差。若消费水平随时间变化，三十日均值与七日均值对应不同时间分布下的平均行为。长窗更平稳也更滞后，短窗更灵敏也更受稀疏与偶然事件影响。没有脱离任务的“最佳窗口”：应在训练内比较预先定义的候选，并检查不同人群的覆盖，而不能看完整测试期间相关性后决定窗口。

设窗口内金额在给定实体状态下独立、方差相同且有效样本数为 $`n`$，样本均值方差是 $`\frac{\sigma^2}{n}`$。真实交易常有时间相关，同一天多笔受同一活动影响；此时均值方差为所有协方差之和除以 $`n^2`$，并不只由记录数决定。一个用户在一分钟内刷出一百笔，不一定比一个月分散的一百笔提供更多关于长期习惯的信息。计数是证据规模的一部分，不能代替相关结构分析。

指数衰减可以平滑硬窗口的突然过期。例如给历史事件权重 $`w_i=\exp[-\lambda(t-e_i)]`$，加权均值为金额加权和除以权重和。所有事件仍需先满足可用条件；衰减不能让未来事件变合法。半衰期 $`h`$ 对应 $`\lambda=\frac{\log2}{h}`$，需要统一时间单位。若金额缺失，其权重不能进入金额均值分母，却可以进入事件强度的独立分母。零权重和时均值依旧未定义。

在独立同方差假设下，固定权重加权均值方差是 $`\sigma^2\sum_i\frac{w_i^2}{(\sum_iw_i)^2}`$，由此可定义等效样本数 $`\frac{(\sum_iw_i)^2}{\sum_iw_i^2}`$。它说明权重高度集中时，即使有很多历史行，真正决定输出的也只有少数事件。这个量不是对相关交易的万能修正，也不证明模型泛化好，但能帮助解释短半衰期特征为何经常波动。

硬窗口与衰减窗口还会产生不同响应：一笔大额在七日窗左端跨过时，金额和骤降；指数衰减则连续减弱。如果模型对这一跳变敏感，可以同时提供多尺度历史与时间距最近事件，但候选数增多会增加选择偏差和解释成本。应报告哪些尺度在训练阶段确定、哪些在验证阶段选择、最终测试是否保持冻结，而不是让窗口搜索成为隐形的超参数竞赛。

<a id="pd3-observation"></a>

### 6.7 观测机制可能造成选择偏差

事件表通常只包含发生过的行为，而监督样本可能代表所有符合条件用户。直接把每笔交易当成一次评分锚点，会使高频用户出现更多次，也会排除完全没有交易的用户。即使窗口没有泄漏，学习任务仍可能从“每用户每天预测”变成“交易发生时预测”。应独立生成锚点总体，再连接历史；是否允许事件触发锚点，要由真实服务方式决定。

在固定日历锚点下，用户消失也有不同原因：没有行为、退出服务、采集停止、身份迁移。对这些状态统一生成零历史可能造成选择偏差。若目标是活跃账户，需要在每个决策时点按当时已知资格确定样本，而不是用今天仍活跃的账户列表回填所有历史。后者把未来存活条件带入了训练总体，改变了问题本身。

延迟往往不是随机的。高风险订单可能审核更久，大额交易可能跨系统核验，某地区可能批量上报。严格可见窗口因此可能更偏向快速到达的事件。它依然符合部署条件，但解释“历史金额”时应说明这是当时可见金额。可以增加来源覆盖、延迟摘要或已知待处理计数，前提是这些状态在当时可见。不能直接用最终到账总额校正，否则又把未知未来补进模型。

研究上可以比较三个视图：当时可见视图、固定等待后的视图、事后完整视图。差异帮助量化信息延迟造成的性能损失。比较时必须固定锚点总体、标签和评估区间，否则结果可能同时混入选择变化。完整视图的高分可以作为信息上界参考，但只有满足额外获取条件时才能成为可部署方案，不能据此宣称即时系统也能达到同样水平。

<a id="pd3-numerics"></a>

### 6.8 数值稳定、可加统计与诊断分解

金额以整数分存储时，加法可以精确，但必须检查整数范围。单笔合法不代表窗口累计不会溢出；跨币种也不能直接求和，应按当时可用汇率转换并保留转换版本，或者分币种输出。若改用浮点，应区分业务对账容差与机器舍入容差，不能把所有金额差异都归结为浮点误差。

滑动方差尤其容易暴露数值问题。用平方和减去均值平方，在金额基线很大而波动很小时，会发生相近数相减，甚至得到微小负数。直接把所有负数截到零可能掩盖严重错误。可以使用更稳定的中心化算法或维护经过验证的可撤回统计状态，再用小规模直接重算对照；极小负值仅在已证明属于舍入范围时才可按规则截断。对在线更新与删除的组合，应同时测试大数小差场景。

撤回统计可以用中心化量直接推导。对当前 $`n`$ 个有效金额保存均值 $`\mu`$ 与 $`M_2=\sum_j(x_j-\mu)^2`$，删除其中一个已确认存在的金额 $`z`$。当 $`n>1`$，新计数为 $`n'=n-1`$，新均值由总和守恒得到

$$
\mu'=\frac{n\mu-z}{n-1}
=\mu-\frac{z-\mu}{n-1}.
$$

把剩余各项写为 $`(x_j-\mu)+(\mu-\mu')`$，平方后求和，并利用剩余偏差和为 $`-(z-\mu)`$，可化为

$$
M_2'=M_2-(z-\mu)(z-\mu').
$$

这个更新避免直接计算两个量级巨大的平方和之差。取三个金额 $`10^9+1,10^9+2,10^9+3`$，原均值为 $`10^9+2`$、$`M_2=2`$；删除首项后，均值为 $`10^9+\frac{5}{2}`$，$`M_2'=2-(-1)(-\frac{3}{2})=\frac{1}{2}`$，与直接中心化重算一致。若再加入新值 $`u`$，可用 $`\mu_{\rm new}=\mu'+\frac{(u-\mu')}{(n'+1)}`$、$`M_{2,\rm new}=M_2'+(u-\mu')(u-\mu_{\rm new})`$ 恢复同一种状态。均值、中心平方和与计数必须一起更新，否则公式会混用不同时间点。

这里还必须明确三个边界。原来只有一个有效值时，删除后进入空状态，均值未定义，不能令除零结果继续传播；剩余一个值时总体方差为零，但用 $`n'-1`$ 作分母的样本方差未定义；缺失金额退出窗口不改变金额统计的有效计数，但仍可改变独立维护的事件计数。修订金额时应撤回该事件此前生效的版本，再加入新版本，不能只把新金额追加一次。每次删除必须能通过成员身份确认其原本在状态中，仅有一个相同数值并不足以证明删除正确。

中心化撤回也不是任意长序列下的精确运算。反复增删仍会积累舍入，尤其删除后剩余波动远小于旧波动时可能发生抵消。可以按更新次数或误差诊断触发从当前成员重新构造状态，并与直接中心化结果比较；重新计算周期属于算法契约。测试应包含连续删至空、删除后再加入、版本反复修订，以及大基线小波动的数据。单次三点手算通过，只证明局部公式一致，不能替代长期状态漂移检查。

增量状态出现差异时，可建立贡献分解：本次值减上次值，等于新可见事件贡献减过期事件贡献加修订净贡献，再加窗口规则变化的影响。在固定规则下若剩余差无法解释，就说明有丢事件、重复消费或状态恢复问题。对均值不能直接分解均值变化，应先对分子与分母分别分解，再合成结果。这使诊断从“今天波动很大”变成具体哪一类事实导致变化。

可审查性还要求输出身份链。生产表不一定保存每个样本全部事件列表，那可能很昂贵；可以保存查询版本、输入分区、锚点、源版本范围与可追溯摘要，并对抽查样本展开明细。哈希摘要能够帮助发现输入变化，却不能解释一笔交易为什么应该纳入。机器指纹、守恒量与人工可读成员证据各有职责，应结合使用，而不是互相替代。

上线前还应区分无数据与计算失败。查询超时后返回空表，再输出零计数，会把基础设施故障伪装成用户无活动。特征结果应具有计算状态与数据覆盖状态，失败时按产品约定拒绝评分、沿用有有效期的旧结果或走明确降级策略，并记录采用了哪条路径。离线评估也应模拟这些路径，否则只评价全部计算成功的样本，会高估真实服务表现。降级特征的生成规则同样需要版本与时间边界。

最后考虑规则迁移。把七日改成七个自然日，即使列名未变，也已经改变成员集合；把严格发布边界改成允许同刻，也会在高并列来源上集中改变样本。迁移时应在同一冻结输入上并行计算新旧版本，报告变化样本比例、成员增减、金额差异与人群分布，再决定是否重新训练。仅检查输出类型和均值接近，不能证明可以沿用旧模型，因为变化可能集中在最关键的少数事件上。

## 7. 练习与解析

<a id="pd3-ex1"></a>

### 7.1 练习一：三个时钟的手算

**问题：** 事件九日发生、十一日入库、十三日被纠正，十日、十二日、十四日评分各应看到什么？假设首次金额二十，纠正金额二十五，均位于事件窗内。

**解析：** 十日看不到该事件，不能因为九日发生就纳入。十二日看到首次二十版本，十三日之后的修订尚不可用。十四日看到二十五替代二十，而不是二十与二十五相加。每个锚点分别计算可见集合，不能先在全表去重到最终版本再回放。若历史快照只保存二十五，十二日应看到的二十已经丢失，任何窗口参数都无法凭空恢复。

<a id="pd3-ex2"></a>

### 7.2 练习二：左端恰好相等

**问题：** 一月十日零点评分，历史窗为七日左闭右开。三日零点、三日零点前一微秒、十日零点各有金额十，且均提前可用，金额和是多少？

**解析：** 只有三日零点进入，结果十。前一微秒已超出窗口，当前时刻命中被排除的右端。若源时间精度只有秒，不能伪造微秒区分，只能按实际精度测试相邻可表达值。修改窗口为左开右闭后成员会变化，但不是简单“同样也十元”就表示等价；应比较事件身份，金额相同会掩盖边界交换。

<a id="sec-7-1"></a>

### 7.3 边界追问：排除当前行是否等于排除当前时刻

**问题：** 同一用户同一秒两笔金额十和二十，先按事件编号排序再移动一行，第二笔能否使用第一笔？

**解析：** 如果服务整秒批量决策，两笔在同一批，第二笔不应看到第一笔；移动一行会给它错误历史。如果真实服务逐条接收且有可靠先后日志，才可能允许。事件编号排序只证明结果确定，不证明可用次序。完整答案应同时给出决策触发机制、时间精度、并列规则与可用时间，不能只写“用了稳定排序所以安全”。

<a id="pd3-ex4"></a>

### 7.4 练习四：先移动金额再按时间滚动

**问题：** 一日十元、十日三十元，十日过去三日严格历史为空。为什么将金额移动一行后按三日滚动可能得到十？

**解析：** 移动后十元被放到十日的标签下，算法按新标签选择它，原本一日的事件时间信息已经丢失。移动值不是移动事实发生时间。应直接按原事件时间定义不等式，或者在满足无延迟条件时用正确端点的时间滚动。对最近几行问题，组内移动可以正确；对时间跨度问题，不能把相同行为无条件复用。

<a id="pd3-ex5"></a>

### 7.5 练习五：均值零与没有历史

**问题：** 用户甲有十元与负十元退款，用户乙无交易，用户丙的采集服务中断。三人的历史金额和能否都填零？

**解析：** 甲可以确定和为零且事件数二，乙在采集完整的前提下可以确定和零且事件数零，丙则金额总和未知。若产品需要统一数值输入，可以在训练内填补，但同时保留合法缺失与覆盖标记。对丙直接声称“零消费”改变了事实含义。审查应同时核对事件数、有效金额数、采集覆盖和填补来源，而不是只比较最终数值矩阵。

<a id="pd3-ex6"></a>

### 7.6 练习六：平均的平均

**问题：** 同刻批次甲有金额十、二十、三十，批次乙有金额一百。先得到两批均值二十与一百，再求平均六十，能否代表四笔均值？

**解析：** 不能，真实均值为四十。批次均值需要按有效金额数三与一加权，得到 $`\frac{(3\times20+100)}{4}=40`$。若批次包含金额缺失，权重应是有效金额数，而非总事件数；事件计数仍作为独立特征保留。这个反例说明为解决并列时间而预聚合时，要保存可合成统计量，否则窗口语义正确但聚合公式仍然错误。

<a id="pd3-ex7"></a>

### 7.7 练习七：最新状态与未来状态

**问题：** 状态有效于一月一日，二月一日才发布。能否按有效时间向后连接给一月十五日样本？

**解析：** 如果模拟当时系统决策，不能，因为发布时刻晚于决策；如果做事后事实重建，可以按最终有效状态分析，但应标为另一产物。单一有效时间连接无法表达系统当时知道什么。需要先限制发布可见性，再从可见版本中判定当时有效的状态。把发布字段丢掉后再用`merge_asof`，只是高效实现了错误查询。

<a id="pd3-ex8"></a>

### 7.8 练习八：三日容忍与恰好同刻

**问题：** 状态十日发布，十三日评分，容忍三日，严格排除同刻。它能匹配吗？十日评分又如何？

**解析：** 十三日与发布时间恰差三日，容忍边界允许时可以匹配；十日评分由于严格早于要求不能匹配。两个边界作用于不同条件，不要把“严格早于”误解释为“年龄也必须严格小于三日”。实际实现应使用最小表核验，再在契约中保留端点定义。若状态在十日发布后立即失效，还需有效期条件，单纯容忍间隔并不能描述撤销。

<a id="pd3-ex9"></a>

### 7.9 练习九：整表按实体再按时间排序

**问题：** 甲有十日、二十日，乙有一日、二日，按实体与时间排序后，为何最近时间连接仍可能报时间未排序？

**解析：** 全表顺序可能为十日、二十日、一日、二日，连接时间键不是整体升序。分组内部有序不等于算法要求的全局连接键有序。应按连接时间整体排序并使用实体限制匹配，再按样本身份恢复展示顺序。恢复身份要靠键，不要认为输出自然保留原文件顺序。排序要求是算法输入契约，历史可见性仍由连接方向、时钟与端点决定。

<a id="pd3-ex10"></a>

### 7.10 练习十：晚到事件与窗口过期

**问题：** 一日交易在二十日才到达，当前七日金额是否应增加？如果做一月十日的完整财务重算呢？

**解析：** 二十日当前七日窗不包含一日，因此实时七日金额不增加；一月十日的事后完整事实窗也不含一日，因为十日的左端是三日。若改为一月五日的完整事实重算，一日可进入，但五日当时在线重放仍不能进入。此题刻意同时改变锚点和产物口径，提醒不能只看到“晚到”就一律补进所有过去窗口。

<a id="pd3-ex11"></a>

### 7.11 练习十一：未来污染测试

**问题：** 将所有晚于决策时刻的版本金额改为极大值，历史特征不变，是否证明绝对无泄漏？

**解析：** 它证明当前测试输入与修改范围内，输出不依赖这些金额，但没有覆盖未来版本的存在性、实体属性、清洗阈值或标签参与。未来信息也可能通过删除行、选择样本或拟合填补值进入。应扩展污染字段、增加不存在与重复版本反例，并审查完整数据流。测试能为明确性质提供证据，不能代替对所有信息通路的定义与推理。

<a id="pd3-ex12"></a>

### 7.12 练习十二：窗口分区边界

**问题：** 每月独立读取当月交易构造过去七日特征，月初偏低，应该如何修正？

**解析：** 月初窗口跨入上月，需要读取相应历史并保持实体状态。只额外读取七日事件文件在无延迟、无修订时可能足够；若旧事件在当月收到修订，还需读取可用版本日志并恢复其当时状态。修正后应对月末、月初同一连续序列与未分区规范版比较，检查成员集合和统计。把月初统一填均值只掩盖算法截断，不会恢复正确历史。

<a id="pd3-ex13"></a>

### 7.13 练习十三：历史金额不单调是错误吗

**问题：** 同一用户七日金额从一百下降到六十，没有新的退款，是否一定有缺数？

**解析：** 不一定，四十元旧事件可能恰好滑出左端；也可能有合法修订降低金额。应分解变化为新增事件贡献、过期贡献、修订净贡献与覆盖变化，而不是只看方向。对于累计终身金额、滑动金额和当时已知金额，单调性前提各异。只有明确保证非负追加且无撤销的累计量，才自然具有单调不减性质。

<a id="pd3-ex14"></a>

### 7.14 练习十四：设计一个反例矩阵

**问题：** 要审核新的向量化实现，怎样选少量案例覆盖主要风险？

**解析：** 至少包含两个实体防跨组，一笔左端、一笔右端验证端点，两笔同刻验证并列，一笔晚到验证可用边界，一个未来修订验证版本，一位空历史用户验证保留，一条未知金额验证分母，一笔退款验证符号。再随机打乱行序、改变未来数据、分区后重算。每个案例标明预期成员与具体统计，不用“大致合理”替代答案。规范版与优化版共同通过这些案例，再做随机小表对照，才能把性能提升建立在稳定语义之上。
