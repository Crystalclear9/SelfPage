## 1. 先写样本契约

<a id="pd4-unit"></a>

### 1.1 预测单位、决策触发与目标总体

建模前首先问“一行代表什么”。每用户每天一行、每笔提交订单一行、每次设备报警一行，会得到不同的样本权重与部署接口。每用户每天预测未来购买时，应从当日符合资格的用户生成锚点，不能只从购买日志生成样本；否则从未购买的用户会消失，高频购买者则出现更多次。算法看到的总体已经变化，再精细的清洗也无法纠正任务定义偏差。

样本键通常由实体、决策时刻和任务版本组成，也可以另设稳定样本编号。实体键本身不必唯一，因为同一实体可以在多个时刻重复预测；但一个任务中的同一实体时刻是否允许多行，必须说明。若一次用户有多个商品候选，则预测单位还应包括候选商品。随机添加行号只能让物理行唯一，不能证明没有重复业务样本。

目标总体要按当时资格界定。例如只对仍有服务权限的用户评分，资格应来自当时可见账户状态，而不是当前最新账户名单。用今天仍留存的人重建去年样本，会删去后来退出的人，可能产生存活选择。资格规则本身也需要版本、可用时间与缺失处理。如果身份合并、账户迁移，必须说明历史样本沿用当时身份还是按一份明确映射重新归并。

一份最小契约应回答：谁被评分、何时评分、输入截止在哪里、目标发生在哪段未来、何时认为标签可确认、输出给谁使用。任务定义不一定复杂，但必须可执行。比如“预测活跃度”太模糊；“每天零点，对前一日已注册且未冻结用户，预测未来七个完整自然日是否出现一次成功支付”才足以推导锚点、来源和窗口。若服务在提交交易时触发，则应另写当前订单哪些字段已经可见。

<a id="sec-1-1"></a>

### 1.2 基础算例：样本生成应对齐标签观察结束时间

一月一日零点评分，预测 $`[t,t+7\mathrm d)`$ 是否至少购买一次。标签窗末端是一月八日零点，数据只观察到一月四日时，没有买过的人不能直接标负类。购买一旦发生也不一定立即可确认：可能支付延迟、订单撤销、来源漏报。要确定标签，既需目标观察窗结束，又需标签来源满足完整性与确认规则。

若系统承诺目标事件最迟两日可用，且当前抽取快照已完整覆盖到一月十日零点，则一月一日锚点可以成熟。这里“两日”必须是被验证的来源契约或任务特定等待规则，不是凭平均延迟猜出的常数。若仍可能有超期事件，延后两日只能降低遗漏概率，不能严格保证全部负标签正确。应报告迟到率与后续修订策略，或采用更适合不完整观察的目标定义。

二分类“窗口内至少一次”允许某些已确认正类提前识别，但如果只提前纳入正类、负类等待完整窗口，新近样本会严重偏正。训练样本的纳入条件应统一考虑标签成熟，而不是由当前标签取值决定。若专门采用提前正类与删失样本方法，则需要相应统计建模和评估设计，不能仍按普通完整标签二分类解释结果。

<a id="pd4-contract-table"></a>

### 1.3 用契约表固定边界

| 项目 | 本章完整实验的约定 | 需要拒绝的混用 |
|---|---|---|
| 预测单位 | 用户与预先给定零点锚点 | 以交易行代替用户锚点 |
| 特征 | 过去七日、严格早于决策且已可用的支付 | 用最终快照倒填历史 |
| 标签 | 未来七日是否有支付，左闭右开 | 把观察不足标成零 |
| 成熟条件 | 标签窗结束加两日，来源完整性成立 | 只检查事件日期早于抽取日 |
| 用户属性 | 决策前已发布且已生效的版本 | 全部连接当前最新属性 |
| 模型输入 | 明确允许的特征列 | 自动把数值列全部作为特征 |
| 拟合时间 | 一月二十日零点 | 使用此后才成熟的训练标签 |

契约并非写完后就永远不变。若目标从支付改为净支付，退款处理与标签成熟都需要重新审查；若零点 UTC 改成本地营业日，所有窗口端点可能变化。应把契约变化视为任务版本变化，并在同一冻结数据上比较新旧样本键、标签比例与特征差异。只修改列注释而沿用旧模型，无法保证预测含义仍然一致。

## 2. 按阶段处理

<a id="pd4-stages"></a>

### 2.1 从原始来源到模型输入的责任链

第一阶段保存原始来源身份并验证格式；第二阶段按业务规则处理重复与冲突；第三阶段独立生成合法预测锚点；第四阶段为每个锚点查询当时历史与属性；第五阶段构造成熟标签；第六阶段依据部署问题划分样本；第七阶段在训练部分拟合预处理和模型；第八阶段用冻结状态转换验证、测试和服务输入。阶段顺序体现信息依赖，而不是为了代码整齐随意分函数。

原始表清洗时不应盲目删除所有含缺失行。一个用户缺少地区，不意味着其交易身份无效；一笔金额解析失败也不必让所有该用户锚点消失。应按字段责任隔离：身份或时间不可确定时无法进入历史查询，金额缺失时可能保留事件计数但金额统计需报告有效覆盖。清洗粒度决定后续估计总体，因此删除规则需要与样本契约一起审查。

每个阶段保留输入身份集合、输出身份集合和原因分解。订单清洗可对账订单，特征聚合则对账锚点；两者行数本来不同，不能要求简单相等。需要写清哪些阶段保持粒度，哪些阶段改变粒度。聚合后输出锚点数应与输入锚点数一致，事件数可以成为特征；标签成熟筛选则允许减少样本，但被排除锚点应能明确列出。

<a id="sec-2-1"></a>

### 2.2 机制展开：拟合式处理与确定式处理分阶段

固定单位转换、严格日期解析与预先确定的合法值域，可以作为确定规则执行。中位数填补、标准化、类别词表、稀有类别阈值、特征选择，都从数据估计状态，属于拟合式处理。即使完全没用标签，利用测试集的分布估计这些状态，也会让评估不再对应仅用训练资料上线的流程。应在训练折内拟合，并将所得状态应用到其他部分。

历史查询是第三种操作：它不一定具有一个全局`fit`，而是每个锚点都有独立的信息截止。把它放进 Pipeline 不会自动消除未来信息，必须先保证查询函数的参数包含实体、决策时刻、来源快照与规则。反之，Pandas 在划分前构造所有锚点的历史特征也不必然错误，只要每个锚点只使用当时合法信息，且没有共享未来拟合统计。

分类有助于定位责任。解析函数承诺字符串到值的转换，历史函数承诺时点可见性，预处理器承诺只在训练样本估计参数。三者混在一个`clean_all`函数里，往往难以看出哪一步读了测试分布。更好的接口让每类状态显式输入输出：来源版本、时间查询规则、训练拟合参数各有名称，评估时逐一冻结。

<a id="deep-dive-2"></a>

### 2.3 深入讲解：从预测对象到特征标签表的一条可回放流水线

将整个流程视为依赖图很有帮助。锚点依赖资格状态与日历规则，历史特征依赖锚点和可见事件，标签依赖锚点、未来目标与完整性，划分依赖锚点和部署设定，预处理依赖训练部分，模型依赖预处理后的训练输入与标签。某个结果若反过来影响上游，例如根据未来标签决定清洗用户，就出现需要单独论证的信息回路。

可回放不等于“代码能再运行”。如果读取的外部表不断更新，相同代码可能产生不同样本；如果类别词表从当前全表生成，历史模型输入维度也可能变化。应明确记录输入快照或可重建版本、规则版本、依赖环境、抽取参数与训练截止。重新运行时先验证输入身份与版本，再比较输出指纹，差异才有机会被解释。

一个清晰的接口可以返回样本表和审查信息，使调用者能够同时检查数据与构造依据。本章完整实验把审查摘要留在内存中，通过断言验证。真实工程可能将审查元数据纳入数据产品；无论存在哪里，它都应该与样本版本关联，不能把一份漂亮的独立报告当成实际样本的证明。真正需要的是从某行样本追到其输入事实和规则。

## 3. 特征字典

<a id="pd4-dictionary"></a>

### 3.1 从列名扩展到可执行语义

`amount_7d`这个名字没有说明币种、退款、金额单位、左右端点、版本选择和缺失规则。完整字典应包括预测单位、来源事实粒度、时间条件、聚合分子分母、可空状态、合法范围、默认值与可用性条件。例如`sum_cents_7d`可以定义为严格可见七日支付的整数分金额和，空且覆盖完整时为零；金额未知则另外报告覆盖，不能把未知当零。

标签字段也需要字典。`y=0`应表达完整观察窗内未发生目标，不是“数据库没有找到记录”；`y`缺失应区分未成熟、来源中断、资格变化与目标无法判定。模型输入允许列表最好显式列出，样本编号、用户编号、标签结束时间和来源更新时间默认作为元数据，不因其数值类型就自动进入模型。某些身份特征可以合法使用，但必须经过部署可用性和记忆风险审查。

同一列类型可能有多种统计角色。整数地区代码是类别，整数年龄是有序数量，整数用户编号通常是身份。自动对所有整数标准化，会给地区代码引入虚假的距离；自动对所有字符串独热，又可能让高基数身份记忆训练。字典应记录语义类型与转换路径，而不仅是 Pandas `dtype`。存储类型解决编码，语义类型决定模型如何理解。

<a id="pd4-schema"></a>

### 3.2 列顺序、未知类别与缺失约定

模型输入契约包含有序列列表。两个矩阵形状相同但年龄与金额列互换，仍会产生错误预测；纯 NumPy 数组不会提醒语义错位。可以在转换边界使用显式列名选择，并记录转换后的特征名和顺序。新列是否忽略、旧列缺失是否报错，应由契约确定，不能依赖文件加载后恰好出现的列顺序。

未知类别与缺失类别不同。未知表示提供了一个训练词表没有见过的合法取值，缺失表示值未给出或无法获得。未知编码为全零时，需注意是否与被删除的基准类别表示冲突；若希望区分，可以使用显式未知桶或保持完整类别列。类别映射属于训练状态，线上不能根据当天数据重新排序编码，否则相同列号会指向不同含义。

数值缺失也可能带预测信息。训练内中位数填补给模型一个可计算值，但不声称它是真实观测；缺失指示能够保留某些信息，不过采集机制改变时，这种关联可能不稳定。模型应报告缺失率与覆盖人群的表现，避免只在完整记录子集展示指标。若训练列全缺失，要显式决定保留、固定填补还是删除，防止转换维度在不同折中悄悄变化。

<a id="sec-4"></a>

## 4. 产物与验收

<a id="pd4-invariants"></a>

### 4.1 身份、数量、金额和时间的四种验收

身份验收保证应该保留的样本键集合没有增减，数量验收保证每个键恰好对应一行；二者相关却不等价。删掉一个样本同时复制另一个，行数不变而身份集合变化。连接后先比较样本键集合，再检查唯一性，比只比较`len`更强。对聚合阶段则要在源事实身份和目标锚点身份上分别定义检查，不能混用粒度。

金额验收需要明确是否本应守恒。多对一属性连接通常应保持交易金额；按窗口聚合到多个锚点时，同一笔交易可能合法地影响多个样本，总金额不应要求与原表相等。应对每个锚点的成员事实逐项核对，或用独立规范查询检验。简单要求所有阶段金额不变，会把合法重复使用历史误判成错误，同时可能漏掉真实多对多膨胀。

时间验收应保存每条样本的决策时间、特征查询规则、标签窗末端、标签可确认时间和拟合时刻。训练样本标签在最终抽取日已成熟，不代表在模拟拟合日已成熟。如果评估假设一月二十日上线，使用一月三十日才确认的标签训练，就违背了上线条件。这个问题与特征泄漏不同，必须检查标签可用时间到拟合时间的关系。

<a id="pd4-quarantine"></a>

### 4.2 错误隔离、原因统计与总体变化

隔离不是把错误从视野中删除，而是保留可修正的边界。原始行中实体为空、日期非法、金额单位不明，可能对应不同修复路径。隔离表应记录原值、来源和原因，重跑时能够确定哪些行被修复、哪些仍拒绝。训练样本若因来源异常而排除，还应统计受影响人群，否则清洗可能有系统地删去困难样本，使测试指标变高。

失败规则存在优先关系。身份无法解析时，其后时间规则是否适用？同一行同时金额非法与时间非法时，原因数可以大于隔离行数，但最终接受加隔离应按唯一原始行身份守恒。可建立互斥的主原因供总量对账，再保留全部原因供排查。不要把每条规则删除数简单相加，重叠失败会造成解释上的重复计数。

质量阈值应在训练和业务知识范围内确定。用整个测试期分位数定义“异常大额”，再删去这些测试样本，会改变评估总体；用模型预测错误来反向决定哪些记录应清洗，则更直接选择了容易样本。合理流程是先说明目标总体和来源约束，再决定不可用记录的处理，并同时报告覆盖率与保留样本表现，必要时展示被隔离部分的独立分析。

<a id="pd4-lineage"></a>

### 4.3 血缘、版本与可复现实验边界

一条样本的血缘至少包括锚点来源、参与聚合的源版本、属性版本、目标来源与规则版本。实际系统可按分区和查询条件压缩保存，不必每次复制全部原始行，但应能对某个样本展开明细。仅保存最终 CSV 无法回答为什么某条晚到事件被排除，也无法恢复旧版本属性；仅保存脚本而没有源快照，同样无法保证重现。

版本分为来源版本、语义规则版本、训练拟合版本与环境版本。来源新增晚到数据可以改变事后标签而不改变旧时点特征；规则改动可能改变所有样本；重拟合预处理会改变同一原始行的模型输入。把这些变化都称为“数据更新”过于粗糙。应在重跑差异中分别定位来源变化、规则变化和拟合状态变化，才能知道是否需要重新训练或只更新评估。

随机种子只能控制特定随机过程，不能冻结外部数据、线程数值差异或依赖接口。完整实验应使用固定输入、明确版本和断言；有随机模型时再设置种子。文件指纹能快速发现变化，但不能证明数据语义正确。反过来，手算样本能检验局部语义，但不能证明整库未丢分区，仍需全局身份和覆盖检查。

## 5. 从一个预测时点手工还原样本

<a id="pd4-manual"></a>

### 5.1 一条样本的逐层证据

考虑用户甲一月十日零点的样本，过去七日有一月四日十分支付，未来一月十二日五十分支付。历史金额十分、次数一；十二日的支付只用于未来七日标签，不能用于十日特征。属性表显示甲一月一日起是基础会员，金牌升级一月十八日生效、一月十九日才发布，因此十日仍是基础会员。标签窗结束十七日，两日完整性等待后十九日可确认，二十日拟合时可用于训练。

把这条链拆开可发现多种独立错误：若用最新会员状态，特征包含未来升级；若把十二日支付加入历史，窗口方向反了；若在十日拟合时使用七日标签，标签尚不可用；若从支付表直接生成锚点，只会在四日、十二日评分，任务触发机制变了。结果表看上去仍可有用户、日期、金额和标签四列，因此仅检查列存在不足以验收。

用户丙十日没有历史但十五日购买，合法样本应该是计数零、金额和零、最近间隔未知、标签一。对历史交易做内连接会把这个重要样本删掉；把缺失最近间隔填为零，又会让“从无历史”看起来像刚刚交易。应先保留全部锚点，再连接聚合结果，区分结构性空历史与数据缺口，并把统计型填补留给训练内流程。

<a id="pd4-label-boundaries"></a>

### 5.2 标签窗口重叠与重复决策

每天预测未来七日时，相邻样本的标签窗高度重叠，一笔支付可能让多个日锚点变成正类。这不一定错误，因为真实服务确实每天决策；但样本不再近似独立，同一用户多次记录也会共享行为状态。评估时的置信区间、重采样和平均指标需要考虑依赖结构，不能把每行当作独立新用户来计算过度乐观的不确定性。

重复决策还改变损失权重。每天都有锚点的长期用户比只观察两天的新用户占更多行；按行平均评估的是随机用户日表现，按用户先平均再平均评估的是随机用户表现。两者都可能有用，但应对应产品目标。若部署只在事件触发时评分，固定日历锚点又可能过度代表无活动时段，需在契约中固定采样机制。

标签定义必须处理撤销和重复事件。未来窗内一次支付随后全额退款，若目标是成功支付次数，可能仍为正；若目标是最终保留购买，则需更长确认期。用最终退款状态标记短期目标时，标签可确认时间也延后。目标业务含义、观察窗和等待窗是三个参数，不能只调整一个而沿用其他默认。

<a id="sec-6"></a>

## 6. 进阶：Point-in-time正确性与训练服务一致

<a id="sec-6-1"></a>

### 6.1 把原始表转换成带契约的学习样本

历史正确性要求样本特征等于服务在相同锚点、相同规则、相同已知来源状态下能够计算的值。它比“所有事件日期都早于预测日”更强，因为字段可能后到达或事后修订。第三章已经推导双时间窗口，本章只在管道中复用这一责任：历史函数明确限制事件时间和可用时间，属性函数明确选择当时可见的有效版本。

双时间属性可同时记录业务有效区间和系统可见区间。业务有效区间回答某状态被认为适用于哪段现实时间，系统可见区间回答某版本在数据库何时被知道。事后更正可以追溯生效，但不能追溯改变当时服务已经知道什么。只查有效区间会得到事后事实，结合系统可见性才能得到历史决策输入。若来源根本没有版本日志，不能假装已有数据足以完成严格历史重放。

完整样本不仅包含 $`X`$ 和 $`y`$，还包括解释其合法性的元数据。模型通常不读标签成熟时间、源版本和成员身份，但这些字段仍应在样本产品中保留。训练时用允许列表选择 $`X`$，审查时用元数据验证时间与身份。把所有审查字段删除后只留下矩阵，会让后续故障难以定位；把审查字段全部送进模型，又可能直接引入泄漏。

<a id="pd4-split"></a>

### 6.2 时间划分与对象划分分别回答什么

时间划分模拟用过去训练、向未来预测，适合已有用户的未来服务，但相同用户可能同时出现在训练和测试。对象划分模拟向未见用户迁移，能够减少身份记忆，却不自动模拟未来分布变化。二者不互相替代：随机分用户但混用未来记录，仍可能无法评价按过去上线的系统；只按时间划分，也不能声称测试了完全新用户泛化。

可以建立多个明确评估面板：老用户未来、新用户未来、特定来源迁移。每个面板固定锚点、拟合时间与可用标签。若要求新用户未来，就在时间条件之外排除训练出现过的用户。严格对象隔离可能减少训练量，也改变目标总体，因此报告性能时应同时报告样本数、阳性率与覆盖；不能把更困难面板分数较低视为划分错误。

所有拟合式预处理都必须随划分重建。交叉验证中先对全体训练部分标准化再分折，验证折已经参与均值估计；正确流程是每折单独拟合。最终选定方案后，可在允许使用的完整训练范围重拟合，再对独立测试一次评估。窗口候选、缺失规则与类别阈值也属于方案的一部分，不能只冻结最后的分类器参数。

<a id="pd4-embargo"></a>

### 6.3 清除重叠与设置间隔需要具体目的

假设验证从二十日开始，训练锚点在十八日，标签窗延伸到二十五日。如果模型二十日拟合，十八日标签不成熟，因此本来就不能训练；检查标签可用时间会自然排除它。若采用包含未来训练区间的某种研究交叉验证，还可能需要清除与验证信息区间重叠的训练样本，并在边界设置缓冲间隔，以减轻相邻信息共享。必须说清是哪种设计，不要把一个固定天数间隔当成无泄漏证明。

间隔长度应来自标签观察期、来源等待期、历史依赖和评估目标。七日标签并不自动推出所有任务都应空七日；若标签两日后才完整确认，拟合时间约束还包含这两日。另一方面，训练与测试特征共享同一条早期合法历史，不一定构成泄漏，因为上线时这些历史本来已知。禁止任何原始记录共享可能过度清除，得到与服务无关的冷启动任务。

对象隔离和时间间隔也控制不同依赖。即使间隔一个月，同一用户稳定身份仍可能被记住；即使用户完全隔离，共同促销、天气或政策冲击仍造成时间相关。合适评估应围绕预期部署条件组合限制，并在报告中说明不能覆盖的迁移方向。统计依赖、信息不可用和任务分布变化是相关但不同的问题，需要分别处理。

<a id="pd4-preprocess"></a>

### 6.4 训练内填补、缩放与类别编码

本章采用列变换器分别处理数值与类别列，外层 Pipeline 将变换器和分类器一起拟合。数值用训练中位数填补并保留缺失指示，再用训练统计缩放；类别缺失变为显式标记后独热，未见类别采用预定处理。官方建议将预处理纳入训练流程以减少数据泄漏，见[scikit-learn 数据泄漏说明](https://scikit-learn.org/1.8/common_pitfalls.html#data-leakage)。

`SimpleImputer`的全缺失列处理需要明确配置，`OneHotEncoder`的未知类别处理也应显式设定。本章代码分别设置保留空特征、未知类别忽略及非稀疏输出；接口详见[填补器文档](https://scikit-learn.org/1.8/modules/generated/sklearn.impute.SimpleImputer.html)与[独热编码文档](https://scikit-learn.org/1.8/modules/generated/sklearn.preprocessing.OneHotEncoder.html)。这些是工程转换约定，不保证中位数或独热在所有任务上最优。

类别全零编码表示“没有命中训练词表任何类别”，它与显式缺失标记能否区分取决于训练词表是否包含该标记。本章保留原始来源状态和未知率用于审查，模型输入只遵循固定编码契约。真实应用可以选择预定义类别全集或专用未知桶，但不应在每次预测时重新拟合词表。服务面对新类别时，预处理状态必须仍是训练时那一份。

<a id="pd4-serving"></a>

### 6.5 训练与服务的一致性是函数级契约

可将预测函数写成三个组合：历史查询 $`h(u,t,S)`$、冻结预处理 $`g_\eta`$、模型 $`f_\theta`$。其中 $`S`$ 是当时可见来源状态，$`\eta`$ 是训练得到的填补缩放编码参数，$`\theta`$ 是模型参数。训练服务一致要求输入语义、查询规则与冻结状态一致，而不只是模型权重一致。线上金额由元变分、时间窗由 UTC 改本地日历，都可能在模型完全相同时改变结果。

可构建少量基准样本，给定同一来源快照和锚点，分别走离线与服务查询，再比较原始特征、转换特征与最终预测。比较应分层进行：最终分数接近可能是多个错误相互抵消，原始特征一致而转换不同则说明拟合状态或列顺序有问题。容差要按字段定义选择，身份和类别应精确一致，浮点统计按已知数值误差比较。

状态缓存与降级路径也属于服务函数。线上查询失败后沿用昨日报告，离线却永远使用完整新数据，就存在覆盖差异。应记录特征年龄、来源状态与降级原因，并在评估中考察这些情形。实时缓存是否允许迟到修订更新历史记录、同刻请求是否共享新状态，都需要与离线回放保持一致，不能只检查正常路径。

<a id="pd4-selection"></a>

### 6.6 样本抽样、重复权重与目标风险

完整样本表太大时经常抽样负类或限制每位用户的锚点数。抽样改变训练分布，不能只在日志中写“加速”。设原始任务风险是所有合格锚点损失的平均，某行以已知概率 $`\pi_i`$ 被保留，那么可用与 $`\frac{1}{\pi_i}`$ 成比例的权重校正某些总体平均估计，但这依赖正确抽样概率和非零覆盖。对于从未进入候选框的用户，后续权重无法凭空恢复其特征与标签。

类别下采样还会改变概率含义。正类全部保留、负类只取十分之一，训练中的正类比例增大；未经修正的输出通常不能直接解释成原始总体购买概率。分类排序在某些条件下可能仍有用，阈值与校准却需要对应真实部署分布。应保存抽样策略、每行概率、训练权重与评估总体，不能把平衡训练集上的准确率直接当作服务指标。

重复锚点也相当于隐式加权。同一用户同一天被两条资格来源重复生成，模型就把它看成两次证据。即使重复行完全相同、训练损失下降，也没有增加独立信息。应在进入特征查询前检查业务锚点唯一性；若任务确实允许多候选或多渠道，键中要包含这些维度，并说明最终指标按用户、请求还是候选加权。粒度不是数据库附属信息，它直接决定优化目标。

抽样最好在合法锚点总体与成熟标签确定后，根据事先设定规则进行，并保留未抽样总体用于评估。若根据模型错误反复增加难例，形成的是自适应训练方案，需要独立验证，不能继续声称样本是简单随机抽样。不同策略可以合理存在，但报告应能还原它们如何改变总体和权重，而不是把所有差异隐藏在一个随机种子里。

<a id="pd4-crossfit"></a>

### 6.7 跨折特征、历史标签与状态更新

某些特征会使用过去已经确认的标签，例如某商户此前欺诈率。它不因包含标签就必然非法，但必须同时满足历史可用性、样本隔离与训练评估设计。训练样本不能使用自己的未来结果，验证样本也不能使用在其决策时刻尚未成熟的训练标签。仅做普通随机折外编码，可以排除自身标签，却未必满足时间先后；时间任务需要按合法历史构建编码状态。

对于每天更新的目标统计，输入应是截至当天可用的标签日志，并记录分子、分母、平滑先验与更新时间。先验若由全测试期总体正类率估计，也会泄漏。新商户没有历史时如何编码，应由训练阶段确定。分母过小的极端比率可用平滑降低方差，但平滑强度要在训练验证流程内选择；不能从未来真实率反向挑最合适参数。

模型是否滚动重训也需要固定。一次拟合后测试一个月，与每天获得新标签后更新模型，是不同策略。后者可以合法使用测试月较早时点已经成熟的标签，但必须逐日模拟拟合时间，不能先用整月标签训练再回填每天预测。每次更新都应保存当时的训练样本键和预处理状态，避免无法判断某次提升来自更多合法标签还是不经意读到了未来。

这个视角也解释了为什么“测试数据完全不能碰”过于粗略。测试期特征在真实决策时可见，可以进入在线状态；测试期标签只有在未来成熟后、且策略允许更新时，才能影响后续模型。独立最终测试的设计通常冻结方案选择，具体允许哪些状态更新应事先声明。关键是按时间和职责限制信息流，而不是仅靠文件名划一道线。

<a id="pd4-change"></a>

### 6.8 版本迁移与差异归因

当来源补录、规则升级或依赖版本变化导致输出不同，可用逐阶段差异定位。先比较锚点键集合，再比较每个锚点的源成员和版本，再比较原始特征，最后比较转换矩阵与预测。锚点已经不同就不应只比较矩阵均值；原始特征一致而编码列变了，则优先检查训练词表与列顺序。这样的诊断顺序让变化具有可解释的因果位置。

发布新规则前，可在同一冻结快照上计算旧版与新版，统计身份增减、标签翻转、缺失变化、数值差异与人群覆盖。若来源也同时变化，最好另做固定规则换来源的对照，避免把两种变化混为一谈。所谓可复现，不要求所有未来重跑永远得到相同结果，而要求在相同约束下可重复、约束变化时能说明差异来自哪里。

修正历史标签后，旧评估指标可能需要重新报告，但旧模型训练过程仍应保留当时实际使用的标签版本。用修正版标签重新训练得到的是新模型，不能把新结果覆盖成旧上线记录。对数据错误、规则缺陷和真实业务变化分别处理，才能形成可信的实验记录。研究结论依赖哪些版本，也应在学习笔记或项目说明中准确标明。

## 7. 完整实验：原表、成熟标签与模型输入

<a id="pd4-experiment-contract"></a>

### 7.1 实验设计与手算验收点

我们固定四位用户和四个评分日：一月十日、二十日、三十日、二月八日，总计十六个锚点。来源快照为二月十二日，标签为未来七日支付，来源保证两日内到达，因此最后四个锚点尚未成熟，只保留为待标注。前三个评分日共十二个成熟样本，阳性各有两位。模型拟合日是一月二十日，只允许使用一月十日那四条已成熟标签。

过去七日特征包括支付次数、金额有效数、金额和与距离最近支付的天数。实验金额全部使用非负整数分。解析先验证最多十九位的十进制整数字符串与 int64 范围，再转换，不能只用`to_numeric`后直接转整数：`"1.5"`可能被截成一分，边界整数经过浮点中转也可能失真。

非法金额保留为可空整数中的未知值，事件表合并后仍保持`Int64`，身份与时间须单独验证。窗口金额先用 Python 整数求和，只有构造模型连续特征时才显式转成浮点；这一步是近似表示，巨大金额若要求逐分精确核算，应使用整数账本，不能从模型浮点输入反推原账本。

历史空窗时次数与金额和为零，最近间隔缺失。甲十日金额十分、乙有两笔支付但一笔金额未知所以总额未知、丙零、丁三十分；一月二十日甲已经可见升级后的会员版本，十日仍是基础版本。丁后来出现新地区类别，训练词表不应提前包含它。另放入一条无法解析金额的原始行：交易身份和时间仍有效，因此仅将金额字段隔离，事件仍参与计数与目标判定，不能把整笔事实静默删除。

这个实验的样本量不足以评估模型优劣，分类器只用于检查从原表到固定维度输入、概率输出的完整连接。我们不根据这几条测试记录调参，也不把任何分数宣称为泛化证据。真正验收点是时间边界、标签成熟、键集合、隔离对账、训练词表冻结和预测有限；模型性能研究应在更大且符合任务分布的数据上开展。

### 7.2 完整自足实现

```python
import numpy as np
import pandas as pd
import sklearn
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler
pd.options.mode.copy_on_write = True

def ts(x):
    return pd.Timestamp(x, tz='UTC')

# 业务契约：这里每行是一笔最终确认支付，无退款或后续修订，最迟两日到达。
raw = pd.DataFrame([
    ('p1','A','2026-01-04','2026-01-05','10'),
    ('p2','B','2026-01-08','2026-01-09','20'),
    ('p3','D','2026-01-09','2026-01-09','30'),
    ('p4','A','2026-01-12','2026-01-14','50'),
    ('p5','C','2026-01-15','2026-01-16','40'),
    ('p6','B','2026-01-22','2026-01-23','60'),
    ('p7','D','2026-01-24','2026-01-25','70'),
    ('p8','A','2026-02-01','2026-02-02','80'),
    ('p9','C','2026-02-02','2026-02-03','90'),
    ('bad','B','2026-01-06','2026-01-07','not_money')],
    columns=['payment','user','event_time','available','raw_cents'])
raw['source_row'] = np.arange(len(raw))
def parse_cents(text):
    # 先验证整数分语法，再用Python整数核对范围，避免浮点舍入或astype截断。
    text = text.astype('string').str.strip()
    syntax = text.str.fullmatch(r'[0-9]{1,19}').fillna(False)
    result = pd.Series(pd.NA, index=text.index, dtype='Int64')
    limit = np.iinfo(np.int64).max
    for idx, value in text.loc[syntax].items():
        integer = int(value)
        if integer <= limit:
            result.loc[idx] = integer
    return result

probe = parse_cents(pd.Series(['0', '1.5', '-1', 'inf',
                               '9223372036854775807', '9223372036854775808']))
assert probe.iloc[0] == 0 and probe.iloc[4] == np.iinfo(np.int64).max
assert probe.isna().tolist() == [False, True, True, True, False, True]
amount = parse_cents(raw['raw_cents'])
invalid = amount.isna()
quarantine = raw.loc[invalid].copy()
quarantine['reason'] = 'invalid_integer_cents'
events = raw.loc[~invalid].copy()
events['cents'] = amount.loc[~invalid].astype('Int64')
for col in ['event_time','available']:
    events[col] = pd.to_datetime(events[col], utc=True, errors='raise')
assert len(events) + len(quarantine) == len(raw)
assert set(events['source_row']).isdisjoint(quarantine['source_row'])
assert events['payment'].is_unique and events['user'].notna().all()
assert (events['cents'] >= 0).all()
assert ((events['available'] - events['event_time']) >= pd.Timedelta(0)).all()
assert ((events['available'] - events['event_time']) <= pd.Timedelta('2D')).all()
assert int(events['cents'].sum()) == 450
# 字段级隔离：金额失败不否定支付存在，保留身份与时间，金额设未知。
unknown_amount = quarantine.copy()
unknown_amount['cents'] = pd.Series(pd.NA, index=unknown_amount.index, dtype='Int64')
for col in ['event_time','available']:
    unknown_amount[col] = pd.to_datetime(unknown_amount[col], utc=True, errors='raise')
facts = pd.concat([events, unknown_amount], ignore_index=True)
assert len(facts) == len(raw) and facts['payment'].is_unique
assert facts['cents'].dtype == pd.Int64Dtype()
assert facts['cents'].notna().sum() == 9
assert (facts['available'] - facts['event_time']).between(pd.Timedelta(0), pd.Timedelta('2D')).all()

# 属性为发布日志；本实验只允许向前生效，更新后持续到下一条更新。
attrs = pd.DataFrame([
    ('A','2026-01-01','2026-01-01','basic','east'),
    ('B','2026-01-01','2026-01-01','basic','west'),
    ('C','2026-01-01','2026-01-01','basic',np.nan),
    ('D','2026-01-01','2026-01-01','basic','west'),
    ('A','2026-01-18','2026-01-19','gold','east'),
    ('D','2026-01-25','2026-01-26','basic','new_region')],
    columns=['user','effective','published','tier','region'])
for col in ['effective','published']:
    attrs[col] = pd.to_datetime(attrs[col], utc=True)
assert not attrs.duplicated(['user','published']).any()
assert (attrs['effective'] <= attrs['published']).all()

users = ['A','B','C','D']
dates = pd.to_datetime(['2026-01-10','2026-01-20',
                        '2026-01-30','2026-02-08'], utc=True)
anchors = pd.MultiIndex.from_product([users, dates],
    names=['user','decision']).to_frame(index=False)
anchors['sample'] = (anchors['user'] + '@' +
                     anchors['decision'].dt.strftime('%Y-%m-%d'))
assert anchors['sample'].is_unique and len(anchors) == 16
snapshot = ts('2026-02-12')
assert (facts['available'] <= snapshot).all()

# 特征函数完全不读取标签表或抽取截止，只按各锚点的合法信息计算。
def features(source, attribute_log, qs):
    rows = []
    for q in qs.itertuples(index=False):
        h = source.loc[(source['user'] == q.user) &
            (source['event_time'] >= q.decision - pd.Timedelta('7D')) &
            (source['event_time'] < q.decision) &
            (source['available'] < q.decision)]
        a = attribute_log.loc[(attribute_log['user'] == q.user) &
            (attribute_log['published'] < q.decision) &
            (attribute_log['effective'] <= q.decision)]
        a = a.sort_values(['published','effective'])
        state = a.iloc[-1] if len(a) else None
        # 原始金额保持整数；仅在构造模型连续输入时显式转换浮点。
        total = sum(int(v) for v in h['cents'].dropna()) if h['cents'].notna().all() else None
        rows.append({'sample':q.sample, 'n_7d':len(h),
            'n_amount_7d':int(h['cents'].notna().sum()),
            'sum_cents_7d':float(total) if total is not None else np.nan,
            'recency_days':((q.decision-h['event_time'].max()).total_seconds()/86400
                            if len(h) else np.nan),
            'tier':state['tier'] if state is not None else np.nan,
            'region':state['region'] if state is not None else np.nan})
    return pd.DataFrame(rows)

feat = features(facts, attrs, anchors)
assert feat['sample'].is_unique
samples = anchors.merge(feat, on='sample', how='left', validate='one_to_one')
assert set(samples['sample']) == set(anchors['sample']) and len(samples) == 16
samples['label_end'] = samples['decision'] + pd.Timedelta('7D')
samples['label_ready'] = samples['label_end'] + pd.Timedelta('2D')
samples['mature'] = samples['label_ready'] <= snapshot
samples['y'] = pd.Series(pd.NA, index=samples.index, dtype='Int64')
for idx, q in samples.loc[samples['mature']].iterrows():
    target = facts.loc[(facts['user'] == q['user']) &
                       (facts['event_time'] >= q['decision']) &
                       (facts['event_time'] < q['label_end']) &
                       (facts['available'] <= snapshot)]
    samples.loc[idx,'y'] = int(len(target) > 0)
assert samples['mature'].sum() == 12
assert samples.loc[~samples['mature'],'y'].isna().all()
by_id = samples.set_index('sample')
assert by_id.loc['A@2026-01-10','sum_cents_7d'] == 10
assert by_id.loc['C@2026-01-10','n_7d'] == 0
assert by_id.loc['B@2026-01-10','n_7d'] == 2
assert by_id.loc['B@2026-01-10','n_amount_7d'] == 1
assert pd.isna(by_id.loc['B@2026-01-10','sum_cents_7d'])
assert by_id.loc['A@2026-01-10','tier'] == 'basic'
assert by_id.loc['A@2026-01-20','tier'] == 'gold'
assert by_id.loc['C@2026-01-10','y'] == 1
assert by_id.loc['D@2026-01-10','y'] == 0

fit_time = ts('2026-01-20')
train = samples.loc[(samples['decision'] < fit_time) &
                    (samples['label_ready'] <= fit_time)].copy()
valid = samples.loc[samples['decision'] == ts('2026-01-20')].copy()
test = samples.loc[samples['decision'] == ts('2026-01-30')].copy()
assert len(train) == len(valid) == len(test) == 4
assert (train['label_ready'] <= fit_time).all()
assert train['y'].nunique() == 2
num_cols = ['n_7d','n_amount_7d','sum_cents_7d','recency_days']
cat_cols = ['tier','region']
allowed = num_cols + cat_cols
num = Pipeline([
    ('impute',SimpleImputer(strategy='median', add_indicator=True,
                            keep_empty_features=True)),
    ('scale',StandardScaler())])
cat = Pipeline([
    ('impute',SimpleImputer(strategy='constant', fill_value='__MISSING__',
                            keep_empty_features=True)),
    ('encode',OneHotEncoder(handle_unknown='ignore', sparse_output=False))])
pre = ColumnTransformer([('numeric',num,num_cols), ('category',cat,cat_cols)],
                        remainder='drop', verbose_feature_names_out=True)
model = Pipeline([('preprocess',pre),
                  ('classifier',LogisticRegression(max_iter=1000, random_state=3))])
model.fit(train[allowed], train['y'].astype(int))
ztrain = model.named_steps['preprocess'].transform(train[allowed])
ztest = model.named_steps['preprocess'].transform(test[allowed])
assert ztrain.shape[1] == ztest.shape[1]
assert np.isfinite(ztrain).all() and np.isfinite(ztest).all()
encoder = model.named_steps['preprocess'].named_transformers_['category'].named_steps['encode']
assert 'new_region' not in encoder.categories_[1]
assert 'gold' not in encoder.categories_[0]
prob = model.predict_proba(test[allowed])[:,1]
assert np.isfinite(prob).all() and ((prob >= 0) & (prob <= 1)).all()

# 相同查询函数模拟离线与服务，核对列顺序和冻结变换。
service_raw = features(facts, attrs, test[['user','decision','sample']])
service_raw = service_raw.set_index('sample').loc[test['sample']].reset_index()
pd.testing.assert_frame_equal(service_raw[allowed].reset_index(drop=True),
                              test[allowed].reset_index(drop=True))
np.testing.assert_allclose(model.predict_proba(service_raw[allowed])[:,1], prob)
# 扰动未来金额不会影响最早锚点特征。
changed = facts.copy()
changed.loc[changed['available'] >= ts('2026-01-10'),'cents'] *= 100
old_q = anchors.loc[anchors['decision'] == ts('2026-01-10')]
pd.testing.assert_frame_equal(features(facts,attrs,old_q),
                              features(changed,attrs,old_q))
print('versions', pd.__version__, np.__version__, sklearn.__version__)
print('金额可用/金额隔离/事实总数/成熟/待定:',len(events),len(quarantine),len(facts),12,4)
print('训练/验证/测试:',len(train),len(valid),len(test))
print('输入维度:',ztrain.shape[1], '测试概率:',np.round(prob,6).tolist())
```

### 7.3 实验保证什么，尚未保证什么

代码验证九笔金额可用、一笔金额解析失败，已知金额和四百五十分；十笔事实全部保留，未知金额不冒充零，乙首个锚点的总金额保持缺失；十六个锚点完整保留，十二个成熟、四个待定；训练、验证、测试各四条。最早锚点扰动未来数据不变，训练词表不包含未来升级与新地区，服务查询使用同一特征函数并与离线输入一致。这些都是针对明确性质的检查，能捕捉身份丢失、时间反向、全表拟合及编码漂移等错误。

来源完整性仍是外部前提。我们检查已观测事件延迟不超过两日，并声明教学源完整；仅凭已观测延迟不能证明不存在永远漏报的事件。真实系统需要对账、来源确认或其他完整性证据。同样，服务与离线共用一个函数只能防止两个实现分叉，无法证明这个共同函数符合业务；手算和独立时间断言仍然必要。

属性函数只适用于本例的向前更新日志，不声称实现任意双时间数据库。若更正能追溯覆盖旧有效区间，应保存完整有效区间与系统版本，并重新设计选择规则；不能照抄本例按发布时间取末条。标签也假设支付最终确认、无撤销，若任务涉及退款，目标与成熟条件必须随之变化。明确限制是让示例可推广的起点，忽略限制反而容易在复杂来源中失效。

<a id="pd4-composition"></a>

### 7.4 用组合契约推导端到端正确性

可以把完整流程的保证写成条件推理。假设原始来源身份和时间可信、支付来源在两日后完整；清洗保持所有可识别事实并隔离未知金额；锚点生成覆盖当时合格总体且唯一；历史查询只读取合法版本；标签只在完整窗口后生成；训练只用拟合时可得标签；预处理只在训练拟合。由这些前提，模型输入就不会通过本流程中已列出的通路使用未来信息，并且每行对应预定义预测单位。

这个结论有意带着前提。它不证明来源没有漏报、不证明标签代表真实需求，也不证明模型有因果解释；它证明的是在明确来源与任务契约下，组合的处理没有破坏身份和信息边界。发现新的通路，例如资格名单来自未来退出状态，就需要扩展契约并修正锚点生成，而不是继续依赖原有断言。

验证时可采用故障注入：复制一条属性版本应触发唯一性或冲突检查，修改未来金额应保持过去特征，删除一个锚点应触发键集合检查，把未成熟标签强置零应触发成熟性检查。每个注入对应一条承诺，能检验检查机制确实有效。仅证明正常输入能够运行，远不如同时证明典型错误会被识别；但也不应无限堆积与风险无关的形式测试，优先覆盖真实信息边界。

## 8. 进阶研究练习与解析

<a id="pd4-ex1"></a>

### 8.1 练习一：事件表能否直接当样本表

**问题：** 服务每天给所有合格用户评分，直接把每笔交易当一条样本，为什么即使窗口完全正确仍可能做错任务？

**解析：** 无交易用户被排除，高频用户权重增加，决策时刻从日历零点变成交易发生时刻。模型估计的是交易条件下的风险，而非全体用户日风险。应独立生成合格用户与日历锚点，再连接历史特征；如果部署本来是交易触发，则应重新写契约并确定当前订单字段可用性。样本总体错误不能靠类别权重随意修复，除非有明确抽样概率与对应统计目标。

<a id="sec-8-2"></a>

### 8.2 边界追问：标签未成熟能否当作负样本

**问题：** 七日目标只观察三日，尚未购买，可以标零吗？若已经购买，可以立即把它加入训练吗？

**解析：** 前者不能，尚未看到不等于完整窗口未发生；后者也不能无条件单独纳入，否则新近样本选择偏向正类。普通完整标签流程应按统一成熟条件纳入。若希望利用提前确认正类与未完成观察，需要采用专门的删失或延迟反馈设计，并按该设计评估。把未成熟样本仅从负类删除而保留正类，会改变标签比例和特征分布。

<a id="pd4-ex3"></a>

### 8.3 练习三：抽取日成熟不等于拟合日可用

**问题：** 十五日锚点标签二十四日可确认，二月抽取时已经成熟，能否用于模拟二十日上线模型？

**解析：** 不能，二十日拟合时还不知道该标签。需要同时检查标签相对抽取快照成熟，以及标签可用时间不晚于模拟拟合时间。后者约束训练，前者约束最终评估可否赋标签。可以在二十四日以后更新模型时使用它，但那对应另一次拟合任务。混用会让回测模型拥有未来监督信息，即使所有特征都严格过去仍然不合法。

<a id="pd4-ex4"></a>

### 8.4 练习四：对象划分能否替代时间划分

**问题：** 将用户完全分开，训练数据包含二月、测试数据是一月，能否证明模型可在一月上线？

**解析：** 不能。对象隔离只说明用户未重合，训练仍用了未来时间分布和未来成熟标签。若研究目标是跨用户但不限制日历时间，应明确这样解释；若研究按过去上线，则训练的特征、标签与预处理状态都受拟合时间约束。还可以同时施加时间和对象限制，分别报告新用户未来与老用户未来，避免一个总分混淆迁移方向。

<a id="pd4-ex5"></a>

### 8.5 练习五：为什么七日间隔不是万能规则

**问题：** 特征三十日、标签七日、标签两日后完整，验证从二十日开始，简单删去此前七日锚点是否保证可上线？

**解析：** 不保证，最后允许训练锚点的标签还可能在二十日之后才完整。应直接检查每条训练标签可用时间不晚于拟合时刻，而不是只按固定间隔猜测。同时历史特征共享早期合法事实不必全部禁止。若另有重叠清除目的，应定义各样本的信息区间与评估设计。一个标量间隔无法同时表达来源延迟、标签成熟、用户依赖和未来分布变化。

<a id="pd4-ex6"></a>

### 8.6 练习六：全表中位数没有标签，为什么仍有问题

**问题：** 只用全表数值列估计中位数，没有读取标签，为什么还要在训练内拟合？

**解析：** 因为测试分布已经影响了模型输入函数，评估不再对应仅有训练数据时上线的流程。若任务明确允许上线前得到无标签目标域并进行适配，可以另作半监督或传导式设计，但必须事先声明。普通独立测试应冻结训练中位数，并观察测试缺失和分布变化。交叉验证也要每折重拟合，否则验证折参与参数估计，选择结果会偏向利用这种额外信息的方案。

<a id="pd4-ex7"></a>

### 8.7 练习七：未知类别全零是否等于缺失

**问题：** 独热编码忽略未知类别后返回全零，能否声称模型能区分未知与缺失？

**解析：** 不一定。如果训练词表包含显式缺失桶，缺失有专用非零位置，而未知全零，可以区分；如果缺失桶从未进入词表，缺失也可能被当未知，二者合并。若删除基准类别，全零还可能与基准类别冲突。应检查实际编码映射，必要时预定义缺失与未知类别，并监测各状态覆盖，而不是仅看`handle_unknown`参数就得出语义结论。

<a id="pd4-ex8"></a>

### 8.8 练习八：连接行数不变是否足够

**问题：** 属性连接前后都是一千行，是否能直接认为样本身份和金额正确？

**解析：** 不能，可能删去一条同时复制另一条，也可能错配了键但没有改变行数。应比较样本键集合、检查唯一性、验证连接基数、核对未匹配原因，并对理应守恒的金额对账。时间版本还需独立核验，因为错误地连到未来属性也可能完全保持行数和金额。结构不变式与历史语义检查互为补充，不能相互替代。

<a id="pd4-ex9"></a>

### 8.9 练习九：新旧规则输出均值相同

**问题：** 旧规则用七个完整本地日，新规则用最近一百六十八小时，整体金额均值接近，是否可以直接替换？

**解析：** 不能，夏令时、锚点时刻和日历边界可能使成员变化集中在某些地区。应固定输入逐样本比较成员、特征差异与分层覆盖，再评估模型影响。整体均值相同可能由正负差抵消，也可能掩盖关键少数群体变化。规则版本应升级，是否沿用模型要基于输入契约和验证结果，而不是仅凭全局摘要接近。

<a id="pd4-ex10"></a>

### 8.10 练习十：只有最终快照能否严格回放

**问题：** 订单表只有最终金额和最后更新时间，没有旧版本，能否用最后更新时间过滤后恢复任意历史？

**解析：** 通常不能。过滤会把晚修订订单整条删掉，但当时可能已存在一个旧金额版本；保留则可能带入未来修订。缺失的历史状态无法由最终状态唯一推断。可以限制到能够证明未修订的字段、取得日志或备份、或者明确采用近似回放并研究误差，但不能把近似称为严格历史正确性。数据记录能力决定可审查边界，不是再加一个筛选条件就能补足。

<a id="pd4-ex11"></a>

### 8.11 练习十一：服务与离线共享代码是否充分

**问题：** 同一个函数同时用于训练和服务，为什么仍可能有训练服务差异？

**解析：** 两边可能读取不同来源版本、使用不同时间精度、传入不同锚点、携带不同预处理状态，也可能线上走缓存或降级分支。共享代码只减少实现分叉，不固定环境与输入语义。应在冻结样本上逐层比较原始特征、转换矩阵与预测，并验证失败路径和状态年龄。若共同函数的边界本身错了，两边一致也只是共同错误，还需独立手算验证。

<a id="pd4-ex12"></a>

### 8.12 练习十二：重叠标签与指标单位

**问题：** 同一用户连续七日评分，一次购买使七个标签为正，将这七行当独立用户计算置信区间有什么问题？

**解析：** 多行共享同一事件与用户状态，误差相关，有效独立信息量通常小于七条。按独立行估计不确定性可能过窄。应依据部署与依赖结构采用合适的分组或时间块重采样，并报告按用户日和按用户的指标差异。重叠标签不必删掉，因为真实服务也重复决策；关键是承认依赖与权重，避免将样本行数误当独立用户数。

<a id="sec-8-1"></a>

### 8.13 综合练习：连接与缺失一起对账

**问题：** 三条唯一样本左连接用户属性，右表有重复版本、一个空用户键、一个无匹配用户。怎样建立验收，而不靠连接后去重凑回三行？

**解析：** 先明确空实体是否允许进入任务，通常无法识别实体的样本应隔离；再对每个锚点恢复当时可见且有效的唯一属性版本，无法定夺的同刻冲突需拒绝或按权威规则处理。左连接声明预期基数，保留无匹配样本并给出原因，核对样本键集合和唯一性。Pandas 空键匹配需显式防止未知身份互相匹配。连接后去重可能随意选择未来版本，数量恢复不代表语义恢复。

<a id="pd4-ex14"></a>

### 8.14 研究练习：设计可审查的回补策略

**问题：** 新到一批迟到支付后，哪些产物需要改，哪些应保持？如何验证没有把事后知识带进历史特征？

**解析：** 先区分当时决策重放、事后完整统计和尚未确认标签。当时特征仍按各自可用边界查询，不因晚到而追溯拥有新信息；事后统计可更新；标签按预定确认与修订政策决定是否更正。记录受影响锚点与来源版本，并用未来污染、历史成员对照和目标对账验证。若迟到超过原完整性承诺，应报告来源契约违约并评估旧标签错误，不能只悄悄补数再宣称流程一直正确。
