## 1. 从列的含义理解 DataFrame

<a id="pd1-grain"></a>

### 1.1 一行是什么：数据粒度先于清洗规则

DataFrame 可以看成共享行索引的一组列，每列有自己的类型；Series 是带索引的一维对象。这个结构说明怎样存储，却不能说明一行在现实中代表什么。一行可以是一位用户、一笔订单、一件商品、一台设备一次上报，或者某个预测时点的用户快照。只有确定这种粒度，才能判断重复是否错误、缺失是否允许、统计分母应是什么。

假设两行都是用户甲、金额二十元、同一天。若表的粒度是一笔交易，它们可能是两次真实购买；若粒度是用户每天的总消费，它们可能违反唯一性；若粒度是订单商品行，甚至需要商品序号才能识别。对整表直接调用去重，只证明若干可见字段相等，不能证明两个现实事件相同。清洗首先需要业务键与事件定义，随后才是程序。

建议先写一份最小数据契约：一行的含义、主键字段、列的单位、允许的缺失、取值范围、时间含义、来源及输出用途。金额应注明是元还是分、含税还是不含税、订单应付还是实付；年龄应注明测量日期与允许区间；编号应注明是否区分大小写和前导零。相同列名也可能包含不同概念，不能仅凭名称相同就合并。

还有一种容易忽略的粒度变化：导出工具把订单头与明细连接后，订单金额被重复到每件商品。此时主键往往从订单编号变成订单编号与明细序号，金额却仍是订单级属性。行数增加是合理的，但再把金额沿行求和会错误放大。因此，数据契约不仅描述键，也应描述每个指标的归属层级；并非同一行出现的所有数值都可以直接相加。

<a id="sec-1-1"></a>

### 1.2 基础算例：先确认一行代表什么再清洗

三笔订单的实付金额是十元、未知、零元。忽略未知后的均值是五元，它描述已知金额订单；把未知填零后的均值是十除以三元，它描述人为补零后的三笔记录。两个结果计算都可以正确，回答的问题却不同。未知金额可能来自支付回调延迟，零元可能来自积分兑换，合并处理会同时破坏业务状态和统计含义。

再假设未知金额订单后来确认实付一百元，真实三单均值应为一百一十除以三元。此例说明，仅从当前两笔已知订单无法推出缺失订单的分布。程序可以按照事先声明的规则输出已知金额均值，但必须同时输出已知订单数、总订单数和缺失率，不能把它包装成完整总体均值。

如果三行其实是同一订单的三件商品，以上“订单平均”解释从一开始就不成立。应该先依据订单键汇总商品实付，确认折扣和运费的分配，再计算订单统计。学习表处理时可以始终追问：当前一行代表什么，分母数的是行、订单还是用户，数据变换后这个答案是否仍然相同。这三个问题比记住默认参数更重要。

<a id="pd1-inspection"></a>

### 1.3 初步画像：结构检查不等于正确性证明

读取后先查看列名、形状、类型、索引、缺失数与样例，再检查键重复、极值、类别频数及各来源分布。`head()`有助于了解格式，`info()`有助于识别类型和非缺失数量，`describe()`有助于发现明显尺度问题，但这些都是诊断入口。最前面五行正常不能说明文件后半部分没有混入另一种单位，均值正常也不能排除正负错误抵消。

画像至少分三个尺度：全表统计发现总量异常，分来源或批次统计发现采集差异，行级失败样例解释异常原因。某列整体缺失百分之十，可能是每个来源都随机缺少十分之一，也可能是一个来源完全丢失该字段。两种情况对填补、部署和来源公平性的影响差别很大。诊断应尽量保留这种结构，而不是只报一个总百分比。

原始行号适合作为追溯位置，不适合作为业务身份。读入后可以保存来源文件标识与源记录序号，清洗过程中保持稳定，使隔离行能够回到原始记录。若清洗后重置索引，应先把需要的来源位置保存成普通列。否则，一个报错中出现的“第七行”可能已经是排序后的第七行，难以定位上游问题。

### 图解：缺失值改变统计分母

![缺失值改变统计分母](images/01-concept.svg)

**图解。** 沿两条分支比较分母：原始列是 10、缺失、20，跳过缺失得到 15，填零后得到 10。图中缺失格特意与数值格区分，因为填零引入了额外假设。

## 2. 缺失值的处理需要业务判断

<a id="pd1-null-representation"></a>

### 2.1 缺失标记与可空类型：值域也包括未知状态

Pandas 的缺失表示并非单一对象。浮点列通常用 NaN，日期时间用 NaT，显式可空整数、字符串和布尔列可以使用`pd.NA`；对象列也可能混有 Python 的 None。应使用`isna()`和`notna()`判断缺失，而不是与某个哨兵做普通相等比较。空字符串、纯空格、文字“未知”默认不一定是缺失，必须依据输入协议转换。

传统整数数组不能直接容纳 NaN，因此含缺失的整数可能被推断为浮点。若字段是可缺失计数，显式`Int64`可以保留整数值域及缺失状态；这里大写类型名称与 NumPy 的普通整数类型不同。可空布尔用`boolean`，字符串可显式用`string`。指定类型不仅节省解释成本，还可以拒绝不符合域的值，避免把编号、计数和连续量都塞进混杂对象列。

可空类型不是“什么都接受”。把一点五转换为可空整数通常应失败，因为它不是整数；清洗应决定这是合法小数、单位误差还是非法计数。不要为了让转换通过先四舍五入，再忘记发生过信息丢失。反过来，若数值是测量结果，转换成整数本身就改变了精度与统计问题，不能因报表只显示整数就丢弃小数。

转换到 NumPy 数组也需要契约。含`pd.NA`的可空整数列可能生成对象数组；数值算法通常需要显式浮点类型与缺失表示，例如选择浮点输出并指定缺失为 NaN，再确认下游算法是否接受。数组转换会失去标签信息，不能一边依赖索引身份，一边默认转换后仍按原标签自动匹配。

<a id="pd1-three-valued"></a>

### 2.2 三值逻辑：未知不总能被直接判真或判假

对于可空布尔，逻辑表达式的结果可以是真、假、未知。未知与真做逻辑与仍未知，未知与假做逻辑与可以确定为假；未知与真做逻辑或可以确定为真，未知与假做逻辑或仍未知。这是从可能值集合推出来的：若缺失项可以是真或假，只有所有可能赋值都给出相同结果，当前结果才确定。

因此，`False & pd.NA`可确定为假，`True | pd.NA`可确定为真。普通比较产生未知时，不应直接把它当布尔标量；例如`bool(pd.NA)`会报歧义错误。布尔筛选接受可空掩码时，未知位置按未选中处理。这是筛选规则，不代表缺失条件在业务上已经被证明为假。需要区分“确定通过”“确定不通过”和“无法判断”时，应保留三组。

假设准入条件为年龄至少十八岁且已同意条款。年龄缺失、条款明确未同意的记录可以确定不满足整个条件；年龄缺失、条款已同意则仍未知。若把全部未知提前填假，最终被拒绝的人数可能相同，但你失去了区分拒绝原因与需要补资料的能力。模型训练时，这种混合也可能把采集缺失误当业务否定。

在向量条件里使用`&`、`|`和`~`，比较项各加括号。Python 的`and`、`or`要求整个对象的真假，不能表达逐行逻辑。还要注意，操作符优先级、对象列中混杂字符串以及缺失传播，都可能让看起来简洁的表达式偏离意图。关键筛选最好拆成命名掩码，分别统计通过、失败与未知数量。

```python
import pandas as pd
age = pd.Series([20, pd.NA, 16, pd.NA], dtype="Int64")
consent = pd.Series([True, True, True, False], dtype="boolean")
eligible = (age >= 18) & consent
assert eligible.tolist() == [True, pd.NA, False, False]
assert eligible.isna().sum() == 1
selected = pd.DataFrame({"age": age}).loc[eligible]
assert selected.index.tolist() == [0]
assert (pd.Series([False], dtype="boolean") & pd.NA).iloc[0] == False
try:
    bool(pd.NA)
except TypeError:
    pass
else:
    raise AssertionError("未知标量不应被静默解释为真假")
print("三值筛选：通过1，未知1，不通过2")
```

### 2.3 机制展开：填补规则改变了统计估计对象

设完整变量为随机变量 X，观测指示为 R，已观测时 R 等于一。删除缺失后计算均值，样本实际逼近的是给定 R 等于一时的条件均值，而不是自动逼近总体均值。只有附加适当条件，二者才会一致。例如观测与 X 独立且抽样过程合适时，已观测值可以代表原总体；若高金额订单更容易漏报，这个条件就被破坏。

固定常数填补的变量可以写作：观测时取 X，缺失时取常数 c。其均值由已观测部分贡献与缺失比例乘 c 组成。即使 c 恰好等于总体均值，使边际均值没有偏移，填补仍可能压缩方差、改变相关性和尾部概率。把均值恢复与把联合分布恢复混为一谈，会在相关分析和风险估计中得到过分乐观的结论。

上述变化可用一个短公式固定下来。令 R 表示是否观测，缺失时填常数 c，得到 $`\widetilde X=RX+(1-R)c`$。只要相关期望存在，就有

$$
\mathbb E[\widetilde X]
=\Pr(R=1)\mathbb E[X\mid R=1]+\Pr(R=0)c.
$$

该式不需要缺失独立假设，只是按观测状态分解期望。要把右侧等同于完整数据均值，还需缺失部分的条件均值等于 c，或其他能使差异抵消的条件。公式中的条件均值无法仅靠填补后没有空值来验证，因此，“程序完成填补”与“总体均值无偏”之间仍隔着统计假设。

中位数填补偏向稳健的中心位置，但并不意味着恢复了真实中位数条件分布。它会制造一个质量集中的点；当缺失很多时，模型可能把这个点误解成真实群体。增加缺失指示可以让模型分开解释真实等于中位数与被填补的记录，但这只是增加可用信息，不是证明缺失机制已被识别。

对预测任务，最佳填补规则还依赖损失、模型与部署分布。线性模型、树模型和能够原生处理缺失的模型，对同一填补的响应可能不同。应把填补作为完整训练流程的一部分，在合法划分中比较，而不是把某个“通用清洗法”当成与后续任务无关的真理。

<a id="pd1-missing-mechanism"></a>

### 2.4 MCAR、MAR、MNAR：假设如何连接可观测信息

完全随机缺失通常指缺失指示与相关完整数据独立。随机缺失这一名称容易误导：MAR 允许缺失依赖已观测变量，只要求在给定这些变量后，不再依赖缺失部分。例如工资调查中，回答概率依赖已经记录的职业类别，而在同一职业内不再依赖未填写工资，可以作为一个 MAR 假设。MNAR 则允许回答概率在控制已观测信息后仍依赖未观测值。

这些分类不是从一张缺失率表里直接读出的标签。已观测数据能够反驳某些过强假设，却通常无法凭自身完全区分多个缺失生成机制。高收入者更不愿填写收入与低收入者更不愿填写收入，在不同完整数据分布下可能形成相近的观测结果。机制判断应结合问卷流程、设备日志、补采样本和领域知识，并承认剩余不确定性。

在认为 MAR 合理且观测概率模型可靠时，可以考虑按观测概率的倒数加权，以修正代表性。这个思路要求相关群体有正的观测概率，概率估计足够好，且加权目标被明确定义；极小概率会产生很大的权重与方差。它不是看到缺失就直接调用的一步修复，更不能在观测概率为零的群体中凭空恢复未见信息。

倒概率加权的基本推理也能写清。令 Z 是总能观测的协变量，观测概率为 $`\pi(Z)=\Pr(R=1\mid Z)`$。在给定 Z 后 R 与 X 条件独立、且 $`\pi(Z)>0`$ 等条件下，迭代期望给出

$$
\mathbb E\left[\frac{RX}{\pi(Z)}\right]
=\mathbb E\left[\frac{\mathbb E[RX\mid Z]}{\pi(Z)}\right]
=\mathbb E\left[\mathbb E[X\mid Z]\right]
=\mathbb E[X].
$$

这说明权重为何出现，而不是让它成为神秘修复系数。实际使用估计的观测概率会引入估计误差，有限样本归一化也有不同形式；条件独立、正概率与有限矩等前提必须单独论证。若某类对象永远不被观测，分母为零，数据不能凭这个公式恢复该类的值。

更实用的分析是做敏感性比较：把缺失金额假定为观测均值的某个倍数，或在合理区间内改变其分布，观察决策是否改变。若结论只在一个非常乐观的填补假设下成立，就应把这种依赖写进结果。敏感性分析不保证找出真实机制，但能够明确目前证据究竟支持多强的结论。

<a id="sec-3"></a>

## 3. 索引对齐的便利与风险

<a id="pd1-loc-iloc"></a>

### 3.1 标签、位置与选择结果的形状

`loc`按标签选择，`iloc`按整数位置选择。索引恰好是整数时最容易混淆：索引为十、二十、三十的表中，`loc[20]`指标签二十，`iloc[1]`指第二行。默认 RangeIndex 使它们经常碰巧相同，但排序、过滤和连接后这种巧合就会消失。代码应表达身份还是位置，而不是依赖当前显示结果。

单个标签选择与标签列表选择还可能返回不同维度：唯一行标签取单行通常得到 Series，传入单元素列表通常保留 DataFrame。重复行标签会进一步改变结果形状，同一个`loc`表达式在唯一与重复索引下可能分别返回一行与多行。需要固定二维输出的函数，应使用列表并显式验证唯一性，不要在下游猜测对象维度。

标签切片在适当索引条件下包含右端点，位置切片遵循 Python 的左闭右开约定。未排序或重复索引的标签切片还可能产生额外限制或歧义，不应把它当通用数值区间查询。若意图是取某列数值落在区间中的行，直接构造比较掩码通常更清楚；若意图是有序索引上的范围，应先证明排序和唯一性条件。

列名同样可以重复。重复列名时取一列可能得到多列，赋值与类型转换也难以解释。很多业务流程应在入口拒绝重复列名，因为它意味着字段映射不再是单值函数。允许重复行标签是一个设计选择，允许重复列名也需要明确理由，不能因 Pandas 允许就默认适合训练表。

<a id="pd1-alignment"></a>

### 3.2 算术和赋值如何按标签匹配

两个 Series 相加默认按索引对齐。甲的索引为甲用户和乙用户，乙的索引为乙用户和丙用户，则结果覆盖并集；只有乙用户两边都存在，另外两处产生缺失。缺失在这里表示没有配对的操作数，不一定表示输入原表有空值。若没有区分这两种来源，你可能把一次身份匹配错误误诊为原始采集缺失。

给 DataFrame 的新列赋一个 Series 时也按索引对齐。经过筛选的表可能保留原来的行号，而新建 Series 使用从零开始的索引；两者就会错位。把新值转换成数组可以强制按位置赋值，但只有在长度一致且顺序已被证明一致时才合理。数组不会帮你检测两批同长度记录被交换，这是放弃标签保护后承担的责任。

如果意图是按业务身份匹配，应让索引承载该身份，或使用显式连接。若意图是按计算后的当前行顺序写回，可以从同一张表直接产生结果，或保存稳定行标识后恢复顺序。最危险的修复是为了消除 NaN 反复重置索引，却没有证明两边行顺序一致；它能让表看起来完整，同时把数据赋给错误的人。

```python
import pandas as pd
left = pd.Series([10, 20], index=["u1", "u2"], dtype="Int64")
right = pd.Series([1, 2], index=["u2", "u3"], dtype="Int64")
out = left + right
assert out.loc["u2"] == 21 and out.isna().sum() == 2
frame = pd.DataFrame({"score": [7, 8]}, index=[10, 30])
frame["wrong"] = pd.Series([100, 200])
assert frame["wrong"].isna().all()
frame["by_position"] = [100, 200]
frame["by_identity"] = pd.Series({30: 200, 10: 100})
assert frame["by_position"].equals(frame["by_identity"])
assert frame.loc[[30]].shape == (1, 4)
print("索引并集", out.index.tolist(), "对齐后缺失", int(out.isna().sum()))
```

<a id="deep-dive-3"></a>

### 3.3 深入讲解：标签对齐缺失值和类型转换为何是一套数据契约

可以把索引理解为从位置到身份的映射，把列类型理解为允许值的集合，把缺失规则理解为某些值为什么不在观测集合中。算术前需要两侧身份匹配，转换前需要输入属于可解释的值域，填补前需要明确未知的来源。三者不是独立小技巧，而是同一条语义链：谁的什么量，在什么条件下被观测，又经过什么规则变成当前值。

重复标签意味着身份映射不再一对一。在两个索引不完全一致且存在重复时，对齐可能展开成同标签组合，或在某些重索引操作中被拒绝；不要凭唯一标签时的经验推断所有重复情况。真正要求每个身份一个值时，先验证`index.is_unique`，不满足则回到粒度定义，决定聚合、补充复合键还是隔离数据。

一个强契约可以分成前置条件和后置条件。前置条件说明输入键唯一、金额以分为单位、时间格式统一；后置条件说明输出保持相同行身份、金额非负、失败行有原因。转换函数若只能保证值域而不保证身份，就不能独自承担训练样本构造。应把身份保持视为与数值精度同等重要的正确性要求。

失败时也不应一律返回空表。缺列属于模式错误，非法日期属于行级解析错误，重复主键属于关系约束错误，业务不适用属于允许状态；这些情形需要不同处理。区分错误类型，才能决定整批拒绝、局部隔离、允许缺失或人工核对。一个把所有问题都转成 NaN 的流程，会失去修复上游所需的证据。

<a id="pd1-reindex-mask"></a>

### 3.4 重索引与布尔掩码：显示顺序不是匹配依据

`reindex`用目标标签定义输出顺序与覆盖范围，找不到的标签会出现缺失；它适合把已有数据放到明确的身份全集上。`reset_index`则把旧标签变成普通列或丢弃，再生成新的位置标签。前者在回答需要哪些身份，后者在改变表示方式，两者不能相互代替。删除旧标签前，应确认身份信息已在其他字段保存。

布尔 Series 作为标签筛选掩码时，也有索引对齐语义。一个来自原表的掩码传给经过重排的表，可能仍能按标签找到正确行；而 NumPy 布尔数组只知道位置。如果索引重复，或者掩码和表的标签集合不同，这种推理就更复杂。要求严格对应的函数，可以先检查索引完全相等，再使用掩码，避免依赖隐式重排。

排序也有稳定性问题。按年龄排序后，相同年龄的用户之间未必具有业务次序；若随后按位置保留第一条，实际选择规则可能没有定义。应增加有意义的排序键，例如版本号与来源序号，并明确并列如何处理。索引对齐能保护身份匹配，却不能替你定义“最新”“第一”或“唯一正确版本”。

<a id="sec-4"></a>

## 4. 类型转换必须检查失败

<a id="pd1-text-id"></a>

### 4.1 文本规范化与标识符：先定义等价关系

编号通常应作为字符串读入。邮编、订单号、设备序列号中的前导零、固定长度和字母大小写，都可能承载身份。若先读成整数再补零，只能恢复你猜测的宽度，不能证明原值就是那个编号。更大的整数字符串若曾经过浮点表示，可能已丢失低位；之后转回字符串也无法恢复。保留原始文本是身份字段的重要保护。

文本清洗不是越激进越好。去首尾空格通常用于消除录入噪声，但若系统允许空格作为合法标识符一部分，规则就必须更谨慎；统一大小写可能适合不区分大小写的地区码，却可能合并区分大小写的令牌。全角半角归一化、Unicode 规范化和去除内部空白，都在定义哪些原值被视作等价，需要通过业务协议确认。

字符串列应分别处理真正缺失、空字符串、只含空白和文字占位符。可以先转换为显式字符串类型，再去首尾空格，将空串映为缺失；只有协议明确时才把“未知”“无”“NULL”等字面量也转换。某位客户姓名真的叫某个占位词的可能性虽小，原则上仍说明规则不能由程序员凭感觉无限扩展。

规范化后还要检查碰撞：两个不同原编号是否变成同一个标准编号。如果“甲空格”和“甲”确实代表同一人，碰撞可能是希望的结果；如果它们代表不同设备，就发生了身份合并。规范化不是纯显示变换，它可能改变键的唯一性、连接基数与样本权重，因此必须在规范化之后重新验证主键。

<a id="pd1-numeric"></a>

### 4.2 数值解析：失败、范围和单位要分开检查

`to_numeric`可以执行受控数值解析。使用`errors="coerce"`时，无法解析的值变成缺失，但这种选项只适合后续明确审计失败的流程；应计算“原本非缺失且转换后缺失”的掩码，把它与原始缺失分开。否则，原本未知、非法字符和不支持格式全部混在一起，你会以为只有缺失率变化，实际输入协议已经被破坏。

解析成功也不代表业务合法。负年龄、一百零一分的百分制成绩、无穷大交易额和错误单位的金额都可能是合法数字。检查至少分成语法解析、有限性、业务范围和单位一致性四层。正则表达式可以限制输入语法，但不能证明数值代表正确单位；范围检查可以发现部分异常，但不能识别所有单位混淆。

金额往往适合用最小货币单位的整数表示，或使用具有明确精度的十进制方案。二进制浮点不能精确表示许多十进制小数，直接乘一百再强制转整数可能受到表示误差影响。若输入协议只有两位小数，可以按字符串的整数部分和小数部分组合成分，或采用十进制定点解析，并明确舍入方式。不能把一个浮点容差当成所有财务规则的替代。

数值越界也需要记录原因。计数列转成小整数类型前，应检查整个允许范围和未来增长空间；为了节省内存而溢出，比暂时多占内存严重得多。`convert_dtypes()`方便探索可空表示，但其推断仍是表示层判断，不知道“这串数字是身份证号码”。最终生产契约应显式指定重要字段类型，而不是每批重新猜测。

<a id="pd1-category"></a>

### 4.3 类别类型：码值不提供自然距离

类别数据的值域是一组允许水平，类别编码只是内部表示。城市编码零、一、二不意味着第二个城市位于另外两个城市中间；把类别码直接输入线性距离算法，会强加不存在的数值几何。应根据任务使用独热编码、适当的类别模型或具有合法信息边界的编码方法，不能因列变成整数就认为可以求平均。

Pandas 的 Categorical 可以限定允许类别，并可显式声明有序类别。等级“小、中、大”的次序有业务意义时可以设置有序；颜色“红、绿、蓝”通常没有这种次序。未知值转换为受限类别时可能变成缺失，因此应在转换前检测新类别，区分原本缺失与超出词表。否则，模型面对新市场时的词表漂移会被静默隐藏。

训练词表与业务词表也不同。业务协议可能完整规定国家代码，此时验证允许值是固定规则；从训练集观察到的商品集合则是学习结果，验证集出现新商品应按预定未知策略处理。不要在训练之前从全量数据提取词表再声称流程完全没有使用测试输入分布。是否允许利用无标签测试分布，取决于任务设定，需要明示。

类别可以节省重复字符串的内存，但节省程度取决于行数、类别数和存储后端。几乎每行都唯一的标识符未必适合类别压缩。选择类型时应先保证语义正确，再做实际内存测量；类别多不等于应该编码成连续数，内存优化也不能成为破坏可解释值域的理由。

<a id="pd1-date"></a>

### 4.4 日期解析：字符串格式与时间含义是两层问题

`to_datetime`应尽可能指定输入格式，并对解析失败单独计数。形如零一斜杠零二的文本可能指一月二日，也可能指二月一日；让库自动猜测不能解决来源协议本身的歧义。混合来源应先识别来源格式，再分别解析，最后统一到目标类型，而不是寄希望于一次全列推断碰巧正确。

时间戳还需要说明它代表事件发生、系统接收、处理完成还是记录更新时间。这些时间可能相差很大。语法上成功解析的更新时间，不能替代预测特征可用时间；本章先建立字段含义，后续时间章节再讨论窗口与时点连接。这里的核心是：数据类型只说明“这是一个时间值”，并不能说明“当时是否已经可知”。

`utc=True`对带时区偏移的输入会统一到 UTC；对没有时区信息的输入则按 UTC 解释，不能假装它会自动知道来源地区。若无时区字符串实际表示上海本地时间，应先按无时区时间解析，再本地化为相应时区，最后转换为 UTC。夏令时地区还可能存在重复或不存在的本地时刻，需要明确歧义处理，不能把所有解析失败当坏数据删除。

在不涉及时间运算的出生日期、账单日期等字段中，日历日期可能比绝对时刻更合适。午夜 UTC 转到另一地区可能落在前一天，若把生日误当瞬时时间转换，年龄或分组就会变化。日期、当地墙上时钟与全球唯一时刻是不同语义，应选择能表达真实对象的表示。

<a id="pd1-parse-experiment"></a>

### 4.5 解析实验：把原始缺失、非法输入与不合法范围分开

下面实验对数量、地区与时间分别定义规则。数量要求非负整数，地区只允许两个明确代码，时间输入明确包含偏移。转换结果里的缺失不是最终原因，原因来自转换前后对照。这样的分离有利于统计上游协议问题，也防止把格式错误当成需要统计填补的随机缺失。

```python
import pandas as pd
raw = pd.DataFrame({
    "qty": ["2", "", "oops", "-1", "1.5"],
    "region": ["N", " S ", "X", None, "N"],
    "at": ["2025-01-01T08:00:00+08:00"] * 4 + ["not-a-date"],
})
qty_text = raw["qty"].astype("string").str.strip().replace("", pd.NA)
parsed = pd.to_numeric(qty_text, errors="coerce")
parse_bad = qty_text.notna() & parsed.isna()
range_bad = parsed.notna() & ((parsed < 0) | (parsed % 1 != 0))
qty = parsed.mask(range_bad).astype("Int64")
region = raw["region"].astype("string").str.strip()
unknown_region = region.notna() & ~region.isin(["N", "S"])
category = region.astype(pd.CategoricalDtype(["N", "S"]))
at = pd.to_datetime(raw["at"], format="ISO8601", errors="coerce", utc=True)
assert int(parse_bad.sum()) == 1 and int(range_bad.sum()) == 2
assert qty.iloc[0] == 2 and qty.isna().sum() == 4
assert unknown_region.sum() == 1 and category.isna().sum() == 2
assert at.isna().sum() == 1 and at.iloc[0].hour == 0
print("数量解析失败1，范围失败2，新类别1，时间失败1")
```

<a id="sec-5"></a>

## 5. 进阶：索引对齐与数据契约

<a id="sec-5-1"></a>

### 5.1 缺失值处理应从生成机制开始

真实零值、未采集、不适用和系统故障是四种不同状态。例如零贷款余额可能表示已经结清，未申请贷款导致余额不适用，接口故障导致余额未知。若全部填零，模型就无法区分偿付良好、没有贷款与数据不可用。应在可行时保留原因字段，而不是仅靠一个数值字段同时编码全部业务状态。

缺失指示也可能成为危险的捷径。某医院只有重症患者会接受一项检测，检测是否缺失就包含诊疗决策；部署到检测流程不同的医院，关系可能消失。某字段在标签确定后才补齐，缺失指示甚至可能间接泄漏标签。保留信息是为了能分析来源与合法性，不代表所有保留字段都应直接进入模型。

常数填补是预先固定规则，中位数填补、最频类别和异常分位数阈值则要从数据估计。后者应只在训练部分拟合，应用到验证与测试时保持固定。若做交叉验证，每折都应重新拟合，不能先在全表计算中位数再分折。即使没有直接读取标签，这也改变了评价时允许利用的信息范围。

还应考虑填补规则在部署时能否实现。全用户历史均值需要可用历史；某个群体样本过少，组中位数可能不稳定；新群体没有对应统计值，需要明确回退规则。回退到全训练中位数、保留未知或拒绝预测，各有代价，应在实验前定义，而不是上线报错后临时加一个填零。

<a id="pd1-duplicates"></a>

### 5.2 重复行、重复键与冲突版本

全行重复与主键重复要分开检查。全行重复可能是重复导出，也可能是缺少了某个区分事件的字段；主键重复但内容不同，可能是合法历史版本、上游冲突或错误地选择了主键。使用`duplicated(subset=..., keep=False)`可以定位所有冲突参与者，往往比只保留首条后看剩余数量更有诊断价值。

对版本数据，保留最新通常需要至少两个条件：版本排序确实对应业务有效性，并且同一优先级下不存在未解决冲突。更新时间相同但内容不同，单纯排序后取最后一条只是依赖当前输入顺序。可靠流程应拒绝这种并列，或者采用事先约定的来源优先级，并记录被覆盖的记录及原因。

不同来源的重复也可能形成非传递的模糊匹配。例如名字相似、电话号码部分相同并不能保证实体相同；合并实体属于独立的记录链接问题，不应藏在普通去重函数里。错误合并会污染标签，错误拆分会使同一人跨训练测试出现，从而影响评估。确定性主键存在时优先使用它，模糊匹配需要单独的质量评估。

主键允许缺失时更要谨慎。多条缺失编号并不说明它们是同一个实体，按缺失键去重可能只留下一条。对训练样本要求唯一身份的任务，常见做法是把缺失键记录隔离，或者使用可靠的复合键，而不是随意生成新编号后就宣称身份问题已解决。临时行号能够区分文件行，不能证明它们对应不同现实事件。

### 5.3 修改语义与 Copy-on-Write 的版本前提

本章代码核验在 Pandas 2.3.3 下完成，该版本不能假定 Copy-on-Write 已经默认启用。下面使用选项上下文显式开启，代码意图也不依赖全局设置。CoW 的重点是让派生对象的修改不意外传播到另一个 Pandas 对象，同时尽可能延迟真正的数据复制；逻辑上的独立与内存当下是否共享是不同层次。

在 CoW 下，从表取出一列再修改那个 Series，不会通过链式路径修改原表。需要改变原表时，应把选择与赋值放到同一次针对原表的`loc`操作中。`df["x"][mask] = value`或对临时列使用原地方法，都不应当作可靠的更新方式。代码应该清楚指出被修改对象，而不是依赖视图传播的偶然性。

`.copy()`适合表达需要独立结果的意图，但深拷贝也有边界。对于对象列中嵌套的 Python 列表或字典，DataFrame 的深拷贝并不递归复制每个嵌套对象。若两个表引用了同一个列表，对列表内部的修改仍可能在两边可见。应优先使用标量、不可变值或正规明细表结构；确实需要嵌套可变对象时，另行设计复制策略。

导出数组同样涉及别名与可写性。CoW 下某些共享底层数据的 NumPy 视图会只读，不能假定`to_numpy()`总给出可自由修改的独立数组。若外部算法需要写入，应明确请求副本，再检查类型与缺失表示。不要为了绕过只读限制而直接强行改标志，除非完全理解它可能破坏的共享状态。

```python
import pandas as pd
with pd.option_context("mode.copy_on_write", True):
    original = pd.DataFrame({"x": [1, 2], "y": [10, 20]})
    derived = original[["x"]]
    derived.loc[0, "x"] = 99
    assert original.loc[0, "x"] == 1
    original.loc[original["x"] == 2, "y"] = 77
    assert original.loc[1, "y"] == 77
    array = original["x"].to_numpy(copy=True)
    array[0] = -1
    assert original.loc[0, "x"] == 1
nested = pd.DataFrame({"items": [[1], [2]]})
copied = nested.copy(deep=True)
copied.loc[0, "items"].append(9)
assert nested.loc[0, "items"] == [1, 9]
print("CoW修改对象边界与嵌套对象深拷贝边界均已验证")
```

### 5.4 一个可审计清洗器应承诺什么

把清洗器写成函数时，应区分模式验证、字段规范化、转换诊断、行级决策和结果验收。模式验证确认必需列存在且列名唯一；规范化只执行已声明的等价变换；转换诊断产生数值与原因；行级决策把记录送入接受集或隔离集；验收检查身份、类型与数量平衡。这个分层使失败可以定位，而不必从最终少了几行倒推。

行级原因可以是多个布尔标记，而不必强行只留一个。某条记录可能同时金额非法、日期非法和地区未知；若只记录第一个错误，修好金额后还会再次失败。多原因记录支持统计交叉分布，但报表中的原因计数之和可能超过隔离行数，必须明确说明。若需要互斥的主原因，应在保留全部标记后另设有优先级的摘要字段。

清洗器最好保留原始值，并输出单独的标准列。原始列用于追踪转换是否正确，标准列用于分析；覆盖原始金额后，就难以区分上游真的传入了空值还是程序解析失败。对于敏感字段，保留原始值需要符合现有访问政策，这属于数据管理约束；本章的原则是保留足够追溯证据，而不是无限复制所有敏感信息。

后置条件应包括输入行数等于接受行与隔离行之和，来源行标识无重复且集合完全覆盖，接受行主键唯一，标准列类型与范围正确，原始输入没有被意外修改。金额总量核对需要说明核对哪部分：原始非法字符串无法直接求和，不能把解析后总和与包含未知意义的原始列求和盲目比较。应先确定可比口径，再检查守恒。

<a id="pd1-idempotence"></a>

### 5.5 幂等性、不可逆变换与拒绝悄悄修复

清洗规则常希望具有幂等性：对已符合标准的数据再次执行规范化，结果不再变化。去首尾空白、统一明确的代码形式通常可以设计为幂等；每运行一次就除以一百的金额换算却不是。若重复执行会再次改变单位，应通过原始与标准列、版本标识或独立输入接口防止误用，不能只靠使用者记住“这个函数只能运行一次”。

幂等也不代表正确。把所有金额设为零是幂等函数，却显然破坏信息。它只是工程性质之一，应与语义保持、范围约束、行级追溯和业务守恒一起检查。另一个重要性质是失败可见：新增未知地区时流程应产生明确错误或隔离原因，而不是把它吸收到默认类别后使指标突然变化却没有警报。

不可逆转换尤其需要记录。删除原始空白、截断小数、合并类别与删除记录，都会把多个输入映成同一输出。若之后发现规则不合适，单靠标准表往往无法恢复。保留输入快照引用与规则版本，可让流程从原始数据重算；不一定需要在每个中间步骤保存文件，但必须能够知道最终结果由什么输入与规则产生。

## 6. 完整实验：从原始订单到可解释的接受与隔离结果

<a id="pd1-design-experiment"></a>

### 6.1 明确本实验的协议与有限目标

实验输入一行代表一笔订单，订单键必须存在且在规范化后唯一；编号去首尾空白，不改变大小写；地区仅允许北区和南区代码。金额输入以元为单位，非负，最多两位小数，不允许千位分隔符和科学计数法；标准输出以分为整数。支付时间必须符合严格的四位年、两位月、两位日格式，表示上海本地日期的午夜，本实验只做格式与来源时间约定，不构造历史特征。

本实验故意不做统计填补。缺失订单键、重复键冲突、非法金额、未知地区和非法日期全部隔离，目的是得到可以审计的事实表，而不是马上为模型造出没有缺失的矩阵。将未知金额替换成中位数属于另一个训练变换，应从接受的、有合法样本身份的数据出发，在划分之后单独拟合。这样可以避免把业务错误修复与统计估计混成一个不透明步骤。

对重复订单键，本实验隔离所有冲突参与者，而不是随便保留第一条。这个选择适合没有可靠版本字段的情况；若上游提供可靠版本号，可以增加明确的冲突消解协议。保守隔离可能减少可用样本，因而还应监控隔离比例和来源结构；拒绝猜测并不意味着被隔离样本对总体没有影响。

### 6.2 自足实现：原始值、原因矩阵与分区对账

```python
import re
import pandas as pd
from pandas.testing import assert_frame_equal

def clean_orders(raw):
    required = ["order_id", "amount_text", "region", "date_text"]
    if not raw.columns.is_unique:
        raise ValueError("重复列名")
    if any(name not in raw for name in required):
        raise ValueError("缺少必需字段")
    work = raw.copy(deep=True).reset_index(drop=True)
    work.insert(0, "source_row", range(len(work)))
    oid = work["order_id"].astype("string").str.strip().replace("", pd.NA)
    amount = work["amount_text"].astype("string").str.strip().replace("", pd.NA)
    region = work["region"].astype("string").str.strip().replace("", pd.NA)
    date = work["date_text"].astype("string").str.strip().replace("", pd.NA)
    # 解析语法限定最多九位元，保证转换远离Int64溢出边界。
    pattern = re.compile(r"[0-9]{1,9}(?:\.[0-9]{1,2})?\Z")
    valid_amount = amount.str.fullmatch(pattern).fillna(False)
    cents = pd.Series(pd.NA, index=work.index, dtype="Int64")
    for idx, text in amount.loc[valid_amount].items():
        whole, dot, fraction = text.partition(".")
        cents.loc[idx] = int(whole) * 100 + int((fraction + "00")[:2])
    valid_date_syntax = date.str.fullmatch(r"[0-9]{4}-[0-9]{2}-[0-9]{2}").fillna(False)
    parsed_date = pd.to_datetime(date.where(valid_date_syntax), format="%Y-%m-%d", errors="coerce")
    # 明确输入为当地午夜，再转UTC；不把无时区输入直接误解为UTC。
    paid_at = parsed_date.dt.tz_localize("Asia/Shanghai").dt.tz_convert("UTC")
    duplicate_key = oid.notna() & oid.duplicated(keep=False)
    reasons = pd.DataFrame({
        "missing_key": oid.isna(),
        "duplicate_key": duplicate_key,
        "missing_amount": amount.isna(),
        "invalid_amount": amount.notna() & ~valid_amount,
        "invalid_region": region.isna() | ~region.isin(["N", "S"]),
        "invalid_date": parsed_date.isna(),
    }).astype(bool)
    work["order_id_clean"] = oid
    work["amount_cents"] = cents
    work["region_clean"] = region.astype(pd.CategoricalDtype(["N", "S"]))
    work["paid_at_utc"] = paid_at
    bad = reasons.any(axis=1)
    accepted = work.loc[~bad].copy()
    rejected = work.loc[bad].join(reasons.loc[bad].add_prefix("reason_")).copy()
    assert len(raw) == len(accepted) + len(rejected)
    assert accepted["order_id_clean"].is_unique
    assert accepted["order_id_clean"].notna().all()
    assert accepted["amount_cents"].ge(0).all()
    seen = pd.concat([accepted["source_row"], rejected["source_row"]])
    assert seen.is_unique and set(seen) == set(range(len(raw)))
    audit = {"input": len(raw), "accepted": len(accepted), "rejected": len(rejected),
             "accepted_cents": int(accepted["amount_cents"].sum()),
             "reason_counts": reasons.sum().to_dict()}
    return accepted, rejected, audit

raw = pd.DataFrame({
    "order_id": ["001", "002", " 003 ", "004", "004", "", "005", "006"],
    "amount_text": ["10.50", "0", "oops", "5.00", "6.00", "2.00", "7.00", None],
    "region": ["N", "S", "N", "N", "N", "N", "X", "S"],
    "date_text": ["2025-01-02"] * 6 + ["2025-02-30", "2025-01-02"],
})
before = raw.copy(deep=True)
accepted, rejected, audit = clean_orders(raw)
assert_frame_equal(raw, before)
assert audit["input"] == 8 and audit["accepted"] == 2 and audit["rejected"] == 6
assert audit["accepted_cents"] == 1050
assert accepted["order_id_clean"].tolist() == ["001", "002"]
assert audit["reason_counts"] == {
    "missing_key": 1, "duplicate_key": 2, "missing_amount": 1,
    "invalid_amount": 1, "invalid_region": 1, "invalid_date": 1,
}
again = clean_orders(raw)
assert_frame_equal(accepted, again[0])
assert_frame_equal(rejected, again[1])
assert audit == again[2]
nonpadded = raw.copy(deep=True)
nonpadded.loc[0, "date_text"] = "2025-1-2"
assert clean_orders(nonpadded)[2]["reason_counts"]["invalid_date"] == 2
assert clean_orders(nonpadded)[2]["accepted"] == 1
print(audit)
```

### 6.3 逐步解释输出与反事实故障

接受的两条记录是订单零零一与零零二。前者金额十元五角，对应一千零五十分；后者金额为零且所有约束满足，必须保留。订单零零三金额为非法字符串；订单零零四有两条冲突，两条都隔离；空编号无法建立业务身份；订单零零五既地区非法又日期非法；订单零零六原始金额缺失。六条隔离行产生七个原因标记，因为一行可以有多个问题。

源行标识的集合与唯一性检查保证接受与隔离分区没有漏行和重叠。仅检查八等于二加六还不够：若漏掉一条又复制另一条，数量仍然相等。接受订单键唯一性保证当前事实表保持粒度，金额总量一千零五十分提供一项可手算的不变量，原始表相等检查防止函数意外改写调用者输入。这几项检查分别覆盖不同故障，不能相互替代。

这里重复调用同一原始输入得到相同结果，验证的是确定性；它不同于把标准输出再次当原始输入得到相同结果的幂等性。函数接口要求原始字段，输出保留标准列，若直接把输出再次传入会与源行列发生冲突。因此，不应把这个实验宣传为通用幂等清洗器。要支持标准表再清洗，应设计另一个有明确版本和字段协议的接口。

可以故意把零金额加入非法规则，观察接受行从两条降为一条，此时总金额仍是一千零五十分，说明只检查金额总量会漏掉合法零值被删的错误。也可以错误地保留重复键第一条，观察行数增加但身份冲突没有获得证据解决。还有一种错误是直接对全部金额强制数值解析，随后填零，非法字符串就会与真实零合并，错误原因不再可追踪。

本实现以九位元上限回避整数溢出，不适合未经修改地处理任意大金额；日期协议只用于本实验样本，并不覆盖所有历史时区变更；循环解析强调规则可读性，超大表可使用经过等价核对的向量化或分块实现。教材实验应该明确这些边界，而不是让短代码暗示已经解决所有金融和全球时间问题。

<a id="pd1-monitoring"></a>

### 6.4 从一次清洗走向长期质量监控

固定断言适合不可违反的契约，例如主键唯一、金额类型正确；缺失率与类别频率则往往需要基于历史与业务容忍度的监控阈值。把缺失率超过百分之五设为错误之前，需要知道正常波动、批次大小和节假日影响。小批次里一条缺失就可能让比例大幅变化，监控应同时报告分子和分母，而不是只有百分比。

质量指标应按来源、日期和关键群体分层。整体解析失败率保持不变，也可能掩盖某个新来源从零上升到全部失败，而另一个来源流量增加把它稀释。分层过细又会产生大量小样本噪声，需要约定最小样本量和复核策略。目标是找出有行动意义的变化，不是为每个微小波动制造一个警报。

还应监控接受率和任务表现之间的关系。清洗规则收紧后，训练数据更“整齐”，但某类困难群体可能被大量排除，离线指标反而虚高。接受集不是天然代表总体，应记录被排除原因、来源与合法可观测的群体属性，并在评估时说明覆盖范围。如果拒绝预测也是产品行为的一部分，覆盖率和拒绝代价就应进入完整决策评价。

### 7.1 练习一：零值、缺失与统计分母

**问题：** 五笔订单金额为零、十、二十、缺失、缺失。某报告给出平均金额六元，另一报告给出十元，是否必有一个程序写错？应该如何表述？

**解析：** 六元对应把两笔缺失填零后，以五笔订单为分母；十元对应只对三笔已知金额取均值。它们不必存在算术错误，但若都写成真实订单平均金额，就存在解释错误。原始金额未知时，真实总体均值没有被这五行数据唯一确定。应同时说明已知金额合计三十元、已知笔数三、总笔数五，并明确是否采用补零假设。

若业务证明缺失来自免费订单未写入金额，补零可以有依据；若缺失来自支付回调延迟，补零通常不成立。推断需要来源证据，不能通过比较哪个均值更接近预期来决定。还应注意零金额不能被`amount > 0`的随手筛选误删，否则已知订单均值又会变成十五元。

<a id="pd1-ex2"></a>

### 7.2 练习二：整数标签与整数位置

**问题：** 表的索引为一百、三百、二百，想取得显示中的第二行及业务标签二百对应的行，应分别使用什么？把索引排序后原代码是否还能成立？

**解析：** 第二行是位置，应使用`iloc[[1]]`保持二维；标签二百使用`loc[[200]]`。排序后位置一可能对应另一条业务记录，而标签二百仍然指向同一身份，前提是标签唯一且未被改写。因此，选择方法表达的是不同问题，不能以当前结果恰好相同作为相互替换的理由。

若函数声称按身份读取，却使用`iloc`，它对输入排序敏感；可以通过随机重排后按稳定身份对照结果来暴露错误。若函数本来就是计算排序后的第二名，位置选择是合理的，但排序键及并列规则必须明确。位置并不低级，问题在于把位置误当身份。

<a id="pd1-ex3"></a>

### 7.3 练习三：赋值之后全是缺失

**问题：** 从原表筛出索引为五和八的两行，将新建的两元素 Series 赋给新列后全部缺失。直接重置索引是否就是正确修复？

**解析：** 新 Series 默认索引为零和一，赋值按标签匹配，找不到五和八，于是产生缺失。应先判断新值如何计算：如果新值确实按当前两行顺序产生，可以显式使用同一索引构造 Series，或在确认长度和顺序后按数组赋值；如果来自另一张表，应按业务键连接。重置索引只消除表面不匹配，不能证明新值属于正确记录。

一个反例是两元素新值的顺序其实与筛选表相反。重置索引会得到没有缺失但完全错配的结果。解决这种问题需要保存来源身份，检查键集合及一一对应，必要时把两边都按同一稳定键排序。视觉上“没有 NaN”并不是身份正确的证据。

<a id="pd1-ex4"></a>

### 7.4 练习四：三值逻辑与业务拒绝原因

**问题：** 可空年龄与同意条款列组成准入条件。年龄未知且条款为假时，整体条件为什么可以为假？年龄未知且条款为真时为何不能确定？

**解析：** 把未知年龄是否成年看作两种可能。如果条款是假，无论年龄条件真或假，逻辑与都为假，因此结果确定。条款是真时，两种可能分别给出真和假，结果仍未知。这个推理说明三值逻辑不是任意的库约定，而是对部分信息下确定性的一种表达。

筛选时未知不被选中，不代表它在业务上等同拒绝。若业务要求补充年龄后再审核，应单列未知组；若只保留最终通过者，可以用筛选规则，但审计报告仍应区分确定不通过和资料不足。把两者混合会让运营无法判断应拒绝还是补采。

<a id="pd1-ex5"></a>

### 7.5 练习五：解析成功与业务正确

**问题：** 字符串“一千”解析失败，字符串“一千的阿拉伯数字写法”可以解析，负五也可以解析。能否认为只要数值转换没有新缺失，数据就正确？

**解析：** 不能。数值解析只验证特定语法是否可被转换；负五若表示年龄就违反范围，表示温度则可能合法。一千若实际以分计而流程按元使用，解析完全成功却产生百倍单位误差。因此需要分开验证语法、有限性、范围、单位和字段含义，不能让其中一项代替全部。

对书写为中文数词的输入，应该先判断协议是否允许；允许时需要明确的中文数词解析，不允许时隔离并记录。随意删除所有非数字字符会把负号、小数点与单位也删掉，可能把负五变成五、三点五变成三十五。这种“清理”比明确失败更危险。

<a id="pd1-ex6"></a>

### 7.6 练习六：标识符的不可逆损失

**问题：** 邮编零零一二三先被读成整数一百二十三，再转字符串并补齐五位，是否保证恢复正确？很长的编号若经过浮点转换又如何？

**解析：** 固定五位且输入协议确实限定这一宽度时，补零可以恢复规范显示；但若编号长度本身有意义，或者不同系统允许不同宽度，补零是在添加假设。读入阶段显式字符串类型可以避免这种不必要的推断。标准化后还要检查原本不同编号是否发生碰撞，不能只看每个值是否满足长度。

很长编号若经过二进制浮点，低位可能已发生舍入，字符串补零无法恢复丢失位数。应回到保留的原始输入重新解析，不能从已经损失信息的结果猜测。身份字段的精确性比是否能参与数值运算更重要，它们通常应留在字符串域。

<a id="pd1-ex7"></a>

### 7.7 练习七：未知类别为什么不只是缺失

**问题：** 训练允许类别为北区和南区，新批次出现东区；强制转换为原类别类型后得到缺失。能否与原本没填写地区的记录一起填为北区？

**解析：** 不宜无条件如此。原本缺失表示未获得地区，新类别表示已获得一个不在原词表中的值，两者反映不同问题。前者可能是采集缺失，后者可能是业务扩展、拼写错误或训练覆盖不足。应在转换前保存超词表掩码，明确未知类别策略，必要时更新业务协议与模型。

把它们都填成最常见类别会隐去业务变化，也会让东区记录被当成北区处理。若模型允许未知水平，可以映射到专门类别并监控表现；若地区是关键路由字段，则可能需要拒绝或人工复核。策略取决于任务成本，不能由转换产生 NaN 这一表现单独决定。

<a id="pd1-ex8"></a>

### 7.8 练习八：同样的时间字符串可以差八小时

**问题：** 输入“二零二五年一月二日上午八时”实际是上海当地时间。直接按 UTC 解析与先本地化上海再转 UTC 有何差别？

**解析：** 直接将无时区输入按 UTC 解释，会把它当作全球标准时间八时；先按上海本地化再转 UTC，会得到同日零时。差别不是显示格式，而是两个不同的绝对时刻，可能影响跨日统计与特征可见性。库不能从一个无偏移字符串推知来源地区，需要协议提供这个信息。

若字段表示生日这样的日历日期，可能根本不应当转成全球瞬时再跨时区显示。应先辨别它属于日历日期、本地时钟还是绝对时刻。时间清洗的第一步是语义选择，格式解析只能在这个选择之后保证一致表示。

<a id="pd1-ex9"></a>

### 7.9 练习九：为什么隔离全部冲突行

**问题：** 同一订单编号出现两条不同金额，清洗程序隔离两条是否太保守？为什么不保留最后一行？

**解析：** 没有可靠版本信息时，最后一行只表示输入顺序，不能证明它更正确。隔离全部冲突行使问题可见，并避免把任意选择伪装成业务事实。若能够取得可信版本号、有效期或来源优先级，可以据此消解冲突，但仍应保留被替代记录与规则证据。

保守隔离也有代价：若某类渠道更易出现冲突，接受集会改变来源分布。因此，隔离是当前证据下的操作选择，不是对总体无影响的中性处理。应同时报告冲突率、来源与后续补救结果，必要时评估拒绝行为对任务覆盖的影响。

<a id="pd1-ex10"></a>

### 7.10 练习十：深拷贝为什么仍可能相互影响

**问题：** 两个 DataFrame 已使用深拷贝分开，但其中一列存列表，修改一个列表内部元素后另一表也变化，是否说明深拷贝失效？

**解析：** DataFrame 深拷贝复制表层数据结构，不承诺递归复制对象列中任意 Python 对象。列表引用所指向的可变对象仍可能共享，修改列表内部属于 Python 对象变化，不是对表中一个普通标量的独立赋值。CoW 也不能自动拦截所有嵌套对象内部操作。

解决方法可以是把列表展开为正规明细表、使用不可变元组，或对确实需要独立的嵌套对象执行明确的递归复制。哪一种合理取决于数据结构和成本。不能只把`.copy(deep=True)`当作消除所有别名的魔法，也不应因此放弃定义对象所有权。

<a id="pd1-ex11"></a>

### 7.11 练习十一：对账为什么需要集合检查

**问题：** 输入一百行，接受八十行、隔离二十行，数量相加正确。为何还要检查来源标识集合及唯一性？

**解析：** 数量关系不能排除抵消错误：接受集中可能复制一条并漏掉另一条，两个分区还可能重叠，同时有某条输入完全消失。来源标识的唯一性排除复制与重叠，集合覆盖排除漏行，二者与行数关系共同证明分区完整。业务键唯一则回答另一层问题，即接受记录是否保持一行一个业务实体。

进一步，数量与身份都正确也不能保证列值没有错配，需要检查关键列的来源映射和可手算不变量。好的验收不是寻找一个万能断言，而是让不同断言分别覆盖身份、数量、类型、值域和语义。每项检查都应知道它能发现什么以及不能发现什么。

<a id="sec-6-1"></a>

### 7.12 边界追问：填补后没有缺失是否代表无偏

**问题：** 所有缺失金额都填训练中位数，表中不再有空值，是否可以宣称恢复了真实消费分布？若验证分数提高又如何？

**解析：** 不能。填补把未知金额压到同一点，通常改变方差、尾部和变量间关系。训练中位数只保证没有从验证部分估计这个统计量，不保证缺失机制可忽略，也不保证中位数是每个缺失订单的合理预测。加入缺失指示可以帮助模型利用缺失模式，但不能识别未观测真值。

验证分数提高说明在该划分、损失、模型和数据条件下，完整流程的预测表现更好；它不等价于分布恢复，更不等价于因果关系正确。应检查来源与时间外推、覆盖率以及缺失模式变化，并在需要总体统计时采用相应的缺失假设与敏感性分析。预测有效性和完整数据重建是不同目标，需要分别提出证据。

<a id="pd1-ex13"></a>

### 7.13 练习十三：训练规则与固定协议如何区分

**问题：** 把金额单位从元换成分、把缺失年龄填训练中位数、把地区限定为公司公开的服务区清单，哪些必须每个训练折重新拟合？

**解析：** 固定单位换算和外部事先确定的服务区协议不依赖当前样本估计，通常可以作为确定性验证规则应用各折；中位数从数据学习，必须只用该折训练部分拟合。若服务区清单其实来自全量样本观察而非外部协议，它就不再是事先固定知识，应按任务允许的信息边界处理。

这个区分依靠来源和时间，不能靠函数名。有些叫“清洗”的步骤包含分位数截断、最频类别和数据驱动词表，实际上属于拟合；有些叫“编码”的步骤只是固定代码表翻译，并不学习。阅读代码时应追问参数从哪里得到，而不是把所有前处理一概放在划分之前或之后。

<a id="pd1-ex14"></a>

### 7.14 练习十四：设计一个能反驳自己的质量实验

**问题：** 你已实现清洗函数，如何避免只用正常样本证明自己正确？请提出至少四类故障输入与期待行为。

**解析：** 第一类是身份故障：规范化后重复键、缺失键与重复列名，应分别触发隔离或模式错误。第二类是数值故障：非法字符串、负数、过多小数与极大整数，应在既定协议下产生明确原因而非静默截断。第三类是对齐故障：重排索引或给出同长度不同身份的结果，应通过身份检查暴露，而不是只比较形状。

第四类是状态故障：真实零、原始缺失和解析失败同时出现，验收应确认三者没有合并。还可以加入新类别、时间歧义、嵌套对象别名和重复运行，观察函数是否仍遵守承诺。故障实验的价值在于让每项契约面临反例；若所有测试仅复述当前实现的行为，就难以发现实现与需求一起理解错的情况。
