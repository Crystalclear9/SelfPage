## 1. 把训练看成一个可审查的实验协议

一个完整训练程序并不是把前向、反向和保存串起来就结束。它还必须确定数据如何划分、每个样本如何贡献目标、评价指标如何聚合、根据什么规则选择模型，以及恢复后究竟保证什么。代码成功运行只验证语法与部分运行时条件；研究可信度来自这些约定与实现的一致。

本章使用 CPU 合成数据建立完整闭环。我们把一个训练阶段定义为参数更新过程，把验证定义为依照预先指定协议估计候选模型表现，把测试定义为选择规则冻结后的一次独立评价。三者的角色不同，不应该因为某个数据集文件较小就混用。

读者应已经了解上一章的张量、图、模块与优化器所有权。本章重点不再重复链式法则，而是研究“同一条数学损失在训练循环里能否被准确实现”。这尤其涉及不等大小批次、有效位置掩码、类别权重、微批累积与最佳状态保存。

<a id="torch-2-detail-2"></a>

### 1.1 先定义学习目标，再写循环

设每个样本数据为 $`(x_i,y_i)`$，损失为 $`\ell_i(\theta)`$，非负权重为 $`w_i`$。一个常用目标是
$$
L(\theta)=\frac{\sum_{i\in S}w_i\ell_i(\theta)}
{\sum_{i\in S}w_i},
$$
其中分母必须为正。这个定义包含等权样本平均，但不包含所有可能任务。序列按词平均、按句平均和按文档平均，各自对应不同的权重，不应被一个含糊的“平均损失”掩盖。

目标里可能还有正则项 $`\lambda R(\theta)`$。训练日志最好分别记录数据损失与正则项，因为验证通常主要评价预测损失。如果训练曲线包含正则、验证曲线不含，两者的绝对高低不能直接解释为过拟合程度。模型模式的差异也可能使训练损失高于验证损失。

实现目标时要明确分母由什么决定。若权重固定于数据，分母不依赖参数，可以先汇总再求导；若权重由模型预测且需要参与学习，分母也可能具有导数。此时把它转成 Python 数字会改变目标。下面的加权累积默认权重是外部固定权重，进阶应用必须重新审查这一条件。

<a id="torch-2-detail-3"></a>

### 1.2 独立划分与训练前拟合的状态

先划分，再在训练集上拟合标准化、词表选择或缺失值规则。若先看全部数据估计均值和方差，验证样本的信息已经进入训练流程，即使没有使用它的标签也存在信息泄漏。泄漏是否严重取决于任务，但原则上应让部署时不可知的信息保持不可知。

随机按行划分只适用于样本间近似独立的场景。同一用户、病人、设备或连续时间片产生多行记录时，行级随机拆分可能让高度相似的记录落到两边。需要根据真正的泛化目标选择分组或时间划分。评价未来数据，就不能把未来统计用于过去训练。

在本章合成实验里，各数据块独立生成于同一机制，适合展示循环正确性。它不能代表真实数据里的分布漂移、类别稀缺和标注噪声。学习教材代码时要区分验证实现的仪器与评估真实任务的证据，不能因为合成例子漂亮收敛就推出某架构普遍有效。

<a id="torch-2-detail-4"></a>

### 1.3 深入讲解：每个动作为什么有固定职责

一次更新需要清除不打算保留的旧梯度，执行前向，形成定义明确的标量目标，反向计算导数，再让优化器使用这些导数更新参数。清梯度可以在本次前向前，也可以在本次反向前完成；关键是不能误删正在累积的贡献，也不能把上一步残留当作新一步的一部分。

反向本身不改变参数，优化器更新通常也不会替你重新执行前向。因此更新后仍引用的旧输出属于旧参数函数值。若想记录更新后的损失，需要重新前向，而不是把同一个标量打印两次。日志中的时间点含义应明确，否则学习曲线难以与理论预测对齐。

训练、验证和保存应有清晰边界。验证不进行优化更新，模式与梯度记录分别控制；保存则在某个具体参数状态上捕获一致快照。把验证逻辑夹在一次尚未完成的微批组中间，会让指标对应部分累积但未更新的状态，虽然可以定义，却不如在明确更新边界评价容易解释。

<a id="visual-02-concept"></a>

### 图解：微批累积使用共同总分母

![微批累积使用共同总分母](images/02-concept.svg)

**图解。** 把微批次还原成三个有效元素，就能看出应有的权重。两批均值是 1 和 10，直接平均得到 5.5；按元素数 2:1 加权才是全体元素平均值 4。

两个微批贡献应在同一个目标分母下汇总。示例中先平均两个批均值，会让单元素批的每条记录获得更大权重；按有效元素总数归约才能恢复所声明的大批目标。

这种等价性要求计算发生在同一参数位置，而且前向没有被批内统计等机制改变。BatchNorm 或跨样本目标通常不能仅靠延后 optimizer.step 就精确恢复大批前向。

## 2. 损失接口与目标语义

<a id="sec-2-1"></a>

<a id="torch-2-detail-6"></a>

### 2.1 机制展开：交叉熵与类别索引的接口对应

多类单标签任务通常输出 $`(B,C)`$ 的 logits，标签为 $`(B,)`$ 的整数类别索引。损失内部把 logits 转为归一化对数概率，再选择目标类别。先做概率归一化再把结果作为 logits 输入，会在原目标上又套一层变换，从而改变概率模型和梯度尺度。

多标签任务允许多个类别同时为真，输出的多个分量不应被强制总和为一。逐类二元损失拟合各标签的条件边缘概率，并不要求真实标签彼此独立；只有把这些边缘概率相乘作为联合概率时，才加入条件独立假设。它通常使用逐类二元逻辑损失，标签是与输出同形状的零一值或适当软目标。把多个真标签压成一个整数索引会丢失监督信息；反过来，把单标签当作彼此独立任务也改变了建模假设。

软标签不是把整数索引随便转换类型。它通常表达类别分布，必须说明每行是否归一、数值是否非负以及这些分布来自哪里。标签平滑、蒸馏与弱监督的目标虽都可以是分布，却有不同解释。损失接口接受某种形状不等于输入已经满足概率语义。

类别权重还会改变均值的分母。对于本章不使用标签平滑的索引目标，加权交叉熵的平均通常按有效目标类别权重总和归一；这不必等于样本个数。若按批返回的加权均值乘批大小后再汇总，就可能得到错误的全局统计。最透明的方法是计算未归约损失，同时明确统计分子与分母。

<a id="sec-1-1"></a>

<a id="torch-2-detail-7"></a>

### 2.2 基础算例：训练和验证操作对照

训练模式与评估模式决定某些层如何运行，梯度记录开关决定是否建立反向历史。训练阶段通常同时需要训练模式与梯度；验证通常同时需要评估模式和关闭记录。只设置其中一个并不能自动满足另一种要求。尤其是批归一化状态可能在不记录梯度时仍被修改。

验证若要计算输入敏感度等导数，则应在评估模式下保留梯度。这个特例说明“验证永远不能求导”并非原则，真正原则是不能无意更新模型或改变评价协议。本章普通分类验证只计算指标，因此关闭记录以节省内存，并恢复调用之前的模式。

对于模块内部混合训练与评估状态的复杂模型，单个总开关的恢复可能不足以保留每个子模块原状态。下面完整示例的网络没有这种混合状态，所以恢复顶层模式就足够。若存在冻结的归一化子模块，应保存各子模块状态或由训练器显式重设，不能假设一次统一切换适用所有结构。

<a id="torch-2-detail-8"></a>

### 2.3 回归广播和单位尺度

回归损失尤其容易发生静默广播。输出为 $`(B,1)`$ 而目标为 $`(B,)`$ 时，平方差可能扩展为样本间的两两差。这个错误通常不会被反向检测到。应在损失前检查输出、标签形状及单位，并用手算小例确认归约。

均方误差对输出单位敏感：目标乘一千，损失尺度乘一百万。学习率、梯度裁剪和多任务权重都可能受影响。比较不同任务或标准化前后的损失时，必须说明单位，不能只看哪个数小。部署指标若需要原单位，应在明确的逆变换后计算。

多输出回归还需决定各维是否等权。一个量以毫米计、另一个量以秒计，直接平方相加隐含某种单位权衡。可以使用有意义的标准化或任务权重，但这些必须来自训练协议，而不是看到测试结果后选择最有利的尺度。

## 3. 归约、最后一批与可加统计量

<a id="torch-2-detail-10"></a>

### 3.1 为什么不能平均批均值

假设两个批次分别有八个和两个样本，损失均值分别为一和三。按样本平均是 $`\frac{(8\times1+2\times3)}{10}=1.4`$；直接平均两个均值得二。后者给小批每个样本四倍的权重。批次不是任务天然定义的统计单位，它只是执行分组。

因此评价时应汇总损失分子和有效分母，最后除一次。准确率汇总正确数与样本数；带掩码词级损失汇总有效词损失与有效词数；加权平均汇总加权损失与权重和。它们共同遵循“先累加可加量，再进行非线性变换”的原则。

训练日志在整个周期内累计时，参数不断变化，因此周期平均损失不是某个固定模型在整个训练集上的风险。它是训练过程经过各批时的在线统计。若要与验证风险严格对比，可以在周期结束后用固定模型另行评价训练集，但要权衡额外计算成本。

<a id="torch-2-detail-11"></a>

### 3.2 元素、样本与序列的不同分母

若每个样本有相同数量的输出元素，元素平均与先样本平均再整体平均可以相同。若每个序列有效长度不同，按词平均会让长序列贡献更多，按句平均则让每句总权重一致。两种方案都可能合理，但回答不同问题，不应该在训练和验证中不知不觉切换。

假设一句有两个有效词，另一句有八个，词级损失各自均值是一和三。词平均为二点六，句平均为二。若评估用户体验以一句为单位，句平均或许更合适；若评估随机抽取一个词的编码成本，词平均更自然。选择由任务决定，而不是由默认归约决定。

存在全忽略批次时分母为零，均值没有定义。可以按协议跳过该批并记录，也可以拒绝数据，但不能把未定义值默默填成零后纳入平均。若所有数据都无有效目标，应明确报错，因为这不是模型表现完美，而是评价对象不存在。

<a id="torch-2-detail-12"></a>

### 3.3 比率指标与非可加指标

均值可以由分子分母合成，但精确率、召回率和调和平均需要先汇总相应计数，再计算比率。平均每批的调和平均一般不同于全局调和平均。宏平均还需要按类别分别累计统计，不能把微平均结果更名后报告。

排序指标、分位数与某些校准指标需要更多信息，通常不能只保存一个批均值。可保存预测与标签或使用经过说明的流式近似。若数据过大，近似方法的误差与分桶规则也属于评价协议。节省内存不能成为暗中改变指标定义的理由。

对于阈值指标，阈值必须由训练或验证确定，再固定用于测试。测试后遍历所有阈值选择最高结果，相当于让测试参与模型选择。即使模型参数没变，最终系统仍然使用了测试标签信息，报告时应把这种选择偏差识别出来。

## 4. 微批累积如何真正等价于大批

<a id="sec-5-1"></a>

<a id="torch-2-detail-14"></a>

### 4.1 不同大小小批量的梯度累积如何加权

把一个逻辑批分为微批，设第 $`j`$ 个微批权重分子为 $`N_j(\theta)`$，固定分母为 $`D_j`$。整个逻辑批损失为 $`\frac{\sum_jN_j}{\sum_jD_j}`$，梯度就是各分子梯度之和除以总分母。若微批接口返回均值 $`L_j=\frac{N_j}{D_j}`$，应反向 $`(\frac{D_j}{D})L_j`$，而非无条件除以微批数。

实现上有两种常见方法：预先知道逻辑批总分母，每个微批按它缩放；或先反向每个分子的和，累积后把所有梯度除以总分母。后者对在线计数方便，但必须在裁剪和更新前完成，而且仅适合分母不依赖模型参数的场景。若分母可导，不能这样手工忽略其求导。

最后一个不足组大小的逻辑批也必须用实际分母。假设预定每四个微批更新，但最后只剩两个，用四去除会让尾部步长缩小。反过来，最后微批数量相同而有效词数不同，按微批数平均仍会改变权重。计数应与目标的真实单位一致。

<a id="torch-2-detail-15"></a>

### 4.2 进阶：梯度累积的等价条件

精确等价需要损失对样本可分、微批共享同一参数状态、每个样本的前向在拆分前后相同、归约权重一致，而且只在组末更新一次。普通确定性线性层满足这些条件。浮点加法顺序可能造成微小差异，因此通常讨论数学等价与数值近似一致，而非所有位完全相同。

批归一化依赖本批均值与方差，拆批会改变每个样本的前向。对比学习的负样本集合、批内排序或跨样本注意力也具有类似问题。即使梯度缩放完全正确，优化的函数也已经不同。梯度累积节省激活内存，不自动重建全批统计或全批负样本。

随机层也需谨慎。分批调用可能消耗不同的随机数流；即使统计分布类似，逐次实现不必与整批逐元素一致。若要求严格对照，应使用确定性网络或显式控制随机掩码。不能因为两条训练曲线接近就声称每步梯度完全等价。

<a id="visual-batchnorm-partition"></a>

### 图解：损失权重相同，为何拆批仍改变梯度？

![梯度累积无法恢复被拆开的批统计](images/02-batchnorm-partition.svg)

用四个单通道样本 $`x=(0,2,8,10)`$ 和目标 $`t=(-1,-1,1,1)`$ 做一个能够完整复算的反例。归一化层处于训练模式，初始 $`\gamma=1,\beta=0`$，取 $`\epsilon=1`$ 便于展示稳定项的作用；它是本例参数，并非推荐配置。损失固定为 $`L=\frac{1}{8}\sum_{i=1}^{4}(\gamma z_i+\beta-t_i)^2`$。拆为两个微批时，每个微批仍以八为分母，各自反向后只累积梯度，不执行中间参数更新。因此两条路径没有损失权重不等的问题。

整批均值为五，训练前向所用方差为 $`\frac{25+9+9+25}{4}=17`$，所以 $`z=\frac{1}{\sqrt{18}}(-5,-3,3,5)`$。拆成 $`(0,2)`$ 和 $`(8,10)`$ 后，两批均值分别是一和九，方差均为一，得到 $`z_{\mathrm{split}}=\frac{1}{\sqrt{2}}(-1,1,-1,1)`$。图中第二与第三个样本甚至改变了归一化后的正负号。它们原本相对于整批中心位于不同两侧，拆批后却只与各自微批中的邻居比较。

从同一个损失求缩放参数的梯度：

$$
\frac{\partial L}{\partial\gamma}
=\frac{1}{4}\sum_i(z_i-t_i)z_i,
\qquad
\frac{\partial L}{\partial\beta}
=\frac{1}{4}\sum_i(z_i-t_i).
$$

整批的平方和为 $`\sum_i z_i^2=\frac{34}{9}`$，与目标的内积为 $`\sum_i t_i z_i=\frac{16}{\sqrt{18}}`$，因而 $`\partial_\gamma L=\frac{17}{18}-\frac{4}{\sqrt{18}}\approx0.0016354`$；拆批的平方和为二，目标内积为零，因而梯度为 $`0.5`$。两者的偏移参数梯度都为零。这说明检查一个恰好一致的梯度分量不够，必须选能暴露批间依赖的参数和数据。若给同一初始参数执行学习率为 $`0.1`$ 的一次普通 SGD，缩放参数分别约变成 $`0.9998365`$ 和 $`0.95`$。

运行统计还会产生另一层差异。固定 `momentum=0.1`，运行均值初值为零、运行方差初值为一。整批调用一次后，运行均值为 $`0.5`$，运行方差为 $`0.9+0.1\cdot\frac{68}{3}\approx3.1667`$；这里用于缓冲更新的是无偏样本方差，不能直接把前向方差十七代入。拆批调用两次后，运行均值为 $`0.9(0.1\cdot1)+0.1\cdot9=0.99`$，运行方差为 $`0.9(0.9+0.1\cdot2)+0.1\cdot2=1.19`$。即使暂时忽略梯度，两条路径后续的评估行为也可能不同。前向方差、缓冲更新和评估模式的具体规则见 [PyTorch 2.10 BatchNorm1d 文档](https://docs.pytorch.org/docs/2.10/generated/torch.nn.BatchNorm1d.html)。

若改成评估模式并冻结同一份运行统计，归一化成为相同的逐样本仿射运算，才有机会恢复本节所要求的前向一致；这会改变训练方案，不能当作无代价修补。设置 `track_running_stats=False` 也不是修补，因为评估时仍使用当前批统计。同步多个设备的同一次前向可以扩大统计集合，但不会自动合并先后执行的多个微批。实际选择应先确定希望优化的函数，再决定统计范围和内存策略。

<a id="torch-2-detail-16"></a>

### 4.3 正则、裁剪与优化器的次序

若逻辑目标是数据平均加一次正则项，不能每个微批都完整反向同一正则，否则它会被重复累加。可以按微批权重分配正则，也可以在组末单独加入一次。优化器自带的衰减则在更新时发生，应按实际更新频率理解，而不是再额外重复实现同一惩罚。

梯度裁剪是非线性操作。先裁剪每个微批再求和，一般不等于先合成完整梯度再裁剪。因此如果目标是模拟大批更新，应在累积与归一化完成后裁剪一次。裁剪范数的定义与参数集合也应固定，尤其不能遗漏某些训练参数。

动量与自适应优化器每次更新都会改变内部状态。每个微批都调用一步，再调小学习率，不等价于累积后调用一步。有效批增大还改变每周期更新次数，进而影响调度、权重衰减与总计算预算。比较实验时应同时报告样本经过次数和优化器步数。

<a id="torch-2-detail-17"></a>

### 4.4 一个包含不等微批的梯度等价实验

下面使用十一个样本，分成三、五、三个微批，并加入非均匀样本权重。整批目标与累积目标使用完全相同的分子和分母，网络没有随机或批间依赖。比较的是反向后的梯度，再比较一次更新后的参数，能够区分归约正确与优化流程正确。

故意保留一个错误对照：把每批加权均值等权平均。它的目标通常不同，因此梯度应与整批不一致。负例很重要，因为如果所有数据刚好等大，错误实现也能通过，测试就失去发现问题的能力。

```python
import copy
import torch
from torch import nn

torch.manual_seed(7)
x = torch.randn(11, 3, dtype=torch.float64)
y = torch.randn(11, 1, dtype=torch.float64)
w = torch.tensor([1., 2., 4., 1., 3., 1., 5., 1., 2., 4., 1.],
                 dtype=torch.float64)
base = nn.Linear(3, 1, dtype=torch.float64)
full, accumulated, wrong = (copy.deepcopy(base) for _ in range(3))
parts = [slice(0, 3), slice(3, 8), slice(8, 11)]

def numerator(model, sl):
    err = (model(x[sl]) - y[sl]).square().squeeze(1)
    return (w[sl] * err).sum()

(numerator(full, slice(None)) / w.sum()).backward()
for sl in parts:
    (numerator(accumulated, sl) / w.sum()).backward()
    (numerator(wrong, sl) / w[sl].sum() / len(parts)).backward()

for a, b in zip(full.parameters(), accumulated.parameters()):
    torch.testing.assert_close(a.grad, b.grad, rtol=1e-12, atol=1e-12)
assert any(not torch.allclose(a.grad, b.grad)
           for a, b in zip(full.parameters(), wrong.parameters()))
for model in (full, accumulated):
    torch.optim.SGD(model.parameters(), lr=.01).step()
for a, b in zip(full.parameters(), accumulated.parameters()):
    torch.testing.assert_close(a, b, rtol=1e-12, atol=1e-12)
print("unequal weighted microbatches: passed")
```

## 5. 模式、梯度与指标的独立管理

<a id="torch-2-detail-19"></a>

### 5.1 验证必须保护哪些状态

普通验证不应更新参数，不应累积训练梯度，也不应无意改变运行缓冲。评估模式和关闭记录共同满足大部分常规模块的需求，但自定义模块仍可能在前向中修改状态。对可疑模块，可以在验证前后比较状态字典，或者让前向的状态变更显式化。

验证前遗留的训练梯度不会因为切到评估模式而自动清空。若验证在关闭记录区域进行，它们通常保持原值；这不意味着验证产生了那些梯度。调试时可以先把梯度设为 None，验证后确认仍为空，但不要在尚需保留微批贡献时这样做。

当验证需要推理模式时，要注意输出以后是否还会进入训练图。本章只把输出转成统计量，因此关闭记录足够，逻辑更直观。性能优化应在正确性建立后测量，不必为了节省很小开销而在混合训练流程中引入难以理解的限制。

<a id="torch-2-detail-20"></a>

### 5.2 训练损失为何可能高于验证损失

训练阶段可能有随机丢弃、数据增强与正则项，验证阶段没有；训练周期统计还混合了不同时间的参数。因此训练损失高于验证并不自动是错误，也不证明模型没有过拟合。要比较泛化差距，应在相同模式、目标和固定参数下评价训练与验证数据。

反过来，验证损失极低也值得核对。可能是验证集更简单、样本泄漏、重复记录或标签被编码进特征。没有异常报错的循环无法排除这些问题。应结合数据来源、分组结构以及朴素基线判断结果是否合理。

曲线的噪声还受验证集大小影响。每轮细小改善可能只是有限样本波动，尤其当你反复观察同一验证集并据此调整设计。需要把单次曲线当作选择工具，最终用独立测试与多随机种子对照评价稳定性，而不是过度解释每个拐点。

<a id="torch-2-detail-21"></a>

### 5.3 指标统计应该与任务成本匹配

准确率容易理解，但在类别极不平衡时可能掩盖少数类失败。加权损失可以改变训练重点，却不自动说明部署错误成本已被正确表达。应分别报告与任务相关的总体指标、分组指标和校准情况，并事先说明主指标用于选择哪一步。

对概率模型，损失与分类正确数可能朝不同方向变化。一个样本预测类别没变，但真类概率更合理，交叉熵就能改善；过度自信地错一个样本又可能显著恶化损失。模型选择应由真实用途决定，不能在每个候选上临时挑最好看的指标。

阈值、拒绝策略与代价权重同样属于系统。若验证用于决定它们，测试必须使用已固定规则。把测试集当作无穷次调参面板会让所谓最终结果失去独立性，即使每次只改一个很小设置，也在累计使用测试信息。

<a id="visual-02-mechanism"></a>

### 图解：训练模式与梯度记录是两个独立开关

![训练模式与梯度记录是两个独立开关](images/02-mechanism.svg)

两行分别从独立的新 BatchNorm 开始，运行均值为零、运行方差为一，输入均为两个样本 $`(0,2)`$。为使数字易于复算，图中取 $`\epsilon=1`$、$`\gamma=1`$、$`\beta=0`$、运行统计更新系数为 $`0.1`$；这只是教学参数，并非训练建议。上行采用当前批均值一、前向方差一，输出为 $`(-\frac{1}{\sqrt{2}},\frac{1}{\sqrt{2}})`$。更新运行方差时使用无偏估计二，因此运行方差变成 $`0.9\times1+0.1\times2=1.1`$，不是一。关闭梯度记录并没有阻止这些缓冲区变化。

下行使用初始运行统计，输出为 $`(0,\sqrt{2})`$，运行统计保持不变。若仅对第一个输出反向传播，输入梯度为 $`(\frac{1}{\sqrt{2}},0)`$。这直接说明 eval 只改变模块行为，并不会关闭自动微分；no_grad 控制图的记录，也不会切换模块模式。常规训练通常组合 train 与开启梯度，常规验证通常组合 eval 与关闭梯度，但两个开关可以独立选择。

上述统计规则针对 `track_running_stats=True` 的标准 BatchNorm；关闭该选项时，评估阶段仍使用批统计。Dropout 和自定义模块各有自己的模式行为，不能把图中的数值规则推广到所有模块。对应公式和梯度模式边界见 [BatchNorm1d](https://docs.pytorch.org/docs/2.10/generated/torch.nn.BatchNorm1d.html) 与 [Autograd mechanics](https://docs.pytorch.org/docs/2.10/notes/autograd.html#locally-disabling-gradient-computation)。

## 6. 完整可复现实验：训练、选择、保存与测试

<a id="torch-2-detail-23"></a>

### 6.1 实验设计与预期结果

下面构造三类二维高斯簇，训练集、验证集与测试集使用不重叠样本。数据生成机制已知，网络不含随机层或批统计，便于把注意力放在循环协议。我们用训练集均值与尺度标准化其他划分，用验证交叉熵选择状态，最后恢复最佳状态后仅评价测试一次。

保存到内存字节流，因此不会留下中间文件。状态包含模型参数、持久缓冲、优化器与调度器状态，以及基本配置和计数。这里的保存示例用于说明一个一致状态包；精确续训还需要随机数、采样器与数据管道状态，第四章会进一步分析安全加载与恢复边界。

为了避免把最佳状态当作可变引用，使用独立复制。若数据规模巨大，可以立即序列化到持久文件而非保留多份内存状态，但该教材实验刻意不产生任何外部产物。保存与加载只操作本程序自己生成的状态，不涉及不可信文件。

<a id="torch-2-detail-24"></a>

### 6.2 可直接运行的完整程序

代码使用固定随机种子与 CPU 单线程，划分在生成后显式固定。训练时打乱顺序由独立生成器负责，不会因临时插入其他随机操作而改变批次顺序。评价汇总未归约交叉熵之和与样本数，最后一个不足整批的批次仍得到正确权重。

调度器在本轮优化更新完成后按周期推进；检查点在推进后捕获，因此恢复的轮次含义清晰。最佳模型由验证损失选出，准确率只是同时记录的解释指标，不参与临时改变选择规则。早停耐心以完成的验证检查次数计，而不是以微批次数计。

```python
import copy
import io
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

torch.set_num_threads(1)
torch.manual_seed(31)
data_gen = torch.Generator().manual_seed(100)
centers = torch.tensor([[-2., -1.], [2., -1.], [0., 2.]])

def make_split(n_per_class):
    labels = torch.arange(3).repeat_interleave(n_per_class)
    points = centers[labels] + .55 * torch.randn(
        len(labels), 2, generator=data_gen)
    order = torch.randperm(len(labels), generator=data_gen)
    return points[order], labels[order]

xtr, ytr = make_split(61)
xva, yva = make_split(23)
xte, yte = make_split(29)
mean = xtr.mean(0)
scale = xtr.std(0, unbiased=False).clamp_min(1e-6)

class Classifier(nn.Module):
    def __init__(self, mean, scale):
        super().__init__()
        self.register_buffer("mean", mean.clone())
        self.register_buffer("scale", scale.clone())
        self.net = nn.Sequential(nn.Linear(2, 12), nn.Tanh(), nn.Linear(12, 3))
    def forward(self, x):
        return self.net((x - self.mean) / self.scale)

model = Classifier(mean, scale)
optimizer = torch.optim.SGD(model.parameters(), lr=.12, momentum=.8)
scheduler = torch.optim.lr_scheduler.StepLR(optimizer, step_size=12, gamma=.6)
shuffle_gen = torch.Generator().manual_seed(500)
loader = DataLoader(TensorDataset(xtr, ytr), batch_size=32, shuffle=True,
                    generator=shuffle_gen, num_workers=0)

@torch.no_grad()
def evaluate(model, x, y, batch_size=17):
    old_mode = model.training
    model.eval()
    total_loss, correct, count = 0., 0, 0
    try:
        for start in range(0, len(y), batch_size):
            xb, yb = x[start:start + batch_size], y[start:start + batch_size]
            logits = model(xb)
            assert logits.shape == (len(yb), 3)
            total_loss += nn.functional.cross_entropy(
                logits, yb, reduction="sum").item()
            correct += (logits.argmax(1) == yb).sum().item()
            count += len(yb)
    finally:
        model.train(old_mode)
    if count == 0:
        raise ValueError("empty evaluation set")
    return {"loss": total_loss / count, "accuracy": correct / count,
            "count": count}

initial = evaluate(model, xva, yva)
best, best_loss, stale, updates = None, float("inf"), 0, 0
for epoch in range(36):
    model.train()
    numerator, count = 0., 0
    for xb, yb in loader:
        optimizer.zero_grad(set_to_none=True)
        logits = model(xb)
        loss = nn.functional.cross_entropy(logits, yb)
        assert torch.isfinite(loss)
        loss.backward()
        assert all(p.grad is not None and torch.isfinite(p.grad).all()
                   for p in model.parameters())
        optimizer.step()
        updates += 1
        numerator += loss.item() * len(yb)
        count += len(yb)
    scheduler.step()
    val = evaluate(model, xva, yva)
    if val["loss"] < best_loss - 1e-6:
        best_loss, stale = val["loss"], 0
        best = copy.deepcopy({
            "model": model.state_dict(),
            "optimizer": optimizer.state_dict(),
            "scheduler": scheduler.state_dict(),
            "epoch": epoch,
            "updates": updates,
            "config": {"input_dim": 2, "classes": 3, "selection": "val_loss"},
        })
    else:
        stale += 1
    if stale >= 8:
        break

assert best is not None
buffer = io.BytesIO()
torch.save(best, buffer)
buffer.seek(0)
saved = torch.load(buffer, map_location="cpu", weights_only=True)
restored = Classifier(mean, scale)
restored.load_state_dict(saved["model"])
validation = evaluate(restored, xva, yva)
test = evaluate(restored, xte, yte)
assert abs(validation["loss"] - best_loss) < 1e-7
assert validation["loss"] < initial["loss"] * .25
assert test["accuracy"] > .9
assert test["count"] == len(yte)
print("selected epoch:", saved["epoch"] + 1)
print("validation:", validation)
print("test:", test)
buffer.close()
```

<a id="torch-2-detail-25"></a>

### 6.3 如何解读结果而不过度推断

这个实验应表现为验证损失明显下降、独立测试准确率超过设置的宽松阈值。阈值用于检查程序是否学到容易分离的结构，不是要证明某种网络优越。数据本来就简单，线性分类器也可以作为很强基线；增加网络深度通常不构成研究贡献。

最佳轮次恢复后重新计算验证损失，应与保存时一致到浮点容差。若不一致，优先检查是否真正复制了状态、评价模式是否相同、输入预处理是否一致、是否有未保存的随机或缓冲状态。测试分数高并不能掩盖恢复不一致，因为部署依赖的正是可恢复状态。

训练循环里每批梯度都存在的断言适合这个小型全连接网络。条件执行网络不应直接套用，因为一些参数可以合法地未参与本批。把示例断言迁移到新任务时，需要先确定它检查的是普遍约束还是当前结构特有预期，避免为了满足检查而改变正确算法。

<a id="torch-2-detail-26"></a>

### 6.4 为什么把预处理放进状态

均值与尺度注册成缓冲，使保存和迁移时不易遗漏。它们不是通过反向学习的参数，却影响整个预测函数。如果只保存神经网络层的权重而丢掉训练标准化规则，恢复模型将输入错误尺度，得到的预测可能完全不同。

这种做法适合数值预处理，但不代表所有预处理都必须写入模型。文本分词器、类别映射与复杂特征工程可以独立保存，只要版本、配置和应用顺序可追踪。关键是使模型产物包含重建预测函数所需的全部信息，而不是执着于某种单一文件格式。

标准化分母的下界在这里防止常数特征除零，意味着对极小方差采取有限尺度。真实数据应检查这些特征是否无信息或异常，而不是依靠一个常数掩盖数据问题。预处理数值稳定性和统计合理性仍应分别判断。

<a id="torch-2-detail-27"></a>

## 7. 早停、学习率调度与预算公平性

<a id="torch-2-detail-28"></a>

### 7.1 早停也是模型选择算法

早停不是“看到曲线不好就停”的临场判断，而是可以写成规则的选择过程：评价频率、主指标、最小改善、耐心、最大轮次以及最终恢复哪一状态都要明确。若每次实验临时改变规则，候选之间的计算预算和选择机会就不同。

最小改善可以用于减少微小数值波动造成的频繁保存，但它具有量纲，必须与指标尺度匹配。对损失用绝对阈值，对准确率也用同一数值，含义并不一样。耐心按检查次数计时，改变验证频率会改变实际容忍的训练时间，应连同频率一起报告。

最佳验证分数本身受选择偏差影响，因为你在许多候选状态中挑最优。它适合选模型，不应被当作无偏的最终性能估计。最终测试应使用冻结后的选择流程；若反复根据测试调整早停，就需要新的独立保留集来评估新的流程。

<a id="torch-2-detail-29"></a>

### 7.2 调度器的时间单位

学习率调度可能按周期、优化器步、有效样本数或验证指标推进。微批累积后，如果仍每个微批推进一次原本按优化器步定义的调度，学习率会过快变化。无论使用哪种接口，都应把计数变量与数学方案对齐，而不是只记住某个调用位置。

基于验证指标的调度需要先获得本次指标，再把它传入调度规则。固定周期调度不需要指标。不同类型不能用同一模板随意替换。恢复训练时还要保存调度状态及当前更新计数，否则即使权重与动量一致，下一步学习率也可能不同。

在报告中，“训练十轮”不能完整描述预算。数据量、批大小、尾批处理、累积步数与每轮验证开销都会影响实际更新和计算量。公平比较通常需要共同说明样本暴露次数、优化器更新次数以及主要硬件成本，避免把更多训练误认为算法本身更好。

<a id="torch-2-detail-30"></a>

### 7.3 何时选择损失，何时选择任务指标

如果部署需要概率质量，验证交叉熵通常有直接意义；如果部署有固定错误成本，成本指标可能更相关。准确率与损失不一致时，应依据预先定义的用途选择，而不是在实验结束后挑有利结果。可以同时记录多项指标，但主选择规则要固定。

多目标任务可以设定约束，例如在召回率达到阈值的模型中最小化延迟。这也是明确规则，不要求所有问题都压成一个权重和。若使用权重和，权重本身属于偏好与设计，应通过验证或业务要求确定。测试负责评价已选方案，不能再帮你挑偏好。

独立多次运行可以揭示初始化与顺序敏感性，但对同一测试集反复选择“最好种子”同样产生偏差。更合理的做法是事先确定种子集合，报告均值、离散程度和必要的逐次结果，避免把偶然幸运运行当成可稳定重现的表现。

## 8. 保存、加载与恢复的不同保证

<a id="torch-2-detail-32"></a>

### 8.1 推理保存与续训保存

推理通常需要模型参数、持久缓冲、结构配置和预处理定义。续训还需要优化器状态、调度器状态、梯度缩放状态、当前计数以及足够的随机与数据进度信息。二者目标不同，不必为了简单推理携带所有历史状态，也不能拿只有权重的文件承诺精确续训。

保存整个 Python 模块对象会依赖类定义与代码环境。保存状态再用明确结构恢复通常更易审查，但结构演化仍需版本管理。加载成功只说明键和张量具有某种兼容性，不能证明类别含义或特征顺序没变。配置与数据协议必须一起验证。

本章只从自身创建的内存流加载，并明确使用受限权重加载选项。真实外部检查点还涉及来源可信性与格式安全，第四章会专门说明。这里不引入外部文件，也不会留下临时脚本，目的只是演示保存与恢复的状态语义。

<a id="torch-2-detail-33"></a>

### 8.2 最佳状态为什么必须复制

状态字典是当前状态的视图式集合，不应被当作永不变化的快照。若保存一个引用后继续训练，引用中的张量可能随原参数变化。独立复制或立即序列化使“最佳”绑定到一个具体时刻，这才符合早停的定义。

不仅参数，优化器内部动量也具有可变状态。要恢复某个轮次继续训练，应捕获同一时刻的模型与优化器，而不是把最佳模型参数与最后轮次动量拼起来。后者可以定义为一种重启策略，但必须明确说明，不能声称它重现了最佳轮次的连续轨迹。

复制状态存在内存成本。大型模型可以使用可靠的持久化策略，在完整写入成功后替换旧版本，并保留恢复所需元数据。本章以小模型内存保存避免工程细节干扰，但原子性、错误处理与可恢复性在真实系统中同样重要。

<a id="torch-2-detail-34"></a>

### 8.3 参数一致不等于训练轨迹一致

即使恢复后预测相同，后续训练还可能因为优化器状态、学习率、随机层、数据顺序与采样位置不同而分叉。预测一致验证的是当前函数，轨迹一致验证的是整个状态机。两种测试应分开，不要用前一种结果宣称后一种保证。

若只在周期边界恢复，数据进度较容易定义；中途恢复还需知道已消费哪些样本、工作进程预取状态与未完成累积梯度。为了简化工程，可以明确只保证周期边界恢复，而不是含糊承诺任意时刻无损续训。边界清楚的较弱保证比无法兑现的强保证更有价值。

严格位级复现还受硬件、算子实现、并行归约顺序和库版本影响。研究报告应明确目标是统计可复现、数值近似一致还是逐位相同。本章 CPU 小例检查数值容差，不把它推广为所有设备上的位级保证。

## 9. 故障诊断：从一个批次到独立测试

<a id="torch-2-detail-36"></a>

### 9.1 一个批次过拟合测试

选择极少数确定样本，关闭不必要的随机增强，尝试让模型把它们拟合到很低训练损失。若连这个都做不到，优先检查标签、输出形状、损失、学习率、参数注册与梯度路径。这个测试缩小了泛化不确定性，使实现故障更明显。

但无法过拟合也可能有合理原因：模型表达能力不足、标签相互矛盾、强正则或数据本身存在不可消除噪声。需要根据目标函数判断最小可达值，而不是把任何非零损失当错误。对逻辑分类，有限权重下交叉熵通常不会严格到零，宜使用合理阈值。

能够过拟合只说明训练闭环具有一定能力，不说明标签正确或真实泛化良好。若样本里泄漏了目标字段，过拟合会非常容易。下一步仍需独立划分与基线，不能把这个调试工具升级为性能证明。

<a id="torch-2-detail-37"></a>

### 9.2 梯度、更新与数据的三个观察面

梯度面记录是否有限、主要层范数与缺失情况；更新面记录参数实际改变量及优化器计数；数据面记录样本标识、标签范围和有效目标数。三者结合能够区分“损失没依赖参数”“梯度算出但没更新”以及“更新正确却训练了错误数据”。

若梯度突然爆炸，先检查前向数值与输入尺度，再检查目标分母是否意外变小、尾组是否重复放大。裁剪可以限制更新，但不应替代定位源头。若所有梯度为零，则检查饱和、离散决策、误分离以及模型是否真的接收了不同输入。

日志自身也可能出错。重复把累计总数当本批数量、跨周期不清指标、把百分数再乘一百，都会产生看似异常的曲线。记录原始可加计数和归约后的指标，保留少量手算核对点，通常比增加更多图表更有帮助。

<a id="torch-2-detail-38"></a>

### 9.3 训练、验证与部署的函数是否相同

部署时可能使用不同预处理、不同序列截断、不同类别映射或不同阈值。此时离线验证结果不能直接代表部署。应把预测函数定义为从原始输入到最终决策的整个流程，再检查各阶段一致性，而不只比较神经网络权重。

一个实用方法是保存少量代表性原始输入与预期中间形状，分别经过训练评价路径与部署路径，比较标准化结果、logits 和最终输出。差异出现在哪个阶段，就优先检查那个阶段的协议。输入包含敏感信息时应选择合适的合成或匿名例子。

部署分布变化属于另一类问题，即使代码完全一致也可能性能下降。此时需要监控与重新评价，而非把所有下降都归为工程故障。先确认函数一致，再分析数据分布差异，能够避免在两个问题之间来回猜测。

<a id="torch-2-detail-39"></a>

### 9.4 分层验证与故障注入

正常例子通过只能说明某条路径可行。为了检查训练器是否真的能发现错误，还可以故意注入一种可控故障，例如把标签顺序打乱、让尾批大小变化、将一个参数从优化器中移除，或者把最佳状态改成可变引用。预期检查应在相应位置失败，而不是最后仍输出一个看似合理的分数。

故障注入应在独立小型实验中进行，不污染真实训练数据或最终模型。每次只改一个因素，记录应触发的断言以及实际触发位置。若标签乱序后损失和准确率仍与原来完全一样，可能说明标签根本没有进入指标；若遗漏参数后更新检查不报警，可能说明检查集合本身也遗漏了同一参数。

这种方法尤其适合验证统计聚合。构造两个大小差异很大的批次，并让它们损失明显不同，错误的批均值平均就会暴露。再构造全忽略批次，检查分母为零的处理。使用带权重数据时，权重刻意取不均匀值，能够避免错误实现因为特殊对称条件侥幸通过。

<a id="torch-2-detail-40"></a>

### 9.5 报告一个实验需要哪些最少信息

实验记录至少要能够重建目标、数据划分、模型配置、优化规则、选择规则和最终评价。随机种子有帮助，却不能替代这些定义。只给一个种子和最终分数，别人仍不知道标签映射、标准化统计、尾批策略与检查点选择，这样的记录无法可靠复现。

代码版本和依赖版本也需要明确。不同版本的默认行为可能变化，尤其在加载、随机性与设备算子方面。对于教材里的小型实验，可以记录主要库版本与 CPU 运行条件；真实研究则应按风险与复杂度补充环境和数据版本，而不是收集大量无关系统信息。

结果解释还应区分一次运行的结果和跨运行的稳定结论。若只运行一次，应直接标明；若比较多个种子，应预先确定种子集合和汇总方式。不能先运行很多次，再只展示最成功的一次而称其为典型表现。诚实限定证据范围，比堆叠更多小数位更有价值。

## 10. 十六道进阶练习与详细题解

<a id="torch-2-detail-42"></a>

### 10.1 练习一：尾批均值的陷阱

**问题。** 两批大小分别为十和二，均方误差均值分别为二和八，整体均方误差是多少？

**解析。** 总平方误差为二十加十六，除以十二得三。批均值直接平均得到五，过度强调尾批。应保存误差和与元素或样本计数，具体分母由目标定义决定。若每样本多输出，还需确认每批均值是否已经对全部输出元素平均。

**进一步思考。** 如果你的任务明确把每个批次作为一个群组并等权评价，五也可以是有定义的指标，但那应叫群组平均并保证批次划分具有业务意义。随机执行批次通常没有这种意义。

<a id="torch-2-detail-43"></a>

### 10.2 练习二：类别权重的分母

**问题。** 三个有效样本目标类别权重分别为一、一、四，未加权损失分别为二、三、一。按目标权重归一的损失是多少？

**解析。** 分子为二加三加四等于九，分母为六，所以为一点五。若除以样本数三，则为三，它是另一种加权目标尺度。两者方向可能相同但更新尺度不同，跨批权重总和变化时还可能改变相对贡献。接口默认行为必须核对，不能只凭名称猜测。

**进一步思考。** 若标签平滑或概率目标加入不同类别权重，未归约项与分母语义可能不同于简单索引情况。应根据明确公式实现统计，而不是沿用本题分母而不检查条件。

<a id="torch-2-detail-44"></a>

### 10.3 练习三：微批组最后只剩一批

**问题。** 预设四个微批累积一次，最后只有一个同大小微批，仍把损失除以四后更新，会发生什么？

**解析。** 若目标是最后实际逻辑批的平均，梯度被缩小为应有的四分之一。应使用实际有效分母，而不是预设组数。如果有意采用固定总分母以降低尾部权重，也可以定义这种算法，但应说明它不再是每个实际逻辑批的平均目标。

**进一步思考。** 丢弃尾组会改变每周期使用的数据，尤其在样本顺序固定时可能系统性遗漏特定样本。无论保留、丢弃还是补齐，都应把策略写入实验协议并检查覆盖。

<a id="torch-2-detail-45"></a>

### 10.4 练习四：裁剪顺序能否互换

**问题。** 两个标量微批梯度分别为十和负九，裁剪阈值为一，先裁剪再相加与先相加再裁剪是否相同？

**解析。** 先裁剪得到一与负一，相加为零；先相加得到一，裁剪后仍为一。非线性操作不与求和交换。模拟大批时应先完成累积和归一化，再对完整梯度裁剪。若分布式系统按局部梯度裁剪，也需要分析是否改变全局算法。

**进一步思考。** 单个微批的大梯度可能与其他微批抵消，局部裁剪会改变这种抵消关系。这未必永远不好，但属于新算法选择，不能误称为完全等价的内存优化。

<a id="torch-2-detail-46"></a>

### 10.5 练习五：批归一化为何破坏等价

**问题。** 样本独立损失加权正确，拆微批后梯度却与整批不同，网络含批归一化，应如何解释？

**解析。** 每个样本的前向依赖所在批次的统计，拆分改变均值和方差，因此损失函数本身改变。正确加权只能合并已算出的局部目标，不能恢复整批统计。可考虑固定统计、使用不依赖批的归一化，或实现真正的跨微批统计方案，并说明额外条件。

**进一步思考。** 使用运行均值并不自动等于大批训练，尤其若训练和评估公式或统计更新规则不同。需要比较完整前向与状态转移，而不是只看梯度归约。

<a id="torch-2-detail-47"></a>

### 10.6 练习六：验证只切模式够吗

<a id="sec-6-1"></a>

**问题。** 验证时只调用评估模式，没有关闭记录，是否仍能建立图？反过来只关闭记录会怎样？

**解析。** 前者仍可建立图，增加内存且可能因长期保存输出而保留历史；后者仍可能使用训练态随机层和更新批统计。通常验证需要同时设置两者，并避免优化更新。若验证要计算输入导数，应保留记录但仍采用事先确定的评价模式。

**进一步思考。** 评价函数返回后应按调用者协议恢复模式，不能让下一个训练批悄悄运行在评估态。混合状态模块需要更精细恢复，统一顶层开关不一定足够。

<a id="torch-2-detail-48"></a>

### 10.7 练习七：为什么最佳模型一直变

**问题。** 用一个变量保存最佳状态字典，训练结束加载后却等于最后模型，最可能是什么问题？

**解析。** 保存的张量仍引用当前可变存储，后续更新改变了所谓最佳状态。应独立复制或立即序列化，同时记录最佳指标与轮次。验证恢复后还应重新评价，与保存时结果在容差内一致。这个测试直接检查快照语义，而不只检查加载没报错。

**进一步思考。** 若续训还需要优化器与调度器，同样必须捕获相同时刻的状态。最佳权重与末轮动量混合不是完整恢复，而是一种需要明确命名的重启。

<a id="torch-2-detail-49"></a>

### 10.8 练习八：动量状态真的重要吗

**问题。** 恢复相同模型权重，但优化器重新初始化，下一步会不会与不中断训练相同？

**解析。** 对无状态的简单梯度下降，在相同学习率与数据下可以相同；对动量和自适应方法通常不同，因为更新依赖历史。还需匹配调度、随机状态与数据位置。能恢复当前预测，不足以恢复未来状态机。

**进一步思考。** 有时研究者故意重置优化器来微调，这是合理策略。但应报告为重新开始优化，而不是声称无损继续原轨迹，避免对复现性产生错误承诺。

<a id="torch-2-detail-50"></a>

### 10.9 练习九：训练损失高于验证

**问题。** 网络包含随机丢弃，训练损失长期略高于验证，是否必须认为数据划分反了？

**解析。** 不必。训练态函数、正则项与参数时间点都可能不同。应在同一固定模型、相同评价模式和相同损失定义下重新评估训练集，再比较。若差异仍异常，再检查验证难度、数据泄漏与样本重复，而不是只根据曲线相对位置下结论。

**进一步思考。** 如果训练数据增强更难，训练损失衡量的就是另一个输入分布。应明确分别记录增强训练损失和原始输入评价损失，使图表与统计对象一致。

<a id="torch-2-detail-51"></a>

### 10.10 练习十：测试阈值选择

**问题。** 模型参数固定后，用测试集挑最佳分类阈值，再报告该阈值测试分数，是否保持测试独立？

**解析。** 没有。阈值是系统的一部分，使用测试标签选择它已经构成适配。应在验证集确定阈值，再用测试评价完整固定系统。如果已使用测试进行大量设计，需要新的保留数据或清楚报告探索性结果，不能仍把它当一次独立确认。

**进一步思考。** 同样问题存在于选择随机种子、后处理、类别映射与检查点。独立性约束作用于整个决策流程，不只作用于神经网络参数。

<a id="torch-2-detail-52"></a>

### 10.11 练习十一：调度跟微批还是更新

**问题。** 原先每步使用六十四个样本，改成四个十六样本微批累积，调度器每个微批推进一次会怎样？

**解析。** 若原调度以优化器步为时间单位，四倍推进会使学习率进程加快。应在一次逻辑更新完成后推进一次，除非新的方案刻意按样本或其他时间单位定义。还要检查周期计数、预热长度与总更新预算，而非只移动一行调用代码。

**进一步思考。** 改有效批大小也可能改变总更新次数，固定周期数不一定意味着固定优化预算。比较实验时应同时列出样本暴露与更新计数，说明采用哪种公平性标准。

<a id="torch-2-detail-53"></a>

### 10.12 练习十二：准确率与交叉熵相反

**问题。** 候选模型准确率稍高，但交叉熵明显更差，应该选择哪一个？

**解析。** 取决于预先定义的用途。概率评估与风险决策可能更看重概率质量，固定类别选择可能以准确率为主，但仍应关注错误成本与校准。不能在看到结果后临时更换主指标。记录两者帮助解释取舍，选择规则则应由任务需求提前确定。

**进一步思考。** 少数极度自信错误可以显著恶化交叉熵，而大部分样本类别正确数变化很小。检查这些样本有助于理解模型，但不要据测试错误手动修补后仍沿用旧测试结论。

<a id="torch-2-detail-54"></a>

### 10.13 练习十三：空掩码如何处理

**问题。** 某个批次所有位置都被忽略，平均损失得到非数，能否直接替换为零参与周期平均？

**解析。** 不应默默这么做。该批没有有效统计对象，分母为零。可以按事先定义跳过并记录有效计数，也可以拒绝数据；若整个评价集都为空，应报错。填零并按批平均会人为改善分数，掩盖数据管道问题。

**进一步思考。** 训练时跳过空批还影响更新和调度计数。应只在实际进行了有效更新时推进按更新定义的状态，避免没有数据贡献却消耗学习率进度。

<a id="torch-2-detail-55"></a>

### 10.14 练习十四：正则在累积中算几次

**问题。** 三个微批分别反向数据均值加完整正则，再做一次更新，会不会等于整批数据均值加一次正则？

**解析。** 通常不会，完整正则被累计三次，数据部分还需按实际分母加权。应按微批权重分配正则或在组末只反向一次。若优化器已经实现衰减，还要区分是否有意与显式惩罚共同使用，避免无意重复。

**进一步思考。** 衰减频率与更新次数相关，扩大累积组使每周期更新减少，可能改变每周期总衰减。保持同一超参数并不自动保持同一训练动力学，应根据比较目标决定是否调整。

<a id="torch-2-detail-56"></a>

### 10.15 练习十五：批指标不能直接平均

**问题。** 两批分别计算调和平均分数，再对结果取均值，能否得到整体调和平均？

**解析。** 一般不能。应先汇总真正例、假正例和假负例，再计算整体精确率、召回率与调和平均。宏平均还要先按类别分别汇总。指标中的非线性比率通常不与批平均交换，必须保存足够的统计量或原始预测。

**进一步思考。** 对排序指标可能需要全体分数与标签，不能只保留混淆矩阵。实现流式近似时应说明近似方法与误差，而不是把不同指标用同一个批均值模板处理。

<a id="torch-2-detail-57"></a>

### 10.16 练习十六：如何评价完整训练器

**问题。** 一个训练器在合成数据上高准确率，还需要哪些检查才能迁移到新任务？

**解析。** 检查输入标签契约、数据独立性、归约单位、参数所有权、模式、状态保存与恢复，随后设计适合新任务的基线与独立评价。合成数据验证闭环，不能覆盖时间泄漏、复杂指标和部署预处理差异。应迁移原则与检查方法，而不是机械复制所有断言。

**进一步思考。** 最小训练器最好能在固定小例上验证一次前向、一次反向、一次更新、一次恢复以及一个尾批统计。完整研究结果则需要更广的数据证据，两类验证相互补充。

<a id="torch-2-detail-58"></a>

## 11. 从教材循环走向可扩展训练器

一个合理训练器可以把数据读取、前向与损失、优化更新、评价和持久化分开组织，但这些分层必须围绕明确数学边界。抽象的价值是让分母、计数与状态更容易审查，而不是让关键步骤隐藏在过多回调里。读者应能清楚定位一次更新到底使用了哪些样本。

扩展到设备、混合精度与分布式之前，应保留一个小型 CPU 参考实现。新实现首先比较同一输入的前向、有效目标计数和单步更新，再比较长期统计表现。性能提升只有在这些语义维持一致时，才可以被解释为对同一算法的加速。

后续章节会继续说明数据管道、设备和检查点安全。本章建立的核心约束始终不变：目标由明确分子分母定义，更新发生在明确边界，评价对应固定协议，保存捕获一致状态。它们共同决定一个实验是否可解释、可比较和可恢复。
