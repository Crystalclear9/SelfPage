## 1. 从数值数组到可训练程序

一个张量同时回答四类问题：数据是什么、数据如何存储、计算在哪里发生、数值如何依赖可训练变量。初学时只看形状，常会把“能运行”误认为“含义正确”。研究代码需要进一步说明每一维的数学身份、每一块内存由谁共享、每条导数路径是否存在、每个参数究竟由哪个优化器管理。本章沿这四个问题建立模型，而不把接口名称当成孤立的记忆条目。

本章默认实数稠密张量、CPU 和普通急切执行。稀疏、复数、分布式以及编译执行各有补充约束，不能把下面的局部结论机械推广。代码面向本库核对过的 PyTorch 2.10，使用合成数据，不下载模型。涉及底层属性的示例用于观察语义，业务程序应优先使用稳定的公开接口。

<a id="torch-1-detail-2"></a>

### 1.1 先给每一维写出含义

设输入是 $`X\in\mathbb R^{B\times D}`$，行表示样本，列表示特征。线性层权重为 $`W\in\mathbb R^{K\times D}`$，偏置为 $`b\in\mathbb R^K`$，前向是 $`Z=XW^\top+\mathbf1b^\top`$。输出具有形状 $`(B,K)`$。这个记号立即解释了为什么参数数目是 $`KD+K`$，为什么改变批大小不改变参数数目，也解释了权重在框架中的排列为什么与部分数学教材的列向量写法不同。

当输入升级为 $`(B,T,D)`$，线性层仍作用在末维，得到 $`(B,T,K)`$。这里并没有隐含地混合时间位置；共享的是每个位置使用的同一组权重。若目标是联合处理整个序列，就必须另外表达注意力、卷积、池化或展开操作。接口接受三维输入并不意味着它自动理解时间结构。

形状检查还必须防止“合法但错误”的广播。预测为 $`(B,1)`$，标签若是 $`(B,)`$，相减可能产生 $`(B,B)`$，损失仍是标量并能反向，但每个预测被拿去比较所有标签。正确做法是让任务定义决定标签形状，再显式断言一致。自动微分不会替你发现任务层面的样本错配。

数值类型承载不同职责。浮点输入可以求导；整数类别索引用于查找目标类别，本身通常没有实数微分意义。把类别索引改成浮点并不等于获得软标签。设备则决定运算地点，参数、输入以及参与运算的缓冲状态都需兼容。将一个张量移动到新设备可能产生新对象，因而还要考虑其叶子身份和优化器是否仍持有预期对象。

### 1.2 基础算例：自动求导先从一个标量计算图开始

令 $`x=2`$，$`y=x^2+3x`$。逐步分解为平方项与线性项，得到 $`y=10`$，两条路径对 $`x`$ 的贡献分别是 $`2x=4`$ 与 $`3`$，总梯度为七。这个简单例子已经包含计算图最重要的规则：同一变量沿多条路径影响输出时，反向贡献要相加，而不是取最后一条路径。

若计算的是 $`L=(3w-1)^2`$，在 $`w=2`$ 时，外层平方导数是十，内层仿射导数是三，因此梯度为三十。梯度不是残差本身，也不是损失数值。学习率随后把梯度转换为参数改变量，二者是不同阶段。把这几个量打印出来能帮助判断数值异常究竟来自目标、求导还是更新规则。

下面把梯度累积、重新前向和非叶梯度保留放在同一个最小实验中。两次反向使用两次新建的图，因此不会遇到复用已释放中间状态的问题。第二次反向得到十四说明叶子梯度缓冲累积了两次七，并不意味着第二次的局部导数变了。

```python
import torch

x = torch.tensor(2.0, dtype=torch.float64, requires_grad=True)
y = x.square() + 3 * x
y.retain_grad()
y.backward()
assert x.grad.item() == 7.0
assert y.grad.item() == 1.0
(x.square() + 3 * x).backward()
assert x.grad.item() == 14.0
x.grad = None
((3 * x - 1).square()).backward()
assert x.grad.item() == 30.0
print("scalar graph and accumulation: passed")
```

清空梯度不是修改参数，也不是删除模型。它只是处理上一次导数的存储位置。训练中常把梯度设为 None，这与填入全零张量在内存分配、是否参与优化器更新方面可能不同。先理解“某对象是否有梯度”和“某梯度数值是否恰好为零”，才能在冻结参数、条件分支和稀疏更新中作出正确判断。

<a id="torch-1-detail-4"></a>

### 1.3 一个变量具有数值、对象和存储三种身份

两个张量可以数值相等，但不是同一个 Python 对象；也可以不是同一对象，却共享底层存储；还可以存储独立，但通过复制操作在计算图中保持导数联系。这三种关系互不等价。比较对象身份使用身份判断，比较数值使用数值比较，判断存储关系需要结合创建方式、偏移和步幅理解。

例如别名赋值没有复制任何东西，两个名称指向同一对象。切片通常产生共享存储的视图，改动一处可能影响另一处。克隆产生新的数据存储，但可微的克隆仍保留来源关系。分离操作切断图，却可能共享数据。把这些操作统称为“复制”会使模型调试极其混乱。

实际设计应先确定所有权：这份数据是否允许被别处改动？这份日志是否应该持有图？这份参数是否应该接收更新？如果三个答案分别不同，就需要组合操作，而不是寻找一个万能接口。后文会用独立克隆、停止梯度以及参数注册分别解决不同问题。

## 2. 存储、步幅、视图与别名

<a id="torch-1-detail-6"></a>

### 2.1 步幅是从逻辑索引到存储位置的规则

对一个二维张量，逻辑元素 $`(i,j)`$ 在存储中的偏移可写成 $`o+i s_0+j s_1`$，其中 $`o`$ 是起始偏移，$`s_0,s_1`$ 是以元素计的步幅。连续排列的 $`(2,3)`$ 张量通常具有步幅 $`(3,1)`$。转置只交换形状与步幅，不必搬动元素，因此得到 $`(3,2)`$ 和步幅 $`(1,3)`$。

这说明连续性是特定布局关系，不是“这块内存存在空隙”的日常说法。一个转置矩阵可以完整使用同一块存储，却不满足当前维度次序下的连续条件。反过来，某些切片仍能满足合并部分维度的规则，即使它不符合最朴素的整块连续想象。

理解步幅还有性能意义。内层循环若访问相邻存储位置，通常更有利于缓存和向量化；如果每次跨越很长距离，访存模式可能变差。不过性能不是由一个布尔连续标记完全决定，运算内核、维度长度以及硬件都会影响结果。不要为了追求连续而在每一行代码前无条件复制数据。

<a id="torch-1-detail-7"></a>

### 2.2 view、reshape 与 contiguous 的可观察差异

改变形状时，必须确认新的逻辑索引能否用原有存储与步幅表达。能够表达时，视图可以不复制；不能表达时，严格要求视图的操作会报错。较宽容的重排接口可能选择复制，因此不能把“代码运行成功”当作仍然共享存储的证据。

连续化操作也不是永远产生新数据：如果输入已经满足要求，它可以直接返回原对象。若业务要求一份独立快照，就应明确克隆；若业务只要求某种布局，就用布局转换。将布局要求和所有权要求分开，能够同时避免无谓复制与意外别名。

下面观察转置、展平和克隆。对比的是公开行为：转置后的逻辑顺序是零、三、一、四、二、五；强行用视图合并全部维度不符合步幅条件，而重排能够得到正确逻辑内容。克隆的修改不会污染来源。它并不试图把所有非连续张量都判为不能视图变形，那个更强的说法是错误的。

```python
import torch

base = torch.arange(6.0).reshape(2, 3)
transposed = base.t()
assert transposed.stride() == (1, 3)
failed = False
try:
    transposed.view(-1)
except RuntimeError:
    failed = True
assert failed
flat = transposed.reshape(-1)
assert torch.equal(flat, torch.tensor([0., 3., 1., 4., 2., 5.]))
view = base[:, :2]
view[0, 0] = 99
assert base[0, 0].item() == 99
copy = base.clone()
copy[0, 0] = -9
assert base[0, 0].item() == 99
print("layout and alias: passed")
```

### 2.3 扩展、广播与重复不只是形状问题

把长度为一的维度扩展到较大长度，可以用零步幅表示：多个逻辑位置指向同一个存储元素。因此扩展后的张量看起来拥有更多元素，却未必拥有相应数量的独立数据。若要为每个位置写入不同值，必须先获得独立存储，不能把这些逻辑位置当作互不相关的可写槽位。

广播在前向里复用数值，在反向里把复用位置的贡献求和。设 $`Y_{ij}=X_{ij}+b_j`$，上游导数为 $`G_{ij}`$，则偏置梯度为 $`\sum_iG_{ij}`$。这种求和由图结构决定，与偏置是否显式扩展成二维视图无关。重复存储虽然布局不同，只要表达了同一个数学函数，其梯度也应汇集到原变量。

但重复数据与重复参数不是一回事。通过普通数据复制构造两个独立叶子参数，它们以后可以各自更新；把同一个参数对象在两个位置使用，则两条路径汇聚到同一梯度。设计共享嵌入、孪生网络或循环复用层时，这种所有权差异直接决定模型自由度。

<a id="torch-1-detail-9"></a>

### 2.4 NumPy 互操作与独立数据边界

从某些已有数组构造张量可以共享主机内存，因此数据预处理程序对原数组的原地修改可能在训练端立即可见。另一种构造方式会复制数据。不要仅凭函数名字猜测所有权，尤其是在缓存、异步读取或反复复用工作数组时，应通过小实验确认共享关系，并把允许修改的边界写清楚。

把需要梯度的结果转换成外部数组之前，通常要先分离并移动到主机。这样得到的数据只能用于外部计算与记录，外部库算出的损失不会自动回到原图。之后再新建一个需要梯度的张量，只是建立新的叶子，无法恢复已经失去的历史依赖。

如果一段外部算法确实需要参与训练，可以改写为可微张量操作，或者实现具有正确反向规则的自定义算子。后者的前提是你知道它的数学导数、边界行为与数值稳定性。为了消除报错而反复转换数组，通常只会把显式错误变成静默的训练失效。

## 3. 自动微分计算的究竟是什么

<a id="torch-1-detail-11"></a>

### 3.1 动态计算图与局部线性映射

对函数 $`y=f(x)`$，微分描述小扰动的一阶影响：$`\delta y\approx J_f(x)\delta x`$。自动微分把复杂程序分解成基本操作，并组合它们的局部线性映射。它既不是逐个扰动输入的有限差分，也不是把整段程序先变成一个庞大符号公式再化简。

反向传播从输出端给定一个权重向量 $`v`$，计算 $`J_f(x)^\top v`$。标量损失时上游权重通常是一，因此自然得到梯度。向量输出不能不加说明地要求“它的梯度”，因为不同输出分量对应不同导数行；你需要求和、取某个分量，或者显式给出上游权重。

动态图只记录实际执行的可微运算。条件分支取了哪一条、循环运行了多少次，都会反映在本次图中。但这不意味着框架会对离散分支选择本身给出有意义的导数。例如通过整数索引选择专家，通常只对实际选择的数值路径求导，不会自动获得“换另一个专家”的离散决策梯度。

在光滑区间，这种路径导数符合链式法则；在跳变点或不可导点，框架必须采用某种约定或产生不适定数值。研究时需要区分几乎处处可导与处处可导，更要区分一个程序可运行与它是否表达了你需要的估计量。

<a id="torch-1-detail-12"></a>

### 3.2 手算一次向量雅可比积

令 $`f(x_1,x_2)=(x_1x_2,x_1^2)`$，则雅可比矩阵为
$$
J_f(x)=
\begin{pmatrix}
x_2&x_1\\
2x_1&0
\end{pmatrix}.
$$
若上游权重是 $`v=(v_1,v_2)`$，反向结果为 $`(v_1x_2+2v_2x_1,v_1x_1)`$。在 $`x=(2,3)`$ 与 $`v=(5,7)`$ 处，结果是 $`(43,10)`$。这里没有必要构造完整雅可比，就可以通过局部乘积得到最终输入梯度。

前向模式则给定输入方向 $`u`$，得到 $`J_f(x)u`$。例如 $`u=(1,-1)`$ 时，输出方向为 $`(1,4)`$。同一个雅可比的两种乘法具有不同计算方向；当输入维度很少而输出很多，前向方式可能更合适，标量损失与海量参数则常适合反向方式。

二者可以通过伴随恒等式核对：$`v^\top(Ju)=u^\top(J^\top v)`$。它是检查自定义导数的重要工具，因为不需要列出完整雅可比。有限差分再提供独立数值对照，不过必须选择合适精度、步长并避开非光滑点，不能把两种都依赖同一错误公式的实现当作相互验证。

```python
import torch
from torch.func import jvp, vjp

x = torch.tensor([2., 3.], dtype=torch.float64)
u = torch.tensor([1., -1.], dtype=torch.float64)
v = torch.tensor([5., 7.], dtype=torch.float64)

def f(z):
    return torch.stack((z[0] * z[1], z[0].square()))

y, ju = jvp(f, (x,), (u,))
_, pullback = vjp(f, x)
jtv, = pullback(v)
assert torch.allclose(ju, torch.tensor([1., 4.], dtype=x.dtype))
assert torch.allclose(jtv, torch.tensor([43., 10.], dtype=x.dtype))
assert torch.allclose(v @ ju, u @ jtv)
h = 1e-5
fd = (f(x + h * u) - f(x - h * u)) / (2 * h)
assert torch.allclose(fd, ju, atol=1e-8)
print("JVP, VJP and adjoint check: passed")
```

### 3.3 机制展开：未注册参数不会自动进入优化器

“可求导”与“被优化器更新”是两套机制。一个临时创建的叶子张量可以具有正确梯度，但如果优化器从未收到它，更新时就会被遗漏。相反，一个参数即使被优化器持有，如果本轮没有参与前向或梯度被清成 None，也可能不发生更新。

最危险的是每次前向都新建一个线性层：本次损失确实依赖这个新层，反向也能产生梯度，但下一次前向又换成另一组随机参数。即使训练损失偶然下降，也不代表同一组模型权重正在学习。检查参数名称、对象身份以及更新前后的数值差异，比单看损失曲线更直接。

注册机制负责让模块能够递归发现子模块、参数和缓冲状态。优化器则在构造时接收一组具体参数对象，它不会在以后每一步自动重新扫描模型。一旦替换模块属性中的参数，就必须重新检查优化器参数组是否与新模型匹配，不能以为名称相同就等于身份相同。

## 4. 图的生命周期与求导接口

<a id="torch-1-detail-15"></a>

### 4.1 backward 与 grad 的不同职责

反向接口可以把导数累积到叶子的梯度字段，也可以把导数直接作为返回值交给调用者。前者适合传统优化循环，后者适合函数式推导、元学习与局部检查。不要在同一段代码里混用两种方式后，又假设返回梯度已经自动写入所有参数字段。

设损失由两个任务组成 $`L=L_a+\lambda L_b`$，分别对它们反向再相加，在共享图及生命周期处理正确时可以得到联合梯度。更简单的实现通常是先组合标量损失再反向一次。对任务梯度分别分析时，才有必要显式保留共享计算或重新执行前向。

图需要保存反向所需的部分中间数据。普通反向完成后，这些保存内容通常会被释放；第二次沿同一图反传可能因此失败。重新前向会建立新的图，并不需要为整个训练过程设置保留图。无条件保留每一张图会增加内存压力，还可能掩盖不必要的重复求导。

<a id="torch-1-detail-16"></a>

### 4.2 retain_graph 与 create_graph 为什么不同

保留图解决的是“以后还要再沿同一次前向求导”，建立导数图解决的是“还要对刚算出的导数继续求导”。这两个需求不能互换。计算海森向量积需要让一阶导数本身保留对原变量的可微依赖；仅保存原前向的中间数据并不足以表达二阶求导。

例如 $`L(x)=\sum_i x_i^3`$，一阶梯度为 $`3x_i^2`$，与方向 $`v`$ 做内积后再求导，得到 $`6x_i v_i`$。这是海森矩阵与向量的乘积，无需显式建立平方规模的矩阵。它在曲率分析、隐式微分和二阶优化中都很有价值，但对非光滑目标必须谨慎解释。

一个容易忽略的边界是线性函数的梯度可以是与输入无关的常量。即使请求建立导数图，得到的常量梯度也未必具有可继续反向的依赖。不能把这种情况直接判为框架出错；数学上的二阶导数为零，需要让程序显式处理常量或未使用变量。

```python
import torch

x = torch.tensor([1., 2., -1.], dtype=torch.float64, requires_grad=True)
v = torch.tensor([2., -1., 3.], dtype=torch.float64)
loss = x.pow(3).sum()
g, = torch.autograd.grad(loss, x, create_graph=True)
hv, = torch.autograd.grad((g * v).sum(), x)
assert torch.allclose(hv, 6 * x.detach() * v)
assert x.grad is None
z = torch.tensor(2., requires_grad=True)
a = z.square()
a.backward()
failed = False
try:
    a.backward()
except RuntimeError:
    failed = True
assert failed
print("higher derivatives and graph lifetime: passed")
```

### 4.3 深入讲解：动态计算图叶子参数与梯度归属怎样配合

用户直接创建、要求梯度的张量通常是叶子；由可微操作产生的结果通常是非叶子。参数一般以叶子形式参与优化，这样反向可以把汇总导数存入稳定对象。某些设备或类型转换会产生新的可微结果，因此应在目标设备和类型上创建参数，或者让模块统一迁移后再构造优化器。

非叶子没有默认梯度缓存，不等于没有梯度流过。传播是一次计算，保存字段是额外存储策略。若确实需要观察中间激活的梯度，可以显式保留，或通过钩子记录；记录时通常还需要分离并复制，避免把调试工具变成新的图持有者。

多次使用同一参数会把贡献累加到同一叶子；不同参数即使初始数值完全一致，也不会自动合并梯度。这一点解释了参数共享为何是结构约束，而不只是初始化策略。共享能够减少自由度，也会让多个任务对同一表示形成相互作用，应在设计阶段明确。

**图解：共享参数的分支梯度怎样汇合。**

![一个共享参数的两条导数路径与独立参数更新对照](images/01-shared-gradient.svg)

同一参数 w=2 同时进入平方与三倍两条分支，损失为 w²+3w=10，两条导数贡献相加得到梯度 7。取学习率 0.1 的普通 SGD，共享 w 更新到 1.3；若改为两个初始均为 2 的独立参数，梯度分别是 4 与 3，更新到 1.6、1.7。初始前向相同不代表参数所有权或后续轨迹相同；一次链式求导的分支求和与多次 backward 的缓冲累积也需区分。

是否在多次调用前清零 `.grad` 应服从训练目标。[PyTorch 的 backward 文档](https://docs.pytorch.org/docs/stable/generated/torch.autograd.backward.html)说明了叶子梯度的累加规则。

## 5. 切断历史、关闭记录与修改数值

<a id="torch-1-detail-19"></a>

### 5.1 detach、clone 与重新构造张量的组合

分离结果停止沿原历史反传，但数据仍可能共享。克隆产生独立存储，却通常保留可微关系。因此“我要一份可继续训练但不影响原值的副本”与“我要一份固定日志快照”需要不同组合。日志常使用分离后克隆；可微分支常使用克隆但不分离。

重新构造张量通常建立新的数据边界，而不是重接原图。假设外部计算给出一个数组，再将其包装为需要梯度的张量，所得梯度只说明新叶子如何影响后续损失，无法说明原模型参数如何影响外部计算结果。若不知道这点，训练程序可能只更新了临时数据而没有更新模型。

分离也可以有明确数学意义，例如目标网络、交替优化或停止梯度估计器。此时必须把目标写成“本次更新将这个量视为常数”的偏导问题，而不是声称仍在求原完整目标的全导数。两个估计器数值前向相同，反向规则不同，可能对应不同算法与偏差。

<a id="torch-1-detail-20"></a>

### 5.2 no_grad、inference_mode 与 eval 的职责边界

关闭梯度记录适合参数更新、验证和固定特征提取，但是否允许关闭，需要沿完整依赖链判断。一个冻结的中间网络若仍需要把输入梯度传给前面的可训练模块，就不能整体放到不记录的区域中。冻结参数只排除对那些参数求导，不应误切其他所需路径。

评估模式改变某些模块的运行行为，例如随机丢弃和批统计的使用方式；它没有承诺关闭求导。因此可以在评估模式下计算输入敏感度，也可以在不记录梯度时使用训练模式更新某些统计状态。二者是独立维度，应根据任务分别设置。

推理模式进一步减少记录开销，同时对产生的张量有更严格的后续使用限制。纯推理可以使用它；若输出之后还要作为训练图中的中间量，较普通的关闭记录上下文更容易管理，必要时在上下文外复制成普通张量。不要把一次速度测试的收益推广到所有混合流程。

<a id="torch-1-detail-21"></a>

### 5.3 原地修改与版本计数

反向公式有时需要前向时的旧输入或旧输出。例如平方需要原输入，指数可以利用原输出。若某个共享别名在反向前原地修改这些值，数学上已经无法按原前向恢复正确导数。框架的版本检查能够抓住许多这种问题，但不能把“未报错”当作任意修改都安全的证明。

原地操作节省一个输出对象不等于节省整个训练的峰值内存。自动微分可能已经高效复用缓冲，而原地修改反而引入限制和调试负担。优化前应先测量峰值与瓶颈，再判断某处替换是否值得。使用绕过检查的旧式数据属性会破坏可追踪性，不应作为常规修复手段。

参数更新通常放在不记录区域中，在反向结束后进行。这是有意把优化算法与当前前向图分开；若研究可微优化，则需要函数式更新并保留参数更新的导数关系。普通优化器更新与元学习中的可微更新不是同一个数学对象。

<a id="torch-1-detail-22"></a>

### 5.4 无效运算不能靠最后的掩码挽救

先对零做除法，再把无效输出乘以零，不保证导数安全。无穷值与零相乘可以形成未定义表达式，反向仍可能访问已经记录的危险算子。正确思路是让无效元素根本不进入危险运算，或者使用满足目标语义的安全分母与选择机制。

同理，条件选择函数可能先计算两个候选表达式，再选择结果；如果其中一个分支已经产生非法值，选择后看起来有限也不说明反向安全。只有在实际执行路径上避免无效操作，才能从源头处理问题。稳定化时加入的小常数也必须说明改变了什么函数，而不是任意调到不报错。

```python
import torch

x = torch.tensor([1., 1.], dtype=torch.float64, requires_grad=True)
denom = torch.tensor([0., 2.], dtype=torch.float64)
valid = denom != 0
safe = torch.zeros_like(x)
safe[valid] = x[valid] / denom[valid]
safe.sum().backward()
assert torch.equal(x.grad, torch.tensor([0., .5], dtype=x.dtype))

a = torch.tensor([2.], requires_grad=True)
b = a.detach()
b.add_(1)
assert a.item() == 3
snapshot = a.detach().clone()
snapshot.add_(5)
assert a.item() == 3
print("safe masking and detached aliases: passed")
```

#### 把“前向有限、反向无效”拆到两个元素

![除法之前与之后应用掩码的计算路径对照](images/01-mask-before-division.svg)

图与上面的安全代码使用相同输入。若改成 `torch.where(valid, x / denom, torch.zeros_like(x))`，Python 会先计算 `x / denom` 再调用选择函数，零分母项已经进入求导图。选择后输出虽然为 $`[0,0.5]`$，损失也是有限的 $`0.5`$，但选择算子传给未选分支的零上游导数仍会进入除法反向：对第一个输入分量产生 $`\frac{0}{0}`$，得到 NaN；第二项得到 $`\frac{1}{2}`$。

安全版本先取有效位置，只让第二项进入除法，然后把结果写回零初始化张量。无效项没有那条除法依赖，因此对输入的贡献为零。两个程序在这个输入处的最终数值相同，但实际记录的局部运算不同，不能仅比较最终损失判断梯度安全。

这里把无效项定义为常数零，并将分母视为固定数据。若研究问题要求学习分母或让有效集合随参数变化，还需另外分析零附近的定义域与离散掩码边界；本图并未为原本未定义的除法创造经典导数。该机制与 [PyTorch 的零除自动微分说明](https://docs.pytorch.org/docs/2.10/notes/autograd.html#division-by-zero-in-autograd)一致。

### 图解：detach 与 clone：分别检查存储和梯度

![detach 与 clone：分别检查存储和梯度](images/01-advanced.svg)

对普通稠密张量，detach 返回的新张量与原张量共享存储，同时断开反向和前向自动微分关系；clone 则创建独立数据副本，并在输入需要梯度时保留可微复制的历史。图中第三行组合两项操作，得到既独立存储又断开历史的快照。三行按同一输入条件比较：圆形是两个不同张量对象，蓝线最终指向实际数值缓冲，橙线只在 clone 行返回输入。第一行两个对象的蓝线汇入同一缓冲，第二行虽有两份数据却保留反向依赖，第三行才同时满足数据独立与断开历史。不能把“新张量对象”直接等同于“新数据缓冲”。

## 6. 模块、参数与可迁移状态

<a id="torch-1-detail-24"></a>

### 6.1 Module 是递归状态管理协议

模块不仅是一个带前向函数的类，还负责组织子模块及其状态。把子模块赋给模块属性，或放进受管理的容器，能够让递归遍历、设备迁移、保存和模式切换共同工作。普通列表仅管理 Python 对象集合，并不自动承担模块协议的全部职责。

普通张量属性也不自动成为参数。参数表达需要优化的自由变量，缓冲表达应随模块迁移或保存但不由常规梯度更新管理的状态，例如固定归一化系数、运行均值或索引表。缓冲是否持久化是另外一个选择：有些可重建缓存适合随设备迁移但不进入持久状态。

设计模块时应逐项分类：可学习量放参数，必要运行状态放缓冲，纯配置放明确字段，临时中间量放局部变量。若把所有数据都塞进参数，优化器可能更新不该更新的量；若把所有常量都放普通属性，设备迁移与加载时又可能遗漏关键状态。

<a id="torch-1-detail-25"></a>

### 6.2 参数名称、对象身份与共享层

同一个层对象被两次调用，表示同一组参数作用两次；两个独立构造的层表示两组自由参数，即使初始化值一样。共享层会让图中多次使用的贡献相加。参数遍历通常会处理重复对象以避免无意重复更新，但在手动组合参数组时仍应自己检查身份集合。

参数名称是序列化和解释结构的重要索引，却不能替代对象身份。给同名属性赋一个新参数，相当于更换对象。已经创建的优化器可能继续持有旧对象，导致日志显示有梯度的新参数不更新，旧参数却保留无用状态。可靠做法是完成结构和设备安排后再建立优化器。

模块的调用入口还承担钩子等管理逻辑，因此通常应通过调用模块实例执行前向，而不是直接绕过入口调用内部前向函数。自定义模块也应实现清晰的输入输出约定，尽量避免在前向中偷偷替换参数或改变不可见的全局状态。

<a id="torch-1-detail-26"></a>

### 6.3 状态字典不是完整程序，也不是天然快照

状态字典保存参数及持久缓冲等状态，不自动保存任意 Python 控制逻辑、数据预处理约定与实验配置。恢复时需要兼容的模型结构。即使张量名称与形状都能匹配，也要确认类别顺序、特征定义与归一化规则一致，否则得到的是数值合法而语义错误的模型。

直接获取状态字典后放在一个变量里，里面的张量可能仍引用当前存储。若要保存最佳轮次的内存快照，需要独立复制，或者立即序列化。否则后续训练改变参数，所谓“最佳权重”也可能随之改变。下一章会在完整训练循环中执行真正的快照恢复。

下面的模块同时展示参数、缓冲、共享参数与普通列表的差别。普通列表中的层仍能在手动调用时运算，但不出现在注册遍历中。实验不是鼓励保留这种坏结构，而是让遗漏可以被断言直接发现。

```python
import torch
from torch import nn

class Good(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = nn.ModuleList([nn.Linear(2, 2)])
        self.register_buffer("center", torch.tensor([1., -1.]))
        self.register_buffer("scratch", torch.zeros(1), persistent=False)
    def forward(self, x):
        return self.layers[0](x - self.center)

class Bad(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = [nn.Linear(2, 2)]
    def forward(self, x):
        return self.layers[0](x)

good, bad = Good(), Bad()
assert sum(p.numel() for p in good.parameters()) == 6
assert list(bad.parameters()) == []
assert "center" in good.state_dict() and "scratch" not in good.state_dict()
shared = nn.Linear(2, 2)
pair = nn.ModuleList([shared, shared])
assert len(list(pair.parameters())) == 2
assert pair[0].weight is pair[1].weight
print("module ownership and state: passed")
```

## 7. 参数所有权、冻结与优化器边界

<a id="sec-5-1"></a>

<a id="torch-1-detail-28"></a>

### 7.1 梯度保存位置与计算图是两个概念

参数参与计算图说明它影响了本次输出；叶子梯度字段说明导数存在哪里；优化器参数组说明谁负责使用这些导数。这三个集合通常有交集，但并不天然相同。调试时应分别列出参与前向、实际得到梯度以及预期更新的对象，再比较差异。

某个参数梯度为零，可能是当前数据刚好抵消、激活落入零导数区间，或者目标本身与它局部无关。梯度为 None 则通常意味着没有累积到这个字段、被显式清除或根本未参与本次路径。两者不能仅靠打印时都“看起来没变化”而混为一谈。

优化器带动量、权重衰减或其他状态时，零梯度参数仍可能变化；没有梯度的参数在常见优化器实现中通常会跳过。冻结前若遗留旧梯度，也可能产生意外更新。因此改变训练阶段时，除了设置求导标记，还要清理旧梯度并审查优化器状态与参数组。

<a id="visual-optimizer-missing-gradient"></a>

### 进阶图解：缺失梯度暂停状态，零梯度仍推进状态

![SGD 缺失梯度与零梯度的参数和动量轨迹](images/01-optimizer-missing-gradient.svg)

用一个标量把前面的区别算完整。采用学习率 $`\eta=0.1`$、动量系数 $`\mu=0.9`$ 的 SGD，不使用权重衰减、阻尼或 Nesterov。设动量缓冲已经建立，参与更新时的规则是

$$
b_{\mathrm{new}}=\mu b_{\mathrm{old}}+g,
\qquad
w_{\mathrm{new}}=w_{\mathrm{old}}-\eta b_{\mathrm{new}}.
$$

这里的 $`b`$ 是优化器缓冲，不是模型偏置。先从 $`w=1`$ 用数据梯度 $`g=2`$ 热身一次，得到 $`(w,b)=(0.8,2)`$。下一步计算与这个参数无关的分支，比较清梯度策略：

| 当前参数的梯度字段 | 是否进入本例 SGD 的参数更新集合 | 该步之后的参数与动量 |
| --- | --- | --- |
| `None` | 跳过 | $`w=0.8,\ b=2`$ |
| 数值为零的张量 | 参与 | $`b=0.9\times2=1.8,\ w=0.8-0.1\times1.8=0.62`$ |

这不是“零是否足够小”的数值问题，而是更新分支不同。[PyTorch 2.10 的 zero_grad 文档](https://docs.pytorch.org/docs/2.10/generated/torch.optim.Optimizer.zero_grad.html)明确区分这两种行为；[对应版本 SGD 源码](https://github.com/pytorch/pytorch/blob/v2.10.0/torch/optim/sgd.py)先筛选具有梯度张量的参数，再对筛选结果更新状态和参数。即使当前数据没有贡献，已有历史动量也可能继续推动参数。

#### 不只当前值不同，重新参与时也不同

再让两条路径收到同一个数据梯度 $`g=1`$。缺失梯度路径的动量一直保留为二，因此

$$
b=0.9\times2+1=2.8,\qquad
w=0.8-0.1\times2.8=0.52.
$$

零梯度路径已经将动量衰减过一次，并移动了参数，因此

$$
b=0.9\times1.8+1=2.62,\qquad
w=0.62-0.1\times2.62=0.358.
$$

本例故意使用与参数数值无关的线性损失，使下一梯度精确相同，隔离出优化器状态的差异。在通常的非线性模型中，参数位置已经不同，后续数据梯度还可能继续分叉。对于条件分支模型，应明确“未激活参数”采用暂停状态、零输入推进状态，还是重置状态；三者对应不同的训练算法。

再看冻结：热身后旧梯度二仍存于字段中，若只设 `requires_grad_(False)` 而直接再调用本例优化器，标志变化不会删除这个旧张量。于是 $`b=0.9\times2+2=3.8`$，参数变成 $`0.42`$。是否允许未来生成梯度，与优化器此刻能否读到旧梯度，是两条不同边界。

#### 完整实验：同时核对参数、缓冲与旧梯度

```python
import torch

dtype = torch.float64

def make_warm():
    parameter = torch.nn.Parameter(torch.tensor(1.0, dtype=dtype))
    optimizer = torch.optim.SGD(
        [parameter], lr=0.1, momentum=0.9,
        dampening=0.0, weight_decay=0.0, nesterov=False,
        foreach=False,
    )
    (2.0 * parameter).backward()
    optimizer.step()
    return parameter, optimizer

def snapshot(parameter, optimizer):
    return (parameter.item(),
            optimizer.state[parameter]["momentum_buffer"].item())

def check(actual, expected):
    torch.testing.assert_close(
        torch.tensor(actual, dtype=dtype),
        torch.tensor(expected, dtype=dtype),
        rtol=0, atol=1e-12,
    )

for mode, idle, resumed in [
    ("none", (0.8, 2.0), (0.52, 2.8)),
    ("zero", (0.62, 1.8), (0.358, 2.62)),
]:
    parameter, optimizer = make_warm()
    check(snapshot(parameter, optimizer), (0.8, 2.0))
    optimizer.zero_grad(set_to_none=(mode == "none"))
    # This unrelated branch does not use parameter.
    other = torch.tensor(3.0, dtype=dtype, requires_grad=True)
    other.square().backward()
    assert (parameter.grad is None) == (mode == "none")
    optimizer.step()
    check(snapshot(parameter, optimizer), idle)
    optimizer.zero_grad(set_to_none=True)
    parameter.backward()  # The same next data gradient, 1, for both paths.
    optimizer.step()
    check(snapshot(parameter, optimizer), resumed)

parameter, optimizer = make_warm()
parameter.requires_grad_(False)
assert parameter.grad.item() == 2.0  # Old storage survives this flag change.
optimizer.step()
check(snapshot(parameter, optimizer), (0.42, 3.8))

# Zeroing does not allocate a missing gradient tensor.
parameter = torch.nn.Parameter(torch.tensor(1.0, dtype=dtype))
optimizer = torch.optim.SGD([parameter], lr=0.1)
optimizer.zero_grad(set_to_none=False)
assert parameter.grad is None
print("missing, zero, stale gradients and momentum states: passed")
```

最后一个断言避免另一种误解：`zero_grad(set_to_none=False)` 会把**已有**梯度张量清零，不会为从未获得梯度的每个参数强制分配一个零张量。因此它对某个分支参数的影响还取决于此前是否建立过梯度字段，不能脱离执行历史只看调用参数。

冻结阶段可以在修改求导标志的同时明确将旧梯度清成 `None`，并检查所选优化器是否按这种字段跳过。重新启用时保留历史动量是一种方案，重置它是另一种方案；保存和恢复检查点时必须保持选择一致。移出参数组也可用于限定优化器所有权，但后续重新加入时如何恢复状态需另行定义，不能把重建优化器默认为等价操作。

本图只对声明的 SGD 配置给出数值。Adam、AdamW 等方法还有矩估计、步数与偏差校正，应核对其实际实现；不要把这里的动量衰减公式套用到所有优化器。即使没有动量，显式零梯度参与带衰减的更新，也可能改变参数。判断“参数应不应该动”时，需要同时查看梯度字段、参数组、算法状态和本步更新规则。


<a id="torch-1-detail-29"></a>

### 7.2 冻结中间层仍可能需要输入梯度

考虑 $`h=f_\theta(x)`$，输出为 $`g_\phi(h)`$。如果只训练 $`\theta`$，冻结 $`\phi`$ 并不意味着可以在不记录区域中计算整个 $`g`$，因为仍需 $`\frac{\partial g}{\partial h}`$ 把梯度传回 $`\theta`$。参数梯度与输入梯度是同一个算子的不同偏导，关闭一类不应粗暴删除另一类。

若只训练后面的分类头，前面的特征提取器既没有可训练参数，也不需要输入梯度，那么可以在不记录区域中提取固定特征。两种场景表面上都叫“冻结网络”，却拥有不同的依赖图。先写明要更新哪个变量，才能判断图应该保留到哪里。

此外，冻结参数并不自动固定运行统计。批归一化在训练模式下可能继续改变缓冲，即使权重不需要梯度。是否允许这种适配属于实验方案：小批域迁移、纯特征提取与联合训练可能选择不同规则，必须明确记录，不能让默认模式替你作决定。

<a id="torch-1-detail-30"></a>

### 7.3 更新前后的三重核对

第一重核对对象：优化器中参数身份是否等于预期可训练集合。第二重核对导数：损失反向后，关键参数梯度是否存在、有限，尺度是否合理。第三重核对更新：一步之后参数究竟是否变化，变化与学习率及算法状态是否相符。三者组合比观察最终准确率更快定位实现错误。

在大型模型里不必逐元素打印所有张量，可以记录形状、范数、是否有限以及更新差值。对明确应冻结的参数，则比较更新前后是否完全一致。共享参数要按对象去重统计，避免把相同存储的多条名称当作多个独立变量。

不要把“每个参数都应该每步非零更新”当成通用标准。条件执行模型、稀疏专家以及部分损失天然可能只激活子集。正确检查依据是设计预期，而不是所有数字必须变化。相反，一个不该参与本轮任务的参数变化，可能比某个零梯度更值得警惕。

<a id="torch-1-detail-31"></a>

## 8. 研究级求导验证与调试顺序

<a id="torch-1-detail-32"></a>

### 8.1 前向意义先于梯度检查

有限差分与自动微分一致，只证明它们对同一个已实现函数给出了相符的一阶变化。若标签错位、归约权重错误或样本被错误广播，它们可以一起通过。因此验证顺序应先检查输入与输出的任务含义，再检查手算小例，之后检查导数，最后观察训练轨迹。

方向导数检查适合高维参数，因为一次正负扰动就能检查某个随机方向。多个方向可以提高发现错误的机会，但仍不构成完整证明。坐标检查更容易定位具体参数块，代价随维度增长；两者可以结合使用，而不是只报告一个全局误差数。

数值检查优先使用双精度与小规模平滑数据。步长太大有截断误差，太小有舍入抵消；在多个步长上观察误差趋势比固定一个魔法常数更可靠。随机层要固定随机状态或关闭，运行缓冲要保持一致，否则比较的已不是同一函数。

<a id="torch-1-detail-33"></a>

### 8.2 自定义算子必须交代边界

实现一个自定义反向规则，需要声明输入域、形状、广播与数值类型，再写出上游导数如何转换为每个输入的导数。反向实现应该兼顾高阶求导需求；使用不可追踪的外部计算可能让一阶检查通过，却无法继续求二阶导数。

非光滑点也不能隐藏。绝对值在零点没有经典导数，最大值在并列处也可能有多种合法广义导数选择。框架给出一个约定不等于数学上唯一正确，有限差分在这些位置的结果可能依赖扰动方向。测试应覆盖光滑区间，再另写边界语义测试。

异常检测可在调试时帮助定位产生问题的操作，但会带来额外开销，适合缩小后的复现例而非永远开启。若出现无穷或非数，应从最早的前向非法值开始排查，而不是首先把所有梯度截断或分离。错误越靠后修补，越可能偏离原任务。

<a id="torch-1-detail-34"></a>

### 8.3 函数式思维为更高级研究铺路

传统模块把参数藏在对象状态里，便于常规训练；函数式表达把参数作为显式输入，便于向量化、元学习和参数空间分析。两种风格可以共存，但不要在函数变换内部偷偷修改全局参数或把张量转成 Python 标量驱动无法兼容的控制逻辑。

例如研究多个初始化的平均梯度，概念上是对“参数到损失”的函数进行映射，而不是复制一堆相互共享不清的模块。显式参数让依赖关系更容易审查，也能明确哪些状态是每个模型独有、哪些是所有模型共享的固定数据。

进阶时还应区分程序的微分与训练算法的微分。对一次损失求导只是局部任务；对训练若干步后的验证损失求导，还涉及每次更新、优化器状态及随机过程。普通一步训练代码不能通过简单添加保留图就自动成为正确的元学习实现。

<a id="torch-1-detail-35"></a>

### 8.4 用一个可解释的小模型串起所有检查

可以把二维线性回归当作调试仪器：人为选择真实权重与偏置，生成没有噪声的输入输出，再从错误初值开始拟合。因为目标函数与最优值都清楚，若训练不收敛，就能优先检查实现而不是归咎数据难度。但这种实验只能验证当前路径，不能替代真实任务的数据协议。

第一步固定一个小批，手算前向与均方误差。第二步写出解析梯度，检查偏置是否沿样本轴求和、均值系数是否只应用一次。第三步比较自动微分与方向差分。第四步只更新一次，确认参数沿预期方向移动。最后才运行多个迭代观察收敛。每一步都消除一个独立不确定性，失败位置也更容易解释。

如果希望验证共享参数，可以把同一线性映射在两个分支中使用，两个分支的输入取不同数值。分别计算损失梯度，再计算联合损失梯度，比较是否等于向量和。这个实验能够区分“同一个对象被使用两次”与“两个初值相同的独立对象”，也能暴露手动参数组中重复更新的问题。

如果希望验证停止梯度，可以构造数值前向相同的两条程序：一条保持完整依赖，另一条对中间量分离。比较输出应该一致，但输入导数可能不同。这说明导数属于所表达的计算关系，不只是最终数值。研究停止梯度方法时，应把这种差异当成算法定义的一部分，而非框架技巧。

<a id="torch-1-detail-36"></a>

### 8.5 梯度范数、条件数与单位尺度

梯度很大或很小没有脱离单位的绝对意义。把输入特征从米改成毫米，会改变对应参数与梯度的尺度，而函数预测可以保持等价。检查梯度时应同时看参数尺度、更新尺度和数据单位，尤其不要仅凭一个全局范数阈值判断所有层是否健康。

对二次目标，不同方向的曲率差异会造成狭长等高线：某些方向允许较大步长，另一些方向极易振荡。自动微分能给出正确梯度，却不会自动改善这种条件数问题。标准化、重新参数化以及适当预条件属于优化设计，应与导数实现是否正确分开分析。

相对更新量可以帮助发现异常，例如用参数改变量范数除以参数范数加一个有说明的尺度常数。但接近零的参数会让比值敏感，所以还应同时报告绝对量。对偏置、归一化尺度与巨大嵌入表使用同一个解释口径也不一定合理，应结合各自角色分析。

梯度消失还可能来自饱和激活或很长的链式乘积，而非断图。此时梯度可能存在、有限但非常小。反过来，字段缺失常指向路径或存储策略问题。把这两类现象分开之后，才能决定是调整模型结构、初始化与数值精度，还是修复分离和注册错误。

<a id="torch-1-detail-37"></a>

### 8.6 复现实验应保存哪些解释信息

最小复现除了随机种子，还应交代形状、数值类型、设备、库版本与运行模式。一个在双精度小张量上通过的导数检查，不自动保证低精度大批训练稳定；一个在评估模式下确定的前向，也不说明训练模式中随机层的行为一致。复现信息的作用是限定结论适用范围。

当错误只在复杂工程中出现，可以逐步剥离数据加载、并行执行与混合精度，保留最小仍失败的算子序列。若简化后错误消失，就把最后移除的因素单独加回并设计对照。这样的二分缩小比直接改几十处设置更容易形成可信因果解释，也更便于向他人提供可运行问题描述。

<a id="sec-6"></a>

<a id="torch-1-detail-38"></a>

## 9. 十六道进阶练习与详细解析

<a id="torch-1-detail-39"></a>

### 9.1 练习一：形状合法为何仍错

**问题。** 预测为 $`(4,1)`$，标签为 $`(4,)`$，两者相减再平方平均。程序可以反向，是否实现四个样本的均方误差？

**解析。** 两个维度从右对齐，第一项末维是一而第二项末维为四，所以广播得到 $`(4,4)`$。第一个索引选择预测样本，第二个索引选择标签样本，形成十六组交叉配对。正确目标只有四组对应关系，应统一为 $`(4,1)`$ 或统一为 $`(4,)`$，再断言形状相同。梯度检查可能通过，因为它验证的是错误的十六项函数。

**延伸。** 若损失显著变小，也不能据此排除错误。交叉配对会倾向预测整体均值，在某些数据上同样有明显下降。用各样本标签差异较大的确定性例子，比较手算四项与实现结果，比随机跑一轮训练更有辨别力。

<a id="torch-1-detail-40"></a>

### 9.2 练习二：数值一样是否同一参数

**问题。** 创建两个数值相同的参数，分别用于两个分支，是否等价于同一参数共享两次？

**解析。** 初始前向可能一致，但独立参数有两份自由度与两份梯度，更新后可以分离。共享参数只有一个自由变量，两条路径的梯度相加，再由一次更新处理。即使分别给独立参数施加相同初始化，也不会自动施加相等约束。若目标需要共享，应共享对象或明确参数化共同来源。

**延伸。** 软约束如平方差惩罚只鼓励接近，并不等价于严格共享；惩罚系数有限时允许不同，系数过大还会改变优化条件。结构共享、约束优化与正则近似应分别解释。

<a id="torch-1-detail-41"></a>

### 9.3 练习三：为什么中间量的梯度为空

<a id="sec-6-1"></a>

**问题。** $`y=x^2`$，$`L=y^2`$，反向后 $`x`$ 有梯度，$`y`$ 的梯度字段却为空，能否推断链路断开？

**解析。** 不能。传播到 $`x`$ 的链式法则必须经过 $`y`$，但默认不必把每个中间导数长期存进字段。显式保留后，在标量例子中 $`\frac{dL}{dy}=2y`$，而 $`\frac{dL}{dx}=4x^3`$。检查字段之前先明确对象是否叶子、是否请求保留以及是否被清理，避免把存储策略错当可导性。

**延伸。** 对巨大的每层激活都保留梯度会增加内存，分析时最好只选少数关键节点。钩子中保存的张量也应适当分离，否则一个监控列表可能持续持有历史图。

<a id="torch-1-detail-42"></a>

### 9.4 练习四：切断图是否也复制数据

**问题。** 对参数取分离结果，再原地写入新值，会不会影响原参数？如何获得安全日志快照？

**解析。** 分离主要改变导数历史，结果可能共享原存储，因此写入可能改变原参数并触发版本问题。独立日志快照需要分离并克隆，必要时再移动到适合记录的设备。仅克隆会保留图，适合可微副本而非长期日志；仅分离则没有独立所有权。

**延伸。** 在保存中间预测供其他线程使用时，还要保证同步与生命周期。即使已经独立复制，也应明确它对应哪个训练步，避免把不同轮次的标签和预测混合统计。

<a id="torch-1-detail-43"></a>

### 9.5 练习五：为什么冻结后仍需图

**问题。** 前层可训练、后层参数冻结，是否可以把后层前向放进关闭记录的上下文？

**解析。** 若损失在后层输出上定义，前层梯度需要后层对输入的导数。关闭整段记录会删除这个依赖，因此不可以。正确方法是冻结后层参数，但保留相对于输入的可微运算。只有当后层输出完全不再影响任何需要梯度的上游量时，才可以省去图。

**延伸。** 这也适用于优化输入、对抗样本与解释性分析。评估模式下的模型可以固定权重而仍对输入求导，因此“推理用模型”与“完全不求任何导数”并不是同义词。

<a id="torch-1-detail-44"></a>

### 9.6 练习六：为什么第二次反向报错

**问题。** 对同一个平方损失连续反向两次报错，但重新算损失后第二次反向成功，原因是什么？

**解析。** 第一次反向已经消耗并释放了部分保存数据，复用同一图可能找不到所需中间值。重新前向创建了新图，所以能够再次计算；叶子梯度仍会累积，需要另行清理。若确实需要同一图多次反向，可保留图，但要说明必要性与内存代价。

**延伸。** 某些简单运算没有需要保存的中间值，重复反向偶尔成功，不能据此推出所有图都可复用。依赖偶然实现细节会使代码在替换一个操作后突然失效。

<a id="torch-1-detail-45"></a>

### 9.7 练习七：保留图能否自动得到二阶导数

**问题。** 一阶求导时仅要求保留原图，随后对返回梯度求导，是否总能得到海森矩阵？

**解析。** 不能。必须让一阶导数的计算本身建立可微关系，保留原前向中间值只解决再次使用的问题。对 $`x^3`$，一阶为 $`3x^2`$，二阶为 $`6x`$；若一阶结果被当作固定数据保存，第二次求导没有需要的依赖。还要处理常量导数与未使用输入的边界。

**延伸。** 完整海森矩阵有平方级元素，很多任务只需海森向量积。先求梯度与方向内积再求导，可以减少显式存储，也更贴合二阶优化的实际计算需求。

<a id="torch-1-detail-46"></a>

### 9.8 练习八：向量输出应提供什么上游量

**问题。** 输出是三个残差，想得到残差平方和的梯度，能否直接对残差向量执行默认反向？

**解析。** 应先明确标量目标 $`L=\sum_i r_i^2`$，或者向残差提供上游权重 $`2r`$。默认的标量反向隐含权重一，但向量有多个分量，不能凭空决定如何组合。若只给全一权重，得到的是残差和的梯度，目标已经不同。

**延伸。** 显式权重若本身依赖参数，使用它作为某次向量雅可比积的外部种子，与对完整乘积目标求导有不同含义。需要先写数学函数，避免把求导接口当作自动补全目标的工具。

<a id="torch-1-detail-47"></a>

### 9.9 练习九：零梯度为何仍会更新

**问题。** 某参数当前梯度全零，使用带动量或衰减的优化器后参数仍改变，是否证明导数错误？

**解析。** 不一定。优化器更新可以依赖历史动量或参数本身，并非只使用当前梯度。零梯度与缺失梯度也可能触发不同分支。若要冻结，需设置求导策略、清除旧梯度并确认优化器规则；若要研究当前数据梯度，则直接检查导数，不把参数变化全部归因于它。

**延伸。** 记录更新范数与梯度范数可以发现这种差异。对比时应注明是否使用耦合正则、解耦衰减以及已有状态，否则同一梯度数值不足以唯一确定下一步参数。

<a id="torch-1-detail-48"></a>

### 9.10 练习十：替换参数后的旧优化器

**问题。** 创建优化器后，把模型权重替换为一个新参数，新参数得到梯度却不变化，应如何定位？

**解析。** 比较新参数身份是否出现在优化器所有参数组中。通常旧优化器仍引用旧对象，新对象虽然注册在模块里，却未被收集。应在模型结构确定后重建优化器或显式管理参数组，同时考虑旧状态是否应迁移。只按名称比较会漏掉这种身份变化。

**延伸。** 动态扩展网络不只是增加层，还涉及学习率组、优化器状态、保存格式与恢复兼容性。每次结构变更后都应重新核对预期可训练集合，而非假设已有训练器会自动发现。

<a id="torch-1-detail-49"></a>

### 9.11 练习十一：视图失败是否代表数据损坏

**问题。** 转置后无法用视图展平，但重排成功，是否说明前一种操作更不可靠？

**解析。** 两者承诺不同。严格视图要求新形状能由当前存储与步幅表达，因此拒绝不能满足的请求；重排可以选择复制来满足逻辑顺序。失败是约束被正确检查，并不代表数据损坏。业务若需要独立存储，还应明确克隆，不能依赖重排偶然复制。

**延伸。** 性能实验要同时量时间与是否复制。把重排换成视图若需要前面先连续化，并不一定减少复制次数；局部代码更短不等于总体内存行为更好。

<a id="torch-1-detail-50"></a>

### 9.12 练习十二：广播偏置的梯度为何是求和

**问题。** 偏置被加到一百个样本上，损失对每个输出的导数都是一，偏置梯度是多少？

**解析。** 每个样本贡献一，同一偏置共有一百条路径，合计一百。如果损失先对样本平均，上游每项成为百分之一，合计才是一。广播本身只规定复用，最终尺度由归约方式共同决定，不能把“平均梯度”当成偏置接口固定行为。

**延伸。** 在序列任务里偏置还可能跨时间复用。若掩码排除部分位置，只有有效路径贡献；若先按句子平均再按批平均，则每个有效位置的权重又取决于句长。

<a id="torch-1-detail-51"></a>

### 9.13 练习十三：如何验证自定义反向

**问题。** 一个自定义归一化算子在训练中没有报错，是否足以信任它？应设计什么证据？

**解析。** 先在远离奇点的小型双精度输入上比较前向手算，再检查多个随机方向的有限差分与向量雅可比积，并使用伴随恒等式核对前向和反向模式。然后单独检查零向量、极小范数、广播维度和非连续布局。若研究需要高阶导数，还要再验证二阶能力。

**延伸。** 两种求导实现若复制同一个错误公式，彼此一致并不独立。有限差分虽然有数值误差，却提供不同证据来源；步长扫描与边界测试共同提高可信度。

<a id="torch-1-detail-52"></a>

### 9.14 练习十四：先算无效值再筛选

**问题。** 先计算所有样本的对数，再把非正输入位置筛掉，输出损失有限，是否保证梯度有限？

**解析。** 不保证。非法对数已进入图，反向可能经过未定义值。应先构造有效子集，再对有效输入运算；如果任务要求为无效输入定义替代值，则应明确替代函数与相应导数。简单把结果乘零不等于消除非法运算。

**延伸。** 对数稳定化也应区分数值实现与统计建模。给概率加常数可以避免无穷，却改变了评分函数；若只是稳定计算，应尽量使用等价的对数域算法。

<a id="torch-1-detail-53"></a>

### 9.15 练习十五：模块状态是否只含权重

**问题。** 权重完全一样的两个模型，评估输出却不同，除了随机数还应检查什么？

**解析。** 检查偏置、持久缓冲、运行统计、预处理参数、类别顺序与模式。状态不仅是名字里含权重的张量，批归一化等层依赖非参数状态。还要确认两者输入数值、设备精度和前向结构相同。参数数量一致远不足以证明函数相同。

**延伸。** 保存资料时应把模型结构配置与预处理规范作为实验产物的一部分。状态字典解决数值状态迁移，配置解决函数解释，两者共同支持恢复。

<a id="torch-1-detail-54"></a>

### 9.16 练习十六：如何判断一次反向真正正确

**问题。** 所有参数都有有限梯度，损失连续下降，是否已经可以发布实验结论？

**解析。** 还需要确认数据划分独立、标签配对正确、目标归约符合任务、训练与验证模式符合协议，随后验证关键导数及更新对象。有限梯度只能排除一部分数值故障，不能证明研究问题得到正确实现。结论应有独立测试、基线比较和误差分析支持。

**延伸。** 实践中可以保留一组极小确定性测试作为模型的语义契约：形状、手算输出、梯度方向与一步更新都可复现。它们成本很低，却能在以后调整网络或加速实现时及时暴露行为改变。

<a id="torch-1-detail-55"></a>

## 10. 综合检查清单与后续阅读

读完本章，应能够独立回答：一个变量是参数还是状态，某次重排是否可能共享数据，一条冻结路径是否仍需输入梯度，某个导数为什么没有保存在字段中，以及优化器究竟更新哪组对象。这些问题属于训练程序的基础语义，后续再复杂的架构也无法绕开。

真正熟练的标志不是记住更多接口，而是遇到异常时能缩小成最小函数，写出依赖关系并区分三类错误：前向任务错误、求导关系错误、更新管理错误。先做语义检查，再做数值检查，再做性能优化，通常比围绕最终分数反复猜测更有效。

下一章把这些原则放进完整训练、验证与保存流程，重点研究指标归约、微批累积、最佳模型选择与恢复。数据加载和设备性能交给后续章节，避免一开始把语义、统计与硬件问题混成一个难以验证的巨大程序。
