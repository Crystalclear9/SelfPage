向量化不是把所有循环一次性展开，而是让表达式准确对应数学计算，并把适合批量执行的部分交给数值核心。本章把正确语义、数值稳定、内存规模与实验复现放在一起讨论。你会实现训练统计标准化、线性求解、分块最近中心和稳定概率计算，并知道每种实现在哪些条件下有意义。

本章矩阵接口部分需要知道矩阵乘法、线性方程与最小二乘的基本含义；首次学习数组时，可先阅读形状、标准化、随机流与内存部分，再配合[线性代数第2章](../../Mathematics/LinearAlgebra/02-投影最小二乘与矩阵分解.md)返回求解器与数值秩小节。不要求先完成奇异值分解的完整证明；这里侧重调用语义、诊断证据与实现取舍，数学结构的系统推导放在线性代数主题。

代码以 NumPy 2.4 为依据，每个完整 Python 块独立运行。计算例子使用温和规模，不要求下载数据或配置加速设备。性能结论会区分理论运算量与实际测量，随机结论会区分相同流重建与统计质量，避免把一条短表达式或一个固定种子当成普遍保证。

## 1. 区分逐元素乘法与矩阵乘法

逐元素乘法把对应位置相乘，并按广播规则共享长度一的轴；矩阵乘法则在共同的收缩维上乘后求和。两者可能输出完全不同形状，也可能碰巧形状相同但语义不同。编程前先写一个输出位置的公式，确定是否需要对特征求和，再选择算子，比从结果形状猜测可靠。

样本矩阵每行一条样本，权重向量每位置对应一个特征，线性预测是每行特征与权重的内积。逐元素乘法得到的是每个特征的贡献表，还需要沿特征轴求和；矩阵乘法则一次表达这项收缩。贡献表有时本来就是需要的解释对象，但不能把它与最终预测混同，尤其不能随意平均后替代求和。

偏置的共享也要明确。一个标量偏置作用于全部样本，一个输出维度向量在多输出模型中跨样本共享。若误把样本长度向量当偏置，就可能给每条训练样本独立自由度，既改变模型类，也难以应用到新样本。数组允许的运算比合理统计模型多，代码作者必须维护参数轴与数据轴的区别。

一维参与矩阵乘法时会按相应规则临时补矩阵轴，计算后再去掉该临时轴，因此矩阵乘向量得到一维，两个一维向量相乘得到标量。不要以为这种方便规则使一维天然成为固定行向量或列向量。高维批量情形更应检查末两轴与前导批轴，第三章会完整展开。

复数内积还涉及共轭。普通矩阵乘法不会自动把一个输入共轭成 Hermitian 内积；不同内积函数的展平、批量与共轭约定也不同。大多数初学模型只用实数，但接触信号处理时，不能把实数公式不加修改地套过去。算子选择应同时看轴和代数结构，不只看函数名包含 dot。

<a id="sec-1-1"></a>
### 基础算例：一批预测与逐条预测相互核对

取两行特征一二与三四，权重二与负一。第一条预测为二减二等于零，第二条为六减四等于二；加偏置零点五后是零点五与二点五。这个例子用负权重与不对称数据，能暴露误用逐元素乘法、错误特征归约与偏置广播。全部正一数据不具备同样判别力。

```python
import numpy as np

X = np.array([[1.0, 2.0], [3.0, 4.0]])
weight = np.array([2.0, -1.0])
bias = 0.5
prediction = X @ weight + bias
reference = np.array([
    sum(float(X[i, j]) * float(weight[j]) for j in range(X.shape[1])) + bias
    for i in range(X.shape[0])
])
np.testing.assert_allclose(prediction, [0.5, 2.5])
np.testing.assert_allclose(prediction, reference)
contributions = X * weight
np.testing.assert_allclose(contributions.sum(axis=1) + bias, prediction)
assert contributions.shape == (2, 2)
assert prediction.shape == (2,)
```

参考循环显式列出样本与特征索引，容易检查公式。正式大数据运行不必用它，但小输入对照提供独立语义证据。扩展到多个输出时，权重变成特征乘输出矩阵，每个输出有自己的收缩和偏置。此时要避免用 .T 随意翻转所有高维轴，也不要把单输出 squeeze 规则无条件套到多输出。

<a id="deep-dive-1"></a>
### 深入讲解：向量化是批量算法而不是删除循环

向量化主要减少解释器逐元素调用开销，让底层循环利用连续访问、向量指令或矩阵核心。底层仍然在执行运算，复杂度不会因为表达式变短就消失。一个平方规模算法写成单行，仍可能比一个带外层分块循环的线性算法慢且耗内存。先选择合适算法，再选择批量表达。

不是所有 Python 循环都应删除。外层遍历少量批次、内层调用大矩阵乘法，常常兼顾吞吐与内存；对每个元素调用 Python 函数则可能很慢。区分“控制大块工作”和“解释器处理每个标量”这两个层次，才能合理比较。没有必要把一个自然的批次循环伪装成巨大广播张量。

另外，某些看起来向量化的包装只是便利地遍历 Python 函数，不保证成为真正高性能数值内核。判断性能应看实际执行路径与测量，而非函数名。对于复杂逻辑，清楚的参考实现也有价值；只有当测量显示瓶颈且存在可靠替代时，再进行更复杂优化。

## 2. 标准化的完整例子

标准化先在训练集估计每特征均值和尺度，再用同一统计量变换所有后续样本。它改变特征坐标，可能改善优化尺度，但不保证所有模型都需要，也不自动消除异常值。每列代表什么单位、是否应中心化和缩放，需要结合任务。对类别编号直接标准化通常不具备普通连续量的解释。

本节使用总体标准差分母，也就是当前训练列中心平方差的平均再开方。无偏样本方差使用不同分母，它服务于某些统计估计目标；标准化工具默认哪一种必须明确。不能在训练与预测或不同实验中无声切换，否则参数与距离尺度都会改变。

```python
import numpy as np

train = np.array([[1.0, 10.0], [2.0, 10.0], [3.0, 10.0]])
validation = np.array([[4.0, 12.0]])
mean = train.mean(axis=0, keepdims=True, dtype=np.float64)
scale = train.std(axis=0, keepdims=True, dtype=np.float64, ddof=0)
constant = scale == 0
safe_scale = np.where(constant, 1.0, scale)
train_z = (train - mean) / safe_scale
validation_z = (validation - mean) / safe_scale
np.testing.assert_allclose(mean, [[2.0, 10.0]])
np.testing.assert_allclose(scale, [[np.sqrt(2.0 / 3.0), 0.0]])
np.testing.assert_allclose(train_z.mean(axis=0), [0.0, 0.0], atol=1e-15)
np.testing.assert_allclose(validation_z, [[np.sqrt(6.0), 2.0]])
np.testing.assert_array_equal(constant, [[False, True]])
```

第一列均值二，方差三分之二，验证值四变成根号六；第二列训练全为十，尺度按约定回退一，因此验证十二变成二。这个非零输出提示验证出现训练未见偏移，并非程序错误。若任务希望常数列永远输出零，应选择另一政策并说明它丢弃新变化，而不是声称两种回退完全等价。

<a id="sec-2-1"></a>
### 机制展开：零方差特征需要明确回退

零方差与近零方差不同。这里`scale == 0`对温和算例正确，但在任意极小数值上，非恒定列的偏差平方也可能下溢成零。因此通用实现不能只凭计算尺度为零就认定精确常数；应比较原列是否恒定，若不恒定却算出零尺度，就采用缩放方差算法或明确拒绝，而不能无声套用常数列回退。

精确常数列可以选择单位尺度、删除或专门标记；近常数列除以很小尺度会大幅放大微小噪声。加一个固定小数并不只是防止报错，它改变每列权重，而且该常数有单位。应依据测量精度与任务定义最小尺度，而不是从网上复制一个通用 epsilon。

若把训练和验证分别归一到各自均值零、方差一，模型看到的是不同坐标系统，而且验证分布信息参与处理。某些适应方法确实会更新统计量，但那是另一实验设置，需要独立评估。普通监督学习流程应先冻结训练统计，再应用验证；交叉验证时每折也要单独在其训练部分拟合。

标准化之后的参数也处于新坐标。若模型在标准化特征上使用系数 a 和偏置 b，回到原始特征时，每个系数应除以对应训练尺度，偏置还要减去训练均值与原尺度系数的内积。只把系数除尺度而保留旧偏置，会改变预测。可以在一小批原始输入上同时运行两种表达，核对预测，而不是只比较参数打印值。

例如某个特征训练均值十、尺度二，标准化模型系数三、偏置一。原空间系数是一点五，偏置是负十四；原始输入十二在新坐标为一，预测四，原空间计算也得到四。如果错误保留偏置一，预测会变成十九。这个手算说明坐标转换不是只改权重单位，中心移动也进入截距。

常数列回退尺度一时，同一代数关系仍适用于本章变换，但训练数据无法区分该列系数与截距的某些组合，参数可辨识性需要另行考虑。若采用删除常数列，回到原模式还要决定如何表示被删参数。不要把数值上能还原预测误解为已经识别了每个物理特征的因果贡献。

正则化也依赖坐标。如果在标准化系数上惩罚普通欧氏长度，映回原空间通常相当于按尺度加权的参数惩罚；它不必与直接在原始系数上使用同一个正则数值等价。比较预处理前后模型时，除了优化速度，还应考虑这种偏好变化。标准化可能同时改变数值条件与统计归纳偏置，不能把所有性能变化都归因于求解器更稳定。

标准化还应保存特征顺序。只保存两个均值向量，后来输入列交换，形状仍匹配却应用错误参数。可以在接口保留列名或模式版本，并验证一致。数组核心没有自动字段名，因此模型之外的数据契约同样重要。不能用 shape 正确替代特征身份正确。

## 3. 随机数与数值求解

随机数生成器是带状态对象。给相同初始状态并执行相同调用，能重建相应序列；插入一次额外抽样会推进状态，之后结果不同。推荐把生成器显式传给需要随机性的组件，而不是各处修改全局状态。这样可以解释数据、初始化和抽样之间的依赖，也方便单独验证。

固定种子不等于所有环境永远逐位一致。随机算法、库版本、调用形状与顺序都可能影响结果，外部并行数值计算也有自己的非确定性。复现报告应说明具体生成器与版本，而不是只写一个整数。统计质量与可重建是不同性质，始终返回零的函数也非常可复现，却不是合格随机源。

数值求解则应先辨认问题。方阵且非奇异的线性系统可以用 solve；矩形或可能秩亏的最小二乘使用 lstsq；显式求逆只在确实需要逆矩阵对象时考虑。把数学解析式里的逆号直接翻译成 inv 再乘向量，通常增加不必要成本，也掩盖求解对象的结构。

求解成功不意味着参数精确。病态矩阵可以把输入或舍入的微小扰动放大，返回残差很小但解误差很大。需要结合条件数、尺度与任务预测讨论。第九节会用完整小例子区分残差、数值秩和最小范数，避免把没有抛异常当作可靠性证书。

<a id="sec-4"></a>
## 4. 向量化也要估计中间内存

内存估算先数元素，再乘每元素字节数，同时考虑输入、输出与中间对象是否同时存活。两个点集分别有样本数和中心数，每点维度为特征数，直接广播差值需要三者乘积规模。最终距离矩阵只有前两者乘积，却可能已经很大。不要只看最终变量大小，忽略平方、差值和归约临时量。

一万个样本、一千个中心、一百二十八维，单个单精度差值张量约五点一二十亿字节，尚不包括平方副本、输入与输出。最终距离矩阵约四千万字节。这个数量级足以说明短代码的危险，而无需真的分配巨量内存进行演示。内存不足不应靠反复运行碰运气解决。

若最终只需要每个样本最近中心，不必保存完整距离矩阵。可以按样本或中心分块，保留当前最佳距离与编号。算法仍计算必要距离，但存储从全量结果降到局部块与线性状态。若中心数也很大，双向分块更合适。先明确最终需要什么信息，往往比优化某个广播表达式更有价值。

运算量与内存不是同一个目标。更少存储可能增加重复计算或 Python 控制开销；矩阵代数改写可能更快，却引入相消误差。需要同时比较正确性、峰值与时间，不能因为某个版本在小数组最快，就断言它适合所有规模。第八节会给出可检验的分块实现与明确并列规则。

<a id="sec-5"></a>
## 5. 聚合精度与随机流

浮点加法不是严格结合的，归约顺序改变可能影响最后几位。数组库可能采用分组求和或不同底层实现，因此与逐元素 Python 累加不必逐位一致。判断差异要看误差尺度、数据条件与任务容忍，而不是要求所有数学等价表达式输出同一二进制结果。反过来，明显倍数差或错轴不能被解释成正常舍入。

归约 dtype 可以改变累计精度。单精度数据用双精度累加，在许多大规模求和中能降低误差，但成本与输出类型也变化。先做低精度乘法再高精度求和，不能修复乘法已经丢掉的信息；类似地，输入在转换前已被量化，双精度不能恢复原值。应分析完整计算链，而不是只给最后一个 sum 加参数。

相消是另一种风险。两个很大的接近数相减，可能失去相对精度；方差的平方均值减均值平方，距离的范数和减两倍内积，都可能遇到。更稳定表达通常先中心化或直接求差，但可能付出更多内存或计算。数值方法选择经常是多目标权衡，不存在对所有输入总优的一个短公式。

随机流分离可以避免无关模块互相干扰。数据生成、参数初始化和评估抽样使用不同子流，修改其中一项的抽样数量不应直接推进其他流。可以通过种子序列派生明确子流，并记录角色映射。不能每次都拿同一个种子新建多个本应不同的生成器，然后认为它们独立；那会得到相同序列。

并行任务也要有稳定身份。若子流按任务编号分配，任务调度顺序变化不必改变每个任务的随机序列；若所有任务竞争一个共享流，则调度可能改变消费顺序。统计独立的设计与实际实现需要一起考虑。使用合适派生工具有助于建立高质量流，但仍应避免声称有限伪随机序列具有数学上完美独立性。

<a id="sec-6"></a>
## 6. 进阶：归约误差与线性代数调用

线性代数库选择实现时会考虑数据类型、形状与布局，并可能调用多线程底层核心。你看到一个矩阵乘号，不代表它只执行一条机器指令，也不代表输入无需临时整理。比较表达式性能时，线程数、连续性、首次初始化和缓存都可能影响结果。应记录这些条件，避免把环境差异误当算法差异。

正规方程把最小二乘转成特征维方阵系统，代数上很简洁，但在满列秩情形中，二范数条件数会平方。小奇异方向的误差因此可能更严重。直接使用合适分解求最小二乘，通常比显式构造逆更稳健。条件数很差时，任何求解器都不能凭空补足信息，还需要正则化或重新设计问题。

残差与误差不同。残差衡量当前解代回方程还有多大不匹配，前向误差衡量离真实解多远；病态系统可能让大参数误差仍对应小残差。若最终只关心某些输入方向的预测，参数距离也未必直接等于任务风险。数值诊断与统计评价要连接起来，而不是只盯一个指标。

<a id="sec-6-1"></a>
### 向量化需要同时核算运算量与中间内存

平方距离可以展开为两边范数平方相加再减两倍内积，只保留样本乘中心矩阵，而不建立额外特征轴。它利用矩阵乘法核心，通常适合某些规模；但两点很接近而范数很大时，三个大项相减可能丢失精度。微小负值可以是舍入，显著负值则应先排查尺度与实现。

把所有负值直接截为零，会隐藏严重相消，也可能改变最近中心排序。合理策略是先在温和样本与直接差法对照，必要时对接近候选用直接差重算，或采用数据中心化与更高精度。截断只是处理理论非负范围的一种后处理，不是证明原计算准确。

![数学等价的距离公式，浮点结果可能不同](images/02-distance-cancellation.svg)

图中坐标均能在 float64 中精确表示，先求差得到 (−1,1)，平方距离是 2。改用范数展开时，真实的第二个平方范数为 20000000000000002，在本例浮点计算中舍入为 2e16；于是三个大项按图示顺序运算得到 0。e16 表示乘以十的十六次方。这个例子展示的是大数相减丢掉小差异，既不是输出只需裁成非负数就能修好的问题，也不说明直接差法在所有极端尺度下都不会失效。

若输出本来就是平方规模，减少中间轴并不能消除最终存储下界。百万样本的完整两两矩阵仍极其庞大；如果只需要近邻、核乘向量或某种汇总，应考虑相应算法接口，不必先物化全部对象。向量化是实现工具，需求重写有时能带来更大节省。

<a id="sec-7"></a>
## 7. 分层练习与参考解析

**练习一：贡献与预测。** 三条样本、四个特征，权重长度四。逐元素乘法得到三乘四贡献表，矩阵乘法得到三条预测。若想算每样本平方损失，应先得到配对预测，再与同形标签相减。解析应说明哪个轴被收缩，而不是仅答一个函数名。

**练习二：训练与验证坐标。** 训练某列为一二三，验证只有四。训练均值二、尺度根号三分之二，验证变成根号六；若验证自己拟合，单个值方差零，结果可能被回退成零。两者回答完全不同问题。普通评估应沿用训练参数，不能把验证看起来居中当作正确标准。

**练习三：求逆是否必要。** 要求解方程得到一个向量，不需要逆矩阵本身，使用求解器直接表达任务。若矩阵奇异，方程可能无解或多解，需要最小二乘或额外约束，不能仅换一个更宽异常捕获继续返回零。数值工具选择应由数学问题决定。

<a id="sec-7-1"></a>
### 边界追问：向量化是否总比循环更节省内存

不一定。全量广播可能创建巨大中间张量，分块循环则控制峰值；一次矩阵乘法可能更快，但结果仍要占空间。比较时先给出输出需求与预算，再测结果误差、时间和峰值。不能用代码行数或是否出现 for 作为优劣判据。

还要观察结果消费方式。如果下游只取每行最小值，保存完整矩阵是多余工作；如果确实要做全部距离可视化，存储就无法仅靠局部最小状态替代。算法正确性必须保持任务输出，不能为了节省内存悄悄删除用户需要的信息。

<a id="sec-8"></a>
## 8. 完整案例：受控内存的最近中心分配

我们实现双向分块最近中心。输入样本与中心均为二维有限浮点矩阵，特征数相同，至少有一个中心；空样本允许返回空结果。按中心编号从小到大扫描，只有严格更小距离才更新，因此精确并列时保留最小编号。距离使用局部直接差，避免本例首先引入范数展开的相消问题。

设样本块大小与中心块大小固定，临时差张量规模是两块大小乘特征数，而不是全体样本乘全体中心乘特征数。每条样本只保存当前最好距离与编号。算法仍需要计算所有候选比较，时间复杂度没有神奇下降；收益主要是内存可控与无需保存完整结果。若中心巨大，近邻索引等方法可能另有优势。

```python
import numpy as np

def nearest_centers(samples, centers, *, sample_block=2, center_block=2):
    X = np.asarray(samples, dtype=np.float64)
    C = np.asarray(centers, dtype=np.float64)
    if X.ndim != 2 or C.ndim != 2 or X.shape[1] != C.shape[1]:
        raise ValueError("expected two compatible feature matrices")
    if C.shape[0] == 0 or X.shape[1] == 0:
        raise ValueError("centers and features must be nonempty")
    if not np.isfinite(X).all() or not np.isfinite(C).all():
        raise ValueError("expected finite values")
    if any(type(size) is not int or size <= 0 for size in (sample_block, center_block)):
        raise ValueError("block sizes must be positive integers")
    labels = np.full(X.shape[0], -1, dtype=np.intp)
    best = np.full(X.shape[0], np.inf)
    for start in range(0, X.shape[0], sample_block):
        stop = min(start + sample_block, X.shape[0])
        local_best = best[start:stop]
        local_labels = labels[start:stop]
        for first in range(0, C.shape[0], center_block):
            last = min(first + center_block, C.shape[0])
            with np.errstate(over="raise", invalid="raise"):
                difference = X[start:stop, None, :] - C[None, first:last, :]
                distances = np.sum(difference * difference, axis=-1)
            local_index = distances.argmin(axis=1)
            candidate = distances[np.arange(stop - start), local_index]
            improve = candidate < local_best
            local_best[improve] = candidate[improve]
            local_labels[improve] = first + local_index[improve]
    return labels, best

X = np.array([[0.0, 0.0], [2.0, 0.0], [5.0, 1.0], [1.0, 0.0]])
C = np.array([[0.0, 0.0], [2.0, 0.0], [5.0, 0.0]])
labels, squared = nearest_centers(X, C, sample_block=2, center_block=1)
np.testing.assert_array_equal(labels, [0, 1, 2, 0])
np.testing.assert_allclose(squared, [0.0, 0.0, 1.0, 1.0])
reference = ((X[:, None, :] - C[None, :, :]) ** 2).sum(axis=-1)
np.testing.assert_array_equal(labels, reference.argmin(axis=1))
np.testing.assert_allclose(squared, reference.min(axis=1))
empty_labels, empty_distances = nearest_centers(np.empty((0, 2)), C)
assert empty_labels.shape == empty_distances.shape == (0,)
```

最后一条样本在中心零与中心一之间等距，保留编号零。局部 argmin 也取该块首个最小位置，中心块按递增编号扫描，所以跨块与块内并列政策一致。如果更新条件改成小于等于，后遇到的并列中心会覆盖先前结果，虽然距离一样，标签却不同。明确并列政策让分块大小变化时仍能比较身份。

代码使用 best 的基本切片视图，因此局部更新回写全局状态；若这里改成高级整数索引读取，得到副本而未写回，就会丢失更新。这个例子把第一章共享语义用于真实算法。性能优化前应先解释状态对象关系，避免把看似等价索引换掉后破坏结果。

极端有限输入的差或平方可能溢出，示例把相关浮点异常转为明确失败，而不是返回全无穷导致标签仍为负一。若业务范围确实需要更大动态范围，可以考虑缩放或稳定范数算法，但要同时保证不同候选距离可比较。输入有限并不自动保证中间计算有限。

分块大小影响临时空间与内核效率，不应影响温和精确算例的结果。可以扫描多组块大小，核对编号与距离；浮点路径不同的代数实现则可能在非常接近候选上改变排序，需要报告容差与政策。算法验证与性能调优分开，先固定结果规则，再选择预算下的合适块。

<a id="sec-9"></a>
## 9. 最小二乘、数值秩与残差

最小二乘寻找使残差平方和最小的参数。方程精确可解时，最小残差为零；不可解时，得到标签在设计列空间上的投影；参数不唯一时，还需要一个选择准则，常见求解器给最小欧氏范数解。三个问题不能混为“求一个逆”。矩阵形状与数值秩决定解集合，而不是单凭参数比样本多就下结论。

数值秩还受阈值影响。非常小的奇异值在有限精度下可能被视为零，求解器就不沿该方向放大参数。阈值改变相当于改变可用方向，可能显著影响系数与残差。应记录 rcond 与奇异值，不把不同默认行为造成的差异误当成新算法偏好。软件版本变化也可能影响默认选择。

```python
import numpy as np

X = np.array([[1.0, 1.0], [1.0, 2.0], [1.0, 3.0]])
y = np.array([2.0, 3.0, 5.0])
coefficient, residuals, rank, singular_values = np.linalg.lstsq(X, y, rcond=None)
np.testing.assert_allclose(coefficient, [1.0 / 3.0, 1.5])
residual = y - X @ coefficient
np.testing.assert_allclose(X.T @ residual, [0.0, 0.0], atol=1e-13)
np.testing.assert_allclose(residual @ residual, 1.0 / 6.0)
assert rank == 2

underdetermined = np.array([[1.0, 1.0]])
minimum_norm, *_ = np.linalg.lstsq(underdetermined, [1.0], rcond=None)
np.testing.assert_allclose(minimum_norm, [0.5, 0.5])
assert np.linalg.norm([0.5, 0.5]) < np.linalg.norm([1.0, 0.0])
assert singular_values.shape == (2,)
```

第一例系数三分之一与一点五，预测为 $`\frac{11}{6}`$、$`\frac{10}{3}`$ 和 $`\frac{29}{6}`$，残差是 $`\frac{1}{6}`$、$`-\frac{1}{3}`$ 与 $`\frac{1}{6}`$，平方和为六分之一。更直接写成小数也可以，但精确分数有助核对。残差与每列正交是无约束最小二乘的一阶条件，提供独立于求解器内部实现的验证。

<a id="numpy-2-rank-truncation"></a>
### 数值秩截断以后，残差与哪个空间正交

上述正规方程描述原矩阵的无约束最小二乘。若把一个非零奇异方向按阈值截去，返回值求解的是保留方向上的截断问题，不能再不加区分地要求残差与原矩阵的全部列严格正交。设实矩阵的奇异值分解为 $`A=U\Sigma V^\mathsf T`$，保留索引集合为 $`K`$，则截断解和拟合量为

$$
x_K=\sum_{j\in K}\frac{u_j^\mathsf Tb}{\sigma_j}v_j,
\qquad
Ax_K=U_KU_K^\mathsf Tb.
$$

因此 $`U_K^\mathsf T(b-Ax_K)=0`$，但被舍弃的非零方向仍可能使 $`A^\mathsf T(b-Ax_K)\ne0`$。只有全部非零方向都保留时，才回到原问题的完整列空间投影；若舍弃的方向本来就是严格零奇异值，则没有改变原来的列空间。这里还应将数学上的严格等式与浮点实现采用的尺度相关容差分开。

取 $`A=\operatorname{diag}(1,10^{-8})`$ 和 $`b=(1,1)^\mathsf T`$。保留两方向时解为 $`(1,10^8)^\mathsf T`$，残差为零；以 $`\texttt{rcond}=10^{-6}`$ 丢弃第二方向时解为 $`(1,0)^\mathsf T`$，残差为 $`(0,1)^\mathsf T`$，而 $`A^\mathsf Tr=(0,10^{-8})^\mathsf T`$，虽很小却非零。低残差、大参数和截断后的剩余误差分别反映不同取舍，不能只凭“正规方程近似为零”宣称原问题已经精确求解。

```python
import numpy as np

A = np.diag([1.0, 1e-8])
b = np.ones(2)
full, _, rank_full, _ = np.linalg.lstsq(A, b, rcond=1e-10)
cut, reported, rank_cut, _ = np.linalg.lstsq(A, b, rcond=1e-6)
np.testing.assert_allclose(full, [1.0, 1e8])
np.testing.assert_allclose(cut, [1.0, 0.0], atol=1e-14)
residual = b - A @ cut
np.testing.assert_allclose(residual, [0.0, 1.0])
np.testing.assert_allclose(A.T @ residual, [0.0, 1e-8], atol=1e-20)
assert rank_full == 2 and rank_cut == 1
assert reported.size == 0 and residual @ residual == 1.0
```

![保留与截断小奇异方向时的参数和残差对照](images/02-rank-truncation.svg)

图中的原矩阵数学秩为二；“数值秩一”来自明确的求解阈值，并非矩阵凭空少了一列。保留小方向能拟合此例的全部响应，但将该方向的输入误差放大到参数中；截断则用拟合偏差换取较小参数。是否适合实际预测，仍需结合噪声与任务验证。接口对小奇异值及空残差字段的定义见 [NumPy 2.4 最小二乘文档](https://numpy.org/doc/2.4/reference/generated/numpy.linalg.lstsq.html)。

返回的残差数组可能为空，不意味着真实残差一定为零；在某些形状或秩条件下，接口不以该字段返回残差平方和。应根据实际预测显式计算需要的诊断，并核对文档。把空数组当作零误差，是一个容易使评估过于乐观的接口误读。

对于病态系统，还要考虑输入扰动与测试方向。参数某一分量大，不一定意味着训练内预测差；但未来输入若沿该方向变化，误差可能被放大。可以同时报告参数、训练残差与独立预测。正则化通过限制敏感方向引入偏差，是否有利要结合信号与噪声，不能只看残差更小。

## 10. 稳定概率：最大值平移与对数归约

分类模型常从一组实数得分构造概率，指数后除以指数和。直接计算在得分很大时可能溢出，而得分都很负时可能整体下溢。概率只依赖相对差，因此可以先减去每行最大值，让最大指数为一，其余不超过一。这个平移在精确算术下不改变结果，却显著改善普通有限输入的动态范围。

稳定 softmax 应按类别轴归约，并保留长度一轴。若数据是样本乘类别，最大值与分母都按末轴处理；若误按样本归约，就把不同样本混成一组概率。结果可能依然有限，却每行不再表达一个预测分布。首先检查每行非负、总和接近一，再用已知得分差手算，不能只检查数组形状。

对数概率最好直接用得分减去对数归一化常数，而不是先算概率再取对数。极小概率可能在浮点中下溢为零，之后对数变成负无穷；直接对数表达仍可能保持有限值。交叉熵通常只需要真实类别的对数概率，无需先保留一个可能下溢的中间概率再恢复。运算顺序的选择影响数值对象，不只是速度。

对数和指数归约可以写成最大值加上平移后指数和的对数。若使用这一式，得分全为负无穷、包含正无穷或非数值时需要另有政策，因为减最大值可能出现无穷减无穷。本例接受有限二维得分，拒绝空类别轴与非有限输入；若有限得分之差本身超出 float64 范围，也会明确抛出异常。

例如`[1e308, -1e308]`的数学对数概率包含约`-2e308`，最大值平移不能使这个结果突然变得可表示。指数下溢为零在本算法中允许，因为对数概率直接由平移后的得分计算，并未对零概率取对数。稳定算法解决有限范围计算问题，不代表无限输入也自然有唯一概率含义。

```python
import numpy as np

def log_probabilities(scores):
    scores = np.asarray(scores, dtype=np.float64)
    if scores.ndim != 2 or scores.shape[1] == 0:
        raise ValueError("expected a 2D array with a nonempty class axis")
    if not np.isfinite(scores).all():
        raise ValueError("scores must be finite")
    with np.errstate(over="raise", invalid="raise", under="ignore"):
        shifted = scores - scores.max(axis=1, keepdims=True)
        log_normalizer = np.log(np.exp(shifted).sum(axis=1, keepdims=True))
        result = shifted - log_normalizer
    if not np.isfinite(result).all():
        raise FloatingPointError("log probability exceeds float64 range")
    return result

scores = np.array([[1000.0, 1001.0, 999.0], [-1000.0, -1000.0, -1000.0]])
logp = log_probabilities(scores)
probability = np.exp(logp)
np.testing.assert_allclose(probability.sum(axis=1), [1.0, 1.0])
np.testing.assert_allclose(probability[1], [1/3, 1/3, 1/3])
np.testing.assert_allclose(
    log_probabilities(scores + np.array([[500.0], [-200.0]])), logp
)
labels = np.array([1, 0])
loss = -logp[np.arange(2), labels].mean()
expected = (np.log(np.exp(-1) + 1 + np.exp(-2)) + np.log(3)) / 2
np.testing.assert_allclose(loss, expected)
assert log_probabilities(np.empty((0, 3))).shape == (0, 3)
try:
    log_probabilities([[1e308, -1e308]])
except FloatingPointError:
    pass
else:
    raise AssertionError("unrepresentable log probability should fail")
```

第一条得分平移后是负一、零、负二，真实类别为中间位置，负对数概率是平移指数和的对数；第二条三类相同，损失是三的自然对数。每样本共同加常数不改变概率，是一个有数学前提的变形检查。若只改变一个类别得分，结果通常应变化，不应误用同一不变性。

这里还存在极端有限值相减溢出的边界。两个接近浮点最大范围且符号相反的数，差可能超出可表示范围。普通机器学习得分通常远小于这个尺度，但严格接口若声称覆盖所有有限数，仍需检查中间结果或采用更受控策略。不要把常用稳定公式描述成对所有浮点异常的绝对屏障。

标签索引也需要验证。标签应为每样本一个合法整数类别，长度与样本一致；负索引在 NumPy 中有合法末尾含义，但在分类标签里往往应拒绝，否则非法负标签会悄悄变成末尾类别。布尔标签是否允许也要决定，不能因为它能转换成整数就接受。数组接口允许的索引域可能比业务标签域更宽。

类别概率质量与校准是另一问题。每行和为一，只说明形成分布，不证明概率与实际频率匹配。温度缩放、先验偏移或错误类别映射都可能影响解释。数值稳定 softmax 保证的是计算方式与公式对应，统计校准需要独立数据与评估。不要让“稳定”这个词跨越未被证明的层次。

对数损失在概率趋零时无界，本章例子计算有限得分的经验值，不自动提供任何有界损失泛化定理。如果后续理论要求损失范围，需要裁剪或相应尾部分析，并说明改变了什么。数值表达、优化目标与理论假设要一致，不能用一个公式在三个场景里承担不同未声明角色。

## 11. 浮点验证：公式、容差与梯度检查

验证向量化表达式，先确认数学对象，再验证实现，最后研究数值误差。一个错误广播目标可以被准确计算，也可以拥有完全正确的导数，因此数值梯度通过不证明业务目标正确。第一章配对误差反例在这里仍适用：前向手算、形状契约与梯度检查必须互相补充，不能选其中一个代替全部。

温和数据上，可以用慢但透明的显式循环作为参考。参考应按索引公式重新构造，不把同一行数组表达式复制过去。比如矩阵乘法逐输出位置累加，距离逐点逐维求差，损失先列每样本误差。这样的独立性降低共享同一轴错误的概率。较大输入再用性质检查补覆盖，不必全量运行慢参考。

近似比较应先检查形状，再比较数值。某些比较函数会广播，导致不同结构也得到真；常数数据尤其容易掩盖。绝对容差处理接近零的误差，相对容差按结果尺度放宽。容差不是越松越好，应来自预期舍入、条件数与任务需求。若为了通过不断增加容差，可能把错误倍数与漏项都放进来。

求和与矩阵乘法可能使用不同归约顺序，因此参考循环末位差异可以合理。但若差异集中在某个轴或随样本数成比例，优先检查分母、广播与维度。数值误差通常有可分析尺度，不应成为任何不一致的借口。记录 dtype、输入范围与条件数，有助于区分误差机制。

有限差分可以检查光滑标量目标的解析梯度。中心差分在一个参数正负扰动后比较目标变化，步长过大有截断误差，过小有相消与舍入；应在若干合理步长下观察稳定区域。对于绝对值、最大值与分类错误等非光滑目标，在拐点处不能期待普通导数存在，检查策略也要改变。

```python
import numpy as np

X = np.array([[1.0, 2.0], [2.0, -1.0], [0.0, 3.0]])
y = np.array([1.0, -2.0, 2.0])
w = np.array([0.2, -0.3])
regularization = 0.1

def objective(parameters):
    residual = X @ parameters - y
    return 0.5 * np.mean(residual * residual) + 0.5 * regularization * (parameters @ parameters)

gradient = X.T @ (X @ w - y) / len(y) + regularization * w
epsilon = 1e-6
numeric = np.empty_like(w)
for j in range(w.size):
    direction = np.zeros_like(w)
    direction[j] = epsilon
    numeric[j] = (objective(w + direction) - objective(w - direction)) / (2 * epsilon)
np.testing.assert_allclose(gradient, numeric, rtol=1e-7, atol=1e-8)
np.testing.assert_allclose(gradient, [4.0 / 3.0 + 0.02, -14.2 / 3.0 - 0.03])
```

这段目标使用样本平均与二分之一系数，梯度分母与正则项必须对应。若把数据损失改成求和却仍除样本数，检查会发现；若同时在数值目标和解析公式里复制同一错误尺度，检查仍可能通过。因此还应手算一个参数方向的贡献，确认研究定义本身。第四章会完整实现线性回归训练，这里只验证计算部件。

方向导数可以降低高维检查成本。随机取一个单位方向，比较梯度与方向内积和沿该方向的中心差分；它不逐参数覆盖，但适合大型模型局部诊断。需要固定检查随机源，并使用多个方向与合理尺度。某些稀疏错误可能在少量方向中不明显，所以它是补充证据，不是形式化全局证明。

数值警告应有明确政策。开发检查时可以把溢出与无效运算设成异常，尽早找到首个非有限位置；正式缺失处理则需要有意允许某些非数值并通过掩码隔离。不要全局关闭所有警告让日志安静，也不要把预期缺失警告与真正训练发散混为同一类。错误处理要与数据契约一致。

对正规方程、直接分解和迭代法，可以比较训练残差、参数范数与独立预测，而不只比较系数逐位一致。秩亏时多个解都能最小化残差，若选择准则不同，系数差异不必是错误。测试应核对各自承诺，例如最小范数与正交残差，而不是强迫所有算法输出同一个向量。

最后要区分经验数值验证与定理。一次梯度检查、几个条件数案例或三百次随机试验，都能发现实现问题，却不证明对任意输入成立。严格论证依赖假设与推导，实验检验其具体预测与实现。报告清楚证据层次，比把每次成功运行都称为“已验证正确”更有研究价值。

## 12. 随机实验：分流、配对与不确定性

随机实验设计先确定独立单位。数据点独立、训练重复独立、模型扰动独立是不同层次；同一训练集上多次初始化，并不产生多份独立数据集。若把所有预测误差当独立样本，会低估不确定性。数组数量可以很大，真正的信息单位却可能只有少数用户、任务或随机训练重复。

种子序列可以为数据、初始化和抽样派生独立角色的伪随机流。这样增加评估抽样次数不会改变训练初始化，修改数据生成也不直接推进另一个流。角色映射应固定并记录，不能每次按当前遍历顺序临时分配后假设任务身份稳定。并行实验尤其需要把任务编号与子流关联。

```python
import numpy as np

root = np.random.SeedSequence(2026)
data_seed, init_seed = root.spawn(2)
data_rng = np.random.default_rng(data_seed)
init_rng = np.random.default_rng(init_seed)
data = data_rng.normal(size=(3, 2))
initial = init_rng.normal(size=2)

recreated = np.random.SeedSequence(2026).spawn(2)
np.testing.assert_array_equal(
    data, np.random.default_rng(recreated[0]).normal(size=(3, 2))
)
np.testing.assert_array_equal(
    initial, np.random.default_rng(recreated[1]).normal(size=2)
)
data_rng.normal(size=100)
after_data_change = init_rng.normal(size=2)
reference_init = np.random.default_rng(recreated[1])
reference_init.normal(size=2)
np.testing.assert_array_equal(after_data_change, reference_init.normal(size=2))
```

这个测试验证流状态隔离与相同构造的重建，没有证明伪随机数在数学上完美独立，也不承诺任意库版本所有分布变换逐位相同。应该记录生成器选择、种子派生规则、调用结构与版本。保存种子有帮助，但实际失败小输入往往更稳健，尤其当生成代码后来改变。

比较两种方法时，共同随机数有时能降低差值噪声。使用同一份生成数据与同一评估样本，让差异更集中于方法，而不是两次独立抽样的偶然变化。但是否降低方差取决于相关结构，不能无条件保证。对于训练随机性，两个方法也未必有相同参数维数与调用轨迹，简单填同一种子不等于完全对齐随机因素。

重复实验应该预先说明重复次数、停止规则与汇总方式。只运行到出现漂亮结果再停止，会引入选择；只报告最佳种子，则不代表典型表现。可以报告每次结果、均值与变异程度，并使用与独立单位相符的不确定性分析。不要把标准差与均值标准误混用，也不要把训练样本数代入训练重复次数的位置。

数据拆分同样需要专属随机流程和身份。先固定用户或时间边界，再生成样本索引，特征与标签共同使用。若在每次模型比较时重新随机拆分，差异混入数据难度变化；若反复看同一验证结果调整方案，又需要承认验证选择过程。随机流组织不能替代科学实验协议，但能让它更清楚执行。

置信区间与统计检验不是本章的完整主题，但有一个基本原则：计算代码正确不意味着不确定性估计正确。相关样本、重复观测与多次选择都可能破坏简单公式前提。应先说明抽样机制，再选择方法。数组运算使重复试验容易，反而更需要防止把大量相关数字包装成高置信证据。

对于随机性质检查，可以固定一组生成规则并覆盖多种结构，而不是仅取正态小数。空输入、重复点、常数列、秩亏矩阵和极端尺度往往不是普通随机分布常见事件，需要专门构造。随机测试适合补充广度，手算反例负责关键边界，两者组合更可靠。

随机失败发生后，保留具体输入、生成状态和版本。不要只是换种子直到通过；也不要把所有失败都归咎于偶然数值噪声。先判断是否违反接口，是否数值容差不合理，还是实现确实在某个结构上错误。可重复的失败是宝贵证据，应先缩小再修复。

## 13. 性能比较与端到端预算

性能比较先固定任务输出与正确性标准。两个实现如果一个保存完整距离矩阵，另一个只返回最近编号，它们不是同一接口；可以比较满足实际需求的不同方案，但必须说明输出差异。若一个版本省略输入验证或采用更低精度，速度变化也不能全部归功于向量化。先使比较对象公平，再讨论优化。

测量范围应对应用户关心的成本。只测矩阵乘法可以研究核心内核，端到端还包括数据生成、转换、复制、分配与结果消费。二者都合理，却不能混用。首次调用可能初始化线程池或载入路径，后续调用又受缓存影响，因此可以分别记录冷启动和重复运行，不把它们混成一个没有定义的平均时间。

重复计时应使用适合测耗时的单调时钟，固定输入并多次测量，报告中位数与波动范围。不要在每次计时里重新生成随机数据，除非数据生成本来就是比较任务的一部分；也不要只挑最快一次宣布提升。极短操作受计时与解释器开销影响，代表规模更能反映实际，但规模必须在安全内存预算内。

线程控制很重要。一个 NumPy 矩阵乘法可能已使用多个底层线程；外层再开很多进程，每个都开启同样线程数，容易过度竞争，速度反而下降。记录硬件与数值库配置，按应用的总资源预算选择并行层。不能把在独占机器上的多线程结果与另一个单线程表达式简单归因为算子更优。

内存带宽常限制逐元素操作。每个元素只做少量算术，却反复从内存读写，中间数组越多，数据移动成本越大。矩阵乘法则可能重用数据，计算密度更高。理解这种差别有助于解释为什么同样元素数量的两种运算性能不同，也说明把一个乘法拆成很多小切片调用可能损失核心效率。

显式输出缓冲可以减少某些重复分配。先分配独立工作数组，减均值写入，再原地除尺度，可以避免为每一步都保留完整新结果；但必须检查工作类型、形状和共享关系。如果 out 指向输入，就改变调用方数据；如果输入与输出重叠复杂，库可能需要内部临时处理。提供 out 不意味着绝对零额外内存，更不意味着副作用自动安全。

```python
import numpy as np

X = np.array([[1.0, 10.0], [3.0, 14.0]])
mean = np.array([[2.0, 12.0]])
scale = np.array([[1.0, 2.0]])
before = X.copy()
reference = (X - mean) / scale
work = np.empty_like(X)
np.subtract(X, mean, out=work)
np.divide(work, scale, out=work)
np.testing.assert_allclose(work, reference)
np.testing.assert_array_equal(X, before)
assert not np.shares_memory(X, work)
```

这个例子只证明温和输入下的结果与非修改契约，未测峰值也未承诺一定更快。分配复用在大量重复批次中可能有价值，在一次小计算中差异可能不值得复杂化。优化应保留清晰接口，如果为了省一个临时量引入难以解释的别名，维护成本可能超过收益。

矩阵链括号还能改变运算量。三个矩阵形状分别是十乘一千、一千乘五与五乘一千，先算前两个大约需要五万次乘加，再与第三个相乘约五万；先算后两个会得到一千乘一千中间矩阵，后续成本大得多。数学结合律允许不同顺序，浮点结果可能有末位差异，内存与时间却能差几个数量级。

这种优化需要同时考虑中间形状。某个括号运算次数少，却可能生成大中间对象；某个布局有利矩阵核心，却需要一次复制。可以使用专门矩阵链工具或明确选择顺序，但仍要检查数值容差。优化器不是业务语义验证器，输入轴错误时，它只会更高效地计算错误表达。

估算内存时，数组的 nbytes 只反映它逻辑元素占用，不自动给出整个进程峰值。共享视图重复计数可能高估独占存储，底层工作区、临时对象与外部库又可能使实际使用更大。可以结合形状估算与适合平台的内存测量，但应说明工具观察层次，不把一个 Python 追踪器数字当作全部原生分配。

批次边界也影响汇总解释。每批单独求平均再直接平均，会让最后一个较短批次获得和完整批次相同权重；若目标是样本等权，应累计损失总和与样本数，最后统一相除。分块本来是资源策略，不应无声改变统计口径。功能对照应包含不足一批的结尾，而不只使用恰好整除的输入。

性能回归验证也要有容忍。机器负载、缓存与线程调度会造成波动，普通功能测试不宜要求极小固定时限。可以设宽松异常退化门槛，另行维护受控基准。对学习项目，记录规模、dtype、布局、线程与时间，比只写“提高十倍”更可复查。

最终优化决策应回到目标。若程序大部分时间读文件，微调一个小矩阵表达式可能无明显收益；若内存峰值导致无法运行，分块比局部速度更关键；若结果数值不稳定，略慢的直接算法可能更合适。正确性、可解释性、数值误差、内存与时间共同构成工程取舍，不能只优化单一分数。

## 14. 综合研究练习与参考资料

**任务一：建立向量化参考。** 对一个线性预测函数，写出逐样本逐特征循环与矩阵表达式，用非方形、不对称、含负值数据核对。再扩展多输出，明确哪个轴收缩，偏置在哪些方向共享。解析中应给出一个输出位置的公式，而不只是两个数组比较相等。若两个实现共享同一误用转置，比较通过仍不构成独立判据。

接着构造逐元素乘法直接平均的错误版本，手算它与正确预测的差别。用常量数据时错误可能碰巧不明显，因此检查样本应有不同特征幅度。将这个最小反例保留，再用随机数据补广度。这样既理解公式，也知道测试为什么能发现特定错误。

**任务二：标准化政策比较。** 对含普通、常数和近常数列的训练矩阵，比较单位回退、删除常数列和设置最小尺度。验证集包含常数列新变化，解释各策略如何处理。解析必须说明输出维度、坐标与分布变化含义，不能只比较有没有除零警告。若删除列，特征模式与模型参数也要同步。

再比较总体与样本标准差分母。训练只有两条时，二者尺度差异明显；单样本时样本方差未定义，需要政策。这个练习不是要选出普遍最好分母，而是理解默认参数怎样改变坐标，并确保训练和预测使用同一拟合对象。统计估计目标与优化缩放目标可以不同。

**任务三：距离的三种实现。** 在温和规模比较直接广播、范数展开和双向分块最近中心，核对结果、临时空间与时间。对重复中心规定并列编号，扫描不同块大小。再把所有点整体加一个很大公共偏移，观察范数展开的相消风险。直接差理论上平移不变，但机器输入表示仍可能丢失细节，需要适当尺度选择。

报告不要只给最快结果。列出最终输出需求、完整矩阵是否保存、dtype、最大误差、最近编号差异与估算峰值。若只需要最近中心，全矩阵算法不是必须基线；若要保留所有距离，分块只能控制临时量，仍需存储输出。把需求与实现分开，结论才能被复用。

**任务四：残差小是否代表解准？** 取对角矩阵第一项一、第二项为一亿分之一，真实参数都是一，对应右端第二项也是一亿分之一。若右端第二项再增加一亿分之一，解第二分量变成二，参数误差达到一，而相对原方程的残差仍只有一亿分之一。解析用这个例子区分小残差与小前向误差，并解释条件数为什么重要。

再加入秩亏设计，比较最小二乘最小范数与另一个同样残差的参数，观察训练预测相同而未见方向预测不同。不要强迫所有解逐位一致，应核对各自选择准则。线性代数主题会系统推导投影与分解，这里重点是正确调用、记录数值秩并解释诊断。

**任务五：稳定对数概率。** 对同一行得分共同加大常数，检查稳定概率与损失保持；对一个类别单独改变，结果应变化；对极小概率类别，比较先概率再对数与直接对数表达。解析应说明轴、有限输入前提与标签域，尤其负类别索引不能因数组允许就被业务接受。

进一步研究损失裁剪。如果为了有界范围把对数损失截断，它与原目标不同，梯度与评估含义也可能改变。数值防护、统计假设与优化目标应分别说明。不要因为某条理论要求损失有界，就在报告中隐去裁剪事实；也不要把数值稳定平移误称为改变模型概率定义。

**任务六：梯度与前向双重检查。** 为平均平方损失加正则写解析梯度，使用中心差分与方向导数验证。然后故意把标签广播成两两样本差，观察对这个错误目标的梯度仍可能通过。解析说明为什么前向手算与梯度检查都必需，以及均值归约、二分之一系数与正则尺度怎样进入导数。

选择若干步长，观察误差随步长的合理变化，不要求越小越准。对于非光滑函数，另选不在拐点的输入或使用适合的判据。梯度检查是一项数值实验，它的输入范围、容差与目标都需要记录，不能只保存一句通过。

**任务七：随机流隔离。** 给数据、初始化与评估分配子流，增加评估抽样次数，要求数据与初始化不变；重建同一根种子与角色映射，要求同一调用重现。再构造所有组件共享一个流的版本，解释为什么插入调试抽样会改变后续结果。此处比较的是状态依赖，不是伪随机分布质量。

设计两方法配对实验，固定共同数据但保留各自训练随机性，报告差值分布与多次重复。若方法参数维数不同，同一整数种子并不代表完全相同随机轨迹，应说明可对齐与不能对齐的因素。科学比较需要明确控制，而不只是给两个脚本写同一个 seed。

**研究延伸：精度与资源的共同预算。** 固定一个实际任务误差要求，比较单精度输入、双精度累计与全双精度计算的时间、内存和结果。分析哪些误差来自输入表示、哪些来自归约、哪些来自病态。不要仅比较小数位数量，也不要假设低精度一定不可用。以可接受任务误差为约束，再寻找资源方案，更接近真实数值工程。

另一条延伸是审查复现实验的证据链。保存有效配置、数据身份、随机流角色、库版本与关键数值诊断；区分代码编译、局部例子执行、完整流程和统计评估。一次小规模运行提供的保证有限，但只要范围清楚，就能成为后续研究可靠起点，而不是被夸大成任意规模的全部证明。

本章掌握标准是能把公式转成正确批量表达，选择合适求解器，估计中间内存，识别相消与条件数风险，管理独立角色随机流，并用手算、参考计算与性质共同验证。下一章进一步追踪高级索引、批量轴与内存布局，解释同样数学表达为何可能有不同共享与性能行为。
