## 1. 花式索引表达重排

整数数组索引可以选择任意位置、重复位置和重排位置。它描述的是从源数组读取一组坐标，而不是在原地调整源数组顺序。读出的高级索引结果拥有选出数据的独立数值缓冲，因此修改这个结果通常不回写源数组。它与普通连续切片的视图语义不同，即使选中的数值完全一样。

样本洗牌可以先生成一个排列索引，再用同一索引读取特征、标签与编号。分别对特征与标签生成排列，长度与形状仍然正确，监督关系却被破坏。可复现种子并不能修复这种逻辑错误；两个独立调用也不应被期待恰好相同。配对数据的共同索引属于实验契约，而不是性能细节。

重复选择也有统计含义。从样本列表读取同一编号两次，生成两条逻辑记录，但没有产生新的独立观测。用于自助重采样时，这是有意的重复权重；用于训练去重时，则可能是错误。数组允许重复，不知道它应代表抽样、拷贝还是数据污染。报告样本量时要区分逻辑条数与独立单位。

整数索引数组应使用合适整数类型，原生索引类型适合表示位置。负值按末尾解释，越界会失败；浮点值即使显示为整数也不能直接作为普通整数索引。业务编号不是位置索引，不能把用户编号直接用于数组读取，除非已经建立明确映射并验证范围。否则合法大编号可能越界，或小编号碰巧读到错误样本。

布尔索引表达成员筛选，整数索引表达坐标列表，两者不应混淆。一个只含零一的整数数组选择的是第零和第一位置，可重复，并不是真假掩码；需要布尔时明确类型并验证形状。反过来，把布尔数组强制转换成整数后再索引，可能把原本按条件筛选改成大量重复读取前两个元素。

<a id="sec-1-1"></a>
### 基础算例：重复索引与普通切片的状态变化

取四个数十、二十、三十、四十。普通切片中间两项与原数组共享，修改首项会影响原第二项；整数列表选择同样两项得到副本，修改不回写。加入重复下标后，读取可以重复同一数值，但后续增量赋值不自动等同于逐次循环累计。读、算、写要分别解释。

```python
import numpy as np

source = np.array([10, 20, 30, 40])
view = source[1:3]
selected = source[[1, 2]]
assert np.shares_memory(source, view)
assert not np.shares_memory(source, selected)
view[0] = 25
selected[1] = -1
np.testing.assert_array_equal(source, [10, 25, 30, 40])
repeated = source[[0, 0, 3]]
np.testing.assert_array_equal(repeated, [10, 10, 40])
assert not np.shares_memory(source, repeated)
```

这个实验应在每次测试前重新构造输入，避免前一次修改影响后一次结论。检查共享关系与实际修改结果提供互补证据：前者观察存储关联，后者验证具体写路径。只看打印值相同无法判断身份，也不能从一次未观察到变化推断没有共享，因为你也许改了不重叠位置。

<a id="deep-dive-1"></a>
### 深入讲解：配对选择与笛卡尔选择有何差别

二维矩阵用两个同形整数数组索引时，通常按位置配对。行数组零二与列数组一三，选的是坐标零一和二三两个值，而不是两行两列的四个交叉。若希望笛卡尔子矩阵，应把行索引增加列单轴、列索引增加行单轴，让它们广播为二维坐标网格，或使用专门工具表达。

两种选择都合理。分类损失读取每样本真实类别概率，需要样本与类别配对；取指定用户与指定特征子表，需要行列交叉。错误操作可能输出一个小数组且没有异常，所以先列出期望坐标对非常有效。不要把“两个索引数组”理解为“独立选两组轴位置”，它们还会互相广播。

索引广播与数据算术广播使用相似形状思想，但对象不同。这里广播的是坐标数组，最终再按这些坐标从源数据取值；不是先把源数据广播成结果形状。理解这一点能解释为什么行索引形状二乘一与列索引形状一乘三产生二乘三选取，同时也能计算实际输出规模。

<a id="visual-03-concept"></a>

### 图解：重复索引需要散射累加

![重复索引需要散射累加](images/03-concept.svg)

固定 a=[0,0,0]，两条记录的索引都是 1，每条贡献均为 2。上行的高级索引增量先读出两个临时零值，再把临时值都加成 2，最后写回同一个源位置，因此 a[1] 为 2。下行使用 np.add.at(a,[1,1],2)，两次贡献分别进入原存储，a[1] 经历 0→2→4。这两项操作必须从各自独立的初始数组开始比较。

这里故意令两条贡献相同，避免把重复目标的普通赋值先后次序当作可靠累加协议。若原任务中的贡献是 2 与 3，正确散射累加应得到 5；不应依赖缓冲写回碰巧保留哪一次值。NumPy 官方给出了重复索引下的缓冲与不缓冲区别，参见 [ufunc.at 文档](https://numpy.org/doc/stable/reference/generated/numpy.ufunc.at.html)。

在嵌入表或共享参数的反向传播中，各记录分别产生贡献，归约阶段应把它们汇入同一参数位置；是否复制读取结果是另一回事。add.at 说明的是同一调用的累积语义，不是任意多线程原子更新或通用性能最优的保证；也可先按编号归约再写回。

<a id="sec-2"></a>
## 2. 批量矩阵运算

矩阵乘法的末两轴分别表示行、收缩维与列，前导轴表示矩阵批次。左边批量乘行乘共同维，右边批量乘共同维乘列，结果是批量乘行乘列。收缩维必须相等，前导批轴按广播兼容。它不是把所有前导轴一起点积，也不是自动求不同批次之间的所有组合。

右边只有一份二维权重时，所有批次共享同一线性变换；右边有同样批量轴时，每批使用自己权重。两者输出形状可能一样，但参数共享含义不同。若权重本来应该共享，却无意为每样本独立生成矩阵，就改变模型自由度；若应独立却被广播共享，也会漏掉差异。

```python
import numpy as np

A = np.arange(24.0).reshape(2, 3, 4)
W = np.arange(20.0).reshape(4, 5) / 10
shared = A @ W
assert shared.shape == (2, 3, 5)
for batch in range(2):
    np.testing.assert_allclose(shared[batch], A[batch] @ W)

per_batch = np.stack([W, 2 * W])
individual = A @ per_batch
np.testing.assert_allclose(individual[0], shared[0])
np.testing.assert_allclose(individual[1], 2 * shared[1])
```

这个参考逐批调用二维乘法，容易验证批次是否被错误交叉。一般广播可以让多个前导批轴形成组合，但必须显式设计长度一位置。比如一组任务与一组专家矩阵，需要任务乘专家的全组合，就应分别增加相应单轴，不能期待普通批乘自动理解“所有配对”。

<a id="sec-2-1"></a>
### 机制展开：matmul 的前导轴代表批量广播

两个批轴长度都为二，默认按同位置配对，不产生四种组合；一方长度一则共享。若双方批轴分别二与三且没有额外单轴，通常不兼容。这个规则与高级索引中配对和交叉的区别相似：同形表示对应，增加互补单轴才表达笛卡尔组合。先写输出任务索引，再决定结构。

高维 dot 与 matmul 的轴规则不同，不能因为二维时一致就随意替换。某些 dot 会保留来自两边的多个非收缩轴，产生意外交叉批次与更大结果。代码若从二维扩展到批量，应重新核对接口，而不是只改输入 reshape 后沿用原调用。第三节之后的例子会继续用显式参考防止这种升级错误。

<a id="visual-03-mechanism"></a>

### 图解：批量矩阵乘法：先广播批轴，再收缩内轴

![批量矩阵乘法：先广播批轴，再收缩内轴](images/03-mechanism.svg)

图把形状规则落到两个可手算的批次。$`A`$ 的形状为 $`(2,2,2)`$，两批分别为 $`\begin{bmatrix}1&2\\3&4\end{bmatrix}`$ 和 $`\begin{bmatrix}5&6\\7&8\end{bmatrix}`$；$`B`$ 的形状为 $`(1,2,2)`$，唯一一批为 $`\begin{bmatrix}2&0\\1&3\end{bmatrix}`$。批轴的长度一使同一张 $`B`$ 参与两个批次，而每次真正相乘的仍是两张二阶矩阵。

逐位置规则是 $`C_{b,i,j}=\sum_{k=0}^{1}A_{b,i,k}B_{0,k,j}`$。高亮处取第一批的第一行和 $`B`$ 的第二列，得到 $`1\cdot0+2\cdot3=6`$。其余位置同样收缩 $`k`$，得到两批结果 $`\begin{bmatrix}4&6\\10&12\end{bmatrix}`$ 与 $`\begin{bmatrix}16&18\\22&24\end{bmatrix}`$，输出形状为 $`(2,2,2)`$。图中的跨批箭头只表达逻辑复用，不表示必须把底层存储复制两遍。

这个例子特意让 `A * B` 与 `A @ B` 的结果形状相同：前者第一批却是 $`\begin{bmatrix}2&0\\3&12\end{bmatrix}`$，没有内轴求和。形状检查能够发现一部分错误，却不能发现这个合法但语义错误的替换；至少还要手算一个不对称位置。全部单位矩阵或全一输入可能掩盖这种区别。

一般规则中，末两轴承担矩阵行列角色，前导批轴按广播规则对齐，内收缩维必须相等；批轴可广播不能修复内维不匹配。具体规则及 `dot` 的高维差异见 [NumPy 2.4 matmul 官方说明](https://numpy.org/doc/2.4/reference/generated/numpy.matmul.html)。当 `B` 也有多批时，还需确认目标是同批配对，还是有意新增轴求所有批次组合，不能仅凭“程序没有报错”判断批身份正确。

## 3. 连续性与复制成本

数组逻辑顺序由形状与索引定义，物理地址由起点、步幅和元素大小共同决定。连续数组通常可以沿某种顺序不跳空洞读取，转置或间隔切片则可能成为非连续视图。非连续不代表错误，也不代表不能计算；它描述访问模式，可能影响底层内核如何读取或是否先复制整理。

步幅以字节计量。一个双精度三行四列的 C 顺序矩阵，沿末轴移动通常跨一个元素字节数，沿首轴移动跨一整行。转置交换轴时，也交换相应步幅，所以无需立即挪动数值。间隔取列会增加末轴步幅，翻转则可能产生负步幅。写出地址映射有助于理解这些变化。

复制会建立新的数值缓冲，增加内存与时间，但也可能改善后续重复访问。一个小视图还可能保持巨大父数组存活，导致你以为只保留几项，实际整块内存仍未释放。此时复制小片段反而能降低长期占用。不能把“零复制”无条件视为最优，它要结合生命周期与后续使用。

连续标记应通过接口检查，不凭打印外观判断。某些长度一轴让同一数组同时满足多种连续性条件，空数组还有特殊情况，因此不能只看某个步幅数字推断唯一布局。更不能根据 .base 恰好指向哪个对象，就把它当作所有共享关系的完整证明；对象可能引用中间祖先，而共享检查更直接。

<a id="sec-4"></a>
## 4. 理解批轴与矩阵轴的计算

批量矩阵乘向量有一个常见陷阱。矩阵形状是批量乘行乘特征，向量若形状批量乘特征，右侧会被当成二维矩阵，而不是自动识别为一批向量。应增加末尾单轴，把它变成批量乘特征乘一，乘完再删除已知结果列轴。若批量数碰巧等于某个矩阵维度，错误表达甚至可能合法，输出却不同。

转置批量矩阵时也应只交换末两轴。对三维数组直接 .T 会反转全部轴，把批轴移动；对复数还要判断是否需要共轭转置。普通转置、矩阵轴交换和 Hermitian 转置是不同对象。实数二维例子里它们容易混在一起，升级到批量或复数时必须拆开。

```python
import numpy as np

A = np.arange(24.0).reshape(2, 3, 4)
v = np.array([[1.0, 0.0, -1.0, 2.0], [2.0, 1.0, 0.0, -1.0]])
result = (A @ v[..., None])[..., 0]
assert result.shape == (2, 3)
reference = np.stack([A[batch] @ v[batch] for batch in range(2)])
np.testing.assert_allclose(result, reference)
assert A.swapaxes(-1, -2).shape == (2, 4, 3)
assert A.T.shape == (4, 3, 2)
```

显式增减轴的优势是保留批量一与行数一时的结构。无条件 squeeze 可能把两个轴都删掉，后续返回类型随批量变化。若接口规定结果始终批量乘行，就只删除最后那个已知长度一轴。形状稳定让调用者无需为每种偶然尺寸写特殊分支。

批量共享也影响梯度与统计。一个权重矩阵跨所有批次共享，相关更新应汇总这些贡献；每批独立矩阵则保留批次差异。虽然本章不实现自动求导，但前向结构已决定依赖关系。不要因为广播没有复制输入，就以为参数只影响一个输出位置。

<a id="sec-5"></a>
## 5. 进阶：高级索引的重复写入反例

普通增量赋值看起来像逐项增加，但高级索引可能先把选中数据读到临时结果，执行运算，再写回源位置。重复下标在读取时得到相同原值，写回时并不表示按出现次数顺序累计。因此重复零号位置两次，不保证像循环那样加两次。需要明确逐次累积时，应使用相应散射归约接口或先聚合贡献。

直接覆盖还存在冲突。多个不同值写入同一位置时，不应依赖未经约定的最终覆盖顺序。若需求是最后事件生效，应先按确定顺序与身份合并，再写唯一目标；若需求是求和，应采用累积；若是最大值，则使用对应归约。符号相似不能代替冲突政策。

```python
import numpy as np

index = np.array([0, 0, 1])
buffered = np.zeros(3, dtype=np.int64)
buffered[index] += 1
np.testing.assert_array_equal(buffered, [1, 1, 0])

accumulated = np.zeros(3, dtype=np.int64)
np.add.at(accumulated, index, 1)
np.testing.assert_array_equal(accumulated, [2, 1, 0])

weighted = np.zeros(3, dtype=np.int64)
np.add.at(weighted, index, [5, 7, 11])
np.testing.assert_array_equal(weighted, [12, 11, 0])
```

这个例子只涉及单线程确定操作，不应把 add.at 理解为跨线程或跨进程的通用原子更新机制。它保证相应索引重复时的无缓冲逐项效果，不替你管理并发共享状态。若多个工作者同时写同一数组，仍需要合适同步或独立局部聚合再合并。

<a id="sec-5-1"></a>
### 视图、复制与重复索引的三个反例

第一个反例是切片共享：外层名字不同，底层数值仍相同。第二个是高级读取复制：选中相同位置，修改结果却不回写。第三个是高级赋值：直接以原数组为目标可以写入，但重复增量仍不等于逐次循环。三者分别涉及身份、读取与写回，不能用一句“索引总是视图”或“索引总是复制”概括。

链式赋值尤其容易混合这些机制。先高级选择得到副本，再切片赋值，只改副本；先基本切片得到视图，再对视图高级赋值，可以回写源数组。即使最终括号形式很像，操作对象已经不同。可以先拆成中间变量，画出共享关系，再判断写入落在哪里，避免凭直觉解释复杂一行。

<a id="sec-6"></a>
## 6. 分层练习与参考解析

**练习一：共同洗牌。** 先生成一组样本排列，再同时选择特征、标签与编号。解析应说明为什么两次独立排列不可靠，为什么同样形状不证明配对。加入编号检查能使错位更容易发现，但编号本身也应来自同一原始记录，而不是事后重新生成位置。

**练习二：配对与交叉。** 行索引零二，列索引一三，配对得到两个坐标，交叉得到四个。分别写出索引结构与手算值。若只有一行或一列，结果可能碰巧一致，因此验证应至少两个不同位置，避免退化样例掩盖区别。

**练习三：批量向量乘法。** 矩阵两批、每批三行四列，向量每批四维。先增加结果列轴，再批量乘法，最后删除该列。解析要给每个批次二维参考，而不是只检查输出维度。再把批量设成一，确认接口仍返回一乘三而非长度三。

<a id="sec-6-1"></a>
### 边界追问：重复索引增加是否等于逐项增加

不等于。高级读取与写回的批量语义可能让重复位置只增加一次；需要每次贡献都累计，使用明确的散射归约。即使值都相同，这一区别仍存在；不同贡献时更明显。先说明冲突目标是求和、最大、首条还是末条，才能选择实现。

对浮点贡献，逐次累积的顺序也可能影响最后几位。改成先排序分组再归约，数学总和一致，数值路径不同。应按任务容差比较，但计数和索引身份仍严格核对。不能把语义漏加一项解释成普通舍入，也不能要求所有合法归约逐位相同。

<a id="sec-7"></a>
## 7. 高级索引的广播形状与轴位置

多个整数索引数组先彼此广播，形成共同索引形状，再与未被高级索引消除的基本切片轴组合。若高级索引相邻，广播后的索引轴通常插入原高级索引所在位置；若它们被切片、新轴或省略号隔开，广播索引轴会移动到结果前面。这是高维索引最容易让人意外的部分，不能只数元素猜结果。

整数标量在混合高级索引中还有一个细节：虽然它独自出现时属于基本索引并消去一个轴，但已经存在整数数组索引时，判断索引组是否相邻也要把整数标量算进去。它不像切片、新轴或省略号那样成为分隔符。于是不能仅寻找两个数组对象，再凭它们之间的距离预测轴位置。下面比较同一次索引与先固定首轴再索引，两者选到同一组值，但轴顺序不同。

```python
import numpy as np

A = np.arange(6 * 3 * 4 * 5).reshape(6, 3, 4, 5)
selected = np.array([1, 3])
combined = A[0, :, selected]
staged = A[0][:, selected]
assert combined.shape == (2, 3, 5)
assert staged.shape == (3, 2, 5)
np.testing.assert_array_equal(combined, staged.swapaxes(0, 1))
for j in range(2):
    for i in range(3):
        np.testing.assert_array_equal(combined[j, i], A[0, i, selected[j]])
```

同一次索引中，整数零与整数数组之间隔着完整切片，因此索引广播轴移至前面；分步骤时，第一步已经取得三维子数组，第二步中只剩一个整数数组，索引轴位于原第二轴。这里不是把两次索引与一次索引任意互换，而是明确比较两套坐标规则。记不住时先写输出坐标对应关系，再用非等长轴运行核对，比依赖输出打印外观更可靠。

先看二维配对。行索引长度二、列索引长度二，共同形状长度二，读取两个配对值。把行变成二乘一、列变成一乘三，共同形状二乘三，读取所有交叉。源矩阵的行列在这里被坐标选择消去，输出轴来自索引数组的广播结构。理解“输出轴属于谁”能解释许多看似不规则结果。

三维混合时，保留的切片轴还会加入。对三乘四乘五数组，第一和第三轴用长度二的整数数组，中间轴完整保留，结果为二乘四；高级索引广播轴在前，四是原中间切片轴。若第一轴完整保留，后两个相邻高级索引选配对，结果则是三乘二。二的位置变化不是转置发生在内存里，而是索引结果结构的约定。

```python
import numpy as np

A = np.arange(3 * 4 * 5).reshape(3, 4, 5)
rows = np.array([0, 2])
last = np.array([1, 3])
separated = A[rows, :, last]
assert separated.shape == (2, 4)
for pair in range(2):
    np.testing.assert_array_equal(separated[pair], A[rows[pair], :, last[pair]])

adjacent = A[:, [0, 2], [1, 3]]
assert adjacent.shape == (3, 2)
for first in range(3):
    np.testing.assert_array_equal(adjacent[first], [A[first, 0, 1], A[first, 2, 3]])

matrix = np.arange(20).reshape(4, 5)
cartesian = matrix[np.ix_([0, 2], [1, 3, 4])]
np.testing.assert_array_equal(cartesian, [[1, 3, 4], [11, 13, 14]])
paired = matrix[[0, 2], [1, 3]]
np.testing.assert_array_equal(paired, [1, 13])
```

这种规则值得用小数组理解，但不意味着正式代码应尽量写复杂混合索引。可以分步骤使用明确轴选择工具，或先移动目标轴再读取，减少读者记忆负担。步骤更多可能产生中间副本，需要在正确性清楚后比较成本。代码最短不是唯一目标，尤其当轴长度变化时复杂表达很难审查。

布尔索引可以理解为选择真位置，但其维数与所覆盖轴必须匹配。一个二维掩码可以消耗源数组相应两个轴，选出真位置后剩余轴继续保留；多个布尔索引组合还会转化为坐标配对，不是任意独立筛选。若想按独立行掩码和列掩码取子矩阵，明确构造交叉索引更容易解释。

一个特殊风险是高级索引结果的存储顺序不应作为稳定契约假定。虽然它是数据副本，输出不一定按你期待的连续布局排列。若下游明确需要连续缓冲，可以在边界转换；若只是继续普通 NumPy 运算，不必立刻复制。复制与连续是两个性质，前者说明独立存储，后者说明布局。

索引数组本身也占内存。为每个高维输出位置物化完整坐标网格，可能和结果一样巨大；互补单轴的索引可以通过广播表达交叉，减少坐标存储。某些任务只需沿一个轴选择，使用 take 或 take_along_axis 可能避免难读坐标网格。算法选择先看所需映射，不是所有任务都要建立 meshgrid。

还要注意索引越界与数据长度变化。如果过滤后数组缩短，旧位置索引不再对应同一记录；如果合并批次后沿用局部下标，也可能读取错误全局位置。索引应与其来源数组版本一起使用。保存样本身份能帮助追踪，但不能自动修复陈旧位置。明确局部与全局坐标系，是大型数据处理的基本要求。

<a id="sec-8"></a>
## 8. 沿轴选择：排序、类别读取与配对保持

take 表达沿某个轴使用同一索引集合，take_along_axis 表达每个其他轴位置拥有自己的目标索引。两者服务不同映射。每行取相同两列，可以用统一列索引；每行取自己的最大两项，则每行排序结果不同，需要沿轴读取。盲目把二维索引直接放进一个括号，可能额外增加轴或交叉样本。

分类概率读取是配对选择：每条样本有一个类别编号，输出每样本一个概率。可以用行索引与标签配对，也可以把标签保留为单列后沿类别轴选择。两种写法都应验证标签长度、整数类型与合法非负范围。数组允许负索引，但业务标签往往不允许，这个域差异不能忽略。

排序只返回位置时，原数值尚未重排。要同时重排关联数组，应使用同一排序索引，并明确它针对哪个轴。如果每行各自排序，不能把它当作共同样本顺序拿去重排标签；如果按某个样本指标排序，则整条样本的所有字段都应同步。排序位置的语义比 dtype 是整数更重要。

```python
import numpy as np

scores = np.array([[4.0, 1.0, 7.0], [2.0, 9.0, 3.0]])
order = np.argsort(-scores, axis=1, kind="stable")
top_index = order[:, :2]
top_value = np.take_along_axis(scores, top_index, axis=1)
np.testing.assert_array_equal(top_index, [[2, 0], [1, 2]])
np.testing.assert_allclose(top_value, [[7.0, 4.0], [9.0, 3.0]])

labels = np.array([0, 2], dtype=np.intp)
selected = np.take_along_axis(scores, labels[:, None], axis=1)[:, 0]
np.testing.assert_allclose(selected, [4.0, 3.0])
np.testing.assert_allclose(selected, scores[np.arange(2), labels])
```

本例用稳定排序，分数相同时保留原列顺序，因此可以建立确定并列政策。若使用部分选择，得到的候选集合不一定内部有序，并列边界也需要额外规则。不能把“取前 k 个位置”的代码当成默认已按分数从大到小排好。接口若返回排名，应显式完成与验证排名。

对大类别数，完整排序成本可能超过只取少量候选。部分选择可以减少工作，但输出需求必须明确：只要集合、需要有序列表、还是需要最小编号优先的确定并列。不同需求影响后处理成本。优化时不能为了速度悄悄改变边界并列结果，尤其当排名用于评估或外部展示。

布尔筛选会改变长度，不同样本每行真值数量可能不同，通常不能自然保留固定二维形状。高级布尔读取可能展平成一个长列表，丢失每行分界。若需要变长结果，可以保存每行数量或列表结构；若模型需要固定长度，可以采用填充与掩码。不要强行 reshape 回原行数，除非已经证明每行选择数量相同。

沿轴读取的返回值通常是新数组，后续修改不意味着把分数表对应位置更新。若要写回，需使用明确赋值接口并处理重复位置冲突。读取和散射更新是两个方向；同一索引映射在逆方向可能变成多对一，不能假设天然可逆。这个区别会在分组统计和梯度累加中再次出现。

## 9. 显式收缩：einsum 与批量参考计算

显式下标表达可以让你直接写哪些轴保留、哪些轴求和。对于批量矩阵乘法，批次标记在两边与输出中共同出现，收缩特征标记只在输入出现，行列标记保留到输出。这样的表达与数学索引接近，适合复杂批次与多种归约，但同样需要清楚命名轴，不能把字母当作不需要解释的魔法。

同一字母在不同输入中通常表示对齐的轴，省略输出的字母表示求和；单个输入中重复字母可以表示对角选择。省略号用于表示若干前导轴并支持相应广播。是否采用隐式输出会影响轴顺序，因此教学与公共代码中显式写输出更容易审查。不要依赖字母排序规则推断重要接口。

```python
import numpy as np

A = np.arange(24.0).reshape(2, 3, 4)
B = np.arange(40.0).reshape(2, 4, 5) / 10
product = np.einsum("bik,bkj->bij", A, B)
np.testing.assert_allclose(product, A @ B)

x = np.arange(12.0).reshape(3, 4)
y = x + 1
row_inner = np.einsum("ij,ij->i", x, y)
np.testing.assert_allclose(row_inner, (x * y).sum(axis=1))

square = np.arange(18.0).reshape(2, 3, 3)
trace = np.einsum("bii->b", square)
np.testing.assert_allclose(trace, [12.0, 39.0])
```

批次求和与批次保留是不同表达。若把输出中的批次标记省掉，就会把所有批次结果相加；若两边使用不同批次字母并都保留，则可能形成所有批次交叉。形状错误不一定报异常，尤其各轴长度相同时更危险。先给出一个输出坐标的显式求和，再翻译下标字符串，能减少这类误用。

这种表达也不自动保证最快。库可能根据收缩路径选择不同中间结果，启用优化选项后可能调用不同核心；一个简单矩阵乘法用 @ 往往更熟悉。多输入收缩路径影响运算量与内存，最好查看实际路径并测代表规模。符号更一般不意味着所有具体任务都该改写。

还要区分代数等价与中间舍入。不同收缩顺序会改变浮点累计与临时类型，末位差异可能合理；条件差或相消严重时差异可能更大。测试应控制 dtype 并按任务容差核对，不能只因一种表达更短就忽略数值诊断。对于复数，下标表达不会自动按你的物理内积约定添加共轭。

一个常见用途是每样本加权平方范数。先确认权重是每特征、每样本还是完整位置，再决定对应字母。若每样本权重只应缩放最终损失，却误放到特征收缩中重复作用，结果可能多一个维度因子。显式下标能暴露这种结构，但前提是作者认真赋予字母含义，而不是从能运行的表达中反推需求。

多头注意力可以把这些概念连起来：批量、头、查询位置、键位置与特征收缩分别有独立轴。查询与键收缩得到位置对位置得分，归约 softmax 应在键轴；值聚合又沿键位置求和。这里不展开模型理论，但足以说明数组语义为何是后续复杂网络的基础。任何轴误用都可能得到合法张量却计算另一机制。

<a id="sec-10"></a>
## 10. 步幅、顺序与重塑的复制边界

一个普通数组位置的字节地址，可以概念上写成起始地址加每个索引乘相应步幅再求和。这个仿射映射解释了切片、转置、翻转和广播：切片改变起点与步幅，转置排列轴与步幅，翻转可能使用负步幅，广播共享轴可以具有零步幅。它不是说所有数组对象都必须占一块全新连续数据。

C 顺序通常让末轴变化最快，Fortran 顺序通常让首轴变化最快；这描述逻辑遍历与连续条件，不赋予轴业务含义。一个特征矩阵可以按不同存储顺序保存相同位置值，数学任务不变，但不同操作访问成本可能不同。不要把 C 顺序误读成“最后轴永远是特征”，那仍由接口约定。

```python
import numpy as np

A = np.arange(12, dtype=np.int64).reshape(3, 4)
assert A.strides == (4 * A.itemsize, A.itemsize)
T = A.T
assert T.strides == (A.itemsize, 4 * A.itemsize)
assert np.shares_memory(A, T)
assert T.flags.f_contiguous

columns = A[:, ::2]
assert columns.strides == (4 * A.itemsize, 2 * A.itemsize)
reversed_rows = A[::-1]
assert reversed_rows.strides[0] == -4 * A.itemsize
contiguous = np.ascontiguousarray(T)
np.testing.assert_array_equal(contiguous, T)
assert contiguous.flags.c_contiguous
assert not np.shares_memory(contiguous, A)
```

连续化函数在输入已经满足要求时可能直接返回原数组，并不承诺每次复制。因此如果目的是获得独立可修改存储，应明确 copy；如果目的是满足外部内核布局，则连续化更准确。两种目的可能同时需要，但不能用一个函数名默认推导所有性质。检查修改契约比只看 flags 更重要。

重塑的 order 参数规定按什么逻辑顺序读取并重新填入索引，不等于总是强制生成该物理布局。一个布局可以在某些重塑下仅改步幅，另一些需要复制。NumPy 新版本提供更明确的复制控制时，应按所用版本核对；无复制要求若无法满足，明确失败通常比静默占用大内存更容易管理。

ravel 与 flatten 也有不同复制承诺。需要视图时不能盲目使用总复制接口，需要独立存储时也不能以尽量展平视图替代 copy。对负步幅、转置和间隔切片，结果可能不同；应该用共享检查与元素对应验证。不要把某个简单连续例子的结果概括到全部布局。

共享检测工具也有成本与保守性差异。确定共享检查可能对复杂步幅关系需要较多工作，可能共享检查则可以快速给出保守可能性；后者返回真不一定证明实际重叠。读接口文档时要分清保证方向。对普通小例子可使用精确检查，但正式算法不必在每次元素操作都重新分析共享。

数组的 .base 只能显示某个基础关联，不保证恰好是你最初的变量；经过多次视图操作后，它可能指向更早的缓冲拥有者。判断两个结果是否共享，应比较它们的存储关系，而不是只看两个 .base 是否相同。多个不同对象也可能引用同一外部缓冲，身份与内存别名不是同一个概念。

<a id="sec-11"></a>
## 11. 重叠窗口、别名与逻辑内存

滑动窗口把一个序列的相邻片段表示为多行。例如长度六、窗口三，得到四个窗口，每行与下一行共享两个原始位置。窗口视图可以不复制所有数值，但逻辑元素数已经变成十二。它很适合解释局部计算，却不意味着后续对全部窗口的运算也零成本；归约仍需要访问逻辑位置，复杂度通常与窗口数乘窗口长度有关。

重叠造成同一原始元素拥有多个逻辑入口。若允许任意窗口位置写入，可能同时改变其他窗口与源序列，让更新顺序变得难以推理。安全接口默认通常给只读视图，避免把这些入口当独立存储。只读标记限制当前数组写入，不保证源数组不被其他入口修改，所以窗口内容仍可能随源变化。

```python
import numpy as np
from numpy.lib.stride_tricks import sliding_window_view

source = np.arange(6, dtype=np.int64)
windows = sliding_window_view(source, 3)
np.testing.assert_array_equal(windows, [
    [0, 1, 2], [1, 2, 3], [2, 3, 4], [3, 4, 5],
])
assert windows.shape == (4, 3)
assert np.shares_memory(source, windows)
assert not windows.flags.writeable
assert windows.nbytes == 12 * source.itemsize
assert source.nbytes == 6 * source.itemsize
source[2] = 99
assert windows[0, 2] == windows[1, 1] == windows[2, 0] == 99
independent = windows.copy()
source[2] = 2
assert independent[0, 2] == 99
```

这个例子说明 nbytes 是逻辑元素数量乘元素大小，不是独占物理内存。窗口逻辑大小是源的两倍，却共享同一小缓冲；复制后才建立独立重复存储。若对大量窗口直接复制，峰值可能巨大；若直接对视图运行复杂算法，虽然不复制输入，计算与输出仍可能很大。资源分析要同时看逻辑规模、物理共享与后续临时量。

滑动均值可以直接对窗口求平均，但窗口很长时，前缀和或专门滤波方法可能减少重复工作。它们也有数值与边界政策：前缀大数相减可能相消，滤波需要定义填充、中心对齐与起止位置。不能因为窗口视图创建很快，就断言整个滑动统计是线性时间；真正成本由后续算子决定。

多维窗口还会增加窗口轴，并缩短被滑动的原轴。应核对输出轴顺序与每个坐标对应的源位置，特别是图像小块提取。后续把窗口轴展平成特征时，必须保证通道与空间排列符合模型约定。只看最终每块元素数相同，不足以证明每个像素的相对位置保留。

窗口数据还涉及统计依赖。相邻窗口共享多数原始观察，不能把所有窗口当独立样本去计算过于乐观置信区间。训练测试若随机按窗口拆分，可能让高度重叠片段出现在两边，造成泄漏。应按原序列、用户或时间边界先切分，再在各部分构造窗口，并根据任务设必要间隔。存储重叠与信息重叠在这里直接联系。

例如原序列前五个位置用于训练，后五个用于测试，窗口跨越边界就可能把测试输入带进训练样本；若任务还有未来标签，标签范围也要一起限制。先定义每个窗口使用哪些时间点与预测哪个目标，再决定划分。不能只筛选窗口起点落在哪边，因为终点可能已跨到另一部分。

更底层的任意步幅构造可以表达许多视图，但错误的形状或步幅可能访问缓冲之外，或造成难以理解的重叠写入。本章不鼓励手工使用危险低层工具替代安全窗口接口。确实需要时，必须证明地址范围、元素对齐与写入策略，而不是从一个能打印的小例子推广。知道机制边界也是进阶能力的一部分。

广播视图与窗口视图都可能让多个逻辑位置指向同一存储，但映射不同：广播沿某轴固定输入位置，窗口按起点与局部偏移共同决定源索引。反向累计时，两者都需要把多条路径贡献加到源位置，不能简单赋值覆盖。这个联系有助于理解卷积展开与梯度散射，也再次说明重复索引归约的重要性。

如果只保留少量窗口供长期分析，复制这些小片段可能释放巨大原始缓冲；如果所有窗口只被短暂只读消费，视图更节省。选择依赖生命周期，而不是固定偏好复制或零复制。可以把保存策略写在接口中，让调用者知道结果是否随源变化，以及何时必须自己复制。

## 12. 聚合与写回：分组总量的完整案例

分组统计是典型多对一映射：每条记录有组编号，把其特征贡献加到对应组。若组编号重复，普通高级增量赋值可能漏加，因此需要明确累积。我们实现每组特征总和、记录数与均值，允许空组但不允许非法组号；空组均值保存为非数值，不能冒充观测到零。

输入约定为二维有限数值矩阵与同长度一维整数组号，组数为非负整数。负编号在数组索引中可以指末尾，但在这里非法；布尔组号也不被接受，因为它表达不同域。组数零只在没有记录时可行。先验证全部输入，再开始归约，可以避免部分失败后把半更新结果当成功输出。

```python
import numpy as np

def grouped_summary(values, groups, group_count):
    X = np.asarray(values, dtype=np.float64)
    group = np.asarray(groups)
    if X.ndim != 2 or group.ndim != 1 or group.shape[0] != X.shape[0]:
        raise ValueError("incompatible sample shapes")
    if type(group_count) is not int or group_count < 0:
        raise ValueError("group_count must be a nonnegative integer")
    if group.dtype.kind not in "iu":
        raise ValueError("groups must be an integer array")
    if not np.isfinite(X).all():
        raise ValueError("values must be finite")
    if np.any(group < 0) or np.any(group >= group_count):
        raise ValueError("group index out of range")
    group = group.astype(np.intp, copy=False)
    totals = np.zeros((group_count, X.shape[1]), dtype=np.float64)
    counts = np.zeros(group_count, dtype=np.int64)
    with np.errstate(over="raise", invalid="raise"):
        np.add.at(totals, group, X)
    np.add.at(counts, group, 1)
    means = np.full_like(totals, np.nan)
    np.divide(totals, counts[:, None], out=means, where=counts[:, None] > 0)
    return totals, counts, means

X = np.array([[1, 10], [2, 20], [3, 30], [4, 40]], dtype=float)
groups = np.array([2, 0, 2, 1], dtype=np.intp)
totals, counts, means = grouped_summary(X, groups, 4)
np.testing.assert_allclose(totals, [[2, 20], [4, 40], [4, 40], [0, 0]])
np.testing.assert_array_equal(counts, [1, 1, 2, 0])
np.testing.assert_allclose(means[:3], [[2, 20], [4, 40], [2, 20]])
assert np.isnan(means[3]).all()
np.testing.assert_allclose(totals.sum(axis=0), X.sum(axis=0))
assert counts.sum() == X.shape[0]
np.testing.assert_array_equal(groups, [2, 0, 2, 1])
empty = grouped_summary(np.empty((0, 2)), np.array([], dtype=np.intp), 3)
np.testing.assert_array_equal(empty[1], [0, 0, 0])
```

手算组二接收第一与第三条，两个特征总和四与四十，计数二，均值二与二十；组零只有第二条，组一只有第四条，组三为空。总量守恒检查能发现漏加，但不能发现把组零与组一完全互换，所以还需每组手算。计数与位置映射是另一层证据，不应只用最终全局和作为唯一判据。

这里没有向输入数组写入，输出为新建缓冲。即使规范化 X 时共享输入，函数只读它，因此调用期间不修改；返回结果也不共享输入数值。若未来为了性能把 totals 指向输入某片段，这项契约就会改变，需要重新验证。优化不能无声破坏调用者对独立结果的期待。

求和、计数与均值的分块合并规则不同。总和与计数可以相加，均值必须按计数加权或重新由合并总和除合并计数。空组没有均值，不能把非数值或零随意加入平均。若任务按组等权而不是按记录等权，那又是另一个总体汇总，需要明确权重。数组归约从来不自动决定抽样单位。

如果组编号范围小且非负，一维计数可以用 bincount 等专门工具；多特征累加可以用散射、排序分段或循环块。加权计数接口的输出类型与精度也要检查，不能因为输入金额是整数就假设所有路径都保持精确大整数。算法选择取决于组数、稀疏程度、特征宽度与所需精度。

组号非常大但只有少数实际组时，直接分配最大组号加一的数组会浪费内存。可以先把业务键映射为紧凑连续编号，并保存反向映射；也可以使用其他稀疏聚合结构。映射必须稳定且可追踪，不要把排序后的内部编号当成原始业务身份。结果解释需要恢复真实组名，而不是只给用户零一二。

浮点聚合顺序可能影响末位。散射按输入顺序更新，排序分组会改变顺序；并行局部聚合再合并又是另一条路径。数学总和一致不保证逐位一致，应该按误差需求比较。对于需要精确货币计算，整数最小单位或其他明确表示可能更合适，但也要检查范围溢出。精度选择属于数据契约，不是事后补丁。

加权均值需要另外保存权重和，而不是直接复用记录数分母。权重可以表示频数、重要性或可靠度，不同解释影响后续方差与不确定性。若允许零权重，应明确它是否计入记录数；若拒绝负权重，则启动时验证。不能只给 add.at 的数值多乘一项，就声称所有统计语义已正确扩展。

失败时示例只返回异常，没有发布半成品；全部归约在局部结果中完成。若把累计器作为长期对象，更新中途溢出可能留下部分状态，需要候选状态或事务式提交策略。这里的新建输出让异常安全相对简单，但在在线系统里不能直接忽略。接口生命周期决定需要多强恢复保证。

## 13. 布局优化、外部接口与性能证据

布局优化应从真正的消费方式出发。逐行处理通常喜欢某种连续访问，逐列处理可能有另一种偏好，矩阵核心也可能接受多种布局或先内部打包。不能仅凭 C 连续标记就断言必然最快；转置视图有时能被底层高效解释，强制复制反而增加一次大数据搬运。代表规模与下游算子共同决定收益。

一次复制可以在多次重用中摊销。如果一个非连续数组会被同一核心处理一百次，先整理一次可能划算；若只使用一次小片段，复制成本可能主导。测量应包含实际重复次数和生命周期，不把只测整理后核心时间与另一个端到端路径混为公平比较。第二章的预算原则在布局层同样适用。

批量矩阵也可能因每批尺寸很小而难以充分利用核心。把许多小乘法逐个 Python 调用，控制开销高；批量接口可以减少调用，但底层是否使用专门批内核依赖实现。不能从语法批量就推出所有硬件上同样加速。记录输入形状、批数、dtype 与线程配置，结果才有可解释性。

外部接口可能对负步幅、对齐、字节序、只读状态或连续性有要求。普通 NumPy 能处理某个视图，不代表另一个库接受同样缓冲；转换函数也可能复制或共享。跨库时应核对文档，并实际检查写入是否相互可见、设备是否变化和对象生命周期。不要因为两个库都叫 array，就推断它们有相同所有权规则。

数据类型字节序尤其说明元信息的重要性。相同原始字节按不同 dtype 或字节序解释，可能得到完全不同数值；把字节直接视作新类型，不等于执行数值转换。数值转换通常要重新计算表示，而视图式类型解释只改变读取方式。处理外部二进制数据时，应明确格式、长度、对齐与单位，不能靠文件扩展名猜测。

内存映射允许把文件内容映射为数组，访问时由系统按需处理页面，但它不意味着计算无需内存，也不自动提供一致快照或事务。多个进程修改映射还涉及同步与持久性；文件被替换后不同句柄可能观察不同对象。学习阶段可以先理解其资源模型，不必把所有大数据问题都改成映射解决。

共享数组的并发写入需要专门设计。即使某个 NumPy 操作释放解释器锁以提高并行，不代表对共享位置的读改写自动原子。可以让工作者处理不重叠区域，或各自累计局部结果再按明确规则合并；存在冲突时需要同步。重复索引的单调用语义与跨线程竞争是不同问题，不能用 add.at 名字中的 at 推出线程安全。

测量内存时要分清逻辑大小、独占缓冲与进程驻留。一个小视图可能保留大源数组，一个大广播视图可能几乎不新增数值存储；原生数值库工作区又可能不被某些 Python 追踪工具完整统计。可以把静态元素估算、共享关系检查与实际工具测量结合，说明各自范围，避免给出看似精确却口径不明数字。

布局改变也可能改变数值归约顺序。比如沿不同连续方向求和，底层实现选择的分组方式可能不同，末位结果变化不一定是错误。但如果转换成较低精度、错误重解释字节或漏掉共轭，差异不是普通布局噪声。先核对数学与类型，再分析舍入与性能，不能倒过来用“底层优化不同”解释一切。

一个合理优化报告应给原始与目标布局、复制次数和位置、峰值估算、端到端耗时、结果误差及使用次数。若只展示整理后数组更快，却不算整理本身，读者无法判断是否适合自己的单次任务。对于教学代码，宁可保留清楚表达，也不为没有测到的收益添加复杂别名和手工步幅。

最后回到资源边界。缓存一个视图会延长原数据生命周期，缓存一个副本会占新空间；将数组交给异步消费者时，生产者是否还会修改底层存储也要说明。零复制接口节省搬运，却增加共享状态责任。性能收益与所有权约定是一组共同决策，不能只谈前者。

### 14.1 从坐标出发推导结果，而不是猜形状

**问题一：** 一个四乘五矩阵按行优先依次保存零到十九。行索引为零、二，列索引为一、三。请分别求配对选择、交叉选择和先取行再取列的结果，并说明哪些表达等价，哪些共享源缓冲。

**解析：** 配对选择只访问坐标零一与二三，结果为一与十三，形状长度二。交叉选择访问零一、零三、二一、二三，排成两行两列，结果为第一行一与三、第二行十一与十三。先高级取两行得到两乘五副本，再对其列轴高级选择，数值与交叉选择相同，但通常经过额外中间数组。

三种高级读取都不与原始数值缓冲共享；不能因为先取行的结果有两行，就把随后两个列号解释成配对两行。关键是第二个索引针对哪个数组、哪个轴，以及输出坐标如何映射到源。

进一步把列索引改成一、三、四。直接用两个一维索引配对不能广播，因为长度二和三不兼容；交叉选择则仍然合理，输出两乘三。这个改动很有诊断价值：原来两个长度相等的索引既可以代表配对，也可以代表交叉需求，单靠长度无法确定意图。为每个轴选择不同长度，并写出一两个实际坐标，比在全都等长的张量上测试更容易揭示轴错位。

**问题二：** 已知四维数组形状六、三、四、五，整数数组含一、三。比较同一次使用首轴整数零、中间完整切片、第三轴数组索引，与先固定首轴再选择第三轴的差别。为什么两个表达选择相同元素，却不能直接逐位置比较？

**解析：** 同次索引的整数零也参与整数索引组相邻性的判断，它与整数数组之间有切片，因此高级索引广播轴前移，输出二、三、五。分步第一下消去首轴，第二下在剩余三维数组中使用一个整数数组，输出三、二、五。前者位置零、一、二与后者位置一、零、二对应，需要交换前两轴才能比较。仅比较展平后的序列还可能误导，因为展平顺序由结果轴排列决定，集合相同并不等于序列相同。

### 14.2 从读取映射推导散射更新

**问题三：** 向长度三的零数组按目标位置零、零、二写入贡献二、五、七。需求分别是每次贡献求和、最后一条事件生效、取最大贡献，应如何表达？为什么一种高级增量赋值不能同时满足三种需求？

**解析：** 求和应得到七、零、七，可使用明确的累积归约。最后事件生效应得到五、零、七，但必须先声明事件顺序，并按稳定规则把同一目标归并为唯一写入，不能依赖普通冲突覆盖的偶然顺序。取最大贡献应得到五、零、七，但这是本例恰巧与最后事件相同；调换两个零号贡献顺序，最后生效变为二，最大仍为五。设计反例必须打破这种偶合，否则一个错误实现会因测试数据而通过。

最大归约还需选择初始值。若所有贡献可能为负，使用零初始化会错误保留不存在的零；通常应使用适合域的最小哨兵，并另存是否观察到贡献。空位置应该报告缺失、保留旧值还是输出默认值，属于接口政策。求和的零单位元不应被机械推广为所有聚合的合理初值。均值、方差等统计又需要更丰富状态，而非仅选择一种二元覆盖运算。

**问题四：** 为什么类别嵌入查表的反向传播需要散射累积？假设两个样本读取同一个词向量，能否把它们各自梯度直接赋回参数表？

**解析：** 同一参数行同时影响两个样本的前向结果，总目标微分中含两条依赖路径，因此该行梯度是两份贡献的和。直接赋回可能覆盖其中一份，普通带重复索引的增量也可能发生缓冲语义漏加。应先保证逐条贡献已按目标归约，再进行参数更新。

若目标使用样本均值，还要在累积后或每条贡献中施加同一总分母；重复词出现次数是贡献数，不能因为词编号相同就把两条训练记录去重。这里的累加由链式法则决定，与业务是否把重复文本视为独立观测是两个层次。

<a id="visual-gather-adjoint"></a>

### 图解：从读取矩阵推导索引梯度

![把索引反向传播写成一张线性映射](images/03-gather-adjoint.svg)

把离散索引固定后，读取本身可以写成连续参数上的线性映射。取 $`x=(2,3,5)^{\mathsf T}`$，索引为零、零、二，对应

$$
G=
\begin{bmatrix}
1&0&0\\
1&0&0\\
0&0&1
\end{bmatrix},
\qquad
y=Gx=(2,2,5)^{\mathsf T}.
$$

矩阵的每一行代表一条输出记录，一列代表一个源参数。第一列有两个一，表示同一参数被读取两次；第二列全零，表示那个参数未参与前向。这里构造稠密矩阵是为了证明，不建议真实嵌入表显式创建这样的大矩阵。索引运算正是在不存储全部零元素的情况下完成同一映射。

令目标 $`t=(1,4,2)^{\mathsf T}`$，使用未取均值的损失 $`L=\frac{1}{2}\|Gx-t\|_2^2`$。残差为 $`u=(1,-2,3)^{\mathsf T}`$，微分满足 $`dL=u^{\mathsf T}G\,dx=(G^{\mathsf T}u)^{\mathsf T}dx`$，故源梯度为 $`(-1,0,3)^{\mathsf T}`$。图中两条斜线汇入第一项，是贡献 $`1+(-2)=-1`$，不是重复覆盖，也不是把两条记录按源编号去重。若把损失改为三条记录的平均，最终梯度整体再除以三；分母是记录数，不能擅自换成两个被读取的不同源编号。

这个例子还给出一种比“输出看起来合理”更强的独立验证。任取输入扰动 $`v=(1,2,-1)^{\mathsf T}`$，前向扰动为 $`Gv=(1,1,-1)^{\mathsf T}`$；因此 $`u^{\mathsf T}Gv=1-2-3=-4`$，同时 $`(G^{\mathsf T}u)^{\mathsf T}v=-1-3=-4`$。两边相等是转置映射应满足的内积关系。有限差分还可验证 $`\frac{L(x+hv)-L(x-hv)}{2h}=-4`$；本例目标为二次函数，精确算术下中心差分对任意非零 $`h`$ 都成立，浮点实现仍应选择适当步长。

实现时可以从零梯度缓冲开始调用 `np.add.at(grad, [0, 0, 2], u)`。按 [NumPy 2.4 的无缓冲累加语义](https://numpy.org/doc/2.4/reference/generated/numpy.ufunc.at.html)，重复位置会收集各条贡献。反向传播求的是被读取数值的导数，不是整数索引本身的普通导数；若索引由 argmax 或检索选择产生，上述推导只描述固定选择分支，不能据此把离散选择操作当作处处可微。

<a id="sec-14-3"></a>
### 14.3 给性能实验建立可证伪的预测

**问题五：** 一个双精度一千乘一千数组，连续副本与转置视图的逻辑字节数相同。能否由此断定二者独占内存相同、矩阵乘法速度相同？请设计比较方案。

**解析：** 一百万元素各八字节，逻辑大小都是八百万字节；转置视图可以共享原缓冲，副本则需要新的数值存储。比较速度前先规定下游计算、调用次数与是否计入整理成本。分别记录原输入直接处理、每次先复制再处理、仅复制一次并多次处理三条路径；检查它们得到同一数学结果，并固定规模、类型与线程条件。单独计时转置视图创建只能回答元信息操作成本，不能代表随后读取所有数据的时间。

可以预先预测：重复次数很少时，额外复制可能难以摊销；重复次数增大时，若布局确实限制内核访问，整理可能逐渐有利。但这不是保证，底层可能已经高效处理该转置。若实验未显示加速，应保留结果并分析消费算子，而不是反复挑规模直到出现期待结论。报告计时分布而非一次最小数，还要说明预热、工作区和环境边界，避免把噪声或缓存条件写成普遍定律。

**问题六：** 长度一百万、窗口一千的滑动窗口视图需要多少逻辑元素？创建视图很快是否说明滑动均值也只需一次线性扫描？

**解析：** 有九十九万九千零一个窗口，每个一千元素，逻辑元素总数九亿九千九百万一千。源数据若为双精度约八百万字节，窗口逻辑大小约七十九亿九千二百万八千字节，但只读视图并不新增同等数值缓冲。直接逐窗口归约仍涉及大量重复访问，不能从视图创建成本推出整体复杂度。前缀和可改变工作量，但要处理相消与边界；分块直接计算可减少峰值，却不会自动消除窗口长度因子。先把存储、读取量与算术量分别写出，才能比较算法。

<a id="sec-14-4"></a>
### 14.4 一个可继续扩展的研究任务

实现分组加权均值，输入为样本特征、合法组号和非负权重，输出每组加权总量、权重和、记录数与均值。明确零权重记录是否计数，本任务规定仍计入记录数；没有正权重的组没有可定义的加权均值，输出缺失标记。先给四条小记录手算，再验证拆成两块后合并状态得到同一结果。均值本身不能直接等权合并，必须携带权重和；记录数也不能替代权重分母。

完成正确版本后，比较散射累积与排序后分段归约，变化组数、重复率和特征宽度。每次都核对业务组键没有因内部排序而错配，并区分数值容差与身份完全一致。研究输出应说明哪一类输入使哪种方法更合适，而不是选一个最快数字宣称通用优胜。若排序版本出现较大浮点差异，应检查累积顺序、输入动态范围与 dtype，再判断是否需要更稳定求和，而不是直接认定另一算法错误。

最后把特征矩阵改为间隔切片、转置再转回的视图，以及共享巨大源缓冲的小片段，观察接口语义是否保持。研究不要求每条路径都零复制，要求每次复制都有目的、每次共享都有清楚生命周期、每项统计都有明确分母。能够从一个输出位置追溯到输入记录及其权重，并解释它占用哪些存储，这才把本章的索引、归约与布局连成了一套可检验方法。
