## 1. 函数把步骤变成可复用接口

函数给一段计算建立明确入口。调用者把实际对象交给参数，函数执行后返回结果，或者通过异常表示无法满足请求。这个边界使同一算法可以用于不同输入，也使你能够单独检查某一步，而不必从文件读取一直重跑到绘图。把代码放进函数的价值，不只是少复制几行，而是把一件事变成可理解的承诺。

参数名应表达含义，而不是只用位置编号。计算误差的函数若接收真实值与预测值，最好让名字明确区分二者；二者在某个对称指标里也许可交换，在另一个指标里却未必。对于容易混淆的选项，可以设计仅限关键字参数，让调用者写出参数名。一个阈值到底是置信阈值、距离阈值还是误差容忍度，不应靠阅读函数内部猜测。

返回值与打印输出不同。打印适合向人展示信息，返回值让其他程序继续计算。如果底层函数只打印均值而返回空值，上层就难以组合它，也难以写自动检查。没有执行显式返回时，普通函数返回空值；这不是计算结果丢在屏幕里等待被其他函数读取。应让计算函数返回结构化结果，由入口或展示层决定怎样打印、绘图或保存。

下面函数计算非空有限内置数值序列的平均值。它先验证整组输入，再求和；不会修改原序列。这里返回浮点数，输入的类型与范围检查是我们主动实现的，并不是注解自动执行。整数也必须能转为有限浮点数；即使每项符合要求，求和仍可能溢出，本例会明确报错。

例如两个`1e308`的均值本身可表示，但中间总和不可表示；当前教学实现会拒绝，尚未采用缩放求均值算法。使用更一般数值类型时，需要重新设计验证，而不是把这个例子的限制偷偷当成 Python 的普遍规则。

```python
import math

def finite_mean(values):
    if not values:
        raise ValueError("values must not be empty")
    for index, value in enumerate(values):
        if type(value) not in (int, float):
            raise TypeError(f"value at {index} is not a supported number")
        try:
            finite = math.isfinite(value)
        except OverflowError:
            raise ValueError(f"value at {index} exceeds float range") from None
        if not finite:
            raise ValueError(f"value at {index} is not finite")
    try:
        return math.fsum(values) / len(values)
    except OverflowError:
        raise ValueError("sum exceeds supported numeric range") from None

data = [1.0, 2.0, 6.0]
before = data.copy()
assert finite_mean(data) == 3.0
assert data == before
```

参数传入以后，函数内部名字绑定到相应对象。重新给局部参数名赋值，不会替调用者重新绑定名字；修改同一可变对象则能被调用者观察到。因而“函数没有返回值”不意味着“函数没做事”，它可能修改了输入、文件或全局状态；“函数返回新列表”也不意味着完全没有副作用，它可能在返回前已经排序了原列表。这些问题都应由接口明确。

默认值适合表达稳定、常见的选项，例如阈值或是否保留缺失。但一个默认值会影响调用者不写参数时的行为，因此改默认值可能改变大量实验。对于决定统计口径的重要选项，有时要求显式传入比给一个方便默认值更可靠。例如标准差使用总体分母还是样本分母，应该有清楚名字和说明，不应隐藏在实现的一处减一里。

参数过多往往提示职责混杂，但不意味着见到很多参数就立刻包装成一个巨大配置对象。先检查哪些参数属于同一个稳定概念，哪些是可分离步骤的依赖。若函数同时接收路径、网络连接、数据清洗规则、模型、画图样式和上传选项，通常应拆分流程。配置对象也应保持语义边界，不能成为什么都往里塞的袋子。

<a id="sec-1-1"></a>
### 基础算例：参数、返回值与副作用分别检查

任务是接收列表`[1, 2]`，返回平方结果`[1, 4]`，同时保持输入。可以写成列表推导式返回新列表。验收时至少检查两个独立结论：输出是否正确，输入是否未变。如果只看输出，一个把原列表逐项改成平方后再返回它的实现，也会在这个样例上得到同样打印结果，但违反了不修改输入的承诺。

接着考虑嵌套数据。函数返回新外层列表，但复用了内部字典；调用方后来修改结果的字典，可能影响原输入。若契约只承诺函数调用期间不修改输入，这也许仍满足字面要求；若承诺结果可独立编辑，则不够。精确表达契约能避免争论：到底保证“调用过程没有写入”，还是保证“返回对象图与输入图无可变共享”，这是两个不同性质。

副作用不是天然错误。原地更新优化器状态、写入日志、把结果保存到文件都需要副作用。合理做法是让它们出现在明确边界，名字与说明暴露意图，并尽量使失败时状态可解释。危险的是计算函数看似只返回数值，却暗中修改下一次实验会复用的输入。可见性比一味追求所有函数纯粹更重要。

<a id="deep-dive-1"></a>
### 深入讲解：接口契约比函数名字更重要

完整契约至少包含输入域、结果含义、状态变化、失败条件和成本预期。输入域不仅是外层类型，还包括空输入、有限性、长度关系和顺序要求；结果含义包括单位、排序、缺失处理与分母；状态变化说明哪些对象会被修改；失败条件解释哪些情况抛异常；成本说明是否会读取全部数据或触发昂贵计算。

以前面的平均函数为例，输入必须是可重复访问且支持长度检查的有限序列，而不是任意一次性迭代器。函数先遍历验证，再求和，还调用长度，所以直接传入生成器并不符合当前实现。若要支持任意迭代器，应在一次遍历中累计总和与计数，或先物化。不能因为参数名字叫 values，就声称它天然支持所有数据源。

前置条件与后置条件帮助审查逻辑。前置条件是调用者必须满足的假设，后置条件是函数在这些假设下提供的保证。若前置条件过于宽泛，实现就难以兑现；若过于狭窄，接口就不必要地限制复用。异常处理可以把某些违反前提的情况变成清晰反馈，但不必假装函数能对所有 Python 对象给出有意义的数值答案。

研究代码尤其应写清“拟合”与“应用”。拟合从数据学到统计量，应用则使用已有统计量。若每次调用变换函数都会重新学习均值，验证数据可能影响预处理，从而造成泄漏。把两个阶段拆成独立接口，不只是风格选择，而是把实验协议编码进程序结构。完整案例会展示这种边界。

**图解。** 图中用执行位置和局部变量追踪两次 next：先在 i=1 的 yield 暂停并返回 1，继续后在 i=2 的 yield 返回 4。创建、暂停与耗尽是不同状态，暂停后会从当前位置继续而不是重启函数。

## 2. 类组织状态与行为

类适合表达具有生命周期的对象：它拥有一组状态，并通过方法维持这些状态之间的关系。归一化器保存训练均值与尺度，计数器保存累计数量，随机采样器保存随机状态。若一个步骤只根据输入产生输出且没有跨调用信息，普通函数通常更直接。是否使用类，应由状态与接口需求决定，而不是因为某个项目看起来需要面向对象风格。

实例属性属于具体实例，类属性则由类层共享。把可变列表写在类体上，可能让所有实例共用它；在初始化方法里为每个实例建立新列表，才得到独立状态。类属性共享有时是有意设计，例如只读常量或注册表，但不应把实例历史误放成全类共享历史。对象图模型仍然适用：类也是持有引用的对象，状态放在哪里决定谁能到达它。

方法中的实例参数只是一个约定名字，帮助访问当前实例。调用`obj.update(x)`时，普通方法绑定使对象参与调用；方法并不会自动得到所有外部变量。把依赖藏在模块全局，仍会制造难以追踪的环境要求。初始化方法应该保存必要配置，方法参数传入每次调用变化的数据，二者的区分使对象生命周期清楚。

对象的不变式比字段数量更重要。例如累计器要求计数非负、总和对应已经接收的值、尚无数据时均值未定义。每个公开修改方法都应在完成后维持这些性质。直接让外部任意写计数与总和，容易出现计数三、实际只累加两个值的状态。Python 的命名约定不是强制封装，但你可以通过清晰公开接口降低误用概率。

<a id="sec-2-1"></a>
### 机制展开：类的方法如何约束对象状态

一个更新操作往往涉及多个字段。若先把计数加一，再验证输入，验证失败后对象可能残留错误计数。更可靠的是先检查输入并计算候选新状态，最后再提交相关字段。对本地纯数值更新，这种顺序能保持异常后的对象一致；若操作涉及外部文件或并发，还需要更强机制，不能把几行顺序赋值当作普遍事务保证。

拟合型对象还有状态阶段：未拟合、已拟合，必要时还有失败或关闭。未拟合就调用变换，应清楚报错，而不是因为某个字段不存在产生难懂异常。再次拟合时究竟覆盖统计量、累积统计量还是禁止，应明确定义。常见接口把普通拟合定义为替换，把增量拟合定义为累积，两者不能只靠用户猜方法名。

当类只保存配置而没有复杂行为时，数据类可以减少样板代码，但它不自动验证业务条件，也不自动保证嵌套对象深层不可变。第四章会具体讨论数据类与配置组织。这里先掌握一个原则：选择语法工具之后，仍需回答状态是否合法、可否变更、由谁拥有，以及错误后处于什么状态。

## 3. 迭代与惰性计算

迭代把“依次拿到元素”从具体容器中抽象出来。列表、元组和文件都可以被逐项读取，但它们对重复读取、长度获取和随机访问的支持不同。写函数时如果只需一遍扫描，接受一般迭代输入能支持更大数据；如果算法必须多轮或随机访问，就应承认这个要求，而不是在内部偷偷把全部数据转成列表却仍宣传常数内存。

可迭代对象能够提供迭代器，迭代器保存当前位置。对列表反复获取迭代器，通常能从头开始；对同一个生成器反复迭代，则继续原位置直到耗尽。两个概念在语法上都能放进循环，行为却不同。数据准备中的“第一轮有样本、第二轮无样本”往往来自把一次性流当成了可重复数据集。

生成器函数通过产生值语句分段执行。调用时创建生成器对象，真正计算在消费时发生，这让中间结果不必全部同时存储。代价是异常与资源访问也被推迟。若你在创建生成器之后打印“数据检查完成”，而实际验证代码在函数体内，这个提示可能完全不真实。应该在确实消费并验证后再宣称完成，或明确说只是建立了处理流程。

惰性还有一个调试陷阱：为了查看内容，把生成器转成列表打印出来，相当于消费了它。后面再把同一个对象交给训练，可能已经为空。可选择先取少量预览并把它们与剩余流重新连接，或重新建立数据源，或在规模允许时明确物化。每种方案都应说明消费行为，不能让调试语句悄悄改变实验语义。

迭代器支持的错误传播也影响统计。若第六条记录读取失败，前五条可能已被处理并更新状态。是保留部分结果、整体失败还是回滚，取决于接口契约。简单循环不会自动撤销之前更新。对可恢复任务，可以记录已完成位置并设计幂等更新；对需要完整数据的评估，可能更适合先验证再提交总体结果。

<a id="sec-4"></a>
## 4. 纯函数有助于排查实验

理想的纯函数只根据显式输入计算结果，不改变外部可观察状态。在相同输入与数学环境下，它更容易独立验证、缓存和比较。一个把摄氏温度转换为华氏温度的函数就很接近这种模式；一个读取当前时间、依赖全局随机状态或修改输入列表的函数则有额外依赖。纯度是理解行为的一种工具，不是对程序价值的道德评价。

机器学习训练必然包含状态：模型参数在更新，优化器保留动量，随机源推进，日志持续写入。合理的结构是把状态变化放在明确的外层，把损失计算、数据校验和指标整理等能独立表达的部分保持清楚。这样某个指标异常时，可以只给它一小组真实值与预测值，验证它的公式，而无需复现完整训练机器与所有历史状态。

显式传入随机数源是一个例子。函数若直接使用全局随机模块，其他地方多调用一次随机操作，就可能改变本函数结果；若接收专属随机数生成器，依赖关系更可见。但随机数生成器本身有状态，传入它并不让函数变纯，也不保证两次连续调用结果相同。要重现实验，需要保存或重建对应初始状态，同时保持调用顺序一致。

纯函数也会受到数值环境影响。浮点运算、库版本和并行归约顺序可能造成细微差异，所以“同输入同输出”要在具体环境假设下理解。不要因为这个边界就放弃显式依赖设计：它仍然能减少大量隐藏变量。区分逻辑确定性、逐位一致和统计可复现，会比笼统要求所有结果完全一样更精确。

接口副作用可以分级说明。最容易验证的是返回新标量或新不可变结构；其次是返回新外层容器但共享只读内部对象；更复杂的是原地修改或同时返回结果与更新状态。选择哪一种要看性能和使用方式，但说明必须具体。例如“按用户编号排序后返回同一列表”与“返回按用户编号排列的新列表”只有几个字之差，却决定调用者是否还能使用原始顺序。

测试非修改承诺时，不要只检查最外层身份。结果与输入不是同一列表，仍可能共享字典；输入在调用后数值相同，也不代表函数没临时修改再恢复。一般应用通常关心调用边界可观察状态，而不是禁止所有内部动作；并发读者或异常路径则可能让临时修改也可观察。因此契约越接近实际使用环境，检验越有意义。

<a id="sec-5"></a>
## 5. 组合函数与小型接口

把流程拆成读取、解析、校验、计算和展示，让每一步只承担稳定职责。这里的“一项职责”不是“一行代码”，而是一个可以独立描述和改变的原因。一个验证函数可以包含多条检查，因为它们共同维护输入合法性；一个同时读文件、拟合模型、生成图并发送通知的函数则混合了明显不同的变化来源。

函数组合需要关注前后契约是否匹配。清洗函数返回的可能是合法记录列表，而指标函数需要真实值与预测值等长序列。中间应有明确转换，不要让后者自己猜从哪个字段取数据。若每个函数都容忍任意结构并自行修复，错误可能被一层层掩盖，最后得到看似合理却来源不明的数值。边界明确有时意味着更早拒绝不合适的输入。

有时一个函数返回多个相关结果，用元组足够清楚；字段多且含义易混时，命名结构更适合。不要让调用者记住“第七项是标准差，第八项是缺失数”。同样，函数返回一个巨大字典也不是天然清晰，仍要有稳定字段与类型说明。好的结果结构让使用者根据名字理解含义，不需要阅读内部实现。

错误处理应放在能够采取有意义行动的层。底层数值函数发现空输入，可以抛出清晰异常；入口知道正在处理哪个数据文件，可以补充上下文并决定终止或跳过。若每层都捕获所有异常并返回零，上层将无法区分真实零值与计算失败。若每层都重复打印堆栈，日志又会变得嘈杂。保留错误原因、在合适边界作决策更有效。

下面示例把校验与误差计算分开。指标函数明确要求两个非空等长序列，并先验证有限性。平方误差的平均值使用全部配对样本作为分母；没有静默丢弃某一侧缺失值。若未来需要掩码，应把掩码规则作为显式输入，而不是在循环中遇到错误就任意跳过。

```python
import math

def validate_pair(actual, predicted):
    if len(actual) != len(predicted):
        raise ValueError("lengths must match")
    if len(actual) == 0:
        raise ValueError("at least one pair is required")
    for label, values in [("actual", actual), ("predicted", predicted)]:
        for index, value in enumerate(values):
            if type(value) not in (int, float):
                raise ValueError(f"invalid {label} value at {index}")
            try:
                finite = math.isfinite(value)
            except OverflowError:
                finite = False
            if not finite:
                raise ValueError(f"invalid {label} value at {index}")

def mean_squared_error(actual, predicted):
    validate_pair(actual, predicted)
    squared = [(a - p) ** 2 for a, p in zip(actual, predicted)]
    return math.fsum(squared) / len(squared)

assert mean_squared_error([1, 3], [2, 1]) == 2.5
```

这个实现有一个明确边界：虽然输入各自有限，极端大差值平方仍可能溢出或成为非有限值。若接口要对整个浮点范围提供稳定误差计算，需要进一步的尺度处理与输出有限性检查。教学代码应该说明这种限制，而不是因为加了输入验证就宣称所有数值问题都已解决。后续数值方法会系统处理这些情况。

组合还有层次上的控制。底层函数不应依赖命令行参数解析对象，也不应在导入时自动运行完整实验。入口负责把外部配置转换成内部清晰参数，再调用计算逻辑。这样的设计让同一功能既能在命令行使用，也能被测试和其他模块调用，不必复制逻辑。第三章会进一步讨论脚本入口与外部文件。

<a id="sec-6"></a>
## 6. 进阶：迭代器协议与有状态接口

类、闭包和生成器都能保存跨调用状态，但它们暴露状态的方式不同。类通常提供多个方法，适合拟合、变换、重置、导出等多种操作；闭包把少量环境封装在一个或几个函数里，适合局部策略；生成器围绕一个推进流程保存状态，适合数据流。若需求只有一次计算，三者都可能不如普通函数简单。

有状态接口需要定义重置与复用。一个累计器的 add 是累积，reset 是清空；一个拟合器的 fit 可能覆盖此前状态。若同一个方法有时累积、有时覆盖，调用者就很难推理。进一步还要说明多个消费者是否共享进度：两个名字引用同一迭代器时，交替取值会共同推进；对一个可重复容器分别获取迭代器，则通常各自推进。

调用顺序构成对象状态机。未拟合时 transform 不允许；拟合后允许变换；重新拟合会替换统计量；若关闭资源后再调用读取，应给出明确失败。可以画出状态与合法操作，而不必为了状态机立刻引入复杂设计模式。只要把状态集合与转移说明白，就能发现某些含糊路径，例如拟合到一半失败后旧模型到底还有效吗。

异常安全在这里尤其重要。若 fit 遍历数据途中失败，而已经改写一半内部统计量，对象可能既不是旧模型也不是新模型。可以先在局部变量或临时累计器中完成拟合，验证成功后再一次性替换公开使用的状态。对于这个进程内数值对象，这能提供清晰失败语义；若多个线程同时操作，还需要同步策略，不能直接套用。

<a id="sec-6-1"></a>
### 可变默认参数与迭代器耗尽的共同根源

二者共同提醒你关注对象生命周期。默认参数对象在定义阶段建立并被函数保留，连续调用可能访问同一个对象；迭代器在创建后保留当前位置，连续消费访问同一个进度状态。错误都来自把持久对象误以为每次调用自动重建，但具体修复不同：默认参数可在调用时建立新容器，迭代器可由工厂重新创建或明确物化。

默认使用空值只是常见技巧，不是普遍正确答案。如果空值本来就是合法且需要与“未提供”区分的输入，可以使用独立哨兵。若确实希望有意共享缓存，也可以明确建立共享对象，但需要键、清理、并发与测试策略。不要把“可变默认参数通常危险”误读成“函数永远不能接收可变对象”或“任何默认可变对象都必然错误”。

生成器也不适合靠深复制获得新的独立进度。它可能保存局部变量、外部资源和解释器执行状态，复制语义远比普通列表复杂。一般数据处理选择重新建立读取流程或保存已经读取的数据。若数据源本身不可重读，需要承认这一限制，并在第一次读取时同时完成所有必要统计，或建立明确的持久缓存。

<a id="sec-7"></a>
## 7. 分层练习与参考解析

**练习一：找出隐藏依赖。** 一个函数只接收样本，却读取模块全局阈值和随机数源。它的真实依赖是什么？解析：至少还有阈值、随机状态与可能的全局配置版本。把它们显式传入，可以重现实验并隔离调用，但若传入的是可变随机数源，函数仍会推进该状态。需要说明推进行为，而不是只改参数列表就宣布纯函数化。

**练习二：修改参数与重新绑定。** 函数里先把参数名赋成新列表，调用方原列表是否改变？如果改为对参数列表追加元素呢？解析：前者只改变局部绑定，后者修改共享对象。再增加一个别名作为调用方观察入口，能更清楚地区分。正确答案应提到对象关系，不只是背“按引用传递”或“按值传递”的模糊口号。

**练习三：平均函数的输入域。** 先检查空值，再两遍遍历验证与求和的函数，能否直接接收任意生成器？解析：不能由当前实现保证。生成器的真假也不代表有没有元素，且第二次遍历可能已经耗尽。若需要一般迭代输入，应一次累计总和与计数，并在结束后判断计数，或明确先物化。输入域变化会影响内存与异常时机。

**练习四：构造失败时的对象状态。** 拟合函数已经更新均值，随后计算尺度失败。该对象能否继续用于变换？解析：若没有明确设计，状态可能不一致。推荐先在局部完成候选均值与尺度，再统一提交；失败时保留旧状态，或明确将对象标为不可用。两种策略均可，但调用者需要知道采用哪种。

<a id="sec-7-1"></a>
### 边界追问：生成器重复消费为什么变空

生成器不是保存所有结果的容器，而是带位置的执行过程。第一次完整遍历后，它已经到达结束状态，第二次遍历自然没有新值。如果第二次才创建新的生成器对象，则会重新执行函数体，但输出是否一样还取决于底层数据、随机性和外部环境。不要把“能够重建过程”与“数据内容固定”合并成同一个保证。

还要检查部分消费：先取两个值，再转成列表，只会得到剩余值，不会包含先前两个。若多个函数共享同一生成器，一个函数的预览会影响另一个函数的输入。可以把消费权集中在一个调用者，或明确复制已物化的数据。后续流式接口章节会展示如何把验证与批处理时机写得更清楚。

## 8. 完整案例：训练集拟合与验证集变换

我们实现一个一维标准化器。训练阶段估计均值与尺度，之后用同一组统计量变换训练、验证和预测数据。对训练样本 x，变换是减去训练均值，再除以训练标准差。这里采用总体方差分母 n，而不是无偏样本方差分母 n 减一，因为目标是定义当前训练数据的缩放规则；这个选择不等于声称两种方差估计在所有统计问题中等价。

常数训练列需要明确约定。若所有值相同，标准差为零，直接除法无定义。数值计算得到零方差也可能源于极小的非零偏差平方下溢，不能反推原列恒定；本例会对这种非恒定列明确失败并保留旧状态。本例把尺度约定为一，因此训练列变成全零，新数据仍表示相对训练常数的偏移。另一种做法是删除常数特征，或使用专门标记，但必须一致应用于训练与预测。不要在除法里随手加一个极小数，就假装没有改变尺度解释。

验证数据不能参与拟合。假设训练值是负一和正一，训练均值零、尺度一；验证值为三，变换后仍是三。如果把验证值加入拟合，均值与尺度会改变，验证分布的信息便进入预处理。即使没有用验证标签，也可能让评估协议发生偏移。对时间切分或部署变化尤其要严格保持阶段边界。

下面代码将验证、拟合和变换分开。拟合先建立本地候选统计量，全部成功之后才提交对象状态。空拟合数据被拒绝；变换空数据允许返回空列表，因为应用阶段可以合法遇到一个空批次。输入只支持有限内置整数与浮点数，极端数值导致的中间溢出会显式失败，而不是悄悄保存无效尺度。为保持示例聚焦，我们处理一维序列，多维扩展留给 NumPy 章节。

```python
import math

def checked_values(values):
    result = list(values)
    for index, value in enumerate(result):
        if type(value) not in (int, float):
            raise TypeError(f"unsupported value at {index}")
        try:
            finite = math.isfinite(value)
        except OverflowError:
            raise ValueError(f"value at {index} is too large") from None
        if not finite:
            raise ValueError(f"non-finite value at {index}")
    return result

class Standardizer:
    def __init__(self):
        self._state = None

    def fit(self, values):
        data = checked_values(values)
        if not data:
            raise ValueError("cannot fit empty data")
        try:
            mean = math.fsum(data) / len(data)
            variance = math.fsum((value - mean) ** 2 for value in data) / len(data)
            scale = math.sqrt(variance)
        except (OverflowError, ValueError):
            raise ValueError("statistics exceed supported numeric range") from None
        if not math.isfinite(mean) or not math.isfinite(scale):
            raise ValueError("statistics must be finite")
        if scale == 0:
            if any(value != data[0] for value in data):
                raise ValueError("nonconstant variance underflowed to zero")
            scale = 1.0
        self._state = (mean, scale, len(data))
        return self

    def transform(self, values):
        if self._state is None:
            raise RuntimeError("fit must be called first")
        data = checked_values(values)
        mean, scale, _ = self._state
        result = [(value - mean) / scale for value in data]
        if not all(math.isfinite(value) for value in result):
            raise ValueError("transformed values must be finite")
        return result

    def summary(self):
        if self._state is None:
            raise RuntimeError("fit must be called first")
        mean, scale, count = self._state
        return {"mean": mean, "scale": scale, "count": count}

train = [-1.0, 1.0]
validation = [3.0]
normalizer = Standardizer()
normalizer.fit(train)
assert normalizer.transform(train) == [-1.0, 1.0]
assert normalizer.transform(validation) == [3.0]
assert normalizer.transform([]) == []
assert train == [-1.0, 1.0]
old_summary = normalizer.summary()
try:
    normalizer.fit([float("nan")])
except ValueError:
    pass
else:
    raise AssertionError("invalid fit should fail")
assert normalizer.summary() == old_summary
try:
    normalizer.fit([-1e-200, 1e-200])
except ValueError:
    pass
else:
    raise AssertionError("nonconstant underflow should fail")
assert normalizer.summary() == old_summary

constant = Standardizer().fit([4.0, 4.0])
assert constant.transform([4.0, 6.0]) == [0.0, 2.0]
unfitted = Standardizer()
try:
    unfitted.transform([1.0])
except RuntimeError:
    pass
else:
    raise AssertionError("unfitted transform should fail")
```

对象把均值、尺度和计数保存在同一个不可变元组状态中，便于在成功之后整体替换。摘要返回新字典，修改摘要字典不会改变内部元组。这不是防恶意访问的安全隔离，调用者仍可以绕过命名约定；它是合理使用下的清晰接口。真正需要跨线程同步时，还要讨论并发读写，不应把单次引用替换当作整套线程安全证明。

失败语义在这里值得逐步核对。非法拟合输入会在提交前失败，因此旧拟合状态保留；未拟合变换会先检查阶段，给出明确错误；非法变换输入不会改变拟合统计量；返回结果是新的数值列表，不改变原序列。这样的四项保证比一句“实现了标准化”更容易检查，也更能指导调用者如何恢复。

为什么 fit 返回对象自身？这样可以写构造后立即拟合的链式调用。但这只是接口约定，不是 Python 规定。原地更新方法也可以返回空值，重要的是一致性与文档。不要假设所有叫 fit 的方法都返回同类对象，也不要在不知道返回值语义时无脑串联调用。框架之间接口相似不代表细节完全相同。

当输入是生成器时，checked_values 会把它物化为列表。这是有意设计，使拟合能够多次访问数据并统一验证；代价是额外线性内存。因此这个标准化器不是严格流式拟合。下一节会推导一遍统计，但即使在线拟合只保存少量状态，若后面还要变换全部训练样本，仍需重读数据或保存数据。算法阶段的需求不能靠一个在线公式全部消除。

多维扩展需要新增形状契约：每行特征数一致、每列单独统计、缺失值如何处理、常数列如何标记，以及样本轴在哪里。不要直接用嵌套循环把一维代码照搬，然后忽略轴的意义。标准化对象还应该记录特征顺序或名称，避免训练与预测列顺序变化。这里的接口思想会直接迁移到数组和表格处理中。

<a id="sec-9"></a>
## 9. 在线统计：从公式推导状态更新

一次性数据可以直接求和再除以数量，但流式数据可能不能全部保留。我们希望只维护数量、均值和离均差平方和，逐个更新统计量。这个问题既是算法设计，也是对象状态设计：每个字段都有明确数学含义，更新必须共同保持不变式。只会写一个类而不理解这三个字段的关系，仍容易得到错误方差。

设已经处理 n 个值，均值是 m；新值是 x。新的均值等于旧总和加 x 后除以 n 加一。把旧总和写成 n 乘 m，再整理，就得到新均值等于 m 加上 x 与 m 的差再除以新数量。这个形式不需要保存旧总和，也比每次重新扫描历史数据高效。初始数量零时，第一个值自然把均值更新为自身。

离均差平方和记为 M2，即全部已见值相对当前均值的平方偏差之和。新值到来后，旧样本的参照均值也改变了，所以不能只把新值对旧均值的平方差直接加进去。展开旧样本对新均值的平方项，利用旧样本偏差之和为零，可以得到更新增量等于“新值减旧均值”乘以“新值减新均值”。这一步同时补偿了旧样本参照中心的移动。

因此一次更新依次计算差值、候选新均值、候选新平方和，再提交数量、均值和平方和。总体方差为 M2 除以 n，样本方差为 M2 除以 n 减一，后者需要至少两个样本。没有数据时均值和方差都未定义；一个样本的总体方差为零，但无偏样本方差仍未定义。不同分母对应不同问题，不应靠程序有没有除零来决定统计含义。

下面实现接受有限内置数值，范围过大导致候选状态非有限时会拒绝更新。浮点舍入可能让理论上非负的平方和出现很小负值，读取方差时用零下限防止微小舍入产生负方差；这不是修复明显数值发散的方法。正式数值库可能采用更细致策略，本例强调推导与状态契约。

```python
import math

class OnlineMoments:
    def __init__(self):
        self._count = 0
        self._mean = 0.0
        self._m2 = 0.0

    def add(self, value):
        if type(value) not in (int, float):
            raise TypeError("expected int or float")
        try:
            if not math.isfinite(value):
                raise ValueError("expected finite value")
            count = self._count + 1
            delta = value - self._mean
            mean = self._mean + delta / count
            m2 = self._m2 + delta * (value - mean)
            if not math.isfinite(mean) or not math.isfinite(m2):
                raise ValueError("update exceeds supported numeric range")
        except OverflowError:
            raise ValueError("update exceeds supported numeric range") from None
        self._count, self._mean, self._m2 = count, mean, m2

    def summary(self, *, sample=False):
        minimum = 2 if sample else 1
        if self._count < minimum:
            raise ValueError("not enough observations")
        denominator = self._count - 1 if sample else self._count
        return {
            "count": self._count,
            "mean": self._mean,
            "variance": max(self._m2, 0.0) / denominator,
        }

moments = OnlineMoments()
for value in [1.0, 2.0, 3.0]:
    moments.add(value)
population = moments.summary()
sample = moments.summary(sample=True)
assert population["count"] == 3
assert population["mean"] == 2.0
assert math.isclose(population["variance"], 2.0 / 3.0)
assert sample["variance"] == 1.0
before = moments.summary()
try:
    moments.add(float("inf"))
except ValueError:
    pass
else:
    raise AssertionError("invalid update should fail")
assert moments.summary() == before
```

手算三次更新：第一个值一使数量一、均值一、平方和零；第二个值二的旧差值为一，新均值一点五，新平方和零点五；第三个值三的旧差值一点五，新均值二，增量一点五，最终平方和二。总体方差二除以三，样本方差二除以二。这个小算例可以逐字段对照代码，避免把公式当作无法解释的记忆片段。

直接用“平方的平均减去均值的平方”计算方差，在数据均值很大但波动很小时，可能发生严重相消。在线中心化更新往往改善这种情况，但仍不是无限精度保证。若数据尺度超出浮点可表示范围或输入已丢失低位，任何普通双精度算法都不可能恢复不存在的信息。数值方法章节会进一步讨论稳定性，这里要能区分公式代数等价与有限精度实现差异。

在线算法的好处是一次遍历、常量级统计状态；不足是默认不能恢复每个历史值，也不能直接回答中位数等需要更多分布信息的问题。想得到分位数，需要保存数据、近似摘要或其他结构。选择状态时应从需要回答的问题反推，不能因为均值方差可以在线计算，就推断所有统计量都能靠三个字段精确维护。

<a id="sec-9-1"></a>
### 把更新式和合并式写成可逐项核对的数学关系

为了避免只凭文字记忆，把数量、均值和平方和分别记作 $`n,m,M_2`$。新样本为 $`x`$，令 $`\delta=x-m`$，则候选状态满足：

$$
\begin{aligned}
n' &=n+1,\\[6pt]
m' &=m+\frac{\delta}{n'},\\[6pt]
M_2' &=M_2+\delta(x-m').
\end{aligned}
$$

推导平方和更新时，旧样本相对新均值的差等于“相对旧均值的差”再减去均值移动量。展开平方并求和，交叉项含旧偏差之和，因此消失；剩余旧样本的中心移动贡献，再与新样本平方偏差合并，就得到上式。这里消失的是精确算术下的偏差和，机器计算可能只有近似零，这也是数值结果需要容差比较的原因。

若两批分别有状态 $`(n_A,m_A,M_A)`$ 与 $`(n_B,m_B,M_B)`$，两批均非空，令 $`N=n_A+n_B`$、$`d=m_B-m_A`$，合并式是：

$$
\begin{aligned}
m &=m_A+d\frac{n_B}{N},\\[6pt]
M &=M_A+M_B+d^2\frac{n_A n_B}{N}.
\end{aligned}
$$

最后一项不能省略，因为它表示两组中心不同造成的组间离散程度。假设第一批只有一和三，第二批只有五和七：两批数量都为二，均值分别二与六，内部平方和都为二；合并均值四，组间项为十六，合并平方和二十。直接对一、三、五、七相对四的偏差平方求和，得到九加一加一加九，确实也是二十。若只相加两批内部平方和，就只剩四，严重低估总体方差。

空批不能直接代入含未定义均值的公式，应该把它视为不改变已有状态的单位情形。合并许多批时，精确算术下分组顺序不改变数学结果，浮点运算下不同合并顺序可能产生细微差异。并行计算报告应说明容差与归约策略，不能仅因最后几位不同就断言算法错误，也不能把明显差异都归咎于浮点。先做这个四元素手算，再扩大实验规模，更容易识别公式、实现和精度三个层次的问题。

在线累计器还可以扩展到非负权重，但应先定义权重含义。设已累计总权重为 W，新样本 x 的权重为 w；当 w 为正时，新均值等于旧均值加上“新样本减旧均值”乘以 w 除以新总权重。这里保存的不再只是整数样本数，而是总权重；如果还需要报告实际记录条数，应另存计数，不能把两个量混用。

加权离均差平方和也有对应更新：先计算旧差值，再更新均值，最后把“权重乘旧差值乘新样本对新均值的差”加入原平方和。它与前面无权公式结构一致，但对象不变式已经改变：平方和解释为每个偏差平方乘相应权重之后求和。接口与摘要字段应该体现这种变化，不能只在 add 里多乘一个数，其余说明仍沿用普通样本含义。

手算一个例子：先接收数值二、权重一，再接收数值十、权重三。总权重四，加权均值八；第二步旧差值八，新均值八，因此平方和增加三乘八乘二，得到四十八，按总权重定义的方差为十二。若这些权重表示重复次数，与直接处理序列 [2, 10, 10, 10] 相同。

权重零可以定义为不影响统计状态，但是否仍验证该记录，需要契约决定；负权重则不属于本节普通加权方差的输入域。非有限权重必须拒绝。第一次接收正权重前，总权重为零，均值仍未定义；连续接收零权重不能假装已经拟合成功。失败之前应先计算候选状态，确保非法权重不会污染已有累计量。

频数权重、重要性权重与可靠性权重不具有完全相同的统计解释。尤其是样本方差的无偏修正，不能对所有加权情形都机械采用总权重减一。若只是定义一个加权总体描述量，除以总权重很直接；若要做总体推断，需要额外说明抽样机制与估计目标。程序接口里的 sample 开关不足以自动表达所有这些选择。

这个扩展展示类接口设计的一般方法：先为新状态写数学含义，再推导保持关系，然后规定输入、失败与摘要，最后才增加方法参数。若扩展使旧方法含义改变过大，建立独立加权累计器可能更清楚。复用几行更新代码不是首要目标，让调用者能预测行为和解释结果才是。

## 10. 流式批处理：验证时机、消费与错误传播

上一章用切片对序列分批，需要随机访问和长度。本节改为接收一般可迭代对象，一次读取一个元素，缓冲到批量大小时产生一批，最后剩余不足一批也保留。这样无需预先知道总长度，适用于生成器或逐行数据。除当前批次外不保存全部输出，但上游或下游是否物化，仍由它们自己的实现决定。

这里有一个容易忽略的设计：如果整个分批函数本身含产生值语句，参数验证也会被推迟到第一次消费。调用者创建批次流时传入非法大小，却暂时不报错，可能难以定位。可以让外层普通函数立即检查配置，再返回内部生成器。这样配置错误在创建时暴露，数据读取错误则仍在消费时暴露，两种时机都有明确理由。

```python
def iter_batches(source, size):
    if type(size) is not int or size <= 0:
        raise ValueError("size must be a positive integer")

    def generate():
        batch = []
        for item in source:
            batch.append(item)
            if len(batch) == size:
                yield batch
                batch = []
        if batch:
            yield batch

    return generate()

source = (value * 2 for value in range(5))
batches = list(iter_batches(source, 2))
assert batches == [[0, 2], [4, 6], [8]]
assert len({id(batch) for batch in batches}) == 3
assert list(source) == []
try:
    iter_batches([1, 2], 0)
except ValueError:
    pass
else:
    raise AssertionError("invalid size should fail immediately")
```

为什么产生一批后要重新建立列表，而不是清空同一个列表继续复用？因为消费者可能保存已经收到的批次。如果反复产生同一列表再原地清空，之前保存的批次也会变化，最终可能全部指向相同对象。重新绑定 batch 到新列表，已经交出去的列表仍保持原内容。这正是对象图模型在流式接口中的直接应用。

输入本身是可迭代对象，不代表每个元素都满足后续数值要求。分批函数只负责边界，不应顺便悄悄删除非法样本；数值验证可以作为单独阶段。若某条非法记录使后续处理失败，已经消费的输入通常无法自动放回。对于可恢复系统，应保存数据位置或使用可重放源；对一次性流，需要明确部分处理的结果是否可用。

提前停止时，分批生成器不一定拥有上游资源。上游可能是调用者共享的迭代器，也可能在外层上下文中管理文件。本函数没有擅自关闭它，这个选择应写入契约。如果你设计一个自己打开文件的数据源，则应为它提供可靠的上下文与关闭路径。不要无差别地让每个包装层都关闭上游，否则多个消费者会相互干扰。

惰性流还会放大顺序错误。假设清洗函数统计合法数，分批函数控制数量，训练函数更新模型：在数据中途失败时，模型已经发生部分更新。需要完整失败重试时，应从检查点恢复，而不是简单从头重跑并在同一个半更新模型上再次训练。语言层生成器只负责推进执行，不为业务操作提供幂等性。

## 11. 接口比较：函数、闭包、类与生成器

四种形式都能表达计算，但适用的生命周期不同。普通函数强调一次调用的输入输出；闭包保留局部配置，适合创建小型专用函数；类为同一状态提供多个相关操作；生成器把一次长流程拆成逐步消费。比较方案时，先问状态需要活多久、谁能修改、是否需要重置和导出，而不是先决定使用哪一种语法。

| 形式 | 典型优势 | 应特别说明的边界 | 本章中的合适用途 |
| --- | --- | --- | --- |
| 普通函数 | 输入输出直接、便于组合 | 副作用、空输入、错误类型 | 指标计算、字段校验 |
| 闭包 | 封装少量局部配置 | 捕获对象可变性、取值时机 | 固定阈值的小型策略 |
| 类 | 状态阶段与多种操作清晰 | 拟合、重置、失败后状态 | 标准化器、在线累计器 |
| 生成器 | 渐进产生、减少中间物化 | 一次性消费、资源与异常时机 | 流式分批、逐行转换 |

闭包很适合固定一个阈值，返回判断函数。例如构造器接收阈值后，返回一个对分数判定是否通过的函数。若阈值是不可变数值，行为相对直观；若捕获一个可变配置字典，外部改字典就可能改变函数行为。闭包不是天然只读配置，仍要检查对象关系。第六章会进一步说明名字捕获与后绑定机制。

类的优势在于明确阶段。标准化器可以提供拟合、变换和摘要，而不需要让每个函数都携带同一组均值与尺度参数。但它也更容易被不小心复用：同一个对象在另一数据集上重新拟合，会改变后续所有变换。若多个实验需要独立处理器，应分别创建对象，不能只用两个名字引用同一个实例。是否复制已有拟合状态，也应有明确接口。

生成器则围绕消费组织操作。如果你的接口需要随时查询当前统计量、重置、导出并继续，类通常比双向发送生成器容易读；如果只需要不断读取下一批数据，生成器比自写复杂迭代器类更简洁。高级能力不代表应在每个位置使用它，最小足够机制往往最容易验证。

还可以采用组合：普通函数验证字段，类保存拟合统计，生成器逐批读取，再由入口驱动完整流程。每个组件都只暴露必要能力，错误从能解释它的位置传播。这样的结构既保留了函数的可测试性，也承认训练与数据流中的状态存在，不需要把所有东西强行变成同一种抽象。

## 12. 综合实践、研究问题与参考资料

**综合任务一：标准化器的失败契约。** 给标准化器补一组边界实验：未拟合调用、空拟合、常数列、非法字符串、非有限输入、成功拟合后再次非法拟合。每次记录预期异常类型及对象摘要是否变化。解析路线是先列状态，再为每种输入确定转移；成功拟合进入已拟合状态，失败拟合保留原状态，变换不改状态。若实现与这张表不一致，先修接口或代码，不要只改断言去迎合结果。

进一步检查摘要是否泄漏可变内部状态。在本章实现中，摘要是新字典，数值字段不可变，修改它不影响对象。若未来摘要包含内部可变列表，原结论就需要重新审查。验收应实际修改返回摘要中的可变字段，并观察处理器后续行为。单纯检查返回对象不是同一个字典，不足以证明所有深度独立。

**综合任务二：在线与批量统计对照。** 使用同一组温和尺度数值，比较在线均值方差与两遍计算结果，允许合理浮点容差。然后构造均值很大而波动较小的数据，比较直接平方均值相减公式与中心化公式。解析应区分代数等价、舍入误差与输入表示本身的精度限制；不能只看到某次在线结果更接近就宣称它对任意输入无条件最优。

再提出分块合并问题：两个批次分别有数量、均值和离均差平方和，怎样得到合并统计？合并均值按数量加权，平方和除了两边内部平方和，还要加上两批均值差异产生的组间项，其系数与两边数量乘积除以总数量有关。推导时把每个样本相对合并均值的差拆成相对本组均值的差与组均值偏移，交叉项因组内偏差和为零而消失。这为并行统计建立了基础。

**综合任务三：流式批次的保真性。** 对不同长度与批量大小验证，按顺序展开全部批次后恰好还原输入。检查空输入、大小一、大小大于样本数、恰好整除和不足最后一批。解析的不变式是：已经产生的完整批次与当前缓冲区连接起来，等于已消费前缀；缓冲区长度始终小于批量大小，产生批次时恰好达到大小。终止时把非空缓冲交出，即得到完整覆盖。

接着故意把重新建立 batch 改成清空原列表，保存所有结果后观察变化，解释别名错误。这种反例练习比只记正确写法更有价值，因为它连接了引用共享与惰性执行。还可以让上游在第三条抛出异常，记录下游已经拿到了哪些批次，说明异常并不会撤销已经产生的结果。

**研究问题：如何选择接口的严格程度？** 严格函数拒绝所有字符串，宽松函数尝试转换；严格拟合器拒绝空输入，宽松拟合器可能保留旧状态。比较两种设计在数据接入、错误定位和复现上的代价。合理答案不必一致，但必须明确每个失败输入的结果与状态转移。宽松不是随便吞错，严格也不是对用户毫无信息地崩溃。

**研究问题：能否让训练与验证误用更难发生？** 可以把拟合统计量导出成只读状态，再用一个只提供变换的对象交给验证流程；也可以让接口明确区分拟合型和已拟合型对象。这样的设计增加结构，却减少在验证环节意外重新拟合的机会。是否值得取决于项目规模和误用风险，但它展示了接口设计如何支持实验方法，而不只是组织语法。

本章完成后，应能独立说明一个函数的完整契约，识别隐藏状态，为有生命周期的数据设计对象，推导在线更新，并解释生成器的消费与失败时机。继续阅读文件与异常章节时，重点观察这些接口边界怎样延伸到外部资源。后续数组、表格和训练框架章节会重复出现同样问题，只是数据规模与形状更加复杂。
