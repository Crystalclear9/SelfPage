## 1. 从输出需求选择算法

处理大量数据时，最重要的问题常常不是如何把已有程序向量化，而是到底需要输出什么。如果只要最大的一百条，完整排序可能维护了过多信息；如果只要每组均值，不必保存每个原始观测；如果要求全部两两距离，输出本身已是平方规模，分块只能降低峰值内存，不能消除输出数量。

本章围绕三个问题展开：怎样用少量状态得到精确 Top-k，怎样在向量检索中区分精确与近似，以及怎样把数据量超过内存的问题转为可合并或多遍处理。核心线索是输出契约、比较规则、可合并性与误差保证，而不是某个库函数的名字。

<a id="deep-dive-1"></a>

<a id="algo-4-detail-2"></a>

### 1.1 候选正确、有序输出和稳定身份是不同要求

Top-k 可以只要求返回最大的值集合，也可以要求按降序返回，还可以要求同分优先较早记录、按唯一编号决定顺序或保留全部并列项。这些契约不等价。一个大小为 k 的堆只维护候选集合，不直接给出完整排序；如果要求有序，最后还要对候选排序。

若要求“包括第 k 名的全部同分”，输出可能远大于 k，最坏情况下所有记录都同分，不能仍承诺只用 k 个输出槽位。若要求恰好 k 个，应定义完整同分规则，避免分块、重试或输入顺序变化导致结果身份不可复现。

排序键还要具有一致比较语义。NaN 不符合普通全序直觉，字符串与数值混合、不可比较的负载对象也可能让堆在某些同分时失败。应先验证和规范化键，不要让某次碰巧没有同分的实验掩盖接口缺陷。

<a id="algo-4-detail-3"></a>

### 1.2 三种成本要分别估算

算法成本至少包括读入、计算与输出。流式堆降低候选维护成本与内存，却仍要读取每个未被索引排除的记录；分块矩阵乘法降低内存，却仍要执行距离计算；外部排序减少随机访问，却可能进行多遍完整读写。

对于向量检索，还应分开索引训练、构建、更新与查询。一个查询很快但构建需要大量时间和内存的索引，适合查询很多次且数据库稳定的场景，不一定适合频繁变化的小库。应按实际查询量摊销成本，而不是只展示一次最短查询。

计算机系统章节会进一步讨论设备带宽与流水线，本章主要建立算法层资源账本。渐近复杂度给出规模趋势，实际测量则用于判断常数、数据分布和内存访问是否改变方案选择。两者都不能替代另一个。

### 图解：Top-k 堆根保存当前门槛

![Top-k 堆根保存当前门槛](images/04-concept.svg)

**图解。** 初始候选是 {8,9}，随后连续读取 1、8.5、10：1 不超过门槛 8，被丢弃；8.5 替换 8，门槛于是升到 8.5；10 接下来淘汰的是新门槛 8.5，最终留下 {9,10}。三行是同一条执行轨迹，不能每次都用初始门槛解释后续输入。

此例采用严格大于门槛才替换的值排序规则。最小堆只保证根最小；展示前二名的降序列表仍需排序。同分时若还要求稳定身份，应把相应规则纳入比较键。参见 [Python heapq 文档](https://docs.python.org/3/library/heapq.html)。

保存最大 k 项时采用最小堆，让根成为当前最差候选。新记录一到来后先与当前堆根比较，未超过当前门槛就丢弃；无条件替换根会错误删除更好的候选。

堆只组织候选的局部顺序，不是完整排名。稳定同分规则也必须进入维护键，不能等最终输出时再补；若目标改成实体聚合排名，还需先重新定义记录贡献。

## 2. 堆的不变量与构建代价

<a id="algo-4-detail-5"></a>

### 2.1 最小堆只约束父子关系

在从零开始的数组表示中，位置 i 的两个孩子为二 i 加一与二 i 加二。最小堆要求父键不大于存在的孩子键，沿树向下递推可知根是全体最小值。但同层兄弟与不同子树之间没有完整次序，整个数组并非升序列表。

插入新元素时，把它放到末尾并沿祖先上浮；弹出根时，把末尾元素移到根再向下恢复。树高为对数级，因此单次维护通常为 $`O(\log n)`$。这里依赖键比较成本有界；若比较长字符串或复杂对象，应计入键构造与比较代价。

堆适合维护当前极值并动态增删，不适合直接支持任意次序统计或快速按键查找。若需要频繁修改某个已存在元素的优先级，需要位置映射、版本标记或其他结构。不能只在数组中找到元素改值，却不恢复堆不变量。

<a id="algo-4-detail-6"></a>

### 2.2 自底向上建堆为什么是线性

把每个元素逐个插入，最坏可花 $`O(n\log n)`$；自底向上从最后非叶节点开始下沉，整体只需线性工作。证明不能简单用节点数乘最大高度，因为大多数节点靠近叶子，下沉距离很短。

高度至少为 h 的节点数量约按 $`\frac{n}{2^h}`$ 下降，所以总下沉工作可界为 $`n\sum_{h\geq1}\frac{h}{2^h}`$ 的常数倍，级数收敛，因此为 $`O(n)`$。这展示摊开不同层工作量的重要性：最大单节点成本不一定代表所有节点都付同样成本。

如果实现每次下沉又重新计算复杂键，线性比较次数也不意味着总字节处理线性。可以预先计算比较键并与记录身份一起保存，但这会增加内存。算法证明要说明单位操作，工程实现要说明缓存哪些派生值。

<a id="sec-8-2"></a>

<a id="algo-4-detail-7"></a>

### 2.3 堆数组为什么不能直接当有序答案

例如数组一、三、二、七、八、四满足最小堆关系，却不是升序，因为三排在二之前。反复弹出堆顶能得到升序，但会消耗堆；对副本排序可保留原堆，但需要额外工作。选择哪种方式取决于后续是否继续更新。

最大 k 候选的最小堆中，根代表保留者里最弱的门槛，正适合判断新记录是否值得替换。它不是全局第一个输出应显示的最大值。把堆根误当成最大候选，是混淆“用最小堆保留最大集合”这一技巧的常见错误。

因此测试应分别验证候选身份与展示顺序。集合正确但顺序错误，可能影响后续截断、用户展示或排名指标；顺序看起来正常但同分身份不符合契约，也会影响可复现比较。

## 3. 流式 Top-k 的证明与稳定键

<a id="sec-6-1"></a>

<a id="algo-4-detail-9"></a>

### 3.1 前缀不变量与替换规则

设比较键越大越好，读完前 t 条记录后，堆保存这段前缀中最大的至多 k 项。未满时全部加入；已满时，若新键不大于堆根，它已有至少 k 个不差于自己的候选，无需保留；若更大，则替换最弱者。

归纳证明很直接：未满时不丢任何记录；满后新记录若不够好，原最大 k 集合仍正确；若足够好，旧最弱者恰好是应被淘汰的一项。使用完整全序键时同分也有确定结果，不必在证明中含糊地说随便保留某些值。

如果 k 是正整数，维护时间常写为 $`O(n\log k)`$，但在 k 为一时应理解每项常数比较，总时间为线性；更稳妥可写 $`O(n\log(k+1))`$。最后排序候选还需 $`O(k\log k)`$，实际候选数取 k 与输入长度的较小者。

<a id="sec-1-1"></a>

<a id="algo-4-detail-10"></a>

### 3.2 手算稳定前二

记录分数依次为三、一、五、二、四，保留最大二项。前两项门槛为一，五进入后门槛升到三，二被拒绝，四替换三，最后保留五与四。门槛在堆满后不会下降，这是另一个可以检查的不变量。

若分数五再次出现且要求同分优先较早编号，可以使用“分数、负编号”作为越大越好的键。较小编号的负数更大，所以被优先保留。方向必须与堆根代表最弱者的约定一致；直接用正编号会偏好较晚记录。

负载本身可能是字典，不能参与元组同分比较。只要唯一编号保证比较在负载之前已经分出次序，就不会落到不可比较对象；若编号不唯一，则仍可能失败。唯一性是稳定键契约的一部分，不是可省略的装饰字段。

<a id="algo-4-detail-11"></a>

### 3.3 自足实现与分块一致性检查

下面明确要求分数有限、编号唯一且为整数。函数在流式处理时只保存候选，不为检查所有编号而额外保存全体身份；测试输入负责满足全局唯一契约。若生产数据无法保证唯一，需要独立去重或身份验证流程，不能一面承诺严格 k 空间，一面隐式保存 n 个编号。

```python
import heapq
import math
from random import Random

def top_k(records, k):
    if type(k) is not int or k < 0:
        raise ValueError("k must be a nonnegative integer")
    heap = []
    for score, ident, payload in records:
        if not math.isfinite(score) or type(ident) is not int:
            raise ValueError("finite scores and integer unique IDs required")
        if k == 0:
            continue
        entry = (score, -ident, ident, payload)
        if len(heap) < k:
            heapq.heappush(heap, entry)
        elif entry[:2] > heap[0][:2]:
            heapq.heapreplace(heap, entry)
    return [(score, ident, payload)
            for score, neg_id, ident, payload in sorted(heap, reverse=True)]

rng = Random(43)
records = [(rng.randrange(6), i, {"source": i % 3}) for i in range(83)]
for k in [0, 1, 7, 83, 100]:
    expected = sorted(records, key=lambda row: (row[0], -row[1]),
                      reverse=True)[:k]
    assert top_k(iter(records), k) == expected
    chunks = [records[:2], records[2:37], records[37:]]
    candidates = [row for chunk in chunks for row in top_k(chunk, k)]
    assert top_k(candidates, k) == expected
assert top_k([(5, 0, {}), (5, 1, {}), (4, 2, {})], 1)[0][1] == 0
print("streaming and partitioned top-k agree with stable full sorting")
```

<a id="algo-4-detail-12"></a>

### 3.4 接口边界与惰性更新

例子里 k 为零仍验证每条输入但不保存候选，属于明确的接口选择；另一种实现可以立即返回而不消费流，应在文档中说明。对于带副作用或只能读取一次的数据源，是否消费输入本身就影响后续程序。

优先队列若需要更新，可以给同一任务加入新版本，并在弹出时丢弃旧版本。这样避免在堆中间直接修改键，但过期条目会占内存，可能需要在旧条目过多时重建。逻辑任务数小，不代表底层堆一定同样小。

并发共享堆还需要同步，不应把标准库的普通堆操作自动当作跨线程原子事务。若多个操作共同维护字典与堆的一致性，锁必须覆盖相应复合不变量。更详细的线程与共享状态分析见计算机系统主题。

## 4. 可合并性：精确成立的条件与反例

<a id="algo-4-detail-14"></a>

### 4.1 分块前 k 为什么足以恢复全局前 k

使用同一完整比较键，把记录划为若干不重叠块。若某条记录没进入其块前 k，则该块内至少有 k 条记录按同一规则更优，它在全局也不可能进入前 k。因此每块保留前 k，再对所有候选取前 k，得到与全量一致的结果。

证明依赖不重叠身份、同一比较规则与同一候选资格。块大小可以不同，合并树顺序也可以不同；空块贡献空集合。对于固定全序和恰好 k 契约，候选压缩操作可以重复进行，支持树状分布式归并。

这不意味着任意“先局部挑选再全局处理”都正确。只要全局目标还包含去重、组约束、过滤或重新评分，局部淘汰可能删掉后来需要的记录。应把这些操作纳入目标，再重新证明局部摘要是否充分。

<a id="algo-4-detail-15"></a>

### 4.2 去重和过滤为什么会破坏简单合并

假设一个块中分数最高的十条都属于同一个实体，另一个实体稍低。若先取十条再按实体去重，就只剩一个实体，原本应该进入全局实体前十的其他实体已经被丢掉。记录级 Top-k 不是实体级 Top-k 的充分摘要。

正确方案可能是在局部先按实体定义聚合键与得分，再维护实体候选；但若同一实体跨块，其全局分数是各块贡献之和，局部低分实体仍可能通过合并变高，单纯各块实体前 k 也未必足够。最大值聚合与总和聚合有不同可合并性质，不能混为一谈。

资格过滤同理。先取全库前 k 再删除不合条件记录，未必得到合条件集合的前 k；应在精确筛选中先应用资格，或者继续检索直到能够证明未检索候选不会进入。近似检索中只增加固定数量候选是一种经验策略，不自动有完整性保证。

<a id="algo-4-detail-16"></a>

### 4.3 重新评分不能复活已经遗漏的候选

很多检索流程先用廉价分数取候选，再用昂贵模型重排。重排能改善候选内部次序，却不能恢复候选集合中不存在的记录。最终结果质量同时受第一阶段候选召回与第二阶段评分质量影响，应分别评价。

若希望给出精确剪枝保证，需要便宜分数提供昂贵最终分数的上界或下界，且当前门槛足以排除未访问记录。没有这种联系时，扩大候选通常有帮助，但不能只凭“重排使用精确模型”就声称全库精确。

![重排只能重新排列已经进入候选的记录](images/04-rerank-candidate-recall.svg)

全库四条记录按最终评分应排为 a、b、c、d，真正的前一名是 a。假设廉价第一阶段只交付 b、c、d，即使第二阶段对这三条采用完全精确的最终分数，最优返回也只能是 b。图中分数只是固定的课堂算例，不代表某个具体索引的召回率。评价时应同时检查候选召回与候选内排序；除非另有可证明的剪枝界，否则“精确重排”不等于“全库精确检索”。

分块局部排序后再重新标准化也会改变原键。比如每块各自计算标准分数再合并，原始分数相同的记录可能获得不同尺度。应固定全局归一化统计或明确新目标，不能把不同块的局部排名数字当作可直接比较的分数。

## 5. 外部排序、多路归并与 I/O 模型

<a id="algo-4-detail-18"></a>

### 5.1 超过内存时先生成有序段

设数据有 N 条记录，内存只能容纳 M 条。可以每次读入不超过 M 条，按固定键排序并写成有序段，再对这些段进行多路归并。最终全局次序由归并维护，不需要一次把全部原始记录载入内存。

这里的 M 是资源预算，而不是简单用空闲内存除以原始文件平均字节。解码后的字符串、对象引用、排序临时区和输出缓冲都可能占额外空间。应按峰值工作集估算段大小，并保留运行环境余量，避免分块读取后在排序阶段再次超限。

同分稳定性可通过全局记录序号进入键保证。若只用块内序号，不同块的同分记录就无法恢复统一原始顺序。排序键还需要保存足够精度与编码规范，序列化再读取后若键改变，归并前提也会失效。

<a id="algo-4-detail-19"></a>

### 5.2 多路归并堆维护的是每段下一个候选

每个有序段只需把当前最小未输出项放入堆。弹出全局最小项后，从它所属段补入下一项。由于每段其余项都不小于当前头，所有可能的下一输出都在这些段头中，堆根因此安全。

![三路归并的段头候选与一次补入](images/04-merge-frontier.svg)

图中三个有序段分别为 A=(1,4,7)、B=(2,5,8)、C=(3,6,9)。开始只比较段头 1、2、3；输出 A 的 1 后，仅从 A 补入 4，候选变为 4、2、3，新的最小项是 B 的 2。图示三个项组成的最小堆是一种合法排列，并不要求同层节点之间有序。实际外存实现还要为输入与输出保留有限缓冲；这幅图展示候选维护过程，不把整段常驻内存作为前提。

归并 N 项、R 个段时，比较维护约为 $`O(N\log R)`$，状态包括每段游标、堆项与输入输出缓冲。若所有段本身已经在内存列表中，这只是在模拟归并逻辑，并没有展示真正的外存内存优势；真实实现需要按块读取的迭代器与有限缓冲。

同时打开的文件数、存储吞吐和每段缓冲大小会限制归并路数。路数越多不一定越快，因为每路缓冲变小会增加 I/O 调度开销。超过资源上限时可分多轮归并，不能以一个巨大的堆取代文件系统与内存限制的分析。

<a id="algo-4-detail-20"></a>

### 5.3 按块传输模型估算遍数

在简化模型中，每块能传 B 条记录，内存 M 条且至少容纳多个块。初始有序段数约为 $`\lceil\frac{N}{M}\rceil`$；为每个输入段保留一块并留一块输出缓冲，可用归并路数约为 $`\lfloor\frac{M}{B}\rfloor-1`$，还应预留堆和元数据。

若实际可用路数为 F 且至少二，每轮把段数缩到原来的约 F 分之一，归并轮数约为初始段数的以 F 为底对数向上取整。初始造段和每轮归并都要完整读写，传输量约为每轮两遍数据。若最后结果直接流给下游，末轮写出可能省去。

这个模型假设顺序块传输成本占主导，不包含压缩、网络、随机访问与故障重算等因素。它帮助比较方案趋势，但不是某块硬盘的实测秒数。报告应同时给出记录字节大小、有效缓冲、轮数和实际传输测量，不把抽象 I/O 次数当成设备速度承诺。

<a id="algo-4-detail-21"></a>

### 5.4 归并也能服务去重与分组聚合

全局按键排序后，相同键记录连续出现，可以流式去重或累计聚合。每块独立去重再直接拼接不够，因为相同键可能跨块；归并恰好提供它们最终相遇的边界。类似思路也用于排序连接，但一对多和多对多连接的输出可能很大。

若某个键对应的数据组超过内存，组内操作仍可能成为瓶颈。求和只需少量状态，输出所有配对可能需要巨大结果，某些复杂聚合还需要保留整组。把数据按键汇合只是必要组织步骤，不能自动消除组内计算与输出规模。

还有哈希分区方案：把相同键送到同一分区，再在分区内处理。它依赖统一哈希与合理负载，热点键可能导致倾斜。排序与哈希各有条件，应依据是否需要顺序、是否存在倾斜、内存预算和可恢复性比较，而不是按习惯固定选择。

## 6. 流式统计：哪些摘要可以合并

<a id="algo-4-detail-23"></a>

### 6.1 均值的充分状态是总和与计数

两块分别有十条、均值二和九十条、均值八，总均值为七点四，而不是五。均值不是按块直接等权可合并的量，应该保存计数与总和，再相加后除总计数。空块不贡献计数，全部为空时均值未定义。

如果权重不是记录数，应保存权重和与加权总和，且说明权重含义。加权质量不自动等于独立样本数量，算法合并正确不代表统计区间可以把权重和当样本数。数据结构只保证代数目标，没有替推断提供额外假设。

总和本身也有浮点误差。不同分块与合并树改变加法顺序，可能得到略不同结果；精确整数求和与浮点求和的性质不同。要求逐位复现时要固定归并顺序或使用相应精确、补偿方法，不能仅凭数学结合律宣称程序结果完全一致。

<a id="algo-4-detail-24"></a>

### 6.2 方差的稳定合并公式

每块保存样本数 n、均值 $`\mu`$ 和中心平方和 $`M_2=\sum_i(x_i-\mu)^2`$。两块 A、B 合并，令 $`\delta=\mu_B-\mu_A`$，总数为 $`n=n_A+n_B`$，则

$$
\begin{aligned}
\mu &=\mu_A+\delta\frac{n_B}{n},\\[6pt]
M_2 &=M_{2,A}+M_{2,B}+\delta^2\frac{n_An_B}{n}.
\end{aligned}
$$

证明可把每块的离差写成相对块均值的离差加均值偏移，块内一阶离差和为零，交叉项消失。最后除以 n 得总体二阶中心矩，除以 n 减一得常见样本方差，二者分母不同。

与先求平方和再减均值平方相比，中心化更新通常能减少大均值小方差时的相消，但不是任意浮点输入下都精确。均值差非常大、值超出范围或状态混用精度仍可能失败。应按问题尺度设置验证容差，而不是用一个固定极小误差对所有输入要求逐位一致。

将省略的代数展开一次：块 A 中 $`x-\mu=(x-\mu_A)+(\mu_A-\mu)`$，平方后求和，交叉项因 $`\sum_{x\in A}(x-\mu_A)=0`$ 消失，故该块贡献 $`M_{2,A}+n_A(\mu_A-\mu)^2`$。块 B 同理。由于 $`\mu_A-\mu=-\frac{\delta n_B}{n}`$、$`\mu_B-\mu=\frac{\delta n_A}{n}`$，两项偏移合起来为 $`\frac{\delta^2[n_An_B^2+n_Bn_A^2]}{n^2}=\frac{\delta^2n_An_B}{n}`$。如果只相加块内平方和，就恰好漏掉块均值之间的变化。

例如 A 为 $`(0,2)`$，B 为 $`(4,6)`$，各块都有 $`n=2`$、$`M_2=2`$，块均值分别为一、五。合并均值为三，额外项为 $`4^2\times2\times\frac{2}{4}=16`$，总 $`M_2=2+2+16=20`$，总体方差为五，样本方差为 $`\frac{20}{3}`$。直接枚举四个数相对三的平方离差同样得到 $`9+1+1+9=20`$。这也解释了并行归约为什么要携带均值与样本数，而不能只把各块方差平均。


<a id="algo-4-detail-25"></a>

### 6.3 分位数不能靠块分位数精确恢复

中位数需要全体顺序信息。仅知道每块中位数和大小，通常无法恢复全局中位数，因为不同块尾部可以发生大幅变化而不改变局部中位数。若需要精确分位数，可以外部排序、选择算法或保留足够可比较信息；若接受近似，可用带明确秩误差目标的摘要。

秩误差与数值误差不同。分位点秩偏差很小，在分布有大间隙时仍可能产生很大数值差；反过来，密集区域中较大秩偏差可能只有很小数值差。应按应用选择保证，不要把“百分之一误差”留成无法判断的模糊描述。

同样，可合并摘要还要统一参数、随机化或规范。两个不同箱边界的直方图不能直接逐格相加；两个不同哈希种子的频率草图也不能直接相加后沿原规则查询。摘要元数据与状态值同样属于算法输入。

<a id="algo-4-detail-26"></a>

### 6.4 完整归并与统计对照实验

下面在内存中模拟有序段归并和方差摘要合并，使用不等长块验证均值权重。实验不写临时文件，不宣称测量了磁盘性能；它核对的是算法层的次序、计数与合并公式。真实外存流程还要单独测试 I/O、文件完整性与资源上限。

```python
import heapq
import math
from itertools import chain
from random import Random

rng = Random(47)
data = [rng.uniform(-3, 5) for _ in range(151)]
chunks = [data[:1], data[1:20], data[20:100], data[100:]]
runs = [sorted(chunk) for chunk in chunks]
assert list(heapq.merge(*runs)) == sorted(data)

def summarize(values):
    n, mean, m2 = 0, 0.0, 0.0
    for value in values:
        n += 1
        delta = value - mean
        mean += delta / n
        m2 += delta * (value - mean)
    return n, mean, m2

def merge_stats(a, b):
    na, ma, sa = a
    nb, mb, sb = b
    if na == 0:
        return b
    if nb == 0:
        return a
    n = na + nb
    delta = mb - ma
    return n, ma + delta * nb/n, sa + sb + delta*delta*na*nb/n

state = (0, 0.0, 0.0)
for chunk in chunks:
    state = merge_stats(state, summarize(chunk))
reference_mean = math.fsum(data) / len(data)
reference_m2 = math.fsum((x-reference_mean)**2 for x in data)
assert state[0] == len(data)
assert math.isclose(state[1], reference_mean, abs_tol=1e-12)
assert math.isclose(state[2], reference_m2, rel_tol=1e-12)
assert merge_stats((0, 0.0, 0.0), state) == state
print("k-way merge / count / centered moment summaries verified")
```

## 7. 精确近邻：距离、分块与数值语义

<a id="algo-4-detail-28"></a>

### 7.1 先固定检索空间和距离定义

给定查询 q 与数据库向量 x，欧氏距离、平方欧氏距离、余弦相似度和内积对应不同排序目标。平方欧氏距离与欧氏距离排序一致，但平方距离一般不满足三角不等式；若后续剪枝依赖度量性质，不能把平方形式不加修改地代入。

如果两侧向量都归一为单位长度，平方欧氏距离等于二减二倍内积，因此其最近排序与最大内积、最大余弦一致。只归一查询或只归一数据库通常不够；零向量的余弦未定义，需要明确排除或约定，而不是除零后让 NaN 进入候选结构。

向量表示本身也属于检索协议。编码模型、预处理、维度、归一化和版本必须一致。旧数据库向量与新查询编码器混用，算法仍能算出距离，却可能不再反映同一语义空间。精确检索只保证对给定数值和度量正确，不保证表示一定符合任务相关性。

<a id="algo-4-detail-29"></a>

### 7.2 全量扫描是重要的精确参考

对 N 个 d 维数据库向量，每个查询逐一计算距离，常见成本为 $`O(Nd)`$。它不需要训练索引，支持灵活过滤，适合小库、批量矩阵运算或作为近似方法的真值参考。复杂索引并不保证在所有规模与硬件上更快。

若有 Q 个查询，一次构造 Q 乘 N 距离矩阵可能过大。可以分查询与数据库块，并对每个查询维护 k 个候选，避免保存全部两两结果。总距离计算量仍在，节省的是工作集和不必要输出，不应把分块说成消除了计算复杂度。

还要决定查询是否来自数据库、是否排除自身、重复向量是否视为不同记录，以及边界并列怎样处理。近似召回如果拿一个任意同分真值集合做唯一标准，可能惩罚另一组同样精确的并列邻居。可以固定全序编号规则，或采用清楚的同距离集合评价。

<a id="algo-4-detail-30"></a>

### 7.3 距离公式的数值风险

平方距离可写成向量差平方和，也可写成两个范数平方之和减二倍内积。后者便于矩阵乘法，但当向量很大且彼此非常接近时，可能发生严重相消，得到微小负数或不准确排名。把负数裁成零只修补显示范围，不能恢复已经丢失的区分信息。

直接差分通常避免这类大数相消，却仍可能在极端尺度下溢出或上溢。可以检查有限性、缩放数据、选择合适精度，并在接近门槛时用更稳定计算重排。所谓精确搜索一般指没有算法性候选遗漏，不意味着浮点距离等于实数精确值。

索引与精确参考还应采用一致距离约定。若索引返回平方距离、参考用欧氏距离，排序可一致但数值不同；若参考使用更高精度，边界近似同分可能变化。评估时应记录精度和容差，必要时检查困难查询的距离间隔。

<a id="algo-4-detail-31"></a>

### 7.4 分块精确近邻实验

下面只对每个查询保留 k 个候选，键为负平方距离与负编号，越大越好。数据库仍以小型数组存在内存，实验验证分块算法与稳定全扫描一致，不声称测试了真正超内存数据。真实应用可把块来源替换为受控迭代读取，但必须保留全局编号。

```python
import heapq
import numpy as np

def nearest_blocks(database, queries, k, block_size):
    if np.iscomplexobj(database) or np.iscomplexobj(queries):
        raise ValueError("real vectors required; complex parts must not be discarded")
    x = np.asarray(database, dtype=np.float64)
    q = np.asarray(queries, dtype=np.float64)
    if x.ndim != 2 or q.ndim != 2 or x.shape[1] != q.shape[1]:
        raise ValueError("aligned two-dimensional vectors required")
    if not np.isfinite(x).all() or not np.isfinite(q).all():
        raise ValueError("finite vectors required")
    if type(k) is not int or k < 0 or type(block_size) is not int or block_size <= 0:
        raise ValueError("invalid k or block size")
    output = []
    for query in q:
        heap = []
        if k:
            for start in range(0, len(x), block_size):
                delta = x[start:start+block_size] - query
                distances = np.sum(delta * delta, axis=1, dtype=np.float64)
                if not np.isfinite(distances).all():
                    raise ValueError("distance overflow; rescale the input")
                for offset, distance in enumerate(distances):
                    ident = start + offset
                    key = (-float(distance), -ident)
                    if len(heap) < k:
                        heapq.heappush(heap, key)
                    elif key > heap[0]:
                        heapq.heapreplace(heap, key)
        ordered = sorted(heap, reverse=True)
        output.append([(-neg_id, -neg_distance)
                       for neg_distance, neg_id in ordered])
    return output

rng = np.random.default_rng(53)
database = rng.normal(size=(61, 5))
database[1] = database[0]
queries = np.vstack([database[0], rng.normal(size=(4, 5))])
for k in [0, 1, 6, 80]:
    expected = []
    for query in queries:
        d2 = np.sum((database-query)**2, axis=1)
        ids = np.lexsort((np.arange(len(database)), d2))[:k]
        expected.append([(int(i), float(d2[i])) for i in ids])
    for block_size in [1, 7, 31]:
        actual = nearest_blocks(database, queries, k, block_size)
        assert [[i for i, d in row] for row in actual] == [
            [i for i, d in row] for row in expected]
        for got, want in zip(actual, expected):
            assert np.allclose([d for i, d in got], [d for i, d in want])
assert nearest_blocks(database, queries[:1], 1, 8)[0][0][0] == 0
for bad_database, bad_query in [(database.astype(complex) + 1j, queries),
                                (database, queries.astype(complex) + 1j)]:
    try:
        nearest_blocks(bad_database, bad_query, 1, 8)
    except ValueError as error:
        assert "real vectors required" in str(error)
    else:
        raise AssertionError("complex coordinates were silently projected")
print("blocked exact neighbors agree under all block sizes and tie rules")
```

## 8. 近似检索：候选、压缩与评价

<a id="algo-4-detail-33"></a>

### 8.1 空间树剪枝为什么需要合法距离界

空间树把数据库划入区域，对查询计算区域内可能最小距离的下界。若下界已经大于当前第 k 候选距离，就能安全排除整个区域。精确性来自下界不高估真实最小距离，以及候选门槛维护正确，而不是来自树的名称。

在低维且分布适合时，区域界能排除很多节点；高维、复杂分布或距离集中时，下界可能很弱，访问量接近全扫描。不能简单承诺树查询总是对数时间。索引构建成本、区域重叠和查询分布都会影响实际效果。

若提前停止搜索或使用不够保守的界，就进入近似方案，应给出误差或召回目标。某些度量树的证明依赖三角不等式，任意学习相似度不满足该条件时，原剪枝保证可能失效。度量选择与索引可用性需要共同分析。

<a id="algo-4-detail-34"></a>

### 8.2 倒排候选与图搜索代表不同节省方式

倒排式向量检索可先把数据分配到粗粒度区域，查询只搜索部分区域，以减少距离计算。探查区域更多通常提高候选覆盖，同时增加工作；但不能只根据区域数就保证某个固定召回，因为数据分布与分配误差不同。

图式近似检索把数据库记录连接成邻接结构，从入口沿较有希望的邻居探索，常维护待探索候选与当前较优结果。分层结构可帮助从粗到细导航。其工程表现依赖连边、搜索宽度、构建和数据分布，不能把经验上的快速查询写成所有输入的对数最坏保证。

本章不把一个短队列搜索示例冒充成熟索引库。真正实现还涉及并发更新、删除、内存布局和持久化。可以先使用精确参考与固定查询集建立评价，再比较成熟实现；方法细节应查原始论文和库文档，而不是仅调一个参数看最快数字。

<a id="algo-4-detail-35"></a>

### 8.3 量化节省表示空间，也改变距离

把原向量 x 替换为近似向量 $`\hat x`$，若重建误差范数不超过 $`\varepsilon_x`$，由三角不等式有

$$
\big\vert \Vert q-x\Vert -\Vert q-\hat x\Vert \big\vert \leq\varepsilon_x.
$$

因此两个候选的近似距离间隔若大于相应误差界之和，可以保证它们的真实顺序；若间隔很小，则排名可能变化。量化误差小不自动保证所有 Top-k 身份不变，边界距离间隔同样重要。

分块量化可把向量拆成若干子空间，每部分只保存一个码本索引。若每个子空间有 C 个中心、共有 m 个子空间，码长约为 $`m\log_2C`$ 比特，另加码本与其他索引开销。这是表示预算，不是整个系统内存的全部；还要计入编号、图边、倒排表和缓存。

用原始向量重排可以消除候选内部的部分量化排名误差，但未被候选生成访问的近邻仍然丢失。应分别区分压缩误差、候选遗漏与浮点误差，不要把三者全部归到一个模糊的近似标签中。

<a id="algo-4-detail-36"></a>

### 8.4 召回与延迟必须在同一协议下比较

Recall@k 常定义为近似返回集合与精确前 k 的交集数除以 k，要求真值参考、候选库、过滤和同分规则一致。若库不足 k，应明确实际分母；若返回重复身份或不足 k，不能把重复项当作多次命中。

均值召回会掩盖困难查询，可以同时查看低分位查询表现、按来源或查询长度分层，以及真正下游目标。高向量近邻召回不一定对应高任务相关性，因为表示本身可能失配；但若只研究索引近似误差，精确邻居仍是重要参照。

延迟要报告批量、并发、设备、线程、冷暖缓存和尾部分位。吞吐提高可能伴随单请求延迟增加，索引内存下降也可能增加解码成本。比较应尽量给出召回与资源的曲线或多个操作点，而不是各选一个最有利数字放在一起。

<a id="algo-4-detail-37"></a>

### 8.5 过滤与更新会改变适用边界

真实检索常有时间、权限或类别过滤。先做近似检索再过滤，可能剩余结果太少；先过滤则可能改变索引访问结构与有效候选密度。应以相同资格规则下的精确结果作参考，不能用未过滤召回代表过滤场景效果。

动态数据库还需要删除、插入与版本切换。旧向量与新向量混用可能导致表示不一致，删除标记长期积累也可能影响内存与查询路径。评价一次静态构建结果，不足以证明长期运行成本稳定。

查询集也不应只来自建索引时已经反复调参的数据。可以用开发查询选择操作点，用保留查询报告主要结果。若后续根据失败查询修改索引或表示，这些查询就承担开发作用，最终结论需要新的独立验证。

<a id="algo-4-detail-38"></a>

## 9. 有保证的流式近似与随机抽样

<a id="algo-4-detail-39"></a>

### 9.1 Count-Min 的单边误差来自哪里

考虑只允许非负更新的频率流，用若干行独立哈希表累计计数，查询某键时取各行对应桶值的最小值。每行桶中都包含该键自己的全部频率，再加其他键碰撞贡献，因此估计不会低于真实频率。这一单边性质依赖非负贡献，不能直接推广到任意带删除流。

设总质量为 F，每行宽度为 w，哈希族使任意不同键碰撞概率至多为 $`\frac{1}{w}`$，则固定查询键的期望碰撞质量至多为 $`\frac{F}{w}`$。取 $`w\geq\frac{e}{\varepsilon}`$，由 Markov 不等式，一行碰撞超过 $`\varepsilon F`$ 的概率至多为 $`\frac{1}{e}`$。

若各行哈希独立，取 d 行最小值只有在所有行都过大时才失败，概率至多为 $`e^{-d}`$。取 $`d\geq\log(\frac{1}{\delta})`$，得到固定查询以至少一减 $`\delta`$ 的概率处于真实频率到真实频率加 $`\varepsilon F`$ 之间。这里给的是加性总质量误差，不是每个低频键的相对百分比误差。

<a id="algo-4-detail-40"></a>

### 9.2 查询数量、哈希协议与可合并性

上述概率通常针对预先固定查询或适当独立条件下的查询；若同时对很多键要求成立，需要考虑联合失败概率，不能把单查询保证直接称为所有键同时保证。自适应查询和对抗输入还可能需要更强分析。

两个草图只有在尺寸、哈希函数与计数含义一致时，才可逐桶相加，得到合并数据流的同类状态。不同种子或不同宽度不能直接相加。合并后总质量也相加，误差尺度随总质量变化，不能继续使用单块较小 F 给全局保证。

频率草图还能辅助寻找重频键，但单独一张桶计数表并不保存全部键身份，因此“能估计给定键的频率”和“能列出所有重频键”是两个任务。需要额外候选结构或其他方案。摘要压缩掉什么信息，应与最终输出需求一起说明。

<a id="algo-4-detail-41"></a>

### 9.3 蓄水池抽样不是 Top-k

Top-k 按得分偏好记录，蓄水池抽样则希望在未知总长度的数据流中均匀选出固定数量记录。维护容量 k 的池，读第 t 条且 t 大于 k 时，从零到 t 减一均匀取整数；若落在池位置范围内就替换，否则丢弃。

对已有记录，进入池后在后续每一步被保留的概率逐项相乘，当总记录数至少为 k 时，可得最终每条包含概率为 k 除以总数；少于 k 时全保留，每条包含概率为一。但相同边缘包含率本身并不充分证明整个子集均匀，严格论证还应对每个 k 子集做归纳，分别分析是否包含最新记录，两类都得到相同组合数倒数。

如果要求按实体均匀，而流中实体出现次数不同，按记录抽样会偏向高频实体。若只在每块抽同样 k 条再均匀合并，也会让小块与大块获得错误权重。抽样单位和合并方法必须与目标总体一致，不能把随机化当作自动无偏。

完整子集归纳可以补上这个保证。假定前 $`t-1`$ 条上的池在全部 $`k`$ 子集中均匀，且 $`t>k`$。对一个不含第 $`t`$ 条的目标子集 $`S`$，只能由原池正好为 $`S`$ 且新记录未入池得到，概率为 $`\frac{\binom{t-1}{k}^{-1}(t-k)}{t}=\binom tk^{-1}`$。对一个包含第 $`t`$ 条的目标子集，记其余 $`k-1`$ 条为 $`R`$；前一个池必须为 $`R\cup\{j\}`$，其中 $`j`$ 可在前 $`t-1`$ 条且不在 $`R`$ 的 $`t-k`$ 条中选择。每种原池概率为 $`\binom{t-1}{k}^{-1}`$，恰好替换 $`j`$ 的概率为 $`\frac{1}{t}`$，求和仍为 $`\binom tk^{-1}`$。初始 $`t=k`$ 只有一个子集，所以归纳成立。

例如 $`k=2,t=4`$，六个二元子集的概率应都为 $`\frac{1}{6}`$，而不仅是每条记录包含率均为 $`\frac{1}{2}`$。后一个条件更弱：只以各一半概率返回集合 $`\{1,2\}`$ 或 $`\{3,4\}`$，四条记录的边缘包含率同样为 $`\frac{1}{2}`$，但另外四个子集永远抽不到。因此研究多样性、样本对统计量或联合覆盖时，必须确认所需的是边缘公平还是整个子集的均匀分布。


<a id="algo-4-detail-42"></a>

### 9.4 用穷举随机分支核对小例子

下面实现标准记录级蓄水池，并对四条记录取两条的全部随机分支进行枚举。第三条有三种等概率选择，第四条有四种，十二条等概率路径最终落在六个子集，每个恰好两条路径。这是对小规模联合均匀性的精确验证，不是只看一次随机结果是否像随机。

```python
from collections import Counter
from itertools import product
from random import Random

def reservoir(stream, k, rng):
    if type(k) is not int or k < 0:
        raise ValueError("k must be a nonnegative integer")
    pool = []
    for t, item in enumerate(stream, 1):
        if t <= k:
            pool.append(item)
        else:
            j = rng.randrange(t)
            if j < k:
                pool[j] = item
    return pool

outcomes = Counter()
for j3, j4 in product(range(3), range(4)):
    pool = [0, 1]
    for item, j in [(2, j3), (3, j4)]:
        if j < 2:
            pool[j] = item
    outcomes[tuple(sorted(pool))] += 1
assert len(outcomes) == 6 and set(outcomes.values()) == {2}
sample = reservoir(iter(range(100)), 7, Random(59))
assert len(sample) == len(set(sample)) == 7
assert all(0 <= x < 100 for x in sample)
assert reservoir([1, 2], 5, Random(1)) == [1, 2]
assert reservoir([1, 2], 0, Random(1)) == []
print("reservoir subset uniformity verified by all 12 small-case branches")
```

## 10. 资源预算与研究比较的完整性

<a id="algo-4-detail-44"></a>

### 10.1 峰值内存不是最终状态大小

一个候选堆只占 k 项，并不说明整个流程只占 k 项。输入解码、向量块、临时差分数组、序列化缓冲、索引结构与输出列表都要计入。若每次流式处理完一块却把所有块结果追加到列表，内存仍会随总量增长。

同样，读取压缩文件的原始字节大小不能直接代表解码后的向量和对象内存。可以用定宽数组估算基础存储，再检查临时复制与框架保留。代码中的切片是视图还是复制，也会改变峰值。资源账本应列出同时存活对象，而不是把互不同时出现的所有分配简单相加。

对外部排序，临时磁盘空间也属于预算。多轮归并若保留所有旧段，空间可能远大于单轮；若过早删除旧段，故障恢复又可能失去输入。完整工程要在发布新结果后安全回收旧段，本章不实际创建这些文件，但不能在算法模型中把它们当作免费。

<a id="algo-4-detail-45"></a>

### 10.2 代表性测量与摊销查询量

比较完整排序、堆和分区选择时，应同时改变 n 与 k 的比例。k 很小时堆有明显状态优势；k 接近 n 时完整排序可能更合适，常数和连续访问也会重要。不能只拿一个最有利的 k 宣称某结构普遍更快。

向量索引则要把构建成本按查询次数摊销。若构建耗时 A，每次相对扫描节约 B 秒，忽略其他成本时需要约 A 除以 B 次查询才抵消构建开销；若 B 不为正，就没有这种时间盈亏点。加入更新、存储与质量损失后还需更完整的目标。

还应明确测量是否包含数据读取、查询编码和结果重排。只计核心搜索而另一方案计端到端，会制造不公平优势。冷缓存首查、热缓存稳态和高并发尾延迟都可能重要，应该按照部署目标选择，而不是混成一个没有条件的平均查询时间。

<a id="algo-4-detail-46"></a>

### 10.3 精确基线是近似研究的坐标系

在可以承受的小库或查询子集上，建立精确排序、精确扫描和完整统计参考，有助于校准近似方法。参考本身也要检查键、过滤与数值精度，不能把一个含错真值文件当作绝对标准。

扩展规模时可以保留固定的代表查询和困难查询，观察召回分布与资源曲线。若只能在抽样数据库上求真值，应明确它不是完整库真值，邻居关系可能随库扩大而改变。不能把小库高召回直接外推到更大候选集合。

最终研究结论应该同时说明目标、精度、资源和更新条件。一个近似方案可能在特定召回要求下最佳，另一个在高更新或小批量下更合适。比较算法是在约束下选择可接受的计算，而不是寻找一个脱离任务的永久赢家。


<a id="algo-4-detail-47"></a>

### 10.4 局部中位数不足的明确反例

取两块各三条，第二块固定为负一百、十、一百，中位数十。第一种第一块为负一百、零、一，中位数零；第二种第一块为负一、零、一百，中位数仍为零。块大小与块中位数完全相同，但第一种合并排序为负一百、负一百、零、一、十、一百，全局中位数为零点五；第二种合并中位数为零与十的平均，即五。

这提供了一个不可恢复性的证据：如果摘要输入完全相同，却存在两个合法原数据对应不同正确答案，任何只读该摘要的算法都不可能对两者都精确。证明摘要不足，不需要列出所有失败实现；构造这样一对不可区分输入就足够。该方法同样可以用来审查局部 Top-k 后去重、缺少库存的动态规划以及丢失身份的配对评价。

<a id="algo-4-detail-48"></a>

### 10.5 未读数据没有界，就不能凭当前门槛提前停止

流式最大 Top-k 的门槛在堆满后不下降，但它只描述已读前缀。如果剩余记录可以有任意更大分数，当前候选看起来再好也不能证明已是最终答案。因此堆节省状态，不自动节省全扫描读取。想安全提前停止，需要额外结构提供未读部分的上界。

例如每个输入段已按最终得分降序排列，段头就是该段未读最大可能值。当所有未读段头的完整键都不优于当前第 k 键，才可以排除剩余项。若最终目标还要重新评分，而段序只按廉价代理分数排列，就需要代理对最终分数的合法界，否则原证书不再成立。同分身份也要进入比较，不能仅看数值相等就停止。

这类证书把精确检索、分支定界和有序多源合并联系起来。近似方案可以故意在证书成立前停止，以资源预算换质量，但应把提前停止规则与召回实验写清。是否访问全部数据不是精确与近似的唯一分界，真正的分界是未访问部分是否已经由有效证明排除。

## 11. 综合算例与可核对协议

<a id="algo-4-detail-50"></a>

### 11.1 一百万条记录只取前十

若记录按单遍输入且只需精确前十，可以用大小十的堆，保持唯一键并最终排序十项。主要内存是读取缓冲与十个候选，时间包括读取百万记录和候选维护。若后续还要所有排名，应重新比较完整排序或外部排序，而不是反复运行不同 k 的扫描。

若数据分在多块且无额外实体聚合，各块前十可以继续合并；若要按用户累计分数排名，就不能把记录前十直接当用户前十摘要，应先设计按用户合并总分的流程。这个目标变化往往比换数据结构更重要。

验收应包含重复分数、极端 k、空输入、非法键与同分身份，还要核对最终降序要求。对代表数据与完整排序对照，再报告性能。输出正确与内存按预期增长是不同检查，二者都通过才构成可靠大数据方案。

<a id="algo-4-detail-51"></a>

### 11.2 一千万向量的近邻服务

先估算原始向量字节、编号、索引与候选缓冲，再选择可接受的查询延迟与召回目标。若内存不足，可考虑压缩或外存，但需记录距离误差和 I/O 成本；若查询很少，建立复杂索引可能不合算。

把候选生成、原向量重排与过滤分成可观察阶段，分别记录耗时和遗漏。若最终结果差，可以判断是表示不相关、候选未命中还是重排次序错误。只看最终一个召回数，往往难以确定该增加搜索宽度、改码本还是重训表示。

更新时保留编码版本与索引身份，避免查询端和库端处于不同空间。性能报告应有稳定负载、并发和尾延迟条件，质量报告应有独立查询与固定真值。算法、数据和系统共同决定结果，任何单个参数都不能替代完整协议。

## 12. 进阶练习与逐步解析

<a id="algo-4-detail-53"></a>

### 12.1 练习一：堆数组不是排序结果

**题目。** 数组一、四、二、七、五、三是否可以是最小堆？是否升序？怎样得到升序而保留原堆？

**解析。** 每个存在孩子都不小于父节点，因此满足最小堆；但四在二前面，显然不是升序。可以排序一个副本，或复制堆后反复弹出。候选结构与展示次序不同，若直接把数组交给依赖排名的下游，会在值集合正确时仍产生错误顺序。

<a id="algo-4-detail-54"></a>

### 12.2 练习二：稳定最大前 k 的键方向

**题目。** 同分优先编号较小记录，用越大越好的键维护最大候选时，编号应取正还是负？为什么编号唯一有意义？

**解析。** 应取负编号，较小编号对应较大负数，优先进入最大集合。唯一编号保证比较在负载前已区分，不会继续比较不可排序字典。若编号重复，既破坏稳定身份定义，也可能触发负载比较异常。空间严格受限时，唯一性需要上游契约或独立验证，不能隐式存全体身份却仍声称只用 k 空间。

<a id="algo-4-detail-55"></a>

### 12.3 练习三：替换操作的前提

**题目。** 大小二的最小堆保存分数八和九，新值一到来，能否无条件调用替换根操作？结果为何错误？

**解析。** 无条件替换会丢掉八、加入一，得到一和九，已经不再是已读数据最大二项。应先比较新键是否大于门槛，只有更好才替换，或使用语义相符的插入后弹最小操作。不同组合接口虽都维持堆结构，却不自动维持 Top-k 的前缀不变量。

<a id="algo-4-detail-56"></a>

### 12.4 练习四：可合并性的反证

**题目。** 某块中最高十条全属于实体甲，实体乙分数略低。先取十条再去重，为什么不等于实体前十？如何修改目标建模？

**解析。** 局部摘要只保留甲，乙已经丢失，后续去重不能恢复。应先定义实体分数如何从记录得到，再选择足够摘要。若实体分数是跨块总和，局部实体前十仍可能不足，需要保留或分区聚合所有相关贡献。先处理输出身份与聚合规则，才能证明候选压缩安全。

<a id="algo-4-detail-57"></a>

### 12.5 练习五：分块均值

**题目。** 三块大小一、九、九十，均值分别十、二、四。总均值是多少？块均值简单平均估计的是什么？

**解析。** 总均值为 $`\frac{(10+18+360)}{100}=3.88`$；简单平均为十六除以三，表示随机等权选块后块均值的平均。两者对应不同权重。合并状态应保存计数和总和，不能只留下均值，除非块大小相同或目标本来就是块等权。

<a id="algo-4-detail-58"></a>

### 12.6 练习六：方差合并的额外项

**题目。** 两块各两个值，第一块全为零，第二块全为十，块内中心平方和都为零。合并中心平方和为何不为零？

**解析。** 总均值为五，每个观测离差平方为二十五，总中心平方和为一百。公式的额外项为 $`10^2\times2\times\frac{2}{4}=100`$，描述块均值之间的差异。只相加块内平方和会完全丢掉组间变动；这也是只保存块方差不足以正确合并的原因。

<a id="algo-4-detail-59"></a>

### 12.7 练习七：归一化后的距离关系

**题目。** 两单位向量内积为零点八，平方欧氏距离是多少？若只有查询归一，是否仍能直接用二减二内积？

**解析。** 两侧均单位长度时为零点四。只有查询归一时，数据库向量范数平方不一定为一，完整公式还包含它，排序也可能改变。零向量无法按普通余弦归一，应明确处理。距离协议必须在编码、索引和精确参考中保持一致。

<a id="algo-4-detail-60"></a>

### 12.8 练习八：重排不能恢复遗漏

**题目。** 第一阶段只返回五十候选，真实最近邻未在其中。第二阶段精确计算全部候选原向量距离，能否宣称最终全库最近邻精确？

**解析。** 不能，精确只发生在候选集合内。缺失的全库最近邻没有被重新考虑。要保证全局精确，需要完整扫描或合法剪枝证书；否则应报告候选召回与最终召回，分析遗漏阶段。增加候选通常是调节精度成本的手段，不自动给所有输入保证。

<a id="algo-4-detail-61"></a>

### 12.9 练习九：量化距离间隔

**题目。** 两候选近似欧氏距离分别一点零与一点五，各自重建误差范数至多零点一。能否保证前者真实更近？若第二距离为一点一呢？

**解析。** 第一种间隔零点五大于误差界之和零点二，所以真实顺序不会反转。第二种间隔零点一不够，真实距离区间重叠，无法仅凭这些界保证顺序。误差界提供充分条件，不表示间隔小就一定错；需要更准确距离或接受不确定排名。

<a id="algo-4-detail-62"></a>

### 12.10 练习十：外部归并遍数

**题目。** 初始有十六个有序段，资源只允许四路归并，需要几轮合为一个？为何不能同时打开全部段直接归并来忽略资源限制？

**解析。** 第一轮缩为四段，第二轮变为一段，共两轮。四路上限可能来自缓冲、文件描述符或设备调度，不能用算法调用一次就消除。若增加路数，需要重新分配每路缓冲与元数据预算，并测量其实际影响。抽象比较次数与系统可用资源应同时满足。

<a id="algo-4-detail-63"></a>

### 12.11 练习十一：草图误差是加性还是相对

**题目。** Count-Min 总质量一百万，参数允许加性误差一千。对真实频率为一的键，这是否意味着估计在百分之一相对误差内？

**解析。** 不是。保证针对总质量尺度，估计可能高达约一千零一，远超真实频率的百分之一。对重频键这种误差可能相对可接受，对低频键则很宽。选摘要前应说明关心重频发现、精确小计数还是相对误差，不能只看一个误差百分数。

<a id="algo-4-detail-64"></a>

### 12.12 练习十二：草图合并的元数据

**题目。** 两块使用相同表大小但不同哈希种子，逐格相加后还能按第一块种子查询吗？

**解析。** 一般不能。第二块某键计入的桶位置与第一块不同，相加后的桶不再代表同一哈希映射。需要同一尺寸、哈希协议和计数含义才能直接合并。元数据是摘要数学定义的一部分，不仅是用于复现的附加说明。

<a id="algo-4-detail-65"></a>

### 12.13 练习十三：蓄水池与分块抽样

**题目。** 一块十条、一块九十条，各均匀抽一条，再从两条中等概率选一条，是否得到全体一百条的均匀样本？

**解析。** 不是，小块每条概率为二十分之一，大块每条为一百八十分之一。等权选择块与等权选择记录不同。若只要一个样本，可以按块大小选择块，再取其均匀样本；更一般合并抽样需要匹配目标与摘要信息，不能把独立局部随机选择当作自动全局均匀。

<a id="algo-4-detail-66"></a>

### 12.14 练习十四：平方距离的三角不等式

**题目。** 一维点零、一、二，平方距离是否满足三角不等式？这对度量树剪枝有什么提醒？

**解析。** 零到二平方距离为四，经过一的两段平方距离之和为二，所以不满足普通三角不等式。可以使用真实欧氏距离建立合法界，再按需要转换；不能因为平方距离排序相同，就直接把所有度量证明中的距离符号替换为平方距离。

<a id="algo-4-detail-67"></a>

### 12.15 练习十五：索引构建的盈亏点

**题目。** 构建索引耗一百秒，每次查询比扫描节约零点零二秒，忽略其他成本需多少次查询才能抵消？若数据库每分钟重建，结论还足够吗？

**解析。** 约需五千次查询。频繁重建时，还要结合每分钟查询量、更新成本、并发资源和质量损失，不能只使用一次构建的简单盈亏点。若构建影响在线服务尾延迟，也应计入实际目标。单查询最快不等于整个生命周期成本最低。

<a id="algo-4-detail-68"></a>

### 12.16 练习十六：输出本身的规模

**题目。** 想输出十万向量全部两两距离，分块是否能把输出空间从平方降为线性？如果只要每个向量最近十个，又有什么不同？

**解析。** 要显式保存全部两两距离，输出条目仍为平方级，分块只降低计算时峰值工作集。若只要最近十个，可在扫描或索引过程中只保留每查询十个候选，输出变为线性乘十，但距离计算或索引工作仍需分析。输出契约改变才是真正减少所需信息的关键。

## 13. 研究任务与验收

<a id="sec-8-1"></a>

<a id="algo-4-detail-70"></a>

### 13.1 同一数据流选择排序、堆与分块

固定一批有重复分数、唯一编号和不等块大小的数据，分别用完整稳定排序、单遍堆与分块候选合并求前 k。改变 k 与总量比例，核对身份和次序一致，再比较读取、键计算、维护和输出成本，避免只计某一小段。

随后增加实体去重、资格过滤或跨块累计分数，检查原合并证明在哪一步失效，并给出新方案。验收不仅要求结果对照，还应解释局部摘要保存了什么、丢失了什么，以及为何足够或不够。这个实验能把数据结构、输出目标和可合并性联系成完整推理。

<a id="algo-4-detail-71"></a>

### 13.2 近似索引的操作点研究

使用固定编码和距离，在小库建立精确真值，比较多个候选宽度、压缩强度和过滤比例下的召回、平均与尾延迟、内存和构建成本。预先划分开发查询与最终查询，不用最终查询反复挑参数。

验收时检查困难查询与距离并列规则，区分候选遗漏、压缩与重排误差，说明精确参考的精度和样本范围。若暂时没有专用索引库，可以先用可控候选子集模拟召回损失，但要明确它只是机制实验，不把模拟速度当真实索引性能。
