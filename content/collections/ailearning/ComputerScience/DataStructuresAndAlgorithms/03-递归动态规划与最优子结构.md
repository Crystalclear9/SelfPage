## 1. 递归、子问题图与动态规划的真正联系

递归是一种用自身定义求解过程的程序组织方式，动态规划则是一种利用状态复用计算的方法。两者经常共同出现，却不能互相替代。一个没有重复子问题的递归算法可能已经很高效；一个状态定义不充分的程序，即使加上缓存，也只是更快地得到错误结果。本章把重点放在状态为什么可以合并、递推为什么覆盖全部方案，以及空间优化之后是否仍在求同一个问题。

学习目标不是记住若干双层循环，而是能够从一个新问题建立状态、边界、转移、求值顺序和方案恢复，并给出复杂度与正确性理由。完整例子将覆盖最少硬币、零一背包、编辑距离和带权区间选择，再联系有限时域决策与研究中的优化条件。

<a id="algo-3-detail-2"></a>

### 1.1 递归终止需要一个严格推进的量

递归函数必须有边界，并保证每条调用路径最终到达边界。常用证明是给每个调用赋一个非负整数度量，每次递归都严格减小。对于正整数面额的零钱问题，剩余金额就是这样的度量；若允许零面额，调用可能不推进；若允许负面额，金额可能反而增加。

这说明输入约束是算法证明的一部分，而不只是程序风格。金额与面额若不是整数，按整数数组索引的状态空间已经不成立。面额为布尔值在某些语言中可能表现为整数，但是否接受应由接口明确决定，不能让类型继承关系偶然决定数学问题。

终止还不同于在现实执行环境中可运行。理论上深度一万的有限递归会终止，但解释器递归栈可能先达到限制。可以改用显式栈或自底向上求值；简单提高递归限制并不能证明内存足够，也不能改善重复计算的渐近复杂度。

<a id="algo-3-detail-3"></a>

### 1.2 从递归树压缩为状态依赖图

计算 Fibonacci 时，朴素递归会在不同分支反复求同一个较小下标。展开调用得到一棵树，记忆化则把下标相同的节点合并为一个状态，形成依赖有向无环图。此时复杂度主要取决于不同状态数与每个状态的转移工作，而不是原递归树节点总数。

对于 $`F(n)=F(n-1)+F(n-2)`$，缓存后只有线性多个下标，每个状态做常数次加法。不过若按严格位复杂度计算，整数本身随下标增长，不能把任意大整数加法永远视为常数。教材中的线性时间常对应单位代价算术模型，应知道这个隐含假设。

树到图的压缩只有在相同键代表相同子问题时才正确。如果函数还读取会变化的全局数组、随机状态或外部文件，仅按一个下标缓存就可能混用不同问题的答案。缓存键必须覆盖影响结果的必要输入，或者保证这些输入在整个求解过程中固定。

<a id="algo-3-detail-4"></a>

### 1.3 记忆化与自底向上的取舍

自顶向下记忆化从目标出发，只访问实际需要的状态，适合稀疏可达空间；自底向上按依赖顺序计算，避免调用栈开销，通常更容易分析内存与并行性。二者可以实现相同递推，性能差别来自访问集合、数据结构和执行方式，不是一个永远比另一个高级。

缓存应以一次问题实例为边界。若把面额或图保存在闭包中，缓存只在闭包内部使用，可避免跨实例混淆；若复用全局缓存，就要把实例身份纳入键或清空。缓存还会持有键和值，状态过多时可能造成内存压力，不能把记忆化当作没有代价的优化。

有界缓存可能让被驱逐状态重新计算，破坏“每个状态最多计算一次”的复杂度证明。并发缓存通常只保证内部结构一致，也不自动保证同一缺失键只被计算一次。本章实验使用单线程、单次实例与无界问题内缓存，明确保证所采用的状态计数分析。

## 2. 状态充分性与最优子结构

<a id="deep-dive-2"></a>

<a id="algo-3-detail-6"></a>

### 2.1 状态是对历史的可证明压缩

一个决策历史可能包含所有已选动作，但未来未必需要全部细节。如果两个历史在未来可选动作、转移效果和后续代价方面完全等价，就可以把它们归为同一状态。状态压缩的任务，是丢弃无关历史，同时保留决定未来的必要信息。

最少硬币问题中，面额固定且每种可无限使用，未来只取决于剩余金额，与此前硬币排列无关。因此可以只记录金额。若每枚只能用一次，剩余金额相同的两个历史可能留下不同库存；仅按金额合并就可能允许重复使用本来已耗尽的资源。

状态不仅需要描述可行性，还要说明已经付出的代价怎样处理。若同一状态的未来代价完全相同，累计成本较差的历史可以被较优者支配；若目标包含路径依赖惩罚或多目标约束，这种支配关系可能失效。不能只因为当前数值较大就丢掉一个历史，必须证明它不会在未来重新变得有利。

<a id="algo-3-detail-7"></a>

### 2.2 从最后一步分类得到 Bellman 递推

设 $`V(s)`$ 为到达状态 $`s`$ 的最小代价，每个合法方案都有某个最后转移 $`u\to s`$。如果移除最后一步后，前缀可以由状态 $`u`$ 的最优方案替代而不影响后续可行性，则

$$
V(s)=\min_{u\to s}\{V(u)+c(u,s)\}.
$$

证明包括两个方向。任意完整方案都属于某个最后转移，且其前缀代价至少为 $`V(u)`$，所以完整最优值不小于右侧；反过来，选择达到右侧最小值的前驱，把其最优方案与合法最后一步连接，就得到同样代价的完整方案，所以不大于右侧。

如果最小值不一定达到，需要使用下确界并另行讨论近似方案；本章有限离散例子中候选集合有限，最小值可以取得。这个条件在连续控制或无限动作空间中很重要，不能只看同样的最小符号就假定存在可实现的最优动作。

<a id="algo-3-detail-8"></a>

### 2.3 最优子结构不是任意局部贪心

最优子结构允许在已经固定某个状态转移之后，用子问题最优解替代前缀；贪心则进一步要求一个局部选择无需保留其他候选就一定安全。后者更强，通常需要交换论证、切分性质或其他结构保证。

面额一、三、四，金额六时，取最大面额的贪心得到四加一加一，动态规划得到三加三。失败并非因为实现慢或样例特殊，而是局部最大面额没有保证能嵌入全局最少枚数方案。不能把常见货币体系的经验推广到任意面额。

反过来，存在合适贪心算法的问题不一定值得做巨大状态表。比如特定区间调度目标有交换论证，可以按结束时间选择；加入权重后原贪心往往失效，需要其他算法。研究时先比较结构与目标，再决定是贪心、动态规划、图算法还是搜索。

<a id="algo-3-detail-9"></a>

### 2.4 依赖顺序决定怎样求值

若每个状态只依赖更小的某个度量，状态图是无环的，可以按该度量递增计算。金额递推依赖较小金额；序列前缀递推依赖较短前缀；区间动态规划通常按区间长度递增。一个合法顺序就是依赖图的拓扑顺序。

若存在环，简单递归加缓存可能在结果尚未生成时再次进入同一状态，不能靠缓存自动解决。有限时域问题可以把时间加入状态，形成分层无环图；无限时域可能需要固定点迭代、最短路松弛或求解方程，并分析收敛与解的选择。

例如零成本自环形成 $`V(s)=V(s)`$，这个方程本身不能唯一确定值。负成本可重复环可能使最小成本为负无穷。写出一个 Bellman 形式不是算法完成，还要明确边界、可达性、循环条件和求解方法。

## 3. 最少硬币：从状态表到可验证方案

<a id="sec-1-1"></a>

<a id="algo-3-detail-11"></a>

### 3.1 手算完整状态表

面额为一、三、四，令 $`dp[a]`$ 表示组成金额 $`a`$ 的最少枚数。边界 $`dp[0]=0`$，其余先为不可达。按金额递增，有 $`dp[1]=1`$、$`dp[2]=2`$、$`dp[3]=1`$、$`dp[4]=1`$，再由四加一得到 $`dp[5]=2`$。

金额六的候选包括 $`dp[5]+1=3`$、$`dp[3]+1=2`$ 与 $`dp[2]+1=3`$，因此最优为二。每个候选表示一个合法最后面额，不需要枚举所有硬币排列。保存获胜的最后面额三，再回到金额三，就能恢复三加三。

这个例子同时揭示不可达状态的重要性。面额只有二，金额三时，金额一不可达，不能把它当作零成本前缀。若初始化所有位置为零，代码会制造不存在的方案。数值初始化必须忠实于状态含义，而不是为了方便累加随意选择。

<a id="sec-2-1"></a>

<a id="algo-3-detail-12"></a>

### 3.2 边界、同分规则和接口

最小化目标的不可达值可以用正无穷，或在已知上界时使用一个严格更大的整数哨兵。使用无穷时，恢复方案前应先判断可达；使用整数时，要证明任何合法答案不会超过哨兵，并避免加法溢出。在 Python 大整数中溢出问题较少，但算法意义仍需明确。

同样最优的方案可能不唯一。可以按输入面额顺序取第一个，也可以选择字典序等规则。最优值正确不意味着方案身份唯一，测试不应把某一种同分方案当成唯一答案，除非接口明确要求。重复面额可以去重以减少重复转移，但不应误把重复面额当作可用枚数。

金额零的最优方案是空列表，空面额集合只能组成零。负目标、非整数和非正面额应按契约拒绝，而不是进入数组后由负索引产生偶然结果。边界测试应直接对应这些定义，不只测试普通有解情况。

<a id="algo-3-detail-13"></a>

### 3.3 完整实现与独立广度优先参考

下面的动态规划同时返回最优值与一个可行方案。独立参考把金额看作节点、加一枚硬币看作单位边，广度优先搜索到目标的最短步数，因此用不同求解顺序核对最少枚数。它仍使用同一数学问题，但不复用动态规划的更新代码，能帮助发现循环与恢复错误。

```python
from collections import deque
from random import Random

def coin_solution(coins, target):
    if type(target) is not int or target < 0:
        raise ValueError("target must be a nonnegative integer")
    coins = tuple(coins)
    if any(type(c) is not int or c <= 0 for c in coins):
        raise ValueError("coin values must be positive integers")
    coins = tuple(sorted(set(coins)))
    unreachable = target + 1
    dp = [0] + [unreachable] * target
    last = [None] * (target + 1)
    for amount in range(1, target + 1):
        for coin in coins:
            if coin > amount:
                break
            if dp[amount-coin] + 1 < dp[amount]:
                dp[amount] = dp[amount-coin] + 1
                last[amount] = coin
    if dp[target] == unreachable:
        return None
    used, amount = [], target
    while amount:
        coin = last[amount]
        assert coin is not None
        used.append(coin)
        amount -= coin
    assert sum(used) == target and len(used) == dp[target]
    return dp[target], used

def bfs_count(coins, target):
    queue = deque([(0, 0)])
    seen = {0}
    while queue:
        amount, count = queue.popleft()
        if amount == target:
            return count
        for coin in coins:
            nxt = amount + coin
            if nxt <= target and nxt not in seen:
                seen.add(nxt)
                queue.append((nxt, count+1))
    return None

rng = Random(13)
for _ in range(100):
    coins = sorted(set(rng.randint(1, 7) for _ in range(3)))
    target = rng.randint(0, 25)
    answer = coin_solution(coins, target)
    assert (None if answer is None else answer[0]) == bfs_count(coins, target)
assert coin_solution([1, 3, 4], 6)[0] == 2
assert coin_solution([2], 3) is None
assert coin_solution([], 0) == (0, [])
print("coin DP and BFS agree on 100 random cases")
```

<a id="algo-3-detail-14"></a>

### 3.4 时间、空间与伪多项式边界

设目标为 $`A`$，不同面额数为 $`m`$，表中有 $`A+1`$ 个状态，每个至多考虑 $`m`$ 个转移，因此常见单位代价模型下时间为 $`O(Am)`$，额外表空间为 $`O(A)`$。恢复方案长度至多为 $`A`$，这是正整数面额带来的上界。

但金额的二进制输入长度约为 $`\log_2(A+1)`$，所以按金额数值多项式，不等于按输入比特长度多项式。这类复杂度通常称为伪多项式。把目标从一百万改成一万亿，输入字符串只增长少量数字，数组规模却增加一百万倍。

若面额最大公约数不能整除目标，可以先判无解；若能整除，也不保证小金额一定可达。可以按公共因子缩放数值，但仍需分析缩放后的状态规模。数学预处理可以减少工作，不能把所有巨大整数问题都变成小表。

## 4. 零一背包与循环顺序的证明

<a id="algo-3-detail-16"></a>

### 4.1 二维状态先表达物品使用约束

给定 $`n`$ 件物品，重量为正整数 $`w_i`$，价值为 $`v_i`$，每件至多使用一次，容量为 $`C`$。定义 $`F(i,c)`$ 为只考虑前 $`i`$ 件、总重量不超过 $`c`$ 时的最大价值。允许空集合，故 $`F(0,c)=0`$，即使某些价值为负，也可以选择不取。

考虑第 $`i`$ 件，任何最优方案要么不取，价值不超过 $`F(i-1,c)`$；要么取一次，剩余只能从前 $`i-1`$ 件中选择，价值为 $`F(i-1,c-w_i)+v_i`$。因此在重量合法时取两者最大。这个按最后物品分类的论证明确保证没有重复使用当前物品。

如果问题要求恰好装满容量，边界就不同：除容量零外，其他初始状态都应为不可达，不能全部设零。若允许负价值且必须装满，最优值也可能为负。状态中“至多”与“恰好”两个词会改变整个递推，不能只改最终返回值修补。

<a id="algo-3-detail-17"></a>

### 4.2 一维压缩为什么必须倒序

二维递推的第 $`i`$ 行只读取第 $`i-1`$ 行，可以复用一个数组。但更新容量时必须保证读到的较小容量仍是旧行。如果容量从大到小遍历，$`c-w_i<c`$ 尚未在当前物品轮次更新，因而对应前 $`i-1`$ 件，保持零一约束。

若从小到大，较小容量可能已经包含当前物品，新状态又在其上加一次价值，于是变成允许当前物品重复使用。这个变化不是微小实现误差，而是求解了不同问题。单件重量二、价值三、容量四，倒序得到三，正序会得到六，就是最小的反例之一。

相反，无限次可用背包常正需要正序依赖当前行。这说明循环方向由依赖语义决定，不是背包题的固定口诀。加入次数上限、多种资源或组内互斥时，应重新推导状态和读写关系，不能按问题名称机械套模板。

<a id="algo-3-detail-18"></a>

### 4.3 空间压缩可能破坏方案恢复

只求最优值时，一维表足够；若要恢复具体物品，简单保存每个容量的一个可变前驱指针可能失效。后续物品会覆盖前驱所依赖的旧版本，回溯时可能重复使用同一物品，或者恢复出与最优值不一致的方案。

稳妥方案包括保留完整二维选择表、保存不可变版本链接，或采用分治重建。它们在内存和重算之间取舍。不能把数值表空间降为 $`O(C)`$ 后，就无条件宣称包含完整方案恢复的总空间也为 $`O(C)`$。

任何恢复结果都应检查物品索引唯一、重量不超容量、价值与最优值一致。仅检查最优数值无法发现回溯错误。若价值改为浮点，正向累加与回溯求和的舍入顺序可能不同，需要重新定义容差与数值目标，不能保留整数实现中的严格等式并假定对任意实数也成立。对于小规模，可以枚举所有子集作为独立参考，再逐步测试更大输入与空间优化。

<a id="algo-3-detail-19"></a>

### 4.4 用穷举验证值与见证

下面的教学实现要求重量和价值均为整数，保留二维表并恢复一个方案，同时用子集穷举对照。价值允许为负，状态定义为不超过容量且允许空集合；因此无需把负价值物品强行选入。测试还包含空物品集合与容量零，保证边界与状态含义一致。

```python
from itertools import product
from random import Random

def knapsack(items, capacity):
    if type(capacity) is not int or capacity < 0:
        raise ValueError("capacity must be a nonnegative integer")
    if any(type(w) is not int or w <= 0 for w, _ in items):
        raise ValueError("weights must be positive integers")
    if any(type(v) is not int for _, v in items):
        raise ValueError("values must be integers in this exact implementation")
    n = len(items)
    table = [[0] * (capacity+1) for _ in range(n+1)]
    take = [[False] * (capacity+1) for _ in range(n+1)]
    for i, (weight, value) in enumerate(items, 1):
        for c in range(capacity+1):
            table[i][c] = table[i-1][c]
            if weight <= c:
                candidate = table[i-1][c-weight] + value
                if candidate > table[i][c]:
                    table[i][c] = candidate
                    take[i][c] = True
    chosen, c = [], capacity
    for i in range(n, 0, -1):
        if take[i][c]:
            chosen.append(i-1)
            c -= items[i-1][0]
    assert len(chosen) == len(set(chosen))
    assert sum(items[i][0] for i in chosen) <= capacity
    assert sum(items[i][1] for i in chosen) == table[n][capacity]
    return table[n][capacity], sorted(chosen)

def brute(items, capacity):
    best = 0
    for mask in product([0, 1], repeat=len(items)):
        weight = sum(w * bit for (w, _), bit in zip(items, mask))
        value = sum(v * bit for (_, v), bit in zip(items, mask))
        if weight <= capacity:
            best = max(best, value)
    return best

rng = Random(29)
for _ in range(80):
    items = [(rng.randint(1, 6), rng.randint(-2, 9))
             for _ in range(rng.randint(0, 7))]
    capacity = rng.randint(0, 14)
    assert knapsack(items, capacity)[0] == brute(items, capacity)
assert knapsack([(2, 3)], 4)[0] == 3
print("0/1 knapsack values and witnesses verified")
```

## 5. 同一状态，不同代数与计数含义

<a id="algo-3-detail-21"></a>

### 5.1 最优值、可达性与方案数

同样的状态依赖图，可以在每个节点保存最小代价、最大价值、可达布尔值或方案数。它们使用不同的合并运算与转移运算：最小代价用最小与加法，可达性用或与合法转移，计数则累加互不重叠方案集合的大小。

关键条件是计数中的候选集合必须避免重复。如果两条转移最终代表同一个组合，却被当作不同方案相加，结果就会多算。最优值递推中重复候选通常只浪费时间，计数递推中则会改变答案，因此不能只把最小改成加号就期待语义自动正确。

在图路径、序列标注和语法分析中，这种“同一图、不同聚合代数”的视角很有价值。它能帮助从最优路径推广到总概率、配分函数或布尔识别。但每个运算体系都需要相应的边界与合法性条件，尤其有环或无限路径时，求和可能不收敛。

<a id="algo-3-detail-22"></a>

### 5.2 硬币组合数与排列数的区别

若金额为三、面额一和二，按顺序区分的方案有一一一、一二、二一，共三种；忽略顺序的组合只有三枚一和一枚一加一枚二，共两种。二者共享金额范围，却不是同一个计数任务。

按金额外层递增、每个面额作为最后一步相加，通常得到顺序敏感的方案数，因为一二与二一来自不同最后面额。按面额外层、金额内层递增，则可以把方案规范成按已处理面额构造的组合，避免不同排列重复计数。

如果每枚物品独立有身份，即使面额相同，零一选择的组合定义又会变化。应先定义方案何时视为相同，再设计状态和转移。计数结果很容易在小样例上看似合理，因此最好手动列出全部方案，明确循环对应的是哪一种等价关系。

<a id="algo-3-detail-23"></a>

### 5.3 支配剪枝与 Pareto 前沿

多资源问题中，一个状态可能需要同时记录重量、时间和价值。若某历史使用的资源不少于另一历史、价值又不更好，且未来动作只依赖这些资源，则它可被支配而删除。保留非支配状态形成 Pareto 前沿，可以比完整网格更省空间。

但这种压缩依赖可比较的资源与相同未来可行性。若某历史还隐含拥有特殊权限、已访问节点或不同剩余物品，即使当前资源数值较差，也不能直接删除。支配证明仍然是状态充分性证明的一部分。

最坏情况下 Pareto 前沿也可能很大，稀疏存储并不保证多项式规模。研究中应同时报告实际状态数与最坏分析，避免只在容易样本上观察到少量状态，就声称解决了高维组合爆炸。

<a id="algo-3-detail-24"></a>

## 6. 编辑距离：二维依赖与方案恢复

<a id="algo-3-detail-25"></a>

### 6.1 三种最后操作覆盖全部最优方案

给定两个字符串 $`a,b`$，允许单位代价插入、删除与替换，定义 $`D(i,j)`$ 为把 $`a`$ 的前 $`i`$ 个字符变为 $`b`$ 的前 $`j`$ 个字符的最少代价。边界为 $`D(i,0)=i`$、$`D(0,j)=j`$，因为空串到非空前缀只能插入，反向只能删除。

最后一步要么删除 $`a`$ 的末字符，前驱为 $`D(i-1,j)+1`$；要么插入 $`b`$ 的末字符，前驱为 $`D(i,j-1)+1`$；要么匹配或替换两个末字符，前驱为 $`D(i-1,j-1)+[a_{i-1}\ne b_{j-1}]`$。三类覆盖最后对齐方式，取最小得到递推。

这个定义不包含交换相邻字符的操作；若要支持交换，需要改变状态或转移，不能把标准编辑距离的答案当成所有拼写修改模型的答案。插入、删除、替换若有不同权重，也要重新写出相应成本与边界。

<a id="algo-3-detail-26"></a>

### 6.2 字符单位和应用语义

Python 字符串按 Unicode 码点索引，不等于用户眼中的所有可见字符单元。一个带组合标记的字符可能由多个码点构成，表情序列也可能有多个组成部分。编辑距离作用于什么 token，应由应用决定：码点、字素簇、词、音素或其他单元都可以。

若先做大小写或 Unicode 规范化，计算的是规范化后序列的距离。这个选择可能合理，但会改变事件与可恢复信息。不能把删除空白后得到更小距离解释成原始文本生成质量自然更好，而不说明预处理。

在机器学习评价中，字符错误率与词错误率还要定义分母、样本汇总和空参考处理。动态规划给出编辑数，不自动决定如何跨文档平均。算法正确与评价口径正确是两个层次，应分别核对。

<a id="algo-3-detail-27"></a>

### 6.3 两行滚动数组与分治重建

若只需距离值，每个单元依赖上一行与当前行左侧，可以把空间降到线性。若让较短字符串作为列，额外空间可为 $`O(\min(m,n))`$。对称的单位成本距离允许交换两输入；对于方向性或非对称成本，不应未经推导就交换。

若要完整对齐，直接保留所有前驱需要二维空间。线性空间分治重建可以计算前向与后向代价，找到某个中间切分，再递归恢复两部分。它通过额外重算换空间，但需要正确处理同分切分与边界，不能简单说两行数组仍保留了全部路径。

实际选择取决于输出需求。短文本保留完整表更易解释，长序列只求分数时滚动数组更合适。若问题有已知最大误差阈值，可以研究带状算法，但必须保证最优路径位于所搜索带内，或者把结果明确作为受限近似。

<a id="algo-3-detail-28"></a>

### 6.4 小序列独立搜索核对

下面实现两行编辑距离，并对很短的二元字母表字符串用操作图的广度优先搜索对照。搜索只用于小规模验证：每一步枚举插入、删除、替换，状态数迅速增加，不是面向长文本的替代算法。限制中间长度不超过两串最大长度，在这里的单位成本标准编辑问题中可保留一个最优方案。

```python
from collections import deque
from itertools import product

def edit_distance(a, b):
    if len(a) < len(b):
        a, b = b, a
    prev = list(range(len(b)+1))
    for i, ca in enumerate(a, 1):
        current = [i]
        for j, cb in enumerate(b, 1):
            current.append(min(prev[j]+1, current[-1]+1,
                               prev[j-1]+(ca != cb)))
        prev = current
    return prev[-1]

def tiny_edit_search(a, b, alphabet=("a", "b")):
    limit = max(len(a), len(b))
    queue = deque([(a, 0)])
    seen = {a}
    while queue:
        word, depth = queue.popleft()
        if word == b:
            return depth
        candidates = []
        for i in range(len(word)):
            candidates.append(word[:i]+word[i+1:])
            for c in alphabet:
                candidates.append(word[:i]+c+word[i+1:])
        if len(word) < limit:
            for i in range(len(word)+1):
                for c in alphabet:
                    candidates.append(word[:i]+c+word[i:])
        for nxt in candidates:
            if nxt not in seen:
                seen.add(nxt)
                queue.append((nxt, depth+1))
    raise AssertionError("target should be reachable")

words = [""] + ["".join(chars) for n in [1, 2]
                for chars in product("ab", repeat=n)]
for a in words:
    for b in words:
        assert edit_distance(a, b) == tiny_edit_search(a, b)
assert edit_distance("kitten", "sitting") == 3
print("rolling edit distance verified against operation search")
```

## 7. 带权区间选择：排序与动态规划的组合

<a id="algo-3-detail-30"></a>

### 7.1 兼容前驱把全局冲突压缩为前缀

每个任务有开始时间、结束时间和价值，任务区间采用左闭右开，结束恰好等于下一开始视为兼容。先按结束时间排序，令 $`p(i)`$ 为第 $`i`$ 个任务之前最后一个兼容任务的位置，定义 $`V(i)`$ 为前 $`i`$ 个任务中的最大兼容总价值。

最优方案若不选第 $`i`$ 个任务，值为 $`V(i-1)`$；若选，则此前所有任务必须在其开始前结束，最优前缀值为 $`V(p(i))`$。所以递推为两者最大。排序使兼容候选形成一个前缀，这是能够只用一个下标状态的关键，不是任意冲突图都具备的性质。

无权区间调度中按最早结束贪心可以最大化任务数；加入价值后，选一个很早结束但低价值的任务，可能阻挡稍晚却高价值的任务，因此不能直接沿用原贪心。动态规划保留选与不选两个分支，正是在补上被贪心过早删除的选择。

<a id="algo-3-detail-31"></a>

### 7.2 二分前驱与边界语义

结束时间有序，可以二分找到不超过当前开始时间的最后结束位置。采用左闭右开区间时使用不超过；若区间端点都占资源，兼容条件可能变为严格小于，二分边界也要改变。同一行代码选左边界还是右边界，背后对应具体问题定义。

零长度区间需要额外约定。本章要求开始严格小于结束，避免零长度任务在某些资源语义下产生特殊兼容情况。任务有重复时间或相同价值不影响递推，但恢复时应保存唯一身份，以区分不同任务，并明确同分方案选择规则。

预处理排序与前驱查找合计 $`O(n\log n)`$，动态规划和恢复为线性。这里改进来自对兼容结构的利用，不是把所有候选转移暴力枚举后用缓存隐藏。分析算法时应分别计算预处理、状态求值和输出恢复成本。

<a id="algo-3-detail-32"></a>

### 7.3 完整实现与所有子集对照

下面返回最优总价值和原任务编号。穷举参考检查任意选中任务两两不冲突，用不同结构验证状态压缩确实保留全部合法组合。负价值可以存在，允许空集合，因此最优值至少为零。

```python
from bisect import bisect_right
from itertools import combinations
from random import Random

def interval_schedule(jobs):
    if any(start >= end for start, end, value in jobs):
        raise ValueError("use nonempty half-open intervals")
    ordered = sorted((end, start, value, idx)
                     for idx, (start, end, value) in enumerate(jobs))
    ends = [job[0] for job in ordered]
    predecessor = [bisect_right(ends, start, 0, i)
                   for i, (end, start, value, idx) in enumerate(ordered)]
    dp = [0] * (len(jobs)+1)
    take = [False] * len(jobs)
    for i, (end, start, value, idx) in enumerate(ordered):
        candidate = value + dp[predecessor[i]]
        dp[i+1] = dp[i]
        if candidate > dp[i]:
            dp[i+1] = candidate
            take[i] = True
    selected, i = [], len(jobs)
    while i:
        if take[i-1]:
            selected.append(ordered[i-1][3])
            i = predecessor[i-1]
        else:
            i -= 1
    selected.sort()
    assert sum(jobs[idx][2] for idx in selected) == dp[-1]
    for a, b in combinations(selected, 2):
        assert jobs[a][1] <= jobs[b][0] or jobs[b][1] <= jobs[a][0]
    return dp[-1], selected

def brute_intervals(jobs):
    best = 0
    for mask in range(1 << len(jobs)):
        ids = [i for i in range(len(jobs)) if mask >> i & 1]
        if all(jobs[a][1] <= jobs[b][0] or jobs[b][1] <= jobs[a][0]
               for a, b in combinations(ids, 2)):
            best = max(best, sum(jobs[i][2] for i in ids))
    return best

rng = Random(37)
for _ in range(60):
    jobs = []
    for _ in range(rng.randint(0, 8)):
        start = rng.randint(0, 9)
        jobs.append((start, start+rng.randint(1, 5), rng.randint(-2, 10)))
    assert interval_schedule(jobs)[0] == brute_intervals(jobs)
assert interval_schedule([(0, 2, 3), (2, 4, 4)])[0] == 7
print("weighted interval DP and reconstruction verified")
```

## 8. 进阶状态：区间、子集和约束自动机

<a id="algo-3-detail-34"></a>

### 8.1 矩阵链乘法选择的是计算括号

矩阵相乘的结果在数学上满足结合律，但不同括号的标量乘法次数可以差很多。矩阵链区间状态 $`M(i,j)`$ 表示第 $`i`$ 到第 $`j`$ 个矩阵乘积的最小代价。枚举最后一次乘法的切分点 $`k`$，把左右子链最优成本加上两部分相乘成本。

例如维度依次为十乘三十、三十乘五、五乘六十，先乘前两矩阵总成本为一千五百加三千，共四千五百；先乘后两矩阵总成本为九千加一万八千，共两万七千。结果维度相同，计算工作却相差六倍。

状态数为平方级，每个区间枚举线性多个切分，常见算法时间立方级。按区间长度递增计算能保证子区间已求解。若实际目标是运行时间、内存峰值或通信成本，纯标量乘法数模型可能不够，应修改代价与状态，不能把理论乘法最少自动等同本机最快。

<a id="algo-3-detail-35"></a>

### 8.2 子集状态减少重复，却仍可能指数级

旅行商问题可定义 $`D(S,v)`$ 为从固定起点出发、恰访问集合 $`S`$、最后停在 $`v`$ 的最小路径代价。转移枚举上一个末点，状态需同时保存集合和当前位置；只记当前位置会遗漏哪些城市已访问，允许非法重复或错过必访城市。

位掩码让集合操作简洁，但没有让集合数量变小。可能状态为 $`O(n2^n)`$，转移常达到 $`O(n^22^n)`$。相比枚举排列的阶乘规模，它是重大改进，却仍不适合任意大的城市数。这是“动态规划”不等于“多项式算法”的另一个具体例子。

若只存集合不存末点，未来返回起点成本可能不同；若只存末点不存集合，可行剩余任务不同。状态充分性可以通过构造两个被合并历史的不同后续来反驳，通常比观察若干样例失败更能定位设计问题。

<a id="algo-3-detail-36"></a>

### 8.3 正则约束可以与原状态做乘积

若序列选择还要求不能连续出现三次某类动作，可以用一个小自动机记录最近连续次数，并与原来的位置或资源状态组成乘积。自动机状态只保留约束需要的历史，不必保存整个前缀，从而把路径约束转成局部转移是否合法。

但若约束是任意复杂的全局属性，所需自动机或记忆可能很大。比如“每个元素最多出现一次”通常就需要集合信息。把状态命名为合法标志，并不能神奇地压缩所有约束；应说明这个标志如何更新，以及是否真的足以决定未来。

这个视角连接序列解码、有限状态语言、受约束搜索和强化学习。它提供一种构造状态的方法：先找出原目标需要的状态，再找出约束识别器需要的状态，取二者组合。之后仍要评估乘积规模与可达性，必要时只存实际访问状态。

<a id="algo-3-detail-37"></a>

## 9. 从确定性递推到有限时域与折扣决策

<a id="algo-3-detail-38"></a>

### 9.1 时间维度让随机决策形成无环递推

若系统状态为 $`s`$，动作 $`a`$ 决定即时成本和下一状态分布，有限时域最优值可写为

$$
V_t(s)=\min_a\left\{c_t(s,a)+
\sum_{s'}P_t(s'\mid s,a)V_{t+1}(s')\right\}.
$$

终点给定 $`V_T`$，从后往前计算。随机转移把单个前驱代价换成期望，但最优子结构仍依赖当前状态包含未来所需的信息。若系统实际上依赖更长历史，却只用当前观测作为状态，递推可能求解错误模型。

有限时域中相同物理状态在不同剩余时间下价值不同，所以时间不能随意省略。最后一步与还有一百步时的资源价值不一样。把时间加入状态还消除了求值环，尽管物理系统可以返回曾经出现的位置，分层依赖始终向终点推进。

部分可观测问题中，当前观测未必充分。可以把对隐藏状态的信念分布作为信息状态，但其空间通常连续且求解更难。这说明理论上能构造充分状态，不意味着计算上容易；模型化误差与状态空间代价需要一起讨论。

<a id="algo-3-detail-39"></a>

### 9.2 折扣 Bellman 算子的收缩条件

在有限状态动作、即时成本有界且折扣 $`0\leq\gamma<1`$ 的设置，定义 $`T`$ 为一步最优更新。对任意两个值函数 $`U,V`$，每个动作期望差不超过 $`\gamma\Vert U-V\Vert _\infty`$，取最小值也不会放大这个界，因此

$$
\Vert TU-TV\Vert _\infty\leq\gamma\Vert U-V\Vert _\infty.
$$

这给出唯一固定点与迭代收敛的依据。若当前残差为 $`r=\Vert TV-V\Vert _\infty`$，则由三角不等式与收缩可得距最优固定点不超过 $`\frac{r}{(1-\gamma)}`$。折扣接近一时，同样残差对应更大的误差界，因此停止阈值应结合折扣而定。

当折扣等于一、成本无界或状态模型不同，不能直接沿用收缩结论。最短路、平均成本和随机终止问题有各自条件。研究中看到 Bellman 方程时，先核对求解的是哪种目标，比只比较迭代曲线是否下降更重要。

<a id="algo-3-detail-40"></a>

### 9.3 近似值函数会引入新的误差对象

大状态空间常用函数近似表示值函数或策略，此时每次更新可能还包含投影、采样和优化误差。原始 Bellman 算子收缩，不自动意味着加入任意投影与训练过程后仍收缩。离策略数据、函数类失配和估计误差可能改变稳定性。

同样，动态规划的精确状态表能给出理论最优值，不表示神经近似会在有限训练预算下达到它。可以先用小有限问题建立精确参考，再逐步加入近似组件，观察误差与稳定性来源。这个分层实验思路与前面用穷举核对小规模算法是一致的。

对 AI 学习者，这一节主要建立联系，而不是替代强化学习课程。进一步学习时，应把状态充分性、目标时间范围、数据分布和近似误差持续放在同一张问题清单中，避免只记更新公式而忽略其成立条件。

<a id="algo-3-detail-41"></a>

## 10. 优化之前先保存正确性证据

<a id="algo-3-detail-42"></a>

### 10.1 单调队列、分治优化与结构假设

某些动态规划的转移最优位置具有单调性，或代价满足四边形不等式等结构，可以减少候选枚举。另一些递推可以把滑动窗口最值交给单调队列，或者把线性形式比较转成适合的包络结构。这些技巧很有价值，但每一种都需要相应证明。

不能因为状态写成某个最小表达式，就直接套用分治优化或所谓通用模板。若最优切分不单调，限制搜索范围会删掉真正最优候选；若包络斜率与查询顺序不满足条件，队列删除也可能错误。先保留一个小规模正确基线，再用反例测试结构条件。

用一个具体递推说明单调队列究竟证明了什么。设 $`f_0=0`$，对 $`t\ge1`$ 定义

$$
\begin{aligned}
f_t &=c_t+\max_{\max(0,t-L)\le j<t}f_j,\\[6pt]
L &\ge1.
\end{aligned}
$$

含义是到达时刻 $`t`$ 获得收益 $`c_t`$，上一状态最多早 $`L`$ 步，求必须到达 $`t`$ 的最大总收益。朴素算法每个位置检查最多 $`L`$ 个前驱，耗时 $`O(nL)`$。这里能优化的关键不只是出现了最大值，而是候选窗口左右边界都随 $`t`$ 向前移动，且候选比较值 $`f_j`$ 不随查询时刻改变。

队列按下标递增保存候选，并使对应 $`f_j`$ 严格递减。计算 $`f_t`$ 前，先从队首删除下标小于 $`t-L`$ 的过期项，剩余队首便是窗口最大值。得到新值后，从队尾删除所有 $`f_j\le f_t`$ 的旧候选，再把 $`t`$ 放到队尾。删除的理由是支配：对任何以后仍允许旧下标 $`j`$ 的窗口，新下标 $`t>j`$ 都还没有过期，且数值不小于 $`f_j`$，所以旧项永远不能严格改善未来最大值。按这个理由逐项删除，才证明丢弃候选不会丢掉所需最优值。

例如 $`L=3`$、$`c_1,\ldots,c_5=(2,-1,3,-2,4)`$，逐项得到 $`f=(0,2,1,5,3,9)`$。处理完时刻一，队列只剩下标一；时刻二后为一、二；时刻三的新值五同时支配两项，队列变为三；时刻四后为三、四；时刻五取队首值五，加收益四得到九，再删除被支配项。每个下标只入队一次，且只会从队首过期或从队尾淘汰一次，因此队列总操作数为 $`O(n)`$，工作空间为 $`O(L)`$，而非每一步都重新扫描整个窗口。

同分处理取决于输出契约。上述尾部使用“小于等于”会保留较新的同值候选，保证最优值正确；若恢复方案时要求同分优先更早前驱，应只删除严格较小项并保留同值项的下标次序。若奖励改成依赖 $`(j,t)`$ 的一般函数，旧候选在当前更差不代表未来仍更差，支配证明就不再成立。优化模板必须连同候选有效期、比较函数和同分规则一起使用。

优化报告应同时说明时间模型与数值行为。把二维表改成一维数组可能更省内存，却破坏恢复；把整数代价改成浮点近似可能改变同分；把稠密表改成字典可能减少状态，却增加对象开销。渐近分析与实现测量应相互补充。

<a id="algo-3-detail-43"></a>

### 10.2 验证值、方案、状态数和边界

算法验证至少有四个层次：最优值与参考一致，恢复方案满足原约束，实际访问状态符合规模预期，非法与不可达输入有清楚行为。只对随机正常输入比较返回数字，可能漏掉无限递归、错误同分和回溯覆盖等问题。

对复杂算法，故意构造不满足充分性的小例子非常有帮助。有限库存却只记金额、零一背包正序更新、区间端点混用、编辑距离字符单位变化，都能让读者看到定义如何影响代码。反例不是边角知识，而是理解正确性假设的主要工具。

最终还要对输出需求负责。若只求值，可以采用更强空间压缩；若要解释和证书，应保留可恢复信息；若要所有最优方案，输出本身可能指数级。不能宣称一个多项式计算的最优值算法，也能在同样时间内列出指数多个最优解。

<a id="algo-3-detail-44"></a>

## 11. 研究延伸：概率递推与近似保证

<a id="algo-3-detail-45"></a>

### 11.1 从最优路径到所有路径的总权重

在一个有限无环状态图中，若每条边有非负权重，可以把每条完整路径的权重定义为沿途边权乘积，并对所有路径求和。节点前向值等于所有前驱值乘对应边权后相加。这与最短路径的依赖图相同，却使用求和与乘法，而不是最小与加法。

若边权是条件概率且图确实表达一个规范化生成过程，总权重可以解释为观测事件概率；若边权只是未归一化分数，总和则是配分函数，不能自动叫概率。路径可能共享节点，但前向递推仍正确，因为每个进入状态的前缀与后续边组合构成明确的路径分解。

数值很小时可以在对数域计算，以 log-sum-exp 代替直接求和乘法。取最大值的最优路径递推与 log-sum-exp 的总路径递推并不相同。前者只保留最好方案，后者累计所有方案，即使许多单条路径概率较小，总质量也可能占主导。把两者替换会改变学习目标。

<a id="algo-3-detail-46"></a>

### 11.2 前向后向与边使用概率

设 $`F(u)`$ 为到节点 $`u`$ 的前缀总权重，$`B(v)`$ 为从节点 $`v`$ 到终点的后缀总权重，总路径权重为 $`Z>0`$。边 $`u\to v`$ 权重为 $`w_{uv}`$，则通过该边的路径总权重为 $`F(u)w_{uv}B(v)`$，除以 $`Z`$ 得到按路径权重归一后的边使用概率。

这个公式不是凭经验把两个数相乘，而是利用无环路径在指定边处的唯一前后分解。如果一条完整路径可多次通过同一边，解释会涉及期望次数，求和与收敛条件也需重新处理。本节限定有限无环图，避免把有限动态规划公式直接推广到无限循环。

在合法路径支持固定、相关边权为正且可微的条件下，令 $`s_e=\log w_e`$，有限路径和可逐项求导，得到 $`\partial_\theta\log Z=\mathbb E_\pi[\sum_{e\in\pi}\partial_\theta s_e]`$。固定零权边应先从有效支持排除；在支持变化或边权穿过零的边界，不能无条件沿用这个对数分数恒等式。这把动态规划与可微学习联系起来。实际自动微分可以沿前向程序反传，但手推前向后向提供独立检查，也帮助理解缓存哪些量、何时重算以及归一化因子从哪里来。

<a id="algo-3-detail-47"></a>

### 11.3 零一背包的价值缩放与近似证明

当容量巨大时，按容量建表可能不可行。若价值为非负整数，也可以改用“达到某个总价值所需最小重量”的状态。这样复杂度依赖总价值，而不是容量。这仍可能是伪多项式，却提供了按价值缩放构造近似算法的入口。

先删除重量超过容量的物品，令剩余最大价值为 $`V_{\max}>0`$，精度参数为 $`0<\varepsilon<1`$，缩放步长取 $`\Delta=\frac{\varepsilon V_{\max}}{n}`$。把价值变为 $`\lfloor\frac{v_i}{\Delta}\rfloor`$，对缩放价值运行精确动态规划，再返回原价值下的所选集合。每件向下舍入损失小于 $`\Delta`$，至多选择 $`n`$ 件，总损失小于 $`n\Delta`$。

设原最优集合为 $`S^*`$，缩放问题最优集合为 $`\hat S`$。后者缩放总价值不低于前者，所以其真实总价值至少为 $`\operatorname{OPT}-n\Delta`$。又因为每件剩余物品都可单独放入，$`V_{\max}\leq\operatorname{OPT}`$，因此得到至少 $`(1-\varepsilon)\operatorname{OPT}`$ 的保证。若最大价值为零，任意可行空方案已最优，应单独处理。

每件缩放价值不超过约 $`\frac{n}{\varepsilon}`$，总缩放价值为 $`O(\frac{n^2}{\varepsilon})`$，朴素价值表时间为 $`O(\frac{n^3}{\varepsilon})`$。这是一个具有明确近似保证的构造，不只是随意减少表大小。严格位复杂度还需计入整数与有理数运算成本，使用浮点缩放时也要避免舍入跨越整数边界破坏证明。

<a id="algo-3-detail-48"></a>

### 11.4 近似状态合并必须说明误差怎样累计

有时研究者把相近资源值归到同一桶，以减少状态。这不自动产生上述近似保证。若合并后的状态拥有不同未来可行性，可能漏掉唯一可行方案；若每一步引入小误差，也可能在长路径上累积或被后续非线性放大。

一个可靠近似应说明哪些量被舍入、舍入朝哪个方向、可行性是否保留，以及最终代价界如何从局部界推出。若只能通过实验观察误差，应称为经验近似，并在具有精确参考的小规模上报告分布与最坏观察值，不能把实验最大误差当成所有输入的理论上界。

这也是动态规划与研究方法的重要连接：既要能够构造精确状态，也要能够判断什么时候可以有控制地压缩它。状态越少不必然越好，只有在正确性或误差目标清楚时，计算节省才具有可解释价值。


<a id="algo-3-detail-49"></a>

### 11.5 最优值也可以附带局部可核对证书

对最小代价路径问题，可以给每个相关状态一个有限势值，使起点势值为零，并对每条合法边满足终点势值不超过起点势值加边成本。沿任意起点到目标路径把这些不等式相加，中间势值消去，得到目标势值不超过该路径成本。因此它提供所有可行路径共同的下界。

若另给一条合法路径，其成本恰好等于目标势值，下界与可行上界相合，就证明该路径最优。动态规划表在正确递推下自然提供这样的势值，但审阅者可以只检查边不等式和返回路径，而不必相信求解程序的全部内部过程。检查全部边的代价可能仍然很大，不过逻辑上把求解与核验分开了。

这也解释为什么一个数值答案不足以成为充分学习成果。能够恢复方案只证明可行上界，能够给出下界或递推证据才能证明没有更优方案。对于近似算法，同样可以报告可行值与可证明界之间的差距；若只有经验参考，应准确称为在已测样例上核对，而不是通用最优证书。

<a id="algo-3-detail-50"></a>

### 11.6 求最优方案数需要独立处理同分

在无环图上，可同时保存最优代价和达到该代价的路径数。某个候选严格更优时，用其计数替换；与当前最优相等时，累加其计数。前提是不同转移代表互不重复的完整方案分解，并且同分比较有明确定义。若浮点成本接近却不完全相等，使用任意容差可能把非最优路径也算入，需要说明数值目标。

如果问题把硬币排列视为同一方案，直接按最后硬币计数仍会重复；即使最优值表正确，最优方案数也可能错。应先建立规范表示，或者在状态中保留避免重复的顺序约束。大量最优方案的计数还可能需要很长整数，不能继续把任意精度加法当作固定成本而不注明计算模型。

<a id="algo-3-detail-51"></a>

### 11.7 空间优化对应状态生存期分析

一张表中，某状态何时可以释放，取决于是否还有尚未计算的消费者会读取它。两行编辑距离之所以可行，是因为更早的行不再被未来转移使用；零一背包倒序则是在同一数组里维持旧状态的生存期。可以把这种分析看作依赖图上的内存调度，而不只是数组技巧。

若必须保存恢复路径、梯度或解释证据，状态的消费者就增加了，生存期也会延长。重计算可以用时间换空间，但应估算额外工作，并确保重计算读取同样输入与规则。这个思想与深度学习中的激活检查点相通：释放中间值不改变数学问题，前提是后来能以正确依赖重新得到它。

实际实现还要区分表内元素数量与真实内存。Python 的整数对象、列表引用与字典键都有开销，一百万个逻辑状态不等于一百万个固定宽度机器字。若转成定宽数组节省内存，又需检查代价和计数是否溢出；因此状态数、数值范围和表示方式应一起进入资源预算。

<a id="algo-3-detail-52"></a>

## 12. 进阶练习与详细解析

<a id="algo-3-detail-53"></a>

### 12.1 练习一：缓存键遗漏了什么

**题目。** 函数只按金额缓存结果，但面额保存在可修改全局列表中。先用一、三、四求六，再把面额改成二、五继续求六，会有什么问题？

**解析。** 金额相同不再代表同一子问题，缓存可能返回前一个面额体系的答案。应为每个实例建立独立缓存，或把不可变面额集合纳入键。仅仅把全局列表改成元组而仍在外部替换引用，也不能修复已有缓存含义；必须明确缓存的实例边界与失效规则。

<a id="algo-3-detail-54"></a>

### 12.2 练习二：零面额为何破坏证明

**题目。** 最少硬币递推若允许面额零，递归形式会发生什么？自底向上实现没有无限循环，是否就说明设定正确？

**解析。** 递归会出现同金额依赖自身，严格减小的终止度量失效。表格实现可能只是忽略无用零币，但这需要单独论证，不能沿用原证明。若目标改为方案数，无限次零币甚至产生无限多个方案。输入约束应与问题目标一起定义，而不是只看某段实现是否停止。

<a id="algo-3-detail-55"></a>

### 12.3 练习三：贪心反例的最优性

**题目。** 面额一、三、四，金额六，为什么三加三不仅比贪心好，而且确实最优？

**解析。** 方案使用两枚，所以最优值至多二；不存在面额六，因此不可能用一枚，零枚又只能组成零，故最优值至少二。两侧界相合证明最优。只展示比某算法更好的方案，可以反驳该算法最优性，却未必已经证明新方案最优，本题用简单下界补齐证明。

<a id="algo-3-detail-56"></a>

### 12.4 练习四：零一背包的正序错误

**题目。** 单件物品重量三、价值五，容量六，一维数组正序更新会得到什么？倒序为什么避免它？

**解析。** 正序先把容量三更新为五，随后容量六读取已经包含该物品的容量三，再加五得到十，相当于用两次。倒序时容量六先读取旧容量三，其值为零，因此只能得到五。正确性来自读到上一层状态，而不只是某个循环方向在样例中碰巧有效。

<a id="algo-3-detail-57"></a>

### 12.5 练习五：恰好装满的初始化

**题目。** 重量三、价值负二，容量三，要求恰好装满。若所有初始容量值都设零，会怎样？正确值是什么？

**解析。** 允许空方案的零初始化会让算法返回零，但空方案并未装满。正确设置只有容量零可达，其他初始状态为负无穷或明确不可达标记，最终容量三值为负二。最大化中的不可达与真实零值必须分开，尤其当价值允许负数时更明显。

<a id="algo-3-detail-58"></a>

### 12.6 练习六：组合与排列的边界

**题目。** 面额一和二，金额四，列出忽略顺序的组合数与区分顺序的排列数，并解释为何循环组织不同。

**解析。** 组合为四枚一、两枚一加一枚二、两枚二，共三种；排列为一一一一、一一二、一二一、二一一、二二，共五种。按最后面额分解会区分不同顺序，按已处理面额前缀构造组合可避免排列重复。状态相同并不意味着聚合的方案集合相同。

<a id="algo-3-detail-59"></a>

### 12.7 练习七：同一金额不代表同一库存

**题目。** 面额二、三且每种只有一枚，两个历史都剩金额三，但一个已经用过三，另一个没有。能否合并为同状态？

**解析。** 不能，因为后者还能用三完成目标，前者不能。剩余金额没有包含未来可行动作所需的库存信息。可以加入物品前缀维度，或在一般资源约束中记录剩余库存。若用循环顺序隐式表达物品使用限制，也必须证明它与相应二维状态等价。

<a id="sec-6-1"></a>

<a id="algo-3-detail-60"></a>

### 12.8 练习八：金额复杂度与输入长度

**题目。** 目标从 $`2^{20}`$ 增到 $`2^{40}`$，金额表规模扩大多少？输入二进制长度约增长多少？这说明什么？

**解析。** 表规模约扩大 $`2^{20}`$ 倍，二进制长度只从约二十一位增到约四十一位。按数值大小线性并不等于按输入长度线性，这正是伪多项式的区别。算法选择必须估算实际状态数，不能仅看到递推是双循环就认定可扩展。

<a id="algo-3-detail-61"></a>

### 12.9 练习九：方案输出的成本

**题目。** 一个问题有指数多个最优方案，但最优值可用多项式时间求出。能否在同样多项式时间内显式列出全部最优方案？

**解析。** 一般不能，因为输出本身已需要指数大小。可以返回一个方案、方案计数或压缩表示，但它们是不同输出契约。报告复杂度时应包含输出规模，不能把求值算法的界直接用于完整枚举。即使路径图紧凑，展开所有路径仍可能很大。

<a id="algo-3-detail-62"></a>

### 12.10 练习十：编辑距离的单位

**题目。** 同一可见字符可以由一个预组合码点或多个组合码点表示。直接按 Python 字符串求编辑距离，是否一定得到零？怎样定义更合适任务？

**解析。** 不一定，因为算法比较的是码点序列。可以先按明确规范化规则处理，或把字素簇作为 token，但这改变了评价空间，应说明。算法对输入序列正确，不代表其单位自动符合用户感知；文本评价还需要定义分词、规范化与跨样本汇总。

<a id="algo-3-detail-63"></a>

### 12.11 练习十一：区间端点与前驱

**题目。** 两任务为零到二、二到四，在左闭右开规则下是否兼容？若都视为闭区间，前驱二分条件有何变化？

**解析。** 左闭右开时第一个不占用时刻二，二者兼容，结束不超过开始即可。闭区间若端点资源冲突，则必须严格早于开始，二分边界从包含等号改为不包含。数据结构接口的左右边界选择，应由资源语义推导，而不是按记忆选择函数。

<a id="algo-3-detail-64"></a>

### 12.12 练习十二：子集状态为何需要末点

**题目。** 两条旅行路径访问相同城市集合，却停在不同城市，能否只按已访问集合合并最小成本？

**解析。** 一般不能，未来到未访问城市及最后回起点的成本依赖当前末点。一个当前成本较高的历史可能因所在位置更有利而最终更优。状态需包含集合与末点，或使用其他能证明充分的表示。仅比较累计成本的支配剪枝在这里缺少共同未来条件。

<a id="algo-3-detail-65"></a>

### 12.13 练习十三：固定点残差的误差界

**题目。** 折扣为零点九，Bellman 残差为零点零二，在本章有限有界假设下可推出什么最大范数误差界？折扣变为零点九九如何？

**解析。** 分别为 $`\frac{0.02}{(1-0.9)}=0.2`$ 与二。折扣接近一时残差要求更严格。这个界依赖正确 Bellman 算子与收缩假设；如果残差只是一个采样小批次上的估计，不能直接当作全状态最大残差，也不能据此宣称同样确定性误差界。

<a id="algo-3-detail-66"></a>

### 12.14 练习十四：有界缓存的复杂度

**题目。** 记忆化递归使用只能容纳十个状态的缓存，却有一万个不同状态。能否仍断言每个状态只计算一次？

**解析。** 不能，状态被驱逐后再次访问会重算，实际代价取决于依赖访问模式。有界缓存可能节省内存，但原无界记忆化的状态次数证明不再直接成立。应分析命中与驱逐，或改用明确的自底向上顺序，只保留真正不再需要的依赖层。

<a id="algo-3-detail-67"></a>

### 12.15 练习十五：价值缩放的保证来自哪里

**题目。** 近似背包中每件向下舍入损失小于 $`\Delta`$，为什么选择 $`\Delta=\frac{\varepsilon V_{\max}}{n}`$ 能得到相对误差界，而任意固定步长不一定可以？

**解析。** 任意方案至多含 $`n`$ 件，累计损失小于 $`n\Delta=\varepsilon V_{\max}`$。删除不可单独放入物品后，$`V_{\max}\leq\operatorname{OPT}`$，所以损失不超过最优值的 $`\varepsilon`$ 比例。任意固定步长没有与最优值尺度建立关系，只能给绝对损失估计，不能自动声称相对保证。

<a id="algo-3-detail-68"></a>

### 12.16 练习十六：概率递推不能替换成最大路径

**题目。** 两条合法路径概率均为零点三，另一个候选只有一条路径概率零点五。按总概率与最大路径选择会怎样？

**解析。** 总概率把前一候选两条互斥路径相加为零点六，因此偏好前者；最大路径只看零点三与零点五，会偏好后者。二者回答不同问题，一个边缘化隐藏路径，一个做最优路径解码。不能把最大值近似当成精确总概率而不说明目标已经改变。
