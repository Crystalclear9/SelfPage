## 1. 先决定什么可以作为状态

<a id="search-identity"></a>

### 1.1 位置相同，后续动作可以不同

把地图上的每个地点当作一个结点，是最短路建模里自然的第一步。地图给出的通道长度不变，每次从同一个地点出发都可以尝试相同的边，边的可行性也不依赖来路。一旦加上门禁、剩余电量或者只能用一次的优惠，地图上的一个圆点就代表了许多不同的未来。两名维修员到达同一扇门，一个已领取许可，一个还没有，接下来可选的动作并不一样。

![同一地点的两个许可状态允许不同后续动作](images/05-location-and-permission-state.webp)

[打开原图放大](images/05-location-and-permission-state.webp)

图中把位置写作 P，把许可位分别写作 0 和 1。从 $`(P,0)`$ 到 $`(P,1)`$ 可以是一次领取动作，即便位置没有移动。只有 $`(P,1)`$ 可以尝试过门。如果只以 P 为字典键，算法可能先以低成本到达未持证状态，再把成本稍高的持证状态当作重复记录丢弃。错误发生在比较两条前缀是否到达同一个对象时。更精确的堆和更强的启发函数都无法找回已经被错误合并的未来。

这与动态规划的状态充分性是同一个条件。比较到达同一状态的两个前缀时，若后续可行动作、即时成本、后继状态和目标判定都只取决于当前记录，就可以保留成本更低的前缀。电量采用离散档位时，还要说明该档位能否准确判定动作。如果同档内有一个真实电量足够过门、另一个不够，这就是近似模型，搜索保证只适用于离散化后的问题。

检验状态可以把两条声称相同的记录放到同一个后缀前。若一个后缀从一条记录可以执行，从另一条记录却失败，就找到了缺失变量。通道跨午夜开放时要记录时间或时段。优惠可使用一次时要记录剩余次数。路线字符串本身可以另存前驱；若把展示信息也放进状态，会人为拆开本来可以合并的记录。充分状态允许适当冗余，最小化状态的目标是控制计算成本。

<a id="search-certificate"></a>

### 1.2 给可行性和最优性不同的证据

确定性搜索问题包含初始状态、可行动作、后继函数、动作成本和目标测试。状态集合既可以显式枚举，也可以由后继函数按需生成。对给定动作，后继必须唯一。最短路可以看成动作标签与边标签一致的特例。规划通常从动作规则生成边，无须事先画出所有组合状态。

程序首先要提供可重放的路径或动作序列。读者可以从起点独立检查每步是否合法，再复算总代价。接下来才核对最优证据，例如与哪个小实例的枚举结果比较，或者采用哪条停止条件。路径全部合法，只证明找到可行解。搜索达到时间限制时，还应分开记录队列耗尽与预算耗尽。前者可用于证明有限模型不可达，后者表示此次求解未完成。

本章分别用简单路径枚举、笛卡尔积和动作解释器核对三个实验。参照采用比主算法更直接的实现。把同一个更新器复制一份作为参照，两份程序可能共享同一种状态遗漏，即便结果一致也难以发现。

## 2. 从一致代价搜索走到 A*

<a id="search-priority"></a>

### 2.1 三种优先队列回答不同问题

令 $`g(s)`$ 为目前找到的从起点到状态 $`s`$ 的前缀代价，$`h(s)`$ 为从该状态到某个目标的剩余代价估计。一致代价搜索按 $`g`$ 从小到大展开，显式非负图上的做法与 Dijkstra 一致。贪心最佳优先搜索只按 $`h`$ 排序，优先看起来最接近终点的结点。A* 则比较

```math
f(s)=g(s)+h(s).
```

把 $`h`$ 全设为零，A* 退化为一致代价搜索。只按 $`h`$ 时，已经付出的代价不参与选择。一个昂贵的动作可以直接把维修员送到门前，剩余距离确实短，却可能比绕行路线昂贵得多。三种排序使用相同地图，分别比较已经走过的部分、剩余部分的估计，以及当前前缀接上未来的估计总成本。

队列项保存的是某次发现的前缀，它有当时的 $`g`$ 快照。最佳代价表保存的是同一状态当前最便宜的记录。第一次写入代价三，随后发现代价二，可以追加一项而不修改旧项。弹出时若快照与最佳值不同，旧项已经失效。这个检查与“已经展开的结点后来是否需要再展开”各有职责。实现平局规则时可放一个递增计数器，避免尝试比较状态对象。比较算法展开数时要固定平局规则，因为同一个最优成本可能对应大量相同的 $`f`$ 值。

<a id="search-reopen"></a>

### 2.2 逐步复算一次需要重开的搜索

在四结点有向图中，S→A 成本 3，S→B 成本 1，B→A 成本 1，A→G 成本 2。目标为 G。设 $`h(S)=0`$、$`h(A)=0`$、$`h(B)=3`$、$`h(G)=0`$。B 的真实剩余成本正好为 3，其他估计也未超过真实成本。可是 B→A 的成本只有 1，B 的估计大于边成本加 A 的估计，这条边违反一致性。

![不一致启发式下更便宜路径使已展开状态重开](images/05-astar-state-reopen.webp)

[打开原图放大](images/05-astar-state-reopen.webp)

| 步骤 | 弹出状态 | 前缀代价 | 新记录 |
| --- | --- | ---: | --- |
| 1 | S | 0 | A 的优先值为 3，B 为 4 |
| 2 | A | 3 | G 的候选成本为 5 |
| 3 | B | 1 | A 获得成本为 2 的前缀 |
| 4 | A | 2 | G 的候选成本改进为 4 |
| 5 | G | 4 | 返回 S→B→A→G |

永久关闭 A 会失去第 4 步，可能返回成本五的合法路线，真正最优值却是四。首次生成 G 同样不足以终止。第 2 步已经给出可行解，但 B 还在队列中，它代表一条可以改善解的前缀。实验应将永久关闭和过早终止作为两种单独改动，便于定位究竟是前沿信息丢失，还是停止时机过早。

## 3. 启发函数的条件、证明与设计

<a id="search-guarantees"></a>

### 3.1 可采纳与一致性分别保证什么

记真实最小剩余成本为 $`h^*(s)`$。本章使用有限状态、非负边成本和目标处启发值为零的设定。若 $`0\le h(s)\le h^*(s)`$，称估计可采纳。若对每条合法边还满足

```math
h(s)\le c(s,s')+h(s'),
```

则称它一致。沿任意通往目标的路径相加，中间启发值抵消，留下起点估计不超过整条路径成本。目标处为零时，这就证明一致性推出可采纳性。前面的例子说明反向不成立。

还可以给边重新计价。

```math
c'(s,s')=c(s,s')+h(s')-h(s).
```

一致性保证新边成本非负。将新成本沿路径相加，得到旧前缀成本加当前启发值，再减一个共同的起点常数。A* 的排序与在新成本上做一致代价搜索相同。由 Dijkstra 的首次结算性质可知，一致时首次展开状态就已获得它的最优前缀。零代价边会产生平局，严格改进的更新规则仍可避免相同代价的记录因零代价环不断入队。

只有可采纳性时，新成本可能为负，首次结算的论证失效。只要允许更便宜的前缀重开状态，第一次弹出的有效目标仍最优。证明时沿一条最优路线从起点向前看。只要最优路线尚未走完，存在第一个尚未用正确前缀展开的状态。它的前驱已经以不更贵的前缀展开，因此队列里保留一个前缀不超过正确成本的候选。可采纳性使该候选的 $`f`$ 不超过最优总成本。更贵目标的启发值为零，无法先于它成为有效的最小优先项。若某个目标恰好以最优代价先出队，已经达到要求。

这个论证同时解释三个实现细节。目标判定在丢弃旧项之后。优先值使用该项的前缀快照。已展开状态发现严格改进时允许再次展开。删掉第三步，证明依赖的最优路线前沿就可能消失。对于无限状态，还要另加保证有限代价层可探索完的条件。有限分支且每步代价有正下界是一种常用充分条件。本章实验不依赖对无限图的保证。[Berkeley CS188 启发式搜索](https://inst.eecs.berkeley.edu/~cs188/textbook/search/informed.html)

<a id="search-relax"></a>

### 3.2 从松弛问题得到下界

常见构造方式是放宽原问题的部分约束，同时维持计价尺度。原图要求绕过障碍，松弛图取消障碍但保留相同起点和目标。每条原路线在松弛图中仍可执行且成本不增加，因此松弛最优值不超过原问题。四连通格点、每步成本至少为一时，曼哈顿距离是这样的下界。如果增加低成本的对角动作，要重新分析单步坐标差的最大变化，不能直接沿用旧下界。

选择松弛时，逐步把原路线投影到新问题中。先问对应动作是否仍存在，再问对应成本是否不增加。删掉便宜边，或者把原动作拆成多段并多收费用，都可能让下界失效。某个问题更简单，只意味着它可能更易求解，不能由此推断其最优值更小。

对于目标固定的静态有向图，也可从目标反向做一次最短路。每条边反转方向并保留成本，由此计算状态到目标的真实距离。多个目标可用零成本边连接到反向搜索的共同起点。反向距离适合多次查询共享目标的场合，但一次搜索的成本变成了预计算、存储和更新成本。路网版本或目标变化后，旧距离可能不再是当前问题的下界。缓存应记录目标集合及可影响成本的地图配置。

<a id="search-stop"></a>

### 3.3 用反例检验停止准则

只有一条候选路径时，先发现目标常常恰好正确，对终止缺陷没有判别力。更有效的测试是 S→G 成本九、S→A 成本一、A→G 成本一。即使 $`h=0`$，生成 G 就返回仍会错。另一个测试将 A* 改成贪心，A 的估计为一、G 为零，也会得到错误值，但原因变成排序只看未来估计。让两个测试分别失败有助于定位缺陷。

必须在预算内停下时，可以记录当前最好的可行解成本 $`U`$，以及尚未处理前沿的最小下界 $`L`$。若完整解已经从队列中弹出、还在继续找更好的方案，需要把已知可行成本一起纳入下界，可报告 $`\min(L,U)`$。没有可行解时，上界仍不可用。若堆首是旧项，先清除旧项再报告界。精确终止与预算停止的差别会直接影响读者怎样解读结果。

## 4. 实验一：实现并独立核对 A*

<a id="search-code-astar"></a>

### 4.1 完整实现与受控反例

程序只用 Python 标准库。相同图、初始状态、目标、估计和入队次序用于两次运行，唯一干预是是否允许重开。堆内的第二项是递增序号，避免状态在平局时参与比较。无路可达时返回无穷和空路径，预算中止在实际接口中应使用不同状态。本实验没有人为预算。

```python
from heapq import heappop, heappush
from itertools import count
from math import inf


def astar(graph, start, goal, h, reopen=True):
    serial = count()
    queue = [(h[start], next(serial), start, 0)]
    best = {start: 0}
    parent = {}
    expanded = []
    closed = set()

    while queue:
        _, _, state, cost = heappop(queue)
        if cost != best[state] or (not reopen and state in closed):
            continue
        expanded.append(state)
        if state == goal:
            path = [state]
            while path[-1] != start:
                path.append(parent[path[-1]])
            return cost, path[::-1], expanded
        closed.add(state)
        for neighbor, edge in graph[state]:
            assert edge >= 0
            if not reopen and neighbor in closed:
                continue
            candidate = cost + edge
            if candidate < best.get(neighbor, inf):
                best[neighbor] = candidate
                parent[neighbor] = state
                heappush(
                    queue,
                    (candidate + h[neighbor], next(serial), neighbor, candidate),
                )
    return inf, [], expanded


def simple_path_costs(graph, source, goal, seen=frozenset()):
    if source == goal:
        yield 0
        return
    seen = seen | {source}
    for target, edge in graph[source]:
        if target not in seen:
            for rest in simple_path_costs(graph, target, goal, seen):
                yield edge + rest


graph = {
    "S": [("A", 3), ("B", 1)],
    "A": [("G", 2)],
    "B": [("A", 1)],
    "G": [],
}
h = {"S": 0, "A": 0, "B": 3, "G": 0}
cost, path, expanded = astar(graph, "S", "G", h)
assert (cost, path, expanded) == (
    4, ["S", "B", "A", "G"], ["S", "A", "B", "A", "G"]
)
assert astar(graph, "S", "G", h, reopen=False)[0] == 5
assert sum(dict(graph[s])[t] for s, t in zip(path, path[1:])) == cost

# Enumerate all 64 edge subsets of a four-node acyclic graph.
edges = [(i, j) for i in range(4) for j in range(i + 1, 4)]
for mask in range(1 << len(edges)):
    small = {i: [] for i in range(4)}
    for k, (i, j) in enumerate(edges):
        if (mask >> k) & 1:
            small[i].append((j, k % 3))
    oracle = {
        i: min(simple_path_costs(small, i, 3), default=inf)
        for i in small
    }
    estimate = {
        i: 0 if i % 2 == 0 or oracle[i] == inf else oracle[i]
        for i in small
    }
    got, recovered, _ = astar(small, 0, 3, estimate)
    assert got == oracle[0]
    if recovered:
        assert recovered[0] == 0 and recovered[-1] == 3
        assert sum(dict(small[s])[t] for s, t in zip(recovered, recovered[1:])) == got
    else:
        assert got == inf

print("best cost:", cost, "path:", path, "expanded:", expanded)
print("checked 64 small graphs against simple-path enumeration")
```

若程序返回五，先打印展开序列。出现 S、A、B、G 而没有第二次 A，说明程序未重开。若只出现 S、A 后立即返回，错误在目标生成时就终止。若序列正确却返回一条成本不符的路线，则查前驱是否只在严格改进时更新。把这三种故障映射到三项可观察量，比在一个大图上只断言最终成本更能定位问题。

<a id="search-oracle"></a>

### 4.2 用独立枚举核对整个图族

枚举器保存当前路线的已见集合，递归列出所有简单路径的成本。因为成本非负，任意可行路线中的环都可删除而不增加成本，所以至少存在一条简单最优路线。枚举无需启发函数和堆，可以独立发现搜索实现中的错误。它在一般图上代价很高，本章只在小规模下将它用作参照。

六十四种图来自六条候选边的所有存在组合。这里主动加入零代价边、断开起点和不同的路径组合。手造的可采纳但不一致图覆盖重开。继续扩展时，可选有环结构、多个目标或不可比较的状态类型。验证多目标时，先将接口改成目标谓词，再用对每个目标分别求最优后取最小值作参照。验证状态类型时，用只支持哈希与相等的对象替换字符串，保留计数器处理平局。

本实验用字典恢复路径，每对结点间只有一条边。平行边场景仅保存前驱结点不足以辨认选中了哪条边，前驱表还要保存动作标识与边成本。重放时按标识查找。这里队列快照的严格等号依赖整数构造。浮点场景应说明数值表示与验收容差。若任意丢弃小于某个容差的真实改进，就需要重新分析损失多少最优性。

## 5. 把排班写成约束满足

<a id="search-csp-model"></a>

### 5.1 变量、域和约束的职责

假设出发、检查、交付需要分别安排时间。输入可以写成变量、每个变量的候选域以及联合约束。完整解给每个变量选定一个域内值且满足全部约束。域记录单个变量可以取什么，约束记录一组联合取值为何不可行。两个任务不能同时用一台仪器，或者一个步骤必须先于另一个步骤，都是联合约束。若还要在可行解中选成本最低者，应另加目标。第一组可行指派不提供最优排班证据。

与路径搜索相比，局部记录可以是尚未填完的指派。先填 X 再填 Y、先填 Y 再填 X，若最终值相同，代表同一个解。只要规则不依赖录入次序，每一步就只需选一个变量，再枚举其取值。避免了把同一个答案因填表顺序反复计数。先试哪个变量通常改变在第几层暴露矛盾，完整解集由约束决定。

将约束写成可独立检查的谓词。例如任务有持续时间时，不重叠要比较区间而非只比较起始点。如果每次选择的是整个时段，变量的值可以同时包含起止时间和资源。把不相容关系简化成“不同颜色”适合下面的局部传播示例。真实排班还涉及容量、资源组、维护窗口和人员可用性，需要按实际规则重新建模。

<a id="search-arc"></a>

### 5.2 弧一致性怎样传播

在二元约束下，X→Y 的弧一致指 X 域里的每个值，都能在 Y 域找到至少一个与它相容的值。方向很重要。X 的所有值有支持，Y 的所有值未必都有支持。若约束是 X 早于 Y，反向检查仍使用同一关系，只是交换自变量的来源。将反向也写成“Y 早于 X”会凭空添加相反的规则。

令 X 的域为 $`\{1\}`$，Y 与 Z 的域均为 $`\{1,2\}`$，约束是 X 与 Y 不同、Y 与 Z 不同。检查 Y→X，Y 的 1 找不到支持，只剩 2。检查 Z→Y，Z 的 2 找不到支持，只剩 1。X 和 Z 没有直接边，变化仍能经 Y 传播。

![相邻约束传播从两个候选域依次删除无支持值](images/05-arc-consistency-propagation.webp)

[打开原图放大](images/05-arc-consistency-propagation.webp)

若待删值出现在一个全局解中，邻接变量在该解中必有相容取值。此前的删值若保留所有全局解，邻接取值就仍在当前域内，这与没有支持矛盾。因此逐步删除不丢解。空域确证当前分支无解。有限域只减不增，传播最终到达不动点或遇到空域。

AC-3 用队列保存待查有向弧。若一次修订缩小 X 的域，其他邻居可能失去过去依赖的支持，就把指向 X 的相关弧重新加入。刚被删的 X 值没有任何 Y 支持，因此这一步不会让 Y 失去与 X 的有效支持，可以跳过刚修订弧的反向。这个优化要求两个方向表示同一个二元相容关系。如果同一对变量有多条独立约束，本实验的弧表示它们组合后的关系。[Berkeley CS188 约束过滤](https://inst.eecs.berkeley.edu/~cs188/textbook/csp/filtering.html)

<a id="search-csp-limits"></a>

### 5.3 局部一致与全局有解

把三个变量改成三角形，每对都不同，域都为 $`\{1,2\}`$。检查任意有向弧，1 可找 2 作为支持，2 可找 1，传播不会删值。但三个变量必须两两不同，两种取值不够，问题无解。各自找到的支持无法组合成一份同时成立的指派。

全异约束也有类似情形。若四个任务都从三台仪器中选一台，每个二元不等约束都可能有支持。把四个任务整体看作“必须各用一台不同仪器”，候选仪器联合只有三台，匹配检查能更早发现矛盾。二元分解的解集可以与全异约束相同，传播力度仍可能不同。

树形二元约束图提供一个对照。每个域非空且双向弧一致时，可以先给根选任意一个域内值，再逐层给孩子选支持值。树上子树之间没有额外连边，已选分支不会在别处冲突。三角形破坏了这个条件。一般图上应使用回溯、更强传播或全局推理补足缺失的证据。

## 6. 实验二：传播、回溯与全局核验

<a id="search-ac3-code"></a>

### 6.1 实现 AC-3 与最少剩余值

本实验用不等约束演示二元传播。递归时从非单元素域里选候选最少的变量，试一个值后复制域，再传播，避免兄弟分支共享可变集合。原始输入保持不变，便于用笛卡尔积独立复算。

```python
from collections import deque
from itertools import product


def directed_rules(edges):
    rules = {}
    for left, right in edges:
        rules[left, right] = lambda a, b: a != b
        rules[right, left] = lambda b, a: a != b
    return rules


def ac3(domains, rules):
    if any(not values for values in domains.values()):
        return False
    incoming = {v: set() for v in domains}
    for x, y in rules:
        incoming[y].add(x)
    pending = deque(rules)
    while pending:
        x, y = pending.popleft()
        relation = rules[x, y]
        revised = {
            a for a in domains[x]
            if any(relation(a, b) for b in domains[y])
        }
        if revised == domains[x]:
            continue
        domains[x] = revised
        if not revised:
            return False
        pending.extend((z, x) for z in sorted(incoming[x] - {y}))
    return True


def solve(domains, rules):
    keys = tuple(sorted(domains))
    current = {key: set(values) for key, values in domains.items()}
    if not ac3(current, rules):
        return
    undecided = [key for key in keys if len(current[key]) > 1]
    if not undecided:
        yield tuple(next(iter(current[key])) for key in keys)
        return
    variable = min(undecided, key=lambda key: (len(current[key]), key))
    for value in sorted(current[variable]):
        child = {key: set(values) for key, values in current.items()}
        child[variable] = {value}
        yield from solve(child, rules)


def brute(domains, edges):
    keys = tuple(sorted(domains))
    for values in product(*(sorted(domains[key]) for key in keys)):
        assignment = dict(zip(keys, values))
        if all(assignment[x] != assignment[y] for x, y in edges):
            yield values


chain = [("X", "Y"), ("Y", "Z")]
fixed = {"X": {1}, "Y": {1, 2}, "Z": {1, 2}}
reduced = {key: set(values) for key, values in fixed.items()}
assert ac3(reduced, directed_rules(chain))
assert reduced == {"X": {1}, "Y": {2}, "Z": {1}}
assert list(solve(fixed, directed_rules(chain))) == [(1, 2, 1)]
assert fixed["Y"] == {1, 2}

triangle = [*chain, ("Z", "X")]
for colors in (2, 3):
    domains = {key: set(range(1, colors + 1)) for key in ("X", "Y", "Z")}
    snapshot = {key: set(values) for key, values in domains.items()}
    rules = directed_rules(triangle)
    assert ac3(snapshot, rules) and snapshot == domains
    computed = list(solve(domains, rules))
    assert len(computed) == len(set(computed))
    assert set(computed) == set(brute(domains, triangle))
    assert len(computed) == (0 if colors == 2 else 6)
    print("triangle colors:", colors, "solutions:", len(computed))
```

固定链的唯一解是 $`(1,2,1)`$。双色三角形第一次传播后域不变，完整求解却得到零个解。三色三角形有六个解，对应三种颜色的排列。程序比较整个解集，并检查重复计数。只核对某一次返回值是合法解，会漏掉漏解和重复枚举。

<a id="search-csp-cost"></a>

### 6.2 在相同输出任务上比较代价

当所有域都退化为单值且完成双向传播时，每对相邻变量的唯一值必须相容，因此本实验可以直接返回元组。如果实现只检查部分弧，最后还需要逐约束验证。复制域的做法易审查，但会增加内存和复制成本。更高效的实现可以记录删值日志，在回溯时按日志恢复。测试恢复应比较整个域快照，而不只是检查该变量是否标成未分配。

域最多 $`d`$ 个值时，一次扫描可能做平方数量的相容判断。重新检查某条弧来自某个域的缩小，域最多缩小 $`d`$ 次。在单次相容判断视为常数的设定下，这给出朴素 AC-3 的 $`O(ed^3)`$ 上界，其中 $`e`$ 是有向弧数。缓存上一次支持值可以少试探，但要在支持值被删除后重新核对。外层还有分支搜索，单次传播的多项式界不能代替求解器的最坏复杂度。

度量可分别记录分支次数、域删除数、相容判断数、复制域占用和总耗时。传播更强可能减少分支，也可能增加单结点开销。比较时先统一输出任务是求第一个解、全部解还是无解证明。最少剩余值通常用来更快暴露矛盾。域大小相同时可比较它还约束多少未定变量，或用固定标识保证重放。最不限制取值则优先尝试对邻居域影响较小的值。它们改变遍历顺序，保证仍来自检查全部合法分支。[Berkeley CS188 变量与取值排序](https://inst.eecs.berkeley.edu/~cs188/textbook/csp/ordering.html)

## 7. 把动作规则变成确定性规划

<a id="search-strips"></a>

### 7.1 前置条件、增加效果与删除效果

到这一节重新考虑维修员的任务。已知许可、位置和电量，但没有显式画出所有可能的状态。用命题描述事实，例如“在中转站”“已领取许可”“电量充足”。一个状态记录当前成立的事实。采用本节的封闭世界表示时，未出现在集合里的事实视为假，含义与现实中尚未观测到它不同。初始事实与动作后果完全给定，属于可观测的确定性规划。

动作包含三个集合。前置条件是执行前必须成立的事实。增加效果是执行后变为真的事实。删除效果是执行后变为假的事实。对已实例化的动作 $`a`$，执行要求 $`\mathrm{Pre}(a)\subseteq s`$，下一状态按先删后加计算。本文在每个动作里让增加集合与删除集合互斥，便于解释规则。

```math
s'=(s\setminus\mathrm{Del}(a))\cup\mathrm{Add}(a).
```

过门需要人在门口、已经持证并且电量充足，过门后人在目的地、门口位置被移除并消耗电量。没有列入增加或删除集合的事实保留。每个动作通常只修改少数状态变量，这使规则比逐个列出所有组合边更紧凑。执行时仍需明确互斥条件，例如一个维修员在同一时刻只占据一个地点。若忘记删除旧地点，模型会允许人在两个地方，这不是搜索器能靠降低代价修复的问题。

![过门前置条件、位置转换和保留许可](images/05-planning-action-effects.webp)

[打开原图放大](images/05-planning-action-effects.webp)

目标也是一组要求成立的事实。交付成功不需要指定“交付时许可证还剩几次”，除非任务明确要求。目标集合被当前状态包含即可达到目标。这让同一个目标对应许多完全状态。举例来说，已经持证的维修员可以先充电再出发，也可以先出发后绕行，最后都交付成功。搜索比较的是可以满足目标的所有路径代价。只检查最后一个动作是否叫“交付”会把不合法前缀一起放过。

动作模板可以先带变量，例如从地点 u 移动到 v，再把模板与已知对象实例化。实验直接给定几个无变量动作，以便每个条件都能核对。实例化时还要筛选不可能的对象组合，例如只有连通的地点才生成移动动作。若有 10 个地点，未经筛选的成对模板会生成最多 100 个候选，真实道路边可能远少于这个数。规则描述的体积、候选动作数和真正到达的状态数是三种成本。

<a id="search-delete"></a>

### 7.2 删除松弛与资源复用反例

忽略删除效果，且前置条件和目标均只要求正命题时，原计划仍可以在松弛模型中执行。用归纳验证即可。初始两者事实相同，每一步后松弛状态包含原状态，所以原计划下一步所需的事实仍成立。若每个动作成本保持不变，精确松弛最优值不超过真实最优值。这里的结论涉及精确求得的松弛最优值。任取一条松弛可行计划，可能比松弛最优方案贵，也可能比真实最优值贵，因此不能直接拿来当下界。

只考虑电量的最小反例很适合手算。初始有电，必须安装 A 与 B 两件设备。每次安装成本一且消耗电量。充电成本二。在真实模型里，两次安装之间要充电一次，最优成本四。若删除效果被忽略，第一次安装不会删掉“有电”，第二次可以复用这个事实，松弛最优成本二。松弛的数值能提示剩余工作量，却不能把其动作序列当作真实计划。第 8 节将用相同的求解器分别计算这两个值，再用原规则重放。

这也说明正前置条件的限制。若某个动作要求“设备已经没电”，忽略删除反而可能让这个负条件永远无法满足，原计划不一定能原样迁移到松弛问题。类似地，若目标要求“确认系统中不存在某条记录”，只允许增加事实也会改变可达性。应用之前要写清动作语言和比较条件。[AIMA 第四版自动规划目录](https://aima.cs.berkeley.edu/)

<a id="search-policy"></a>

### 7.3 从计划过渡到策略

在已知确定性模型中，计划给出一个动作序列，执行结果可以逐步预测。若每次过门有概率成功、也有概率退回门口，预先写死下一步动作可能不可执行。这时合适的输出是策略，它根据观察到的状态选择动作。评价也从单一路线成本变成期望成本、最坏情况或指定风险口径。若电量不可观测，还需要明确状态估计如何形成，不能拿真实隐藏状态直接做在线决定。

课程位置也因此清晰。学习第 2 章后可以读本章的搜索，学习第 3 章后可对照有限时域递推。若问题已经给定随机转移模型，进入[有限状态动态规划](../../ReinforcementLearning/MDP/03-有限状态动态规划完整算例.md)。若模型未知并且通过交互获得样本，再进入价值学习。三条路径的共同点是首先确定“什么决定未来”，区别在于能否直接调用后继规则以及最后交付路线还是策略。

还要区分用户的自然语言要求与系统执行权。用户可以说“把设备送到目标”，模型可以提议动作序列，但真实工具仍应按当前状态和权限验证每一步。规划结果中的“许可成立”只是模型事实，不能替代执行时的授权检查。现实系统遇到门禁撤销、传感器读数滞后或中途失败，应返回观察和失败原因，再重新求解。对接语言模型工具时可读[工具状态机](../../AI-Domains/LargeLanguageModels/03-RAG工具使用与系统评估.md#llm-3-detail-23)。

## 8. 实验三：生成计划，再独立重放

<a id="search-plan-lab"></a>

### 8.1 地点、许可与电量的完整实验

下面用事实集合与动作表构造后继。每项动作含名称、前置、增加、删除和成本。三个地点事实中恰有一个为真。起点在中心站，先办许可、充电并走到门口，过门成本二，最后交付成本一。还有一条无需许可的远路，从中心站出发成本七。以零启发搜索，能核对哪个分支更便宜。

```python
from dataclasses import dataclass
from heapq import heappop, heappush
from itertools import count
from math import inf


@dataclass(frozen=True)
class Action:
    name: str
    pre: frozenset
    add: frozenset
    delete: frozenset
    cost: int


def action(name, pre, add, delete, cost):
    return Action(name, frozenset(pre), frozenset(add), frozenset(delete), cost)


def plan(start, goal, actions, relaxed=False):
    serial = count()
    best = {start: 0}
    queue = [(0, next(serial), start, ())]
    while queue:
        cost, _, state, route = heappop(queue)
        if best[state] != cost:
            continue
        if goal <= state:
            return cost, route
        for step in actions:
            assert step.cost >= 0 and not (step.add & step.delete)
            if not step.pre <= state:
                continue
            next_state = state | step.add if relaxed else (state - step.delete) | step.add
            candidate = cost + step.cost
            if candidate < best.get(next_state, inf):
                best[next_state] = candidate
                heappush(
                    queue,
                    (candidate, next(serial), next_state, (*route, step.name)),
                )
    return inf, ()


delivery = (
    action("permit", {"hub"}, {"permit"}, set(), 1),
    action("charge", {"hub"}, {"charged"}, set(), 1),
    action("approach", {"hub"}, {"gate"}, {"hub"}, 1),
    action("return", {"gate"}, {"hub"}, {"gate"}, 1),
    action("pass", {"gate", "permit", "charged"}, {"site"}, {"gate", "charged"}, 2),
    action("detour", {"hub"}, {"site"}, {"hub"}, 7),
    action("deliver", {"site"}, {"delivered"}, set(), 1),
)


def replay_delivery(route):
    position, permit, charged, delivered, total = "hub", False, False, False, 0
    for step in route:
        if step == "permit":
            assert position == "hub"
            permit, total = True, total + 1
        elif step == "charge":
            assert position == "hub"
            charged, total = True, total + 1
        elif step == "approach":
            assert position == "hub"
            position, total = "gate", total + 1
        elif step == "return":
            assert position == "gate"
            position, total = "hub", total + 1
        elif step == "pass":
            assert position == "gate" and permit and charged
            position, charged, total = "site", False, total + 2
        elif step == "detour":
            assert position == "hub"
            position, total = "site", total + 7
        elif step == "deliver":
            assert position == "site"
            delivered, total = True, total + 1
        else:
            raise AssertionError(step)
    assert delivered
    return total


start, goal = frozenset({"hub"}), frozenset({"delivered"})
cost, route = plan(start, goal, delivery)
assert cost == replay_delivery(route) == 6
assert route[-2:] == ("pass", "deliver")
assert replay_delivery(("detour", "deliver")) == 8

two_jobs = (
    action("charge", set(), {"charged"}, set(), 2),
    action("install_a", {"charged"}, {"a_done"}, {"charged"}, 1),
    action("install_b", {"charged"}, {"b_done"}, {"charged"}, 1),
)
initial = frozenset({"charged"})
both = frozenset({"a_done", "b_done"})
real_cost, real_plan = plan(initial, both, two_jobs)
relaxed_cost, relaxed_plan = plan(initial, both, two_jobs, relaxed=True)
assert real_cost == 4 and relaxed_cost == 2
assert len(real_plan) == 3 and "charge" in real_plan
assert len(relaxed_plan) == 2 and "charge" not in relaxed_plan
print("delivery:", route, "cost:", cost)
print("two jobs:", real_cost, "relaxed lower bound:", relaxed_cost)
```

典型路线依次办许可、充电、走到门口、过门、交付，成本是一加一加一加二加一，等于六。许可与充电都必须在站内完成，两者可以交换顺序，因此返回次序由平局处理决定。远路成本八。验收以可重放性和总代价为准，不要求所有正确实现给出同一个同成本路线。

<a id="search-plan-audit"></a>

### 8.2 计划证书和环境变化

重放器用位置枚举及布尔量，和搜索器的事实集合采用不同表示。比如重放“过门”时，先验证地点、许可、电量，再显式将电量设置为不足。这一步独立于通用删加函数。如果动作表忘记删除原地点，但示例路线碰巧合法，重放只能证实该路线，没有验证全部规则。可进一步在小规模上穷举前缀，比较每个可达状态的动作集合和下一状态。完整一致需要验证的是转换关系，而不是一个最终数值。

证书至少保存初始事实、动作版本、返回序列、总代价和目标核验结果。时间预算要另记，不能写进状态的展示信息中。对真实执行，应在每次动作前按当前观察重新核对可行性。例如原计划到门口时许可证仍有效，但执行期间被撤销，先前证书依旧解释了旧版本的决策，却不授权新动作。应读取新事实、从当前状态重新规划，避免再执行已经完成且有副作用的前缀。

规划也可以在给定步长上编码成约束问题。为每个时点引入事实变量，为每步引入动作变量，加入前置、效果及未修改事实的保持约束，再要求最后时点满足目标。这个编码能利用跨时点传播，但要指定时域长度。固定长度无解只说明该长度内不满足给定编码，无法证明所有长度都无解。还要说明是否允许等待，否则“恰好 T 步”和“至多 T 步”是两个不同问题。这样的联系让读者能用同一任务比较前向搜索和全局约束求解。

## 9. 进阶：组合下界、带权搜索与资源边界

<a id="search-combine"></a>

### 9.1 多个下界何时能相加

令 $`h_1`$ 表示忽略电量后的交通成本下界，$`h_2`$ 表示忽略门禁后的交通成本下界。只要二者都不超过真实剩余成本，它们的最大值也不超过真实成本。直接相加则可能重复计价。例如剩余路径恰好包含一条成本五的移动边，两个松弛都把这条移动边算作必要成本。两者分别报告五，相加得到十，高于真实最优的五。产生错误的是对同一动作收费两次。

若能把每条真实边成本分给两个投影问题，且两份非负成本之和不超过原成本，就可以构造可加下界。任取一条真实后缀，两种投影各自最优值不超过该后缀在对应预算下的投影成本。将两条不等式相加，再应用逐动作预算限制，得到合计不超过这条真实后缀的成本。对所有真实后缀取最小值，合计仍是下界。这种方法通常称为成本划分。它要求明确投影如何映射动作，也要求每一份下界在自己的计价模型里成立。

例如动作只有两类，领取和充电不改变位置，移动不改动许可位。将移动费用全部分给位置投影，将办理费用全部分给许可投影。若领取许可有确定成本且所有原计划都必须领取，许可投影能给出相应下界。如果另有一条不需许可的合法远路，许可投影就不能假定所有最优路线都要付许可费。要么保留该替代动作，使许可下界在允许绕路时可以为零，要么将问题明确限制在必须经过门禁的路线集合中。能否相加取决于任务定义与投影保持性，并非仅看两个估计的名称是否不同。

一致性也可以按相同逻辑分析。两个一致启发函数取最大仍一致，因为两者在当前状态各自不超过同一个边成本加后继最大值。对可加情形，若各自在分到的边成本上一致，逐边相加就得到原成本下的一致性。只知道两者可采纳时，取最大仍可采纳，但不能据此启用永久关闭。把搜索结果分成“最优性是否成立”和“首次展开是否已结算”有助于避免混用这两种性质。

<a id="search-resources"></a>

### 9.2 代价和内存预算怎样进入选择

带权 A* 把队列分数改成 $`g+w h`$，其中 $`w\ge1`$。增大权重常用于更早检查看起来接近终点的候选，但实际展开数和耗时取决于图。$`w=1`$ 回到精确 A*。在本章有限、非负成本、目标处为零的设置中，使用可采纳 $`h`$、允许改进重开，并以弹出有效目标终止，可以证明返回成本不超过 $`w C^*`$。

证明仍从最优路线上的有效前沿开始。其前缀成本不超过最优路线相应的前缀成本，记后者为 $`g^*`$。它的加权分数不超过 $`g^*+w(C^*-g^*)`$。因为 $`g^*\ge0`$，这个上界至多为 $`w C^*`$。弹出的目标没有启发项，目标成本就是它的优先值，故不超过前沿候选的上界。若在生成目标时提前停止，或者因为错误关闭丢失了前沿，这个证明不能使用。带权排序本身也不会让任意候选的分数继续成为最优成本的下界，预算报告要分别维护未加权的下界。

例如第 2.2 节中取 $`w=2`$，B 的优先值从四变成七，A 仍是三。目标五可能在 B 之前弹出，满足两倍保证但比最优值四大。输出里应明确标记近似模式和当前证据。加权策略改变的是探索顺序及可声明的误差，不是定义一条边时可以违反任务限制。

显式图中使用一致估计，且每个状态的后继只展开一次时，简单堆实现会为每次成功改进追加一个候选，入队数受实际扫描边数约束。它可能同时保存许多旧项，所以峰值内存不能只按不同结点数计。允许重开时，还要分别统计唯一状态数与展开次数。若一个状态展开三次，生成它的邻居也可能重复三次。用唯一状态数冒充扫描工作，会低估不一致估计的代价。

内存不足时可以考虑按分数阈值反复深度优先搜索。每轮只展开估计总成本不超过当前阈值的前缀，将这一轮遇到的最小超阈值设为下一阈值。经典 IDA* 减少了显式前沿存储，但可能反复访问同一前缀，还要处理路径上的环。直接让下一阈值固定加一，既可能跳过真实成本尺度，也可能做无谓轮次。已有可行解时，另一个办法是以它为上界做深度优先分支定界，只有能证明下界不小于上界的分支才可剪去。小内存和少重算之间需要折中。

评估这类策略时固定图、目标、代价单位、平局规则和预算，再分别报告解的代价、展开数、重开数、堆峰值、启发计算次数和总用时。比较加权方法时还要报告它是否达到目标保证。实验中已知最优值可以直接比较近似比；真实大实例没有精确最优参照时，可报告有效下界和可行解上界。允许结论为“更快得到可行解，但当前证书更弱”。只比较耗时，会把更早停止带来的精度差异隐藏起来。
