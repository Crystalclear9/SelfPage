## 1. 二分搜索：从猜中元素到定位边界

<a id="algo-two-2"></a>

### 1.1 把问题写成单调判定

二分搜索最容易被误解为“在数组中猜一个值”。更一般而且更可靠的理解是：在有序的候选空间中，定位真假判定发生变化的边界。设下标范围为零到 $`n-1`$，某个谓词在前面全为假、后面全为真，目标是返回第一个真的位置；若全部为假，返回 $`n`$。这样，重复值、元素不存在和空输入都只是同一规格中的自然情形。

对升序数组寻找第一个不小于目标的位置，谓词是当前元素大于等于目标。对寻找第一个严格大于目标的位置，谓词改为严格大于。两个规格只差一个等号，返回值却可能相差整个重复区间。先写清“第一个”“最后一个”“不小于”“严格大于”这些词，再写代码，比在出错后调整加一减一更有效。

单调性来自数据和比较规则的共同作用。若数组按数值升序，查询也应使用同样的数值关系；按字符串排序的数字不能直接用于数值二分。缺失值、非数值与不一致的自定义比较可能让判定不再单调，导致二分丢弃真正答案。二分速度来自排除整段候选的合法性，失去单调性后，对数步数并不意味着得到正确结果。

<a id="algo-two-3"></a>

### 1.2 半开区间中的完整不变量

使用半开搜索区间`[lo, hi)`时，可以维护三个性质：所有小于`lo`的位置都判定为假；所有大于等于`hi`且小于 $`n`$ 的位置都判定为真；尚未分类的位置位于中间。初始化为零与 $`n`$，左右已分类区域均为空，所以性质自然成立。目标边界作为一个位置，位于闭区间`[lo, hi]`中；注意这与尚未检查的元素区间是两个不同概念。

取中点后，若判定为假，根据单调性，中点及其之前都不可能是答案，把`lo`改为中点加一；若判定为真，中点可能正是第一个真，不能丢掉其作为边界的可能性，因此令`hi`等于中点。每一步都保留上述性质，同时让非负整数`hi-lo`严格减小，证明循环会终止。终止时两者相等，左边全部为假，右边全部为真，返回位置就满足规格。

这套证明同时包含初始化、保持、终止与答案解释。仅写“答案还在区间里”通常不够，因为没有说明区间是元素区间还是边界区间，也没有说明为什么更新时可以丢弃中点。严谨的不变量还可以指导测试：检查空输入、全假、全真和一段重复值，而不是只测试一次恰好命中的查询。

<a id="sec-1-1"></a>

<a id="algo-two-4"></a>

### 1.3 重复值中的手工推导

数组为一、二、二、四，寻找第一个不小于二的位置。初始区间从零到四，中点二的元素为二，属于真区域，于是右边界移到二；接着中点一仍为真，右边界移到一；最后中点零的元素为一，属于假区域，左边界移到一。两端相遇返回一，恰好是重复段的左端。

若寻找第一个严格大于二的位置，前两个二都属于假区域，最后返回三。重复值的出现次数等于右边界减左边界。若目标不存在，两种边界相同，差为零；若全部元素都等于目标，左边界为零、右边界为长度。这些结论由规格直接推出，不需要分别编写特殊分支。

返回 $`n`$ 是一个合法插入位置，却不是合法元素下标。若调用者想确认目标是否存在，必须先检查返回位置小于长度，再检查对应元素是否相等。很多边界错误来自把“算法成功返回边界”误读为“算法已找到一个可读取元素”。接口文档应该明确返回值的含义，让后续程序承担正确的存在性判断。

<a id="deep-dive-1"></a>

<a id="algo-two-5"></a>

### 1.4 推广到答案空间与连续区间

如果存在一组按数值排列的候选答案，且“某个候选能否满足约束”具有单调性，就可以对答案空间二分。例如固定截止时间，判断若干处理器是否能完成任务；更长时间若总不会更差，则可搜索最小可行时间。但判定过程本身也有成本，若单次需要线性扫描，整体可能是线性乘对数，而不是仅有对数工作。

二分答案之前要分别证明两个命题：可行性判定正确；可行集合具有所需单调结构。一个贪心判定若只是看起来合理，外层二分无法修复它。若约束在某些区间可行、某些区间不可行并反复变化，简单二分也不适用。搜索框架和判定算法是两个独立的正确性责任。

连续实数二分则通常返回容差范围内的近似解，不是精确下标。需要明确绝对或相对误差、最大迭代数、浮点中点可能与端点相等的情况，以及可行端与不可行端是否已知。对带噪判定，单次误判可能永久丢弃正确区间，不能直接照搬确定性证明。数值章节讨论的舍入与停止条件，在这里同样重要。

<a id="algo-two-6"></a>

### 1.5 比较次数与容器访问成本

数组二分每步常数次访问和比较，区间大致减半，所以比较次数为对数级。如果容器不支持常数时间随机访问，例如某些链式结构，寻找中点位置本身可能很贵；如果每次比较都计算复杂特征或扫描长字符串，时间还应乘上比较代价。把“二分比较次数”与“完整执行时间”分开，才能正确使用算法结论。

插入位置通过二分找到，并不意味着插入也是对数时间。在动态数组中为新元素腾出位置通常要移动后缀，整体仍可能线性。反复在线插入 $`n`$ 条记录，不能只把二分次数相加而忽略移动。Python 的二分模块明确区分搜索与有序插入，这一差别正是数据结构与算法共同决定成本的例子。

如果每条记录的排序键很昂贵，可以预计算键数组并对键二分，但要维护键与原记录的一致性；记录改变时，旧键也许已经失效。额外缓存带来时间收益，同时引入空间与更新责任。学习算法时应习惯完整计算这些责任，而不是把所有准备工作藏在“输入已经有序”一句话之后。

## 2. 排序：顺序关系、稳定性与下界

<a id="algo-two-8"></a>

### 2.1 比较关系首先必须一致

排序需要一个足以支撑算法推理的一致比较关系。对通常的数值，可以按升序定义；对记录，可以按分数、时间、编号形成字典序。若自定义比较出现甲小于乙、乙小于丙、丙又小于甲，就存在环，无法形成普通有序序列。排序程序可能仍返回某个列表，但“所有元素按一致大小排列”的目标本身已经不成立。

浮点 NaN（Not a Number）会破坏许多直觉关系：它与普通数值进行有序比较时，既不小于对方也不大于对方，而且与自身也不相等。这是 NaN 的特殊语义，不能泛化成“所有非数值对象都与自身不相等”；字符串等对象仍有各自一致的相等与排序规则。缺失数据和异构类型则需要显式政策。可以先把有效性标记、规范化数值和确定的次级键组成排序键，让缺失值放在指定一侧。重要的是把业务规则写出来，而不是依赖当前输入恰好没有触发异常。

排序键也应尽量纯粹且稳定。若计算键时修改外部状态，或比较结果依赖不断变化的时钟和随机数，同一记录的次序可能在排序过程中改变，破坏推理前提。预先定义一个可复现的键不仅提高可解释性，也让后续二分、分组和去重能够使用同一关系。

<a id="sec-2-1"></a>

<a id="algo-two-9"></a>

### 2.2 稳定排序与多关键字

稳定性表示排序键相等的记录保持原相对顺序。它并不表示不同键的记录位置不变，也不表示数值方法意义上的抗扰动。若数据先按时间升序，再稳定地按用户分组，同一用户内部仍按原时间顺序。多轮稳定排序时，应先处理低优先级键，再处理高优先级键，因为后一次排序决定主要分组，稳定性保留前次形成的组内顺序。

也可以使用元组键一次表达所有条件，例如用户升序、分数降序、时间升序。两种方式通常在规格层面等价，但必须注意缺失值处理、升降序组合与最终并列规则。若所有键完全相等，稳定排序保留输入次序；若输入来自无保证顺序的数据源，稳定性不能自动创造跨运行的确定顺序，仍需加入唯一编号等确定键。

Python 的内置排序接口保证稳定性，排序键在一次排序中对每个输入记录计算一次。利用键函数通常比反复在比较器中计算昂贵特征更清楚。这里讨论的是接口语义，而不是要求读者记住某个版本的全部内部优化。对于返回新列表与修改原列表的差异，还应关注调用者是否依赖原顺序，以及输入是否被多个组件共享。

<a id="algo-two-10"></a>

### 2.3 插入、归并、快速与堆排序

插入排序维护已经有序的前缀，将新元素放入合适位置。若输入接近有序，移动次数可能很少；最坏逆序时，每个新元素都要跨越整个前缀，总工作平方。它适合小规模或局部近序场景，也常作为混合算法的组成部分。算法的最坏量级不能单独解释它在小数据上的价值。

归并排序把输入分为两半，分别排序后线性合并。在平衡拆分下，每层处理总量线性，层数对数，所以总工作为 $`\Theta(n\log n)`$。合并时遇到相等键先取左侧，可以保持稳定性。常见数组实现需要线性辅助缓冲；若每层都通过切片新建子数组，要核算分配和复制，而不能仅引用抽象递归式。

快速排序通过枢轴划分，性能取决于划分平衡与实现细节。若每次枢轴恰好最极端，递归成本形成平方总量；随机枢轴能对固定输入建立期望对数层级的分析，但最坏情况并没有消失。重复值很多时，三路划分可把等于枢轴的一段单独处理，避免把相同元素不断递归。随机性提供的是特定期望保证，不是任意一次运行的最坏保证。

堆排序利用极值堆反复把边界元素放到最终位置，最坏时间为对数乘线性，可以在数组上使用较少额外存储，但普通实现不稳定且访问局部性与归并不同。选择排序算法时应比较稳定性、最坏界、额外空间、输入分布和实现常数。实际库通常采用经过精心设计的混合方案，手写教科书算法主要用于理解和验证，不应默认比成熟库更快。

<a id="algo-two-11"></a>

### 2.4 比较排序的下界到底限制什么

对 $`n`$ 个互异元素的比较排序，可以把每次比较看作决策树分支。为了区分所有可能的输入次序，决策树至少需要 $`n!`$ 个可区分叶子，因此最坏深度至少为 $`\log_2(n!)`$。由乘积中后一半因子均不小于 $`\frac{n}{2}`$，可以直接得到对数阶乘是 $`\Omega(n\log n)`$，无需依赖更精细的近似公式。

这个下界针对一般比较模型和所有排列，不表示任何排序任务都必须执行这么多步骤。若键是范围有限的整数，可以用计数排序，以遍历输入与键范围的成本换取顺序；基数排序利用固定表示的多个数字位。它们使用了比较之外的结构信息，因此不与比较下界矛盾。若范围巨大、键很长或额外数组不可承受，优势又可能消失。

已有顺序同样是额外结构。只需检查输入是否有序可以线性完成；自适应排序可以利用已存在的有序段。下界并没有禁止某些特殊输入上线性执行，它约束的是对应模型中最坏输入或适当平均意义。研究算法最优性时，必须同时说清任务范围、模型和保证类型，否则容易把一个正确定理推广到它从未覆盖的场景。

<a id="algo-two-12"></a>

### 2.5 先排序再扫描的模式

排序可以把相似记录变成连续段，随后用一次扫描完成去重、分组、区间合并或双指针匹配。这经常用较高的预处理成本换取简单顺序访问。若结果需要按键排序，排序本来就是输出规格的一部分；若只需要成员关系，则哈希可能避免全序。但哈希与排序的内存、顺序保证和最坏条件不同，不能只比较两个量级就宣布普遍胜负。

区间合并是典型例子：按左端点排序后，维护当前合并段的右端点；下一段左端点若在当前覆盖范围内，就扩展右端点，否则输出前段并开启新段。闭区间、半开区间以及端点相接是否视为合并，都改变判断符号。排序提供局部处理的机会，真正的正确性仍来自对当前已覆盖区域的不变量。

对于大型数据，外部归并可以把内存内排序的块写出，再多路合并，重点资源变成外部读取写入和缓冲区。先排序再扫描因此不只是“小数据做法”，还与顺序访问和可控内存有关。下一章的递归与动态规划会继续讨论分解，但在这里已经可以看见：好的表示和已有顺序经常比复杂技巧更有价值。

## 3. 图模型：先定义什么是一条合法路径

<a id="algo-two-14"></a>

### 3.1 顶点、方向、边与状态

图由顶点集合与边集合构成。有向边只允许指定方向的移动，无向边通常在邻接表中保存两个方向。重边、自环、孤立顶点与不存在的顶点都应按任务约定处理。把有向图自动补成无向图，会改变可达性；把重复边简单丢弃，也可能改变计数或带权任务的含义。构图错误不会被后续正确的搜索算法修复。

路径长度可以指边数，也可以指边权之和。这两个优化目标在边权不同的时候并不等价。一个经过一条边、费用十的路径，比经过两条边、总费用二的路径边数更少，却不是费用更低。社交关系中的两跳邻居、道路中的最短时间和调度依赖中的可行顺序，虽然都能画成图，但需要的算法保证不同。

状态表示也决定图是否正确。迷宫中若钥匙会影响未来可走的门，仅用当前位置作为顶点是不够的；同一位置在有钥匙和无钥匙时具有不同后继。应把位置与钥匙集合一起构成状态。压缩状态可以减少规模，但只有在被合并状态对未来可行行为和目标具有等价影响时才安全。访问集合的键必须代表完整状态，而不只是方便存储的部分字段。

<a id="algo-two-15"></a>

### 3.2 邻接表示与遍历范围

邻接表遍历的 $`O(V+E)`$，通常指每个顶点和每条存储边被有限次处理，且字典集合操作在相应假设下为常见常数成本。从单一起点出发时，实际上只访问可达部分，可以写为可达顶点与相关边之和；若要覆盖全部分量，需要对未访问顶点启动额外搜索。不要把一次单源遍历的结果误称为整个图的连通性分解。

邻接矩阵中，即使某顶点只有一个邻居，找出全部邻居也可能扫描一整行，因此完整遍历可能平方。隐式图不提前保存全部边，而是在扩展状态时生成后继，复杂度需要计入后继生成成本。若每个状态要做昂贵的合法性检查，不能把它藏进一个抽象常数操作。图算法的复杂度应与实际表示匹配。

还应明确是否允许搜索过程中修改图。标准 BFS 和 DFS 的常见证明通常针对固定图，若邻接关系在遍历时变化，已访问节点可能获得新的边，原结论未必直接成立。对动态图可以使用快照、版本或专门算法，但需要新的契约。算法能运行结束，不等于它返回了某个清晰时间点上的正确图结果。

<a id="algo-two-16"></a>

## 4. 广度优先搜索的层序证明

<a id="algo-two-17"></a>

### 4.1 发现、入队与处理

BFS 从起点开始，将距离设为零并入队。每次取队头，检查其邻居；未发现邻居的距离设为当前距离加一，记录父节点，并立刻标记发现后入队。这里“发现”和“处理完成”是不同状态。若等到出队才标记，在多个前驱共享一个邻居时，同一节点可能多次入队，增加重复工作并使父节点和距离更新难以解释。

队列保持按发现层次推进。处理距离为 $`k`$ 的节点时，新发现节点距离为 $`k+1`$；先前排在队列里的节点距离不会大于这一新层。由此可证明出队距离非递减。若某节点首次被赋值为 $`k+1`$，假设存在更短路径，则其倒数第二个顶点应在更早层被处理并已经发现该节点，产生矛盾。因此第一次发现给出最小边数。

这一证明要求每条边具有相同的正单位代价，或者任务本来就在最小化边数。对所有边同一个正权重，最小边数也对应最小总代价；若权重为零，最小总代价可能出现很多并列，而边数最小并不是全部目标；若存在不同权重，层序就不能代表代价序。算法适用条件直接出现在证明的关键一步中。

<a id="algo-two-18"></a>

### 4.2 父指针、路径恢复与多源搜索

父指针记录某节点首次被发现时的前驱，从目标沿父指针回到起点，再反转即可得到一条最短路径。最短路径可能不唯一，邻居的迭代顺序会影响选中哪条。若业务要求字典序最小等特定并列规则，需要额外论证，不能因为输出了最短长度就假定路径也满足所有偏好。

多源 BFS 可以把全部起点距离设为零并同时入队，结果是每个节点到最近起点的最小边数。它相当于加入一个虚拟超级源，用零代价连向各起点，再按相应层解释；实现时直接初始化更简单。如果不同起点有不同初始代价，普通多源同层初始化就不再表达原问题，需要合适的带权方法。

只搜索距离不超过两跳的邻居时，可以在深度达到二后停止扩展该节点，而不是遍历全图再筛选。这样总工作与实际探索的局部子图有关。若图有非常高的度数，即便只有两跳，结果规模仍可能巨大，不能把固定跳数误写成常数运行时间。输出数量本身就提供了必要工作下界。

<a id="algo-two-19"></a>

### 4.3 无路径、双向搜索与空间压力

若队列耗尽仍未发现目标，说明目标在该固定图中不可达。返回空路径、特殊值还是异常，应由接口明确；起点等于终点时，零边路径通常是合法答案，不应与无路径混淆。对有向图，目标一侧的反向搜索必须使用反图，不能直接沿原边从目标向外走，否则搜索的并不是能够到达目标的状态。

双向 BFS 可以在合适图结构中显著减少实际探索，但停止条件需要保证当前最优连接已经无法被更浅的未探索层改进。随意在两个搜索集合第一次有任意交点时停止，若层扩展组织不清楚，就容易写出错误变体。应完整按层维护距离并比较连接长度，而不能只依赖“从两边搜更快”的直觉。

BFS 的主要空间通常来自已发现集合、父指针和前沿。树形搜索中，宽度可能随深度指数增长，因此求最短边数的代价可能是很大的内存。DFS 在某些结构中前沿更小，但会失去同样的最短路保证。算法选择需要同时讨论答案性质与资源，不应把空间不足简单解释为程序写得不够优化。

## 5. 深度优先搜索与结构分析

<a id="algo-two-21"></a>

### 5.1 递归栈到底保存什么

DFS 选择一个未发现邻居深入，直到没有可继续的边，再回退。递归调用栈不仅保存顶点，还保存“这个顶点的邻居已经检查到哪里”。因此，简单把顶点压入列表的迭代遍历，虽然可能得到一种深度优先式可达访问顺序，却未必完整复现递归 DFS 的进入时间、退出时间和边分类。涉及拓扑或强连通分量时，回退语义非常重要。

要精确模拟递归，可以在显式栈中保存顶点与邻居迭代器，或保存进入和退出两类事件。处理栈顶时只前进一步，直到邻居耗尽才记录退出。这使每条边仍只检查有限次，且不依赖 Python 递归深度。简单提高递归限制并不能消除底层栈与内存风险，长链图更适合显式栈。

全图 DFS 需要从每个尚未发现顶点开始搜索，形成一片深度优先森林。森林中的树边只是原图的一部分，非树边仍保存重要信息。输出一棵生成树并不意味着原图无环；访问集合只是防止重复搜索，不是已经完成了环检测。要检测特定类型的环，需要跟踪更细的状态。

<a id="algo-two-22"></a>

### 5.2 颜色状态与有向环

有向图中，可以把节点分成未发现、当前递归路径中和已经退出三种状态。检查边时，如果指向当前路径中的节点，就形成沿树路径返回祖先的有向环；指向已退出节点则不自动表示有环。只用一个“访问过”布尔值，会把这两种情况混淆，导致错误报告。

无向图的处理还要区分沿父边返回的自然反向邻接项。若简单把所有指向已发现节点的边都判为环，会连一条单边连接两个顶点都误报。重边又会让“跳过所有指向父节点的边”漏掉长度二的多重边环，因此需要在多重图中用边编号区分具体父边。图的类型和环的定义必须先写清楚。

进入与退出时间产生嵌套区间：祖先的活动区间包含后代的区间，不相关子树的区间则分离。这种性质可以解释很多 DFS 结构算法，也为实现检查提供依据。时间戳不是为了装饰输出，而是对递归调用的偏序关系做显式记录，便于证明与进一步查询。

<a id="algo-two-23"></a>

### 5.3 拓扑排序与依赖执行

有向无环图存在使每条边都从前指向后的顶点排列，这就是拓扑序。DFS 在无环条件下按退出顺序反转可以得到拓扑序，因为对每条边，目标要么在源退出前已完成，要么是其后代先完成；有向回边会破坏这一条件，所以必须先检测环。单纯反转某个 DFS 访问序列，不是正确拓扑算法。

另一种方法维护入度，把当前入度为零的顶点入队；每移除一个顶点，就减少其出边目标的入度，出现新的零入度顶点继续处理。若最终处理数量少于顶点总数，剩余部分存在有向环。证明可以利用有限无环图必有零入度顶点：若每个点都有前驱，反复沿前驱走必然重复顶点，形成环，与无环矛盾。

拓扑序通常不唯一。构建任务调度、课程先修和计算图时，若需要确定输出，可用堆选择当前最小编号的零入度顶点，但这会增加对数因子。拓扑序只保证依赖先后，不直接给出最短工期、最大并行度或资源可行调度。那些目标还需要处理任务持续时间、机器数量和共享资源。

<a id="algo-two-24"></a>

### 5.4 强连通分量与压缩图

有向图中，若两个顶点互相可达，它们属于同一强连通分量。互相可达是等价关系，因此可以把顶点划分成不重叠分量。将每个分量缩成一个点后，得到的分量图必为有向无环图；否则环上的各分量互相可达，应该合并为同一个分量，产生矛盾。这是把复杂循环依赖分解为局部循环和全局偏序的重要方法。

两遍 DFS 的一种方法先在原图记录退出顺序，再按退出顺序的逆序在反图搜索，每次搜索得到一个强连通分量。为什么不能随意用进入顺序替代？退出顺序对分量之间的依赖具有特殊性质：若分量间存在单向可达关系，相关最大退出时间的次序会让第二遍优先选到不会在反图中越过未处理分量边界的源分量。证明依赖整个分量的结构，而不是单个顶点的直觉。

更正式地，对分量 $`C`$ 定义 $`F(C)`$ 为其中最大的退出时刻。若原图有跨分量边从 $`C`$ 指向 $`D`$，则 $`F(C)>F(D)`$。若先进入 $`C`$，搜索能够沿边进入并完成 $`D`$，而 $`C`$ 的活动祖先稍后才退出；若先进入 $`D`$，它不能到达 $`C`$，否则两者互相可达应属于同一分量，所以 $`D`$ 先完成，随后才开始尚未发现的 $`C`$。两种情况都得到严格次序。

第二遍首先选择最大退出时刻所在分量，它在尚未处理的原图分量中没有入边，因此在反图中没有通向其他未处理分量的出边。反图内分量内部仍然互相可达，所以一次搜索恰好取出该分量。移除已处理分量后重复同样论证，构成归纳证明。反图中的边可能指向已经取出的分量，但访问标记会阻止再次进入；这正是两遍顺序与标记机制共同工作的理由。

实际实现要包含全部顶点、建立反向边，并在两遍之间清空访问状态。若没有反图而只是重复原图搜索，会混淆单向可达与互相可达。另一条研究路线是使用低链接值的单遍算法，但其栈成员状态、回边处理与完成分量条件都需要严谨维护。先掌握两遍算法的证明与实验，再学习更紧凑的实现，通常更容易理解。

## 6. 有权最短路：为什么换队列还不够

<a id="algo-two-26"></a>

### 6.1 松弛与最短路的基本不等式

设当前距离估计为 $`d`$，对边 $`u\to v`$、权重为 $`w`$，松弛操作尝试把 $`d(v)`$ 改成 $`d(u)+w`$ 中更小的值。任何通过已有路径得到的有限估计都对应某条实际路径，因此是最短值的上界。算法的核心问题是：以什么顺序松弛，什么时候可以确定某个估计不会再下降，何时能证明没有遗漏更优路径。

距离初始化通常为起点零、其他顶点无穷。不可达节点始终没有有限路径，不应通过无穷加权重产生伪答案。父指针在成功改进时更新，用于恢复路径。对于零权边和相同最优距离，要避免随意在相等时更新父指针造成环；严格改进更新通常更容易维持可解释的前驱结构。

最短路还需要区分“存在最小路径”和“下确界有限”。有限图在没有相关负环的通常情形下，最优简单路径存在；若起点可达的负环还能通向目标，就能反复绕行让目标代价无限下降，有限最短值不存在。仅仅图中某个完全不可达区域有负环，并不会让当前单源所有答案都失去意义。

<a id="algo-two-27"></a>

### 6.2 Dijkstra 的非负权证明

Dijkstra 每次从尚未确定的顶点中取出当前估计距离最小者。非负权保证任何经过尚未确定区域再返回的路径，不可能比当前最小边界估计更早获得更小代价。标准反证法取一条假设更短的路径，找到其中第一个未确定顶点，其前驱已经确定并应已松弛相应边，从而与被选顶点的最小估计矛盾。

关键步骤使用后续边不会减少总代价，所以要求非负权。若存在负边，某个已经看似最小的顶点可能经较远节点和负边被改得更小，过早确定就错了。某些允许重新打开顶点的变体在特定负边图上可能碰巧得到正确结果，但已不是原先一次确定的复杂度与证明。不能凭一次成功运行宣布非负条件不必要。

使用普通二叉堆且采用惰性旧条目时，一条成功松弛可以加入新条目，旧条目出堆时若距离已过期就跳过。堆条目数量与成功松弛有关，常见总界可写为 $`O((V+E)\log(V+E))`$；在通常简单图等条件下可化为熟悉的对数顶点表达。空间不能只算一个顶点一个堆条目，因为惰性策略允许多个历史条目同时存在。

<a id="algo-two-28"></a>

### 6.3 零一权、负边与负环

边权只有零和一时，可以使用双端队列：零代价改进放队头，一代价改进放队尾，维护与当前距离相关的层次结构。这是零一 BFS，其理由来自权重结构，不是普通 BFS 随意换个队列。若出现权重二或小数，就不能继续直接套用同样规则，需要重新证明或选择其他算法。

允许负边但需要检测相关负环时，可以使用逐轮松弛的思想。Bellman–Ford 在最多 $`V-1`$ 轮后已经覆盖所有不含重复顶点的路径，因为简单路径最多含 $`V-1`$ 条边。若之后仍能从可达顶点成功改进，就存在可达负环的影响。想判断某个特定目标是否无下界，还要检查被负环影响的区域能否到达目标，而不是一见任何负环就把所有顶点一概标记。

对有向无环图，即使有负边，也可以按拓扑序一次处理边，时间与图规模线性。因为所有可能前驱在节点处理前已经完成，不需要非负权来保证顺序。这说明算法条件常有多种可替代结构：非负权允许按距离确定，无环性允许按依赖确定。看到负权就机械选择最慢通用方法，也会错过更强的输入性质。

<a id="algo-two-29"></a>

### 6.4 启发式、隐式图与状态爆炸

在路径规划中，可以用启发式估计剩余代价来引导搜索。若要保留最优性，需要说明启发式是否不高估、是否满足相邻状态的一致性，以及实现是否允许在发现更短路径时重新打开状态。仅有一个“看起来接近目标”的分数，不能自动保证最短路径。启发式改善的通常是实际展开顺序，而不是消除最坏规模。

隐式图避免提前保存全部边，但状态数仍可能指数增长。例如状态包含若干布尔开关，理论组合数是二的开关数量次方；后继按需生成并不会改变可达状态总数的潜在规模。可以利用对称性、支配关系或可证明的状态合并减少搜索，但必须证明不丢失最优解。将状态表示缩小到只剩当前位置，很可能只是错误地合并了不同未来。

在机器学习相关检索图中，近邻搜索通常允许近似，目标与精确最短路不同。图的边连接相似对象，不意味着沿图边累计代价就等同于原始向量距离。评价应采用召回率、候选数量、查询时间和内存等对应指标，不能把 BFS 或 Dijkstra 的正确性定理直接挪来保证近似检索质量。

## 7. 独立实验：用性质和反例验证证明

<a id="sec-6-1"></a>

<a id="algo-two-31"></a>

### 7.1 二分边界与稳定排序交叉检查

下面的二分实现对所有短长度、重复值和多种目标进行交叉检查。参考答案使用线性查找表达规格，并额外与标准库二分接口一致比较。这样测试不只是运行一个正常样例，而是覆盖空数组、全部小于、全部大于、目标重复和目标缺席。排序实验则验证多轮稳定排序与元组键的等价关系，使用唯一编号检查并列记录顺序。

```python
from bisect import bisect_left, bisect_right
import random

def boundary(values, target, strict=False):
    lo, hi = 0, len(values)
    while lo < hi:
        mid = (lo + hi) // 2
        is_true = values[mid] > target if strict else values[mid] >= target
        if is_true:
            hi = mid
        else:
            lo = mid + 1
    return lo

rng = random.Random(17)
for n in range(55):
    values = sorted(rng.randrange(-4, 5) for _ in range(n))
    for target in range(-6, 7):
        left = next((i for i, x in enumerate(values) if x >= target), n)
        right = next((i for i, x in enumerate(values) if x > target), n)
        assert boundary(values, target) == left == bisect_left(values, target)
        assert boundary(values, target, True) == right == bisect_right(values, target)
        assert right - left == values.count(target)

rows = [('b', 2, 0), ('a', 1, 1), ('b', 1, 2), ('a', 1, 3)]
by_time_then_group = sorted(sorted(rows, key=lambda r: r[1]), key=lambda r: r[0])
assert by_time_then_group == sorted(rows, key=lambda r: (r[0], r[1]))
assert [r[2] for r in by_time_then_group if r[:2] == ('a', 1)] == [1, 3]
print('binary boundaries and stable sorting passed')
```

不建议把标准库结果当作所有验证的唯一证据，因为理解接口错误时，可能同时误用两边。这里增加线性规格和出现次数性质，分别从三个方向核对边界。真正的一般正确性仍由前面的不变量证明提供。实验的价值是发现实现偏离证明的地方，而不是用有限输入代替逻辑论证。

### 7.2 BFS 路径与不可达状态

下面保留父指针并恢复一条路径，起点自身使用自指父标记。返回的距离字典只包含可达顶点，避免把不存在的路径混成某个巨大整数。实验检查路径的每条边真实存在、边数等于最短距离，并且孤立节点不会被错误发现。图中既有环也有多个前驱，入队标记保证每个节点只进入队列一次。

```python
from collections import deque

def bfs(graph, source):
    distance = {source: 0}
    parent = {source: source}
    queue = deque([source])
    while queue:
        u = queue.popleft()
        for v in graph[u]:
            if v not in distance:
                distance[v] = distance[u] + 1
                parent[v] = u
                queue.append(v)
    return distance, parent

def path_to(parent, target):
    if target not in parent:
        return None
    result = []
    while True:
        result.append(target)
        if parent[target] == target:
            break
        target = parent[target]
    return result[::-1]

graph = {'s': ['a', 'b'], 'a': ['c'], 'b': ['c'],
         'c': ['s', 't'], 't': [], 'alone': []}
distance, parent = bfs(graph, 's')
assert distance['t'] == 3 and 'alone' not in distance
path = path_to(parent, 't')
assert len(path) - 1 == distance['t']
assert all(v in graph[u] for u, v in zip(path, path[1:]))
assert path_to(parent, 's') == ['s']
assert path_to(parent, 'alone') is None
# None是合法的可哈希节点，不能同时用作父节点终止标记。
none_graph = {None: ['a'], 'a': ['b'], 'b': []}
none_distance, none_parent = bfs(none_graph, None)
assert path_to(none_parent, 'b') == [None, 'a', 'b']
assert path_to(none_parent, None) == [None]
print('BFS distance and path checks passed')
```

父指针让起点指向自身，恢复路径时遇到这个自指关系才终止，因此`None`也能作为普通业务顶点。不可达目标仍返回`None`，而起点为`None`的合法路径返回列表`[None]`，两种结果可以区分。这里假定节点具有稳定的哈希与相等语义，且邻接表中的目标都列在图字典中；业务身份不应与控制流终止标记混用。

### 7.3 显式退出顺序、拓扑序与强连通分量

以下 DFS 使用邻居迭代器准确记录退出事件。两遍搜索得到强连通分量，再用一个独立的逐点可达性检查验证“同分量当且仅当互相可达”。这一参考方法对大图较慢，但在微型测试上概念直接，能发现反图、退出顺序或访问状态重用中的错误。实验还对一百六十个固定随机种子的微型图检查整个划分，并用五千节点的长链验证显式栈不依赖递归深度。拓扑排序另用入度方法，检验全部边的前后关系和有环时的失败行为。

```python
from collections import deque

def finish_order(graph):
    seen, order = set(), []
    exhausted = object()  # 独立哨兵，不占用任何合法节点值。
    for root in graph:
        if root in seen:
            continue
        seen.add(root)
        stack = [(root, iter(graph[root]))]
        while stack:
            u, neighbors = stack[-1]
            v = next(neighbors, exhausted)
            if v is exhausted:
                stack.pop()
                order.append(u)
            elif v not in seen:
                seen.add(v)
                stack.append((v, iter(graph[v])))
    return order

def components(graph):
    reverse = {u: [] for u in graph}
    for u in graph:
        for v in graph[u]:
            reverse[v].append(u)
    assigned, result = set(), []
    for root in reversed(finish_order(graph)):
        if root in assigned:
            continue
        assigned.add(root)
        group, stack = [], [root]
        while stack:
            u = stack.pop()
            group.append(u)
            for v in reverse[u]:
                if v not in assigned:
                    assigned.add(v)
                    stack.append(v)
        result.append(set(group))
    return result

def topological(graph):
    degree = {u: 0 for u in graph}
    for neighbors in graph.values():
        for v in neighbors:
            degree[v] += 1
    queue = deque(u for u in graph if degree[u] == 0)
    order = []
    while queue:
        u = queue.popleft()
        order.append(u)
        for v in graph[u]:
            degree[v] -= 1
            if degree[v] == 0:
                queue.append(v)
    if len(order) != len(graph):
        raise ValueError('directed cycle')
    return order

graph = {0: [1], 1: [2, 3], 2: [0], 3: [4], 4: [3], 5: []}
assert finish_order({'a': [None], None: []}) == [None, 'a']
assert components({'a': [None], None: ['a']}) == [{'a', None}]
groups = components(graph)
assert {frozenset(c) for c in groups} == {frozenset({0, 1, 2}),
                                          frozenset({3, 4}), frozenset({5})}
def reachable(start):
    seen, stack = {start}, [start]
    while stack:
        for v in graph[stack.pop()]:
            if v not in seen:
                seen.add(v)
                stack.append(v)
    return seen
all_reach = {u: reachable(u) for u in graph}
for u in graph:
    for v in graph:
        same_group = any(u in group and v in group for group in groups)
        assert same_group == (v in all_reach[u] and u in all_reach[v])
import random
rng = random.Random(101)
for n in range(1, 9):
    for _ in range(20):
        graph = {u: [v for v in range(n) if rng.random() < 0.22] for u in range(n)}
        groups = components(graph)
        all_reach = {u: reachable(u) for u in graph}
        assert sorted(v for group in groups for v in group) == list(range(n))
        for u in graph:
            for v in graph:
                assert any(u in group and v in group for group in groups) == (
                    v in all_reach[u] and u in all_reach[v])
chain = {i: [i + 1] if i < 4999 else [] for i in range(5000)}
assert finish_order(chain) == list(reversed(range(5000)))
dag = {'a': ['c'], 'b': ['c'], 'c': ['d'], 'd': [], 'isolated': []}
order = topological(dag)
position = {u: i for i, u in enumerate(order)}
assert all(position[u] < position[v] for u in dag for v in dag[u])
try:
    topological({0: [1], 1: [0]})
except ValueError:
    pass
else:
    raise AssertionError('cycle was missed')
print('DFS finish order, SCC and topological checks passed')
```

迭代器耗尽使用新建的独立对象作哨兵，并用身份比较识别，因此不会把合法的`None`节点误当成搜索结束。邻接列表中的目标必须都出现在顶点字典中，包括无出边节点。把完整顶点集合显式列出，有助于保留孤立节点并避免反图构建遗漏。复杂度证明要求每个邻接迭代器只向前推进，因此不能每次回到栈顶都重新创建迭代器。

### 7.4 非负最短路与失败反例

下面使用惰性堆实现 Dijkstra，先检查所有权重有限且非负，再运行搜索。独立参考方法对这个微型图重复松弛，检查最短距离一致。反例展示普通 BFS 选一条边的路径会得到更高费用；负边输入则明确拒绝，防止读者把偶然成功误当作适用性。代码不用浮点近似比较证明真实数值最短路，样例采用整数权重。

```python
from heapq import heappush, heappop
from itertools import count
from math import inf, isfinite

def dijkstra(graph, source):
    if any(not isfinite(w) or w < 0 for edges in graph.values() for _, w in edges):
        raise ValueError('finite nonnegative weights required')
    distance = {u: inf for u in graph}
    distance[source] = 0
    ticket = count()
    heap = [(0, next(ticket), source)]
    while heap:
        du, _, u = heappop(heap)
        if du != distance[u]:
            continue
        for v, weight in graph[u]:
            candidate = du + weight
            if not isfinite(candidate):
                raise OverflowError("path sum is not representable as a finite value")
            if candidate < distance[v]:
                distance[v] = candidate
                heappush(heap, (candidate, next(ticket), v))
    return distance

graph = {'s': [('t', 10), ('a', 1)], 'a': [('t', 1)],
         't': [], 'isolated': []}
actual = dijkstra(graph, 's')
reference = {u: inf for u in graph}
reference['s'] = 0
for _ in range(len(graph) - 1):
    for u in graph:
        for v, weight in graph[u]:
            reference[v] = min(reference[v], reference[u] + weight)
assert actual == reference
assert actual['t'] == 2 and actual['isolated'] == inf
assert len(graph['s']) == 2  # one-hop t costs 10, two-hop route costs 2
try:
    dijkstra({'s': [('t', -1)], 't': []}, 's')
except ValueError:
    pass
else:
    raise AssertionError('negative edge was accepted')
print('Dijkstra reference and precondition checks passed')
```

堆条目中加入递增票号，是为了让相同距离时不必比较业务顶点对象。距离比较使用整数，因此过期判断没有受到舍入误差干扰。有限浮点边相加仍可能溢出，因此实现显式拒绝不可表示的候选路径和，不把它混同不可达的无穷哨兵。实际浮点权重还应认识到累加可能有舍入；但不能随意加入一个误差阈值后仍声称得到原始精确优化问题的同一答案。数值容差需要对应明确的误差要求。

## 8. 进阶练习与详细题解

<a id="algo-two-36"></a>

### 8.1 练习一：边界与元素下标

**题目。** 在空数组、全部元素小于目标、全部元素等于目标三种情况下，分别给出左边界与右边界。为什么返回长度不是异常？

**题解。** 空数组没有真实元素，两种边界都为零；全部小于目标时，两种边界都为长度；全部等于目标时，左边界为零，右边界为长度。边界表示插入点或真假变化的位置，允许位于最后一个元素之后，因此返回长度符合定义。只有将它误用为可直接索引的元素位置，才会发生越界。

若调用者需要判断目标存在，应检查左边界小于长度且对应值等于目标。若只想插入并保持顺序，左边界和右边界都可能合法，但会决定新条目放在旧并列条目前还是后。容器中保存完整记录时，这一选择还可能影响稳定语义，应在接口中说明。

<a id="algo-two-37"></a>

### 8.2 练习二：错误更新为何不终止

**题目。** 半开区间二分中，在中点判定为假时把左边界设为中点，而不是中点加一，会出现什么问题？给出最小反例并解释下降量。

**题解。** 只剩一个候选元素且判定为假时，中点等于左边界，更新后区间完全不变，循环永远执行。例如长度一的数组元素为一、目标为二，初始区间零到一，中点零是假；若左边界仍为零，就没有进展。正确更新应排除已经确认是假且不可能为答案的中点，因此加一。

证明终止时应选择非负整数变元`hi-lo`，检查每个分支都严格减少，而不是泛泛说“区间越来越小”。这种方法适用于很多循环：若状态可能原地不变，即便数学意图看起来在逼近答案，也必须明确处理停滞情况。

<a id="algo-two-38"></a>

### 8.3 练习三：二分答案的双重证明

**题目。** 某程序用二分搜索最小可行容量，判定函数采用未经证明的贪心分配。即使判定结果随容量单调，是否足以说明答案正确？

**题解。** 不足。单调性只保证二分可以找到这个判定函数从假到真的边界，不能保证该边界等于真实问题的可行边界。一个始终返回真的函数也是单调的，却显然会给出错误最小容量。必须先证明判定函数当且仅当真实可行，再证明真实可行性随容量单调。

还要保证初始搜索区间覆盖答案，特别是至少包含一个已知可行上界。如果上界不可行，二分可能返回边界数值并被误认为答案。复杂度则为判定成本乘以判定次数，必要时还要加上寻找上界的成本。

<a id="algo-two-39"></a>

### 8.4 练习四：多轮稳定排序的顺序

**题目。** 要按班级升序、班内分数降序、同分按时间升序排列。若采用多轮稳定排序，应该按什么次序执行？若输入次序跨运行不确定，稳定性是否保证最终完全一致？

**题解。** 先按时间升序，再按分数降序，最后按班级升序。每一轮稳定保留前一轮在相等主键组内形成的顺序，最后班级成为最高优先级。反过来先排班级再排时间，会让时间变成主要顺序，不能实现目标。也可以一次使用明确的组合键表达同样规则。

若三种业务键都相等，稳定排序只保留原输入顺序；输入本身不确定时，结果仍可能变化。若需要可复现的完整次序，应加入唯一且稳定的编号作为最低优先级键。这不是稳定性的缺陷，而是业务规则尚未定义所有并列情况。

<a id="algo-two-40"></a>

### 8.5 练习五：线性排序为何不违背下界

**题目。** 对取值范围零到九百九十九的整数使用计数排序，总成本可以与输入长度加范围大小成正比。它是否推翻一般比较排序的对数乘线性下界？

**题解。** 没有。计数排序利用键值可以直接索引有限范围数组这一额外结构，不只通过两两比较获得顺序信息，因此不在一般比较决策树模型的限制内。其空间与范围大小相关，如果键范围远大于输入长度，初始化与存储计数数组可能很不划算。

若记录还带有附加字段并要求稳定输出，需要通过累计计数确定位置并保持相同键的原顺序，不能只按次数重复输出整数。任务规格变化会影响实现细节。下界应始终带着模型一起阅读，不能把限定条件丢掉后制造假矛盾。

<a id="algo-two-41"></a>

### 8.6 练习六：BFS 为何在入队时标记

**题目。** 图中起点连接两个节点，这两个节点都连接同一个终点。若等到出队才标记，终点会怎样？这一定改变最短距离吗？

**题解。** 两个前驱都可能在终点首次出队前将它加入队列，造成重复条目。在某些实现中距离仍可能保持正确，但工作量、父指针和更新逻辑会变得复杂；若进一步无条件覆盖距离，就可能引入更严重错误。不能把“某个简单图没错”当作该策略与标准证明完全等价。

入队时标记把发现事件唯一化，每个顶点最多一次入队，每条邻接边只需在其源处理时检查，从而直接得到图规模级别的工作界。这个细节不是性能小技巧，而是让状态定义与正确性证明保持一致的关键设计。

<a id="sec-7-1"></a>

<a id="algo-two-42"></a>

### 8.7 练习七：无权 BFS 能否直接求带权最短路

**题目。** 起点到目标有一条代价十的边，另有经中间点两条各代价一的边。解释 BFS 和最短费用目标的差异；若所有边权都等于五，结论又如何？

**题解。** BFS 优先发现一条边的直达路径，得到最少边数一，但其费用十高于两条边路径的费用二。它的队列按边数层扩展，不能保证累计费用非递减。非负但不相同的权重一般应采用匹配权重结构的方法，例如 Dijkstra，而不是只把边权字段附加到原 BFS 数据结构中。

若全部边权为同一个正常数五，任一路径费用就是边数乘五，最少边数与最小费用等价，因此 BFS 可以使用。这个推广来自目标函数的等价关系，说明适用性应通过证明判断，而不是只看输入有没有一个叫“权重”的字段。

<a id="algo-two-43"></a>

### 8.8 练习八：DFS 访问过是否表示有环

**题目。** 有向无环图中，两条不同路径汇合到同一个顶点。DFS 遇到一个已经完成的节点，是否说明存在有向环？无向图又要注意什么？

**题解。** 不说明。已经完成的节点可能属于先前搜索的分支，边指向它不会自动形成回到当前祖先的路径。有向环检测需要区分当前活动路径与已退出状态；指向当前活动祖先才是关键回边。只用已访问集合无法表达这一区别。

无向图还存在父子边的反向邻接项，不能把沿原边回到父节点当作新的环。多重图需要用边编号区分父边与另一条平行边，否则会漏掉合法定义下的多重边环。对图类型作出精确约定，比反复添加例外条件更清楚。

<a id="algo-two-44"></a>

### 8.9 练习九：拓扑序不是最短工期

**题目。** 对任务依赖图得到一个拓扑序后，是否已经求出了在两台机器上的最短完成时间？若处理顶点数量少于总数，说明什么？

**题解。** 拓扑序仅保证所有前驱排在后继之前，没有安排任务持续时间、资源冲突和并行开始时刻。不同合法拓扑序可能产生不同调度结果，最短工期是更强的优化问题，需要额外算法和约束。把可行执行次序当作最优资源调度，是常见的目标混淆。

入度消除算法若无法处理全部节点，说明剩余依赖中存在有向环。剩余节点不一定每个都位于环上，也可能只是被环阻塞的后继，因此不能直接把剩余集合全部报告为环成员。若需要精确定位循环组，应进一步做强连通分量分析。

<a id="algo-two-45"></a>

### 8.10 练习十：强连通分量为何形成无环压缩图

**题目。** 假设将每个强连通分量缩成一点后，压缩图仍有一条经过多个分量的有向环。为什么会产生矛盾？它对依赖分析有什么帮助？

**题解。** 沿压缩图的环，每个分量都能到达其他分量；分量内部原本又互相可达，所以环上任意两个原顶点也互相可达。它们理应属于同一个强连通分量，与此前被分成多个分量矛盾。因此压缩图必为有向无环图。

这允许先把循环依赖作为局部组处理，再对组之间建立拓扑顺序。一个分量内是否能执行，还需要业务解释，例如循环公式能否求固定点、软件依赖是否允许共同构建。图分解揭示结构，不能代替领域规则判定循环是否可接受。

<a id="algo-two-46"></a>

### 8.11 练习十一：负边的最小反例

**题目。** 起点到甲的边为二，到乙的边为五，乙到甲的边为负四。解释一次确定型 Dijkstra 的关键证明为什么失效，以及这个图是否需要有负环才会出问题。

**题解。** 甲会先以距离二被选为当前最小，而经过乙到甲的路径总费用为一，更短。若实现将甲永久关闭且不再更新或传播，就可能错过正确答案。问题来自后续负边可以把较远前缀的费用降低，破坏“选出最小估计后不会再下降”的论证。

图中不需要任何环，单条负边已经足以使标准非负证明失效。由于此例本身是有向无环图，可以按拓扑序处理得到正确答案；这也说明负边与负环是不同问题。负环影响是否存在有限最优值，负边则影响某类确定顺序是否安全。

<a id="algo-two-47"></a>

### 8.12 练习十二：负环影响哪些目标

**题目。** 起点可达一个负环，但负环无法到达目标甲；另一个目标乙可从该负环到达。是否应将两者都判为负无穷？

**题解。** 不应一概处理。对乙，可以绕负环任意多次后再走向乙，使费用无下界，所以不存在有限最短值。对甲，若没有其他能影响它的相关负环，路径仍可能具有有限最优值；负环无法把改进传播到甲，就不改变甲的最优费用。

算法检测到额外可改进顶点后，通常需要沿有向边传播受影响标记，再判断具体目标是否在影响范围内。不可从起点到达的负环更不会影响当前单源路径。这里再次体现方向和可达性条件的重要性，不能把局部结构性质推广到所有顶点。

<a id="algo-two-48"></a>

### 8.13 练习十三：状态遗漏造成错误去重

**题目。** 机器人到某位置时可能持有钥匙，也可能没有钥匙；门只有持钥匙时能通过。若访问集合仅记录位置，可能发生什么错误？

**题解。** 机器人可能先在没有钥匙时到达某位置并标记，之后带钥匙再次来到同一位置时被当成重复状态而丢弃，导致明明可达的目标被判不可达。位置相同不意味着未来可选动作相同，访问集合使用了错误的等价关系。正确状态至少应包含影响后继的钥匙信息。

若钥匙集合很大，状态空间可能指数增长，这是真实问题复杂度的一部分，不能通过省略状态伪装成低成本算法。可以寻找支配关系，例如在某些单调条件下，相同位置拥有更多钥匙且费用不高的状态支配较少钥匙状态；但这种剪枝需要正式证明，不能在钥匙有负担或会触发惩罚时继续套用。

<a id="algo-two-49"></a>

### 8.14 练习十四：递归与显式栈是否等价

**题目。** 为避免递归深度限制，把 DFS 改成“弹出一个顶点，再把所有邻居压栈”。这个程序可用于可达性，但为什么不能直接认为它的弹出顺序就是递归退出顺序？

**题解。** 递归退出发生在所有相关后继调用结束之后，而简单顶点栈的弹出恰好表示准备处理该顶点，两种事件的时间含义相反。若直接把弹出序列反转用于强连通分量或拓扑排序，就可能使用错误顺序。可达性只关心最终哪些点被发现，对精确退出时机不敏感，因此同一简化在该任务上仍可正确。

要模拟退出顺序，可以保存邻居迭代器，使顶点在所有邻居处理完后才真正出栈；也可以加入进入和退出事件，并清楚安排压栈顺序与访问标记。改写控制流时，应先确定原算法依赖哪些事件关系，再证明新表示保留了这些关系，而不是只比较是否访问相同节点。

<a id="algo-two-50"></a>

## 9. 研究练习：建立算法选择与反例档案

<a id="algo-two-51"></a>

### 9.1 将方法与证明前提配对

可以为每种算法整理五列：任务目标、输入前提、维护状态、正确性关键句和最小失败反例。二分对应单调判定与严格缩小区间；稳定排序对应一致的比较键和并列顺序；BFS 对应等权层次；Dijkstra 对应非负权下的确定顺序；拓扑方法对应无环依赖。每个结论都与一个可检查条件绑定，便于迁移到新任务。

这种档案比背诵复杂度更有价值，因为真实问题经常只改变一个条件。加入一条负边，原最短路证明可能立即失效；让输入时间戳乱序，窗口队列的过期逻辑可能失效；让记录比较关系不一致，排序后再二分的整体流程都可能失效。找到证明中使用该条件的具体位置，可以直接指导修复，而不是在失败样例上盲目调参。

<a id="algo-two-52"></a>

### 9.2 进一步的理论与工程问题

理论上可以继续研究比较决策树、随机枢轴的期望分析、强连通分量的低链接不变量，以及最短路中的势函数和重新赋权。每一项都连接了本章的基本思想：利用结构排除不可能答案，或者找到使局部决策可以安全确定的顺序。不要急于记住所有算法名字，先能复述它为何不会漏掉更优解。

工程上可以继续研究外部排序、压缩图表示、并行遍历与动态更新。此时渐近操作次数仍然重要，但通信、同步、缓存和数据分区会带来新成本。一个理论上访问每条边一次的程序，若每次都触发远程请求，实际代价仍可能巨大。把计算模型与执行环境联系起来，是从完成练习走向设计可靠工具的必要一步。
