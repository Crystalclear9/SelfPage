## 1. 从一次优化更新建立对象账本

<a id="effsys1-detail-2"></a>

### 1.1 参数量为什么不是训练内存

设模型有 $`P`$ 个可训练标量。参数量只描述模型的一部分自由度，不能告诉我们反向传播需要保留什么。前向产生的层输入、非线性中间量、注意力概率和随机掩码可能被自动微分保存；反向生成梯度；优化器更新时读取历史矩；通信还会临时创建连续缓冲。只计算权重文件大小，会遗漏这些彼此不同、存活时间也不同的对象。

应先区分持久对象和阶段对象。参数、优化器矩和某些主权重跨步存在；梯度常在反向到更新之间存在，但使用清零而非设为无值时，其存储可能跨步保留；激活主要从前向存到相应反向；工作区按算子生成和释放。真正的峰值发生在某个具体时刻，而不一定发生在最大的单个算子。只列一张没有时间轴的总表，容易重复计数，也容易漏掉重叠。

还应区分逻辑张量与底层存储。一个视图有自己的形状，却可能与原数组共用同一存储；参数展平、切片、共享权重也会产生别名。逐个相加张量的元素数可能把同一块内存算两次。反之，一个逻辑参数可能拥有计算副本和优化器主副本，需要分别计数。账本的基本单位是具有明确所有者和生命周期的存储，而非变量名。

<a id="effsys1-detail-3"></a>

### 1.2 一个有条件的十六字节模型

考虑明确指定的混合精度配置：每个参数有两字节计算权重、两字节梯度、四字节主权重、两个四字节 Adam 矩。于是持久训练状态粗预算是 $`16P`$ 字节。这里没有把所有训练都归结为十六；例如梯度保留为四字节时会变成十八，计算权重本身采用四字节且没有主副本时又是另一种分解。优化器还可能有逐参数步数和额外临时张量。

以十亿参数为例，十六字节模型给十六十进制 GB，换算为 GiB 需要除以 $`2^{30}`$，不能把两个单位混写。还需确认账本讨论的是单个模型副本、某个分片组内的每设备值，还是整个集群总量。这三个口径之间不能只靠更换单位转换，必须按复制与唯一拥有关系重新求和。

这里的字节数尚未包含激活、通信和工作区；也没有承诺实际分配器恰好按这些紧凑数组保存。估算的价值是指出数量级和主导对象，再由测量解释差额，而不是给出看似精确的设备容量承诺。

冻结参数后，账本也必须重画。冻结层通常不需要自己的参数梯度或优化器状态，但若其前向在可训练模块之后，为了把梯度传回前面的可训练模块，仍可能保留计算图和激活。冻结不等于整段前向可包在无梯度上下文中。低秩适配减少可训练参数，却不能直接推断基础模型权重、输入激活和注意力工作区全部同比减少。

<a id="effsys1-detail-4"></a>

### 1.3 一步之内的峰值函数

用 $`S_j`$ 表示第 $`j`$ 块存储的字节数，用 $`I_j(t)`$ 表示时刻 $`t`$ 是否存活。逻辑存活量为 $`M(t)=\sum_j S_j I_j(t)`$，峰值是对时间取最大。某些短命对象虽然不大，但恰好在激活尚未释放时出现，就能决定是否越界。重计算、预取和卸载主要改变这些指示函数，因此系统优化必须研究时间。

假设持久状态二 GB、前向激活逐层累计到三 GB、反向某时刻聚合参数又占一点二 GB；如果聚合发生在全部激活仍存活时，峰值可能接近六点二 GB，而不能分别测出三个阶段最大后只取最大项。反过来，若聚合工作区在大激活出现前已经释放，直接把每项历史最大相加会过估。峰值总和与总和峰值的区别，是后面所有预算的基础。

## 2. 数据并行的数学目标与归约

<a id="effsys1-detail-6"></a>

### 2.1 先规定哪个经验风险被优化

假设训练数据被分成若干设备和微批，各有效样本损失为 $`\ell_i(\theta)`$，权重为 $`w_i\ge0`$。一个更新真正要优化的目标应先写成 $`L=\frac{\sum_i w_i\ell_i}{\sum_iw_i}`$。样本平均、有效 token 平均、序列平均和按来源重加权都是不同目标，即使使用同一组句子也会产生不同梯度。讨论系统等价时不能省略这个分母。

若每个设备只计算自己的均值而通信原语又对设备取平均，最后得到的是等权设备目标。只有每个设备有效权重相同，它才与全局有效样本目标一致。变长序列、最后一个不完整批、被掩码的监督位置和不同大小图都可能破坏这个条件。问题不是分布式计算特有的数值误差，而是精确算术下目标就已经变化。

<a id="deep-dive-2"></a>

<a id="effsys1-detail-7"></a>

### 2.2 从局部和推导全局梯度

设共有 $`D`$ 个设备，第 $`d`$ 个设备有效权重和为 $`N_d`$，局部均值为 $`L_d`$，总权重 $`N=\sum_dN_d`$。当通信平均设备梯度时，在本地对 $`\frac{D N_d L_d}{N}`$ 反向，归约结果是

$$
\frac1D\sum_d\nabla\left(\frac{D N_d}{N}L_d\right)=\nabla\frac{\sum_dN_dL_d}{N}.
$$

该等式要求权重是当前更新的数据常数；若权重本身由可训练网络决定且目标要求对它求导，不能随意停止相关导数。普通有效 token 数是非可训练计数，因此通常没有这个问题。全局分母应由所有参与设备的有效计数得到，不能依赖某一设备猜测其他设备长度。

两卡分别二个和六个有效 token，局部均值梯度分别一和三。正确梯度是二点五，等权卡平均给二。局部反向乘数分别为零点五和一点五，平均后才得到二点五。若某卡没有有效位置，可以计算连接计算图的零损失并参与一致的通信；不能让它随意跳过其他卡仍在执行的集体操作，否则这不是权重小，而可能是通信协议不一致。

<a id="effsys1-detail-8"></a>

### 2.3 微批累积的精确边界

同一参数版本下，梯度对样本损失的求和是线性的。因此把一个大批拆成多个微批，将各微批损失之和统一除以本次更新的有效总数，最后只执行一次优化器更新，在确定性逐样本模型中可恢复同一梯度。每个微批先取均值再除以微批数，只有有效数相同才正确。梯度缓冲在微批间保留，参数和优化器矩在此期间不应更新。

使用 Adam 时，每微批更新再把学习率缩小，不与累积后更新等价。平方矩和偏差修正依赖更新次数，梯度的非线性变换不能与平均交换。即使普通 SGD 没有动量，多次更新也会让后面的梯度在改变后的参数上计算。累积的数学理由是同一点的梯度线性，而不是任意优化器轨迹都可以重排。

随机层需要另外讨论。Dropout 在分块后可能消耗不同顺序的随机数；BatchNorm 以微批统计归一化，输出本身依赖分块；对比损失可能把批内其他样本当负例。它们使大批目标与微批目标不再逐项相同。固定随机种子并不能证明两种形状的随机调用产生相同掩码，也不能把批耦合结构变成逐样本函数。

<a id="effsys1-detail-9"></a>

### 2.4 归约精度与可复现性层次

浮点加法不满足结合律，树归约、环归约和不同微批顺序可能产生小差异。应先验证数学目标一致，再用说明过的容差比较浮点结果。逐位相同是比数学等价更强的要求，许多高效并行执行不承诺它；但明显的固定比例误差通常不应被归咎于浮点，而应先查分母、损失缩放和重复归约。

验收可分四层：同一输入下损失的含义一致；梯度张量接近；一次优化器更新与状态接近；多步独立评价没有不可解释的系统偏差。只比较最后一个训练损失，无法区分中间梯度错误和偶然拟合。后面的完整累积实验会比较每一步参数以及独立测试误差，而不只展示一个下降曲线。

## 3. 状态分片如何改变所有权

<a id="effsys1-detail-11"></a>

### 3.1 优化器状态分片与逐坐标更新

Adam 对每个参数坐标维护一阶矩和二阶矩。在全局梯度已正确归约、相同步数和超参数下，每个坐标的更新只需要该坐标的权重、梯度和历史矩。因此可以把坐标分给不同拥有者，分别更新后再让需要者获得更新结果。减少复制的原理是把原来每卡重复保存的状态变成唯一拥有，而不是改变了 Adam 的数学形式。

若梯度仍是各卡局部梯度，直接在不同拥有者上更新后平均权重，通常不等于用平均梯度更新一次 Adam。二阶矩中的平方使平均与更新不交换。共享全局梯度是分片等价的前提，而非可有可无的通信步骤。对跨参数耦合的优化器，还要检查范数、预条件矩阵和全局统计量是否需要额外归约，不能把逐坐标论证推广到所有优化器。

<a id="effsys1-detail-12"></a>

### 3.2 三个阶段的明确预算

采用前面的十六字节模型，并把四字节主权重与八字节两矩一起记为十二字节优化器相关状态。普通复制预算为 $`16P`$；只分片这十二字节状态时，每卡为 $`4P+\frac{12P}{D}`$；再分片两字节梯度时，为 $`2P+\frac{14P}{D}`$；最后计算参数也持久分片时，理想长期保留量为 $`\frac{16P}{D}`$。这些式子只讨论指定模型的持久状态。

十亿参数、八设备时，四个数依次是十六、五点五、三点七五和二 GB。若只把八字节矩分片而保留主权重复制，则得到九 GB，这是另一种配置，不能把它与前一种状态划分混为同一阶段的唯一数字。很多争论实际来自“优化器状态”是否包含主权重没有说清，而不是数学不一致。

全分片并不意味着计算每一层时只见到八分之一参数。常见执行会在需要某个单元时聚合它的完整参数，计算结束再释放或重新分片。于是必须加上当前单元、可能预取的下一个单元及通信缓冲的存活量。最大可聚合单元太大时，长期状态虽能放下，瞬时仍会越界。包装粒度因此是容量、通信次数与调度开销的共同选择。

![参数分片与完整聚合缓冲并存时的峰值](images/01-shard-peak.svg)

仅统计一个含四个 FP32 权重的计算单元：每个权重 $`4`$ 字节，总量 $`16`$ 字节，两台设备各持久拥有两个坐标，因此每卡分片为 $`8`$ 字节。图示协议在当前层计算前，另行分配 $`16`$ 字节的完整聚合缓冲，同时继续保留原来的本地分片；此时仅这两类参数缓冲就共占 $`24`$ 字节。完成当前层并释放完整缓冲后，再回到每卡 $`8`$ 字节。

这个账本依赖明确的存活关系：图中假设聚合缓冲与分片缓冲并存。若实现复用、释放或别名共享了缓冲，峰值需要按真实所有权重新计算。激活、梯度、优化器矩、通信工作区及下一单元预取均未计入，因此不能把任何一个图中数字当作完整训练显存预算。分片降低持久复制量，是否容得下瞬时计算仍要逐个检查聚合单元。


<a id="effsys1-detail-13"></a>

### 3.3 梯度回分与参数聚合的逻辑

参数全聚合让各设备获得相同计算权重；局部前向和反向使用不同数据；梯度 reduce-scatter 将求和或平均后的坐标片分给对应拥有者；拥有者更新状态。下一轮再次聚合得到新参数。每一步都需要清楚标明通信结果是和还是均值，否则再正确的坐标更新也会优化另一个尺度的目标。

共享参数和跨模块视图使工程实现更复杂。同一权重在两处使用，逻辑上仍只有一个优化对象，不能被当作两个互不相关坐标片分别更新。重新构造参数视图时也要让前向使用当前聚合版本，而非保存过期引用。学习系统的状态身份包括参数对象、存储和版本，单凭形状正确不足以证明更新使用了正确数据。

<a id="sec-3-1"></a>

<a id="effsys1-detail-14"></a>

### 3.4 环通信的字节与延迟模型

对 $`D`$ 设备、每设备需要归约的 $`N`$ 字节梯度，理想 ring reduce-scatter 有 $`D-1`$ 轮，每轮发送约 $`\frac{N}{D}`$；all-gather 再做同样轮数。每设备发送量主项为 $`\frac{2(D-1)N}{D}`$。这里是每设备发送字节口径；若把发送加接收或全系统总和统计进去，会多出因子，比较报告前必须统一口径。

粗略的延迟带宽模型写作 $`2(D-1)\alpha+\frac{2(D-1)N}{(D\beta)}`$，其中 $`\alpha`$ 是每轮启动延迟、$`\beta`$ 是理想有效带宽。小消息时第一项可能主导，合并梯度桶能减少启动；过大桶要等更多梯度就绪，又会推迟通信开始。最佳桶大小依赖计算图与拓扑，公式给的是分析框架，不是任何硬件上的精准预测器。

全分片还要计算前向和反向的参数聚合次数。如果每步两次参数聚合、一次梯度回分，通信量与普通数据并行并不相同；如果参数被保留、重新计算引发额外前向或存在混合分片，次数又会改变。应从实际状态机列出集体操作，而不能用一个“分片通信量”常数涵盖所有策略。

<a id="effsys1-detail-15"></a>

### 3.5 通信重叠的关键路径

假设一块计算需 $`c`$ 时间、下一块参数传输需 $`m`$。完全串行的局部时间是 $`c+m`$；若依赖允许、资源独立且启动及时，稳态可能接近 $`\max(c,m)`$。但首块没有前序计算可隐藏，尾部也有排空，且通信和计算可能竞争显存带宽，因此整步时间通常不能简单取所有计算与通信总和的最大值。

预取把下一单元参数提前搬入，缩短等待却增加同时存活量。于是容量约束和关键路径优化直接耦合：更深预取可能更快但超显存；限制在途聚合可能留下可见空隙，却避免分配失控。看到时间线上 CPU 暂停不能立刻判断低效，它可能是限流协议。要结合设备执行、分配峰值和真实等待原因解释。

## 4. 激活大小、注意力和存活调度

<a id="effsys1-detail-17"></a>

### 4.1 形状比层数更具体

全连接层输入形状 $`B\times T\times d`$，只保存一份相同精度输入就需要与 $`BTd`$ 成正比的字节。多层网络保存数量由自动微分实际需要决定，不能简单把所有前向输出都乘层数。某些算子反向只需输出，某些需要输入，融合算子可能采用另一种保存策略。应从具体计算图或保存张量钩子核对，而不是把理论张量全算成必然长期保留。

朴素注意力显式产生 $`B\times h\times T\times T`$ 分数或概率，序列长度翻倍可能使该部分增至四倍。采用不同注意力实现可能避免把完整矩阵写到高带宽存储，但运算含义、工作区和反向重计算策略需要分别说明。仅减少参数状态的复制，不能解决所有长序列激活问题；参数小而序列长的模型也能内存不足。

<a id="effsys1-detail-18"></a>

### 4.2 一段可手算的检查点调度

考虑 $`L`$ 层串行网络，每个边界激活大小近似 $`A`$。朴素保存量与 $`LA`$ 成正比。每 $`k`$ 层设一个检查点，持久边界约 $`\frac{L}{k}`$ 份，反向处理一个片段时临时保留约 $`k`$ 份，因此峰值近似 $`A(\frac{L}{k}+k)`$，外加参数、梯度和框架常数。对连续 $`k`$ 优化得 $`k\approx\sqrt L`$，相应激活项约 $`2A\sqrt L`$。

这个平方根推导假定层大小和计算代价相近、网络串行、重计算一个片段时只需该片段内部激活。真实 Transformer 各部分大小不同，跳连、共享分支和融合实现也会改变存活；不能把平方根式当通用性能保证。它的价值在于显示边界数与片段内部峰值之间的取舍，并给初始搜索点。

若有四十九层、每层边界十 MB，理想模型中不检查点约四百九十 MB；每七层设点时，两类激活加起来约一百四十 MB。这里忽略输入输出重复计数，属于数量级演示，不是精确分配器预测。若某一层本身有三百 MB 工作区，检查点再精细也无法消除这个单层峰值，必须优化算子、分块或改变负载。

<a id="effsys1-detail-19"></a>

### 4.3 存活量与重计算量的不同目标

检查点并不使前向结果永远消失，而是让它们在第一次前向后释放，反向需要时再生成。若被检查点部分原前向成本为 $`F_c`$，常见额外成本约再执行一次所需前向；但是否完整重做、能否早停和反向保存规则取决于实现。不能一概把整步时间乘二，也不能把检查点说成免费节省内存。

更合理的问题是在容量约束下最小化时间：哪些片段省下的字节最多、重算代价最小；哪些算子大而便宜，适合重算；哪些算子计算昂贵而输出小，适合保存。若内存节省允许更大微批或减少卸载，整步可能变快；若原来已经完全放得下，重算又不能改善其他瓶颈，则通常会增加计算工作。

### 图解推导：从一条 16 层链复算检查点的峰值与重算量

![从一条 16 层链复算检查点的峰值与重算量](images/01-checkpoint-memory-work.svg)

为了让账本可以手算，设链有 $`h_0,\ldots,h_{16}`$ 共十七个等大状态，每层前向只依赖前一状态，局部反向只需要该层输入、输出。图不计参数、梯度、优化器、通信及算子工作区。全部保存时，原前向求值十六次，状态峰值十七。

每四层保留一个边界时，长期保存 $`h_0,h_4,h_8,h_{12},h_{16}`$ 共五个。反向从最后一段开始，重建 $`h_{13},h_{14},h_{15}`$，结合已存边界执行局部反向；峰值为五个边界加三个内部状态，即八。完成该段后丢掉其输出边界和内部状态，下一段更不会超过这一峰值。

在这个允许复用已存段末输出的手写调度中，每段重算三次，四段共十二次，前向总求值变为二十八。一般分段长度 $`s`$ 整除十六时，边界数为 $`\frac{16}{s}+1`$，内部数为 $`s-1`$，故峰值为 $`\frac{16}{s}+s`$；重算为 $`16-\frac{16}{s}`$。右图只标合法离散选择，$`s=4`$ 的八个状态优于 $`s=2,8`$ 的十个；连续平方根推导只是选择附近整数的线索。

这不是 PyTorch 峰值或实际加速数据。若反向需要额外缓存、原位操作破坏状态、层大小不等，或框架必须重执行段末算子，内存和求值次数都要重新计算；重算还必须保持随机数、模块状态与精度相容。激活重计算的动机可结合 [ZeRO 原论文第 2.2.1、4.2.1 节](https://arxiv.org/html/1910.02054v3)阅读，本图进一步明确了一个可枚举的手写调度。

## 5. 重计算的正确性条件

<a id="effsys1-detail-21"></a>

### 5.1 同一个函数在同一个状态上重演

数学上设片段输出为 $`y=f_\theta(x)`$。反向要恢复相同点处的雅可比，重算时必须使用与原前向一致的输入、参数和影响计算的状态。若片段读取可变全局变量、更新计数器、修改缓存或依赖外部队列，第二次前向可能不是同一个函数。输出形状一致也无法排除这样的错误。

训练步骤中通常先完成反向再更新参数，因此普通顺序执行不会在重算前改变参数；但异步更新、手写流水线和不恰当的原地修改可能破坏这一点。应把重计算看作执行协议的一部分，而不只是给函数加一个包装器。具有副作用的模块要么让副作用幂等或显式隔离，要么不进入重算区域。

<a id="effsys1-detail-22"></a>

### 5.2 随机状态为什么属于计算状态

带 Dropout 的片段可写成 $`f_\theta(x;\xi)`$。若重算使用新掩码 $`\xi'`$，反向可能对应另一个随机实现，与原前向的损失并不匹配。某些检查点实现会保存并恢复随机数状态，使重演使用同一随机样本；关闭这种保护能减少管理成本，却会改变梯度语义，不能只检查前向损失相同就认定安全。

即便开启随机状态保护，也要核对所用设备类型、在片段内迁移设备和自定义随机源是否都在框架覆盖范围内。使用 NumPy 或自建生成器的随机调用，不应无证据假定跟随默认 Torch 状态一起被恢复。后面的实验使用 Torch CPU 默认随机源，明确限定它验证的范围，而不声称所有随机程序都已正确重演。

<a id="effsys1-detail-23"></a>

### 5.3 保存张量统计与真实峰值

自动微分保存张量钩子可以统计反向登记的张量总字节。这能说明重计算是否减少了需要长期保存的激活，但它不是进程内存、分配器保留量或 GPU 峰值。同一存储被多次保存会重复计数，钩子也可能看不到内核工作区。应把它命名为保存张量的登记字节，而不是测得的显存。

我们的实验用独立同构模型、同一输入与随机种子比较普通执行和非重入检查点，核对前向损失和全部参数梯度，同时报告登记字节。另一次关闭随机保护只用于制造机制反例。它不展示真实 GPU 内核、不验证跨设备随机源，也不据计数字节推断端到端加速倍数。

## 6. 优化器、裁剪和混合精度的次序

<a id="effsys1-detail-25"></a>

### 6.1 全局裁剪需要全局范数

对全局梯度 $`g`$，范数裁剪为 $`g\min(1,\frac{c}{\Vert g\Vert _2})`$。分片后每个设备只拥有部分坐标，可以先计算本地平方和，再归约为全局平方范数，所有片使用同一个缩放因子。如果各片分别以阈值 $`c`$ 裁剪，得到的总梯度通常不同，总范数还可能达到 $`\sqrt D c`$。坐标独立更新不意味着所有预处理也独立。

在数据并行复制梯度时，每卡持有相同全局梯度，重复求一次范数只增加计算，不需再把复制的平方和当独立片归约，否则会多出设备数因子。实现必须知道当前张量是复制还是唯一拥有。相同 API 名称在不同所有权布局下可能需要不同通信语义，不能靠变量名判断。

<a id="effsys1-detail-26"></a>

### 6.2 累积、缩放和裁剪的合理顺序

若采用固定损失放大 $`s`$，反向得到 $`s g`$；应在裁剪或基于真实梯度的诊断前恢复尺度，否则裁剪阈值的含义随 $`s`$ 改变。微批梯度应先按目标累积，再计算这次更新的全局范数；每微批单独裁剪后相加不等于对总梯度裁剪。是否存在溢出也必须按本次更新的一致协议决定，不能只有部分拥有者更新而其他部分跳过。

本章 CPU 主实验使用双精度，不模拟低精度溢出处理。混合精度的条件讨论旨在说明状态机还包含缩放器和跳步决策，不能把双精度验证当作其完整实测。若后续扩展到 GPU，应在原有梯度身份通过后加入缩放，再核对跳步时参数、优化器步数和学习率调度器是否保持一致。

<a id="effsys1-detail-27"></a>

### 6.3 权重衰减与没有梯度的参数

解耦权重衰减在优化器步中对权重施加缩放，与把二次惩罚加入 Adam 梯度不是一般等价。分片实现要沿用同一公式、学习率和步数。某些参数没有参与当前计算，梯度可能为无值，也可能是显式零；优化器对这两种状态的行为可能不同，影响动量延续和衰减。清梯度策略因此属于训练语义，而不只是内存技巧。

在完整恢复时还要保存参数组归属和每组超参数。只按形状把矩恢复到另一组参数，可能没有报错却使状态错配。检验恢复应至少比较下一次更新，而不止比较加载后的权重。模型能完成前向，只证明权重可读，不证明训练轨迹可续。

![局部裁剪与聚合后全局裁剪不交换](images/01-extension.svg)

两分片梯度分别为(3,0)与(0,4)，拼接全局范数为5。按阈值1全局裁剪得到(0.6,0.8)，而每片分别裁剪会得到(1,1)，全局范数为√2。通信与归约顺序因而属于正确性的一部分。

## 7. 并行方式如何组合而不混淆

<a id="effsys1-detail-29"></a>

### 7.1 数据、张量与流水线分工

数据并行在不同数据上复制计算任务，再合并梯度；状态分片改变这些复制任务的持久状态所有权；张量并行把一次层计算沿张量维度拆开；流水线并行把不同层放在不同阶段。它们解决的瓶颈不同，通信发生的位置也不同。多种方案可以组合，但设备数不能被无条件重复用来除每一种内存。

例如把十六设备分成四个张量并行组，每组四设备，再在四组之间数据并行，则某层权重的切片可能在四个数据副本间复制。若又对数据组做状态分片，需要明确在哪一个通信域分。有效全局样本数通常由数据并行副本数贡献，不能把张量并行设备也当成独立样本副本再次相乘。

<a id="effsys1-detail-30"></a>

### 7.2 流水线气泡的简化推导

假设有 $`p`$ 个平衡阶段、$`m`$ 个等大微批，单阶段每个微批前向时间为 $`t`$。只看理想前向流水线，完成时间为 $`(m+p-1)t`$，工作总量为 $`mpt`$，利用率为 $`\frac{m}{(m+p-1)}`$。这是填充和排空造成的气泡，不包含反向、不同阶段时长或通信，因此不能直接当完整训练利用率公式。

增加微批数能摊薄气泡，却可能增加保存激活和调度开销。若最慢阶段时间是其他阶段两倍，吞吐受它限制，增加微批不能消除负载不平衡。实际训练还要选择前后向调度、权重版本和激活重算，数学梯度是否仍对应同一参数版本需要单独证明。把“流水线更忙”当作“同一目标更快收敛”是不充分的。

<a id="effsys1-detail-31"></a>

### 7.3 通信拓扑与故障范围

节点内高速互连与节点间链路的带宽延迟不同，层内频繁小通信通常更依赖低延迟。选择并行布局要考虑哪种通信落在哪一级拓扑，而不是只看总设备数。分片组过大可能减少状态，却使参数聚合跨慢链路；混合分片可以改变取舍，但会保留部分复制状态。

故障恢复也有拓扑含义。一个拥有者保存唯一状态片时，丢失该片不能只从其他复制权重恢复全部矩。检查点要说明是模型导出、训练续跑还是容灾快照；三者需要的信息不同。重分片恢复还涉及参数身份、随机状态与数据游标，不只是把文件均匀分给新设备。

<a id="effsys1-detail-32"></a>

## 8. 卸载与带宽预算

<a id="effsys1-detail-33"></a>

### 8.1 容量换成传输不是消除成本

把状态移到 CPU 或其他存储能扩大容量，但每次使用时需要传输。设每步必须搬运 $`V`$ 字节、有效带宽 $`\beta`$，单就这些字节的传输时间下界为 $`\frac{V}{\beta}`$；若多个传输可重叠，也仍受共享链路总容量限制。低估传输量会把能跑误判成高效，尤其当计算块太小、没有足够时间隐藏传输。

主机内存还需承担固定页缓冲、数据加载和其他进程，不能视为无限免费。若卸载对象超过内存而触发系统换页，实际行为可能远离设计模型。更远层存储带来额外延迟、队列深度和可靠性问题。容量层级应按真实访问频率分配，高频状态与冷检查点不能用同一吞吐假设。

<a id="effsys1-detail-34"></a>

### 8.2 一个可否隐藏传输的手算

假设下一片状态两 GB，有效链路二十 GB 每秒，理想传输需零点一秒。当前计算只有零点零四秒，即使完美预取也至少留下约零点零六秒等待；若当前计算零点一五秒，则有可能完全隐藏该片传输，但仍需两片同时存活的容量。这是局部必要条件，不保证整步所有传输都能隐藏。

如果多片共用链路，不能各自都以峰值带宽计算并声称重叠后免费。应列出每条边的流量、依赖、最早启动与可用时间窗。数据加载也可能与状态卸载争夺同一主机链路；改变其中一个参数后，需要重测整个系统，而不能把孤立微基准带宽直接贴到训练时间上。

<a id="effsys1-detail-35"></a>

## 9. 正确性与性能的实验协议

<a id="effsys1-detail-36"></a>

### 9.1 从一次更新到完整学习

先建立小确定性参照：相同初始化、同一有效样本目标、同一参数版本和优化器配置；比较前向值、梯度、更新后权重及状态。通过后再增加随机层、累积、检查点、分片和低精度，每次只增加一个机制。否则多个误差抵消时，最后训练损失可能看起来正常，而无法定位真正的语义偏差。

一次更新一致不能保证数据加载、检查点和调度器长期都正确，因此还要做多步训练及恢复后的下一步比较。完整小任务应提供固定训练、开发与测试协议，不根据最终测试表现挑选系统设置。本章的人工回归实验采用固定预算，不通过测试调整迭代次数；它验证更新等价，不代表大型模型上的泛化结论。

<a id="effsys1-detail-37"></a>

### 9.2 强扩展和弱扩展回答不同问题

强扩展固定全局工作量，增加设备看时间能缩短多少，效率为 $`E_D=\frac{T_1}{(D T_D)}`$，其中 $`T_1`$ 与 $`T_D`$ 分别表示单设备和 D 设备完成同一工作量的时间。弱扩展保持每设备工作量近似固定，全局批或数据量随设备增加，测的是扩大问题后的吞吐和效率。若弱扩展同时增大全局批，训练优化轨迹也会变化，达到固定质量所需步数不能从每步速度推出。

应该同时报告每步时间、有效 token 吞吐、达到目标质量的总时间、峰值内存和失败率。填充 token 不等于有效监督 token，丢弃长样本也可能让吞吐数字变好却改变任务。不同方案需要相同信息与选择预算，才能把差异解释为系统机制，而不是负载被悄悄简化。

<a id="effsys1-detail-38"></a>

### 9.3 测量本身会改变执行

GPU 异步执行下，宿主调用返回不表示设备完成，测量要选择合适事件或在明确边界同步；但每层强制同步会破坏原本重叠。应把微基准与端到端测量分开，用代表性预热、多个重复和稳定负载报告分布。分配器已分配量与已保留量也要分别说明，二者差额不一定是泄漏。

本地没有实跑多卡，因此本章不提供虚构的通信加速曲线或 GPU 峰值。可执行实验只报告真实完成的 CPU 数值核对与明确参数化的模拟预算。研究扩展部分给出怎样在具备设备时复现的步骤；未执行的步骤保留为任务，不把计划写成结果。

<a id="effsys1-detail-39"></a>

## 10. 实验一：状态与峰值的独立预算

以下代码只做整数账本和存活事件模拟，所有数值由显式假设产生。它分别核对主权重归属的两种阶段一预算、环归约发送量，以及预取导致的同时存活增大。没有分配十亿参数模型，也没有访问 GPU。

```python
from collections import defaultdict
P,D=10**9,8
states={'replicated':16*P,'stage1':4*P+12*P//D,
        'stage2':2*P+14*P//D,'stage3':16*P//D,
        'moments_only':8*P+8*P//D}
assert states=={'replicated':16000000000,'stage1':5500000000,
               'stage2':3750000000,'stage3':2000000000,'moments_only':9000000000}
def peak(intervals):
    events=defaultdict(int)
    for start,end,size in intervals:
        assert start<end
        events[start]+=size;events[end]-=size
    live=best=0
    for time in sorted(events):
        live+=events[time];best=max(best,live)
    return best
# 半开时间区间，相同时刻释放与获得按净变化处理。
base=[(0,10,2_000_000_000),(1,7,3_000_000_000),
      (3,5,1_200_000_000)]
assert peak(base)==6_200_000_000
assert peak(base+[(4,6,1_200_000_000)])==7_400_000_000
N=2*P
send=2*(D-1)*N/D
assert send==3_500_000_000
print('decimal GB', {k:v/1e9 for k,v in states.items()})
print('peak/prefetch GB',peak(base)/1e9,peak(base+[(4,6,1_200_000_000)])/1e9)
print('ring bytes sent per device',send)
```

基准预算六点二 GB 加一份重叠预取后变七点四，说明相同持久分片也能产生不同峰值。事件模拟使用理想紧凑存储与半开区间，没有表示碎片、网络内部缓冲或自动微分延迟释放。读者可把测得的对象生命周期代入，但不能把模拟输出当作硬件测量。

<a id="effsys1-detail-40"></a>

## 11. 实验二：不等长有效位置的完整训练

这里构造人工逐 token 回归任务，填充位置由掩码排除。大批参照和微批累积使用完全同构的无随机、无批耦合模型，优化器只在所有微批完成后更新一次。每轮比较实际参数，最后用独立测试集评价。这验证整个固定预算训练，而不是只验证一次求和。

```python
import copy
import torch
from torch import nn
torch.set_num_threads(1);torch.set_default_dtype(torch.float64)
torch.manual_seed(631)
N,T,F=30,7,3
x=torch.randn(N,T,F);length=torch.arange(N)%T+1
mask=torch.arange(T)[None,:]<length[:,None]
y=1.4*x[:,:,0]-.7*x[:,:,1]+.3*x[:,:,2]+.05*torch.randn(N,T)
model=nn.Linear(F,1);accum=copy.deepcopy(model);wrong=copy.deepcopy(model)
opts=[torch.optim.Adam(m.parameters(),lr=.04) for m in [model,accum,wrong]]
parts=[torch.arange(0,3),torch.arange(3,11),torch.arange(11,N)]
counts=[int(mask[ix].sum()) for ix in parts];total=int(mask.sum())
for step in range(120):
    opts[0].zero_grad(set_to_none=True)
    e=(model(x).squeeze(-1)-y).square()
    (e[mask].sum()/total).backward();opts[0].step()
    opts[1].zero_grad(set_to_none=True)
    opts[2].zero_grad(set_to_none=True)
    for ix in parts:
        e=(accum(x[ix]).squeeze(-1)-y[ix]).square()
        (e[mask[ix]].sum()/total).backward()
        e_bad=(wrong(x[ix]).squeeze(-1)-y[ix]).square()
        (e_bad[mask[ix]].mean()/len(parts)).backward()
    opts[1].step();opts[2].step()
    for a,b in zip(model.parameters(),accum.parameters()):
        assert torch.allclose(a,b,atol=2e-13,rtol=2e-13)
g=torch.Generator().manual_seed(632)
xt=torch.randn(1000,F,generator=g)
yt=1.4*xt[:,0]-.7*xt[:,1]+.3*xt[:,2]
with torch.no_grad():
    mse=[float((m(xt).squeeze()-yt).square().mean()) for m in [model,accum,wrong]]
assert abs(mse[0]-mse[1])<1e-13 and mse[0]<.002
assert any(not torch.allclose(a,b,atol=1e-6) for a,b in zip(model.parameters(),wrong.parameters()))
print('effective counts',counts,'total',total)
print('independent noiseless-target test MSE: full/accum/wrong',mse)
print('fixed budget 120 updates; no test-based model selection')
```

错误版本仍可能学得很好，因为它优化的是另一种加权经验目标，而不是随机噪声程序。不能以两者最终误差都小来消除目标差异；也不能预先要求错误目标在每一个测试集都更差。这里断言的是逐步等价与参数差异，独立误差只用来说明这确实是一个完成训练的可运行例子。

## 12. 实验三：检查点、随机重演与保存量

```python
import copy
import torch
from torch import nn
from torch.utils.checkpoint import checkpoint
torch.set_num_threads(1);torch.set_default_dtype(torch.float64)
torch.manual_seed(641)
base=nn.Sequential(nn.Linear(16,64),nn.Tanh(),nn.Dropout(.4),
                   nn.Linear(64,64),nn.Tanh(),nn.Linear(64,8))
x=torch.randn(32,16)
def run(use_checkpoint,preserve=True):
    model=copy.deepcopy(base);record=[]
    def pack(t):record.append(t.numel()*t.element_size());return t
    def unpack(t):return t
    torch.manual_seed(642)
    with torch.autograd.graph.saved_tensors_hooks(pack,unpack):
        out=checkpoint(model,x,use_reentrant=False,preserve_rng_state=preserve) if use_checkpoint else model(x)
        loss=out.square().mean()
    # 只统计初次前向登记量，反向重算不再纳入该记录口径。
    saved=sum(record)
    loss.backward()
    gradients=torch.cat([p.grad.reshape(-1) for p in model.parameters()])
    return float(loss.detach()),gradients,saved
ordinary=run(False);safe=run(True,True);unsafe=run(True,False)
assert abs(ordinary[0]-safe[0])<1e-15 and abs(ordinary[0]-unsafe[0])<1e-15
assert torch.allclose(ordinary[1],safe[1],atol=1e-13,rtol=1e-13)
assert not torch.allclose(ordinary[1],unsafe[1],atol=1e-8,rtol=1e-8)
assert safe[2]<ordinary[2]
print('losses',ordinary[0],safe[0],unsafe[0])
print('saved-tensor registration bytes',ordinary[2],safe[2])
print('max gradient difference safe/unsafe',
      float((ordinary[1]-safe[1]).abs().max()),float((ordinary[1]-unsafe[1]).abs().max()))
```

普通和安全重算的全部梯度一致；关闭随机状态保护后，初次前向仍相同，梯度却不同。这正是只比较 loss 无法检出的故障。登记字节下降只说明该检查点安排减少了首次前向保存的自动微分张量，不能据此声称进程总内存同比降低，更不能把 CPU 数字写成 GPU 峰值。

## 13. 实验四：完整 Adam 状态分片与裁剪反例

```python
import numpy as np
rng=np.random.default_rng(651)
w=rng.normal(size=12);full=w.copy();pieces=[a.copy() for a in np.split(w,3)]
m=np.zeros_like(w);v=np.zeros_like(w)
ms=[np.zeros_like(a) for a in pieces];vs=[np.zeros_like(a) for a in pieces]
b1,b2,lr,eps=.9,.99,.01,1e-8
for t in range(1,41):
    # 每一轮先得到全局平均梯度，再交给坐标拥有者。
    local=rng.normal(size=(3,12));g=local.mean(0)
    m=b1*m+(1-b1)*g;v=b2*v+(1-b2)*g*g
    full-=lr*(m/(1-b1**t))/(np.sqrt(v/(1-b2**t))+eps)
    for k,gk in enumerate(np.split(g,3)):
        ms[k]=b1*ms[k]+(1-b1)*gk
        vs[k]=b2*vs[k]+(1-b2)*gk*gk
        pieces[k]-=lr*(ms[k]/(1-b1**t))/(np.sqrt(vs[k]/(1-b2**t))+eps)
    assert np.allclose(full,np.concatenate(pieces),atol=2e-15,rtol=2e-15)
    assert np.allclose(m,np.concatenate(ms)) and np.allclose(v,np.concatenate(vs))
g=np.array([3.,4.]);threshold=1.
correct=g*min(1.,threshold/np.linalg.norm(g))
separate=np.clip(g,-threshold,threshold)
assert np.allclose(correct,[.6,.8]) and np.linalg.norm(separate)>threshold
local=np.array([1.,3.])
mean_then=local.mean()/(abs(local.mean())+eps)
step_then=np.mean(local/(np.abs(local)+eps))
# 同号时差异很小，用相反号清楚展示Adam非线性。
local=np.array([1.,-3.])
mean_then=local.mean()/(abs(local.mean())+eps)
step_then=np.mean(local/(np.abs(local)+eps))
assert abs(mean_then-step_then)>.9
print('40-step full/sharded Adam max difference',np.max(np.abs(full-np.concatenate(pieces))))
print('global/separate clip',correct,separate)
print('Adam first-step mean-then-update/update-then-mean',mean_then,step_then)
```

四十次更新的每个矩和权重都一致，支持的是给定逐坐标公式与全局梯度下的所有权重排等价。代码没有启动分布式进程或模拟丢包，也没有验证某个框架的分片实现。裁剪反例与相反号局部梯度说明：需要全局统计的操作和非线性更新不能随意移到归约之前。

## 14. 进阶练习与详细解析

<a id="effsys1-detail-44"></a>

### 14.1 题一：十六字节为什么不是常数

题目：模型计算权重两字节、梯度四字节、主权重四字节、Adam 两矩共八字节，每参数多少持久字节？解析：相加得十八，十亿参数是十八十进制 GB。若有人仍以十六预算，少算了两 GB 梯度。再问框架是否另有临时更新副本，不能把十八当峰值上界。答案的关键是逐对象确认，而不是背诵参数量倍数。

<a id="effsys1-detail-45"></a>

### 14.2 题二：阶段一的两个数字谁正确

题目：八卡十亿参数，有人算阶段一五点五 GB，有人算九 GB，是否必有一个算错？解析：如果前者把十二字节主权重与矩都分片，预算是四加十二除八；后者只分片八字节两矩，预算是八加八除八。两种指定方案均可算对，术语若不说明所有权便没有唯一数字。实际采用哪种必须检查实现。

<a id="effsys1-detail-46"></a>

### 14.3 题三：有效token的归约

题目：三卡有效数一、二、七，局部均值梯度二、四、八，求全局 token 均值梯度与本地缩放。解析：加权和为二加八加五十六，总计六十六，除十得六点六。通信若平均三卡，本地损失分别乘零点三、零点六、二点一。直接平均局部梯度得十四除三，已经改变目标。

<a id="effsys1-detail-47"></a>

### 14.4 题四：最后一个微批的影响

题目：微批九个和一个样本，两个局部均值梯度为零和十，均值再平均得到什么？解析：得到五，而全局样本均值为一。较小微批被放大五倍权重。应累计局部和并统一除十，或对局部均值乘十分之九和十分之一。问题在精确算术下已存在，与设备和随机误差无关。

<a id="effsys1-detail-48"></a>

### 14.5 题五：为什么先裁剪微批不等价

题目：标量微批梯度三和负二，阈值一，比较先加后裁与先裁后加。解析：前者总梯度一，裁后仍一；后者一加负一得零。若目标梯度应是均值，还需一致放入分母，但不交换的现象保留。裁剪是非线性算子，不可由梯度求和的线性性质推出交换合法。

<a id="effsys1-detail-49"></a>

### 14.6 题六：复制范数与分片范数

题目：两卡各有同一个梯度向量三、四，平方和是否要两卡再求和？解析：复制布局下每卡已能得到全局范数五，再求和会得到平方范数五十，错误缩小梯度。若卡一只拥有三、卡二只拥有四，则必须求和九与十六得到二十五。通信逻辑取决于唯一拥有的坐标集合。

<a id="effsys1-detail-50"></a>

### 14.7 题七：峰值的两个上界

题目：对象甲最大三 GB、乙最大四 GB，能否确定峰值七 GB？解析：只能得总峰值不超过七，前提没有遗漏对象。若二者峰值不同时出现，总峰值可以更小；若二者部分重叠，应求具体时间的和。应列存活区间，不能从两个历史最大唯一恢复同时峰值。

<a id="effsys1-detail-51"></a>

### 14.8 题八：预取为什么能更慢

题目：预取消除了可见等待，端到端反而变慢，有什么合理原因？解析：预取可能增加内存峰值导致分配回收、与计算竞争带宽，或者引发更频繁重计算。只看等待区间缩短不能保证总时间缩短。应固定负载，记录通信重叠、峰值和计算时长，才能区分资源争用与调度收益。

<a id="effsys1-detail-52"></a>

### 14.9 题九：平方根检查点的条件

题目：最优间隔约为层数平方根，是否适合有一个超大层的网络？解析：不一定。推导把每层边界大小和片段内部峰值视作均匀；超大层会使均匀切分失效。应按每个边界字节和重算代价重新求调度，且单层工作区仍是容量下界。公式是简化模型解，不是所有网络的结构定理。

<a id="effsys1-detail-53"></a>

### 14.10 题十：重计算与随机源

题目：Torch 随机状态恢复后，片段还调用 NumPy 生成噪声，能否断言梯度等价？解析：不能。恢复一个生成器不自动恢复另一个。需显式保存所有相关随机状态，或把噪声作为固定输入传入；同时验证所用设备与执行路径。只固定进程启动种子，不保证原前向与重算之间没有其他随机调用。

<a id="effsys1-detail-54"></a>

### 14.11 题十一：冻结层为何仍需反向

题目：可训练映射之后接冻结非线性网络，是否能把冻结网络放进无梯度上下文？解析：若训练目标要更新前面的映射，必须通过冻结网络对输入求导。冻结参数仅取消这些参数的梯度需求，不取消输入雅可比。无梯度上下文会切断传回映射的路径，从而改变学习问题。可以避免优化器状态，却不能直接去掉所需激活。

<a id="effsys1-detail-55"></a>

### 14.12 题十二：保存字节下降意味着什么

题目：钩子登记字节降八成，能否说显存降八成？解析：不能。登记量可能重复别名，不包含所有工作区和分配器缓存，也没有直接处理对象同时存活。应把它当作反向保存机制的证据，再用目标设备峰值测量判断真实节省。单位都是字节，不意味着统计对象相同。

<a id="effsys1-detail-56"></a>

### 14.13 题十三：多卡为何放不下

题目：单卡模型状态十六 GB，四卡普通数据并行是否变成每卡四 GB？解析：普通复制数据并行每卡仍十六 GB，只有每卡数据激活可能因微批变小而减少。若模型状态本身超容量，需要改变所有权或层计算分工。设备数并不自动进入每项内存的分母。

<a id="effsys1-detail-57"></a>

### 14.14 题十四：模型恢复和训练恢复

题目：加载权重后预测一致，是否足以证明可续训？解析：不足。Adam 矩、步数、学习率调度、随机状态、数据位置和参数组均可能缺失。应在参照训练保存后比较恢复过程的下一次更新及状态，而不只比较前向输出。若只交付推理导出，则应明确目标较窄，不要求恢复优化器。

<a id="effsys1-detail-58"></a>

### 14.15 题十五：强扩展的负收益

题目：固定总批，设备数翻倍而每卡计算减半，时间为何可能增加？解析：通信启动、同步与调度开销没有相应减半，计算块变小后隐藏通信的窗口也缩短。公式中的带宽项之外还有延迟项，不能只看理论总算力。报告端到端时间和效率即可，不应删除变慢的结果。

<a id="effsys1-detail-59"></a>

### 14.16 题十六：怎样验收一个新系统优化

题目：提出将优化器状态卸载并增加检查点的组合，怎样证明有用？解析：先验证同一目标的一次与多步更新、保存恢复；再固定全局有效批、数据和训练预算，测峰值与每步时间。分开比较只卸载、只检查点、组合与基线，记录新增传输和重算。最终看相同质量达到时间及容量收益，不以一个更低的内存数字替代全部结论。

<a id="effsys1-detail-60"></a>

## 15. 研究扩展与方法选择

<a id="effsys1-detail-61"></a>

### 15.1 从主导项选择第一步

若状态复制占主要容量，优先研究状态分片；若长序列激活主导，优先检查形状、注意力实现和重计算；若单层聚合巨大，调整包装单元或层内分工；若链路等待主导，重新研究分组拓扑与预取。这里不是固定排行榜，而是把可观测瓶颈映射到改变该项的机制。针对错误对象优化，容易得到复杂度增加而容量没有明显改善。

选择还受设备和训练目标限制。某方法省内存却增加到目标质量的总时间，可能仍是唯一能运行大模型的方案；另一方法只在足够快互连上受益，也应如实限制适用范围。好的研究报告把容量可行性、数学正确性和效率分别测量，最后再说明共同取舍，避免把其中一项成功当作另外两项证明。

<a id="effsys1-detail-62"></a>

### 15.2 一份可复核的实验记录

记录参数总量和可训练量、各类状态精度、有效批与有效 token 分母、累积步数、数据并行与其他并行组、分片粒度、预取深度、重算区域、卸载对象、梯度裁剪与随机协议。性能记录要有设备、互连、软件版本、预热与同步边界、重复次数和失败情况。缺少这些条件，显存与时间数字很难用于解释机制。

若研究只能使用单机 CPU，可像本章一样完成代数、存活模拟、梯度等价与完整小训练；尚未验证的分布式通信、真实峰值和吞吐明确留待目标环境。这样得到的结果仍有学习价值，因为它排除了许多基础错误；但研究结论应与实际执行证据同宽，不能把合理设计等同于已经交付的大规模系统。


<a id="effsys1-detail-63"></a>

## 16. 把局部等价提升为可检验的研究结论

<a id="effsys1-detail-64"></a>

### 16.1 用误差分解避免错误归因

设原始训练目标的全精度大批梯度为 $`g`$，实现实际使用的梯度为 $`\hat g`$。可插入若干中间参照，把误差拆成目标归约差、随机实现差、浮点归约差和近似通信差。三角不等式可以给总误差不超过各项误差范数之和，但这只是上界，不意味着每一项都能从最后一个差值识别。若不同错误方向相反，总差可能很小，因此实验要逐项固定后再比较。

例如先在双精度无随机网络上核对有效数分母，再加入同掩码随机层，再改变精度，最后引入压缩通信。每一步保存梯度与一次更新差异，能知道误差在哪一层首次出现。若从一开始就同时更改数据批次、损失缩放、精度与优化器，最终曲线即使改善，也无法把收益归属于某一个系统设计。这是研究因果解释的基本要求，不只是调试技巧。

近似通信还需要区分无偏梯度压缩与训练更新无偏。即使条件于当前梯度有 $`E[C(g)]=g`$，Adam 对压缩梯度的平方和归一化仍是非线性，因此不能推出期望更新等于原更新。误差反馈改变状态机，新增残差必须保存和恢复。声称保持优化行为时，应指出保持的是哪个期望、哪个条件分布以及什么时间尺度，而不能只引用压缩算子的一个局部性质。

<a id="effsys1-detail-65"></a>

### 16.2 层级内存约束与策略选择

把设备内存容量记为 $`M_{\max}`$，一种策略的峰值模型为 $`M(s)`$、时间模型为 $`T(s)`$。容量不足时，优化问题首先是找满足 $`M(s)\le M_{\max}`$ 的可行策略，再在可行集合内比较时间或成本。若没有策略可行，报告相对节省比例并不能交付训练；需要改变模型分工、负载或硬件。若多种策略均可行，则无需为了最低内存不惜增加任意时间。

可以将检查点、预取和分片粒度视作离散变量，枚举一组小候选，先用预算排除明显不可行组合，再在目标设备测代表负载。预算误差应留安全余量，因为长样本、优化器首次建状态和偶发工作区可能高于稳定期。安全余量不是固定百分比定律，应来自负载分布与实际波动；把一次低峰值运行当作容量认证，会漏掉这些阶段差异。

首次优化器更新往往才创建历史矩，所以只测第一个前向或第一个反向会低估稳态持久内存。某些编译与内核选择又使首步工作区高于后续。应分别记录初始化、首次完整更新、预热后稳态和保存恢复的峰值。真正部署训练要求所有必经阶段可行，而不只要求最快的稳定片段可行。

<a id="effsys1-detail-66"></a>

### 16.3 微批大小与累积步数的联合选择

固定全局有效工作量时，增大微批常使矩阵乘法更饱满，并减少重复调度；但激活峰值增加，可能迫使使用更多重算或更深卸载。减小微批增加累积步数，能降低单次激活，却不减少权重和优化器状态，也可能使通信与计算都过于碎片。最优选择来自这几种成本的交点，不能单凭“更大批更快”或“更小批更省”决策。

对变长序列，按序列数固定微批并不固定有效 token 数。长度分桶能减少填充，但改变样本排列及局部相关性；若为了省内存直接截断长样本，又改变了训练信息。系统报告应同时给有效 token 和填充 token，明确是否保留全部样本与监督位置。若新增动态批处理，以固定总有效权重归约，才能把算法变化控制在可解释范围内。

<a id="effsys1-detail-67"></a>

### 16.4 检查点恢复的状态映射

分片状态可看作从逻辑参数身份到若干坐标区间及其历史变量的映射。恢复到不同设备数时，要重建每个逻辑坐标的权重和矩，再按新布局分配，而不是按旧文件编号一一对应新卡。映射还要处理参数组、共享参数、填充区间和扁平化顺序。两个布局拥有相同总元素数，不代表坐标语义一致。

可设计一个不依赖多卡的恢复测试：把完整状态按不等长片切开，在内存中重排成另一组片，再拼回并比较下一次更新。若只比较拼回权重而没有矩和步数，可能错过训练状态丢失。本章第四实验已核对坐标所有权重排的更新身份，但没有实现通用检查点格式；该恢复测试是进一步任务，不能误称已有文件可以跨任意框架迁移。

<a id="effsys1-detail-68"></a>

## 17. 实跑结果与进一步练习

<a id="effsys1-detail-69"></a>

### 17.1 本地四项实验观察

状态账本实验得到复制十六、完整优化器状态分片五点五、再分梯度三点七五、全分片长期二 GB；仅两矩分片得到九 GB。两种阶段一数字对应的对象分解已明确。存活模型的六点二 GB 在增加重叠预取后成为七点四 GB，这些全部是指定字节和区间的计算结果，没有真实分配对应大模型。

不等长回归实验的三个微批有效数为六、三十二、七十七，总数一百一十五。固定一百二十次 Adam 更新后，大批与正确累积在每一步容差内相同，独立无噪声目标测试 MSE 都约为一点三三乘十的负五次方；错误等权微批约为八点五五乘十的负五次方。一次任务中的大小关系不是一般性能定律，确定成立的是两种归约优化了不同经验目标。

检查点实验首次前向登记字节从一二四九二八降至六一四四，安全重演最大梯度差为零；关闭随机保护后最大差约零点零零八七九，而三个前向损失完全相同。完整 Adam 所有权实验四十步参数差为零。不同 Torch 版本可能改变保存张量的实现数量，因此复现时优先核对身份断言与口径，再比较具体计数字节。

<a id="effsys1-detail-70"></a>

### 17.2 题十七：通信无偏是否更新无偏

题目：通信压缩器条件无偏，是否能直接说 Adam 更新无偏？解析：不能。平方矩、开平方和除法使更新成为压缩随机量的非线性函数，期望不能穿过这些运算。可构造相反号或不同幅值的两点压缩分布检查第一步方向。若要建立算法保证，需要控制压缩噪声与优化器状态演化，而不是只证明压缩器均值。

<a id="effsys1-detail-71"></a>

### 17.3 题十八：首次更新为什么应单独测

题目：只跑前向反向发现内存足够，执行 Adam 后失败，是否说明梯度有异常？解析：未必。优化器可能在首次更新时才创建一阶矩与二阶矩，新增持久对象使峰值越界；更新临时量也可能贡献。应按阶段记录分配和状态创建，而不是从失败时刻推断数学梯度错误。账本必须包括完整必经步骤。

<a id="effsys1-detail-72"></a>

### 17.4 题十九：从数据副本数计算全局批

题目：八设备分成两个四路张量并行组，每组每微批三条序列，累积五次，独立序列数多少？解析：若两组数据不同、组内设备共同计算同一序列，则为二乘三乘五等于三十，而不是一百二十。有效 token 还要按每条真实长度计数。并行设备数与独立数据副本数是不同量。

<a id="effsys1-detail-73"></a>

### 17.5 题二十：怎样解释未达八倍的节省

题目：八设备全分片持久状态接近八分之一，实测峰值只降两倍，如何建立可证伪解释？解析：先列未分片的激活、最大聚合单元、同时预取量和更新工作区，预测改变某一项后峰值应怎样变化。固定其他条件分别调整序列长度、包装粒度和预取深度，检查预测。若所有变化都不能解释差额，再调查别名、缓存与实现错误；不能仅凭不达八倍断言成功或失败。
