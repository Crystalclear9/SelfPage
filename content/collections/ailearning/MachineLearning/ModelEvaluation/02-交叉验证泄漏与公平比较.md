## 1. 划分是在模拟哪一次未来使用

任何验证协议都在回答一个条件化的问题：在某种历史数据、可见信息和训练规则下，系统遇到某种新对象时会怎样。随机留下百分之二十并不能自动让这个问题合理。行之间是否独立、实体是否重复、目标何时成熟、未来环境是否变化，都决定这百分之二十究竟代表什么。评价设计应先写部署情景，再选择工具。

假设每个用户有一百次行为。如果未来主要预测同一批已知用户的下一次行为，那么按用户完全隔离会评价一个更困难但不同的“新用户”问题；若产品将服务从未出现的新用户，随机拆行为行又会让身份和历史特征帮助记忆已见用户。两种划分各有用途，不能因为其中一种分数高就声称它更正确。正确性取决于它与预先描述的部署对象是否对应。

<a id="eval-2-detail-2"></a>

### 1.1 三种常见部署单位

第一种是新的独立对象，例如来自同一来源的一批新样本，没有共享用户、时间序列或近重复簇。随机划分或普通交叉验证在这个假设下有直接解释。第二种是新实体，包括新患者、新门店、新设备，这时同一实体的所有相关记录通常需要放在同侧。第三种是未来时间，需要训练信息早于预测信息，并尊重标签与特征的实际可得时间。

真实项目经常同时具有后两种结构。比如医院系统既希望预测现有医院下个月的患者，也希望推广到一家从未参与训练的新医院。单一分数无法替代这两个问题，可以设置时间外评价和机构外评价，分别报告。若希望推广到新医院的未来患者，则评价需要同时留出机构与时间，且注意留出之后训练数据是否仍覆盖主要标签。

还要区分记录单位与独立推断单位。一个患者有多次检测，一段视频有很多帧，一个设备一天产生大量读数，这些行通常不是新的独立重复。训练可以利用多行信息，指标也可以按服务请求计算，但不确定性重采样时需要保留相关结构。把一千个视频帧当成一千段独立视频，会制造过窄区间和过度自信的结论。

<a id="eval-2-detail-3"></a>

### 1.2 标签窗口决定合法训练边界

假设在时间 $t$ 预测未来七天是否发生事件，标签的观察区间为之后七天。若在某个重训日使用最近一天的这些样本，其标签尚未成熟；即便数据库事后能查到结果，历史重放时也不能使用。训练资格应检查标签成熟时间不晚于当时训练时间，而不只检查样本的事件时间早于训练时间。

特征也有事件时间和可用时间之分。昨天发生、明天补录的交易，在今天预测时不可用；三个月后修订过的历史特征版本，也不能直接拿最终版本回填到过去评价。合法时间重放需要保留当时可得版本，或者明确说明只能评价修订后离线情景。模型训练代码没有直接读取未来标签，并不保证整个特征链路没有未来信息。

窗口重叠还会使训练标签与测试标签共享结果。是否需要清除、留间隔或按实体隔离，取决于部署过程与被估计对象。不能机械地认为间隔一天就防住全部泄漏，也不能把任意相关性都称作非法；例如线上确实能使用某实体的成熟历史标签时，这种历史依赖可能是合法信息。需要逐条画出预测时点、特征截止、标签区间和拟合时点。

<a id="eval-2-detail-4"></a>

### 1.3 分层、分组与时间顺序的作用边界

分层划分保持标签比例相对接近，可以避免小类在某个折完全缺失，改善工程可运行性。它并不让相关记录独立，也不保证未来基率相同。分层可能让各折看起来比自然抽样更均匀，折间离散程度就更不能随意解释为总体不确定性。若组与类别分布冲突，分层和组隔离未必能同时精确满足，应说明折的实际组成。

分组划分要求训练与测试的组标识不相交，但组标识必须覆盖真实依赖来源。仅按用户分组，无法阻止同一原始文档的不同副本分散两侧；仅按文档去重，也无法阻止同一模板来源被模型识别。可以把用户、原始对象、近重复、家庭或机构关系视为图中的边，必要时以连通分量作为分组单位，但这会改变有效样本量和可覆盖的部署范围。

时间划分通常不打乱顺序，扩展窗口与滚动窗口有不同的历史利用范围。普通按行数留间隔的工具，不一定等于真实时间间隔：不规则采样时，十行可能代表一分钟，也可能一个月。应检查时间戳和标签成熟规则，必要时自定义索引。工具提供的是索引生成机制，不能替项目决定时间语义。

## 2. 从信息流理解泄漏

<a id="eval-2-detail-6"></a>

### 2.1 泄漏是使用了当时不应可得的信息

泄漏可来自标签、输入、时间、实体和选择过程。直接把结果后的处理状态当特征，是标签代理；全体样本上选相关特征，是选择泄漏；未来修订过的统计是时间泄漏；同一内容副本跨侧是重复泄漏；在测试结果上不断改方案，是适应性泄漏。它们不一定都表现为训练数组里多了一列名为标签的字段。

有些步骤不用标签也会学习测试分布，例如全体数据估计均值、缺失值填补、主成分方向、词表或异常阈值。若目标是评价严格归纳式预测，它们也越过了训练边界。影响可能很小、很大甚至使分数下降；泄漏的定义不是分数一定变高，而是协议允许的信息被改变。若研究的是明确的传导学习场景，允许未标注目标输入参与训练也可以，但必须事先说明，并用对应方法公平比较。

固定的单位转换、字符串格式清理、按公开规范映射类别，不一定需要从样本中学习统计量。即便如此，还要检查所需输入是否在预测时存在。把某列按一千换算单位通常没有拟合泄漏；先看全体数据决定去掉哪些列，则可能包含分布适应。区分规则的制定来源，比给所有预处理一概贴上安全或危险标签更有用。

<a id="sec-2"></a>

<a id="eval-2-detail-7"></a>

### 2.2 Pipeline 保护的是拟合生命周期

一个管道把学习型变换和估计器组合起来。交叉验证每一折克隆并拟合整个管道，训练数据决定变换参数，验证数据只调用已拟合的变换和预测。它防止先用全体数据拟合标准化，再把变换后的数组交给交叉验证这类常见错误。但管道之外已经完成的筛词、目标编码或特征选择不会被自动撤销。

对每个步骤，可以记录四个对象：拟合所见的输入索引、拟合所见的标签索引、变换调用的索引、规则的版本。只要沿依赖链追溯到测试标签或不允许的测试输入，就说明边界发生变化。这样的信息流检查比仅检查代码中是否出现某个类名可靠；一个名为管道的对象也可能包住事先污染好的数组。

<a id="sec-1-1"></a>

<a id="eval-2-detail-8"></a>

### 2.3 手算标准化泄漏为何成立

训练输入为零和二，训练均值为一，验证输入为一百。合法变换把验证值减一，训练点围绕一对称；若先用三点拟合均值，则均值为三十四，训练和验证都围绕另一原点变换。即使某些具有截距且尺度不敏感的模型最后预测恰好相同，验证输入已经参与决定模型看到的坐标系，评价的学习规则发生了改变。

使用方差、主成分或正则化后，这种改变可能影响更明显。不能以某一次实验数值没变证明方法合法，也不能以非法方案分数更低证明不存在泄漏。评估协议应由可用信息约束定义，数值实验只是展示某种后果。若部署时确实会拿到完整未标注批次并重估变换，就应把它作为另外一套传导流程评价。

<a id="eval-2-detail-9"></a>

### 2.4 监督编码需要更细的交叉拟合

目标编码用类别的平均标签作为特征，若某类别只出现一次，直接用自身标签编码训练行会把目标抄进特征。即便把编码器放入管道，如果其训练阶段 `fit_transform` 没有适当交叉拟合，训练特征仍可能与部署变换不一致。应核对具体实现是否在训练行内部生成折外编码，以及平滑、未知类别和时间边界如何处理。

折外编码并非把所有训练样本标签永远禁用，而是对某行的训练表示避免使用该行不应直接可见的结果。若存在用户、时间结构，内部折也必须遵守这些结构。随机折外目标编码可能使用某个时点之后的标签生成过去特征，不符合时间部署。接口层的交叉拟合功能是否满足任务，需要读实现和实际索引，不能只看名字。

重采样也要区分拟合和评价。过采样、欠采样和合成样本应只发生在训练部分，验证保留目标总体分布。把合成样本先生成再拆分，可能让原样本和近似副本跨边界；把验证集也平衡，会改变精确率、概率与平均成本的总体含义。训练权重和评价权重可以不同，但都要解释相应目标。

<a id="eval-2-detail-10"></a>

### 2.5 实验一：全局监督筛选如何读取测试标签

以下构造纯噪声特征和标签，固定留出前半为训练、后半为测试。对每个噪声特征计算与训练标签的相关，再选择最强者，是合法的开发步骤；用全体标签选特征则直接使用了测试标签。实验不依赖声称某一次非法分数必然更高，而是核对全局筛选统计量确实随着测试标签改变。这样验证的是泄漏机制，而不是随机噪声中的偶然排名。

```python
import numpy as np
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(42)
X = rng.normal(size=(120, 1000))
y = rng.integers(0, 2, size=120)
train = np.arange(60)
test = np.arange(60, 120)
y_changed = y.copy()
y_changed[test] = 1 - y_changed[test]
global_a = SelectKBest(f_classif, k=5).fit(X, y)
global_b = SelectKBest(f_classif, k=5).fit(X, y_changed)
local_a = SelectKBest(f_classif, k=5).fit(X[train], y[train])
local_b = SelectKBest(f_classif, k=5).fit(X[train], y_changed[train])
assert not np.allclose(global_a.scores_, global_b.scores_)
assert np.allclose(local_a.scores_, local_b.scores_)
model = make_pipeline(SelectKBest(f_classif, k=5), LogisticRegression(max_iter=1000))
model.fit(X[train], y[train])
prediction = model.predict(X[test])
assert len(prediction) == len(test)
print('改变测试标签会改变全局筛选，不会改变合法训练内筛选')
```

这个反事实检查可以推广：保持训练数据不变，改变一个不应该被模型使用的评价对象，看训练产物是否改变。它不能检测全部泄漏，因为变化可能恰好不影响结果；但一旦出现不允许的依赖，就能明确定位越界步骤。正式流程还要检查缓存、数据连接、特征生成服务和人工选择记录，这些可能在管道外部引入信息。

## 3. 交叉验证估计的是完整学习规则

<a id="eval-2-detail-12"></a>

### 3.1 固定模型风险与训练算法风险

一个已经拟合的模型 $f_D$，在新的独立样本上的条件风险为 $R(f_D)$，其中训练集已经固定。另一个问题是：如果重新抽取训练集、重新初始化并运行学习算法，平均能得到怎样的风险。后者还要对训练数据和算法随机性取期望。两种对象都重要，但对固定模型的测试重采样，不能自动覆盖重新训练产生的变化。

交叉验证通常每折重新训练，因此更接近评价某种学习规则在略小训练集上的表现。它不是给最终用全部开发集训练的那个特定权重，直接生成一个精确无偏的风险证书。折数越大，每次训练量越接近全量，但训练集合之间重叠更多，计算也更贵；折数越小，每次训练量更小、训练集效应更明显。不存在不看任务和样本结构就普遍最优的折数。

若目标是部署一个固定已选模型的性能，可以用从未参与选择的独立测试集直接评价；若目标是比较整个开发方法，可以用预先固定的嵌套评价或多数据集实验。报告中写明训练规模，尤其在小样本时重要，因为两个学习方法的学习曲线可能交叉。某方法在较小折训练集上领先，不保证在全量数据上仍领先。

<a id="eval-2-detail-13"></a>

### 3.2 折均值与合并预测对应的权重

若各折样本数相等，对逐例平均损失先求折均值再等权平均，与汇总所有折外损失相同；若大小不等，等权折均值和按样本数加权结果不同。对于精确率、调和分数和排序面积等非线性指标，即使折一样大，平均折指标也一般不等于合并折外预测后计算一个指标。

以排序面积为例，各折分数可能来自不同拟合模型，数值尺度不完全可比。合并之后的面积会加入“甲折正例与乙折负例”的跨模型比较，这些对并没有由同一个模型共同打分。逐折面积平均则只比较折内样本对。二者回答的问题不同，不应为了得到较高数值任意替换。若部署本来使用跨折集成，需要按那个最终集成政策另行评价。

折外预测非常有用，可以用于误差分析、堆叠和校准开发，但它不是不受选择影响的神奇测试集。如果依据这些预测反复更改特征、调阈值、挑校准器，再在同一折外预测上报告最好效果，仍然发生适应性选择。数据角色由实际依赖关系决定，而非由折外、保留集、测试集这些名称决定。

<a id="eval-2-detail-14"></a>

### 3.3 为什么不能把折间标准差直接变成置信区间

不同折的验证集合虽不相交，训练集合往往高度重叠，所以各折得分通常相关。若把它们当独立观测，直接用标准差除以折数平方根，会忽略协方差。均值方差包含所有方差项和成对协方差项，删除后者没有一般依据。分层又可能使折间标签组成更均匀，让观察到的离散程度进一步变小。

这不意味着折分数不能展示。逐折表能揭示来源、时间和训练规模造成的不稳定，重复交叉验证也能描述协议下的变化；但区间应说明其构造及覆盖对象。要对算法平均风险进行严格推断，需要专门分析依赖、数据生成假设与重复层次，不能让一个默认绘图库误差带替代这些问题。本主题第四章进一步区分区间、训练波动和外部泛化证据。

## 4. 模型选择为什么需要额外评价层

<a id="eval-2-detail-16"></a>

### 4.1 最佳验证分数含有挑选噪声

设候选方法的真实性能为 $\mu_j$，验证观测为 $\hat\mu_j=\mu_j+\epsilon_j$。即使各候选都无偏，取最大的观测值也会偏向噪声正好较大的候选。在所有真实性能都相同的特例里，最大观测值的期望一般高于共同真值。候选数量、噪声大小和候选相关性都会影响这种乐观程度，不能只用调参次数一个数字概括。

这不是说搜索越多越糟。更多搜索可能找到真实更好的模型，只是用于选择的最佳分数不再能原样担当独立效果估计。应把搜索带来的真实收益与对验证噪声的适应分开。独立测试在选择被冻结后估计最终方案，嵌套交叉验证则反复把完整选择过程放入外层训练部分，从而评价这套选择规则的泛化。

<a id="eval-2-detail-17"></a>

### 4.2 嵌套流程的逐步边界

在某个外层拆分中，先把外层测试完全封存。只在外层训练中进行内层拆分，对所有候选重新拟合预处理、模型和必要校准，按预定义规则选择候选。之后用整个外层训练重拟合被选流程，最后在外层测试上评价一次。对其他外层折重复，得到各次独立于本折选择信息的外层分数。

外层模型可能选出不同参数，这是正常现象，不应在外层结束后挑其中最好的一个权重当最终模型。嵌套评价完成后，通常在完整开发数据上重新运行预定选择规则，再拟合最终产物；外层结果支撑的是该规则在相应训练规模与数据条件下的表现。最终产物若另有独立测试，可以再评价，但不能倒过来依据该测试修改选择规则后保留独立称号。

阈值选择、特征数量、编码平滑、校准方法、停止轮数和人工挑方案都可能属于选择规则。只把模型正则化参数放内层，外面再根据外层结果挑特征数，外层就承担了额外选择。完整嵌套并不要求所有工程细节都随机搜索，而是要求所有会利用评价结果作决定的自由度，被清楚放在相应开发层或作为探索局限披露。

<a id="sec-6"></a>

<a id="eval-2-detail-18"></a>

### 4.3 形式化：评价随机选择算子

把整个内层开发流程写成算子 $A(D,U)$，输入训练数据和随机源，输出包含变换、模型、校准和阈值的服务规则。外层留出样本只评价 $L(Y,A(D,U)(X))$。若外层样本与训练在目标假设下独立，而且没有后续用该外层结果改变算子，条件于训练产物，外层经验平均可以估计它在对应总体上的风险。

这个论证解释了嵌套的作用，也显示其边界。外层训练量比最终全量小，外层划分若不符合部署独立性，形式化独立条件不成立；若研究者看到外层结果后修改算子，已评价的对象又改变。嵌套不是永久保护所有未来尝试的外壳，而是对一个已描述流程进行外部检验的结构。

<a id="sec-6-1"></a>

<a id="eval-2-detail-19"></a>

### 4.4 实验二：在每一层检查实体隔离

以下实验生成四十个实体，每个三条记录。外层和内层都按实体拆分，管道内标准化与逻辑回归只见对应训练数据。数据完全在内存生成，搜索只有三个正则化强度；断言既检查索引边界，也检查每个最终外层拟合的标准化均值确实等于外层训练均值。实验不要求某个偶然性能阈值，从而避免把流程正确性和样本可分性混在一起。

```python
import numpy as np
from sklearn.model_selection import GroupKFold, GridSearchCV
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import log_loss

rng = np.random.default_rng(7)
groups = np.repeat(np.arange(40), 3)
X = rng.normal(size=(120, 4))
y = (X[:, 0] + 0.4 * X[:, 1] + rng.normal(size=120) > 0).astype(int)
outer = GroupKFold(n_splits=4)
losses = []
for train, test in outer.split(X, y, groups):
    assert set(groups[train]).isdisjoint(groups[test])
    inner = list(GroupKFold(n_splits=3).split(X[train], y[train], groups[train]))
    for a, b in inner:
        assert set(groups[train][a]).isdisjoint(groups[train][b])
    pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
    search = GridSearchCV(pipe, {'logisticregression__C': [0.1, 1., 10.]},
                          cv=inner, scoring='neg_log_loss', n_jobs=1)
    search.fit(X[train], y[train])
    scaler = search.best_estimator_.named_steps['standardscaler']
    assert np.allclose(scaler.mean_, X[train].mean(axis=0))
    prob = search.predict_proba(X[test])
    losses.append(log_loss(y[test], prob, labels=[0, 1]))
assert len(losses) == 4 and np.isfinite(losses).all()
print('四个外层损失=', np.round(losses, 6), '组与拟合边界均合法')
```

这里预先把内层索引列表化，使每个候选共享完全相同的拆分。列表索引是相对于外层训练子数组，而不是原始全局索引；混用这两个坐标系，是手写嵌套循环的常见错误。若需要按时间和组同时隔离，就应先构造满足两种条件的索引列表，再放入搜索，而不是把普通分组交叉验证误当作时间验证。

<a id="eval-2-detail-20"></a>

### 4.5 独立测试与嵌套评价如何取舍

数据充足时，训练、开发、最终测试的分工最直观，且部署最终模型的评价训练规模可明确。小数据时，嵌套评价能更充分轮换使用数据，但计算成本更高，外层折间依赖依旧存在。没有必要把所有小练习都强制做复杂嵌套，但任何报告都应明确哪些数用于选择，哪些数用于最终效果估计。

可以先用一次合法开发划分快速调试，再在冻结搜索空间后进行外层评价。若调试期间已经查看最终测试，就需要把它视为开发材料，另找后续数据或者承认探索性质。数据角色不是永久由文件名赋予；一旦标签参与决定方案，相关独立性就已被消耗。固定随机种子、隐藏最终小数或者仅公布最后一次尝试，都不能恢复它。

<a id="eval-2-detail-21"></a>

## 5. 公平比较需要共同的资源与目标

<a id="eval-2-detail-22"></a>

### 5.1 同样超参数数量不等于同样开发预算

比较一个方法搜索一百组配置，另一个只用默认值，得到的差异既包含算法，也包含搜索投入。公平不总是要求相同配置数量，因为每次拟合的成本、参数空间结构和早停收益不同；可以固定总训练时间、总算力、候选数量或实际工程预算，关键是预先定义并报告。若研究问题是各方法在相同时间下能达到多好，就应把时间预算作为实验因素。

预算还包括人工特征工程、预训练数据、外部工具和验证次数。一个看似只训练一次的大模型，可能继承大量外部选择资源；一个简单方法可能需要昂贵特征生成。报告应区分继承资源与本次预算，避免把训练命令执行时长当成全部成本。部署推断内存、延迟和模型更新成本，也可能成为不可忽略的约束。

<a id="eval-2-detail-23"></a>

### 5.2 搜索空间是方法的一部分

候选正则化强度如果只给某方法安排明显不合理的范围，会人为降低其效果；如果根据测试结果为另一方法反复扩大范围，又会污染比较。合理做法是在开发中建立有根据的范围，保留边界命中情况，必要时对所有候选采用同样预定义扩展规则。先冻结规则，再做最终评价，才能把结果解释为可复现的流程比较。

随机搜索和贝叶斯优化会产生自身随机性，单一幸运运行不能代表常规预算下的表现。可以对搜索过程重复若干次，使用成对数据拆分并报告整个预算内最优开发结果对应的独立测试效果。若成本不允许重复，应诚实限定结论为一次搜索结果，并说明搜索日志与随机源。最好的种子不能同时承担平均性能的含义。

<a id="eval-2-detail-24"></a>

### 5.3 数据与计算配对

两个候选应使用相同评价对象、标签版本、拆分和可用信息。若一个模型缺失某些困难样本的预测，不应各自在能预测的子集上比较分数。可以比较共同可服务子集作为辅助分析，但完整服务效果还要把失败、拒答、超时和接管政策纳入。候选池和标签截止日期也必须一致，防止一个版本多等了标签成熟时间而获得不同样本组成。

相同种子可以帮助对齐拆分，不保证两种不同算法内部的随机事件完全一一对应。更稳妥的做法是保存实际索引和种子列表，明确随机源属于数据、初始化、采样还是搜索。不要为了让结果看起来稳定而只公布某个最有利种子；也不要把两个算法不同种子间的独立差值，与同一测试样本上的配对差值混为一谈。

<a id="sec-3"></a>

<a id="eval-2-detail-25"></a>

## 6. 配对比较与不确定性

<a id="eval-2-detail-26"></a>

### 6.1 对差值建模比比较两个独立区间直接

设同一独立测试对象上两个固定模型的损失分别为 $L_{Ai},L_{Bi}$，定义 $d_i=L_{Ai}-L_{Bi}$，平均差为 $\bar d$。差值方差为两种损失方差之和减去两倍协方差。如果两个模型总在同样的困难对象上出错，这个正协方差可以显著减小差值的不确定性。分别对两模型重采样却使用不同索引，会丢失这种配对优势。

两个各自区间是否重叠，不是差值检验的正确替代。区间重叠时差值仍可能稳定偏离零，区间不重叠时也需要检查估计对象和假设是否一致。直接计算差值、给出其区间并说明实际意义，通常更清楚。即使差异统计可辨识，也可能远小于部署成本或维护代价；显著性不是自动上线的充分条件。

<a id="eval-2-detail-27"></a>

### 6.2 独立单位是组时如何重采样

若每个用户有多条相关记录，可以先计算用户内平均损失差，再以用户为单位重采样，得到典型用户平均差。若目标是请求加权的总体差，重采样完整用户簇后还要按每次重采样中请求总数重新加权，不能直接把用户平均等权结果冒充请求平均。这两种重采样都保留簇内结构，但目标不同。

按时间依赖时，简单独立抽行同样会破坏结构。块重采样或其他时间序列方法需要关于依赖衰减与近似稳定性的条件；若过程持续变化，扩大块长也不自动恢复对任意未来分布的保证。预先定义的外部时间窗评价提供另一种证据，但通常不是许多独立同分布重复。选择方法时应先明确要对哪一层随机性进行推断。

<a id="eval-2-detail-28"></a>

### 6.3 实验三：保持用户配对的自助区间

下面有八十个独立用户，每人三次请求。先算用户内两个模型的平均损失差，再以用户为单位进行配对重采样。小模型差异由可解释的构造决定，但区间端点不要求某个固定显示值。代码同时证明若对每个用户使用同一损失，则配对差始终为零，而独立打乱两份用户列表会人为引入差值波动。

```python
import numpy as np

rng = np.random.default_rng(123)
base = rng.uniform(0.1, 1., size=(80, 3))
loss_a = base + rng.normal(0, 0.03, size=(80, 3))
loss_b = base + 0.04 + rng.normal(0, 0.03, size=(80, 3))
d = (loss_a - loss_b).mean(axis=1)
indices = rng.integers(0, len(d), size=(3000, len(d)))
replicates = d[indices].mean(axis=1)
interval = np.quantile(replicates, [0.025, 0.975])
assert interval[0] <= interval[1]
assert np.isfinite(interval).all()
assert np.allclose((base.mean(axis=1) - base.mean(axis=1))[indices].mean(axis=1), 0)
independent_indices = rng.integers(0, len(d), size=(3000, len(d)))
wrong = base.mean(axis=1)[indices].mean(axis=1) - base.mean(axis=1)[independent_indices].mean(axis=1)
assert wrong.std() > 0
print('典型用户平均损失差=', d.mean(), '配对百分位区间=', interval)
```

这是固定两个模型、独立用户抽样假设下的示范，百分位自助区间没有对所有分布的精确有限样本覆盖承诺。没有重新训练，所以不包含训练数据、初始化和搜索变化；也没有模拟未来漂移。代码输出一个窄区间，只能说明该层面的估计精度，不能推导出算法在任意新时期都稳定领先。

<a id="eval-2-detail-29"></a>

## 7. 从原始记录到冻结报告的完整实例

<a id="eval-2-detail-30"></a>

### 7.1 一个带延迟标签的用户预测项目

考虑每天预测用户未来七天是否活跃。原始记录有用户标识、事件发生时间、事件入库时间和标签成熟时间。产品准备每周重训一次，线上只服务已经注册的用户。合理的主要评价是按重训日滚动：每次只取当日已成熟标签的训练样本，并按预测时点重建可得特征，然后预测下一周的请求。不能把未来七天真实活动直接聚合进当前特征，也不能让刚刚进入观察期的样本参与训练。

若还关心新用户，可在同一时间窗口单独标记此前未出现用户，报告其表现，或者设置一个额外新用户留出实验。不要为了让两类场景合并成一个更好看的平均数，删掉样本较少的新用户。两类人群的可用历史长度不同，模型服务规则也可能不同，应在报告中保留这种异质性，并明确总体权重来自实际服务量还是预定义目标组成。

开发阶段可以使用较早的多个时间窗选择特征和参数，最后一个未触碰时间段用于冻结后的评价。若每周重训策略本身也是候选，就把它放入开发比较：每周一次、每两周一次和固定模型各是一套完整服务流程，而不只是同一个权重的三个打分方式。最终评价重放实际更新时间，不允许在某个窗口观察结果后临时提前更新。

<a id="eval-2-detail-31"></a>

### 7.2 数据合法性断言比目测切分更可靠

每个外层窗口都应检查训练标签成熟时间不晚于重训时点，测试预测时间在指定未来区间，特征可得时间不晚于各自预测时点。若模拟新用户，增加用户集合不相交断言；若模拟已知用户，可以允许交集，但仍需防止同一预测事件或未来标签跨界。检查应与任务对应，不能把所有交集都当错误，也不能仅验证行索引不交叉就宣布没有泄漏。

存储实际索引和时间规则，可使后续复核不依赖某个库版本对默认划分器的解释。对不规则时间序列，要按真实时间计算间隔和观察期；若样本数量在节假日突变，用固定行数切窗可能产生不等长日历区间。部署按日运行时，评价也要保留日级候选池，不能把整个测试期混成一次随机批次。

<a id="eval-2-detail-32"></a>

### 7.3 实验四：标签成熟与特征可得的双重边界

这个独立实验构造二十个日级样本，目标需要三天观察后成熟，特征有一天入库延迟。重训日在第十二天，模型预测第十二至十五天；训练资格由成熟时间决定，而不是只看样本发生在过去。代码还构造一次非法的未来特征连接并明确拦截，展示数据层断言如何定位问题。

```python
import numpy as np

prediction_time = np.arange(20)
label_ready = prediction_time + 3
feature_event = prediction_time - 2
feature_available = feature_event + 1
retrain_time = 12
train = np.flatnonzero(label_ready <= retrain_time)
test = np.flatnonzero((prediction_time >= retrain_time) & (prediction_time < 16))
assert train.max() == 9
assert np.all(label_ready[train] <= retrain_time)
assert np.all(prediction_time[test] >= retrain_time)
assert np.all(feature_available <= prediction_time)
naive = np.flatnonzero(prediction_time < retrain_time)
assert set(naive) - set(train) == {10, 11}
illegal_available = feature_available.copy()
illegal_available[13] = 14
bad = np.flatnonzero(illegal_available > prediction_time)
assert bad.tolist() == [13]
print('合法训练末日=', train.max(), '被成熟边界排除=', sorted(set(naive) - set(train)))
```

注意边界的等号来自本实验的约定：第十二天重训前，所有标记为第十二天成熟的标签已经可用。若实际系统在当天上午重训而标签晚上到达，日级时间戳不足以判断，应使用精确时刻或保守截止。评价的时间精度必须足以区分信息先后，否则一个看似正确的等号也可能泄漏。

<a id="eval-2-detail-33"></a>

### 7.4 缓存、人工查看与实验日志

缓存可以减少重复预处理，但键必须包括训练索引、数据版本、变换参数和必要随机源。若不同折错误地复用全体数据拟合的缓存产物，管道外表仍然正确，信息边界却被跨越。缓存命中只能证明复用了同一产物，不能证明这个产物在当前折合法。应能追溯其拟合数据范围，而不是只记录文件名。

人工查看也属于信息流。研究者反复检查最终测试失败样本、修改清洗规则再重测，即使没有把测试标签作为程序输入，方案已经适应该测试集。人工分析有价值，但应把该集合重新视为开发资料，并用后续独立证据确认。可以保留一个探索测试和一个最终审计测试，但不能只靠给文件改名宣称边界恢复。

实验日志至少记录数据与标签版本、候选空间、选择规则、实际拆分、拟合与搜索随机源、训练与推断成本、失败尝试及选择结果。失败配置不能无声消失，否则平均预算和方法稳定性会被美化。若某方法在部分折无法拟合，应说明原因，并按预定规则处理，不能只对成功折算平均，再与另一个全折方法比较。

## 8. 十六道练习与完整解析

<a id="eval-2-detail-35"></a>

### 8.1 练习一：随机拆行到底测了什么

**题目。** 每个患者有十次检查，同一患者的稳定背景特征强烈关联标签。随机拆检查行得到高分，能否推断模型能推广到新患者？

**解析。** 不能。训练与测试可能含同一患者，模型能够利用个体身份、稳定背景或重复内容，这更接近已知患者的新记录问题。应按患者留出评价新患者，同时检查检查序列和标签时间。并不是所有跨患者交集都无效，而是必须让协议与部署对象一致；如果目标确实是已知患者的下一次成熟信息预测，时间合法的个体历史可以是允许的信号。

<a id="eval-2-detail-36"></a>

### 8.2 练习二：没有标签参与的全局标准化

**题目。** 先对所有输入拟合标准化，再交叉验证，研究者说没有使用测试标签，所以绝无泄漏。如何回应？

**解析。** 严格归纳式协议只允许训练输入决定学习型变换，测试输入参与均值方差就改变了规则。分数未必一定上升，但信息边界已经变化。若部署允许拿到完整无标签目标批次并拟合变换，可以把它定义为传导学习并公平评价；不能在事后只因没有标签就把两种协议当作同一个实验。

<a id="eval-2-detail-37"></a>

### 8.3 练习三：静态单位转换是否要每折拟合

**题目。** 所有长度从毫米除以一千转换为米，是否必须放在折内重新学习？

**解析。** 固定公开换算没有样本估计参数，不存在从测试分布学习均值这类拟合过程，可以一致应用于两侧。若转换后再依据全体样本选择异常阈值，则后者是学习型步骤，需遵守边界。规则是否安全取决于制定来源与预测时可得输入，而不是简单地看它是不是预处理代码。

<a id="eval-2-detail-38"></a>

### 8.4 练习四：分组隔离为什么没挡住文档副本

**题目。** 训练按用户隔离，但不同用户转发同一文档，模型测试表现极高。分组已做，问题在哪里？

**解析。** 用户不是唯一依赖来源。同一文档内容或近重复模板跨侧，可能让模型通过记忆内容完成评价。应按部署目的决定是否隔离内容簇，必要时把用户和文档关系形成连通分量。若真实部署本来就会重复处理同一公共文档，这可能是合法场景，但结论不能扩展为新内容泛化。需要分别报告已见与新内容的效果。

<a id="eval-2-detail-39"></a>

### 8.5 练习五：标签窗口的七天不是装饰

**题目。** 一月十日重训，目标为未来七天是否购买。能否使用一月九日预测样本的完整标签？

**解析。** 一月九日样本的七天结果尚未成熟，事后数据库能查到不代表一月十日已可知。应仅使用重训时已完成观察且可用的标签；若提前出现购买可确认阳性，阴性仍须等待完整窗口，这会造成不对称成熟机制，也必须按实际协议处理。不能只用已提前出现的阳性而忽略未成熟阴性，制造选择偏差。

<a id="eval-2-detail-40"></a>

### 8.6 练习六：折外预测能无限调阈值吗

**题目。** 每条预测都由没见过该行标签的模型产生，研究者用这些折外预测试了上千种阈值，然后报告最低成本是独立测试结果。是否成立？

**解析。** 折外模型对单行拟合独立，不代表阈值选择没有使用该行结果。上千种阈值的选择使这些标签承担开发角色，最低观测成本有选择乐观性。可以把阈值选择放入外层训练内，再由外层测试评价完整政策，或者留出独立最终测试。折外性质不能替代外部选择边界。

<a id="eval-2-detail-41"></a>

### 8.7 练习七：嵌套后为何参数不同

**题目。** 五个外层折分别选择不同正则化强度，是否说明嵌套评价失败，应挑外层最高分参数？

**解析。** 不同训练样本导致选择变化是正常的，恰能反映选择稳定性。外层评价的是内层搜索算子，不能再按外层分数挑参数，否则外层变成开发层。评价完成后在全部开发数据上重新执行冻结的选择流程，并重拟合最终模型；必要时报告各折选择频率作为稳定性分析，而不是把最幸运折当最终代表。

<a id="eval-2-detail-42"></a>

### 8.8 练习八：折平均与汇总损失

**题目。** 两个验证折分别有十条和九十条，平均绝对误差为一和三。求等权折平均与全样本平均，解释适用对象。

**解析。** 等权折平均为二；按样本数加权为二点八。前者若折代表同等重要的两个环境，可以有明确意义；后者代表当前一百条请求的平均损失。不能因为其中一个更低就任意选择。若折内指标为非线性比值，还要从原始计数合并，不能仅用折样本量加权就保证等于总体指标。

<a id="eval-2-detail-43"></a>

### 8.9 练习九：合并折外面积的跨模型比较

**题目。** 两折模型各自排序完美，但一折得分都在零到零点一，另一折都在零点九到一。合并折外分数的面积一定完美吗？

**解析。** 不一定。高尺度折的负例会排在低尺度折的正例前，产生跨折逆序，尽管每折内部完全正确。逐折面积平均与合并面积回答不同问题。若需要最终统一概率或集成排序，应合法训练最终服务规则并独立评价；不能因某一种聚合更好看就当成另一种的无损替代。

<a id="eval-2-detail-44"></a>

### 8.10 练习十：折间标准误的独立假设

**题目。** 五折分数标准差为零点零一，直接除以根号五就是完整算法风险的标准误吗？

**解析。** 没有一般保证。各折训练集合重叠，分数存在依赖，方差公式需要协方差项；同时这五次拟合没有覆盖全部搜索与未来分布变化。折间标准差可描述本次协议下的离散程度，但若构造置信区间，应采用与目标和依赖假设对应的方法，并明确不包含哪些随机层次。

<a id="eval-2-detail-45"></a>

### 8.11 练习十一：两个区间重叠能否证明无差异

**题目。** 同一批测试样本上，两个模型各自的准确率区间重叠，研究者说二者没有显著差异，结论是否必然？

**解析。** 不必然。两个估计高度相关时，差值的方差可以远小于各自方差；应直接对同一样本的配对损失差进行推断。反过来，没有拒绝零差异也不证明实质等效；若要证明足够接近，需要预先定义实际等效界限并选择相应分析。总体数值与实际成本都应纳入解释。

<a id="eval-2-detail-46"></a>

### 8.12 练习十二：用户平均与请求平均

**题目。** 甲用户有一条请求，损失差为负一；乙用户有九条请求，每条损失差为零。两个平均差各是多少？

**解析。** 典型用户等权平均为负二分之一，请求平均为负零点一。二者都合法，但对应不同权重。如果对用户簇重采样后想估计请求平均，应在每次重采样中汇总损失差与请求数后取比，不能把用户平均直接等权。重采样单位和指标权重是两个相关但不同的设计选择。

<a id="eval-2-detail-47"></a>

### 8.13 练习十三：相同搜索次数是否公平

**题目。** 两种方法都搜索二十组参数，一种每组一分钟，另一种每组两小时。能否声称资源预算完全相同？

**解析。** 只能声称候选次数相同，不能声称时间或算力相同。公平标准取决于研究问题：同样次数、同样壁钟时间、同样算力或同样部署成本都可能有意义。应预定义预算，并记录早停、失败拟合与并行资源；若一种方法额外获得大量人工调试，也应在比较局限中说明。

<a id="eval-2-detail-48"></a>

### 8.14 练习十四：测试后改清洗规则

**题目。** 查看测试错误后发现某类文本总被误解，于是新增清洗规则，重测明显提高。能否称测试仍未参与训练？

**解析。** 参数拟合也许没有直接读取标签，但人工规则选择已经使用测试结果，所以该集合参与了开发。可以将发现视为有价值的误差分析，并在后续独立数据上验证改进。不能仅以训练函数没有接收测试数组为由，否认人工适应。这也是保留实验历史而不仅保存最后一版代码的原因。

<a id="sec-7-1"></a>

<a id="eval-2-detail-49"></a>

### 8.15 练习十五：管道内一切就都合法了吗

**题目。** 词表在全体数据预先生成，随后特征选择和模型都在管道中。研究者说管道已经防住全部泄漏，应如何审查？

**解析。** 先明确归纳或传导协议，再追溯词表来源。严格归纳任务下，全局词表已使用测试输入，后续管道不能撤销该依赖；若词表还根据测试标签筛选，问题更直接。把词表拟合也纳入每折流程，或使用真正外部固定词表。审查应沿所有上游数据依赖展开，不能只检查最末端对象类型。

<a id="eval-2-detail-50"></a>

### 8.16 练习十六：重复随机种子能恢复独立测试吗

**题目。** 一套方案在测试集上调过很多轮，研究者重新固定一个随机种子并重训，说这样是全新实验，是否成立？

**解析。** 随机种子改变初始化或抽样，不会删除方案设计对测试结果的依赖。已有测试已经承担选择角色，新的权重仍来自适应过它的流程。需要独立新证据或明确探索性结论。若仅评价某个固定最终模型的抽样误差，也不能因此把历史选择偏差忽略掉。

<a id="eval-2-detail-51"></a>

## 9. 进阶研究：把验证流程当成统计对象

<a id="eval-2-detail-52"></a>

### 9.1 用纯噪声实验观察选择乐观性

构造多个真实性能完全相同的候选，让各自开发观测带有零均值噪声，再按开发观测挑最好者。为被选候选生成独立测试噪声，重复整个过程。开发最佳值会随候选数量增多而倾向上升，独立测试均值仍围绕共同真值。这个理想实验隔离选择机制，不涉及真实模型容量，所以适合解释为什么最佳验证分数不能原样充当泛化证据。

进一步让候选噪声高度相关，观察同样候选数量下的乐观程度变小；让真实性能差异增大，观察搜索的真实收益与选择噪声如何同时存在。研究目标不是推出一个普遍次数惩罚，而是理解相关性、噪声和真实差异共同决定结果。真实项目中候选还会被人工适应性生成，简单独立候选模型只能提供局部直觉。

<a id="eval-2-detail-53"></a>

### 9.2 时间与群体双重迁移的评价矩阵

可以把测试情景组织为二维矩阵：已知实体或新实体，历史同分布时段或未来时段。四格分别对应不同外推难度，不能只保留容易的一格。对每格报告样本量、成熟标签比例、关键特征可用性和性能；若某格没有支持，应标明缺证，不能由其他格外推出精确数值。

这个矩阵还有助于选择工程行动。只在新实体上退化可能提示身份依赖或冷启动问题；只在未来时段退化可能与漂移、标签延迟或特征链路变化有关；两者同时退化需要检查交互。评价本身不能单独证明原因，但能把诊断问题缩小。后续干预实验或受控消融应围绕具体假设设计，而不是再次随机拆分寻找更高分。

<a id="eval-2-detail-54"></a>

### 9.3 学习曲线与最终训练规模

嵌套外层常用不到全部数据进行训练，若两方法随样本量增长的收益不同，外层排名可能不能直接代表全量排名。可以在开发范围内预定义若干训练规模，保持相同外部评价规则，研究学习曲线。对高成本方法，可以用少量规模点，但不要把稀疏曲线无条件外推到远超观察范围的数据量。

同时区分数据量和独立单位数量。把同一用户行为复制十倍可以增加行数，却不会等价地产生十倍新用户信息；模型拟合可能更稳定，外部群体泛化仍缺少证据。学习曲线应分别记录行数、用户数、时间跨度和类别支持度，这样才能判断收益来自更多重复观测，还是来自真正覆盖了新环境。

<a id="eval-2-detail-55"></a>

### 9.4 置换检验也需要保持设计结构

若研究模型是否利用了超过随机的标签关联，可以考虑置换标签后重跑完整流程。关键是置换方式必须在零假设下保持可交换性，不能随意打乱有强时间或组结构的标签；并且特征选择与调参也要在每次置换中重新执行，否则零分布没有包含实际选择自由度。单次固定模型的标签打乱，无法代表整个已选择流程的零分布。

置换检验拒绝零假设只说明观察到的关联难以由所定义的零机制解释，不证明模型能跨来源推广，更不证明因果效应。若训练与测试含重复，模型可能学到真实但无部署价值的关联。应先保证部署边界合理，再决定需要检验哪个统计问题。推断工具不能修复一个与使用场景不对应的实验设计。

<a id="eval-2-detail-56"></a>

### 9.5 自适应探索与可复用证据

真实研究通常需要不断观察、修改与再试，不必假装所有决定都在第一次实验前完成。合理做法是区分探索和确认：探索用于提出方法与诊断机制，确认用于对冻结流程产生外部证据。可以通过定期收集新时间批次、保留未使用来源、预注册关键比较或采用专门的自适应评估方法降低偏差，但每种方法都有成本与假设。

记录探索历史能让读者理解结论的选择范围。只公布最后一次漂亮数字，会把大量失败搜索从证据链抹掉；完整日志不要求在主报告堆砌所有尝试，却至少应说明搜索预算、选择依据和最终评价何时被冻结。可复现性不仅是同一代码得到同一小数，还包括别人能重建为什么恰好选中了这一套代码。

<a id="eval-2-detail-57"></a>

### 9.6 算法稳定性与评价方差的联系

若训练集替换一个独立对象就能使预测规则大幅改变，说明学习过程对样本扰动敏感。高维小样本、强特征选择、接近多个局部最优的训练、极端类别不平衡，都可能造成不稳定。交叉验证折间变化既包含验证样本组成，也包含不同训练产物，不宜仅解释为评价噪声。可以通过固定测试集、对训练数据进行合法的组级重采样，单独研究这种变化，但这仍需要关于训练样本代表性的假设。

稳定性分析也能帮助比较两种流程。某方法平均风险略低，却在少量重训中严重退化，若业务难以承受版本波动，就应报告尾部与失败频率。另一方法稍差但稳定，并不自动更优，关键在部署损失是否真的惩罚这种波动。可以把重训失败或性能低于下限定义为独立验收量，让结论与真实更新机制对应，而不是只展示跨种子的最好值。

不要把固定种子等同于稳定算法。固定种子可以让同一输入的实现容易复现，却没有回答训练集略变、库版本变化或未来环境改变时输出如何。稳定性是一种关于扰动分布和损失变化的性质；复现性是一种关于过程记录和执行一致性的性质。两者需要不同实验，能够互相支持，却不能互相替代。

<a id="eval-2-detail-58"></a>

### 9.7 公平预算下的提前停止与失败配置

如果搜索采用提前停止，停止规则必须只使用允许的开发信息。某候选因为前几轮验证较差而被淘汰，会节省计算，但若方法收敛速度不同，同样早停规则也可能系统性偏向快收敛方法。公平性应从研究目标说明：若目标是有限时间内可获得效果，这种偏好可能正是资源约束的一部分；若比较充分收敛后的模型类别，就需要不同预算设计。

失败配置也要计入预算。数值发散、显存不足或训练超时，意味着方法在相应约束下没有产生有效服务，不应从搜索时间和成功比例中删去。最终主表可以只展示被选可用模型，但日志与附表应记录失败次数和处理政策。若某候选在外层测试后才因表现差被认定为异常而删除，那已经成为结果驱动的选择，应重新评价或明确其探索性质。
