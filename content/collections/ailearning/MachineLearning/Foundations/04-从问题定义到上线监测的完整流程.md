## 1. 把任务协议变成可执行契约

<a id="detail-1"></a>

### 1.1 任务卡必须允许他人重建样本

任务卡至少写明总体、样本单位、预测时点、可用信息、目标窗口、标签成熟规则和用途。别人仅靠这张卡，应能判断一条记录是否属于任务、何时可以训练、某列是否泄漏。模糊目标例如“预测风险”无法支持这种判断；应改写成在某时点对某类对象预测某个可观察结果。

例如建筑能耗项目可以规定：每天零点，对具有完整基础设备信息的建筑，使用此前已入库的历史读数与当时已经发布的天气预报，预测未来二十四小时总用电量。真实未来天气不能作为当时输入，事后修订的电表读数也要与实时可用版本区分。目标需要未来一天结束并经过补录缓冲后才成熟。

任务卡还应定义例外：停电、设备故障、计量器重置、建筑关闭以及不完整目标窗口如何处理。排除规则会改变总体，不能只把难样本删掉而继续声称覆盖全部建筑。可以设正常运行预测与异常检测两条路径，但应明确各自的目标和评价分母。

<a id="detail-2"></a>

### 1.2 指标、成本与容量在训练前对应起来

主要指标应反映用途。能耗均方误差强调大幅偏差，绝对误差对大残差较稳健，按建筑平均的相对误差又与按总能耗加权的误差不同。如果系统用于采购或调度，过高与过低预测可能代价不对称，需要相应损失或决策分析。

没有单一指标能够同时表达精度、偏差、极端日表现与服务约束。可以指定一个主要选择指标，再列少量关键约束，例如某类建筑不超过允许退化、请求必须在规定延迟内完成。这样避免看到结果后任意改主指标，也让性能与资源的取舍可审查。

<a id="detail-3"></a>

### 1.3 验收标准应区分三类问题

数据验收检查字段、单位、时间和标签是否正确；预测验收比较独立样本上的损失、校准或覆盖；系统验收检查延迟、错误处理和回退；行动效果则可能需要随机实验或其他识别设计。训练任务结束只说明程序完成运行，不意味着这些层面都通过。

验收数值应结合基线、实际成本和估计不确定性制定。一个任意规定的高准确率可能被类别基率轻易满足；一个很小的平均提升也可能在大规模调用时有价值。标准来自任务和可接受风险，而不是凭感觉追求更大模型或更多小数。

<a id="sec-2"></a>
## 2. 从错误观察到可反驳的实验

<a id="detail-4"></a>

### 2.1 错误表应保留可以定位机制的信息

对开发验证集保存预测、真值、损失、来源、时间、关键缺失与模型版本。连续目标还可以查看残差正负、目标区间和预测区间。保存原始请求的必要引用，便于核对是否有单位、连接或标签问题。错误表的目的不是积累一批有趣故事，而是支持可验证的分类与对照。

分组可以按来源、历史长度、设备类型或目标范围进行，但要同时报告组样本量。某个小组误差特别高，可能反映真实薄弱点，也可能只是少量极端样本。先阅读记录、检查数据质量，再决定是否需要补充样本或专门模型。反复挖掘大量组也会产生发现偏差，需要后续确认。

<a id="sec-2-1"></a>
### 机制展开：误差分析需要竞争解释与对照

某设备来源误差高，至少有几种解释：输入单位不同、缺失更严重、真实对象更难、标签延迟不同、训练覆盖不足或模型结构不合适。直接宣布“来源偏差”只给现象换了名字，没有定位机制。应设计能够使这些解释给出不同预测的检查。

例如先统一单位，如果性能恢复，支持接口问题；再限制在输入完整样本，如果差距缩小，支持缺失机制；在目标范围相近的样本上比较，检查难度组成；补充少量独立来源数据后重训，研究覆盖效应。每一步尽量控制其他因素，使结果具有解释力。

<a id="deep-dive-2"></a>
### 深入讲解：将错误分析转成一组可被证伪的改进实验

一个完整假设应包含观察、机制、干预和预期反证。例如观察是新建筑预测偏低，机制假设是缺少历史长度信息，干预是增加历史覆盖量与冷启动表示；若在同样历史长度与来源下仍无改善，或改善只发生于已有建筑，就削弱该假设。明确什么结果会让自己改变判断，比只写预期提升更重要。

模型替换可以是一个实验，但它往往同时改变容量、优化和输入处理，难以独自解释机制。可以先用小规模受控实验定位，再进行完整方案比较。工程上允许组合有效修复，研究结论则需要足够对照来支持归因。

<a id="detail-5"></a>

### 2.2 标签审查与模型错误要分开

若高损失样本是电表重置导致的负能耗，模型没有拟合它未必是缺陷。应检查目标构建、单位、事件对齐和异常规则。修正标签后，需要对所有方案重新计算，不能只把新模型不擅长的样本删掉。排除应依据任务定义，而不是预测是否正确。

有些目标本身存在歧义或噪声，不能通过人工查看后随意改成更符合模型的答案。可以进行盲化复核、保留争议标记或评价多个合理标准。审查者知道预测时可能受到锚定影响，因此高质量复核需要明确流程，而不仅是“专家确认”。

<a id="detail-6"></a>

### 2.3 错误分析不应消耗最终测试而不记账

开发集适合反复研究错误，最终测试用于确认已经选择的流程。如果从测试错误发现新特征并训练改进，原测试已经参与开发。可以继续利用它解决问题，但新结论需要新的独立证据。长期项目中应把这类转变记录下来，避免同一个固定集合在每轮都被称为新测试。

<a id="sec-3"></a>
## 3. 部署的是一个组合函数

<a id="detail-7"></a>

### 3.1 把接口写成函数链

完整系统可写为 $`F(r)=\delta_\tau(g_\theta(T_\psi(V(r))))`$。输入检查规定字段与合法范围，预处理包含单位转换、填补与编码，模型产生分数，决策规则把分数变成行动。任何一层变化都可能改变结果，因此版本不能只等同于模型权重。

某些检查应拒绝请求，某些可以进入明确回退。例如缺少非关键特征时使用已验证的填补；缺少实体主键或预测时点时无法构造合法样本，则应返回结构化错误或使用业务允许的默认策略。回退不是临时补丁，也属于需要评价的系统行为。

<a id="sec-1-1"></a>
### 基础算例：部署的是组合函数而非孤立权重

设请求金额以分传入，预处理先除以一百变为元，再用训练均值一百元、标准差二十元标准化。一个分类模型计算 logit 为 $`0.5z-1`$。原始金额一万二千分变成一百二十元，标准化为一，logit 为负零点五，正例概率约零点三七七五。

若上线漏掉分到元的转换，会把一万二千当作元，标准化变成五百九十五，logit 变成二百九十六点五，概率近乎一。网络权重完全相同，业务行为却彻底不同。固定样例需要核对原始字段、中间特征、分数和最终行动，而不仅是接口是否返回了一个合法数值。

<a id="detail-8"></a>

### 3.2 离线在线一致性如何验证

构建一组代表正常、边界、缺失、新类别和极端范围的原始请求，让离线管道与服务管道分别运行。逐层比较特征名、顺序、数据类型、单位、填补值、类别索引和输出。浮点实现可能有微小误差，应使用与业务阈值匹配的容差，而不是无条件要求字节一致。

若不同运行库或精度造成概率微小差异，接近决策边界的样本仍可能翻转行动。除了平均数值误差，还要检查行动差异数量、来源与成本。量化或编译优化也应通过同样流程核验，不能只比较吞吐量。

<a id="detail-9"></a>

### 3.3 批量、单条与顺序语义

批量推理不应因任意请求排列而改变每条独立样本的结果，除非模型明确使用同批上下文。训练与推理中的归一化、状态缓存和随机性可能破坏这种预期，需要测试。序列模型还要明确状态是否跨请求保留、何时重置，以及不同实体是否隔离。

线上特征更新和模型更新可能不同步。如果新模型期待新类别映射，而服务仍用旧映射，就会产生合法数值但错误语义。应把相互依赖的状态作为一致版本切换，或提供兼容期与显式版本检查。仅给模型文件改名不足以保证组合函数正确。

<a id="sec-4"></a>
## 4. 模型更新与回退的证据链

<a id="detail-10"></a>

### 4.1 先解释为什么需要更新

触发可能来自成熟标签上的性能退化、新增代表性数据、目标或成本改变、数据接口升级，也可能是资源优化。输入漂移告警只是调查线索，不自动等于模型应该重训。若单位错误导致失效，重新训练可能适应错误而掩盖根因；应先修复契约。

定期更新也需要评价。新增数据可能有异常、标签尚未成熟或选择机制已变，自动跑完训练不保证更好。可以预先定义候选生成、外部评价和上线标准，让更新成为可回放的学习算法，而不是一个只检查任务是否成功退出的定时器。

<a id="detail-11"></a>

### 4.2 新旧版本必须在共同证据上比较

固定回归集检查曾经重要的场景，近期独立数据检查当前总体，关键群体与资源指标检查代价。回归集经过多轮修复后主要用于防止已知故障重复，不再提供无限独立的新泛化证据。近期测试也要避免被反复用于挑选大量候选。

如果目标口径改变，新旧版本可能需要在新口径下重新建立基线。不能直接拿旧报告和新报告的数值相减，因为分母、标签或采样不同。应在同一套新协议上回放旧方案，或者明确哪些部分无法公平比较。

<a id="detail-12"></a>

### 4.3 回退恢复状态，调查解释原因

保留旧模型、预处理、阈值和必要兼容配置，才能真正恢复旧行为。只回退权重但继续用新词表，可能并未回到旧系统。回退条件可以包括服务错误、关键行为异常或成熟指标退化，但阈值应结合波动、延迟与业务影响制定。

回退不是根因分析的结束。需要查清是数据、接口、模型还是行动规则变化，并检查同类请求是否受影响。对于已经执行的行动，回退未来预测不能自动撤销过去后果，所以日志与版本归属对后续评价仍然重要。

<a id="sec-5"></a>
## 5. 实验假设、预算与选择历史

<a id="detail-13"></a>

### 5.1 实验表不只是参数清单

每次实验记录观察、假设、改变因素、主指标、计算预算、验证结果和决定。对于“历史过短导致冷启动差”这样的假设，还要记录支持与反驳条件。若新增历史长度特征后只改善老用户，不能仍宣称解决了冷启动，应重新检查机制。

基线必须和候选使用同样合法输入与评价数据。若新模型额外使用未来天气，而旧模型只用当时预报，差距主要来自信息条件变化；如果一个方案得到十倍调参预算，也应说明比较的是不同开发资源下的系统，而不是算法本身的纯粹优劣。

<a id="detail-14"></a>

### 5.2 选择历史也是算法状态

人工阅读错误、改变标签、筛选特征、挑随机种子和修改阈值，都可能根据开发结果适应数据。这些步骤未必写成代码，却属于实际选择过程。记录历史并不要求逐字保存所有想法，而是要知道最终结果经历了哪些信息与选择预算。

若每次试验都使用独立且有效的百分之五检验，五十次独立检验中至少一次假阳性的概率为 $`1-0.95^{50}\approx0.923`$。真实模型比较往往相关，因此这个数值不能直接照搬，但“试得多就更容易看到幸运结果”的机制仍在。主要指标和确认数据应提前确定，探索发现则留待新的确认。

<a id="detail-15"></a>

### 5.3 失败实验需要留下可复用结论

某个特征没有改善，可能因为表示无效，也可能因为样本量、优化或任务条件不同。报告应说明在哪个协议和预算下没有观察到改善，而不是宣布该思想永远无用。若明确排除了一个强假设，失败实验同样有知识价值。

还要区分技术失败与科学负结果。代码异常、标签错位或资源不足，没有真正测试原假设；训练成功且结果稳定无改善，才更接近方法层面的负证据。把两者混在一张最优分数表里，会误导下一次决策。

<a id="sec-6"></a>
## 6. 学习流程本身是评价对象

<a id="detail-16"></a>

### 6.1 从数据到预测器的映射

把完整开发过程写为 $`\mathcal A(D)`$，其内部包含样本构造、预处理、候选搜索、早停、阈值和集成。若外层评价希望估计这个算法的表现，就必须在每个外层训练部分重新运行内部选择。只固定最终权重再测试，回答的是另一个、条件于已完成选择的问题。

这一区别在数据量小、调参多时尤其重要。一个流程可能偶然选到很好的模型，但平均选择表现不稳定；另一个流程最高分稍低，却经常给出可靠方案。评价算法时应关心重复采样下的完整结果，而不是单次幸运权重。

<a id="sec-6-1"></a>
### 训练、上线与更新应共享同一预测契约

样本单位、时点、字段单位、缺失策略、类别映射和标签窗口在三个阶段需要一致。若训练模拟零点预测未来二十四小时，线上改成每天十点却继续使用原特征截止规则，任务已经改变。若更新时标签成熟逻辑变了，版本差异也不再只是模型参数。

契约可以随需求修订，但修订应生成可辨认的新版本，并重新建立比较。保持同一个文件名不等于保持同一个任务。对每次预测，至少要能定位当时输入语义、特征状态、模型和决策规则，这样才有可能解释历史行为。

<a id="detail-17"></a>

### 6.2 滚动回放与预序贯评价

对持续更新系统，可以按时间模拟：先用当时已知数据训练，预测下一批；等结果成熟后评价，再按既定规则更新。把每个样本在结果未知时产生的预测汇总，构成预序贯评价的一种形式。它能更贴近实际学习与部署顺序。

这些误差通常有时间相关，也可能来自不同版本，因此不应直接套独立样本置信区间。需要按时间批次、实体或明确依赖模型分析不确定性。回放时如果使用事后修订的特征或未来标签，仍然破坏了信息顺序；时间排序本身不能保证回放合法。

<a id="detail-18"></a>

### 6.3 固定回归集与外部评价的不同职责

回归集适合防止已知错误重现，比如单位转换、未知类别和某种边界输入。长期根据它修复后，模型自然会适应该集合，因此它主要提供已知行为的稳定性证据。外部评价则需要未参与这些修改的数据，以支持新的泛化结论。

两类数据都重要，不能用一类替代另一类。独立测试未必覆盖每个罕见接口故障，回归集也不能代表所有未来。把它们混成一个总分，会掩盖各自的证据作用。

<a id="versions"></a>
## 7. 数据、特征与版本的完整关联

<a id="detail-19"></a>

### 7.1 一个版本需要回答哪些问题

版本记录应关联训练数据截止点与标签规则、特征定义及拟合状态、模型结构与权重、训练配置与选择规则、概率或数值后处理、决策阈值以及输入输出接口。不是所有项目都需要复杂平台，但至少要有可恢复的关联，不能只保存一个无法解释的权重文件。

随机种子有助复现某次运行，却不能代替数据和环境信息；相同种子在不同实现或硬件下也不必保证每个数值完全一致。复现目标可以分层：数据与语义可重建、主要指标在合理波动内一致、某些关键样例行为一致。应选择与任务需要匹配的标准。

<a id="detail-20"></a>

### 7.2 数据快照与动态来源

训练数据来自会更新的数据库时，只记录查询语句可能不够，因为历史行会补录、修订或删除。可以保存快照、不可变事件引用或足以回放的版本机制。核心要求是能够重建当时允许使用的内容，而不是强制某一种存储工具。

特征也会随业务规则变化。同名“活跃天数”可能从任意登录改为有效交互；类别表可能合并渠道；时间窗口可能改变。应把语义版本与数值状态一起管理。否则一次性能变化无法区分是模型学习不同，还是输入本来就不同。

<a id="detail-21"></a>

### 7.3 日志连接的统计含义

预测日志与后续标签应通过稳定的样本标识、预测时点和目标窗口连接。只按用户标识连接会把多次预测与多个结果混在一起，造成重复或错配。若一次请求重试多次，还应区分逻辑预测与技术调用，避免同一事件重复计入指标。

日志是否完整也需要检查。服务失败的请求如果没有预测记录，评价只剩成功请求，可能高估系统总体表现。应分别报告请求覆盖率、有效预测率和有效样本上的误差；若把失败统一转为回退行动，也应将回退结果纳入实际系统评价。

<a id="detail-22"></a>

### 7.4 可追溯性不等于无差别保存所有原始内容

保存足以复现与审计的必要信息，和无限保留每个原始字段不是同一要求。可以使用受控引用、聚合统计或适当权限机制，具体取决于数据性质与项目约束。删除或脱敏会影响可重建范围，应准确说明哪些历史行为仍可解释。

对学习资料而言，关键是认识到版本与日志服务于具体问题：定位错误、比较候选、重建信息边界。过多无用途的记录增加维护成本，也可能掩盖真正需要的状态。应从需要回答的问题反推记录内容。

<a id="monitoring"></a>
## 8. 监测输入、预测和成熟结果

<a id="detail-23"></a>

### 8.1 无标签监控可以及时发现什么

输入侧可监测字段缺失率、非法范围、类别新颖度、单位异常、时间延迟与来源组成；预测侧可监测均值、分位数、极端概率、行动比例与回退率；系统侧可监测错误、延迟和资源。这些指标能在真实标签到来前暴露接口或分布异常，但它们是代理信息。

只监测每列均值不够。联合关系可以改变而边缘均值不变，例如两个二元输入从独立变为高度相关，各自仍有一半为一。模型依赖交互时，风险可能改变。可以监测合理的联合摘要、模型表示或分层分布，但任何有限摘要都不能覆盖所有变化。

<a id="detail-24"></a>

### 8.2 分布距离不是性能退化的证明

一个简单的两箱稳定性统计量可写为 $`\sum_b(q_b-p_b)\log(\frac{q_b}{p_b})`$。当参考比例为零点八、零点二，当前为零点六、零点四时，值约零点一九六二。它反映分箱比例差异，但依赖箱划分、零频处理和样本量；没有脱离任务的统一阈值能直接推出需要重训。

某个变量发生明显漂移，模型可能完全不使用它；某个小范围变化却可能集中在决策敏感区域。监测应结合模型依赖、关键人群与成熟结果，而不是只按距离从大到小自动修复。统计检验发现差异，也不等于差异具有实际成本意义。

<a id="sec-8-2"></a>
### 边界追问：输入不漂移是否保证模型不退化

设输入 $`X`$ 是公平二元变量，旧环境目标为 $`Y=X`$，新环境目标为 $`Y=1-X`$。两边输入分布完全相同，目标边缘分布也都正负各半；旧模型预测 $`X`$，错误率却从零变为一。输入均值、预测分布甚至目标基率都无法发现这种条件机制翻转，只有连接输入与真实结果的评价才能看到。

这个反例说明无标签监控存在识别边界。它仍然有价值，因为能够及时发现很多真实故障；但不能代替有标签的误差与校准监测。标签迟到时，应明确当前结论只是“代理未异常”，不能说性能已获保证。

<a id="detail-25"></a>

### 8.3 标签成熟后按预测队列评价

若目标是未来七天事件，今天生成的样本需要七天加缓冲才有完整标签。监控应按预测日期队列等待成熟，再计算同一窗口指标。将尚未发生事件的近期样本记为负例，会让看板虚假改善，并可能触发错误重训。

不同来源标签延迟可能不同。只评价已经到达的结果，会偏向更快反馈的样本；例如失败事件更快被记录，成功结局更晚，早期比例不代表完整队列。应记录覆盖率与延迟分布，必要时等待或使用有假设的删失处理，不能默认早到标签是随机样本。

<a id="detail-26"></a>

### 8.4 告警需要考虑连续查看

对固定批次中独立有界损失，集中不等式可以给出平均风险估计误差界。例如损失位于零到一，样本一千，双侧失败概率零点零五时，Hoeffding 半径约为 $`\sqrt{\frac{\log40}{2000}}\approx0.04295`$。真实项目可能需要更紧界或依赖修正，这里只展示如何把样本量与告警证据连接。

若每天反复查看同一个百分之五检验，长期误报不再由单次百分之五描述。一种保守思路是给第 $`m`$ 次有效检验分配 $`\alpha_m=\frac{\alpha}{[m(m+1)]}`$，总和为 $`\alpha`$，再用联合界控制至少一次错误告警。它要求每次检验在相应条件下有效，不需要不同次事件独立；但阈值可能较保守，序贯方法可以更精细地利用信息。

不能把这个公式直接用于任意自适应模型和重叠样本而不检查有效性。如果模型根据同批结果被更新，或者损失依赖未处理，单次检验本身可能无效。告警规则应与数据到达、更新和查看方式共同设计。

<a id="rollout"></a>
## 9. 影子运行、分阶段比较与行动效果

<a id="detail-27"></a>

### 9.1 影子运行首先验证可执行性

候选模型接收真实请求但不改变实际行动，可以检查输入覆盖、延迟、输出分布与旧模型差异。等标签成熟后，还可以比较预测误差。它能发现离线数据没覆盖的接口情况，但不能直接测量由新行动引起的业务增量，因为行动仍由旧系统决定。

若旧行动会改变标签，例如推荐曝光影响点击或运营干预影响回访，那么影子预测评价的是旧策略生成的数据。候选上线后数据机制可能变化，离线优势未必完整转化。应先明确目标是预测旧策略下结果，还是选择更好的行动。

<a id="detail-28"></a>

### 9.2 分阶段引入控制影响范围

可以先让部分符合条件的流量使用候选，并明确分配规则、版本记录、停止与回退条件。若想比较行动效果，随机分配通常提供更清晰的识别，但单位可能是用户、建筑或时间段，需要考虑相互影响与持续效果。按请求随机而同一用户跨版本，可能产生干扰或体验混合。

阶段比例不是数学上的安全保证，只是管理影响与收集证据的一种方式。关键是每阶段知道观察什么、多少样本才有意义，以及遇到什么结果改变决策。看到早期有利结果就随意提前结束，也会影响统计解释，应使用预定或合适的序贯分析。

<a id="detail-29"></a>

### 9.3 预测改善与业务改善需要分别测量

一个能耗模型预测更准，但控制策略没有使用其改善部分，实际节能可能很小；一个流失模型识别风险更准，却选中了无法被优惠改变的人，也可能没有增量。模型指标与行动收益之间需要明确机制，必要时通过实验检验。

举例说，两组各一千人，转化率从百分之五到百分之六，表面提升一个百分点。独立二项近似下，差值标准误差约为 $`\sqrt{0.05\times\frac{0.95}{1000}+0.06\times\frac{0.94}{1000}}\approx0.01019`$，与观察差同量级。这个小样本结果不能仅凭正向数值就强烈断言效果。实际实验还要考虑随机单位、分层、干扰和多次查看。

<a id="case-study"></a>
## 10. 完整案例：建筑能耗预测系统

<a id="detail-30"></a>

### 10.1 数据契约与时间线

目标是在每天零点预测各建筑未来二十四小时总用电量，单位为千瓦时。历史电表按统一时间基准存储，展示时才转换为业务时区；天气特征使用当时已经发布的预报版本，不能用事后观测天气替代。输入窗口包含过去一天、过去七天同一时段与建筑属性，标签需要目标日结束并完成约定补录后成熟。

如果一月一日零点产生预测，其目标覆盖一月一日全天；一月二日零点刚过，仍可能有读数未到。假设约定额外一天缓冲，则在一月三日才将该队列纳入完整结果评价。实际缓冲长度应根据系统延迟与任务要求确定，而不是为了让指标好看而修改。

缺读数时要区分局部缺失、计量器重置和完整停电。总能耗标签只有在覆盖达到预定标准后才有效，不能把缺测小时填零后声称是真实耗能。若使用估计补全目标，需记录质量标记，并分别检查高质量标签与补全标签上的表现。

<a id="detail-31"></a>

### 10.2 基线、模型与选择顺序

第一基线使用上周同一天能耗，第二基线使用近期同类日期均值，第三方案加入当时天气预报与建筑特征。先在较早时间训练，在后续开发月份选择窗口、正则与模型，再留出更晚月份确认。模型和所有预处理都只能使用当时成熟的数据。

若要服务新建筑，另设未见建筑组，确保历史长度不足时有明确回退。可以使用建筑类型与面积共享统计信息，但不应要求一个新建筑拥有完整个人历史。已见与未见建筑结果分开报告，避免旧建筑数量较多掩盖冷启动失败。

<a id="detail-32"></a>

### 10.3 四个样本的完整指标计算

为理解指标，取四个建筑日，真实能耗为一百、二百、一千、二千。基线预测为一百一十、一百九十、一千零二十、一千九百八十，误差为十、负十、二十、负二十；候选预测为一百、二百、一千、二千零三十，误差为零、零、零、三十。

基线绝对误差均值为十五，平方误差均值为二百五十，平均有符号误差为零；候选分别为七点五、二百二十五和七点五。候选在两种平均误差上更好，却出现更大单点误差，并具有正向平均偏差。这并不矛盾：聚合方式不同，强调的行为也不同。

若业务特别关心最大采购缺口，还需要对应的尾部或成本指标；若关心总能耗偏差，应查看加权汇总。四个样本只是算例，不能支持统计优越结论。真实比较要使用代表性队列、配对损失和不确定性分析，同时核对候选是否在小建筑、大建筑或极端天气中系统退化。

<a id="detail-33"></a>

### 10.4 从离线模型到服务版本

发布包包含字段规范、单位转换、历史聚合定义、缺失处理状态、类别表、模型、后处理与回退。固定原始样例覆盖普通建筑、缺历史、新类别、极端温度和非法单位。离线与服务逐层比较，确保预测相同输入时行为在预定容差内一致。

影子运行发现某来源面积按平方米传入，另一来源按百平方米传入。由于输入仍是正数且范围可能部分重叠，简单类型检查未发现。修复来源单位映射后重新回放，而不是重训模型去适应错误。这个故障说明契约需要语义与来源，不只是数据类型。

<a id="detail-34"></a>

### 10.5 监控与更新的具体闭环

实时监控缺读数率、天气预报发布时间、未知建筑比例、预测与基线差异、回退率和服务延迟。目标成熟后，按预测日期、建筑类型、历史长度和天气情况计算损失。若极端温度组退化，先核查训练覆盖、天气版本与设备运行策略，再决定补数据、改表示或重新训练。

更新候选在固定回归集和新成熟时间段比较，并保留旧版本。若候选改善近期普通日却损害关键极端日，不能只用总体平均决定，应按预定成本与约束审查。若后续控制策略改变建筑耗能，新的标签分布可能受到系统行动影响，需要将预测误差与控制效果区分。

<a id="detail-35"></a>

### 10.6 形成一个可以复查的结论

最终报告写明服务总体、测试月份、样本与建筑数量、排除规则、主要基线、主指标、关键分组、资源约束和未覆盖场景。结果应描述完整方案改善了什么，不把一次离线高分扩展为所有建筑与所有季节的保证。对于陌生建筑或极端天气样本不足的部分，明确证据限制并安排后续收集。

报告还应说明哪些结果来自实际执行、哪些只是理论推导或压力测试。对本章算例而言，手算指标不是训练一个真实能耗系统的实测结果。学习时保持这种区分，有助于在自己的项目中避免把合理设计当作已经验证的成功。

<a id="diagnosis"></a>
## 11. 故障定位与研究延伸

<a id="detail-36"></a>

### 11.1 按信息链定位，而不是先责怪模型容量

上线突然退化，先核对请求覆盖、字段单位、类别映射与时间，再检查中间特征、分数、阈值与实际行动，最后连接成熟标签。若离线和线上同一原始请求已不同，优先解决系统一致性；若输入与预测一致而标签关系变化，再研究统计漂移。

这种顺序并不意味着复杂模型永远无关，而是先排查能够直接解释异常的链路。更换模型会同时改变很多东西，可能暂时掩盖接口问题。定位时保存最小复现样例与版本归属，确认修复不仅改善某一个记录，也没有破坏其他合法行为。

<a id="detail-37"></a>

### 11.2 数据质量、模型误差与行动执行可以分层分解

某次收益下降可能来自覆盖不足：大量请求进入回退；也可能来自预测质量下降；还可能预测正确但行动没有执行或执行延迟。总体业务结果是多层机制的共同产物。监测只看模型损失，会漏掉执行问题；只看业务总量，又无法区分季节变化和模型贡献。

可以把服务覆盖、预测误差、行动一致率与最终结果分别记录，并通过样本链连接。分层不是为了把责任拆散，而是让修复针对真正瓶颈。各层指标的关系往往不是简单乘法，应基于具体系统计算，不能用一套固定漏斗公式替代机制分析。

<a id="detail-38"></a>

### 11.3 部署反馈与选择性标签

风控模型决定哪些申请获批，推荐模型决定哪些内容被展示，审核模型决定哪些样本得到人工标签。后续训练数据因此受历史模型影响。若新模型只在这些可见结果上评估，可能忽略未尝试行动或被筛除群体，形成反馈循环。

记录行动与采样机制、维持适当覆盖或设计随机复核，可以帮助研究这种问题，但每种方式都有成本与假设。纯预测模型不能凭空恢复未观察反事实。上线监测需要知道标签为何出现，而不只是等待标签到达。

<a id="detail-39"></a>

### 11.4 自动化应自动执行规则，也保留可解释边界

自动训练、评价和发布可以减少重复劳动，但自动化必须有明确输入、成熟条件、验证对象与失败行为。如果任何漂移都触发重训、任何更低训练损失都触发发布，自动化只是更快重复错误。应先建立可回放的更新规则，再决定哪些步骤适合自动执行。

人类审查也不是万能保证。若每次审查都根据同一个测试分数挑选方案，同样会适应噪声。关键是信息与选择边界，而非流程由人还是机器完成。研究系统应把人工与自动步骤都作为完整算法的一部分。

<a id="detail-40"></a>

### 11.5 用组成标准化区分“人群变了”与“组内变差”

设系统服务容易组与困难组，旧错误率分别为零点一与零点四，旧流量比例为零点八与零点二，总错误率为零点一六。如果新流量比例变为零点四与零点六，而组内错误完全不变，总错误率就变为零点二八。告警反映真实总体成本上升，但不证明模型在相同组内能力退化。

可以同时计算原始总体指标与固定参考组成指标。后者始终使用旧比例加权当前组内误差，本例仍为零点一六。两者差异帮助定位组成变化。该标准化不是说当前总体成本不重要，而是把“服务对象更难”与“同类对象表现变差”拆开，指导是补容量、补覆盖还是修复模型。

还存在相反的掩盖：旧比例为零点二、零点八，旧组内错误零点一、零点四，总体零点三四；新组内错误都恶化到零点一五、零点四五，但流量变成零点八、零点二，总体却降到零点二一。只看平均会宣布改善，实际上两组都退化。固定旧组成下，新错误率为零点三九，能揭示被组成掩盖的变化。

标准化依赖组定义、组内样本量与覆盖。若新出现一个旧数据没有的来源，不能用旧风险填补后声称没有问题；应单独报告未知组及其覆盖，补充成熟标签。分组也不应无限细到每组几乎无数据，实际需要在可解释结构与估计稳定性之间平衡。

<a id="detail-41"></a>

### 11.6 同一批配对损失怎样支持版本比较

对相同成熟样本记录旧版损失与新版损失，定义差值 $`d_i=\ell_{old,i}-\ell_{new,i}`$。正均值表示新版在这批样本上更好。配对分析保留样本难度共享的信息，通常比把两个平均值视为独立更符合设计；如果同一建筑连续多日相关，重采样与不确定性计算还应尊重建筑和时间结构。

给出一个纯数值例子。四条旧损失为一、九、四、十六，新损失为二、四、五、九，差值为负一、五、负一、七，平均二点五。总体改善来自第二与第四条，另两条变差。报告差值分布、重要组与极端退化，比只说新平均损失从七点五降到五更有解释力。

如果这四条正是开发者反复挑模型使用的样本，配对计算正确也不会恢复独立性。统计公式只能利用既有设计，不能洗去选择历史。同样，如果新模型日志缺少最难请求，必须先对齐完整样本与回退行为，否则所谓配对只比较了有利子集。

<a id="detail-42"></a>

### 11.7 标签延迟会造成什么样的表面改善

假设某批一百个预测，最终有二十个失败与八十个成功。失败通常当天被报告，成功需要七天确认。第二天只收到二十个失败标签，若只对已到结果计算，失败率是百分之百；若把另外八十个暂时记为成功，又恰好得到百分之二十，但这次“准确”依赖事先知道了最终分布，不是合法估计。

下一批如果成功比例不同，或者失败也有延迟，这种临时填补会产生任意偏差。正确处理应以预定成熟队列为分母，或使用有明确条件的延迟模型。监控看板可以展示“已到标签中的比例”，但必须同步展示到达覆盖，并明确它与最终队列指标不同，避免把采集速度变化误读为模型变化。

<a id="detail-43"></a>

### 11.8 覆盖率与回退风险怎样组成真实系统风险

把请求分成模型成功服务集合 $`A`$ 与进入回退的集合 $`A^c`$。根据全期望公式，完整系统风险为 $`P(A)E[\ell\mid A]+P(A^c)E[\ell\mid A^c]`$。这是一条精确分解，不需要两组相互独立。两组条件风险可能随着版本一起变化，所以不能只比较成功请求上的模型损失。

假设旧版覆盖率零点九九，成功请求错误率零点零五，回退错误率零点五，则完整错误率为 $`0.99\times0.05+0.01\times0.5=0.0545`$。新版成功请求错误率改善到零点零三，但覆盖率降为零点八，回退错误率仍为零点五，完整错误率反而为 $`0.8\times0.03+0.2\times0.5=0.124`$。只看有预测日志的行，会错误宣布新版显著更好。

如果新版拒绝的恰好是困难请求，它在成功集合上的低错误还包含选择效应，两版本条件总体已不同。可以在共同请求队列回放全部行为，将拒绝、超时和默认行动都映射到实际成本，或分别报告覆盖与条件风险。没有回退真值时，应明确完整风险尚不可计算，而不能把缺失结果默认为成功。

该分解还帮助决定修复优先级。若主要损失来自接口失败，先改善服务覆盖可能比微调模型带来更大收益；若覆盖已高但某关键组预测差，才针对模型与数据。系统优化应围绕请求总体的真实结果，而不是最容易记录的局部指标。

<a id="sec-7"></a>
## 12. 分层练习与详细解析

<a id="detail-44"></a>

### 12.1 接口练习：同权重为何不同预测

**题目。** 一个模型训练时金额单位为元，线上单位为分；标准化和权重没有变化。程序没有报错，是否说明部署正确？如何设计最小检查？

**解析。** 不能。数值类型合法并不等于语义正确。选择一条已知金额请求，逐层核对原始值、单位转换、标准化、分数和行动；再覆盖零、缺失、极端金额与不同来源。只比较最终平均概率可能掩盖局部错误。修复后应检查整组样例，确保没有对原本正确来源重复除以一百。

<a id="detail-45"></a>

### 12.2 标签练习：近期队列为何看似更好

**题目。** 目标为未来七天事件，监控把最近三天尚未发生事件的样本都标零，准确率明显提高。应如何修正？

**解析。** 近期目标未成熟，未知不等于负例。按预测日期分队列，等待七天及缓冲后评价，并同时展示标签覆盖与到达延迟。若必须提前估计，需要删失或延迟模型及其假设，而不是直接填零。不同来源延迟不同时，还要检查早到标签是否具有选择性。

<a id="detail-46"></a>

### 12.3 漂移练习：边缘稳定也能彻底失效

**题目。** 旧环境 $`Y=X`$，新环境 $`Y=1-X`$，输入为公平二元变量。旧模型预测 $`X`$。计算两边输入均值、目标均值与错误率。

**解析。** 两边输入均值和目标均值都为二分之一，预测分布也不变；错误率从零变为一。条件关系改变而边缘不变，所以监测均值或基率不足。必须连接预测与成熟结果。这个反例不说明无标签监控无用，只说明它不能为所有机制变化提供保证。

<a id="detail-47"></a>

### 12.4 监测练习：分箱距离如何解读

**题目。** 参考箱比例为零点八、零点二，新比例为零点六、零点四。计算第八节统计量，并说明为何不能据此直接发布新模型。

**解析。** 值为 $`(-0.2)\log(\frac{0.6}{0.8})+0.2\log(\frac{0.4}{0.2})\approx0.1962`$。它说明这个分箱表示发生变化，但与性能的联系取决于变量作用、区域难度与样本量。应核查数据契约、关键分组和成熟结果，再决定修复还是更新。即使确实需要更新，候选也要通过共同数据比较。

<a id="detail-48"></a>

### 12.5 评价练习：固定模型与学习规则

**题目。** 开发者看了一百个测试分数后选最好权重，再把该权重保存并只运行一次最终测试。是否恢复了独立性？

**解析。** 没有。最后只运行一次不抹去此前使用测试信息的历史。测试已经参与选择，最好分数包含选择幸运。应在开发内部完成选择，再用新的独立数据评价；若评价整个调参规则，可以使用合适外层设计。给同一个集合改名或重复运行不能创造新证据。

<a id="detail-49"></a>

### 12.6 实验练习：一个百分点提升够不够

**题目。** 随机独立两组各一千，比例零点五与零点五一，与第九节的零点零五和零点零六相比，哪一种差值标准误差更大？这说明什么？

**解析。** 前者标准误差约为 $`\sqrt{0.5\times\frac{0.5}{1000}+0.51\times\frac{0.49}{1000}}\approx0.02236`$，大于后者约零点零一零一九。相同绝对提升与样本量下，不确定性取决于基率。统计证据还受随机单位和依赖影响，不能只按“提升一个百分点”判断。业务价值则又取决于规模和成本，是另一个维度。

<a id="detail-50"></a>

### 12.7 版本练习：回退权重为什么不够

**题目。** 新版改变了类别索引并更新模型，出现故障后仅恢复旧权重，保留新索引。是否真正回退？

**解析。** 不一定。旧权重的每个输入位置对应旧类别语义，新索引会把同一请求送入不同位置。应恢复相互依赖的预处理、类别表、后处理与模型，或使用明确兼容转换。回退后仍要逐层比较固定原始样例，不能只看服务恢复返回值。

<a id="detail-51"></a>

### 12.8 项目练习：影子运行能否证明节能

**题目。** 新能耗模型影子运行误差更低，但实际控制策略仍用旧模型。能否声称新模型已经节能？

**解析。** 只能说明在旧行动产生的数据上观察到预测改善及服务可行性，未直接测量新行动的能源影响。节能需要说明控制策略如何使用新预测，并通过适当实验或识别设计比较结果。天气、建筑使用和持续效果可能造成混杂，应选择合理随机单位或对照，而不是直接比较上线前后总能耗。

<a id="detail-52"></a>

### 12.9 指标练习：平均更好为何仍可能不适用

**题目。** 第十节候选 MAE 与 MSE 都更低，为何仍需检查最大误差、偏差和分组？

**解析。** 候选把误差集中到一个样本，最大误差从二十变为三十，平均有符号误差从零变为七点五。若极端缺口成本大或某关键组承担全部退化，平均改善可能不符合用途。多指标不是事后挑选，而应由任务预先规定主目标与关键约束。四个示例不足以证明真实统计差异。

<a id="detail-53"></a>

### 12.10 研究练习：告警次数如何进入保证

**题目。** 每次检验失败概率分配为 $`\frac{\alpha}{[m(m+1)]}`$，证明总分配为 $`\alpha`$。这个分配能否修复一个原本无效的检验？

**解析。** 利用 $`\frac{1}{[m(m+1)]}=\frac{1}{m}-\frac{1}{(m+1)}`$，前 $`M`$ 次和为 $`1-\frac{1}{(M+1)}`$，极限为一，所以总和为 $`\alpha`$。联合界因此能控制各次有效错误事件的并集。它不能修复单次检验假设不成立、损失依赖未处理或信息重复适应等问题。概率预算只连接有效事件，不凭空使无效统计量有效。

<a id="sec-8"></a>
## 13. 进阶研究练习与解析

<a id="detail-54"></a>

### 13.1 无信号搜索为何产生进步幻觉

**问题。** 在随机标签上尝试越来越多候选，开发集最好分数提高，是否说明模型逐渐发现隐藏规律？如何设计实验区分？

**解析。** 更多候选增加适应开发噪声的机会。应在独立训练与开发之外保留未参与选择的测试，并固定标签生成机制没有真实可预测信号。逐步增加候选预算，记录最好开发分数与被选模型测试分数。若前者提高而后者维持基率水平，支持选择幸运解释。注意不能反复根据测试表现修改实验而仍把它当完全独立确认。

可以进一步比较候选相关性：一组模型只是微小参数变化，另一组预测相对独立，开发最优值的波动可能不同。这研究的是搜索空间与噪声关联，而不只是候选计数。实验中报告完整分布和预算，比只画一条最好曲线更有解释力。

<a id="sec-8-1"></a>
### 综合练习：检查高分任务是否定义正确

**问题。** 延迟订单模型准确率百分之九十九，特征包含最终签收时间和未来天气实测。开发者提出保留这些列，但加大正则强度来减少泄漏。请给出完整修复和验收顺序。

**逐步解析。** 先固定预测时点，说明在交接时两列为何不可获得；删除或改为当时可见的历史与预报版本。然后按事件、入库和标签成熟时间重建特征，检查聚合是否仍间接包含未来。重新建立模拟部署的时间划分和真实可替代基线，再在开发部分完成预处理拟合、调参与阈值选择。

最终在新的独立时间段评价完整系统，同时检查未知线路、标签延迟和服务契约。原高分不应作为合法基线；更强正则也不能让未来字段变成当时已知。验收至少包含一条原始请求的历史可见性证明、一个中间特征回放、一个成熟标签连接，以及新旧方案在共同合法协议下的比较。

<a id="detail-55"></a>

### 13.2 反馈系统的目标能否保持不变

**问题。** 新风险模型上线后，系统拒绝更多申请，后续观察到的违约率下降。能否据此证明模型对所有申请者的预测更准？

**解析。** 被观察到还款结果的人群已经改变，违约率下降可能来自选择更严格，而非原总体预测改善。被拒者的获批后结果没有被观察，存在选择性标签。需要明确目标是获批群体风险、所有申请风险还是策略收益，并收集相应证据。历史策略日志、适当随机审核或其他识别设计可能有帮助，但都需要覆盖与假设。

这个问题揭示学习闭环的深层逻辑：模型改变行动，行动改变未来数据，未来数据又训练下一模型。更新规则如果忽略观察机制，可能不断强化自己造成的样本选择。研究应把环境与行动纳入数据生成图，而不是只把新日志看成更多独立标签。
