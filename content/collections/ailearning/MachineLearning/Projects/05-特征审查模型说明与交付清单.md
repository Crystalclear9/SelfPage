## 1. 先确定交付的是哪个函数

<a id="project-5-detail-2"></a>
### 1.1 权重只是完整预测链的一部分

把完整系统写成 $`F=Q\circ M\circ T\circ V`$：输入验证与规范化 $`V`$，已拟合前处理 $`T`$，参数化模型 $`M`$，以及阈值、逆变换或拒绝规则 $`Q`$。即使模型权重完全相同，列顺序、单位、类别映射或后处理不同，也可能得到另一套行为。交付身份应绑定这条链，而不只给某个权重文件取名。

对回归，输出需说明目标单位、是否经过指数还原、是否截断范围以及是否附区间。对分类，概率矩阵的每一列对应哪个类别必须明确，阈值也不能隐含在调用者记忆中。模型文件能够打开，只证明序列化格式可读取，不证明完整函数已被重建。

可以先定义一个最小正确性问题：给定同一批合法原始输入，参考流程与交付入口是否在约定容差内输出相同结果。它检验实现恢复，不直接检验模型在新总体中是否有效。统计效果需要独立数据，服务延迟需要相应运行环境，训练恢复还需要额外优化器和随机状态。三种验收各有对象。

<a id="project-5-detail-3"></a>
### 1.2 交付边界与调用者责任

接口应说明接收原始字段还是已变换数组。如果接收原始字段，前处理应该由交付包拥有；如果接收标准化数组，调用者就必须持有同一模式与变换版本。两种方案都能实现，但不能一边宣称封装原始输入，一边把填补、编码和列排序留成未经记录的隐含动作。

拒绝、回退与正常预测也应是不同状态。缺少必需字段可以直接拒绝，可选缺失按已保存规则处理，未知类别可以进入明确回退并标记。一个统一的浮点输出无法告诉使用者是否发生了支持不足或规则替换，因此输出可附非敏感状态与版本信息，而不是悄悄掩盖所有异常。

<a id="sec-1-1"></a>
<a id="project-5-detail-4"></a>
### 1.3 一条原始样例怎样逐步复算

假设两个字段分别为负载与摄氏温度，训练中心为一、二十，尺度为二、五，权重为三、负二，截距十。输入负载三、温度二十五，标准化后为一、一，预测为十一。若把温度二十五误放在负载列，程序仍可能算出数字，却不再对应原定义。

固定样例应保存字段名、单位、缺失表示、变换后顺序与参考输出，并说明容差。单个样例不能覆盖全部函数，但能迅速发现列交换、重复标准化和错单位等常见问题。还应补缺失、边界、未知类别和错误输入，让验收有明确失败路径，而不只证明正常样本可以运行。

<a id="visual-projects-05"></a>
### 图解：交付的单位契约：同一物理输入必须产生同一结果

![交付的单位契约：同一物理输入必须产生同一结果](images/05-concept.svg)

上方两条对齐数轴表示同一物理时长：$`u=1000t`$，其中 $`t`$ 按秒计、$`u`$ 按毫秒计。模型在秒接口上为 $`f(t)=0.5t`$，所以毫秒入口的完整函数必须满足
$$
h(u)=f\left(\frac{u}{1000}\right)=\frac{u}{2000}.
$$
图中的两条合法路径追踪同一个两秒对象：直接送入秒模型得到一；以两千毫秒进入适配接口，经除以一千再调用同一模型，也得到一。等式 $`h(1000t)=f(t)`$ 对全部合法时长成立，不只是这一个测试点。对一、二、三秒，两个入口依次给出 $`0.5,1,1.5`$，可以作为同一性质的多个回放样例。

漏掉适配时，直接计算 $`f(2000)=1000`$，输出相对正确值放大一千倍；对一秒对象，相应错误是五百而非零点五。权重和文件摘要完全可以保持不变，错误发生在输入解释。因而字节完整性与单位契约需要分别验收：前者确认载入了哪份产物，后者确认产物是否作用于定义的物理量。对于摄氏与华氏等含偏移的换算，仅调整比例还不够，后文第11.2节会推导系数、截距与范围的一致变换。

这张图只核验单位机制；完整交付还需固定字段名称、缺失策略、预测时点、前处理和阈值版本，并由独立入口重建同一行为。

<a id="project-5-detail-5"></a>
## 2. 输入模式：名称、类型、单位与范围

<a id="project-5-detail-6"></a>
### 2.1 字段名相同不表示语义相同

一个名为 temperature 的字段可能是摄氏温度、华氏温度，也可能是过去一小时均值或当前瞬时值；age 可能按天、月、年计算。模式应同时说明业务含义、单位、时间窗口和来源。只保存一串列名，不足以阻止同名异义字段接入。

类型也要具体。整数编码不一定是有序数值，布尔类型在某些语言中又可被当作整数接收，数值字符串可能包含空格或地区格式。接口应先确定允许的输入形式，再进行显式转换；不要让解析器的宽松默认值替项目决定含义。特别是把解析失败统一转换为缺失，会隐藏数据管线错误。

<a id="project-5-detail-7"></a>
### 2.2 范围检查能发现什么，不能发现什么

物理或协议上的硬范围可拒绝明显非法值，例如负载比例超出系统允许区间。但训练分位数不等于物理界限，合法罕见输入与错误输入要区别处理。可以同时保留硬约束和软支持诊断，前者决定能否计算，后者提示是否超出已评价范围。

单位错误也不总能靠范围识别。二十五摄氏度与二十五华氏度都可能处于某个宽数值区间，程序无法从数字本身推断真实单位。应由带单位的接口或受控适配器转换，并把适配规则版本化。对来源不明的数据，范围检查通过不构成语义正确的证据。

<a id="project-5-detail-8"></a>
### 2.3 自包含实验：拒绝错误模式并保留名称语义

下面定义一个只接收两字段的小接口。它接受数值或明确缺失，拒绝布尔、字符串、非有限值、额外列与不符单位；读取顺序由保存模式决定，而非字典插入顺序。该严格接口是教学设计，可以根据实际需求调整，但每个放宽都应有清楚语义。

```python
import math
import numpy as np

NAMES = ("load", "temperature")
UNITS = {"load": "unitless", "temperature": "degC"}
CENTER = np.array([1., 20.]); SCALE = np.array([2., 5.])
MEDIAN = np.array([1., 20.]); COEF = np.array([3., -2.])
LIMITS = {"load": (0., 5.), "temperature": (-20., 80.)}

def predict(request):
    if not isinstance(request, dict) or set(request) != {"values", "units"} or request["units"] != UNITS:
        raise ValueError("request structure or units mismatch")
    values = request["values"]
    if not isinstance(values, dict) or set(values) != set(NAMES):
        raise ValueError("feature names mismatch")
    row = []
    for j, name in enumerate(NAMES):
        value = values[name]
        if value is None:
            value = MEDIAN[j]
        elif isinstance(value, bool) or not isinstance(value, (int, float)):
            raise ValueError("numeric or explicit missing required")
        if not LIMITS[name][0] <= value <= LIMITS[name][1] or not math.isfinite(value):
            raise ValueError("value outside contract")
        row.append(value)
    return float(((np.array(row)-CENTER)/SCALE) @ COEF + 10)

valid = {"values": {"temperature": 25., "load": 3.}, "units": UNITS.copy()}
assert np.isclose(predict(valid), 11)
missing = {"values": {"load": None, "temperature": 25.}, "units": UNITS.copy()}
assert np.isclose(predict(missing), 8)
bad = [
    {"values": {"load": 10**400, "temperature": 25.}, "units": UNITS},
    {"values": {"load": -(10**400), "temperature": 25.}, "units": UNITS},
    {"values": {"load": True, "temperature": 25.}, "units": UNITS},
    {"values": {"load": "3", "temperature": 25.}, "units": UNITS},
    {"values": {"load": 3., "temperature": float("nan")}, "units": UNITS},
    {"values": {"load": 3., "temperature": 25., "target": 11.}, "units": UNITS},
    {"values": {"load": 3., "temperature": 25.},
     "units": {"load": "unitless", "temperature": "degF"}},
]
for request in bad:
    try:
        predict(request)
    except ValueError:
        pass
    else:
        raise AssertionError("invalid request was accepted")
print("schema, missing policy, units and reference predictions passed")
```

<a id="project-5-detail-9"></a>
### 2.4 缺失值、未知类别与拒绝覆盖率

填补不是恢复真值，而是按训练规则生成可计算表示。需要保存训练中位数、指示列和类别表，不能在每个请求或测试批次重新估计。未知类别的回退也应固定，特别是类别顺序、被丢弃的基准类和输出列数不能依赖当前批次临时出现了什么。

若接口拒绝一部分请求，模型效果必须与覆盖率一起报告。仅对最容易的已接受样本计算较低 MAE，不能直接与处理全部请求的模型比较。拒绝原因、各群体覆盖与下游回退成本也属于系统表现。合理拒绝有价值，但不能通过隐藏未服务样本制造虚假改进。

## 3. 特征审查从来源与时间开始

<a id="project-5-detail-11"></a>
### 3.1 建立字段依赖图

对每个特征记录原始来源、转换规则、拟合状态与可得时点。聚合特征需要写出窗口、实体键、迟到数据和修订规则；编码特征需要写出词表、统计来源和未知处理。这样才能沿依赖图检查输入究竟来自当时可用信息，还是从结果或未来记录倒流。

一个看似普通的维修次数，可能包含预测之后发生的维修；一个风险标记可能由最终标签回写；一个账户状态可能是今天的最新值而非历史时点值。即使这些列在当前表中完整存在，也不能直接用于历史预测。字段审查应把数据提取版本和时间合法性一起核对。

<a id="project-5-detail-12"></a>
### 3.2 用反事实约束检查不可用信息

若只追加可用时间晚于预测时点的记录，过去特征不应改变；若把测试标签替换为另一组值，已冻结训练流程和特征不应读取它们；若调换无关字段顺序，命名接口的预测不应改变。这些性质能够针对特定泄漏建立检查，但不是所有数据错误的完备证明。

标签本身允许来自未来观察窗，但训练时需等待成熟，并区分事件发生与标签何时记录。特征截止时点与标签确认时点职责不同，不能用统一的时间小于训练截止条件混在一起。版本修订、删除和新群体信息还需明确重放规则，具体查询可对照数据库主题。

<a id="project-5-detail-13"></a>
### 3.3 实验：事件早于预测仍可能不可用

下面以小型记录表检查可得时点。历史事件如果晚入库，不允许进入当时预测；未来新记录也不能改变已定义的过去特征。代码不是数据库引擎实现，只是为字段可见性提供独立参考。真实系统还应把版本选择与业务窗口接入同一个协议。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Event:
    event_time: int
    available_time: int
    value: float

def historical_sum(events, cutoff):
    return sum(e.value for e in events
               if e.event_time < cutoff and e.available_time <= cutoff)

base = [Event(2, 2, 3.), Event(4, 8, 100.), Event(5, 5, 7.)]
assert historical_sum(base, 6) == 10
assert sum(e.value for e in base if e.event_time < 6) == 110
future_append = base + [Event(3, 10, 500.), Event(9, 9, 20.)]
assert historical_sum(future_append, 6) == historical_sum(base, 6)
assert historical_sum(base, 9) == 110
print("event time and availability boundary checks passed")
```

<a id="project-5-detail-14"></a>
### 3.4 来源捷径与部署可获得性

某些字段时间合法、统计上也有预测力，却主要识别来源、设备身份或标注流程。若部署换来源，这种依赖可能失效。可以按来源留出、遮蔽身份代理、检查数据收集过程并分析残差，形成多种证据。不能仅因为某列重要就认定它是稳定机制，也不能只看名称是否像身份判断代理风险。

特征是否容易取得也是模型成本。昂贵传感器、人工审核或外部查询的依赖应进入延迟、费用和缺失回退评价。删去一个高成本字段后性能略降，可能仍是更合适方案；但取舍需要共同目标与独立评价，不能只给一张重要性图就代替项目决策。

## 4. 固定模型的特征依赖：先定义扰动分布

<a id="project-5-detail-16"></a>
### 4.1 置换重要性是一个风险差

设评分使用损失，固定模型为 $`f`$，在评价总体上的风险为 $`R(f)`$。将第 $`j`$ 个字段按某种规则置换，得到风险 $`R_j^{perm}(f)`$，差值 $`\Delta_j=R_j^{perm}(f)-R(f)`$ 描述该模型在这种扰动下损失增加多少。若库使用越大越好的评分，符号相应写成原评分减扰动评分，必须与接口约定对齐。

置换保持单列边缘分布，却通常破坏它与其他列及标签的关系。如果原数据里两个字段几乎满足确定关系，独立置换会生成训练和部署中不可能出现的组合。得到的大误差可能部分来自范围外输入响应，不宜直接解释为现实中移除该测量后的性能损失。扰动应有明确科学问题，而不是任意打乱后统一称为重要性。

对固定模型置换不重新训练，衡量当前函数依赖。删除字段并重训，衡量学习规则在其他信息可替代时能做到什么。条件置换试图保留给定其他特征的分布，又提出条件生成模型的要求。三者都可能有用，但不应混为一个无条件的“变量真实价值”。

<a id="project-5-detail-17"></a>
### 4.2 相关字段的可替代性与组扰动

两个重复传感器都包含同一个信号，线性模型可能把权重分到两列。删掉任意一列重训仍可完整恢复信号；固定模型单列置换却会改变输出；把两列共同置换又会保留两列一致性，但破坏它们与原目标的对齐。不同实验结果并不冲突，因为它们干预的对象不同。

若业务成本以传感器组计算，可以按组共同扰动，并保留组内结构。组重要性也不能简单等于各列独立重要性之和，交互、相关与非线性会改变组合。实际选择应结合重训、缺失回退与采集成本，而不是拿某个大分数直接证明传感器不可替代。

<a id="project-5-detail-18"></a>
### 4.3 实验：重复信号的三种审查得到不同答案

下面使用五点、两个完全相同字段，线性回归分配相同权重。反向排列单字段让两个输入互相抵消，整体反向排列保留两列一致却改变标签对齐；删去一列重训则仍精确拟合。反向排列是一个具体压力测试，随机多次置换的平均数值会不同。

```python
import numpy as np
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error

x = np.array([-2., -1., 0., 1., 2.])
X = np.column_stack([x, x]); y = x.copy()
f = LinearRegression().fit(X, y)
assert np.allclose(f.coef_, [.5, .5])
assert np.isclose(mean_squared_error(y, f.predict(X)), 0)
one = X.copy(); one[:, 0] = one[::-1, 0]
both = X[::-1].copy()
assert np.isclose(mean_squared_error(y, f.predict(one)), 2)
assert np.isclose(mean_squared_error(y, f.predict(both)), 8)
refit = LinearRegression().fit(X[:, [1]], y)
assert np.isclose(mean_squared_error(y, refit.predict(X[:, [1]])), 0)
assert np.isclose(mean_squared_error(y, np.full_like(y, y.mean())), 2)
print("single permutation MSE 2; group permutation MSE 8; refit one field MSE 0")
```

这个例子不是比较泛化性能，因为数据极小且用于定义反例。它说明一个固定函数的扰动敏感性不能自动代替重训后的信息价值。真实项目应在合法评价样本上、按训练边界重训并给出不确定性；多次置换还应保持同一随机样本对照，避免比较噪声主导结论。实现细节可核对[官方置换重要性指南](https://scikit-learn.org/1.8/modules/permutation_importance.html)。

<a id="project-5-detail-19"></a>
### 4.4 重要性为负与不稳定怎样解释

有限评价数据上，扰动后损失偶然下降可能得到负重要性；过拟合或不良依赖也可能使平均扰动有改善。它不是自动证明这列在任何模型中有害，应结合重复扰动、支持、相关结构与重训对照。仅把所有负数截成零，会隐藏模型可能利用错误信号的线索。

还应先检查模型在目标数据上是否有实质预测力。一个整体表现很差的模型，其小重要性不说明数据里没有可用信息；它可能根本没学到。依赖审查应与基线、主指标和适用总体一起阅读，而不是脱离模型表现孤立给变量排名。

### 深入图解：边际置换相关特征可能制造原数据之外的组合

![边际置换相关特征可能制造原数据之外的组合](images/05-insight.svg)

图与第4.3节代码使用同一次反向置换。原始五个对象 A 至 E 的两个字段与标签均为 $`x=(-2,-1,0,1,2)`$；固定模型为 $`f(x_1,x_2)=\frac{x_1+x_2}{2}`$。箭头将每一个对象从 $`(x,x)`$ 水平移至 $`(-x,x)`$，始终保持第二字段与标签身份。橙圈不代表新采集对象，也不能按最近位置重新配标签。除中心对象外，扰动坐标都离开原联合支持 $`X_1=X_2`$，所以这是一项明确的范围外压力测试。

预测由原来的 $`x`$ 变为零，各对象平方损失为 $`4,1,0,1,4`$，平均为二。这个数对应图示的**确定反向排列**，不能不经计算就当作普通随机置换重要性的期望。对任一排列 $`\pi`$，
$$
L_\pi=\frac15\sum_{i=1}^{5}
\left(x_i-\frac{x_{\pi(i)}+x_i}{2}\right)^2
=\frac1{20}\sum_{i=1}^{5}(x_i-x_{\pi(i)})^2.
$$
若从全部 $`5!=120`$ 种排列中均匀抽取，每个 $`x_{\pi(i)}`$ 的边缘均值为零、二阶矩为二，因此
$$
E_\pi[L_\pi]=\frac14\big(E[X^2]+E[X'^2]-2E[X]E[X']\big)=1.
$$
这里独立性用于对随机行与随机排列联合平均后的单位置边缘，不要求同一次排列中五个位置彼此独立；逐项期望相加就足够。枚举全部一百二十种排列也得到一。反向排列恰好产生最强负相关，因此损失二高于随机平均一，显示“如何扰动”本身就是被研究对象。

本图将对象身份、支持关系和模型损失放在同一条证据链上；固定模型依赖仍不能代替删字段后重训的价值。与 [官方置换重要性算法](https://scikit-learn.org/1.8/modules/permutation_importance.html#outline-of-the-permutation-importance-algorithm)对照时，应保持评分方向、重复方式与评价集不变，并分别声明边缘置换、条件置换和联合扰动的问题。

## 5. 局部解释：参照与条件化决定答案

<a id="project-5-detail-21"></a>
### 5.1 一次预测的解释需要一个对照世界

局部贡献通常把某次输出与一个参照值比较。参照可能是背景数据平均预测、某个基准样本或合法默认输入。选择参照改变“为何比什么高”的问题。模型的高输出不必表示相对所有参照都高，跨群体使用同一背景还可能掩盖不同基线。

在线性模型与固定中心下，单特征项可以直接展开；非线性模型中，交互与相关需要明确分摊规则。贡献相加恢复某个输出差异，是代数一致性，不证明分摊等于真实因果作用。解释既要说明模型和目标输出尺度，也要说明如何处理未观察或被移除特征。

<a id="project-5-detail-22"></a>
### 5.2 两字段 Shapley 的完整计算

对两字段的值函数 $`v(S)`$，贡献为 $`\phi_1=\tfrac12[v(\{1\})-v(\varnothing)+v(\{1,2\})-v(\{2\})]`$，第二字段类似。四个集合的取值先定义清楚，才能讨论贡献。常见选择是固定部分字段后对背景边缘取平均，或对与固定字段相容的条件背景取平均，两者处理相关性不同。

设背景等概率为负二、负二与正二、正二，模型只读取第一字段；解释正二、正二。边缘替换中，只固定第二字段不改变模型平均输出，贡献全给第一字段。条件解释中，第二字段已经能推断第一字段，因此两者各分一。第二字段在程序中没被读取，却可有条件信息贡献，这不矛盾，说明值函数的问题不同。

```python
import numpy as np

background = np.array([[-2., -2.], [2., 2.]])
point = np.array([2., 2.])
def model(rows):
    return rows[:, 0]
def intervention(S):
    rows = background.copy()
    for j in S:
        rows[:, j] = point[j]
    return model(rows).mean()
def conditional(S):
    keep = np.ones(len(background), dtype=bool)
    for j in S:
        keep &= background[:, j] == point[j]
    if not keep.any():
        raise ValueError("no background support")
    return model(background[keep]).mean()
def shapley2(value):
    v0, v1, v2, v12 = value(()), value((0,)), value((1,)), value((0,1))
    return np.array([.5*(v1-v0+v12-v2), .5*(v2-v0+v12-v1)])
phi_i = shapley2(intervention); phi_c = shapley2(conditional)
assert np.allclose(phi_i, [2., 0.])
assert np.allclose(phi_c, [1., 1.])
assert np.isclose(phi_i.sum(), 2) and np.isclose(phi_c.sum(), 2)
print("marginal replacement", phi_i, "conditional information", phi_c)
```


<a id="projects-shapley-information-dependence"></a>
#### 5.2.1 同一模型为何出现两套贡献

![同一背景分布在边缘替换与条件筛选下保留不同对象](images/05-shapley-information-vs-dependence.svg)

图先固定两个等概率背景对象 $`(-2,-2)`$ 与 $`(2,2)`$，灰虚线表示原支持关系 $`X_1=X_2`$；模型始终只读取第一字段 $`f(x_1,x_2)=x_1`$。现在解释对象为 $`(2,2)`$，先只知道第二字段等于二。两幅图操作的是同一背景，而非换了模型。

左图执行**边缘替换**：保留背景中的第一字段，把第二字段统一替换成二。负对象沿竖线移到 $`(-2,2)`$，正对象仍为 $`(2,2)`$，两者权重各半，所以 $`v_{\mathrm{marg}}(\{2\})=\frac{-2+2}{2}=0`$。橙点 $`(-2,2)`$ 已离开原支持线，这正是该操作制造的新输入组合。右图执行**条件筛选**：不移动原对象，只剔除与 $`X_2=2`$ 不相容的 $`(-2,-2)`$，留下 $`(2,2)`$，所以 $`v_{\mathrm{cond}}(\{2\})=2`$。知道第二字段携带了第一字段的信息，不等于程序实际读取了第二字段。

也可以不记组合系数，只平均两种等概率加入顺序。对条件信息：

- 先知第一字段再知第二字段：输出预期从 $`0`$ 升到 $`2`$、再保持 $`2`$，两个增量分别归第一字段 $`2`$、第二字段 $`0`$。
- 先知第二字段再知第一字段：输出预期同样从 $`0`$ 升到 $`2`$、再保持 $`2`$，这次增量分别归第二字段 $`2`$、第一字段 $`0`$。

每字段平均都为 $`1`$。对边缘替换，第二字段无论先后都不影响函数输出，增量恒为零；第一字段在两种顺序中都贡献 $`2`$。于是两组向量分别为 $`(1,1)`$ 与 $`(2,0)`$，却都精确加回 $`f(2,2)-\mathbb E[f(X)]=2`$。贡献和正确是必要的内部核验，无法独自决定哪种归因回答了项目的问题。

这里还需分清两个层次的“无贡献字段”。程序函数 $`f`$ 对第二字段完全不敏感；但条件值函数 $`v_{\mathrm{cond}}`$ 在加入第二字段时会增加，因为它携带关于第一字段的信息。因此，对**给定集合值函数**成立的 Shapley 公理，不会自动保证**另一个对象——程序函数**的未使用字段得到零分。若目标是检查实际计算依赖，应结合固定函数扰动、代码与输入链；若目标是分配背景分布中的预测信息，条件值函数可以是有意的选择。

[Sundararajan 与 Najmi 的 The Many Shapley Values for Model Explanation](https://proceedings.mlr.press/v119/sundararajan20b.html) 在第 2–3 节系统区分了这些值函数与“未使用字段仍获归因”的问题。该讨论也提醒我们：这里命名为边缘替换的操作只是对**模型输入**的替换；在没有真实结果的结构因果假设时，不能把它的贡献直接写成对现实目标的因果效应。

<a id="project-5-detail-23"></a>
### 5.3 解释图的验证与范围

应核对贡献之和恢复了哪个模型输出，分类中是概率、对数几率还是其他链接尺度；不同尺度的贡献不能直接混用。背景数据、近似方法和抽样误差也应记录。若解释对合理背景选择高度敏感，报告这种敏感性比挑一张最符合预期的图更有信息。

用户真正要问的可能是“若改变输入，会怎样”，这属于行动或干预问题。模型贡献不能自动回答因果效应，也不保证建议输入组合可行。应区分统计关联、模型敏感性、可操作变化与真实结果机制。预测项目能够明确给出的证据，应与它实际验证的层次一致。

## 6. 删特征重训与消融：评价一个学习规则

<a id="project-5-detail-25"></a>
### 6.1 每个版本都重新拟合完整变换

删除一个字段后，填补、缩放、编码和模型都应按新列集合重建，并在对应训练折拟合。如果先对全数据做监督筛选再删列比较，评价仍受到选择影响。对各候选设置相同数据角色和合理搜索预算，才能解释性能差异来自信息与模型，而非不同开发机会。

若某列可被其他列替代，删列后的性能可能保持；若模型存在交互，单独删两列的影响也不等于各自删列差的和。对高成本信息组，可以比较整组移除与不同采集策略。报告应同时列性能、覆盖、依赖和成本，而不是只把候选按一个最优分数排序。

<a id="project-5-detail-26"></a>
### 6.2 消融发现与最终选择分开

多个消融结果中挑最好者，本身就是模型选择。若都在最终测试上反复比较，再只给胜者区间，会忽略选择机会。可以在开发或嵌套流程中进行消融，把最终确认留给冻结协议；探索结果可以诚实报告，但不能称为未受选择的独立证据。

配对比较应保留相同样本或设备，并记录缺失和拒绝。移除某传感器后虽然 MAE 略升，却覆盖更多请求或降低成本，可能形成合理取舍；反之，小幅误差改善却依赖不可获得输入，不构成可交付优势。第五章的审查要把这些实际条件连接到模型说明。

<a id="visual-example-projects-05"></a>

### 图解算例：固定模型的依赖与删特征后的可替代性不同

![同一五点数据的单列置换联合置换和删除后重训](images/05-example.svg)

本图与第 4.3 节的可运行代码使用同一组数据：$`x=(-2,-1,0,1,2)`$，两个输入列都等于 $`x`$，标签也等于 $`x`$。不加正则的最小范数线性拟合平均使用两列，得到 $`f(x_1,x_2)=\frac{x_1+x_2}{2}`$；原样本上的 MSE 为零。

**只把第一列反向排列。** 第一列变成 $`-x`$，第二列及标签不动，固定模型的输出恰好全为零。五条平方误差为 $`4,1,0,1,4`$，平均为二。原模型确实依赖第一列，但这个扰动也打破了原先 $`X_1=X_2`$ 的支持关系。

**把两列作为一组共同反向排列。** 两列仍互相一致，却都与原标签错位，预测变成 $`-x`$。误差为 $`2x`$，因此 MSE 变为 $`4E[x^2]=8`$。这次扰动保留了组内特征关系，破坏的是整组与目标的关系，不能与单列实验混称。

**删除第一列后重新训练。** 新模型可仅用第二列恢复 $`y=x`$，MSE 回到零。图中对应蓝色直线，与原模型的预测重合；重合的是这一数据上的输出，模型参数和输入要求已经改变。

这个例子中的二与八来自明确的反向置换，未对随机排列取期望。固定函数的依赖、特征组信息和重新训练后的可替代性是三个不同对象；不能仅凭其中一个数声称某列“本质上重要”或“本质上无用”。第 4.3 节程序另外验证了这三种操作及对应误差。

## 7. 模型说明：让每个主张都有对应证据

<a id="project-5-detail-28"></a>
### 7.1 用途、对象与预测时点先于模型名称

模型说明首先写谁在什么时点、利用什么输入、预测哪一观察窗的目标。然后才写模型族、训练方式和超参数。一个模型名称无法说明目标总体、新设备或旧设备、单位与标签成熟时间，也无法替代数据来源和选择过程。

性能表应包含数据角色、样本数、独立单位数、基线、指标和选择规则。不同表格若来自不同产物或不同数据版本，应分别注明。分类还需基率、工作点与覆盖，回归应列目标单位与尾部或群体表现。错误分析应保留可核查样本角色，避免只展示最有利的几个案例。

### 7.2 一份与上一章结果对应的说明片段

可以把第四章产物称为“设备回归教学流程第一版”：训练来自四十八台开发设备，测试来自十二台外部设备，共九十六行；主要指标是 MAE，超参数在分组开发流程中选择。固定本章核对种子下，岭回归测试 MAE 约一点九二，均值基线约三点六五。说明应同时写它是人工数据教学结果，未覆盖新站点或真实设备。

限制不应只写“可能不准”，而应说明未评价哪些来源、合法范围在哪里、未知类别如何回退、标签多晚成熟、何种输入直接拒绝。每个主要结论链接到相应表或实验，每个尚未验证的推广对应补证据计划。这样读者可以判断某次使用是否仍在已支持范围内。

模型说明还应记录版本责任、更新条件与退出条件。预测接口恢复正确，但关键群体效果失败，仍不能宣称整个项目验收完成；性能指标符合预期但输入模式错位，也不能通过。交付完整性与统计证据需要共同成立，二者不能互相抵消。

## 8. 产物身份：格式、内容与来源分别固定

<a id="project-5-detail-32"></a>
### 8.1 一个最小包应该包含什么

可把交付包分为参数文件、机器可读清单、参考样例与报告证据。清单记录格式版本、模型身份、输入字段与单位、缺失策略、前处理规则、目标及后处理，并关联代码、数据、依赖和选择记录。某些小对象可直接放入一个文件，文件数量不是标准，关键是能否恢复完整函数。

本章最小实验将中位数、中心、尺度、系数和截距放入数组文件，将模式、规则与摘要放入 JSON。它只表达一个标准化仿射预测器，不尝试序列化任意 Python 对象。正式使用 Pipeline 时，应选择适合项目的保存机制，记录环境与依赖，并验证载入行为；格式能保存对象不意味着跨版本行为必然相同。

<a id="project-5-detail-33"></a>
### 8.2 摘要绑定字节，不自动证明真实性

内容摘要适合检测文件是否改变，并把报告关联到特定产物。如果压缩方式、字段顺序或浮点编码改变，即使数学参数相同，字节摘要也可能不同；反之，只摘要权重而遗漏前处理，无法识别完整函数改变。应说明摘要的对象与规范化规则。

摘要与来源认证也不同。若清单和文件同时被改写，新摘要仍可匹配，所以仅校验摘要不能证明谁生成、是否经过审查。受控发布位置、授权流程和需要时的签名承担另一层职责。本章实验只检验意外改动与产物错配，不把它扩展成完整发布安全体系。

<a id="project-5-detail-34"></a>
### 8.3 数据身份与可重建来源

数据目录名、日期或表名可以帮助查找，但内容可能被覆盖。应记录不可变快照或提取版本、查询与参数、划分键、标签成熟规则及必要摘要。若原始数据受访问限制，也应说明如何在合适权限下定位同一版本，而不是把个人临时路径写成唯一复现入口。

不要求每个项目复制全部原始数据进模型包，但必须能够解释模型依赖什么。转换词表、外部统计、预训练来源和人工映射都可能影响输出。任何没有进入依赖图、却在运行时参与预测的对象，都是交付审查应追踪的隐藏输入。

### 9.3 逐个解释验收断言

参数正规方程检查拟合的数学对象；摘要检查载入的是预期字节；形状和有限性检查恢复的结构；参考样例检查前处理、单位和输出链；新请求跨进程对比检查行为恢复；错误单位和文件改动检查失败路径；临时目录退出检查清理。每项支持不同结论，不能只因最后打印成功就忽略前置约束。

参考样例只是有限集合，两个不同函数可能在这些点相同。应选能区分常见错误的样例，例如温度不在中心、缺失值与普通值分别出现、列插入顺序不同、接近合法边界。正式回归集可逐步扩展，但不应把来自测试标签的期望输出混入训练或选择过程。

<a id="project-5-detail-39"></a>
### 9.4 同环境恢复与跨环境兼容

同一解释器的新进程验证去除了父进程内存依赖，却没有覆盖依赖升级、浮点库差异或硬件精度变化。跨环境测试应另外固定兼容策略与容差，核对预处理和数值结果。若某版本加载后预测有所不同，需要定位是序列化、接口默认值、数值求解还是不支持的算子，而不是只修改容差直到全部通过。

对于训练完整恢复，还要保存优化器、采样与随机状态、调度器及数据位置。本章小岭模型没有迭代优化状态，因此预测恢复较简单。把这个简化案例推广到深度学习训练时，不能只搬运权重和均值就宣称轨迹恢复一致，应回到 PyTorch 检查点主题核对额外状态。

## 10. 报告可复算：指标必须连到同一批预测

<a id="project-5-detail-41"></a>
### 10.1 保存逐行证据而不只保存截图

每条评价记录应关联样本标识、标签版本、预测器身份、预测值、是否拒绝及必要群体字段。报告脚本从这批记录计算指标与支持，避免手工在表格里抄写多个来源。分类类别顺序、回归目标单位和残差符号同样属于报告模式，不应靠图标题猜测。

若为了隐私或体量不能随包保留全部逐行数据，仍需给出受控可访问来源、指标定义、聚合规则与复算入口。不能只留下无法检索的数字。正式报告应说明哪些检查可由包内样例完成，哪些需要相应数据权限；可复查的边界应清楚，不要求公开不必要原始信息。

<a id="project-5-detail-42"></a>
### 10.2 实验：用标识连接，拒绝重复与漏行

下面故意打乱预测顺序，通过唯一标识连接标签再复算 MAE。若直接按位置配对，会得到错误结果；若存在重复或缺失预测，接口明确失败。本例还要求评价集合非空，标签与预测均为有限实数；空表不能被当作零误差，NaN 或无穷也不能作为一次成功评价的结果。真实分布式输出还可能有重试、重复和部分覆盖，不能用最终平均数接近预期来掩盖行级错配。

```python
import numpy as np

labels=[("a",1.0),("b",3.0),("c",8.0)]
predictions=[("c",7.0),("a",2.0),("b",4.0)]
def evaluate(labels,predictions):
    truth=dict(labels);pred=dict(predictions)
    if len(truth)!=len(labels) or len(pred)!=len(predictions):
        raise ValueError("duplicate sample identifier")
    if set(truth)!=set(pred):
        raise ValueError("prediction coverage mismatch")
    if not truth:
        raise ValueError("empty evaluation set")
    keys=sorted(truth)
    actual=np.asarray([truth[k] for k in keys])
    estimated=np.asarray([pred[k] for k in keys])
    for values in (actual,estimated):
        if (values.ndim!=1 or not np.issubdtype(values.dtype,np.number)
                or np.iscomplexobj(values) or not np.isfinite(values).all()):
            raise ValueError("finite real scalar targets and predictions required")
    # 用浮点减法避免整数残差回绕；中间计算溢出也不能产出成功指标。
    try:
        with np.errstate(over="raise",invalid="raise"):
            residual=actual.astype(np.float64)-estimated.astype(np.float64)
            mae=float(np.abs(residual).mean())
            bias=float(residual.mean())
    except FloatingPointError as error:
        raise ValueError("metric arithmetic overflow; rescale values") from error
    return mae,bias
mae,bias=evaluate(labels,predictions)
assert np.isclose(mae,1)
assert np.isclose(bias,-1/3)
wrong=np.mean(np.abs(np.array([v for _,v in labels])-np.array([v for _,v in predictions])))
assert not np.isclose(wrong,mae)
for bad in [predictions+[('a',2.)],predictions[:-1]]:
    try:
        evaluate(labels,bad)
    except ValueError:
        pass
    else:
        raise AssertionError("bad result table was accepted")
for actual,estimated in [([],[]),
                         ([("a",1.)],[("a",float("nan"))]),
                         ([("a",float("inf"))],[("a",1.)]),
                         ([("a",1+1j)],[("a",1.)]),
                         ([("a",1e308)],[("a",-1e308)])]:
    try:
        evaluate(actual,estimated)
    except ValueError:
        pass
    else:
        raise AssertionError("undefined or nonfinite metric was accepted")
# 有符号整数的减法应先转换，不能在 int64 内发生回绕。
wide=np.iinfo(np.int64).max
wide_mae,wide_bias=evaluate([("a",wide)],[("a",np.int64(-wide))])
assert wide_mae>1e19 and wide_bias>1e19
print("joined MAE/bias",mae,bias,"positional MAE would be",wrong)
```

### 10.3 覆盖、版本和后处理一起进入报告

两模型若输出集合不同，应在共同覆盖与全部请求层面分别报告，说明拒绝与回退成本；不能删去漏预测样本再让它们看起来拥有相同评价范围。标签更新后复算指标，也应生成新评价版本，保留旧结论对应的标签快照。

阈值、概率校准和目标还原改变时，权重可能不变，但系统决策已经变化。应给后处理新的身份或完整系统版本，并重新核对相关指标。一个不可变预测文件可以支持多种事后分析，但这些分析是否参与了选择，仍需记录，不能因文件固定就认为所有新结论天然独立。

## 11. 性质检查：有限样例之外怎样增加辨识力

<a id="project-5-detail-45"></a>
### 11.1 不变量来自接口，而不是所有模型通用

对按字段名读取的接口，合法列插入顺序改变不应改变预测；对逐请求独立预测器，把同一批分成两批后拼接，结果应保持；对已冻结的填补与缩放，新请求不应更新训练统计。这些性质来自该接口定义，可以击败一类隐藏状态错误，而不是简单多复制几个正常样本。

但如果系统本来定义了组内排序、批次配额或上下文联合预测，拆批可能合法地改变输出，不能把逐样本不变量无条件套用。测试前先写清函数是否有状态、批次上下文和时间依赖。训练模式 BatchNorm 与推理模式的差别也是一个例子：错误模式可能使同一请求随同批其他样本改变。

<a id="project-5-detail-46"></a>
### 11.2 单位转换应满足可交换关系

若适配器把华氏转换为摄氏，原接口与适配接口应对同一物理输入给出一致输出。这个关系需要同时变换数值和单位声明，不能只把清单里的单位字符串改掉。对一般仿射坐标变换 $`u'=au+b`$，保持线性函数相同需调整系数与截距；数值相同不代表语义相同。

例如原函数为 $`wu+c`$，代入 $`u=\frac{(u'-b)}{a}`$，得到新系数 $`\frac{w}{a}`$ 和新截距 $`c-\frac{wb}{a}`$，前提是 $`a\ne0`$。标准化中心、尺度和范围规则也要相应处理。用几个实际数值核对整个转换链，比只验证适配器单独能算出一个温度更能发现重复转换和漏转换。

<a id="project-5-detail-47"></a>
### 11.3 数值容差与决策一致不是一回事

参数与特征有小扰动时，线性输出差可按权重、输入误差和截距误差分别估计。输入范数很大，极小系数误差也可能放大；不同特征尺度会改变容差含义。因此容差应与输出单位、数值精度和用途相关，不能所有模型统一接受若干小数位差。

若分类决策阈值附近有很多样本，概率仅改变很小幅度也能翻转大量标签。此时同时核对概率误差、阈值边距与最终决策；回归后处理有区间截断时，也应检查边界附近行为。浮点接近保证某种数值一致，不自动保证业务动作一致，更不保证真实世界损失相同。

更具体地，令输入表示误差为 $`\delta z`$，权重误差为 $`\delta w`$，截距误差为 $`\delta b`$，则输出差可界为 $`\Vert \delta w\Vert\;\cdot\;\Vert z\Vert +\Vert w\Vert\;\cdot\;\Vert \delta z\Vert +\Vert \delta w\Vert\;\cdot\;\Vert \delta z\Vert +\vert \delta b\vert `$。这个式子来自展开两套仿射函数并用柯西不等式，显示容差与输入范围有关，不能只检查参数小数位。

实际可同时设输出单位下的绝对容差与相对容差。接近零的输出主要靠绝对项约束，大量级输出则需说明可接受比例。若阈值决策要求严格一致，还要检查误差界是否小于阈值边距；边距不够的样本可以单独审查，而非把全部差异都归为无害舍入。

<a id="project-5-detail-48"></a>
### 11.4 故障注入应该针对真实失效窗口

可以用受控小改动测试列名缺失、单位不符、模型与前处理错配、标签版本变化、重复预测和产物截断。每次写明预期哪个检查失败、哪些旧结果仍有效。若所有故障都只导致同一句模糊异常，维护者仍很难判断是输入、产物还是评价数据的问题。

故障注入不必破坏真实系统。像本章在临时目录修改自己生成的文件，就足以检验摘要与加载边界；用人工记录重复标识，可以验证报告连接。真实服务并发、断电和存储一致性需要相应环境与协议，不应把小型异常实验描述成已验证所有生产失败。

<a id="project-5-detail-49"></a>
## 12. 版本、兼容与更新：让结果始终可追溯

<a id="project-5-detail-50"></a>
### 12.1 数据版本、模型版本与评价版本分开

同一个模型在不同标签快照上会得到不同指标；同一个数据集用不同划分或评分也会得到不同报告；相同权重配不同阈值又会给不同决策。可以分别记录数据、预测函数和评价协议身份，再通过清单建立对应，而不是让一个笼统版本号承担所有含义。

标签修订后，如果保留原预测并复算，可以研究评价变化来自标签；重新训练则又混入模型变化。研究设计应隔离这些因素。旧报告不必被偷偷覆盖，可以标记其标签与评价版本，再给出新的可复算结果，使后来者知道两个数字为何不同。

<a id="project-5-detail-51"></a>
### 12.2 兼容规则不能只看文件能否打开

新增可选字段若默认值和旧行为明确，可能保持兼容；修改某字段单位、类别编码或目标含义，即使文件格式完全相同，也通常改变接口语义。格式版本负责解析规则，预测函数版本负责行为，模式版本负责输入含义。应给调用者清楚的升级与适配方式。

跨版本验收可同时包含旧输入回归集、新功能样例、非法输入和真实独立数据。旧样例全部一致并不证明新来源性能相同，新来源分数改善也不能抵消旧接口被意外破坏。功能恢复与统计推广应在报告中分别列出。

<a id="sec-6-1"></a>
<a id="project-5-detail-52"></a>
### 12.3 交接记录应让另一人走完整条链

另一人应能从一条结果找到其输入身份、前处理、参数、后处理与评分规则，再按说明重算。若某步需要特定环境或数据权限，应记录前提；若只支持固定产物推理，就不要把训练轨迹恢复当作默认保证。可复现不是一句是或否，应说明恢复了哪些对象。

对随机训练，可以给固定输入下的产物预测容差，以及重复训练的统计范围。多次训练得到略不同参数但相近效果，与同一产物加载后输出不一致，是不同问题。交接时把它们分开，能够减少为了追逐逐位相同而掩盖真正语义错配的情况。

<a id="project-5-detail-53"></a>
## 13. 发布前的完整验收与恢复入口

<a id="project-5-detail-54"></a>
### 13.1 用状态定义完成，而非只检查文件存在

一个可交付版本应满足清单与文件匹配、前处理可重建、输入输出模式通过、参考行为一致、报告可复算，以及统计结论仍在已评价范围内。它们可按顺序执行，任何失败都产生具体状态和诊断。仅检查一个 final 文件夹存在，不能证明其中内容属于同一次训练。

多文件包在写入过程中也可能半成品可见。可以先在独立版本位置完成保存与验证，再切换一个正式入口；读取者固定版本，避免前处理来自新版本、权重来自旧版本。原子可见、崩溃持久与多写者并发需要不同机制，具体文件协议可对照 Linux 与数据库章节。

<a id="project-5-detail-55"></a>
### 13.2 更新触发与自动响应要有证据

输入分布变化可以提示审查，不一定代表性能下降；无标签时也可能看不到条件关系变化。自动重训、重新校准与修改阈值应分别有触发条件、可用数据和独立验收。若标签未成熟，不能把暂时未观察到事件当作可靠负类，驱动错误更新。

新版本应在固定回归集和相应新评价数据上检查，同时比较资源、覆盖与关键群体。旧版本回退入口需要绑定完整函数，而不是只有权重；否则切回权重却保留新缩放，也不是真正恢复旧行为。回退本身不能撤销所有已经发生的外部决策，应明确它解决的范围。

<a id="project-5-detail-56"></a>
### 13.3 清理中间产物之前先验证最终结果

训练目录可能有探索日志、临时文件和失败检查点，也有最终模型所必需的映射与统计。清理应依据依赖清单和保留规则，先确认正式产物能够独立重建预测，再移除确属本次生成的临时对象。文件名看起来普通，不意味着可以删除；名字带 final 也不构成唯一有效依据。

本套学习资料保留 Markdown 正文及正文引用的本地插图，实验临时模型和脚本由临时目录自动清理。这种做法让示例可运行，又不把生成过程散落成需要读者管理的附加文件。真实项目则应保留必要证据与产物，不应照搬教学目录的只留正文规则去删除生产依赖。

## 14. 二十道练习与逐题详解

<a id="sec-8-2"></a>
<a id="project-5-detail-58"></a>
### 14.1 题一：同权重不同缩放是否同模型

**题目。** 两个包使用相同系数和截距，一个按训练均值缩放，另一个按请求批次重新求均值。能否称为同一已交付预测函数？

**解析。** 一般不能。输入映射改变，单个请求的输出还可能随同批其他请求变化。应保存训练统计并在推理中冻结，除非接口明确要求批次上下文。权重摘要只覆盖链的一部分。验收可以把同一请求单独与混在其他样本中预测，检查是否符合定义的拆批不变量，同时核对变换版本。

<a id="project-5-detail-59"></a>
### 14.2 题二：模式通过为何仍可能错单位

**题目。** 一个摄氏模型收到数值二十五，调用者实际记录华氏，却在请求里仍声明摄氏。范围检查能否必然发现？

**解析。** 不能，两个数值都可能落在宽合法范围。模式声明仍依赖上游按协议提供真实语义。需要来源契约、受控单位适配和端到端样例，不能从数字本身可靠推断单位。接口检查减少错误，不是对任意虚假元数据的全知验证。报告应说明哪些假设由上游负责保持。

<a id="project-5-detail-60"></a>
### 14.3 题三：为什么拒绝布尔比强行转换更清楚

**题目。** 某语言把布尔真当作整数一，数值字段是否应无条件接收它？把解析失败都变成缺失是否更健壮？

**解析。** 取决于模式，但无条件接受会把拼接或编码错误伪装成合法数值。若契约只接受明确数值与显式缺失，就应拒绝布尔和不合法字符串。缺失是业务状态，解析失败是格式问题，二者不宜默认混合。可按项目需求放宽转换，但要记录规则、错误状态和样例，而不是依赖运行时隐式行为。

<a id="project-5-detail-61"></a>
### 14.4 题四：事件早于预测为何仍不能用

**题目。** 事件发生在第四天，第八天才入库，第六天已经作预测。回填后的数据库包含它，是否可放进第六天特征？

**解析。** 按当时可见信息预测的目标，不能。必须同时检查事件窗口与可得时点。仅按事件时间筛选会把迟到信息带回过去。标签确认可以发生在未来，但特征可见性职责不同。应保存历史版本或真实可用记录，必要时用追加未来记录不改变过去特征的性质检查实现。

<a id="project-5-detail-62"></a>
### 14.5 题五：重复字段的重要性为何有三种答案

**题目。** 两列完全相同，固定线性模型各用一半权重。置换单列、共同置换两列和删一列重训，为什么不应期待同样损失变化？

**解析。** 单列扰动破坏两列原本关系，组扰动保留组内关系但破坏目标对齐，重训允许剩余列重新承担信号。它们分别评价固定函数在特定输入变化下的依赖和学习规则的可替代性。数值不同并不互相矛盾，应先选择与采集成本、部署缺失或解释问题相符的实验。

<a id="project-5-detail-63"></a>
### 14.6 题六：组重要性是否等于单列之和

**题目。** 两个相关输入的置换损失增加分别为一，能否推断共同置换增加二？

**解析。** 不能。相关、交互与模型非线性使联合扰动分布不同，风险差通常不满足逐列可加。即使在线性预测中，平方损失也包含交叉项。应直接定义并运行组扰动，保留组内关系和共同评价样本，再与删组重训区分。不能把柱状图相加后冒充已经测量的系统成本。

<a id="project-5-detail-64"></a>
### 14.7 题七：没被读取的字段能有局部贡献吗

**题目。** 模型只读第一列，但第二列与它完全相同。条件信息型 Shapley 解释给第二列非零贡献，是否一定说明实现错误？

**解析。** 不一定。条件值函数中，知道第二列就能推断第一列，因此它携带关于预测的信息；边缘替换值函数则可能把全部贡献给真正被读取的第一列。应说明解释的是统计信息、计算依赖还是行动效果。相加恢复输出差异不能唯一决定科学含义，选择不同值函数本来就在回答不同问题。

<a id="project-5-detail-65"></a>
### 14.8 题八：贡献和正确能证明因果吗

**题目。** 一套局部贡献严格相加得到预测减基准，能否证明把某字段提高一个单位会让真实目标按该贡献变化？

**解析。** 不能。相加是该解释体系的代数性质，真实干预还涉及混杂、变量之间约束和作用机制。改变一个输入可能不改变结果，也可能连带改变其他输入。若要行动建议，应提出可识别的因果问题并收集相应证据。模型解释可以帮助形成假设，但不能单独完成因果验证。

<a id="project-5-detail-66"></a>
### 14.9 题九：重要性很低能否直接删字段

**题目。** 一列在固定模型上的置换重要性接近零，是否可直接从生产接口移除且不重验？

**解析。** 不能。当前模型可能未利用它，相关列可能替代，某些小群体仍可能依赖，接口与缺失回退也可能受影响。应明确删除对象、重新拟合或调整流程，并检查主要指标、覆盖、群体与兼容性。低分数是审查线索，不是替完整验收作出的授权结论。

<a id="project-5-detail-67"></a>
### 14.10 题十：摘要匹配能证明谁发布的吗

**题目。** 参数文件与清单中的 SHA-256 匹配，能否据此证明文件来自指定作者并经过模型审查？

**解析。** 不能。摘要验证内容与清单一致，若二者同时被替换仍可匹配。来源和审查需要受控发布记录、适当授权或相应签名机制。摘要仍很有价值，可以发现意外修改和错配，但不应让它承担身份认证与统计效果证明。交付检查应写明每项证据实际覆盖的层次。

<a id="project-5-detail-68"></a>
### 14.11 题十一：新进程成功是否等于跨环境成功

**题目。** 同机新进程加载通过，是否可以宣称任意依赖版本与硬件都恢复相同输出？

**解析。** 不可以。它主要排除父进程内存里的隐藏对象依赖，仍共享解释器、数值库和系统。跨环境兼容应另设支持矩阵、参考样例和容差，并比较预处理与后处理。若加载后的差异超标，应定位原因，而非无条件放宽容差。测试范围是结论的一部分，需要在模型说明中保留。

<a id="project-5-detail-69"></a>
### 14.12 题十二：有限参考样例为何还不够

**题目。** 十条参考输入全部一致，是否证明两个实现对所有合法输入完全相同？应该补什么检查？

**解析。** 有限点通常不能证明任意函数全域相等。可根据结构补名称顺序、单位转换、缺失、边界、批次拆分等性质检查，并对简单线性模型核对参数映射与代数。复杂模型还需更广回归与独立数据。样例选择应针对可辨识错误，不是只不断复制同一类正常输入。

<a id="project-5-detail-70"></a>
### 14.13 题十三：浮点接近为何仍会决策翻转

**题目。** 两版本概率差小于万分之一，阈值为二分之一。能否保证分类标签完全相同？

**解析。** 不能，原概率若就在阈值附近，小改变也可跨边界。应同时报告概率误差、阈值边距和最终标签变化；若业务容许不确定区间或拒绝规则，也需保存其版本。数值容差与决策容差不同，不能只因数组近似相等就省去行动层验收。统计性能还需要真实标签与目标总体。

<a id="project-5-detail-71"></a>
### 14.14 题十四：为什么不能按输出顺序拼标签

**题目。** 标签顺序为 a、b、c，预测并行返回 c、a、b。两表行数一样，是否能直接逐位置计算 MAE？

**解析。** 不能，行数一致不代表标识对齐。应检查键唯一和覆盖，再按标识连接。示例正确 MAE 为一，而错误位置配对会得到十一除以三。分布式重试还可能重复或漏行，不能靠最终平均数看起来合理来发现所有错配。逐行证据与连接规则是报告可复算的基础。

<a id="project-5-detail-72"></a>
### 14.15 题十五：标签修订为何不该覆盖旧报告

**题目。** 同一预测器在新标签快照上 MAE 下降，是否可以直接把旧报告数值改掉而不保留版本说明？

**解析。** 应记录新的评价版本，并说明变化来自标签而非模型。保留旧预测与标签身份，可以分离数据修订和模型更新的影响。若同时重训、换划分又换指标，无法仅凭分数差判断原因。报告的可追溯性要求每个数字绑定其数据角色与规则，而不只是绑定一个模型名称。

<a id="project-5-detail-73"></a>
### 14.16 题十六：只在接受样本上更准是否更好

**题目。** 新版本拒绝百分之二十请求，接受部分 MAE 更低，能否直接宣布超过处理全部请求的旧版？

**解析。** 比较对象已经不同。应报告覆盖率、拒绝群体、共同接受集合表现及全部请求的回退成本。若拒绝主要集中在困难群体，单独低 MAE 可能只是选择容易样本。拒绝策略可以有价值，但需按完整系统目标评价，不应通过删去未服务请求制造同条件比较的错觉。

<a id="project-5-detail-74"></a>
### 14.17 题十七：修改阈值是否需要新版本

**题目。** 权重与前处理不变，仅把分类阈值提高。模型文件摘要没变，是否可继续当成完全相同的系统结果？

**解析。** 概率函数可能相同，但决策函数、告警量与成本已经改变。应记录后处理或完整系统的新身份，并重新评价工作点指标。回归逆变换、范围截断和校正同理。版本应绑定实际交付行为，不能只跟随最大的权重文件。报告也要区分概率性能与动作表现。

<a id="project-5-detail-75"></a>
### 14.18 题十八：回退权重为何可能回退不完整

**题目。** 新版出现异常，将权重换回旧版，却保留新版缩放和类别编码，是否真正恢复了旧预测？

**解析。** 一般没有。旧权重依赖旧输入映射和后处理，混用会构成未经验证的新函数。回退入口应绑定完整不可变版本，再验证参考样例与当前兼容条件。即使恢复旧行为，也不能撤销已经发生的全部外部决策，应按具体系统说明恢复边界，而非只发一条成功日志。

<a id="project-5-detail-76"></a>
### 14.19 题十九：为何清理前要先做独立重建

**题目。** 目录里有一个统计量文件，看起来像中间结果。是否可以在训练完成后直接删除？

**解析。** 它可能是填补、归一化、词表或校准所需依赖，文件外观不能决定用途。应先建立依赖清单，让新进程只从正式包恢复预测，再清理确属本次临时对象。教学示例使用自动清理临时目录，不代表真实项目也只需保留权重。清理目标是去除无用产物，同时保留可重建函数与必要证据。

<a id="project-5-detail-77"></a>
### 14.20 题二十：怎样表达一次小幅性能提升

**题目。** 新版本在多个尝试后得到略好测试分数，应如何最低限度地形成可信结论与交付？

**解析。** 记录选择机会与预算，区分探索和确认，使用恰当配对与独立单位比较，并报告成本、覆盖和群体取舍。若测试参与选择，应补新的评价或限制结论。完整交付还需模式、前处理、产物、阈值及可复算预测。一个小数提升与一堆齐全文件，都不能单独替代这条证据链。

<a id="project-5-detail-78"></a>
## 15. 综合研究：从误差发现走到可用版本

<a id="sec-8-1"></a>
<a id="project-5-detail-79"></a>
### 15.1 从新来源误差形成下一轮实验

若新来源 MAE 高于旧来源，先核对单位、缺失、标签、时间与覆盖，再提出可能的机制：输入组成变化、条件响应改变、传感器偏差或模型表示不足。每个解释对应能够区分它的检查，而不是直接增加模型层数。来源编号重要也未必说明来源本身有因果作用，可能只是数据流程代理。

在开发数据上选定一个可反驳改动，并冻结新评价。比较原模型、修正数据流程后的模型与必要的简单基线，保持资源和样本角色一致。若改善仅发生在参与诊断的旧样本，应说明尚缺独立支持。研究报告既保留发现，也保留没被证实的假设和失败尝试。

<a id="project-5-detail-80"></a>
### 15.2 五阶段完整交付练习

第一阶段写字段与时间契约，构造合法、缺失、错单位和重复标识输入。第二阶段训练最小预测流程，核对目标、拟合边界与基线。第三阶段做固定模型依赖与重训对照，说明相关信息如何影响解释。第四阶段保存完整包并在新进程恢复，验证失败路径。第五阶段从保存预测复算报告，给出支持与更新条件。

验收结果应允许别人逐阶段定位失败。例如模式测试通过但统计效果弱，说明需要改善模型或证据；报告复算成功但产物无法重建，说明交付链不完整；参考输出一致却新来源退化，说明兼容与推广是不同问题。不要把所有失败都归为代码未运行，也不要把任何一层通过当作全部完成。

<a id="project-5-detail-81"></a>
### 15.3 把限制转成明确的研究问题

若独立单位太少，下一步是补充怎样的数据；若输入支持不足，哪些区域需要标签；若解释对背景敏感，怎样比较合理参照；若模型依赖昂贵字段，怎样评估采集替代方案。限制应指向可行动的证据需求，而不是笼统重复模型可能出错。

对于复杂模型，可逐步扩展本章实验，但保留对象清楚的原则。权重更大、解释图更多、文件更多，不会自动提高可审查性。能够从一条预测追溯到输入、函数、选择与评价，再由另一人复算，才使项目结果成为可以持续学习和改进的材料。



**延伸算例：基准值改变时，相同预测的贡献总和也会改变。** Shapley 效率要求贡献总和等于 $`v(N)-v(\varnothing)`$，并不无条件等于预测本身。预测固定为三，背景基准为一时，贡献合计二；更换合法背景基准为二后，贡献合计一。模型和这条输入没有改变，解释任务的参照却改变了。不能把两次贡献大小差异直接解释为模型依赖发生变化，也不能把每次贡献都相加到零作为一致检查。交付时应保存背景总体、空集合值、集合值函数和条件分布处理规则；这些是解释对象的组成部分，和模型文件身份一样影响结果含义。
