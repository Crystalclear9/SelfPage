## 1. 本章要完成哪一种分类闭环

本章把第一章的协议落实为一个可以整块复制运行的 CPU 实验。数据完全由 NumPy 生成，没有下载、隐式文件或外部服务。每台人工设备产生八条巡检记录，输入是四项数值读数，目标是三个状态类别。设备共同偏移使同设备记录具有相关性，因此训练、概率校准、行动阈值开发和最终测试在设备层面分离。设备号只负责分组，不进入模型特征。

这个项目同时保留两个输出：三分类概率和一个“是否将类别二送去复检”的二元行动。三分类主指标是宏平均 F1；行动按漏掉类别二的代价为五、错误复检代价为一计分。二元行动没有修改三分类标签，也没有把三分类 F1 当成复检收益。这样可以在同一数据上看清模型、概率和决策的不同职责，而不把多个任务的分数混成一个成功结论。

从头到尾只搜索三个正则强度。小搜索不是为了保证结果漂亮，而是让读者能逐一解释候选、拟合与信息来源。最终测试集在所有选择冻结后统一计算预定指标。代码断言关注分组隔离、形状、概率语义和可重算性，不强行要求模型必须超过某个猜测分数。若候选表现不如预期，应先检查机制和协议，再决定下一轮探索。

<a id="project-2-detail-2"></a>
### 1.1 人工数据中哪些关系是真实可学的

生成器先为每台设备抽一个共同偏移，再为每条巡检生成四个读数。类别由前两项读数、第三项的线性项、设备未完全可见的偏移和独立噪声共同决定。输入确实包含预测信号，但仍有不可消除的不确定性。第四项读数不直接进入标签公式，可作为有限样本中的无关变量。最后给输入加入少量独立缺失，用于练习折内填补。

这些机制带来可检查的预期：线性模型应该能够学习一部分关系；设备偏移没有被完整观察，组外泛化仍有难度；增加复杂度不保证改善；缺失指示在本生成器中并不蕴含额外真实信号。若在另一个实验中让缺失概率依赖设备状态，任务就改变了，必须将其记录为新数据机制。不要因为都是`NaN`就认为两个项目具有相同缺失语义。

类别由两个固定切点生成，而非根据全体标签分位数重新划分。这避免为了人为平衡测试类别而使用全局标签分布。切点来自本章预先定义的机制，不是部署时需要估计的模型参数。若真实任务需要从数据学习分类边界，例如按历史维护成本定义等级，那一规则也必须只在允许的训练数据中估计并冻结。

<a id="project-2-detail-3"></a>
### 1.2 四个数据区域各负责什么

训练区域用于预处理、基础模型拟合和分组交叉验证搜索；校准区域只用于拟合已冻结基础模型的概率映射；行动开发区域只用于挑选预定阈值网格；测试区域只用于最终报告。四个区域的设备集合互斥。这样做简单清楚，但付出了训练样本减少的代价，尤其校准和阈值区域较小时结果会波动。本章选择可解释的边界，而不是声称四块划分总是样本效率最高。

若数据不足，可以研究交叉拟合、嵌套选择或外部代价直接给定阈值，但每种方法都需要重新画出信息流。不能因为样本少，就让校准器拟合基础模型训练样本上的过度乐观分数；也不能在最终测试上挑阈值。第三章讨论配对不确定性，第四章展示另一种将内外分组验证结合的回归流程，本章不把所有替代方案强塞进同一段代码。

本图是独立四样本手算，不代替本章完整程序输出。真实标签为一、零、一、零，概率依次零点八、零点六、零点四、零点二，概率不小于阈值则预测正类。

A：按分数排序扫描得到ROC阶梯，面积为零点七五。B：阈值零点五时TP、FN、FP、TN均为一，准确率为一半；AUC并未替代这个工作点的评价。右侧保留四条记录的分数与标签，向左移动阈值时，每接纳一个正例ROC向上，每接纳一个负例向右。概率为零点六的负例先于零点四的正例进入，形成错误排序。


C：误报成本一、漏报成本四时，五个阈值的总成本依次为二、一、五、四、八。阈值须在开发阶段选择并冻结，不能在最终测试上反复挑最低成本。成本、基率和校准改变时需重审决策政策。

## 2. 完整代码：搜索、校准、阈值与冻结测试

运行环境为 Python 3.11 与 scikit-learn 1.8 系列接口，使用 NumPy 与 pandas。`FrozenEstimator`的作用是让校准阶段使用已经训练好的基础模型，不再次拟合它；这是本代码明确依赖的接口。官方文档随稳定版更新，查阅时可优先选择文末固定到 1.8 的链接。整个实验只在内存中生成表格和结果，不写文件。

```python
import numpy as np
import pandas as pd
import sklearn
from sklearn.calibration import CalibratedClassifierCV
from sklearn.dummy import DummyClassifier
from sklearn.frozen import FrozenEstimator
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (accuracy_score, classification_report,
                             confusion_matrix, f1_score, log_loss)
from sklearn.model_selection import GridSearchCV, GroupKFold
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(20261017)
n_groups, rows_per_group = 96, 8
groups = np.repeat(np.arange(n_groups), rows_per_group)
n = len(groups)
offset = rng.normal(0, 0.7, n_groups)
X = rng.normal(size=(n, 4))
X[:, 0] += offset[groups]
latent = (1.5 * X[:, 0] - 1.1 * X[:, 1] + 0.4 * X[:, 2]
          + 0.5 * offset[groups] + rng.normal(0, 0.9, n))
y = np.digitize(latent, [-0.7, 0.9])
X[rng.random(X.shape) < 0.06] = np.nan
keys = np.array([f"device-{g:03d}-visit-{i % rows_per_group}"
                 for i, g in enumerate(groups)])
assert len(set(keys)) == n

order = np.random.default_rng(73).permutation(n_groups)
role_groups = {
    "train": order[:48], "calibrate": order[48:60],
    "policy": order[60:72], "test": order[72:],
}
indices = {name: np.flatnonzero(np.isin(groups, gs))
           for name, gs in role_groups.items()}
roles = list(indices)
for i, name in enumerate(roles):
    assert set(np.unique(y[indices[name]])) == {0, 1, 2}
    for other in roles[i + 1:]:
        assert set(role_groups[name]).isdisjoint(role_groups[other])
assert sorted(np.concatenate(list(indices.values())).tolist()) == list(range(n))
tr, ca, po, te = (indices[k] for k in roles)

folds = list(GroupKFold(4).split(X[tr], y[tr], groups[tr]))
for a, b in folds:
    assert set(groups[tr][a]).isdisjoint(groups[tr][b])
    assert set(np.unique(y[tr][a])) == {0, 1, 2}
    assert set(np.unique(y[tr][b])) == {0, 1, 2}

pipe = Pipeline([
    ("imputer", SimpleImputer(strategy="median", add_indicator=True)),
    ("scale", StandardScaler()),
    ("model", LogisticRegression(max_iter=3000, solver="lbfgs")),
])
search = GridSearchCV(
    pipe, {"model__C": [0.05, 0.5, 5.0]}, scoring="f1_macro",
    cv=folds, refit=True, n_jobs=1, error_score="raise",
    return_train_score=True,
)
search.fit(X[tr], y[tr])
base = search.best_estimator_
assert np.array_equal(base.classes_, [0, 1, 2])
statistics_before = base.named_steps["imputer"].statistics_.copy()
calibrated = CalibratedClassifierCV(FrozenEstimator(base), method="sigmoid")
calibrated.fit(X[ca], y[ca])
assert np.array_equal(statistics_before, base.named_steps["imputer"].statistics_)
assert np.array_equal(calibrated.classes_, [0, 1, 2])
positive_column = np.flatnonzero(calibrated.classes_ == 2).item()
policy_probability = calibrated.predict_proba(X[po])[:, positive_column]
policy_truth = y[po] == 2
thresholds = np.linspace(0.1, 0.9, 17)

def action_loss(truth, action):
    return np.where(truth & ~action, 5.0,
                    np.where(~truth & action, 1.0, 0.0))

costs = [action_loss(policy_truth, policy_probability >= t).mean()
         for t in thresholds]
# 最小代价并列时，选择网格中最先出现的较低阈值。
threshold = float(thresholds[int(np.argmin(costs))])
frozen = {"C": float(search.best_params_["model__C"]),
          "threshold": threshold, "classes": base.classes_.tolist()}
baseline = DummyClassifier(strategy="prior").fit(X[tr], y[tr])

# 此行以后只评价，不再调用任何 fit 或修改选择规则。
probability = calibrated.predict_proba(X[te])
raw_probability = base.predict_proba(X[te])
prediction = calibrated.classes_[probability.argmax(axis=1)]
baseline_prediction = baseline.predict(X[te])
assert probability.shape == (len(te), 3)
assert np.all(np.isfinite(probability))
assert np.all(probability >= 0) and np.all(probability <= 1)
assert np.allclose(probability.sum(axis=1), 1)
cm = confusion_matrix(y[te], prediction, labels=[0, 1, 2])
report = classification_report(y[te], prediction, labels=[0, 1, 2],
                               output_dict=True, zero_division=0)
assert cm.sum() == len(te)
assert np.array_equal(cm.sum(axis=1), np.bincount(y[te], minlength=3))
assert np.isclose(accuracy_score(y[te], prediction), np.trace(cm) / cm.sum())
assert all(report[str(c)]["support"] == cm[c].sum() for c in range(3))
summary = {
    "baseline_macro_f1": f1_score(y[te], baseline_prediction, average="macro"),
    "model_macro_f1": f1_score(y[te], prediction, average="macro"),
    "raw_log_loss": log_loss(y[te], raw_probability, labels=[0, 1, 2]),
    "calibrated_log_loss": log_loss(y[te], probability, labels=[0, 1, 2]),
    "action_cost": action_loss(y[te] == 2,
                              probability[:, positive_column] >= threshold).mean(),
}
errors = pd.DataFrame({"key": keys[te], "device": groups[te],
                       "truth": y[te], "prediction": prediction,
                       "confidence": probability.max(axis=1)})
cv_table = pd.DataFrame(search.cv_results_)[[
    "param_model__C", "mean_train_score", "mean_test_score", "std_test_score",
]]
print("sklearn:", sklearn.__version__, "frozen:", frozen)
print("role counts:", {name: (len(gs), len(indices[name]))
                       for name, gs in role_groups.items()})
print(cv_table.to_string(index=False))
print(summary)
print(cm)
print(errors[errors.truth != errors.prediction].head(5).to_string(index=False))
```

这段代码故意让所有关键步骤处在一个块中，读者不需要从多个文件猜测变量状态。训练、校准和行动开发共用一个预定的设备角色映射，最终测试没有被传入任何拟合对象。基础模型的填补统计在校准前后相同，是冻结行为的一个直接检查；它不能独自证明所有组件未变，但配合接口定义和信息流，可以定位常见误用。

### 2.1 逐个解释每一次拟合

`search.fit`包含三个候选、每个候选四折的拟合，以及选定参数后在全部训练区域上的一次重新拟合。每次拟合都拥有独立克隆的填补器、尺度器和分类器，验证折只调用变换与预测。`refit=True`使返回的基础模型可以直接用于新样本，但其交叉验证最优均分仍是选择统计量，不能当成独立风险估计。训练区域外的数据不进入这些拟合。

`calibrated.fit`使用校准区域标签学习概率映射，基础 Pipeline 被冻结，不在校准数据上重估中位数或系数。随后行动区域的标签只用于比较阈值，不能回头选择哪个正则强度更好。基线在训练区域拟合类别先验，与候选共享最终测试对象。若想比较校准前后哪个系统作为最终方案，应在开发协议中事先安排选择依据；本例预先指定校准后系统为主，原始概率对数损失只作辅助诊断。

<a id="project-2-detail-6"></a>
### 2.2 哪些断言证明了什么

设备集合互斥断言证明的是当前生成表中的组边界，而不是未来所有隐藏关联都消失。类别支持断言保证当前分割与每个训练折都能评价三个类别，不代表小类的估计已经稳定。概率归一与有限性断言检验接口输出，不证明概率已校准；分类报告支持数与混淆矩阵对账，检验的是指标实现的一致性。区分这些层次，才不会把“测试通过”扩张为“模型正确”。

本例没有写`assert model_macro_f1 > baseline_macro_f1`，因为预定实验的合法运行不应取决于结果是否讨喜。可以把超过基线设为项目验收标准，并在未超过时报告未通过；但代码完整性检查与统计成功判定应分别记录。否则一次随机波动就会被错误地描述为程序崩溃，失败候选也容易被无声删去。

## 3. 折内预处理如何成为一个可以观察的事实

Pipeline 的价值是把学习变换与模型绑定为同一个估计器，让交叉验证克隆并重拟合整条流程。但它不是魔法屏障：若进入 Pipeline 前已经做了全表目标编码、按测试相关性选列或使用全局标签修正输入，泄漏仍然存在。审查时要沿着原始数据到每一次`fit`的路径，识别所有使用数据估计规则的步骤。

中位数填补会学习每列的训练中位数；缺失指示会根据训练中出现缺失的列构造指示列；标准化会学习变换后各列的均值和尺度。模型最终看到的特征数量因此可能多于原始四列。应保存或查询变换后的列语义，不能把最后四个逻辑回归系数简单对应原始四列。当一个训练折某列完全缺失时，还需查接口对空特征的处理；本例数据规模和缺失率较低，未特意制造这种退化情形。

<a id="project-2-detail-8"></a>
### 3.1 实验二：直接观察每折的训练均值

为了观察边界，下面使用没有缺失的一维小表，返回每折已经拟合的估计器，再核对其标准化均值等于该折训练均值。组内相邻数值使不同训练折的均值确实不同。如果提前全表标准化，再用分类器交叉验证，就失去了这个边界。这里不比较哪个分数更高，直接验证应当成立的机制。

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GroupKFold, cross_validate
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X = np.arange(24, dtype=float).reshape(-1, 1)
y = np.tile([0, 1], 12)
groups = np.repeat(np.arange(6), 4)
folds = list(GroupKFold(3).split(X, y, groups))
pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
out = cross_validate(pipe, X, y, cv=folds, return_estimator=True,
                     scoring="accuracy", error_score="raise")
means = []
for (train, valid), fitted in zip(folds, out["estimator"]):
    learned = fitted.named_steps["standardscaler"].mean_[0]
    assert np.isclose(learned, X[train].mean())
    assert set(groups[train]).isdisjoint(groups[valid])
    means.append(learned)
assert len(set(means)) > 1
print("fold means:", means, "global mean:", X.mean())
```

把这个思路推广到填补器，可以核对各折`statistics_`；推广到词表，可以检查验证独有类别没有进入训练词表；推广到目标编码，则必须核对训练行自身的标签是否参与其编码。所谓“每个拟合参数来自哪里”，可以通过对象属性、受控反例和独立参考计算获得证据，而不只是阅读一行`Pipeline(...)`后就停止审查。

<a id="project-2-detail-9"></a>
### 3.2 新类别、空列和形状漂移

真实数据常包含训练中没有出现的类别。数值实验无需独热编码，但迁移到混合表时应使用列级处理，并定义未知类别策略。未知类别忽略、映射到专用桶、拒绝预测，各自对应不同系统行为。静默把未知设备类型变成全零向量可能让模型仍输出概率，却不代表此类型被充分评价。第五章会将这种模式约束写进交付合同。

空列也需要明确策略：训练中全空而测试有值时，模型没有学到该值与目标的关系；不能因为测试出现了非空数值就自动恢复一个未经训练的特征维度。输入列顺序、单位和缺失约定同样属于预测函数。模型文件能加载，只能证明对象可反序列化，不证明调用者构造了相同的输入空间。

## 4. 搜索结果回答什么，又没有回答什么

本机实际运行三个候选的分组验证宏 F1 约为零点六一五、零点六九七和零点七二四，因此按既定规则选择`C=5`。这不是某种正则强度普遍最好的证据，只是三个预定候选在当前训练设备上的比较。`C`越大通常意味着更弱的正则约束，但不同样本规模、特征尺度和实现目标下，同一个数值不能直接比较。项目报告应给候选表，而不是只留下一个最优数字。

最终校准后模型在一百九十二条测试记录上的宏 F1 约为零点五六三，多数类基线约为零点一八二。两者共享同一批测试设备，说明当前完整流程优于这个无输入参照；不能由此断言它优于所有其他模型。验证最优均分与测试结果存在明显差距，需要同时考虑组间抽样变化、验证选择乐观性，以及校准步骤改变了概率和分类边界。不能把差距全部归于一个未经验证的原因。

<a id="project-2-detail-11"></a>
### 4.1 最优均分的乐观性从哪里来

假设每个候选的验证分数是其真实表现加估计噪声。即使噪声均值为零，取多个候选中的最大值，也更容易选到噪声偏高的那一个。因此`best_score_`同时承载模型质量和选择过程影响。候选越多不意味着必然更差，但使得直接把最大值当作独立性能估计更加危险。外部测试评价的是已经选出的完整流程，嵌套验证则可以在开发阶段评价选择方法本身。

折间标准差不能简单除以折数平方根就当成一般有效的独立样本标准误。不同折的训练集合高度重叠，且设备的难度和样本量不同。标准差在这里主要描述当前折表现的变化，不直接构成所有未来数据的置信区间。若需要推断，应明确抽样单位和重采样方案，第三章会讨论配对损失与组级不确定性，不能用一个便利公式代替设计。

<a id="project-2-detail-12"></a>
### 4.2 训练与验证差距如何用于提出假设

如果训练很高而验证明显低，可能是过拟合，也可能是训练与验证来源差异、重复结构或标签机制改变。更强正则是一个候选假设，更多独立设备是另一个，审查非法特征也是必要排查。若训练和验证都低，则可能是表示不足、任务噪声大、优化没有收敛或指标与目标不匹配。单看两个均值不足以唯一识别原因，应结合受控对照和错误样本。

本例的逻辑回归基于线性分数，而真实标签还包含未完全观察的设备偏移和噪声。即使优化完成，也不应期待完美分类。中间类别由两个切点夹出的区域定义，在噪声和校准映射下可能被两侧类别挤压。这个机制为后续分析提供具体方向，但需要在开发区域检验，例如观察各类概率分布，而不是直接用最终测试为每个错例写专用规则。

## 5. 混淆矩阵必须能回到原始支持数

本机冻结模型的混淆矩阵为：真实类别零的七十二条中，六十七条正确，一条到类别一，四条到类别二；真实类别一的四十一条中，仅两条正确，二十三条到零、十六条到二；真实类别二的七十九条中，六十七条正确，五条到零、七条到一。总正确数一百三十六，因此准确率约为零点七零八。宏 F1 较低，主要因为中间类别表现差，不能用准确率掩盖它。

逐类精确率看预测列，召回率看真实行。类别一的预测总数为十，因此精确率为二除以十，召回为二除以四十一，F1 为四除以五十一。这里给出整数核对，比输出四位小数更能说明问题。若一个类别在测试中没有支持，某些指标无法定义；`zero_division=0`是报告约定，不是证明该类真的具有零质量，也不能补足缺少的评价样本。

<a id="sec-1-1"></a>
<a id="project-2-detail-14"></a>
### 5.1 从某个分数追到一组记录

错误表保留稳定记录键、设备、真实标签、预测和置信度。键使读者能追溯原始输入，设备使读者能检查错误是否集中在少数来源，置信度帮助区分模糊边界与高置信错误。只保存被误分的特征值而不保存键，容易在去重、重排序和标签修订后失去对应关系。完整审计通常还需要保存模型身份、时间和概率列顺序。

查看测试错误可以帮助描述当前局限，但据此修改模型后，原测试就不再承担下一轮独立确认。更合理的持续研究是用开发区域的错误形成候选假设，把本轮测试作为固定回归检查，后续收集新设备作确认。资料中的错误解释不是邀请读者不断重跑同一个最终测试，直到类别一的数字变得好看；它是在示范如何透明报告一个并不完美的结果。

<a id="sec-2-1"></a>
<a id="project-2-detail-15"></a>
### 5.2 支持数、宏平均和加权平均为何会分离

宏平均 F1 先对每类计算 F1，再等权平均，强调类别层面的覆盖；加权 F1 按真实支持数加权，容易受到大类影响；微平均在普通单标签完整多分类中与准确率一致，因为所有类别的总正确数和总错误数形成同一个比率。它们都可以有意义，但不能在结果出现后只挑最有利的一项作主要结论。

宏 F1 也并非自动等于设备公平。如果某台设备的多条记录都属于难类别，它仍会通过记录数影响各类混淆。等权设备的分类表现需要另行定义，并对无支持类别给出一致规则，或者改用可逐记录相加的损失再先组内平均。选择“宏”字并不能代替对抽样和权重的明确说明。本例每组八条记录，所以逐行与等权设备的零一损失一致，但 F1 的非线性仍然需要谨慎。

### 5.3 实验三：指标方向和概率列语义

下面用手工混淆构造一份小报告。模型概率列明确对应类别顺序，预测时通过类别数组映射最大概率位置，而非假定类别总是从零连续编码。断言证明指标可从计数重算，也展示错误的列顺序会改变对数损失。这个实验没有训练，专门检查常见的输出解释错误。

```python
import numpy as np
from sklearn.metrics import accuracy_score, confusion_matrix, f1_score, log_loss

classes = np.array([10, 20, 30])
y = np.array([10, 10, 20, 20, 30, 30])
P = np.array([[.8, .1, .1], [.2, .6, .2], [.1, .8, .1],
              [.6, .3, .1], [.1, .1, .8], [.1, .2, .7]])
pred = classes[P.argmax(axis=1)]
cm = confusion_matrix(y, pred, labels=classes)
assert np.array_equal(cm, [[1, 1, 0], [1, 1, 0], [0, 0, 2]])
per_class_f1 = [2 * cm[k, k] / (cm[k].sum() + cm[:, k].sum())
                for k in range(3)]
assert np.isclose(f1_score(y, pred, average="macro"), np.mean(per_class_f1))
assert np.isclose(accuracy_score(y, pred), 4 / 6)
assert np.isclose(f1_score(y, pred, average="micro"), 4 / 6)
correct = log_loss(y, P, labels=classes)
wrong = log_loss(y, P[:, ::-1], labels=classes)
assert not np.isclose(correct, wrong)
print(cm, "macro F1:", np.mean(per_class_f1), "log losses:", correct, wrong)
```

这里两份概率矩阵都非负且每行和为一，只有一份拥有正确的类别语义。可见归一化断言无法发现类别列交换。交付时必须将类别顺序与模型一起保存，调用方不能按自己习惯重排。类似地，混淆矩阵的行列顺序也应固定，否则两次报告的同一单元格可能对应不同类别，造成假象。

## 6. 校准：输出概率需要单独接受检验

概率校准关注在模型给出某个概率的样本中，真实频率是否与之匹配。排序正确、分类准确和概率准确是相关但不同的性质。把所有概率变得更尖锐可能不改变最大概率类别，却显著恶化对数损失；把概率缩向先验可能改善某些损失，却使边界类别更少被预测。校准后依然需要评价，不存在“调用了校准器所以概率必然更可信”的结论。

本机运行中，原始概率对数损失约为零点五七一，校准后约为零点六二五，后者反而更差。校准区域只有十二台设备、九十六条记录，映射估计存在方差，且与测试设备的条件分布未必完全一致。这个结果说明当前预定校准步骤没有在本测试上改善该指标；它不证明所有校准都无效，也不授权我们看完测试后自动选择原始模型并仍报告其独立最优表现。

<a id="project-2-detail-18"></a>
### 6.1 校准器为何需要独立于基础拟合的数据

基础模型在自己的训练样本上通常产生偏乐观的分数。若校准器也用这些分数和标签拟合，学习到的是训练内行为，不一定适用于新样本。独立校准区域提供基础模型未见对象的分数。另一种设计是利用折外分数，但要明确最终基础模型的重新拟合与校准映射之间的关系，以及分组结构是否在每个折内被保留。不能默认库内的普通分层折会自动按设备隔离。

本例使用冻结估计器，基模型不在校准阶段重新训练，映射只学习校准区域的对应关系。多分类校准还涉及各类别概率的一致化，因此它可能改变三分类`argmax`。读者若想研究未校准与校准系统，应在新的开发设计中把两者作为预定候选，并用合适外层证据比较，而不是在最终测试上选择对数损失较低的一行。

<a id="project-2-detail-19"></a>
### 6.2 可靠性图的分箱与样本数

可靠性图把预测概率按区间或分位数分箱，再比较箱内平均概率和真实频率。分箱过细时每箱样本太少，曲线剧烈波动；分箱过粗时局部失配被平均掉。应报告每箱数量，并说明多分类采用逐类一对其余还是最大置信度图。只画最大置信度的校准，不能证明每个类别都校准，尤其不能补足本例类别一的表现问题。

对数损失是一种完整概率损失，极端错误概率会受到较大惩罚；Brier 分数使用概率与真实指示的平方距离。它们与分箱图提供互补证据，但并不能从一个总分唯一拆出校准和区分能力。项目可预先报告这些指标，若在多个指标间出现取舍，就把取舍写清楚，而非给“概率更好”一个不加限定的标签。

## 7. 阈值选择是行动策略的训练

本例把类别二视作需要复检的状态，对它使用一个单独阈值。概率低于阈值不代表一定属于类别零，而是当前策略不触发复检。三分类预测仍然由三列概率的最大值产生；复检动作则只看类别二概率与阈值。这两个输出可以同时存在，报告中应分别评价。不能用复检召回替代三分类类别召回，也不能把二元动作表当作原三分类混淆矩阵。

阈值网格从零点一到零点九，共十七个值。行动开发区域计算每个阈值的平均代价，取最小；并列时选择较低阈值，这相当于在相同经验代价下倾向更积极复检。并列规则写在代码中，避免不同平台排序或人工挑选产生隐式选择。最终阈值零点二五只来自行动区域，测试代价零点二一八七五只是冻结后的评价结果。

<a id="project-2-detail-21"></a>
### 7.1 从概率与代价推导理论阈值

若 $`p=P(Y=2\mid X)`$ 是目标总体中的真实条件概率，误报代价为一、漏检为五，触发复检的条件期望损失为 $`1-p`$，不触发为 $`5p`$。比较得到 $`p\ge\frac{1}{6}`$ 时触发可以达到较小期望损失。这个推导假设动作只有这两种、正确动作代价为零、无容量或后续反馈，并且概率语义正确。经验阈值与理论阈值不同，可能来自有限样本、校准误差和分布变化。

若业务容量每天只能处理十台设备，最优规则不再是对所有日子使用固定阈值，而可能是按预期收益排序后选前十台。若设备多条窗口只能触发一次，则需要先聚合到决策单位，不能逐窗口独立算代价再声称容量满足。政策研究必须把行动约束落实到相应单位，不能停留在调一个数字的层面。

<a id="project-2-detail-22"></a>
### 7.2 实验四：阈值改变收益却不改变概率

下面用四个固定概率展示阈值选择。两个阈值给出不同动作和代价，概率数组完全不变。因此调整阈值不是重新学习概率模型，也不能被称为校准。代码对每条样本的代价直接求和，避免把精确率、召回率等指标不加推导地拼成业务收益。

```python
import numpy as np

p = np.array([0.1, 0.3, 0.4, 0.9])
y = np.array([0, 1, 0, 1], dtype=bool)
original = p.copy()

def losses(t):
    action = p >= t
    return np.where(y & ~action, 5, np.where(~y & action, 1, 0))

assert losses(0.5).tolist() == [0, 5, 0, 0]
assert losses(0.25).tolist() == [0, 0, 1, 0]
assert losses(0.25).sum() < losses(0.5).sum()
assert np.array_equal(p, original)
print("costs:", losses(0.5).mean(), losses(0.25).mean())
```

如果这些四条记录用于挑选阈值，就不能把在它们上面改善的代价当作独立验证。一个小反例能证明机制，却不能证明部署收益。真实研究还要考虑类别先验漂移、复检标签如何获得以及行动是否改变后续结果。最后一个问题进入因果和反馈系统范围，本章只研究给定标签的静态决策，不把离线表格自动扩展为在线干预证据。

## 8. 错误诊断：从现象到可检验假设

错误诊断应先验证实现，再研究统计机制。实现层检查标签与特征行是否对齐、类别映射是否正确、缺失是否按相同规则处理、测试列是否重排、指标是否使用相同样本。统计层再观察错误与设备、输入范围、缺失模式和置信度的联系。若顺序颠倒，列错位可能被描述成“数据分布很复杂”，导致无效地增加模型容量。

本例类别一大多数被分到零或二，至少有三类候选解释：生成机制中的中间区间在噪声下本来较难；线性多分类概率表达与切点生成不完全一致；小校准区域使中间类别概率被压低。开发诊断可以比较原始与校准概率的类别一分布、查看折外混淆、扩大独立校准设备数，或采用有序分类结构作为新候选。每项都需要在开发信息中比较，不能把一段解释文字当成已经证实的原因。

<a id="project-2-detail-24"></a>
### 8.1 高置信错误与低置信错误

低置信错误可能出现在边界重叠区，高置信错误则可能提示输入异常、标签问题、来源变化或概率过度尖锐。高置信并不自动意味着标签错了；反过来，低置信也不证明预测合理。应从多个同类样本寻找可重复模式，再回到数据生成和标注流程核查。删除高置信错误会直接美化评价，除非排除规则有独立证据且在适当协议中重新定义了总体。

可以在开发区域定义拒绝策略，例如最大概率低于某值时请求人工判断，但必须报告覆盖率、被拒样本的支持和剩余风险。一个只预测最容易一半样本的系统，不能仅凭剩余准确率与全覆盖系统直接比较。拒绝阈值也是策略参数，需要开发数据和预定代价；不应成为掩盖困难类别的工具。

<a id="project-2-detail-25"></a>
### 8.2 学习曲线与数据价值

若想知道应增加设备还是增加每台设备记录，可在开发区域按组数绘制学习曲线。每个训练规模都重新拟合预处理与模型，并使用相同的组外验证对象；若同时重新选择参数，应把搜索预算写清楚。训练行数增加而独立设备数不变，回答的是组内密集观察的价值；增加设备则回答来源覆盖的价值，两条曲线不能混用横轴。

曲线在当前范围趋于平缓，不证明更多数据永远无用。可能是模型容量限制、标签噪声或缺少关键来源；也可能现有输入的可学信息已接近饱和。需要通过不同模型与数据机制的对照缩小解释范围。项目的下一步应是“运行某个能区分假设的实验”，而非泛泛写“继续优化模型”。

<a id="project-2-detail-26"></a>
### 8.3 不平衡处理为什么也要嵌入协议

类别加权改变训练目标，重采样改变训练分布，阈值调整改变行动规则，三者不是同一方法。若过采样发生在划分之前，同一个原始记录或其近似副本可能进入训练与验证；若类权重由最终测试频率决定，则使用了不允许的信息。应在训练折内部处理，并评价原始目标总体的质量与代价。

本例没有自动启用平衡权重，因为类别分布来自预先定义的机制，且主要目标不等于让每一条训练样本对参数产生相同效果。若加入权重，应作为新候选，比较各类召回、概率质量和行动代价。训练权重使概率含义可能变化，校准也可能受到影响，不能假设多加一个参数就能同时解决少数类识别和概率可信度。

<a id="project-2-detail-27"></a>
### 8.4 对数损失的逐样本分解与错误集中度

宏 F1 难以逐行分解，但对数损失可以：第 $`i`$ 条记录的贡献为 $`-\log p_{i,y_i}`$。把这些贡献按设备求均值，可以检查平均概率质量是否被少数设备主导；把最大的若干项列出，可以核对是否存在概率极端自信却错误的样本。分析时仍需保留所有样本作分母。只展示最差五个贡献能说明尾部案例，不能估计总体频率，也不能证明某个输入导致了损失。

对数损失对真实类概率接近零的记录非常敏感。库通常为数值稳定进行适当处理，但这种数值处理不等于业务上忽略极端错误。如果把所有概率人为截断后重新归一，已经改变了预测系统，需要在开发中定义并冻结。给报告增加一个没有声明的概率下限，可能让测试损失更好看，却也会改变真实概率含义与行动阈值。分析程序和预测程序应使用同一份明确概率，不能各自偷偷修饰。

还可以计算按设备的校准前后损失差，观察改善是否一致。若平均变差主要来自两台设备，下一步应检查其来源和输入，而非立即删除这两组。如果目标总体确实包含它们，删除会改变任务。若有独立证据说明它们违反输入契约，例如传感器单位损坏，应在所有数据上执行相同规则，记录排除数量并重建相应评价。错误集中度是一条研究线索，不是一张自动排除许可证。

<a id="project-2-detail-28"></a>
### 8.5 容量与正则化的比较需要保持选择预算一致

若想加入随机森林，可在训练区域内为其设置少量有解释的深度和叶节点样本数候选，继续使用相同分组折。树模型未必需要标准化，但仍要处理缺失与输出语义；是否使用模型原生缺失能力、是否增加指示，应视作完整方案。不同模型不必拥有完全相同的预处理，但应共享允许的信息、目标对象、评价指标和清楚说明的资源条件。

随后需要决定校准和行动规则是否也对每个模型重新拟合。若最终系统包括这些步骤，比较就应包住全部步骤，而不能把某个模型的最佳校准阈值与另一个模型的默认阈值相对照。若研究问题只是基础分类器的区分能力，也可以先固定只比较未校准概率或预定分类规则，但报告应避免把局部结果扩张为完整复检系统收益。所谓公平比较，首先是问题相同，而不是代码表面长得一样。

当候选模型数量增加时，开发区域承受更多选择压力。可以预先限制总训练次数，保留完整候选历史，再利用外层分组评价选择流程。不要把不断新增模型视作零成本的探索：它消耗计算，也消耗验证信息。若最后所有模型都接近，优先选择简单方案可以是合理规则，但应按事先约定执行；若规则事后形成，也应记录为下一轮假设。这样不同批次的研究才能积累，而不是每次从一张最高分截图重新开始。

<a id="project-2-detail-29"></a>
### 8.6 通过反事实小输入检查预测函数

模型解释不一定从大型可视化工具开始。可以构造一个合法样本，保持其余字段不变，只改变一项传感器读数，观察概率如何移动。对本例线性模型，这能检查数值方向、标准化和缺失填补是否符合预期；但因为真实数据中的字段往往相关，人工改变单个字段可能得到低概率的输入组合。结果说明固定模型在该输入路径上的行为，不自动等于现实干预效果。

也可以把同一条记录的列交换、单位放大一千倍或设为全缺失，检查系统能否识别契约违反。若当前模型仍无声输出概率，这不是它鲁棒的证明，而是接口尚未包含所需校验。第五章将增加模式与单位验收，本章保留这种缺口作为明确的后续工作。预测模型负责在有效输入域内给出函数值，输入验证负责确定请求是否落在已声明的域内，两者需要共同交付。

对于有效域内的微小扰动，应记录响应是否平滑、是否被单个缺失指示触发大幅变化，以及某类概率是否总被压低。这些观察可以形成开发假设，例如核查尺度器是否把极低方差指示放大、某个正则强度是否过度依赖噪声列。它们仍需通过开发对照验证。一个漂亮的局部解释不能替代组外评价，也不能由几个看似合理的响应证明全体预测可信。

<a id="project-2-detail-30"></a>
### 8.7 失败候选与收敛信息也是实验结果

训练达到最大迭代数、数值警告或某折类别不足，都应明确记录。简单把最大迭代数调到极大并隐藏警告，并不能证明优化问题已解决；应检查尺度、容忍度、数据退化和目标函数变化。本例选择较宽裕的迭代上限，在实际环境运行没有出现收敛警告，仍不表示所有数据版本都如此。若迁移后出现警告，首先核查输入单位与尺度，而不是只延长运行。

`error_score="raise"`使本教学实验在候选失败时立即暴露问题，避免将失败折静默变成缺失分数。较大的生产搜索可以允许部分候选失败，但必须保存失败原因并规定如何排名。失败发生在特定数据组，可能透露该组具有空列、未知类别或标签支持不足，这些都是需要理解的结构信息。把失败都删去只保留成功表，会使读者误以为整个流程比实际更稳定。资源异常也应分类记录：超出内存预算、达到时间上限与数值不收敛不是同一种失败。

前者提示方案在当前执行条件下不可行，后者可能允许调整优化配置后重试。重试仍消耗预算，应保留原尝试与修订版本。如果某个候选只有在删除困难设备后才能运行，它已经改变评价对象；即使最终指标很高，也不能与原完整测试直接排名。稳定性评价可以报告预定候选完成比例及不同来源上的失败分布，让工程可靠性成为可观察结果，而不是训练完成后附带的一句主观判断。

## 9. 迁移到内置葡萄酒与时间数据

内置葡萄酒数据适合练习数值分类接口：十三项输入、三个类别、无需下载。若没有设备或批次标识，不应编造一个真实来源分组并宣称验证了酒厂迁移。可以按常见独立同分布教学假设做分层留出，并把结论限制在该数据与该假设；若用人工构造组，只能作为方法演示。数据来自库并不意味着所有部署语义都已被证明。

迁移时保留的应是职责结构：固定测试、折内处理、有限搜索、冻结输出、同样本基线、支持数对账。具体划分器要随采样结构改变，而不是机械替换数据读取一行。连续时间预测也不能照搬随机组留出：需要按预测时刻前推、处理特征窗口和标签成熟，并考虑同设备过去是否在部署中可见。第一章的协议在这里决定第二章哪些代码要重新设计。

<a id="project-2-detail-32"></a>
### 9.1 时间分类的最小设计思路

设每周训练一次模型，预测接下来一周的状态。对每个训练截止时刻，只使用此前已成熟的标签与当时可见的特征，内层选择也只能使用更早数据。验证周结束后等待标签成熟再计算指标，下一轮可以把成熟历史纳入训练。若特征窗口与目标窗口跨越边界，应审查是否存在实际不可得信息，而非简单按表格行序切开。

若同一设备在训练与验证均出现，只要这符合“已见设备的未来”部署，并且时间信息合法，就不自动构成泄漏。若目标是新设备，则需要额外实体隔离。这说明协议中的“组不能相交”是当前项目的明确假设，不是可以无条件移植到所有时间任务的教条。完整报告应说明为什么这一划分回答了所需问题。

## 10. 十六道练习与逐题解析

<a id="project-2-detail-34"></a>
### 10.1 为什么设备号不能直接作为一个数值特征

**问题：** 设备号从零到九十五，加入模型能否提高效果？

**解析：** 该编号在本生成器中只是身份，不具备连续距离含义。把它当数值会让模型学习任意编号顺序；当部署出现新设备时，编号关系没有已验证的预测意义。若设备属性本身合法可用，应提供型号、使用年限等有语义字段。设备号仍可用于划分和审计，角色不同于输入特征。即使某次随机划分提高分数，也需要检查是否只是记忆组身份。

<a id="project-2-detail-35"></a>
### 10.2 四块数据为何不直接合在一起训练

**问题：** 合并校准和行动区域，基础模型会得到更多数据，是否一定更好？

**解析：** 合并会改变信息边界。如果之后仍在这些样本上校准或选阈值，分数不再是基础模型未见对象的输出。可以设计更高效的交叉拟合或重新分配角色，但需要整体评价，而非只看训练样本数增加。数据效率与独立证据存在设计取舍，不能通过忽略边界免费获得。当前实验故意采用明确的四区域，便于逐个解释每次拟合。

<a id="project-2-detail-36"></a>
### 10.3 `best_score_` 为什么不等于最终模型测试表现

**问题：** 验证最优均分约零点七二四，测试约零点五六三，是否必然说明程序错误？

**解析：** 不必然。最优均分用于候选选择，含选择影响；测试设备不同；最终系统还包括在独立区域拟合的校准映射。应先核对实现，再分别分析这些因素。不能把两者差值全部称作过拟合程度，更不能据此反复调测试。若需要比较完整校准流程，应在开发阶段增加外层评价，使所有步骤都位于外层训练信息范围内。

<a id="project-2-detail-37"></a>
### 10.4 多分类概率为什么不能直接取第二列作正类

**问题：** 目标正类标签为二，为什么不直接写`probability[:, 2]`？

**解析：** 当前类别恰好为零、一、二时这样可行，但接口语义应来自`classes_`。若标签换成十、二十、三十，列位置不等于标签值。通过`np.flatnonzero(classes_ == positive_label)`显式定位，能够在类别顺序变化时保持正确。还应断言该标签存在且唯一，否则程序应明确失败，而不是静默把另一类别概率用于行动。

<a id="project-2-detail-38"></a>
### 10.5 校准后对数损失更差，应怎样报告

**问题：** 是否应删除校准结果，改把原始模型称为最终方案？

**解析：** 本次方案预先指定校准后系统，应该如实报告其表现及原始概率辅助指标。可以据此形成下一轮比较假设，但不能在测试上选较好者后继续称原方案获得独立最优评价。校准不保证有限样本改善，校准区大小、映射形式和来源差异都可能影响结果。若未来把原始与校准系统并列候选，应在开发数据上决定选择并获得独立确认。

<a id="project-2-detail-39"></a>
### 10.6 混淆矩阵某行大，是否说明该类预测很多

**问题：** 类别零的行和为七十二，能否说模型预测了七十二次零？

**解析：** 不能。本章约定真实类别为行、预测类别为列，所以行和是真实支持数，列和才是预测数量。类别零的预测数应把第一列相加，得到九十五。精确率为六十七除以九十五，召回为六十七除以七十二。先统一方向，再进行任何错误归因，否则“流入”和“流出”会被颠倒。

<a id="project-2-detail-40"></a>
### 10.7 宏平均改善能否忽略某个类别

**问题：** 新候选宏平均更高，但关键类别召回下降，能否直接宣布全面改进？

**解析：** 不能。宏平均只是一种聚合，仍可能掩盖具体类别取舍。检查关键类别是否有事先约束，再报告其支持数与错例变化。若约束被违反，主要指标改善不能自动抵消。若没有预定约束，可讨论任务是否需要修订，但这属于下一版协议；不能只在当前测试出现不利结果后临时改变成功标准。

<a id="project-2-detail-41"></a>
### 10.8 冻结基础模型后为何还要检查填补统计

**问题：** 使用`FrozenEstimator`已经说明不重拟合，属性断言是否多余？

**解析：** 属性断言提供一个具体可观察的机制检查，帮助读者理解基础变换与校准映射分离。它不是对整个对象的完备等价证明，但能发现误用可变估计器导致的某类问题。对于正式交付，还可比较固定输入预测与配置身份。测试应围绕关键行为设计，而非仅重复接口名称；本例选择中位数是因为它直接体现训练数据来源。

<a id="project-2-detail-42"></a>
### 10.9 折均值有一个等于全局均值，是否泄漏

**问题：** 实验二的某一折均值恰好为十一点五，与全表均值相同，是否违反折内处理？

**解析：** 不违反。数值相同可能是对称数据带来的偶然相等，判断依据是它是否由该折训练行计算。代码逐折比较训练均值，并显示其他折不同，因此能检查来源。不能仅凭一个统计量碰巧相等判断泄漏；同样，统计量不同也不能证明没有其他路径泄漏。机制审查与受控输入需要结合。

<a id="project-2-detail-43"></a>
### 10.10 在最终测试上挑阈值能否只称作后处理

**问题：** 基础模型没有改动，只调一个阈值，是否仍保留独立性？

**解析：** 阈值影响行动与损失，属于完整系统的选择参数。用测试标签挑阈值后，再报告同一测试上的最佳代价，会产生选择乐观性。应该使用行动开发区域或来自外部代价的固定规则，并在测试前冻结。后处理这个名称不改变信息使用事实；任何能改善被报告指标的选择都需要合法证据来源。

<a id="project-2-detail-44"></a>
### 10.11 类别权重与降低阈值是否等价

**问题：** 为少数类加权与降低该类阈值，能否互换？

**解析：** 一般不能。权重改变模型训练目标和可能的排序、边界及概率含义；阈值固定概率模型，只改变决策。某些理想化模型和条件下可以推导关系，但有限样本、多分类、正则化与模型失配会破坏简单等价。应根据任务分别设计候选，并同时检查概率和行动指标，不能从两者都增加召回就认定它们是同一个方法。

<a id="project-2-detail-45"></a>
### 10.12 为什么不把训练准确率当作基线

**问题：** 复杂模型训练准确率很高，是否比多数类测试分数更能证明学到规律？

**解析：** 训练准确率评价已参与参数学习的样本，受到拟合乐观性影响。基线与候选必须在相同外部对象上比较，才能隔离预测方案差异。训练分数仍有诊断价值，例如结合验证分数观察容量和优化，但不能与另一个模型的测试分数直接排名。比较对象、样本和信息边界都必须一致。

<a id="project-2-detail-46"></a>
### 10.13 一类在某折消失，怎样处理

**问题：** 少数类别只出现在一台设备，分组后某训练折没有该类，可以改用行随机吗？

**解析：** 不能仅为分数方便改变目标协议。该现象说明现有设备覆盖不足以支持所需组外类别识别。可以收集更多含该类别的独立设备、减少折数或重新定义可估计范围，并说明限制。行随机虽然可能让各折都有类，却回答了同设备新记录的问题，不能替代未见设备目标。断言失败应暴露设计不足，而不是被随手删除。

<a id="project-2-detail-47"></a>
### 10.14 只记录误分类样本是否足够

**问题：** 错误表没有正确样本，是否还能研究高置信度与错误率的关系？

**解析：** 不能完整研究，因为缺少相应分母。比如某设备出现十个错误，若它有一千条样本与只有十条样本，含义完全不同。应保存全部冻结预测及其键，再按规则筛选错误视图。错误案例有助于定性分析，但概率校准、组错误率和覆盖率都需要完整支持，不能从精选错例推断整体频率。

<a id="project-2-detail-48"></a>
### 10.15 测试错误发现一个新模式，下一步是什么

**问题：** 发现缺失较多的测试设备更差，能否立刻加缺失规则并报告新测试分数？

**解析：** 可以探索，但需要承认测试已参与开发。更严谨的路径是在开发数据检验相同模式，形成预定候选，再用新设备确认。还要区分缺失本身、设备来源与目标难度的混杂关系。相关性不证明缺失造成错误，补填数值也不一定解决来源差异。下一步实验应能区分机制，而不是直接为某台测试设备添加例外。

### 10.16 一个完整实验成功的最低要求是什么

**问题：** 本章模型并非所有类别都好，是否算完成项目？

**解析：** 若数据协议、拟合边界、独立报告和可重算检查都完成，实验作为研究流程是完整的；若项目质量验收包含关键类别召回下界，则当前模型可能未通过应用要求。这两种结论应同时写清楚。不能为了宣称完成而忽略低召回，也不能因为模型不够好就否认透明实验的价值。完整交付应包含失败模式、证据限制和具体下一步，第三至第五章会进一步展开。

<a id="project-2-detail-50"></a>
## 11. 进阶研究：把整个分类流程作为被比较的对象

第一项研究比较不校准、固定独立校准与分组交叉拟合校准。要在开发设备上设置外层分组折，每个外层训练部分重新完成正则选择、基础拟合和校准，外层验证只做评价。各方案共享外层对象、主要指标和资源条件，记录所有选择。最终根据开发证据冻结一个方案，再用真正未使用设备确认。这才能回答哪个完整流程在当前预算下更可靠，而不是比较三次测试中的最好数字。

第二项研究关注中间类别。由于生成目标由连续潜分数的两个切点产生，可以尝试有序结构与普通多分类的对照，并控制输入、缺失和设备划分。预先关注类别一召回、宏 F1、对数损失和行动代价，避免只挑有序方法最占优的指标。改变噪声水平和设备偏移强度，观察方法优势是否具有机制一致性。人工实验中的优势仍需要限定在生成机制下，不能直接推到所有有序真实任务。

第三项研究考察阈值在类别先验变化下的稳定性。固定已训练概率模型，在新的人工设备批次中改变类别组成或噪声机制，分别观察排序、校准和固定阈值代价。只改变先验与改变条件分布是不同实验，应分别生成并报告。如果要依据目标批次未标记输入适配，需要提前规定允许的信息；如果使用目标标签重选阈值，则已进入新一轮开发，而不是无需代价的部署修正。

这些研究都以本章完整代码为起点，但不必把全部复杂性加进初学者的第一轮运行。先能解释每一项输入、每次拟合、每张表和每个失败，再扩大候选和协议层数。一个可以清楚说明局限的十二次交叉验证拟合，通常比一千次没有数据边界记录的搜索更能产生可积累的知识。
