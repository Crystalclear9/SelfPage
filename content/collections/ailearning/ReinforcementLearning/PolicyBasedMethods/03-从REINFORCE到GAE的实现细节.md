## 1. 一条轨迹首先是一份带身份的数据

实现策略学习时，动作、奖励和观察不仅是数组，还属于某个回合、某个策略版本和某个时间位置。两个张量形状完全相同，也可能分别表示执行前状态和重置后状态，交换后代码仍能运行，却优化另一个目标。本章围绕可追踪轨迹建立真实训练，把前两章的梯度与优势转成可检查程序。

每条交互至少要知道当前策略输入、实际动作、奖励、真实下一输入、任务终止、外部截断、回合边界和采集身份。若下一章复用数据，还需要旧 log 概率和旧价值。部分可观测任务要记录或重建策略记忆，不能把单个观察当成完整状态。本章人工环境完全可观测，并显式含时间索引。

<a id="policy-3-detail-2"></a>

### 1.1 时间步与批次轴

用时间在前、回合在后的二维结构，奖励为时间乘回合，动作可以再带动作维度。反向回报递推沿时间轴，样本平均沿明确的回合或有效步数。若把这两个轴交换后仍使用同一循环，会把不同回合连接。批量向量化应先以单回合手算为参照，再核对每列互不影响。

有效掩码表示该回合在动作前仍未结束，终止掩码表示本次动作后原任务没有后续价值。两者时序不同。终止动作本身的奖励和 log 概率仍有效，后续填充才忽略。常见错误是在发现终止后把当前步也屏蔽，直接删除成功奖励对应的信用。

<a id="policy-3-detail-3"></a>

### 1.2 收集与更新分开

采样时策略负责产生动作，环境负责转移，收集器保存数值。随后根据固定这批数据构造回报和优势，再重新评分动作以建立需要的梯度图。也可以保存采样时 log 概率图，但长轨迹会保留大量激活，并使多轮复用和状态身份更难管理。采用哪种方式，应能说明梯度来自哪里。

本章收集器在无梯度区域运行，更新时从记录的状态和动作重新计算当前 log 概率。由于每批只做一次 actor 更新且评分前策略未改变，它对应采集策略；多轮更新则需要下一章的旧概率与比率协议。不能把本章的单次做法原封不动重复多轮后仍称为同样的无偏估计。

## 2. 回报计算与终止边界

<a id="policy-3-detail-5"></a>

### 2.1 完整回合的反向递推

相对折扣回报满足当前奖励加折扣后续回报，真正终止后后续项为零。反向扫描可以在线性时间完成，不需要每个时间位置重新求和。终止前的最后动作仍参与更新，填充位置输出零。若多个回合被拼在一列，边界必须切断，否则后一回合回报会错误回传到前一回合。

有限任务到期也可能是任务终止，本章环境最多五次决策，到期后没有未来奖励，因此最后时间边界价值为零。若只是为了收集固定窗口而暂停无限任务，则应保留合法下一状态的自举，这与当前任务不同。程序字段应该表达该区别，不能根据数组结束就替所有任务选零。

<a id="sec-2-1"></a>

<a id="policy-3-detail-6"></a>

### 2.2 一个双回合手算

第一回合奖励一、二后结束，第二回合奖励三后结束，折扣零点九。各自起点回报分别为二点八与三，而不是把三接在二后得到更长序列。若第一回合只是外部截断，且真实最终状态价值五，则最后一步的目标需要另加零点九乘五。相同数组长度可以对应完全不同语义。

保留最终观察尤其重要。自动重置接口可能立刻返回下一回合起点，使用它自举会把状态身份弄错。可以在测试夹具里故意设置终点值五、重置值一百，检查目标使用哪一个。这样的已知边界测试比在训练后看分数是否能上升更能定位问题。

## 3. 实验一：批量回报与跨回合隔离

下面使用三步、两回合数组，验证提前终止列不会吸收后面填充的大数；再用单步截断核对自举。它不依赖环境或训练，适合作为每次重构收集器后的回归检查。测试数值特意包含无效填充，确保掩码真的生效。

```python
import numpy as np
def returns(reward,valid,continuation,gamma,tail):
    out = np.zeros_like(reward,dtype=float)
    carry = np.array(tail,dtype=float)
    for t in range(len(reward)-1,-1,-1):
        carry = (reward[t]+gamma*continuation[t]*carry)*valid[t]
        out[t] = carry
    return out
r = np.array([[1.,3.],[2.,999.],[888.,777.]])
valid = np.array([[1.,1.],[1.,0.],[0.,0.]])
cont = np.array([[1.,0.],[0.,0.],[0.,0.]])
result = returns(r,valid,cont,.9,[0.,0.])
assert np.allclose(result,[[2.8,3.],[2.,0.],[0.,0.]])
changed = r.copy();changed[valid==0] = -10000
assert np.allclose(returns(changed,valid,cont,.9,[0.,0.]),result)
cut = returns(np.array([[2.]]),np.array([[1.]]),np.array([[1.]]),.9,[5.])
assert cut[0,0] == 6.5
print('batched_returns',result.tolist(),'truncated_target',cut.item())
```

这个函数的尾部自举只表达窗口最后边界，若在窗口中间截断并重置，需要逐步真实下一价值与单独迹掩码，不能简单把一个全局 tail 用于所有边界。实现接口的适用范围要准确，后文 GAE 使用每条转移明确的下一价值。

## 4. Actor 损失、停止梯度和统计单位

<a id="policy-3-detail-9"></a>

### 4.1 负 log 概率乘固定权重

REINFORCE 的 actor 损失是采样动作负 log 概率乘相对回报减基线，并按照目标加入外层时间折扣。回报与基线在当前 actor 更新中作为固定数值，避免额外通过 critic 或回报构造反向。它是梯度替代目标，不等于负环境回报的直接观测值，因此 loss 的绝对大小不用于比较策略质量。

动作张量在离散采样时通常不带普通导数，梯度通过 log 概率对应的策略参数传播。连续策略若使用可重参数样本，需要明确动作是否作为固定评分样本；否则 log 概率可能多出动作路径。先在解析例子上核对，再用复杂分布接口，能避免自动微分悄悄替算法做选择。

<a id="sec-1-1"></a>

<a id="policy-3-detail-10"></a>

### 4.2 按回合还是按有效步平均

本章目标按初始回合期望定义，因此先对每条轨迹的折扣梯度项求和，再按固定采集回合数平均。若直接除以本批随机有效步数，分母与策略轨迹长度相关，可能改变有限样本期望和隐含权重。值网络可以另按有效状态样本拟合，那是它自己的监督目标，不必与 actor 分母相同。

整体常数与样本相关分母不同。固定长度、固定批次时某些平均可能只差确定常数；可变终止时则不应不加说明。日志最好保留可加分子、回合数与有效步数，让别人能够复算。只写一个 mean 不足以描述完整训练目标。

### 4.3 实验二：基线梯度的额外路径

用一个二元动作样本和可训练基线，比较正确固定权重与未分离权重。两种 actor loss 前向数值相同，但错误版本会给基线额外梯度。随后检查 actor 的手算得分，以及多维动作 log 概率必须求和的身份。该实验专门检查计算图，不主张分离张量自动消除统计依赖。

```python
import torch
torch.set_num_threads(1)
logit = torch.tensor(.3,dtype=torch.float64,requires_grad=True)
baseline = torch.tensor(.4,dtype=torch.float64,requires_grad=True)
reward = torch.tensor(1.2,dtype=torch.float64)
logp = torch.nn.functional.logsigmoid(logit)
good = -logp*(reward-baseline).detach()
bad = -logp*(reward-baseline)
good_grads = torch.autograd.grad(good,(logit,baseline),allow_unused=True,retain_graph=True)
bad_grads = torch.autograd.grad(bad,(logit,baseline))
assert torch.allclose(good,bad)
assert good_grads[1] is None and bad_grads[1] is not None
expected = -(1-logit.detach().sigmoid())*(reward-baseline.detach())
assert torch.allclose(good_grads[0],expected)
old = torch.tensor([-.4,-.7],dtype=torch.float64)
new = torch.tensor([-.2,-.5],dtype=torch.float64)
correct_ratio = (new.sum()-old.sum()).exp()
wrong_ratio = (new.mean()-old.mean()).exp()
assert not torch.allclose(correct_ratio,wrong_ratio)
assert torch.allclose(wrong_ratio.square(),correct_ratio)
print('actor_gradient',good_grads[0].item(),'unwanted_baseline_gradient',bad_grads[1].item())
```

共享主干时，critic 的独立损失仍可训练共同参数；这里禁止的是 actor 权重构造中未声明的额外导数。应分别反向每个目标，理解每条路径，再检查合并更新。某参数有梯度不等于更新正确，也不保证它被当前优化器持有。

<a id="visual-insight-policybasedmethods-03"></a>
### 深入图解：不停止优势梯度会多出一条参数依赖路径

![不停止优势梯度会多出一条参数依赖路径](images/03-insight.svg)

构造单个已采样动作，其概率为 sigmoid(theta)，奖励一，基线同样取 theta。actor 损失为负对数概率乘一减 theta；把优势当固定权重时，只保留对数概率的导数，若让梯度穿过优势，会多出对数 sigmoid(theta) 项。参数零处正确半梯度为负零点五，错误全导数约负一点一九三一。图仅用于说明计算图权限，不是完整策略目标的无偏性证明；真实共享网络中 critic 自己的损失仍可更新共享参数，但不应无意混入 actor 的优势权重路径。

## 5. 从回报到 GAE 的数据接口

<a id="policy-3-detail-13"></a>

### 5.1 旧价值与真实下一状态

构造优势前，先用本次更新前的 critic 对当前状态和真实下一状态评分，保存数值。残差为奖励加折扣自举再减当前值，迹递推还需要单独回合连接标志。旧值只代表本批构造目标时的固定参考，不是另一个永久不更新的网络。之后 critic 可以拟合目标，但 actor 本轮权重保持不变。

GAE 加旧值常作为某种自举回报目标，它不是在所有迹参数下等于 Monte Carlo 回报。真实终止时两种边界都切断；外部截断可以保留下一价值却切断跨重置递推。前章已经推导误差来源，本章实现应让每个字段与这些条件一一对应。

<a id="policy-3-detail-14"></a>

### 5.2 优势中心化不是无害重命名

将优势减本批均值会使用当前样本自己的回报，随机标准差又加入额外缩放；它可能改善实践稳定性，但不自动保持原无偏估计。若不同回合长度、状态与奖励差异很大，影响更复杂。本章完整训练不使用优势标准化，使目标与解析约定更容易核对。

如果确实采用，应记录在哪个集合上算统计量，是整个 rollout 还是每个 minibatch，是否跨设备，是否排除填充。标准差接近零要定义行为，不能只加一个极小数掩盖异常。与 PPO 裁剪共同使用时，中心化还可能改变优势符号和裁剪支路，下一章会明确配置。

<a id="policy-3-detail-15"></a>

## 6. 人工环境的完整契约

<a id="policy-3-detail-16"></a>

### 6.1 状态、动作与随机转移

环境只有位置零、一、二，初始在零，二为目标。动作零向左，动作一向右，边界位置裁到合法范围。每次执行有零点一概率把左右动作翻转，噪声独立。抵达目标奖励一并终止，其他有效步奖励负零点零二，最多五次决策，到期后任务结束且无未来奖励。

策略按时间与位置给出二动作分布，critic 也按时间位置估值。它们是可训练表格，不含深网络、真实传感或隐藏状态。时间显式进入索引，避免有限期限的信息遗漏。这个任务足够小，能够解释训练过程和边界，却不能代表复杂控制或长期部分观测。

<a id="policy-3-detail-17"></a>

### 6.2 收集器如何处理结束样本

批量收集多条回合时，已经结束的样本保持其最后位置，后续奖励为零、有效掩码为假。可以继续为整批向量化采样动作，但这些无效位置不会进入损失或环境状态变化。抵达目标的那一步仍有效，最后期限动作也有效。正确掩码保证成功奖励不被删除，填充动作不产生学习信号。

当前代码没有中途自动重置，所有回合在每次收集开始独立重置，因此不会把下一回合接进同一列。它也没有外部截断，五步是任务真实期限。若扩展到持续环境，应新增相应字段和自举处理，而不是默认当前结束逻辑适用于所有情形。

<a id="policy-3-detail-18"></a>

### 6.3 两种训练方法的共同条件

两种方法都使用零初始化表格 actor 与 critic，每轮采集六十四回合，执行一次 actor 和一次价值更新，共二百轮。REINFORCE 用完整回报减更新前基线，GAE 使用迹参数零点九的残差和。两者都按回合归约 actor，并显式乘起始折扣时间权重，critic 按有效步拟合固定目标。

它们使用不同训练随机流，只有一次固定运行，不作显著优劣结论。初始参考回合与开发、测试均用独立固定随机流，开发每二十轮选择一次，最后恢复最佳状态再在四千零九十六回合测试。重复查看开发属于选择过程，测试不参与超参数或轮数调整。

<a id="policy-3-detail-19"></a>

## 7. 实验三：实际 REINFORCE 与 GAE 训练

下面代码独立包含环境收集、回报、优势、梯度、状态选择和测试。没有安装 Gym 或读取外部数据，不保存权重文件。采用双精度和单线程，目的是让机制容易复算。测试阈值只确认当前受控任务训练达到预期，不意味着作者未知任务上的严格盲测。

```python
import torch
from torch import nn

torch.set_num_threads(1)
dtype = torch.float64
H,gamma = 5,.95
def collect(actor,n,policy_seed,environment_seed,slip=.1):
    pg = torch.Generator().manual_seed(policy_seed)
    eg = torch.Generator().manual_seed(environment_seed)
    pos = torch.zeros(n,dtype=torch.long)
    alive = torch.ones(n,dtype=torch.bool)
    rows = []
    with torch.no_grad():
        for t in range(H):
            state = pos.clone()
            probabilities = actor[t,state].softmax(-1)
            action = torch.multinomial(probabilities,1,generator=pg).squeeze(1)
            flip = torch.rand(n,generator=eg)<slip
            executed = torch.logical_xor(action.bool(),flip).long()
            proposed = (pos+2*executed-1).clamp(0,2)
            next_pos = torch.where(alive,proposed,pos)
            reached = alive & next_pos.eq(2)
            reward = torch.where(reached,torch.ones(n,dtype=dtype),
                                 torch.where(alive,torch.full((n,),-.02,dtype=dtype),torch.zeros(n,dtype=dtype)))
            ended = ~alive | reached | (t==H-1)
            rows.append((state,action,reward,alive.clone(),ended,next_pos.clone()))
            alive = alive & ~ended
            pos = next_pos
    packed = tuple(torch.stack([row[k] for row in rows]) for k in range(6))
    discounted = (packed[2]*gamma**torch.arange(H,dtype=dtype)[:,None]).sum(0)
    return packed,discounted,pos.eq(2)
def train(method,seed):
    actor = nn.Parameter(torch.zeros(H,3,2,dtype=dtype))
    critic = nn.Parameter(torch.zeros(H+1,3,dtype=dtype))
    oa = torch.optim.Adam([actor],lr=.04)
    ov = torch.optim.Adam([critic],lr=.04)
    best,best_step,state = -float('inf'),None,None
    first = collect(actor,1024,700,701)[1].mean().item()
    for update in range(1,201):
        batch,_,_ = collect(actor,64,seed+2*update,seed+2*update+1)
        states,actions,rewards,valid,ended,next_states = batch
        times = torch.arange(H)[:,None]
        with torch.no_grad():
            oldv = critic[times,states]
            nextv = critic[times+1,next_states]
            if method=='reinforce':
                ret = torch.zeros_like(rewards);carry = torch.zeros(64,dtype=dtype)
                for t in range(H-1,-1,-1):
                    carry = (rewards[t]+gamma*(~ended[t])*carry)*valid[t]
                    ret[t] = carry
                advantage = (ret-oldv)*valid
                target = ret
            else:
                delta = (rewards+gamma*(~ended)*nextv-oldv)*valid
                advantage = torch.zeros_like(delta);carry = torch.zeros(64,dtype=dtype)
                for t in range(H-1,-1,-1):
                    carry = (delta[t]+gamma*.9*(~ended[t])*carry)*valid[t]
                    advantage[t] = carry
                target = advantage+oldv
        logp = actor[times,states].log_softmax(-1).gather(-1,actions[:,:,None]).squeeze(-1)
        actor_loss = -(gamma**torch.arange(H,dtype=dtype)[:,None]*valid*advantage*logp).sum()/64
        value = critic[times,states]
        value_loss = .5*((value-target).square()*valid).sum()/valid.sum()
        oa.zero_grad();actor_loss.backward()
        assert torch.isfinite(actor.grad).all()
        oa.step()
        ov.zero_grad();value_loss.backward()
        assert torch.isfinite(critic.grad).all()
        ov.step()
        if update%20==0:
            dev = collect(actor,512,800,801)[1].mean().item()
            if dev>best:
                best,best_step = dev,update
                state = (actor.detach().clone(),critic.detach().clone())
    with torch.no_grad():
        actor.copy_(state[0]);critic.copy_(state[1])
    _,test_return,success = collect(actor,4096,900,901)
    assert test_return.mean().item()>first+.2
    assert success.double().mean().item()>.85
    assert torch.equal(critic[-1],torch.zeros_like(critic[-1]))
    return {'method':method,'initial_dev_reference':first,'selected_dev':best,
            'selected_update':best_step,'test_discounted_return':test_return.mean().item(),
            'test_success':success.double().mean().item()}
for method in ['reinforce','gae']:
    print(train(method,1000 if method=='reinforce' else 2000))

```

<a id="policy-3-detail-20"></a>

### 7.1 本次运行结果

初始参考折扣回报约零点四八三。REINFORCE 的开发选定第二百轮，测试折扣回报约零点八八九二三，成功率约百分之九十八点二四；GAE 同样选第二百轮，测试回报约零点八九零二五，成功率约百分之九十八点三四。所有 actor 与 critic 梯度有限，最后时间价值行保持零。

二者差异很小，训练随机流不同，也没有重复完整训练，因此不能据此宣称 GAE 在该任务显著更优。实验主要验证从轨迹到更新再到独立评价的完整链路。环境噪声仍会造成失败，满分不是断言目标；已知有限任务上的高成功也不能外推到真实机器人或大模型策略。

<a id="policy-3-detail-21"></a>

### 7.2 哪些数据参与了选择

训练回合用于梯度，开发五百一十二回合的固定随机流用于每二十轮选点，最终测试四千零九十六回合在冻结后运行。初始参考使用另一组回合，仅用于描述起点。固定开发噪声有助于比较检查点，但重复选择会对它适应，因此开发分数不是独立最终证据。

所有回合仍来自相同人工机制，不代表跨动力学泛化。若希望研究新翻转概率、新期限或新奖励，应预先安排相应留出，并重新说明目标。根据测试失败修改后，应另设新的确认流，而不是继续把原测试称作未见。

<a id="sec-5"></a>

<a id="policy-3-detail-22"></a>

## 8. 每个更新对象的梯度审计

<a id="policy-3-detail-23"></a>

### 8.1 Actor 与 Critic 分开

本章两者没有共享参数，actor 反向只应影响策略表，价值反向只应影响价值表。构造优势在无梯度区域，随后用当前 log 概率建立 actor 图，用当前值建立 critic 图。每次更新前清空相应梯度，检查梯度存在且有限，再执行优化器。

若改成共享网络，应重新分析两部分如何累加，不能照搬互不影响的结论。即使 actor 项平坦，critic 也可能通过主干改变策略。反过来，错误地把全部主干放入无梯度区域，会让预期可训练层失去导数。前面多模态章节的冻结链经验在这里仍适用。

<a id="policy-3-detail-24"></a>

### 8.2 当前批基线来自哪里

当前 critic 是用过去训练批次更新的，本批采样前已经固定。给定策略与状态，其数值不直接用本次动作结果拟合，因此更接近普通动作无关基线条件。当前批先完成 actor 更新，再让 critic 拟合本批固定目标，不让新 critic 反过来改变已使用的优势。

这种顺序不是唯一可行算法，但它清楚说明依赖。若先用本批过度拟合 critic 再更新 actor，统计自依赖需要另行讨论；若在多个 epoch 重建优势，目标也在变化。实现可以不同，名称应准确，不能把所有顺序都混称为同一个 REINFORCE 或 GAE 更新。

<a id="sec-6"></a>

<a id="policy-3-detail-25"></a>

## 9. 常见失效与定位路线

<a id="policy-3-detail-26"></a>

### 9.1 回报下降先检查什么

先核对奖励发生时间、终止动作是否有效、折扣是否重复和下一状态是否真实。然后检查动作 log 概率、优势停止梯度、优化器参数身份和平均分母。若连少量确定性任务都无法改善，扩大网络和样本通常不是首要步骤。机制测试应该先于泛化故事。

如果机制正确但训练不稳定，才研究回报尺度、基线误差、探索覆盖和步长。若训练回报高但独立评价差，重点检查开发选择、随机流、任务分布和环境重置。不同现象有不同竞争解释，不能每次都归因于 GAE 参数或网络宽度。

<a id="sec-6-1"></a>

<a id="policy-3-detail-27"></a>

### 9.2 归约和日志

累计总回报与回合数，累计 actor 分子与回合分母，累计 critic 误差与有效步数，分别记录。批次平均再平均在批量不等时可能错误。最后一个小批、提前结束和填充都影响实际数量。日志应能复算，而不是只保留经过平滑的单个标量。

同一条随机流重复运行不会创造更多独立证据。固定参数下增加评价回合减少采样误差，重复完整训练测量学习随机性，两个维度分开。当前代码只运行一次每种方法，故结论严格限定为机制演示和给定设置的实际观察。

<a id="policy-3-detail-28"></a>

## 10. 进阶练习与详细解答

<a id="policy-3-detail-29"></a>

### 10.1 题一：终止步是否有效

题目：本次动作抵达目标，随后回合结束，当前奖励和 log 概率是否应屏蔽？

解答：不应，它们属于真实有效决策，正是成功信用来源。只屏蔽后续填充，下一价值才因终止为零。若根据动作后 alive 标志回头屏蔽当前步，会删除最重要奖励。应分别保存动作前有效性和动作后终止状态。

可以把有效性定义为执行动作前的 alive，把结束定义为动作后的 reached 或 deadline。两者在成功步分别为真和真，不矛盾。更新下一轮 alive 时才变假。这个时序约定应在单步环境中先检查，防止成功回报被当作填充抹去。

<a id="policy-3-detail-30"></a>

### 10.2 题二：填充值干扰

题目：结束后的填充奖励被写成很大数，正确程序的前面回报是否应变化？

解答：不应，边界与有效掩码应使它完全不参与。实验一故意用大数验证，能发现仅在最后 loss 乘 mask 却已让递推污染过去的错误。掩码必须在正确计算阶段生效，而不只用于显示。

仅在最终 loss 乘掩码还不一定够：如果回报反向累计时已经把后面大数加到前面，有效位置的目标会受污染。实验先在递推中应用边界，再检查填充替换不变量，针对的是整个目标构造，而不是只保证无效位置最后不反向。

<a id="policy-3-detail-31"></a>

### 10.3 题三：按步平均的目标

题目：两回合长度一和五，将全部有效项平均是否等于先各回合求和再平均？

解答：通常不同，前者分母是六，后者是二；可变随机长度还使分母与数据相关。应根据初始回合目标或随机状态样本目标选择，并解释整体尺度和相对权重。不能只因都叫平均就默认同一估计器。

若两条轨迹的项和分别为二和十，按回合平均为六，按总步数平均为二。固定当前样本时是比例差，但当策略改变长度、批次长度随机或与其他损失结合，不能统一视为常数。应区分有限批估计器与总体平均，并记录真正分母。

<a id="policy-3-detail-32"></a>

### 10.4 题四：重新评分为何可用

题目：收集时没有保存梯度图，如何让 actor 学习？

解答：保存状态和实际动作后，在更新前用对应策略重新计算 log 概率，建立新的图。单次更新前参数未变可匹配采集分布；多轮更新则需要旧行为概率与比率等协议。缺少采样图不妨碍似然比，缺少正确动作身份才会出错。

重新评分必须使用与采样相同的输入规范、合法动作和分布参数。若采样时有额外温度而更新时忘记，虽参数未变也不是同一个策略。多维连续动作还要还原相同变换与联合 log 密度。前向调用相同模型名不够，实际函数必须一致。

<a id="policy-3-detail-33"></a>

### 10.5 题五：优势需要梯度吗

题目：actor loss 中让优势通过 critic 回传，会发生什么？

解答：加入了普通得分估计之外的路径，当前权重不再被视为固定。前向数值可能完全相同，梯度对象却改变。Critic 应通过自己的明确目标训练，共享参数时也要分别理解贡献。detach 解决图路径，不自动证明统计无偏。

实验二错误路径给基线约负零点五五四的额外梯度，正确路径没有这项。Actor 对 logit 的梯度约负零点三四零四，与手算一致。这个小数例子可以直接查清哪个参数应收到信号，避免只看到某个总体梯度非零就宣布实现正确。

<a id="policy-3-detail-34"></a>

### 10.6 题六：到期与截断

题目：本章五步结束为何设未来值零，而某些收集窗口不应设零？

解答：五步是任务真实期限，之后定义无回报；窗口暂停只是执行预算，原任务可能继续。两种停止原因不同。应把任务语义写在环境契约，再映射到自举和迹掩码，不能从数组长度猜测。

例如当前一步奖励二、外部窗口结束但未来值五，折扣零点九时目标应为六点五；若真正终止则只有二。一个 done 标志无法同时表达两种语义，除非接口另有明确约定。测试夹具应该同时覆盖它们，而不是只在自然结束环境里通过。

<a id="policy-3-detail-35"></a>

### 10.7 题七：旧值和当前值

题目：为什么构造目标后价值网络可以更新，但本轮 actor 优势仍固定？

解答：这样每次更新的对象可清楚对应同一批参考。若随 critic 每步重算优势，就成为另一个交替算法，可能有不同偏差与稳定性。固定不代表永远不学习，而是说明某轮目标的身份。

本章旧值在每轮采集结束后从当前 critic 取得，目标构造完成后分离。Actor 更新不会直接改分离的旧值，critic 随后用独立图拟合。若改为共享网络，actor 更新还可能改变当前 critic 预测，但旧目标仍应保持当时数值，数据身份需明确。

<a id="policy-3-detail-36"></a>

### 10.8 题八：归一化优势

题目：减本批均值除本批标准差是否只是改变学习率？

解答：不一定，均值含自身数据，标准差随机，符号也可能改变；在裁剪目标中还会改变支路。它可以有实践价值，但不是普通固定基线定理直接保证。应记录统计集合与零方差处理，并按共同任务评价。

还要说明统计量是在有效时间步、回合还是每个小批上计算。把填充零包含进去，会使长度变化影响均值和标准差；各小批独立标准化又产生不同局部目标。正确排除填充只解决一项问题，不能证明其余随机归约都与原目标等价。

<a id="policy-3-detail-37"></a>

### 10.9 题九：最后价值行

题目：时间表格里最后一行为什么应保持零？

解答：当前有限任务到期后没有价值，该行用于表达终端边界而非待学习未来。代码没有对它提供有效拟合目标，梯度应为零。若使用权重衰减或其他更新改变它，还需明确是否仍符合任务定义。

最后时间行可以保留在参数张量中以方便索引，但它代表固定终端边界，不应被不相关损失或权重衰减推离零。另一种实现是根本不存该行，直接返回零。两种接口都可以，只要对终止与到期的取值一致，并且未终止窗口不被误判。

<a id="policy-3-detail-38"></a>

### 10.10 题十：GAE 目标是否纯回报

题目：GAE 加旧价值一定等于本回合实际完整回报吗？

解答：迹参数小于一时通常不等，包含多步自举混合。只有适当终止和端点条件下某些特例恢复完整回报。Critic 目标应准确命名，不能拿两个不同目标数值直接评价谁更真实。

例如前章三步数组在迹参数零点七时，GAE 加旧值约为三点八五四、四点一八七和三；Monte Carlo 回报则为五点二三、四点七和三。差异来自自举混合，不表示其中某个数组数值算错。命名准确有助于解释 critic 学到了哪一种目标。

<a id="policy-3-detail-39"></a>

### 10.11 题十一：共享参数的改变

题目：改成共享主干后，价值更新会不会改变策略？

解答：可能，即使策略头没有直接梯度，共享表示变化也会改变 logits。因此需检查完整优化器步后行为，而不是只看 actor 项。当前表格分离设计特意排除这类交互，便于先理解基础链路。

如果共享主干还包含运行统计或随机层，训练模式与评估模式也可能改变策略函数。应在完整更新后用固定输入重新评分，并检查所有预期状态。当前分离表格排除这些变化，让读者先把 actor 和 critic 目标学清楚，再研究更复杂耦合。

<a id="policy-3-detail-40"></a>

### 10.12 题十二：开发固定随机流

题目：开发每次用相同随机流是否构成最终独立测试？

解答：不是，它可降低检查点差异的评价噪声，却因重复选择参与开发。最终另用独立流确认，且不能根据确认结果继续挑参数。固定开发有价值，但不提供无限独立证据。

本章每二十轮读取同一开发流，最多十次选择机会，保存其中最好状态；测试流只在冻结后调用。开发得分用于选点，因此再好也不能当未参与决策的证据。若增加查看频率，应把它当选择程序变化记录，而不是假装同一预算。

<a id="policy-3-detail-41"></a>

### 10.13 题十三：两方法差异很小

题目：本章 GAE 测试比 REINFORCE 高一点，能否宣布普遍更优？

解答：不能，只有各一次训练、随机流不同、差异很小，且同一人工机制范围有限。应重复完整训练、匹配预算并估计不确定性。当前结果主要验证两条实现都能工作，而不是方法排行榜。

可以先固定训练结果增加测试回合，判断当前回报差是否主要由评价噪声造成；再重复从头训练，判断初始化与交互路径差异。两种实验不能互相代替。当前数据只支持两条实现都能学到接近已知参照的策略，不能支持普遍方法排序。

<a id="policy-3-detail-42"></a>

### 10.14 题十四：填充动作消耗随机数

题目：向量化时为已结束样本仍采动作，是否必然改变任务？

解答：若其状态、奖励和损失都被正确隔离，不会成为真实决策，只改变随机数消费细节。复现需固定同一实现，不能假设换批量后相同种子逐条一致。若填充动作进入递推或统计，则是另一类错误。

比如某回合两步结束，后面三步抽样虽然消耗了随机数，却不应移动终态或产生奖励。改变批量会影响随机数映射，因而同种子逐回合输出未必相同。统计机制仍可保持一致。复现报告应明确要匹配的是完整轨迹还是相同分布结论。

<a id="policy-3-detail-43"></a>

### 10.15 题十五：当前基线的数据依赖

题目：为什么当前批用之前训练的 critic，比先拟合当前回报再作基线更易分析？

解答：当前采样前其参数固定，给定状态不直接使用本次动作结果。先在当前批拟合会产生统计自依赖，即使计算图分离也需考虑。两种程序可以研究，但必须说明顺序和近似，不能由函数输入没有动作就证明无偏。

条件于采样前所有参数和历史，当前状态基线固定，当前动作按策略抽取，得分均值零。若先用当前动作回报拟合，再把预测值用于同批，参数随机性会与动作相关。停止梯度不会删除这种统计关系，需交叉拟合、其他规则或准确承认近似。

<a id="policy-3-detail-44"></a>

### 10.16 题十六：怎样扩展到持续任务

题目：把本章环境换成无限持续过程，第一步该改哪里？

解答：重新定义停止与采样窗口，保存真实下一状态、自举与迹边界，必要时维护持续记忆。不能只删五步上限而沿用全部终止逻辑。再建立可解析小例子核对，然后接完整环境，避免目标被收集器悄悄改变。

持续任务还可能要求跨窗口保存策略记忆与环境状态，而不是每个窗口独立初始。若只是为了训练效率重置，等于改变了任务分布。应先重新写随机过程和评价单位，再决定如何收集、何处自举和怎样统计回报。原有小测试可以保留，但不代替新增边界。

<a id="sec-7-1"></a>

<a id="policy-3-detail-45"></a>

## 11. 综合研究任务

先保持当前环境，比较不同基线、迹参数与回合批量，所有选择在开发角色完成，最终统一测试。记录每轮真实交互与优化器步数，区分固定参数估计器噪声和完整训练随机性。再加入外部窗口截断，验证正确自举与错误清零的差异，保持真实任务不变。

下一章将在同类可审查环境中加入旧 log 概率、多 epoch、策略裁剪与熵项，形成完整 PPO。当前代码只执行一次 actor 更新，不应被无条件重复后当作 PPO。逐步增加机制并保留精确测试，让每次新增复杂性都有清楚可核验的含义。

<a id="policy-3-detail-46"></a>

## 12. 轨迹契约的进一步展开

<a id="policy-3-detail-47"></a>

### 12.1 当前状态、下一状态和最终观察

对于每条转移，可以把身份写成回合编号、动作时间、当前状态、动作、奖励、真实下一状态和停止原因。当前策略 log 概率评分必须使用动作前输入，下一价值使用动作后原回合输入。若某个接口把 reset 结果覆盖 final observation，需要在存储时保留原始字段，而不是希望训练函数从数值猜出身份。

一个简单审计是打印一条成功回合：位置零选择向右，未翻转到一得负成本，再向右抵达二得一并结束。对应两份 log 概率都有效，第二步下一值零，后面填充无效。若第一步被翻转，位置仍零，状态序列和奖励仍应一致。先能逐步解释这条表，再讨论批量实现，能减少许多隐蔽错误。

<a id="policy-3-detail-48"></a>

### 12.2 截断需要两种边界信息

假设原任务持续，收集器在某一步暂停并重置。该条记录的残差可以使用原最终状态价值，但后续优势递推不能接到新回合。因此自举与迹连接是不同布尔量。若只是同一回合窗口切分且下一窗口将继续，是否跨窗口联合计算又取决于实现协议，不能统一按 reset 处理。

数据加载时常把所有停止标志合并，导致后面无法恢复语义。应该在边界处记录足够信息，让回报函数接受明确参数。否则即使后来知道应自举，也没有真实下一状态可用。缺失字段不是通过换一个 GAE 公式就能补救，信息采集必须先正确。

<a id="policy-3-detail-49"></a>

### 12.3 终止奖励的时间位置

本章抵达目标的奖励在导致抵达的动作之后产生，并属于该动作的当前奖励。若代码把它写到下一条记录，再用相同折扣递推，会多折扣一次，甚至在终止掩码处被删除。环境和收集器必须共同约定奖励索引，不能只凭数组名叫 rewards 就认为一致。

可以用只有一次有效动作的任务测试：动作成功奖励一，目标梯度应直接乘一，而非折扣后的数或零。再加入两步任务，核对第一动作信用包含一次相对折扣。单步与双步组合能明确暴露索引错位，比在五步环境里看一个总分更容易定位。

<a id="policy-3-detail-50"></a>

### 12.4 可用时间与策略输入

有限任务同一位置在早期与最后一次决策可能有不同价值，本章用时间索引表格直接表达。若改为一个只读位置的网络，得到的是受限时间无关策略，不再与当前策略类相同。可以研究这种限制，但应重新比较最优参照，不把表现差距全部归因于训练算法。

同样，部分观测环境中的历史或记忆应随回合重置。若在训练保留隐藏状态而测试每次清空，或相反，输入函数已经变化。轨迹不仅保存环境状态，还要保存或重建策略内部状态。当前表格刻意不含记忆，排除这层因素以便先核验基本程序。

<a id="policy-3-detail-51"></a>

## 13. 回报归约与梯度目标

<a id="policy-3-detail-52"></a>

### 13.1 固定回合分母的含义

对固定数量独立初始回合，样本梯度是每回合时间项之和的平均，匹配初始分布期望。可变长度只是每条轨迹贡献项数量不同，并不要求重新按本批总步数归一化。如果把分母换成随机总步数，得到的是一个比值估计器，有限样本下其期望通常不等于原分子期望除以固定常数。

在大样本下，某些按步平均可能趋向一个按平均长度缩放的量，但策略与回合长度的关系、终止机制和更新目标仍需分析。不能用渐近直觉证明每个有限批次更新相同。若目的确实是随机有效状态上的代理目标，可以采用相应平均，但应准确描述，而不是把两种约定混在同一算法名里。

<a id="policy-3-detail-53"></a>

### 13.2 外层折扣在完整代码中的位置

代码中优势和回报使用从当前时刻开始的相对折扣，actor 再乘从回合起点的折扣幂。当前环境策略显式按时间索引，因此漏掉外层因子会改变不同时刻参数的相对更新。前章的有限轨迹梯度已经提供解析反例，本章保留相同约定以避免实现漂移。

Critic 拟合的是相对状态价值，不应再把所有目标无条件乘起点折扣，否则其语义改变。Actor 和 Critic 使用不同归约，并非自相矛盾，而是它们估计的对象不同。把每个张量标注为相对回报、起始权重或有效数量，能够清楚解释代码中的每一次乘法。

<a id="policy-3-detail-54"></a>

### 13.3 半梯度目标和 actor 权重

完整训练用无梯度区域构造旧价值、下一值、回报和优势，随后 actor 只经 log 概率反向，critic 只经当前预测反向。这样明确实现半梯度与固定权重。若直接把网络输出连在回报构造图上，actor 和 critic 都可能收到未声明的额外导数，前向数字仍一致，因此必须逐路径检查。

无梯度区域并不是越大越安全。若 actor 自身评分也被包进去，策略根本没有梯度；若未来采用可训练上游编码器，冻结中间层也可能仍需传输入导数。应该按目标推导需要的路径，而不是为了减少内存随意 detach。计算正确性与资源优化要有先后依据。

<a id="policy-3-detail-55"></a>

### 13.4 优化器身份与原地操作

优化器持有具体参数对象，模块替换或重新初始化后，旧优化器未必更新新对象。可以在一次小更新前后比较预期参数，确认不仅有梯度，而且数值确实变化。原地修改共享张量也可能使所谓旧值或最佳状态随训练漂移，保存状态需要独立副本。

本章开发检查点使用张量 clone，最终恢复 actor 与 critic 两份选定状态。只保存最佳分数而没有对应权重，不能证明测试来自最佳模型。继续训练还需要优化器、随机流与更新计数等更多状态；当前内存恢复只为推理评价，不宣称精确恢复训练轨迹。

## 14. 精确动态规划参照

<a id="policy-3-detail-57"></a>

### 14.1 为什么还需要一个已知最优值

完整训练回报上升说明程序学到某种有用行为，却不能仅凭接近一就知道离最优多远。当前环境足够小，可以按剩余步数动态规划，不给训练器提供这些值，只用于独立分析。它享有完整模型知识，因此是理想参照，不是与无模型学习同信息预算的竞争算法。

状态一选择向右时，九成直接得一并结束，一成翻转到零且得负成本；状态零向右时，九成到一、一成留零，普通步奖励均为负成本。把这两类分支写出来，再按后续价值递推，就能得到每个剩余时间的动作值。最后一步位置零无法到目标，两动作在当前回报上可能平局，程序可以按固定规则选一个。

<a id="policy-3-detail-58"></a>

### 14.2 实验四：模型参照与成功概率

下面分别累计折扣回报与成功概率，按回报选择动作。二者不是同一个指标，不能用成功率替代所有成本与延迟。代码不参与前面的训练、开发或选点，只在冻结任务定义后提供可复算参照。它同样只使用内存与 NumPy。

```python
import numpy as np
H,gamma,slip = 5,.95,.1
value = np.zeros((H+1,3))
success = np.zeros((H+1,3))
policy = np.zeros((H+1,2),dtype=int)
for h in range(1,H+1):
    for state in [0,1]:
        choices = []
        for action in [0,1]:
            q,hit = 0.,0.
            for flip,probability in [(0,1-slip),(1,slip)]:
                executed = action^flip
                new = int(np.clip(state+2*executed-1,0,2))
                terminal = new==2
                reward = 1. if terminal else -.02
                q += probability*(reward+(0. if terminal else gamma*value[h-1,new]))
                hit += probability*(1. if terminal else success[h-1,new])
            choices.append((q,hit))
        best = int(np.argmax([pair[0] for pair in choices]))
        policy[h,state] = best
        value[h,state],success[h,state] = choices[best]
assert np.isclose(value[5,0],.89832212771125)
assert np.isclose(success[5,0],.98739)
assert np.all(policy[1:,1]==1) and np.all(policy[2:,0]==1)
print('optimal_start_value_by_remaining_steps',value[1:,0].tolist())
print('optimal_five_step_success',success[5,0])

```

<a id="policy-3-detail-59"></a>

### 14.3 从手算核对前两轮

只剩一步时，位置零必得负零点零二，位置一向右的价值为零点九乘一加零点一乘负零点零二，等于零点八九八。剩两步时，位置零向右价值为负零点零二加零点九五乘两种后继价值的加权和，得到零点七四五八九。继续递推五步，起点最优折扣值约零点八九八三二二，成功概率约零点九八七三九。

训练后随机策略的测试回报约零点八八九与零点八九零，接近但低于这个已知参照。差距可能来自策略仍随机、有限训练和评价抽样，不应在没有进一步分析时唯一归因于基线或 GAE。增加固定模型评价样本可减少抽样误差，重复完整训练才能估计学习波动，两者分工不同。

<a id="policy-3-detail-60"></a>

### 14.4 最优参照与测试角色

解析值可以在教材中解释任务上限，但若研究者据它反复调模型直至接近，该信息也参与了方法设计。真正比较新算法仍需预先冻结预算与评价，或采用新的确认任务。不能因为参照来自公式就认为任何基于它的选择都不算开发。信息边界包含人类设计者使用的知识。

本章没有让训练器查询最优动作，也没有用动态规划值作为 critic 标签。两条训练路径只用采样奖励与自己估计值。保留这种隔离，才能说实际实现了 REINFORCE 与 GAE，而不是用已知最优监督替代了学习。参照负责解释，不负责偷偷解决任务。

<a id="policy-3-detail-61"></a>

## 15. 随机性、评价与复现

<a id="policy-3-detail-62"></a>

### 15.1 策略采样与环境噪声分开

代码为动作抽样和环境翻转使用不同随机流，便于独立控制。开发与测试也使用单独固定种子，不消耗训练随机流。若评价直接复用训练随机数，可能改变后续训练轨迹，使评价频率成为隐藏超参数。分离随机源可以减少这种不必要耦合，但不代表所有跨平台执行逐位一致。

同一随机种子在不同批量、向量化顺序或采样算法下可能消费不同数量随机数，因此输出不一定逐条匹配。复现应固定程序与配置，并同时关注统计结论。若需要严格轨迹一致，要另行固定软件、精度与执行条件，不能只写一个 seed。

<a id="policy-3-detail-63"></a>

### 15.2 每种误差来自哪里

训练随机性包括初始参数、动作、环境和数据顺序；评价抽样误差是在固定训练结果下估计回报的不确定性；开发选择又引入适应性。当前 actor 零初始化，减少了一种变化，但动作和环境仍随机。一次较好的测试不提供完整稳定性估计，应准确限定。

可以固定训练模型增加评价回合，研究测试均值稳定；再重复从头训练，研究方法波动。两种资源成本不同，不应把前者很小的标准误当作整体训练可靠。比较两方法时还要匹配选择机会、交互预算和优化器步数，避免把额外调参优势当作估计器改进。

<a id="policy-3-detail-64"></a>

### 15.3 成功率与回报同时报告

本章任务提前成功减少负成本并减少奖励折扣，因此更快到达通常有更高回报。两个策略成功率相近，也可能因到达时间不同而回报不同。应保留成功、失败、步数和折扣奖励分解，分析差异来源。只看一个比例会丢失这些取舍。

若未来引入高代价失败，应按风险与状态分层，而不是只用均值。评价者可以使用环境真值标记成功，但策略输入仍限制在声明状态。模拟器中的调试字段不能无意传入 actor。观察、奖励和评价标签的权限应共同核对。

<a id="policy-3-detail-65"></a>

### 15.4 无中间产物不等于无依赖

本章所有状态在内存中，最终 Markdown 已包含生成机制与完整代码，不需保留权重或临时脚本。若扩展到真实工程，必要配置、词表和模型依赖必须按交付需求保存，不能为了目录整洁删除唯一运行条件。清理应针对无用生成物，而非破坏结果可复现性。

一个独立读者应能从当前代码重算奖励、回报、优势和更新对象，不依赖口头解释。若某个条件只能从聊天记录得知，应补进正式章节。详实资料的标准不只是字数，而是每个关键数值、状态与结论都有清楚来源。

<a id="policy-3-detail-66"></a>

## 16. 深入实现的研究练习

<a id="policy-3-detail-67"></a>

### 16.1 题十七：模型最优值是否给了学习器

题目：教材能算最优回报，是否意味着训练已使用最优监督？

解答：不一定，要看信息是否进入训练或选择。当前动态规划独立于两条训练路径，训练器只用采样奖励和自身价值；参照用于分析。若后续据参照反复选超参数，应承认设计使用该知识。公开模型的小任务更适合机制研究，不能无条件叫未知任务盲测。

<a id="policy-3-detail-68"></a>

### 16.2 题十八：成功率相同为什么回报不同

题目：两个策略都成功九成，是否对当前目标等价？

解答：不一定，到达时间和失败前步数会改变成本与折扣。应该比较实际原目标均值，并检查成功条件和预算一致。若只关心成功率，可另定义该目标，但不能在训练优化折扣回报时把二者混同。指标应服务明确任务，而不是只挑最容易提高的数。

<a id="policy-3-detail-69"></a>

### 16.3 题十九：一次更新后优势仍正确吗

题目：同一批数据 actor 更新多次，每次仍用原 REINFORCE log 概率权重，是否自动无偏？

解答：不自动。策略已偏离行为分布，固定动作与状态来自旧策略。需要说明离策略校正或局部替代近似，不能把重复计算当作更多 on-policy 样本。下一章通过固定旧 log 概率和比率明确这个问题，但裁剪也不等于完全消除偏差。

<a id="policy-3-detail-70"></a>

### 16.4 题二十：终止后状态保持为何重要

题目：已到目标样本虽然 loss 被屏蔽，收集器仍随机让它离开目标，会有什么风险？

解答：当前损失可能暂时不受影响，但最终成功标记、日志或下一状态自举可能被污染。保持终态能让数据身份更清楚，避免未来重构时无效动作变成真实状态变化。向量化可以保留无用抽样，但不能无声修改已结束轨迹的业务事实。

<a id="policy-3-detail-71"></a>

## 17. 用具体数值核验实现解释

<a id="policy-3-detail-72"></a>

### 17.1 一条最短成功轨迹

若从位置零连续两次实际向右，第一步到一得负零点零二，第二步到目标得一。两步相对回报分别为负零点零二加零点九五，等于零点九三，以及一。初始目标下第二步梯度还乘一次外层零点九五。当前 critic 若初始全零，REINFORCE 权重就是这些回报，第一批目标非常容易手算。

如果第一步动作被翻转并留在零，该步仍有效且得成本，后续所有时间权重相应后移。若到期没有成功，最后一步仍有负成本，但没有额外未来。成功、翻转和到期三条轨迹分别覆盖环境的主要分支，应该逐条检查，不能只依赖平均回报。

<a id="policy-3-detail-73"></a>

### 17.2 回报递推与 GAE 的同边界核对

在同一条完整终止轨迹上，将迹参数设为一，残差和应等于回报减旧价值，无论旧价值是否精确。这个恒等式是路径代数，不需要训练收敛。若结果不一致，检查下一状态索引、终端值、连接标志与是否误把不同回合接在一起，再考虑浮点容差。

外部截断时还会保留边界自举，不能再与清零终端的完整回报直接比较。应在手算里明确补上同一个边界值，才能检验等式。很多看似 GAE 理论矛盾，实际来自比较两种不同边界目标。把边界数值写出来，比讨论抽象 done 更有效。

<a id="policy-3-detail-74"></a>

### 17.3 表格策略与神经策略的迁移

当前 actor 是时间位置表，每个索引直接产生两个 logits。迁移到网络时，输出维度与动作数仍应一致，评分使用记录的实际动作，联合 log 概率与掩码规则不变。新增主干会共享不同状态信息，可能改善泛化，也可能让一个状态更新影响其他状态。原来的逐参数独立直觉不再成立。

因此应保留当前表格实现作为精确参照，再在同一环境验证网络前向、梯度与训练。若网络结果异常，先判断是共享表达、优化还是接口变化。不能一换网络就同时换奖励、采样和评价，否则很难解释差异。算法的核心统计对象应跨实现保持清楚。

<a id="policy-3-detail-75"></a>

### 17.4 结果文件中保留真实边界

本章四段独立 CPU 实验中，前三类分别检查数组、计算图和真实训练，第四段用已知模型求上界参照。没有生成外部脚本或权重，没有安装环境，也没有把解析最优标签喂给学习器。完整代码和条件已写入 Markdown，读者可以从零复算。

真正进阶的下一步，是明确一个新困难并给出对应测试：例如外部截断、策略记忆、共享主干、概率比或多轮复用。每一步都说明改变了什么以及哪些旧结论不再自动适用。这样复杂算法仍能被拆成一串可验证对象，而不是只能凭训练曲线相信它。

<a id="policy-3-detail-76"></a>

### 17.5 初始零价值下两种权重为何不同

在最短成功轨迹中，初始 critic 全零，两个残差就是负零点零二与一。REINFORCE 第一优势为零点九三；GAE 迹参数零点九时，第一优势为负零点零二加零点九五乘零点九，等于零点八三五。第二优势都为一。两者并非同一梯度估计器的数值实现，GAE 此时依赖尚不准确价值，确实改变了早期信用分配。

这个差别不妨碍两种方法在当前简单任务都学会，但也说明不能用最终分数接近来证明它们每步无偏且等价。随着 critic 变化，GAE 权重又会改变。估计器条件、训练动态与任务结果应分别解释，既不夸大一个默认参数的理论地位，也不因存在近似就否定其实用性。

<a id="policy-3-detail-77"></a>

### 17.6 Actor 更新后 Critic 拟合谁

当前批来自更新前策略，回报与优势在那一批上构造，随后 actor 改变，critic 再拟合固定旧目标。因此 critic 不是瞬间变成新策略的精确价值，它在跟踪随训练变化的目标。下一轮新交互又来自新策略，继续提供数据。这个滞后是实际 Actor–Critic 程序需要理解的一部分，不应在描述里假装每轮 critic 都精确求解。

若希望研究这种滞后，可以固定 actor 多做价值更新，或改变两者更新比例，再在共同交互与计算预算下比较。额外拟合也可能过度迎合同一批目标，因此仍需独立数据。当前代码只采用一种明确顺序，没有把它宣称为所有环境最优安排；它提供的是可追踪、可复算的实现基线。

<a id="policy-3-detail-78"></a>

### 17.7 期限更长为何不保证每个状态价值单调

在位置一，剩一步最优值零点八九八；剩两步却约零点八九六一。原因是向右被翻转到零时，额外期限要求再执行一次带成本的动作，而一步任务已经结束。成功概率此时仍是零点九，额外失败成本使价值略低。这个结果可由精确递推复算，不是浮点误差。

若允许随时免费停止，智能体可能选择忽略额外机会，单调性条件会改变。当前环境没有该动作，不能套用另一个任务的直觉。研究期限、成本和策略时，应先检查合法动作与停止权利；看似反常的数值往往能帮助发现我们无声加入了模型没有的假设。
