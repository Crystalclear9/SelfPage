[主题目录](README.md) · [分类目录](../README.md) · [总目录](../../README.md) · [上一章](03-凸性二阶方法与约束优化.md)

前三章解释了下降方向、状态、曲率与约束。本章把这些知识变成一个能复核的实验：明确比较对象，设计有判别力的基准，记录能解释原因的信号，再用独立对照定位失败。重点不是把更多指标堆进日志，而是让每个数字都对应一个明确问题，并能指出它没有证明什么。

## 1. 使用可解释的小目标：先决定实验要证伪什么

<a id="optimization-4-detail-2"></a>

### 1.1 把研究问题写成可以失败的命题

“方法甲更好”不是足够清楚的实验问题。它可能指在同一更新数后目标更低、达到同一精度需要更少梯度、总时间更短、峰值内存更小，或者独立预测风险更低。这些命题需要不同的预算和验收，不能由一张横轴只有轮次的损失图同时回答。

可先写一个具体命题：在固定初始化与同一正定二次目标上，预条件后达到相对目标差阈值的更新数减少；再另写成本命题，要求计入构造预条件器和每步求解。第一个命题即使成立，第二个也可能不成立。先把两者分开，就不会把减少迭代自动翻译成减少总计算。

每个命题还要有能推翻它的对照。若认为对角缩放改善任意病态问题，应旋转一个保持相同特征值的二次目标；若认为小更新表示已收敛，应把学习率缩小很多并查看梯度；若认为平均损失下降能证明无偏，应直接在固定点计算抽样方向期望。对照针对具体推理环节，而非为了让实验显得复杂。

<a id="optimization-4-detail-3"></a>

### 1.2 基准不是越像真实模型就越有解释力

一个好的初始基准应有已知目标、可检查梯度、可解释最优集合和足够简单的数值参考。正定二次目标非常适合，因为可以独立给出最优点、曲率和目标差。它不覆盖所有训练机制，但能隔离步长、方向缩放、状态和日志是否正确。

可以定义 $`f(x)=\tfrac12(x-x^*)^TH(x-x^*)`$，其中 $`H`$ 对称正定，最优值为零。这样计算目标差不需要从两个接近的大数相减。等价展开式 $`\tfrac12x^THx-b^Tx+c`$ 在数学上相同，但接近最优时可能发生严重消去；若研究的是优化而非表达式稳定性，应先选不会无意污染实验的参考形式。

基准也要有适度变化。只测试对角 Hessian，会偏向按坐标缩放的方法；只测试零初值，可能掩盖状态或不稳定方向；只测试整齐整批，可能漏掉归约错误。变化应围绕问题结构设计，例如旋转角、条件数、初始误差方向、噪声方差和约束活跃情况，而不是仅换几个随机种子。

<a id="optimization-4-detail-4"></a>

### 1.3 已知解与未知解需要不同证据

在教学二次目标上，直接计算 $`f-f^*`$、$`\Vert x-x^*\Vert `$ 和方向误差都可行；真实模型通常没有精确最优值，不能把当前最好观测当作已知最优，随后宣称剩余差距就是优化误差。当前最好值只提供一个上界候选，真正下界可能远低于它。

凸问题可能有对偶下界或其他证书，可以把原始可行目标与下界之差作为停止依据；有约束问题也能用投影映射或适合的最优性残差。非凸问题常只能报告一阶残差和预算内达到的值。证据弱一些并不是实验失败，但应使用与证据匹配的结论，不把“未发现更低值”写成“已证明全局最优”。

比较多个实现时，独立参考非常重要。两个程序若共享同一个有错目标函数，它们的最终参数和损失可能一致。应从分量手算、解析线性解、方向差分和结构不变量中选择不同来源的检查，让证据尽量不依赖同一条实现路径。

## 2. 观察多个信号：日志是一组有时间语义的测量

<a id="optimization-4-detail-6"></a>

### 2.1 每个检查点对应一份确定状态

日志中的目标、梯度、参数和优化器状态应对应同一个检查点。若先记录旧参数的目标，再更新参数后计算梯度，最后把两者放在同一行，就会产生难以解释的混合状态。最简单的约定是记录初始化，然后每次接受更新后同时评价目标和梯度；试探但未接受的点另设事件。

评价频率也要固定。某方法每步检查验证，另一方法每十步检查，前者拥有更多选择机会和额外计算；最终选择的检查点也可能更有利。应该把更新、训练评价、验证评价、候选选择和最终测试分成明确事件，各自记录次数和成本，而不只给一个看似统一的训练步号。

保存参数快照需要独立副本。若把同一可变数组引用反复放进列表，后续原地更新可能让全部历史都变成最终状态；目标历史还在下降，参数轨迹却只剩一个点。这是存储语义错误，不能用优化理论解释。对于动量和自适应方法，快照还应包含状态数组，而不仅是模型参数。

<a id="optimization-4-detail-7"></a>

### 2.2 目标分解比一个总损失更有诊断力

至少区分数据项、惩罚项和实际任务指标。例如数据平均损失零点一、二次惩罚零点四，总目标零点五；另一个配置总目标零点三，可能只是减小了惩罚系数，并不表示拟合改善。跨配置比较应使用共同定义的数据指标，含惩罚目标则用于解释每个配置自己的优化。

还要记录归约分母。按样本平均、按有效标签平均、按全部输出元素平均，会导致不同尺度；掩码数量随批次变化时，同一个损失数值更难直接比较。日志可以保留有效数量和损失和，使离线汇总能重新构造同一目标，而不是平均一堆大小不同的批均值。

如果只看到总目标突然降低，应检查是否换了数据、正则系数、样本权重或归约规则。算法更新可能毫无变化，目标定义却已经变化；反过来，目标不变但测量时刻变了，也能造成曲线跳跃。把配置版本与检查点关联起来，才能区分真实进展与口径切换。

<a id="sec-1-1"></a>

<a id="optimization-4-detail-8"></a>

### 基础算例：用梯度范数识别尚未收敛

取 $`f(x,y)=x^2+100y^2`$，在 $`(1,0.001)`$ 处目标为一点零零零一，梯度为 $`(2,0.2)`$。如果步长仅为十亿分之一，一步目标改善很小，但梯度并不小，说明小变化来自小更新而非接近驻点。仅用两次损失差作为停止标准，会把这种人为停滞误判为成功。

另一方面，把参数改成另一种单位，梯度范数会改变，因此也不能把一个绝对梯度阈值跨所有表示机械使用。对已知正定二次目标，可同时报告目标差与能量误差；对实际模型则说明尺度、容差来源及残差含义。日志是推理证据，不能替代先确定评价对象。

<a id="sec-2-1"></a>

<a id="optimization-4-detail-9"></a>

### 机制展开：更新范数、梯度范数与预测改善

给定位移 $`s`$，一阶模型预测目标降低 $`p=-g^Ts`$，实际降低为 $`a=f(x)-f(x+s)`$。若 $`p>0`$，可以记录比值 $`\rho=\frac{a}{p}`$。它不是信赖域二次模型使用的同名比值，本章明确只以一阶预测为分母，避免把不同模型混在一起。

对准确二次目标，$`a=-g^Ts-\tfrac12s^THs`$，所以 $`\rho=1-\frac{s^THs}{(2p)}`$。正定曲率会消耗一部分一阶预测；步子足够小通常接近一，过大则可能为负。即使梯度正确，实际改善也可能远低于一阶预测，不能仅凭比值小就认定导数错了。

若 $`p\le0`$，不要继续除以它打印一个看似正常的比值。方向可能不是当前梯度的下降方向，或者动量历史暂时主导、梯度过期、参数版本错配。先记录这个状态，再查算法是否本来允许非下降步，以及是否有相应接受机制。一个指标的定义域也是日志契约的一部分。

<a id="deep-dive-2"></a>

<a id="optimization-4-detail-10"></a>

### 深入讲解：用可解析二次目标把训练故障拆成原因

考虑 $`H=\operatorname{diag}(1,100)`$，初始误差为 $`(1,1)`$，使用普通步长零点零一。第一步后误差为 $`(0.99,0)`$，目标从五十点五降到零点四九零零五。最初的大幅下降只是陡峭方向被消除，后续慢下降来自平缓方向每步只乘零点九九。

这条轨迹可以验证许多日志解释。梯度范数先快速变小，随后缓慢收缩；更新范数随之变化；目标与梯度都能由同一个误差向量重建。如果目标在第一步后还报告五十点五，可能是记录在更新前；若参数已经归零但梯度仍大，可能拿了旧梯度；若全部历史参数都等于最后一个点，可能是快照别名。

同时改变步长、初值、正则和数据顺序，会让这些诊断信号互相混杂。更有效的排查是先固定小目标和确定环境，再逐个注入故障，预测它应影响哪个不变量。小目标的作用是建立一套可以复算的因果链，而不是声称真实网络也有相同的简单曲率。

## 3. 分离优化与泛化：训练最优不是唯一研究终点

<a id="optimization-4-detail-12"></a>

### 3.1 三个目标不能共用一个结论

优化误差比较当前参数与固定训练目标的最优值，统计误差比较由有限训练数据学到的规则与目标总体，任务效用还可能包含成本、约束和部署变化。更快降低训练目标，只回答其中第一层；独立评价改善，也不一定意味着梯度更准确，因为正则、早停或随机性可能改变估计偏好。

固定目标、初值和预算的算法对照，适合研究更新效率；允许不同方法各自调参，则是在比较完整学习程序。后者同样有价值，但搜索次数、选择数据与候选范围必须纳入协议。不能让某方法在测试集上反复试验，再把最终分数称为一次纯算法改动的收益。

对真实训练，建议同时记录训练数据项、总优化目标、内部验证指标和最终外部指标。内部验证用于选择，最终测试只服务冻结后的程序评价。根据测试结果修改训练时长、随机种子或指标后，它已进入选择过程；没有发生反向传播，也不代表信息没有被使用。

<a id="optimization-4-detail-13"></a>

### 3.2 一个能精确解释过度拟合的单方向模型

设观测为 $`Y=\theta+\varepsilon`$，噪声均值零、方差 $`\tau^2`$。训练目标为 $`\frac{(w-Y)^2}{2}`$，从零开始做步长 $`\eta\in(0,1]`$ 的梯度下降。经过 $`t`$ 步，$`w_t=a_tY`$，其中 $`a_t=1-(1-\eta)^t`$。训练残差逐步缩小，最终完全拟合这个带噪观测。

但估计真实均值的平方风险是

$$
E[(w_t-\theta)^2]=(1-a_t)^2\theta^2+a_t^2\tau^2.
$$

第一项为平方偏差，第二项为方差。取 $`\theta=1,\tau^2=4`$，风险随收缩因子 $`a`$ 的最优位置为零点二，最小风险零点八；起点风险为一，完全拟合风险为四。步长零点一、两次更新得到 $`a=0.19`$，风险零点八零零五，已经很接近该模型中的最佳折中。

这并不证明总应训练两步。真值和噪声在实际问题中未知，最优时点需要合法选择，数据条件变化后也会变化。这个例子只提供一个明确反例：训练目标一直下降，统计风险仍可以先降后升。早停不是单纯放弃优化，而可能构成一个需要评价的估计规则。

<a id="optimization-4-detail-14"></a>

### 3.3 用重复数据生成验证风险，而非挑一条漂亮轨迹

下面每个观测代表一份独立训练问题，同一份观测在各训练时长中共用，以便做配对比较。真值仅用于模拟世界中的误差测量，训练更新不读取它。若要预测独立的新观测而非真实均值，风险还需加上新观测噪声方差；两者的最优时点相同，但数值并不相同。

```python
import numpy as np

rng = np.random.default_rng(730)
truth, noise_sd, eta = 1.0, 2.0, 0.1
observed = truth + rng.normal(scale=noise_sd, size=80000)
for steps in (0, 2, 10, 100):
    response = 1.0 - (1.0 - eta) ** steps
    estimate = response * observed
    train_objective = float(np.mean(0.5 * (estimate - observed) ** 2))
    risk = float(np.mean((estimate - truth) ** 2))
    theory = (1.0 - response) ** 2 * truth ** 2 + response ** 2 * noise_sd ** 2
    assert np.isclose(risk, theory, rtol=0.02, atol=0.002)
    print("updates:", steps, "mean training objective:", train_objective,
          "mean-estimation risk:", risk, "theory:", theory)
```

一次真实训练集上的验证曲线含有选择噪声，不能像这个有已知机制的重复实验一样精确读出风险。若反复查看许多时点，选择最低观测验证误差，最终记录也受候选数量影响。比较不同算法时应给相近的选择机会，或清楚说明各自完整选择程序，再用未参与选择的数据评价。

<a id="optimization-4-detail-15"></a>

### 3.4 重复种子不是所有不确定性的替身

固定训练数据换初始化或打乱种子，主要测量算法随机性；重新抽取训练集，测量数据敏感性；更换测试对象或来源，测量评价与迁移波动。把一种重复的标准差当作全部不确定性，容易严重低估结论范围。实验记录应说明随机种子控制哪一层，而非仅给一个整数。

在多个数据集或多个初值上比较方法，可按相同问题与相同种子配对，分析每对差异。若各方法消耗随机数的顺序不同，使用相同初始种子并不保证所有内部噪声相同；要实现有意义的共同随机数，需要明确共享数据和抽样对象，不能只把随机数生成器状态名字设成一样。

跨问题汇总时还要防止选择性报告。删除难例、只保留成功种子或只展示某个最有利条件数，都会改变研究对象。失败应保留状态与预算，问题集合应在主要比较前冻结；探索中新发现的异常则可以成为下一轮预先设计的研究问题。

## 4. 读取示例损失变化：一段有停止状态的完整轨迹

<a id="optimization-4-detail-17"></a>

### 4.1 实验对象、单位与参考定义

本节比较普通梯度、对角预条件和精确二次预条件。设初始 Hessian 特征值为一和一百，旋转角取零与四十五度，最优点固定为 $`(0.5,-1.5)`$，初始化固定为 $`(2,1)`$。旋转保持谱和维数，却改变曲率是否对齐坐标轴，适合检验对角方法的能力边界。

目标使用中心化形式，最优值为零。停止阈值同时包含绝对与初始目标相对部分，两种尺度都记录；如果初始点已满足阈值，应允许零次更新成功。达到预算却未满足阈值时，状态是预算结束，不是收敛；出现非有限值则单独报告，并保留最后有限状态。

为了不让某种算法免费获得曲率信息，程序还记录设置阶段是否做了谱计算或矩阵分解。二维小问题上的这些计数只用于揭示成本类别，不足以证明实际时间优劣；真实规模下应按同一计时协议测量，且明确矩阵是否原本已经提供。

<a id="optimization-4-detail-18"></a>

### 4.2 自足实现：记录参数、梯度与每次接受更新

程序每次联合返回一个目标和梯度，因此把两类评价都按一次计数；实际软件若能单独缓存或计算，应采用更精细计数。精确预条件使用一次 Cholesky 分解，随后用专门的三角求解接口解两个方程，避免每步又对同一个因子调用通用分解。设置分解次数与每步求解次数属于不同成本；前者在返回记录中明确计数，后者可由精确方法的更新数乘二得到，仍不与目标或梯度评价混算。

```python
import numpy as np
from scipy.linalg import solve_triangular

def problem(angle):
    c, s = np.cos(angle), np.sin(angle)
    Q = np.array([[c, -s], [s, c]])
    H = Q @ np.diag([1.0, 100.0]) @ Q.T
    return H, np.array([0.5, -1.5])

def run(H, target, method, max_updates=4000, rtol=1e-10, atol=1e-12):
    x = np.array([2.0, 1.0])
    setup_spectral, setup_factorizations = 0, 0
    if method == "gradient":
        eta = 1.0 / np.linalg.eigvalsh(H)[-1]
        setup_spectral = 1
        def direction(g):
            return -g
    elif method == "diagonal":
        diagonal = np.diag(H)
        invroot = 1.0 / np.sqrt(diagonal)
        effective = invroot[:, None] * H * invroot[None, :]
        eta = 1.0 / np.linalg.eigvalsh(effective)[-1]
        setup_spectral = 1
        def direction(g):
            return -g / diagonal
    elif method == "exact":
        factor = np.linalg.cholesky(H)
        setup_factorizations = 1
        eta = 1.0
        def direction(g):
            return solve_triangular(factor.T, solve_triangular(factor, -g, lower=True), lower=False)
    else:
        raise ValueError("unknown method")

    evaluations = 0
    def evaluate(point):
        nonlocal evaluations
        evaluations += 1
        error = point - target
        with np.errstate(over="raise", invalid="raise"):
            g = H @ error
            value = float(0.5 * (error @ g))
        if not np.isfinite(value) or not np.isfinite(g).all():
            raise FloatingPointError("non-finite objective or gradient")
        return value, g

    value, g = evaluate(x)
    initial = value
    tolerance = atol + rtol * initial
    trace = [{"update": 0, "value": value, "grad_norm": np.linalg.norm(g),
              "step_norm": 0.0, "predicted": None, "rho": None, "x": x.copy()}]
    reason = "budget"
    for update in range(max_updates):
        if value <= tolerance:
            reason = "objective_tolerance"
            break
        step = eta * direction(g)
        predicted = float(-g @ step)
        candidate = x + step
        if not np.isfinite(candidate).all():
            reason = "non_finite_parameter"
            break
        try:
            new_value, new_g = evaluate(candidate)
        except FloatingPointError:
            reason = "non_finite_evaluation"
            break
        actual = value - new_value
        trace.append({"update": update + 1, "value": new_value,
                      "grad_norm": np.linalg.norm(new_g), "step_norm": np.linalg.norm(step),
                      "predicted": predicted,
                      "rho": actual / predicted if predicted > 0 else None,
                      "x": candidate.copy()})
        x, value, g = candidate, new_value, new_g
    if value <= tolerance:
        reason = "objective_tolerance"
    return {"method": method, "reason": reason, "updates": len(trace) - 1,
            "evaluations": evaluations, "spectral_setups": setup_spectral,
            "setup_factorizations": setup_factorizations, "initial_value": initial,
            "tolerance": tolerance, "trace": trace}

for angle in (0.0, np.pi / 4):
    H, target = problem(angle)
    outputs = [run(H, target, method) for method in ("gradient", "diagonal", "exact")]
    for result in outputs:
        trace = result["trace"]
        assert result["reason"] == "objective_tolerance"
        assert result["evaluations"] == result["updates"] + 1
        assert trace[-1]["value"] <= result["tolerance"]
        if len(trace) > 1:
            assert not np.shares_memory(trace[0]["x"], trace[1]["x"])
        print("angle:", angle, "method:", result["method"],
              "updates:", result["updates"], "evaluations:", result["evaluations"],
              "final value:", trace[-1]["value"])
    if angle == 0.0:
        assert outputs[1]["updates"] == outputs[2]["updates"] == 1
    else:
        assert outputs[0]["updates"] == outputs[1]["updates"]
        assert np.isclose(outputs[0]["trace"][-1]["value"],
                          outputs[1]["trace"][-1]["value"])
```

<a id="optimization-4-detail-19"></a>

### 4.3 怎样解释输出，而不把步数当作总成本

未旋转时，对角矩阵恰好包含全部曲率，单位预条件步等同于精确二次求解，因此一步到达。旋转四十五度后，对角预条件只看到两个相同的五十点五，丢失了非对角耦合；配套稳定步长让它与普通梯度得到相同的有效更新，因而步数相同。

精确预条件仍一步求解，只是把困难转移到矩阵构造、分解和线性求解。二维中这是合理教学操作，大规模中矩阵存储和分解可能成为主要成本。结论应是“在这个已知二次模型里精确曲率消除了迭代误差”，而不是“所有训练都应该直接使用精确曲率”。

在当前核对环境下，未旋转的普通梯度用了 866 次更新、867 次联合评价；对角和精确方法各更新一次。旋转后，普通梯度与对角方法都用了 1047 次更新、1048 次评价，末目标约为 $`2.90\times10^{-9}`$；精确方法一次更新后约为 $`2.72\times10^{-30}`$。这些数对应给定初值、容差和步长规则，不能当作算法普遍复杂度；换容差或初始方向，具体计数会随之变化。

轨迹中的 $`\rho`$ 也有解释力。精确 Newton 二次步的一阶预测是实际下降的两倍，所以比值为二分之一，并非接近一；这完全正确，因为二次项贡献不可忽略。若采用二次模型的预测作为分母，精确模型下比值才为一。指标同名而分母不同，会造成表面矛盾，必须先核对定义。

<a id="optimization-4-detail-20"></a>

### 4.4 从轨迹还原停止原因

查看末行时，要同时看阈值、实际目标、更新计数和状态。预算结束的目标即使低于其他算法某个早期值，也不自动算达到共同目标；数值失败更不能把最后有限值当作正常最终解参与排名。可以保留它作为诊断信息，但成功判据必须事先统一。

如果选择改用梯度阈值，应对各方法使用同一问题坐标下的梯度定义，而不是拿预条件后的方向范数混比。若改用验证早停，应记录最佳检查点和选择次数，不能把它与已知目标差证书视为同一种成功。不同停止标准可以并列报告，只需清楚说明各自回答什么问题。

## 5. 综合算例与实现核对：按错误来源建立诊断顺序

<a id="optimization-4-detail-22"></a>

### 5.1 先检查目标，再检查导数，再检查更新

第一层是数据与目标：输入、样本对应、标签形状、有效元素和惩罚对象是否一致。第二层是导数：解析或自动微分是否与当前前向函数一致。第三层是算法：这些梯度是否在正确基点、按正确状态和步长产生更新。第四层是实验协议：选择、预算和报告是否回答原来的研究问题。

这个顺序避免用后层技巧掩盖前层错误。错误广播产生的目标可以有完全正确的梯度；用它训练也可以稳定下降；最终甚至可能在某个偏移评价上表现不错。每层通过只支持对应结论，不能倒推出所有前提都已成立。

小型核对可以固定一个参数点，分别用分量手算、方向差分和独立公式计算目标与导数。差分步长要考虑截断和舍入，随机函数要固定随机状态或明确估计目标；对不光滑点，则应检查方向或次梯度条件，不能把普通中心差分当成唯一真值。

<a id="optimization-4-detail-23"></a>

### 5.2 梯度错误、过期梯度与状态错配

梯度数值看起来合理，不代表它属于当前参数。若参数已经更新，仍使用上一个点缓存的梯度，这属于延迟更新；如果算法理论本来允许延迟，应记录延迟长度和条件，否则就是实现错配。用新参数重新评价一次导数，可以区分真正导数错误与缓存版本错误。

动量和自适应优化器的状态也有版本。重新开始一个候选实验时，只重置权重却保留上一次速度，会让所谓相同初值不再相同；恢复训练时只保存权重、不保存矩估计与步数，也无法接续原轨迹。模型状态定义当前预测，优化器和随机状态定义下一次转移，应一起审查。

还要检查更新对象。程序可能计算了一份新数组，却让后续前向继续读取旧数组；也可能优化器持有另一份参数副本。打印梯度和学习率都正常，损失仍不变。此时应追踪参数对象与数据流，验证前向真正读取的是被更新的状态，而不是继续调大学习率。

<a id="optimization-4-detail-24"></a>

### 5.3 一个方向检查可能恰好漏掉错误

下面故意把第二个梯度分量增加十。只检查第一个坐标方向，会完全通过；检查第二个方向才发现问题。随机方向通常更容易发现这类错误，但仍不是有限次检查覆盖全部输入的证明。可以结合坐标方向、随机方向和结构不变量，提高对具体故障的判别力。

```python
import numpy as np

H = np.array([[4.0, 1.0], [1.0, 2.0]])
target = np.array([0.5, -1.0])
x = np.array([1.0, 2.0])

def value(point):
    error = point - target
    return float(0.5 * error @ H @ error)

def true_grad(point):
    return H @ (point - target)

def directional_difference(point, direction, h=1e-5):
    return (value(point + h * direction) - value(point - h * direction)) / (2.0 * h)

bad = true_grad(x) + np.array([0.0, 10.0])
first, second = np.eye(2)
assert np.isclose(directional_difference(x, first), bad @ first, atol=1e-8)
assert not np.isclose(directional_difference(x, second), bad @ second, atol=1e-5)

current = x - 0.05 * true_grad(x)
stale = true_grad(x)
assert not np.allclose(stale, true_grad(current))
assert np.isclose(directional_difference(current, second),
                  true_grad(current) @ second, atol=1e-8)

# 参数不动可能来自更新小于本地可表示间隔。
large32 = np.float32(1e8)
after32 = large32 - np.float32(1.0)
after64 = np.float64(large32) - 1.0
assert after32 == large32 and after64 != np.float64(large32)
print("one direction missed the bug; stale gradient detected; float32 update vanished")
```

这里的浮点例子只是定位证据，不意味着应对所有参数都改用最高精度。更合理的处理包括单位缩放、保留高精度主参数、调整更新累计方式，或重新考虑目标精度。需要同时检查存储参数、运算中间量和累加类型；只把打印格式改成更多小数位不会恢复已经被舍掉的更新。

<a id="optimization-4-detail-25"></a>

### 5.4 非有限值要追踪首次发生的位置

出现 NaN 或无穷时，应区分输入已经非法、前向溢出、梯度异常、预条件求解失败和参数更新溢出。最后一个打印值无法告诉我们最早的原因。可在小实验中按阶段检查有限性，并保留导致首次异常的参数范围、损失组成和操作名称。

不要把所有异常统一替换成零后继续比较。这样会改变梯度、目标或状态，甚至让失败方法看起来突然收敛。若确有预先定义的降级或跳过策略，应把它作为算法的一部分记录，包括触发次数和对预算的影响，而不是隐藏在数据清理中。

有限输入也不保证中间计算安全。平方、指数、矩阵乘法或范数都可能溢出；相消则可能让目标差失去有效数字。稳定表达、缩放和误差模型应结合[浮点计算](../NumericalMethods/01-浮点误差条件数与稳定计算.md)理解。优化器的正确性与数值实现的可靠性相互关联，却是不同检查层次。

<a id="optimization-4-detail-26"></a>

### 5.5 把干预设计成有明确预期的实验

改变一个因素前，先写下预期：目标整体乘十并把普通梯度步长除以十，更新应保持；共同重排样本，在固定参数上的全量目标与梯度应保持；改变未来才可见数据，不应影响过去锚点特征；旋转坐标则不一定保持按坐标自适应方法的轨迹。

如果观察与预期不同，先检查这项不变性是否真的适用。例如整体缩放目标却没有同步缩放正则，就不是同一干预；加入梯度裁剪后，步长缩放也可能不再等价；随机训练换了抽样顺序，不能要求逐步参数相同。一个错误的理论预期同样会造成错误诊断。

干预不应只追求让程序失败。也要构造错误算法恰好通过的案例，研究检查的盲区。例如零初值掩盖不稳定方向，零标签掩盖样本错配，对角目标掩盖旋转耦合。知道某个检查何时没有判别力，才能合理决定下一步需要什么独立证据。

## 6. 进阶：预条件实验与公平的停止规则

<a id="sec-6-1"></a>

<a id="optimization-4-detail-28"></a>

### 用受控二次问题拆分几何、迭代与成本

本节把预条件矩阵记为 $`M`$，更新方向通过 $`Md=-g`$ 求得，即使用 $`M^{-1}g`$；这与把乘法矩阵直接记成预条件器的另一种约定不同，阅读公式时必须对齐。设 $`M`$ 与 $`H`$ 都对称正定，参数误差满足 $`e^+=(I-\eta M^{-1}H)e`$。

虽然 $`M^{-1}H`$ 通常不对称，它与对称正定矩阵 $`B=M^{-\frac{1}{2}}HM^{-\frac{1}{2}}`$ 相似。令 $`z=M^{\frac{1}{2}}e`$，则 $`z^+=(I-\eta B)z`$。因此稳定条件由 $`B`$ 的最大特征值决定，收缩在这个变换后的欧氏度量中解释，而不是直接把非对称矩阵当作拥有原坐标正交特征基。

即使变换后的误差收缩，原参数欧氏长度也不必每步按同一个因子收缩。可以通过两个范数的等价关系获得带 $`M`$ 条件数的上界；渐近收敛与每步原范数下降是不同结论。对正定二次目标，目标能量和相应残差往往比随意选择的参数单位更适合作为共同评价。

<a id="optimization-4-detail-29"></a>

### 6.1 旋转反例揭示对角近似的边界

未旋转时 $`H=\operatorname{diag}(1,100)`$，取 $`M=\operatorname{diag}(H)`$ 就是精确矩阵，$`B=I`$。旋转四十五度后，$`H`$ 的两个对角元素都为五十点五，非对角元素为负四十九点五。对角预条件成为同一个标量乘单位阵，$`B`$ 的条件数仍为一百，无法消除相关方向的差异。

这个反例不表示对角方法没有价值。它便宜、容易存储，对单位尺度差明显的问题可能很有效；只是能力依赖坐标结构。实验应同时包含轴对齐和旋转问题，并解释成功来自哪些结构，而不能仅凭一类友好基准推广到全部高维目标。

精确 $`M=H`$ 使 $`B=I`$，但要求可获得并处理完整曲率。若近似矩阵每隔若干步更新，设置成本还可跨步摊销；若目标曲率不断变化，旧预条件可能逐渐失效。应把更新频率、分解复用、求解精度和内存写进配置，而不只记录一个方法名称。

<a id="optimization-4-detail-30"></a>

### 6.2 共同容差需要共同定义

对同一问题，可用同一原目标差阈值比较；已知下界时可使用可行目标与下界间隙；有约束时应使用合适的一阶或最优性残差。若各方法分别使用自己的内部方向范数，就可能让缩放更激进的方法轻易达到阈值，而真实目标差并未更小。

绝对容差与相对容差各有用途。目标单位很大时固定绝对阈值可能过严，目标初值接近零时纯相对阈值又可能不稳定；可以同时报告两者及实际停止值。若目标整体加常数，最优点和梯度不变，但以原始目标值为分母的相对标准可能变化，因此最好使用有意义的目标差或事先固定的参考尺度。

在非凸未知最优值问题中，不应伪造一个共同目标差。可以报告达到预设梯度残差的成本、预算内最优观测或某个可信下界差，并明确没有全局最优保证。指标诚实地弱一些，比用没有依据的最优值让表格显得精确更有价值。

<a id="optimization-4-detail-31"></a>

### 6.3 达到目标的时间与失败记录

若算法在预算内未达到目标，真实达到时间只知道大于当前预算。把预算值直接当作成功时间，会让未完成方法得到虚假排名；只删除失败，则会让不稳定方法只在容易问题上参与比较。应保留失败状态，分别汇报成功比例与成功问题上的成本，并说明后者存在条件选择。

随机方法应报告多次预设运行，而不是只取最好种子。对每个问题，固定成功定义和最大预算，保留中断、非有限、不可行和正常预算结束的区别。把全部失败都记成一个无限成本可以方便某些汇总，但原始原因仍应保留，否则无法判断改进应针对稳定性还是速度。

时间测量还应控制预热、线程、设备同步、缓存和并行环境。某些异步加速器的提交时间不是计算完成时间；小任务的调度开销可能主导。教学二维例子适合核对计数，不适合直接推出某个线性代数接口在真实大模型中更快。

<a id="optimization-4-detail-32"></a>

### 6.4 性能剖面怎样保留问题与失败结构

对固定问题集合，令 $`t_{p,s}>0`$ 是方法 $`s`$ 在问题 $`p`$ 上达到共同目标的成本，失败记为无穷。只要该问题至少有一种成功方法，定义 $`r_{p,s}=\frac{t_{p,s}}{\min_u t_{p,u}}`$，再令 $`\rho_s(\tau)`$ 为比值不超过 $`\tau`$ 的问题比例，$`\tau\ge1`$。它描述该方法在多少问题上离当前最好方法不超过指定倍率。

在一处首次最好不一定代表总体最快；某方法可能经常第二但极少失败，另一方法偶尔很快却常不成功。性能剖面把这些区别画在同一类累计比例中。若所有方法都失败，该行没有有限基准，不能计算无穷除无穷；本章约定将其保留为所有方法的失败，并单独报告这种问题数。

```python
import numpy as np

# 每行一个冻结问题，每列一个方法，单位可为已定义的正计算成本。
cost = np.array([[4.0, 8.0, np.inf],
                 [100.0, 20.0, 40.0],
                 [np.inf, 5.0, 10.0],
                 [np.inf, np.inf, np.inf]])
assert np.all(cost[np.isfinite(cost)] > 0.0)
best = np.min(cost, axis=1)
has_success = np.isfinite(best)
ratio = np.full_like(cost, np.inf)
ratio[has_success] = cost[has_success] / best[has_success, None]
for factor in (1.0, 2.0, 5.0):
    profile = np.mean(ratio <= factor, axis=0)
    print("factor:", factor, "profiles:", profile)
assert np.allclose(np.mean(ratio <= 2.0, axis=0), [0.25, 0.75, 0.5])
assert np.count_nonzero(~has_success) == 1
print("success proportions:", np.mean(np.isfinite(cost), axis=0))
```

这些是构造成本，不是真实算法计时结果。方法乙在倍率二时覆盖四分之三问题，甲只覆盖四分之一；所有方法都失败的最后一行阻止任何方法达到全覆盖。不能使用无穷倍率来比较，因为把失败也与无穷比较会错误计入；观察的是有限倍率逐步增大的行为。

性能剖面是冻结问题集合上的描述工具，不自动产生对全部未来问题的统计保证。增加或删除问题、改变共同容差、替换成本单位，曲线都会变化。原始成本表、成功判据与问题结构应一起保留，必要时按结构分层解释，避免一条总体曲线掩盖特定类型的失败。

<a id="optimization-4-detail-33"></a>

### 6.5 搜索预算也属于算法成本

比较学习率、动量或衰减配置时，候选数量和选择规则应提前定义。给一种方法搜索一百组、另一种只用默认值，得到的是两套不同投入的程序。可以比较默认即用，也可以比较相同搜索预算下最佳程序，但不能把二者的结论混在一起。

相同数值范围也未必公平。不同算法的步长含义和状态尺度不同，机械使用同一列表可能让某方法完全错过有效区域。更合理的是为各方法设定有原理依据的范围，记录候选数、搜索成本和内部评价，再用共同外部问题检查。搜索的合理性与预算的透明性需要同时满足。

实验探索可以逐步改进协议，但确认性比较应冻结。根据最终测试问题调整搜索空间后，再把相同问题用于声称普遍优势，会产生隐性选择。可把探索问题与最终问题分开，或明确把结果限定为当前基准上的开发成果，避免把反复试出来的设置当作独立发现。

## 7. 练习与解析：把一行结论拆成可检查证据

<a id="optimization-4-detail-35"></a>

### 7.1 日志练习：末项究竟属于哪个参数

**问题：** 训练每轮先记录损失，再更新参数，循环共一百轮。返回最终参数和历史最后一项后，两者重新计算的目标不完全相同，是否说明梯度有错？怎样修改日志约定？

**解析：** 最后一项来自第九十九次更新后的参数，最终参数已经经过第一百次更新，差异可能只是一个合法更新。应明确记录初始化及每次更新后状态，或将历史标为更新前；两种都可以，但不能混配。验证时应按相同参数快照重新计算，若仍不同，再调查目标状态、随机性和数值实现。日志错位与梯度错误属于不同故障，不应靠改小学习率让数值看起来更接近。

<a id="optimization-4-detail-36"></a>

### 7.2 停滞练习：小更新提供了什么证据

**问题：** 当前梯度范数为一百，学习率为十亿分之一，更新范数只有千万分之一。连续目标改善极小，能否报告接近驻点？

**解析：** 不能，小更新来自步长缩放，梯度仍明显非零。应报告学习率、梯度、更新及目标尺度，检查步长是否过小，或参数更新是否被舍入吞掉。若改用预条件方向，还要说明内部方向范数与原梯度不同。停止规则可以基于业务预算或有限精度，但应使用相应状态，不能把任何不再明显变化的程序都描述为已达到数学驻点。

<a id="optimization-4-detail-37"></a>

### 7.3 模型练习：精确 Newton 的比值为什么不是一

**问题：** 对 $`f(x)=\frac{x^2}{2}`$，从二走精确 Newton 步到零。本章的一阶预测降低量和实际降低量分别是多少？若记录比值二分之一，是否意味着只有一半更新正确？

**解析：** 梯度为二，位移为负二，一阶预测为四，实际目标从二降到零，降低二，比值为二分之一。缺少的一半由正二次曲率项解释，算法完全正确。若使用完整二次模型作为预测，预测降低也为二，比值才是一。判断比值之前必须读取分母定义，不能把不同日志中的同名指标直接比较；更不能凭一个不接近一的比值就认定梯度失准。

<a id="optimization-4-detail-38"></a>

### 7.4 口径练习：总目标更低是否拟合更好

**问题：** 甲数据损失零点一、惩罚零点四；乙数据损失零点二、惩罚零点零五。哪个总目标更低？能否据此认定乙对相同训练任务拟合更好？

**解析：** 甲总目标零点五，乙零点二五，但乙的数据损失更高。如果二者惩罚系数或参数化不同，总目标数值还不一定属于同一个可比较函数。应分别记录数据项、惩罚定义与独立任务指标，并明确比较的是各自优化进度还是共同预测效果。一个较低总量可能只是成本权重改变，而不是误差下降；拆分日志是识别这种差别的必要条件。

<a id="optimization-4-detail-39"></a>

### 7.5 旋转练习：相同条件数为何有不同收益

**问题：** Hessian 特征值为一和一百。轴对齐时采用对角预条件可以一步求解，旋转四十五度后为何不再如此？这个结果推翻了对角预条件吗？

**解析：** 轴对齐时对角项包含完整矩阵，预条件后的曲率为单位阵；旋转后两个对角项均为五十点五，非对角项仍承担强相关结构，对角近似只提供整体缩放，条件数没有被消除。它没有推翻方法，而是限定收益来源。公平实验应同时包含多种坐标结构，报告哪些问题更适合该近似；不能只在友好坐标上观察成功，也不能用一个不利反例宣布它毫无价值。

<a id="optimization-4-detail-40"></a>

### 7.6 误差练习：目标一样时梯度也一样吗

**问题：** 对 $`f(x,y)=\frac{(x^2+100y^2)}{2}`$，点甲为 $`(1,0)`$，点乙为 $`(0,0.1)`$。比较目标、参数距离和梯度范数，说明它们为何不应共用一个排序。

**解析：** 两点目标都为零点五；到最优点的欧氏距离分别为一和零点一；梯度范数分别为一和十。目标按曲率加权平方，梯度又额外乘一次曲率，参数距离则只看原单位。三个排序差异来自不同度量，不是计算矛盾。实验应根据研究目标选择证据，并在转换界中给出曲率条件，不能看到同一个小数就认为所有意义下同样接近最优。

<a id="optimization-4-detail-41"></a>

### 7.7 导数练习：一个方向通过为何不够

**问题：** 真梯度为 $`(3,4)`$，程序返回 $`(3,14)`$。只对方向 $`(1,0)`$ 做中心差分，能够发现什么？至少怎样补充核对？

**解析：** 这个方向只读取第一分量，错误恰与方向正交，所以检查会通过。增加第二坐标方向或不与错误正交的随机方向，可以发现问题；同时要先验证前向目标正确，否则差分可能验证了错误函数的导数。对多参数结构还可用共享梯度、广播反向和守恒关系检查。有限方向集合不是全局证明，但应让检查覆盖预期故障模式，而非只选择最容易通过的方向。

<a id="optimization-4-detail-42"></a>

### 7.8 缓存练习：梯度正确为何更新仍错

**问题：** 目标与梯度函数都通过独立检查，程序仍使用上一次参数的缓存梯度更新当前点。是否能报告实现了普通梯度下降？怎样定位？

**解析：** 普通梯度下降要求方向在当前基点计算，过期缓存改变了算法。可以给每次参数状态和梯度附版本编号，在小目标上核对更新前参数、梯度来源和实际位移；再用当前参数重新求导对照缓存。如果研究本来使用延迟梯度，也应明确延迟模型和保证条件，而不是拿普通无延迟结论解释。局部函数正确不等于状态转移正确，这一层需要独立验证。

<a id="optimization-4-detail-43"></a>

### 7.9 快照练习：为什么历史参数全部相同

**问题：** 每轮把参数数组直接放入列表，随后原地减去梯度。最后列表中的参数全部等于最终值，但损失历史不同，最可能是什么原因？

**解析：** 列表很可能保存同一个可变数组的引用，后续原地更新改写了所有观察位置。应在需要保留历史时复制参数或使用明确的不可变快照，并对状态数组采用相同规则。不要据此认定参数从未变化，也不要用复制后的新轨迹补造原日志；应重新运行受控实验。这个错误展示数据所有权为何也是科学记录的一部分，数值看似合理并不保证历史被正确保存。

<a id="optimization-4-detail-44"></a>

### 7.10 失败练习：替换非有限值有什么后果

**问题：** 一次更新使梯度出现无穷，代码把它替换成零后继续。最后目标不变且梯度打印为零，能否算成功停止？

**解析：** 不能，零是异常处理新造的值，并不是原目标导数。程序既改变了更新，也销毁了故障证据。应记录首次异常阶段并停止或采用事前定义的降级算法；若降级是实验方法的一部分，要保留触发次数及其成本。最终有限不等于全过程可靠，特别是把失败状态静默改成普通数值，会让后续成功率和性能汇总一起失真。

<a id="optimization-4-detail-45"></a>

### 7.11 预算练习：一次分解是否免费

**问题：** 甲用一千次矩阵向量乘法，乙先做一次完整矩阵分解，再一步求解。仅按更新次数，乙明显更少，能否直接宣布时间和内存都更好？

**解析：** 不能，完整矩阵可能根本未显式存储，构造、分解、求解和内存都可能主导。需要记录规模、稀疏性、可用运算接口与分解能否复用，再按共同成本测量。若只是研究消除多少迭代误差，可以报告一步结果，但要把它与总资源结论分开。一个算法把工作移到设置阶段，并不意味着工作消失；评价指标应覆盖真正使用的资源。

<a id="optimization-4-detail-46"></a>

### 7.12 失败汇总练习：只看成功均值偏向谁

**问题：** 方法甲只在两道容易题成功，平均成本一；方法乙十道题都成功，平均成本五。若删除甲失败的八题再排名，会产生什么偏差？

**解析：** 两个均值的条件集合不同，甲被允许只在最有利子集展示成本。应首先报告成功比例，再在共同成功集或明确条件下比较成本，并保留所有问题上的失败记录。性能剖面可以展示成本倍率与覆盖，但仍需要固定问题集合和成功定义。未达到目标的预算不是实际成功时间，不能把它填进表格后伪装成完整测量。

<a id="optimization-4-detail-47"></a>

### 7.13 选择练习：同样候选数就公平了吗

**问题：** 两个方法都搜索十个学习率，但甲的范围覆盖有效区域，乙的十个点全部过大。能否仅凭候选数相同认定搜索公平？

**解析：** 候选数是投入的一部分，不保证范围合理。应根据各算法更新尺度和已有原理设定可解释范围，记录失败与扩展规则，必要时同时报告默认配置和调优程序。对某方法有意使用明显无效区间，会把配置失败混成算法失败；反过来，看到最终测试后只为某方法扩范围，也引入选择。公平性来自协议、预算与信息边界共同透明，而非某个单一数字相等。

<a id="optimization-4-detail-48"></a>

### 7.14 随机性练习：一个种子覆盖哪些波动

**问题：** 固定训练集与测试集，换一百个初始化种子得到分数标准差很小，是否说明换训练来源或部署群体后仍可靠？

**解析：** 这个重复主要研究当前固定数据下的算法随机性，没有观察新训练样本或来源变化。需要在允许的抽样层级重复数据生成、分组或时间评价，才能研究对应敏感性。更换部署群体还可能改变任务分布，单纯增加种子数量无法补足覆盖。报告应说明随机化层级，避免把一个容易控制的波动源当成全部不确定性。

<a id="optimization-4-detail-49"></a>

### 7.15 早停练习：训练曲线下降与风险上升

**问题：** 在本章单方向噪声模型中，$`\theta=1,\tau^2=4`$，为何完全拟合训练观测的风险四，比零初值风险一更差？这是不是优化失败？

**解析：** 完全拟合把观测噪声也写入估计，训练误差达到最小，但估计真实均值的方差为四；零初值虽然有偏，平方偏差只有一。最优收缩在中间位置，风险零点八。优化器可以正确完成训练目标，同时给出统计风险更高的估计。应通过合法验证选择或改变目标研究折中，而不是一味要求更低训练误差，也不能把单个模拟参数点的结果推广到所有数据。

<a id="optimization-4-detail-50"></a>

### 7.16 约束练习：普通梯度非零是否失败

**问题：** 在 $`x\ge0`$ 上最小化线性函数 $`f(x)=x`$，参数停在零但梯度恒为一。实验报告该用什么证据，而不是继续调大学习率？

**解析：** 零是合法边界最优，所有可行方向都不会下降。应检查可行性和投影梯度映射，或用凸目标的变分最优条件；此时映射为零。普通梯度不消失并不矛盾。若更新采用了未经证明的修补而非准确投影，还需检查投影本身；可行性仅保证落在集合内，不保证完成了声明的算法。停止标准必须与约束结构匹配。

<a id="sec-8-2"></a>

<a id="optimization-4-detail-51"></a>

### 边界追问：更低训练目标为何未必是更好模型

**问题：** 延长训练后数据损失下降，独立验证变差，应把它归为优化器错误，还是继续只追求损失下降？

**解析：** 两者都不能直接决定。先检查目标和评价口径是否一致，再确认实现与预算；如果更新正确，现象可能来自过度拟合或训练目标与任务效用不完全一致。可按预设验证规则选择，或研究正则与表示，但不能根据最终测试反复改动后仍声称独立评估。报告应明确改善发生在优化、统计还是业务层，避免把所有数字都叫作模型效果。

<a id="optimization-4-detail-52"></a>

### 7.17 停止状态练习：怎样写一句准确结论

**问题：** 三次运行分别因达到已知目标差阈值、达到最大步数、验证连续五次未改善而停止。能否都写“算法已经收敛”？

**解析：** 第一种提供该基准上的优化证据；第二种只说明预算耗尽；第三种是依据验证选择的停止规则，不一定代表训练目标最优。应保留各自状态、阈值、预算和最终检查点，必要时并列报告目标与验证结果。准确措辞能让后续读者知道什么已经验证、什么仍未知，也能避免在性能统计中把不同比较对象混合成一个成功率。

<a id="optimization-4-detail-53"></a>

### 7.18 平移练习：目标加常数为何影响停止

**问题：** 把目标由 $`f`$ 改成 $`f+10^6`$，梯度和最优点不变，但程序以相对目标改善停止，为什么可能提前停下？

**解析：** 如果分母采用原始目标绝对值，加入大常数会把同样的实际下降变成很小相对比例。算法更新没有改变，停止与测量却改变了。可以采用目标差、合理参考尺度或同时记录绝对标准，但不能在未知最优值时随意减去一个希望的常数。这个例子说明数值看似无害的表达平移，也可能经由协议改变实验结论。

<a id="sec-8"></a>

<a id="optimization-4-detail-54"></a>

## 8. 进阶研究练习与解析：组织一份可复核的优化研究

<a id="sec-8-1"></a>

<a id="optimization-4-detail-55"></a>

### 综合练习：从谱得到稳定学习率

**任务：** 对 Hessian 为 $`\operatorname{diag}(2,20)`$ 的正定二次目标，比较步长零点零五与零点一五。先预测轨迹，再设计日志证明失败原因。进一步加入旋转和对角预条件，说明哪些保证仍保持。

**逐步解析：** 参数误差各方向分别乘 $`1-\eta\lambda_j`$。零点零五时因子为零点九与零，两个方向都收缩；零点一五时为零点七与负二，第二方向放大。全方向稳定的开区间是零到零点一之间。应使用包含两方向分量的非零初始误差，避免恰好没有不稳定分量而暂时看不出问题。

日志记录目标、各方向误差、梯度、实际位移和停止状态。大步长下出现交替放大的坐标，支持曲率与步长不匹配；独立梯度检查若通过，则无需为了消除发散而篡改导数公式。旋转保持特征值，因此普通梯度的稳定界保持；对角预条件的有效谱则可能变化，需要重新计算，不能沿用轴对齐结论。

**验收：** 提交手算预测、完整配置和失败原因，而不只给最终损失。若预算内目标已经溢出，应保留首次异常；若曲线仍有限但逐步上升，报告不稳定更新而非随机波动。这个练习把理论保证和日志证据对应起来，要求每个结论都有一条可以独立检查的支持链。

<a id="optimization-4-detail-56"></a>

### 8.1 研究任务一：建立结构化问题集合

**任务：** 构造不同维度、条件数和旋转角的正定二次问题，保持最优点可知。比较普通梯度、对角预条件和一种带状态方法，要求问题集合在主要比较前冻结。

**解析路线：** 先通过对角谱确定难度，再用正交矩阵改变坐标结构。分别控制初始误差主要位于快方向、慢方向或多个方向，避免把初值差异混成算法差异。每个问题记录谱构造、旋转方式、最优点、初值和目标表达；数值参考应检查矩阵对称正定，而非只信任生成代码。

性能评价至少包含共同目标阈值下的成功比例和成本，以及固定预算下的目标差。预条件设置成本、状态内存和超参数搜索都应保留。若某方法只在轴对齐问题有优势，结论应限定到该结构；若整体汇总优势来自某类问题数量更多，可按结构分层展示，而不是用一条平均曲线掩盖来源。

**进阶追问：** 随机正交生成不代表真实网络曲率的总体分布。可以把这些问题看作针对机制的压力测试，而不是现实任务的随机样本。理论与基准各自解释不同层面，研究报告需要明确这种适用范围，才能避免把设计出来的测试集过度外推。

<a id="optimization-4-detail-57"></a>

### 8.2 研究任务二：把噪声、批量和成本拆开

**任务：** 在已知二次目标上加入条件无偏噪声，比较不同批量、固定步长和递减步长。不要只选最后一段曲线，要求同时观察瞬态与长期波动。

**解析路线：** 固定点上先验证噪声均值和方差，再在多条独立轨迹中验证均值与二阶矩递推。不同批量既可以按相同更新数比较，也可以按相同样本梯度预算比较，二者应分别呈现。较大批量的长期波动较小，不代表在相同总成本中已经更接近目标，因为更新次数可能不足以消除初始误差。

若引入相关噪声或按轮重排，需要重新说明条件信息与协方差结构，不能继续使用独立噪声方差除以批量的公式。估计轨迹末端的不确定性时，也不能把同一条相关序列的每个时点当成独立重复；可以增加独立运行，或采用有条件依据的时间序列分析。

**验收：** 每条曲线注明更新、样本访问和随机重复层级；每个理论值注明依赖的矩与独立条件。模拟与理论不符时，优先核对抽样机制、计数口径和初值项，而不是先删掉异常种子。真正有价值的偏离，应该能引出一个可检验的新机制解释。

<a id="optimization-4-detail-58"></a>

### 8.3 研究任务三：设计有盲区说明的故障集合

**任务：** 在同一个小实验器中逐次注入错误目标系数、过期梯度、状态未重置、快照共享、错误投影和低精度停滞，建立每项故障与检测证据的映射。

**解析路线：** 每次只注入一种错误，先预测目标、梯度、更新和日志中哪些量会变化。用手算检查目标，用方向差分检查局部导数，用固定参数的分批一致性检查归约，用状态重放检查下一步转移，用独立求解检查整体结果。不要让所有检测都调用同一个可能有错的函数，否则所谓多个证据其实共享同一盲区。

同时构造错误恰好不被发现的输入。例如只在错误梯度的正交方向做差分，或使用没有激活不稳定方向的初值。记录这些失败检测，而不是隐藏它们。它们能说明检查适用范围，并指导增加哪种独立案例，比把测试通过率包装成普遍正确性更有研究价值。

**验收：** 最终表格包含故障、预期、实际观察、能发现的检查和仍不能排除的其他原因。这样的表格可以作为后续复杂训练的排查路线，但移植时仍要补充新状态、随机层和约束，不能把小目标检查当成大型系统的完整证明。

<a id="optimization-4-detail-59"></a>

### 8.4 一份最终报告怎样组织证据

报告应先给具体问题和结论范围，再介绍目标、方法与预算，随后展示支持结论的轨迹、成功与失败统计，最后讨论限制。只按实验执行顺序堆日志，会让读者难以判断哪项证据真正支持主张；按问题组织，则能把配置、预测和结果连起来。

配置需覆盖目标归约、正则对象、初值、状态约定、随机流、数据版本、评价频率和停止阈值。代码或库版本、硬件、线程和数值类型影响复现边界，也应保留。并不是任何实验都要求逐位一致，但应说明追求的是同一状态轨迹、合理数值容差，还是重复实验中的统计一致结论。

失败案例和限制不是末尾可有可无的装饰。它们帮助读者判断方法在哪些结构中可信，也帮助后来者避免把不同问题的结果混用。完成本章后，学习者应能把“损失下降了”推进为一个更完整的陈述：下降的是哪个固定目标、用了什么信息与成本、由哪些独立证据核验，以及哪些结论仍然没有被证明。
