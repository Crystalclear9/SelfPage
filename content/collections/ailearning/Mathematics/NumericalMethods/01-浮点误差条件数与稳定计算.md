## 1. 从表示集合到一次舍入

<a id="numerics-1-detail-1"></a>
### 1.1 二进制科学记数法决定了误差结构

实数是一条连续数轴，固定长度的浮点格式只有有限多个码字。以二进制规格化数为例，其形式是 $`(-1)^s(1.b_1\cdots b_{p-1})_2 2^e`$。这里的有效位数包含隐含的最高位一；指数控制可覆盖的量级，有效位控制同一量级中相邻数的间距。这两个能力互不替代。指数范围很大仍可能无法区分相近数，有效位很多也不能表示任意大的有限实数。

在常见 IEEE binary64 格式中，有效位数为五十三，最小正常指数为负一千零二十二，最大正常指数为一千零二十三；binary32 的有效位数为二十四。所谓双精度约十五到十六位十进制有效数字，是二进制有效位换算后的量级描述，不代表小数点后固定有十六位。一个数乘上很大的二次幂，其绝对间距也随之扩大，保持的主要是相对分辨率。

考虑一个玩具系统：有效位四位，数落在一到二之间。可表示的正数依次为一、一点一二五、一点二五，直到一点八七五，相邻间隔八分之一。进入二到四之间后，间隔变为四分之一。因此同样的零点零五扰动，在某些量级可能改变表示，在另一些量级完全消失。浮点网格不是固定精度的小数刻度尺，而是一组按指数分段伸缩的网格。

十进制零点一的二进制展开无限循环，因为约分后分母包含五，不能写成有限二次幂分母。把它转换成机器数，已经发生第一次近似。随后加法再发生舍入，最后打印算法选择足以识别结果的十进制字符串。看到`0.1 + 0.2`与`0.3`不相等，应追问表示误差与运算误差各在哪里，而不是认为某个十进制运算符偶尔失效。

这里还有一种容易忽略的区分：浮点数本身是一个精确的有理数；它作为某个理想输入的近似时才带有表示误差。例如程序收到的零点一可以被精确转换为分数，但这个分数不等于一除以十。验证算法时，必须说明目标是真实十进制问题，还是已舍入二进制输入上的问题。两种参考各有用途，却不应该混为同一精确答案。

<a id="numerics-1-detail-2"></a>
### 1.2 机器间距 eps 与单位舍入误差 u

设采用就近舍入，在两个候选距离相等时按偶数尾位选择。对二进制有效位数 $`p`$，一的右邻居与一之差为 $`\epsilon=2^{1-p}`$，常由`finfo.eps`给出；标准误差分析中的单位舍入误差是 $`u=2^{-p}=\frac{\epsilon}{2}`$。许多文章把两者都叫机器精度，直接照抄常数就可能相差二倍。本章一律用 $`u`$ 表示就近舍入模型中的相对上界。

在正常范围内，精确结果位于某个指数区间，最近网格点的距离不超过该区间间距的一半。再除以精确结果的大小，可以得到不超过 $`u`$ 的相对误差界。因此当精确结果非零、没有上溢，且处于适合该模型的范围时，可以写成 $`\operatorname{fl}(z)=z(1+\delta)`$，其中 $`\vert \delta\vert \le u`$。这是一条带前提的模型，不是所有计算输出的永久合同。

为什么一附近的上下间距不相同？一左边属于较小的指数区间，间距为右边的一半。因此“在一上加上多小的数开始改变结果”还涉及方向与平局规则。以 binary64 为例，一加 $`u`$ 正好处于一与右邻居的中点，按偶数舍入仍是一；不能据此把 $`u`$ 解释为任意方向都能观测到的最小增量。

此外，`eps`不是所有函数的相对误差，也不是所有结果的验收阈值。一个百万项求和经历许多舍入，一个敏感问题会放大输入误差，某个超越函数的实现也需要单独分析。把每次运算的局部尺度直接当成整个算法的最终保证，等于忽略了运算次数与误差传播。

<a id="sec-1-1"></a>
### 基础算例：用相对尺度解释误差是否可接受

设甲仪器报告长度一千米，乙报告一微米，两者计算绝对误差都为千分之一米。甲的相对误差为百万分之一，乙的相对误差却为一千。两组数据的绝对误差相同，并不意味着科学结论同样可靠。换一种单位后，绝对误差数值会变，相对误差不变；所以验收规则既需要单位，也需要参考尺度。

但相对误差并非处处优越。某个力在平衡点的理论值为零，计算得到极小残量，除以真值没有意义。此时应根据力的典型量级、输入误差与任务容许量给绝对容差。常用组合判据 $`\vert \widehat y-y\vert \le a+r\vert y\vert `$，其中 $`a`$ 有输出单位，$`r`$ 无量纲。它既能保护零点附近，也能随输出尺度变化，但仍需要使用者解释常数的来源。

<a id="numerics-1-detail-3"></a>
### 1.3 次正规数、渐进下溢和表示范围

正常数最小值附近，若仍要求最高有效位为一，就会从最小正常数突然跳到零。次正规数允许最高有效位为零，使接近零的一段改为固定绝对间隔。binary64 的最小正常正数为 $`2^{-1022}`$，最小正次正规数为 $`2^{-1074}`$；后者远小于前者，但有效相对位数会逐步减少。

因此“下溢意味着立即变零”并不准确。若系统保留渐进下溢，小量还可能以次正规数存在；再小才会舍入成零。此区间内用固定 $`u`$ 控制相对误差可能失效，更合适的解释需要绝对误差项。可以采用保守形式 $`\vert \operatorname{fl}(z)-z\vert \le u\vert z\vert +\frac{\eta}{2}`$，其中 $`\eta`$ 为最小正次正规数，且仍排除上溢等异常。这里额外的绝对项使接近零的情况不被错误纳入纯相对模型。

部分硬件、内核或加速配置会把次正规输入或结果当零处理，行为与完整渐进下溢不同。不能只看存储 dtype 就推断实际执行模式。实验若依赖极小量，应明确设备与模式，并在目标执行路径上验证；普通温和数据上的通过不能替代对这类边界的核查。

上溢则是另一回事。精确结果超过有限表示范围时，某些操作得到无穷大；随后无穷大减无穷大可能产生 NaN。有限输入并不保证有限中间结果，也不保证有限输出。两个大数平方后求和可以上溢，即使最终希望得到的归一化方向本来有定义。稳定实现需要在危险的中间步骤之前改变尺度。

<a id="numerics-1-detail-4"></a>
### 1.4 特殊值是诊断信息，不是自动修复方案

正负无穷、NaN 与带符号零具有各自语义。无穷可能来自上溢，也可能是模型合法边界；NaN 通常表示某次运算没有相应实数结果或已经接收 NaN。带符号零在倒数、分支和复数边界中可能影响行为。因此诊断首先定位产生特殊值的操作，再解释它对应的数学对象。

若日志概率本来是负无穷，说明某事件在模型下概率为零；把它改成零会把该事件变成概率一的对数值。若损失因为上游溢出得到 NaN，最终替换为零会掩盖错误并改变训练权重。正确做法通常是明确输入域、排除意外非有限值，并用保持目标的稳定公式；只有当业务本来规定截断或缺失处理时，才按该定义修改数据。

<a id="visual-numericalmethods-01"></a>
### 图解：相消为何放大浮点影响

![相消为何放大浮点影响：机制、算例与边界](images/01-concept.svg)

在 IEEE binary64、最近舍入且平局取偶数的约定下，$`a=10^{16}`$ 可以精确表示，附近相邻浮点数的间距是二。精确实数和 $`a+1`$ 位于 $`a`$ 与 $`a+2`$ 正中间；$`a`$ 对应偶数尾数，因此舍入回 $`a`$。这时再减 $`a`$ 得到零，最后一次减法本身并没有引入误差，丢失的一早在相加时就已消失。

相反，先计算 $`a-a=0`$ 再加一，则得到一。两条路径使用相同的三个可精确表示输入，区别是中间结果的舍入位置；因此不能把差异归咎于输入十进制数本身无法表示。也不能笼统地说“相近数相减一定产生新的舍入误差”：它可以完全精确，却暴露并放大之前误差的相对影响。条件性与算法误差的区别可对照 [《Fundamentals of Numerical Computation》问题与条件数](https://fncbook.com/conditioning/)。

下排进一步检查二进制指数分界处的格点。令 $`u=2^{-53}`$，在一左侧相邻 binary64 数间距为 u，在一右侧间距却为 $`2u`$。名义 $`h=10^{-16}`$ 约等于 $`0.90072u`$，所以 $`1-h`$ 舍入到 $`1-u`$，$`1+h`$ 则舍入到一。两边使用相同实数步长，不保证机器中实际生成的两个节点仍对称；这与下一章差分末端的节点退化直接相关。

这里的 u 是为了画数轴选用的左侧格点间距，不应与有些资料用 u 表示的任意局部 ULP 混为一谈。精度定义、单位舍入与局部格距必须分别确定：单位舍入给相对误差模型，局部间距还随指数区间变化。指数分界处的一侧较密、一侧较疏，是表示集合本身的结构，不是加法程序偶然偏向某一边。

图只固定上述运算格式与求值顺序。扩展精度、重排求和或补偿算法可能改变结果；复现实验应显式控制顺序，而不是仅凭表达式在实数域中等价就认为浮点结果相同。

## 2. 条件数描述问题，稳定性描述算法

<a id="numerics-1-detail-5"></a>
### 2.1 从一阶扰动推导条件数

设标量函数在输入 $`x`$ 可微，扰动后满足 $`f(x+\Delta x)-f(x)=f'(x)\Delta x+o(\vert \Delta x\vert )`$。若以绝对输入扰动为尺度，局部绝对条件数是 $`\vert f'(x)\vert `$。若输入和输出均非零，比较相对变化得到 $`\kappa_{\mathrm{rel}}(x)=\vert \frac{xf'(x)}{f(x)}\vert `$。条件数不是计算过程使用了多少位，而是精确问题在该点对指定扰动模型的敏感性。

例如平方函数在非零处的相对条件数为二，说明相对输入误差很小时，输出相对变化约为其二倍。指数函数的相对条件数为 $`\vert x\vert `$，所以输入绝对值很大时，即使指数计算实现很好，输入相对误差也会显著影响输出。对 $`f(x)=x-1`$，当输入趋近一，输出趋近零，相对条件数发散；然而绝对条件数始终是一。病态与否必须连同误差度量一起说。

多变量情形需要规定输入集合与范数。若 $`F:\mathbb R^n\to\mathbb R^m`$ 可微，雅可比为 $`J`$，则小扰动下 $`\Vert \Delta y\Vert \lesssim\Vert J\Vert\;\cdot\;\Vert \Delta x\Vert `$；相对范数条件数是 $`\frac{\Vert J\Vert\;\cdot\;\Vert x\Vert }{\Vert F(x)\Vert }`$。诱导范数表示在所选输入方向中最不利的放大率。更换单位或缩放坐标，会改变未经尺度归一的范数条件数，这不是矛盾，而是扰动模型发生了变化。

若不同分量有各自的测量误差，使用统一范数球可能过于粗糙。假设 $`\vert \Delta x_i\vert \le \varepsilon \vert x_i\vert `$，则第 $`j`$ 个输出满足 $`\vert \Delta y_j\vert \lesssim\varepsilon\sum_i\vert J_{ji}\vert \vert x_i\vert `$。再除以 $`\vert y_j\vert `$ 可以得到分量相对条件量。这个公式把“每个输入大约有相同相对精度”直接写进分析，比用一个大坐标掩盖小坐标更贴合许多实验数据。

<a id="numerics-1-detail-6"></a>
### 2.2 加法、减法与求和的条件量

计算 $`s=a+b`$，假定两个输入各有不超过 $`\varepsilon`$ 的相对扰动，则输出绝对扰动至多约为 $`\varepsilon(\vert a\vert +\vert b\vert )`$，相对扰动上界为 $`\frac{\varepsilon(\vert a\vert +\vert b\vert )}{\vert a+b\vert }`$。两个同号数相加时该比值为一；接近抵消时比值可能很大。一般求和的分量相对条件数是 $`\kappa_{\mathrm{sum}}=\sum_i\frac{\vert x_i\vert }{\vert \sum_i x_i\vert }`$，真和为零时通常不应以它作有限相对指标。

设输入为一亿与负一亿加一，精确和为一。若每个输入只知道到相对百万分之一，其绝对不确定性可达百，最后的一并无可信依据。换一种减法实现不能恢复已经未知的输入末位。相反，如果这两个机器输入是精确给定的整数，某些减法完全精确，此时输出一可能准确无误。相同算式在不同输入来源下，结论可以截然不同。

因此“减法会损失有效数字”应理解为它容易放大操作数已有误差，而非减法指令总会产生巨大舍入。在符合条件的浮点系统中，两个足够接近的同号浮点数相减甚至可能精确。真正需要追踪的是前面如何得到这些操作数，以及相减后相对尺度缩小了多少。把误差归因于最后一个减号，常常错过更早的舍入和输入不确定性。

<a id="sec-2-1"></a>
### 机制展开：后向稳定不等于原问题不敏感

前向误差比较实际输出 $`\widehat y`$ 与原问题的精确输出 $`F(x)`$。后向误差则问能否找到小扰动 $`\Delta x`$，使 $`\widehat y=F(x+\Delta x)`$；其最小允许大小衡量程序是否精确解决了附近的问题。若算法的后向扰动与单位舍入误差同阶，并且常数对问题规模可控，通常称其后向稳定。这个定义一定依赖允许扰动哪些输入、用什么范数度量。

把后向解释代入局部条件分析，可以得到前向相对误差近似不超过“条件数乘后向相对误差”。这不是无条件等式；需要扰动足够小、解的分支保持、局部模型适用。有些问题还能推出包含分母 $`1-\kappa\varepsilon`$ 的非渐近界；当分母接近零，线性直觉不再提供有效保证。

考虑 $`A=\operatorname{diag}(1,10^{-12})`$，右端 $`b=(1,10^{-12})^T`$，精确解为 $`(1,1)^T`$。若右端第二分量增加 $`10^{-15}`$，输入的整体二范数相对变化约为千万亿分之一，第二个解分量却增加千分之一。算法可能完美求出新问题的解，但原问题的解已对这种扰动敏感。第三章将进一步区分矩阵残差、后向误差与分量条件数。

从实验上看，输入测量误差、数据类型转换误差、运算舍入和模型误差是四个不同来源。提高相应阶段的计算精度可以降低表示与运算舍入误差，却不能消除测量误差或模型失配，也不会使带噪观测自动变成真实值。若目标参数本身不可辨识，还需要改变实验、加入明确先验或重新定义问题。数值稳定性是可靠计算的一部分，并不替代统计识别。

<a id="numerics-1-detail-7"></a>
### 2.3 稳定改写为什么不违背条件数

同一函数如果病态，任何算法都不能统一消除对真实输入扰动的敏感性；但某种表达可能引入比条件数要求更大的额外误差。稳定改写修复的是这一部分。判断改写是否有效，先看两个表达在数学定义域内是否同一函数，再看各自中间量与舍入传播。仅仅观察一种实现更接近某个输出，还不能确定原因。

一个典型情形是 $`f(x)=\sqrt{1+x}-1`$ 在接近零而非零的位置。导数为 $`\frac{1}{(2\sqrt{1+x})}`$，有理化可得相对条件数 $`\kappa(x)=\frac{(\sqrt{1+x}+1)}{(2\sqrt{1+x})}`$，其极限是一。也就是说小输入的相对误差没有被问题本身异常放大；直接算法却先把一加上极小数，再取平方根，最后相消，可能丢掉全部有用输出。这是算法表达不稳定，而不是原问题必然困难。

<a id="sec-3"></a>
## 3. 稳定计算指数和与概率

<a id="numerics-1-detail-8"></a>
### 3.1 平移恒等式及其误差意义

设输入都是有限实数，定义 $`L(z)=\log\sum_{i=1}^n e^{z_i}`$。令 $`m=\max_i z_i`$，有 $`L(z)=m+\log\sum_i e^{z_i-m}`$。移位后的指数属于零到一之间，且至少有一项等于一，因此不会在单个指数步骤上溢，求和也不会成为空的极小值。对于实际可存储规模的数组，这通常显著改善范围安全。

取两个 logits 为一千与一千零一，原式中的指数超出 binary64 常见范围，而稳定式只需计算一与 $`e^{-1}`$。结果为 $`1001+\log(1+e^{-1})`$，约一千零一点三一三二六。注意整个结果的大部分是一千零一，如果任务只需要两个概率，先算巨大对数总和再相减还会引入不必要的相近大数相减。直接使用移位后的对数概率更合适。

具体来说，先算 $`v_i=z_i-m`$，再算 $`\ell=\log\sum_i e^{v_i}`$，返回对数概率 $`\log p_i=v_i-\ell`$。若写成 $`z_i-(m+\ell)`$，两者实数上相同，但后者在 $`m`$ 极大而差值很小时可能损失有效位。稳定不是一种只在函数最外层添加的标签，而是整条依赖链中持续维护的性质。

输入都平移常数 $`c`$ 时，$`L(z+c\mathbf1)=c+L(z)`$，概率不变。这个不变性可以用于测试，但也有浮点边界：若 $`c`$ 太大，平移操作本身把不同 logits 舍入成同一个数，后续算法无法恢复原差值。结构测试应使用不会先摧毁输入信息的范围，并明确这是实现检查而非关于所有有限精度平移的恒等保证。

<a id="numerics-1-detail-9"></a>
### 3.2 被忽略的小指数与可证明的绝对影响

稳定移位后，某些极小指数仍可能下溢成零。是否有害取决于目标。设保留项之和为 $`S>0`$，被忽略项的真实总和为 $`r\ge0`$，则对数总和的差为 $`\log(1+\frac{r}{S})\le\frac{r}{S}`$。只要丢失总质量相对已保留质量很小，对数总和的绝对误差也很小。这里需要控制的是所有丢失项之和，而不是单个最小项。

但若任务要输出某个罕见事件的对数概率，就不应先得到已经下溢为零的概率再取对数。直接计算移位对数概率可以保留一个很大的负有限值。例如二分类 logit 为一千，错误类别的概率在双精度中可能无法正常表示，但对应的对数概率约为负一千，仍然容易表示。数值接口的输出对象决定应在哪个空间计算。

所有输入为负无穷时，原始指数和为零，对数是负无穷；机械执行“减最大值”会产生负无穷减负无穷。存在正无穷时，若只求对数总和，可以定义结果为正无穷；若还求 softmax，多个正无穷如何分配概率则需由具体极限或接口合同确定，不能由一个 NaN 替换规则猜出。本章代码刻意只接受非空有限实数向量，使实验结论与输入域一致。

<a id="deep-dive-3"></a>
### 深入讲解：从数学恒等式到稳定损失

二分类交叉熵若先算 sigmoid，再对概率取对数，在极端 logit 上容易遇到概率舍入为零或一。对标签 $`y\in\{0,1\}`$，令 $`s=2y-1`$，单样本损失为 $`\log(1+e^{-sz})`$。再利用 softplus 稳定式 $`\max(t,0)+\log(1+e^{-\vert t\vert })`$，其中 $`t=-sz`$，就避免了巨大正指数。

写成带符号的 softplus 还有一个好处：正确且极其自信时，可以保留应当很小但非负的损失。如果先计算 $`\operatorname{softplus}(z)-yz`$，当 $`y=1`$ 且 $`z`$ 较大，两大项相消可能直接得到零；这不一定影响某些粗尺度目标，却不适合把微小损失当作高精度诊断量。表示等价不等于所有局部数值特征等价。

梯度也需要独立稳定表达。对上述损失，导数为 $`-\frac{s}{(1+e^{sz})}`$，可以用 $`-s\exp(-\operatorname{softplus}(sz))`$ 实现。直接写 sigmoid 减标签，在正类大正 logit 时会把接近一的 sigmoid 舍入为一，从而过早得到零。这里不是宣称微小梯度总有优化意义，而是说明算法选择会影响尾部保真度，必须根据研究对象决定是否需要保留。

这些变换都保持原始损失的数学定义域与含义。与之不同，强行把概率截到一个固定下界，会改变损失和梯度；它有时是明确的建模选择，却需要说明截断阈值、零梯度区间或偏差。稳定实现和改变目标可以同时有用，但应在文档中分开解释，以免实验比较混入不同问题。

<a id="sec-4"></a>
## 4. 相消、尺度变换与专用函数

<a id="numerics-1-detail-10"></a>
### 4.1 两个平方根之差的完整分析

先看 $`f(x)=\sqrt{x+1}-\sqrt{x}`$，假设 $`x>0`$。乘以共轭可得 $`f(x)=\frac{1}{(\sqrt{x+1}+\sqrt{x})}`$。当 $`x`$ 很大，真实差值约为 $`\frac{1}{(2\sqrt{x})}`$，而两个平方根各自约为 $`\sqrt{x}`$。若各有相对量级 $`u`$ 的误差，直接相减的绝对误差约为 $`u\sqrt{x}`$，除以真实差值得到相对量级约 $`ux`$。因此即使每次平方根都计算得很好，组合后的相对误差也可能极差。

稳定式的分母是同号相加，没有主导相消，倒数再产生一次温和舍入；在合适范围内可保持接近单位舍入的相对精度。即使浮点求得的 $`x+1`$ 恰好等于 $`x`$，分母近似为 $`2\sqrt{x}`$，仍可能很好地逼近函数真实值。直接式则可能完全为零。这个例子清楚展示了同一中间舍入在不同依赖链中可以有不同后果。

然而有理化也不是不检查范围就能到处套用。对 $`\sqrt{1+x}-1`$，稳定式 $`\frac{x}{(\sqrt{1+x}+1)}`$ 要求 $`x\ge-1`$；当 $`x`$ 接近负一时，导数变大，问题本身更敏感。当 $`x`$ 极大，若某种分母结构还能上溢，就需继续缩放。每一个改写都应附上定义域、危险中间量以及适用误差模型，而不只是记住一个“稳定公式”。

<a id="numerics-1-detail-11"></a>
### 4.2 log1p 与 expm1 保留靠近零的信息

对很小的 $`x`$，直接计算 $`\log(1+x)`$ 会先把 $`1+x`$ 舍入。若 $`x`$ 比一附近的间距小，和可能等于一，最终对数为零；然而真实结果约为 $`x`$。`log1p(x)`是针对这个组合目标设计的接口，避免必须先丢弃小增量。类似地，`expm1(x)`计算 $`e^x-1`$，可以绕开先把指数舍入成一再相减的问题。

二者可以组合解决更多问题。例如比较两个接近的正数 $`a`$ 与 $`b`$ 的对数比时，若 $`a=b(1+t)`$ 且 $`t`$ 能可靠计算，可以求`log1p(t)`，而非先算两个接近对数再相减。复利的小利率、短时间生存概率、指数分布尾差都可能出现相同结构。关键是先识别需要的是小增量，而不是先计算一个接近一的大背景值。

但是接口不能恢复参数构造时已丢失的信息。如果输入`x`本身是在低精度中由两个几乎相同数相减得到，换成`log1p`只能准确处理这个已舍入的 x。应把独立参考建立在原始数据上，检查误差发生于参数转换、差分构造，还是专用函数内部。稳定运算常常需要从更早的表达式开始设计。

<a id="numerics-1-detail-12"></a>
### 4.3 二次方程根与保留的小根

对于实系数二次方程 $`ax^2+bx+c=0`$，朴素求根式在 $`\vert b\vert `$ 很大而 $`\vert ac\vert `$ 相对小时，其中一支会出现 $`-b`$ 与平方根相消。设判别式非负、$`a\ne0`$，先计算 $`q=-\tfrac12(b+\operatorname{sign}(b)\sqrt{b^2-4ac})`$，再求两个根 $`\frac{q}{a}`$ 与 $`\frac{c}{q}`$，可以让关键加法同号，并利用根的乘积 $`\frac{c}{a}`$ 恢复小根。这里约定 $`b=0`$ 时选定一个符号，并单独处理 $`q=0`$ 的退化情形。

例如 $`x^2-10^8x+1=0`$，大根接近一亿，小根接近一亿分之一。直接公式的小根是两个约一亿的数相减后再除以二，很容易丢失大量相对位；稳定路径先算大根，再利用乘积求小根。校验时同时查看两个根的残差、和与积，且以尺度归一残差，不能只看某个根打印了几位。

这还不是通用二次方程求解器。直接计算判别式的 $`b^2`$ 或 $`4ac`$ 仍可能上溢，近重根时判别式本身敏感，系数范围极端还需缩放或更精细算法。本例用于说明相消修复与条件数的区别；后续求根章节会说明近重根和停止证据，避免把一个局部技巧误当成全面保证。

<a id="numerics-1-detail-13"></a>
### 4.4 先缩放再求范数与方差

计算向量二范数时，直接平方再求和可能上溢或下溢，即使最终范数可表示。设 $`m=\max_i\vert x_i\vert `$，非零时写成 $`\Vert x\Vert _2=m\sqrt{\sum_i(\frac{x_i}{m})^2}`$，把平方输入限制在一以内；全零向量则返回零。这个表达仍需考虑最终结果是否超范围，但已消除一种不必要的中间上溢。专用范数实现可能采用更精细的缩放累积，不应由名字直接推断算法。

方差的朴素恒等式 $`E[X^2]-E[X]^2`$ 则容易在均值很大、波动很小时相消。把数据先中心化，累加 $`(x_i-\bar x)^2`$，通常更合适；在线场景可以使用带明确更新公式的中心矩算法。这里不能声称中心化使一切问题消失，因为均值本身有误差，极大跨度和输入量化也可能破坏小波动。

特别是若原始数据先存为低精度，均值附近的变化已经小于输入间距，则任何后处理都无法恢复。例如把一亿附近相差一的观测存入 binary32，多个值会合并成同一个表示。后来转为 binary64，只是把相同机器值更精确地存储起来。混合精度应在信息被压缩之前考虑，而不是只在最终统计步骤升级 dtype。

<a id="sec-5"></a>
## 5. 求和与点积：从局部舍入到整体界

<a id="numerics-1-detail-14"></a>
### 5.1 顺序求和的误差界怎样得到

设输入机器数 $`x_1,\ldots,x_n`$ 视为精确，顺序求和的每次加法满足正常范围的相对舍入模型。展开递推后，每个输入都会乘上一串 $`(1+\delta_j)`$；若 $`ku<1`$，这些乘积相对一的偏差可以用 $`\gamma_k=\frac{ku}{(1-ku)}`$ 控制。由三角不等式可得保守界 $`\vert \widehat s-s\vert \le\gamma_{n-1}\sum_i\vert x_i\vert `$。

证明的关键不是假设误差随机抵消，而是把每个输入经历的舍入次数上界代入，并对所有符号都采用最坏情形。若进一步除以非零真和，便有相对误差界 $`\frac{\vert \widehat s-s\vert }{\vert s\vert }\le\gamma_{n-1}\kappa_{\mathrm{sum}}`$。这把算法的舍入累积与问题的抵消程度清楚分开：正项和条件数为一，混合符号和可能病态。

界通常比实际误差保守，但保守并不等于无意义。它回答最不利情况可以多大，而不是预测每次运行最后几位。用若干随机正态样本观察到误差更小，不能推翻最坏界；同样不能因此保证未来所有数据都很准。研究中应注明讨论的是确定界、经验分布还是特定数据集结果。

如果 $`nu`$ 不再远小于一，线性化的 $`nu`$ 近似和这个简单界都缺乏吸引力。可以增加累积精度、改变求和结构，或按块归约。若发生上溢、非有限输入、次正规特殊行为，前述纯相对模型的前提也需重审。误差分析不能只在最后给一个公式，而不检查实际循环是否满足它。

<a id="numerics-1-detail-15"></a>
### 5.2 平衡树、排序与可复现性

平衡二叉树求和让每个输入大约经历 $`\lceil\log_2n\rceil`$ 层加法，因此在相同前提下可把相应深度代入 $`\gamma`$ 得到更好的上界。它也自然适合并行，但具体分块、线程数量和归约树会改变输出末位。声明采用二叉归约，比声明“使用并行所以更准”更有信息，因为并行本身不是特定误差算法。

按绝对值从小到大累加有时可以减少小项被大部分和吞掉，然而需要排序成本，也不对所有混合符号数据给出统一最优结果。若排序改变了原数据语义或破坏流式处理约束，更不应把它当作随手可用的标准补丁。比较方案应列出额外内存、访问次数、排序时间与误差变化。

逐位可复现与数值更准确是两个不同目标。固定一棵归约树可以让同一路径重现相同结果，但该结果仍可能有误差；更高精度或补偿求和可能更准，却在不同底层实现上不一定逐位相同。论文和工程报告应分别写清重现要求与误差要求，不把其中一个当成另一个的证据。

<a id="numerics-1-detail-16"></a>
### 5.3 补偿求和保存被舍弃的低位

补偿求和的思想是给主和附带一个小修正，尽量把每次加法遗漏的部分带入后续运算。最经典的 Kahan 形式维护主和与补偿变量，运算顺序必须保持；如果编译器按实数代数把补偿式重排为零，算法就失去意义。普通 Python 示例可以明确呈现顺序，但移植到开启激进重排的内核时还需检查编译语义。

本章实验采用 Neumaier 的补偿变体。令新主和 $`t=\operatorname{fl}(s+x)`$，若 $`\vert s\vert \ge\vert x\vert `$，把 $`(s-t)+x`$ 加入补偿；反之把 $`(x-t)+s`$ 加入补偿。这样根据较大操作数选择提取低位的表达，能处理某些经典 Kahan 形式表现不佳的大幅抵消序列。最终返回主和加补偿。

用序列 $`10^{16},1,-10^{16}`$ 演示：第一步把一加入巨大主和时，一可能丢失；补偿记录这一项。随后大正数与大负数抵消为零，最后加回补偿得到一。这个小例子既能验证修正项确实被使用，也说明“所有输入都是有限整数”并不保证普通浮点累加保留精确整数和。

补偿不是无限精度，补偿变量自身也会舍入，数据极端时仍可能上溢或丢失信息。其理论界需要相应舍入模式、运算顺序和无异常范围条件。本章不把某个简短实现描述为对所有输入精确，而是将它作为在温和范围中改进误差的算法，并用独立高精度参考与恶意构造数据检验。

<a id="numerics-1-detail-17"></a>
### 5.4 点积、融合乘加与积的误差

点积 $`s=\sum_i a_ib_i`$ 有两个阶段：每个乘积的舍入和归约的舍入。即使使用精确求和算法，如果乘积已在低精度中舍入，仍不等于精确实数点积。普通分析可在合适前提下得到形如 $`\vert \widehat s-s\vert \le\gamma_n\sum_i\vert a_ib_i\vert `$ 的界，常数取决于具体运算组织，不能只从 API 名称推断。

融合乘加对 $`ab+c`$ 先形成精确组合再只舍入一次，可以减少一次中间舍入，也能改变结果末位。它不等于无限精度点积，也不解决输入量化。若两个实现一个使用融合、另一个分开乘加，输出不同未必是语义错误；比较需要参照数学目标和误差尺度，而不是要求每个硬件路径逐位一致。

独立参考需要尽可能打破与被测实现相同的错误路径。仅用另一个同精度矩阵乘法作为参考，可能共享归约和乘积问题。对于小规模测试，可以将机器输入精确转成有理数或 Decimal，再做高精度乘加；另一个参考则从原始十进制字符串重建理想数据。这两者分别检验计算误差与端到端误差，报告时应标明对象。

<a id="numerics-fma-midpoint"></a>

### 图解：一次乘法舍入如何抹掉最终答案

![浮点中点上的精确乘积：先乘后加丢失低位，融合乘加保留结果](images/01-fma-midpoint.svg)

**选择没有输入表示误差的算例。** 以下使用 IEEE binary64、最近舍入且平局取偶数，并假定分开计算时确实先把乘积舍入到 binary64；没有上溢、下溢或额外扩展精度。令

$$
h=2^{-27},\qquad a=1+h,\qquad b=1-h,\qquad c=-1.
$$

四个输入都是二进制有限小数，均能精确表示。数学乘积和最终结果分别为

$$
ab=(1+h)(1-h)=1-h^2=1-2^{-54},
\qquad ab+c=-2^{-54}.
$$

为了看清为什么先乘后加会失败，记 $`\delta=2^{-54}`$。它不是本章的单位舍入误差 $`u=2^{-53}`$；这里用它表示这道算例的精确残差。紧邻 1 下方的 binary64 数是 $`1-2^{-53}=1-2\delta`$，而 1 本身也可表示。精确乘积 $`1-\delta`$ 恰好在二者中间，无法存进一个 binary64 数。

**平局为何选 1？** 在下方间距为 $`2^{-53}`$ 的格点上，1 对应整数系数 $`2^{53}`$，是偶数；前一个数对应 $`2^{53}-1`$，是奇数。最近舍入的平局规则因此选择 1。分开执行的结果是

$$
p=\operatorname{round}(ab)=1,\qquad
\operatorname{round}(p-1)=0.
$$

后一减法本身没有产生误差，它准确地算出了两个已经相等的机器数之差。错误在前一步已发生。即使接下来使用补偿求和，甚至精确求和处理列表 $`[1,-1]`$，也只能得到零，因为该列表已不包含被舍弃的 $`-\delta`$。这正是“求和准确”与“点积准确”之间需要补上的一层。

**融合改变的是中间舍入位置。** FMA 的语义是把 $`ab+c`$ 当作精确组合，再只对最终结果舍入一次。本例的 $`-\delta`$ 是可精确表示的二次幂，所以

$$
\operatorname{fma}(a,b,-1)
=\operatorname{round}(-2^{-54})
=-2^{-54}
\approx-5.551115123125783\times10^{-17}.
$$

这一单次舍入约定可参照 [GNU C 手册的融合乘加说明](https://www.gnu.org/software/c-intro-and-ref/manual/html_node/Fused-Multiply_002dAdd.html)。图中画的是语义差异，不是在比较指令速度。编译器若把源码中的乘加自动收缩为 FMA，或者先在更宽的寄存器中运算，“分开表达式”的结果可能变化；复现实验必须记录实际运算规则，不能只看源代码是否写了两个运算符。

**如何建立不共享舍入路径的参考？** 将机器输入直接转换为精确有理数，分别计算 $`ab-1`$，可得

$$
-\frac{1}{18014398509481984}.
$$

把这个有理数转换回 binary64 后应与 FMA 的结果一致，而单独存储乘积再减一得到零。这个检查从精确输入出发，避免拿另一个同精度乘法当真值。它同时揭示一个容易忽略的事实：最终答案能够精确表示，并不保证求它的中间步骤也能够精确表示。

这个例子不意味着用一串 FMA 就获得精确点积：每次 FMA 的输出仍会舍入，后续累积仍可能丢失信息。它也不能修复已经量化的输入。应将输入误差、乘积误差、累积误差分别追踪，再判断融合、补偿或更高精度应该放在哪个位置。

<a id="numerics-1-gamma-proof"></a>
### 5.5 乘积引理的推导与误差界的使用限制

为使求和界不只停留在结论，考虑 $`P_k=\prod_{j=1}^k(1+\delta_j)`$，其中 $`\vert \delta_j\vert \le u`$ 且 $`ku<1`$。上侧可通过展开乘积并用几何级数控制：各阶交叉项的绝对和不超过 $`ku+(ku)^2+\cdots=\frac{ku}{(1-ku)}`$。这里采用 $`\binom{k}{r}u^r\le(ku)^r`$，虽非最紧，却使推导清楚。下侧也可从 $`1-(1-u)^k\le ku`$ 得到不超过同一 gamma 的偏差。因此 $`P_k=1+\theta_k`$，且 $`\vert \theta_k\vert \le\gamma_k`$。

顺序求和展开后，最早的输入乘上最多的舍入因子，越晚加入的输入经历因子越少。分别把这些乘积写成一加 theta，精确和与计算和之差成为各输入乘 theta 的总和；对每项取绝对值，再用统一最大深度，便得到正文中的界。这种证明允许舍入误差彼此相关，也允许符号最不利排列，所以不需要假设随机独立。

然而把该界用于实际点积前，应先确认乘法误差是否已计入。若把低精度乘积当成输入，求和界只描述这些乘积的归约误差；要对照原始实数点积，还必须加入每个乘积的偏差。类似地，如果库采用分块归约，深度应按真实分块结构分析，而不能一面享受树形界、一面实际执行顺序累加。数学界与代码路径必须对应。

一个有价值的研究练习是固定同一输入，逐步增加长度，记录实际绝对误差除以 $`\sum_i\vert x_i\vert `$，再与 gamma 界比较。若实测超过理论上界，先检查参考、上溢、精度转换和算法组织，而非立即宣称理论错误；若远低于界，也应如实报告它是当前数据的观察。

理论给出允许区间，实验给出具体实例，两者承担不同职责。若改变舍入模式，单位误差常数也要重新选择；若程序允许编译器重新结合加法，原来按逐语句展开的证明未必仍描述实际执行。因而实验应记录精度、运算顺序与优化条件，让读者能够检查前提是否一致。

<a id="sec-6"></a>
## 6. 误差预算、混合精度与可解释的验收

<a id="sec-6-1"></a>
### 6.1 前向误差、后向误差与消去现象

设真实输入为 $`x_\star`$，程序存储输入为 $`x`$，实际输出为 $`\widehat F(x)`$。可以把端到端差异拆为 $`\widehat F(x)-F(x_\star)=[\widehat F(x)-F(x)]+[F(x)-F(x_\star)]`$。第一项是给定机器输入后的计算误差，第二项是输入表示或测量误差经过精确问题的传播。这条恒等式比笼统说“浮点不准”更有诊断价值。

若再存在近似模型 $`G`$ 与目标模型 $`F`$，还要加入 $`G(x)-F(x)`$。例如用低阶离散网格近似连续积分，即使用无限精度运算仍有截断误差。下一章将具体分析它与舍入的竞争。本章的重点是先分清误差来源，避免试图用换 dtype 修复模型定义、用加样本修复系统偏差，或者用更小步长修复随机噪声。

实践中可以先为每个来源设置量级预算。例如任务允许输出绝对误差千分之一，测量噪声传播已经约为万分之八，则没必要承诺最后十五位可信；但仍应让算法误差远小于剩余预算，避免运算噪声主导。反过来，如果研究需要分辨十亿分之一的改进，而验证误差本身就达百万分之一，该比较没有充分证据。

<a id="numerics-1-detail-18"></a>
### 6.2 混合精度必须拆成表示、运算与累积

一次矩阵运算至少涉及输入存储格式、乘法执行格式、累积格式、输出格式四层。低精度存储可以节省带宽，高精度累积可以降低长归约误差；但已经量化的输入细节不会在高精度累积时重生。讨论混合精度时，必须明确这四层，而不是只给出一个模型参数 dtype。

范围与精度也不同。两种低精度格式可能拥有相近存储位数，却用不同位数分配指数与有效位，因此一种更不容易上溢，另一种在一附近分辨率更好。应根据实际格式查询范围与精度；不能把“都是十六位”当成等价。训练内核可能采用额外执行模式，设备与库配置也是算法合同的一部分。

损失缩放的基本原理是先把微小梯度乘上尺度因子，使中间值落入更可表示区域，再在更新前缩回。它主要针对某些下溢风险，不会消除抵消造成的有效位损失，也可能因缩放过大引起上溢。缩放因子、溢出检测与跳过更新策略会影响实际轨迹，需要与基准比较一起记录。

迭代改进是另一类混合精度思想：用较低精度近似求解，再以较高精度计算残差，求校正。它能够成功通常依赖问题条件、低精度因子的质量和高精度残差的可靠性；不能只凭“高精度最后检查一下”推断一定恢复全精度。具体线性系统条件与收敛界留在第三章，读者应把这里视作分层精度设计，而非无条件加速承诺。

<a id="numerics-1-detail-19"></a>
### 6.3 独立参考如何构造

参考答案首先要独立于被测公式。平方根差可以用高精度共轭式计算，求和可以用精确分数或高精度 Decimal，概率损失可以对照带符号 softplus 与高精度解析值。若把被测输出再格式化成更多位数当作参考，只是放大显示，不会增加证据。

其次要区分“高精度”和“精确”。有限精度 Decimal 仍有舍入，只是使用十进制且可以调整精度；高精度结果应通过增加精度后稳定、与结构恒等式相符等方式校验。对于有限机器输入的求和，精确 Fraction 可以给出真正有理数答案，但规模较大时成本明显。因此高精度参考适合小测试集，不一定适合作为生产主算法。

第三，要避免参考数据从低精度浮点先转换。如果要验证理想十进制的零点一，应该从字符串构造 Decimal；若从已存储的 binary64 转换，得到的是那个二进制有理数的高精度展开。后者也有价值，只是检验的问题不同。实验报告最好给出输入构造代码，让别人能够判断比较对象。

<a id="numerics-1-detail-20"></a>
### 6.4 从容差到研究结论

组合容差 $`a+r\vert y\vert `$ 通常是以参考值为尺度的非对称规则；交换两个参数可能改变判断。若需要对称距离，可以自行定义 $`a+r\max(\vert a_1\vert ,\vert a_2\vert )`$ 等规则，但要说明为何适合任务。数组全体通过也需要明确是逐分量约束，还是只控制整体范数；后者可能掩盖少数重要小分量。

对近零输出，应报告绝对误差与背景尺度；对非零且有物理意义的量，再报告相对误差。对概率，可以关注归一化、非负性、对数概率和任务敏感事件，而不是只对所有分量使用同一个相对阈值。对优化，比较损失、梯度、参数与预测也应区分，因为病态模型中参数变化大而预测变化小完全可能。

可靠性不能靠不断放宽阈值直到测试通过。先写清输入精度与允许输出偏差，给出误差来源估计，再选择验收标准；若失败，定位哪一项超预算。只有新证据表明原预算不合理时才修改它，并保留原因。这样的过程能把“感觉差不多”变成可检查的数值论证。

<a id="sec-7"></a>
## 7. 分层练习与详细解析

<a id="numerics-1-detail-21"></a>
### 7.1 练习一至四：表示与扰动

**练习一：四位二进制玩具系统。** 采用就近偶数舍入，把实数一点零六二五舍入到该系统的可表示数，结果是什么？若把输入改成一点一八七五呢？请明确候选数与平局规则。

**解析：** 一到二区间的网格间距为八分之一，一点零六二五正好在一与一点一二五中间；一的末位为偶，选择一。一点一八七五在一点一二五与一点二五中间，后者的尾部最低位为零，因此选择一点二五。两个平局不总朝同一方向移动，这使大量特定场景下不至于固定向上偏，但不能据此把所有舍入当作独立零均值噪声。

**练习二：为何 eps 不等于 u？** 对有效位二十四的二进制格式，写出两者，并解释一加 u 为什么可能仍是一。

**解析：** 一的右间距为 $`2^{-23}`$，就近舍入的单位误差界为 $`2^{-24}`$。后者是一与右邻居的半间距，平局按偶数选择一。因此 eps 描述特定点的邻居距离，u 用于局部舍入界，两者含义不同。若改成定向舍入或位于别的指数区间，相关阈值又会改变，不能把这个实验当作普遍最小正增量定义。

**练习三：接近零的相对误差。** 精确结果为零，程序输出十的负十四次方，是否说明算法不可靠？请分别构造可接受和不可接受场景。

**解析：** 如果背景是单位量级的两个力抵消，且输入误差已约十的负十二次方，该残量可能远小于输入不确定性，可以接受。若目标是计算本来只有十的负二十次方量级的微弱信号，输出十的负十四次方则可能完全失真。零点本身不允许普通相对误差，判断需要绝对尺度、背景量级与任务精度。相同数字不能脱离问题被认定为好或坏。

**练习四：从导数得到条件数。** 分别求 $`f(x)=x^3`$、$`g(x)=\log x`$ 的局部相对条件数，并解释对数在一附近的行为。

**解析：** 非零 x 处，立方函数条件数为三。对数要求正输入且输出非零，条件数为 $`\frac{1}{\vert \log x\vert }`$，接近一时发散。这不意味着对数的绝对导数在一发散，它在一等于一；发散来自输出趋近零后的相对归一。若需要的是接近一的小偏离，应把绝对误差或相对增量作为合适对象，并结合 log1p 避免算法额外损失。

<a id="numerics-1-detail-22"></a>
### 7.2 练习五至八：稳定改写与条件

**练习五：平方根差的条件数。** 对 $`h(x)=\sqrt{x+1}-\sqrt{x}`$，求 x 为正时的相对条件数，说明大 x 的直接算法误差为什么不是问题病态所必需。

**解析：** 令 $`a=\sqrt{x+1}`$、$`b=\sqrt{x}`$，有 $`h=\frac{1}{(a+b)}`$，且 $`\frac{h'}{h}=-\frac{(\frac{1}{(2a)}+\frac{1}{(2b)})}{(a+b)}=-\frac{1}{(2ab)}`$。故条件数为 $`\frac{x}{(2\sqrt{x(x+1)})}=\tfrac12\sqrt{\frac{x}{(x+1)}}`$，随 x 增大趋近二分之一，问题相对良态。直接式的误差却可按 ux 放大，所以主因是中间相消。此例也提示条件数分析能帮助区分不可避免的敏感与可避免的实现损失。

**练习六：平移后的指数丢项。** 保留指数和为二，丢失项的真实总和不超过十的负十二次方，对数总和的绝对变化有何保证？这个保证能否用于每个罕见事件的相对概率？

**解析：** 变化为 $`\log(1+\frac{r}{2})\le\frac{r}{2}`$，因此不超过五乘十的负十三次方。但某个被丢弃事件原概率虽小，其计算值变成零，相对误差可以是一，故不能把对数总和的绝对保证迁移为每个分量的相对保证。需要罕见事件对数概率时，应直接在对数空间输出，而不是先舍弃概率再求对数。

**练习七：有限输入却上溢。** 两个分量都是十的二百次方，直接二范数实现可能失败，缩放实现应返回什么量级？是否说明任何二范数都能避免上溢？

**解析：** 平方中间量约十的四百次方，超出 binary64 有限范围；缩放后平方和为二，结果为根号二乘十的二百次方，仍在可表示范围。若真实范数本身超过最大有限值，再好的改写也不能在该 dtype 中返回一个有限且正确的值，必须改变表示或输出约定。稳定算法避免不必要的中间范围问题，不负责突破输出格式的数学容量。

**练习八：输入升级的极限。** 原始三条观测是一亿、一亿加一、一亿加二，先存为 binary32，再转为 binary64 计算中心方差，为什么可能不能恢复真实方差？

**解析：** 一亿附近 binary32 间距大于一，小变化可能在第一次存储时合并。转成高精度只保留已有机器值，无法知道每条原始值曾偏离多少。真实等权总体方差为三分之二，但量化数据可能得到完全不同结果甚至零。若任务必须分辨这些波动，应更早选择足够精度，或者在采集时保存基准与小偏移，而不是指望统计公式恢复未知信息。

<a id="numerics-1-detail-23"></a>
### 7.3 练习九至十二：求和与参考

**练习九：求和的条件与算法。** 对序列 $`10^8,1,-10^8`$，求精确和与求和条件数。如果某次 binary64 顺序和恰好准确，是否推翻条件数分析？

**解析：** 真和为一，绝对值和为两亿加一，条件数相同。条件数描述允许输入相对扰动下的最不利敏感，不预言每个具体机器计算都出错。这些整数在 binary64 中可精确表示，某些加法也可精确，因此得到一完全合理。若输入原本只有较低测量精度，精确求和也不能把观测含义变成一的高可信估计；必须区分计算输入和真实输入。

**练习十：平衡树的深度界。** 对一千零二十四个数，普通顺序与完全平衡求和中，每项最多参与多少次加法舍入传播？这个改善何时仍不足以保证小相对误差？

**解析：** 顺序展开最早项最多经历一千零二十三次加法，平衡树深度为十。对应最坏绝对误差界可分别使用相应 gamma 系数乘绝对值和。但若真和接近零，求和条件数巨大，即使深度十也可能无法保证小相对误差；若发生上溢，模型也不适用。树结构改善算法因子，不能消除输出本身对输入的敏感性。

**练习十一：两种高精度参考。** 为什么`Decimal("0.1")`与`Decimal.from_float(0.1)`的用途不同？应怎样用于端到端误差诊断？

**解析：** 前者表示精确十分之一，后者精确记录已经舍入的二进制机器数。在高精度上下文中对二者分别运算，可以把理想十进制数据到最终输出的误差，与给定机器输入之后的运算误差分开。如果只用后者，可能看不见初始数据转换带来的偏差；如果只用前者，又可能错误指责一个准确处理了机器输入的算法。两种参考都不是多余的，关键是标明目标。

**练习十二：点积先乘后加。** 对两个向量，先在 binary32 中逐元素相乘，再把乘积转换成 binary64 求和，为什么不等于先把两个向量转为 binary64 再乘加？

**解析：** 第一种路径的每个乘积已在低精度中舍入，累积升级不能去掉这些误差；第二种路径保留相同量化输入，但用更高精度形成乘积，通常有更小的运算误差。两者仍都不能恢复输入存储之前丢失的信息。比较时应该设置能揭示乘积误差的非整数输入，使用高精度的机器输入参考，并明确乘法与累积格式，而不只比较最终数组 dtype。

<a id="sec-7-1"></a>
### 边界追问：同一精度类型为何仍有不同数值结果

**练习十三：逐位一致与可信度。** 两个训练实现都宣称使用 float32，损失最后几位不同，其中一个更可复现，能否断言它更准确？

**解析：** 不能。归约树、融合乘加、设备内核、实际累积格式都会影响舍入；固定执行路径只帮助重现某个结果，并不证明该结果更接近数学目标。先确认样本、归约、掩码与模型完全相同，再用小规模高精度参考分析误差。若差异远小于任务允许误差，可以作为数值路径差异报告；若影响结论，应进一步提高诊断精度或修改算法，而不是用可复现替代准确性。

**练习十四：后向误差小却解误差大。** 对本章对角矩阵算例，把第二个右端增加十的负十五次方。写出新的精确解，并解释为何一个极小残差不能单独证明原解的每个分量准确。

**解析：** 新解为一与一点零零一。对扰动右端，该解残差为零；相对于原右端，残差只有十的负十五次方，但第二解分量差千分之一。矩阵逆把该方向放大一万亿倍。残差与前向误差之间还隔着逆算子、尺度和条件数，因此需要单独的误差解释。此问题若来自测量，增加算法精度也不能知道第二右端本应是哪一个值。

<a id="sec-8"></a>
## 8. 完整实验：用不同证据检验稳定计算

<a id="numerics-1-detail-24"></a>
### 8.1 表示、相消与指数范围的独立实验

下面的程序既包含应该通过的结构断言，也故意显示一个不稳定表达。它不把“输出不同”直接当作算法失效，而是以高精度 Decimal 的独立数学值作为参考。平方根例子的高精度输入由字符串构造，避免参考先经过二进制舍入。打印的有效数字是观测结果，不代表在所有系统上每个末位都必须相同。

```python
import math
from decimal import Decimal, localcontext
import numpy as np

info = np.finfo(np.float64)
u = info.eps / 2
assert 1.0 + u == 1.0
assert np.nextafter(1.0, 2.0) - 1.0 == info.eps
assert 0 < np.nextafter(0.0, 1.0) < info.smallest_normal

x = 1e-16
naive = math.sqrt(1.0 + x) - 1.0
stable = x / (math.sqrt(1.0 + x) + 1.0)
with localcontext() as context:
    context.prec = 90
    dx = Decimal('1e-16')
    reference = dx / ((Decimal(1) + dx).sqrt() + Decimal(1))
    stable_error = abs(Decimal.from_float(stable) - reference)
    naive_error = abs(Decimal.from_float(naive) - reference)
    assert stable_error < abs(reference) * Decimal('1e-14')
    assert naive_error > abs(reference) * Decimal('0.1')

z = np.array([1000.0, 1001.0])
m = float(np.max(z))
v = z - m
log_norm = math.log(math.fsum(math.exp(float(t)) for t in v))
log_p = v - log_norm
lse = m + log_norm
assert abs(lse - 1001.3132616875182) < 2e-13
np.testing.assert_allclose(np.exp(log_p).sum(), 1.0, atol=1e-15)
shifted = z + 16.0
sv = shifted - shifted.max()
slp = sv - math.log(math.fsum(math.exp(float(t)) for t in sv))
np.testing.assert_allclose(log_p, slp, rtol=0, atol=1e-15)
print('eps, u:', info.eps, u)
print('sqrt difference:', naive, stable, 'reference:', reference)
print('logsumexp, log-probabilities:', lse, log_p)
```

本实验的平移常数选得温和，使两个 logits 的差仍被保留。它没有证明任意巨大平移都能逐位保持输出。最小次正规数检查只验证当前执行环境的该操作，并不保证所有设备内核都采用相同模式。若把实验改到加速设备，应重新检查其实际计算路径，而不是照搬这里的断言解释。

<a id="numerics-1-detail-25"></a>
### 8.2 求和、点积与方差的误差分层实验

第二个程序把输入机器值视为精确有理数据，用 Decimal 的高精度表示求和与点积参考。这里的上下文精度对给定温和规模足够，并可通过提高精度重复核对；它不是对任意长输入都精确的通用声明。补偿实现保留原运算顺序，不使用会把补偿式代数消去的优化。

```python
import math
from decimal import Decimal, localcontext
import numpy as np

def naive_sum(values):
    total = 0.0
    for value in values:
        total = total + float(value)
    return total

def compensated_sum(values):
    total, correction = 0.0, 0.0
    for value in values:
        value = float(value)
        updated = total + value
        if abs(total) >= abs(value):
            correction += (total - updated) + value
        else:
            correction += (value - updated) + total
        total = updated
    return total + correction

values = [1e16, 1.0, -1e16]
with localcontext() as context:
    context.prec = 100
    exact = sum((Decimal.from_float(v) for v in values), Decimal(0))
assert exact == 1
assert naive_sum(values) == 0.0
assert compensated_sum(values) == float(exact)
assert math.fsum(values) == float(exact)

a = np.array([1.0001, 1.0002, -1.0003], dtype=np.float32)
b = np.array([1.0004, -1.0005, 1.0006], dtype=np.float32)
low_products = a * b
low_then_high = float(np.sum(low_products, dtype=np.float64))
high_products = a.astype(np.float64) * b.astype(np.float64)
high_then_high = math.fsum(float(v) for v in high_products)
with localcontext() as context:
    context.prec = 100
    dot_reference = sum(
        (Decimal.from_float(float(x)) * Decimal.from_float(float(y))
         for x, y in zip(a, b)), Decimal(0))
    low_error = abs(Decimal.from_float(low_then_high) - dot_reference)
    high_error = abs(Decimal.from_float(high_then_high) - dot_reference)
assert high_error < low_error

source = np.array([1e8, 1e8 + 1, 1e8 + 2], dtype=np.float64)
quantized = source.astype(np.float32).astype(np.float64)
true_variance = float(np.mean((source - source.mean()) ** 2))
lost_variance = float(np.mean((quantized - quantized.mean()) ** 2))
assert abs(true_variance - 2.0 / 3.0) < 1e-15
assert lost_variance == 0.0
print('sum:', naive_sum(values), compensated_sum(values), math.fsum(values))
print('dot absolute errors:', low_error, high_error)
print('variance before/after input quantization:', true_variance, lost_variance)
```

三组实验对应三个不同结论。求和例子展示归约算法能改变给定输入的误差；点积例子展示累积升级不能修复已舍入乘积；方差例子展示计算升级不能修复输入量化。若把三个现象统称为 float32 不好，就失去改进方向。实际项目应先定位是哪一层限制了精度，再计算升级那一层的时间与内存代价。

<a id="numerics-1-detail-26"></a>
### 8.3 从小算例扩展到研究问题

扩展实验时，至少改变输入长度、动态范围、符号抵消程度和精度层次。对每组条件，保留理论和、绝对值和、实际误差与运行成本；若真和近零，单独使用绝对误差和背景尺度。对多次随机数据试验，应展示误差分布而不只展示最好一次；对最坏构造，则解释构造揭示了哪条边界。

进一步可以把大向量拆成不同块大小，比较顺序、树形与补偿归约；保持输入完全相同，避免把随机数据差异当成算法差异。将高精度参考仅用于小样本与代表性块，另用不变性和残差检查大规模路径。这里的关键是组合多种独立证据，每种证据都明确自己的覆盖范围。

最终交付一个数值实现时，应能回答：数学对象是什么，输入精度如何形成，算法在哪些范围有效，主要误差界是什么，参考如何独立构造，验收容差依据是什么。能够回答这些问题，才算把一个稳定技巧提升为可审查的计算方法；仅仅展示某次程序没有 NaN，还远远不够。
