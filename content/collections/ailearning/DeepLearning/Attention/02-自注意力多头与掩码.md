## 1. 注意力来源与信息流

<a id="attention-2-detail-2"></a>

### 1.1 自注意力并不等于只读取自己

设输入为一个包含若干位置的矩阵，每个位置对应一个词、图像块、事件或者集合元素。用三个共享线性映射分别生成查询、键和值，然后每个位置都从允许的全部位置读取内容，得到自注意力。名称中的“自”指查询与键值来自同一个输入集合，并不表示位置只关注自身。若每个位置只能读取自己，权重总是一，注意力退化成逐位置的值映射，位置之间没有信息交换。

自注意力的输出位置数与输入位置数相同，每个输出仍然对应一个原始查询位置，但其表示已经包含其他合法位置的信息。这种对应关系使它能接残差连接，也使逐位置监督成为可能。不能因为输出融合了上下文就忽略位置身份；在序列标注任务里，某个标签仍然要与正确的查询位置对齐。

设 $`X\in\mathbb R^{L\times d_{\rm model}}`$，投影为 $`Q=XW_Q`$、$`K=XW_K`$、$`V=XW_V`$。三个矩阵虽然源自同一个输入，参数却可以不同，因此某一位置用来提出需求的特征、供别人检索的特征和被别人读取的内容并不相同。输入梯度会汇集查询、键和值三条路径。训练排查中只看其中一条，可能误判共享输入对当前预测的真实作用。

<a id="attention-2-detail-3"></a>

### 1.2 交叉注意力把读取接口与记忆接口分开

交叉注意力令查询来自一个集合，键和值来自另一个集合。例如解码端当前状态提出查询，编码端表示构成可读取记忆。查询长度可以不同于记忆长度，查询特征维和记忆输入特征维也可以不同，只要投影后查询键的匹配维一致。输出长度由查询决定，而不是由记忆决定。

将两个集合简单拼接再做自注意力，有时能表达相似的信息交流，但它同时允许两侧互相更新，并改变掩码结构、计算成本和输入身份。交叉注意力提供一种更明确的单向接口：本次读取更新查询侧输出，记忆本身保持不变。若后续还有其他层更新记忆，那是额外的信息通路，不能由当前层的单向定义自动推出。

交叉注意力是否安全取决于记忆构建时使用了哪些数据。如果记忆编码器已经看过目标答案，后续把交叉掩码写得再严格也不能消除已有泄漏。研究信息边界时应沿整个计算图追踪依赖，而不是只看最后一个分数矩阵上有没有三角形。

<a id="sec-1-1"></a>

<a id="attention-2-detail-4"></a>

### 1.3 三类读取结构的统一记号

以下统一使用批大小 $`B`$、查询长度 $`L_q`$、键长度 $`L_k`$、头数 $`H`$、每头匹配维 $`d_h`$、每头值维 $`d_v`$。投影与拆头后，查询形状为 $`(B,H,L_q,d_h)`$，键为 $`(B,H,L_k,d_h)`$，值为 $`(B,H,L_k,d_v)`$。分数与权重形状均为 $`(B,H,L_q,L_k)`$，每头输出为 $`(B,H,L_q,d_v)`$。

双向自注意力允许每个有效位置读取所有有效位置，适合整体输入已经可用的编码任务。因果自注意力限制读取到当前及过去位置，适合按时间或生成顺序预测。交叉注意力让查询读取外部记忆，其合法性由任务决定，不天然要求三角形。三个名称分别描述来源或依赖约束，不能把交叉注意力自动等同于“允许看未来”，也不能把所有自注意力自动当作因果结构。

## 2. 多头不是把同一张权重图复制多次

<a id="attention-2-detail-6"></a>

### 2.1 每个头拥有独立的匹配与内容投影

第 $`h`$ 个头计算 $`Q_h=XW_{Q,h}`$、$`K_h=YW_{K,h}`$、$`V_h=YW_{V,h}`$，再得到 $`O_h=\operatorname{softmax}(\frac{Q_hK_h^T}{\sqrt{d_h}}+M_h)V_h`$。最后沿特征轴拼接各头，再乘输出矩阵 $`W_O`$。自注意力时 $`X=Y`$，交叉注意力时两者可以不同。每个头的 softmax 独立执行，因此能够为同一个查询形成不同的候选分布。

如果只是把一组查询键和值复制多份，各头权重相同，新增的头可能只是冗余重复。真正的表达自由度来自不同投影和独立归一化。即使各头初始化不同，也不保证训练后一定学出互补功能；头之间可能相似、退化或只在某些样本上分工。观察到不同颜色的权重图，并不足以证明它们拥有稳定的人类语义角色。

<a id="attention-2-detail-7"></a>

### 2.2 拼接和输出投影分别做什么

拼接保留每个头读取的独立通道，输出投影则把这些通道重新组合到模型需要的维度。如果没有输出投影，后续层仍可能执行类似组合，但接口与参数位置不同。把各头输出直接平均，会提前压缩差异；拼接后可训练线性组合能够对不同头和不同值坐标使用不同权重。

输出投影还说明裸注意力的凸组合性质不能直接套在整个多头层输出上。每头结果在该头值的凸包里，但拼接和一般线性投影可以改变符号、尺度与坐标关系，再接残差后更不受原始输入坐标极值约束。判断输出是否合理时，必须先说明观察的是哪一个中间张量，不能混用各层的数学边界。

<a id="sec-2-1"></a>

<a id="attention-2-detail-8"></a>

### 2.3 固定模型宽度下的参数与成本

常用设计令 $`Hd_h=d_{\rm model}`$ 且 $`Hd_v=d_{\rm model}`$。忽略偏置，查询、键、值与输出投影各有一个模型宽度平方量级的参数，因此改变头数但保持总宽度，投影参数总量大致不变。变化的是每个头的子空间宽度、权重分布数量和实现开销，不能简单说头数翻倍就让所有参数翻倍。

分数矩阵的元素数为 $`BHL_qL_k`$，所以即使固定总匹配宽度，多头仍可能增加显式保存权重的内存。主要矩阵乘法算术量对总宽度而言相近，但额外的 softmax、布局转换和内核调度可能改变实际延迟。只依据理论乘加次数，不能预测指定设备上的准确吞吐；本章只验证语义，不声称完成硬件性能基准。

<a id="deep-dive-2"></a>

<a id="attention-2-detail-9"></a>

### 2.4 单头与多头为何不能简单互换

单头可以用更宽的值向量承载丰富内容，但同一个查询对所有值通道共享同一组候选权重。多头则允许不同通道组使用不同权重。假设输出一部分要读取最近事件，另一部分要读取最早异常，多头能直接形成两组不同选择；单头若共享一组分布，就需要通过其他表示设计间接实现类似行为。

这并不构成任何有限头数模型都严格优于单头的普遍结论，因为完整网络的宽度、深度与非线性也会影响可表达函数。公平比较必须固定预算和训练协议，再报告任务性能、收敛和冗余程度。把头数当作只增不减的能力旋钮，忽略每头维度变窄和有限数据的影响，容易产生误导。

## 3. 掩码是一张合法依赖图

<a id="attention-2-detail-11"></a>

### 3.1 从允许集合定义权重

对每个查询位置 $`i`$，先规定合法候选集合 $`\mathcal A_i`$。若集合非空，则只在这些位置上归一化：合法位置的权重为 $`\frac{\exp(s_{ij})}{\sum_{\ell\in\mathcal A_i}\exp(s_{i\ell})}`$，其他位置严格为零。这个定义比“给分数加一个很小的数字”更根本，因为它直接说明了算子的数学支持。

常见实现对非法位置加负无穷，利用其指数为零实现相同效果。使用一个有限大负数只是近似，效果取决于分数尺度和数值精度。如果所有位置都加同一个有限负数，softmax 的平移不变性甚至会让权重保持原样，而不是形成空读取。完全屏蔽一行需要额外语义，不能靠把常数写得更大来回避。

<a id="attention-2-detail-12"></a>

### 3.2 因果掩码必须对应预测目标

对等长、从零开始的位置，包含自身的因果允许条件为 $`j\le i`$。这保证位置 $`i`$ 的注意力输出不依赖更晚的键值。若用该输出预测下一个符号，输入通常包含当前位置及其过去；如果用当前位置输出预测当前位置本身，而当前位置输入已经含目标符号，就可能出现标签复制捷径。三角掩码正确，并不自动意味着输入输出对齐正确。

严格过去条件 $`j<i`$ 与包含自身条件是不同设计，前者使第一个查询没有合法候选，需要特殊起始记号或显式空行策略。实际语言建模经常使用起始记号和右移后的目标，让每个预测都只依赖已经提供的前缀。应把“哪个位置预测哪个标签”写成索引等式，再决定掩码，而不是先画三角形然后猜测任务语义。

<a id="attention-2-detail-13"></a>

### 3.3 填充掩码处理的是候选身份

把不同长度序列组成同一批时，填充位置只是占位符，不应被真实查询当作内容读取。键填充掩码因此屏蔽填充键列。但填充查询行是否输出零、是否参与残差、是否进入损失，是另一个问题。仅屏蔽键列并不会自动让填充查询的输出为零，因为它仍可以读取有效键。

如果后续执行全位置平均而没有排除填充查询，这些无语义输出仍可能污染样本表示。若监督损失包含填充位置，也会改变有效样本权重。可靠实现需要分开记录键有效性、查询有效性与标签有效性；它们在一些任务里相同，在另一些任务里并不相同，不能因为形状相似就共用一张未经说明的掩码。

<a id="attention-2-detail-14"></a>

### 3.4 局部、分段与前缀结构

局部注意力可以规定 $`\vert i-j\vert \le w`$，因果局部注意力可以规定 $`0\le i-j\le w`$。分段注意力还可能要求查询与键属于同一个样本片段，以免打包后的独立文档互相读取。前缀结构可以允许已知前缀内部双向可见，而生成区域只看前缀及自己之前的生成位置。

这些规则都能表示为合法边的布尔关系，再通过逻辑与组合。先写清允许关系，能避免多个掩码相加时方向或广播出错。对打包训练尤其要检查文档边界：普通三角掩码虽然不看后面，却可能读取前一篇独立文档的内容。这未必符合任务定义，必须显式使用段身份限制依赖。

## 4. 接口中的布尔值不是通用语言

<a id="attention-2-detail-16"></a>

### 4.1 两个 PyTorch 接口的相反约定

本章使用的 PyTorch 版本中，函数式缩放点积注意力的布尔`attn_mask`以真值表示允许参加读取；而`MultiheadAttention`的布尔注意力掩码及键填充掩码以真值表示禁止读取或忽略。把同一个布尔张量直接传给两个接口，会把语义反转。接口迁移时必须根据文档重新解释，而不是依据变量名猜测。

一个稳妥做法是在自己的代码里统一使用`allowed`表示允许关系，只在调用参考接口的边界转换为其所需约定。这样，业务规则始终使用同一种语言，接口差异集中在一个小范围内。仍然需要用只允许一个候选的最小例子验证，因为注释本身也可能写错。若输出不等于唯一允许候选的值，就应立刻停止更复杂的训练。

<a id="attention-2-detail-17"></a>

### 4.2 浮点掩码与布尔掩码的不同

浮点掩码通常表示加到原始分数上的偏置，因此零表示不改变，负无穷表示禁止，其他有限值表示软偏好。这不仅是合法性，还能表达距离惩罚或可训练关系偏置。布尔掩码则只表达是否参加。将一个取零与一的浮点张量当作布尔掩码使用，会把“允许位置加一”的语义误当成“另一位置禁止”，两者完全不同。

当同时使用注意力掩码和键填充掩码时，还要核对接口对类型兼容与形状广播的要求。本章实验不依赖隐式合并策略，而是先构造最终允许关系，再在调用处明确转换。这样更容易审查每一条非法边是否真的被屏蔽，也能用相同数学关系对照手写与参考实现。

<a id="attention-2-detail-18"></a>

### 4.3 广播要逐轴写出

形状为 $`(L_q,L_k)`$ 的掩码通常可在批与头维共享，但如果不同样本具有不同有效长度，仅有二维掩码就不足以表达差异。形状为 $`(B,1,L_q,L_k)`$ 的允许关系可以在头维广播，适合每个样本独立而各头共享规则。若需要每个头不同规则，则使用完整的四维表示或接口规定的等价布局。

危险情况是某些尺寸恰好相同，例如批大小等于头数，使一个错误排列的张量仍能广播成功。测试时应故意选不同的批、头、查询和键长度，让错误布局尽早暴露。形状检查不仅要比较数字，还应标注数字代表的轴；“这个维度等于二”无法区分它是批、头还是位置。

## 5. 完全屏蔽行必须显式定义

<a id="attention-2-detail-20"></a>

### 5.1 为什么负无穷行会产生不确定运算

若所有分数都为负无穷，直接 softmax 的稳定化步骤需要减去行最大值，形成负无穷减负无穷，数学上未定义。不同实现可能采用不同特例处理，不能把某次运行得到零或无效值当作跨接口、跨版本保证。业务层面更应先问：这个查询没有任何可读内容，期望输出是什么？

常见策略包括拒绝非法输入、增加一个真实定义的空记忆候选，或者规定空行输出为零并在后续排除相应查询。它们是不同模型语义。增加空候选会改变归一化集合且引入可学习内容；输出零可能使残差保留原查询；拒绝输入则要求数据处理阶段保证非空。选择应与任务一致，并在测试中覆盖，而不是让数值库偶然决定。

<a id="attention-2-detail-21"></a>

### 5.2 一个确定性的零输出约定

下列手写函数明确规定空行权重与输出均为零。实现先用有限零分数替换空行，计算普通 softmax 后再把所有非法位置清零。对非空行，非法位置仍使用负无穷；对空行，安全替换避免未定义的减法。因为最后全部权重为零，值路径和分数路径的局部梯度也为零。

这个约定意味着空行权重和为零，而不是一。若后续代码无条件断言所有行和为一，就会把合法的空行策略误判为错误。正确的断言应按“有合法候选”和“无合法候选”分别检查。若任务不允许空行，则更简单可靠的策略是进入注意力前直接抛错；教学函数支持零策略，是为了让边界行为可见且可验证。

```python
import torch

torch.set_num_threads(1)
torch.manual_seed(201)
dtype = torch.float64

def safe_attention(q, k, v, allowed):
    scores = q @ k.transpose(-2, -1) / (q.shape[-1] ** .5)
    allowed = torch.broadcast_to(allowed, scores.shape)
    assert allowed.dtype == torch.bool
    has_any = allowed.any(dim=-1, keepdim=True)
    masked = scores.masked_fill(~allowed, -torch.inf)
    safe = torch.where(has_any, masked, torch.zeros_like(masked))
    weights = torch.softmax(safe, dim=-1).masked_fill(~allowed, 0.)
    return weights @ v, weights

q = torch.randn(2, 3, dtype=dtype, requires_grad=True)
k = torch.randn(4, 3, dtype=dtype, requires_grad=True)
v = torch.randn(4, 2, dtype=dtype, requires_grad=True)
allowed = torch.tensor([[False, True, False, False],
                        [False, False, False, False]])
o, a = safe_attention(q, k, v, allowed)
assert torch.allclose(o[0], v[1])
assert torch.equal(o[1], torch.zeros_like(o[1]))
assert torch.equal(a.sum(-1), torch.tensor([1., 0.], dtype=dtype))
grads = torch.autograd.grad(o[1].sum(), (q, k, v))
assert all(torch.isfinite(g).all() and torch.equal(g, torch.zeros_like(g)) for g in grads)
print('single allowed candidate, empty row, zero gradients: passed')
```

<a id="attention-2-detail-22"></a>

### 5.3 零注意力输出不等于整个网络零输出

如果注意力模块后面带有输出偏置，即使各头读取结果为零，投影后仍可能等于那个偏置。接残差时还会加上原查询，再接归一化和前馈层，输出一般非零。因此“空行输出零”的契约必须指定模块边界：它可以指裸加权和，也可以指整个注意力子层，但二者需要不同处理。

对于填充查询，常见做法是在需要的位置再次按查询有效性清零，或者从聚合与损失中排除。何处清零会影响残差和归一化路径，应该在模型设计里明确。如果只是为了让打印结果看起来干净而随意清零，可能无意中切断有意义的梯度；如果完全不处理，又可能让填充信息参与样本级统计。


<a id="visual-example-attention-02"></a>

### 图解：完全屏蔽行为什么没有普通概率解

![完全屏蔽行为什么没有普通概率解](images/02-example.svg)

**读图与计算。** 正常行仅有一个合法键，该键权重为一；空行却没有任何合法候选。把全部分数写成负无穷后执行普通稳定 softmax，会遇到负无穷减负无穷的问题。表中合法数为零的行需要先识别，再根据任务决定报错、跳过查询或返回约定的零输出。

**适用条件。** 零输出是接口约定而不是一个和为一的候选概率分布；还应阻止后续层误把无效查询当成有效监督位置。

## 6. 因果性必须在整个计算图上成立

<a id="attention-2-detail-24"></a>

### 6.1 一层不看未来为什么还不够

假设第一层已经用双向注意力把未来内容混入当前位置表示，第二层即使用严格因果掩码，也只是限制第二层读取哪些中间位置，无法删除那些位置已经携带的未来信息。因此，一个模型的因果性需要从原始输入到目标输出的所有路径都满足时间约束。检查最后一层的权重图，只能说明局部边存在与否，不能证明整个系统没有泄漏。

同样，跨时间求均值、用全序列统计做归一化、把未来标签参与特征构建，都可以绕开注意力掩码形成泄漏。如果数据预处理用完整序列的均值标准化每个时间点，过去表示已经依赖未来。若模型宣称在线使用，就应按照上线时可获得的信息重新计算统计，并在每一条处理路径上检查可用时刻。

这里的时间还包括事件发生时间与记录可用时间。一个检测结果可能来自过去的样本，却在当前预测以后才发布；它不能因事件时间较早就被当作当前可用记忆。交叉注意力记忆库尤其需要记录可用性，而不是只按内容中的时间字段排序。合法候选应由任务信息集决定，不是由文档看起来“属于过去”决定。

<a id="attention-2-detail-25"></a>

### 6.2 教师强制、输入右移和标签对齐

训练自回归模型时，可以把整段已知目标放进一个批张量并用因果掩码并行计算，但每个位置的输入与所预测标签必须错开。设原序列为 $`x_0,x_1,\ldots`$，在位置 $`i`$ 提供到 $`x_i`$ 为止的前缀，预测 $`x_{i+1}`$。如果错误地在位置 $`i`$ 预测已经作为输入提供的 $`x_i`$，即使注意力完全因果，也可能只学到复制当前符号。

教师强制意味着训练时使用真实前缀，而生成时使用模型先前产生的符号，这会带来分布差异，但它不是未来泄漏的同义词。两者需要分开讨论：一个是训练与推理的条件分布不同，一个是预测时使用了不合法信息。把任何训练推理差异都称为泄漏，会模糊真正的信息边界问题。

<a id="attention-2-detail-26"></a>

### 6.3 证明多层因果结构的归纳方法

若第零层位置 $`i`$ 只依赖原始位置不晚于 $`i`$ 的内容，每一层的注意力只读取不晚于当前查询的位置，且其余子层都逐位置独立，那么可以用层数归纳证明整个网络因果。归纳步中，位置 $`i`$ 只读取 $`j\le i`$ 的上一层表示，而这些表示又只依赖原始位置 $`k\le j\le i`$，所以无法到达未来输入。

证明必须检查残差、归一化和额外分支是否满足前提。沿特征维逐位置的层归一化通常不引入其他位置的信息，而沿时间维计算统计的操作可能引入。全局池化后再回写到每个位置，也会形成跨位置路径。一个简洁的归纳证明比只对随机样本做未来扰动更强，但扰动测试仍能帮助发现实现没有遵守证明中的假设。

<a id="attention-2-detail-27"></a>

### 6.4 缓存读取的绝对位置偏移

增量生成时，当前查询可能只有一个位置，而键值包含很长的已缓存前缀。此时查询局部下标零并不代表绝对时间零。若直接按局部条件 $`j\le0`$ 构造一个一乘长序列的下三角掩码，就只允许读取第一个键，错误屏蔽了绝大多数合法历史。应使用绝对查询位置与键位置比较，或直接规定当前查询可读取全部有效前缀。

如果一次处理多个新查询，查询绝对位置通常从缓存长度开始递增，需要与缓存和新键的共同位置轴对齐。不同接口对非方形因果偏置可能采用特定对齐规则，因此最稳妥的教学对照是显式构造允许关系，避免把接口默认值当作业务语义。第三章会进一步检查具体张量变换，第四章讨论缓存成本与位置表示的一致性。


<a id="visual-mechanism-attention-02"></a>

### 图解：未来信息也可能绕过正确的因果掩码

**图中的机制。** 未来 token 即使在注意力矩阵中被遮住，仍可能经跨时间预处理统计影响早期表示。图用一条被屏蔽的直接边和另一条经全序列统计的绕行路径区分局部掩码正确与整个计算图因果。检查因果性时应从早期输出反向追踪所有输入依赖。

## 7. 接口对照与信息隔离实验

<a id="attention-2-detail-29"></a>

### 7.1 实验二：同一规则在两个接口中的转换

下面把单头多头模块的四个投影都设成单位映射，使它与裸缩放点积读取直接可比。允许关系在每一行都至少保留一个键，避免把接口空行行为与布尔语义测试混在一起。函数式接口直接接收允许矩阵，模块接口接收其逻辑取反；两者都关闭随机丢弃并使用双精度。

```python
import torch
import torch.nn.functional as F
from torch import nn

torch.set_num_threads(1)
torch.manual_seed(202)
dtype = torch.float64
x = torch.randn(1, 3, 2, dtype=dtype)
allowed = torch.tensor([[True, False, False],
                        [True, True, False],
                        [False, True, True]])
m = nn.MultiheadAttention(2, 1, dropout=0., bias=False, batch_first=True).to(dtype)
with torch.no_grad():
    m.in_proj_weight.copy_(torch.eye(2, dtype=dtype).repeat(3, 1))
    m.out_proj.weight.copy_(torch.eye(2, dtype=dtype))
m.eval()
module_output, weights = m(x, x, x, attn_mask=~allowed, need_weights=True,
                           average_attn_weights=False)
functional_output = F.scaled_dot_product_attention(
    x[:, None], x[:, None], x[:, None], attn_mask=allowed, dropout_p=0.)[:, 0]
assert torch.allclose(module_output, functional_output, atol=1e-12, rtol=1e-12)
assert torch.equal(weights.masked_select(~allowed[None, None]),
                   torch.zeros_like(weights.masked_select(~allowed[None, None])))
assert torch.allclose(module_output[0, 0], x[0, 0])
print('opposite boolean conventions and identity projections: passed')
```

这个实验并没有证明所有接口参数组合都等价。它只覆盖无偏置、一个头、无随机丢弃、显式布尔掩码与固定投影的情形。扩展到多个头时，需要继续核对拆头排列和输出拼接；扩展到不同输入维度时，需要核对模块如何组织独立投影。把对照条件写清楚，可以防止一个小测试被夸大成整个实现的完整认证。

<a id="attention-2-detail-30"></a>

### 7.2 实验三：扰动未来与填充内容

下列实验直接构造多头形状张量。首先对后半段键值做大幅扰动，检查前半段因果输出严格保持数值一致；再模拟一个样本末尾两条记录为填充，修改填充内容，检查所有查询对有效记忆的读取保持不变。这两个测试分别对应时间边界和候选有效性，不把它们混为同一个条件。

```python
import torch
import torch.nn.functional as F

torch.set_num_threads(1)
torch.manual_seed(203)
dtype = torch.float64
q = torch.randn(2, 3, 5, 4, dtype=dtype)
k = torch.randn(2, 3, 5, 4, dtype=dtype)
v = torch.randn(2, 3, 5, 2, dtype=dtype)
pos = torch.arange(5)
causal = pos[None, :] <= pos[:, None]
base = F.scaled_dot_product_attention(q, k, v, attn_mask=causal, dropout_p=0.)
k2, v2 = k.clone(), v.clone()
k2[:, :, 3:] += 100.
v2[:, :, 3:] -= 200.
changed = F.scaled_dot_product_attention(q, k2, v2, attn_mask=causal, dropout_p=0.)
assert torch.allclose(base[:, :, :3], changed[:, :, :3], atol=1e-12, rtol=1e-12)
valid_keys = torch.tensor([[True, True, True, False, False],
                           [True, True, True, True, True]])
allowed = valid_keys[:, None, None, :].expand(2, 1, 5, 5)
pad_base = F.scaled_dot_product_attention(q, k, v, attn_mask=allowed, dropout_p=0.)
k3, v3 = k.clone(), v.clone()
k3[0, :, 3:] = 1e4
v3[0, :, 3:] = -1e4
pad_changed = F.scaled_dot_product_attention(q, k3, v3, attn_mask=allowed, dropout_p=0.)
assert torch.allclose(pad_base, pad_changed, atol=1e-12, rtol=1e-12)
query_valid = valid_keys[:, None, :, None]
clean = pad_base.masked_fill(~query_valid, 0.)
assert torch.equal(clean[0, :, 3:], torch.zeros_like(clean[0, :, 3:]))
print('future intervention, padded keys, explicit query cleanup: passed')
```

未来扰动不改变过去输出是因果结构的必要检查，但有限样本通过仍不等于完整证明。例如某条未来通路可能因当前参数恰好为零而没有产生影响，训练后又变为非零。因此应把计算图证明与扰动测试一起使用。对于真实模型，还要在词嵌入、位置处理、缓存更新和最终读出之间执行相同审查。

<a id="attention-2-detail-31"></a>

### 7.3 实验四：合法支持上的梯度隔离

如果某个键和值对一个查询完全不可见，该查询的标量损失对那条键值路径的梯度应为零。下面只用第一个查询输出构造损失，让第三个候选非法，检查它的键梯度和值梯度。随后故意去掉掩码，确认测试输入足以让这些梯度通常变为非零。后一步是故障对照，避免使用退化输入让错误实现也通过。

```python
import torch

torch.set_num_threads(1)
torch.manual_seed(204)
dtype = torch.float64
q = torch.randn(1, 3, dtype=dtype, requires_grad=True)
k = torch.randn(3, 3, dtype=dtype, requires_grad=True)
v = torch.randn(3, 2, dtype=dtype, requires_grad=True)
allowed = torch.tensor([[True, True, False]])
s = q @ k.T / (3 ** .5)
a = torch.softmax(s.masked_fill(~allowed, -torch.inf), -1)
loss = ((a @ v) * torch.tensor([[1., -2.]], dtype=dtype)).sum()
gk, gv = torch.autograd.grad(loss, (k, v))
assert torch.equal(gk[2], torch.zeros_like(gk[2]))
assert torch.equal(gv[2], torch.zeros_like(gv[2]))
unmasked_loss = ((torch.softmax(q @ k.T / (3 ** .5), -1) @ v)
                 * torch.tensor([[1., -2.]], dtype=dtype)).sum()
ubk, ubv = torch.autograd.grad(unmasked_loss, (k, v))
assert ubk[2].norm() > 1e-8 and ubv[2].norm() > 1e-8
print('forbidden key/value gradients and fault control: passed')
```

梯度为零的结论依赖观察的是这一次读取路径。若同一个输入还通过其他查询、残差、共享编码器或辅助损失参与目标，它的总梯度仍可能非零。因此，应先选择局部损失并隔离路径，再逐步接回完整模型。把完整训练中某个参数的非零梯度当作掩码失效证据，可能混淆合法的其他通路。

## 8. 多头学习、冗余与可解释研究

<a id="attention-2-detail-33"></a>

### 8.1 头置换是一种参数对称性

如果同时重排所有头的查询键值投影，并按相同方式重排输出投影对应的输入块，整个多头层函数保持不变。这说明“第一头”“第二头”的编号本身没有固定语义，不同训练种子里的同编号头也不一定可比较。比较头行为时，应根据功能或表示相似性匹配，而不是默认编号能够跨模型对齐。

头之间也可能存在冗余。如果两个头在研究样本上产生相同输出，输出投影可以通过不同权重组合得到同一最终结果。移除一个头后是否保持性能，取决于是否重新训练、如何调整输出尺度以及该头在未观测样本上的作用。一次剪枝结果不能反过来证明这个头在原模型训练过程中从未发挥作用。

<a id="sec-6-1"></a>

<a id="attention-2-detail-34"></a>

### 8.2 头级消融需要区分三个问题

第一种实验在固定模型中把某个头输出置零，测量当前函数对这个通路的依赖；第二种删除头以后重新训练，测量其他头能否替代它；第三种从更少头数开始训练，比较不同架构的可学习能力。三者分别对应局部依赖、可补偿性和设计选择，结果可能明显不同。

公平消融还需控制参数预算。保持模型宽度但减少头数会增加每头维度，保留原每头维度则会缩小总通道数；二者都不是纯粹删除一组分布的同一种操作。报告时应写清改变了哪些矩阵形状、输出投影和训练预算。若只给出“少两个头性能不变”，读者无法判断这个结论针对什么设计。

<a id="attention-2-detail-35"></a>

### 8.3 随机丢弃与权重图的解释

训练中对归一化后的注意力权重执行随机丢弃并按保留概率重标定，单次权重和通常不再严格为一，输出也不再是普通确定性凸组合。其期望可能保留某些性质，但单个随机样本不能直接套用第一章无随机丢弃时的全部结论。可视化时要说明处于训练模式还是评估模式，是否展示了丢弃前或丢弃后的系数。

函数式接口的随机丢弃参数需要由调用者显式控制；仅把外层模块切到评估模式，未必自动改变一个硬编码的函数参数。因此示例都明确传入零。编写自定义层时，可以根据模块训练状态选择概率，并验证评估重复调用给出相同结果。若解释图每次变化，先检查随机性来源，再讨论模型是否拥有不稳定的内部机制。

<a id="attention-2-detail-36"></a>

### 8.4 不把稀疏图案直接当作结构知识

某些头经常关注前一个位置，可能与位置偏置有关；某些头常读起始记号，可能把它当作全局汇总通路。但要声称它学会特定语法、物理关系或因果结构，还需要针对性对照。可构造保持词频但改变关系的样本，改变位置而保持语义，或对头输出进行可解释范围内的干预，观察最终任务行为。

观察性相关与机制性证据并不冲突，只是力度不同。一张权重图可以提出研究假设，消融和反例可以筛选假设，受控任务可以验证某个局部机制。把这几个阶段区分开，会比给每个头取一个生动名字更有助于理解模型，也更容易发现多种解释都能适配同一组观测的情况。

<a id="attention-2-detail-37"></a>

## 9. 从任务定义到掩码契约

<a id="attention-2-detail-38"></a>

### 9.1 先画信息可用表，再写张量

设计新任务时，应先列出每种输入的身份、来源、可用时刻与允许服务的预测目标。在线预测中，某条记录可用于哪些查询由时间和权限共同决定；图结构任务中，合法边可能由邻接关系决定；多模态任务中，某种模态可能只在训练时出现而在推理时缺失。掩码需要忠实表达这些约束，不能只套用语言模型里最熟悉的下三角图案。

把允许关系写成一个返回布尔值的数学谓词，例如“同一文档且键可用时间不晚于查询预测时间”。然后分别构造时间条件、身份条件和有效性条件，最后取逻辑与。这个过程允许每个条件独立测试，也便于定位某条非法边为什么被允许。若直接拼接多个负数矩阵，不同条件的含义可能被隐藏在广播和数值常量里。

对于无合法候选的查询，还要明确它是数据错误还是正常状态。若是错误，进入模型前拒绝；若是正常，规定空行输出、标签是否有效以及后续聚合如何处理。把异常情况留给底层算子处理，往往使同一业务逻辑在不同实现中表现不一致，最终难以解释训练与部署差异。

<a id="attention-2-detail-39"></a>

### 9.2 区分样本独立性与样本内部信息流

在批维堆叠样本通常不意味着它们可以互相读取。标准批处理让每个样本独立计算，只有共享参数；如果错误地把批和序列轴合并，不同样本可能进入同一个候选集合。这种错误尤其危险，因为训练损失可能下降得更快，看起来像模型能力提升，实际上使用了其他样本的信息。

有些研究确实允许跨样本记忆，例如外部检索库或上下文学习，但这需要明确实验协议：测试样本能否检索训练样本，能否检索其他测试样本，检索库是否包含标签。合法的跨样本机制与意外的批混合是不同事情。把二者都叫作“利用更多上下文”，会掩盖评估条件的改变。

<a id="attention-2-detail-40"></a>

### 9.3 训练与推理应共享同一合法性定义

训练阶段若提供完整目标序列，掩码负责限制每个位置的可见前缀；推理阶段若使用缓存，输入布局不同，但合法关系应在绝对位置意义上相同。可以用短人工序列对照一次性因果计算与逐步前缀计算，验证相同位置的结果一致。若不一致，应检查位置编码偏移、缓存内容、随机丢弃、掩码对齐和归一化状态。

注意，包含相同合法信息不保证所有网络实现都自然给出相同结果。例如训练模式中的随机丢弃或依赖批统计的操作会引入额外差异。对照应关闭这些随机因素，使用相同参数和数值精度，再逐项增加复杂度。这样能够区分信息集合不一致与执行环境不一致，避免把所有差异都归咎于缓存。

<a id="attention-2-detail-41"></a>

### 9.4 评价掩码修改时要有针对性基线

若提出一种稀疏掩码，可以比较完整注意力、相同边数的随机掩码、具有任务先验的局部掩码与新方法。控制边数有助于区分收益来自结构选择还是来自单纯减少计算；保持参数与训练预算则有助于公平比较。还应报告关键依赖是否能通过多层路径传播，而不只统计一层的边数。

例如局部窗口无法在一层内连接远处位置，多层堆叠后可扩大可达范围，但传播长度和中间表示压缩会影响实际效果。存在一条图路径不等于模型一定能可靠传递所有信息，更不等于与完整注意力函数等价。研究报告应把图可达性、理论表达能力与实际训练性能分开。

## 10. 进阶习题与完整解析

<a id="attention-2-detail-43"></a>

### 10.1 自注意力和交叉注意力怎样从形状辨认

**题目。** 查询输入长度为六、记忆长度为九，两侧输入维度分别为八和十。投影后使用两个头，每头匹配维四、值维三。写出各中间形状，并判断输出应有几个位置。

**解析。** 忽略批维时，各头查询为二乘六乘四，键为二乘九乘四，值为二乘九乘三。分数为二乘六乘九，沿最后一维归一化，各头输出为二乘六乘三，拼接为六乘六。输出投影可以再把六个通道映射到指定模型宽度。输出位置数始终是六，因为每个查询产生一个读取结果。仅根据两侧长度不等可判断它不是通常的同一输入自注意力，但长度相等也不能证明一定是自注意力，仍要检查数据来源。

<a id="attention-2-detail-44"></a>

### 10.2 固定宽度后增加头数的代价

**题目。** 模型宽度为六十四，头数从四增加到八，并保持总匹配和值宽度不变。忽略偏置，投影参数是否翻倍？显式权重张量大小怎样变化？

**解析。** 每头宽度从十六降到八，查询键值和输出矩阵仍然各为六十四乘六十四，投影参数总数不因这个变化翻倍。若批大小和序列长度固定，权重张量包含批乘头数乘查询数乘键数个元素，因此头数翻倍会让显式权重元素数翻倍。主要点积总乘加量可能近似不变，实际延迟仍受小矩阵效率、softmax 数量和实现选择影响。不能只凭参数数目相同就断言内存和速度完全相同。

<a id="attention-2-detail-45"></a>

### 10.3 因果掩码能否阻止当前标签复制

**题目。** 输入位置 $`i`$ 已经放入符号 $`x_i`$，模型用当前位置输出预测同一个 $`x_i`$，并使用允许 $`j\le i`$ 的掩码。这是否构成可靠的自回归训练？

**解析。** 不构成通常的下一符号预测，因为目标已经直接进入当前输入。模型可以通过当前位置值路径或残差复制标签，而不需要学习前缀规律。掩码只限制未来位置，不会删除当前位置的已知答案。应右移输入或目标，使位置 $`i`$ 用可用前缀预测尚未提供的符号。也可以采用严格过去结构，但需要处理第一个位置的空支持和起始条件。评价训练协议时必须同时检查掩码与标签索引。

<a id="attention-2-detail-46"></a>

### 10.4 为什么填充键掩码不负责清空填充查询

**题目。** 某样本只有前三个位置有效，批张量长度为五。只屏蔽最后两个键列，最后两个查询输出是否必然为零？

**解析。** 不必然。填充查询仍有自己的查询向量，可以对前三个有效键形成分布并读取其值，所以输出通常非零。如果后面有偏置和残差，非零情况更常见。应单独保存查询有效性，在需要的模块边界清零，或者在聚合与损失中排除相应位置。若使用全位置均值，分母也应是有效位置数，而不是固定批长度，否则较短样本会被不同程度缩小。候选有效性和监督有效性需要分别定义。

<a id="attention-2-detail-47"></a>

### 10.5 两个接口复用同一个布尔掩码有什么后果

**题目。** 允许矩阵在每行只有一个真值。直接把它同时传给函数式缩放点积接口与多头模块布尔注意力接口，为什么输出会不同？

**解析。** 本章对应版本中，函数式接口把真值解释为允许参与，多头模块把真值解释为禁止读取。因此前者只读取那个候选，后者恰好排除它而读取其他候选。正确方法是在自己的代码中统一使用允许语义，到模块接口处取逻辑反。应使用不同值且每行至少有一个合法候选的最小例子验证，而不是依赖复杂训练结果猜测。接口约定是具体版本的契约，升级或迁移框架时需重新核对。

<a id="attention-2-detail-48"></a>

### 10.6 全部加同一个大负数是否能屏蔽一行

**题目。** 为了避免负无穷，有人给空行所有分数减去一百万，认为这样权重会全部变零。为什么错误？

**解析。** softmax 对行内共同平移不变，减去一百万只改变共同偏移，不改变相对分数和归一化结果。稳定实现还会再减去最大值，直接抵消这个共同量。如果用不稳定指数实现，可能出现全下溢导致零除零，也不是正确零权重。空支持需要独立策略，例如拒绝、加入有定义的空候选，或者显式返回零行。不能让一个数值近似常数代替数学上未定义的归一化。

<a id="attention-2-detail-49"></a>

### 10.7 空行零输出应不应该满足权重和为一

**题目。** 采用本章空行零策略后，有测试断言每一行权重和必须为一。这个测试应怎样修改？

**解析。** 对至少有一个合法候选的行，权重和应为一，非法位置为零；对没有合法候选的行，权重应全零，行和也为零。应先根据允许矩阵计算有效行标记，再分别检查。若希望所有行都和为一，就必须通过增加空候选等方式改变模型定义，而不是仅修改断言。测试应忠实表达契约，不能为了让某条通用规则成立而忽视任务正常存在的边界状态。

<a id="attention-2-detail-50"></a>

### 10.8 为什么最后一层因果不能修复上一层泄漏

**题目。** 第一层双向读取，第二层使用因果掩码。第二层位置零是否一定不依赖原输入的最后一个位置？

**解析。** 不一定。第一层位置零可能已经读取最后位置，第二层即使只读取位置零，也会获得混入的未来信息。可以构造第一层统一平均所有值，使每个位置都含末尾内容，这个反例不依赖复杂训练。要证明整个模型因果，必须保证每层和每条旁路都遵循依赖边界，再用归纳证明。只观察最后一张三角权重图，遗漏了中间表示的来源。

<a id="attention-2-detail-51"></a>

### 10.9 缓存场景中的非方形三角形

**题目。** 已缓存八个历史键，当前只有一个新查询，绝对位置为八。若按查询局部下标零构造 $`j\le i`$，会发生什么？

**解析。** 它只允许键下标零，错误地屏蔽了其余合法历史。正确关系应比较绝对位置，当前查询可以读取所有可用历史，以及按照任务定义允许的当前键。若键包含零到八位置，允许条件为键位置不超过八。非方形布局不能仅凭形状推断因果对齐；接口可能有特定偏置规则，因此应显式验证。缓存测试应与完整前缀计算在相同绝对位置对照。

<a id="attention-2-detail-52"></a>

### 10.10 打包多个文档时普通因果掩码缺少什么

**题目。** 把两篇独立文档首尾连接成一个长序列，只使用下三角掩码。第二篇文档是否会读取第一篇内容？如何修改？

**解析。** 普通下三角允许读取所有更早位置，所以第二篇可以读取第一篇。如果任务要求文档独立，应额外要求查询键属于同一文档段，最终允许条件是时间因果与段身份相同的逻辑与。位置重置并不能自动屏蔽跨段边；相同位置编号也不意味着相同身份。训练前可以给两篇文档使用截然不同的人工值，扰动第一篇，检查第二篇输出是否保持不变。

<a id="attention-2-detail-53"></a>

### 10.11 键被屏蔽为什么它的总梯度仍可能非零

**题目。** 对某个查询不可见的输入位置，在完整模型训练中仍有非零梯度，这能否直接证明掩码失效？

**解析。** 不能。该位置可能被其他查询合法读取，也可能通过残差、值编码器共享参数或辅助目标参与损失。掩码只阻断指定注意力边，不保证整个输入与全部目标独立。应构造只依赖单个查询输出的局部损失，并隔离其他路径，再检查被禁止键值的梯度。局部测试通过后再接回完整图，可以定位非零梯度来自合法通路还是掩码错误。

<a id="attention-2-detail-54"></a>

### 10.12 多头平均为何一般弱于保留拼接信息

**题目。** 两个头分别读取温度变化和振动变化，直接平均它们的输出，与先拼接再投影是否等价？

**解析。** 一般不等价。平均提前把两个头的同坐标混在一起，丢失了来源身份，后续无法对两个来源独立加权。拼接保留两组通道，输出投影可以学习平均，也可以学习差分、选择或其他线性组合。因此平均可以视为某种受约束的组合，但不是完整拼接投影的全部表达范围。若两个头本身有特殊冗余或后续结构不同，实际性能仍需实验，不能只由局部表达自由度预测。

<a id="attention-2-detail-55"></a>

### 10.13 头编号为什么不具有跨模型语义

**题目。** 两个不同训练种子的模型中，第三个头权重图不同，能否说明其中一个没有学会原来的关系？

**解析。** 不能直接这样判断。头的参数具有置换对称性，功能可能移动到另一个编号，多个头也可能分摊相同作用。应先依据功能、表示或干预结果进行匹配，再比较相应机制。即使找不到一一对应，也可能是分布式实现不同而任务行为相近。头编号只是参数组织索引，不是由训练目标规定的人类概念标签。研究应报告匹配方法及不确定性。

<a id="attention-2-detail-56"></a>

### 10.14 随机丢弃后的权重为什么不一定和为一

**题目。** softmax 权重为二分之一、二分之一，训练时随机丢弃其中一个并按保留率二分之一重标定。单次结果可能是什么？

**解析。** 每个保留项会变成一，被丢弃项变成零，所以可能得到零零、一零、零一或一一，行和分别可能为零、一或二。期望权重仍是原值，但单次样本不再是概率分布。若两项都保留，输出是两个值之和，可能超出原凸包。解释训练时的注意力张量必须说明丢弃发生在何处；评估时应关闭随机丢弃，再应用无随机性的归一化与凸包结论。

<a id="attention-2-detail-57"></a>

### 10.15 局部窗口多层可达是否等于完整注意力

**题目。** 若堆叠足够多层局部注意力后任意两个位置之间存在路径，是否就与一层完整注意力等价？

**解析。** 不等价。图路径只说明信息可能经过中间位置传播，实际内容会经历多次压缩、非线性与权重选择。完整注意力在一层内直接按当前查询匹配远处候选，局部传播需要不同的中间机制和深度。即使最终能表达某些相同函数，参数量、训练难度和误差传播也可能不同。研究应分开讨论可达性、表达能力与实际性能，不把其中一个结论自动替代另外两个。

<a id="attention-2-detail-58"></a>

### 10.16 未来扰动测试为何需要故障对照

**题目。** 改变未来输入没有影响过去输出，能否说明测试一定有效？怎样提高可信度？

**解析。** 不能，模型可能忽略全部输入，或者测试张量存在特殊对称性，让错误掩码也看不出变化。应加入故障对照，例如移除掩码后使用相同扰动，确认过去输出确实发生变化；再选择非对称值和非零投影，排除退化情形。最终仍应检查计算图并证明依赖约束。测试通过是执行证据，故障对照说明它有发现特定错误的能力，两者结合才更有说服力。

<a id="attention-2-detail-59"></a>

## 11. 更深入的结构与优化分析

<a id="attention-2-detail-60"></a>

### 11.1 掩码图上的置换等变条件

第一章无位置注意力的置换等变性，在有掩码时需要同时变换依赖图。设位置置换矩阵为 $`P`$，输入重排后，分数变为 $`PSP^T`$；若允许关系也变为 $`PAP^T`$，其中这里的 $`A`$ 表示布尔邻接而非权重，则合法候选与输入身份仍然一致，输出同步重排。若只重排内容，却固定原来的因果三角形，改变的是时间位置与内容的关系，通常不应期待输出只是简单重排。

这个区分解释了为什么图注意力可以对节点编号等变，而因果序列对任意词序重排不等价。图任务重命名节点时也重命名边，依赖结构本身没有变化；序列任务打乱词序却保留时间方向，实际上改变了任务输入。讨论位置敏感性时，应明确哪些变换只是重新编号，哪些变换改变了真实关系。数学对称性的前提不能凭视觉相似省略。

<a id="attention-2-detail-61"></a>

### 11.2 合法支持上的雅可比与空行边界

对非空合法集合，softmax 雅可比仍为合法支持上的 $`\operatorname{diag}(a)-aa^T`$，扩展到全部候选后，非法位置对应的行列都为零。因此分数变化只有在合法候选之间重新分配质量，非法候选既不获得权重，也不从合法候选那里夺取质量。若只用有限负偏置近似屏蔽，非法权重理论上仍可能为正，这个精确零梯度结论就不再严格成立。

空行零约定不是普通概率单纯形上的 softmax，而是一个分段定义的算子。允许关系在前向中作为固定离散结构时，空行对有限输入的导数可以明确规定为零；如果想学习掩码本身，离散允许关系如何变化又是另一个优化问题，需要连续松弛、采样估计或其他方法。不能因为查询键值可微，就认为硬布尔边的选择也自动拥有普通梯度。

<a id="attention-2-detail-62"></a>

### 11.3 内容筛选与权限筛选不能混合解释

有些系统先根据查询筛选候选，再在小集合上注意力读取。若筛选只依据内容相关性，可能漏掉有用信息，影响准确率；若筛选还承担访问权限或时间边界，则错误允许会改变合法信息集合，性质更根本。应把不可违反的合法性条件与可优化的相关性排序分开，先确定哪些内容有资格参与，再在其中比较匹配分数。

这也有助于理解检索召回与注意力读取的分工。注意力不能读取没有进入候选集合的内容，增加头数也不能补回被硬筛选删除的证据；反过来，候选召回完整并不保证读取正确，因为表示、缩放和训练都可能失败。端到端评估之外，应分别报告候选覆盖率与条件于候选已包含答案时的读取性能，避免把两个阶段的错误混成一个指标。

<a id="attention-2-detail-63"></a>

### 11.4 多头对称性对优化的启示

如果所有头采用完全相同的初始化，并且结构、输入与随机因素也完全相同，它们可能在对称条件下得到相同梯度，从而一直保持相同功能。不同初始化通常帮助打破这种对称，但并不保证最终头功能互补。优化目标只要求完成任务，不要求每个头都学到独特的人类概念。为了鼓励互补而增加正则项，也可能牺牲任务目标，需要通过独立验证检查取舍。

头多样性可以在权重分布、输出表示或最终功能层面定义，这些指标并不等价。两头权重不同但读取了相似值，输出仍可能高度相关；两头权重相似但值投影不同，输出可能互补。设计多样性指标时，应先说明希望避免的冗余发生在哪个层面，再选择测量对象。只让权重图看起来不同，不能保证完整模型获得更多有效信息。

<a id="sec-7-1"></a>

<a id="attention-2-detail-64"></a>

### 11.5 把学习成果组织成可审阅契约

完成本章后，可以用一页说明记录模型的查询来源、记忆来源、绝对位置定义、候选合法谓词、空行策略、布尔接口转换与标签有效性。再把四类最小实验附在相应契约旁：唯一允许候选验证语义，空行验证边界，接口对照验证转换，未来及填充扰动验证信息隔离。这样的材料能够让后来修改模型的人快速理解哪些性质必须保留。

继续到手写多头实现时，最重要的任务不是增加代码长度，而是让每次重排和投影都能与这些语义对应。若某个中间张量无法说清批、头、查询、候选和特征轴的含义，就应该在扩大模型前解决。结构证明给出应该成立的性质，人工实验给出当前实现遵守这些性质的证据，两者相互补充，才能使更复杂的研究建立在可靠基础上。

<a id="attention-2-detail-65"></a>

另一个实用检查是把同一批样本按不同顺序重新组成批，关闭随机因素后比较每个样本的对应输出。如果标准逐样本注意力结果随同批其他样本内容改变，就应检查是否意外合并了批轴、使用了跨样本统计或引入共享记忆。若模型本来就允许跨样本读取，则要明确这种依赖属于任务协议，并在评估时使用相同条件。这个检查把输入身份与时间边界联系起来，能发现单条序列内部掩码测试覆盖不到的错误。
