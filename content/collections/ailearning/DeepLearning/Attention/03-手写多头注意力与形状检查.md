## 1. 先规定要实现的函数

<a id="attention-3-detail-2"></a>

### 1.1 实现目标与有意保留的限制

本章实现一个批优先的多头注意力层，查询、键和值输入可以具有不同长度，但使用相同输入特征宽度。头数必须整除模型宽度，每头的查询键维和值维都等于总宽度除以头数。层包含查询、键、值和输出四个带偏置线性映射，不加入随机丢弃、缓存、额外记忆或位置编码。限制并不代表这些功能不重要，而是为了建立一个可以逐参数、逐输入梯度对照的最小可信模块。

设查询输入形状为 $`(B,L_q,E)`$，键和值输入形状分别为 $`(B,L_k,E)`$。键和值长度必须一致，查询长度独立。输出形状为 $`(B,L_q,E)`$，保留每个查询的位置身份。允许掩码使用真值表示合法候选，并可广播到 $`(B,H,L_q,L_k)`$。本章对完全空行选择拒绝输入，因为参考模块与不同优化路径对该边界可能有不同特例；第二章已经给出零输出策略的独立定义和梯度实验。

等价性验证必须先匹配这些条件。若手写模块没有偏置，参考模块有偏置，或者一边在训练中随机丢弃，一边处于确定性评估状态，输出差异未必来自代码错误。应先列出比较契约，再选择能够满足契约的参考层。把所有可选功能一次性开启，会让故障来源难以分离，也会让测试变得脆弱。

<a id="attention-3-detail-3"></a>

### 1.2 数学定义不能被张量技巧覆盖

对每个头，计算查询和键的缩放内积，沿候选轴归一化，再读取对应值。不同头拥有独立的投影子空间与权重分布，最后拼接并执行输出映射。任何高效布局都必须实现这个函数。重排、视图和批矩阵乘法只是执行方式，不能反过来改变“哪个查询对哪些候选竞争”的定义。

实际编码时最常见的问题不是乘法完全无法执行，而是某些尺寸碰巧相等，错误轴排列仍然合法。例如批大小、头数与长度都为二时，混淆轴可能不触发异常。教学实验应故意选不同的批、头、查询与键长度，并让数据不对称，使错误不能靠巧合隐藏。最终输入形状只是接口检查，中间元素身份同样需要检查。

<a id="sec-1-1"></a>

<a id="attention-3-detail-4"></a>

### 1.3 用元素编号理解拆头

假设模型宽度为六，头数为二，每头宽度为三。某个位置投影后得到六个通道，前三个属于第一头，后三个属于第二头。把最后一维重塑成头乘每头宽度，得到 $`(B,L,H,D)`$，再把头轴移到位置轴前，得到 $`(B,H,L,D)`$。这里的两个步骤不能交换成一个未经证明的直接重塑，因为原始存储顺序按位置组织，目标布局按头组织。

例如一个样本两个位置的通道分别编号零到五和六到十一。第一头应包含零一二与六七八，而不是零到五组成一头。直接把批位置通道连续内存改成批头位置每头维，可能得到看似正确的形状，却把同一位置的不同头混成不同位置。用递增整数构造元素身份测试，能比随机误差更直观地揭示这个问题。

<a id="deep-dive-1"></a>

<a id="attention-3-detail-5"></a>

### 1.4 投影矩阵在数学和框架中的方向

数学书常把行向量线性映射写成 $`XW`$，其中 $`W`$ 的形状为输入宽度乘输出宽度。PyTorch 线性层的权重存储为输出宽度乘输入宽度，前向执行 $`XW^T+b`$。将论文符号直接复制进参数张量而忘记转置，会得到不同函数；当输入输出宽度相同，形状无法提醒你。

参考多头模块通常把查询、键、值投影沿输出轴堆叠存储，其顺序为查询块、键块和值块。映射到三个独立线性层时，应沿第一轴切分权重与偏置，每块再按框架原有方向复制，不需要额外转置。输出映射也按对应存储方向复制。等价验证中应把参数身份写成明确映射，而不是只用相同随机种子，希望两种初始化恰好相同。

## 2. 可审阅的最小模块

<a id="attention-3-detail-7"></a>

### 2.1 每个函数只负责一个布局约定

下面的模块把拆头集中到一个小方法，避免查询、键、值三条路径各自写出略有不同的转置。前向先检查批与特征尺寸，再投影和拆头，计算分数并应用允许掩码，最后合头和输出投影。模块返回输出及逐头权重，方便研究时核对；实际部署若不需要权重，可以设计只返回输出的接口，并使用融合实现节省中间内存。

掩码要求布尔类型，并显式广播到分数形状。广播之后检查每行至少一个真值，避免把空行留给 softmax 的数值行为。这个检查可能增加运行开销，但它为教学建立明确边界。生产实现可以在数据入口集中验证，前提是保持相同契约，而不是悄悄删除边界定义。

<a id="attention-3-detail-8"></a>

### 2.2 实验一：完整参数与输入反向对照

以下代码是一个独立实验，既包含模块定义，也包含参考参数映射。查询、键、值采用相互独立的输入副本，以便分别比较三条输入路径；若使用同一个张量做自注意力，总输入梯度是三条路径相加，不便定位单条错误。损失使用固定上游张量与输出内积，避免后续损失层引入额外差异。

```python
import torch
from torch import nn

torch.set_num_threads(1)
torch.manual_seed(301)
dtype = torch.float64

class ManualMHA(nn.Module):
    def __init__(self, width, heads):
        super().__init__()
        assert width > 0 and heads > 0 and width % heads == 0
        self.width, self.heads, self.dim = width, heads, width // heads
        self.q_proj = nn.Linear(width, width)
        self.k_proj = nn.Linear(width, width)
        self.v_proj = nn.Linear(width, width)
        self.out_proj = nn.Linear(width, width)
    def split(self, x):
        b, length, _ = x.shape
        return x.reshape(b, length, self.heads, self.dim).transpose(1, 2)
    def forward(self, query, key, value, allowed):
        b, lq, e = query.shape
        assert key.ndim == value.ndim == 3
        assert key.shape == value.shape
        assert key.shape[0] == b and e == key.shape[2] == self.width
        q, k, v = self.split(self.q_proj(query)), self.split(self.k_proj(key)), self.split(self.v_proj(value))
        scores = (q @ k.transpose(-2, -1)) / (self.dim ** .5)
        assert allowed.dtype == torch.bool
        allowed = torch.broadcast_to(allowed, scores.shape)
        assert allowed.any(-1).all(), 'empty support is rejected'
        a = torch.softmax(scores.masked_fill(~allowed, -torch.inf), -1)
        z = a @ v
        joined = z.transpose(1, 2).reshape(b, lq, self.width)
        return self.out_proj(joined), a

width, heads, batch, lq, lk = 6, 2, 3, 4, 5
manual = ManualMHA(width, heads).to(dtype)
ref = nn.MultiheadAttention(width, heads, dropout=0., bias=True, batch_first=True).to(dtype)
with torch.no_grad():
    for i, layer in enumerate((manual.q_proj, manual.k_proj, manual.v_proj)):
        layer.weight.copy_(ref.in_proj_weight[i*width:(i+1)*width])
        layer.bias.copy_(ref.in_proj_bias[i*width:(i+1)*width])
    manual.out_proj.load_state_dict(ref.out_proj.state_dict())
raw = [torch.randn(batch, length, width, dtype=dtype) for length in (lq, lk, lk)]
xs = [x.clone().requires_grad_() for x in raw]
ys = [x.clone().requires_grad_() for x in raw]
allowed = torch.ones(lq, lk, dtype=torch.bool)
allowed[0, 2:] = False
allowed[1, 0] = False
out, a = manual(*xs, allowed)
expected, weights = ref(*ys, attn_mask=~allowed, need_weights=True, average_attn_weights=False)
assert torch.allclose(out, expected, atol=1e-12, rtol=1e-11)
assert torch.allclose(a, weights, atol=1e-12, rtol=1e-11)
upstream = torch.randn_like(out)
(out * upstream).sum().backward()
(expected * upstream).sum().backward()
for x, y in zip(xs, ys):
    assert torch.allclose(x.grad, y.grad, atol=1e-11, rtol=1e-10)
for i, layer in enumerate((manual.q_proj, manual.k_proj, manual.v_proj)):
    assert torch.allclose(layer.weight.grad, ref.in_proj_weight.grad[i*width:(i+1)*width], atol=1e-11, rtol=1e-10)
    assert torch.allclose(layer.bias.grad, ref.in_proj_bias.grad[i*width:(i+1)*width], atol=1e-11, rtol=1e-10)
assert torch.allclose(manual.out_proj.weight.grad, ref.out_proj.weight.grad, atol=1e-11, rtol=1e-10)
assert torch.allclose(manual.out_proj.bias.grad, ref.out_proj.bias.grad, atol=1e-11, rtol=1e-10)
print('forward, per-head weights, three inputs, all projection gradients: passed')
```

### 2.3 对照通过究竟证明了什么

该实验为当前参数和输入提供很强的一致性证据：不仅输出一致，逐头权重、查询键值输入梯度及所有投影参数梯度也一致。它覆盖带偏置、不同查询键长度、多批与多头、非均匀合法支持的路径。它没有覆盖随机丢弃、空行、不同键值输入宽度、缓存或低精度执行，不能把报告扩大成对这些功能的验证。

随机测试不是对所有实数输入的形式化证明。它的价值在于发现实现偏离推导的常见错误。配合逐轴定义、元素身份测试和故障干预，可以形成互补证据。若要扩展模块，应增加针对新功能的最小算例，而不是只把现有随机张量变大，期待规模增加自然带来更全面覆盖。

## 3. 逐轴追踪与内存布局

<a id="attention-3-detail-11"></a>

### 3.1 转置改变逻辑轴，不一定移动数据

张量转置通常通过修改步长描述新的逻辑视图，不立即重排底层数据。转置后的张量可能不连续，直接使用要求特定连续布局的视图操作可能失败。`reshape`在需要时可以创建合适副本，因而比机械使用`view`更容易正确表达本章合头操作，但它也可能产生额外内存复制。正确性与性能需要分别检查。

不能为了消除一次复制就删除必要的转置。先明确目标元素对应关系，再研究如何让布局转换更高效。某些融合实现直接在内部使用合适布局，表面代码看不到显式转置，但它仍然遵守相同语义。对手写教学实现，清晰的轴操作通常比过早压缩成一个难以审阅的表达式更重要。

<a id="attention-3-detail-12"></a>

### 3.2 实验二：拆头合头与错误重塑对照

用递增整数测试可以精确追踪每个元素。下面先验证正确拆头和合头互为逆变换，再证明直接重塑为目标形状得到不同元素分组。错误结果虽然尺寸完全正确，却不满足头与位置身份。测试还检查转置后的非连续性，提醒读者布局属性和逻辑形状是不同对象。

```python
import torch

torch.set_num_threads(1)
x = torch.arange(2 * 4 * 6).reshape(2, 4, 6)
heads, dim = 2, 3
split = x.reshape(2, 4, heads, dim).transpose(1, 2)
assert split.shape == (2, 2, 4, 3)
assert torch.equal(split[0, 0, 1], torch.tensor([6, 7, 8]))
assert torch.equal(split[0, 1, 1], torch.tensor([9, 10, 11]))
joined = split.transpose(1, 2).reshape(2, 4, 6)
assert torch.equal(joined, x)
wrong = x.reshape(2, heads, 4, dim)
assert wrong.shape == split.shape and not torch.equal(wrong, split)
assert not split.is_contiguous()
print('element identity, inverse merge, wrong reshape detection: passed')
```

<a id="attention-3-detail-13"></a>

### 3.3 展平批与头的合法条件

为了使用批矩阵乘法，可以在正确拆头以后把批和头合并为一个执行批轴，形状变为 $`(BH,L,D)`$。这只是执行层面的合并，各组依然独立，不能让一个组的查询读取另一个组的键。结果还原时必须使用相同的批头顺序。若展平和还原采用不同排列，即使每个小矩阵乘法都正确，输出也会被分配给错误样本或错误头。

掩码也需要按同一顺序展开。如果每个样本的允许关系不同，不能只复制第一张掩码给所有批头组合。最小测试应让不同样本具有不同合法键，并让不同候选值容易区分，再检查每个输出是否来自正确样本。把批头执行维度误解成新的候选维，是更严重的错误，会直接引入跨样本读取。

<a id="attention-3-detail-14"></a>

### 3.4 合头后为什么还需要保留查询顺序

每头输出按头、查询、值通道组织。合头的目标是在同一查询位置收集全部头的通道，因此应先交换头与查询轴，再合并头和值通道。若直接把头优先布局展平，得到的相邻通道可能来自不同查询，而非同一查询的不同头。输出投影随后会把错误内容混合，损失仍可能有梯度，却优化了错误函数。

检查合头时可以让每个头输出一个不同常数，每个查询再加不同编号。正确合头后，每行应包含同一查询编号与各头常数的组合。这种构造不依赖随机参数，能够精确区分“只改变存储布局”和“改变了元素语义”。在复杂模型中保留一组这样的身份测试，往往比每次训练出错后再打印大张量更高效。

<a id="attention-3-detail-15"></a>

## 4. 用故障干预检验测试是否有辨识力

<a id="attention-3-detail-16"></a>

### 4.1 正确输出并不总能证明正确实现

如果值全部相同，许多错误分数和掩码都会产生相同输出；如果所有投影都是零，拆头错误也可能被遮蔽；如果损失恰好在输出最优点，错误梯度可能因为上游梯度为零而难以发现。测试不应只追求“代码运行没有报错”，还要检查输入能否让目标错误显现。故障注入就是有意制造一种已知错误，观察测试是否拒绝它。

有辨识力的测试通常包含非对称输入、非零偏置、不同长度和不同轴尺寸，以及不退化的上游梯度。也可以设计唯一合法候选，让正确答案不依赖任何复杂算术；设计非均匀权重与不同值，让错配明显改变结果；设计独立查询键值副本，使单路径梯度可以定位。不同构造针对不同故障，不能只靠一个随机种子承担全部验证。

<a id="attention-3-detail-17"></a>

### 4.2 实验三：前向相同但反向错误

下面比较正常读取与故意截断权重梯度的错误读取。两者前向严格相同，但错误实现把查询和键的匹配路径从计算图中断开。为了让自动微分仍能请求查询键梯度，示例加入数值上为零的连接项，得到明确的零梯度。值路径仍然有梯度，这说明只检查“模型有参数更新”不能证明所有训练路径正确。

```python
import torch

torch.set_num_threads(1)
torch.manual_seed(303)
dtype = torch.float64
q = torch.randn(2, 3, dtype=dtype, requires_grad=True)
k = torch.randn(4, 3, dtype=dtype, requires_grad=True)
v = torch.randn(4, 2, dtype=dtype, requires_grad=True)
g = torch.randn(2, 2, dtype=dtype)
a = torch.softmax(q @ k.T / (3 ** .5), -1)
good = a @ v
bad = a.detach() @ v + (q.sum() + k.sum()) * 0.
assert torch.equal(good, bad)
grad_good = torch.autograd.grad((good * g).sum(), (q, k, v), retain_graph=True)
grad_bad = torch.autograd.grad((bad * g).sum(), (q, k, v))
assert grad_good[0].norm() > 1e-8 and grad_good[1].norm() > 1e-8
assert torch.equal(grad_bad[0], torch.zeros_like(q))
assert torch.equal(grad_bad[1], torch.zeros_like(k))
assert torch.allclose(grad_good[2], grad_bad[2], atol=1e-12)
print('identical forward, broken query/key backward, unchanged value backward: passed')
```

这类错误可能来自不恰当的`detach`、把中间结果转换到其他数组库、在无梯度上下文中预计算本应训练的内容，或者错误重建张量。前向一致性无法发现它，因为前向数值没有变化。第三章的完整参数反向对照因此不是多余步骤，而是覆盖另一类真实风险。

<a id="attention-3-detail-18"></a>

### 4.3 实验四：键值配对与掩码方向的故障对照

下面选择单个查询，使正确读取可以直接算出。同步重排键值不应改变输出，只重排值应改变；唯一允许候选时，输出必须等于其值。最后把允许关系取反，确认得到不同结果。这个实验不依赖参考层，因此为接口对照提供一条独立证据，避免双方共享同一种错误输入约定。

```python
import torch

torch.set_num_threads(1)
dtype = torch.float64
q = torch.tensor([[1.]], dtype=dtype)
k = torch.tensor([[0.], [1.], [2.]], dtype=dtype)
v = torch.tensor([[1., 0.], [0., 2.], [4., -1.]], dtype=dtype)
def read(q, k, v, allowed):
    s = q @ k.T
    return torch.softmax(s.masked_fill(~allowed, -torch.inf), -1) @ v
all_allowed = torch.ones(1, 3, dtype=torch.bool)
base = read(q, k, v, all_allowed)
p = torch.tensor([2, 0, 1])
assert torch.allclose(base, read(q, k[p], v[p], all_allowed), atol=1e-12)
assert not torch.allclose(base, read(q, k, v[p], all_allowed))
one = torch.tensor([[False, True, False]])
assert torch.equal(read(q, k, v, one), v[1:2])
assert not torch.allclose(read(q, k, v, one), read(q, k, v, ~one))
print('paired permutation, value mismatch, boolean reversal: passed')
```

<a id="attention-3-detail-19"></a>

### 4.4 故障对照结果应怎样报告

正确测试应明确说出它发现了哪种故障，而不是只展示一串通过。上述四个实验分别覆盖完整前向与反向参数身份、布局元素身份、梯度截断以及配对和掩码语义。它们没有模拟所有可能的软件缺陷，但每个故障都有可解释的失败信号。修改实现以后，若某个故障不再被检测，应重新检查测试输入是否退化，或新实现是否改变了观察边界。

故意错误的代码应该只存在于教材中的局部对照，不应混入可复用模块默认路径。对于教学文档，可以在明确命名的实验里保留错误表达式，并用断言展示其差异；对于实际项目，测试与生产实现应分开组织。用户运行教材时也应知道哪些行是故障示例，避免把它们误复制成训练代码。

## 5. 参数梯度对照的推导与诊断

<a id="attention-3-detail-21"></a>

### 5.1 线性投影梯度为什么能定位转置错误

对一个线性层 $`Y=XW^T+b`$，把批与位置暂时合并为样本轴，上游梯度为 $`G`$，则权重梯度是 $`G^TX`$，偏置梯度为所有样本行的梯度和，输入梯度为 $`GW`$。这组公式说明存储方向与反向形状是相互一致的。若错误地转置参数，前向可能在某个对称矩阵上碰巧一致，但非对称参数及梯度通常会暴露差异。

查询、键和值投影共享同一个原输入时，三个输入梯度需要相加。独立副本实验先分别验证三条路径，再把相同数据作为同一个张量传入，可以进一步检查总梯度等于独立路径之和。若错误地覆盖梯度而不是累积，某条分支贡献会丢失。框架自动微分通常负责累积，但自定义反向或手工缓存逻辑需要尤其注意。

<a id="attention-3-detail-22"></a>

### 5.2 为什么键偏置可能出现接近零的梯度

在没有额外位置相关项的点积注意力中，给所有键增加相同偏置，会对同一个查询的全部分数增加共同常数，因此权重不变。标准键投影偏置恰好在每个位置加同一向量，所以在这种结构下，损失经匹配路径对键偏置的梯度理论上为零。掩码固定且非空时，共同偏移在合法支持内部同样抵消。

因此，对照键偏置梯度时，不应要求它必须大于某个正阈值；接近零可能是正确结构性质，而不是训练失效。浮点归约可能留下极小误差，应按精度设置绝对容差。若键还通过其他路径参与模型，或者附加算子破坏这种共同平移性质，则需要重新分析。识别结构零梯度，有助于避免把正常现象当成优化器问题。

<a id="attention-3-detail-23"></a>

### 5.3 查询偏置与值偏置为何不同

查询偏置给不同键的分数增加不同内积，因此通常会改变分布，梯度不必为零。值偏置则给每个候选加相同返回向量，由于合法行权重和为一，输出在每个查询上都增加这个向量，随后再经过输出映射。因此值偏置可以直接改变输出，不会像键偏置那样自动抵消。

这个比较强调三种投影虽然尺寸相同，功能却不对称。把它们初始化成相同参数用于简单测试，可以降低变量数量，但不足以覆盖全部角色差异。完整对照应使用一般非对称权重和偏置，再分别检查三组参数的梯度。若只检查总梯度范数，键偏置的结构零可能被其他参数掩盖，也可能让开发者产生错误预期。

<a id="attention-3-detail-24"></a>

### 5.4 先查最大误差，再查误差的结构

输出对照失败时，可先打印最大绝对误差和相对误差，但不能停在一个数。应观察误差是否仅出现在某个批、某个查询、某个头或某组通道。只在部分样本出现，可能是掩码广播；头间交换而数值集合相似，可能是拆头合头排列；所有输出差一个共同向量，可能是偏置；梯度差固定倍数，可能是缩放或损失归约。

前向一致而查询键梯度错误，优先检查分数路径是否断开、手写反向是否遗漏缩放。值梯度错误而分数梯度对照正常，优先检查值配对或合头路径。输出投影梯度正确但投影前参数错误，可能表明前向中间量被重新构建或断开。诊断应利用数学结构缩小范围，而不是随机修改容差直到测试通过。

<a id="attention-3-detail-25"></a>

### 5.5 数值差异与语义差异的判别

不同矩阵乘法归约顺序可能产生浮点舍入差异，尤其在低精度、大张量或融合内核中。语义相同不保证逐比特一致，因此示例使用双精度和合理容差。但若误差集中在非法位置、样本之间串扰、输出随填充内容明显变化，则属于语义错误，不能靠扩大容差解决。

选择容差时，应结合数值精度、输入尺度和操作深度；同时保留某些无需近似的断言，例如张量形状、布尔合法关系、元素编号和禁止位置的精确零权重。这样可以避免把所有检查都退化成一个过宽的数值接近测试。对具有大幅度抵消的输入，相对误差尤其需要和绝对误差一起解释。

<a id="attention-3-detail-26"></a>

## 6. 从正确前向到可训练模块

<a id="attention-3-detail-27"></a>

### 6.1 参数注册与优化器身份

一个张量参与前向并获得梯度，并不意味着优化器会更新它。参数必须作为模块参数注册，并在构造优化器时进入其参数集合。若每次前向都创建新的线性层，优化器持有的旧参数可能与当前计算使用的参数不同；若用普通列表保存子层，某些框架机制可能无法自动遍历。应使用模块提供的注册容器，并检查参数身份，而不只是检查名字相似。

优化器通常在构造时记录参数对象。之后把某个参数替换成新对象，旧优化器不一定自动跟随。加载权重与重建参数也需要区分：向已有参数复制数值通常保留对象身份，直接赋成新参数则可能改变。教学模块用固定构造和数值复制建立对照，避免这些额外生命周期因素，但实际研究实现应把它们纳入检查。

<a id="sec-6-1"></a>

<a id="attention-3-detail-28"></a>

### 6.2 一步训练应验证哪些对象确实改变

可训练模块的最小更新检查包括：清空旧梯度，计算非退化损失，反向以后确认预期参数得到有限梯度，再执行优化器一步，比较参数前后差异。结构上梯度为零的参数不应被错误要求改变；带权重衰减的优化器即使当前梯度很小，也可能造成数值变化，因此参数变化不等于模型从监督里学到有效信号。

还要区分优化器遗漏与自动微分断开。若参数梯度非零但数值不变，可能没有进入优化器、学习率为零或更新被覆盖；若梯度为空，可能没有参与图或尚未反向；若梯度为零，可能是结构退化、饱和或上游目标特殊。把所有情况都称为“梯度消失”，会失去排查所需的具体信息。

<a id="attention-3-detail-29"></a>

### 6.3 训练循环的模式与随机性

本章所有对照都关闭随机丢弃，模块的训练和评估模式不会改变核心数值。扩展随机丢弃以后，模式会变得重要；函数式调用还需要显式根据模式选择概率。若对照两边使用不同随机掩码，输出和梯度自然可能不同，即使期望意义上的定义一致。可以先把随机概率置零建立确定性基线，再研究随机路径。

固定随机种子有助于重现实验，却不能保证不同内核和设备使用相同随机序列或归约方式。最可靠的步骤是先对照确定性数学核心，再对随机机制单独测试统计性质和模式切换。不要把“设置了种子”当作所有比较条件已经相同的替代说明。

<a id="attention-3-detail-30"></a>

### 6.4 小样本过拟合检查的作用与边界

在完整任务训练前，可以选极小人工数据集，要求模型明显降低训练损失。这能检查参数更新、标签对齐和主要通路是否连通，但无法证明泛化能力，也不能替代输入梯度和掩码验证。错误模型也可能记住少量样本，尤其当标签泄漏或样本身份被编码进输入时。

小样本检查的目标应是发现基础训练故障，而不是展示一个漂亮的近零误差。应同时记录基线损失、梯度和参数更新，确认目标确实需要模型使用预期信息。若在随机标签上也轻易达到极低训练误差，应把它解释为记忆能力，而不是学到了正确检索机制。研究报告应清楚区分优化可行性与任务有效性。

<a id="attention-3-detail-31"></a>

## 7. 用分层验证取代单一大测试

<a id="attention-3-detail-32"></a>

### 7.1 第一层：代数身份与元素身份

最低层检查不需要训练，也不需要参考库。查询键内积必须收缩匹配特征，权重值乘法必须收缩候选身份，拆头合头必须保持每个元素的来源。手算例子、唯一允许候选和整数编号足以覆盖这些问题。优先建立这一层，可以防止开发者把所有错误都归咎于参考模块内部的复杂优化路径。

这类检查还有一个优点：失败时能给出接近错误根源的解释。例如某个查询合头后混入另一查询的元素，问题显然在布局，而不是学习率或数据分布。若只观察最终训练精度下降，可能需要很长时间才发现同一个错误。局部验证不是对整体任务的替代，而是让整体实验结果更容易归因。

<a id="attention-3-detail-33"></a>

### 7.2 第二层：独立表达式与参考实现

可以用显式循环逐批逐头执行同一数学公式，再与向量化实现比较。循环实现速度慢，但结构接近定义，适合作为小张量基准。参考层提供另一个独立实现，特别适合检查框架参数布局和接口转换。三者一致比只有两个复杂模块一致更可靠，因为某些相同错误不容易同时出现在不同表达方式中。

不过，独立性不是由代码文件数量决定的。如果循环版和向量化版复制了同一个错误掩码，结果仍会一致。应让至少一条证据来自手工可知的答案或结构性质。例如唯一合法候选的输出就是其值，不依赖任何循环或参考库；同步键值置换的不变性则来自代数证明。把不同类型证据组合，比重复运行相同逻辑更有效。

<a id="attention-3-detail-34"></a>

### 7.3 第三层：微分与局部扰动

自动微分对照检查当前实现与参考实现的反向是否一致，方向有限差分检查反向是否与前向局部变化一致。前者可能共享框架的基础算子，后者在数值上独立于反向图，因此能够发现某些梯度截断或自定义反向错误。差分测试通常选少量随机方向，比逐参数扰动便宜，也适合验证高维输入。

差分失败不一定立即说明反向错。若扰动跨越硬掩码变化、分段操作或不光滑点，中心差分可能不对应单侧导数；若步长太小，舍入误差可能主导。应先固定离散结构、使用平滑输入区间和双精度，再扫描几个合理步长，观察误差是否呈现预期趋势。不能只选择一个偶然通过的步长而忽略其余结果。

<a id="attention-3-detail-35"></a>

### 7.4 第四层：信息边界与批独立性

完成数值对照后，还需用未来扰动、填充扰动和批重组检查任务语义。一个模块可以完全复现参考实现，却使用错误的业务掩码。参考库只执行传入的规则，不知道哪些内容在预测时合法。把不正确掩码同时传给两边，前向与反向都能一致，却仍然泄漏答案。

因此，模型审查应包含一份独立于实现的允许关系说明，并用人工样本检查它。对于打包文档，应改变前一文档内容验证后一文档独立；对于在线预测，应改变未来记录验证过去输出独立；对于标准批处理，应改变同批其他样本验证当前样本独立。每种测试都针对一种明确依赖，而不是把所有不变性混为一谈。

<a id="attention-3-detail-36"></a>

### 7.5 第五层：优化与实验协议

只有在核心算子可信以后，训练曲线才适合用来研究学习规律。此时可以比较初始化、头数、温度和优化器，但仍需保持数据划分和预算一致。若改变头数同时改变总宽度，结果混合了两个因素；若一种实现每步更快而训练步数也更多，需要分别报告固定步数与固定时间下的结果。

对于教材的小型 CPU 实验，主要目标是验证机制，不应把运行耗时推广到大型 GPU 训练。融合内核、混合精度与内存带宽会改变瓶颈。研究者可以先建立正确且清晰的参考实现，再把高效实现逐项映射到同一契约；性能优化不应该削弱已有语义测试。

<a id="attention-3-detail-37"></a>

## 8. 参数化、冗余与梯度的进阶理解

<a id="attention-3-detail-38"></a>

### 8.1 查询键的基变换自由度如何映射到参数

对某个头，只要查询输出右乘可逆矩阵，键输出右乘相应逆转置，分数矩阵保持不变。在线性投影参数层面，可以相应变换两组权重和偏置，得到不同参数却完全相同的读取函数。这个自由度说明参数空间里存在表达相同函数的多个点，某些参数距离并不直接代表函数距离。

优化器会受到参数化影响。即使两组参数表示相同函数，普通梯度下降在不同坐标下的后续轨迹未必等价，权重衰减对不同尺度分配也可能施加不同偏好。因此，函数等价不意味着训练动力学等价。比较初始化或正则化时，应把前向表达能力与优化路径分开讨论，避免从一个基变换恒等式推出不成立的训练结论。

<a id="attention-3-detail-39"></a>

### 8.2 头置换对称与参数比较

同时交换头的投影块和输出投影对应列块，整个函数保持不变。两个训练模型若只是头编号不同，逐参数欧氏距离可能很大，预测却完全一样。直接平均它们的未对齐参数，也可能破坏原有功能。因此，研究模型合并或参数相似性时，需要考虑这种结构对称，不能只比较名字相同的张量位置。

这类对称也影响调试。若手写模块的头顺序与参考模块不同，但输出投影按对应方式转换，最终输出可以一致，逐头权重却呈置换关系。此时并不一定是函数错误，而是比较时没有对齐内部身份。本章选择相同头顺序，是为了让逐头直接对照成立；若采用其他布局，应把映射写进验证协议。

<a id="attention-3-detail-40"></a>

### 8.3 输出投影可以掩盖中间误差

如果输出投影在某个方向上为零，头输出沿那个方向的错误不会影响最终输出。只比较最终结果可能漏掉内部故障，之后训练让输出投影不再为零时，故障才显现。逐头权重与投影前读取对照可以提高覆盖，随机非退化参数也能降低偶然零空间遮蔽的概率。

另一方面，中间表示不同但最终函数等价并非总是错误，例如合法的头置换或基变换。判断时应区分“实现违反指定布局契约”与“采用另一套等价内部坐标”。如果目标是替换现有模块并加载同一权重，就需要严格遵守参数映射；如果目标是独立架构研究，可以使用不同参数化，但不能声称直接逐参数兼容。

<a id="attention-3-detail-41"></a>

### 8.4 掩码与参数梯度的稀疏结构

某条注意力边被严格屏蔽后，其分数不影响该查询输出，局部梯度为零。但投影参数通常被所有位置共享，因此同一参数仍可通过其他合法边更新。不能把稀疏依赖图误解成参数梯度也按位置稀疏到同样程度。参数共享把多个位置的梯度累积到同一矩阵中，局部边零梯度与全局参数非零完全可以同时成立。

分析稀疏注意力训练时，可以分别统计边级权重、输入级梯度和参数级梯度。三者对应不同聚合层次，不能互相替代。若某个输入位置从未作为键被读取，它仍可能作为查询产生损失，或者通过值编码和其他分支影响输出。完整依赖分析应沿计算图跟踪每条路径。

<a id="attention-3-detail-42"></a>

### 8.5 共享输入梯度的一个可检验恒等式

当自注意力把同一个输入分别送入查询键值投影，链式法则要求输入梯度等于三个独立副本在相同数值处的梯度之和。这是很有用的结构检查，因为它直接覆盖共享张量的累积语义。若在重构时不小心把一条路径断开，最终输出仍可能接近，但这个恒等式会出现可解释差异。

也可以用这个恒等式分析训练信号来源。查询路径改变当前位置如何提出需求，键路径改变它如何被其他位置匹配，值路径改变它被读取时提供的内容。它们在同一输入空间相加，可能增强也可能抵消。总梯度较小并不意味着每条路径都弱，可能是方向抵消；诊断时记录分路径结果能提供更细致的机制解释。

<a id="attention-3-detail-43"></a>

## 9. 扩展模块时怎样维护兼容性

<a id="attention-3-detail-44"></a>

### 9.1 添加不同记忆宽度

交叉注意力的记忆宽度可能不同于查询宽度，此时查询投影的输入维度与键值投影输入维度应分别设置。投影后匹配维一致即可，原始维度不需要相同。参考模块也可能为这种情况采用不同参数存储方式，不再使用一个简单的三块堆叠矩阵。迁移权重时应重新读接口和参数列表，而不是沿用本章等宽切分代码。

验证时选择查询宽度、记忆宽度和输出宽度互不相同，可以让错误矩阵方向更容易暴露。仍然需要前向、逐输入和逐参数梯度对照。若只把形状改到能运行，却没有明确输出投影和残差接口的维度，后续网络很容易出现隐含投影或错误广播。

<a id="attention-3-detail-45"></a>

### 9.2 添加位置偏置或旋转变换

位置机制可以加在输入、投影后查询键或分数上，不同位置意味着不同函数。若比较手写模块与参考层，需要在同一个计算位置施加相同变换。把一种位置偏置加在缩放前，另一种加在缩放后，会让其有效尺度不同；若带有缓存，还要使用绝对位置偏移，而不是每步从零重新编号。

位置机制也改变结构测试。任意内容重排后保持原位置不变，通常不再满足无位置置换等变性；若把位置身份与内容一起重新编号，可能保留另一种关系。测试应根据新定义更新，不能把原来正确的不变性强行要求所有扩展都满足。第四章将进一步推导位置变换的条件及效率边界。

<a id="attention-3-detail-46"></a>

### 9.3 添加缓存时的状态身份

缓存不仅是一组张量，还包含它们对应的序列身份、绝对位置、层、头布局和参数版本。复用错误样本的缓存会造成信息串扰，复用旧参数生成的缓存则可能不再对应当前模型。增量推理通常在参数固定的评估阶段使用缓存；训练中若复用带图缓存，还涉及梯度保留和跨步状态问题，不能照搬推理写法。

一个可靠缓存测试先在短序列上比较完整因果前向与逐前缀读取，再打乱样本批顺序验证缓存身份映射，最后检查重置和长度边界。缓存的预期收益来自减少重复投影和读取，不应该改变数学输出。若为了近似或压缩而改变缓存内容，需要把这种误差单独列为研究因素。

<a id="attention-3-detail-47"></a>

### 9.4 添加低精度和融合执行

低精度可能改变分数累加、指数归一化和反向误差，高效融合实现可能不显式保存完整权重。两者都应先与本章确定性双精度参考在小输入上对照，再根据目标精度设置容差。无法返回权重的高效接口，可以比较输出和输入参数梯度，并保留单独的数学实现用于解释性实验。

若融合内核在某些掩码或形状下退回其他实现，性能变化不代表数学定义改变。报告应记录实际环境与功能组合，避免把某个特定优化路径的优势推广到所有输入。教学 CPU 对照只证明本章覆盖路径的数值一致性，不支持关于专用硬件内存和吞吐的结论。

## 10. 进阶习题与完整解析

<a id="attention-3-detail-49"></a>

### 10.1 直接重塑为什么破坏头身份

**题目。** 输入为两个位置，每位置四通道，按顺序编号零到七。拆成两头、每头两通道时，第一头应包含哪些元素？直接重塑到头位置通道布局会怎样？

**解析。** 正确第一头在两个位置分别包含零一与四五，第二头包含二三与六七。直接把连续数据重塑为头乘位置乘通道，会让第一头得到零一与二三，混淆了同一位置的不同头和不同位置。应先按位置头通道解释末维，再交换位置与头轴。错误结果尺寸完全正确，所以必须用元素身份而非仅用形状断言检查。

<a id="attention-3-detail-50"></a>

### 10.2 参考投影权重应沿哪个轴切分

**题目。** 参考层堆叠投影权重形状为十八乘六，模型宽度为六。如何映射到三个独立线性层？是否需要转置？

**解析。** 沿第一轴按六行一块切成查询、键和值三组，每组形状为六乘六。PyTorch 两边线性层都按输出乘输入存储，因此直接复制，不需要转置。偏置也按同样顺序切成三段。若在数学推导中采用输入乘输出的矩阵方向，应在符号与存储之间明确转换，不能把数学记号的转置机械加到已经符合框架布局的参数上。

<a id="attention-3-detail-51"></a>

### 10.3 为什么相同随机种子不等于相同参数

**题目。** 手写模块和参考模块前都设置同一个种子，为什么仍可能初始化不同？

**解析。** 两种构造可能创建参数的顺序、形状、初始化分布或随机抽样次数不同。相同种子只能固定各自随机过程，不保证不同过程产生逐参数相同数值。等价对照应显式复制参数并检查映射。若研究初始化本身，则应把分布、缩放和偏置规则当作实验因素，而不是用种子相同掩盖结构差异。输出不一致时先核对实际参数，能避免误查注意力公式。

<a id="attention-3-detail-52"></a>

### 10.4 查询键长度不同为什么是好测试

**题目。** 所有测试都令查询和键长度相等，会漏掉哪类错误？

**解析。** 某些转置或轴混淆只有在长度不同才导致形状异常；等长时错误矩阵仍可能相乘，并输出看似合理形状。使用四个查询、五个键以及不同批头数，可以让多种错误更早暴露。还应保留非对称值，因为即使形状能区分问题，候选错配仍可能需要数值断言。测试尺寸的选择应服务于辨识错误，而不是只追求整齐或常用大小。

<a id="attention-3-detail-53"></a>

### 10.5 为什么值梯度正确仍不能证明训练正确

**题目。** 一种实现把注意力权重断开梯度，前向和参考一致，值投影梯度也一致。为什么仍是错误？

**解析。** 值路径对输出的导数直接由当前权重决定，所以只要前向权重数值相同，值梯度可以相同。查询与键路径依赖权重对分数的导数，断开权重会把这些路径清零，无法学习匹配关系。应分别比较三路输入和三组投影参数梯度。只检查总损失下降，模型可能靠值投影或后续层补偿，掩盖匹配部分没有正常训练。

<a id="attention-3-detail-54"></a>

### 10.6 键偏置梯度为何接近零

**题目。** 对照中键投影偏置梯度几乎为零，查询和值偏置却不是。是否应该人为放大键偏置梯度？

**解析。** 不应该。键偏置对所有候选添加相同向量，对单个查询的分数只形成共同偏移，被 softmax 抵消，所以这是结构性质。查询偏置会与不同键产生不同内积，值偏置则直接平移读取内容，因此不具有相同抵消。应核对前提并使用合理绝对容差，而不是把每个参数都必须有显著梯度当作训练正确标准。其他分支若使用键表示，结论需重新分析。

<a id="attention-3-detail-55"></a>

### 10.7 合头为何要先交换轴

**题目。** 逐头输出为批、头、查询、通道布局，为什么不能直接重塑为批、查询、总宽度？

**解析。** 直接重塑按现有存储顺序把不同查询的通道相邻拼接，目标却要求同一查询汇集全部头。应先把查询轴放到头轴前，再合并头与通道。可以给每个查询和头不同编号，精确检查每一行的来源。若输出投影恰好把错误方向置零，最终输出可能偶然接近，因此中间元素身份测试仍有必要。

<a id="attention-3-detail-56"></a>

### 10.8 非连续张量是否意味着计算错误

**题目。** 拆头后的张量不是连续存储，是否应立即判断实现错误？

**解析。** 非连续只是逻辑索引与底层步长的关系，不代表元素语义错误。转置通常产生非连续视图，许多矩阵操作可以正确处理。需要连续布局时可以显式整理或使用能处理布局的重塑，但可能增加复制。应先验证元素与结果，再研究性能；为了让张量连续而删除必要转置，会把存储问题变成语义错误。布局优化应保留已有身份断言。

<a id="attention-3-detail-57"></a>

### 10.9 输出一致但逐头权重不同是否一定错误

**题目。** 两个实现最终输出一致，逐头权重却按头顺序交换。怎样判断？

**解析。** 若所有头投影及输出投影对应块都同步交换，这是合法头置换，完整函数等价。若只交换内部头而没有转换输出投影，则一般是错误，某个样本相同可能来自特殊参数。应写出头映射并对参数与中间结果按映射比较。本章要求直接逐头一致，因为它选择相同布局契约；另一种实现可以采用不同布局，但必须提供清楚的兼容映射。

<a id="attention-3-detail-58"></a>

### 10.10 为什么不能用更宽容差修复配对错误

**题目。** 只打乱值后输出误差较大，有人提高容差直到测试通过。问题在哪里？

**解析。** 键值身份错配改变了数学函数，不属于浮点舍入。容差用于允许相同算法在有限精度下的微小差异，不用于接受语义错误。应恢复同步配对，并用唯一合法候选或可手算例子验证。若误差随候选顺序或样本身份呈结构变化，更应优先查映射。容差选择必须有精度和尺度依据，不能由“让测试变绿”决定。

<a id="attention-3-detail-59"></a>

### 10.11 独立输入梯度怎样合成为自注意力梯度

**题目。** 查询键值使用相同输入数值但三个独立张量，所得梯度分别为三组。若改成同一个张量作为全部输入，理论梯度是什么？

**解析。** 根据复合函数链式法则，共享输入的梯度是三条路径梯度之和。前向值不变，但同一变量同时影响匹配需求、候选索引和返回内容。这个恒等式可以验证共享图的累积是否正确。总梯度可能因方向抵消而较小，所以只看总范数不能判断每条路径都弱。若某条路径被断开，独立对照能更容易定位遗漏。

<a id="attention-3-detail-60"></a>

### 10.12 参数有梯度但不更新应查什么

**题目。** 查询投影梯度非零且有限，执行优化器一步后参数仍未改变。有哪些合理排查方向？

**解析。** 检查该参数对象是否进入优化器、学习率是否为零、更新前后是否比较同一对象、是否在更新后重新加载旧权重，以及变化是否小于当前精度分辨率。梯度存在说明反向路径至少连通，不等于优化器持有正确对象。如果参数在构造优化器后被替换，旧优化器可能仍引用旧对象。应区分对象身份、梯度数值和更新规则，不能把所有不更新都归因于注意力饱和。

<a id="attention-3-detail-61"></a>

### 10.13 为什么空行选择拒绝仍是合理实现

**题目。** 第二章支持空行零输出，本章模块却拒绝空行，是否矛盾？

**解析。** 不矛盾，两章明确采用不同契约。第二章研究一种边界定义并验证零梯度，本章为与参考层做确定性对照，把输入限制为每行至少一个合法候选。关键是调用者知道限制，并在数据入口或模块检查中得到明确反馈。若任务正常存在空行，应扩展模块并增加相应测试，而不是悄悄依赖底层 softmax 的未定义行为。

<a id="attention-3-detail-62"></a>

### 10.14 前向内创建线性层为什么危险

**题目。** 每次前向都创建一个新的查询线性层，损失也能反向。为什么这通常不是正确训练？

**解析。** 新层参数每次重新初始化，优化器通常没有持有当前新参数，学习状态无法持续。旧参数即使更新也可能下一次不再使用。模块应在构造时创建并注册参数，前向只用现有对象计算。若确实研究动态参数生成，应把生成机制作为模型的一部分，并明确哪些基础参数被优化，而不是把意外重建误当作灵活架构。

<a id="attention-3-detail-63"></a>

### 10.15 输出投影零空间怎样掩盖错误

**题目。** 两种实现的头输出不同，最终输出却相同，除了头置换还有什么可能？

**解析。** 差异可能位于输出投影的零空间中，被线性映射消除。若投影为零，任何头输出都会给出相同偏置。应使用一般非退化参数，并检查逐头权重和投影前读取。相同最终输出可以证明当前样本的最终行为一致，却不能唯一识别内部机制。若目标是兼容指定参数布局，中间差异仍需要解释，不能被最终一致自动豁免。

<a id="attention-3-detail-64"></a>

### 10.16 梯度差固定倍数通常提示什么

**题目。** 前向一致，查询键梯度总比参考大每头维度的平方根倍，值梯度正常。优先检查哪里？

**解析。** 优先检查反向是否遗漏分数缩放因子。查询键梯度经过点积除以平方根维度的链式路径，值梯度不经过该因子，因此这种分路径固定比例很有诊断价值。也要排除损失归约不同等其他整体尺度因素，但后者通常会同时影响值梯度。结构化观察误差比只看最大差值更能缩小问题范围。

<a id="attention-3-detail-65"></a>

### 10.17 中心差分为什么不能无限减小步长

**题目。** 用双精度中心差分验证梯度，步长越小是否越准确？

**解析。** 不是。较大步长带来截断误差，过小步长使两次接近的函数值相减，舍入误差被除以微小步长放大。应在合理范围扫描步长，选择误差稳定的区间，并避免跨越离散掩码变化或不光滑点。方向差分适合小型确定性输入，不能直接在随机丢弃每次不同的函数值上使用。应先关闭随机性，再解释差分与反向的关系。

<a id="attention-3-detail-66"></a>

### 10.18 参考一致为何仍可能泄漏答案

**题目。** 手写层与参考层所有前向反向都一致，是否可以保证整个预测协议合法？

**解析。** 不可以。两边可能使用同一张错误掩码，也可能输入中已经包含目标标签或未来统计。参考层只保证执行传入的算子，不知道业务信息何时可用。还要独立检查标签对齐、预处理与记忆构建，并用未来扰动和样本隔离测试验证。实现正确性与实验设计正确性是互补要求，任何一项缺失都可能让性能数字失去意义。

<a id="attention-3-detail-67"></a>

## 11. 形成一份可以继续扩展的实现说明

<a id="attention-3-detail-68"></a>

### 11.1 参数映射应与模型一起保存

当手写模块用于替换参考层时，最有价值的交付材料之一是参数对应表：每个查询键值块来自哪里、偏置顺序是什么、头顺序怎样排列、输出映射采用什么方向。表中还应注明模型宽度、头数、输入布局和版本。仅保存一份数值权重而不保存这些解释，后来加载成功也可能运行不同函数。

兼容性不仅包含文件能否读取，还包含输入语义和掩码约定是否一致。若旧模型使用禁止语义，新模块使用允许语义，迁移边界必须转换；若旧接口自动处理键填充，新接口要求最终允许矩阵，调用者也要同步调整。可以把本章的最小对照样本作为兼容性参考，升级后先复验再运行大型任务。

<a id="sec-7-1"></a>

<a id="attention-3-detail-69"></a>

### 11.2 可靠结果需要同时说明通过与覆盖范围

一份准确的验证报告可以写明：在双精度 CPU、关闭随机丢弃、等宽投影、非空合法支持条件下，手写层与参考模块的输出、逐头权重、三路输入梯度及全部投影参数梯度一致；布局编号和两种故障对照也按预期表现。随后列出尚未覆盖的缓存、低精度和其他输入维度，作为后续扩展的工作边界。

这种报告并不是削弱成果，而是让读者知道哪些结论有直接证据，哪些仍需进一步实验。尤其在研究实现中，明确边界能避免下游把教学代码直接当作所有功能都完备的训练库。下一章可以在这个可信参考之上研究精确分块、稀疏近似和位置变换，仍然保留本章的参数身份、微分与故障验证思想。

<a id="attention-3-detail-70"></a>

还可以保存一个极小的固定输入及期望输出作为版本回归样本，但它只能检查有限行为，不能替代完整参数映射。若修改了头布局、偏置或归一化位置，应先判断属于兼容重构还是模型定义变化：前者应保持参考结果，后者需要新版本说明和重新验证。把两类修改分清，能避免为了保留旧输出而压制合理研究，也能避免把无意错误包装成架构创新。每次扩展都应保留已有通过的局部性质，再新增针对变更的证据。
