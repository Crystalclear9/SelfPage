## 1. 训练预算是一个多维对象

一轮训练表示读过一次定义的数据集合，一次优化更新表示参数发生一次更新，微批表示一次前反向计算的输入，词元表示具体分词器生成的离散单位。四者没有普遍固定换算关系。改变数据去重、序列长度、批量、梯度累积或分词器，会改变相同轮数或更新数背后的信息与计算。对比两个系统时应列出这些量，而不能凭“都训练十轮”认定机会相同。

有效监督词元、实际处理位置和独立内容也不是同一量。填充占用数组和某些计算，却不参与损失；提示上下文可能参与前向但不被监督；同一文本重复十次增加曝光，却不创造十份独立内容。训练报告应至少区分原始数据规模、去重后的内容、监督词元、处理位置、更新与总计算时间，并说明搜索和失败运行是否计入。否则“样本效率提升”可能只是换了计数方法。

<a id="transformer-4-detail-2"></a>
### 1.1 从全局批量推导曝光数量

假设每个数据并行工作进程每微批八条序列，四个工作进程，每次更新累积四个微批，则每次全局更新处理一百二十八条。若平均每条有五百一十二个有效监督词元，每次更新监督六万五千五百三十六个位置，一万次更新共六亿五千五百三十六万个。这里假定每个微批足够完整且平均长度稳定，末批和无有效目标批次应按实际计数修正。

如果数组长度统一为一千零二十四，同一运行每更新实际放入十三万一千零七十二个位置，监督利用率只有一半。这并不意味一半时间必然浪费，因为底层内核可能利用变长结构，也可能仍对整块计算。计数利用率与硬件利用率需要分别测量。将有效分母翻倍不会让模型凭空获得更多真实标签，它只改变你报告的口径。

<a id="transformer-4-detail-3"></a>
### 1.2 相同 token 也未必相同数据机会

两个分词器可以把同一句文本编码成不同数量的词元，因此跨分词器比较时，训练词元和困惑度都不能直接当共同尺度。可以额外给出原始字节、字符或固定评价文本上的总负对数似然，并说明编码条件。即便分词器相同，不同数据质量、重复率、领域与时间覆盖也会改变每个词元的价值。固定曝光数量不是自动消除数据差异的控制变量。

实验设计要先决定想回答哪个问题。若比较结构在共同数据上的计算效率，可以固定内容与评价分布，分别记录真实计算；若比较数据配方，就应承认输入信息改变，报告来源与清洗边界。将更高质量数据与新结构同时替换后获得提升，只支持整个方案，不能把收益全归到其中一个名字。清楚描述改变，比强行宣称所有条件完全公平更有用。

<a id="transformer-4-detail-4"></a>
### 1.3 学习率调度到底按什么时间走

调度器可按更新、已见词元或样本推进，选择应与研究目标一致。采用梯度累积后，若仍在每个微批推进原本按更新设计的调度，学习率会提前衰减；若许多批次因无目标而跳过更新却继续计时，也可能改变有效训练路径。日志应保存实际完成更新数、有效监督数量和当前学习率，而不只记录外层循环下标。

对不等长序列，固定更新数可能对应波动的词元曝光。按词元调度可对齐某一预算维度，却不保证相同参数轨迹，因为批内组成、梯度噪声和归一化层统计仍会改变。把进度轴定义清楚，不意味着所有算法因素都等价；它的价值是让比较知道已经控制什么、还没有控制什么，而不是给一种调度单位加上普遍最优标签。

<a id="transformer-4-detail-5"></a>
## 2. 不等长微批的梯度与文档打包

若一次逻辑更新的有效总数为 $D=\sum_j D_j$，第 $j$ 个微批损失和为 $S_j$，目标是 $L=\sum_jS_j/D$。对各微批分别反向 $S_j/D$，累积得到完整目标梯度；若先求微批均值再除微批数，得到的是微批等权目标。当 $D_j$ 不同时，两者一般不同。差异不是一个统一常数，所以不能只靠改全局学习率修复。

<a id="transformer-4-detail-6"></a>
### 2.1 实验一：完整批与加权微批的梯度一致

下面回归算例用两条与五条有效记录组成两个微批。先在全部七条上求均值，再按全局分母累积，并构造错误的微批等权路径。它直接比较参数梯度，避免把不同训练后结果混入目标审查。实际系统还需考虑随机层、累积清零、优化器步数和分布式平均；本实验只证明当前确定性线性目标的归约等价。

```python
import torch

dtype = torch.float64
x = torch.tensor([1., 2., 3., 4., 5., 6., 7.], dtype=dtype)
y = torch.tensor([0., 0., 2., 2., 2., 2., 2.], dtype=dtype)
w = torch.tensor(.3, dtype=dtype, requires_grad=True)
full = ((w*x-y)**2).mean()
g_full, = torch.autograd.grad(full, w)
w2 = w.detach().clone().requires_grad_()
for part in (slice(0, 2), slice(2, 7)):
    (((w2*x[part]-y[part])**2).sum()/len(x)).backward()
assert torch.allclose(w2.grad, g_full)
w3 = w.detach().clone().requires_grad_()
for part in (slice(0, 2), slice(2, 7)):
    (((w3*x[part]-y[part])**2).mean()/2).backward()
assert not torch.allclose(w3.grad, g_full)
print('full / weighted micro / wrong equal micro gradients:',
      g_full.item(), w2.grad.item(), w3.grad.item())
```

<a id="transformer-4-detail-7"></a>
### 2.2 打包需要说明文档之间是否独立

将多个短文档放入一个固定块可以减少填充，但必须决定后一文档是否允许读取前一文档。若目标定义为独立文档似然，通常需要阻断跨文档读取，重置或明确规定位置，并避免把前一文档末尾预测后一文档首词当成普通监督。若目标本来是连续文本流，允许跨边界也可成立，但它已是另一分布假设。插入分隔符不自动从数学上阻断注意力。

例如两文档各三位，拼接后普通因果矩阵允许第四位读取前三位；块对角因果矩阵则不允许。两种数组长度和监督数量可以完全相同，模型使用的信息却不同。位置重新从零编号又不等于掩码阻断，因为内容路径仍可能互通。完整协议应分别定义边界可见性、位置、首词条件和损失掩码，不能把“已打包”当作这四项都正确的缩写。

<a id="transformer-4-detail-8"></a>
### 2.3 实验二：对角因果边界与单文档计算等价

实验把长度三和二的两个文档拼在一个五位置张量，只计算无位置偏置的单头注意力。按照相同文档身份且键不晚于查询的规则生成可见矩阵，结果应与两篇分别计算后拼接一致。普通因果矩阵会让第二篇读到第一篇，通常得到不同输出。这个实验验证读取边界，不代表自动处理真实分词、结束符和损失构造。

```python
import math
import torch

torch.manual_seed(58)
x = torch.randn(5, 4, dtype=torch.float64)
doc = torch.tensor([0, 0, 0, 1, 1])
index = torch.arange(5)
causal = index[:, None] >= index[None, :]
allowed = causal & (doc[:, None] == doc[None, :])
def attention(a, mask):
    score = a @ a.T / math.sqrt(a.shape[-1])
    return score.masked_fill(~mask, -torch.inf).softmax(-1) @ a
packed = attention(x, allowed)
a = attention(x[:3], torch.ones(3, 3, dtype=torch.bool).tril())
b = attention(x[3:], torch.ones(2, 2, dtype=torch.bool).tril())
assert torch.allclose(packed, torch.cat((a, b)), atol=1e-12, rtol=1e-10)
leaky = attention(x, causal)
assert not torch.allclose(leaky[3:], b)
assert allowed.sum().item() == 9 and causal.sum().item() == 15
print('packed allowed pairs / ordinary causal pairs:',
      allowed.sum().item(), causal.sum().item())
```

## 3. 从矩阵乘法推导训练与推理成本

先规定一次乘加记为两个浮点操作。一个输入宽度 $a$、输出宽度 $b$ 的线性层，对 $m$ 行输入做主矩阵乘，前向约需 $2mab$ 次操作；输入梯度和权重梯度各有同阶矩阵乘，因此训练前反向主成本约为前向的三倍。若把主要线性参数数目记为 $N$，处理的训练位置总数记为 $D$，会得到常见近似 $C\approx6ND$。它忽略注意力平方项、非线性、归一化、输出头处理方式、重算及通信等，不是任意 Transformer 的精确公式。

<a id="transformer-4-detail-10"></a>
### 3.1 何时近似会开始误导

固定模型宽度而上下文增加时，线性投影与前馈随长度一次增长，稠密注意力的查询键和权重值乘积随长度平方增长。此时只按参数数量乘词元数估算，会漏掉越来越重要的项。长词表输出头、稀疏专家激活比例、跨设备通信和激活重算也可能破坏简化口径。估计式应附上假设和遗漏，再与真实分析器、时间及内存测量对照。

在一层标准多头自注意力中，模型宽 $d$、长度 $n$、批量 $B$，四个宽度投影的前向主成本约为 $8Bnd^2$，两次注意力矩阵乘约为 $4Bn^2d$。若前馈中间宽 $f$，两层前馈约为 $4Bndf$。这里没有把因果三角自动当成恰好节省一半，因为实际内核可能计算、跳过或分块处理的方式不同。数学可见对数与执行算量应分开记录。

<a id="transformer-4-detail-11"></a>
### 3.2 用边际收益推导一个理想预算分配

为了理解模型规模和数据量的取舍，可自行设教学近似 $\mathcal L(N,D)=L_\infty+aN^{-\alpha}+bD^{-\beta}$，其中系数与指数都为正。固定理想预算 $C=kND$，代入 $D=C/(kN)$，对 $N$ 求导，得到 $\alpha aN^{-\alpha}=\beta bD^{-\beta}$。于是最优规模随预算按 $N\propto C^{\beta/(\alpha+\beta)}$、数据按 $D\propto C^{\alpha/(\alpha+\beta)}$ 增长。这是所设函数内部的最优化，不是未经拟合就适用于所有模型的自然定律。

如果指数相等，两者对预算呈平方根关系；若指数不同，比例也不同。真实实验还受可用高质量数据、推理成本、内存和延迟限制。某个训练计算最优点可能需要过大的部署模型，未必是端到端生命周期最优。相关规模研究提供有用经验，但应用时应重新明确数据范围、拟合误差和目标，而不能把一个固定词元参数比当成永久通用配方。

<a id="transformer-4-detail-12"></a>
### 3.3 训练最优与服务最优为什么分离

假设两个模型达到相近质量，一个训练成本低但参数多，另一个训练较贵却推理便宜。若未来服务请求很多，总生命周期成本可能更偏好第二个；若只是一次研究验证，训练效率可能更重要。目标可写成训练成本加预期请求数乘单请求成本，再加内存或延迟约束，但各项权重来自实际需求，不能把不同单位直接相加。

此外，服务质量不只是一项平均损失，可能有长上下文、约束输出、特定领域和尾部延迟要求。规模拟合通常只覆盖某些观测范围，外推到全新架构或数据配方时不确定性会增大。严谨报告把经验曲线、优化模型和实际部署决策分开：前者是数据，第二个是简化推理，最后一个还需要目标负载与约束的证据。

## 4. 预填充与逐步解码为什么有不同瓶颈

预填充同时处理提示中的许多位置，建立每层历史键值，并产生首个待生成位置的分布。逐步解码每次只添加一个或少量查询，读取历史缓存，再执行当前符号的投影和前馈。在同一模型中，两阶段使用的权重相同，但可并行行数、历史读取量和内存访问方式不同。一个提高预填充速度的优化，不必同样改善持续解码。

<a id="sec-4"></a>
<a id="transformer-4-detail-14"></a>
### 4.1 没有缓存、带缓存和窗口裁剪是三种对象

每步完整重算前缀会重复计算历史位置；正确缓存保存各层不再随未来改变的键值，减少重复，而仍读取需要的历史。窗口裁剪则只保留最近部分内容，改变可见信息，通常不是精确等价优化。若把三者都叫缓存加速，就会掩盖质量问题来自实现、数值还是信息删除。优化声明应明确是等价执行、数值近似还是模型/上下文改变。

普通目标因果模型中，历史状态不读取未来，所以扩展前缀后可复用；双向编码器若追加源内容，旧位置可能改变，不能直接使用同一假设。即便目标因果结构正确，已有前缀内容编辑、位置规则改变、模型权重更新或缓存身份混乱也会使旧缓存无效。状态是否可复用，是一个关于完整计算依赖的命题，不是张量已经放进字典就成立。

<a id="transformer-4-detail-15"></a>
### 4.2 算量降低不必等比例降低时间

粗略下界可用 $t\gtrsim\max(F/P, M/W)$ 表示，其中 $F$ 为操作数、$P$ 为可用计算吞吐、$M$ 为必须传输的字节、$W$ 为相应带宽。这个理想界还未加内核启动、排队、同步和通信。减少乘法次数若没有减少主导的数据移动，墙钟收益可能很小；反过来融合减少中间写回，即使算量近似不变，也可能有实际收益。

单请求解码每步输入行数少，权重读取难以像大矩阵一样充分摊销；增加批量可改善复用，却增加缓存与请求等待。在某个形状、精度和硬件上是带宽主导，不意味所有解码都必然如此。应先估计再测量，不用“计算受限”或“带宽受限”充当无需证据的标签。实际内核和量化也会改变这两项的相对大小。

<a id="sec-5"></a>
<a id="transformer-4-detail-16"></a>
## 5. KV 内存账本：容量与实际分配分开

设层数为 $L$，批量为 $B$，每条当前缓存长度为 $n$，键值头数为 $H_{kv}$，每头维度为 $d_h$，每元素字节为 $s$。同时保存键和值时，理想稠密缓存为 $2LBnH_{kv}d_hs$ 字节。这个公式不含页表、对齐、碎片、预分配空位、请求元数据和临时工作区。它是有用的内容下界，不是显存监控工具必然显示的精确值。

<a id="transformer-4-detail-17"></a>
### 5.1 一个可以复算的具体容量

取二十四层、四请求、每条四千零九十六位置、八个键值头、头维六十四、每元素两字节。理想缓存为八亿零五百三十万六千三百六十八字节，除以二的三十次方得到零点七五 GiB，即七百六十八 MiB。若查询头有三十二，改用同数键值头则缓存变为三 GiB。这是在固定层、批、长度、头维和表示字节时的四倍关系，不表示模型质量或总推理时间也有四倍关系。

分组查询共享键值头可以减少缓存和某些投影，但它改变模型参数化与读取结构。把已有普通多头模型的键值简单平均后使用，不应未经训练和质量验收就称作精确替代。另一方面，数值量化减少每元素表示，页面管理减少未利用分配，两者改变的层次又不同。报告中分别写清头结构、数值格式和分配策略，才知道内存收益从何而来。

<a id="transformer-4-detail-18"></a>
### 5.2 变长批量与预留容量

若请求长度不同，理想内容数量按各请求长度求和，而统一稠密数组常按批次最大长度乘请求数分配。提前为最大窗口全部预分配，会使短请求在监控中也占据大量保留容量；分页或动态管理可以改善利用，但仍有颗粒、元数据和调度成本。保留内存、实际活跃张量字节和有效缓存内容不是同一个计数，需要相应工具和定义。

模型权重、优化器、激活和缓存又属于不同阶段。训练常要保存反向信息和优化器状态，推理虽没有这些，仍有权重、缓存和工作区。不能拿训练峰值直接减掉优化器就预测推理峰值，也不能只算缓存就判断模型一定能运行。算账先列各对象生命周期，再按是否同时存活合并；依次存在的临时张量不应无条件相加成峰值。

<a id="transformer-4-detail-19"></a>
### 5.3 实验三：整数字节与形状账本

此实验仅用整数计算，并用一个很小的真实张量核对元素字节。它不申请大缓存，也不把公式当作实际显存读数。顺便核对有效监督利用率以及前述训练词元曝光，使读者能够区分十进制 GB 和二进制 GiB。单位错误可能造成数值上几个百分点的差异，结构假设错误则可能造成数倍差异，都应在测量前排除。

```python
import torch

def kv_bytes(layers, batch, length, kv_heads, head_dim, item_bytes):
    assert min(layers, batch, length, kv_heads, head_dim, item_bytes) > 0
    return 2*layers*batch*length*kv_heads*head_dim*item_bytes
shared = kv_bytes(24, 4, 4096, 8, 64, 2)
full = kv_bytes(24, 4, 4096, 32, 64, 2)
assert shared == 805306368 and shared/2**30 == .75
assert full == 4*shared and full/2**30 == 3
small = torch.empty(2, 3, 5, 4, 7, dtype=torch.float16)
assert small.numel()*small.element_size() == 2*3*5*4*7*2
supervised = 8*4*4*512
processed = 8*4*4*1024
assert supervised == 65536 and supervised/processed == .5
assert supervised*10000 == 655360000
print('KV GiB shared / full:', shared/2**30, full/2**30)
print('supervised / processed per update:', supervised, processed)
print('1 GB in GiB:', 10**9/2**30)
```

## 6. 优化分类：等价执行、数值近似与结构变化

精确分块注意力通过重新组织中间量减少读写和峰值存储，数学目标仍是同一稠密 softmax 注意力；浮点计算顺序变化可能产生容差内差异。稀疏注意力限制读取集合，改变信息路径；低秩或核近似则以另一计算形式近似目标。量化改变数值表示，分组查询改变头共享结构。它们都可能有价值，但其正确性目标并不一样，不能用一个“加速比”替代质量与机制说明。

<a id="transformer-4-detail-21"></a>
### 6.1 量化误差为什么需要看任务裕量

设线性输出为 $z=Wx$，量化后权重为 $W+E$，则单输出误差满足 $|e_i^\top x|\leq\|e_i\|_2\|x\|_2$。这个界说明输入范数与权重误差共同影响 logits，并不直接给出最终准确率。若原最大和次大 logits 相差 $m$，每个 logits 绝对扰动不超过 $\delta$，当 $m>2\delta$ 时最大类别保持；若原本近乎并列，很小误差也可能改变离散预测。

多层网络中误差还会通过后续雅可比传播，激活分布和层敏感性不同，单层界不能直接当整个模型界。概率变化、排序变化和生成长链变化也不是同一指标。量化校准数据应来自合法开发角色，选择位宽、分组和阈值后再评价独立任务，不能反复看测试调配置。节省权重内存未必节省缓存，模型加载成功也不表示目标设备有高效低位内核。

<a id="transformer-4-detail-22"></a>
### 6.2 实验四：逐行对称量化与一个决策翻转反例

下面对每一权重行用自己的最大绝对值确定步长，舍入到有限整数再还原浮点，核对线性误差不超过柯西不等式界。它是量化—反量化的数值模拟，矩阵乘仍在浮点完成，不会给出低位硬件加速。再构造两个极接近的 logits，说明很小绝对扰动仍能交换最大类别，因此“平均误差很小”不是决策一致的充分条件。

```python
import torch

torch.manual_seed(11)
W = torch.randn(6, 7, dtype=torch.float64)
x = torch.randn(5, 7, dtype=torch.float64)
scale = W.abs().amax(dim=1, keepdim=True).clamp_min(1e-12)/7
integer = (W/scale).round().clamp(-7, 7)
reconstructed = integer*scale
error = reconstructed-W
actual = ((x@reconstructed.T)-(x@W.T)).abs()
bound = x.norm(dim=1, keepdim=True)*error.norm(dim=1)[None, :]
assert torch.all(actual <= bound+1e-12)
assert integer.abs().max() <= 7
z = torch.tensor([1., 1.00001], dtype=torch.float64)
z_changed = z + torch.tensor([.00002, -.00002], dtype=torch.float64)
assert z.argmax().item() != z_changed.argmax().item()
assert (z-z_changed).abs().max() < .0001
margin = z.topk(2).values.diff().abs().item()
print('max logit error / bound:', actual.max().item(), bound.max().item())
print('tiny perturbation flips near tie, original margin:', margin)
```

<a id="sec-6-1"></a>
<a id="transformer-4-detail-23"></a>
### 6.3 先建立等价参考，再优化测量

对声明等价的实现，固定模型、输入、位置、掩码、评估模式和精度，逐位置比较 logits；需要时对训练用途再比较梯度。对数值近似，预先设误差容差与任务接受标准，报告失败率而不只给平均误差。对结构或可见性变化，需要重新训练或至少按相应适配方法评价，不得把旧参数上的某个近似输出自动称作同一模型。

速度测量在正确性通过后进行，固定预热、重复、同步、输入输出长度和批量。GPU 操作可能异步，直接用主机计时包住提交调用会漏掉设备工作；真实测量需用合适同步或设备事件，并说明包含哪些阶段。本章没有 GPU 设备实验，因此只讲方法和成本边界，不给出臆造的设备加速数字。换硬件、精度或内核后必须重新测量。

<a id="transformer-4-detail-24"></a>
## 7. 首 token、持续解码与排队是不同延迟

用户从请求到首个有效输出的时间包括排队、输入处理、预填充和首步生成；后续每词元间隔反映持续解码与调度；端到端时间还受输出长度和停止影响。服务吞吐表示一段时间完成的请求或词元数，不能直接当单请求延迟的倒数。并发系统中，同一批请求可能等待较久却同时完成，使高吞吐与某些较差交互体验并存。

<a id="transformer-4-detail-25"></a>
### 7.1 时间边界和分位数需要精确定义

首词元时间从客户端发送、服务接收还是进入设备开始计，得到的数字不同；报告必须指出边界。持续速度是否排除首词元、是否包括客户端网络，以及流式缓冲是否合并多词元，也影响可比性。对完成请求计算平均速度还可能排除超时和取消，形成幸存者偏差。应报告覆盖、失败和截断，而不只从成功请求中挑一个漂亮均值。

分位数揭示长尾，但需要足够请求和对应负载。一个单请求重复计时的九十九分位数，不等于真实多用户负载下的服务九十九分位数。稳态到达率、突发模式、提示和输出长度联合分布都会改变队列。若只想测设备内核，就明确这是离线固定形状测量；若想评价交互服务，就加入排队和真实请求生命周期，避免把两种对象混称“延迟”。

<a id="sec-2-1"></a>
<a id="transformer-4-detail-26"></a>
### 7.2 实验五：一个透明的批处理调度模型

为隔离吞吐与等待，构造二十个在零时刻同时到达的请求。方案甲每请求服务四毫秒、串行完成；方案乙每批四个、整批十毫秒完成。服务时间是人为给定的模拟参数，不来自某设备实测。甲第一个请求四毫秒完成，乙十毫秒；乙最后一批五十毫秒完成，甲八十毫秒。可见更高总吞吐仍可能让最早请求等待更久。

```python
import numpy as np

requests = 20
serial = np.arange(1, requests+1, dtype=float)*4
batched = np.repeat(np.arange(1, requests//4+1, dtype=float)*10, 4)
assert len(serial) == len(batched) == requests
assert serial[0] == 4 and batched[0] == 10
assert serial[-1] == 80 and batched[-1] == 50
throughput_a = requests/(serial[-1]/1000)
throughput_b = requests/(batched[-1]/1000)
assert throughput_b > throughput_a
assert batched[0] > serial[0]
print('simulated requests/s serial / batched:', throughput_a, throughput_b)
print('first / mean / last completion ms serial:', serial[0], serial.mean(), serial[-1])
print('first / mean / last completion ms batched:', batched[0], batched.mean(), batched[-1])
```

<a id="transformer-4-detail-27"></a>
### 7.3 模拟能说明什么，不能说明什么

这个模型证明一种关系在逻辑上可能发生，不能预测实际服务的最优批量。真实批服务时间不是固定常数，会随长度、缓存、并发、内核和资源竞争变化；到达也并非总在零时刻。若要部署决策，需要用真实或代表性负载标定服务时间，再验证队列模型。先理解机制，再收集数据，比直接把示例数字当基准更可靠。

连续批处理允许请求完成后及时替换位置，减少长短输出不齐的空耗；但需要维护每个请求的缓存身份、位置、结束和取消状态。调度改进若把别人的缓存读到当前请求，就算吞吐很高也未实现同一预测函数。性能测试之外，应同时做请求置换、提前结束、部分取消和缓存复用隔离的正确性检查，避免只在所有请求等长的容易情形下通过。

<a id="sec-3"></a>
<a id="transformer-4-detail-28"></a>
## 8. 长上下文：能接收、能计算与能使用

一个接口接受某个最大长度，说明索引和配置允许；设备能完成运行，说明当前内存与计算负担可承受；模型能正确使用远处证据，则是统计任务能力。三者既有关联又不等价。仅展示没有报错或一条成功回答，不能支持整个窗口内可靠检索、计数、跨文档推理和冲突消解等多种主张。

<a id="transformer-4-detail-29"></a>
### 8.1 建立有控制的证据位置实验

固定问题和正确证据，把证据放到开头、中间、末尾，并独立改变无关内容数量。使用同一问题的配对版本，可以减少题目难度差异；但同一模板产生的多条变体不应当作完全独立题目来计算过窄区间。再增加相似干扰、冲突版本和多片证据需求，分别检验定位、筛选和整合。位置、长度和干扰要尽量分开控制。

评分前确认原始证据是否真的进入模型输入。字符层文档在场，不意味分词、截断和模板拼接后仍在窗口中；检索候选存在，也不等于最终提示包含了它。若前处理丢掉正确证据，主要问题是输入构造；若证据清楚在场仍失败，才进一步研究模型利用。日志应保存最终 token 级可见输入或足以重建的记录，不能只保留原始文档长度。

<a id="transformer-4-detail-30"></a>
### 8.2 实验六：容量不等于证据可见性

此例不用语言模型，而使用确定性读取器检查评价设计。长度一百的记录中仅一个标记携带答案，放在五、五十、九十五位置。完整读取器都能找到，保留前十二或后十二位置的窗口则有不同成功位置。这个反例说明接口数组长度相同，不保证不同前处理策略拥有相同证据；它不测量任何 Transformer 的真实长距离能力。

```python
positions = (5, 50, 95)
def read(records):
    found = [v for kind, v in records if kind == 'answer']
    assert len(found) <= 1
    return found[0] if found else None
rows = []
for pos in positions:
    records = [('noise', i) for i in range(100)]
    records[pos] = ('answer', 17)
    rows.append((pos, read(records), read(records[:12]), read(records[-12:])))
assert [r[1] for r in rows] == [17, 17, 17]
assert [r[2] for r in rows] == [17, None, None]
assert [r[3] for r in rows] == [None, None, 17]
print('position / full / head-window / tail-window:', rows)
```

<a id="transformer-4-detail-31"></a>
### 8.3 从证据在场到多段信息整合

单一醒目标记任务容易被局部模式解决，成功不必代表跨文档推理。更强任务可以要求两个位置提供的数字相加、按版本时间选择最新有效规则，或将实体标识跨段连接。要避免答案直接出现在某个固定模板位置，也避免问题词与唯一标记之间有过于明显的捷径。生成器本身需要审查，否则模型可能绕过研究者想测的能力。

冲突版本任务必须定义采用哪份证据、时点和优先级。没有清楚规则的题，模型给出不同答案未必是能力差，可能是题目不可判定。评价应允许有证据的拒答或明确标记冲突，不能强迫从缺失信息推断唯一答案。长上下文研究不只加长数组，还要确保问题、证据、评分和实际可见信息构成一致契约。

<a id="transformer-4-detail-32"></a>
## 9. 一份质量—资源联合研究协议

先定义研究对象，例如在同一批合法问题上达到某个质量下限，同时满足延迟与内存约束。候选可能是精确缓存实现、量化格式、共享键值结构或检索压缩方案。不同候选改变的层次不同，但都要回到完整函数、数据角色和资源测量。报告中清楚列出哪些输入信息相同、哪些参数重新训练、哪些数值改变，比给所有候选贴上一个笼统“优化”标签更有解释力。

<a id="transformer-4-detail-33"></a>
### 9.1 固定质量比较成本与固定成本比较质量

固定质量比较成本时，需要事先定义质量门槛及验证方法，筛掉不满足者后再比较资源；若只按每个模型最好看的某一指标达标，实际门槛可能不一致。固定成本比较质量时，需要明确成本是训练计算、端到端时间、峰值内存还是服务预算，并把候选搜索开销纳入所选口径。两个问题都合理，却不能把不同控制条件下的数字直接排在同一优劣榜。

如果有多个质量或资源指标，可以先展示帕累托关系：某候选在全部关心维度不差且至少一个更好，才称支配另一个。互有优劣时，由任务需求决定取舍，不能无声地把准确率、毫秒和字节直接求平均。实际需求若设置硬约束，还应报告哪些候选违反约束；一个均值很好但尾延迟超标的方案，可能根本不属于可行集。

<a id="transformer-4-detail-34"></a>
### 9.2 配对评价与独立单位

对同一问题同时运行两个系统，保存逐题差值，可以控制题目难度差异。若一个基础问题生成多个位置变体，重采样应优先以基础问题或真实独立来源为单位，保留相关变体在同一组，而不是把每个位置版本当独立观察。若请求来源于会话或用户，评价单位还可能上升到会话或用户；“每行都有一个答案”不自动意味着每行独立。

延迟也可以做配对实验，但共享设备上的先后运行可能受到温度、缓存、后台负载和预热影响。随机化候选顺序、使用相同负载和足够重复有助于辨别真实差异。若两个系统并发争用同一设备，又会改变各自资源环境；应明确是在单独基准还是共同负载下比较。统计区间不能补救测量对象本身不一致的问题。

<a id="transformer-4-detail-35"></a>
### 9.3 搜索、重复使用验证与最终冻结

位宽、分组大小、批量、窗口和调度参数都可能被反复选择，选择使用了验证标签或测量反馈。即便优化没有反向传播，候选也已适应开发集。最终测试应该在配置冻结后进行，并报告搜索机会。一次显著改进如果来自大量隐藏尝试，可信度和可复现性与只比较事先两个候选不同，需要让读者看见完整选择过程。

测试后发现失败当然可以继续研究，但那批数据从此成为开发信息，应再保留独立确认。不要为了维持“测试只用一次”的表述而不记录看过的失败。更好的实践是维护版本化实验记录，说明问题发现、候选修改和最终核验分别使用哪些数据。学习教材中的小实验也应遵守这种角色清晰原则，避免在微型例子上养成隐含挑选结果的习惯。

<a id="transformer-4-detail-36"></a>
## 10. 长度外推的四种竞争解释

长输入失败可能来自证据被截断、位置表示超出熟悉范围、干扰使检索失败，或任务需要多段整合而模型只会局部匹配。这些解释可以同时存在。若只观察长输入准确率下降，不能唯一识别原因。应构造能够区分它们的干预，而不是一看到曲线下降就宣布位置编码失效或模型缺少记忆。

<a id="transformer-4-detail-37"></a>
### 10.1 先测可见，再测定位，最后测整合

可见性检查直接核对最终输入包含哪些证据；定位任务让一个明确证据给出答案；整合任务要求多个证据共同决定结果。三个阶段逐步增加难度，分别报告。若定位也失败，先研究位置和干扰；若定位成功而整合失败，可以更有针对性地研究关系组合。把所有类型混成一个“长上下文分数”，会让改进不知道究竟解决了哪一环。

可进一步设置无答案和矛盾答案条件。无答案条件检查模型能否承认可用信息不足，避免模型总按模板猜一个值也获得表面成功；矛盾条件检查规则和版本处理。这里仍需明确题目是否确有唯一答案，评价不能把研究者未说明的优先规则藏在评分程序里。一个好的生成器应同时输出证据角色、正确推理和可见性记录，便于发现错误标签。

<a id="transformer-4-detail-38"></a>
### 10.2 位置缩放改变几何，不能免费承诺能力

修改位置机制或频率尺度可以让更长索引进入计算，改变不同距离之间的相似性。但模型参数是在某种位置分布下学到的，改变表示可能同时影响短距离与长距离。验证应既测新长度，也回归原长度，尤其关注局部次序、精确检索和停止。接口容量扩展是一项实现事实，能力改善需要任务证据，两者不应合并成一个无条件承诺。

如果继续训练以适配更长序列，增加的数据、计算与优化步骤也属于候选方案。不能拿“改一个配置再额外训练大量数据”的结果，全部归功于配置本身。可以分开比较不训练直接改变、相同额外训练保持原设置、额外训练配新设置三条流程，帮助识别适配数据和位置修改的作用。它们仍需共同评价信息和预算。

<a id="transformer-4-detail-39"></a>
### 10.3 压缩、检索和滑窗如何改变信息目标

压缩把原文映射为较短表示，可能丢失问题所需细节；检索选择部分文档，可能漏掉关键证据；滑窗丢掉远处历史。它们可以大幅节省成本，但不是一般意义上的精确替代。评价应分别给证据召回与给定正确证据时的回答质量，区分上游筛选失败和下游利用失败。仅在筛选成功的样本上报告很高回答率，会遗漏真实端到端损失。

如果用户问题在压缩后才到达，还需区分与问题无关的通用压缩和针对当前问题的选择。后者拥有额外条件，不能将其优势解释为纯表示压缩能力。压缩器或检索器若使用答案标签训练，也要纳入合法训练边界。沿所有中间模块追踪信息来源，比只审查最终生成模型是否见过测试标签更可靠。

<a id="transformer-4-detail-40"></a>
## 11. 从执行计划到内存峰值的进阶分析

中间激活是否保存、何时释放和是否重算，会影响训练内存与时间。激活检查点用更多前向重算换较少长期保存，目标是在相同随机与状态条件下保留所需梯度；它不是删除层或截断反传。若重算期间随机掩码、状态更新或外部副作用不同，可能不再执行同一计算。使用时要查清具体接口的重算与随机状态政策，并用小例做梯度对照。

<a id="transformer-4-detail-41"></a>
### 11.1 内存峰值来自同时存活的对象

假设两大中间张量从不同时存在，其字节和大于实际峰值；若框架保留自动微分引用，它们又可能比源代码直觉存活更久。缓存管理、分配器保留和碎片还会让设备保留量高于活跃张量和。分析时先画生命周期，再用实际内存工具核对，不能只把源码中出现的所有数组相加，也不能只看最终权重文件大小。

推理启用不求导可减少反向图保存，但并不会自动消除所有临时矩阵、缓存或Python引用。每步把 logits、注意力图或全部隐藏状态追加到列表，仍会让内存随生成增长。性能排查应明确哪些输出确实需要返回，哪些只用于调试；测量调试版与正式版时说明功能差异，不把删除用户需要的输出也算成等价优化。

<a id="transformer-4-detail-42"></a>
### 11.2 服务缓存共享需要完整身份契约

前缀缓存命中要求相关输入、模型版本、位置规则、提示模板和数值配置相容。仅比较原始文本前几个字，可能漏掉系统提示、特殊符号或不同分词结果。请求取消与缓存回收还需避免仍在使用的状态被覆盖。正确性验证可以对同一前缀不同续写、同一文本不同版本和并发交错请求做对照，确保共享只发生在合法身份之间。

共享命中还会改变测量分布。只测重复前缀的热缓存吞吐，再与全新请求的冷启动基准比较，不能把差异全归于内核。报告应给命中率、提示长度、缓存建立和维护成本，并说明测量包含哪些阶段。缓存收益取决于负载复用，而不是对所有输入都存在的常数倍加速；在无复用场景中，维护成本甚至可能抵消部分好处。

<a id="transformer-4-detail-43"></a>
### 11.3 保留一条慢而清楚的参考路径

为缓存、分块、量化和调度保留小规模参考实现，可以在工程重构后发现位置错位、掩码反转、请求串线和停止错误。参考不要求在大负载上高效，但应该足够独立，避免与优化实现共享同一段有问题的索引逻辑。两份代码如果复制同一个错误，即使输出一致也不能证明正确；手算和性质干预提供额外证据。

参考路径的容差也应随目标区分。精确数学实现看数值误差与决策；训练用途看梯度；近似方案看任务质量；调度方案还看请求身份和生命周期。只有明确验收对象，才能知道一次失败应修数值、改结构，还是重新定义目标。把所有差异压成一个布尔“通过”会丢掉关键诊断信息，研究记录应保留差异大小和触发条件。

<a id="transformer-4-detail-44"></a>
## 12. 二十道进阶练习与逐题解析

<a id="transformer-4-detail-45"></a>
### 12.1 相同一万步是否就是相同训练预算

**问题：** 两个系统都更新一万次，为什么还需要批量和有效长度？

**解析：** 每步曝光等于实际全局批量与有效监督数量之和。一个每步监督六万位置，另一个三万，同步数下数据曝光已经不同；模型宽度、注意力长度和重算又决定实际计算。应分别报告有效词元、处理位置、参数与计算、时间和选择开销。固定一种预算维度可以回答特定问题，却不能同时声称全部维度相同。对比前先选研究目标，再检查其他变化是否构成混淆。

<a id="transformer-4-detail-46"></a>
### 12.2 从局部微批算出全局曝光

**问题：** 每进程八条、四进程、累积四次、平均监督长度五百一十二，一万更新看多少词元？

**解析：** 全局每更新八乘四乘四等于一百二十八条，乘五百一十二得六万五千五百三十六，再乘一万得六亿五千五百三十六万。这个计算不把同一条重复曝光当新独立内容，也不假定每批长度恰好平均。真实运行应累积实际分母，并记录末批、空批和过滤；若按填充后长度计算，则回答处理位置而非有效监督数量。

<a id="transformer-4-detail-47"></a>
### 12.3 两微批均值直接平均为什么不对

**问题：** 两个微批有效数二和五，求各自均值后除二，有什么隐含目标？

**解析：** 每个微批总权重相同，因此第一个微批单样本权重为四分之一，第二个为十分之一；完整七样本均值则全部七分之一。它优化微批等权风险，通常不是预设样本等权风险。正确累积可将各分子除全局有效数，或让均值乘各自分母占比。实验一梯度分别约负二点二八六与负一点一五，直接展示两目标并不相同，而不是浮点误差。

<a id="transformer-4-detail-48"></a>
### 12.4 打包后只放分隔符够不够

**问题：** 两篇独立文档之间插结束标记，还需要阻断跨文档读取吗？

**解析：** 分隔符是一种内容，不自动改变可见矩阵。若目标要求独立文档条件，后一文档仍可能通过普通因果注意力读取前一文档，需明确块对角边界、位置与首词损失。若任务定义为连续流，可以允许读取，但要承认目标已不同。实验二相同五位置产生九与十五个可见对，说明数组与词元计数一致并不足以保证信息条件一致。

<a id="transformer-4-detail-49"></a>
### 12.5 六倍参数词元估计什么时候失效

**问题：** 为什么不能用同一公式精确预测任意长度训练成本？

**解析：** 该近似主要计线性参数矩阵的前反向操作，假定主要成本与参数乘处理位置同阶。长序列稠密注意力含长度平方项，重算、输出头、稀疏结构、通信和内核执行也影响实际成本。应列出遗漏并按形状估算额外项，再与真实工具和时间对照。公式在某范围有用，不代表它能自动跨架构、硬件和长度外推；越接近资源约束越需要具体核对。

<a id="transformer-4-detail-50"></a>
### 12.6 理想规模分配为何不是固定配方

**问题：** 教学损失中模型项与数据项指数相等，会得到什么关系？

**解析：** 在固定乘积预算且没有其他约束时，最优模型和数据都随预算平方根增长；系数决定比例。指数改变、数据质量变化、推理成本或可用内存加入约束，最优点都会移动。这个结果来自所设函数与预算假设，并非无条件经验事实。正式使用应拟合目标范围、报告不确定性，再判断简化模型是否足以支撑决策，不能只记一个普遍词元参数比。

<a id="transformer-4-detail-51"></a>
### 12.7 八键值头与三十二键值头缓存差多少

**问题：** 保持层、批、长度、头维和精度，其余不变时内存比例是什么？

**解析：** 缓存公式对键值头数线性，所以三十二是八的四倍，本章例子分别三 GiB 与零点七五 GiB。这里不推断总显存四倍，因为权重和工作区另有大小；也不推断速度或质量四倍，因为结构、复用和内核不同。若把头共享作为候选，应说明模型如何训练或适配，并独立验证任务质量。一个字节账本只能证明对应内容存储的算术关系。

<a id="transformer-4-detail-52"></a>
### 12.8 为什么监控内存大于公式缓存

**问题：** 公式只有零点七五 GiB，设备保留更多是否必然泄漏？

**解析：** 不一定。权重、临时激活、内核工作区、预分配空位、页粒度和分配器保留都可能额外占用。应区分有效缓存内容、活跃张量和设备保留内存，观察对象生命周期及请求结束后的行为。只有排除正常保留政策并发现不应存活的引用持续增长，才更有依据定位泄漏。把一种工具读数与另一种理论口径直接相减，不能自动给出错误结论。

<a id="transformer-4-detail-53"></a>
### 12.9 缓存历史什么时候可以原样复用

**问题：** 追加新目标 token 后，为什么旧状态可能不变？何时会失效？

**解析：** 在因果结构中，历史位置只依赖当时前缀，所以追加未来不改变旧表示。前缀编辑、权重变化、位置规则变化、非法跨请求复用或双向读取都会破坏这个条件。应逐步对比同前缀参考 logits，并核对请求身份和位置，而不只比较最终一条输出。窗口裁剪可能保留部分旧状态但改变可见集合，也不能未经说明宣称与完整历史精确等价。

<a id="transformer-4-detail-54"></a>
### 12.10 参数更少为何不必更快

**问题：** 减少参数或乘法数量后，墙钟时间为什么可能几乎不变？

**解析：** 运行可能受数据移动、内核启动、同步或调度主导，减少非主导算量未必降低关键路径。新结构还可能失去高效矩阵形状，或增加碎片化操作。先用算量与字节下界估计，再在同硬件和负载测量；明确包含预热、数据传输和调度哪些阶段。理论成本用于提出瓶颈假设，实际时间用于核验，两者不能互相替代或只挑有利的一项报告。

<a id="transformer-4-detail-55"></a>
### 12.11 小量化误差为何可能翻转答案

**问题：** logits 平均误差很小，能否保证最高类别不变？

**解析：** 若原第一、第二类接近，两个很小但方向相反的扰动也能交换顺序。充分条件可用原间隔大于两倍最大绝对扰动，平均误差本身不提供该保证。实验四以约万分之零点二的扰动翻转近乎并列类别。多层生成还会把离散选择带到新历史，因此需要任务与序列级回归，不只比较一个局部均方误差。数值接近和决策一致是不同目标。

<a id="transformer-4-detail-56"></a>
### 12.12 反量化浮点模拟能证明硬件加速吗

**问题：** 将整数权重还原成浮点再矩阵乘，测得时间是否代表真正低位计算？

**解析：** 不能。它检验舍入和重建误差，实际乘法仍由浮点内核执行，还可能额外增加转换成本。低位硬件收益取决于压缩存储、内核、设备支持、分组与实际形状，需要对应实现实测。报告应明确模拟只是数值实验，不把有限整数范围当真实存储已打包，也不把文件大小下降直接等同端到端吞吐提高。验证层次需要与所声称结论一致。

<a id="sec-8-2"></a>
<a id="transformer-4-detail-57"></a>
### 12.13 吞吐提高为什么首请求更慢

**问题：** 调度模拟中批处理四百请求每秒优于串行二百五十，为何首请求十毫秒反而差？

**解析：** 批处理让四个请求共享一批十毫秒服务，整体效率提高，但首个请求要等整批完成；串行首个四毫秒就完成。二十请求全在零时刻到达时，批处理均值也更低，却仍不能支配每个请求的延迟。这个反例只说明指标可以有取舍，服务时间是人为参数，不是设备结论。真实决策应使用代表性到达、长度和服务测量，分别看首词元与尾部等待。

<a id="transformer-4-detail-58"></a>
### 12.14 冷请求与热缓存比较有什么混淆

**问题：** 一个基准重复同提示，另一个全新提示，速度差能否全归于实现？

**解析：** 不能，两者命中缓存和建立缓存的工作量不同。应统一命中条件或分别报告冷、热与混合负载，并给实际命中率、提示长度和维护成本。缓存结构优化可以提高复用场景效率，但不保证全新输入同样收益。若未固定模型模板或分词，所谓相同前缀甚至可能不是相同 token。先明确输入身份与生命周期，再测速度，避免混入不同任务量。

<a id="transformer-4-detail-59"></a>
### 12.15 支持十万位置为什么不能保证十万位置推理

**问题：** 接口运行未报错、输出格式正确，仍缺什么证据？

**解析：** 还缺对实际可见证据、位置与干扰的任务验证。能接收说明配置允许，能算完说明当前资源足够，能利用则要求模型正确找到、筛选和整合信息。用配对位置变体与多证据题分开评价，再核对截断后输入。单一成功提示无法支持整个窗口和全部任务；若证据本身被前处理丢掉，首先修输入链，不应直接归罪网络位置能力。

<a id="transformer-4-detail-60"></a>
### 12.16 位置变体能全部当独立题目吗

**问题：** 一百个基础题各生成十个位置版本，是否可直接按一千独立观察给区间？

**解析：** 同一基础题共享语义、答案和模板，错误通常相关，逐行独立处理可能低估不确定性。应按基础题或真实独立来源保留整组变体重采样，并同时报告配对位置差异。有效独立单位由生成和应用过程决定，不由表格行数决定。若后续换成会话数据，还需考虑会话与用户层级，不能机械沿用当前分组。区间假设需要与数据依赖相符。

<a id="transformer-4-detail-61"></a>
### 12.17 检索成功样本上的高回答率缺少什么

**问题：** 只在正确证据被检索出的题目上评价生成器，是否代表完整系统质量？

**解析：** 它是一个有条件的下游指标，遗漏检索失败题目，不能替代端到端成功。应同时给证据召回、给定证据质量和整体任务结果，并说明拒答与覆盖。若检索使用答案标签或测试反馈调节，还要纳入选择边界。拆分指标有助于定位问题，但拆分后必须回到共同总体，不能只展示最容易成功的条件子集来宣称整个系统可靠。

<a id="transformer-4-detail-62"></a>
### 12.18 激活重算与截断反传哪里不同

**问题：** 两者都节省保存内容，是否可以互换？

**解析：** 激活重算尝试在反向需要时恢复原计算，保留完整依赖的梯度；截断反传主动切断部分历史导数，改变梯度估计。重算若随机流或状态副作用不一致，也可能偏离原计算，因此需具体接口和梯度对照。不能仅按节省多少内存把它们归为等价技巧。研究应同时报告数值目标、资源和最终质量，说明节省是用额外计算还是用信息/导数删减换来。

<a id="transformer-4-detail-63"></a>
### 12.19 最快候选为何可能不是可用候选

**问题：** 某方案平均吞吐最高，但尾延迟超约束且长证据题明显退化，如何判断？

**解析：** 若尾延迟和质量是硬约束，它不在可行集，平均吞吐再高也不能直接胜出。先定义应用需求，再比较满足条件的候选，互有优劣时展示帕累托取舍。不得把毫秒、准确率和字节未经权重定义就平均成总分。若需求尚不明确，应保留多维结果供判断，而不是替用户隐藏取舍。评价问题的约束决定“更好”的含义。

<a id="transformer-4-detail-64"></a>
### 12.20 一个最大长度错误应怎样转成研究

**问题：** 模型在中间证据和长干扰条件下失败，应该立即换位置机制吗？

**解析：** 先核对证据经过最终模板与截断后确实可见，再把定位与整合分开，控制位置、长度、相似干扰和重复结构。只有这些竞争解释得到区分，位置改动才成为有针对性的候选。若增加继续训练，应给相同额外预算的对照；配置冻结后再用独立题组确认。一个现象可以对应多个原因，研究价值在于设计排除解释的实验，而非尽快给它一个熟悉标签。

<a id="transformer-4-detail-65"></a>
## 13. 综合研究与交付标准

<a id="sec-8-1"></a>
<a id="transformer-4-detail-66"></a>
### 13.1 用一个共同任务比较三类方案

选择固定问题集，比较完整精确缓存、某种量化和一个有限窗口方案。先在开发区检查参考一致性或允许的数值误差，再评价共同质量指标。对窗口方案另报告证据可见率，承认输入信息改变；对量化另报告位宽、分组和是否真实低位内核。最终配置冻结后，用未参与选择的问题和代表性负载给质量、首词元、持续解码、峰值内存与失败覆盖。

每种候选都保留逐题预测与资源条件，按基础题、长度和证据位置分组。性能差异若只在某个固定长度出现，不应推广成所有负载下更快；质量改善若伴随更多数据和搜索，也要列出额外机会。完成报告应让别人能够重算指标，知道哪些成本是真测、哪些是公式或模拟，以及哪些结论仍需目标设备和真实请求确认。

<a id="transformer-4-detail-67"></a>
### 13.2 本章算例的最终边界

六段实验实际核对了微批梯度、文档可见矩阵、缓存字节、量化误差、模拟调度与前处理证据。它们没有测量某个真实大模型的 GPU 吞吐、在线服务尾延迟或自然语言长距离推理。机制实验和真实基准各有用途：前者帮助排除逻辑与计量错误，后者需要更完整的数据与环境。把两者连成证据链，比让一个小算例承受它无法支持的宏大结论更可靠。
