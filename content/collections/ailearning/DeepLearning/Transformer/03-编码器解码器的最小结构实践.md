## 1. 从条件分布确定两个网络的职责

设源序列为 $`x=(x_1,\ldots,x_S)`$，目标正文为 $`y_1,\ldots,y_L`$，并在末尾附上结束符。条件生成模型描述 $`p_\theta(y_1,\ldots,y_L,\mathrm{EOS}\mid x)`$，按链式法则分解为各位置条件概率的乘积。编码器读取合法的完整源，解码器在每个位置读取源表示和此前目标。这一区分先于具体层数：如果任务允许完整源在生成前到达，编码器双向读取符合契约；如果源本身持续到达，普通双向编码器就不能被原封不动视作在线系统。

训练数据里完整目标已经知道，但用于计算第一个目标概率的输入只能包含起始符，用于第二个目标概率的输入可以再包含第一个真值。教师强制并没有取消自回归条件，而是用真实历史计算条件似然。因果掩码保证并行计算时每个位置遵守这个限制。若把完整目标未经右移送入解码器，当前位置可能直接读取待预测答案；后面再加一个三角掩码并不能阻止它读取自己。

<a id="transformer-3-detail-2"></a>
### 1.1 源表示不是一句话只有一个向量

经典编码器—解码器 Transformer 输出 $`M\in\mathbb R^{B\times S\times d}`$，保存每个源位置的上下文表示。它没有强制把整句压成一个固定向量。解码器用当前状态生成查询，按需要组合这些表示。源表示可被多个目标位置反复读取，其时间索引属于源，不必与目标索引一一对应。目标比源长或短都符合结构定义，长度关系应由任务决定。

这与先平均池化源表示再预测整句有本质差异。平均池化可以用于分类，却会丢掉逐位置访问接口。即使源表示包含全局信息，交叉注意力仍提供一种按目标上下文选择读取的机制。不能从存在这条机制直接推断读到了正确语义；需要任务证据和干预。无训练的随机模型也会产生一张平滑权重图，但它的数值不是语言对齐证明。

<a id="transformer-3-detail-3"></a>
### 1.2 一份明确的符号与输入契约

本章以零作为填充，一作为起始符，二作为结束符，三到五作为普通符号。源不含起始、结束和填充以外的控制语义，目标正文是源的逆序。源长度至少一，目标正文长度等于源长度。模型还要生成结束符，所以监督位置数比正文多一。空源、超长源、非法符号和缺失结束符在正式系统中应各有政策，不能让数组越界来替代输入验证。

词表整数只是编号，不携带大小和距离。编号五不意味着比三更强的语义；嵌入查表学习一个向量，位置表示另外提供顺序。改变符号编号同时一致重排所有嵌入、输出头和数据，可以保持同一问题；只改推理输入编号而不改模型，则是在调用另一种词表。交付时词表映射和特殊符号必须与权重绑定。

<a id="sec-1-1"></a>
<a id="transformer-3-detail-4"></a>
### 1.3 手算一个源长与目标长不同的批次

第一条源为三、四、五，目标正文为五、四、三。训练解码输入是起始、五、四、三，监督标签是五、四、三、结束。第二条源为四、三，解码输入是起始、三、四、填充，监督标签是三、四、结束、填充。批量源张量形状为二乘三，目标张量为二乘四，监督有效数为四加三等于七，而不是八。

解码器位置零读取起始符后预测首个正文；位置二对第二条序列应预测结束，而不应因为第一条更长就再等一步。结束符参与似然，填充不参与。生成时没有真实后续目标，要把刚预测出的符号追加到前缀，遇到结束后停止该条。训练和推理张量都能排列整齐，并不表示它们使用的历史来源相同，这正是后续评价必须分开报告的原因。

## 2. 三条注意力路径与四类掩码

编码器自注意力的分数形状为 $`B\times H\times S\times S`$；解码器自注意力为 $`B\times H\times T\times T`$；交叉注意力为 $`B\times H\times T\times S`$。最后一维永远对应键位置，即归一化和加权求和的对象。查询数决定输出位置数，键数决定可读取集合。让源长三、目标长四的例子进入测试，比只测等长序列更容易揭示角色混淆。

在常规离线条件生成中，编码器有效源位置互相可见，目标自注意力只能读取不晚于当前解码输入的位置，交叉注意力可以读取全部合法源位置。这里没有规定目标位置只能读取同编号源位置，也没有默认给交叉注意力施加目标因果三角形。不同任务可进一步限制源可见性，但必须由信息到达契约推导，不能因为三角形看起来熟悉就到处复用。

<a id="sec-2-1"></a>
<a id="transformer-3-detail-6"></a>
### 2.1 键填充、查询输出与损失分别处理

源键填充掩码阻止编码器读取无效源位置；交叉键填充掩码阻止解码器读取相应记忆。目标键填充掩码阻止目标自注意力读取无效历史。它们不自动把填充位置作为查询产生的输出清零。一个填充查询仍可以读取有效键，经过残差、偏置和前馈得到非零表示。因此摘要或损失阶段仍要显式排除无效位置。

只在最后池化时把填充输出乘零也不够。如果有效查询此前已经读取填充键，其表示已被污染，最后排除无效查询不能逆转这种混合。反过来，只在注意力中屏蔽键而直接对所有输出平均，又会混入非零填充查询。两个操作作用于计算链的不同位置，应分别验收。全空序列还会导致全屏蔽注意力行和零分母，本章契约直接拒绝，避免依赖某个内核对极端输入的特殊处理。

<a id="deep-dive-2"></a>
<a id="transformer-3-detail-7"></a>
### 2.2 用可见矩阵而不是变量名字核对边界

对目标长度四，因果可见矩阵逐行包含一、二、三、四个位置。PyTorch 本章使用的 Transformer 接口中，布尔真表示禁止读取，所以构造的是严格上三角真值。这个约定与某些底层函数的布尔意义相反；将同一张布尔矩阵原样传给不同接口可能反转边界。更可靠的审查是列出第一行究竟能读取哪个键，再通过改动未来输入检验过去输出。

结构证明也需要说明组成操作。若每层自注意力只能读取当前及过去，每位置前馈和归一化不混合时间，残差连接同位置，那么按层归纳，位置 $`t`$ 的输出只依赖前缀。交叉注意力又只读取合法固定源表示，因此整体满足给定源的目标因果性。若额外加入跨时间均值归一化、双向卷积或使用全目标统计的门控，即使自注意力掩码正确，归纳条件也已被破坏。

<a id="transformer-3-detail-8"></a>
### 2.3 为什么不能给解码器自动猜一个因果提示

有些接口允许用户通过额外标志提示掩码具有因果结构，但提示不是重新定义实际矩阵的自由许可证。教学实验直接构造掩码并核对行为，减少自动推断带来的不透明性。真实工程若依赖高效路径，还应在所用版本、设备和形状上复验。相同高层网络可能选择不同内核，数值容差要合理，但信息依赖不应因追求速度而变成未经验证的假设。

源端和目标端都采用右侧填充时，有效位置的绝对编号不会因添加尾部填充而改变，这有助于做不变性测试。若改成左侧填充而仍从零开始生成位置编号，有效 token 的位置全部平移；此时输出变化不必是掩码错误。测试必须固定实际有效位置规则，否则同时改变内容位置与填充长度，无法单独定位键屏蔽是否正确。

## 3. 最小模型的完整计算链与参数角色

原始符号先进入源、目标嵌入，再加对应位置向量，形成宽度为 $`d`$ 的表示。编码器层在源中交换信息并执行逐位置非线性变换，输出记忆。解码器层先处理目标前缀，再用交叉注意力读取记忆，最后经过逐位置前馈。线性输出头把宽度映射到词表大小，得到未归一化 logits。训练交叉熵直接接收 logits，无需先手动 softmax。

注意位置表、嵌入和输出头都不是裸 Transformer 模块自动附送的任务组件。单独调用网络块得到连续表示，只证明结构可运行；要形成模型还需定义词表、位置、任务头、损失和解码。模块文档中的输入维度也不替代数据协议，例如层接受浮点嵌入，不负责判断源里是否混入了未来标签。任务语义必须由上游组织。

<a id="transformer-3-detail-10"></a>
### 3.1 参数共享与初始化需要单独说明

源、目标若共享词表，可以共享嵌入，但这不是编码器—解码器结构的必要条件。输出头是否与目标嵌入绑定，也是一项参数化选择。共享减少独立参数并增加路径上的梯度汇合；它不表示源和目标位置可以共用同一套掩码。若词表不同而强行按整数位置共享，可能把完全无关符号绑在一起。共享决定应来自表示语义和比较协议。

本章完整实验使用独立源、目标嵌入和独立输出头，避免把额外共享机制混入最小结构。只有一层编码与一层解码，因此不存在多层复制模块初值相同的混淆。扩展到多层时应审查库的构造和初始化，不能把 Python 中多个引用指向同一个对象误当成多个独立层。用参数身份集合可以核对共享是否符合设计，不能只看打印出来有几行模块名。

<a id="transformer-3-detail-11"></a>
### 3.2 编码器摘要的正确与错误计算

若另接分类头，可用有效源表示的均值：$`r_b=\frac{\sum_sm_{bs}M_{bs}}{\sum_sm_{bs}}`$。分母是本条有效长度，而不是批次最大长度。对于长度二、补到四的序列，直接平均相当于额外引入两个查询结果，并可能把填充数量当成任务特征。即使填充嵌入严格为零，位置向量、注意力读取和偏置仍可能使这些查询的最终输出非零。

正确池化仍不是所有任务都适用的万能选择。两个序列若逐位置表示的均值相同，分类头无法再区分它们；某些任务需要首位置、可学习查询或其他聚合。是否保留顺序依赖于表示和聚合的组合，不能仅看到用了位置编码就保证任意池化都不丢关键信息。这里的均值实验只检验填充契约，不将其作为最强分类架构。

<a id="transformer-3-detail-12"></a>
## 4. 实验一：用干预验证结构可见性

以下独立实验固定随机参数、关闭 Dropout，并使用双精度小张量。它核对三项性质：修改未来目标输入不改变过去输出；改变被屏蔽源填充值不改变有效表示与解码；增加右侧填充不改变有效源表示。最后对比正确池化与全位置均值。实验不训练模型，不把随机输出解释成已学知识；它检验的是计算路径的必要条件。

```python
import torch
from torch import nn

old_threads = torch.get_num_threads()
torch.set_num_threads(1)
try:
    torch.manual_seed(73)
    net = nn.Transformer(d_model=8, nhead=2, num_encoder_layers=1,
                         num_decoder_layers=1, dim_feedforward=16,
                         dropout=0., batch_first=True).double().eval()
    src = torch.randn(1, 4, 8, dtype=torch.float64)
    tgt = torch.randn(1, 5, 8, dtype=torch.float64)
    src_pad = torch.tensor([[False, False, True, True]])
    causal = torch.ones(5, 5, dtype=torch.bool).triu(1)
    def forward(s, t):
        return net(s, t, tgt_mask=causal, src_key_padding_mask=src_pad,
                   memory_key_padding_mask=src_pad)
    with torch.no_grad():
        base = forward(src, tgt)
        changed = tgt.clone(); changed[:, 3:] += 20
        assert torch.allclose(base[:, :3], forward(src, changed)[:, :3],
                              atol=1e-10, rtol=1e-9)
        other_src = src.clone(); other_src[:, 2:] += 100
        assert torch.allclose(base, forward(other_src, tgt), atol=1e-10, rtol=1e-9)
        short = net.encoder(src[:, :2])
        padded = net.encoder(src, src_key_padding_mask=src_pad)
        assert torch.allclose(short, padded[:, :2], atol=1e-10, rtol=1e-9)
        correct = (padded * (~src_pad).unsqueeze(-1)).sum(1) / 2
        assert torch.allclose(correct, short.mean(1), atol=1e-10, rtol=1e-9)
        assert not torch.allclose(padded.mean(1), short.mean(1), atol=1e-5)
    print('causality, masked source and valid pooling: passed')
finally:
    torch.set_num_threads(old_threads)
```

<a id="transformer-3-detail-13"></a>
### 4.1 通过干预之后还能断言什么

未来目标干预只在评估模式中进行，避免随机掩码差异混入结果。把第三个之后的输入改掉，比较前三个位置，直接检查目标前缀隔离。测试没有声称过去输出必须对合法历史敏感；一个永远输出常数的错误模型也能通过“不读取未来”。因此还需要反向梯度、参考计算和任务训练，验证模型确实利用可用信息，而不是仅仅避开不可用信息。

改变源填充时同时保留源自注意力与交叉读取的掩码。若只屏蔽交叉读取，填充可能先经编码器污染有效源表示；若只屏蔽编码器，解码器仍可能直接读取填充查询产生的记忆。故障注入可以有控制地去掉其中一项，观察性质是否失效。性质测试应针对竞争错误设计，不应把某一次随机差异是否明显当成所有参数下的定理。

<a id="sec-5-1"></a>
<a id="transformer-3-detail-14"></a>
### 4.2 不变性成立的条件与数值容差

增加尾部填充的不变性依赖于同一有效位置编号、相同参数、确定性模式和正确键屏蔽。数学上有效查询只对原有效键归一化，因此多出来的被屏蔽键不进入和式，逐层结果保持。不同形状可能选择不同浮点计算顺序，所以数值检查使用绝对与相对容差，而不是要求每一位相同。接近决策阈值时，浮点接近仍可能导致离散结果改变，应进一步报告决策裕量。

反向性质也值得检查。若某个源位置完全被隔离为填充，它不应通过合法输出损失获得来自读取路径的梯度；但是嵌入行可能在其他有效位置复用，参数级梯度不一定为零。必须区分输入位置梯度和共享参数梯度，不能因为填充编号对应参数出现非零梯度就直接断言信息泄漏。下一实验先把监督目标和位置分开，后面再检验交叉读取的梯度。


<a id="visual-example-transformer-03"></a>

### 图解：用未来干预检验目标因果掩码

![用未来干预检验目标因果掩码](images/03-example.svg)

**填充干预的完整前提。** 在保持输入长度、位置编号和有效性掩码不变的条件下，只改变填充位置的内容。源编码器自注意力必须屏蔽这些键，解码器交叉注意力也须屏蔽对应源位置；若源编码器先让有效位置读到了填充内容，事后只屏蔽交叉注意力不能撤销污染。固定模型并关闭随机性后，才将有效输出的变化与数值容差比较。

**读图与计算。** 结构可见性可以用有针对性的输入干预检验。固定模型与合法输入，改变某个未来目标 token，若更早位置的输出也变化，就应调查掩码、归一化或其他跨位置通路。源序列是合法条件，改变源端真实内容通常可以影响多个目标位置。

**适用条件。** 测试必须关闭随机干扰并选择敏感输入；一次没有变化可能只是参数退化，不能代替结构分析与多组故障测试。


<a id="transformer-3-detail-15"></a>
## 5. 右移、结束符与损失归约的独立验收

令扩展目标为正文加结束符，解码输入为起始符加正文。它们长度相同，却不是逐位置相同的字符串。有效目标位置数等于正文长度加一，填充只用于批量对齐。若把结束符从监督中排除，训练就没有直接奖励在正确时刻停止；若把填充也当普通类别大量监督，模型可能靠输出填充降低平均损失，而任务正文仍很差。

<a id="transformer-3-detail-16"></a>
### 5.1 一段可手算的损失与梯度实验

实验构造前述两条源的目标。所有有效位置 logits 为零，因此每个有效位置交叉熵都是词表大小的对数，平均后保持该值。无效位置的 logits 刻意设成非常大，正确损失应不受影响。进一步检查忽略位置梯度全零、有效位置梯度非零，并比较有效词元平均与先每序列平均：在当前均匀损失下值相同，但改变某条难度后权重差异就会显现。

```python
import math
import torch
import torch.nn.functional as F

PAD, BOS, EOS, V = 0, 1, 2, 6
decoder = torch.tensor([[BOS, 5, 4, 3], [BOS, 3, 4, PAD]])
labels = torch.tensor([[5, 4, 3, EOS], [3, 4, EOS, PAD]])
valid = labels != PAD
assert valid.sum().item() == 7
assert torch.equal(decoder[:, 1:][decoder[:, 1:] != PAD], labels[:, :-1][decoder[:, 1:] != PAD])
z = torch.zeros(2, 4, V, dtype=torch.float64, requires_grad=True)
loss = F.cross_entropy(z.reshape(-1, V), labels.reshape(-1), ignore_index=PAD)
assert abs(loss.item() - math.log(V)) < 1e-12
loss.backward()
assert torch.all(z.grad[~valid] == 0) and z.grad[valid].abs().sum() > 0
z2 = z.detach().clone(); z2[~valid] = 100 * torch.arange(V, dtype=z2.dtype)
again = F.cross_entropy(z2.reshape(-1, V), labels.reshape(-1), ignore_index=PAD)
assert torch.allclose(loss.detach(), again)
per = F.cross_entropy(z.detach().transpose(1, 2), labels, reduction='none',
                      ignore_index=PAD)
assert torch.allclose(per.sum()/valid.sum(), loss.detach())
per[0, :4] *= 2
by_token = per.sum()/valid.sum()
by_sequence = (per.sum(1)/valid.sum(1)).mean()
assert not torch.allclose(by_token, by_sequence)
print('valid targets:', valid.sum().item(), 'uniform loss:', loss.item())
```

<a id="transformer-3-detail-17"></a>
### 5.2 归约对象必须与报告对象一致命名

有效词元平均给长序列更多总权重，序列等权则先按各自长度平均。两者都可定义，但它们是不同风险。若两条目标分别有四与三个有效位置，单个词元在第一种目标中权重都是七分之一，在第二种目标中分别是八分之一与六分之一。调一个全局学习率无法消除这种相对贡献差异，因为不是所有位置梯度同时乘一个常数。

训练可用有效词元均值，报告仍同时给逐词元质量和整序列精确匹配；这并不矛盾，前提是明确命名。整序列正确要求顺序、内容和停止时刻都正确，一条只错一个符号的长序列仍记为不匹配。逐词元准确率会掩盖错误积累，整序列指标又不显示错在哪里，二者与长度分组一起看才能形成较完整解释。不要把教师强制词元准确率直接叫作自由生成准确率。

<a id="transformer-3-detail-18"></a>
## 6. 完整实验的任务、划分与可证伪目标

本节枚举长度二到四、符号三到五的所有源字符串，共九加二十七加八十一等于一百一十七条。固定随机排列后，前八十条为训练，随后十八条为验证，其余十九条为测试。三种角色中的源字符串互不重复，但来自同一个有限生成机制，词表和长度范围相同。这个设计研究的是已见长度范围内对未见组合的泛化，不是未知符号、未知长度或自然文本泛化。

目标是源反序加结束符，因而标签可由已定义规则确定，不需要外部标注。枚举全部可能输入使我们清楚有限总体大小，同时也意味着测试只覆盖十九个特定字符串，不能把样本分数称为普遍证明。模型即使把这十九条全做对，也仍需更长长度、其他生成分布和不同种子的研究才能评价更广泛能力。这里将这些研究留为独立后续实验，不在看到测试后修改模型。

<a id="transformer-3-detail-19"></a>
### 6.1 固定选择规则，再接触最终测试

训练最多三百次完整训练批更新，使用同一固定网络宽度与学习率。每二十步计算一次验证教师强制交叉熵，保存最小值对应的完整参数副本。验证是用于检查点选择的数据，不是最终独立性能证明；测试在选择结束、恢复最佳状态后一次性计算。我们不同时尝试许多学习率再只展示最好的测试运行，因为这种隐含搜索会改变结论中的选择机会。

教师强制交叉熵用于选择便于得到稳定连续信号，但最终报告自由生成的整序列精确匹配。二者可能不一致，这恰是值得报告的结果。若正式任务以整序列正确率为首要目标，可以预先改用验证生成指标选择，但不能在看到测试差异后临时换规则再把同一测试当独立。每一种选择规则都应看成完整学习流程的一部分。

<a id="transformer-3-detail-20"></a>
### 6.2 长度与停止预算的边界

实验源最长四，正确生成最多四个正文加一个结束符，所以生成预算固定五步。位置表大小八，为起始前缀和这些步骤预留空间；这只说明当前程序的索引范围。超出训练长度的调用即使没有越界，也不代表已被验证。若五步未产生结束符，报告中应记为未正常停止，不能在评分前自动补一个结束符使其看起来正确。

对批量已结束序列，后续追加填充，其他序列继续生成。这样每个请求的结束身份被单独跟踪，不能因为某一条产生结束就停止整个批次。整序列比较只保留第一个结束之前的正文，但同时要求确实观察到结束，避免“正确正文后继续生成”与“正确停止”被混为一谈。实际自然语言任务还需要考虑起始空回答、非法控制符和长度截断的独立统计。

<a id="transformer-3-detail-21"></a>
### 6.3 独立可运行的训练、选择、生成与恢复

下面代码只依赖 PyTorch 和标准库。随机种子用于重现当前训练样例，不把它当跨版本逐位相同的保证。固定一条 CPU 线程是为了使小算例成本可控，结束后恢复线程设置。训练集在每次更新中完整使用，因此没有 DataLoader 顺序或微批归约的额外变量。报告训练损失下降是程序健全性检查，测试分数不作为必须通过的断言。

```python
import copy
import itertools
import torch
from torch import nn
import torch.nn.functional as F

PAD, BOS, EOS, V = 0, 1, 2, 6
old_threads = torch.get_num_threads()
torch.set_num_threads(1)
try:
    torch.manual_seed(204)
    items = [tuple(x) for n in (2, 3, 4)
             for x in itertools.product((3, 4, 5), repeat=n)]
    order = torch.randperm(len(items)).tolist()
    train = [items[i] for i in order[:80]]
    val = [items[i] for i in order[80:98]]
    test = [items[i] for i in order[98:]]
    assert len(items) == 117 and len(set(train) & set(test)) == 0
    assert not (set(train) & set(val)) and not (set(val) & set(test))
    def batch(rows):
        src = torch.zeros(len(rows), 4, dtype=torch.long)
        dec = torch.zeros(len(rows), 5, dtype=torch.long)
        label = torch.zeros_like(dec)
        for i, row in enumerate(rows):
            rev = list(reversed(row)); n = len(row)
            src[i, :n] = torch.tensor(row)
            dec[i, :n+1] = torch.tensor([BOS] + rev)
            label[i, :n+1] = torch.tensor(rev + [EOS])
        return src, dec, label
    class TinySeq2Seq(nn.Module):
        def __init__(self):
            super().__init__()
            self.source = nn.Embedding(V, 32, padding_idx=PAD)
            self.target = nn.Embedding(V, 32, padding_idx=PAD)
            self.position = nn.Embedding(8, 32)
            self.core = nn.Transformer(
                d_model=32, nhead=4, num_encoder_layers=1, num_decoder_layers=1,
                dim_feedforward=64, dropout=0., batch_first=True)
            self.output = nn.Linear(32, V)
        def embed(self, ids, table):
            assert ids.shape[1] <= 8
            return table(ids) + self.position(torch.arange(ids.shape[1]))
        def encode(self, src):
            return self.core.encoder(self.embed(src, self.source),
                                     src_key_padding_mask=src.eq(PAD))
        def decode(self, dec, memory, src_pad):
            causal = torch.ones(dec.shape[1], dec.shape[1], dtype=torch.bool).triu(1)
            h = self.core.decoder(self.embed(dec, self.target), memory,
                tgt_mask=causal, tgt_key_padding_mask=dec.eq(PAD),
                memory_key_padding_mask=src_pad)
            return self.output(h)
        def forward(self, src, dec):
            return self.decode(dec, self.encode(src), src.eq(PAD))
    def objective(z, label):
        return F.cross_entropy(z.reshape(-1, V), label.reshape(-1), ignore_index=PAD)
    model = TinySeq2Seq()
    optimizer = torch.optim.Adam(model.parameters(), lr=.01)
    tr = batch(train); va = batch(val)
    with torch.no_grad():
        initial = objective(model(tr[0], tr[1]), tr[2]).item()
    best, best_step, best_state = float('inf'), None, None
    for step in range(1, 301):
        model.train(); optimizer.zero_grad(set_to_none=True)
        loss = objective(model(tr[0], tr[1]), tr[2])
        assert torch.isfinite(loss)
        loss.backward()
        norm = torch.nn.utils.clip_grad_norm_(model.parameters(), 1.)
        assert torch.isfinite(norm)
        optimizer.step()
        if step % 20 == 0:
            model.eval()
            with torch.no_grad():
                score = objective(model(va[0], va[1]), va[2]).item()
            if score < best:
                best, best_step = score, step
                best_state = copy.deepcopy(model.state_dict())
    assert best_state is not None
    model.load_state_dict(best_state); model.eval()
    @torch.no_grad()
    def generate(net, src, max_steps=5):
        memory = net.encode(src)
        prefix = torch.full((len(src), 1), BOS, dtype=torch.long)
        done = torch.zeros(len(src), dtype=torch.bool)
        result = [[] for _ in range(len(src))]
        for _ in range(max_steps):
            token = net.decode(prefix, memory, src.eq(PAD))[:, -1].argmax(-1)
            for i in range(len(src)):
                if not done[i] and token[i].item() != EOS:
                    result[i].append(token[i].item())
            done_before = done.clone()
            done |= token.eq(EOS)
            token = torch.where(done_before, PAD, token)
            prefix = torch.cat((prefix, token[:, None]), dim=1)
            if done.all():
                break
        return result, done
    te = batch(test)
    with torch.no_grad():
        final_train = objective(model(tr[0], tr[1]), tr[2]).item()
        test_ce = objective(model(te[0], te[1]), te[2]).item()
        logits = model(te[0], te[1])
        valid = te[2].ne(PAD)
        teacher_acc = (logits.argmax(-1)[valid] == te[2][valid]).float().mean().item()
    predicted, stopped = generate(model, te[0])
    exact = sum(bool(stopped[i]) and p == list(reversed(test[i]))
                for i, p in enumerate(predicted)) / len(test)
    restored = TinySeq2Seq(); restored.load_state_dict(best_state); restored.eval()
    with torch.no_grad():
        assert torch.allclose(logits, restored(te[0], te[1]), atol=1e-6, rtol=1e-5)
    assert final_train < initial
    print('split sizes:', len(train), len(val), len(test))
    print('initial / selected train CE:', initial, final_train)
    print('selected step / validation CE:', best_step, best)
    print('test teacher CE / token accuracy:', test_ce, teacher_acc)
    print('test free exact / stopped:', exact, int(stopped.sum()), '/', len(test))
    for i in range(min(4, len(test))):
        print('source / prediction / expected:', test[i], predicted[i], list(reversed(test[i])))
finally:
    torch.set_num_threads(old_threads)
```

## 7. 怎样审阅完整实验而不只盯着分数

第一步追踪标签依赖。验证和测试的源与标签只用于相应角色；没有用它们拟合词频表、长度阈值或选择训练步数以外的隐含组件。特殊符号与枚举规则是任务预先定义的契约，不是从测试目标推断出的统计。若真实任务需要从语料构造词表，那一步就属于拟合，必须纳入训练边界；本例固定六个编号不能自动证明真实文本前处理也没有泄漏。

第二步审阅状态选择。保存的是深复制参数字典，否则后续优化可能让所谓最佳状态继续变化。恢复后显式切换评估模式，测试不再调用优化器。完整训练恢复还需要优化器、步数和随机流，而本例只验证选定预测函数的加载一致；它没有声称从中途继续训练能完全复现原轨迹。两种恢复目标要分别命名和检查。

第三步审阅生成。编码器记忆在每条生成期间固定，目标前缀每步增长，没有偷偷喂入后续真值。程序每步重算目标前缀，这是简单清楚的参考实现，并未实现解码器 KV 缓存。前一章的缓存技术可以作为优化分支，但要同时维护自注意力与交叉注意力状态、位置和已结束请求身份，再与这份参考逐步比对。不能把固定源记忆等同于完整解码缓存。

<a id="transformer-3-detail-23"></a>
### 7.1 不同指标揭示不同错误

教师强制交叉熵评价真实历史条件下分配给正确符号的概率，词元准确率忽略概率大小，只看最高类别。自由生成整序列匹配进一步要求模型能在自己的历史下产生全部正确符号并在正确时刻停止。若前一步出错，后续看到的是训练中未必常见的前缀，错误可能放大；因此高词元分数与较低整序列分数并不矛盾。

还可以把错误分成内容替换、次序错误、重复、过早结束、未结束和非法控制符。一个任意长输出中偶然包含正确反序片段，不等于完成任务。评分规则应在看测试前固定，不能把格式异常在事后都清洗掉。对真实文本，合法的等价表达和字符串精确匹配又不同，需另设评估目标；本人工任务刻意只允许一个确定答案，使实现边界更易观察。

<a id="transformer-3-detail-24"></a>
### 7.2 记忆、规则与有限组合泛化

在有限输入空间中，一个足够大的查表也可以达到完美训练成绩；测试未见组合成功提供比训练记忆更强的证据，但仍不足以证明模型学会任意长度的反序算法。当前位置表、层数和训练分布都限制了外推。可以另构建长度五到七的集合，但应将其命名为长度外推实验，独立记录，不把它和原测试混成一个含义模糊的平均分。

若外推失败，可提出位置范围不足、长度统计变化、注意力分辨率或优化捷径等竞争解释。一次失败不能直接归因某个模块，应该固定其他条件，分别改变位置方案、训练长度覆盖和监督规模。扩展位置表只改变程序可接收的索引，不自动建立远距离算法能力。这样将实现容量、训练覆盖和任务表现分开，研究问题才可检验。

<a id="transformer-3-detail-25"></a>
## 8. 交叉注意力的梯度与遮挡验证

对单头输出 $`O=AV`$，$`A=\operatorname{softmax}(\frac{QK^\top}{\sqrt{d_k}}+M)`$。给定输出梯度 $`G`$，值梯度为 $`A^\top G`$，权重梯度为 $`GV^\top`$，再经过逐行 softmax 雅可比得到分数梯度。被永久屏蔽的键权重为零，在只考虑这次读取的图中，其键和值输入对有效输出的导数为零。这比只观察前向结果接近多提供一种局部证据。

<a id="transformer-3-detail-26"></a>
### 8.1 参考模块与输入梯度的完整对照

下面把注意力投影设为单位矩阵，输出投影也设为单位，使多头模块退化成容易核对的单头交叉注意力。查询数三，键数五，最后两个源位置屏蔽。手写路径与模块共享同一组输入值，分别建立独立求导图，比较输出、查询梯度、记忆梯度，再确认屏蔽输入位置梯度为零。它不验证任意多头参数映射，那一问题已由注意力专题独立展开。

```python
import math
import torch
from torch import nn

torch.manual_seed(90)
d = 4
layer = nn.MultiheadAttention(d, 1, dropout=0., bias=False,
                              batch_first=True).double()
with torch.no_grad():
    layer.in_proj_weight.copy_(torch.cat([torch.eye(d)]*3).double())
    layer.out_proj.weight.copy_(torch.eye(d).double())
q = torch.randn(2, 3, d, dtype=torch.float64, requires_grad=True)
memory = torch.randn(2, 5, d, dtype=torch.float64, requires_grad=True)
pad = torch.tensor([[False, False, False, True, True]]*2)
a = (q @ memory.transpose(-1, -2) / math.sqrt(d)).masked_fill(pad[:, None], -torch.inf)
manual = a.softmax(-1) @ memory
g = torch.randn_like(manual)
gq, gm = torch.autograd.grad((manual*g).sum(), (q, memory))
q2 = q.detach().clone().requires_grad_()
m2 = memory.detach().clone().requires_grad_()
reference, _ = layer(q2, m2, m2, key_padding_mask=pad, need_weights=False)
rq, rm = torch.autograd.grad((reference*g).sum(), (q2, m2))
assert torch.allclose(manual, reference, atol=1e-10, rtol=1e-9)
assert torch.allclose(gq, rq, atol=1e-10, rtol=1e-9)
assert torch.allclose(gm, rm, atol=1e-10, rtol=1e-9)
assert torch.all(gm[pad] == 0) and gm[~pad].abs().sum() > 0
assert q.shape[1] != memory.shape[1]
print('cross reading output and input gradients: passed')
```

<a id="transformer-3-detail-27"></a>
### 8.2 梯度为零不等于整个系统完全无关

上面屏蔽的是直接作为输入的记忆位置，且没有别的路径把它们混入有效记忆。如果这些记忆来自一个漏掉源掩码的编码器，原始填充已经可能影响其他位置，后续交叉层对被屏蔽记忆的梯度为零仍不能保证原始填充无影响。全系统依赖分析要沿所有路径追踪；局部性质不能越过未检验的上游模块扩张成端到端结论。

共享嵌入、权重绑定和正则也会让参数梯度比位置梯度复杂。某个编号在本条源中是填充，但对应参数可能经别条合法数据或惩罚项收到梯度。一个输入位置被隔离与一整行参数永远不更新，是不同命题。审查时先说明对什么变量求导、损失读取哪些输出、是否包括正则，再解释零梯度，否则容易把正确的共享路径误报为泄漏。


<a id="visual-mechanism-transformer-03"></a>

### 图解：交叉注意力把每个目标查询连接到源位置

![交叉注意力把每个目标查询连接到源位置](images/03-mechanism.svg)

**图中的机制。** 图用三行目标查询与五列源位置形成长方形权重热图。各目标可以把监督通过读取权重与值路径送回多个源位置，而不需要源长等于目标长。每行强度按行和为一构造，展示同一源位置可以服务多个目标。

## 9. 实际运行结果：局部预测与整序列成功有距离

在本章记录的 PyTorch 2.10.0 CPU 环境中，初始训练交叉熵约为二点零三九，按验证选择的第二十步状态训练交叉熵约零点零三六七，验证交叉熵约零点一七一五。最终测试教师强制交叉熵约零点二一五八，词元准确率约百分之九十一点零一；自由生成十九条中十一条整序列正确，约百分之五十七点八九，十九条都在预算内产生结束符。这些是一次固定划分与种子的观测，不是对所有重跑的确定数值承诺。

三百步训练并不意味着最后一步被选中。验证规则在十五个候选检查点中选择了第二十步，随后训练继续进行却没有覆盖保存的参数。这正好说明训练损失下降与未见组合质量不是同一问题。我们没有为了提高测试结果再尝试另一种选择规则，也没有给“不理想”的测试数字换种子。性能描述必须忠实对应事先定义的完整流程，而不是只保留最好看的样例。

<a id="transformer-3-detail-29"></a>
### 9.1 用具体错例区分次序与长度问题

源三、四、四、五的正确目标是五、四、四、三，本次模型生成五、四、三、四。词表和长度都正确，停止也正常，但后两个位置次序错了；这类错误不能通过删除多余标点之类的格式修复解决。源三、三、三的正确正文长度三，本次却生成四个三后结束，符号身份正确而计数错误。把所有问题都记成一个“错误”会丢掉下一步实验的方向。

两个成功例子也不能证明模型理解了全部反序规则。源三、四、五、三生成三、五、四、三，源五、四、五、三生成三、五、四、五，与正确目标一致。它们说明当前状态在这些输入上能执行任务，但没有揭示内部策略是否为可外推算法。应把成功和失败一起保留，再按重复符号、源长度、位置和训练组合覆盖进行开发分析，最终独立测试仍保持一次性角色。

<a id="transformer-3-detail-30"></a>
### 9.2 怎样解释百分之九十一与百分之五十八

逐词元准确率在真实前缀下统计八十九个有效目标位置，整序列匹配则在模型自生成前缀下以十九条序列为单位。统计单位、输入历史和判定函数都不同，不能用二者相减定义一个纯粹的“暴露偏差量”。即使历史都正确，只要每条序列有一个位置出错，整序列分数也可能很低；历史改变又额外影响后续。因此这个差距提示研究方向，却不能单独分解各因素贡献。

一种开发实验是在固定模型上分别计算真实前缀、只在某个位置注入错误前缀、完全自由生成三种条件，按同一后续位置指标比较。注入要说明替换分布，不能把所有可能错误均匀抽样就当成模型实际错误。另一种研究在不改变输出长度的条件下分析次序错误，避免把停止差异混入内容质量。每个干预只支持对应人工条件，不能由一次图表直接推出普遍因果机制。

<a id="transformer-3-detail-31"></a>
### 9.3 停止率和任务成功率应当一起报告

本次十九条都正常结束，只说明在五步预算内观察到结束符，并不表示结束时刻正确。重复符号例子生成了多余正文后结束，就是停止率百分之百而任务仍失败的直接反例。还可发生过早结束、先输出非法起始符再结束等情况。合法结束、正文正确和完整精确匹配是嵌套关系中的不同事件，报告时应给出清楚定义。

如果生成未结束，程序保留这一状态，而不默默把最后一个符号改为结束。若正式接口允许截断回答，应在输出元数据中标记长度截断，用户与评价程序才能知道它与自然结束不同。请求超时、取消和非法输入也不能被当作普通任务错误混进同一个准确率；它们需要明确的覆盖或失败计数，才能解释服务是否完成约定功能。

<a id="transformer-3-detail-32"></a>
## 10. 从最小算例走向严谨实验

最小结构实验的价值在于可隔离变量。先验证右移与掩码，再证明梯度进入该进入的路径，再训练极小任务，最后评价未见组合。直接从大型自然语料开始会让词表、采样、预处理、架构、目标和服务同时变化；即使分数差，也很难定位原因。规模扩展应保持一个可执行的小参考，并在每次修改后继续核对关键信息边界。

<a id="transformer-3-detail-33"></a>
### 10.1 消融需要重新定义完整学习流程

想研究交叉注意力是否重要，可以比较完整模型与移除该路径的候选，但二者参数量、信息和优化难度都改变。若没有源读取，目标模型仍可能依据训练目标的边际规律猜对一些序列，这不是源条件生成能力。更有辨识力的开发测试是固定目标前缀，交换两条合法源，看预测是否随正确源改变；再将源与目标打乱配对，检查任务证据如何变化。

这个干预也不等于交叉注意力权重的因果解释。交换整条源同时改变内容、长度和分布，应该根据问题控制其中哪些因素。比较不同结构时，应各自从头拟合，使用预先规定的验证和搜索预算；不能把训练完的完整模型某层突然删除造成的损失，当成该层在重新训练替代系统中的不可替代程度。固定模型依赖和学习规则比较是两个对象。

<a id="transformer-3-detail-34"></a>
### 10.2 长度外推要先排除接口和评分错误

若测试长度六，先保证源数组、目标预算、位置表和掩码尺寸都支持六及其结束。否则模型失败可能仅是截断、越界或允许生成步数不足。接口验收通过后，再按训练内长度、略超长度和远超长度分组报告。将短和长混成平均分，可能让大量简单短样本掩盖真正关心的外推失效。

外推研究还应记录词表组成与重复率。对只有三个符号的长序列，重复显著增加，任务可能更依赖计数和位置区分；因此长度变化并非只增加矩阵大小。可以固定符号重复结构、改变长度，再做独立的重复模式研究。不要把所有长序列错误都归因位置编码，因为网络容量、优化与训练覆盖也可能解释同一现象。

<a id="transformer-3-detail-35"></a>
### 10.3 位置和填充的联合干预

先固定有效位置编号，只改变右侧填充，验证表示与输出不变。再在相同内容和掩码下平移有效位置编号，观察绝对位置表示的响应。两种试验分开，才能区分填充泄漏和位置依赖。若换成相对位置机制，应从它实际使用的相对关系推导预期，而不能沿用绝对表实验的所有结论。

同样要分开内容顺序交换与纯编号置换。交换两个源符号改变反序答案，应允许预测改变；一致重命名整个词表则是在改变表示约定，只有权重和评分映射同步变换才谈等价。很多所谓“模型不具有不变性”的判断，实际上是没有先说明任务本来应该保持什么不变。先列契约，再做干预，是设计有意义测试的关键。

<a id="transformer-3-detail-36"></a>
### 10.4 资源与实验记录也属于可复现内容

本章小模型使用单线程完整批量训练，不代表这种配置对大模型最快。完整批量省去了数据管线变量，却增加每步内存；重复前缀解码便于审阅，却会重算历史。报告资源时应把教学参考和目标服务分开：前者追求清楚可查，后者还需要实际硬件、负载、批量与数值条件。改成缓存后要先做等价验证，再测速度。

交付最小记录应包括符号映射、源目标构造、划分索引、网络超参数、随机种子、选定步数、损失分母、生成预算和停止规则，以及逐条预测。只有一个权重文件无法重建这些选择。若输出报告只保留平均准确率，后续发现重复符号问题时无法复算分组结果。保存足够证据并清理自动生成临时文件，可以同时实现可追溯与整洁，而不是二选一。

## 11. 二十道练习与完整解析

<a id="transformer-3-detail-38"></a>
### 11.1 源长三、目标正文长二，三张分数矩阵多大

**问题：** 一个头的编码器自注意力、训练解码自注意力和交叉注意力各有多少行列？

**解析：** 目标正文后还监督结束，因此训练解码长度三。三张分数矩阵分别为三乘三、三乘三、三乘三，此例恰好同形，但角色仍不同。再把源改长五，得到五乘五、三乘三、三乘五，便能直接暴露错误复用。测试应该主动打破源目标等长的巧合，不能用一次同形调用通过证明接口正确。每张矩阵的最后一维都对应被归一化的键集合。

<a id="sec-6-1"></a>
<a id="transformer-3-detail-39"></a>
### 11.2 为什么目标因果三角不能屏蔽交叉读取

**问题：** 在源长五、目标长三时，给交叉注意力一个三乘五的“上三角”矩阵是否天然正确？

**解析：** 形状可以相容，但离线条件生成允许首个目标读取全部合法源。按编号禁止读取后面源位置，额外施加了任务未要求的到达限制。只有在线源逐步到达等明确协议，才应按实际源可得位置构造限制。矩阵是方还是长方不决定因果语义，信息到达契约才决定。自注意力的目标因果索引不能自动解释源目标之间的时间关系。

<a id="transformer-3-detail-40"></a>
### 11.3 给出一个带结束符的完整右移例子

**问题：** 源四、五、三，目标反序，写解码输入和监督标签，并说明各位置预测。

**解析：** 解码输入为起始、三、五、四；标签为三、五、四、结束。第一位置只见起始和合法源，预测三；第二位置见起始与三，预测五；第三位置再见五，预测四；第四位置见完整正文，预测结束。若输入改成三、五、四、结束，即便只允许读取当前及过去，每个位置都可能看见自己的标签，目标已被泄漏。右移与因果掩码必须共同成立。

<a id="transformer-3-detail-41"></a>
### 11.4 长度二与四的目标有多少监督位置

**问题：** 两条目标正文分别长二和四，补齐后有效分母应该是多少？

**解析：** 每条增加一个结束符，所以有效监督为三与五，总数八。批量最大目标长度五，数组共有十个位置，另外两个填充不计入均值。若按序列等权，两个序列各占一半；若按有效词元，较长序列占八分之五。二者不是纯粹代码写法差别。若对填充也监督零类别，模型会接受额外任务，报告分母也变了，不能继续把它称作同一条件似然。

<a id="transformer-3-detail-42"></a>
### 11.5 填充嵌入为零为何不消除所有填充影响

**问题：** 设置`padding_idx`后，是否可以删除源键填充掩码？

**解析：** 不可以。零词向量还可能加上非零位置向量，经偏置与注意力得到非零键和值；即便值恰好零，额外键也可能进入 softmax 分母，降低有效键总权重。填充是否允许读取由掩码规定，不由某个初始化数值代替。固定输入向量为零和把该位置从归一化集合移除，是不同数学操作。训练中的参数更新会让数值巧合更不可靠。

<a id="transformer-3-detail-43"></a>
### 11.6 正确键屏蔽以后为什么还要有效池化

**问题：** 编码器已经屏蔽所有填充键，直接对所有查询输出求平均有什么问题？

**解析：** 填充查询仍能读取合法源，输出不一定零，均值会随填充数量变化。正确做法先按有效查询筛选或加权，再除真实长度。实验一比较短源与尾部填充源，验证有效表示保持而全位置平均改变，正是在区分这两个阶段。若全空源，均值分母仍不存在，应根据契约拒绝或用独立空输入分支，不能默默夹分母后把它当一条正常观察。

<a id="transformer-3-detail-44"></a>
### 11.7 未来干预通过能证明模型学会任务吗

**问题：** 改变未来目标不影响过去 logits，可否认定模型正确？

**解析：** 它只排除一类非法依赖，常数模型也能通过。还需验证合法输入确实能影响输出、参数获得正确梯度、极小数据能拟合，以及独立任务分布上表现如何。必要条件不能当充分条件。可以加入源交换、手算参考前向、输入梯度和真实训练，将不同竞争错误分开排除；每项检查的证据范围都要明确，不能用通过次数代替逻辑覆盖。

<a id="transformer-3-detail-45"></a>
### 11.8 为什么干预时要关闭随机性

**问题：** 同一模型在训练模式下，两次改动前后输出不同，能否认定填充泄漏？

**解析：** Dropout 等随机层可能使完全相同输入的两次输出也不同，因此差异无法只归因输入改变。应先进入评估模式并固定参数，必要时使用确定性小参考与合理数值容差。若专门研究随机训练行为，则需要耦合随机流或分析分布，而不能把单次差值当结构证明。控制变量的含义是让比较对应一个明确改动，并说明没有控制住的来源。

<a id="transformer-3-detail-46"></a>
### 11.9 验证最优第二十步为何仍训练三百步

**问题：** 早期检查点最优是否说明后续运行全是错误？

**解析：** 固定预算内比较多个候选状态是预先定义的选择流程，后续状态可能更适合训练但不更适合未见组合。保存最优状态后继续训练，可以观察优化与泛化分离，但最终独立报告必须使用选定状态。若生产中希望提前停止节约资源，应在开发阶段预先设耐心与最小改进规则，并把它作为另一学习流程评价。不能看到测试后再改早停政策而继续宣称独立。

<a id="transformer-3-detail-47"></a>
### 11.10 保存最佳参数时为什么必须复制

**问题：** `best_state = model.state_dict()`是否总能冻结当前最优点？

**解析：** 不能依赖它冻结张量，参数字典中的张量可共享底层存储，后续原地更新可能改变所引用数值。深复制或写入独立存储才保留该时点状态。验收可以保存后再训练一步，比较已保存张量是否未变，并在结束后恢复核对固定输入输出。保存对象的身份和内容是两个层次，变量名叫“最佳”不会赋予它时间冻结语义。

<a id="transformer-3-detail-48"></a>
### 11.11 加载权重输出相同是否能继续原轨迹

**问题：** 本章恢复 logits 一致，是否已经验证中断续训？

**解析：** 没有。固定预测函数只需相同模型参数、前处理与评估配置，而继续训练还涉及优化器矩、步数、调度、随机流和数据位置。将旧权重和新的优化器状态组合，可能立刻走向不同更新。本章只明确验证推理恢复，没有声称完整训练恢复。若要验证后者，应在同一下一批上比较连续训练与恢复训练的参数更新，再扩大到完整后续轨迹。

<a id="transformer-3-detail-49"></a>
### 11.12 为什么教师强制准确率不是生成成功率

**问题：** 测试词元准确率约百分之九十一，为什么整序列只有约百分之五十八？

**解析：** 词元统计在真实历史下逐位置判断，整序列在自身预测历史下要求所有内容与停止都正确。即使每次历史都真实，多个位置联合全对也比单位置正确更严格；真实生成还可能积累错误。不能直接将两数差解释为某一种偏差的精确大小。应分别检查历史条件、长度、内容与停止，再设计控制干预区分各因素，本次数字只说明两种评价回答不同问题。

<a id="transformer-3-detail-50"></a>
### 11.13 全部在预算内结束是否代表长度建模正确

**问题：** 十九条都产生结束符，可以认定停止机制成功吗？

**解析：** 只能说未发生“预算内无结束”的事件。过早或过晚结束仍然错误，重复三个三的源被生成四个三后结束就是反例。停止率应与正文长度误差、首结束位置和完整匹配共同看。如果接口强行在预算末插入结束符，观察到的停止更不能归于模型能力，必须区分模型自然结束与程序截断。正确计数和合法终止是相关但不相同的目标。

<a id="transformer-3-detail-51"></a>
### 11.14 固定源记忆是否等于完整 KV 缓存

**问题：** 生成中只运行一次编码器，是否已经实现高效增量解码？

**解析：** 它避免重复源编码，但每步仍重算整个目标前缀的自注意力、前馈和交叉查询。本章这样做是建立透明参考。完整缓存还需保存每层历史目标键值，可能预计算各层交叉键值，并维护请求、位置、掩码与长度。优化后应逐步与无缓存参考比较同前缀 logits；只看到速度变快不证明历史语义没有改变。

<a id="transformer-3-detail-52"></a>
### 11.15 屏蔽记忆位置梯度为零能否证明源填充无影响

**问题：** 实验四中被屏蔽的记忆输入梯度为零，是否可省略编码器源掩码？

**解析：** 不可以。局部交叉读取隔离了这些记忆位置，但未经屏蔽的源填充可以先改变其他有效记忆，再被解码器读取。需要端到端前向干预与路径检查共同确认。梯度证据还只在当前参数和输入附近描述局部变化，不能自动替代所有有限改动测试。明确上游依赖和变量身份，是把局部导数用于系统审查的前提。

<a id="transformer-3-detail-53"></a>
### 11.16 为什么长度外推应单列测试

**问题：** 在原十九条测试后附上一批长度七的序列，直接合并平均是否合理？

**解析：** 可以定义某个混合总体，但必须给出权重与用途；它不能替代分别报告训练内组合和训练外长度表现。新增长序列同时改变位置范围、计数需求、重复结构和资源，混合平均会掩盖失效边界。先验收接口、预算和评分支持，再按长度分组。若长度七实验用于改模型，原有测试也不能自动继续作为无限次开发的独立证据。

<a id="transformer-3-detail-54"></a>
### 11.17 相同词表是否必须共享源目标嵌入

**问题：** 本任务源目标都是三到五，独立嵌入是否犯错？

**解析：** 没有，共享是一种可比较的参数化选择，不是语义正确性的必要条件。共享可减少参数并连接梯度路径，但也施加相同向量约束。若要研究收益，应在固定数据与选择预算下比较，并明确其他参数或计算是否匹配。源目标词表相同只使共享具有合理解释，不保证它总更优；不同词表按编号强行绑定则可能连基本语义都不成立。

<a id="transformer-3-detail-55"></a>
### 11.18 符号反序的成功能说明翻译能力吗

**问题：** 如果人工测试达到百分之百，是否可把模型称作可用翻译器？

**解析：** 不能。反序有确定规则、极小词表、短长度和单一答案，真实翻译包含词义、多种合法表述、领域变化与长距离结构。人工任务主要检验编码解码协议和有限组合学习，成功不能跨越分布与目标差异。可以把相同工程接口迁移到真实数据，但词表、清洗、训练、评估和错误分析都需重新建立，不能继承一个人工分数作为质量保证。

<a id="transformer-3-detail-56"></a>
### 11.19 验证集选检查点后还是独立测试吗

**问题：** 验证只选一次检查点，没有更新权重，为什么不能称作最终独立性能？

**解析：** 选择也使用了数据，即便没有对验证反向求导。十五个检查点谁被保留取决于验证标签，所以最终模型与验证样本相关；该分数可能包含选择乐观性。独立测试在选择后评价完整流程，回答不同问题。检查点越多、搜索越广，这种角色区分越重要。数据有没有进入梯度不是判断它有没有参与学习决策的唯一标准。

<a id="transformer-3-detail-57"></a>
### 11.20 怎样把一个错例变成下一轮研究

**问题：** 观察重复符号多生成一次，应立刻增加层数吗？

**解析：** 先提出竞争解释：结束监督不足、训练组合覆盖、计数困难、位置依赖或选择指标偏好。用开发数据构造重复次数与长度受控的集合，分别比较内容与停止；检查标签构造无误后，再按固定预算比较结构或目标改动。每项修改应有预期能排除的解释，并保留原失败样例作回归核对。层数只是候选手段，不是从一个现象唯一推导出的原因。

<a id="transformer-3-detail-58"></a>
## 12. 综合研究：从接口正确走到可解释的学习改进

<a id="transformer-3-detail-59"></a>
### 12.1 沿完整损失路径核对编码器是否真的学习

交叉注意力把目标损失传回源记忆，再通过编码器传回源嵌入和源位置参数。对记忆的梯度会累积所有目标位置、所有解码层的读取贡献。若为了“缓存”在训练中把记忆提前算好并永久分离求导图，编码器就不再接受当前目标的更新；这已变成冻结特征训练，不能继续称为同一个端到端目标。推理缓存与训练冻结有不同条件，不能只因为两者都保存一个张量就混用。

可以先在两条样本上记录源嵌入、目标嵌入、编码层、解码层和输出头的梯度范数，再逐块屏蔽路径验证变化。非零梯度证明存在当前局部依赖，却不证明梯度方向有利于独立质量；零梯度也可能来自饱和、当前误差抵消或参数没有参与损失。若模型无法拟合极小集，应结合参数更新差值、标签对齐和合法输入敏感性，而不是看到任意一个梯度非零就停止排查。

<a id="transformer-3-detail-60"></a>
### 12.2 一份可独立完成的五阶段扩展任务

第一阶段复算两条右移样例和七个有效位置，故意加入不右移、错误分母和丢失结束三种故障。第二阶段执行可见性干预，分别去掉源自注意力与交叉键掩码，解释为何只修一处仍可能泄漏。第三阶段复现完整训练，保留逐条生成与选择记录，不把测试分数当调参信号。第四阶段仅用开发区域分析重复和停止，预先选择一个候选改动。第五阶段在新冻结测试上比较两套完整流程，并给出按源长度分组的结果。

完成标准包括能重建每条信息路径、手算目标构造、解释所有日志对象，并清楚说明尚未验证的长度与分布。若改动改善了教师强制却损害生成，要如实报告；若人工任务全部正确，也应保留其有限总体边界。研究的产出不只是一个更高分数，还应包含哪些解释已被排除、哪些条件下改进有效，以及下一次实验如何继续区分剩余可能性。
