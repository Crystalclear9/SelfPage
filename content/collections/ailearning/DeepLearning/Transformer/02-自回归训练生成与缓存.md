## 1. 先定义序列概率，再安排输入与标签

<a id="transformer-2-detail-2"></a>

### 1.1 链式法则不要求模型结构，模型结构实现信息限制

对离散序列 $`x_1,\ldots,x_T`$，联合概率可以按链式法则写为 $`p(x)=\prod_{t=1}^Tp(x_t\mid x_{<t})`$。这是任意联合分布都满足的分解，不是 Transformer 独有性质。模型用可计算的条件分布 $`p_\theta`$ 近似这些项，再通过因果边界保证每项只能读取相应前缀。架构是否因果与概率是否归一是两个问题：每行 softmax 确保条件分布归一，正确掩码确保条件只依赖合法信息。

有限长度任务还需要说明长度本身如何进入分布。常见做法是把结束符作为普通可预测事件，序列概率包含第一次结束符及其以前的条件概率。若模型从不以概率一终止，则有限序列上的总概率可能小于一；部署中添加最大长度可以让程序一定停止，但那是在定义一个额外的截断输出协议，并没有改变原模型对结束符的概率。评价长度和失败时必须区分模型终止与预算终止。

起始符可以作为给定条件，不作为预测目标。例如 $`[\mathrm{BOS},A,B,\mathrm{EOS}]`$ 代表从给定起点依次预测三个事件。也可以不用专门起始符而采用其他上下文约定，但不能让训练代码和生成代码对第一项条件各自理解。特殊符号的名字不是数学定义，其是否输入、是否监督、是否停止都需要明确。

<a id="sec-1-1"></a>

<a id="transformer-2-detail-3"></a>

### 1.2 用一张短序列表定位移位错误

完整 token 列为起始、甲、乙、结束。输入三列依次为起始、甲、乙，标签三列依次为甲、乙、结束。输出第一列读取起始并预测甲；第二列读取起始和甲并预测乙；第三列读取整个输入并预测结束。三项条件概率都合法，所有标签虽然在训练张量中已知，却没有被接到对应预测的允许输入上。

另一种常见接口输入整段，模型内部把 logits 的最后一列丢弃、把标签的第一列丢弃。这和外部移位可以等价，但若外部已经移位、内部又移位，就会变成跨两词预测。相反，若内外都不移位，模型会得到复制当前位置的任务。最有效的排查不是看损失是否下降，而是把一个四符号样本的每个输出位置、可见输入与监督标签打印成表，并手算其中一项交叉熵。

当一个提示包含多个 token 时，训练目标还要说明是否监督提示区域。有的任务监督整段续写，有的只监督回答。只监督回答并不表示提示不能被注意；它只改变哪些条件项进入目标。把标签有效掩码误当注意力可见掩码，会在应该读取提示的地方错误屏蔽上下文，或在应该屏蔽填充的地方只忽略损失。

<a id="deep-dive-1"></a>

<a id="transformer-2-detail-4"></a>

### 1.3 负对数似然、交叉熵与三种分母

给定 logits $`z_{btv}`$、目标 $`y_{bt}`$、有效标签指示 $`m_{bt}`$，单位置负对数似然为 $`\ell_{bt}=\operatorname{logsumexp}_v z_{btv}-z_{bt,y_{bt}}`$。按有效 token 平均的训练损失为

$$
 L_{\mathrm{token}}=\frac{\sum_{b,t}m_{bt}\ell_{bt}}{\sum_{b,t}m_{bt}}.
$$

先对每条序列内部平均再对序列平均，则不同长度序列具有相同总权重，通常不是同一个目标；按序列总和再平均则更强调长序列。三者都可能合理，但必须根据训练单位选择。不能只把日志字段都命名为“loss”就在不同批长设置之间直接比较。

梯度累积尤其容易写错：若每个微批先平均再把均值等权累加，短微批中的每个 token 会得到更大权重。与大批 token 平均等价的做法，是累计各微批损失总和并按整个累积窗口有效 token 总数缩放，或对各微批平均乘它的有效数占比。分布式训练还要考虑所有工作进程的全局分母，不能把本地长度不均匀当作不会影响梯度的实现细节。

困惑度通常定义为验证负对数似然平均的指数，使用自然对数时为 $`\exp(L)`$。先对每批困惑度取平均，一般不等于对全体有效 token 的总损失求指数。不同分词器下 token 单位不同，困惑度不可以直接作为跨分词方案的公平可比指标；至少要同时报告分词与文本计量单位。

## 2. Teacher forcing 的并行条件与暴露偏差

<a id="sec-6-1"></a>

<a id="transformer-2-detail-6"></a>

### 2.1 并行计算的是不同已知条件项

训练时真实完整序列已知，所以可以一次构建所有合法前缀的条件计算图。每个输出位置只访问不晚于自己的输入位置，因果掩码使同一层能够矩阵化计算所有位置。这个过程没有把真实下一词作为当前条件，只是让不同输出在同一批运算里各自使用对应的已知前缀。层与层之间仍有依赖，注意力矩阵化也不等于整个网络只有一步计算。

生成时，下一 token 本身是随机变量的实现结果。必须先决定它，才能知道再下一步的输入；常规自回归采样因此具有串行依赖。一次产生多个候选并校验、或对固定候选序列评分，是不同算法，不应因为也使用同一模型就把它们与普通逐步生成的代价混写。缓存避免重复历史计算，并不取消新 token 之间的条件依赖。

从概率角度，teacher forcing 直接计算数据分布下真实前缀的条件似然，因此是自回归最大似然的正确计算方式。它不是一种偷看答案的近似，只要标签错位和信息边界正确。问题出现在部署会访问模型自己生成的前缀，其中可能有训练中少见的错误组合；似然目标并不会自动保证这些偏离前缀上的行为优良。

<a id="transformer-2-detail-7"></a>

### 2.2 局部高准确率不保证整句成功

假设一个简化任务每步在正确前缀下都以零点九九概率选对目标，共有一百步；若各步成功条件适当分解，整段全对的概率约为零点九九的一百次方，明显低于单步准确率。实际错误会改变后续前缀，条件分布也随之变化，所以不能把这个简化乘积当作真实所有任务的预测，但它解释了为什么 token 指标和严格整句指标可能差别很大。

验证负对数似然评价参考前缀下模型给真实词的概率，生成评估则同时涉及解码规则、停止、错误恢复和任务约束。一个模型把多个合法答案分配得更合理，参考答案单一路径的似然未必能完整反映生成可用性；反过来，少数提示上的漂亮样例也不能替代系统的概率评价。两类指标测量不同对象，需要并行保留。

可以构造受控扰动前缀：先用真实前缀评估，再在某个位置替换成错误词，比较后续恢复概率和约束违反情况。这个实验不能直接给出所有现实错误分布，却能把“生成会累积错误”从口号转成可观察的条件敏感性。扰动应预先设定，避免只挑最能证明自己观点的例子。

<a id="transformer-2-detail-8"></a>

### 2.3 文档边界和回答掩码改变所估计的分布

若把两个独立文档直接拼接并允许后者读取前者，训练的是连续流条件模型；如果目标是独立文档分布，就需要隔离边界，或者明确把上个文档作为无关上下文的训练条件。结束符并不在数学上自动阻断注意力，它只是一个可被模型读取的符号。若要求严格隔离，必须通过掩码或分别前向实现。

对回答区域才计损失的监督，分母应只计被监督 token；不能把提示长度混入平均后让长提示样本的同样回答被额外降权。结束符通常需要监督，否则程序的停止规则没有对应学习信号。多个回答拼接时，还要防止上段结束后的填充被预测，或把另一条回答开头当作本段续写目标。

### 图解：标签移位与增量 KV 缓存

![标签移位与增量 KV 缓存](images/02-concept.svg)

**先读监督对应，再读增量计算。** 上半图把输入 A、B、C、D 与目标 B、C、D、EOS 按预测时刻对齐：A 所在位置预测 B，D 所在位置预测结束符。箭头是监督对应关系，并不允许 A 读取未来的 B。下半图显示推理中已经处理并缓存 A、B、C，现在将 D 作为新输入。旧位置 K、V 保持原样，新查询会读取前三处和 D 自己。

图进一步指定一维注意力核心的数值，使“复用”可以实际复算：新查询 $`q_D=1`$，四处键为 $`(0,\ln2,\ln3,\ln4)`$，值为 $`(2,4,8,10)`$，键维一所以缩放因子为一。指数归一化得到权重 $`(0.1,0.2,0.3,0.4)`$，读取为 $`0.1\times2+0.2\times4+0.3\times8+0.4\times10=7.4`$。这些是手工指定的单头张量，图没有把读取值 $`7.4`$ 当作完整模型的 logit，也没有声称它是本章随机解码器的实测输出。

每一层都保存自己的缓存。D 处理后得到的分布用于抽取下一词；**刚抽出的词尚未进入模型，它自己的 K、V 还没有生成**，必须在后一次前向中追加。这区分了已返回 token 数与已处理缓存长度。标签移位改变监督对齐，缓存改变计算复用；若训练接口内部已经移位，不应再次移动标签。预填充与后续步骤可对照 [PagedAttention 原论文第 2.2 节](https://arxiv.org/html/2309.06180v1#S2.SS2)。

## 3. 从 logits 到采样分布：每一步变换都要有定义

<a id="sec-2-1"></a>

<a id="transformer-2-detail-10"></a>

### 3.1 温度改变概率比，不只是随机程度标签

对正温度 $`\tau`$，$`p_i(\tau)=\frac{\exp(\frac{z_i}{\tau})}{\sum_j\exp(\frac{z_j}{\tau})}`$，故 $`\frac{p_i}{p_j}=\exp(\frac{(z_i-z_j)}{\tau})`$。降低温度扩大对数概率差，高温则缩小差异。给 logits 加同一常数不改变分布；乘常数与改变温度等价，前提是没有中间的截断、惩罚等其他操作。温度不是可以脱离 logits 尺度独立比较的绝对“创造力刻度”。

若最大 logit 唯一，温度趋于零时概率集中到最大项；若有多个并列最大值，极限会在这些项上分配，而确定性贪心实现通常按某个索引规则选一个。温度等于零不应通过实际除零实现，应单独定义为贪心分支。负温度会反转排序，不属于本章讨论的普通采样协议。

低温只让模型更常选择自己最确信的选项。如果模型最确信的是错误事实，低温可能让错误更稳定。概率集中与外部正确性没有一般等价关系。若需要验证事实或约束，必须使用相应证据和校验，而不是把采样超参数当作知识修复器。

还可以严格解释温度与熵的关系。令 $`Z(\tau)=\sum_i\exp(\frac{z_i}{\tau})`$，期望对当前温度分布计算，则熵为 $`H(\tau)=\log Z(\tau)-\frac{\mathbb E_\tau[z]}{\tau}`$。对有限词表、固定有限 logits 和正温度求导，有 $`\frac{d\mathbb E_\tau[z]}{d\tau}=-\frac{\operatorname{Var}_\tau(z)}{\tau^2}`$，代回得到

$$
 \frac{dH}{d\tau}=\frac{\operatorname{Var}_\tau(z)}{\tau^3}\ge0.
$$

这说明在未截断的固定 logits 分布上，提高温度确实不会降低熵，且 logits 不全相同时导数为正。结论的对象是单步概率分布，不是最终文本的语义多样性；文本还受到上下文反馈、停止和采样轨迹影响。若温度变化同时改变 top-p 支持集，或者使用依赖概率的其他处理器，就不能不加分析地把同一个导数公式套到整个复合策略上。

这个推导还提供了实用的诊断方向：若一个没有截断的温度处理器在固定 logits 上提高温度却降低熵，应先检查除法方向、归一化轴或数值问题；若文本重复率仍然增加，则应研究生成轨迹，而不是因此推翻单步公式。把严格数学命题与实际任务现象分开，才能在观察不符合直觉时定位到底哪个条件发生了变化。

<a id="transformer-2-detail-11"></a>

### 3.2 Top-k、top-p 与边界项的保留

Top-k 保留分数最大的至多 $`k`$ 个 token，再重新归一。Top-p 先按概率降序排列，保留累计质量首次达到阈值 $`p`$ 的最短前缀，并包含跨过阈值的边界项。若漏掉这个边界项，保留质量可能低于目标，甚至在第一项概率已超过阈值时保留空集合。实现必须至少保留一个候选，并明确并列分数的排序约定。

例如概率为零点五五、零点三、零点一、零点零五，阈值零点八。前两项累计零点八五，因此保留前两项，归一化后概率分别为十一分之十七和六分之十七。若先使用 top-k 再计算 top-p，后者的累计概率是在已截断分布上计算，通常不同于直接对原温度分布计算。多个处理器的顺序是生成函数的一部分，应写入配置而不是藏在代码顺序里。

![Top-p在累计质量越过阈值时保留边界项并重新归一化](images/02-nucleus-threshold.svg)

图中橙线落在 B 的区间内，算法仍保留整个 B，而不是把 B 削成恰好补足零点八的部分。Top-p 选择的是完整词元集合；它不是将最后一个词元的概率裁成剩余预算。原分布中的 A、B 概率比为十一比六，截断后仍保留此比值，只把两项之和从零点八五重新归一到一。

截断会把某些原本非零概率变成零，因而改变支持集。模型分布下的序列似然不能直接当作截断采样器产生序列的概率；后者每步有新的归一化分母。若为了研究采样器而记录概率，需要同时保存原模型概率与实际采样概率，避免把模型评价和解码策略评价混淆。

<a id="transformer-2-detail-12"></a>

### 3.3 贪心不保证全局最大序列概率

贪心每步取当前最大条件概率，但某个较小首词可能通向概率更集中的后续。例第一步甲为零点六、乙为零点四；若甲之后最佳结束概率为零点五，乙之后结束概率为零点九九，两条完整序列概率分别为零点三和零点三九六。贪心选甲却没有得到最大联合概率。结束符和长度归一还会改变搜索偏好，不能只比较当前一步。

束搜索保留多条部分序列，可以减少某些局部选择错误，但有限束仍不是全局最优保证。对开放式生成，最大模型概率序列本身也未必是最有用的回答；训练目标、长度偏置和模型失配都可能使高概率模式重复或过短。因此搜索正确性与任务质量应分别评价，不要把更大搜索预算自动当作更高内容质量。

<a id="transformer-2-detail-13"></a>

### 3.4 结束规则与约束必须处理冲突

生成协议至少需要定义结束 token、最多新增长度、是否把结束 token 放入返回内容、达到预算时的状态，以及多 token 停止串如何匹配。若设置最小长度而在之前禁止结束符，则实际采样分布又被改变。若词表过滤把所有候选都屏蔽，应抛出明确错误或采用预先声明的回退规则，不能静默从全负无穷 softmax 得到非数。

批量生成时，一条样本结束后其后续占位输出不应该被展示，也不应该被当作新的有效上下文影响该样本的统计。未结束样本仍继续生成，缓存长度和物理步数可能共同增长，所以需要记录每条样本的逻辑有效长度。第一条遇到结束就停止整个批量，会无意截断其他请求；所有行都继续把结束后采样当真，则改变了输出定义。


<a id="visual-mechanism-transformer-02"></a>

### 图解：温度改变采样分布但不改变最大项排序

![温度改变采样分布但不改变最大项排序](images/02-mechanism.svg)

**沿着曲线读温度。** 固定三个 token 的 logits 为二、一、零。横轴只改变共同温度，纵轴显示同一个 token 的归一化概率；圆点标记 0.5、一、二，右侧给出温度为一时的概率约 $`(0.665,0.245,0.090)`$。A 的曲线始终最高，故贪心选择不变；采样时三个 token 的频率却在变化。本例中，B 的概率为 $`p_B(\tau)=\frac{1}{1+2\cosh(\frac1\tau)}`$，在正温度下严格增加；C 的概率也严格增加，A 的概率则严格减小。三者始终保持 A、B、C 的排序。图显示有限区间；温度趋向无穷时三条曲线共同趋向 $`\frac13`$，温度趋向零时 A 的概率趋向一。

**条件与边界。** 温度不是概率校准的自动保证。截断采样、重复惩罚等后处理还会额外改变支持与分布。

## 4. KV cache 的正确性来自历史不依赖未来

<a id="transformer-2-detail-15"></a>

### 4.1 为什么过去的键和值可以复用

对逐层因果网络，过去位置的隐藏状态只依赖过去与当前位置输入，不会因追加未来 token 改变。该位置在每层形成的键和值因此固定，可以保存。新位置只需计算自己的查询、键和值，查询读取已有键值和自己的新键值。这个不变量必须逐层成立，若某个预处理或归一化混合未来，缓存与完整前向就不再等价。

缓存不需要保存历史查询，因为新输出只用新查询乘历史键。注意力输出仍需要历史值，不能只保存键而省略值。每一层的键值来自不同参数和不同层输入，因此有独立的缓存；把一层缓存用于另一层，即使形状相同也没有函数等价性。源码中一个简单列表，背后实际上记录了整个多层历史计算的接口。

对于绝对位置嵌入，历史隐藏状态已经包含原位置；新 token 必须使用延续后的正确逻辑位置。对于旋转位置，缓存通常已包含按历史位置旋转的键，新查询也必须按相应位置旋转。位置不是纯粹展示用编号，它进入参数化函数，错一位可能让程序仍然有限且输出流畅，但概率已经不同。

<a id="transformer-2-detail-16"></a>

### 4.2 追加多个 token 时需要带偏移的矩形掩码

设已有缓存长 $`P`$，本次追加 $`Q`$ 个 token。查询长度为 $`Q`$，键长度为 $`P+Q`$，第 $`i`$ 个新查询可以读取物理键索引 $`j\le P+i`$。正确掩码是一个带偏移的下三角矩形，不是从零开始的 $`Q`$ 乘 $`(P+Q)`$ 普通左上三角。特别地，单 token 解码时新查询应读取全部过去键和自己，而不是只读取第一把键。

某些函数式接口对非方阵因果掩码有特定对齐约定，不能凭“causal”参数名猜它与缓存偏移一致。本章用显式索引生成允许矩阵，再与有效键掩码相交，避免把接口默认值当成自己的协议定义。若使用优化内核，应先用这个清晰版本作基准，核对相同位置 logits，再谈性能。

块追加不仅是性能需求，也是一种强验证手段。仅测试逐 token 可能漏掉块内未来遮挡错误；仅测试完整前缀可能漏掉缓存偏移。将同一序列按不同分块方案计算，比较全部有效位置输出，可以同时审查位置计数、历史拼接和矩形边界。

<a id="visual-depth-transformer-cache-mask"></a>

#### 图解：缓存块的绝对位置掩码

![缓存追加块的局部三角掩码与正确绝对位置掩码](images/02-cache-mask-offset.svg)

**逐格定位错误。** 图中已有四个缓存位置 $`0,1,2,3`$，新块对应绝对位置 $`4,5`$，所以两行查询的局部行号虽是 $`i=0,1`$，绝对位置却是 $`4+i`$。左图按 $`j\le i`$ 生成左上三角，分别只允许 1、2 把键；右图按 $`j\le4+i`$ 允许 5、6 把键。错误掩码没有暴露未来，却删除了大部分合法历史，因此“没有未来泄漏”还不足以验证缓存等价。

**用读出均值核对图意。** 令全部未掩码 logits 为零，键值依次为 $`V=(0,1,2,3,4,5)^\top`$。合法位置等权时，正确输出为 $`(\frac{0+1+2+3+4}{5},\frac{0+1+2+3+4+5}{6})=(2,2.5)`$；左图则得到 $`(0,\frac{0+1}{2})=(0,0.5)`$。不用训练模型，只比较这个两行算例，就能暴露偏移错误。

**对应具体接口。** [PyTorch 2.10 SDPA](https://docs.pytorch.org/docs/2.10/generated/torch.nn.functional.scaled_dot_product_attention.html)对非方形 `is_causal=True` 使用左上对齐语义，不能直接当成本图右侧的缓存规则。显式允许掩码应按实际绝对位置构造，再与键有效性相交；此时按接口约定避免同时设置冲突参数。图假定没有 padding、位置从零连续增长，滑动窗口与左填充还需继续按后面的坐标契约核对。

<a id="transformer-2-detail-17"></a>

### 4.3 左填充、逻辑位置和物理缓存槽

批量里较短提示可能在左边填充到统一物理长度。物理索引表示张量槽，逻辑位置表示该样本第几个真实 token，两者不能混为一谈。若训练采用从零开始的真实 token 位置，左填充后可以用有效标记累计和减一得到逻辑位置，填充槽的位置任意安全设置但不能被真实查询读取。这样同一提示单独运行和左填充批量运行才有机会等价。

新块的位置应从历史有效 token 数继续，而不是从历史物理缓存长继续。对右填充后再追加的系统，真实历史之间可能存在无效槽，同样需要有效键掩码与显式逻辑位置。只依据缓存张量最后一维推断所有样本位置，会把批内长度差异变成模型输入差异。

无效查询仍需安全执行：它可能在早期填充位置没有合法真实键。可以给它一个只用于数值安全的占位可读槽，并确保它的键不被真实查询读取、输出不进入损失和读出。本章代码采用这种局部策略；它不改变有效查询函数，但避免全屏蔽行的未定义 softmax。对真正有效查询，则必须保证至少能读取自己或合法历史。

<a id="transformer-2-detail-18"></a>

### 4.4 哪些改变必须使缓存失效

修改实际前缀、模型参数、位置协议、适配器状态、源条件或注意力边界，都可能使旧缓存失效。仅长度相同不构成复用条件。跨请求共享只有在模型与计算协议一致、共享部分输入前缀相同且后续追加不会改变其历史表示时才成立。系统还需要隔离请求身份，避免把其他请求的历史误接进来。

滑动窗口丢弃旧键值，并不等于把剩余 token 从头按一个短提示重新计算。剩余 token 的高层表示可能在生成时读取过后来已被丢弃的历史，所以保留缓存仍携带过去信息。若要宣称与某个窗口定义严格等价，需要明确该定义是逐层局部窗口、重新编码窗口还是带历史状态的流式系统。三者可能都合理，但不能共用一个“截断上下文”的模糊名字。


<a id="visual-example-transformer-02"></a>

### 图解：KV 缓存的有效性依赖历史表示不变

![KV 缓存的有效性依赖历史表示不变](images/02-example.svg)

图让所有可见分数均为零，因此每个位置对合法值等权平均。前缀值为一、三时，因果读取依次输出一、二；追加值八后，旧位置仍输出一、二，新位置才输出 $`\frac{1+3+8}{3}=4`$。双向读取在旧前缀输出二、二，追加后却变为四、四、四：旧表示已经改变。

这是单层汇聚的解析对照，直接解释多层缓存为什么依赖逐层的历史不变性。第一层的键值可能只由固定嵌入投影得到，但更深层的键值依赖上一层输出；双向网络的旧输出一旦变化，深层旧缓存一般也需要重算。不能只检查第一层 K、V 恰好不变就宣称整个网络可以追加复用。

实际数值对照还需固定模型参数、评估模式、位置坐标和所有掩码。当前块可以读取自己的键，不能删掉这一合法位置；滑动窗口或缓存裁剪也必须相应改变可见集合。本章代码用完整前向与逐步前向逐值比较，正是把这个不变性从玩具例子扩展到实际多层网络。

## 5. 三个独立实验：对齐目标、采样与完整缓存

<a id="transformer-2-detail-20"></a>

### 5.1 实验一：有效 token 分母与移位标签

实验构造一长一短两条序列，对 padding 标签设忽略值。先核对框架交叉熵等于手工 log-softmax 的有效项平均，再证明修改被忽略位置 logits 不影响损失，并展示微批均值等权与全体 token 均值不同。它不是语言模型质量实验，而是训练目标接口的数值验收。

```python
import torch
import torch.nn.functional as F

torch.set_num_threads(1)
torch.manual_seed(41)
# 0 is padding, 1 is BOS, 2 is EOS.
seq = torch.tensor([[1, 3, 4, 2, 0], [1, 5, 2, 0, 0]])
inputs = seq[:, :-1]
labels = seq[:, 1:].clone()
labels[labels == 0] = -100
assert inputs.tolist() == [[1, 3, 4, 2], [1, 5, 2, 0]]
assert labels.tolist() == [[3, 4, 2, -100], [5, 2, -100, -100]]
logits = torch.randn(2, 4, 6, dtype=torch.float64, requires_grad=True)
valid = labels != -100
logp = logits.log_softmax(-1)
manual = -logp[valid].gather(1, labels[valid, None]).mean()
loss = F.cross_entropy(logits.reshape(-1, 6), labels.reshape(-1), ignore_index=-100)
assert torch.allclose(loss, manual, atol=1e-12)
changed = logits.detach().clone()
changed[~valid] = 100 * torch.randn_like(changed[~valid])
assert torch.allclose(F.cross_entropy(changed.reshape(-1, 6), labels.reshape(-1)), loss)
loss.backward()
assert torch.count_nonzero(logits.grad[~valid]) == 0
per_sequence = [F.cross_entropy(logits[b], labels[b], reduction='sum') for b in range(2)]
counts = valid.sum(1)
correct = sum(per_sequence) / counts.sum()
wrong = sum(per_sequence[b] / counts[b] for b in range(2)) / 2
assert torch.allclose(correct, loss, atol=1e-12)
assert not torch.allclose(wrong, loss)
print('shift and token weighting passed; valid tokens:', int(counts.sum()))
```

注意代码只验证损失标签屏蔽，没有声称已经验证注意力 padding。二者将在缓存实验中分别检查。若一个 batch 完全没有有效标签，平均分母为零，应在数据或训练循环明确跳过或报错；不要期待忽略索引自动为无监督批定义一个有意义的平均损失。

<a id="transformer-2-detail-21"></a>

### 5.2 实验二：温度、边界保留和不同结束时间

下面实现温度后先 top-k、再 top-p 的明确协议，并用人工转移矩阵验证批内独立停止。概率测试不依赖随机抽样频率，所以不会偶然失败；最后的贪心生成测试专门检查一条先结束、另一条后结束时的控制流。

```python
import torch

torch.set_num_threads(1)
def distribution(logits, temperature=1.0, top_k=None, top_p=1.0):
    import math
    if (not isinstance(logits, torch.Tensor) or logits.ndim != 1
            or logits.numel() == 0 or logits.is_complex() or logits.dtype == torch.bool):
        raise ValueError('a nonempty one-dimensional real logits tensor is required')
    if (type(temperature) not in (int, float) or type(top_p) not in (int, float)):
        raise ValueError('temperature and top_p must be real scalar numbers')
    try:
        finite = math.isfinite(temperature) and math.isfinite(top_p)
    except OverflowError:
        finite = False
    if not finite or temperature <= 0 or not 0 < top_p <= 1:
        raise ValueError('finite positive temperature and 0 < top_p <= 1 required')
    z = logits.to(torch.float64) / temperature
    if not torch.isfinite(z).all():
        raise ValueError('this teaching function requires finite logits')
    if top_k is not None:
        if type(top_k) is not int or not 1 <= top_k <= z.numel():
            raise ValueError('invalid top_k')
        order = torch.argsort(z, descending=True, stable=True)
        keep = torch.zeros_like(z, dtype=torch.bool)
        keep[order[:top_k]] = True
        z = z.masked_fill(~keep, -torch.inf)
    probs = z.softmax(-1)
    order = torch.argsort(probs, descending=True, stable=True)
    sorted_p = probs[order]
    # Keep the item that crosses p: mass before the item must be < p.
    keep_sorted = sorted_p.cumsum(0) - sorted_p < top_p
    keep_sorted[0] = True
    keep = torch.zeros_like(keep_sorted)
    keep[order] = keep_sorted
    probs = probs * keep
    return probs / probs.sum()
p = torch.tensor([0.55, 0.30, 0.10, 0.05], dtype=torch.float64)
filtered = distribution(p.log(), top_p=0.8)
assert torch.allclose(filtered, torch.tensor([11/17, 6/17, 0., 0.], dtype=p.dtype))
assert distribution(p.log(), temperature=0.5)[0] > p[0]
assert torch.allclose(distribution(p.log()+91), p, atol=1e-14)
assert torch.count_nonzero(distribution(p.log(), top_k=1)) == 1
for bad_logits, config in [
    (torch.empty(0), {}), (torch.zeros(2, 2), {}),
    (torch.tensor([1+2j]), {}), (p.log(), {'temperature': float('inf')}),
    (p.log(), {'temperature': float('nan')}), (p.log(), {'temperature': True}),
    (p.log(), {'top_k': True}), (p.log(), {'top_k': 1.5}),
    (p.log(), {'top_p': float('nan')}), (p.log(), {'top_p': True})]:
    try:
        distribution(bad_logits, **config)
    except ValueError:
        pass
    else:
        raise AssertionError('invalid sampling contract accepted')
# Tokens: 0 EOS, 1 short prompt, 2 long prompt, 3 middle.
next_token = torch.tensor([0, 0, 3, 0])
last = torch.tensor([1, 2])
finished = torch.zeros(2, dtype=torch.bool)
outputs = [[], []]
for step in range(4):
    chosen = next_token[last]
    for b in range(2):
        if not finished[b]:
            outputs[b].append(int(chosen[b]))
    finished |= chosen == 0
    last = torch.where(finished, torch.zeros_like(chosen), chosen)
    if bool(finished.all()):
        break
assert outputs == [[0], [3, 0]]
assert step == 1
print('sampling support and independent EOS stopping passed')
```

采样函数的接口是单个非空词表的一维实数 logits；批量应逐行调用或另写明确按词表轴操作的实现。温度与 top-p 使用有限的 Python 实数标量，top-k 使用精确整数，布尔配置不当作数值接受。无穷温度不被静默解释为均匀分布，复数 logits 也不会通过类型转换丢弃虚部。缩放后的有限性仍要检查，极小温度可能使有限 logits 除法溢出；本示例对此明确报错。

人工转移表不模拟真实 Transformer，它把停止逻辑从模型概率中剥离，便于精确验收。随后将同一控制流接到模型时，还需测试缓存里有效长度的更新。采样随机数发生器应由调用者控制；只设置全局种子可能因批量大小和请求顺序改变随机数消耗，从而让同一请求输出不同，这属于协议可重现性问题。

<a id="transformer-2-detail-22"></a>

### 5.3 实验三：两层真实解码器的完整前缀与缓存对照

代码使用人工 token、学习绝对位置、两层三头 Pre-LN 块和词表投影。缓存保存每层的键值以及公共有效槽标记。它覆盖整段前向、逐 token、不同块大小追加、左填充批量与单条提示对照，并故意把新位置重新归零，确认测试能够发现错误。模型未训练，实验目标是数学函数等价性；没有预训练权重和任何下载。

```python
import math
import torch
from torch import nn

torch.set_num_threads(1)
torch.manual_seed(53)
DTYPE = torch.float64
class CachedLayer(nn.Module):
    def __init__(self, d=12, heads=3):
        super().__init__()
        self.h, self.dk = heads, d // heads
        self.n1, self.n2 = nn.LayerNorm(d, dtype=DTYPE), nn.LayerNorm(d, dtype=DTYPE)
        self.qkv = nn.Linear(d, 3*d, bias=False, dtype=DTYPE)
        self.out = nn.Linear(d, d, bias=False, dtype=DTYPE)
        self.ff = nn.Sequential(nn.Linear(d, 24, dtype=DTYPE), nn.GELU(), nn.Linear(24, d, dtype=DTYPE))
    def forward(self, x, valid, past_valid, past=None):
        b, qlen, d = x.shape
        q, k, v = self.qkv(self.n1(x)).chunk(3, -1)
        def split(a):
            return a.reshape(b, qlen, self.h, self.dk).transpose(1, 2)
        q, k, v = map(split, (q, k, v))
        plen = 0 if past is None else past[0].shape[2]
        if past is not None:
            k = torch.cat((past[0], k), dim=2)
            v = torch.cat((past[1], v), dim=2)
        all_valid = torch.cat((past_valid, valid), dim=1)
        key_index = torch.arange(plen + qlen)[None, None, None, :]
        query_index = (plen + torch.arange(qlen))[None, None, :, None]
        allowed = (key_index <= query_index) & all_valid[:, None, None, :]
        # Invalid query rows have one numerical safety slot, never a real output.
        allowed = allowed | ((~valid[:, None, :, None]) & (key_index == 0))
        scores = q @ k.transpose(-1, -2) / math.sqrt(self.dk)
        scores = scores.masked_fill(~allowed, -torch.inf)
        a = scores.softmax(-1)
        y = (a @ v).transpose(1, 2).reshape(b, qlen, d)
        u = x + self.out(y)
        return u + self.ff(self.n2(u)), (k, v)
class TinyDecoder(nn.Module):
    def __init__(self):
        super().__init__()
        self.tok = nn.Embedding(13, 12, dtype=DTYPE)
        self.pos = nn.Embedding(64, 12, dtype=DTYPE)
        self.layers = nn.ModuleList([CachedLayer(), CachedLayer()])
        self.final = nn.LayerNorm(12, dtype=DTYPE)
        self.lm = nn.Linear(12, 13, bias=False, dtype=DTYPE)
    def forward(self, ids, valid=None, cache=None, wrong_positions=False):
        b, qlen = ids.shape
        if qlen < 1:
            raise ValueError('nonempty append required')
        valid = torch.ones_like(ids, dtype=torch.bool) if valid is None else valid
        assert valid.shape == ids.shape and valid.dtype == torch.bool
        if cache is None:
            past_valid = torch.zeros(b, 0, dtype=torch.bool)
            past_layers = [None] * len(self.layers)
        else:
            past_valid, past_layers = cache
            assert past_valid.shape[0] == b and len(past_layers) == len(self.layers)
        positions = past_valid.sum(1, keepdim=True) + valid.long().cumsum(1) - 1
        if wrong_positions:
            positions = valid.long().cumsum(1) - 1
        positions = positions.clamp_min(0)
        if int(positions.max()) >= self.pos.num_embeddings:
            raise ValueError('logical position exceeds table')
        x = self.tok(ids) + self.pos(positions)
        saved = []
        for layer, old in zip(self.layers, past_layers):
            x, kv = layer(x, valid, past_valid, old)
            saved.append(kv)
        return self.lm(self.final(x)), (torch.cat((past_valid, valid), 1), saved)
model = TinyDecoder().eval()
ids = torch.tensor([[3, 5, 7, 4, 2, 9], [8, 6, 3, 7, 4, 2]])
with torch.no_grad():
    full, _ = model(ids)
    for chunks in ([1,1,1,1,1,1], [2,1,3], [3,3]):
        cache, parts, offset = None, [], 0
        for size in chunks:
            out, cache = model(ids[:, offset:offset+size], cache=cache)
            parts.append(out)
            offset += size
        assert torch.allclose(torch.cat(parts, 1), full, atol=1e-11, rtol=1e-11)
    altered = ids.clone()
    altered[:, 4:] = torch.tensor([[1, 1], [12, 11]])
    altered_out, _ = model(altered)
    assert torch.allclose(full[:, :4], altered_out[:, :4], atol=1e-12, rtol=1e-12)
    # Left padded prompts: logical positions count only valid tokens.
    padded = torch.tensor([[0, 0, 3, 5, 7], [8, 6, 3, 7, 4]])
    mask = padded != 0
    batch, batch_cache = model(padded, mask)
    for b in range(2):
        single, _ = model(padded[b:b+1, mask[b]])
        assert torch.allclose(batch[b, mask[b]], single[0], atol=1e-11, rtol=1e-11)
    cache, parts = None, []
    for t in range(padded.shape[1]):
        out, cache = model(padded[:, t:t+1], mask[:, t:t+1], cache)
        parts.append(out)
    streamed = torch.cat(parts, 1)
    assert torch.isfinite(streamed).all()
    assert torch.allclose(streamed[mask], batch[mask], atol=1e-11, rtol=1e-11)
    new = torch.tensor([[4], [2]])
    next_logits, _ = model(new, cache=batch_cache)
    extended, _ = model(torch.cat((padded, new), 1), torch.cat((mask, torch.ones(2,1,dtype=torch.bool)), 1))
    assert torch.allclose(next_logits[:, 0], extended[:, -1], atol=1e-11, rtol=1e-11)
    broken, _ = model(new, cache=batch_cache, wrong_positions=True)
    wrong_gap = (broken - next_logits).abs().max().item()
    assert wrong_gap > 1e-3
    # Cached storage is exactly two arrays per layer, with full head width.
    elements = sum(k.numel() + v.numel() for k, v in batch_cache[1])
    assert elements == 2 * 2 * 2 * 5 * 12
print('full/step/chunk/padding cache equivalence passed; wrong-position gap:', wrong_gap)
```

缓存对象在这个教学实现中只验证了必要的基础形状，生产系统还应封装模型版本、设备、精度、请求身份和有效长度约束。代码没有声称接受任意外部构造的缓存；它的测试范围是同一模型自产的缓存与明确给出的左填充协议。把内部缓存直接暴露为任意可反序列化对象，会引入新的接口问题，应与数学机制分开设计。

## 6. 从运算次数推导缓存的收益与代价

<a id="transformer-2-detail-24"></a>

### 6.1 完整前缀重算与增量计算的阶数

设提示长度为 $`P`$，需要生成 $`G`$ 个新 token，模型层数为 $`L`$，模型宽度为 $`D`$，前馈宽度为 $`M`$。若每一步重新计算全部前缀，线性投影和前馈处理的位置数与 $`\sum_{g=0}^{G-1}(P+g)`$ 成正比，注意力位置对数与 $`\sum_{g=0}^{G-1}(P+g)^2`$ 成正比。后者展开包含 $`GP^2`$、$`PG^2`$ 和 $`G^3`$ 量级项。虽然因果矩阵只使用一半位置对，不改变这种增长阶数。

有缓存时，提示预填充只做一次，其注意力成本与 $`P^2D`$ 同阶；后续每个新查询读取 $`P+g`$ 个键，因此生成注意力成本与 $`\sum_g(P+g)D`$ 同阶，线性层只处理新位置。忽略具体常数后，缓存把后续生成的历史注意力重算从平方前缀累加变成线性前缀累加，把重复历史前馈也省去。它没有把历史读取变成常数，也没有消除首次预填充的长提示成本。

当提示很长、生成很短时，首 token 延迟可能由预填充主导；当生成很长且批量很小时，逐步读取权重和缓存的带宽可能很重要。不能根据渐近算术量直接推断真实设备的延迟。教学实验使用小矩阵，Python 循环开销可能比省下的乘法更大，因此本章只验证正确性，不把小 CPU 运行时间当作大模型缓存加速的证据。

<a id="transformer-2-detail-25"></a>

### 6.2 KV 内存公式及一个可手算例子

若每层每条序列有 $`H_{kv}`$ 个键值头，每头维度为 $`d_h`$，缓存物理长度为 $`S`$，每个数占 $`b`$ 字节，则键值数据量为

$$
 \mathrm{bytes}_{KV}=2LBSH_{kv}d_hb.
$$

系数二来自键和值，不应再把查询计进持久历史缓存。这个式子不包含模型参数、激活临时区、缓存对象元数据、分配碎片和优化内核工作区，所以是数据张量的理想量，不是进程总内存。填充到统一物理长度时，无效槽也可能占同样存储；逻辑 token 数较少并不自动节省实际张量空间。

例设层数二十四、批量二、长度四千零九十六、键值头八、每头一百二十八维，每数两字节。计算得到键值数据正好约七百六十八 MiB。若保持查询头不变而键值头从八减到一，理想缓存缩小到八分之一，但实际注意力计算和质量取舍需要另外分析。若并发请求翻倍而长度分布相同，理想缓存也翻倍，这解释了参数能放下不意味着能够承载任意并发。

精度减小也可能减少缓存，但量化缓存需要量化尺度、恢复运算和误差评估，不能只在内存公式里把字节数改小就宣称函数完全等价。应分别报告精度、缓存数据量、误差和生成指标。尤其在 logits 接近并列时，小数值变化就可能改变贪心词，随后整个生成轨迹分叉。

<a id="transformer-2-detail-26"></a>

### 6.3 预填充与解码是不同工作负载

预填充一次处理多个提示位置，矩阵乘法通常更大，能够利用序列维并行；解码通常每条请求只增加一个位置，查询矩阵很窄，需要频繁访问历史缓存。两阶段即使使用同一层参数，也有不同形状、不同并行程度和不同内存访问模式。把平均每秒 token 作为唯一指标，会混合提示长度和输出长度，掩盖用户实际等待的时间。

可分别记录从请求进入到第一个输出的时间、后续相邻 token 间隔、端到端总时间、有效输出 token 数以及并发下吞吐。测量必须说明是否包含分词、排队、编译、缓存命中和数据传输，是否预热以及如何同步。CPU 教学函数无需复杂同步，但在异步设备上仅包一层计时器可能测到任务提交时间而非完成时间。

请求级尾延迟也重要。一个平均吞吐更高的批调度可能让短请求等很久；长请求占用缓存会影响其他请求的资源可用性。研究系统优化时，应固定请求长度分布与到达协议，否则通过换一组更短提示就能得到看似更快的结果。模型机制、缓存实现和服务调度应分别记录，再组合评价。

<a id="transformer-2-detail-27"></a>

## 7. 把生成写成一个可以复现的状态机

<a id="transformer-2-detail-28"></a>

### 7.1 Prefill 返回哪个位置的预测

对真实提示长度为 $`n`$ 的序列，提示最后一个有效位置的 logits 用来预测第一个新 token。右填充批量不能直接读取张量最后一列，因为它可能是填充查询；左填充且末尾都有效时读取最后一列才成立。若实现返回整段 logits，应使用每条样本有效末尾位置索引，或在接口中明确保证末尾是有效 token。

首个新 token 决定后，需要把它作为新输入追加，得到再下一词的 logits；不能把首个新 token 的预测 logits 当作已经处理它之后的状态。一个常见偏移错误是先把抽出的 token 放入返回列表，却没有更新缓存，再用同一 logits 连抽一次。输出可能看起来只是重复，但根因是状态转移少了一次前向。

缓存中保存的是已经作为输入处理过的位置，而输出列表可以包含刚抽出尚未前向处理的 token，二者长度未必在每个控制流时刻相同。明确这个不变量，能避免结束时多处理一次、或者下一轮重复处理同一个 token。建议把状态写成“已处理前缀、待抽样 logits、已返回输出、结束标志”四部分，逐步检查对应关系。

<a id="transformer-2-detail-29"></a>

### 7.2 停止、错误和资源耗尽应有不同状态

遇到模型结束符表示模型选择终止；达到最大新增长度表示资源协议终止；违反输入约束或没有合法候选表示错误。把三者都返回一个字符串，会让评估把预算截断当作正常完成，也不利于排查长度问题。输出记录中应包含停止原因及有效长度，内容展示可以隐藏特殊结束符，但内部计量应保持一致。

若一个停止条件是多个 token 构成的字符串，必须检查边界跨越两次追加的情况，不能只检查新 token 单独的文本。分词解码也可能把一个可见字符串拆成不同 token 序列，所以停止规则是按 token 还是按文本，需要明确。文本级停止可能要求保留一个缓冲区，防止尚未确认的停止串片段过早展示给用户。

当请求被取消或某条样本结束后，缓存应及时从活动请求集合移出或标记无效。继续把无效样本纳入批量有时是实现上的简化，但必须确保其占位 token 不影响真实输出统计，也不会由于共享错误掩码影响其他请求。计算隔离与资源回收是两个不同验收点，只有输出正确还不足以证明系统不会逐步积累无用缓存。

<a id="transformer-2-detail-30"></a>

### 7.3 随机性和批量调度怎样影响复现

相同全局随机种子只有在随机调用顺序相同、分布计算相同的条件下，才可能得到相同样本序列。批大小改变、提前结束样本退出、服务端动态插入新请求，都可能改变随机数分配。若希望请求自身可复现，可以为每条请求使用独立发生器或明确的随机流编号，并记录采样处理顺序。

即便每条请求随机流固定，低精度内核、不同矩阵形状或非确定性算子仍可能使概率轻微变化。靠近累计概率边界的随机数可能落入另一个候选区间，导致后续轨迹不同。复现目标应区分位级 logits 相同、容差内 logits 相同、同种子 token 相同和统计分布相近，不宜把它们统称为“结果一致”。

对研究比较，固定提示、生成预算、温度、截断、停止规则和评估方式比挑选一个种子更重要。若使用随机采样，应跨多个独立随机流报告均值与分布，且同一提示下可以采用成对比较减少难度差异。若只报告一次采样的漂亮示例，结论最多说明存在这样的输出，不能说明稳定质量。

<a id="transformer-2-detail-31"></a>

## 8. 生成评价：让似然、搜索和任务指标各司其职

<a id="transformer-2-detail-32"></a>

### 8.1 验证似然应该独立于解码调参

验证负对数似然使用原模型的条件分布，不应先经过 top-k 或 top-p 再给真实标签打分，否则真实标签可能被截断成零概率，测量对象已经变成采样器。温度是否用于概率校准也应单独声明；训练原始概率与经过温度缩放的评价可以同时报告，但不能让读者误以为模型权重没有改变就意味着预测函数没有改变。

解码超参数可以在验证集选择，再对测试集固定一次评估。若在测试提示上尝试多种温度并挑最好的回答报告，选择过程已经使用测试结果。生成评估尤其容易发生这种隐蔽调参，因为每次输出都看起来像独立样例；应在实验开始时固定候选配置、重复次数和选择指标。

数据去重与前缀重叠同样影响结论。测试序列若只是训练文档的另一种切片，良好似然可能来自记忆。对合成任务，可按底层结构或实体分组切分；对自然文本，需要说明来源和重叠检查范围。单独有正确的因果掩码，并不能防止数据集划分泄漏。

<a id="transformer-2-detail-33"></a>

### 8.2 区分错误的入口与传播

当完整生成失败时，至少要区分第一处错误、错误后的恢复能力和停止行为。某模型可能很少犯首错，但一旦犯错就长时间重复；另一个模型局部准确率稍低，却能恢复约束。只看整句全对会把这些机制压缩成一个数字，难以指导改进。

可以对短任务保留逐位置参考概率、贪心词、当前前缀和停止状态，找出第一处不一致。再固定这个错误前缀，比较模型后续分布是否仍支持合理完成。若参考答案不唯一，还需使用接受所有合法输出的任务检查器，否则会把有意义的替代表达误判为模型错误。检查器本身也要在独立例子上验证。

<a id="transformer-2-detail-34"></a>

### 8.3 搜索预算要进入公平比较

一个系统采样一百条再由评分器选择，另一个只生成一条，最终最佳结果不同不能完全归因于基础模型。候选数量、总生成 token 数、重排序器和外部检索都是系统预算。若评价的是“允许给定资源的最佳系统”，这些组件可以使用；若评价基础模型单次生成能力，则需要固定或剥离它们。

报告最好同时保留原模型似然、单次固定协议任务指标、额外搜索预算后的指标及实际资源。这样既不否认搜索的工程价值，也不把搜索收益误写成模型参数改进。对停止长度不同的系统，还应说明超过预算、空输出和未结束输出如何计分，避免通过删掉困难失败样本得到更高均值。

<a id="transformer-2-detail-35"></a>

## 9. 缓存研究中的等价性边界

<a id="transformer-2-detail-36"></a>

### 9.1 位置重置、滑窗与重编码是不同函数

如果丢掉最早的若干键值但保留后续缓存，保留下来的深层键值仍可能编码已经删除的历史。重新用剩余原始 token 从头计算，会得到另一组隐藏状态。即使两种方案都只保留同样数量的缓存槽，也不代表它们在信息或概率上等价。论文或实现若称“仅使用最近若干 token”，应检查到底限制了原始读取还是持久状态中的信息。

对旋转位置，可以研究统一平移所有位置后旋转内积的变化，但简单平移缓存键并不能一般地把整个深层上下文化状态重新解释成新的短前缀。若模型还使用绝对位置、距离偏置或层内窗口，条件更复杂。最安全的研究方法是先定义希望实现的完整无缓存函数，再判断某种缓存更新是否精确实现它；若只是近似，应量化 logits 与任务差异。

<a id="transformer-2-detail-37"></a>

### 9.2 分支生成与束搜索需要同时重排所有状态

束搜索复制一条前缀到多个候选分支时，每个分支起初可以共享不可变历史，后续追加必须隔离。选择保留束并重新排序后，缓存批轴、有效长度、累计分数、生成 token 历史和结束标志都要使用同一个索引重排。只重排 token 而忘记缓存，程序仍能运行，却把别的前缀状态接过来。

可以构造一个极短、每条前缀 logits 都不同的人工模型，让束在两步中交换排名，检查缓存跟随身份。单纯随机大模型可能恰好对不同前缀给近似输出，难以发现错位。与前面的停止表实验一样，控制性强的反例通常比昂贵但不可解释的大模型试运行更适合验证状态管理。

<a id="transformer-2-detail-38"></a>

### 9.3 输出协议也构成模型的实际使用边界

分词、特殊 token、提示格式和生成限制共同定义使用时的函数。相同权重配上不同起始符或对话模板，前缀就不同，缓存和输出自然不同。工程交付应把这些配置与权重一起版本化，而不是只给一个参数文件再让调用方自行猜测。对评估研究，应把提示格式变化明确列为输入变化。

缓存内容通常是输入历史的派生表示，不宜被当作与输入无关的纯性能数据。是否允许跨会话复用、怎样绑定请求身份、何时清理，都是接口设计问题。本章不展开服务权限体系，但数学上已经说明缓存依赖实际历史；任何忽略这种依赖的共享都可能造成输出混入错误上下文，首先破坏函数正确性。

<a id="transformer-2-detail-39"></a>

## 10. 十六个进阶练习与完整解析

<a id="transformer-2-detail-40"></a>

### 10.1 移位和因果掩码为什么缺一不可

问题：输入起始、甲、乙，标签甲、乙、结束，若取消因果掩码，是否仍是合法下一词训练？

解析：不是。第一位置的输出可以读取后面输入中的甲，第二位置可以读取乙，恰好看到自己的目标，形成泄漏。最后一项结束符未必直接在输入出现，但前两项已经改变了任务。反过来，保留因果掩码却把输入本身当标签，当前位置仍能读取自己的目标。正确性需要同时对齐预测对象和允许条件，不能把“使用了下三角”当作整个训练目标的充分证明。

<a id="transformer-2-detail-41"></a>

### 10.2 两条长度不同的序列应怎样累积梯度

问题：微批甲有九个有效标签，微批乙只有一个，各自平均损失后再等权平均，是否等价于十个 token 的平均？

解析：不等价。甲中每个 token 权重为十八分之一，乙中唯一 token 权重为二分之一；全体平均则每个 token 都为十分之一。若想匹配 token 平均，应把甲的均值乘十分之九，即零点九，乙乘零点一，或先加损失总和再除十。若研究目标就是等序列权重，也可以保留另一种定义，但必须明确说明，而不是把误差伪装成批量实现差异。

<a id="transformer-2-detail-42"></a>

### 10.3 多批困惑度平均为什么不正确

问题：第一批一个 token 损失零，第二批九个 token 每个损失二，平均两个批困惑度与整体困惑度有什么区别？

解析：等批平均是 $`\frac{(1+e^2)}{2}`$，整体 token 平均损失为一点八，因此困惑度为 $`e^{1.8}`$，两者一般不相等。即使两批长度相同，指数的非线性也使平均困惑度与平均损失后取指数不同。正确做法是累计总负对数似然和有效 token 数，在整个验证集合结束后只做一次除法和指数。若分词单位不同，还要说明这个数字无法直接跨分词器比较。

<a id="transformer-2-detail-43"></a>

### 10.4 温度趋零为何不完全等于实现中的贪心

问题：两个 token logits 同为最大值，第三个较小，温度越来越小时分布会怎样？

解析：较小项趋于零，两个并列最大项在没有其他处理时各趋于二分之一；一个通常的确定性`argmax`则按索引规则选其中一个。因而“低温等于贪心”只在最大值唯一等条件下适合作为极限直觉。真实实现中的并列、低精度舍入与处理器顺序都会影响边界。温度零应有单独控制流，不能把除零产生的非数当作一种极低温近似。

<a id="transformer-2-detail-44"></a>

### 10.5 Top-p 为什么必须保留跨阈值项

问题：概率第一项为零点九、阈值零点八，若只保留累计概率不超过阈值的项，会发生什么？

解析：第一项已经超过阈值，会一项都不保留，无法归一化。正确最短前缀应包含第一项，保留质量至少达到阈值。一般做法是根据加入该项之前的累计质量是否小于阈值决定是否保留，并强制第一项有效。数值边界和并列顺序要有明确约定。测试既应包含第一项跨阈值，也应包含恰好等于阈值和多个零概率项，以防仅在普通例子上通过。

<a id="transformer-2-detail-45"></a>

### 10.6 为什么过滤器顺序会影响输出

问题：先做 top-k 再 top-p，与先 top-p 再 top-k 是否总相同？

解析：不总相同。前者在 top-k 后重新归一，累计概率的分母已经改变，所以达到 top-p 阈值的前缀可能更短；后者按原始分布选前缀后再限制数量。即使最终支持集碰巧相同，某些惩罚器若在不同阶段使用概率而非 logits，也可能产生额外差异。实验比较应保存处理顺序，而不能只记录两个超参数值。最简单的验收是用人工可手算的分布逐阶段打印支持与归一化常数。

<a id="transformer-2-detail-46"></a>

### 10.7 贪心为什么可能漏掉最大联合概率

问题：第一词甲零点六、乙零点四，甲后最佳结束概率零点五，乙后零点九九，哪条两步序列概率更大？

解析：甲路径为零点三，乙路径为零点三九六，所以乙更大；贪心却先选甲。这个例子不需要大词表或复杂模型，已经推翻局部最大等于全局最大的说法。束宽二在此特例能够保留乙，但一般有限束仍可过早剪掉最终最优路径。若目标不是最大模型概率而是任务可用性，还需要另一个评价标准，不能把搜索改进与外部正确性直接画等号。

<a id="transformer-2-detail-47"></a>

### 10.8 为什么缓存只保留键值而不保留查询

问题：新 token 做注意力时，为何不需要所有历史查询？

解析：新输出计算的是新查询与历史键的相似度，再用这些权重汇聚历史值；历史查询只用于当时历史位置的输出，那些结果已通过各层状态进入对应缓存。未来不会重新请求历史输出时，没有必要持久保存它们。若任务是双向重新编码或修改中间前缀，历史输出本身会改变，普通因果缓存条件就不成立。这不是查询张量永远没有用，而是特定追加因果计算不需要它。

<a id="transformer-2-detail-48"></a>

### 10.9 缓存长五、追加两词时掩码是什么

问题：已有物理索引零到四，追加索引五和六，两行新查询分别能读哪些键？

解析：第一行读取零到五，第二行读取零到六，再与各样本有效键集合相交。第一行不能读取新块第二词，否则完整前缀因果性被破坏。若错误使用从左上角开始的二乘七下三角，第一行只能读键零，第二行只能读键零和一，会丢掉大部分合法上下文。形状与数值都可能合法，所以必须通过不同块划分与整段 logits 对照发现问题，而不是只检查没有报错。

<a id="transformer-2-detail-49"></a>

### 10.10 左填充后新位置为何不是物理长度

问题：一条提示有三真词，在左边补两槽到长度五，追加新词应该用位置三还是五？

解析：若协议约定真实词从零计数，提示逻辑位置为零、一、二，新词应为三。物理缓存有五槽只是批量布局，不应把无效填充算作模型看到的真实位置。若训练本来采用另一种位置协议，则应遵循那种协议；关键是单条与批量一致。仅屏蔽填充键仍无法修复绝对位置错误，位置输入和可见性必须分别正确。

<a id="transformer-2-detail-50"></a>

### 10.11 为什么仅验证生成词相同不够

问题：有缓存和无缓存生成的前十词完全相同，能否断言两种实现等价？

解析：不能。贪心只读取最大项身份，logits 已经有明显误差但最大项不变时，输出仍相同；随机采样还可能偶然抽中同样词。应在关闭随机层、相同位置与协议下逐位置比较完整 logits，并覆盖不同分块、填充与长度。生成对照是端到端补充，不能替代分布对照。如果数值只是容差内差异，要根据精度说明容差，而不是要求所有设备逐位一致。

<a id="transformer-2-detail-51"></a>

### 10.12 丢弃旧缓存是否严格忘记旧上下文

问题：从一千槽缓存中保留最后一百槽，是否意味着模型只知道最近一百个原始 token？

解析：不一定。保留下来的高层键值在形成时可能读取过被删除的九百个位置，仍携带相关信息。重新用一百原始 token 从头编码则可能得到另一函数。若需要严格的输入遗忘语义，必须分析所有持久状态，而不是只看当前键值槽数。若研究的是有限窗口注意力，也需说明每层局部窗口随深度形成的有效依赖范围；多层局部边界可能通过中间状态传递更远历史。

<a id="transformer-2-detail-52"></a>

### 10.13 缓存内存减半是否让速度也翻倍

问题：把缓存元素从四字节改为两字节，能否直接宣称生成速度翻倍？

解析：不能。理想缓存数据量减半，但执行可能由模型权重读取、投影算术、内核调度或其他阶段主导；精度改变还可能切换不同内核和误差。只有在特定瓶颈与相同其他条件下，带宽收益才可能接近相应比例。应分别报告缓存字节数、首 token 延迟、后续延迟和任务指标，不能从一项静态公式推出整机性能。

<a id="transformer-2-detail-53"></a>

### 10.14 两条请求相同全局种子为何仍可能不同

问题：单独生成和放入一个更大的批量，使用相同全局种子，却得到不同 token，是不是缓存一定错了？

解析：不一定。批量改变随机数消耗与分配顺序，不同矩阵形状也可能带来浮点差异。先用确定性推理逐位置比较 logits；若容差内一致，再检查每请求随机流与采样调用顺序。若 logits 在第一个有效位置就明显不同，应查位置、填充和缓存；若 logits 一致但样本不同，应查随机协议。将问题分层能够避免用重写模型代码解决一个随机数管理问题。

<a id="transformer-2-detail-54"></a>

### 10.15 好的教师强制指标为何仍可能生成失败

问题：验证 token 准确率很高，但自由生成整句正确率低，应该先怀疑哪几类差异？

解析：首先确认两种路径输入、位置、停止和缓存一致，排除实现错误；再定位第一处生成错误，比较参考前缀与自生成前缀下的后续分布；最后分析整句严格指标、答案多样性和长度效应。高局部准确率并不保证长序列全对，模型可能在错误前缀上没有恢复能力。也可能是参考答案唯一性假设错误，检查器把其他合法答案判错。只有逐层排查，才知道应改训练、解码还是评价。

<a id="sec-7-1"></a>

<a id="transformer-2-detail-55"></a>

### 10.16 会话相同长度为何不是缓存共享依据

问题：两条请求都使用同一模型、同样长度提示，能否直接互换缓存？

解析：不能。键值依赖实际 token、位置、前缀上下文以及模型状态，长度只是形状信息。合法共享需要同一计算协议下真正相同的可复用前缀，且后续不会改变该前缀表示。若模型适配器、位置缩放或注意力窗口不同，即使 token 相同也可能不合法。正确的测试可以故意交换两条内容明显不同但形状相同的缓存，确认结果发生变化；接口则应使用明确身份绑定防止这种错误进入正常路径。

<a id="transformer-2-detail-56"></a>

## 11. 综合任务：一份能够复查的自回归实验报告

<a id="transformer-2-detail-57"></a>

### 11.1 给出四种对象各自的证据

第一种对象是训练目标，报告一个短样本的输入、标签、可见集合与有效分母，手算至少一项损失。第二种对象是推理函数，报告整段、逐 token 和多块划分 logits 的最大差，覆盖填充与位置，保留一个故意错误实现能够触发的反例。第三种对象是生成策略，报告温度、截断顺序、结束规则、随机流与预算。第四种对象是任务表现，报告固定划分上的似然和自由生成指标，并说明失败样本如何计分。

这四类证据互相补充，却不能互相替代。一个完整生成样例无法证明损失分母正确；一个雅可比或 logits 对照无法证明模型学到有用知识；一个高吞吐数字无法证明请求之间没有缓存串用。研究报告写清每个测试支持哪一个声明，会比堆叠更多不相干的指标更有解释力。

<a id="transformer-2-detail-58"></a>

### 11.2 进一步研究可以怎样展开

可以固定一个已经通过缓存等价性测试的小模型，再研究不同前缀长度、生成长度和批量的资源曲线；也可以固定推理协议，研究训练前缀扰动对错误恢复的影响。每次只改变一个核心问题，并使用人工可控样本解释机制，随后才扩大任务规模。先有能够理解的反例，再有更大实验，能让新增计算真正带来知识。

如果研究缓存近似，例如压缩、量化或选择性丢弃，基准应是明确的未近似函数。首先测量同前缀 logits 误差，再测教师强制损失变化，最后测自由生成和资源收益。误差可能很小但轨迹分叉，也可能轨迹相同却分布已经明显偏移，所以不能只凭一种观测宣称无损。把正确性、近似误差和实际价值分别说明，才能让读者判断方法适合什么场景。
