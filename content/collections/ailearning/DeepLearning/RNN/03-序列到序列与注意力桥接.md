## 1. 从序列摘要到条件生成

<a id="rnn-3-detail-2"></a>
### 1.1 输入长度与输出长度是两个变量

序列到序列任务给定源序列 $x_{1:S}$，生成目标 $y_{1:T}$，其中 $S$ 与 $T$ 通常不同。翻译、转写、摘要和结构化字符串转换都属于这个框架，但它们的信息可见性与评价要求不同。源序列可能完整可见，也可能以流的方式逐步到达；目标可能要求精确匹配，也可能允许多个正确表述。先说明这些条件，才能判断编码器、注意力与解码协议是否合理。

最简单编码器将源序列压缩成一个向量 $c$，解码器在该向量和已生成前缀条件下逐步输出。固定维向量并不意味着完全无法处理长序列，但它要求把后续生成所需信息提前组织到同一个摘要中。注意力放宽这个读出限制，让不同目标步重新访问不同源位置表示。它改变信息访问方式，却不自动解决目标错位、错误掩码或非法未来信息。

<a id="rnn-3-detail-3"></a>
### 1.2 条件概率的链式分解

给定源序列，自回归模型写为

$$
p_\theta(y_{1:T},\mathrm{EOS}\mid x)=
\prod_{t=1}^{T+1}p_\theta(y_t\mid y_{<t},x),
$$

其中最后一项是结束符。该分解是概率链式法则，具体参数化才决定哪些历史被状态压缩、哪些源信息可以访问。目标长度不是在公式外随意指定的常数，而可由结束符的生成概率共同建模；推理时设置最大长度则是额外的计算与安全边界。

训练负对数似然是各步真实目标的负对数概率之和。若以全部有效目标 token 平均，长序列贡献更多项；若每条序列先平均再求均值，就改变样本权重。结束符应按协议参与目标，填充符通常不参与。忽略结束符会让模型只学习内容分布，却缺少明确何时停止的监督。

<a id="rnn-3-detail-4"></a>
### 1.3 编码器状态与解码器初态

编码器可以是单向或双向循环网络，输出整串表示 $H=(h_1,\ldots,h_S)$。解码器初态可由编码器终态线性投影生成，也可在注意力足够时使用固定零初态。不同层数、方向或状态维度需要显式桥接；不能仅因为两个张量元素个数相同就 `reshape` 成对方接口。若使用 LSTM，隐藏与单元两个初态应分别定义。

初始化桥接是模型的一部分，训练梯度应能从解码器流回编码器。意外 detach 会使前向看起来正确，而编码器得不到预期监督。初态来自源内容时，必须明确源信息在生成开始前是否已全部可见。流式任务不能无条件使用读取完整未来源的编码器终态，否则即使解码器自回归，也不满足在线信息边界。

## 2. 目标右移与教师强制

<a id="sec-1-1"></a>
<a id="rnn-3-detail-6"></a>
### 2.1 把一个三符号目标逐项写出来

目标内容为“甲、乙、丙”时，训练解码输入为 `[BOS,甲,乙,丙]`，监督标签为 `[甲,乙,丙,EOS]`。第一个预测只能看到开始符、源信息和初态；预测乙时可以看到真实甲；预测结束符时可看到完整真实内容。把输入与标签写成同一串而不右移，会让模型读取当前答案再预测当前答案，造成一种容易被误认作快速收敛的捷径。

目标长度包含多少结束位置、填充放在哪里，都应在数据整理函数里固定。若批量最长内容为四，预测步数至少覆盖内容加结束符；短目标在结束符以后补填充，后续位置不计损失。开始符一般不作为内容标签，结束符一般不再作为后续有效输入生成更多答案。特殊符号的角色应分清，不能只看它们都来自同一个词表。

<a id="rnn-3-detail-7"></a>
### 2.2 教师强制为什么能计算似然

训练时每步使用真实前一个目标，所以模型在数据分布的真实前缀条件下估计条件概率。所有位置的对数概率相加，正是当前自回归模型对真实序列赋予的对数似然。它不是由于训练时见到真实历史就“泄漏当前标签”，前提是输入已经正确右移，且计算没有另行读取当前或未来目标。

循环解码器顺序推进状态，但目标输入可以提前构造为整条右移序列。若换成其他支持并行的解码结构，必须使用因果掩码防止当前位置读取未来目标；循环状态本身的时间连接只读过去，不需要因为名称不同而额外制造一个没有作用的全矩阵掩码。应根据真实依赖图判断可见性，而不是把所有序列模块一律套同一种处理。

<a id="sec-7"></a>
<a id="rnn-3-detail-8"></a>
### 2.3 真实前缀与生成前缀的分布差异

推理时真实未来目标不可用，解码器使用自己已经生成的内容。早期错误可能把状态带到训练中少见的前缀上，后续表现因而改变。这常被称为暴露条件差异，但它不自动推翻最大似然目标；它说明似然评价与实际自由生成评价回答不同问题，需要同时观察。

训练 token 损失下降而自由生成较差，可能来自前缀分布差异，也可能来自搜索规则、停止条件、过拟合或目标本来多解。计划采样等方法改变训练使用的前缀，但不应被当作无需分析的默认修复。更直接的基础要求是正确自由解码、按完整序列评价，并记录错误从哪一步开始和之后如何扩散。

<a id="sec-7-1"></a>
<a id="rnn-3-detail-9"></a>
### 2.4 不同多步条件必须分别命名

若每一步预测后都会及时收到真实观测，再继续预测下一步，这是连续单步滚动；若一次性生成完整未来串，中间没有真值，这是自由多步生成。二者可以使用相同循环单元，但评价协议不同。时间预测中把前者的结果标成后者，会高估一次请求的实际能力；文本任务中只报告真实前缀下准确率也有类似问题。

对模型出错后的行为，可以使用受控前缀扰动研究恢复能力，但应标明扰动与真实错误分布的关系。人工替换一个符号不一定代表模型自然会犯的错误。可同时报告真实生成轨迹和受控干预结果：前者说明任务性能，后者帮助定位机制，两者不应相互替代。

## 3. 注意力是查询相关的源端读出

<a id="rnn-3-detail-11"></a>
### 3.1 查询、键和值各来自哪里

设解码旧状态或当前状态生成查询 $q_t$，每个编码器位置提供键 $k_s$ 与值 $v_s$。打分 $e_{t,s}=a(q_t,k_s)$ 后，在有效源位置归一化得到 $\alpha_{t,s}$，上下文为

$$
\alpha_{t,s}=\frac{\exp e_{t,s}}{\sum_{j\in\mathcal V}\exp e_{t,j}},\qquad
c_t=\sum_{s\in\mathcal V}\alpha_{t,s}v_s.
$$

单样本注意力矩阵具有目标步数乘源长度的形状。每个目标步在源轴上归一化，不能误在目标轴上归一化。值维度决定上下文输出维度，键维度只需与打分函数兼容；键和值可以相同，也可以来自不同投影。

<a id="rnn-3-detail-12"></a>
### 3.2 加性与点积打分比较

加性打分可写为 $u^T\tanh(W_qq+W_kk+b)$，允许查询和键先映射到公共空间。点积打分为 $q^Tk$，要求维度兼容；缩放点积再除以键维度平方根，缓解维度增加时某些初始化条件下打分尺度上升。两者都有具体参数化和计算代价，不是仅凭“非线性更多”就能给出普遍优劣。

查询选择在解码状态更新前还是更新后，会改变模型计算顺序。可以先用旧状态读源，再把目标输入与上下文一起送入循环单元；也可以先更新状态再求上下文。两个系统都能定义合理模型，但训练和推理必须一致。复现论文时，画出一步解码的数据流比只写“使用注意力”更准确。

<a id="rnn-3-detail-13"></a>
### 3.3 注意力梯度揭示什么

固定查询且把打分和取值看成两条支路，上下文对某个打分的导数为 $\partial c/\partial e_j=\alpha_j(v_j-c)$。因此一个位置权重虽大，若它的值接近已有上下文，继续增大该打分的影响仍可能很小。真正作用还取决于值、后续读出和其他位置，而非只看权重颜色深浅。

值本身通常来自可训练编码器，并参与键或查询计算，所以对源输入的全导数还包含更多路径。注意力热图可以描述模型当前怎样混合值，却不自动给出原始词的重要性、因果解释或可靠对齐。若要声称某源片段决定答案，应结合遮挡、替换、反事实或其他受控实验，并检查这些干预是否仍符合任务分布。

## 4. 源掩码、目标掩码与空行处理

<a id="rnn-3-detail-15"></a>
### 4.1 源填充必须在归一化前排除

若源长度为二却补到五，注意力应只在前两个有效位置归一化。先对五个位置做 softmax，再把后三个权重乘零而不重新归一化，会让上下文总权重小于一；填充打分还会影响有效位置的权重。这与“这些位置最终没有贡献值”不同，归一化分母已经污染了计算。

通常把无效打分设为负无穷，再做 softmax，使其权重精确为零。前提是每一行至少有一个有效源位置。若整行都无效，所有打分都是负无穷，归一化没有合法概率分布，应明确拒绝空源或提供专门空输入策略。不能靠 `nan_to_num` 把数值错误悄悄改成看似有效的答案。

<a id="rnn-3-detail-16"></a>
### 4.2 目标填充控制损失单位

目标掩码决定哪些预测位置属于训练目标，通常包括真实内容与结束符，排除补齐位置。源掩码控制能读取哪里，目标掩码控制哪些标签计分，两者维度和用途不同。正确屏蔽源填充不会自动屏蔽目标损失，正确忽略目标填充也不会修复源端上下文污染。

损失可按有效 token 总数归一化，也可按序列先平均；零有效目标的样本需明确处理，不能除以零。批量报告时应保存总损失和有效计数再汇总，而不是把不同大小批次的平均损失直接等权平均。否则最终指标随批量切法变化，这通常是汇总协议错误而非模型变化。

<a id="deep-dive-2"></a>
<a id="rnn-3-detail-17"></a>
### 4.3 编码器填充与注意力填充不是同一件事

单向编码器顺序读取时，前面有效位置输出不会受到后面补齐的影响，注意力只访问这些有效输出即可。但若拿补齐后的最终状态初始化解码器，填充仍会污染初态。双向编码器更复杂：反向路径可能先处理填充再到有效内容，即使最后屏蔽注意力位置，也不能撤销有效表示已经受到的影响。

因此完整处理需要同时核对编码器状态计算、初态摘要和注意力可见位置。可以使用打包序列或显式冻结无效状态，并将结果与逐条无填充运行比较。小批量两个不同长度样本是很好的测试，因为它能隔离“批量化不应改变同一样本结果”这个基本不变量，而不依赖真实任务成绩。

<a id="rnn-3-detail-18"></a>
## 5. 实验一：右移、掩码与梯度的最小核对

<a id="rnn-3-detail-19"></a>
### 5.1 三种容易被形状检查遗漏的错误

下面核对右移后的输入与标签，验证源填充不影响上下文、填充值梯度为零，并检查全空源被拒绝。最后让目标填充位置拥有任意极大 logits，证明忽略目标填充后损失与这些值无关。实验用小张量直接断言，而不靠打印一张注意力热图判断。

```python
import torch
import torch.nn.functional as F

torch.set_num_threads(1)
PAD, BOS, EOS = 0, 1, 2
target = torch.tensor([[3, 4, EOS, PAD], [4, EOS, PAD, PAD]])
decoder_input = torch.cat((torch.full((2, 1), BOS), target[:, :-1]), dim=1)
assert decoder_input.tolist() == [[BOS, 3, 4, EOS], [BOS, 4, EOS, PAD]]

def attend(query, source, valid):
    if not bool(valid.any(dim=1).all()):
        raise ValueError('each source must contain a valid position')
    scores = torch.einsum('bd,bsd->bs', query, source)
    weights = scores.masked_fill(~valid, -torch.inf).softmax(dim=-1)
    context = torch.einsum('bs,bsd->bd', weights, source)
    return context, weights

query = torch.tensor([[1.0, -0.5]], dtype=torch.double)
source = torch.tensor([[[1.0, 0.0], [0.0, 2.0], [900.0, -700.0]]],
                      dtype=torch.double, requires_grad=True)
valid = torch.tensor([[True, True, False]])
context, weights = attend(query, source, valid)
short, _ = attend(query, source[:, :2], valid[:, :2])
assert torch.allclose(context, short, atol=1e-12, rtol=1e-12)
assert torch.allclose(weights.sum(dim=-1), torch.ones(1, dtype=torch.double))
assert weights[0, 2] == 0
context.square().sum().backward()
assert torch.equal(source.grad[:, 2], torch.zeros_like(source.grad[:, 2]))
try:
    attend(query, source, torch.zeros_like(valid))
except ValueError:
    pass
else:
    raise AssertionError('all-masked source was accepted')

torch.manual_seed(37)
logits = torch.randn(2, 4, 5, dtype=torch.double)
loss = F.cross_entropy(logits.reshape(-1, 5), target.reshape(-1), ignore_index=PAD)
changed = logits.clone()
changed[target == PAD] = 10000.0
other = F.cross_entropy(changed.reshape(-1, 5), target.reshape(-1), ignore_index=PAD)
assert torch.allclose(loss, other, atol=1e-12, rtol=1e-12)
print('shift, source masking, masked gradients and target loss verified')
```

<a id="rnn-3-detail-20"></a>
### 5.2 验证范围与下一步

实验直接使用源表示，因此没有覆盖双向编码器内部的填充影响；它验证的是注意力与目标损失这两层边界。要测试完整编码器，需额外比较打包批量与逐样本编码。这样的分层验证能明确每个通过的断言支持什么结论，避免把局部正确扩大成整个生成系统已经可靠。

还可以故意在 softmax 后才乘掩码，观察权重和不再为一；把目标输入改成与标签相同，观察右移断言立刻失败；或删掉空源检查，观察负无穷整行产生非有限值。故障注入让测试成为可解释的教学工具，而不只是一次没有报错的运行记录。

## 6. 从概率分布到输出序列

<a id="rnn-3-detail-22"></a>
### 6.1 贪心选择优化的只是当前一步

贪心解码每步选当前条件概率最大的符号。它计算便宜、可复现，但局部最大不保证整串概率最大，因为当前选择还改变后续前缀和条件分布。模型偏好某个第一符号，不代表以它开头的最佳完整序列一定胜过其他开头。这里是搜索问题，即使模型参数已固定也会存在。

采样按条件分布随机选择输出，适合需要多样性的场景；温度、截断采样等会改变抽样分布。贪心、采样和 beam search 对应不同决策规则，不能只改一个参数就假定评价意义不变。需要精确复现的结构转换任务常优先用确定解码；开放文本则还要结合正确性、多样性与人工评价。

<a id="rnn-3-detail-23"></a>
### 6.2 Beam search 保存的是哪些状态

beam search 在每步保留若干高分前缀，每个前缀需要自己的累计对数概率、末符号、解码状态与结束标记。扩展后选中来自哪个父前缀，状态也必须按同样索引重排。只重排 token 而不重排状态，会产生形状合法但条件分布错误的结果，这是序列生成版的实体状态错配。

已经结束的候选不应继续像普通前缀一样反复生成内容。可以放入完成集合，也可使用明确冻结和计分规则。最大长度处未产生结束符的候选应标记为截断，不能悄悄当作正常完成。不同实现的完成集合大小、长度惩罚和停止条件会影响最终结果，应作为解码配置记录。

<a id="rnn-3-detail-24"></a>
### 6.3 长度偏好与分数归一化

序列概率是多个不超过一的数相乘，因此累计对数概率常随长度更负；但概率模型中的结束符与条件分布本来就在建模长度，不能简单宣布所有短句偏好都是搜索错误。长度归一化或惩罚改变候选排序，可能改善某个指标，也可能损害另一个指标。它是需要验证的决策规则，不是恢复真正概率的通用修正。

若评分规则是累计对数概率，未完成前缀的分数对其任何延续构成一个上界，因为后续再加非正数。这个性质可用于安全停止，但换成长度归一化后不能直接沿用同一证明。必须为实际评分定义相应边界，或使用明确最大长度下的保守搜索，不能把一个实现的停止逻辑搬到另一个目标上。

<a id="rnn-3-detail-25"></a>
## 7. 实验二：穷举、贪心与有限 beam

<a id="rnn-3-detail-26"></a>
### 7.1 用完整概率树建立搜索真值

下面的有限树只有两步或三步完整输出，可以穷举得到最高概率序列。贪心第一步选择概率更大的 A，却最终错过 B 开头的最优完整串。beam 宽度二在本例找到最优，但实验不把这种特定成功推广为一般保证；有限 beam 在更深的树上仍可能提前丢弃最终最佳前缀。

```python
import math

EOS = '<eos>'
tree = {
    (): {'A': 0.6, 'B': 0.4},
    ('A',): {EOS: 0.5, 'C': 0.5},
    ('B',): {EOS: 0.9, 'C': 0.1},
    ('A', 'C'): {EOS: 1.0},
    ('B', 'C'): {EOS: 1.0},
}
assert all(abs(sum(row.values()) - 1) < 1e-12 for row in tree.values())

def exhaustive(prefix=(), probability=1.0):
    if prefix and prefix[-1] == EOS:
        return [(prefix, probability)]
    result = []
    for token, chance in tree[prefix].items():
        result.extend(exhaustive(prefix + (token,), probability * chance))
    return result

def greedy():
    prefix = ()
    while not prefix or prefix[-1] != EOS:
        token = max(tree[prefix], key=tree[prefix].get)
        prefix += (token,)
    return prefix

def beam_search(width):
    active = [((), 0.0)]
    finished = []
    for _ in range(3):
        expanded = []
        for prefix, score in active:
            for token, chance in tree[prefix].items():
                candidate = (prefix + (token,), score + math.log(chance))
                if token == EOS:
                    finished.append(candidate)
                else:
                    expanded.append(candidate)
        active = sorted(expanded, key=lambda item: item[1], reverse=True)[:width]
        if not active:
            break
    return max(finished, key=lambda item: item[1])

all_results = exhaustive()
best = max(all_results, key=lambda item: item[1])
assert best[0] == ('B', EOS) and abs(best[1] - 0.36) < 1e-12
assert greedy() == ('A', EOS)
beam = beam_search(2)
assert beam[0] == best[0]
assert abs(math.exp(beam[1]) - best[1]) < 1e-12
assert abs(sum(probability for _, probability in all_results) - 1) < 1e-12
print('greedy', greedy(), 'global best', best, 'beam-2', beam[0])
```

<a id="rnn-3-detail-27"></a>
### 7.2 该搜索实现的确切边界

代码把完成候选单独保存，只对未完成前缀做宽度限制，适合这个很小的完整有限树。它没有实现神经网络的批量状态重排、覆盖惩罚或长度归一化，也没有证明宽度二对任意树最优。例子的作用是把模型概率与搜索质量分开：固定概率树已经能产生局部与全局最优差异，无需先训练复杂网络。

本例 A 后两个分支概率相同，Python 按插入顺序选择先出现的结束符，属于明确的平局规则。实际实现应固定或声明平局处理，尤其在重复词、量化或合成测试中。若实验目标是比较搜索规则，应尽量控制这种细节，避免因隐藏的排序差异导致输出不同又被误解为模型随机性。

<a id="rnn-3-detail-28"></a>
## 8. 评价不能停在真实前缀的 token 准确率

<a id="rnn-3-detail-29"></a>
### 8.1 似然、精确匹配与任务指标

负对数似然评价模型给真实目标分配多少概率，token 准确率评价真实前缀下的局部选择，完整序列精确匹配评价实际生成是否全对。三个指标可以朝不同方向变化。长序列只错一个位置就会让精确匹配为零，却可能仍有很高 token 准确率；反过来，一个分布校准更好的模型可能改善似然但贪心输出不变。

若任务允许多种正确答案，单参考精确匹配过于苛刻，需要合适的结构校验、集合答案或人工评价。翻译与摘要常用的自动指标也各有局限，不能把表面重合直接当事实正确。应围绕任务定义设计主指标，并把长度、停止错误、格式错误与内容错误分开统计，帮助读者理解分数变化的来源。

<a id="rnn-3-detail-30"></a>
### 8.2 结束符、空输出与截断必须统计

模型第一步就输出结束符，可能形成空答案；直到最大长度仍不结束，则是截断输出。这两种都应在评价中保留，而不是清洗掉后只统计剩余样本。若自动去掉重复片段、修补结构或强制加结束符，这些后处理也属于系统，应在所有模型上按同一协议应用并明确记录。

按长度分组能揭示错误是否集中在长输入或长输出。还应检查未见符号组合、罕见实体、源目标长度比和不同来源。若训练样本高度相似，应按实体或模板分组划分，防止仅记忆模板造成虚高评价。人工规则任务则应区分训练集合记忆、同长度新组合与长度外推，不能用一个“测试准确率”混为一谈。

<a id="rnn-3-detail-31"></a>
### 8.3 搜索更好不等于任务更好

更大的 beam 可能找到更高模型分数的输出，却暴露模型本身的短句偏好、重复偏好或错误高置信模式。任务指标不保证随 beam 宽度单调改善。若在同一测试集反复挑 beam 和长度惩罚，也会产生选择偏差；这些超参数应在验证集确定，最终测试只评估固定配置。

因此研究应同时报告模型评分、实际生成质量和搜索成本。若模型分数提高而任务变差，问题可能在训练目标或分布，而不是搜索没有尽力；若两者一起提高，才有更多证据支持搜索改善。把所有生成错误都称为暴露偏差，会掩盖这些不同机制，降低后续实验的针对性。

## 9. 实验三：完整的小型注意力编码解码训练

<a id="rnn-3-detail-33"></a>
### 9.1 实验设计与结论范围

我们枚举字母表 A、B 上长度二到四的全部二十八条源串，目标为倒序串加结束符。模型使用单向 GRU 编码器、显式源掩码、点积注意力和 GRUCell 解码器，训练采用正确右移的教师强制，评价采用自由贪心解码。这是一个有限集合过拟合验收，目标是同时检验编码、掩码、循环状态和生成接口，不能据此声称泛化到未知长度。

为减少依赖，编码器直接处理补齐输入，但解码器初态固定为零，只使用有效源位置的单向编码输出；因此后部填充不会污染被访问的有效状态。若改成双向编码或使用未打包最终状态初始化，就必须重新处理填充边界。训练和生成共享完全相同的一步函数，避免两套计算顺序悄悄不同。

```python
import itertools
import torch
from torch import nn
import torch.nn.functional as F

torch.set_num_threads(1)
torch.manual_seed(43)
PAD, BOS, EOS, A, B = range(5)
sequences = [list(items) for length in range(2, 5)
             for items in itertools.product((A, B), repeat=length)]
count = len(sequences)
source = torch.full((count, 4), PAD, dtype=torch.long)
target = torch.full((count, 5), PAD, dtype=torch.long)
for row, items in enumerate(sequences):
    source[row, :len(items)] = torch.tensor(items)
    target[row, :len(items) + 1] = torch.tensor(items[::-1] + [EOS])
valid = source.ne(PAD)
inputs = torch.cat((torch.full((count, 1), BOS), target[:, :-1]), dim=1)

class TinySeq2Seq(nn.Module):
    def __init__(self):
        super().__init__()
        self.embed = nn.Embedding(5, 8, padding_idx=PAD)
        self.encoder = nn.GRU(8, 16, batch_first=True)
        self.decoder = nn.GRUCell(8 + 16, 16)
        self.output = nn.Linear(32, 5)

    def encode(self, src):
        memory, _ = self.encoder(self.embed(src))
        return memory

    def step(self, token, hidden, memory, mask):
        if not bool(mask.any(dim=1).all()):
            raise ValueError('empty source')
        score = torch.einsum('bd,bsd->bs', hidden, memory) / 4.0
        weight = score.masked_fill(~mask, -torch.inf).softmax(dim=1)
        context = torch.einsum('bs,bsd->bd', weight, memory)
        hidden = self.decoder(torch.cat((self.embed(token), context), dim=1), hidden)
        logits = self.output(torch.cat((hidden, context), dim=1))
        return logits, hidden

    def teacher(self, src, tokens, mask):
        memory = self.encode(src)
        hidden = memory.new_zeros((src.shape[0], 16))
        logits = []
        for step in range(tokens.shape[1]):
            prediction, hidden = self.step(tokens[:, step], hidden, memory, mask)
            logits.append(prediction)
        return torch.stack(logits, dim=1)

    @torch.no_grad()
    def generate(self, src, mask, max_steps=5):
        memory = self.encode(src)
        hidden = memory.new_zeros((src.shape[0], 16))
        token = torch.full((src.shape[0],), BOS, dtype=torch.long)
        finished = torch.zeros(src.shape[0], dtype=torch.bool)
        result = []
        for _ in range(max_steps):
            logits, proposed = self.step(token, hidden, memory, mask)
            predicted = logits.argmax(dim=-1)
            predicted = torch.where(finished, torch.full_like(predicted, PAD), predicted)
            hidden = torch.where(finished[:, None], hidden, proposed)
            result.append(predicted)
            finished = finished | predicted.eq(EOS)
            token = torch.where(finished, torch.full_like(predicted, EOS), predicted)
        return torch.stack(result, dim=1)

model = TinySeq2Seq()
optimizer = torch.optim.Adam(model.parameters(), lr=0.02)
model.train()
with torch.no_grad():
    initial = F.cross_entropy(model.teacher(source, inputs, valid).reshape(-1, 5),
                              target.reshape(-1), ignore_index=PAD).item()
for _ in range(700):
    optimizer.zero_grad(set_to_none=True)
    logits = model.teacher(source, inputs, valid)
    loss = F.cross_entropy(logits.reshape(-1, 5), target.reshape(-1), ignore_index=PAD)
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 2.0)
    optimizer.step()
model.eval()
with torch.no_grad():
    final = F.cross_entropy(model.teacher(source, inputs, valid).reshape(-1, 5),
                            target.reshape(-1), ignore_index=PAD).item()
predicted = model.generate(source, valid)
exact = predicted.eq(target).all(dim=1).float().mean().item()
assert final < initial * 0.1
assert exact >= 0.95
assert torch.equal(predicted.masked_select(target.eq(PAD)),
                   torch.zeros_like(predicted.masked_select(target.eq(PAD))))
print('finite-set overfit only:', 'initial', initial, 'final', final, 'exact', exact)
```

<a id="rnn-3-detail-34"></a>
### 9.2 逐条解释训练与生成的边界

编码输入只有源串，不包含目标；目标输入严格右移；目标结束以后的位置由 `ignore_index` 排除。注意力每一步只在有效源位置归一化。生成一旦结束，后续输出填充并冻结对应状态；尚未结束的样本继续生成，因此批量中不同完成时间不会互相干扰。没有使用目标长度强行决定每条生成何时停止。

所有二十八条字符串都用于训练，所以精确匹配达到高值是实现验收，而非独立测试。若要研究泛化，应另行定义训练与测试规则，例如保留部分同长度组合，或只训练短串再测试更长串。长度外推还需要增大生成上限并避免源数组固定长度限制，不能只换一组数据就沿用当前代码的五步最大输出。

<a id="rnn-3-detail-35"></a>
### 9.3 如果实验失败应该怎样定位

先检查单条最短串能否过拟合，再确认目标是否右移、结束符是否计入损失、特殊符号编号是否一致。随后比较教师强制预测与自由生成的第一个分歧位置：若第一步就错，可能是源编码或初态读出问题；若前几步正确后循环错误，再检查状态传递、结束规则和目标历史。不要直接把训练轮数加十倍掩盖接口错误。

实验使用 CPU 单线程与固定随机种子，便于当前环境复核；不同库版本或硬件的精确损失可能略有不同，断言围绕明显的拟合下降与高精确匹配，而不硬编码某个小数。若修改架构、训练数据或优化协议，应重新执行全部断言，并在报告里更新实际结果，而不是沿用当前运行记录。

## 10. 进阶练习与完整解析

<a id="rnn-3-detail-37"></a>
### 10.1 写出目标右移表

**问题：** 内容为 `[甲,乙]`，目标最大预测步数为四，列出解码输入、监督标签和有效位置。

**解析：** 标签为 `[甲,乙,EOS,PAD]`，输入为 `[BOS,甲,乙,EOS]`，前三个标签位置有效，最后一个不计损失。最后输入 EOS 并非要求继续产生真实内容，它只是右移批量数组的结果，对应标签已无效。生成时不能依赖这个数组，而要根据模型实际结束事件停止。数据整理与推理停止是不同接口，需要分别核对。

<a id="rnn-3-detail-38"></a>
### 10.2 当前目标作为输入有什么问题

**问题：** 解码输入和标签完全相同，损失快速下降，是否说明模型学会了序列转换？

**解析：** 不说明，模型可能读取当前答案再输出同一符号。即使编码器完全无用，也可能获得很低训练损失。应把目标输入右移，并以自由生成评价；还可遮掉源串检查模型是否仍表现异常好。这个反例体现训练成绩必须与信息依赖图一起审查，不能仅凭曲线漂亮认定任务已经完成。

<a id="rnn-3-detail-39"></a>
### 10.3 注意力矩阵在哪个轴归一化

**问题：** 源长七、目标长五、批量为三，单头注意力权重应是什么形状，每个什么切片和为一？

**解析：** 可组织为 $(3,5,7)$，每个样本每个目标步对应的七个源权重在有效源轴上和为一。目标步数由查询数量决定，源长度由键值数量决定。若把 softmax 放在目标轴，模型会让不同目标步竞争源位置，已不是本章定义的逐查询读出。形状仍然相同，所以必须用轴语义和求和断言检查。

<a id="rnn-3-detail-40"></a>
### 10.4 softmax 后乘零为何不够

**问题：** 有效打分都为零，两个有效位置和两个填充位置一起 softmax 后再把填充权重置零，会得到什么？

**解析：** 四个位置原本各四分之一，置零后有效权重和只有二分之一；正确屏蔽后应各为二分之一。上下文整体缩小，且若填充打分变化，有效权重还会变化。应在归一化前排除无效位置，或采用数学上等价的重新归一化并严格处理空行。只令填充值为零无法消除分母污染。

<a id="rnn-3-detail-41"></a>
### 10.5 全空源为什么不能静默接受

**问题：** 一行所有源位置都被掩码，是否可以让 softmax 自己产生一个正常分布？

**解析：** 不可以，零个合法位置不存在按本章定义的归一化分布。全部负无穷可能产生非有限值，全部大负数又可能产生伪均匀分布。应拒绝空源，或显式加入有含义的空输入表示与训练协议。用数值替换把错误压成零只隐藏了语义问题，不能算处理了空样本。

<a id="rnn-3-detail-42"></a>
### 10.6 权重大是否等于影响大

**问题：** 某位置注意力权重很大，能否推出小幅增大该打分会明显改变上下文？

**解析：** 还需看 $\alpha_j(v_j-c)$。若值接近当前上下文，即使权重大，打分的小变化也几乎不改变上下文。后续输出头还可能忽略变化方向。注意力描述混合系数，不自动等于源输入对最终答案的因果贡献。应结合值向量、全导数或受控干预分析，并明确比较的扰动是什么。

<a id="rnn-3-detail-43"></a>
### 10.7 固定向量瓶颈是否是严格不可能定理

**问题：** 编码器只输出固定维向量，是否可以直接证明它不能完成任何长序列任务？

**解析：** 不能，不同任务需要的充分信息不同。例如求和、有限状态判定或简单统计可能用很小状态完成。瓶颈强调复杂目标信息需要被提前压缩，可能增加学习与容量困难，不是对所有任务的否定。有限精度、输入范围与容错要求会影响形式化界。应构造具体冲突或实验，而不是把“固定维”当一条无需条件的失败定理。

<a id="rnn-3-detail-44"></a>
### 10.8 编码器初态桥接为何需要梯度

**问题：** 把编码器终态 detach 后送给解码器，前向值不变，训练是否等价？

**解析：** 不等价，解码损失通过这条状态桥接返回编码器的梯度被删除。若还有注意力支路，编码器可能仍从另一条路径学习，但整体梯度仍改变。应比较全部参数梯度而非只看输出一致。若有意冻结编码器，detach 可以属于明确训练方案；若无意加入，就是计算图错误，不能称作无损节省内存。

<a id="rnn-3-detail-45"></a>
### 10.9 贪心为何错过最高概率整串

**问题：** 第一符号 A 概率零点六、B 概率零点四，随后立即结束概率分别零点五、零点九，为什么贪心可能错？

**解析：** 贪心先选 A，但完整串 A 结束概率为零点三，B 结束概率为零点三六。当前一步最大不等于跨未来分支乘积最大。需要进一步检查其他延续才能确定全局最优，本章概率树已完整列出所有分支。例子针对搜索，不说明模型概率与真实任务质量一致，也不保证有限 beam 总能找到全局最优。

<a id="rnn-3-detail-46"></a>
### 10.10 Beam 状态为何要跟父索引重排

**问题：** 扩展后最好的两个前缀都来自同一父节点，只复制 token 不复制父隐藏状态会怎样？

**解析：** 后续条件概率会以错误状态计算，相当于把另一个历史摘要接到当前前缀上。张量形状仍合法，输出也可能像自然语言，因而错误不易直接察觉。应按选中父索引收集状态，再按子 token 推进，并正确复制所有层、方向与 LSTM 单元状态。可用小概率树或逐前缀单独运行对照，检验批量 beam 与标量实现一致。

<a id="rnn-3-detail-47"></a>
### 10.11 长度归一化为何影响停止证明

**问题：** 累计对数概率只会随扩展下降，为什么这个性质不能直接用于长度归一化分数的停止？

**解析：** 归一化分母随长度变化，延续虽然增加负对数项，也可能通过更大分母改善归一化分数。当前前缀分数不再自动是所有延续的上界。应对实际评分函数构造合法边界，或使用保守规则与最大长度。解码评分与停止条件必须匹配，否则可能提前结束并错失按自己目标更好的候选。

<a id="sec-8-1"></a>
<a id="rnn-3-detail-48"></a>
### 10.12 更大 beam 是否必然提高准确率

**问题：** beam 扩大后模型对数概率提高，外部任务指标下降，这是否自相矛盾？

**解析：** 不矛盾，搜索优化的是模型分数，外部指标评估任务结果，两者不相同。模型可能高估短句、重复串或某类错误，大 beam 更忠实地暴露这种偏好。应在验证集固定解码配置，并同时报告生成质量与成本，不能反复在测试集挑最优 beam 后声称结构进步。

<a id="rnn-3-detail-49"></a>
### 10.13 高 token 准确率能否替代精确匹配

**问题：** 长度一百的每条序列都只错一个位置，token 准确率与整串精确匹配分别可能怎样？

**解析：** token 准确率可为百分之九十九，整串精确匹配却为零。若语法转换要求所有位置都正确，后者更直接；若允许部分信用，可以额外报告编辑距离等指标。关键是主指标对应任务要求。教师强制 token 指标还使用真实前缀，与自由生成条件不同，不能只靠两个数字的名称相似就相互替代。

<a id="rnn-3-detail-50"></a>
### 10.14 为什么有限集合过拟合不等于泛化

**问题：** 正文训练实验二十八条字符串全部生成正确，能够说明长度十的未知串也能正确吗？

**解析：** 不能，所有二十八条都参与训练，只验证当前实现有能力拟合这些映射。长度十引入更长状态链、更多组合和更大输出上限，需要独立数据与代码边界调整。可分别检验同长度新组合和新长度，以区分组合泛化与长度外推。报告必须明确训练与评价是否同一集合，否则会把实现验收误包装为模型能力证明。

<a id="rnn-3-detail-51"></a>
### 10.15 源掩码能否修复双向填充污染

**问题：** 双向编码器先处理补齐数组，注意力再屏蔽填充位置，是否一定等价于逐条无填充编码？

**解析：** 不一定。反向路径可能先读取填充，再把受影响状态传到有效位置；屏蔽填充只排除了直接读出位置，不能撤销有效表示已受到的影响。应使用打包或正确冻结状态，并逐样本对照。单向网络有效前缀的一种便利性质，不能无条件推广到双向与最终状态桥接。

<a id="rnn-3-detail-52"></a>
### 10.16 结束后的状态为什么要冻结

**问题：** 批量生成中一条已结束，另一条继续，若仍更新已结束样本的状态，有何风险？

**解析：** 若输出与评价严格忽略后续内容，可能暂时不影响已完成结果，但会使缓存、调试与后续接口语义混乱；若状态再用于别的请求，还可能泄漏无效更新。明确冻结已完成状态并输出填充，使每条样本在结束后的行为稳定。没有结束而到达最大长度则应标为截断，两种情况不能用同一后处理悄悄掩盖。

<a id="rnn-3-detail-53"></a>
## 11. 研究设计与章节衔接

<a id="rnn-3-detail-54"></a>
### 11.1 三个层面分别建立证据

概率层面检查目标分解、结束符和损失归一化；计算层面检查右移、状态传递与掩码；决策层面检查搜索、停止与外部指标。某一层正确不会自动修复另一层。例如完全正确的 beam 无法挽救读入当前答案的训练协议，合法似然目标也不能保证实际生成搜索已经正确实现。

复现研究时先搭建可穷举的小问题，把模型分数、搜索真值和任务答案分别存下来，再逐步扩展规模。这样能在复杂系统出现异常时判断该回到哪一层。对教科书学习者而言，能解释一个确定反例为什么失败，比复制一个大型模型训练命令更能建立长期可迁移的能力。

<a id="rnn-3-detail-55"></a>
### 11.2 通向更一般注意力结构

本章注意力让循环解码状态访问一组源表示，查询随目标步变化。更一般的结构可以让源位置彼此交换信息，也可以让目标位置在因果约束下交换信息。无论采用哪种模块，查询决定输出位置、键值决定被访问位置、掩码决定合法可见集合这三条原则仍然适用。

后续学习注意力与 Transformer 时，可以把本章的源掩码、目标右移、实际自由生成与搜索反例作为检查清单，但不应把具体循环状态公式强行套过去。结构改变了并行与依赖安排，任务概率与评价边界仍需逐项核对。真正贯穿这些模型的，是对信息流和条件分布的精确描述。

<a id="rnn-3-detail-56"></a>
## 12. 进阶推导：注意力怎样把监督送回源序列

<a id="rnn-3-detail-57"></a>
### 12.1 区分取值路径与打分路径

设损失对上下文的伴随向量为 $u=\partial L/\partial c$，暂把键、值和查询当作独立输入。直接取值路径给出 $\partial L/\partial v_j=\alpha_j u$，打分路径给出 $\partial L/\partial e_j=\alpha_j u^T(v_j-c)$。后一个式子同时包含当前值与整体上下文的差，说明调高某位置权重的效果取决于它替换了怎样的混合，而不是只取决于该位置本身。

若使用缩放点积 $e_j=q^Tk_j/\sqrt d$，则查询梯度为 $\sum_j(\partial L/\partial e_j)k_j/\sqrt d$，键梯度为 $(\partial L/\partial e_j)q/\sqrt d$。当键和值来自同一源表示时，两条梯度必须相加，再通过编码器继续传播。把值复制一份并 detach 虽可能保持前向上下文，却会删除取值路径的学习信号。

这些公式也能检验掩码实现：被严格排除的位置不参与归一化，既不应有直接取值梯度，也不应通过打分影响当前上下文。若源表示之间在编码器内部耦合，被掩码位置的原始输入仍可能间接影响有效表示；所以“注意力局部梯度为零”不能无条件推成“原始填充输入对全模型绝对无影响”。依赖范围必须逐层说明。

<a id="rnn-3-detail-58"></a>
### 12.2 平移不变与相对分差

softmax 对整行打分加同一常数不变，因为分子和分母同时乘相同因子。实现减去最大值正利用这个性质提升数值稳定性。两个有效位置的权重比为 $\alpha_i/\alpha_j=\exp(e_i-e_j)$，因此真正决定相对选择的是分差，单独一个绝对打分没有独立概率意义。

如果所有键都完全相同，纯点积打分无法区分它们，权重会均匀分配；如果值也完全相同，不论权重如何改变，上下文都相同。由此可见，注意力能否提供有效的选择性，取决于编码表示中是否存在可区分信息。给一个已丢失顺序信息的表示集合再加注意力，不会自动恢复原始顺序。

<a id="rnn-3-detail-59"></a>
### 12.3 无位置信息的集合读出与序列结构

同时对键和值使用同一个位置置换，只要查询和掩码同步，单次加权求和的结果保持不变。这是集合读出的一个基本对称性。序列顺序可以来自循环编码器的上下文状态、显式位置表示或其他结构，而不是由加权求和这一操作本身凭空产生。分析模型是否“理解顺序”，应先指出顺序进入计算的具体位置。

本章实验使用单向 GRU 编码，源位置表示已经包含前缀，所以即使注意力读出形式对表示列表置换不变，把原始输入顺序交换再重新编码，表示通常会变化。不要把“重排现成键值对”与“重排输入后重跑编码器”混成同一个实验。前者检验注意力算子的对称性，后者检验整个序列模型的顺序敏感性。

<a id="rnn-3-detail-60"></a>
### 12.4 软对齐不是自动的离散潜变量边缘化

注意力上下文是多个值向量的加权平均，再送入通常非线性的解码输出头。一般有 $g(\sum_j\alpha_jv_j)\ne\sum_j\alpha_jg(v_j)$。因此不能不加条件地把这种计算说成“选择一个源位置生成答案，再对所有选择精确求边缘概率”。这两种结构可能相关，但真实概率模型不同。

若研究确实需要潜在离散对齐，应显式定义对齐变量、其条件分布和输出条件概率，再说明求和、采样或近似推断方法。软注意力之所以便于端到端训练，在于加权平均可微；可微便利并不等于已经建立某个特定潜变量模型的严格解释。把这点分清，有助于避免把热图当成经过证明的唯一对齐答案。

<a id="rnn-3-detail-61"></a>
## 13. 搜索目标、合法约束与完整序列概率

<a id="rnn-3-detail-62"></a>
### 13.1 最大概率、期望风险与采样回答不同问题

最大概率序列是模型分布的众数，不一定是任务损失意义下最优决策。若任务采用某个序列损失，理论上可考虑在模型分布下使期望损失最小的候选；但这个期望通常难以精确计算，且模型分布本身也可能不准确。使用近似候选集时应说明来源和覆盖范围，不能把少量候选的最优称为全空间的最优。

采样旨在反映或改造分布，贪心与 beam 则更偏向高分选择。对开放生成，多样性可能有价值；对结构转换，输出一个随机不同答案可能直接不合要求。评价之前先确定系统要最大概率、控制风险还是提供多样候选，才能判断某种解码方法是否符合用户目标。

<a id="rnn-3-detail-63"></a>
### 13.2 约束后重新归一化会改变排序

若某一步禁止一些符号，可以保留合法符号的原始模型对数概率，只在搜索时屏蔽非法扩展；也可以屏蔽 logits 后重新 softmax。后者在每个前缀下除以该前缀的合法概率总量，这个量随前缀变化，所以不同序列的累计分数排序可能改变。两种做法都可以定义系统，但优化的目标不同。

例如某个前缀原本大量概率放在非法符号上，重新归一化会把剩余合法符号整体抬高，使该前缀在受约束模型中更有竞争力。若任务要比较原模型对合法序列的最高概率，不能默默采用另一种评分；若任务就是生成满足语法的条件化系统，则应明确其逐步条件化规则。约束合法性与模型可信度仍是两个问题，合法字符串也可能事实错误。

<a id="rnn-3-detail-64"></a>
### 13.3 最大长度不是概率模型天然的结束

在最大长度处强制停止，与模型自己输出结束符不同。若把未完成前缀直接当完整答案，最终分数可能没有包含结束符概率；若强行附加结束符，分数又应包含相应项。应预先规定如何处理未完成样本，并在指标中统计截断比例。不同系统若使用不同最大长度，所谓精度差异可能部分来自截断政策。

有限测试树中的所有路径都结束，所以完整串概率之和为一。一般神经自回归模型若允许无限不结束轨迹，不能仅凭每步分布归一化就直接断言有限完成串总质量必为一；还需几乎必然终止等条件。工程上的长度上限保证计算结束，但它是对生成过程的额外规则，不能和模型自身结束行为混写。

<a id="rnn-3-detail-65"></a>
### 13.4 覆盖并非每个源位置恰好访问一次

把某源位置跨目标步的注意力权重求和，可得到一种软覆盖统计，但它没有天然等于一的要求。翻译可能把多个源词合成一个目标词，也可能一词展开多词；摘要更可能有意省略部分来源。强迫所有位置同样覆盖，可能反而违背任务。覆盖惩罚需要依据目标定义，并作为额外决策或训练规则记录。

重复生成有时伴随注意力反复聚焦，也可能来自解码状态、输出头或数据分布。看到重复就直接增加覆盖惩罚，可能暂时压低一个症状而引入遗漏。应先按样例比较注意力、生成前缀和停止分数，确定是哪种机制，再通过受控消融验证修复。可视化适合定位候选原因，不能替代真实任务评价。

<a id="rnn-3-detail-66"></a>
## 14. 训练目标与评价协议的进一步细节

<a id="rnn-3-detail-67"></a>
### 14.1 标签平滑改变的是哪个分布

若对目标类别做标签平滑，交叉熵不再只把全部质量压向单个参考符号，而是拟合一个混合目标。它可能影响置信度和泛化，但也改变训练损失的数值意义。不能把带平滑的训练损失与未平滑验证负对数似然直接当成同一尺度，或把平滑后概率解释为未经修改目标下的最大似然估计。

特殊符号和填充类别如何参与平滑也应说明。目标位置的填充应整体忽略；若把平滑质量分给永远不应生成的填充或开始符，就可能引入不希望的偏好。不同库的默认行为需要按真实接口核对，比较实验时应固定有效词表与目标构造，而不是只记录一个平滑系数。

<a id="rnn-3-detail-68"></a>
### 14.2 数据划分应阻止模板与实体泄漏

同一原始句子的轻微改写、同一用户的相似请求或同一规则模板生成的近重复串，若跨训练测试分布，可能使成绩主要反映记忆。应根据目标部署场景，按实体、来源、时间或模板族划分。随机按行切分只是一个具体协议，并不天然代表未知环境泛化。

构造人工规则数据时，可以独立控制长度、符号组合、变换规则与噪声来源。每次只将其中一项外推，能更清楚理解失败原因。若同时换长度、字母表和规则，成绩下降几乎无法解释。正如本章有限集合实验只检验实现，后续每个新增评价都应先写清它要排除哪种捷径、支持哪种能力结论。

<a id="rnn-3-detail-69"></a>
### 14.3 指标汇总与不确定性单位

每条序列的精确匹配可以直接按请求平均，token 损失应按声明分母汇总，编辑距离还需说明是否按长度归一化。若每个实体贡献多条强相关序列，置信区间宜按实体重采样；把所有 token 当独立样本通常会高估信息量。模型间比较可在同一请求上配对计算差异，再按合适单位重采样。

重采样已固定模型的测试结果，只反映当前测试采样不确定性，不覆盖重新训练随机性、超参数选择和分布漂移。若需要更强结论，应增加独立训练重复与新的测试来源，并说明计算预算。区间很窄也不代表评价协议合法：未来信息泄漏或目标错位可以让错误系统看起来十分稳定。

<a id="rnn-3-detail-70"></a>
### 14.4 缓存、批量化与数值容差

固定模型和源输入时，源编码及键值投影通常可在一次生成请求内缓存，避免每步重算。缓存必须包含正确掩码、样本顺序和模型版本，训练时不能随意缓存跨更新仍要参与学习的表示。若参数已改变却继续复用旧编码，前向已不是当前完整模型，梯度边界也可能错误。

批量生成应与逐样本生成在确定解码、相同初态与模式下近似一致。浮点矩阵内核可能带来微小差异，若两个类别分数几乎平局，argmax 输出可能不同；应区分数值容差与状态错配。可以先比较每步 logits，再检查选中 token，而不是只对最后字符串做一个全或无的断言。重复请求不应因为无关样本加入批次就系统性改变结果。

<a id="rnn-3-detail-71"></a>
## 15. 综合研究任务：把一个生成系统做成可审阅的实验

<a id="rnn-3-detail-72"></a>
### 15.1 先提出能够被否定的机制假设

可以提出“注意力改善长源串转换，是因为目标步能够重新访问源位置”。为了检验，应固定编码器和预算，比较固定摘要与注意力，并按源长度、目标长度和查询跨度分组；还可限制注意力可见范围或打乱键值对应关系，观察预期机制是否被破坏。若只比较两个默认配置，差异可能来自参数量或搜索条件。

也可以研究“自由生成错误主要来自早期前缀偏移”。应记录第一个错误位置，并在相同前缀长度下比较真实前缀与生成前缀后续表现，注意不要在测试集反复调整恢复策略。若模型在真实前缀下也频繁失败，就不应把全部问题归因于暴露条件。机制解释的价值在于排除替代原因，而不是给结果配一个熟悉术语。

<a id="rnn-3-detail-73"></a>
### 15.2 最终报告需要连接哪些证据

报告应同时给出任务与信息可得性、数据划分、词表与特殊符号、目标右移、源端处理、损失分母、训练预算、解码评分与停止规则。随后列出小张量断言、有限集合拟合和独立生成评价，各自明确范围。模型说明还应包括空输入、超长输入、未知符号与未结束输出的行为，便于读者复现真实使用接口。

临时权重、绘图和日志可以在实验后清理，保留 Markdown 中的数据生成、配置、代码与实际结果即可支持本章规模的复核。若未来实验引入大型外部数据，应保留版本与划分规则，而不是把所有中间文件都当最终交付。资料完整性来自信息和证据闭环：读者能知道每项主张如何产生、适用于什么条件，以及下一次运行应该检查哪些断言。

<a id="rnn-3-detail-74"></a>
### 15.3 本章实际运行结果与复核方式

在本资料当前 CPU 环境中，第一段实验的右移、源掩码、无效位置梯度和目标填充损失断言全部通过。第二段概率树实验中，贪心选择 A 后结束，完整概率为零点三；穷举和宽度二的搜索找到 B 后结束，概率为零点三六。第三段固定种子训练的初始有效 token 交叉熵约为一点六零五七，训练后约为零点零零零一六一，自由生成对二十八条训练字符串的精确匹配为一。

这些结果各自支持明确而有限的结论：掩码与目标整理在所测配置下正确，局部最优与整串最优可以不同，完整模型能拟合当前有限映射。它们没有证明新长度泛化，没有测试 GPU、低精度、双向编码或大型词表，也没有证明注意力是本任务唯一或最优方案。读者重新运行时应优先检查断言，损失最后若干小数的差异通常不影响这里的实现验收。

<a id="rnn-3-detail-75"></a>
### 15.4 自主扩展时按因果顺序增加难度

建议先把训练数据改成只含长度二与三的串，固定所有其他条件，再在长度四上独立评价；随后才扩展字母表、输入长度和噪声。每一步都应重新检查源数组容量、目标结束位置和生成上限，否则看似能力下降可能只是固定尺寸截断。若需要比较固定摘要基线，保持相同词嵌入、隐藏维与优化预算，并另报参数数量差别。

接着可以增加一种新的转换规则，例如在源串出现特定标记时改成复制而非倒序，迫使模型同时识别控制信息和执行位置映射。训练、验证与测试应独立采样规则条件，避免标记与长度相关形成捷径。最后再研究带噪输入或多种正确目标，此时评价函数也要同步改变。把难度分阶段增加，才能让每一次失败带来新的知识，而非把所有未知因素压进一个总分。

每次扩展都应保留一组原有小样例作为回归检查，防止修复新任务时破坏旧的结束符或掩码语义。回归检查应覆盖最短合法源、最长当前源、批次中长度不同、提前结束和达到上限这几类边界。若新功能引入随机解码，应将确定性的计算核对与统计性的采样评价分开，避免用一次随机字符串差异判定实现错误。清楚地区分接口正确、有限拟合与统计泛化，是继续学习更大型生成模型的必要基础。
