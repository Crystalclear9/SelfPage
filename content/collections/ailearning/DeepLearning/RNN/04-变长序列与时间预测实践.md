## 1. 把序列长度当作数据契约的一部分

<a id="rnn-4-detail-2"></a>

### 1.1 三种不同的“最后位置”

对一个长度为 $`\ell_b`$ 的样本，真实观测索引为零到 $`\ell_b-1`$。为了组成批量，张量可能扩展到统一长度 $`T`$，其中后面若干槽只是填充。真实最后观测、张量最后槽和循环层最终返回状态，是三个不同概念：不打包时最终状态处理了所有填充；打包时最终状态对应真实序列；双向网络中正向与反向的最终状态又具有不同时间含义。只记住“取最后一个”会在这些设置之间混用。

长度不是可以随意推断的辅助字段。零可以是合法数值观测，负数也可能是正常标准化结果，所以不能通过值是否非零普遍判断有效性。应在数据整理时保存真实长度或有效掩码，并明确是否允许中间缺失、左填充与空序列。标准打包接口主要表达每条样本前部连续有效、后部填充的右填充布局，中间空洞需要另行定义，不宜把任意布尔掩码强行压成一个长度。

循环更新 $`h_t=f_\theta(x_t,h_{t-1})`$ 对零输入通常仍然改变状态，因为存在偏置、循环矩阵和非线性。把填充值设零并不等于跳过更新。若后续只取真实末位置，单向网络早期有效输出可以不受右填充影响；若直接取完整张量最终状态，填充就已进入路径。双向网络的反向通路还可能让尾部填充影响有效前部，必须进一步处理。

<a id="rnn-4-detail-3"></a>

### 1.2 打包与损失掩码承担不同职责

打包让循环层不对超出真实长度的位置执行该样本的更新，改变的是状态计算图。损失掩码只决定哪些输出进入监督，不能撤销此前已经执行的状态更新。若一个填充位置的错误状态后来进入序列摘要、注意力池化或下一块状态，仅忽略它自身标签不能消除影响。反过来，即使打包正确，解包后仍可能产生填充输出槽，读出和损失也需要按真实有效性处理。

设逐位置误差为 $`\ell_{bt}`$，token 平均为 $`\frac{\sum m_{bt}\ell_{bt}}{\sum m_{bt}}`$，等序列平均为 $`B^{-1}\sum_b(\sum_t\frac{m_{bt}\ell_{bt}}{\ell_b})`$。长度不等时两者不同，前者让长序列贡献更多总权重，后者让每条序列权重相同。打包输出的`.data`直接平均通常是按有效位置平均，不能误以为它实现了等序列平均。对实体业务目标还可能需要等实体平均，必须先定义评价单位。

空序列没有真实最后状态，标准打包通常不接受零长度。可以在输入契约拒绝、使用单独的空输入表示，或者定义一个可学习起始状态作为读出；不能为了通过接口把长度改成一而悄悄把填充当真实观测。所有这样的选择都会改变模型处理缺失历史的含义，应在数据和模型两端一致。

<a id="rnn-4-detail-4"></a>

### 1.3 排序、解包与批量身份

按长度排序是执行布局，标签和实体身份必须同步排序。若手动排序输入却保留原标签，训练张量所有维度仍合法，模型会被迫学习错误对应。使用自动排序接口可以减少手动操作，但仍要核对返回输出的顺序约定，尤其是把最终状态接入自定义标签或跨批状态表时。最好的测试是让不同样本内容明显不同，且长度故意不按大小排列。

若排序索引为 $`p`$，输入与标签应都取 $`p`$，输出需要回原顺序时使用逆置换。批内第零行不是稳定实体标识，下一批第零行可能是另一个用户。状态归属必须绑定业务实体或明确连续数据流的编号，不能绑定恰好出现的行号。后面会把这个接口问题与截断反向传播分开讨论。

## 2. 打包和双向末状态的完整数值验收

<a id="rnn-4-detail-6"></a>

### 2.1 实验一：打包等于分别跑真实序列

下面使用三条长度不同、顺序刻意打乱的序列。将打包批量的真实输出和最终状态与逐条运行对照，再改变填充尾部，确认真实结果不变。接着验证双向最终状态与逐位置输出的关系。它覆盖的是确定性双精度循环计算，不包含数据加载或多设备行为。

```python
import torch
from torch import nn
from torch.nn.utils.rnn import pack_padded_sequence, pad_packed_sequence

torch.set_num_threads(1)
torch.manual_seed(61)
lengths = torch.tensor([2, 5, 3], dtype=torch.long)
x = torch.randn(3, 5, 3, dtype=torch.float64)
model = nn.GRU(3, 4, batch_first=True, dtype=torch.float64).eval()
def run(z):
    p = pack_padded_sequence(z, lengths.cpu(), batch_first=True, enforce_sorted=False)
    out, h = model(p)
    out, lens = pad_packed_sequence(out, batch_first=True, total_length=5)
    assert torch.equal(lens, lengths)
    return out, h
with torch.no_grad():
    out, h = run(x)
    for b, length in enumerate(lengths.tolist()):
        single_out, single_h = model(x[b:b+1, :length])
        assert torch.allclose(out[b, :length], single_out[0], atol=1e-12, rtol=1e-12)
        assert torch.allclose(h[:, b:b+1], single_h, atol=1e-12, rtol=1e-12)
    altered = x.clone()
    for b, length in enumerate(lengths.tolist()):
        altered[b, length:] = 100 * torch.randn_like(altered[b, length:])
    out2, h2 = run(altered)
    assert torch.allclose(out, out2) and torch.allclose(h, h2)
    _, unmasked_h = model(x)
    assert not torch.allclose(unmasked_h[:, 0], h[:, 0])
    p = torch.argsort(lengths, descending=True)
    inv = torch.argsort(p)
    sorted_pack = pack_padded_sequence(x[p], lengths[p], batch_first=True)
    _, sorted_h = model(sorted_pack)
    assert torch.allclose(sorted_h[:, inv], h, atol=1e-12, rtol=1e-12)
    bi = nn.GRU(3, 4, batch_first=True, bidirectional=True, dtype=torch.float64).eval()
    packed = pack_padded_sequence(x, lengths, batch_first=True, enforce_sorted=False)
    bo, bh = bi(packed)
    bo, _ = pad_packed_sequence(bo, batch_first=True, total_length=5)
    for b, length in enumerate(lengths.tolist()):
        assert torch.allclose(bo[b, length-1, :4], bh[0, b])
        assert torch.allclose(bo[b, 0, 4:], bh[1, b])
    assert not torch.allclose(bo[1, lengths[1]-1, 4:], bh[1, 1])
print('packing, ordering, padding intervention and bidirectional endpoints passed')
```

双向输出在每个位置拼接正向和反向状态。正向最终状态位于真实末尾，而反向最终状态对应从末尾反向读到开头之后，出现在位置零的反向部分。因此把最后一个真实输出的两半直接当作两个方向的完整摘要一般错误。多层双向网络还要按层与方向解读最终状态第一轴，不能只凭一个切片恰好尺寸正确就认为语义正确。

<a id="rnn-4-detail-7"></a>

### 2.2 双向历史编码不必然构成未来泄漏

如果任务在预测起点已经拥有完整历史窗，双向网络在这段已知历史内部前后读取，是合法的离线编码，不等于读取目标未来。若任务要求每个历史位置都输出一个当时实时可用的预测，反向通路就可能读取相对于那个位置的未来。是否合法取决于预测的时间契约，而不是“使用双向”这个名称。

例如在今天结束后用过去七天预测明天，过去七天内部全部可见；若要求周一早上立即发出预测，却把整周观测送进双向编码器，那就超出当时可得信息。对窗口级预测与逐时在线预测应分开定义标签和读出，不能只检查最终时间戳就认为每个中间输出都合法。

## 3. 时间样本由预测起点而不是窗口行号定义

<a id="sec-1-1"></a>

<a id="rnn-4-detail-9"></a>

### 3.1 统一采用半开区间避免边界歧义

设预测起点为 $`t`$，历史长度为 $`L`$，预测跨度为 $`H`$。输入来自 $`[t-L,t)`$，目标来自 $`[t,t+H)`$。这里 $`t`$ 是第一个未知目标的索引，历史最后一项为 $`t-1`$。训练截止边界为 $`c`$ 时，合法训练标签要求 $`t+H\le c`$；只检查历史结束早于 $`c`$ 不够，因为目标窗可能跨越边界。

如果训练截止在索引一百，跨度三，起点九十八的标签包含九十八、九十九、一百，越过半开训练区间，因此不能作为完全成熟的训练样本。起点九十七对应九十七到九十九，才全部在范围内。这种一位差异在大量滑窗中很常见，应通过最小例子和断言定义，避免靠口头“截止以前”各自理解。

相邻窗口输入重叠，并不自动意味着任何评估都泄漏。真实滚动预测本来就会重复使用已观察历史，测试早期也可以使用训练期间的历史。问题在于训练是否用到了相对于评估起点不应可得的目标、特征、参数拟合或状态，而不是窗口之间是否存在任意共同数值。机械删除所有重叠历史既可能浪费数据，也可能改变部署任务。

<a id="sec-2-1"></a>

<a id="rnn-4-detail-10"></a>

### 3.2 时间戳与可用时间是两个字段

某条观测事件发生在昨天，不代表昨天预测时已经收到它。需要区分事件时间、到达时间和修订版本：预测起点 $`t`$ 只能使用在当时已经发布的版本。历史数据库里的最终值可能经过未来修订，用最终值重建过去特征会形成回看偏差。仅按事件日期筛选并不能防止这种泄漏。

同样，标签可能延迟成熟。今天发生的需求是否退货，要过一段时间才确定；在训练日期拟合时，最近样本的最终标签还不可得。训练可用集合应按标签可用时间筛选，而不是把所有事件发生在训练截止前的行都算作监督。多步预测标签窗还要整体成熟，不能让模型训练使用本来尚未观察到的远期目标。

本章人工项目的观测立即可得、没有修订，目的是先把基本流程做完整。现实数据若不满足该条件，必须加上可用时间与版本筛选，不能直接照搬人工索引规则。对任何时间模型，先审查“这个数在当时真的知道吗”，通常比换一种循环单元更能改善实验可信度。

<a id="deep-dive-2"></a>

<a id="rnn-4-detail-11"></a>

### 3.3 已知未来协变量与未知未来目标

节假日、计划价格或预先确定的设备维护表可能在起点已知，可以作为未来协变量输入；未来实际销量、实际天气或事后修订价格通常不在同一条件下可得。合法输入由发布时间决定，而不是由字段名中是否含“未来”决定。例如天气预报可以已知，但未来实际天气不能假装成当时预报。

若部署会使用带误差的未来协变量预测，训练和评价也应模拟相同来源，不能训练用真实天气、测试宣传成使用天气预报的系统。否则目标映射和输入分布都不一致。可以分别评价理想协变量、实际可得预报和完全无该协变量的方案，明确每个结果对应的条件信息。

<a id="rnn-4-detail-12"></a>

### 3.4 实验二：滑窗标签成熟与延迟到达

下面用短索引序列验证所有训练标签严格位于边界前，并用几条事件展示“按事件时间筛选”与“按当时可用时间筛选”的差别。未来追加的延迟事件不能改变较早起点的合法特征。这个测试将可得性转成可执行断言，而不是只写一条规范。

```python
from dataclasses import dataclass
import numpy as np

L, H, train_end, n = 4, 3, 12, 20
values = np.arange(n, dtype=float)
def origins(start, stop):
    return [t for t in range(max(L, start), stop-H+1)]
train = origins(L, train_end)
assert train[-1] == 9
for t in train:
    history, target = values[t-L:t], values[t:t+H]
    assert len(history) == L and len(target) == H
    assert t-1 < t and t+H-1 < train_end
assert 10 not in train  # its last target would be 12.
validation = origins(train_end, 16)
assert validation[0] == 12 and validation[-1] == 13
assert values[validation[0]-L:validation[0]].tolist() == [8., 9., 10., 11.]
@dataclass(frozen=True)
class Event:
    event_time: int
    available_time: int
    value: float

events = [Event(2, 2, 3.), Event(4, 8, 100.), Event(5, 5, 7.)]
def feature(rows, cutoff):
    return sum(e.value for e in rows if e.event_time < cutoff and e.available_time < cutoff)
assert feature(events, 6) == 10.
assert sum(e.value for e in events if e.event_time < 6) == 110.
assert feature(events + [Event(3, 9, 1000.)], 6) == 10.
assert feature(events, 9) == 110.
# A three-step target is available only after its entire label window matures.
label_delay = 2
mature = [t for t in range(L, n-H+1) if t+H-1+label_delay < train_end]
assert mature[-1] == 7
print('origin boundaries, legal historical reuse and delayed availability passed')
```

边界中的严格小于来自本例定义“起点之前可得”，若业务允许恰好起点时刻发布的数据，应调整等号并统一所有特征与标签规则。重要的是时间契约明确一致，不是某一种不等号永远正确。对修订数据，还需要每条记录的版本选择；本例没有修订，不能宣称已经验证了完整双时间数据库。

## 4. 多步预测：直接、递归与目标权重

<a id="rnn-4-detail-14"></a>

### 4.1 直接多输出的条件对象

直接模型从历史 $`x_{t-L:t}`$ 输出向量 $`\hat y_{t:t+H}`$，可以用一个共享表示和多个输出头，或一个宽度为 $`H`$ 的线性读出。平方误差逐跨度平均时，目标是对每个条件均值的近似；独立点预测并没有自动给出未来路径的联合不确定性。若要模拟整条路径相关结构，需要概率输出或另外的联合建模，而不是只把多个标量拼起来。

共享表示可以在跨度间传递统计信息，但也可能让某些跨度争用容量。损失 $`\sum_{h=1}^Hw_h\ell_h`$ 的权重决定训练关注，远期目标若方差更大，在原尺度平方误差下可能主导梯度。可以按业务成本或训练期尺度确定权重，但不能观察测试误差后再选择最有利权重并当作预先固定的结果。

<a id="rnn-4-detail-15"></a>

### 4.2 递归预测的误差传播不是简单相加

递归模型学一步映射，再把自己的预测反馈。对简化标量系统 $`y_{t+1}=f(y_t)`$，预测误差局部满足 $`e_{t+1}\approx f'(y_t)e_t+\eta_t`$，其中 $`\eta_t`$ 表示该步模型误差。若导数绝对值小于一，扰动可能收缩；若大于一，可能放大；非线性和输入变化还会改变这个系数。因此“递归一定爆炸”与“每步误差只线性累加”都不准确。

训练若只使用真实历史，部署反馈预测，会引入前缀分布差异。可以研究多步展开训练、噪声扰动或其他策略，但每种都会改变训练目标与计算。比较直接和递归时，必须让二者使用相同可得协变量、相同起点和跨度，并说明参数与训练预算，否则容易把额外信息或算力收益误归因于预测方式。

在线性可手算模型中，这个区别更清楚。设 $`y_{t+1}=ay_t+\varepsilon_{t+1}`$，创新独立、均值零、方差为 $`\sigma^2`$，并且模型知道真实系数。固定起点的第 $`h`$ 步条件均值为 $`a^hy_t`$，误差来自未来创新的加权和，所以条件均方误差为 $`\sigma^2\sum_{j=0}^{h-1}a^{2j}`$。当绝对系数小于一时，它随跨度增加但趋于有限极限；系数为一时线性增加；绝对系数大于一时可能快速增加。这里即使模型完全正确，远期误差也会增加，因为未来创新不可预测。

因此观察远期误差上升，不能直接判定循环网络记忆失败或递归实现错误。应与任务本身的条件不确定性、合法基线和模型失配分别比较。若使用真实未来值不断重置起点，测到的是每次仅含一个新创新的一步误差，自然可能显著更低；这再次说明两种评价协议不能混用。

<a id="rnn-4-detail-16"></a>

### 4.3 基线必须服从同一信息契约

最后值基线对所有跨度使用 $`y_{t-1}`$，简单但在高持久性序列上很强。季节复制使用与目标同相位的最近已观察值：季节长度为 $`s`$ 时，若 $`h<s`$，可用 $`y_{t+h-s}`$；跨度超过一个季节时，要重复最近完整季节，而不能读取实际上还未知的 $`y_{t+h-s}`$。把未来真实值作为季节基线输入，会让基线非法地过强。

线性滞后回归或岭回归能检查循环网络是否真正从非线性或状态建模中获益。它们也要只在训练数据拟合，并使用同样标准化规则。一个人工周期序列可能非常适合线性基线，深模型不赢并不说明代码失败；诚实报告会帮助我们理解什么时候复杂性没有带来价值。

## 5. 完整人工项目：直接三步 GRU 与三个基线

<a id="rnn-4-detail-18"></a>

### 5.1 固定任务、划分与选择规则

我们生成三百六十个时点的带季节项、弱趋势与随机扰动的序列，使用过去十二步预测未来三步。训练观测区间为零到二百一十九，验证目标区间为二百二十到二百七十九，测试目标区间为二百八十到三百五十九。每个样本目标窗完全落在所属区间；较晚滚动起点可以使用此前已经观察到的真实历史，模型参数则在整个验证和测试期间固定。

这个协议是滚动原点、每次重新得到真实历史的直接三步预测，不是站在测试开头一次性预测整个八十步。二者可用信息不同。输入包括标准化历史目标和已知时钟的正余弦；标准化参数只用训练观测拟合。我们按验证集原尺度平均绝对误差从固定检查点选择 GRU，再对测试集只评价选中模型，不能按测试最优检查点回选。

<a id="rnn-4-detail-19"></a>

### 5.2 独立可运行的训练、选择、恢复和评价

代码同时训练一个岭回归直接多输出基线，并计算最后值与季节复制。完整流程没有要求 GRU 必须胜过所有基线，断言关注划分、有限性、恢复一致和误差重算。人工任务的意义是学习如何做可信实验，不是制造一个神经网络必胜的展示。

```python
import copy
import numpy as np
import torch
from torch import nn

torch.set_num_threads(1)
torch.manual_seed(79)
rng = np.random.default_rng(79)
n, L, H, train_end, val_end = 360, 12, 3, 220, 280
time = np.arange(n)
y = np.zeros(n, dtype=np.float64)
for t in range(1, n):
    y[t] = 0.65*y[t-1] + 0.25*np.sin(2*np.pi*t/12) + 0.001*t + rng.normal(0, 0.12)
mean, scale = y[:train_end].mean(), y[:train_end].std()
assert scale > 0
features = np.column_stack(((y-mean)/scale, np.sin(2*np.pi*time/12), np.cos(2*np.pi*time/12)))
def build(start, stop):
    anchors = np.arange(max(L, start), stop-H+1)
    X = np.stack([features[t-L:t] for t in anchors])
    Y = np.stack([y[t:t+H] for t in anchors])
    assert (anchors+H-1 < stop).all() and (anchors >= start).all()
    return anchors, torch.tensor(X, dtype=torch.float64), Y
tr, va, te = build(L, train_end), build(train_end, val_end), build(val_end, n)
assert tr[0][-1]+H-1 == 219 and va[0][0] == 220 and te[0][0] == 280
assert set(np.concatenate([np.arange(t, t+H) for t in tr[0]])) <= set(range(train_end))
class Forecast(nn.Module):
    def __init__(self):
        super().__init__()
        self.gru = nn.GRU(3, 12, batch_first=True, dtype=torch.float64)
        self.head = nn.Linear(12, H, dtype=torch.float64)
    def forward(self, x):
        _, h = self.gru(x)
        return x[:, -1, :1] + self.head(h[-1])
net = Forecast()
optimizer = torch.optim.Adam(net.parameters(), lr=0.01)
target = torch.tensor((tr[2]-mean)/scale, dtype=torch.float64)
best_score, best_step, best_state = float('inf'), None, None
for step in range(1, 201):
    net.train(); optimizer.zero_grad(set_to_none=True)
    loss = (net(tr[1])-target).square().mean()
    assert torch.isfinite(loss)
    loss.backward()
    norm = torch.nn.utils.clip_grad_norm_(net.parameters(), 1.)
    assert torch.isfinite(norm)
    optimizer.step()
    if step % 20 == 0:
        net.eval()
        with torch.no_grad():
            prediction = net(va[1]).numpy()*scale + mean
        score = np.abs(prediction-va[2]).mean()
        if score < best_score:
            best_score, best_step = score, step
            best_state = copy.deepcopy(net.state_dict())
assert best_state is not None
net.load_state_dict(best_state); net.eval()
# Direct ridge with an unpenalized intercept, using only training windows.
A = tr[1].numpy().reshape(len(tr[0]), -1)
center = A.mean(0)
A0 = A-center
Ymean = tr[2].mean(0)
coef = np.linalg.solve(A0.T@A0 + 0.1*np.eye(A0.shape[1]), A0.T@(tr[2]-Ymean))
Xtest = te[1].numpy().reshape(len(te[0]), -1)
ridge = (Xtest-center)@coef + Ymean
last = np.repeat(y[te[0]-1, None], H, axis=1)
seasonal = np.stack([y[t+np.arange(H)-12] for t in te[0]])
with torch.no_grad():
    gru = net(te[1]).numpy()*scale + mean
restored = Forecast(); restored.load_state_dict(best_state); restored.eval()
with torch.no_grad():
    assert torch.allclose(net(te[1]), restored(te[1]), atol=1e-12, rtol=1e-12)
print('window counts:', len(tr[0]), len(va[0]), len(te[0]))
print('selected step / validation MAE:', best_step, best_score)
for name, pred in [('last',last), ('seasonal',seasonal), ('ridge',ridge), ('GRU',gru)]:
    e = pred-te[2]
    mae = np.abs(e).mean(0)
    rmse = np.sqrt((e*e).mean(0))
    assert pred.shape == te[2].shape and np.isfinite(pred).all()
    assert np.all(rmse+1e-12 >= mae)
    print(name, 'MAE by horizon:', np.round(mae,6), 'RMSE:', np.round(rmse,6))
print('GRU overall MAE:', np.abs(gru-te[2]).mean())
```

### 5.3 从结果中读出什么，不能读出什么

验证集选择过程是学习流程的一部分，选中的模型在看测试前已经固定。测试起点之间标签重叠，因此每个误差项不是独立重复。三个跨度的误差需要分别报告；总体平均只是按当前等权跨度定义的一个汇总。若业务更关心第三步，应在训练与评价前定义相应权重，而不是看到哪一列好就把它挑作主指标。

人工序列的未来正余弦在数学上已知，但模型仅输入历史时钟，避免扩大示例接口。若加入未来日历特征，对所有可使用它的基线也应公平提供；否则网络与基线的信息不同。弱趋势可能让固定训练标准化在后期出现分布变化，这不是通过全体序列重新标准化就应被“修复”的错误，而是部署中的一个实际挑战，应通过合法的重训或鲁棒设计研究。

## 6. 状态跨批传递：数值连续与梯度连续分别决定

<a id="sec-6-1"></a>

<a id="rnn-4-detail-22"></a>

### 6.1 独立窗口和连续流是两种学习问题

独立窗口训练通常为每个样本重置状态，模型被要求只根据指定历史窗预测；连续流训练则把上一块最终状态传给下一块，模型能够依赖更早历史。两者即使每块输入长度相同，实际条件信息也不同。比较时若一个模型使用连续状态，另一个仅有短窗，就不能把差异只归因于循环单元结构。

状态传递还要求严格时间顺序。若随机打乱滑窗，却把上一批状态原样传下去，模型会混入无关历史；若窗口重叠，还可能重复处理同一段观测，把时间推进两次。可以选择无重叠连续块来维护状态，或明确每个窗口从可重建的状态开始，不能把独立滑窗与连续流两套逻辑混用。

多实体系统需要一张实体到状态的映射。每条新块先按实体取对应状态，按本批顺序堆叠；前向后再按实体写回。实体开始、结束、时间断裂和模型版本更新时的重置条件都要明确。状态表可以在数值上正确，却因没有过期清理占用越来越多内存；计算正确性和生命周期管理都应单独验收。

<a id="rnn-4-detail-23"></a>

### 6.2 Detach 保留历史数值但切断历史导数

设第一块状态为 $`h_a=f_\theta(x_{1:a},h_0)`$，第二块损失为 $`L_2(g_\theta(x_{a+1:T},h_a))`$。完整梯度包含第二块内部参数路径，以及 $`\frac{\partial L_2}{\partial h_a}\cdot\frac{\partial h_a}{\partial\theta}`$。对边界状态 detach 后，前向数值不变，但后一项被删除。截断反传是计算与梯度偏差的折中，不能称作无损节省显存。

如果每处理一块就更新参数，下一块使用的是旧参数形成的边界状态和新参数的更新函数，甚至不再对应一次固定参数下完整长序列的前向。它可以是有效的流式训练算法，但分析与复现时应把更新频率写清。若要单独比较完整与截断梯度，应在同一参数、同一前向数值和同一损失下进行，避免混入优化器更新差异。

只 detach 其中一个状态分量也可能错误。LSTM 同时有隐藏状态和单元状态，通常需要按协议处理两者；多层状态还包含层轴。一个递归函数把状态元组逐项 detach，往往比只处理表面一个张量更可靠。评估推理无需反向图时可以使用禁用梯度上下文，但这不等于允许随意重置数值状态。

<a id="sec-8"></a>

<a id="rnn-4-detail-24"></a>

### 6.3 实验四：同前向、不同梯度与实体重排

用一个标量线性递推即可精确展示截断效应。第二步损失在两种路径上数值完全相同，但完整梯度多一条跨边界路径。随后用简单累加状态检查实体顺序变化必须按身份取回，避免把行号当身份。两部分都不需要训练大网络，反而更容易手算。

```python
import torch

def gradient(detach_boundary):
    w = torch.tensor(0.5, dtype=torch.float64, requires_grad=True)
    h0 = torch.tensor(1., dtype=torch.float64)
    h1 = w*h0 + 2.
    boundary = h1.detach() if detach_boundary else h1
    h2 = w*boundary + 3.
    loss = h2.square()/2
    loss.backward()
    return h2.item(), w.grad.item()
full_value, full_grad = gradient(False)
cut_value, cut_grad = gradient(True)
assert full_value == cut_value == 4.25
assert full_grad == 12.75 and cut_grad == 10.625
assert full_grad != cut_grad
# Entity-specific numeric states; the second batch reverses row order.
states = {'alice': 0., 'bob': 0.}
def consume(batch):
    result = []
    for entity, observation in batch:
        states[entity] += observation
        result.append(states[entity])
    return result
assert consume([('alice', 1.), ('bob', 10.)]) == [1., 10.]
assert consume([('bob', 20.), ('alice', 2.)]) == [30., 3.]
row_based_wrong = [1.+20., 10.+2.]
assert row_based_wrong != [30., 3.]
print('same forward:', full_value, 'full/truncated gradients:', full_grad, cut_grad)
print('entity states after reordered batch:', states)
```

这个反例证明“不等价”，没有证明截断一定更差。真实训练可能通过多个局部目标学到足够状态，也可能因为长期信用分配缺失而失败。截断跨度、梯度裁剪与学习率应作为可控变量研究，并检查资源收益。前向状态仍含过去信息，所以梯度截断长度也不等于模型实际记忆长度。

<a id="rnn-4-detail-25"></a>

## 7. 重叠标签使误差相关：评价单位不能靠样本数猜

<a id="rnn-4-detail-26"></a>

### 7.1 同一个真实时点可能被预测多次

起点 $`t`$ 的第三步目标和起点 $`t+1`$ 的第二步目标可能指向同一实际时点。它们是不同条件信息下的两个预测，因此可以都进入滚动起点评价；但是它们共享真实扰动，不能当作完全独立观测。评价表应同时保留预测起点、跨度、目标时间和实体编号，以便按研究问题选择汇总单位。

如果业务每个实际时点只使用最新预测，主指标可能只计最近起点的一项；如果业务同时决策多个提前量，就应保留每个跨度。两者都可合理，关键是与实际使用一致。将所有重叠预测铺平成一列然后计算误差，实际上选择了等预测对权重，不是等真实时点，也不是等实体权重。

<a id="rnn-4-detail-27"></a>

### 7.2 平均误差方差为何不再是独立样本公式

对平稳误差序列 $`e_1,\ldots,e_n`$，均值方差为

$$
 \operatorname{Var}(\bar e)=\frac{1}{n^2}\left[n\gamma(0)+2\sum_{k=1}^{n-1}(n-k)\gamma(k)\right],
$$

其中 $`\gamma(k)`$ 为滞后协方差。独立假设把所有非零滞后项设为零，若误差正相关，就会低估不确定性。有效样本量的近似只是一种帮助理解的重新表达，不能在非平稳、少量时段或复杂重叠下盲目套公式。这里的误差还可以是两模型的成对损失差，而不仅是原始预测残差。

同一时间块内的天气、设备故障或需求冲击会同时影响多个起点和跨度；逐行自助重采样破坏这些相关结构，容易得到过窄区间。可以考虑按连续时间块、整条实体序列或其他符合设计的单位重采样，但块长度与平稳性前提需要解释。不同方法估计的是条件于当前训练模型的测试波动，还是包含重新训练的不确定性，也必须明确。

<a id="rnn-4-detail-28"></a>

### 7.3 成对比较保留任务难度的一致性

比较模型甲乙时，对同一个预测起点和跨度计算损失差，能消除一部分共同任务难度。若分别对两模型误差各自重采样、再比较均值，就丢失成对关系。时间块重采样应把两模型及所有相关跨度一起抽取，保持同一实际冲击的对应。

只有一段未来测试期时，区间不能自动代表所有可能年代、政策或设备环境。明显结构变化可能比抽样波动更重要，应按时间段、波动强度或已知事件分组报告。分组应预先定义或明确标为探索，避免在测试后只挑某模型有优势的片段。统计区间不是掩盖数据来源限制的装饰。

<a id="rnn-4-detail-29"></a>

### 7.4 必要间隔来自标签成熟与训练协议

训练和验证之间留间隔常被当作通用防泄漏操作，但间隔长度应该由标签跨度、发布延迟和特征计算规则推导。若训练标签已经全部在截止前成熟，验证起点读取此前已观察历史通常合法；不必因为历史重叠而把所有近邻都删除。若标签持续数日、特征由未来平滑构造或数据有延迟，则可能需要更长清除区。

间隔也不能修复全体数据拟合标准化或事后修订特征，因为泄漏发生在预处理函数本身。应先建立起点可得数据集，再拟合各折预处理，最后根据具体重叠依赖增加清除策略。把所有问题都归结为“多留几天”，容易得到看似严谨但仍然使用未来信息的流程。


<a id="rnn-4-detail-30"></a>

## 8. 尺度、缺失、概率预测和漂移的进阶处理

<a id="rnn-4-detail-31"></a>

### 8.1 标准化参数的时间范围与重训节奏

训练期拟合的均值和尺度在测试期固定，是本章项目的明确选择。若部署每周滚动重训，则每个重训起点可以用当时合法历史重新拟合尺度与模型；相应验证也应模拟这个学习算法，而不是把固定模型测试和滚动重训结果混在一起。每次拟合参数都有它的时间有效范围，应该与权重版本绑定。

用整个测试期的均值尺度预先标准化历史，会让早期预测间接知道未来分布。即使只泄漏统计量、不泄漏逐个目标，也改变了预测可得信息。在线标准化如果只累计已观察数据可以合法，但当前值是否先更新统计再标准化、状态重置如何处理，都影响函数定义。为每个起点构造可重复的历史快照，比简单声称“在线处理”更有说服力。

多实体尺度也要区别：每实体独立尺度使模型关注相对波动，却可能抹去规模信息；共享尺度保留绝对差异，却可能让大实体主导损失。可以额外把实体规模作为静态特征，或选择等实体目标。任何尺度策略都要只用训练或当时可得历史，尤其新实体不能借用它未来完整轨迹的均值。

<a id="rnn-4-detail-32"></a>

### 8.2 缺失观测与无事件不应混为一谈

某小时没有记录，可能表示真实数值为零、传感器离线或数据尚未到达。这三种语义需要不同处理。前向填补只使用已知过去通常可实现，但长时间重复旧值会隐藏故障；可以增加缺失指示和距上次观测的时长，让模型知道填充值的来源。线性插值若使用缺口后观测，在离线重建里合理，在当时预测里可能非法。

不规则采样的循环模型还应看到时间间隔，否则连续两条记录可能被当成相同时间距离。把所有缺口都补到固定网格是一种选择，但会增加序列长度和大量缺失槽；直接事件序列则需要时间信息。打包只处理每条序列长度不一，不自动理解事件间隔，更不会替我们决定缺失机制。

<a id="rnn-4-detail-33"></a>

### 8.3 点预测损失对应不同统计对象

平方误差在适当可积条件下的最优点预测是条件均值，绝对误差对应条件中位数。若训练用平方误差、验证用 MAE 选择，两个标准可以同时使用，但要知道它们关注的统计对象不同。高度偏斜分布或异常冲击下，均值和中位数可以差很多，不能把两种输出差异简单判断为模型好坏。

分位数预测可使用 $`\rho_\tau(u)=u(\tau-\mathbf1_{u<0})`$，其中 $`u=y-\hat q_\tau`$。对条件分布求期望并考虑次梯度，最优值满足累计分布在目标分位数附近跨过 $`\tau`$。这个目标提供边际分位数，却不自动给出各跨度的联合路径覆盖。多个分位数独立拟合还可能交叉，需要通过结构或后处理研究，且后处理的拟合也不能使用测试标签。

<a id="rnn-4-detail-34"></a>

### 8.4 区间覆盖要按跨度和场景分别检查

一个九成预测区间，应说明是单个跨度边际覆盖、每条路径全部跨度同时覆盖，还是某个实体群的平均覆盖。这些事件不同。三个跨度各自九成覆盖，不意味着整条三步路径也有九成全覆盖；相关性决定联合概率。区间宽度和覆盖要同时报告，单靠极宽区间获得高覆盖没有足够决策价值。

时间依赖和分布漂移使某些基于交换性的校准保证不直接适用。可以研究滚动校准、块方法或特定依赖假设下的理论，但不能把独立同分布示例的有限样本结论直接搬到任意时间序列。本章不在主项目里添加未经验证的预测区间，保留这一边界，比给点预测误差随意乘一个常数更严谨。

<a id="rnn-quantile-risk"></a>

### 8.5 分位数损失怎样得到分位数：离散例子与联合覆盖

设点预测为 $`q`$，风险为 $`R(q)=E[\rho_\tau(Y-q)]`$。在 $`Y`$ 不等于 $`q`$ 的样本上，损失对 $`q`$ 的导数为 $`\mathbf1[Y<q]-\tau`$；若条件分布连续，期望导数是 $`F(q)-\tau`$。有概率原子时不能把等号位置忽略，零次梯度条件应写为 $`F(q^-)\le\tau\le F(q)`$。这就是“累计分布跨过目标水平”的精确含义，最优分位数也可能不是唯一。

手算离散变量：$`Y=0`$ 的概率为 $`0.8`$、$`Y=10`$ 的概率为 $`0.2`$。平方损失最优值为均值 $`2`$，绝对损失最优值为中位数 $`0`$，九成分位数为 $`10`$。当 $`0<q<10`$ 时，九成分位数风险为 $`0.8\times0.1q+0.2\times0.9(10-q)=1.8-0.10q`$，随 $`q`$ 增加而下降；超过十后两类残差都不再为正，风险转为上升，因此最优为十。若把 $`\tau`$ 改为 $`0.8`$，区间 $`[0,10]`$ 上风险为常数，说明同一个分位水平可以有一整段最优预测。

上下分位数构造的区间也要区分边际和联合事件。三个跨度的漏覆盖事件记为 $`E_h`$，即使每个都满足 $`P(E_h)\le0.1`$，联合界也只能普遍保证 $`P(\text{三步全部覆盖})\ge1-\sum_hP(E_h)\ge0.7`$。若每步覆盖恰为 $`0.9`$ 且三个事件独立，全路径覆盖为 $`0.9^3=0.729`$；若三个漏覆盖事件完全重合且各有 $`0.1`$ 概率，则为 $`0.9`$。这给出了可复算的区别，而不是仅说“相关性影响覆盖”。

若希望三步全路径覆盖至少九成，一个充分办法是分别控制每步漏覆盖不超过 $`\frac{0.1}{3}`$，再用上述并集界。它不要求三个跨度独立，但可能保守；如何获得这些每步的真实覆盖保证，仍需相应的数据机制与校准假设。单纯把训练分位水平设高，或把预测区间拉宽，不自动建立有限样本、漂移下或条件于任意历史的保证。

## 9. 本项目的实际数值与方法比较

<a id="rnn-4-detail-36"></a>

### 9.1 完整运行没有得到“复杂模型必胜”

在本章给定种子与版本的 CPU 运行中，训练、验证、测试分别得到二百零六、五十八、七十八个起点。验证选择第一百次更新，验证 MAE 约为零点一二九九三。测试三个跨度的 GRU MAE 约为零点一四零八、零点一七一二、零点二零六八，总体 MAE 约为零点一七二九。这些结果来自实际代码，而不是预期示意。

同一测试起点上，最后值的三个 MAE 约为零点一八三九、零点二九八九、零点四一六八；季节复制约为零点一六六七、零点一六八八、零点一六五四；岭回归约为零点一一一三、零点一三零九、零点一四四六。GRU 优于最后值，但在总体上没有胜过季节复制与岭回归，第三步差异尤其值得研究。主结果应原样保留，不能通过测试反馈继续改网络再冒充原来一次独立评价。

<a id="rnn-4-detail-37"></a>

### 9.2 为什么这个结果具有解释价值

生成机制本身是线性递推加正弦与弱趋势，线性滞后模型配合时钟特征已经有很合适的表达。GRU 多了非线性和更多参数，不一定在有限训练数据上带来收益。季节复制在周期稳定时强，但无法专门建模短期自回归噪声；最后值在远跨度对周期变化反应不足。这些结构解释与观察一致，但仍是对本例的机制分析，不是关于所有时间序列的普遍排名。

若希望检验非线性优势，应事先定义另一个非线性生成机制，重新划分训练验证测试，而不是不停修改当前测试直到神经网络领先。若希望改进当前项目，可以在训练和验证中研究隐藏宽度、输入长度、直接多步权重或未来日历特征，再对一个新的保留测试段评价。科学问题与评价边界应一起更新。

<a id="rnn-4-detail-38"></a>

### 9.3 恢复一致证明了什么

代码把最佳状态复制到内存，再装入新建同结构模型，测试相同输入输出一致。这验证模型参数恢复与当前推理结构匹配；没有保存优化器、随机状态和批次位置，因此不宣称能够无差别继续原训练轨迹。也没有模拟跨进程部署、外部数据契约或历史状态表恢复，不能把一个状态字典测试当成完整系统交付认证。

这里不保存任何中间权重文件，符合只保留学习资料的要求。读者要扩展为实验工程，可以在临时目录测试序列化再清理，并把输入尺度、时钟定义和训练截止一起记录。权重本身不足以确定完整预测函数，数据处理状态同样需要版本化。

<a id="rnn-4-detail-39"></a>

## 10. 怎样把这个项目扩展成严格的研究

<a id="rnn-4-detail-40"></a>

### 10.1 滚动折验证的是学习算法

建立多个按时间前进的训练截止，每折只使用当时已经成熟的标签，预处理在各自训练期重新拟合。验证起点和跨度按相同协议生成，候选配置在多折表现上选择。测试保留更晚一段，在选择完成后一次评价。这样评价的是“给定历史怎样训练和更新模型”的学习算法，而不只是某个幸运截止的权重。

滚动折之间训练数据可能大量重叠，因此各折分数也不是独立重复。报告折间变化可以揭示漂移，不宜直接把折数当独立样本量计算极小标准误。若每折重新调参，需要把调参嵌套在该折可得数据里，否则外层验证又会被用作训练选择。预算有限时可以减少候选，但应保留清晰的时间信息边界。

<a id="rnn-4-detail-41"></a>

### 10.2 冷启动与已有实体预测是两个泛化方向

按时间分割但同一实体出现在训练测试，评价已有实体的未来；按实体隔离则评价新实体，可能还要求处理未知类别嵌入和缺少个体尺度。两者不能用同一个分数替代。实际部署同时有老实体和新实体时，可以分开设计测试，再按预期比例汇总，但比例和权重应预先定义。

模型如果拥有每实体可学习嵌入，测试新实体不能直接使用训练时为它预留并利用未来数据更新的向量。可以使用统一未知嵌入、静态特征生成表示或少量合法历史适配，并分别报告适配成本。状态表的冷启动策略也属于模型接口，不是上线之后再随意补一行零就没有影响的问题。

<a id="rnn-4-detail-42"></a>

### 10.3 先用故意错误的版本检验测试强度

把填充尾部改成极大值，正确打包结果应不变；把标签窗放跨训练边界，成熟性断言应失败；把实体状态交换，身份测试应发现；把未来真实目标接入递归输入，信息可得性审查应阻止。这些是测试的正向控制：它们证明测试不只是一直显示绿色，而是能够对我们关心的错误作出反应。

也要有不应失败的干预，例如改变未使用的未来观测不能改变过去预测，调整纯填充槽不应改变真实摘要，同一实体分成连续两块与一次完整无梯度前向应数值一致。只有同时检查合法不变量和非法反例，才能逐步建立模型与数据协议的可信度。

<a id="rnn-4-detail-43"></a>

## 11. 二十道进阶练习与完整解析

<a id="sec-8-2"></a>

<a id="rnn-4-detail-44"></a>

### 11.1 零填充后取最后状态为什么不可靠

问题：真实长度二的序列补到五步，填充值都是零，为什么最终状态未必等于第二步状态？

解析：循环函数对零输入仍有循环矩阵、偏置和非线性，第三到第五步仍会继续变换第二步状态，零不是“没有执行”的指令。单向网络可以索引真实末输出，或打包让后续更新不存在；双向网络还需保证反向通路不读尾部填充。只把填充标签忽略不能修复被污染的摘要。一个直接反例是把所有输入矩阵设零、循环权重非零并带偏置，状态仍可在零输入下变化；因此不能把某个碰巧不变的初始化当成普遍保证。

<a id="rnn-4-detail-45"></a>

### 11.2 打包后还需要损失掩码吗

问题：已经用真实长度打包循环输入，解包后对全部矩形输出计算平均误差是否正确？

解析：一般不正确。解包重新创建填充槽，它们不是实际监督对象，全部平均会让填充数量改变目标权重。可以在打包输出和同样顺序打包标签上计算有效项损失，也可以解包后按长度构造掩码。还要决定按 token、序列还是实体平均，三种分母不同。打包负责计算路径，损失掩码负责监督集合，不能用一个接口替代另一个决策。

<a id="rnn-4-detail-46"></a>

### 11.3 手动排序怎样恢复标签对应

问题：长度依次二、五、三，排序后输入顺序为第二、第三、第一，预测输出怎样与原标签对齐？

解析：若训练损失在排序空间计算，就同步重排标签与所有实体字段；若输出要回原顺序，则应用排序索引的逆置换。不要再次应用同一个排序索引，因为置换通常不自逆。可以令每条序列携带易识别的常数身份特征，逐条运行得到基准，再比较排序批量恢复后的结果。只有形状检查不能发现标签错位，数值对应才是验收重点。

<a id="rnn-4-detail-47"></a>

### 11.4 双向最后输出能否当完整摘要

问题：一个双向循环输出最后真实位置，前后两个方向的状态都已读完整序列吗？

解析：正向部分已经从开头读到末尾，反向部分在末尾位置通常只刚开始反向读取，不能代表整个序列的反向摘要。完整反向末状态对应输出位置零的反向部分，或者从返回最终状态的正确层方向切片取得。多层时先明确第一轴排列，再取最终层两个方向。这个错误很容易产生尺寸合法的二倍隐藏向量，却丢失预期的信息，应以逐条双向前向对照验证。

<a id="rnn-4-detail-48"></a>

### 11.5 历史窗口内双向编码为何可能合法

问题：起点为今天结束，输入过去七天，双向编码是否读取未来？

解析：相对于今天结束，这七天全部已发生且假设已可得，窗口内部双向处理并未超出合法信息。若同一网络还要输出上周某天当时实时预测，后半历史就相对于那个时点是未来，目标定义变了。是否泄漏取决于预测时刻和数据可得性，而不只取决于网络是否双向。需要为每个输出位置标注它代表哪个预测起点，才能准确判断。

<a id="rnn-4-detail-49"></a>

### 11.6 标签跨度三如何判断训练成熟

问题：训练允许索引零到九十九，起点九十八预测三步，可以纳入训练吗？

解析：它的目标为九十八、九十九、一百，最后一项越界，不能在当前截止视为全成熟样本。起点九十七的目标为九十七到九十九才合法。若目标还有发布延迟，条件应再推迟相应成熟时间。本章采用半开区间，写成 $`t+H\le c`$ 最容易核对；业务若采用闭区间，要转换后统一，不能在输入窗和标签窗使用不同端点约定。

<a id="rnn-4-detail-50"></a>

### 11.7 验证输入包含训练历史为什么不必删除

问题：第一个验证起点使用训练最后十二个观测，是否因此泄漏？

解析：如果这些观测在该起点真实已知，作为历史输入合法。模型训练本来就可以使用过去，验证任务是向未来预测，不是要求输入原始行完全不重叠。应禁止的是训练使用验证未来目标、预处理用未来统计量或状态读取未来，而不是任何历史共享。若目标是新实体或完全独立序列，则又需要不同划分。先定义部署问题，再决定隔离对象，不能把一种切分口号当作所有任务的标准。

<a id="rnn-4-detail-51"></a>

### 11.8 事件时间早为何仍可能不能用

问题：某传感器四点记录到八点才上传，六点预测能否使用？

解析：不能，尽管事件时间早于六点，可用时间晚于六点。历史数据库在事后可能把它排列到四点，按事件时间重建会让六点模型拥有当时不存在的观测。应筛选到达或发布时间，并按当时版本计算特征。修订数据还要选择当时可得的版本，而非最终修订值。这类问题不是通过时间排序本身就能解决，需要数据来源保留相应信息。

<a id="rnn-4-detail-52"></a>

### 11.9 递归多步可否每步接真实测试值

问题：用一步模型做十步预测，每步把测试真实下一值接回，再报告十步误差，是否合法？

解析：如果声称站在同一起点一次预测十步，就不合法，因为后续真实值当时未知。这样计算得到的是不断获得新观测后的一步滚动误差，不是固定起点十步误差。若任务本来就是每步更新，则合法，但应正确命名。递归固定起点必须反馈自身预测，并给已知未来协变量使用当时确实已知的版本。两种协议的误差可能差很多，不能用同一个“多步预测”标签混淆。

<a id="rnn-4-detail-53"></a>

### 11.10 季节跨度超过一个周期怎样避免偷看

问题：季节长度十二，要从一个起点预测二十步，直接取目标索引减十二对应真实值是否都合法？

解析：不是。远期部分索引减十二后仍可能落在起点以后，读取了未知真实观测。合法季节复制应把最近已观察完整周期重复铺到未来，或者递归使用先前预测值。对每个输出单独检查来源索引是否严格早于起点，是最简单的验收。本章跨度三小于十二，所有季节来源都在过去，因此短公式合法，不能不加改动推广到任意跨度。

<a id="sec-8-1"></a>

<a id="rnn-4-detail-54"></a>

### 11.11 Detach 是否让模型忘掉旧历史

问题：连续流边界把状态 detach，模型是否只能记住当前块？

解析：不是。状态数值仍然由旧历史形成，新块前向继续使用它，所以过去信息仍可影响输出；被切断的是新块损失沿边界回到旧块计算的导数。记忆范围和信用分配范围不同。若把状态直接清零才会丢弃这条数值记忆，但那又改变前向条件。研究截断反传时，要同时报告状态是否传递、导数在哪切断以及参数何时更新，不能只给一个截断长度。

<a id="rnn-4-detail-55"></a>

### 11.12 为什么逐块更新不等于完整长序列训练

问题：每块保留状态、反向后立刻更新参数，即使不重置状态，为什么也不等价于一次长序列梯度？

解析：边界状态由更新前参数产生，新块使用更新后参数，整条前向不再是同一参数函数的连续展开；如果还 detach，就额外删除跨块梯度路径。完整长序列训练则在固定参数下构图、对总目标求导后再更新。逐块算法可能更省资源并适合流式数据，但其数值与梯度都可能不同。比较时应固定损失权重并单独分析截断与更新频率，而不是把差异全归给显存。

<a id="rnn-4-detail-56"></a>

### 11.13 状态为什么不能绑定批量行号

问题：第一批第一行为甲用户，第二批第一行为乙用户，直接传第一行状态有什么后果？

解析：乙会收到甲的历史表示，模型条件变成混合两实体的序列，通常既不符合任务，也可能造成错误的跨实体信息依赖。应按实体标识取回状态，按当前批顺序堆叠，更新后按标识写回。批量重排测试要故意交换行顺序，确认输出仍等价于各实体单独连续运行。形状和损失有限不构成身份正确的证据。

<a id="rnn-4-detail-57"></a>

### 11.14 重叠预测为什么仍可以保留

问题：同一个真实时点被两个起点、两个跨度预测，评价时是否必须删掉一个？

解析：不一定。它们代表不同提前量下的决策，可以都是业务需要的预测。需要明确评价是等预测对、等真实时点还是只看最近可用预测，并据此汇总；统计推断时承认这些误差相关。若为了扩大样本数而把所有重叠误差当独立，区间可能过窄。若机械删掉所有重叠，则又可能丢失真正关心的远期性能，改变研究问题。

<a id="rnn-4-detail-58"></a>

### 11.15 逐行 bootstrap 为什么可能过于自信

问题：模型差异的损失序列连续多天同向，逐行重采样有什么缺点？

解析：它破坏时间相关结构，把一段共同冲击拆成许多看似独立证据。可以在适当前提下按连续时间块成对重采样，保留两模型和相关跨度的共同关系，或使用针对依赖数据的其他方法。块长度、非平稳性与测试期长度都会影响结论，不能只换个采样函数名就宣称区间可靠。还应说明是否重新训练模型，区别条件测试波动与完整学习流程不确定性。

<a id="rnn-4-detail-59"></a>

### 11.16 全序列标准化为何不是无害预处理

问题：只用全体序列均值和方差，没有直接把未来标签输入模型，为什么仍可能泄漏？

解析：统计量编码未来分布，早期预测的标准化结果因此依赖尚未发生的数据。若未来发生均值跳变，模型提前通过尺度得到提示，条件信息已不同。合法选择是只用训练期拟合，或按起点累计已可得历史，并模拟部署中的更新规则。把预处理放在神经网络外部，不会让其免于信息可得性审查；完整预测函数包含这些状态。

<a id="rnn-4-detail-60"></a>

### 11.17 MAE 与 MSE 对应什么最优点预测

问题：同一个条件分布偏斜明显时，为什么以两种损失训练的输出可能系统不同？

解析：平方误差的期望最小点是条件均值，绝对误差的期望最小集合是条件中位数。偏斜或混合分布中二者可以不同，输出差异不必来自优化失败。选择损失应对应业务成本，再用同一标准比较模型。本章训练平方误差、验证按 MAE 选检查点，流程明确但两阶段偏好并不完全相同；进一步研究可以比较直接优化绝对误差，仍只在训练验证阶段选择。

<a id="rnn-4-detail-61"></a>

### 11.18 每个跨度九成覆盖是否保证路径九成覆盖

问题：三个未来跨度分别都有九成区间覆盖，整条路径全部落入区间的概率是否也至少九成？

解析：没有这种一般结论。三个事件的交集概率取决于相关性，即使每个边际都是九成，联合覆盖也可能明显更低。联合保证需要以路径事件为目标校准或建模，不能只复用边际结果。时间依赖还会影响校准前提，因此必须说明保证适用的抽样结构。评估时应分别报告边际覆盖、同时覆盖和区间宽度，避免只展示其中最有利的一项。

<a id="rnn-4-detail-62"></a>

### 11.19 神经网络输给岭回归是否意味着项目失败

问题：本章 GRU 测试误差高于岭回归，应该继续改到获胜才交付吗？

解析：不应拿当前测试反复调参直到获胜。项目已经展示真实的学习流程与基线比较，生成机制偏线性，岭回归的优势有合理解释。可以基于训练验证开展新的配置研究，再使用新的保留测试评价；也可以事先定义非线性机制检验另一个科学问题。强基线帮助发现复杂方法没有带来收益，本身就是有价值结果。诚实比较比预设某类模型必胜更能满足进阶学习。

<a id="rnn-4-detail-63"></a>

### 11.20 恢复参数相同为何不足以恢复整个预测系统

问题：新模型加载最佳状态字典后输出一致，是否说明线上时间预测服务可以完整恢复？

解析：它只证明同结构同输入下参数恢复一致。完整系统还需要历史尺度、特征版本、时钟编码、实体状态表、数据可得快照和模型版本协议；继续训练则还涉及优化器、随机状态和数据位置。若缺少这些信息，即使权重相同也可能给出不同输入和状态。应按交付目标设计恢复测试，逐层增加跨进程、数据状态和连续流验证，不要让一个小断言承受它没有测试的系统结论。

<a id="rnn-4-detail-64"></a>

## 12. 综合验收：从一段代码走向可靠的预测材料

<a id="rnn-4-detail-65"></a>

### 12.1 用四张表固定问题而不是增加口号

第一张表列字段的事件时间、可用时间、修订规则和训练时是否可用，避免用事后数据库替代历史真实条件。第二张表列每个分割的预测起点、标签最后时间和拟合范围，证明监督成熟、预处理合法。第三张表列序列长度、排序索引、实体身份和状态重置条件，说明张量布局没有破坏业务对应。第四张表按跨度和时间段列所有基线与模型的成对误差，注明选择规则和测试只使用一次的范围。

这四张表并非为了让文档看起来更正式，而是分别承担可得性、时间划分、状态身份和统计比较的检查。若其中一张无法填写，说明相应问题尚未被定义清楚。补更多循环层或增加训练轮数不能代替这些定义。可以先在十几个人工时点上完整填表，再扩大到真实长序列，这样边界错误更容易被看见。

<a id="rnn-4-detail-66"></a>

### 12.2 把教材例子扩成可证伪的小研究

建议先固定本章完整项目作为基准，再提出一个具体假设。例如“在同样合法历史与预算下，增加未来日历特征能改善远期误差”，就为 GRU 与线性基线都加入同样已知信息，并预先决定看哪个跨度；若假设“截断跨度影响长期信用分配”，就构造需要跨块记忆的受控任务，保持状态数值与损失归一一致，只改变导数边界。每个假设都需要一个失败时仍能解释的反例。

最后把实际结果、条件和限制写回章节：哪些结论是公式严格推导，哪些是当前人工数据上的观测，哪些需要新的测试期或更强假设。保留最终 Markdown 与可直接复制的独立代码即可，运行时临时文件要自动清理。这样资料增加的每一段内容都在回答一个明确问题，而不是仅仅把章节写长。
