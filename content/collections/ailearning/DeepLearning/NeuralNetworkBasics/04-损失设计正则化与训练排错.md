## 1. 把优化目标写成完整公式

前面三章解释网络如何前向、梯度如何传播，以及初始化、归一化和残差怎样改变优化几何。本章不再重复一份普通训练循环，而是研究循环到底在优化什么：损失的单位和分母、类别与样本权重、软标签、随机正则以及优化器的衰减。随后把这些选择与可执行排错连接起来。训练代码能够运行，仅表明张量接口相容；只有目标表达、数据含义、梯度与更新都一致，下降曲线才有可解释的对象。

最小目标可以写为 $`J(\theta)=D^{-1}\sum_i m_iw_i\ell(f_\theta(x_i),y_i)+\lambda\Omega(\theta)`$。掩码 $`m_i`$ 决定纳入单位，权重 $`w_i`$ 决定重要程度，分母 $`D`$ 决定归约尺度，正则项表达参数偏好。这个公式尚未说明 $`i`$ 是记录、像素、词元还是整条序列，也没有说明权重是否依赖当前参数。实际项目必须把它们全部写清楚，不能仅用“平均损失”四个字代替。

若分母和权重都是与参数无关的固定量，梯度可直接把它们带到求和外；若权重来自模型当前置信度，则对权重是否求导会改变目标。某些难例重加权算法会刻意停止权重梯度，另一些把它作为损失定义的一部分。两种行为不能在实现中无声互换。以下先讨论固定掩码和权重，再在研究部分分析更复杂的依赖。

<a id="deep-dive-1"></a>
<a id="nn4-detail-2"></a>
### 1.1 数据风险、正则目标与报告指标

数据损失用于拟合预测，正则项约束参数或函数，报告指标评价任务。三者可以不同，但必须明确。例如训练交叉熵、使用权重衰减、以宏 F1 选择模型是一个完整方案；训练总损失下降不保证宏 F1 单调提高，权重范数下降也不证明分类关系学得更好。日志应至少分开记录数据项、显式惩罚、有效单位数和主要验证指标。

训练模式下的 Dropout、随机增强和归一化统计会让训练损失与评估损失对应不同函数。若训练日志还包含正则项，而验证只计算数据项，训练数值高于验证完全可能。正确比较需要先统一对象：可以另做一次无增强、评估模式、相同数据损失的训练集诊断，再与验证比较。不要先假定“训练一定低于验证”，再为正常数值差异增加无关修复。

<a id="nn4-detail-3"></a>
### 1.2 缩放损失不一定只是缩放学习率

对无动量普通 SGD，若所有数据梯度统一乘常数且没有其他项，相应调整学习率可以得到同一步更新。但加入固定正则、梯度裁剪、Adam 的二阶矩和数值稳定项、混合精度溢出策略或调度后，简单等价通常不再成立。特别是从求和改成均值却保持正则系数不变，会改变数据项与惩罚项的相对强度，而不只是速度。

例如原目标为 $`\sum_{i=1}^n\ell_i+\lambda\Omega`$，整体除以 $`n`$ 后应写成 $`n^{-1}\sum_i\ell_i+(\frac{\lambda}{n})\Omega`$ 才保持同一最优集合；若写成均值加原来的 $`\lambda\Omega`$，相对惩罚增强了 $`n`$ 倍。随机小批训练还需要解释每步估计对应完整数据风险的哪一种归一化，不能同时把批大小、学习率与正则都当互不相关的旋钮。

## 2. 掩码和有效分母：统计单位先于代码轴

两条序列分别有两个和八个有效词元，每条平均损失为一和三。按有效词元平均为二点六，按序列等权平均为二。前者随机抽一个有效词元，后者先随机抽一条序列再抽其词元。长序列在两个目标中的总贡献不同，都可能合法，但不能称作可互换实现。像素、检测框、变长图结构和多输出缺失同样需要先选择统计单位。

<a id="nn4-detail-5"></a>
### 2.1 有效元素平均与序列平均的梯度

设第 $`b`$ 条序列有效数为 $`n_b`$，元素损失为 $`\ell_{bt}`$。有效元素目标为 $`L_t=\frac{\sum_{bt}m_{bt}\ell_{bt}}{\sum_b n_b}`$；序列等权目标为 $`L_s=B_+^{-1}\sum_{b:n_b>0}n_b^{-1}\sum_tm_{bt}\ell_{bt}`$，其中 $`B_+`$ 是至少有一个有效元素的序列数。若所有长度相同，两者一致；否则一般不同。空序列是否排除，也必须明确，不能默认为它拥有一个零损失观察。

对前一个目标，某元素梯度系数为有效总数倒数；后一个目标中系数为有效序列数与本序列长度乘积的倒数。因此短序列中的单个元素可以获得更大权重。如果数据中长序列与难度相关，改变归约会改变有效学习任务。调学习率无法恢复这种样本之间相对贡献变化，因为不是所有梯度都乘同一个常数。

<a id="nn4-detail-6"></a>
### 2.2 掩码不能在任何数值操作后随意相乘

无效位置的标签可能是专用索引，直接送进普通交叉熵会越界；无效回归目标可能为 NaN，先计算误差再乘零仍可能得到 NaN。即使使用`where`把前向结果盖住，未选分支中不合法操作也可能在反向产生非有限导数。稳妥做法是在需要处先筛选合法位置，或在操作之前构造安全输入，并明确保留哪些梯度路径。

掩码还应与输入轴严格对齐。序列 logits 常为批、时间、类别，但某些损失接口要求类别轴在第二维；错误地转置或展平可能让维度恰好相容却交换样本。先在两条短序列上写出每个位置的标签和有效性，核对展平后对应关系，再扩展大张量。单看最终损失是标量，无法证明轴语义正确。

<a id="nn4-detail-7"></a>
### 2.3 空有效批次不是一个普通零损失批次

当整个批次没有有效目标，均值分母为零，没有可定义的经验损失。可以按协议跳过该批次，并记录跳过数量；如果为分布式同步需要保留可求导零，应清楚它只是通信和图结构安排，不是新增一个有效观察。不能简单把分母夹到一，然后把空批次计入 epoch 平均，稀释真实损失。

跳过反向不总等于跳过更新。优化器的动量、衰减或已累积梯度仍可能移动参数。空批次政策应明确是否执行`zero_grad`、`step`、调度器和计数；最直观的单机教学政策是跳过整个优化更新及其按更新计时的调度。若采用别的政策，应验证实际参数变化，不要仅根据损失为零猜测不会发生任何事。

<a id="nn4-detail-8"></a>
### 2.4 实验一：掩码、两个目标与梯度位置

下面用回归张量构造两条变长序列，忽略位置含 NaN。先筛选有效目标，避免执行非法差值；分别计算有效元素和序列等权目标，核对手算，并确认无效位置梯度为零。它不训练网络，专门检查目标表达是否等于设计。

```python
import torch

target = torch.tensor([[1., 1., float("nan"), float("nan")],
                       [2., 2., 2., 2.]], dtype=torch.float64)
mask = torch.isfinite(target)
prediction = torch.zeros_like(target, requires_grad=True)
per_valid = (prediction[mask] - target[mask]).square()
token_loss = per_valid.sum() / mask.sum()
sequence_loss = torch.stack([
    (prediction[b, mask[b]] - target[b, mask[b]]).square().mean()
    for b in range(len(target)) if mask[b].any()
]).mean()
assert torch.allclose(token_loss, torch.tensor(3., dtype=torch.float64))
assert torch.allclose(sequence_loss, torch.tensor(2.5, dtype=torch.float64))
grad = torch.autograd.grad(token_loss, prediction)[0]
assert torch.all(grad[~mask] == 0)
assert torch.all(torch.isfinite(grad))
assert torch.allclose(grad[0, :2], torch.full((2,), -1/3, dtype=torch.float64))
assert torch.isnan(((prediction - target).square() * mask).sum())
empty = torch.zeros_like(mask)
assert empty.sum() == 0
print("token / sequence:", token_loss.item(), sequence_loss.item())
```

本实验中第一条有效数为二、第二条为四，所以元素平均为三、序列平均为二点五；它与前面长度二和八的说明例是两个独立算例。读者可以将第二条增加到八个位置，检查元素平均如何改变而序列等权保持不变。再让所有序列长度相等，应恢复两个目标相同，这提供一个边界测试。

<a id="nn4-detail-9"></a>
### 2.5 微批与全局有效数

若一个大批拆为多个微批，先对每个微批单独平均再等权累积，会让有效数少的微批拥有过高权重。正确做法是累积可加分子，并按整个更新组的有效总分母归一，或对每个微批均值乘以它的分母占比。若需要先反向后才知道后续有效数，可以先收集分母信息或采用一致的梯度缩放策略，不能假设所有微批都等长。

分布式默认将各工作进程梯度平均时，本地分母不同也会产生类似偏差。若希望全局元素平均，应使用全局有效数，并考虑默认平均带来的进程数因子：每个进程对本地分子乘进程数再除全局分母，平均后才恢复全局分子梯度除全局分母。具体实现还受通信与累积边界影响，应另做多进程等价实验；本章不把单机例子的通过扩张为分布式实现保证。

### 图解：同一批有效位置，分母怎样改变梯度

![变长批次中有效元素平均与序列平均的损失和梯度对照](images/04-concept.svg)

**直接沿用实验一，避免把排错换成另一个分类问题。** 预测全部为零，A 只有两个标签一，B 有四个标签二。A 的误差平方和为二，B 为十六；按六个有效元素平均得到三，先在各序列平均再等权得到二点五。图中灰色两格表示没有观测，不是标签零，也没有进入两个分母。

两个目标对 A 的每个有效预测的梯度分别为 $`-\frac13`$ 与 $`-\frac12`$，对 B 的每个预测分别为 $`-\frac23`$ 与 $`-\frac12`$。这可直接由平方误差导数 $`2(\widehat y-y)`$ 乘相应单位权重得到。A 的改变量比例是 $`\frac32`$，B 的却为 $`\frac34`$，所以不存在一个公共学习率，把所有坐标的两套更新同时对齐。无效位置梯度则为零，前提是在非法差值或索引操作前就排除了它们。图把目标值、分母和梯度接在一起，用于区分目标定义差异与反向实现错误。

下方再把两套梯度变成一次实际预测坐标更新，以无动量、无正则 SGD 和共同步长 $`0.3`$ 为例。元素平均给 A 的每个有效预测增加 $`0.1`$、给 B 增加 $`0.2`$；序列等权则全部增加 $`0.15`$。箭头使用相同长度尺度，只表示本次从零出发的位移，不代表每次迭代梯度都恒定。若想让 A 的两套更新对齐，序列方案的步长需要乘 $`\frac23`$；想让 B 对齐却需要乘 $`\frac43`$，因此一个公共补偿不可能同时满足两者。这个预测坐标实验隔离归约几何，真实共享网络参数还会把各位置梯度通过雅可比汇合。

软件接口中的 mean 也可能有不同分母，例如 [PyTorch 的索引标签与概率标签加权交叉熵](https://docs.pytorch.org/docs/2.10/generated/torch.nn.CrossEntropyLoss.html)分别给出自己的归约式。先确定本图所示的统计单位，再核对接口公式，才能避免把目标变化当作普通学习率变化。

## 3. 类别权重、样本权重与重采样

类别权重通常表示某些标签的损失更重要，样本权重可来自抽样修正、观测可靠性或业务代价，重采样则改变训练样本被看到的分布。三者可能在某些期望目标上对应，但批内方差、重复次数、非线性层统计和训练轨迹一般不同。尤其在小批量、BatchNorm 或自适应优化中，不能只看一行期望公式就宣称完全等价。

<a id="nn4-detail-11"></a>
### 3.1 加权交叉熵改变概率目标

设真实条件类别概率为 $`\eta_c(x)`$，正类别权重为 $`w_c`$。加权条件交叉熵为 $`-\sum_cw_c\eta_c\log p_c`$，在概率单纯形上用拉格朗日乘子求最小，得到 $`p_c^*=\frac{w_c\eta_c}{\sum_kw_k\eta_k}`$。因此输出拟合的是重加权分布，通常不再是原始总体概率。这个推导假设模型可以表达最优分布，有限训练时还会有其他误差。

若二分类真实正类概率为十分之一，正类权重九、负类权重一，理想加权输出为二分之一，而非十分之一。它可能对应更有价值的决策边界，但直接把二分之一解释成原总体发生率就错了。可以在目标总体上校准或使用明确先验修正假设，仍需独立数据检验。提高少数类召回与保持原概率含义不是自动同时获得的结果。

<a id="nn4-detail-12"></a>
### 3.2 分母约定与接口差异

加权目标可以写成权重损失和除以样本数，也可以除以权重和。固定批次中两者只差常数，但常数随批次类别构成改变，便会改变步间梯度尺度。PyTorch 的索引标签加权交叉熵均值使用有效目标权重和，而概率标签路径的均值使用元素数；即使概率标签是一位有效编码，也不应在有权重时假定两条路径的默认归约相同。下面直接用运行验证这个差异。

对索引加权均值，统一把所有类别权重乘同一正数，分子分母一起缩放，因此损失和梯度不变；对按样本数归约的加权软标签，统一缩放权重会缩放损失。若代码将样本权重再次乘在已经归约的标量上，就无法正确表达每条记录的贡献。通常先取逐元素损失，再按明确分母处理，最容易审查。

<a id="nn4-detail-13"></a>
### 3.3 实验二：一位标签也可能拥有不同默认均值

```python
import torch
import torch.nn.functional as F

logits = torch.zeros((2, 2), dtype=torch.float64, requires_grad=True)
y = torch.tensor([0, 1])
soft = F.one_hot(y, 2).to(torch.float64)
w = torch.tensor([1., 3.], dtype=torch.float64)
hard_mean = F.cross_entropy(logits, y, weight=w)
soft_mean = F.cross_entropy(logits, soft, weight=w)
manual = -(soft * w * logits.log_softmax(dim=1)).sum(dim=1)
assert torch.allclose(hard_mean, manual.sum() / w[y].sum())
assert torch.allclose(soft_mean, manual.mean())
assert torch.allclose(soft_mean, 2 * hard_mean)
assert torch.allclose(F.cross_entropy(logits, y, weight=7*w), hard_mean)
assert torch.allclose(F.cross_entropy(logits, soft, weight=7*w), 7*soft_mean)
eta = torch.tensor([.9, .1], dtype=torch.float64)
weighted_target = eta * torch.tensor([1., 9.], dtype=torch.float64)
weighted_target /= weighted_target.sum()
assert torch.allclose(weighted_target, torch.tensor([.5, .5], dtype=torch.float64))
print("hard / soft means:", hard_mean.item(), soft_mean.item())
```

这里的差异来自接口归约定义，不是硬标签与一位概率标签在未归约交叉熵上不等价。比较两个实现时应先核对逐元素损失，再核对分母，最后核对梯度。若只发现训练曲线差一倍就调整学习率，可能暂时掩盖问题，却仍会在批次构成、正则和累积中继续产生不一致。

<a id="nn4-detail-14"></a>
### 3.4 重采样与重要性修正

若原目标分布为 $`P`$，训练按另一抽样分布 $`Q`$ 取样，在支持覆盖且密度比可用时，可用 $`\frac{P}{Q}`$ 权重估计原目标风险。类别平衡采样不自动保留原风险，若不修正，它优化的是重采样后的偏好。若同时平衡采样又使用原类频率倒数权重，可能重复强化少数类，需要从目标公式重新推导，而不是把两个常见技巧叠加。

重要性权重可能极大，造成高方差。裁剪权重可以稳定训练，却引入目标偏差；自归一化权重也有有限样本性质。应报告有效权重范围、权重集中度和每类实际抽样数，并在目标总体评价。小类重复出现更多次并不创造新的独立信息，尤其同一设备或图像的重复样本不能被当作新增来源来缩小评价不确定性。

<a id="nn4-detail-15"></a>
### 3.5 随机分母使小批均值不再是简单无偏估计

前面的条件最优点针对明确的总体加权风险，或对完整数据使用固定总体分母的目标。若每个小批都除以该批随机权重和，梯度是一个随机比率，其期望一般不等于总体分子期望除以总体分母期望。批次大时可能较接近，极小批时差异可以非常明显。因此知道逐元素权重公式，还不足以推出实际随机训练精确优化了哪个总体目标。

最简单的反例是批大小为一、使用索引标签的加权均值。单条损失分子为该类权重乘交叉熵，分母正好是同一个权重，两者完全抵消。每一步的类别权重没有任何作用，均匀抽样时并没有恢复理想的类别加权风险。若改用按样本数的加权和，权重仍保留；若改用平衡抽样，影响来自抽样分布。

这个边界例说明归约与采样需要一起审查，不能只检查损失对象里确实传入了 weight。为了直接核对这一反例，可以固定单条 logits 和标签，用两组不同的正类别权重分别计算损失与参数梯度，两者在索引均值路径应一致；再换成 sum，差异应恢复。这种只改变一个因素的机制测试，比同时修改采样器、权重与学习率后比较曲线更有判定力。

若目标需要无偏估计一个固定归一化风险，可以使用固定的已知归一化常数或相应重要性估计，但可能增加梯度方差；采用批内自归一化可以稳定尺度，却应承认有限批量偏差。二者没有脱离任务与预算的统一优劣。研究时可以固定同一抽样流，比较批大小、类别组成和归约方式，记录梯度期望的经验近似，而不是只观察最终准确率后猜机制。

若每个批次都强制包含完全相同的类别配额，分母可能固定，此时又与随机组批不同；若最后一批不足配额，等价还会在尾批破坏。可见 batch sampler 也参与了目标定义，必须与损失归约一起记录。对分布式训练，各进程类别组成不同会进一步引入局部比率平均问题。应先确定希望得到的全局加权分子与分母，再根据通信归约推导实现，不应把每台机器的 mean 简单平均后当成全局同一个 mean。

<a id="nn4-detail-16"></a>
## 4. 软标签与标签平滑：目标分布发生了什么变化

软标签是一份类别分布，可以来自混合样本、多个标注者、教师模型或明确的平滑规则。相同形状不代表相同语义：多标签任务通常为各类别分别设置伯努利边缘目标，互斥多分类则要求同一行组成一个概率分布。逐类别使用伯努利损失可以分别估计条件边缘概率，不要求真实标签之间条件独立；只有进一步把这些边缘相乘来解释联合事件概率时，才引入相应的独立模型假设。

本节互斥多分类的软目标应该非负、有限且逐行和为一；多标签的伯努利软目标则逐分量位于零到一，不要求跨类别求和为一。库允许某些不合法值通过接口，并不意味着它们具有概率解释；目标质量需要项目自己的断言。

<a id="nn4-detail-17"></a>
### 4.1 梯度推导与目标质量

对 logits $`z`$、softmax 概率 $`p`$ 和软目标 $`q`$，损失为 $`-\sum_cq_c\log p_c`$。若 $`\sum_cq_c=1`$，梯度是 $`p-q`$。若目标质量总和为 $`s`$，梯度则为 $`sp-q`$，所以未归一化标签同时改变目标与梯度尺度。若目标包含负数，还可能不再具有正常交叉熵下界。自动求导依然能正确求出这个错误函数的导数，因此 gradcheck 无法替代标签语义检查。

把目标分布看成标签不确定性时，还要问不确定性来源是否合适。两个标注者各给不同标签，平均成软分布描述的是某种标注过程，并不自动等于客观类别概率。教师模型给出的软标签可能携带有用类间关系，也可能继承来源偏差。研究应比较合法数据边界和目标机制，而不是只因为标签变软就称训练更有知识。

<a id="nn4-detail-18"></a>
### 4.2 标签平滑的最优点与损失下界

均匀标签平滑写成 $`q=(1-\varepsilon)e_y+\varepsilon u`$，其中 $`u_c=\frac{1}{C}`$。真实标签类的目标概率是 $`1-\varepsilon+\frac{\varepsilon}{C}`$，其他类为 $`\frac{\varepsilon}{C}`$。它不是“给错误类各分配同一个额外概率但保持正确类不变”，总质量必须守恒。对固定目标，交叉熵等于目标熵加 $`\operatorname{KL}(q\Vert p)`$，在可实现情况下最小为目标熵，而不是零。

在总体条件风险中，平滑后最优概率为 $`(1-\varepsilon)\eta+\varepsilon u`$。若使用相同均匀平滑且 $`\varepsilon<1`$，理想最大类别次序保持，但概率向均匀收缩；有限模型、优化和类别权重可能改变结果。它可能缓解过度尖锐，却不保证改善校准或准确率。不能把训练损失无法降到零视为故障，也不能将平滑后的输出直接声称为未平滑真实发生率。

<a id="nn4-detail-19"></a>
### 4.3 平滑、类权重与蒸馏不能无声叠加

先平滑再按类别加权，目标相当于对平滑分布各分量再乘权重并归一；先对原条件分布重加权再平滑，通常不同。不同顺序回答不同偏好。若软件同时提供两个参数，应查明它实现的公式与分母，不能凭参数名字自行假设。最可靠的做法是构造两个样本、三个类别，手算逐项损失，再对照库输出。

知识蒸馏还涉及温度、教师冻结和教师信息来源。温度改变软分布与梯度尺度，某些蒸馏目标用温度平方补偿梯度量级，但这属于特定目标定义，不能自动套到普通标签平滑。教师若在最终测试标签上训练，再向学生提供预测，学生训练虽未直接读取标签，信息仍已流入。数据边界需要沿整个依赖链审查。

<a id="nn4-detail-20"></a>
### 4.4 实验三：目标熵、梯度与平滑接口

```python
import torch
import torch.nn.functional as F

z = torch.tensor([[.3, -.2, .8]], dtype=torch.float64, requires_grad=True)
y = torch.tensor([2])
epsilon = .2
q = (1-epsilon) * F.one_hot(y, 3).to(torch.float64) + epsilon/3
manual = -(q * z.log_softmax(dim=1)).sum()
builtin = F.cross_entropy(z, y, label_smoothing=epsilon)
assert torch.allclose(manual, builtin)
g = torch.autograd.grad(manual, z, retain_graph=True)[0]
assert torch.allclose(g, z.softmax(dim=1)-q)
entropy = -(q*q.log()).sum()
optimum = -(q * q.log()).sum()
assert torch.allclose(F.cross_entropy(q.log(), q), optimum)
assert optimum > 0
q_bad = 2*q
bad_loss = -(q_bad * z.log_softmax(dim=1)).sum()
bad_g = torch.autograd.grad(bad_loss, z)[0]
assert torch.allclose(bad_g, 2*z.softmax(dim=1)-q_bad)
assert torch.allclose(bad_g, 2*g)
print("smoothed loss:", manual.item(), "minimum target entropy:", entropy.item())
```

实验中不合法目标恰好整体乘二，所以梯度整体加倍；更一般的不合法目标还会改变方向。将损失缩小一半并不能修复任意负值或类别质量错位。目标来自模型时也要明确是否允许梯度流入目标生成器，普通监督学习标签通常作为固定数据，不应因共用张量图意外参与参数优化。

## 5. 正则化是关于函数、参数和训练轨迹的选择

显式参数惩罚、Dropout、数据增强与早停通过不同机制改变学习。参数惩罚对特定坐标收费，增强在变换输入上增加任务约束，Dropout 训练随机子网络，早停选择优化路径中的某个状态。它们都可能降低过拟合，却不等价，也不必总有益。将四项同时打开后观察到验证改善，只支持整个方案，而不能单独归功于某项。

<a id="nn4-detail-22"></a>
### 5.1 参数范数依赖参数化

ReLU 网络中，将某隐藏单元输入权重与偏置乘正数，再把其输出权重除同一数，可以保持函数不变，但两层的平方范数会变化。参数 L2 惩罚因此不只是“限制函数输出大小”，还在等价参数表示间表达偏好。含归一化的尺度不变结构会使这种关系更复杂，不能简单将权重较小等同于函数更平滑或泛化必然更好。

偏置、归一化尺度与普通矩阵是否都衰减，属于需要记录的方案选择。常见做法将某些参数排除，但这不是数学上普遍必须的规则。应通过参数名、形状和模块角色建立明确分组，并检查每个可训练参数恰好属于预期组，避免遗漏或重复。迁移架构后若继续用旧的名字过滤规则，可能无声改变正则范围。

<a id="sec-2-1"></a>
<a id="nn4-detail-23"></a>
### 5.2 数据增强表达哪一种不变性

若变换不改变目标，例如某些图像的小幅平移，增强训练近似优化对变换分布的期望损失。若变换改变标签，必须同步变换标签；检测框、分割掩码和方向目标尤其如此。对数字图像随意旋转可能改变类别，对时间序列打乱顺序可能破坏目标机制。不能因为一种增强在另一数据集流行就直接移植。

增强还会改变训练难度和输入分布，训练损失升高不代表泛化变差。应分别评价原始输入与目标允许的扰动，并保持验证预处理固定。若增强策略根据验证表现选择，策略搜索属于模型选择；若使用最终测试调增强强度，则测试已进入开发。计算预算也要公平，因为生成更多视图可能隐含更多有效训练次数。

<a id="nn4-detail-24"></a>
### 5.3 早停与平滑轨迹

早停限制实际执行的更新次数，并依赖监控指标、评价频率、容忍幅度与耐心计数。每十步验证一次与每个 epoch 验证一次并非同一算法，尤其批量或数据规模改变时。最佳状态需要冻结参数与相关缓冲，不能只让变量指向仍在训练的同一个对象。训练损失持续下降而验证暂时反弹，不自动证明应立即停止，噪声和小验证集会影响选择。

在特定线性平方损失设置中，可以分析早停与谱过滤或某些正则的联系，但不应由此声称任何网络中的早停都等价于某个 L2 系数。非线性、动量、归一化与学习率调度会改变路径。研究时可固定预算比较早停规则与显式正则，并用外部数据评价完整选择流程，而非仅比较各自最漂亮的中间点。

<a id="nn4-detail-25"></a>
## 6. Dropout：保持期望不等于保持整个网络输出

对保留概率 $`q=1-p`$，倒置 Dropout 将激活变成 $`\tilde h=\frac{mh}{q}`$，其中 $`m`$ 服从参数为 $`q`$ 的伯努利分布。给定激活，期望为 $`h`$，方差为 $`\frac{h^2p}{(1-p)}`$。因此训练时保持一阶均值，但增加输入相关的噪声；丢弃率接近一时方差显著增大。评价模式通常返回原激活，而不是再乘一次保留概率。

<a id="nn4-detail-26"></a>
### 6.1 为什么评价网络不等于随机子网络精确平均

即使 $`\mathbb E[\tilde h]=h`$，经过非线性函数后一般也有 $`\mathbb E[f(\tilde h)]\ne f(h)`$。例如两个激活均为一，后续为二者差的 ReLU，固定输入输出零；独立丢弃后某些子网络输出二，平均大于零。评价时关闭 Dropout 是明确的推理近似与设计规则，不是对任意非线性网络输出期望的恒等式。

Dropout 放在归一化前后还会改变统计分布，特别是运行方差的估计。若训练和验证差异异常，应检查模式与层序，再讨论是否需要新的正则。对很小数据做排错时先关闭 Dropout，可以把随机目标与确定拟合困难区分；小集成功后逐项加回，观察何时破坏预期。极小集测试中的关闭，不代表正式训练永远不该使用它。

<a id="nn4-detail-27"></a>
### 6.2 实验四：精确枚举两单元随机网络

```python
import itertools
import torch

h = torch.ones(2, dtype=torch.float64)
masks = torch.tensor(list(itertools.product([0., 1.], repeat=2)),
                     dtype=torch.float64)
random_h = masks * h / .5
assert torch.allclose(random_h.mean(dim=0), h)
assert torch.allclose(random_h.var(dim=0, unbiased=False), torch.ones_like(h))
random_output = torch.relu(random_h[:, 0] - random_h[:, 1])
deterministic_output = torch.relu(h[0] - h[1])
assert random_output.mean() == .5
assert deterministic_output == 0
layer = torch.nn.Dropout(p=.5)
layer.eval()
assert torch.equal(layer(h), h)
print("expected hidden:", random_h.mean(dim=0).tolist(),
      "mean random output:", random_output.mean().item())
```

这里枚举了全部四种等概率掩码，因此结论没有蒙特卡洛误差。更大网络通常只能采样近似期望，采样次数、模式与归一化状态都需要说明。若研究 MC Dropout，不应简单把整个模型切回训练模式而意外更新 BatchNorm 统计；应明确哪些随机层启用、哪些状态冻结，并评价预测区间或概率的实际质量。

### 图解：Dropout 保持隐藏均值但不保持非线性输出均值

![Dropout 保持隐藏均值但不保持非线性输出均值](images/04-example.svg)

**直接枚举代码里的四种掩码。** 固定隐藏值 $`h=(1,1)`$，两个单元独立以概率 $`\frac12`$ 保留。倒置 Dropout 将保留值放大两倍，因此四种等概率输出是 $`(0,0),(0,2),(2,0),(2,2)`$，逐坐标平均仍为 $`(1,1)`$。图中的蓝、橙柱分别表示两个隐藏坐标，柱高零并非“没有这个坐标”，而是这次掩码令其取零。

再接同一个非线性函数 $`f(h)=\operatorname{ReLU}(h_1-h_2)`$，四种输出为零、零、二、零，故 $`\mathbb E[f(\widetilde h)]=\frac12`$；关闭 Dropout 则为 $`f(\mathbb E[\widetilde h])=f(1,1)=0`$。差别由非线性导致，不是均值缩放实现错误；如果后续只有仿射变换，才可在期望存在时将其与期望交换。

**适用条件。** 图与本节精确枚举代码使用同一输入和独立掩码。相关掩码会改变联合结果概率，不能直接沿用四种等概率计算。[CS231n 的 Dropout 教学](https://cs231n.github.io/neural-networks-2/#reg)可用于理解随机删除连接的结构；这里进一步检查数值期望，避免把推理时关闭 Dropout 误当作所有随机网络预测的精确算术平均。

<a id="nn4-detail-28"></a>
## 7. L2 惩罚与 AdamW：同名衰减不代表同一步更新

考虑 $`J=L+\frac{\lambda\Vert \theta\Vert ^2}{2}`$，惩罚梯度为 $`\lambda\theta`$。无动量 SGD 更新为 $`\theta^+=(1-\eta\lambda)\theta-\eta\nabla L`$，可以写成统一比例衰减加数据梯度。这一等价依赖具体更新形式和系数约定；若惩罚写成没有二分之一的范数平方，梯度多一个二。比较配置时先核对公式，再核对参数名。

<a id="nn4-detail-29"></a>
### 7.1 自适应预条件为何打破简单等价

若将数据梯度加上 L2 项后送进 Adam，惩罚也参与一阶、二阶矩估计，受到各坐标历史尺度的影响。AdamW 则把参数衰减与数据梯度的自适应更新解耦，不让该衰减项进入数据梯度矩估计。因此二者一般无法通过一个全局系数变换得到相同轨迹。称作`weight_decay`的参数，必须结合优化器与具体版本理解。

以数据梯度为零的第一步为例，正参数上的 coupled L2 经 Adam 归一后可能近似按相同绝对量减少，而 AdamW 按参数大小成比例减少。这解释了为什么同一个衰减数值在两个优化器中不具有相同几何含义。它不证明 AdamW 在所有任务都更好，泛化仍需共同数据、预算与搜索规则的实验证据。原论文的结果应限定在其实验设定，不能被用作任意项目的无条件排名。

<a id="nn4-detail-30"></a>
### 7.2 实验五：零数据梯度下的坐标对照

```python
import torch

initial = torch.tensor([1., 10.], dtype=torch.float64)
a = torch.nn.Parameter(initial.clone())
b = torch.nn.Parameter(initial.clone())
c = torch.nn.Parameter(initial.clone())
eta, decay = .1, .2
adam = torch.optim.Adam([a], lr=eta, betas=(.9, .999), eps=1e-12,
                        weight_decay=decay, decoupled_weight_decay=False)
adamw = torch.optim.AdamW([b], lr=eta, betas=(.9, .999), eps=1e-12,
                          weight_decay=decay)
sgd = torch.optim.SGD([c], lr=eta, weight_decay=decay)
for p in (a, b, c):
    p.grad = torch.zeros_like(p)
adam.step(); adamw.step(); sgd.step()
assert torch.allclose(a, initial-.1, atol=1e-9, rtol=0)
assert torch.allclose(b, initial*(1-eta*decay))
assert torch.allclose(c, initial*(1-eta*decay))
assert not torch.allclose(a, b)
# grad=None 与显式零梯度不是相同的优化器输入状态。
d = torch.nn.Parameter(initial.clone())
none_optimizer = torch.optim.AdamW([d], lr=eta, weight_decay=decay)
assert d.grad is None
none_optimizer.step()
assert torch.equal(d, initial)
print("Adam coupled:", a.detach().tolist(), "AdamW:", b.detach().tolist())
```

本实验将零张量显式赋给梯度，使优化器确实处理该参数；没有梯度的参数在当前实现中被跳过，因此连解耦衰减也没有执行。正式训练中冻结参数、未使用分支和清梯度策略可能影响这些状态。不要根据数学上数据梯度为零，就假定软件一定执行与显式零张量完全相同的路径。

<a id="nn4-detail-31"></a>
### 7.3 累积、裁剪与衰减的时间单位

微批累积模拟一次大批更新时，显式 L2 若每个微批都加入完整惩罚，会被重复计数；应按整个更新目标只贡献一次，或按一致权重分摊。AdamW 的衰减按优化器步发生，若把一个大批改成多个独立小步，衰减次数也改变。相同 epoch 数不代表相同衰减轨迹，学习率调度又会影响每步比例。

裁剪数据梯度后再应用解耦衰减，与把 L2 合入梯度再一起裁剪不等价，因为裁剪阈值会同时限制惩罚方向。研究正则时应记录每次更新的学习率、裁剪前后范数与衰减规则。否则“增大衰减效果不明显”可能仅是梯度被裁剪或参数未被优化器持有，而不是理论上的正则不敏感。


<a id="nn4-detail-32"></a>
## 8. 多任务目标：损失数值接近不代表梯度影响接近

设总目标为 $`L=\alpha L_A+\beta L_B`$。共享参数梯度为 $`\alpha g_A+\beta g_B`$，既取决于梯度范数，也取决于方向夹角。两个损失数值同为一，梯度仍可能相差一百倍；两个梯度范数相同，也可能相互抵消。直接把不同单位、不同分母的标量损失相加，会让单位选择无声决定任务优先级。

<a id="nn4-detail-33"></a>
### 8.1 从单位到梯度几何

若任务 A 是小时平方误差，改成分钟后平方损失扩大三千六百倍；任务 B 的类别交叉熵不变，原系数便不再表达相同折中。可以按训练统计量标准化目标或显式定义业务权重，但应说明这改变了哪一种风险。对共享层记录各任务梯度范数及余弦相似度，有助于判断总损失下降是否掩盖某项停滞；这些量是诊断证据，不是自动给出最佳权重的答案。

若任务标签缺失模式不同，各任务需要自己的有效分母。某一批只有任务 A 标签，不应把任务 B 记成真实零损失加入均值；也不应在没有有效目标时错误更新 B 专属参数的动量与衰减。共享参数仍可因 A 更新，专属分支如何处理则需明确。多任务训练的“一个 batch”并不自动意味着所有任务拥有相同统计支持。

<a id="nn4-detail-34"></a>
### 8.2 动态权重本身也是算法

按当前损失大小自适应加权、按梯度范数平衡或按不确定性估计权重，都引入新的状态与假设。若权重依赖网络参数，是否允许梯度穿过它会改变优化；若使用滑动平均，恢复时也需要保存状态。动态方法不应只以某次总损失下降更快评价，还需看各任务质量、成本、稳定性以及预定约束。

研究时可先固定一小组权重作为透明基线，再比较动态方案。所有候选共享数据划分和预算，记录每项未加权损失、权重与关键参数梯度。若某任务改善而另一项退化，报告帕累托取舍或具体约束，而不是把加权和更小直接称作全面更好。权重由研究者决定的价值偏好，不能被一个自动算法名字完全消除。

<a id="nn4-common-descent"></a>

### 8.3 梯度冲突何时仍有共同下降方向

将某次更新写成 $`\theta'=\theta-\eta d`$，在可微点有 $`L_i(\theta')=L_i(\theta)-\eta g_i^Td+o(\eta)`$。因此，所有 $`g_i^Td>0`$ 保证对足够小的正步长同时严格下降，这是一个明确的一阶充分条件；内积为零时需查看高阶项，不能仅由一阶展开断定损失不降。负的梯度余弦只说明两条最陡下降方向存在冲突，不等价于不存在任何折中方向；加权总损失下降也不能自动推出每项下降。

手算 $`g_A=(1,0)`$、$`g_B=(-1,1)`$。两者内积为负，但 $`d=(1,2)`$ 满足 $`g_A^Td=1`$、$`g_B^Td=1`$，因而是共同下降方向。反过来，等权梯度和为 $`(0,1)`$，对任务 A 的一阶改进恰为零。若 $`g_B=(-1,0)`$，要求两个内积严格为正便变成同时要求 $`d_1>0`$ 和 $`d_1<0`$，此处确实没有共同的一阶严格下降方向。后一种情形只能在局部接受某项退让、利用高阶结构或改变约束，不能靠“把梯度归一化”保证同时改善。

一种有助于理解的方向选择是寻找梯度凸包中范数最小的向量 $`d=\sum_i\alpha_i g_i`$，其中 $`\alpha_i\ge0`$、$`\sum_i\alpha_i=1`$。若最优 $`d\ne0`$，对任一梯度 $`g_i`$，沿凸包中的线段 $`d+\epsilon(g_i-d)`$ 做最优点的一侧导数，得到 $`d^T(g_i-d)\ge0`$，所以 $`g_i^Td\ge\Vert d\Vert ^2>0`$。于是负方向在局部共同下降；若凸包包含零，只能说明这个一阶检验无法找到严格共同下降方向，不能直接称作全局帕累托最优。

这些判断针对同一参数点、同一批数据上的真实梯度和足够小步长。随机梯度、动量、自适应预条件以及较大步长会改变实际方向或高阶误差。把它作为机制诊断时，可先用固定小批和普通梯度步验证方向内积，再检查各任务实际损失，而不能由某个算法名称替代下降证据。




<a id="visual-mechanism-neuralnetworkbasics-04"></a>

### 图解：多任务梯度可能同向也可能相互冲突

![多任务梯度可能同向也可能相互冲突](images/04-mechanism.svg)

**先给梯度一个可以回代的目标。** 图使用

$$
L_A(\theta)=\frac{(\theta_1-2)^2+\theta_2^2}{2},\qquad
L_B(\theta)=\frac{(\theta_1+1)^2+(\theta_2-1)^2}{2}.
$$

起点 $`\theta=(0,0)`$ 时，$`g_A=(-2,0)`$、$`g_B=(1,-1)`$，内积为负二。沿等权梯度和、学习率 0.2 更新，得到 $`\theta'=(0.2,0.2)`$；两损失从 $`(2,1)`$ 变为 $`(1.64,1.04)`$。总和下降，但 B 变差，说明优化总目标不是同时改善各项目标的保证。

改用 $`d=0.4g_A+0.6g_B=(-0.2,-0.6)`$，相同步长得到 $`\theta'=(0.04,0.12)`$，两损失变为 $`(1.928,0.928)`$，均低于初值。当前点有 $`g_A^Td=g_B^Td=0.4>0`$，因而它也是一个共同的一阶下降方向。图把实际损失回代列出，防止只凭夹角推断有限步长结果。这里是另一组完整二次目标，用来补充上文只指定两个梯度的局部算例。

**条件与边界。** 图左画梯度，参数更新取负方向；加权还改变合成梯度的尺度，所以两个方案的位移长度不同。这个构造展示共同下降方向的存在，不是在公平预算下比较两个优化算法，也不保证任意权重、步长或后续迭代都同时下降。

## 9. 最小数据过拟合：一项必要但不充分的诊断

极小数据实验的目标是检验实现能否学到一个已知可实现关系，不是证明泛化。固定输入、固定标签、关闭增强和随机层、减弱正则，选择有足够表达能力的网络与适当预算，检查损失、梯度和参数更新。如果失败，先逐层定位；如果成功，再加回正式组件。随机标签能够被记忆，也只证明容量与优化允许记忆，不证明发现可迁移结构。

<a id="nn4-detail-36"></a>
### 9.1 可实现性先于“应该拟合到零”

完全相同输入若对应互相矛盾标签，确定模型不可能同时预测两个不同输出；标签平滑具有正熵下界；强权重衰减和 Dropout 会改变最优训练行为；线性模型无法无误分类 XOR。这些都能让小集误差不为零，却不是程序错误。诊断实验应使用已知可实现目标，并明确损失下界与允许的误差范围，不能把“十条样本”本身当成零误差保证。

下面四个 XOR 点各重复四次，网络含非线性并关闭正则和随机层。标签规则完全一致，容量足够。代码同时插入一个优化器持有旧模型的故障：新模型梯度非零但参数不动，展示为什么只检查`.grad`不足以证明训练更新成功。

<a id="nn4-detail-37"></a>
### 9.2 实验六：学习闭环与旧优化器故障

```python
import copy
import torch
import torch.nn.functional as F

previous_threads = torch.get_num_threads()
torch.set_num_threads(1)
try:
    torch.manual_seed(51)
    X = torch.tensor([[-1., -1.], [-1., 1.], [1., -1.], [1., 1.]])
    y = torch.tensor([0, 1, 1, 0])
    X, y = X.repeat(4, 1), y.repeat(4)
    model = torch.nn.Sequential(torch.nn.Linear(2, 12), torch.nn.Tanh(),
                                torch.nn.Linear(12, 2))
    optimizer = torch.optim.Adam(model.parameters(), lr=.05)
    first = F.cross_entropy(model(X), y).item()
    before = torch.cat([p.detach().flatten() for p in model.parameters()]).clone()
    for step in range(250):
        optimizer.zero_grad(set_to_none=True)
        loss = F.cross_entropy(model(X), y)
        assert torch.isfinite(loss)
        loss.backward()
        assert all(p.grad is not None and torch.isfinite(p.grad).all()
                   for p in model.parameters())
        optimizer.step()
    with torch.no_grad():
        last = F.cross_entropy(model(X), y).item()
        accuracy = (model(X).argmax(dim=1) == y).float().mean().item()
    after = torch.cat([p.detach().flatten() for p in model.parameters()])
    assert last < .02 and last < first
    assert accuracy == 1 and torch.linalg.vector_norm(after-before) > 0

    old = torch.nn.Linear(1, 1)
    stale_optimizer = torch.optim.SGD(old.parameters(), lr=.1)
    fresh = copy.deepcopy(old)
    snapshot = fresh.weight.detach().clone()
    stale_optimizer.zero_grad(set_to_none=True)
    F.mse_loss(fresh(torch.ones(3, 1)), torch.full((3, 1), 10.)).backward()
    assert fresh.weight.grad is not None and fresh.weight.grad.abs().sum() > 0
    stale_optimizer.step()
    assert torch.equal(snapshot, fresh.weight.detach())
    assert {id(p) for p in fresh.parameters()}.isdisjoint(
        {id(p) for group in stale_optimizer.param_groups for p in group["params"]})
    print("XOR loss:", first, "->", last, "accuracy:", accuracy)
    print("nonzero gradient but unchanged fresh parameter: detected")
finally:
    torch.set_num_threads(previous_threads)
```

小数据通过后，按顺序恢复输入变换、缺失处理、随机层、增强、正则和完整数据。每次只恢复能区分竞争原因的一项，保留同一组固定样本作回归检查。如果加回增强后不能拟合，先检查增强是否保持标签、强度是否过大，而不是立即加深网络。若只有正式数据失败，重点转向样本对应、类别支持、批次组成和数据分布。

## 10. 故障矩阵：现象、竞争解释和最小证据

一个现象往往对应多种原因。训练损失不动可能是梯度断开、优化器持有旧参数、学习率为零、目标下界已到或数值打印太粗。训练震荡可能来自学习率、批次难度、随机增强和有效分母变化。诊断不应是把一个症状映射成一个固定药方，而是设计能够排除解释的观察。

| 观察到的现象 | 需要区分的解释 | 优先进行的最小检查 |
| --- | --- | --- |
| 损失不需要梯度 | 在无梯度上下文、detach、重新包装张量 | 检查输出与损失的 requires_grad、grad_fn |
| 某参数梯度为 None | 未经过该分支、未参与图、未反向 | 用固定输入追踪路径，比较其他参数 |
| 梯度有限非零但参数不动 | 旧优化器、学习率零、更新精度不足 | 核对参数对象身份与 step 前后差值 |
| 参数变化但数据损失不降 | 学习率过大、随机目标、错误损失、惩罚主导 | 固定同一批，分开数据项与惩罚项 |
| 某批突然 NaN | 非法输入、空分母、指数或除法溢出 | 找到最早非有限的输入或中间结果 |
| 训练好而验证差 | 分布差、过拟合、模式或前处理错误 | 同定义诊断损失，核对 eval 与输入契约 |
| 总损失降而某任务停滞 | 量纲、梯度冲突、标签支持不均 | 分项损失、分母、共享层任务梯度 |
| 恢复后第一步偏离 | 动量、随机状态、数据位置或调度遗漏 | 固定下一批，对比完整状态与更新 |

<a id="nn4-detail-39"></a>
### 10.1 梯度范数、更新范数与相对尺度

对一个参数块，记录梯度范数和实际更新范数，分别观察求导信号与优化器行为。相对更新量可写为 $`\frac{\Vert \Delta\theta\Vert }{(\Vert \theta\Vert +\epsilon)}`$，有助于比较不同尺度层，但接近零的参数分母需要解释，不能把一个很大比例机械判为异常。偏置和归一化参数也未必适合同一阈值。范数是线索，仍需结合层角色与任务。

若梯度很小但 Adam 更新并不小，是预条件与历史矩的正常可能；若梯度很大而裁剪后更新平稳，也不一定故障。相反，低精度参数可能因更新低于可表示间隔而不变。CPU 双精度小实验可以帮助区分数学目标与数值精度，但不能据此替代正式硬件上的验证。记录实际更新比只打印梯度范数更直接。

<a id="sec-4"></a>
<a id="nn4-detail-40"></a>
### 10.2 梯度检查只回答局部求导问题

梯度检查使用数值差分对照自动微分，适合小规模、双精度、确定函数，并避开 ReLU 折点等不可微位置。差分步长过大有截断误差，过小有舍入误差；随机 Dropout、运行统计更新和非确定算子会干扰比较。通过说明表达出来的函数在该输入附近求导一致，不说明标签、掩码和评价协议正确。

```python
import torch

x = torch.tensor([.2, -.3], dtype=torch.float64, requires_grad=True)
assert torch.autograd.gradcheck(lambda z: torch.tanh(z).square().sum(), (x,))
# 故意交换标签仍可得到数学上完全正确的梯度。
z = torch.tensor([[.4, -.2]], dtype=torch.float64, requires_grad=True)
wrong_label = torch.tensor([1])
assert torch.autograd.gradcheck(
    lambda t: torch.nn.functional.cross_entropy(t, wrong_label), (z,))
print("local derivatives passed; label semantics remains a separate check")
```

这个反例提醒我们分开四层正确性：任务与数据含义、前向目标表达、局部求导、优化更新。每层需要不同证据。一个错误类别映射可以通过 gradcheck，一个正确梯度可以被旧优化器忽略，一个正常训练循环也可能在泄漏数据上得到高分。将所有层合称“模型没问题”，会使排错在错误方向上持续消耗预算。

<a id="nn4-detail-41"></a>
### 10.3 非有限值处理与回滚边界

遇到非有限梯度时，先保留最小输入与配置，在异常检测或逐层探针下定位最早出现位置。直接`nan_to_num`把所有 NaN 改零可能使程序继续，但也隐藏未定义目标和错误数据。只有当替代策略有明确数学语义并经评价，才应纳入正式流程。对空标签、除零、非法对数等问题，应优先修复目标和输入。

如果已经执行了导致参数非有限的优化步，跳过后续批次不能自动恢复，优化器矩也可能被污染。应从最近可信状态恢复模型、优化器、调度、随机和数据位置，或明确重新开始一轮实验。仅加载权重而保留污染动量，不保证下一步正常。恢复实验的完整状态证明见 PyTorch 检查点章节，本章强调故障发生前后哪个边界仍可信。

<a id="nn4-detail-42"></a>
### 10.4 复现实验应固定什么，又保留什么变化

排错先固定输入、目标、模型状态和随机状态，让同一现象稳定出现；研究泛化时再主动变化种子、数据和来源，估计相应波动。固定种子不是普遍可靠性的证明，它只让一个随机路径可重演。若修复后只在一个种子成功，需继续检查失败机制是否仍存在，而不是挑成功种子作为已解决。

记录最小复现时保留原始失败输入的合法性、形状和触发条件，不要在缩小问题过程中顺手清理掉导致故障的关键关系。删除某个批次后程序能跑，并不等于原因被解决；也许只是避开了空分母或未知类别。一个好的修复应对原失败用例通过，并说明为何对同类输入都适用，再回到完整数据验证。

<a id="nn4-detail-43"></a>
### 10.5 梯度方向正确为何单步损失仍可能增加

对光滑目标，负梯度在足够小的局部步长下是下降方向，但一次实际更新还受到步长、曲率、动量与预条件影响。较大步长跨过局部区域，可以让同一批损失增加；随机层或重新抽样数据又使前后目标不同。诊断时应固定同一批和随机状态，必要时在参数快照上试几个小步长，比较方向性预期，而不是要求正式训练每一步都单调下降。

若小步长也不符合预期，可检查损失是否含不同归约、参数是否在记录之间被其他代码修改、前后是否切换了模式，以及更新是否真正沿被检查的梯度。检查数值差分方向导数时，恢复每次探针前的完整参数与缓冲状态，避免第一次数值探针已经改变后续条件。探针的临时更新不应污染正式优化器矩，否则一次诊断会成为新的不可追踪训练步骤。

<a id="nn4-detail-44"></a>
## 11. 十八道练习与逐题详解

<a id="nn4-detail-45"></a>
### 11.1 改成均值后正则为什么突然过强

**问题：** 原目标为样本损失和加一个固定 L2 项，改成损失均值但系数不变，是否只是梯度整体变小？

**解析：** 不是。数据项除以样本数而惩罚未除，二者相对强度改变。若要保持整体比例，原目标整体除以样本数时惩罚系数也要除。即使对应调整学习率，Adam、裁剪和动量下轨迹也未必严格等价。应先写完整目标，再决定在新归约下重新选择正则与学习率，不能仅凭曲线变慢诊断优化器失效。

<a id="sec-8-2"></a>
<a id="nn4-detail-46"></a>
### 11.2 有效词元平均与序列平均何时相同

**问题：** 一条序列短且难，另一条长且易，两个平均是否能互换？

**解析：** 一般不能。词元平均给长序列更大总权重，序列平均给每条非空序列相同总权重。所有有效长度相同，或特定梯度恰好抵消时数值可能一致，但不构成普遍等价。应根据目标抽样单位选择；空序列如何处理也要明确。仅调学习率无法改变序列间相对权重，因此不能用一个全局缩放修复目标差异。

<a id="nn4-detail-47"></a>
### 11.3 NaN 位置乘零为何仍出错

**问题：** 无效目标为 NaN，计算平方误差后乘掩码是否足够？

**解析：** NaN 与零相乘仍为 NaN，而且非法操作的反向也可能污染梯度。应先筛选有效位置或在操作前构造安全输入，同时保持合法梯度路径。不要仅把最终标量替换零，因为这会隐藏有效数和数据问题。实验一直接选择有效元素，并检查无效位置梯度为零，是针对目标表达的证据。

<a id="nn4-detail-48"></a>
### 11.4 空批次损失设零后为什么参数还在变

**问题：** 数据损失为零，执行`step`后权重改变，是否违反求导规则？

**解析：** 不违反。优化器可能拥有历史动量、显式零梯度对应的衰减，或之前累积的梯度。`grad=None`与零张量也可走不同软件路径。应按协议决定空批次是否跳过整个更新，并核对调度器和计数。数据风险没有有效观察时，不能把它当一个正常零损失样本加入平均。

<a id="nn4-detail-49"></a>
### 11.5 全部类别权重乘七是否一定放大梯度

**问题：** 把权重整体放大七倍，为什么某次训练没有变化？

**解析：** 对索引标签加权均值，分子和目标权重和同时放大，结果不变；对按样本数归约的加权软标签，结果会放大。需要核对接口路径、归约和分母，不能只看参数数组变化。逐元素损失与最终标量分别检查，能把目标加权和归约缩放区分开。

<a id="nn4-detail-50"></a>
### 11.6 平衡采样后还用倒数频率权重是否更公平

**问题：** 两种技巧都增加少数类贡献，能否放心叠加？

**解析：** 不应未经推导叠加。重采样已改变训练分布，再加原频率倒数权重可能重复强化少数类。先说明目标是原总体风险、类别等权风险还是代价敏感决策，再推导权重与抽样比例。少数类重复更多次不会创造独立信息，概率解释和评价也需回到目标总体。

<a id="nn4-detail-51"></a>
### 11.7 加权分类器输出二分之一是否就是原发生率

**问题：** 原正类概率十分之一，正类权重九，理想输出二分之一，如何解释？

**解析：** 这是加权条件风险的最优概率，不是原始发生率。由最优点公式，输出与权重乘真实概率成比例。它可能支持有用决策，但若要解释原概率，需要明确修正假设或在目标总体校准，并用独立样本评价。不能把召回改善直接称为概率更准确。

<a id="nn4-detail-52"></a>
### 11.8 标签平滑为何不能把训练损失降到零

**问题：** 所有样本都分类正确，平滑交叉熵仍大于零，是否欠拟合？

**解析：** 平滑目标本身具有正熵，最优交叉熵等于该熵。分类正确只要求最大概率类正确，不要求概率等于一。若不断推尖锐概率，反而可能恶化平滑目标。应对照理论下界与数据项，而不是沿用硬标签交叉熵趋零的直觉。强正则还会进一步改变实际可达点。

<a id="nn4-detail-53"></a>
### 11.9 软标签和多标签为何不能共用概率约束

**问题：** 每行两个类别都为一，能否作为互斥多分类软标签？

**解析：** 这不是和为一的类别分布。若两类可同时成立，应使用适合独立或结构化多标签目标的输出与损失；若只是一份未归一化质量，则其梯度变为总质量乘概率减目标。接口能够计算不证明任务定义正确。应先确认随机对象，再检查形状和数值范围。

<a id="nn4-detail-54"></a>
### 11.10 Dropout 保持激活均值为何不保持网络均值

**问题：** 倒置缩放保证期望，评价网络为何不是所有子网络精确平均？

**解析：** 非线性一般不与期望交换。实验四的两个单元均值保持一，经过差值 ReLU 后随机平均为二分之一，固定网络输出零。保持某层一阶矩只是局部性质。评价关闭随机层是明确推理规则，若采用多次随机推理，需要独立规定模式、统计量和评价，不可混称同一个恒等式。

<a id="nn4-detail-55"></a>
### 11.11 Adam 的 L2 与 AdamW 为何不能换一个系数就相同

**问题：** 两者都让权重变小，是否只差数值大小？

**解析：** coupled L2 进入一阶二阶矩，受到坐标历史预条件影响；AdamW 的衰减独立于这些梯度矩。不同坐标一般需要不同变换，无法用统一系数恢复相同更新。实验五零数据梯度下，前者近似同绝对量下降，后者按比例下降。该反例证明一般不等价，不证明任一算法普遍更好。

<a id="nn4-detail-56"></a>
### 11.12 为什么 `grad=None` 与零梯度要分别检查

**问题：** 数学上都没有数据更新信号，软件为何不同？

**解析：** None 表示未提供梯度，优化器常直接跳过该参数；零张量表示该参数参与本次处理，历史动量或衰减仍可能作用。冻结、未使用分支和清梯度策略都会影响状态。应检查当前优化器实现并用实际更新验证，不能从符号零梯度推断执行路径。恢复训练时也要保持相应状态一致。

<a id="nn4-detail-57"></a>
### 11.13 梯度范数非零为何仍不能证明训练在发生

**问题：** 模型`.grad`有值，损失却不动，首先该看什么？

**解析：** 核对优化器是否持有当前参数对象、学习率是否为零、是否调用了 step，以及实际参数差值。实验六故意让优化器持有旧模型，新模型有梯度但完全不更新。之后再检查数值精度、裁剪和动量等。单个观测应帮助区分原因，不能被过度解释为整个闭环正确。

<a id="nn4-detail-58"></a>
### 11.14 小集无法拟合是否一定是反向传播错误

**问题：** 十六条记录训练准确率不能到一，应直接做 gradcheck 吗？

**解析：** 先检查目标可实现性、模型容量、标签矛盾、平滑下界和正则，再逐层检查前向、求导、更新。线性模型无法拟合 XOR，完全相同输入的冲突标签也无法同时满足。gradcheck 只验证表达函数的局部导数，不能判断任务是否可实现。使用已知可拟合的小生成关系能让诊断更有判定力。

<a id="nn4-detail-59"></a>
### 11.15 多任务两个损失都是一，是否贡献相同

**问题：** 直接等权相加，是否无需再看尺度？

**解析：** 损失值不决定梯度范数与方向。不同单位、分母和参数路径会造成共享梯度不平衡，甚至相互抵消。应记录各任务支持数、未加权损失、共享层梯度及目标质量。动态权重也引入状态与选择，不是自动消除价值偏好。最终按各任务指标和约束评价，而非只看总和下降。

<a id="nn4-detail-60"></a>
### 11.16 训练损失比验证高时应怎样排查

**问题：** 是否应首先怀疑训练集太难或数据泄漏？

**解析：** 先统一对象：训练是否含增强、Dropout、显式正则，验证是否只算数据项，模式与归约是否一致。可以在评估模式、无增强下对训练集重新计算相同数据损失。若差异仍异常，再检查样本组成、分布和信息边界。正常机制能解释一部分差异，但也不能因此排除所有泄漏，需要独立审查。

<a id="nn4-detail-61"></a>
### 11.17 gradcheck 通过后标签映射是否已验证

**问题：** 将零一标签互换，梯度检查仍通过，为什么？

**解析：** 交换标签仍定义了一个可微函数，自动微分可以完全正确求导。局部数值差分不会知道业务类别含义。需要手工样例、类别字典和输入标签对齐检查。数学表达、求导、数据语义和评价是不同证据层，不应由任何单一工具一次性代替。

<a id="nn4-detail-62"></a>
### 11.18 非有限更新后只加载权重够不够

**问题：** 权重恢复正常，但下一步又异常，可能遗漏什么？

**解析：** 优化器矩、调度器、随机状态和数据位置可能仍被污染或错位。恢复需要一个内部一致的可信状态，不能把旧权重与新动量拼接后称作继续原轨迹。若无法重建完整状态，应明确重新训练或迁移实验。恢复完成后用固定下一批核对更新，再回到完整流程，而不是只检查文件能够加载。

<a id="sec-8"></a>
<a id="nn4-detail-63"></a>
## 12. 进阶研究：把训练技巧转成可证伪实验

第一项研究固定同一网络和变长数据，比较有效元素目标与序列等权目标。在同一更新组内核对梯度差异，随后观察长短序列的分别质量。控制学习率和正则尺度，避免把固定整体缩放误认为统计目标改变；再让长度与难度相关，检验两种风险的取舍。报告每组有效数、训练分母和评价单位，不能只保留一条平均曲线。

第二项研究比较 class weight、平衡采样与二者结合。先在可手算条件概率的生成数据中验证理想目标，再固定模型容量研究有限批量方差与概率失配。评价原总体与类别等权两个风险，并清楚命名。若希望校准原概率，使用独立开发区域，记录校准与阈值选择成本；不要在最终测试上恢复先验后再宣称原模型原生校准。

第三项研究用完全相同的数据、初始化和预算比较 coupled L2 与解耦衰减。记录各参数坐标或层的范数、更新、梯度矩，以及共同验证指标。重新选择合理系数，但保持搜索机会可比较，不能将一个优化器精调结果与另一个默认值排名。零梯度反例只证明机制不等价，正式研究还要说明在什么条件下这种差别有实际预测价值。

<a id="sec-8-1"></a>
<a id="nn4-detail-64"></a>
### 12.1 综合验收：从一次失败建立证据链

给一个不能拟合极小数据的训练器，按数据与目标、前向表达、梯度、更新、完整模式五个层次排查。每一层保存一条能够排除竞争解释的证据，例如标签键对应、逐元素损失手算、gradcheck、优化器参数身份与更新差值、关闭随机层后的固定损失。修复应让原失败用例通过，再逐项加回正式设置，不能通过删除失败样本来回避问题。

最终记录原症状、被排除的假设、确定原因、具体修复和剩余限制。若只解决旧优化器问题，就不要顺便宣称数据泛化已被证明；若只是确认损失分母符合协议，也不能由此保证类别概率正确。一个完整排错报告应让下一位读者知道哪里已经验证、哪里仍需要独立证据。这样的记录能积累为训练器的回归用例，减少未来架构迁移时重犯同类错误。
