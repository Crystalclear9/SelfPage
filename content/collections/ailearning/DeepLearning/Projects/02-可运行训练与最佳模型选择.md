## 1. 把学习流程写成一个明确算法

<a id="dlp2-detail-2"></a>

### 1.1 本章使用的任务和信息边界

本章承接第一章的协议，在 scikit-learn 内置 digits 上训练一个小型卷积分类器。图像为八乘八单通道，像素除以固定常数十六。首先用种子四十一分层留出三百六十张测试图像，再在其余图像上用种子四十二分出三百六十张验证图像，训练集为一千零七十七张。没有可靠书写者标识，因此评价单位仍然是图像，不宣称书写者独立。

训练的算法不仅包括梯度更新，还包括初始化、数据顺序、训练轮次、验证测量和快照选择。把这些环节写在一起，是因为最终模型并不是第三十轮参数的同义词。我们会运行三十轮，每轮测量验证交叉熵，并保存严格优于以往结果的状态。最终测试前恢复该状态，因此被评价对象由整个学习流程定义。

本章全部代码面向 CPU，小数据常驻内存，不下载数据或预训练权重，也不生成图片和模型文件。为了便于复算，线程数固定为一。单线程有利于这个小型教学实验的稳定执行，但不是提高大型网络吞吐量的普遍建议。真实资源比较应依据硬件和算子重新测量，不应从本章运行耗时推导其他环境的性能。

<a id="dlp2-detail-3"></a>

### 1.2 前向函数、训练状态和评价对象

记网络前向为 $`z=f_\theta(x)`$，输出十个分数。训练状态不仅包含参数 $`\theta`$，还包括优化器动量、迭代次数以及随机生成器状态。推理状态通常只需要模型参数、必要缓冲、网络结构和输入契约，但精确恢复训练需要更多内容。这解释了为什么“保存可推理权重”和“保存可续训检查点”不能混为一件事。

当前网络不含批归一化和随机失活，因而它的前向在训练与评估模式下形式相同。不过代码仍然显式切换模式，并在评价时关闭梯度。这不是多余仪式，而是把行为边界写清楚。当以后加入会依赖模式的层时，已有评价函数不会因为默认模式而悄悄改变含义。

评价对象还包括类别顺序。第零个输出分量代表数字零，第九个代表数字九。若部署时对类别字典重新排序，即使概率向量数值完全相同，也会输出错误标签。模型状态与标签映射必须一起交付，不能把输出维度十当作映射一致性的证明。

## 2. 从形状与参数量理解小型卷积网络

<a id="dlp2-detail-5"></a>

### 2.1 每一层为何得到这个尺寸

输入形状为 $`(N,1,8,8)`$。第一个三乘三卷积使用步长一、四周各一像素零填充，因此输出空间尺寸保持八乘八，通道变为八。ReLU 逐元素截断负值，不改变形状。第二个卷积仍保持八乘八，输出十六通道。二乘二平均池化使用默认步长二，把空间缩为四乘四。

展平后每张图拥有十六乘四乘四，即二百五十六个特征。最后线性层把它映射到十个类别分数。卷积输出的每个元素有明确的空间邻域，线性层则可以组合所有池化位置。模型并非完全平移不变，因为零填充、池化网格和最终位置相关线性权重都会使绝对位置影响输出。

第一层参数为八个输出通道，每个具有九个输入连接，再加八个偏置，共八十。第二层为十六乘八乘九个权重加十六个偏置，共一千一百六十八。线性层为二百五十六乘十加十，共二千五百七十。三者相加得到三千八百一十八。激活和池化没有可训练参数，但仍消耗计算与存储，参数量不等于总资源成本。

<a id="dlp2-detail-6"></a>

### 2.2 局部感受野与任务信息

第一层单个位置观察原图三乘三区域；第二层单个位置组合前一层三乘三位置，因此最大理论感受野为五乘五。二乘二池化再跨一个相邻位置，最大输入跨度达到六乘六。最终线性层综合所有四乘四位置，可以利用整张图。这里的最大跨度只描述哪些输入可能影响输出，不表示每个像素在训练后具有相同影响。

对八乘八图像而言，边界填充占比较高。某些卷积核在边缘会看到人工补零，因此网络可以通过边界模式感知位置。池化还会混合细线与空白，可能降低局部噪声，也可能抹去区分某些数字的细节。选择这个网络是为了提供一个可解释、可快速运行的学习对象，而不是证明它是该数据集的最优架构。

若把平均池化换成最大池化，就改变了特征汇总方式。平均更关注局部总响应，最大更关注最强响应。不能仅凭直觉断言其中一个一定更好；需要保持其他条件和选择预算一致，检查验证与独立评价。第三章把这样的替换放进明确的消融设计，而不是在本章看到测试结果后临时改动。

## 3. 交叉熵、梯度和稳定数值

<a id="dlp2-detail-8"></a>

### 3.1 从类别概率推导损失

对一个分数向量 $`z`$，类别概率为 $`p_k=\frac{\exp(z_k)}{\sum_j\exp(z_j)}`$。真实类别为 $`y`$ 时，负对数似然为
$$
\ell(z,y)=-z_y+\log\sum_{j=0}^{9}\exp(z_j).
$$
给所有分数加同一个常数不会改变概率和损失。这意味着分数的绝对零点不是可识别量，真正影响分类的是分数之间的差。数值实现可以先减去最大分数，避免直接对很大的正数求指数。

对分数的导数为 $`\frac{\partial\ell}{\partial z_k}=p_k-\mathbf1[k=y]`$。正确类别分量的梯度通常为负，梯度下降会提高它相对于其他类别的分数；其他类别分量梯度为正，更新倾向于降低它们。这个方向解释依赖当前样本在输出层的局部导数，完整参数更新还通过前面各层的链式法则传播，不等于每个内部权重都朝同一方向变化。

交叉熵接受未归一化分数和整数标签。先做一次 softmax 再交给这个损失，会让损失把概率再次当作分数归一化，改变训练目标。预测阶段为了输出概率可以使用 softmax，但计算损失时应直接传入网络分数。标签类型应为长整型，不能因为数字类别看起来像数值就把它们当作连续回归目标。

<a id="dlp2-detail-9"></a>

### 3.2 批量平均的统计含义

本章每个小批量的损失是其中样本损失的算术平均。最后一个批量可能小于六十四，训练日志的轮平均应累计每批平均乘该批样本数，再除以总样本数。若把各批均值再无权平均，最后一个小批量会与一个完整批量拥有相同权重，从而改变评价对象。

训练日志中的平均损失还不是“某个固定模型在全部训练集上的损失”。每个批量都在不同参数状态下计算，随后参数更新。因此轮训练损失是训练路径上的观测汇总，而验证损失是在一轮结束后的同一参数状态上计算。二者可以用于诊断趋势，但不能把它们的差完全解释成标准意义上的固定模型泛化间隙。

若想比较同一状态的训练与验证风险，应在轮末另外切到评估模式，对未增强训练集和验证集分别前向，采用相同损失归约。这样增加计算，但定义更清楚。当前代码保留常用的路径训练损失，同时明确这一限制，避免把一个方便日志误解为精确的统计量。

<a id="dlp2-detail-10"></a>

### 3.3 Adam 更新中状态的作用

Adam 为每个参数维护梯度的一阶与二阶滑动矩估计，并对初始偏差作修正，再用学习率缩放更新。二阶估计让不同坐标的更新尺度有所调整，但不保证任何目标都稳定收敛，也不保证不需要学习率选择。当前固定学习率零点零零三是一个预定教学配置，不能当成所有卷积任务的默认最优值。

若只恢复模型参数而继续使用第三十轮优化器状态，得到的续训轨迹并不是从第二十八轮完整状态继续。因为一阶、二阶矩和迭代计数仍然来自更晚时间。对于推理评价，这些优化器状态不参与前向，因此恢复模型权重足够；对于精确续训，应把优化器、随机状态和训练进度共同恢复。

清零梯度也属于算法定义。PyTorch 默认累积梯度，因此每批更新前调用清零，表示每次只用当前批量的梯度。若有意做梯度累积，应按有效样本数调整归约，并在适当位置执行一次更新。忘记清零通常会让历史梯度以不受控方式叠加，不能把它当作普通动量，因为其权重和优化器内部状态完全不同。

```python
        assert all(p.grad is not None and torch.isfinite(p.grad).all() for p in model.parameters())
        opt.step()
        loss_sum+=loss.item()*len(yb);seen+=len(yb)
    vl,va,_=evaluate(valid)
    history.append((epoch,loss_sum/seen,vl,va))
    if vl<best_loss:
        best_loss=vl;best_epoch=epoch;best_state=copy.deepcopy(model.state_dict())
assert best_state is not None
model.load_state_dict(best_state)
vl,va,_=evaluate(valid)
assert abs(vl-best_loss)<1e-7
tl,ta,logits=evaluate(test)
prob=logits.softmax(1).numpy()
pred=prob.argmax(1);truth=data.target[test]
assert abs(log_loss(truth,prob,labels=np.arange(10))-tl)<1e-5
baseline=LogisticRegression(C=1,max_iter=2000).fit(data.data[train]/16,data.target[train])
bp=baseline.predict_proba(data.data[test]/16)
print("split",len(train),len(valid),len(test),"parameters",sum(p.numel() for p in model.parameters()))
print("best",best_epoch,vl,va,"last",history[-1])
print("test",tl,ta,"errors",int((pred!=truth).sum()))
print("linear",log_loss(truth,bp,labels=np.arange(10)),accuracy_score(truth,bp.argmax(1)))
print("confusion",confusion_matrix(truth,pred,labels=np.arange(10)).tolist())
assert 0<=ta<=1 and np.allclose(prob.sum(1),1,atol=1e-6)

```

### 4.3 一次前向与多个指标之间的关系

## 5. 最佳快照为何必须独立复制

<a id="sec-1-1"></a>

<a id="dlp2-detail-16"></a>

### 5.1 引用、浅字典与张量存储

Python 中赋值通常绑定对象，而不是复制整个对象的内容。模型状态字典虽然是一个新映射，其中张量仍可能引用模型当前参数和缓冲的存储。若只把状态字典赋给最佳状态变量，随后训练更新参数，所谓最佳状态也可能随之改变。日志记录第二十八轮最好，但变量中最终装着第三十轮值，是一种特别隐蔽的错误。

深拷贝把当前状态中的张量内容复制到独立存储，使后续更新不会改变快照。也可以逐个对张量分离并克隆，或立即序列化到可靠介质，但要同时考虑缓冲与设备位置。当前小模型使用深拷贝内存状态，简单且足够。真正的大模型需要管理快照内存与持久化策略，不能直接复制所有训练状态而忽视资源。

保存最佳模型还要与选择条件绑定。只有当当前验证交叉熵严格变小时，才同时更新最优值、轮次和状态。若这三项分开更新，可能出现轮次来自一个模型、权重来自另一个模型的错配。把它们视为一次原子性的逻辑操作，有助于避免报告中拼接不存在的组合。

![共享存储不是独立快照](images/02-snapshot-storage-independence.svg)

**共享存储不是独立快照。** 本图将参数存储问题压成一个标量：在值为一时保存，随后每次原地加 0.2。独立复制一直保留一；共享同一存储的“保存值”则跟着变，七次后变成 2.4。验证最优轮次记录正确，仍无法挽救被后续更新覆盖的权重。此处只说明存储独立性；真实检查点还应检查缓冲、优化器、随机状态和任务配置。

$$
\theta_t=1+0.2t,\qquad \theta_{\mathrm{snapshot}}=1.
$$

### 5.2 实验二：用可观察变化证明快照问题

这个机制实验不训练 digits，不产生任何项目性能数字。它创建一个线性层，分别保留共享状态和深拷贝状态，再主动修改参数。断言显示共享状态随模型改变，深拷贝保持原值，恢复后模型回到原来的前向结果。

```python
import copy
import torch
from torch import nn

torch.manual_seed(1)
m = nn.Linear(2, 1)
x = torch.tensor([[1.0, 2.0]])
before = m(x).detach().clone()
shared = m.state_dict()
snapshot = copy.deepcopy(m.state_dict())
with torch.no_grad():
    m.weight.add_(5)
assert torch.equal(shared["weight"], m.weight)
assert not torch.equal(snapshot["weight"], m.weight)
assert not torch.allclose(m(x), before)
m.load_state_dict(snapshot)
assert torch.allclose(m(x), before)
with torch.no_grad():
    m.bias.add_(1)
assert not torch.equal(snapshot["bias"], m.bias)
print("independent snapshot restored and remained unchanged")
```

注意，恢复后再更新模型，原深拷贝仍然不应变化。这个附加检查确保我们没有在第一次恢复后意外建立新的共享关系。对含批归一化的模型，还要检查运行均值、运行方差等缓冲是否一起恢复；仅复制可训练参数列表会遗漏这些推理相关状态。

<a id="dlp2-detail-18"></a>

### 5.3 恢复应通过功能而非文件名验证

一个文件叫最佳模型，并不能证明它真是被选择的状态。至少应在恢复后重算验证指标，与保存时记录的值比较，并核对模型结构和类别映射。若包含随机或模式相关行为，应先固定评估模式，再解释数值容差。仅比较参数键数量也不够，因为同形状张量可能来自不同训练阶段。

更强的检查可以保存若干固定参考输入的输出摘要，在恢复后复算。这类参考应来自训练或专用接口测试数据，不应为了验收推理代码而反复人工利用测试错误。参考输出是功能回归检查，不能代替独立性能评价，也不能证明所有输入上的行为都未改变。

### 图解：最佳快照必须独立于当前参数存储

![最佳快照必须独立于当前参数存储](images/02-example.svg)

图使用确定的线性模型 $`y=w^{\mathsf T}x`$，输入 $`x=(1,2)`$、初始权重 $`w=(1,2)`$、偏置为零，初始预测为五。当前模型的 state_dict 与名为“最佳状态”的字典若共享张量存储，后续将权重每项加五，就会同时读到 $`(6,7)`$，预测变为二十；独立复制的快照仍保存 $`(1,2)`$，可以恢复预测五。图中是人为指定初值以便手算，本章代码使用随机线性层，但做相同的加五与恢复检查。

## 6. 损失汇总、模式切换和无梯度评价

<a id="dlp2-detail-20"></a>

### 6.1 样本均值与批均值的区别

假设两个批量分别有四条和一条样本，第一批每条损失都是一，第二批损失为九。完整数据的平均为十三除以五，即二点六；批均值无权平均得到五，把最后一条样本放大到一半总权重。若验证集不能整除批量大小，这种错误会使最优轮次选择依赖批次边界。

对于带样本权重或忽略标签的损失，分母还可能不再是批量长度。需要把损失分子和有效权重分母分开累计，而不是盲目乘以样本数。当前任务每张图权重相同、没有忽略标签，因此按批量长度加权即可。将来迁移到分割、序列掩码或类别加权任务时，应重新推导归约，不能照抄这个特例。

训练日志与验证日志也应明确单位。交叉熵通常是每样本的自然对数损失，准确率是比例，耗时可以是每轮或累计秒数。把百分数和比例混用会让阈值判断出错，把批次总和与样本均值混画会让曲线出现无意义的量级差。日志字段本身就是实验接口的一部分，需要像模型输入一样清楚。

<a id="dlp2-detail-21"></a>

### 6.2 实验三：汇总错误与模式错误同时显形

下面的独立实验首先核对加权均值，再用批归一化与随机失活演示两个相互独立的机制：关闭梯度不会自动进入评估模式，进入评估模式也不会自动关闭自动微分。模式控制层的前向行为，无梯度环境控制计算图构建，二者不能互相替代。

```python
import torch
from torch import nn

losses = [torch.ones(4), torch.tensor([9.0])]
weighted = sum(z.sum().item() for z in losses) / sum(len(z) for z in losses)
wrong = sum(z.mean().item() for z in losses) / len(losses)
assert weighted == 2.6 and wrong == 5.0

torch.manual_seed(2)
bn = nn.BatchNorm1d(3)
x = torch.arange(12, dtype=torch.float32).reshape(4, 3)
before = bn.running_mean.clone()
bn.train()
with torch.no_grad():
    bn(x)
assert not torch.equal(before, bn.running_mean)
bn.eval()
saved = bn.running_mean.clone()
out = bn(x.requires_grad_())
assert out.requires_grad
assert torch.equal(saved, bn.running_mean)
with torch.inference_mode():
    a = bn(x)
    b = bn(x)
assert torch.equal(a, b)
drop = nn.Dropout(p=0.5)
drop.eval()
assert torch.equal(drop(x), x)
print(weighted, wrong, "mode and graph controls checked")
```

这里没有断言随机失活在两次训练前向中一定不同，因为随机事件具有相同输出的可能性。用评估模式下确定等于输入的性质更适合做稳定断言。测试设计应优先检查确定机制，而不是把高概率现象写成绝对必然。

<a id="sec-4"></a>

<a id="dlp2-detail-22"></a>

### 6.3 评价函数应满足的四个不变性

第一，评价不应更新模型参数或运行统计。第二，在无随机推理机制时，同一状态和同一输入应给出一致结果。第三，改变评价批量边界不应改变数学上的总体指标，浮点误差除外。第四，重新排列样本并同步排列标签，只应改变输出行顺序，不应改变汇总结果。这些性质比“准确率看起来正常”更能发现实现错误。

对于当前不含批归一化的网络，不同评价批次下输出通常只存在很小浮点差异。若以后使用依赖批统计的自定义层，需要明确推理是否真的应与同批其他样本无关。如果单张图的预测随同批图像变化，在线请求的组合就会影响结果，必须作为模型契约的一部分解释，而不是默认为无关细节。

评价完成后是否恢复训练模式也应由调用者约定。当前训练循环每轮开始显式调用训练模式，因此评价函数留在评估模式不会影响下一轮。另一些代码会保存原模式并在退出时恢复，两种方式都可以。真正的问题是隐藏假设：调用者以为模式已恢复，评价函数却没有恢复，导致后续随机失活或批归一化行为改变。

## 7. 逐行理解完整循环的控制流

<a id="dlp2-detail-24"></a>

### 7.1 为什么数据加载器拥有独立生成器

训练数据每轮打乱，用于改变小批量组合。独立的生成器使批次顺序不直接依赖模型初始化消耗了多少随机数。若以后增加一个随机初始化层，数据加载器仍从同一个种子开始产生顺序，便于比较。不过不同模型训练过程中若额外调用该生成器，仍可能改变后续状态，因此记录种子不能代替记录使用方式。

当前数据在内存中，工作进程数为零，避免多进程加载引入额外随机和平台差异。大型数据任务可能需要多个加载进程来提高吞吐量，那时还需考虑每个工作进程的种子、增强库的随机源以及预取顺序。为了速度而引入的工程机制，也可能成为实验随机性的一部分。

每轮样本数应等于训练索引数。若使用丢弃最后批量，训练每轮实际看到的样本可能少于全集；若使用有放回采样，一些样本重复而另一些缺席。代码中的累计样本数与加载器配置应一致，报告中的“一个轮次”也应说明是否指一次遍历还是固定步数。

<a id="dlp2-detail-25"></a>

### 7.2 为何梯度有限性检查放在更新之前

损失有限并不保证梯度有限。某些运算在当前点可以得到有限前向值，却具有不稳定或不定义的导数。更新前检查梯度可以阻止非有限状态进入参数。当前网络使用常规卷积、ReLU 和交叉熵，数值风险较低，但这一机制仍有教学价值，尤其当未来加入对数、除法或自定义归一化时。

梯度为空也需要解释。有些网络确实存在本批未使用的分支，某些参数可以合理地没有梯度；当前串行小网络所有参数都在前向路径上，因此断言每个梯度存在是合适的。把这个断言不加修改地套到条件计算模型，会把合法稀疏更新误判为故障。断言应反映具体结构，而不是形成一套与任务无关的机械规则。

参数更新后还可以检查有限性，尤其在更激进学习率或低精度环境中。当前完整代码对损失和梯度作检查，并通过后续验证损失的有限值观察训练状态。若要用于更复杂实验，应扩展异常捕获并记录失败配置，而不是在异常后静默跳过批次，使实际训练预算与报告不一致。

<a id="dlp2-detail-26"></a>

### 7.3 验证最优与训练末尾是两个时间点

当前实际运行中最佳轮次是二十八，训练继续到三十。最后两轮并不意味着模型一定已经严重过拟合，只能说在这份验证集上交叉熵没有再优于先前最小值。验证波动可能来自参数更新方向、有限样本和不同错误置信度变化。不能仅凭两轮回升就建立一个关于所有数据的过拟合定理。

恢复最佳快照后，验证损失应回到保存值。若回不去，应依次检查是否复制完整状态、是否使用相同输入和损失、模式是否一致以及是否有随机推理。这条核对把选择记录与实际评价对象连接起来。没有恢复核对，后续任何测试数字都可能对应错误状态。

## 8. 用实际结果检验常见解释

<a id="dlp2-detail-28"></a>

### 8.1 卷积交叉熵更低却少对一张意味着什么

准确率只取决于最大分量的位置。假设模型甲把一张图从轻微错误改为轻微正确，准确率就增加一个单位；但如果它同时在另一张错误图上把真实类别概率从零点一降到万分之一，交叉熵可能显著恶化。反之，一个模型即使少纠正一张图，也可能整体给真实类别分配更合理的概率，因此平均交叉熵更低。

当前卷积与线性结果正好说明两个指标可能分歧，但不能只凭平均数判断具体分歧来自哪些样本。第三章将解释如何在同一行上对齐概率与标签、按样本比较损失差，并检查模型各自独有的错误。只有配对证据才能支持“改进集中在哪些图像”的结论。

还需要注意，逻辑回归的概率分布受正则强度影响，卷积的概率分布受优化轨迹与最佳轮次选择影响。当前比较不是对两类模型完成同等规模的最优搜索，因此结论应限定为预定配置。研究方法家族的全面优劣，需要更系统的预算和独立选择设计。

<a id="dlp2-detail-29"></a>

### 8.2 验证准确率比测试准确率高是否异常

最佳验证准确率为百分之九十七点五，测试准确率约百分之九十五点五六，差七张图。这个差异可能来自样本波动和验证选择效应，不能单凭它断定存在泄露或分布漂移。也不能因为差异在直觉上不大，就宣布所有假设已被证明。应先核对实现，再结合有限样本的不确定性解释。

如果多次独立划分都出现明显验证乐观，需要检查搜索是否过度适应验证、划分是否存在来源差异以及评价代码是否一致。单次结果适合提出问题，多次独立证据才有助于分辨机制。不要通过把测试样本挪到训练集中来“修复”差距，那只会改变评价对象。

<a id="dlp2-detail-30"></a>

### 8.3 训练曲线不是因果解释的自动生成器

训练损失下降说明当前优化目标在路径上改善，不直接说明学到了哪一种笔画机制。验证损失回升也不自动证明某个层过度复杂。多个机制可能产生相似曲线：学习率过大、标签噪声、正则不足、数据漂移或错误汇总。曲线是诊断入口，机制解释需要额外的对照或局部检查。

一个好的诊断陈述应包含可推翻的后续预测。例如怀疑学习率导致后期震荡，可以在同一开发协议下预定较小学习率对照，并检查波动幅度和收敛速度，而不是只挑一条更平滑曲线。第三章与后续资源章节进一步说明如何把诊断变成受控比较。

## 9. 最佳状态选择的进一步边界

<a id="sec-6-1"></a>

<a id="dlp2-detail-32"></a>

### 9.1 早停、最佳快照和最终重训

固定三十轮并保留最佳快照，是一种明确的选择算法。耐心值早停则在连续若干轮没有改善后结束训练，实际预算也取决于验证历史。两者可能返回同一轮状态，但资源消耗和失败行为不同。报告时应写实际执行流程，不能因为最终恢复较早轮次，就说训练在那个轮次停止。

有时会根据验证结果确定超参数，然后把训练和验证合并重训。这个流程可以合理，但最终模型已经不同于原来的最佳快照，必须有预先约定的训练长度或选择策略。不能合并后继续用原验证集评估选择，因为它已经参与参数更新。最终测试应评价实际交付的重训模型，而不是旧快照。

若训练预算有限，可以直接交付已验证的快照，不必为了使用更多数据而强行重训。重要的是使交付对象与报告一致。一个使用略少数据但证据闭合的模型，往往比一个数据更多却没有明确选择与评价链条的模型更容易审查。

<a id="dlp2-detail-33"></a>

### 9.2 精确续训需要哪些额外状态

精确续训通常需要模型状态、优化器状态、学习率调度器状态、混合精度缩放器状态、已完成步骤、各随机源状态以及数据顺序位置。当前项目不使用调度器和混合精度，但这些概念应区分。仅保存模型权重后重新创建 Adam，相当于启动一个新的优化过程，不是原轨迹的无缝延续。

即使保存了所有状态，跨平台也可能无法逐位一致。确定性算子设置、线程与库实现都可能影响数值轨迹。检查点应承诺它实际能支持的恢复级别，例如同一环境中的继续训练或功能近似一致的推理，而不是未经验证地声称任何设备都完全相同。

恢复代码还应拒绝结构不匹配和非有限权重，核对预处理与类别映射。为了加载成功而忽略缺失键，可能让部分层保持随机初始化，产生一个外观上可运行但与报告无关的模型。任何部分加载都应是明确的迁移实验，并记录哪些参数恢复、哪些重新初始化。

## 10. 十六个训练与选择练习

<a id="sec-7"></a>

<a id="dlp2-detail-35"></a>

### 10.1 练习一：推导参数量

问题：本章两个卷积层和线性层为什么共有三千八百一十八个参数？

解析：第一卷积输出八通道，每个输出通道对应一个输入通道的三乘三核，权重七十二，加八偏置为八十。第二卷积输出十六通道，每个连接八个输入通道，权重一千一百五十二，加十六为一千一百六十八。池化把十六乘八乘八变为十六乘四乘四，展平二百五十六维，线性层权重二千五百六十，加十偏置为二千五百七十。相加得到目标值。若忽略偏置或误以为池化有可训练权重，就会产生不同数字，应该回到结构逐项核对。

<a id="dlp2-detail-36"></a>

### 10.2 练习二：先 softmax 会改变什么

问题：网络输出分数后先转为概率，再传入交叉熵，为什么不是一个无害操作？

解析：损失会把传入的概率再次视为分数，执行第二次归一化。原本真实类别概率接近一时，正确负对数似然应接近零；二次归一化后，各输入分数被限制在零到一，类别之间的差距受限，损失和梯度都会改变。自动微分会忠实地计算错误组合的导数，不会替使用者纠正目标。应直接传入未归一化分数，只在推理输出或解释概率时单独做 softmax。数值稳定实现也比手工先指数再取对数更可靠。

<a id="dlp2-detail-37"></a>

### 10.3 练习三：最后小批量如何汇总

问题：一个轮次包含十六个六十四样本批量和一个五十三样本批量，怎样计算样本平均损失？

解析：每个批量均值乘以该批样本数，全部加总后除以一千零七十七。若先把十七个批均值直接平均，五十三样本批量每条样本获得的权重会略高于六十四样本批量中的样本。差异可能不大，但它改变统计定义，且在更不均衡批量下可以很严重。若存在掩码或样本权重，应累计有效损失和有效权重，而不是固定使用原始样本数。正确归约必须由目标风险的单位推导。

<a id="dlp2-detail-38"></a>

### 10.4 练习四：关闭梯度为何还会更新批归一化

问题：评价时使用无梯度环境，但忘记评估模式，运行均值为什么仍可能变化？

解析：运行均值是层前向中的状态更新，不依赖反向传播图。无梯度环境只关闭自动微分记录，不改变模块的训练标志。训练模式的批归一化仍会利用当前批统计并更新缓冲，随机失活也仍会抽样掩码。因此评价通常同时需要评估模式和无梯度或推理模式。当前小网络没有这些层，也应保留明确约定，防止未来扩展后代码悄悄失效。状态变化可以通过前后比较缓冲直接验证，而不必依赖准确率异常。

<a id="dlp2-detail-39"></a>

### 10.5 练习五：最佳状态字典为何会变化

问题：每次验证改善就令最佳状态等于模型状态字典，最终恢复仍然是最后模型，原因是什么？

解析：状态字典内张量可能共享模型存储，后续原位参数更新也会改变这些张量。外层字典是独立对象并不意味着内部张量内容已经复制。应在选择发生时深拷贝，或对所有状态张量克隆，并同时更新轮次和指标。可以用本章机制实验直接观察这一点，再恢复并重算验证损失。只看变量名称或文件名称无法证明快照正确，功能核对才把保存内容与选择记录连接起来。

<a id="dlp2-detail-40"></a>

### 10.6 练习六：最好准确率是否就是当前最佳模型

问题：第二十八轮交叉熵最低，第二十九轮准确率最高，最终应该选哪一个？

解析：当前预定主选择指标是验证交叉熵，所以选择第二十八轮。可以把第二十九轮准确率作为附加观察，但不能在看到结果后自由更换主指标，再把最终模型称为原协议的结果。如果业务真正只关心零一错误，应在下一轮实验前把选择指标改为准确率，并预定相等时的规则。选择函数本身是学习算法的一部分，改变它相当于改变算法，而不是只改报告格式。

<a id="dlp2-detail-41"></a>

### 10.7 练习七：恢复模型后继续训练是否无缝

问题：从第二十八轮恢复权重，但使用第三十轮 Adam 状态继续，是否等同于从第二十八轮继续？

解析：不等同。参数虽然回到较早值，优化器一阶矩、二阶矩和计数仍然来自后续轨迹，下一步更新方向与尺度会不同。若只做推理，优化器状态不参与前向，因此无需恢复；若要精确续训，必须保存匹配的完整状态。也可以有意把恢复权重作为新起点并重新初始化优化器，但应称为新的训练阶段，记录学习率和状态重置，而不是宣称重现原轨迹。

<a id="dlp2-detail-42"></a>

### 10.8 练习八：梯度存在为何参数不变

问题：一个层有非零梯度，训练后参数仍然不变，应检查什么？

解析：先检查该参数是否属于当前优化器的参数组，模型重建后旧优化器可能仍持有旧对象。再检查学习率是否为零、是否真正调用更新、是否在更新后加载旧权重，以及比较的是否是克隆前值而不是共享引用。还要考虑浮点舍入，极小更新可能低于参数当前尺度的表示精度。梯度、优化器成员关系、实际更新和重新前向是不同证据，应逐层核对，而不是看到梯度非零就宣布训练正常。

<a id="dlp2-detail-43"></a>

### 10.9 练习九：为什么不把测试准确率写成断言

问题：教程能否要求测试准确率必须高于百分之九十六才算代码通过？

解析：性能取决于随机轨迹、版本、划分和配置，硬阈值容易把合理统计变化误判为实现失败，也会诱导使用者不断调参直到通过测试。结构性断言应检查索引互斥、形状、有限性、快照恢复与指标复算。性能目标可以作为实验预期，但失败时应分析并报告，而不是偷偷改变测试协议。若项目确有最低验收标准，应把独立验收数据、置信要求和失败处理提前定义，不能让教程断言代替正式评价设计。

<a id="dlp2-detail-44"></a>

### 10.10 练习十：路径训练损失与轮末损失

问题：为什么训练日志平均损失低于或高于轮末完整训练集损失，都不一定是错误？

解析：路径损失在多个不断变化的参数状态下计算，轮末损失在同一个最终状态下计算。若有随机失活、增强或批归一化，二者前向条件还可能不同。即使没有这些机制，参数更新也足以使两者不同。若要研究固定模型的训练与验证间隙，应在轮末用相同评估设置重新计算两个集合。日志方便不等于统计定义相同，比较前应先确认每条曲线到底表示哪一个对象。

<a id="dlp2-detail-45"></a>

### 10.11 练习十一：一张图的差距如何解释

问题：线性基线比卷积多正确一张，是否说明卷积没有价值？

解析：它说明在这次固定图像级测试中，线性配置的零一错误少一个。不能从一张图推断模型家族的普遍优劣，也不能因为卷积交叉熵更低就抹去准确率事实。应同时报告计数、概率损失和配对错误，并根据研究问题讨论资源与稳定性。若要建立可靠的结构性结论，需要多次预定重复、合理选择预算和新的独立证据。一次诚实的指标分歧比强行制造统一胜者更能说明实际建模的复杂性。

<a id="dlp2-detail-46"></a>

### 10.12 练习十二：如何确保同一模型对应所有指标

问题：准确率来自最佳快照，交叉熵来自最后一轮，这样汇总为何危险？

解析：报告行会组合两个不同评价对象，读者无法知道哪个模型真正具有这些指标。应在恢复唯一选定状态后做一次前向，从同一分数或概率数组计算所有指标，并保留索引、标签和类别顺序。若比较多个状态，应分别成行并说明选择规则，而不能把各自最优指标拼接。模型身份是指标解释的前提，不能仅靠相同架构名称把不同参数状态视为同一个对象。

<a id="dlp2-detail-47"></a>

### 10.13 练习十三：验证损失相等时如何处理

问题：两轮验证损失完全相等，应该保留较早还是较晚状态？

解析：两种规则都可以，但必须提前固定。当前使用严格小于，因此保留较早状态。若使用小于等于，则会偏向较晚轮次。浮点近似相等也需要清楚，随意增加容差会改变选择函数。可以预定最小改善阈值，但那属于另一种算法。关键是规则稳定、记录完整，并能在恢复后重现所声明的选择，而不是根据最终测试表现挑一个方便的解释。

<a id="dlp2-detail-48"></a>

### 10.14 练习十四：如何验证评价不改变模型

问题：除了查看参数梯度，如何直接检查评价没有改变状态？

解析：评价前深拷贝完整模型状态，评价后逐键比较参数和缓冲；同时检查模式与输出的重复一致性。梯度为零不代表运行统计没变，也不能证明没有自定义层维护隐藏缓存。若层有状态但未注册为缓冲，需要另外审查其实现。当前网络的简单结构降低了风险，但可扩展代码应以完整状态和功能不变性为准。发现变化时要先区分预期缓存与影响推理的状态，再决定是否违反契约。

<a id="dlp2-detail-49"></a>

### 10.15 练习十五：为什么种子要分开管理

问题：网络初始化和数据打乱共用一个全局随机源，会造成什么比较困难？

解析：增加一个随机初始化层会消耗更多随机数，后续数据顺序也可能改变。这样比较架构时同时改变了初始化和批次顺序，使差异更难归因。独立生成器不能消除所有混杂，但能把两个随机机制分开，便于控制。需要进一步记录每个生成器的用途和状态；仅给不同整数而不控制实际调用仍然可能出错。严格配对实验还应预先设计多种子对应关系，而不是临时选择有利配对。

<a id="sec-7-1"></a>

<a id="dlp2-detail-50"></a>

### 10.16 练习十六：最佳模型的准确表述

问题：如何描述本章返回的模型，避免“全局最好”之类不受支持的语言？

解析：可以说，它是在固定训练划分、固定初始化和三十轮预算中，按验证交叉熵严格改善规则选择的快照。这个定义限定候选集合、随机条件和选择指标。它不是所有网络中的最佳，也不一定是验证准确率最高，更不保证测试交叉熵全局最小。若把这些限定省略，“最佳模型”就容易变成无法检验的宣传词。清楚的局部最优描述有助于后续研究更换预算、种子或目标时正确比较。

<a id="dlp2-detail-51"></a>

## 11. 把完整训练转成可复用知识

<a id="dlp2-detail-52"></a>

### 11.1 在修改网络前先固定证据链

当前完整实验已经连接数据索引、张量单位、网络形状、损失定义、参数更新、验证记录、独立快照和最终预测。修改任何一项都应知道它属于哪一层。若只是重构代码，应检查功能等价与状态一致；若改变优化器或池化，则是新的学习算法，需要重新训练和选择；若改变输入单位，则连任务契约都发生变化。

这条证据链也决定了如何排查失败。若最终预测异常，先验证恢复状态和输入契约，再检查评价模式和类别映射，最后才讨论模型是否学到了不好的特征。直接重新训练可能暂时改变结果，却会丢失问题线索。可解释的局部检查通常比反复随机重跑更能积累知识。

<a id="dlp2-detail-53"></a>

### 11.2 下一章的边界

第三章不会根据当前测试错误重新选择这个卷积模型，而是解释如何阅读冻结预测、构建配对比较和设计下一轮消融。当前错误十六张，是相对于数据集标签的事实，不自动对应十六种独立机制。相同视觉困难可能导致多张错误，一张图也可能同时受到笔画歧义、裁切和置信度问题影响。

真正进阶的研究需要把观察转成受控假设。例如怀疑池化抹去细线，可以预定替换方案，在开发数据中比较，控制参数量和训练预算，并在新的确认评价上检验。训练代码提供可靠测量工具，错误分析提供问题来源，实验设计负责连接二者。三者缺一，就很容易把一次偶然的性能变化误解为机制发现。


<a id="dlp2-detail-54"></a>

### 11.3 从经验风险看当前训练目标

对训练索引集合，当前经验目标是每张图交叉熵的平均。小批量梯度是这一平均梯度的随机估计，但随机打乱且无放回遍历时，各步并非完全独立抽样。每次更新还会改变后续梯度所处的位置，因此一轮小批量更新一般不等价于在轮初计算完整梯度后更新一次。即使累计看过相同样本，优化轨迹也可以不同。

这个区别解释了为什么改变批量大小不是纯粹的内存优化。它改变每次梯度估计的波动、每轮更新次数以及 Adam 矩估计的时间尺度。保持学习率不变时，大批量可能需要不同预算才能达到相近状态；按批量线性调整学习率则是一条经验策略，不是对当前非凸目标普遍成立的等价变换。任何调整都应作为配置记录，而不能被隐藏在数据加载器参数中。

从统计目标看，经验交叉熵把训练样本等权相加，近似的是训练采样分布下的平均损失。若未来类别频率发生变化，最优概率和最优决策都可能改变。对训练损失加类别权重会重新定义目标，也会影响概率含义。不能在训练后直接把加权模型输出解释成原始自然频率下的校准概率，而不考虑权重与采样机制。

<a id="dlp2-detail-55"></a>

### 11.4 数值稳定与可微性不是同一个概念

减去最大分数使 softmax 的指数不再溢出，但不保证所有参数梯度都具有良好尺度。前层激活可能大面积为零，某些通道可能长期没有有效梯度；另一些参数可能因为输入尺度过大而得到非常大的更新。数值稳定计算解决的是表示与运算问题，优化条件还涉及曲率、尺度和学习率，不能把二者混为一谈。

ReLU 在零点不可微，自动微分框架选择一个约定的局部导数用于计算。有限差分检查若刚好跨过零点，数值导数与所选分支导数可能不一致，而不意味着自动微分实现错误。做梯度机制检查时应选择远离折点的参数或使用方向扰动，并解释扰动尺度。扰动太大会观察非局部变化，太小则被浮点舍入主导。

卷积、池化与交叉熵的组合还可能产生对输入扰动敏感的决策。一个图像的最大分数只比次大分数高很少时，极小数值误差也可能改变类别，但概率损失变化很小。因此跨环境比较时，可以分别核对分数容差、概率容差和分类边界附近样本，而不是要求所有类别预测无条件逐位相同。若系统对这些边界样本有高风险，应设计拒识或复核机制。

<a id="dlp2-detail-56"></a>

### 11.5 日志如何成为可审计的数据表

每轮记录应至少包含轮次、实际更新步数、已处理样本数、路径训练损失、轮末验证交叉熵、验证正确数以及是否刷新最佳状态。正确数比只保存浮点准确率更容易复算。若另行记录时间，应说明是本轮还是累计、是否包含评价与数据准备。把这些字段写清，可以避免后续绘图时把不同单位和不同状态混在同一轴上。

日志表与快照之间需要一个稳定身份。可以使用运行标识、配置摘要和最佳轮次共同索引，但摘要不能代替完整配置。若两个运行使用相同网络名称却具有不同划分或缩放方式，不能把它们当作同一次重复。运行身份应由数据、处理、训练、选择和环境共同确定，而不是只有一个模型类名。

报告生成也可能引入错误，例如把最后一轮指标自动填到最佳模型行，或把不同运行的验证值与测试值按行号拼接。应按运行身份和状态身份关联，并加入一致性检查。当前代码在恢复后重新计算验证损失，已经提供一个关键闭环；完整工程还可以对预测行数、索引唯一性和配置身份作额外检查。可审计性不是最后补写一份说明，而是让每一个输出都能追溯到实际产生它的状态。

<a id="dlp2-detail-57"></a>

### 11.6 把性能差异拆成后续研究问题

当前卷积在交叉熵上占优而准确率略低，至少产生三个不同问题。其一，卷积是否减少了大多数样本的平均概率损失，还是主要修正少数极端自信错误；其二，两个模型是否在同一批难例上犯错；其三，差异是否对初始化和划分稳定。这三个问题需要不同证据，不能用一张总分表同时回答。

第一个问题可以研究冻结预测的逐样本损失差和分位数，但任何根据结果新定义的切片都应标为探索。第二个需要逐样本配对表，不能从两个总正确数推导。第三个需要预定重复训练或划分，不应把当前固定模型的测试自助区间当作训练随机性的完整估计。分清问题以后，下一轮实验才知道应该增加哪一种信息，而不是简单地“多跑几次看看”。

最后，模型选择规则也可以成为研究对象。按交叉熵选轮次与按准确率选轮次可能产生不同的概率质量和错误集合。要公平比较这两种规则，应把它们视为两个完整学习流程，在相同开发预算和独立确认评价中比较，不能在当前测试结果出现后挑选规则。这样，最佳状态选择不再只是一个工程技巧，而成为可以严谨讨论的统计学习算法。


<a id="dlp2-detail-58"></a>

### 11.7 读懂一次成功运行的真正含义

一次成功运行意味着在当前环境中，输入检查、梯度计算、快照选择、恢复与指标复算形成了自洽流程。它并不保证模型已经达到任务上限，也不保证每个随机初始化都同样稳定。后续修改应先保留这一基准作为可解释参照，再逐项增加复杂性。

若新方案失败，能够回到一个已理解的流程，比不断累积补丁更有助于定位问题。学习完整训练的目标，是知道每一个数字来自哪个状态、哪个分母和哪一种信息使用，而不只是记住若干库函数的调用顺序。

在比较任何新运行时，先确认它使用同一数据角色、同一输入单位和同一汇总分母。若这些条件发生改变，应另立协议并解释变化，而不是仅凭相同网络名称把两次结果相减。一个分数只有在评价对象和随机机制明确时，才具有可比较的含义。
