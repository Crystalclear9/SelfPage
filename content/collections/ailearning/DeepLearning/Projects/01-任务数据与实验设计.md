## 1. 项目首先是一组可以被推翻的陈述

<a id="dlp1-detail-2"></a>

### 1.1 把“训练一个分类器”变成明确问题

本项目研究一个有限而清楚的问题：给定一幅已经裁切、已经缩放到八乘八网格、具有固定灰度量程的手写数字图像，输出 0–9 共十个类别的概率分布，再通过最大概率决定类别。输入不是整页文档，不包含检测框，不负责寻找纸张位置，也不负责区分空白页与数字。因此，项目的成功不能直接说明系统能识别手机拍摄的作业。拍摄角度、背景纹理、多个字符、笔迹颜色与切割误差，都不在当前输入契约已经覆盖的范围之内。

明确任务并不是降低挑战，而是让每一个挑战有自己的证据。若把检测、裁切、分类混为一个分数，识别失败时就不知道错误发生在哪一环。一个实际系统可以把页面定位、字符分割与分类连接起来，但是必须分别保存中间结果并检查误差传播。当前练习先把分类环节做成可复查的实验，以便将来扩展时能够指出哪一条假设已经改变。

预测对象也需要明确。本文以图像为评价单位，一张图像对应一个标签。类别标签表示数据集提供的数字类别，不表示书写者身份或书写质量。在没有额外人工复核之前，分类器与标签不一致只能称为“相对于提供标签的错误”。若想研究歧义笔迹是否应该允许多个答案，便需要重新定义标注协议和损失，而不能在看到错误后临时把某些标签宣布为无效。

<a id="dlp1-detail-3"></a>

### 1.2 性能目标与知识目标同时存在

性能目标可以写为独立测试图像上的平均交叉熵和准确率。知识目标则是理解数据流、训练更新、验证选择、快照恢复与错误解释能否构成一条闭合链。二者相互支持，却不能互相替代。一个准确率很高但在全数据上拟合了预处理统计量的程序，没有实现原定的独立评价；一个实现规范但准确率较低的程序，仍然可能揭示学习率、网络容量或任务假设的问题。

本组章节不会预先承诺卷积网络一定超过线性分类器。卷积的局部连接和共享权重是归纳偏置，而不是对任意小数据都占优的定理。我们将先冻结比较对象和指标，再接受实际出现的结果。若交叉熵改善而准确率略降，报告应保留这一分歧，分析概率质量与决策错误的区别，而不是挑选有利的指标把结论改写为全面提升。

第二章给出一次完整、可运行的固定配置实验。第三章在冻结预测后研究错误、配对比较和交付边界。后两章进一步讨论曲线、检查点、推理接口与资源比较。当前章的职责是定义这些实验究竟能够回答什么，并在训练发生之前把信息使用方式约束清楚。

<a id="sec-1-1"></a>

<a id="dlp1-detail-4"></a>

### 1.3 从原始灰度到张量的单位推导

内置 digits 数据包含一千七百九十七张图像，每张图像为八行八列，像素取值在零到十六之间。把像素除以十六，是把已知灰度量程转成零到一附近的无量纲坐标。对任意像素值八，变换后的值为二分之一。这个变换没有通过样本估计参数，因此在训练、验证、测试中使用同一个固定常数，不会向模型泄露测试集的经验均值。

这与标准化不同。若变换写成每个像素减去样本均值再除以样本标准差，那么均值和标准差都属于待拟合对象。训练阶段只能从训练图像估计它们，再固定应用到其他划分。假如一个位置训练像素为零、零、十六，均值为十六除以三；测试像素为十六。把测试也加入均值计算就得到八，训练坐标已经受到了测试输入影响。即使没有读取测试标签，训练过程依然不再满足最初的归纳评价协议。

固定量程变换也不是永远正确。若部署设备输出零到二百五十五的八位灰度，却仍然除以十六，输入便会扩大约十六倍。网络的线性层和激活会进入训练时没有覆盖的范围。部署契约必须写明原始像素单位、缩放常数、通道顺序、空间尺寸与可接受的数值范围，而不能只说“输入一张图片”。

<a id="dlp1-detail-5"></a>

## 2. 从数据对象推导评价对象

<a id="dlp1-detail-6"></a>

### 2.1 张量形状承载了哪些语义

本章约定图像张量形状为批量大小、通道、高度、宽度四个维度，即 $`(N,1,8,8)`$。标签形状为 $`(N,)`$，取值为零到九的整数。批量维不是类别维，单通道也不意味着每张图只有一个特征。卷积层在空间位置上重用权重，分类层最终输出 $`(N,10)`$ 个未归一化分数。交叉熵接受这些分数和整数标签，内部完成稳定的对数归一化。

形状正确只是第一道检查。若把数据误转置成八个通道、宽度为一，某些网络仍然可能通过形状检查并开始训练，却已经改变了邻接关系。若标签恰好被打乱，损失也可能下降一点，因为网络在拟合有限样本中的偶然关系。必须通过几个可以手工解释的样本，把原始矩阵、标签、张量切片与前向输出连接起来，确认“第几个样本”在所有对象中代表同一个实体。

数据行的顺序不能承担隐藏的语义。例如先按类别排序再取前百分之六十训练，会让部分类别从训练中消失；按下载批次切分，可能引入来源差异；随机划分虽然缓解这些现象，也不自动解决同一书写者跨集合的问题。每种划分都在对未来对象作出假设，必须明确它希望模拟哪一种部署场景。

<a id="dlp1-detail-7"></a>

### 2.2 图像独立与书写者独立是不同的主张

内置接口提供图像和数字标签，但本项目没有利用可验证的书写者身份字段。因此我们只声明图像级分层随机留出评价，不声明训练与测试来自互不重叠的书写者。即使测试准确率很高，也不能从中推出对全新书写者的同等性能。书写风格可能在不同图像之间共享，随机拆分无法凭空消除这种相关性。

如果未来获得可靠的书写者标识，应先按书写者分组，再在组级别划分，并检查每个集合的类别覆盖。那时有效样本量更接近独立书写者数量，而不是所有图片数量。需要报告组数、每组图片数量分布以及每个类别在多少组中出现。某个类别有很多图片却全部来自两个人，其来源多样性仍然很低。

也不要把像素完全相同的图像直接等同于同一书写者。完全重复是可以通过内容比较检测的特殊问题，近似重复和共享来源则需要更多证据。哈希只能说明规范化后字节是否相同，不能验证数据采集独立性；一个来源可能生成许多不相同的图片，而两个人也可能写出相似图案。数据质量检查与来源设计是互补的工作。

<a id="dlp1-detail-8"></a>

### 2.3 风险函数中的分布不能省略

对分类规则 $`f`$，目标风险可以写成
$$
R_P(f)=\mathbb E_{(X,Y)\sim P}\left[\ell(f(X),Y)\right].
$$
下标 $`P`$ 指定未来任务的联合分布。当前测试集只能为与当前采样条件相近的图像级风险提供经验依据。若部署分布变为手机照片，真正关心的变成另一个风险 $`R_Q(f)`$。除非额外建立 $`P`$ 与 $`Q`$ 的联系，否则仅凭 $`R_P`$ 的低估计值，不能对 $`R_Q`$ 给出数值保证。

这一表达式还揭示了损失定义的重要性。若每个类别同等重要，可能希望研究类别均衡分布；若未来请求按自然频率到来，则请求级平均损失更直接。两种风险都可以合理，但对应不同的权重。不能先用一种分布训练和选择，再在结果不理想时把目标风险重新定义成另一种而不注明变更。

## 3. 三份数据为何必须承担不同角色

<a id="dlp1-detail-10"></a>

### 3.1 本项目唯一固定的划分协议

我们先对全部样本索引做分层随机拆分，使用种子四十一留出百分之二十作为测试集。随后仅在剩余开发索引中使用种子四十二，再留出四分之一作为验证集。最终训练集一千零七十七张，验证集三百六十张，测试集三百六十张。由于整数取整，比例是近似六比二比二，具体人数以索引长度为准。

分层的作用是让各个划分保留相近的类别比例，降低小样本拆分中某类过少的风险。分层并不使样本独立，也不提供来源隔离。种子使这一具体索引集合可以重建，但重建能力依赖数据版本和行顺序。相同种子作用于被重排的数据，会产生不同的实体划分，因此实验记录应同时保存数据身份与划分规则。

训练集允许参与梯度更新和所有待拟合统计量的估计。验证集允许参与配置比较、训练轮次选择和事先约定的停止规则。测试集在配置冻结后进行最终评价。选择最佳轮次时查看验证损失，本质上就是使用了验证标签；这很正常，但也说明验证分数不能再被视为一个完全未参与选择的最终泛化估计。

<a id="dlp1-detail-11"></a>

### 3.2 选择会把验证噪声写入最终模型

设两个候选模型真实风险相同，但验证估计分别带有正负波动。选择验证分数较好者，等于在真实表现相近时偏向选中负误差。候选数量越多、候选越灵活、反复观察后人工修改越多，验证集就越可能被适应性使用。这里不是说任何选择都不可进行，而是说选择后的验证最小值通常不能直接当作无偏的最终风险估计。

一个简单模型是每个候选的验证误差等于共同风险加一个零均值噪声。即使每个候选单独都是无偏的，多个噪声中的最小值期望仍然小于零。独立正态近似下，最小值的偏移规模随候选数量的对数平方根增长；真实神经网络候选之间通常高度相关，不能把这个近似当成精确修正公式，但方向足以解释为何海量搜索容易得到过分乐观的验证最优值。

如果测试后继续调参，就应把原测试集重新称为开发信息来源，并申请新的独立评价数据。没有新数据时，也可以诚实地报告探索性结果和不确定性，却不应通过更名文件恢复其独立性。数据角色来自真实的信息使用历史，而不是文件夹叫训练、验证还是测试。

<a id="sec-2-1"></a>

<a id="dlp1-detail-12"></a>

### 3.3 选择指标可以不同于报告指标

本项目用验证交叉熵选择最佳轮次，同时在最终报告中给出交叉熵和准确率。这样做有清楚的理由：交叉熵利用完整概率分布，对过度自信的错误敏感；准确率只看最大概率对应的类别。一个模型可以在不改变任何类别判断的情况下改善正确类别的概率，从而降低交叉熵。另一个模型也可能纠正一张图，但在其余错误上变得极端自信，导致准确率改善而交叉熵恶化。

必须提前写明主选择指标，否则研究者可能在结果出来后在两个指标之间自由切换。假设第二十八轮交叉熵最好，而第二十九轮准确率最高，最终模型仍应按既定规则选择第二十八轮。报告可以说明另一个轮次准确率更高，但不能把“按交叉熵选择”的模型称为“验证准确率最优”。

当业务确有非对称错误成本时，准确率本身可能不合适。把数字一错成七与把八错成三是否具有不同损失，需要由任务决定。若成本矩阵为 $`C_{a,y}`$，最小期望成本决策选择使 $`\sum_y C_{a,y}p_y(x)`$ 最小的动作。最大概率分类只是零一成本的特殊情形。成本矩阵、拒识阈值与人工复核规则都应在独立的策略选择阶段确定。

## 4. 三个可以独立运行的数据协议实验

<a id="dlp1-detail-14"></a>

### 4.1 实验一：检查索引、量程与类别覆盖

下面代码只载入随 scikit-learn 安装的数据，不下载网络数据，也不创建文件。断言覆盖了长度、互斥、全集覆盖、类别集合与灰度范围。它们的目标是检查实现是否符合本章协议，而不是通过这些断言证明测试图像来自新的书写者。

```python
import numpy as np
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

d = load_digits()
idx = np.arange(len(d.target))
dev, test = train_test_split(
    idx, test_size=0.2, stratify=d.target, random_state=41
)
train, valid = train_test_split(
    dev, test_size=0.25, stratify=d.target[dev], random_state=42
)
assert [len(train), len(valid), len(test)] == [1077, 360, 360]
sets = [set(train), set(valid), set(test)]
assert not (sets[0] & sets[1] or sets[0] & sets[2] or sets[1] & sets[2])
assert set.union(*sets) == set(idx)
for part in (train, valid, test):
    assert set(d.target[part]) == set(range(10))
x = (d.images[:, None] / 16).astype(np.float32)
assert x.shape == (1797, 1, 8, 8)
assert np.isfinite(x).all() and x.min() >= 0 and x.max() <= 1
print([np.bincount(d.target[s], minlength=10).tolist()
       for s in (train, valid, test)])
```

检查类别覆盖并不意味着每类误差都能被精确估计。三百六十张验证图像分到十类，每类只有几十张，一张图的对错就会明显改变该类召回率。若报告到小数点后六位，会给人一种虚假的精确感。保留足够数字便于复算是合理的，但解释时应同时给出分子分母，例如“某类三十六张中错三张”。

<a id="dlp1-detail-15"></a>

### 4.2 实验二：让泄露在一个手算例中显形

下面构造的数据不是 digits 性能实验，只用于证明拟合统计量的边界。训练均值必须只由训练值决定。修改测试值应当影响测试变换结果，但不应改变已经拟合好的训练均值，也不应改变任何训练样本的标准化坐标。

```python
import numpy as np

train = np.array([0.0, 0.0, 16.0])
test = np.array([16.0])
mu = train.mean()
train_before = train - mu
test_changed = np.array([1600.0])
assert mu == train.mean()
assert np.array_equal(train_before, train - mu)
leaky_a = np.concatenate([train, test]).mean()
leaky_b = np.concatenate([train, test_changed]).mean()
assert leaky_a == 8.0 and leaky_b != leaky_a
assert not np.array_equal(train - leaky_a, train - leaky_b)
assert np.array_equal(train / 16, np.array([0.0, 0.0, 1.0]))
print(mu, leaky_a, leaky_b)
```

这一不变性测试比“程序中没有显式读取测试标签”更严格。泄露常常通过全数据归一化、缺失值填补、重复检测后的不当选择、特征筛选甚至缓存传递。检查某条处理是否允许使用验证或测试信息，需要问它的参数由谁确定，以及这些参数是否影响了被评价模型，而不能只检查函数名称是否含训练。

<a id="dlp1-detail-16"></a>

### 4.3 实验三：验证选择偏差的可重复模拟

这里模拟二十个真实风险相同的候选。为避免把数学期望和某次小样本随机结果混淆，我们使用足够多次重复估计平均偏移，同时只对应该成立的方向和数值范围作断言。这些数值不是神经网络在 digits 上的风险，也不能拿来从真实验证分数中直接扣除。

```python
import numpy as np

rng = np.random.default_rng(45)
noise = rng.normal(0, 0.02, size=(20000, 20))
single = 0.2 + noise[:, 0]
selected = 0.2 + noise.min(axis=1)
assert abs(single.mean() - 0.2) < 0.001
assert selected.mean() < 0.17
assert np.all(selected <= single)
fresh = 0.2 + rng.normal(0, 0.02, size=20000)
assert abs(fresh.mean() - 0.2) < 0.001
print(single.mean(), selected.mean(), fresh.mean())
```

模拟中的候选噪声独立，现实候选往往相关，因此不要把二十个候选机械解释成二十次完全独立的机会。重要结论是，开发集既然用于挑选，就不能同时承担最终未选择评价的全部职责。若研究预算只容许一个小型留出测试，控制搜索数量、保留全部尝试记录、明确探索与验证，是比事后包装一个最佳数字更有价值的改进。

## 5. 训练前的最小验证链

<a id="dlp1-detail-18"></a>

### 5.1 从一个样本到一个可解释损失

训练前可以先取一张标签为三的图像，确认它的二维像素排列和保存标签一致，再检查张量范围与模型输出。输出长度应为十，所有分数应有限。若网络初始输出接近零，则各类别概率接近十分之一，单样本交叉熵接近自然对数十，约为二点三零三。初始损失不必恰好等于该值，但若一开始就达到极小值或出现数千的值，应先检查标签泄露、数值尺度和目标格式。

对一条样本，交叉熵为正确类别概率的负对数。若正确类概率为五分之一，损失约一点六零九；若变成十分之九，损失约零点一零五。概率越小惩罚越大，且错误的极端自信尤其昂贵。这解释了为什么交叉熵能反映准确率看不出的变化，也解释了为何只记录准确率不足以排查数值问题。

一个常见错误是在交叉熵之前额外做一次 softmax。内置损失期望未归一化分数，已经完成稳定的对数 softmax；把概率当分数再次归一化会改变目标与梯度。另一个错误是把多分类目标转成连续标量并使用平方损失，隐含数字九与零之间有某种顺序距离。分类标签的数值编号不是几何坐标，除非任务确实定义了这种结构。

<a id="dlp1-detail-19"></a>

### 5.2 小样本过拟合试验能证明什么

取十几张互不矛盾的训练图像，关闭数据增强和正则化，使用足够有表达能力的网络，尝试把训练损失显著降低。若失败，优先检查优化器是否包含所有待训练参数、梯度是否为零、学习率是否过大或过小、标签是否对齐、前向是否被错误放在无梯度环境中。这个试验把泛化难度暂时拿掉，使实现机制更容易观察。

通过小样本过拟合只说明网络有能力记住这批样本，且当前梯度链至少能工作。它不能说明正式划分没有泄露，不能说明在全数据上学习率合适，也不能证明错误标签没有存在。若同一输入对应矛盾的标签，确定性分类器无法同时给两者接近一的正确类概率，损失存在由冲突决定的下界。此时不应把无法归零误判成自动微分故障。

小样本试验的数据必须来自训练集，不应为了“更容易检查”挑取测试图像。即使没有正式更新最终模型，用测试样本调试增强、选择网络或人工修正预处理，也会把测试信息带进开发流程。测试集并不是只在调用反向传播时才会被使用，研究者的人为选择同样是学习系统的一部分。

<a id="deep-dive-3"></a>

<a id="dlp1-detail-20"></a>

### 5.3 梯度、参数更新与指标的三层检查

梯度存在不等于参数已更新。参数可能没有被加入优化器，优化器学习率可能为零，或更新被随后的错误加载覆盖。应该在一次训练步骤前后比较目标参数，确认至少一部分参数发生有限变化；同时检查梯度范数和更新范数，防止把几乎没有影响的微小变化当成正常学习。

参数更新也不等于任务性能改善。学习率很大时，更新可以显著却让损失发散；使用错误标签时，训练损失可以下降而真实任务失败；评价汇总错误时，日志甚至会制造不存在的进步。因此检查需要从输入、标签、损失定义到梯度、更新、重新前向和评价统计逐层闭合。每一层都应有能被独立解释的局部证据。

正式训练开始前还应检查一次评价是否会改变状态。带批归一化的网络在训练模式下会更新运行统计，带随机失活的网络在训练模式下会产生随机输出。只关闭梯度并不自动切换这些行为。本项目小网络没有批归一化和随机失活，但评价函数仍显式调用评估模式，建立可扩展的正确约定。

## 6. 基线不是陪衬，而是对解释的约束

<a id="dlp1-detail-22"></a>

### 6.1 常数、线性与卷积各回答什么问题

最简单的常数基线只预测训练集最常见类别，提供类别频率层面的下限参照。它不能利用图像，因此与图像模型的差距主要说明输入含有可预测信息。若一个复杂模型只略高于常数基线，应先检查实现和任务可辨识性，而不是直接堆叠更深网络。

线性多分类器对展平的六十四维像素做线性打分。它没有学习可平移重用的卷积核，但仍能通过每个位置的权重识别典型笔画。小图像已经被居中并统一尺度，这些预处理可能使线性边界相当有效。因此线性基线不是故意设置的弱对手，而是检验卷积复杂性是否带来实质价值的合理比较。

卷积网络引入局部连接和空间共享，让不同位置使用相同的笔画探测器。共享可以减少自由参数，也可以在某些位移变化下提供有用偏置，但池化还可能丢失区分数字所需的细节。网络的优势取决于任务变换、数据规模、优化状态和参数预算，不能仅从结构名称推断。

<a id="dlp1-detail-23"></a>

### 6.2 比较时哪些公平性必须写出来

本项目固定一组线性配置和一组卷积配置，使用相同训练划分和相同最终测试集。卷积模型通过验证交叉熵选择轮次，而线性分类器使用预定的正则强度一次拟合。两者的开发预算并不完全相同，因此最终比较只能说明这些具体学习流程的表现，不能宣称已经穷尽每种模型家族的潜力。

参数量、更新次数、训练时间和搜索次数分别衡量不同资源。参数更少不代表更快，卷积虽然共享权重，仍然可能在多个空间位置执行大量乘加。训练时间还取决于线程、硬件、库实现和批量大小。若要比较效率，应固定运行环境并重复计时，同时把数据载入和首次初始化开销与稳定计算分开。

当两个模型差距只有一张图时，不能用一个排行榜式百分比宣称结构性优势。需要检查它们在同一批图像上的配对错误，评估差异的不确定性，并考虑多个训练种子或多个划分。性能比较应当服务于一个具体问题，例如“在这一训练预算下，卷积是否降低概率损失”，而不是笼统地证明一种模型永远优于另一种。

## 7. 将实验冻结为一份可执行协议

<a id="dlp1-detail-25"></a>

### 7.1 本组章节采用的预定配置

数据采用上述图像级分层划分，预处理仅除以十六，不使用数据增强。卷积模型为两个带填充的三乘三卷积层，通道数依次为一、八、十六；每个卷积后使用 ReLU；接一个二乘二平均池化，再展平并映射到十类。总可训练参数为三千八百一十八。第二章逐项推导这一数字，避免把参数统计当作一个不可解释的软件输出。

训练使用 CPU、单线程、批量六十四、三十个完整轮次、Adam 优化器、学习率零点零零三。模型初始化种子四十三，训练数据打乱生成器种子四十四。每轮结束后在固定验证集上计算平均交叉熵，只有严格低于此前最优值时才更新快照。因此完全相同的最小验证损失发生多次时，保留最早出现的轮次。这里不是早停，而是固定预算内的最佳状态选择。

线性基线使用像素展平后除以十六、正则强度一、最大迭代次数两千的多分类逻辑回归，只在训练集拟合。所有配置先固定，再看最终测试结果。第二章同时报告验证和测试指标，但模型恢复与测试顺序不因结果好坏而改变。训练期间不根据测试错误修改网络，也不在第三章利用测试分析重新挑选胜者。

<a id="dlp1-detail-26"></a>

### 7.2 协议冻结仍允许发现实现错误

如果运行前发现标签类型错误或模型维度错误，修复它属于实现验证，而不是通过测试指标调参。若运行后发现预注册公式写错，也应纠正并保留版本记录，说明旧结果为何无效。预注册的目的不是禁止思考，而是让读者分辨哪些决定发生在看到结果之前，哪些决定受到结果影响。

同样，一次固定实验不意味着所有研究都必须停止。如果错误分析提示位移敏感，可以另开探索分支，明确记录这是基于当前结果提出的新假设。后续需要新验证安排或新测试数据来确认该假设。研究可以不断迭代，但每次迭代都应保留信息边界，不能把反复参与开发的数据继续包装成从未看过的独立证据。

实验记录至少包含数据版本、划分种子与索引摘要、模型定义、预处理、损失归约、优化器、更新预算、选择规则、环境版本和最终恢复状态。仅保存模型权重无法恢复整条学习过程；仅保存一张曲线也无法确认用于测试的是哪一个状态。第二章和后续章节把这些记录映射到实际代码对象。

## 8. 随机性、预算与预注册比较

<a id="dlp1-detail-28"></a>

### 8.1 随机种子的作用和边界

种子控制某个伪随机数生成器的初始状态。网络初始化、训练批次打乱、数据增强、划分和重采样，可能使用不同生成器。只调用一个随机种子函数不一定控制全部来源。本文为划分、初始化和加载器分别给定种子，使各环节的角色清楚，也便于在只改变某一环节时进行实验。

可重复性有多个层级。同一环境内复现一组近似相同的浮点输出，属于执行层面的可重复；换一台机器、换一个线性代数实现仍能得到相近的统计结论，属于更强的稳健性。固定种子不能保证跨版本逐位一致，也不能保证这个种子具有代表性。一次运行的成功不是对所有随机初始化的概率保证。

多种子实验应把种子当成重复单位，保留每个种子的结果，不只报告最佳种子。若每个配置都试十个种子并挑最好的测试分数，种子本身已经成为超参数，测试再次被用于选择。合理做法是先约定固定种子集合和汇总方式，然后比较完整分布或配对差异，而不是从随机波动中挑一条最漂亮的曲线。

<a id="sec-6-1"></a>

<a id="dlp1-detail-29"></a>

### 8.2 等轮次、等更新与等时间不是同一个设计

若两个模型使用不同批量大小，同样三十轮会包含不同数量的参数更新。小批量每轮更新更多次，优化噪声也不同；大批量每次计算更多样本，硬件效率可能更高。若只说训练轮次相同，就不能排除更新次数造成的差异。反过来，固定更新次数又会让不同批量看到不同数量的样本。

等时间比较更接近资源受限场景，但会受实现效率影响。一个概念上更复杂的模型可能使用高度优化算子，而一个简单模型在解释器中逐样本循环，结果反映的是算法与实现的共同效果。应该区分“这份实现能达到什么效果”和“该模型家族理论上需要多少运算”。

本项目选择固定配置的教学实验，并不宣称实现了所有意义上的公平竞争。后续若研究池化方式，应该明确比较是固定相同训练轮次、相同更新次数还是相同墙钟时间，并说明为什么该预算与研究问题相匹配。必要时同时报告多个预算下的性能曲线，让读者看到结论是否随资源条件改变。

<a id="dlp1-detail-30"></a>

### 8.3 预注册不是一张不可修改的愿望清单

一份有效协议应包含问题、比较对象、主指标、选择规则、数据角色、排除条件和失败处理。比如训练出现非有限损失时，应直接将该次配置记为失败，而不是偷偷缩小学习率后继续沿用原配置名称。比如某次计时因其他进程抢占而异常，应根据预先规定的环境检查规则处理，而不是只删除表现不利的一次。

也需要区分计划的消融和看到错误后提出的解释。前者可以作为预定比较，后者更适合作为探索性假设。二者都可能有研究价值，但证据等级不同。透明记录并不会削弱论文或项目，反而让后续读者知道哪些结果值得优先复现，哪些问题仍然开放。

<a id="dlp1-detail-31"></a>

## 9. 从平均指标走向不确定性

<a id="dlp1-detail-32"></a>

### 9.1 为什么样本数必须与分数一起出现

准确率是正确样本数除以评价样本数。三百六十张测试图像中，一张图对应约零点二八个百分点。若两个模型正确数只差一张，直接写成百分之九十五点五六与百分之九十五点八三，容易让小数精度遮住证据的离散性。正确的报告同时给出计数、分母以及两者是否在同一批图像上比较。

在独立同分布的伯努利近似下，准确率估计的标准误约为 $`\sqrt{\frac{\hat p(1-\hat p)}{n}}`$。这个公式来自样本均值方差等于单个变量方差除以样本数。它假设每张图像可以近似作为独立观测，不能无条件应用于同一来源的高度相关图片。对小样本或接近边界的比例，简单正态区间还可能超出零到一，应考虑更稳健的区间方法。

不确定性至少包含测试抽样、训练随机性、数据划分和任务分布变化几个层次。对固定模型的测试样本重采样，只探索当前模型在类似图像抽样下的指标波动，不包括重新训练后的变化。多个训练种子也不会自动覆盖新书写者分布变化。统计方法必须与它想量化的随机机制对应。

<a id="dlp1-detail-33"></a>

### 9.2 类别切片与多重探索

若总准确率看起来不错，可以按类别观察召回率和混淆方向。但十个类别、多个置信度区间、不同灰度与笔画密度切片，会产生许多比较机会。在大量探索中找到一个特别差或特别好的切片并不意外。应该报告切片样本量，避免只展示最显著的几个，并将新的切片假设留给后续独立数据验证。

切片分析还可能产生条件选择偏差。比如先挑出模型错误的图，再比较其中两种笔迹风格的比例，得到的是错误条件下的分布，不是所有这种笔迹的错误率。要研究“某种笔迹是否更难”，需要分母包含这种笔迹的全部样本，并采用独立、可重复的风格定义。

## 10. 十六个进阶练习与详细解析

<a id="sec-7"></a>

<a id="dlp1-detail-35"></a>

### 10.1 练习一：全数据除以十六是否泄露

问题：训练前把全部图像统一除以十六，有人认为凡是测试数据参与过运算都属于泄露，这个判断是否准确？

解析：关键不在于是否对测试输入执行运算，而在于变换参数是否由测试信息拟合，以及测试信息是否反馈到训练或选择。固定除以十六是预定单位变换，单个输入可以独立完成，修改另一张测试图不会改变训练变换。

对全部数据估计均值则不同，它让训练坐标依赖测试输入，违反当前协议。若十六这个常数本身是看了测试分布后在多个候选中挑出的，仍需要说明它经历了选择。相同代码操作可以因参数来源不同而具有不同的信息含义。

<a id="dlp1-detail-36"></a>

### 10.2 练习二：为什么分层划分仍然不能证明新书写者泛化

问题：训练、验证、测试的每类比例非常接近，是否意味着测试集足够独立？

解析：类别比例只约束标签边际分布，不能约束潜在来源的重叠。一个书写者可以在三个集合中都出现，并保持每个集合类别比例相近。若目标是新书写者泛化，必须有可靠身份并按身份分组，或使用具有可信来源隔离的外部数据。没有身份时，应承认只能进行图像级评价。分层随机拆分是一种具体协议，不是对所有相关结构的通用解决方案，不能从类别直方图推出来源独立性。

<a id="dlp1-detail-37"></a>

### 10.3 练习三：验证集能否用于提前停止

问题：每轮查看验证交叉熵，在最优轮次恢复权重，是否已经污染验证集？

解析：验证集的预定作用就是参与选择，因此这种使用合理。需要承认最终模型依赖验证标签，最优验证分数具有选择效应。所谓污染通常是指超出声明角色的信息使用，例如把验证值当成最终完全独立的风险估计，或把测试值用于停止。采用固定预算内最佳快照和采用耐心值早停是不同算法，前者始终运行完整预算，后者训练长度也取决于验证历史。必须记录实际算法，而不能只笼统写“用了早停”。

<a id="dlp1-detail-38"></a>

### 10.4 练习四：准确率相同为什么交叉熵可以不同

问题：两个模型对十张图都预测正确，其中一个模型正确类别概率都是零点六，另一个都是零点九，比较其指标。

解析：两个模型准确率都为一，但平均交叉熵分别为负对数零点六和负对数零点九，后者更小。准确率只记录最大值位置，忽略分布细节。不过这个例子只包含正确预测，不能据此鼓励无限提高所有预测置信度。若有一张错误预测，对真实类别给出极小概率会产生很大惩罚。交叉熵奖励与真实条件概率相匹配的分布，而不是单纯奖励尖锐分布。实际解释应结合正确与错误样本，而非只看其中一类。

<a id="dlp1-detail-39"></a>

### 10.5 练习五：最终测试后能否修改归一化

问题：测试结果较差，发现按训练均值标准化可能更好，直接修改后重新报告同一个测试集的最佳结果是否合理？

解析：可以把这个过程作为探索，但不能继续把新结果称为未参与开发的最终测试。首次测试已经提供关于方法选择的信息，即使只改变一个常数，研究流程也已利用了测试反馈。应保留原结果，说明修改动机，并在新的独立评价上确认。若没有新数据，可以报告两种方法在现有数据上的探索比较，同时降低结论强度。问题不在于修改本身，而在于是否如实描述证据产生的历史。

<a id="dlp1-detail-40"></a>

### 10.6 练习六：相同种子为什么不等于相同实验

问题：两个人使用相同随机种子，却得到不同划分和模型结果，至少列出四个应检查的条件。

解析：先检查数据版本、样本顺序和划分调用顺序，种子只控制随机序列，不控制实体排序。再检查库版本、随机生成器类型以及是否有别处消耗随机数。模型初始化前若多创建了一个随机层，后续权重就可能不同。还应检查线程、算子实现和确定性设置，不同浮点求和顺序可能放大训练差异。可重复记录应包含环境和完整流程，而不是只写一个整数。即使逐位结果不同，也可以进一步判断统计结论是否仍然一致。

<a id="dlp1-detail-41"></a>

### 10.7 练习七：固定三十轮是否意味着计算公平

问题：模型甲批量三十二，模型乙批量一百二十八，均训练三十轮，是否可以说训练预算完全相同？

解析：两者看到的样本总次数大致相同，但每轮更新次数不同，甲约是乙的四倍。每次更新的计算量、优化噪声和硬件利用率也不同。因此“相同轮次”是一个明确但有限的预算定义，不能替代相同更新或相同时间。若研究学习算法的样本效率，按已见样本数比较可能合适；若研究部署前的资源成本，墙钟时间更有意义。应根据问题选择预算，并同时记录足以让读者理解差异的资源指标。

<a id="dlp1-detail-42"></a>

### 10.8 练习八：小样本无法过拟合时如何排查

问题：取十六张训练图，训练损失始终接近自然对数十，应按什么顺序检查？

解析：先检查输入和标签是否对齐、类别编码是否有效以及目标是否误写为全零。随后检查模型输出维度、损失参数与是否重复 softmax。再检查反向传播是否执行、梯度是否存在、优化器是否持有当前模型参数，以及步骤前后参数是否变化。最后尝试调整学习率或容量，并检查重复输入是否对应冲突标签。这个顺序先排查机制错误，再讨论表达能力，避免用更大的模型掩盖错误的数据管道。通过后仍需回到正常划分验证泛化。

<a id="dlp1-detail-43"></a>

### 10.9 练习九：为什么只保存最佳轮次编号不够

问题：日志中记录第二十八轮最好，但只保留第三十轮权重，是否能够报告第二十八轮测试结果？

解析：不能。轮次编号只是一个描述，无法替代当时的实际参数和缓冲状态。除非能够从完全一致的检查点与随机状态重放并验证，否则重新训练至第二十八轮也不保证得到同一个模型。最佳快照应在选择发生时独立复制，并在测试前恢复。若只剩最后权重，应报告它的结果以及最佳状态已经丢失的限制，不能把日志中的验证最优值与另一个模型的测试值拼成一行，制造一个从未实际存在过的实验对象。

<a id="dlp1-detail-44"></a>

### 10.10 练习十：数据增强是否总是保持标签

问题：把数字图像随机左右翻转用于训练，是否可以仅因它是常见图像增强而直接采用？

解析：增强需要任务语义支持。自然图片分类中某些翻转可能保留物体类别，但数字的方向和笔画结构可能改变可读性，甚至映射成不同符号。即使标签编号没有变化，也不代表变换后的图像仍属于原类别分布。应先可视化变换并由任务知识验证，再控制变换强度和边界填充。对八乘八小图，一像素移动已占明显比例。当前固定实验不使用增强，就是为了先减少变量；后续研究增强时需要独立比较和清楚的语义假设。

<a id="dlp1-detail-45"></a>

### 10.11 练习十一：类别均衡为什么不保证单类估计可靠

问题：每类在测试集约三十六张，能否据此对某类召回率给出很强保证？

解析：均衡只保证每类不是完全缺席，三十多张仍然是较小分母。三十六张中多错一张，召回率就变化约二点七八个百分点。若图像之间相关，有效信息还可能更少。应同时报告正确数和总数，给出适合该抽样假设的不确定性，并避免把某次单类排名视为稳定难度顺序。若某类在独立来源中持续较差，才有更强依据研究其机制。样本均衡解决的是覆盖问题，不自动解决精度问题。

<a id="dlp1-detail-46"></a>

### 10.12 练习十二：训练前能否查看所有测试图片

问题：只看图像不看标签，用它们决定裁切和增强方式，是否仍保持测试独立？

解析：对当前归纳协议而言，这会让预处理设计依赖测试输入分布。即使没有训练梯度，也已经通过研究者的选择向最终系统传递信息。若任务本来允许使用无标签目标域数据，可以定义为转导或域适配协议，但必须提前说明并为该协议设计评价。不能在使用之后仍声称完全未见目标数据。技术上能否读取和研究上是否属于允许信息，是两个不同层次，应由协议明确连接。

<a id="dlp1-detail-47"></a>

### 10.13 练习十三：如何区分错误分析与重新选择

问题：第三章查看测试错误后发现模型对细笔画较差，接下来可以做什么？

解析：可以描述现象、检查是否存在输入异常、提出细笔画相关假设，并设计新的探索实验。不能在同一测试集上反复尝试多个增强后，只报告最好的版本为最终独立成绩。若后续仅用于教学机制演示，应该明确它是基于已知错误提出的探索。确认性比较则需要新的独立测试安排。错误分析的价值在于产生可验证的问题，而不是让测试集成为无限次调参的反馈器。

<a id="dlp1-detail-48"></a>

### 10.14 练习十四：图片内容哈希解决了什么

问题：保存每张图片的内容哈希，是否足以证明训练和测试没有相关样本？

解析：哈希可以有效检测完全相同的规范化内容，但无法识别同一书写者的不同数字、同一原图的轻微压缩版本或不同裁切。哈希相同通常提示重复或内容一致，哈希不同并不证明统计独立。还需要来源标识、采集过程和近似重复审查。计算哈希前的编码方式也要固定，例如浮点字节序或整数像素格式，否则相同语义图片可能产生不同字节。身份记录、内容审查与独立采样设计应共同构成数据证据。

<a id="dlp1-detail-49"></a>

### 10.15 练习十五：如何处理失败的训练配置

问题：某个学习率导致非有限损失，是否应该从报告中删除这次运行？

解析：若研究问题包含该配置，就应记录失败类型、发生轮次与已消耗资源。删除失败会让搜索成功率和预算看起来比实际更好。可以按照预定规则中止并保存最小诊断，但不能把失败运行悄悄换成修改后的配置再沿用原名称。报告表可以单独列出非有限、超时或不收敛，而不是伪造一个可比的最终指标。失败也是关于方法适用范围的信息，尤其在比较优化稳定性时，它本来就是研究对象之一。

<a id="sec-7-1"></a>

<a id="dlp1-detail-50"></a>

### 10.16 练习十六：把有限项目写成诚实结论

问题：假设测试准确率约百分之九十六，如何写一句既有信息又不过度外推的结论？

解析：应包含数据、划分单位、配置范围和评价指标。例如可以说，在内置八乘八数字图像的固定分层图像级留出中，这个经过验证交叉熵选择的具体模型取得相应正确数与测试分数。随后说明未验证新书写者、手机照片或连续字符。不要把“手写数字识别有效”扩展为“适用于所有真实场景”。精确边界不会让结论变弱，而是让读者知道哪些结果可以复用，哪些迁移还需要新的证据。

<a id="dlp1-detail-51"></a>

## 11. 一份可以真正执行的研究计划

<a id="dlp1-detail-52"></a>

### 11.1 按信息依赖安排工作顺序

先确认数据接口和输入契约，再固定实体索引；随后仅使用训练数据完成张量与梯度检查。接着冻结模型、优化器、预算和选择指标，在验证集上执行预定选择。恢复实际保存的最佳状态后，才进行最终测试前向。最后基于冻结预测完成混淆矩阵、错误样本和比较报告，避免为了多计算一个指标而重新选择模型。

这套顺序对应一个有向依赖图：任务定义影响数据协议，数据协议影响训练与选择，选择产生唯一评价对象，评价对象产生冻结预测，冻结预测支持报告。若从测试错误反向连回网络设计，就已经开启下一轮研究。依赖图并不禁止反馈，而是要求把反馈发生的位置标记出来，避免把两轮研究混写成一次预先计划的验证。

<a id="dlp1-detail-53"></a>

### 11.2 可以继续深入的三个问题

第一个问题是来源泛化。若获得书写者身份，应研究图像级与书写者级拆分的差异，并检查性能差距来自书写风格、类别覆盖还是训练数量变化。为了隔离机制，可以在尽量匹配图像数量与类别分布的前提下比较两种拆分，仍需承认来源与样本结构可能无法完全独立控制。

第二个问题是概率质量。相近准确率的模型可能有不同交叉熵、校准和拒识表现。研究应在验证阶段确定温度或拒识阈值，在独立测试上同时报告覆盖率和条件错误率。只对保留下来的高置信样本报告高准确率而省略拒绝比例，会让结果失去完整含义。

第三个问题是资源与稳健性的关系。可以对固定训练预算研究网络宽度、池化和轻微位移，但需同时控制选择次数和数据角色。每一种扩展都应从可检验假设出发，明确改变了哪一个变量、预期改变哪一种误差、什么结果会推翻解释。这样一来，学习资料才不只是一份能够运行的代码，还能成为继续提出新问题的方法。


<a id="dlp1-detail-54"></a>

### 11.3 在开始训练前写下失败标准

成功标准之外还需要失败标准。若任何划分索引相交，实验应在训练前停止；若标签不再是零到九的整数，应先修复数据契约；若发现预处理使用了全数据拟合统计量，应重做受影响的训练，而不是只在报告中补一句说明。若验证选择记录与恢复后的损失不一致，应视为快照链条尚未闭合，暂时不进行最终测试。这些标准使质量检查真正影响流程，而不只是训练结束后的装饰性清单。

失败标准也不能写得过于武断。例如训练损失没有严格单调下降不一定是错误，随机小批量更新和数据打乱都可以造成正常波动。单个类别准确率低于预期也不意味着数据一定坏了。应区分结构性断言和统计性期望：形状、有限性、索引互斥和状态一致性可以作确定检查；性能目标则应结合样本量和不确定性解释。把所有日志波动都改成断言，只会促使人不断调节断言以适应结果。

最后，在正式运行前写下一个能够被否定的预测，例如卷积配置可能降低交叉熵，但不保证准确率一定提高。若实际出现相反结果，应检查实现证据和实验边界，而不是先改写目标。一个能够保留反例、承认不确定性并提出后续验证方案的项目，比一份只展示成功曲线的项目更适合进阶学习。


在开始正式训练前，还应由另一位读者或隔一段时间的自己复述协议：哪些量可从训练拟合、哪些决定允许看验证、最终哪一个具体状态接受测试。如果无法用几句话说清，往往意味着代码中存在尚未显式记录的选择。把这些选择写出来，本身就是一次有效的逻辑检验。
