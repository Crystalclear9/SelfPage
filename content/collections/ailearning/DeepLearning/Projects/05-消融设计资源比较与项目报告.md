## 1. 先写出比较所要估计的量

“方法更好”不是完整研究问题。可以问在固定训练曝光下哪个流程的预期错误更低，也可以问达到某质量门槛的总成本，或给定内存与延迟限制下哪个候选可用。每个问题包含一个总体、一个完整训练与选择规则，以及一个质量或决策函数。若这些对象没有固定，实验很容易在看到结果后切换标准，永远找到一个看起来有利的角度。

例如固定图像划分、验证选择与训练预算，比较 CNN 与线性分类器，是两个完整流程在该协议下的结果。它不自动隔离“卷积本身”的因果收益，因为模型容量、优化、输入参数化和搜索机会也可能不同。研究者可以承认这是方案比较；若要归因结构机制，就进一步设计有针对性的对照。描述范围准确，比把所有实验都称作单因素消融更可靠。

<a id="sec-1-1"></a>
<a id="dl-project-5-detail-2"></a>
### 1.1 固定预算与固定质量为什么可能反转排名

假设候选甲半小时达到零点八八，一小时零点九零；乙半小时零点八六，两小时零点九三。固定半小时可能甲优，充分训练乙可能更高，达到零点九零的成本又是另一个问题。这些数据若没有共同测量点，不能靠想象补出中间曲线。报告应给实际观测、未达到门槛的删失状态和预算，不把所有运行最后分数放一起当固定成本比较。

质量门槛来自预设用途或开发规则，不应看到各候选曲线后临时选最有利高度。测到某检查点首次越过门槛，也不表示真实连续时间精确在那一刻达到；验证频率会影响可观察时间。若只是根据单次随机曲线判断效率，还应考虑重复波动与选择不确定性。成本问题有自己的测量误差，不能因为单位是秒就当作无噪声真值。

<a id="deep-dive-1"></a>
<a id="dl-project-5-detail-3"></a>
### 1.2 比较完整流程与比较固定参数要分开

固定已训练模型，删除某层或遮挡输入，估计的是当前函数对该改动的敏感性。删除后从头训练并重新选择，估计的是替代学习流程的表现。两者可以很不一样：某冗余模块在当前参数中承担重要路径，但其他结构重训后能补偿；某模块当前看似没用，也可能影响优化早期或其他数据条件。不能用一种实验直接回答另一种对象。

同样，比较一个候选默认参数和另一个大量调优版本，实际包含了选择资源差异。默认值可代表某种使用情形，但结论应叫“在该配置与选择协议下”，不应宣称算法本质优劣。先列哪些量固定、哪些允许各自优化、搜索机会怎样分配，再解释结果。不存在一份同时让所有维度完全相同的神奇公平表，只有与具体问题一致的控制。

<a id="dl-project-5-detail-4"></a>
### 1.3 把假设变成可以失败的预测

如果假设增强通过保持笔画标签来改善鲁棒性，就应预期合法变换质量改善，而破坏标签的变换不一定有益；若声称更宽网络解决容量不足，先确认小模型训练风险存在合理差距，而不是标签或优化有错误。预测应在实验前写出，并允许结果反驳它。只观察分数提高后再补一段机制故事，不足以证明原因。

反驳假设也不等于实验没有价值。发现 CNN 未胜线性基线、增强损害某类或预算优势只在部分形状出现，都能帮助修正边界。关键是排除实现错误和协议混淆，再解释已经观测到的事实。教材中的报告应培养这种证据态度，不把所有复杂模块都写成必然提升，也不为每个波动强行提供唯一原因。

## 2. 单因素对照与交互：两张表回答不同问题

在基线里加入一个模块，差值描述该上下文中的增量。如果另一个模块存在时收益不同，就是交互。只做基线、完整方案与逐个删除，能看见一些条件差异，却未必唯一分解全部收益。对两个二元因素，可以完整跑四格：都无、仅甲、仅乙、两者都有，直接计算主效应和差中差。更多因素时需要根据假设选择设计，不能无限增加组合而隐藏搜索成本。

<a id="dl-project-5-detail-6"></a>
### 2.1 两因素饱和模型的手算

令质量为 $q(a,b)=\beta_0+\beta_Aa+\beta_Bb+\beta_{AB}ab$，其中因素取零或一。四格值唯一确定四个系数：基线为都无，单因素差给对应主项，交互等于两者都有减仅甲减仅乙再加基线。这个模型是在四个条件上精确表示观测，不自动意味着任何因素连续取值都按同一公式变化，也不消除训练噪声。

举例质量分别零点八零、零点八四、零点八六、零点八五。甲单独增零点零四，乙单独增零点零六，但共同只增零点零五，交互负零点零五。甲在乙存在时反而降低零点零一，不能用甲在基线中的正收益证明它在所有配置中有益。若每格是噪声估计，还需相应配对重复和区间；手算确定四格只是理解定义的起点。

<a id="dl-project-5-detail-7"></a>
### 2.2 实验一：从四格恢复交互与条件收益

以下人工表不代表图像模型的实测分数。代码用线性方程恢复四个系数，核对两种上下文里的增量，并构造保持单因素结果却改变组合的情形，说明没有完整四格就无法识别交互。它可用于审查报告表的逻辑，而不是替代真实重复实验。

```python
import numpy as np

factors = np.array([[0, 0], [1, 0], [0, 1], [1, 1]], dtype=float)
quality = np.array([.80, .84, .86, .85])
X = np.column_stack((np.ones(4), factors, factors.prod(axis=1)))
beta = np.linalg.solve(X, quality)
assert np.allclose(beta, [.80, .04, .06, -.05])
a_without_b = quality[1]-quality[0]
a_with_b = quality[3]-quality[2]
assert a_without_b > 0 and a_with_b < 0
alternative = quality.copy(); alternative[3] = .93
beta2 = np.linalg.solve(X, alternative)
assert np.allclose(quality[:3], alternative[:3])
assert beta2[-1] != beta[-1]
print('baseline / A / B / interaction:', beta)
print('A without / with B:', a_without_b, a_with_b)
```

<a id="dl-project-5-detail-8"></a>
### 2.3 多因素设计需要考虑机会与可解释性

因素多时全组合成本指数增加，常见做法是围绕关键假设选少量预设组合，或分阶段探索后用独立确认。部分组合设计可能把某些效应混在一起，应说明无法识别的项，不能用一张稀疏表宣称已分解所有贡献。结构改动伴随参数量、步数或预训练信息变化时，也要单独列出，不把未控制项藏进模块名称。

消融表的每一行最好能指向具体配置与产物，而不只写“去掉注意力”。去掉后头维、输出宽度和优化器参数组如何处理，是否重新初始化或加载部分权重，都会影响比较。若某候选训练失败，记录失败标准与实际成本，不静默删除这行；只看成功者的平均质量会低估流程风险。失败本身是方案在规定资源下的一种结果。

<a id="dl-project-5-detail-9"></a>
## 3. 成对预测：不要把共同题目当成独立两组

两个固定分类器在同一测试样本上评价，差值可以按样本构造。令 $a_i,b_i$ 为是否正确，目标差为 $\widehat\Delta=n^{-1}\sum_i(b_i-a_i)$。方差涉及两者的协方差：共同容易或困难样本通常使它们相关。分别对两组准确率套独立误差条再相减，会丢失配对结构。保存逐样本身份与预测，才能复算谁赢在哪些样本，而不只有两个总百分比。

<a id="dl-project-5-detail-10"></a>
### 3.1 四格表与条件二项检验

将样本分为都正确、仅甲正确、仅乙正确、都错，分别记为四个计数。准确率差只由两种不一致计数之差决定。对固定分类器、独立样本和边际正确率相等的零假设，条件于总不一致数，任一方向概率为二分之一，可以用双侧二项检验。这是配对错误比较的一种精确小样本做法；依赖样本、重复选择和其他损失需要重新处理，不能机械套用。

不拒绝相等零假设，不证明两方法等价。若目标是“新方法损失不超过可接受界限”，应预设非劣界并给对应区间与决策。显著差异也不自动有实际价值，一百万人任务里很小差值可能统计上清楚，却不值得额外成本。统计检验、效果大小和业务取舍分别回答不同问题，报告应把它们连起来而非只放一个星号。

<a id="dl-project-5-detail-11"></a>
### 3.2 实验二：准确率差、配对四格和抽样区间

人工构造一百条独立示例，甲正确八十条、乙八十五条，其中共同正确七十、甲独赢十、乙独赢十五、共同错误五。先核对四格与差值，再对成对差重采样，最后进行条件二项检验。百分位区间在这里是教学的有限重复估计，不提供所有小样本和总体下的精确覆盖保证；本实验明确条件于这两个固定分类器，不包含重新训练不确定性。

```python
import numpy as np
from scipy.stats import binomtest

y = np.zeros(100, dtype=int)
a = np.r_[np.zeros(80, dtype=int), np.ones(20, dtype=int)]
b = np.r_[np.zeros(70, dtype=int), np.ones(10, dtype=int),
          np.zeros(15, dtype=int), np.ones(5, dtype=int)]
ca, cb = a == y, b == y
counts = [np.sum(ca & cb), np.sum(ca & ~cb),
          np.sum(~ca & cb), np.sum(~ca & ~cb)]
assert counts == [70, 10, 15, 5]
difference = cb.astype(float)-ca.astype(float)
assert np.isclose(difference.mean(), .05)
rng = np.random.default_rng(19)
index = rng.integers(0, len(y), size=(5000, len(y)))
means = difference[index].mean(axis=1)
interval = np.quantile(means, [.025, .975])
result = binomtest(counts[2], counts[1]+counts[2], p=.5, alternative='two-sided')
assert result.pvalue > .05
assert interval[0] <= difference.mean() <= interval[1]
print('paired cells:', counts, 'accuracy delta:', difference.mean())
print('conditional test p / percentile interval:', result.pvalue, interval)
```

<a id="dl-project-5-detail-12"></a>
### 3.3 为什么两个准确率总数还不够

如果只知道甲八十、乙八十五，无法知道它们共享多少错误。不一致样本可能很少或很多，而配对检验的条件总数正依赖这一信息。总分差相同，不代表比较不确定性相同。第 2 章 CNN 与逻辑回归差一个测试样本，首先应保存并核对逐条预测，再讨论配对证据，不能从两个百分比凭空推导显著性。

对现实数据还需确定独立单位。相同书写者、病人、视频或设备的多条样本可能相关；重复图像和增强版本尤其不能当新独立题目。当前 digits 项目仅有图像级协议，没有完整作者分组证据，所以推断范围要随之限制。如果目标总体是新作者，应获取相应合法身份并重新设计评价，而不是把更多图像行数当作作者独立的替代。

<a id="dl-project-5-detail-13"></a>
## 4. 随机种子、数据来源和测试抽样是不同层级

固定训练数据与协议，改变初始化、批次和增强随机流，可以观察优化过程波动。固定已训练模型，改变测试样本，可以观察评价抽样变化。重新抽训练数据并完整拟合，则研究训练数据变化下的学习流程。三者都叫“不确定性”却不相同，不能用几个种子标准差代表所有新数据风险，也不能对一个固定模型重采样测试就声称包含重新训练波动。

<a id="dl-project-5-detail-14"></a>
### 4.1 全方差分解帮助明确条件

设结果为随机变量 $Z$，训练随机条件记为 $U$，则 $\operatorname{Var}(Z)=\mathbb E[\operatorname{Var}(Z\mid U)]+\operatorname{Var}(\mathbb E[Z\mid U])$。第一项是给定训练条件后的剩余波动，第二项是条件均值随训练变化的波动。若还包含训练集、来源或环境，可以继续分层定义。公式并不告诉你用什么重采样自动估出全部项，但能阻止把一个有条件实验的误差条误标成总体不确定性。

仅三五个种子对尾部和方差估计都很有限。应报告全部预设运行及差值，避免只报最好种子，必要时承认重复不足。相同整数种子也不保证两结构共享相同随机扰动，因为参数数目和随机调用顺序不同；真正的配对应以共同数据划分、开发角色与有意义的随机条件来设计。不要把标签都写同一个 seed 就当严格控制了一切。

<a id="dl-project-5-detail-15"></a>
### 4.2 重采样单位由数据生成和目标决定

如果每个来源有多条观察，按来源等权与按请求等权是不同总体。来源大小不等时，不能先对各来源取平均再称总体请求平均；请求目标应在每次重采样后用总分子除总请求数。与此同时，抽来源时需将其内部相关观察一起保留，不能先打散成独立行。统计权重与依赖单位是两件同时需要说明的事。

若模型在多个共同测试来源上运行多个训练种子，结果形成交叉表，不是种子乘来源那么多独立模型。每个种子影响该行所有来源，每个来源影响该列全部模型。重采样应考虑研究对象的这两个轴，或选择明确条件于其中一个轴的估计。将所有单元格展平，通常会丢掉共享结构；误差条看起来很窄，不代表证据突然更强。

<a id="dl-project-5-detail-16"></a>
### 4.3 实验三：保留训练与来源两个轴

下面人工构造四个训练条件、六个来源、每来源三条记录的损失差表，含明显的训练与来源共享效应。比较两种描述性重采样：按训练条件和完整来源两轴抽取，或把全部单元格假装独立抽取。例子只展示结构被保留或破坏的差别，不能凭四个种子和六组就给所有总体精确覆盖保证。真实项目若要重新训练不确定性，还需完整训练数据与拟合层的设计。

```python
import numpy as np

rng = np.random.default_rng(32)
seed_effect = np.array([-.04, -.02, .01, .03])
source_effect = np.array([-.03, -.02, 0., .01, .02, .04])
delta = (.01 + seed_effect[:, None, None] + source_effect[None, :, None]
         + rng.normal(0, .002, size=(4, 6, 3)))
assert delta.shape == (4, 6, 3)
structured = []
for _ in range(4000):
    seeds = rng.integers(0, 4, size=4)
    sources = rng.integers(0, 6, size=6)
    structured.append(delta[np.ix_(seeds, sources, np.arange(3))].mean())
flat = delta.ravel()
naive = flat[rng.integers(0, len(flat), size=(4000, len(flat)))].mean(axis=1)
ci_structured = np.quantile(structured, [.025, .975])
ci_naive = np.quantile(naive, [.025, .975])
assert ci_structured[1]-ci_structured[0] > ci_naive[1]-ci_naive[0]
assert np.isclose(delta.mean(), flat.mean())
print('point difference:', delta.mean())
print('two-axis / flattened descriptive intervals:', ci_structured, ci_naive)
```

<a id="dl-project-5-detail-17"></a>
### 4.4 差值方向和实际意义也需预先固定

对准确率可设新减旧，正值表示更好；对损失可设旧减新，也能保持正值更好。最重要是每张表和每段代码统一，避免图上正向、检验里反向。区间跨零时应报告不确定，而非把均值正就写“稳定提升”；区间很窄但差极小时，还需与实际门槛比较。统计清晰与实践值得采用是两个步骤。

若主指标与最坏群体指标冲突，应回到预设用途和约束。例如总体增零点二个百分点却严重损害小目标或少数类，可能不满足应用要求。不要只在看到结果后挑一个最有利群体，也不要用总体好看掩盖预先关注的安全或质量条件。各分组需报告支持数与定义，样本很少时标明证据不足，而不是制造过度精确的排名。

## 5. 资源公平是一组明确约束

相同轮数、更新、样本曝光、浮点操作、墙钟时间、峰值内存和部署延迟各自控制不同东西。模型改变后，一般不可能同时保持全部相同。研究应选择与问题对应的主要约束，并列出其他资源差异。固定时间比较时硬件与实现成熟度会影响结果；固定计算比较又未必反映真实等待。承认这些条件，比使用一个没有定义的“同预算”更可审查。

<a id="dl-project-5-detail-19"></a>
### 5.1 参数、优化状态、激活与推理缓存分别记账

参数量是结构大小，不等于训练内存，也不直接决定速度。训练还保存梯度、优化器矩和反向激活，推理可能有缓存与工作区；它们的同时存活情况影响峰值。不同精度与布局也改变字节和内核。比较应给实际测量模式及可复算结构账本，而不从权重文件大小直接预测训练峰值或服务吞吐。

本项目 CNN 结构为两层同尺寸卷积、平均池化与线性头。第一卷积八十参数，第二一千一百六十八，分类头二千五百七十，共三千八百一十八。池化后十六通道四乘四，所以头输入二百五十六。这个手算有助于核对实现，却不证明它一定比线性分类器快；后者虽然输入形式不同，也有自己的求解器与训练成本。时间结论需要对应运行测量，不能用层数或参数数替代。

<a id="sec-2-1"></a>
<a id="dl-project-5-detail-20"></a>
### 5.2 选择成本和失败运行属于流程成本

一个候选单次训练快，若为了找到可用参数需要尝试更多组合，研发成本可能更高。报告应区分最终模型一次拟合成本、全部搜索成本和未来推理成本；三者分别适合不同用途。失败运行也消耗资源，若它们是规定候选的一部分，就不能无声剔除。可以按预算上限或失败政策记账，但要将规则写清，不能只累加成功者。

预训练或外部数据提供额外信息与先前计算。用户可能合理地把已有预训练权重当可用资源，比较时仍需说明其来源与机会，而不将其和从零模型说成相同数据条件。迁移学习是有价值的完整方案，但其优势不能全部归因下游结构。资源比较既包含机器工作，也包含信息与选择机会，遗漏任何一类都可能让结论答非所问。

<a id="dl-project-5-detail-21"></a>
### 5.3 实验四：生命周期成本能反转选择

以下时间完全由人工给定，不是 CPU 或 GPU 基准。方案甲训练一百秒、每请求四毫秒；乙训练一百六十秒、每请求一毫秒，质量假定相同。少量请求时甲总成本低，大量请求时乙低，交点为两万请求。再加入内存硬约束，可以排除原本时间占优的候选。这个算例说明采用决策需要目标负载，不能只看一次训练或单请求速度。

```python
import numpy as np

train_a, infer_a = 100., .004
train_b, infer_b = 160., .001
crossing = (train_b-train_a)/(infer_a-infer_b)
assert np.isclose(crossing, 20000.)
def total(train, infer, requests):
    return train+infer*requests
assert total(train_a, infer_a, 1000) < total(train_b, infer_b, 1000)
assert total(train_a, infer_a, 100000) > total(train_b, infer_b, 100000)
memory_gib = {'A': 1., 'B': 2.}
feasible = [name for name, memory in memory_gib.items() if memory <= 1.5]
assert feasible == ['A']
search_a = 4*train_a
search_b = 10*train_b
assert search_b > search_a
print('request crossing:', crossing, 'feasible under 1.5 GiB:', feasible)
print('1000-request total seconds A/B:', total(train_a, infer_a, 1000),
      total(train_b, infer_b, 1000))
print('100000-request total seconds A/B:', total(train_a, infer_a, 100000),
      total(train_b, infer_b, 100000))
```

<a id="dl-project-5-detail-22"></a>
### 5.4 测量时刻与功能必须一致

推理入口是否含解析、预处理、数据传输、首轮初始化和后处理，会改变延迟含义；批量吞吐不等于单请求等待。若一个候选返回概率和完整特征，另一个只返回类别，功能不同也会影响成本。固定需要的输出，分别记录冷启动、稳态与实际负载，才能判断加速来自执行改善还是工作量删减。

GPU 操作可能异步，真实测量需要合适同步或设备事件；单个小批受启动开销影响，长序列和大批又可能受内存带宽限制。本章没有相应硬件性能实验，因此只给测量设计和人工资源算术。将公式、模拟和实测分开，是报告可信性的基本要求；不能因为理论算量较少，就填入未经测得的加速比例。

## 6. 报告先给结论，再给使结论成立的证据

一份结果表应先回答预设问题，再说明协议和局限。每行包含方法与版本、划分、选择规则、主要指标及支持数、重复方式、训练与推理资源；每个图说明横轴、归约、误差条和数据角色。文本中的结论应能指向具体行与产物，而不是从多轮实验里拼接各自最好部分。没有任何实际模型同时实现的数字组合，不该作为一个方案报告。

<a id="dl-project-5-detail-24"></a>
### 6.1 本项目真实结果应怎样写

第 2 章固定图像级划分为训练一千零七十七、验证三百六十、测试三百六十。CNN 按最小验证交叉熵选择第二十八轮，验证交叉熵约零点零八五五，测试交叉熵约零点一三零二，正确三百四十四条；固定设置的逻辑回归测试交叉熵约零点一九三二，正确三百四十五条。CNN 在概率损失上较低，准确率则少一条。两个指标排序不同，应该一起解释，不能只挑支持深度模型的那个。

第三十轮最后状态不是最佳状态，其验证结果更差，说明“最终训练结束”与“最终选择用于报告”不同。前一章的恢复演练又是另一个人工小网络，只验证工程状态，不应把它的损失或严格相等结论并入 CNN 性能表。把数据、模型和证据对象明确写出，可以防止读者将不同实验误认为同一流程的重复验证。

<a id="dl-project-5-detail-25"></a>
### 6.2 目前证据没有支持哪些更强结论

这是一份固定划分和规定随机条件的教学结果，没有预设多个独立训练种子，也没有完整作者隔离。不能称 CNN 稳定优于线性基线，更不能由一个测试样本差推断算法本质优劣。两模型没有保留本次完整逐条配对表用于本章统计，因此这里不从边际总数捏造不一致计数；配对检验通过单独人工表演示。缺少证据时明确不确定，比填一个貌似精确的概率更诚实。

图像样本尺寸小、类别固定，也不代表真实拍照、背景变化、设备域和新作者场景。若要扩展，需要重新定义输入与标签、获得相关来源信息并建立独立评价。工程完整、代码可跑和性能适用范围是不同轴；一个项目能可靠恢复和交付，不会自动扩大统计外推边界。研究报告应让读者看见这些限制怎样转成下一轮具体实验。

<a id="dl-project-5-detail-26"></a>
## 7. 多重比较、反复查看和确认性证据

研究通常不止比较一个候选，还会试多个增强、宽度、优化器和阈值。若每项都用相同显著性水平独立宣称发现，至少一次假阳性的机会随尝试增加。即使各检验并不独立，联合上界也说明家族错误率不超过各项错误率之和，因此可以通过预设分配控制某类错误。这个结论要求单项概率本身有效，不能替泄漏、错单位或事后选指标提供修复。

<a id="dl-project-5-detail-27"></a>
### 7.1 探索与确认允许采用不同角色

探索阶段可以广泛看图、定位问题、提出新假设，但应承认这些发现受到数据驱动选择。确认阶段用冻结的主要问题、指标、候选和规则，在合适独立数据上检验。二者都重要，不需要假装所有灵感在最开始已知；关键是不要把探索后的最有利结果当未经选择的确认。记录何时看过哪些反馈，是区分角色的可操作方法。

反复查看同一验证集选择检查点本身就是选择，若只用于模型开发可以合法进行，但最终独立报告要评价完整流程。看到测试后再加候选、换种子或改评分，原测试就成为开发信息。增加一层误差条或多重比较校正，不能让已经参与决策的数据自动恢复独立。校正解决的是明确定义检验家族的一类错误，不是所有研究自由度和分布变化。

<a id="dl-project-5-detail-28"></a>
### 7.2 条件置换或符号翻转需要自己的假设

对成对差值，有时可在零假设下翻转各独立组的符号，构造统计量参考分布。但“均值相等”本身未必保证符号可交换；可能需要随机分配的成对设计、相应锐零假设，或独立组差值对零对称等条件。不同来源内多条记录一起变化时，翻转也应以合法独立组为单位，而不能把每行都当独立自由选择。

有六个合法独立组就只有六十四种符号组合，完整枚举可以避免蒙特卡洛误差，却不会增加组数或弥补假设。对有限组，概率分辨率粗是证据限制，不应复制每组行数来制造更小概率。固定模型损失差的分布若不满足交换性，应换用合适方法或明确描述性分析，不能因为枚举看起来精确就称推断无条件有效。

<a id="dl-project-5-detail-29"></a>
### 7.3 实验五：枚举参考分布与分步多重校正

下面第一部分用六个人工组均值差枚举符号，不把它当图像项目的显著性。第二部分实现三个事先给定有效概率的 Holm 分步拒绝规则，用手算对照阈值。两段放在同一机制实验是为了区分“单项检验如何形成”与“多个主张如何控制”；真实使用必须分别满足设计与概率有效性的条件，不能仅复制代码。

```python
import itertools
import numpy as np

d = np.array([.01, .02, .015, -.005, .03, .01])
signs = np.array(list(itertools.product((-1., 1.), repeat=len(d))))
observed = abs(d.mean())
null = abs(signs@d/len(d))
p = np.mean(null >= observed-1e-14)
assert len(null) == 64 and 0 < p <= 1
assert np.isclose(p*64, round(p*64))

values = np.array([.01, .04, .20])
alpha = .05
order = np.argsort(values)
rejected = np.zeros(len(values), dtype=bool)
for rank, index in enumerate(order):
    if values[index] <= alpha/(len(values)-rank):
        rejected[index] = True
    else:
        break
assert rejected.tolist() == [True, False, False]
print('six-group sign reference p:', p)
print('Holm decisions on artificial valid p values:', rejected)
```

<a id="dl-project-5-detail-30"></a>
### 7.4 没有发现差异与证明可互换是两件事

样本不足、噪声较大或效果很小都可能导致不拒绝。若应用需要保证新模型准确率损失不超过某个容忍值，应在看结果前定义该界，并用适当单侧区间或非劣设计评价。若要双向等价，还需两边界相应条件。不能把普通零差异检验概率大于阈值翻译成“二者一样”，那是把证据不足当成证据支持。

反过来，检出差异后仍要说明效果单位。百分之零点二在三百六十条测试上不足一个整数样本，报告可能只是四舍五入或不同平均口径；在更大总体也要看成本和错误严重度。准确率、宏平均和期望业务损失不同，最好把原始计数与具体失效一起呈现。统计语言只有与任务意义相连，才不会变成一个遮住实际问题的符号。

<a id="sec-4"></a>
<a id="dl-project-5-detail-31"></a>
## 8. 从性能观察到机制解释，还缺哪些对照

如果加入增强后总体提高，可能是增加有效数据变化、改变优化难度或正则，而不一定是研究者描述的那个不变性被学会。若网络变宽同时训练更久，容量和预算都改变。机制解释需要竞争假设和能区分它们的实验，而不是在每个正结果后补一句熟悉理论。报告可以先给观察，再将原因作为待检验解释，避免把推测写成已证明事实。

<a id="dl-project-5-detail-32"></a>
### 8.1 一次控制变量不能解决所有归因

保持网络与优化设置，单独加入增强，可以估计该完整增强政策在当前流程中的影响；它仍包含增强分布、强度、随机频率和标签规则。若想解释某种几何变换，应进一步改变其合法性与强度，检查对应错误和分组。不同图像任务对旋转、裁剪与颜色变换的标签条件不同，不能把某个增强名字当普遍保真操作。

若候选使用额外标注、教师输出或更大预训练语料，信息机会也变了。可以比较完整方案，但机制分析要承认额外信息。删除教师后下降既可能来自内容，也可能来自训练目标与优化尺度；需要有针对性的对照。清楚陈述剩余解释比用“消融已证明”过早结束更有研究价值，也更能引出下一轮问题。

<a id="dl-project-5-detail-33"></a>
### 8.2 代表性错例与总体失效率的连接

少数可视化帮助理解具体失败，但不能估计它们在总体中占多少。应从冻结预测中按预设规则抽取或全面分类，报告支持数、交叉错误和来源。手选最能支持某故事的样本属于探索，若要确认机制，需要新样本和对应干预。错误类型的标注也可能有主观差异，必要时制定规范并检查一致性，而不把所有人工判断当无噪声真值。

当一个错误可以归入多类，报告应说明是否多标签、互斥优先级或主因选择，否则分组总数可能误导。把边界样本全部删掉会改变覆盖与任务难度，应按规则记录。若标注本身错了，可以修数据版本并重新定义评价，但不能悄悄修掉模型最难样本后沿用原测试身份。数据修订是有价值的工作，也是一项需要追踪的协议变化。

<a id="dl-project-5-detail-34"></a>
### 8.3 反事实替换应保持问题可判定

遮挡某笔画或替换背景时，应检查标签语义是否仍成立。如果关键证据被删除，模型答错可能只是任务已经不可判定；若加入异常纹理，变化也可能来自分布外输入。可以从人工可控图像开始，保留确定内容标签，系统改变无关背景，再逐步验证真实场景。人工任务有清楚机制，真实任务更贴近使用，两者证据范围互补。

固定模型的干预敏感性也不等于干预政策重新训练后的质量。训练时加入合法变化可能让模型重新利用别的线索，观察到的响应会改变。应说明干预是在测试、训练还是两者同时发生，分别对应鲁棒性、适应和完整学习流程。名字都叫“反事实”并不能消除这些区别，关键还是变量、目标和可用信息的精确定义。

<a id="dl-project-5-detail-35"></a>
## 9. 报告的可追溯结构与复算入口

一个结果表的最小依赖链是：问题与总体、数据版本和划分、配置与选择、状态产物、逐条预测、评价规则和报告。若某环缺失，可能无法判断数字来自哪个模型或样本。第 4 章解决恢复与推理身份，本章继续要求指标和成本也连回同一运行。文件能加载只是链条中一环，不代表最终表已由正确状态计算。

<a id="dl-project-5-detail-36"></a>
### 9.1 结果行不能拼接不存在的模型

假如一轮验证准确率最高，另一轮交叉熵最低，第三轮延迟最低，不应把三者组合成一个“最佳方案”行，除非它们确实属于同一冻结部署配置。每个指标要关联模型与测量状态，另列所需选择规则。多次运行汇总时，也不能逐列挑每个种子最好值；应按预设统计量汇总，并保留每次完整记录。

图中平均曲线要在共同进度轴上对齐，不能把每次运行最好的片段拼接。某运行预算提前耗尽或失败，缺失后续位置不应填上最后最好值而不说明；可以报告存活数、预算与失败政策。可视化越平滑越需要原始记录支撑，否则读者难以发现选择与删失。图是证据展示，不是修饰不一致结果的工具。

<a id="dl-project-5-detail-37"></a>
### 9.2 单位检查与原始计数应并存

秒与毫秒、字节与二进制容量、百分数与百分点都应统一。准确率从百分之九十四到九十五是一个百分点，不是相对增加百分之一的同一表述；相对增幅还需除原值。小测试最好同时写正确数与总数，避免四舍五入掩盖只差一条的事实。损失与概率指标还需说明对数底、归约和标签权重。

资源表应标出测量环境、模式、精度、输入输出形状、是否含预处理和选择成本。若未实测就写“未测”或只给理论量，不借用另一机器或另一模式的数字填空。报告完整并不意味着每一格都必须有漂亮数字，而是让读者清楚知道哪些已验证，哪些是公式、模拟或后续研究。明确缺口是可靠交付的一部分。

<a id="dl-project-5-detail-38"></a>
### 9.3 一个可复算的核心结论段落

可以先写：在当前固定图像级划分和验证规则下，CNN 概率损失较低，准确率略低于逻辑回归；没有多种子与作者隔离证据，因此不宣称稳定整体优势。接着说明最佳状态、支持数和训练条件，再引用错误分析与机制实验讨论下一轮计划。这样的段落直接回答已运行问题，也让读者知道无法从中推出什么。

后续若新增预训练、高分辨率或新来源，应使用新版本协议，列出额外信息和资源。保留原回归集合观察旧场景退化，同时安排新场景独立评价，不把某一方向提升说成全面改进。教材的最终报告应该帮助学习者继续设计实验，而不是用一张分数表宣布一切结束。问题、证据和边界清楚，后续求知才有可推进的路径。

<a id="dl-project-5-detail-39"></a>
## 10. 二十四道练习与逐题详解

<a id="dl-project-5-detail-40"></a>
### 10.1 新模型分数更高能否叫结构改进

**问题：** 新流程同时加宽、加入注意力并训练两倍时间，最终更高，能归因注意力吗？

**解析：** 不能，容量、结构与预算同时变化，只支持完整方案差异。应先定义想估计哪项条件收益，再设相应基线、单因素和必要组合，保留共同数据与选择规则。若基线训练同样久追上，原观察可能主要来自预算。也不必强求所有维度同时匹配，因为那可能无法实现；重要的是选择与问题一致的主要控制，并列出剩余变化，避免把一个模块名字当唯一原因。

<a id="dl-project-5-detail-41"></a>
### 10.2 四格质量怎样手算交互

**问题：** 都无、仅甲、仅乙、共同质量依次为零点八零、零点八四、零点八六、零点八五，交互是多少？

**解析：** 共同减仅甲减仅乙加基线，得到负零点零五。甲在无乙时增零点零四，在有乙时降零点零一，表明收益依上下文改变。交互是当前四条件的差中差，不自动代表某种内部神经机制。若这些质量来自随机训练，每格和差值还需要重复与不确定性；不能把一次噪声表精确代入后就声称交互已稳定确认。先理解定义，再设计证据。

<a id="dl-project-5-detail-42"></a>
### 10.3 只有基线和两个单因素能恢复共同结果吗

**问题：** 已知前三格，能否假设共同等于两项收益相加？

**解析：** 只能把零交互作为额外假设，不能由前三格推出。实验一让共同格从零点八五改为零点九三，前三格不变而交互完全不同。若研究不能承担第四格，应说明该效应未识别，不应把相加预测写成实测。部分设计也可能把效应混合，需明确可估计对象。诚实保留未知，比用一个看似合理的线性叠加填满报告更有价值。

<a id="dl-project-5-detail-43"></a>
### 10.4 固定模型删除与重训消融为何可能相反

**问题：** 删除某头后当前预测下降，能否证明没有它的网络永远做不好？

**解析：** 不能，当前参数已经适应该路径，突然删除不允许其他参数补偿；重训替代模型则重新分配功能。前者描述固定函数依赖，后者描述完整学习流程能力。反过来，当前删头无影响也不证明它在优化早期或其他任务无用。两实验可以结合，但必须分别命名并保持评价与资源条件。结构必要性不是从一次局部干预就能无条件推出的普遍属性。

<a id="dl-project-5-detail-44"></a>
### 10.5 甲八十、乙八十五为什么还要逐样本表

**问题：** 总准确数已知，配对检验缺少什么？

**解析：** 缺少双方在哪些样本不一致，尤其仅甲正确和仅乙正确的计数。它们之差给总分差，但它们之和决定条件二项检验信息。相同边际总数可对应不同共享错误结构，因此无法只从两个百分比恢复配对证据。应保留样本身份与预测，以相同键连接标签，拒绝漏行和重复；如果现成证据没有保留，就明确缺口，不凭感觉捏造一个不一致表。

<a id="dl-project-5-detail-45"></a>
### 10.6 人工四格表的效果与检验结论是什么

**问题：** 都正确七十、仅甲十、仅乙十五、都错五，差值和条件检验怎样解释？

**解析：** 乙比甲多正确五条，占一百条的五个百分点。不一致共二十五，等边际零假设下方向概率二分之一，双侧精确检验约零点四二四，并未在常用阈值拒绝。这个结果不证明两者等价，也不表示提升概率为零点五七六。它只是规定假设下观测不一致方向极端程度的度量。人工表用于教学，不能被移植为当前 digits 两模型的统计结论。

<a id="dl-project-5-detail-46"></a>
### 10.7 差值区间跨零应该怎样写

**问题：** 人工配对差五个百分点，重采样区间负五到十五，能写稳定提升吗？

**解析：** 不宜，当前区间与数据并未清楚排除零或相反方向，应报告点估计、范围和方法条件。区间是对固定模型、当前独立样本假设下的教学估计，不包含重新训练波动。也不能把跨零直接译成“毫无价值”，因为真实效果、成本和证据不足是不同问题。若采用决策允许一定风险，应明确门槛与用途，而不是只用一个显著与否标签代替全部判断。

<a id="dl-project-5-detail-47"></a>
### 10.8 不拒绝相等为何不是等价证明

**问题：** 想证明压缩模型最多损失一个百分点，普通零差检验不显著够吗？

**解析：** 不够，需预设可接受损失界限，并用对应非劣或等价设计与区间。普通检验不拒绝可能只是样本不足，允许较大损失也可能与当前数据相容。证据是否足以支持采用，要看区间相对于实际边界的位置，而不只是概率大于某值。界限应来自任务需求并在结果前确定，不能观察到差值后把容忍界调到恰好通过，这样会改变所声称的问题。

<a id="dl-project-5-detail-48"></a>
### 10.9 三个种子标准差是否包含测试抽样

**问题：** 同一测试集上重复训练三次，误差条能代表新作者或新数据的不确定性吗？

**解析：** 它主要描述当前训练数据与测试条件下所改变随机过程的波动，不能自动涵盖新训练集、测试总体和作者来源。三次估计本身也粗。应写明条件、运行数和汇总，并根据目标另设计数据或来源层重采样。把同一测试样本复用三次并不会创造三倍独立测试观察；种子和数据是不同轴，只有明确研究对象后才能选择误差条。

<a id="dl-project-5-detail-49"></a>
### 10.10 同一个种子为何不保证两模型随机配对

**问题：** 两结构都写种子四十三，是否已经共享每个随机扰动？

**解析：** 参数数目、初始化与随机层调用顺序可能不同，随机流推进也不同，所以整数相同不等于对应掩码和批次相同。可以固定共同数据划分、为采样使用独立流，并按有意义条件构造配对；若无法逐操作对应，应如实说明。配对目的在减少无关差异，不是一个名称惯例。最终还需报告完整预设运行，不挑某个结构恰好最有利的种子代表常规表现。

<a id="dl-project-5-detail-50"></a>
### 10.11 为什么交叉表展平会过度精确

**问题：** 四种训练条件、六来源、各三记录共七十二格，能当七十二独立模型吗？

**解析：** 不能，同一训练条件影响一整行，同一来源影响一整列，多条记录还共享组内因素。展平会把共同波动当许多独立信息，常让区间过窄。实验三均值不变，结构化描述区间却宽于展平区间，就是反例。重采样应匹配目标与依赖，或明确条件于某一轴。更多表格单元不自动等于更多独立来源，方法精度取决于生成结构而非数据形状。

<a id="dl-project-5-detail-51"></a>
### 10.12 来源等权与请求等权何时不同

**问题：** 一个来源一百条，另一个两条，先各自平均再平均是否为全部请求均值？

**解析：** 一般不是，它给两个来源相同总权重；全部请求均值给第一个一百零二分之一百权重。两者可分别对应随机来源与随机请求目标，都需要清楚命名。按来源重采样时，请求目标应在每次抽取后用总损失和除总请求数，不能不加说明地平均来源均值。依赖处理与统计权重同时重要，正确选择重采样单位并不自动保证目标权重也正确。

<a id="dl-project-5-detail-52"></a>
### 10.13 六组符号枚举为何只有六十四种

**问题：** 每组差值可在零假设下独立翻正负，完整参考分布多大？

**解析：** 每组有正负两种，六组共二的六次方六十四种。完整枚举消除模拟抽样误差，却不增加真实组数。实验五参考概率零点零六二五来自该有限分布，只在相应交换或对称假设成立时有推断含义。不能把每组内部复制多行就当更多独立符号，也不能仅凭均值为零就假设符号翻转合法。

<a id="dl-project-5-detail-53"></a>
### 10.14 Holm 三步阈值怎样使用

**问题：** 有效概率零点零一、零点零四、零点二，家族水平零点零五，哪些被拒绝？

**解析：** 按从小到大，先与零点零五除三比较，第一项通过；第二项与零点零五除二比较失败，于是停止，后面不拒绝。它控制的是预先定义家族中某类错误，前提是各项检验本身有效。若数据泄漏、假设错误或在看结果后偷偷加入未记录搜索，该步骤不能万能修复。校正决策和效果大小也不同，被拒绝不表示收益足够值得额外部署成本。

<a id="dl-project-5-detail-54"></a>
### 10.15 相同参数量为何不一定同资源

**问题：** 两模型参数量匹配，能否认为训练时间和峰值内存也匹配？

**解析：** 激活尺寸、序列或图像分辨率、算子类型、优化器状态和工作区不同，执行成本可能差很多。参数量只是结构大小一维，不代表数据移动、内核效率和存活中间量。应提供对应模式的实际测量及理论账本，并说明硬件、精度和批量。若只匹配参数量，就把结论限定为这一约束下的比较，不将其升级为全部成本公平。研究问题决定哪种匹配最有意义。

<a id="dl-project-5-detail-55"></a>
### 10.16 两万请求交点怎样得到

**问题：** 训练成本甲一百秒、乙一百六十秒，每请求甲四毫秒、乙一毫秒，何时总成本相等？

**解析：** 令两条线性总成本相等，额外训练六十秒除每请求节省零点零零三秒，得到两万请求。少量请求甲更省，大量乙更省；若内存上限排除乙，时间优势仍不能使它可行。算例时间为人工参数，不能当真实硬件结果，也没包含搜索与维护。它说明生命周期负载会改变选择，真实应用需标定各项再决策，不能只凭最后模型单次推理速度排名。

<a id="dl-project-5-detail-56"></a>
### 10.17 搜索十次为什么不能只报最后一次成本

**问题：** 一个流程尝试十个候选才找到好配置，报告成本应怎样写？

**解析：** 可以分别写最终一次拟合成本和全部搜索成本，但不能只给前者却称完整研发效率。失败候选与被淘汰运行也占用资源，应按预设政策记录。若用户只关心已知配置复训，最终拟合量有意义；若关心发现该配置的代价，全部搜索更相关。两种口径都可用，必须与研究问题一致。把别人默认值和自己十次调优直接比较时，也要披露选择机会差异。

<a id="sec-9-2"></a>
<a id="dl-project-5-detail-57"></a>
### 10.18 最高分是否就是预算内最佳方案

**问题：** 更高准确率模型超内存、尾延迟也不达标，该如何下结论？

**解析：** 若这些是硬约束，它不在可行集，不能以准确率最高宣布全面优胜。先筛约束，再比较质量与资源，互有优劣时展示帕累托取舍。准确率、毫秒和字节没有未经定义即可直接平均的总分；需求若未确定，应保留多维证据供判断。最高分有研究信息，却不自动成为实际采用建议。报告将可用条件与性能上限分开，才能服务具体决策。

<a id="dl-project-5-detail-58"></a>
### 10.19 CNN 少一条正确却损失更低矛盾吗

**问题：** 本项目 CNN 正确三百四十四，逻辑回归三百四十五，但 CNN 交叉熵更低，如何理解？

**解析：** 准确率只看最高类，交叉熵还看给真实类多少概率，对高置信错误尤其敏感。模型可在更多样本上分配合理概率，却在少数近并列样本 argmax 不利，所以排序不同正常。应报告共同协议与两指标，不事后只挑支持某模型的那个。该结果仍是固定划分与配置，不证明任一算法稳定优越；缺少配对预测时，也不能从一个样本差给出精确显著性结论。

<a id="dl-project-5-detail-59"></a>
### 10.20 为什么不能把最好几轮拼成一行

**问题：** 一轮最佳准确率、另一轮最佳损失、第三轮最快，能合成“最佳模型”吗？

**解析：** 如果没有一个冻结状态同时产生这些结果，就不存在对应模型，表格不可复算。各指标应绑定状态与测量配置，主选择规则在开发前确定。可以另列不同目标选出的多个版本，但不能把它们优势拼成一个虚构方案。重复种子也应按预设统计量汇总，不逐列挑最好值。可追溯身份不是格式细节，它阻止报告无声地改变比较对象。

<a id="dl-project-5-detail-60"></a>
### 10.21 高权重或代表性错例能直接证明机制吗

**问题：** 看到几个像“笔画损坏”的错误，能认定增强降低质量就是破坏笔画导致？

**解析：** 这提供可检验假设，而非唯一原因。还可能有强度、采样、分布变化或优化因素。用开发数据构造合法与破坏语义的受控变换，报告错误支持与随机对照，再用独立确认检查。手选样例不估计总体频率；错误分类规则和标签可判定性也需审查。先给观察，再列竞争解释与下一步，能让报告推动研究，而不是在每个现象后写一个不可反驳故事。

<a id="dl-project-5-detail-61"></a>
### 10.22 反事实删除后答错一定是模型缺陷吗

**问题：** 去掉唯一可识别笔画后预测错误，可以作为原任务鲁棒性失败吗？

**解析：** 若标签已不可判定或语义改变，就不再是原有合法变换，不能直接要求答案不变。应先定义任务允许的干预与标签同步规则，再评价。背景替换、裁剪和旋转也各有条件，名字不保证保真。人工控制任务可先隔离内容和无关因素，真实任务再补外部验证。干预有价值，但必须说明修改了什么、保留了什么证据、评分是否仍有唯一正确目标。

<a id="dl-project-5-detail-62"></a>
### 10.23 为什么测试后修改需要新确认

**问题：** 看见测试的小目标错误后专门改模型，再在同测试提高，哪里限制了结论？

**解析：** 测试反馈已经参与决策，它现在具有开发信息角色，改进可能适应该集合。仍可报告这次开发观察，但不能称未参与选择的独立证明。下一轮冻结配置后安排新来源或独立确认，并保留原回归集合观察修复。校正一个概率或增加种子不会让已看数据自动恢复独立；清楚记录数据何时被用来提出或选择修改，是保持研究解释的关键。

<a id="dl-project-5-detail-63"></a>
### 10.24 完成报告最重要的不是哪张图

**问题：** 一份可交付比较应让读者能够做什么？

**解析：** 应能知道研究对象和约束、重建数据与选择角色、从配置找到模型、从样本键复算指标、区分重复与来源不确定性，并判断资源是真测还是公式/模拟。图表服务这些证据，不替代它们。还应看到失败、限制和待检验解释，知道下次新增信息或预算会改变什么。项目质量不靠模块数量或最高分定义，而在于结论可被追踪、复算、反驳和继续推进。

## 11. 综合研究与最终报告验收

<a id="sec-9-1"></a>
<a id="dl-project-5-detail-65"></a>
### 11.1 用一份预设方案完成下一轮比较

从当前图像项目中选一个开发假设，例如减少某类混淆、改善概率质量或降低部署成本。先写目标总体、主指标、可接受损失、候选和搜索预算，再选择两到三个真正区分解释的对照。固定数据与类别语义，决定哪些随机因素配对、哪些重复独立；配置冻结后再建立新确认，不反复利用旧测试作决策。若研究来源泛化，先补来源身份和划分证据，不能只扩大图像数量。

训练阶段记录所有预设运行与失败，验证阶段按同一主要规则选择，评价阶段保存逐条预测与支持数。资源阶段统一输入输出功能与测量边界，区分一次拟合、全部搜索与推理负载。分析阶段先给效果与区间，再检查群体和机制，不为每一个随机波动编造原因。最终将产物加载、指标复算和统计结论分别验收，避免其中一项通过就宣布全部可靠。

<a id="dl-project-5-detail-66"></a>
### 11.2 三类结论分别怎样表达

实测结论写清当前协议下观察到的数值与范围，例如某固定模型在三百六十测试图上的结果。机制结论写清人工或受控条件，例如相同边际总数不能恢复配对不一致，或者因素收益依另一个因素存在而改变。研究设想则说明假设、竞争解释和待运行设计，不用过去时伪装已证实。三类内容可以同在一份实验报告，但读者必须能分辨证据层次。

本章五个独立机制实验验证交互代数、配对比较、层级结构、资源算术和条件参考分布。它们没有为 digits 补出不存在的多种子数据，也没有创造真实硬件基准。整个主题完成后，学习者应能从任务协议一路走到训练、错误、恢复与报告，既能执行代码，也能解释每个数字的对象和限制。把这些环节连起来，才是一个足够充实、可继续研究的学习项目。
